# 第 29 章　强化学习基础

## 本章在全景图中的位置

第 26 章的 SFT 有一个隐含的前提：**每道题都有一个标准答案，模型去模仿它**。这个前提在很多地方不成立，或者不够：

- **答案不止一种写法**。"a red circle and a blue square" 和 "a blue square and a red circle" 都对；LaTeX 公式 `x^{2}` 和 `x^2` 渲染出来一样（第 3、25 章）。SFT 只奖励和标注逐字相同的那一种；
- **我们真正关心的指标不可导**。OCR 看 NED，定位看 IoU，数数看对不对。交叉熵只是它们的替身；
- **模型生成时看到的是自己写的前文**，训练时看到的却是标注的前文（第 17 章的"曝光偏差"）。模型一旦写错一个字，后面的情形是 SFT 从来没训练过的；
- **模型会犯一些系统性的错误**（第 24 章的幻觉、第 27 章的大小写错误），我们希望直接告诉它"这样不好"。

强化学习（reinforcement learning，RL）换了一个思路：**让模型自己写，再给写出来的东西打分，得分高的写法多写、得分低的少写**。不需要标准答案，只需要一个打分的办法（奖励函数）。

本章是第七部分（第 29–32 章）的地基：

## 29.1 强化学习的设定

### 术语对照

| RL 的术语 | 在 VLM 里是什么 |
|---|---|
| **策略** π_θ | 模型。给定图和问题 x，生成回答 y 的概率 π_θ(y \| x)；θ 是模型的参数 |
| **状态** | 图、问题、以及已经写出的前文 |
| **动作** | 下一个 token |
| **轨迹** | 一个完整的回答 y = (y₁, …, y_T)，到 `<eos>` 为止 |
| **奖励** R(x, y) | 给整个回答打的分 |
| **参考模型** π_ref | 开始 RL 之前的模型（通常是 SFT 之后的模型），冻结不动 |

和"经典"的 RL（下棋、玩游戏、控制机器人）比，语言模型的 RL 有三个特点：

1. **奖励只在最后给一次**。写完整个回答才打分，中间的 token 没有单独的分数；
2. **一条轨迹很短**，而且"状态"完全由前文决定，没有随机的环境；
3. **起点已经很好**。我们不是从随机策略开始学，而是从一个已经会做大部分题目的 SFT 模型开始，RL 只是在它附近微调。这一点决定了后面很多设计（KL 约束、不训练价值网络）。

### 可验证奖励

如果奖励能用程序自动、客观地算出来，就叫**可验证奖励**（verifiable reward）。我们的任务几乎都是：

| 任务 | 奖励 |
|---|---|
| 数数、颜色、有没有、比较 | 回答和真值完全相同：1，否则 0 |
| 场景文字、OCR | 1 − NED（第 25 章），在 0 到 1 之间连续变化 |
| 定位 | 预测框和真实框的 IoU；写不出合法的框：0 |
| 描述 | 1 − NED，或者"提到的物体"的准确率和召回率（第 23 章） |

这些奖励不需要训练一个"奖励模型"，也不需要人打分，所以既便宜又不会被"骗"（至少不会像奖励模型那样被骗，29.8 节）。第 31 章会把它们写成代码。没有可验证奖励的情形（"这个回答有没有帮助？"），要么训练一个奖励模型，要么用第 30 章的 DPO 直接从人的偏好学。

### 和 SFT 的根本区别

SFT 的训练数据是固定的，来自标注；RL 的训练数据是**模型自己刚刚生成的**，每一步都在变。所以 RL 的一步是：

```
1. 采样（rollout）：对一批题目，用当前的模型生成回答
2. 打分：用奖励函数给每个回答打分
3. 更新：让高分的回答变得更可能、低分的变得更不可能
```

第 1 步要生成，比 SFT 的一次前向慢得多；第 3 步要用到第 27 章的"回答的对数概率"。

## 29.2 目标

我们想最大化：

```
J(θ) = E_{y ~ π_θ}[ R(x, y) ]  −  β · KL( π_θ ‖ π_ref )
```

- 第一项：模型自己写的回答，平均能得多少分；
- 第二项：现在的模型和参考模型差多远（第 6 章的 KL 散度），β ≥ 0 是系数。

为什么要第二项？只看第一项，模型会想尽一切办法拿高分，包括钻奖励函数的空子（29.8 节）、丢掉原来会的东西（第 32 章）。KL 项像一根绳子，把模型拴在参考模型附近。β = 0 是没有绳子；β 越大，绳子越短。

（注意 KL 的方向：KL(π_θ‖π_ref) = E_{y~π_θ}[log π_θ(y) − log π_ref(y)]，期望是对**现在的模型**采样的回答求的。这个方向允许模型把概率集中到参考模型的少数几个回答上，但不允许它写出参考模型认为几乎不可能的东西——那样 log π_ref 是很大的负数，KL 会很大。）

## 29.3 策略梯度

### 难点在哪里

先只看第一项 J(θ) = E_{y~π_θ}[R(y)]（省略 x）。我们要 ∇_θ J。

SFT 的损失是"对数概率的平均"，直接求导就行。这里不一样：**期望是对 π_θ 采样出来的 y 求的**，θ 变了，采样出来的 y 的分布也变了。而且 R(y) 是一个程序（比较两个字符串），对 y 根本没法求导；y 是离散的 token，也没法求导。

### 对数导数技巧

把期望写成求和（y 取遍所有可能的回答）：

```
J(θ) = Σ_y π_θ(y) · R(y)
```

R(y) 和 θ 无关，只有 π_θ(y) 依赖 θ：

```
∇_θ J = Σ_y ∇_θ π_θ(y) · R(y)
```

现在用一个恒等式：**∇π = π · ∇log π**（因为 ∇log π = ∇π / π，两边乘以 π）。代进去：

```
∇_θ J = Σ_y π_θ(y) · ∇_θ log π_θ(y) · R(y)
      = E_{y ~ π_θ}[ R(y) · ∇_θ log π_θ(y) ]
```

最后一行又是一个"对 π_θ 采样求期望"，可以用采样来估计：**采 n 个回答，每个算 R(y_i) · ∇log π_θ(y_i)，取平均**。这就是策略梯度（policy gradient），这个算法叫 REINFORCE（Williams，1992）。

它的直觉很简单：∇log π_θ(y) 是"让 y 变得更可能"的方向（第 6 章：最大似然的梯度）。每个采样出来的回答，都朝"让它更可能"的方向推一下，推多远由它的奖励决定：奖励大的推得多，奖励为 0 的不推，奖励为负的反着推。

### 序列的情形

一个回答的概率是每个 token 的条件概率的乘积（第 27 章），所以：

```
log π_θ(y) = Σ_t log π_θ(y_t | x, y_<t)
∇_θ J = E[ R(y) · Σ_t ∇_θ log π_θ(y_t | x, y_<t) ]
```

整个回答的奖励 R 乘到**每一个** token 的对数概率的梯度上。写对了的回答，它的每一个 token 都被推高，包括那些和"对不对"无关的 token（比如格式）。这是奖励只在最后给一次的代价：模型不知道到底是哪个 token 让回答变好的，只能靠大量的采样慢慢平均出来。

### 写成一个损失函数

在 PyTorch 里我们不手写梯度，而是写一个损失，让 autograd 求导。什么样的损失，求导之后正好是策略梯度？

```python
loss = -(R.detach() * seq_logp).mean()          # seq_logp：每个回答的总对数概率（有梯度）
```

对它求导：−R · ∇seq_logp 的平均，正好是策略梯度的负数（我们最小化损失，等于最大化 J）。关键是 R 不带梯度（它本来就是一个常数），y 是采样出来的固定的 token。

这个"损失"本身的数值**没有意义**：它不是 J，也不会随训练单调下降。不要用它的数值判断训练好不好，要看奖励。

把它和 SFT 的损失放在一起：

```
SFT：       loss = −mean( log π_θ(标注的答案) )
策略梯度：  loss = −mean( R · log π_θ(模型自己采样的回答) )
```

SFT 就是"只用标注答案、奖励恒为 1"的策略梯度。反过来，策略梯度是"用模型自己的样本、按奖励加权"的 SFT。

### 练习：softmax 策略的 ∇log π

最简单的策略：K 个动作，π = softmax(θ)，θ 是 K 个数。证明：

```
∂ log π(a) / ∂θ_k = 1[k = a] − π_k          即  ∇_θ log π(a) = onehot(a) − π
```

（提示：log π(a) = θ_a − log Σ_j exp(θ_j)。第 6 章的交叉熵梯度 π − onehot 就是它的负数。）

## 29.4 基线与优势

### 第 1 部分：一个可以精确计算的例子

**多臂老虎机**：有 5 个拉杆（编号 0–4，和代码里的下标一致），拉第 k 个拉杆得到的奖励是 μ_k 加上一个标准正态的噪声，μ = [1.0, 1.5, 2.0, 5.0, 2.5]。策略 π = softmax(θ)，θ 从 0 开始（5 个拉杆等概率）。

这个问题小到可以**精确**地算出梯度：J = Σ_k π_k μ_k，所以

```
∂J/∂θ_k = π_k (μ_k − J)
```

（自己推一下：用上面的练习，∂J/∂θ_k = Σ_a π_a μ_a (1[k = a] − π_k) = π_k μ_k − π_k J。）θ = 0 时 J = 2.40，精确梯度是 [−0.28, −0.18, −0.08, 0.52, 0.02]：最好的拉杆（第 3 个）概率应该增大，其余的减小（第 4 个 μ = 2.5 略高于 J，略微增大）。

现在用采样估计它：每次拉 8 次，用策略梯度公式算一个估计值；重复 20000 次，看估计值的平均和方差：

```
基线      平均梯度                                    平均 / 精确（第 3 维）   各维方差之和
none    [-0.279, -0.182, -0.078, 0.52, 0.019]           1.000             0.825
```

平均值和精确梯度一致：**策略梯度是无偏的**。但方差很大。精确梯度的长度的平方是 0.28² + 0.18² + 0.08² + 0.52² + 0.02² ≈ 0.388，方差 0.825 是它的 2 倍多：一次估计里噪声比信号还大。

### 方差从哪里来

看一次估计：拉了第 0 个拉杆，奖励 1.0 + 噪声。μ₀ = 1.0 是最差的，但奖励是**正的**，所以策略梯度会**推高**第 0 个拉杆的概率。所有拉杆的奖励都是正的，所以不管拉了哪个，都会推高它，只是推多推少的区别。"哪个拉杆更好"这个信号，藏在"推多推少"的差别里，被"每次都推高"的大幅度晃动淹没了。

把所有奖励都加 100，相对的好坏完全没变，问题会严重得多：

```
所有奖励加 100：
  none    各维方差之和     1050.369
```

方差变成了 1000 多倍。

### 基线

解决办法：每个奖励减去一个**和动作无关**的数 b，叫**基线**（baseline）：

```
∇_θ J = E[ (R(y) − b) · ∇_θ log π_θ(y) ]
```

**为什么减去 b 不改变期望？** 只需证明 E[b · ∇log π_θ(y)] = 0：

```
E_{y~π}[ b · ∇log π(y) ] = b · Σ_y π(y) · ∇log π(y)
                         = b · Σ_y ∇π(y)              （∇π = π ∇log π，反着用）
                         = b · ∇ Σ_y π(y)
                         = b · ∇ 1  =  0
```

概率之和永远是 1，对常数求导是 0。所以**任何和 y 无关的 b 都不改变梯度的期望**，但选得好的 b 能大大减小方差：R − b 有正有负，比基线好的回答被推高，比基线差的被压低。

R − b 叫做**优势**（advantage），记作 A：这个回答比"平均水平"好多少。

### 几种基线

| 基线 | b | 无偏？ |
|---|---|---|
| none | 0 | 是 |
| mean | 这 n 个样本的平均奖励（包括自己） | **否**：梯度缩小为 (n − 1)/n |
| loo（留一） | 除了自己以外 n − 1 个样本的平均 | 是 |
| group（组内标准化，GRPO） | (R − 均值) / 标准差 | 方向无偏，但长度被缩放 |
| exact | 真实的期望奖励 J | 是（现实里拿不到） |

实测：

```
基线      平均梯度                                    平均 / 精确（第 3 维）   各维方差之和
none    [-0.279, -0.182, -0.078, 0.52, 0.019]           1.000             0.825
mean    [-0.248, -0.155, -0.07, 0.456, 0.017]           0.877             0.228
loo     [-0.279, -0.177, -0.081, 0.518, 0.019]          0.996             0.293
group   [-0.143, -0.09, -0.037, 0.251, 0.019]           0.483             0.068
exact   [-0.28, -0.179, -0.079, 0.518, 0.019]           0.997             0.246

所有奖励加 100：
  none    各维方差之和     1050.369   平均 / 精确（第 3 维）  0.856
  loo     各维方差之和        0.294   平均 / 精确（第 3 维）  0.994
  group   各维方差之和        0.068   平均 / 精确（第 3 维）  0.484
```

逐行读：

- **mean 缩小了 0.877 ≈ 7/8**。原因：样本 i 的基线里有它自己的奖励 r_i / n。把 A_i = r_i − r̄ 展开，r_i 的系数是 (1 − 1/n)，其余样本的奖励和动作 a_i 独立，期望里贡献 0（上面的证明）。所以 E[A_i ∇log π(a_i)] = (1 − 1/n) · 真实梯度。n = 8 时是 7/8 = 0.875。这个偏差只是把梯度整体缩小，方向不变，一般不致命，但你应该知道它在那里；
- **loo 无偏**（0.996，和 1 的差别是采样误差），因为基线里没有自己。展开可以发现 loo 的优势正好是 mean 的 n/(n − 1) 倍：A_i^loo = (n/(n−1)) · (r_i − r̄)，把 7/8 的缩小补了回来（测试 `test_loo_advantages` 验证了这个关系）；
- **group 缩小到 0.483**：除以组内标准差（这里约 1.7）把梯度的长度改了，方向和 mean 一样。所以它的方差 0.068 看起来最小，有一部分只是因为整体变小了。公平的比较要看**相对方差**：方差 ÷ (平均梯度的长度)²。用上面的数手算：none 约 2.1，mean、loo、group 都约 0.76，exact 约 0.64。**这几种基线降低噪声的能力差不多，都比没有基线好 3 倍左右**；
- **所有奖励加 100**：没有基线时方差变成 1050（"平均 / 精确"的 0.856 也只是因为方差太大、2 万次的平均还不够准）；有基线时几乎没变（0.294、0.068）。**优势只关心相对的好坏，和奖励的绝对大小无关**。

### 第 2 部分：基线是能不能训练的区别

用这些梯度估计去训练 θ（每步拉 8 次，300 步，20 个种子），奖励都加 100。这里训练的只是 5 个数，不是神经网络，几秒钟就跑完：

```
学习率 0.05：
  none   第 50 步 J 的平均  2.33；第 300 步 J 平均  2.65，最差  1.00，最好  5.00
  loo    第 50 步 J 的平均  4.01；第 300 步 J 平均  4.93，最差  4.92，最好  4.95
  group  第 50 步 J 的平均  3.04；第 300 步 J 平均  4.83，最差  4.81，最好  4.86
学习率 0.5：
  none   第 50 步 J 的平均  2.30；第 300 步 J 平均  2.30，最差  1.00，最好  5.00
  loo    第 50 步 J 的平均  4.96；第 300 步 J 平均  4.99，最差  4.99，最好  5.00
  group  第 50 步 J 的平均  4.92；第 300 步 J 平均  4.99，最差  4.98，最好  4.99
```

（最优的 J 是 5.0，即总是拉第 3 个拉杆。）

- **没有基线**：20 个种子的结局天差地别，有的找到了最好的拉杆（5.00），有的锁死在最差的拉杆上（1.00），平均 2.3–2.65，和不学（2.40）差不多。原因就是上面说的：每次拉到的拉杆都被大幅推高（奖励约 100），哪个拉杆早期碰巧被拉得多，它的概率就越来越大，最后锁死。学习率越大，锁死得越快；
- **有基线**：20 个种子都接近最优。学习率 0.05 时 group 比 loo 慢一些（第 50 步 3.04 vs 4.01），因为它的梯度被缩小到一半左右，相当于学习率减半；学习率 0.5 时两者都很快收敛。

### 练习 29.1、29.2：两种优势

```python
def group_advantages(rewards, G, std=True, eps=1e-6):
    r = rewards.float().view(-1, G)
    a = r - r.mean(1, keepdim=True)
    if std:
        a = a / (r.std(1, keepdim=True) + eps)
    return a.view(-1)


def loo_advantages(rewards, G):
    r = rewards.float().view(-1, G)
    base = (r.sum(1, keepdim=True) - r) / (G - 1)
    return (r - base).view(-1)
```

约定：`rewards` 是一维的，每连续 G 个是**同一道题**的 G 个回答。`view(-1, G)` 把它变成"题目 × 回答"的矩阵，每一行单独算均值和标准差。

`r.std` 默认是无偏标准差（除以 G − 1）。手算一个例子（测试里的第一组）：奖励 [1, 0, 0, 1]，均值 0.5，偏差 ±0.5，标准差 √(4 × 0.25 / 3) = 0.577，优势 ±0.5 / 0.577 = ±0.866。

`eps` 防止除以 0：组内奖励全相同时标准差是 0，偏差也是 0，0 / (0 + ε) = 0。

## 29.5 组内标准化与"没有梯度的题"

### 为什么用"组"

老虎机只有一个"题目"。语言模型有成千上万道题，每道题的难度不同：一道简单的题，大部分回答都对，平均奖励 0.9；一道难题，平均奖励 0.1。如果把所有题目的回答混在一起算一个基线（比如 0.5），简单题的回答几乎都被推高（A ≈ +0.4），难题的几乎都被压低（A ≈ −0.4），和"这个回答在这道题上好不好"无关。

所以每道题**单独**采 G 个回答（一组），用这组的平均奖励当基线：A_i = r_i − 这道题的平均。这样不需要额外训练一个"预测每道题平均奖励"的网络（PPO 的价值网络，29.14 节），这是 GRPO（Group Relative Policy Optimization，DeepSeekMath，2024）的核心想法。

再除以组内的标准差，是把每道题的优势统一到差不多的尺度上：不管这道题的奖励在 0–1 之间还是 0–0.1 之间变化，优势的标准差都是 1。这样做是否合理有争议：一道"几乎全对、只有一个错"的题，那个错的回答的优势会被放得很大。第 31 章会比较去掉标准差的做法（Dr. GRPO）。

### 组内奖励全相同：这道题白算了

如果一组 8 个回答都对（奖励都是 1），优势全是 0，这一组对梯度**没有任何贡献**。全错也一样。模型从太简单和太难的题目上都学不到东西：**只有"有时对、有时错"的题目才提供学习信号**。

这件事的实际意义很大：采样是 RL 里最贵的一步，如果一批题目里大部分都是全对或全错，大部分采样都浪费了。所以训练时要监控**没有梯度的组所占的比例**（`zero_variance_fraction`），第 31 章的 DAPO 干脆把这样的组过滤掉、再补采新的题目。

### 第 5 部分：一个真实的模型，有多少题是白算的

用第 24 章的 Qwen3.5-0.8B（只推理，不训练），在我们的三个玩具任务上，每道题用温度 1 采样 8 个回答，按"第一个词和真值相同"给 0/1 奖励：

```
count   平均奖励 86.9%；组内全对 65%、全错 0%、有对有错 35%；没有梯度的组 65%
    真值 '3'：['3', '3', '3', '3', '1', '2', '3', '3']
    真值 '2'：['2', '3', '1', '3', '2', '2', '2', '2']
left    平均奖励 76.2%；组内全对 55%、全错 15%、有对有错 30%；没有梯度的组 70%
    真值 'green'：['red', 'green', 'green', 'green', 'green', 'green', 'green', 'green']
    真值 'yellow'：['yellow', 'blue', 'blue', 'blue', 'blue', 'blue', 'blue', 'blue']
exists  平均奖励 100.0%；组内全对 100%、全错 0%、有对有错 0%；没有梯度的组 100%
```

（每个任务 20 题 × 8 个回答，CPU 上每个任务约 55 秒。）

和第 24 章的贪心解码比（count 98%、left 86%、exists 98%）：

- **温度 1 的采样比贪心差**（count 86.9% vs 98%）。贪心每一步选概率最大的 token；采样会以一定的概率选到别的，小模型的分布不够尖锐，采样就常常出错。RL 训练的正是这个"采样时的分布"：它要把正确答案的概率推得更高，让采样也稳定地写对；
- **大部分题目没有梯度**：count 65%、left 70%、exists 100% 的组是全对或全错。如果用这些题目做 RL，exists 任务的采样全部白算，count 和 left 只有三分之一的题目在提供信号；
- **left 有 15% 的题全错**：这些题模型"根本不会"（比如第二个例子，8 次里只有 1 次写对 yellow，其他 7 次都说 blue——也许它把某个形状看成了别的颜色）。全错的题和全对的题一样没有梯度，RL 帮不了它，要靠更多的 SFT 数据或者更好的视觉编码；
- **有对有错的题正好是 RL 最有用的地方**：比如第一个例子，8 次里写对 6 次，RL 会把那 2 次错误的写法（`1`、`2`）压低，把 `3` 推高。

这也说明了 29.4 节的结论在真实模型上意味着什么：RL 改进的是"模型有时会、有时不会"的那部分能力，前提是题目的难度和模型的水平相匹配。第 31 章会实现"只保留有对有错的组"的动态采样。

## 29.6 KL 惩罚与它的估计

### 怎样算 KL

```
KL(π‖π_ref) = E_{y~π}[ log π(y) − log π_ref(y) ]
```

y 是整个回答，所有可能的回答多到没法求和，只能用采样估计。对语言模型，log π(y) = Σ_t log π(y_t | …)，所以 KL 可以拆成每个 token 的贡献之和，我们在每个采样出来的 token 上算一个估计值。

记 log r = log π_ref(y_t) − log π(y_t)，即 r = π_ref / π（参考模型和现在的模型给这个 token 的概率之比）。三个常用的估计量（Schulman，2020）：

| 估计量 | 公式 | 无偏？ | 每个样本 ≥ 0？ |
|---|---|---|---|
| k1 | −log r | 是 | 否 |
| k2 | (log r)² / 2 | 否（两个分布接近时近似无偏） | 是 |
| k3 | (r − 1) − log r | 是 | 是 |

**k1 无偏**：E_π[−log r] = E_π[log π − log π_ref]，就是 KL 的定义。

**k3 无偏**：E_π[r] = Σ π · (π_ref / π) = Σ π_ref = 1，所以 E_π[r − 1] = 0，k3 的期望和 k1 相同。k3 = k1 + (r − 1)：加上了一个期望为 0 的量（"控制变量"），用来抵消 k1 的一部分波动。

**k3 ≥ 0**：令 f(r) = r − 1 − log r，f'(r) = 1 − 1/r，在 r = 1 处为 0，f''(r) = 1/r² > 0，所以 r = 1 是最小值，f(1) = 0。（也可以从 log r ≤ r − 1 直接看出来。）

k1 为什么会有负值？真实的 KL ≥ 0，但对单个 token，如果参考模型给它的概率比现在的模型大（r > 1），−log r < 0。这在数学上没问题（平均起来是对的），但单个样本的 KL 是负数，看起来很奇怪，而且方差大。

### 练习 29.3：`kl_estimate`

```python
def kl_estimate(logp, ref_logp, kind="k3"):
    log_r = ref_logp - logp
    if kind == "k1":
        return -log_r
    if kind == "k2":
        return log_r ** 2 / 2
    if kind == "k3":
        return torch.exp(log_r) - 1 - log_r
    raise ValueError(kind)
```

注意用对数概率的差算 r：`exp(ref_logp - logp)`，而不是 `exp(ref_logp) / exp(logp)`：后者在概率很小时会下溢成 0 / 0。

### 第 3 部分 (a)：两个已知的分布

20 个类别的两个分布，精确的 KL 可以直接算出来。从 π 采 20 万个样本：

```
π_ref 与 π 接近：精确 KL = 0.0222
  k1  平均 0.0222   每个样本的标准差 0.2141   最小 -0.4642
  k2  平均 0.0232   每个样本的标准差 0.0318   最小 +0.0002
  k3  平均 0.0223   每个样本的标准差 0.0304   最小 +0.0002
π_ref 与 π 差得远：精确 KL = 1.6834
  k1  平均 1.6840   每个样本的标准差 1.6920   最小 -2.8571
  k2  平均 2.8495   每个样本的标准差 3.0418   最小 +0.0514
  k3  平均 1.6849   每个样本的标准差 1.8602   最小 +0.0463
```

- 两个分布接近时：k1、k3 都无偏，k3 的标准差只有 k1 的 1/7；k2 略有偏差；
- 差得远时：k2 的偏差很大（2.85 vs 1.68）；k3 仍然无偏，但标准差不再比 k1 小。k3 的优势只在两个分布接近时成立，而 RL 训练时正好是这种情形（KL 惩罚让它们保持接近）。

### 第 3 部分 (b)：真实的语言模型

π = 第 16 章的字符级 GPT 在温度 0.7 下的分布，π_ref = 同一个模型在温度 1 下的分布。从 π 采 64 条、每条 100 个字符。每个位置上，两个分布都是完整的 100 个字符的概率，所以精确的 KL 也能算出来：

```
每个位置精确 KL 的平均 0.0224，每条序列的 KL（100 个位置之和）平均 2.241
  k1  每个 token 平均 0.0190   每个 token 的标准差 0.1988   最小 -1.9573   每条序列之和的标准差 1.866
  k2  每个 token 平均 0.0199   每个 token 的标准差 0.0780   最小 +0.0000   每条序列之和的标准差 0.776
  k3  每个 token 平均 0.0241   每个 token 的标准差 0.1321   最小 -0.0000   每条序列之和的标准差 1.230
```

（k3 的"−0.0000"是浮点舍入，数学上它 ≥ 0。）

- 6400 个 token 的平均，k1、k3 和精确值的差（−0.0034、+0.0017）都在采样误差之内（标准差 ÷ √6400 约 0.0025、0.0017）；
- 这里 k3 的标准差只比 k1 小 1/3，不像 (a) 那样小 7 倍。原因：π 是温度 0.7 的分布，比参考模型尖锐。偶尔采到 π 认为不太可能、参考模型却觉得很可能的 token 时，r 很大，k3 = r − 1 − log r 跟着很大。"两个分布接近"不仅要看平均的 KL 小不小，还要看有没有这样的尾巴；
- **单条序列的 KL 估计非常不准**：平均 2.24，标准差 1.23（k3）。所以训练时 KL 只有在整批平均之后才有参考价值。

### 第 3 部分 (c)：放进损失之后，梯度对吗

上面讨论的是"估计 KL 的数值"。但训练时我们把 β·k 放进**损失**里求导，关心的是**梯度**对不对。这是两个不同的问题。

在 20 个类别的例子上精确地算：采样分布 π 不求导（采样是在 `no_grad` 下做的），对 E_{x~π}[k(x)] 里的 k(x) 求导，和真正的 ∇KL 比较方向（余弦相似度）：

```
放进损失的量       与 ∇KL(π‖π_ref) 的余弦    与 ∇KL(π_ref‖π) 的余弦     梯度的长度
（精确）                      1.000                 0.750     0.469
k1                              nan                   nan     0.000
k2                            1.000                 0.750     0.469
k3                            0.750                 1.000     0.388
```

三个估计量的梯度完全不同：

- **k1 的梯度期望为 0**：∇k1 = ∇(log π − log π_ref) = ∇log π，而 E_π[∇log π] = 0（29.4 节的证明）。把 k1 直接放进损失，KL 惩罚**什么也不做**；
- **k2 的梯度正好是 ∇KL(π‖π_ref)**：∇k2 = (log π − log π_ref) · ∇log π，它的期望就是 KL 的策略梯度（把 log π − log π_ref 当作"奖励"）；
- **k3 的梯度是另一个方向的 KL，KL(π_ref‖π) 的梯度**：∇k3 = (1 − r) · ∇log π，期望是 Σ π(1 − π_ref/π)∇log π = −Σ π_ref ∇log π，正好是 ∇KL(π_ref‖π)。

自己把这三行推一遍。结论是：**k3 作为数值估计很好，作为损失项，它优化的是"反方向"的 KL**。两个方向的 KL 在两个分布接近时差不多（这里余弦 0.75），所以 GRPO 用 k3 放进损失在实践中能工作，但它不是在精确地优化 29.2 节写的那个目标。最近有不少工作讨论这一点，有的方法（第 31 章的 DAPO 和 Xiaomi-OCR-0 的 Mix-RL）干脆去掉 KL 项。

### KL 放在哪里

两种放法：

- **放进损失**（GRPO）：loss = −A·log π + β·k3，KL 和奖励分开；
- **放进奖励**（经典的 PPO-RLHF）：每个 token 的奖励减去 β·(log π − log π_ref)，再算优势。这相当于用 k1 当"奖励"，再用策略梯度去优化它，梯度是对的（就是上面 k2 那一行的形式）。

第 6 部分的实验用"放进损失、用 k3"，和 GRPO 相同。

## 29.7 重要性比值与裁剪

### 为什么需要

策略梯度要求样本来自**现在的**策略。但采样很贵，我们希望一批样本用好几次：采一次，更新好几步。更新一步之后，策略已经变了（θ → θ'），手上的样本来自旧的策略 π_old，"过期"了。

### 重要性采样

一个恒等式：

```
E_{y~π}[ f(y) ] = Σ_y π(y) f(y) = Σ_y π_old(y) · (π(y) / π_old(y)) · f(y) = E_{y~π_old}[ ρ(y) · f(y) ]
```

ρ = π / π_old 叫**重要性比值**。用旧策略的样本，乘以 ρ，就能估计新策略下的期望。逐 token 地：

```
ρ_t = π_θ(y_t | …) / π_old(y_t | …) = exp( log π_θ(y_t) − log π_old(y_t) )
目标：最大化 E[ ρ_t · A ]
```

在 θ = θ_old 时，ρ = 1，∇ρ = ∇log π，目标的梯度正好是策略梯度。

### 裁剪

ρ 离 1 越远，这个估计的方差越大，而且一步更新可能把策略推得太远。PPO（Schulman 等，2017）的办法：

```
目标_t = min( ρ_t · A,  clip(ρ_t, 1 − ε, 1 + ε) · A )          ε 通常取 0.2
```

### 练习 29.4：`clipped_objective`

```python
def clipped_objective(logp, old_logp, adv, eps_low=0.2, eps_high=None):
    eps_high = eps_low if eps_high is None else eps_high
    ratio = torch.exp(logp - old_logp)
    a = ratio * adv
    b = ratio.clamp(1 - eps_low, 1 + eps_high) * adv
    obj = torch.minimum(a, b)
    return obj, (b < a)
```

`eps_high` 允许上下两边的 ε 不同，第 31 章 DAPO 的"clip-higher"就是把上边放宽到 0.28。

### 第 4 部分：目标和梯度随 ρ 怎样变

```
A = +1（好回答：想让 ρ 变大）
  ρ             0.50   0.70   0.85   0.95   1.00   1.05   1.15   1.30   1.50   2.00
  目标          0.50   0.70   0.85   0.95   1.00   1.05   1.15   1.20   1.20   1.20
  ∂目标/∂logp   0.50   0.70   0.85   0.95   1.00   1.05   1.15   0.00   0.00   0.00
  被裁剪                                                         是     是     是
A = -1（坏回答：想让 ρ 变小）
  ρ             0.50   0.70   0.85   0.95   1.00   1.05   1.15   1.30   1.50   2.00
  目标         -0.80  -0.80  -0.85  -0.95  -1.00  -1.05  -1.15  -1.30  -1.50  -2.00
  ∂目标/∂logp   0.00   0.00  -0.85  -0.95  -1.00  -1.05  -1.15  -1.30  -1.50  -2.00
  被裁剪        是     是
```

（对 log π 求导：∂(ρA)/∂log π = ρA，所以没被裁剪时梯度等于目标本身。）

- **好回答（A > 0）**：ρ 超过 1.2 之后，目标被截在 1.2，梯度为 0：**已经推高了 20%，这一批样本不再继续推**。ρ < 1（这个好回答反而变得不太可能了）时照常推，没有任何限制；
- **坏回答（A < 0）**：ρ 低于 0.8 之后梯度为 0：**已经压低了 20%，不再继续压**。ρ > 1（坏回答反而变得更可能了）时照常压，而且 ρ 越大压得越狠；
- min 让目标总是取"更悲观"的那一个：**只限制朝有利方向走得太远，不限制纠正错误**。

（表里避开了 ρ 正好等于 0.8、1.2 的点：在边界上 min 的两项相等，PyTorch 会把梯度平分给两项，得到 0.4 这样的数，容易让人困惑。）

**什么时候裁剪才起作用？** 只有 ρ 偏离 1 的时候。如果每采一批样本只更新一步，更新前 θ = θ_old，ρ 恒等于 1，裁剪什么也不做，整个目标退化成普通的策略梯度。所以：

- 同一批样本更新多步（PPO 的"多个 epoch"、GRPO 的 μ > 1）时，裁剪是必须的；
- 每批只更新一步时，代码里可以保留它，但它不起作用；
- 一个例外：采样用的是另一套推理引擎（比如 vLLM），它算的概率和训练框架有微小的差别，ρ 从第一步就不等于 1。真实的系统要处理这个问题（rollout.py 的文档说明了我们为什么用同一种前向来算 old_logp）。

## 29.8 奖励投机

### 什么是奖励投机

模型最大化的是**奖励函数**，不是我们心里想要的东西。两者之间只要有一点缝隙，RL 就会找到它，这叫**奖励投机**（reward hacking）。几个在 VLM/OCR 上会真实发生的例子：

| 奖励 | 漏洞 | 模型学会的 |
|---|---|---|
| 1 − NED，但输出为空时程序出错、返回 0.5 | 空输出拿 0.5 | 读不出来就什么都不写 |
| 定位：预测框"包含"真实框就给 1 | 框越大越容易包含 | 永远输出整张图 |
| 描述：提到的物体里真实存在的比例（只看准确率） | 少说少错 | 只说一个最有把握的物体 |
| 回答长度在某个范围内加分 | 长度好控制，正确性难 | 用重复的字凑长度 |
| 奖励模型（不是可验证奖励）给的分 | 奖励模型自己的偏好（比如喜欢长回答、喜欢某些词） | 迎合奖励模型 |

前三个都可以用更仔细的奖励函数堵上：空输出给 0；用 IoU 而不是"包含"；准确率和召回率一起看。这就是为什么**设计奖励函数和设计模型一样重要**，第 31 章会花一整节讨论。

### KL 惩罚怎样帮忙

KL 惩罚不能堵上漏洞，但能让模型钻漏洞的代价变高：参考模型几乎不会"永远输出整张图"或"只写空格"，模型要走到那里，KL 会变得很大。β 越大，模型越难走远，但也越难学到真正有用的改进。

### 第 6 部分：故意设计一个容易投机的奖励（你自己跑）

用第 16 章的字符级 GPT 当策略（它在混合语料上预训练过，会写英文、Markdown、数字），参考模型是它的一份冻结的副本：

- 提示：只有 `<bos>`，让它自由地写 48 个字符；

## 29.9 在我们的 VLM 上采样

第 30、31 章要在我们自己的 VLM 上做 RL，采样用 `miniocr/rl/rollout.py`：

```python
responses, finished = rollout(vlm, images, prompts, G=8, max_new=20, eos=EOS, temperature=1.0)
ids, mask = make_batch([prompts[i // 8] for i in range(len(responses))], responses, finished, EOS, PAD)
with torch.no_grad():
    old_logp = policy_logprobs(vlm, images_repeated, ids)          # (B, T−1)
```

几个设计：

- **按提示长度分组生成**。我们的 GPT 没有"左侧补齐"的 attention mask，同一次 `generate` 里的提示必须一样长。第 23 章的 `ask` 也是这样做的；
- **温度 1**。温度改变了采样的分布，算 log π 时也要用同一个温度（logits / T），否则 ρ 不等于 1。最简单的做法是采样和训练都用温度 1；
- **采样之后重新做一次完整的前向算 old_logp**，而不是用生成时的 logits。生成用 KV cache 逐个 token 算，训练用整条序列一次算完，两者数值上有微小的差别（第 17 章）。用同一种前向算 old_logp 和 logp，第一步的 ρ 精确等于 1；
- **没写完的回答**（到了 max_new 还没写 `<eos>`）：`finished` 为 False，回答后面不加 `<eos>`，mask 只覆盖写出来的 token。第 31 章 DAPO 的"超长惩罚"讨论怎样对待它们；
- `make_batch` 返回的 mask 和第 27 章的约定一致：mask[b, t] = 1 当且仅当 ids[b, t + 1] 是回答的 token（包括 `<eos>`）。测试 `test_rollout_and_logprobs` 检查了补齐不影响每个回答的对数概率。

## 29.12 常见错误

| 错误 | 症状 | 原因与修正 |
|---|---|---|
| 优势没有按组算，所有题目混在一起 | 简单题的回答都被推高，难题都被压低 | `view(-1, G)` 按组算；采样时同一道题的 G 个回答要连续排列 |
| 奖励带着梯度（或者 A 没有 `detach`） | 报错，或者梯度里多了奇怪的项 | 奖励和优势都是常数 |
| 用"损失"的数值判断训练的好坏 | 损失上下乱跳，看不出趋势 | 策略梯度的"损失"没有意义，看平均奖励和 KL |
| 采样时没有 `no_grad` | 内存爆炸 | 采样不需要梯度；梯度在重新算 logp 的那次前向里 |
| old_logp 在多步更新中被重新计算 | ρ 恒为 1，裁剪失效 | old_logp 采样后算一次，之后不变 |
| 采样用温度 T，算 logp 用温度 1 | 第一步的 ρ 就不是 1 | 两者用同一个温度 |
| k1 直接放进损失 | KL 惩罚不起作用 | 用 k3（或者把 KL 放进奖励） |
| 只看奖励，不看输出 | 被投机而不自知 | 每隔一段时间打印几个回答；同时看 KL 和其他任务的分数（第 32 章） |
| 题目太简单或太难 | 奖励不动，大部分组没有梯度 | 监控 `zero_variance_fraction`；按难度挑题（第 31 章） |

## 29.14 深入一步

### 价值网络与 PPO

我们用"同一道题的其他回答"当基线。经典的 PPO 训练一个**价值网络** V(状态)，预测"从这个状态出发，最终能拿多少分"，用它当基线。好处是每个 token 都可以有自己的基线（GAE），能区分"这个回答里哪些 token 好"；坏处是要多训练一个和策略一样大的网络，内存翻倍，而且价值网络本身不好训练。

对"奖励只在最后给一次、起点已经很好"的语言模型 RL，大家发现组内基线就够用了，这是 GRPO、RLOO 流行的原因。

### 为什么 KL 用这个方向

KL(π‖π_ref) 是"反向 KL"：期望对 π 求。它惩罚 π 写出 π_ref 认为不可能的东西，但允许 π 只保留 π_ref 的一部分写法（"模式寻找"）。正向 KL(π_ref‖π) 则要求 π 覆盖 π_ref 的所有写法（"均值覆盖"）。RL 的目标"在参考模型附近、找奖励更高的写法"天然对应反向 KL：我们希望模型放弃那些拿低分的写法。第 3 部分 (c) 告诉我们，GRPO 的 k3 损失实际上优化的是正向 KL 的梯度，这也是近来有人建议换成 k2 或者干脆去掉 KL 的原因之一。

### 带 KL 约束的最优策略

29.2 节的目标有一个解析的最优解（第 30 章推导）：

```
π*(y) ∝ π_ref(y) · exp( R(y) / β )
```

参考模型的概率按奖励指数地重新加权。β 很大时 π* ≈ π_ref；β 很小时 π* 把所有概率放在奖励最高的回答上。这个式子是 DPO 的出发点。

## 29.16 本章小结

1. 语言模型的 RL：策略 = 模型，轨迹 = 回答，奖励 = 给整个回答的分；我们的任务大多有可验证奖励；
2. 策略梯度 ∇J = E[R · ∇log π(y)]，来自对数导数技巧；写成损失是 −R·log π（R 不带梯度），SFT 是奖励恒为 1 的特例；
3. 减去基线不改变期望（Σ∇π = 0），把方差降到原来的 1/3 左右；奖励整体平移 100 时，没有基线根本训练不起来；
4. "含自己的均值"缩小梯度 (n − 1)/n；留一基线无偏；组内标准化改变梯度的长度；
5. 组内奖励全相同的题没有梯度：只有"有时对、有时错"的题提供学习信号；
6. KL 的三个估计量：k1 无偏、方差大、有负值；k3 无偏、非负、两个分布接近时方差小。但放进损失求导时，k1 的梯度为 0，k2 的梯度才是 ∇KL(π‖π_ref)，k3 的梯度是另一个方向的 KL；
7. 重要性比值让一批样本可以用多次；裁剪只限制"朝有利方向走得太远"，只在多步更新时起作用；
8. RL 会找到奖励函数的每一个漏洞。KL 让投机的代价变高，但真正的办法是设计好的奖励。

下一章换一个思路：不采样、不用奖励函数，直接从"这个回答比那个好"的成对数据学，这就是 DPO。

## 参考答案

1. ∇J = E_{y~π}[R(y) · ∇log π(y)]。对数导数技巧是 ∇π = π · ∇log π。J 是对 π 采样的期望，直接求导会得到 Σ ∇π · R，它不是一个期望，不能用采样估计；用了这个技巧，它变回 E_π[R · ∇log π]，可以用采样估计。
2. E[b · ∇log π] = b · Σ ∇π = b · ∇Σ π = b · ∇1 = 0。基线不能依赖于这个样本自己的 y（否则提不出来，证明不成立），但可以依赖于输入 x（比如每道题有自己的基线），也可以依赖于其他样本（留一）。
3. 优势全是 0，这道题对梯度没有贡献：它对模型来说太简单了。
4. 不同题目的难度不同。整批一起算时，简单题的回答几乎都高于平均、被推高，难题的几乎都低于平均、被压低，优势反映的是"题目的难度"而不是"这个回答在这道题上好不好"。
5. 把 k3 放进损失、对它求导（采样的分布不求导），期望的梯度是 E_π[(1 − π_ref/π)∇log π] = −E_{π_ref}[∇log π]，这是 KL(π_ref‖π) 的梯度，不是 KL(π‖π_ref) 的梯度。数值估计的无偏性和梯度的正确性是两回事。
6. 没有作用。更新前 θ = θ_old，ρ 恒为 1，在 [1 − ε, 1 + ε] 之内，裁剪不改变任何东西。
7. ρ = 1.5：不会，目标 min(1.5A, 1.2A) = 1.5A（A < 0 时 1.5A 更小），梯度照常，坏回答被继续压低。ρ = 0.5：会，min(0.5A, 0.8A) = 0.8A 是常数，梯度为 0，已经压低得够多了。
8. 例如：奖励是 1 − NED，但 NED 的实现在预测为空时除以 0 出错、被 try/except 当成 0.5。模型学会读不出来就输出空。修补：空输出明确给 0 分；或者用 max(0, 1 − 编辑距离 / 真值长度)。（定位"包含就给 1"→ 用 IoU，也是一个好例子。）
9. (n − 1)/n = 3/4。loo 的优势 = n/(n − 1) × mean 的优势 = 4/3 倍。
10. 均值 0.25；偏差 [−0.25, −0.25, −0.25, 0.75]；无偏标准差 √((3 × 0.0625 + 0.5625) / 3) = √0.25 = 0.5；优势 [−0.5, −0.5, −0.5, 1.5]。唯一对的那个回答的优势是其他的 3 倍。
11. log r = −1.5 − (−1.0) = −0.5。k1 = 0.5；k2 = 0.125；k3 = e^−0.5 − 1 + 0.5 = 0.6065 − 0.5 = 0.1065。
12. ρ = e^0.3 = 1.35 > 1.2，A > 0：目标 = min(1.35 × 2, 1.2 × 2) = 2.4；被裁剪，梯度 0。
13. 顺序不对：`group_advantages` 假定每连续 8 个是同一道题的 8 个回答。这里每连续 8 个是"同一个回答编号、8 道不同的题"，减的是不同题目的平均。要先把 rewards 排成"题目 × 回答"的顺序（或者用 `view(8, -1).T` 转过来）。
14. 两个问题：(1) KL 项用的是 k1（lp − ref_lp），放进损失时梯度期望为 0，不起作用；(2) KL 项对所有位置求平均，包括提示和补齐的位置，应该只在回答的 token 上（乘 mask 再除以 mask.sum()）。另外 ref_lp 要在 `no_grad` 下算。
