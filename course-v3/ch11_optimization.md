## 11.1 SGD 的问题与动量

### 狭长的山谷

先看一个二维的例子，`python -m labs.ch11.optim_tour 1`：

```
f(x, y) = 0.5·(x² + 25·y²)，从 (-9, 2) 出发
```

它的 Hessian 是 diag(1, 25)：y 方向的弯曲程度是 x 方向的 25 倍，条件数 25（第 7 章）。等高线是一个狭长的椭圆，像一条山谷。

```
  Hessian = diag(1, 25)，条件数 25；梯度下降的稳定上限 lr < 2/25 = 0.08（第 7 章）
  SGD lr=0.07      第 10 步 f =    9.6452  第 50 步 f =   0.02856  降到 1e-3 以下用了 74 步
  SGD lr=0.02      第 10 步 f =   27.0382  第 50 步 f =   5.37110  降到 1e-3 以下用了 >200 步
```

**手算验证**。梯度下降在每个方向上独立进行：x 方向每步乘以 (1 − lr·1)，y 方向每步乘以 (1 − lr·25)。

- lr = 0.07：y 方向乘以 |1 − 1.75| = 0.75，收敛很快；x 方向乘以 0.93，很慢。f 的大部分来自 x：f ≈ ½ · 81 · 0.93^{2t}。令它小于 10⁻³：0.93^{2t} < 2.47 × 10⁻⁵，t > ln(2.47 × 10⁻⁵) / (2 ln 0.93) = −10.6 / −0.145 = 73.1，所以第 **74** 步。与实测完全一致。
- lr = 0.02：x 方向每步乘以 0.98，需要 t > 10.6 / (2 × 0.0202) ≈ 262 步。

**矛盾在于**：学习率受最陡的方向限制（必须 < 0.08，否则 y 方向发散），而收敛速度由最平的方向决定（x 方向每步只缩小 1 − lr）。条件数越大，这个矛盾越严重。真实神经网络的条件数可能是成千上万。

打开 `outputs/ch11/valley.png`，看 lr=0.07 的轨迹：在 y 方向（山谷两壁之间）来回跳，同时沿 x 方向（谷底）缓慢前进。

### 动量

想象一个球从山坡上滚下来。它不只是沿着当前的坡度走，还带着之前积累的速度。在山谷里，左右方向的坡度一会儿向左、一会儿向右，速度相互抵消；沿谷底方向的坡度一直指向同一边，速度越积越大。

**动量法**（momentum）就是这样：

```
v ← μ · v + g            （μ 是动量系数，通常 0.9）
p ← p − lr · v
```

v 是"速度"，是过去所有梯度的加权和：v_t = g_t + μ g_{t−1} + μ² g_{t−2} + …

**有效学习率**：如果梯度一直是常数 g，速度会趋向 v = g + μ v，即 v = g / (1 − μ)。μ = 0.9 时，速度是梯度的 10 倍，相当于学习率放大 10 倍。而在来回震荡的方向上，正负梯度相互抵消，速度不会累积。所以动量能**在平的方向上加速，在陡的方向上不放大**。

```
  动量 0.9 lr=0.02   第 10 步 f =    4.2048  第 50 步 f =   0.47068  降到 1e-3 以下用了 82 步
```

同样是 lr = 0.02，加了动量后从 >200 步变成 82 步。前 10 步的进展（f = 4.2）甚至比 lr = 0.07 的 SGD（9.6）还快。

### 练习 11.1：带动量的 SGD

```python
class SGD(Optimizer):
    def __init__(self, params, lr, momentum=0.0, weight_decay=0.0):
        super().__init__(params, lr)
        self.momentum, self.weight_decay = momentum, weight_decay
        self.state = {}

    @torch.no_grad()
    def step(self):
        for i, p in enumerate(self.params):
            if p.grad is None:
                continue
            g = p.grad
            if self.weight_decay:
                g = g + self.weight_decay * p
            if self.momentum:
                v = self.state.get(i)
                v = g.clone() if v is None else v.mul_(self.momentum).add_(g)
                self.state[i] = v
                g = v
            p.sub_(self.lr * g)
```

要点：

- `@torch.no_grad()` 装饰整个 `step`：参数更新不进入计算图（第 9 章）；
- 每个参数有自己的速度 v，形状与参数相同，存在 `self.state` 里。这就是第 9 章说的"优化器要为每个参数保存额外状态"。带动量的 SGD 要多存一份与模型同样大的张量；
- **第一步 v = g**（`g.clone()`，必须复制，否则 v 与梯度共享内存，下一次 `zero_grad` 或反向传播会改掉它）；
- `v.mul_(μ).add_(g)` 是原地操作，不分配新内存；
- 权重衰减（11.6 节）先加到梯度上。

测试 `test_sgd_matches_torch` 用三种配置各训练 6 步，检查每个参数都与 `torch.optim.SGD` 完全相同。

> PyTorch 的动量公式是 v ← μv + g，有的教材写成 v ← μv + (1 − μ)g。后者相当于把学习率乘了 (1 − μ)，本质相同，但同样的 lr 在两种写法下效果差 10 倍。阅读论文或别的框架的配置时要注意。

## 11.2 Adam：每个参数自己的学习率

### 思想

动量解决了"方向"的问题，但所有参数仍共用一个学习率。在神经网络里，不同参数的梯度大小可能差几个数量级：某些参数（比如很少出现的特征对应的权重）梯度很小，另一些很大。一个学习率很难兼顾。

**Adam**（adaptive moment estimation）给每个参数一个自适应的步长：梯度一直很大的参数，步长缩小；梯度一直很小的参数，步长放大。具体做法是用梯度的"典型大小"去除梯度：

```
m ← β₁ m + (1 − β₁) g            一阶矩：梯度的指数移动平均（≈ 动量）
v ← β₂ v + (1 − β₂) g²           二阶矩：梯度平方的指数移动平均（≈ 梯度大小的平方）
m̂ = m / (1 − β₁ᵗ)                偏差修正
v̂ = v / (1 − β₂ᵗ)
p ← p − lr · m̂ / (√v̂ + ε)
```

默认 β₁ = 0.9，β₂ = 0.999，ε = 10⁻⁸。

- **m** 和动量类似，是梯度的平滑版本，指向"平均来看该往哪走"；
- **√v** 是梯度的均方根（RMS），衡量这个参数的梯度"通常有多大"；
- **m̂ / √v̂** 的大小大约在 −1 到 1 之间：它衡量的是"梯度方向有多一致"，而不是"梯度有多大"。所以每个参数每步移动的距离大约是 lr，与梯度的绝对大小无关。

### 偏差修正：手算第一步

m 和 v 初始为 0。第一步之后：

```
m₁ = 0.9 × 0 + 0.1 × g = 0.1 g
v₁ = 0.999 × 0 + 0.001 × g² = 0.001 g²
```

如果不修正，m₁/√v₁ = 0.1g / (0.0316|g|) = 3.16 · sign(g)，步长被放大了 3 倍多。原因是 m 和 v 从 0 开始，前几步严重偏小（偏向 0），而 v 偏小得更厉害。修正后：

```
m̂₁ = 0.1g / (1 − 0.9) = g
v̂₁ = 0.001g² / (1 − 0.999) = g²
更新量 = lr · g / (|g| + ε) ≈ lr · sign(g)
```

**第一步每个参数都移动 lr，方向是梯度的符号，与梯度大小无关。** 演示验证了这一点：

```
  Adam 第一步：梯度 [0.001, 1.0, 1000.0] → 更新量 [0.099999, 0.1, 0.1]（≈ lr·符号，与梯度大小无关）
```

梯度相差一百万倍，步长都是 0.1（0.001 那个略小一点点，是 ε 的影响：0.001 / (0.001 + 10⁻⁸)）。测试 `test_adam_first_step_is_lr_times_sign` 检查的就是这件事。

随着 t 增大，1 − β₁ᵗ 和 1 − β₂ᵗ 都趋向 1，修正逐渐消失。β₂ = 0.999 时，1 − β₂ᵗ 要到 t ≈ 3000 才接近 0.95，所以 v 的修正会持续较长时间。

### 在山谷里

```
  Adam lr=0.5      第 10 步 f =   17.6632  第 50 步 f =   0.05602  降到 1e-3 以下用了 76 步
```

Adam 不受 2/λ_max 的限制：y 方向梯度大，被 √v 除掉了；x 方向梯度小，也被 √v 除掉了。两个方向的步长都约为 lr。这正是"预条件"（preconditioning）的思想：把狭长的椭圆变得更"圆"。在这个简单的例子里 Adam 没有比动量法快，但它不需要根据 Hessian 精心挑选学习率。

### 练习 11.2：Adam 与 AdamW

```python
class Adam(Optimizer):
    def __init__(self, params, lr=1e-3, betas=(0.9, 0.999), eps=1e-8, weight_decay=0.0, decoupled=False):
        ...

    @torch.no_grad()
    def step(self):
        for i, p in enumerate(self.params):
            if p.grad is None:
                continue
            g = p.grad
            if self.weight_decay:
                if self.decoupled:
                    p.mul_(1 - self.lr * self.weight_decay)
                else:
                    g = g + self.weight_decay * p
            t, m, v = self.state.get(i, (0, torch.zeros_like(p), torch.zeros_like(p)))
            t += 1
            m.mul_(self.b1).add_((1 - self.b1) * g)
            v.mul_(self.b2).add_((1 - self.b2) * g * g)
            self.state[i] = (t, m, v)
            m_hat = m / (1 - self.b1 ** t)
            v_hat = v / (1 - self.b2 ** t)
            p.sub_(self.lr * m_hat / (v_hat.sqrt() + self.eps))
```

- 每个参数存 t、m、v。**Adam 要为每个参数多存两份同样大小的张量**：一个 1 亿参数的模型，参数本身 400 MB（float32），m 和 v 再各 400 MB。第 28 章算显存账时，这是大头之一；
- `decoupled` 决定权重衰减的方式，11.6 节详细讲。`AdamW(...)` 就是 `Adam(..., decoupled=True)`，默认 weight_decay = 0.01。

测试 `test_adam_and_adamw_match_torch` 对三种配置（Adam、带 L2 的 Adam、AdamW）逐步对拍。

## 11.3 怎么选优化器

| 优化器 | 状态（每个参数） | 典型学习率 | 用在哪里 |
|---|---|---|---|
| SGD | 0 | 0.01–0.1 | 很少单独用 |
| SGD + 动量 | 1 份 | 0.01–0.1 | 图像分类的 CNN（ResNet 的经典配方），通常泛化略好 |
| Adam | 2 份 | 10⁻⁴–10⁻³ | 大多数场合，尤其是 Transformer |
| AdamW | 2 份 | 10⁻⁴–10⁻³（预训练）、10⁻⁵–10⁻⁴（微调） | **大模型训练与微调的默认选择** |

微调预训练模型（第 35 章）时学习率要小得多：模型已经学好了，大步长会破坏已有的知识。

> 还有一些较新的优化器（Lion、Adafactor、Muon 等），有的为了省显存（Adafactor 不存完整的 v），有的为了更快收敛。它们的思想都可以看作在动量和"按梯度大小缩放"这两个维度上的变化。掌握了 SGD 和 Adam，读懂它们的论文并不难。

## 11.4 学习率调度

### 为什么要变

固定的学习率面临两难：大了，后期在最优点附近来回跳，停不下来；小了，前期进展太慢。自然的想法是**先大后小**。

第 3 部分用 Adam 训练 2000 步（约 20 轮），峰值学习率 3×10⁻³，比较四种调度：

```
  恒定                     最后 100 步平均训练损失 0.0687  训练准确率  98.4%  验证损失 0.1574  验证准确率  94.8%
  阶梯（1000、1500 步各 ×0.1）  最后 100 步平均训练损失 0.0369  训练准确率  99.3%  验证损失 0.1157  验证准确率  95.8%
  余弦                     最后 100 步平均训练损失 0.0251  训练准确率  99.8%  验证损失 0.1127  验证准确率  96.0%
  预热 100 + 余弦            最后 100 步平均训练损失 0.0231  训练准确率  99.8%  验证损失 0.1106  验证准确率  96.0%
```

（打开 `outputs/ch11/schedules.png` 看四条学习率曲线。）

衰减的三种都明显好于恒定：训练损失低了一半以上，验证损失从 0.157 降到 0.11 左右，验证准确率高 1 个多百分点。注意它们都比第 2 部分的 15 轮 Adam（92.4%）高，原因有二：训练更久（20 轮），以及最后阶段学习率很小、参数"停稳"了。

### 学习率小了为什么就"停稳"了

小批量 SGD 的梯度是有噪声的（每批只有 64 个样本）。可以把每步的梯度写成 g = ∇L + 噪声。在最优点附近 ∇L ≈ 0，只剩噪声，参数会以大约 lr × 噪声大小的幅度随机游走。学习率越小，游走的范围越小，参数越接近最优点。这就是衰减的作用。

### 余弦调度

```
lr(t) = min_lr + (base_lr − min_lr) · ½ · (1 + cos(π · t / T))
```

t = 0 时 cos 0 = 1，lr = base_lr；t = T 时 cos π = −1，lr = min_lr；中间平滑过渡。开始和结束时下降得慢，中间下降得快。它没有阶梯调度的"在哪一步降"这种需要调的超参数，只需要知道总步数 T。

### 预热

**预热**（warmup）是在开始的若干步里，让学习率从接近 0 线性增加到 base_lr。为什么要这样？

1. **刚初始化的模型，梯度可能很大且方向混乱**，大步长会把参数推到不好的区域；
2. **Adam 的 v 在前几步还不可靠**：偏差修正让第一步的步长等于 lr，与梯度大小无关，所以哪怕梯度很小、方向很随意，参数也会被推出整整 lr 那么远。

```
  预热的作用（学习率较大时更明显）：峰值 lr = 1e-2
    预热   0 步：前 20 步的最大损失     7.76  最大梯度范数    11.44   第 300 步验证准确率  86.1%
    预热 100 步：前 20 步的最大损失     4.15  最大梯度范数     3.24   第 300 步验证准确率  84.8%
```

没有预热时，前 20 步损失冲到 7.76（比初始的 4.13 高得多，模型被"打乱"了），梯度范数达到 11.44；有预热时，损失一直不超过初始值。

但第 300 步的准确率，有预热反而略低（84.8% 对 86.1%），因为预热的前 100 步学习率较小，进展慢一些。**在这个小网络上，没有预热也能从混乱中恢复**。在大型 Transformer 上（尤其是后归一化的结构，第 16 章），没有预热，训练常常直接发散。所以预热是大模型训练的标配，通常占总步数的 1%–5%。

### 练习 11.3：预热 + 余弦

```python
def warmup_cosine(step, total_steps, warmup_steps, base_lr, min_lr=0.0):
    if step < warmup_steps:
        return base_lr * (step + 1) / warmup_steps
    progress = (step - warmup_steps) / max(1, total_steps - warmup_steps)
    return min_lr + (base_lr - min_lr) * 0.5 * (1 + math.cos(math.pi * min(1.0, progress)))
```

- 预热阶段用 `step + 1`，这样第 0 步的学习率不是 0（学习率为 0 的一步是浪费的）；第 warmup−1 步恰好到 base_lr；
- `max(1, ...)` 防止 total == warmup 时除以 0；`min(1.0, progress)` 让超过总步数后保持 min_lr。

手算检查（测试 `test_warmup_cosine` 的内容）：total = 100，warmup = 10，base = 1，min = 0.1。

- 第 0 步：1 × 1/10 = 0.1；第 9 步：1 × 10/10 = 1.0；
- 第 55 步：progress = 45/90 = 0.5，cos(π/2) = 0，lr = 0.1 + 0.9 × 0.5 = 0.55；
- 第 100 步：progress = 1，lr = 0.1。

使用时，每一步更新前设置 `opt.lr = warmup_cosine(step, ...)`。PyTorch 里对应 `torch.optim.lr_scheduler.LambdaLR` 或 Hugging Face 的 `get_cosine_schedule_with_warmup`。

### 推导：方差怎样传递

一个线性层的第 j 个输出是 z_j = Σᵢ w_{ji} h_i（先忽略偏置）。假设权重 w 和输入 h 相互独立、均值为 0，权重的方差为 σ_w²。由第 6 章"独立变量之和的方差等于方差之和"：

```
Var(z) = Σᵢ Var(w_{ji} h_i) = n · σ_w² · E[h²]
```

其中 n 是输入维数（fan-in）。

**线性或 tanh（在 0 附近近似线性）**：h 的均值约为 0，E[h²] = Var(h)，所以 Var(z) = n σ_w² Var(h)。要让方差逐层不变，需要 n σ_w² = 1，即

```
σ_w² = 1/n            （Xavier / Glorot 初始化）
```

**ReLU**：h = max(0, z)，z 关于 0 对称时，一半被置零，E[h²] = ½ Var(z_{上一层})。所以 Var(z) = n σ_w² · ½ · Var(z_{上一层})，要求 n σ_w² / 2 = 1：

```
σ_w² = 2/n            （Kaiming / He 初始化）
```

**用实测数据检验**（看第 1 层到第 2 层的比值，ReLU 网络，n = 256）：

| 初始化 | σ_w² | 每层方差乘以 n σ_w² / 2 | 标准差比值（预测） | 实测（第 2 层 / 第 1 层） |
|---|---|---|---|---|
| Xavier | 1/n | 0.5 | √0.5 = 0.71 | 0.402 / 0.559 = 0.72 |
| Kaiming | 2/n | 1 | 1.0 | 0.804 / 0.790 = 1.02 |
| large | 9/n | 4.5 | √4.5 = 2.12 | 3.62 / 1.68 = 2.15 |
| PyTorch 默认 | 1/(3n) | 1/6 | √(1/6) = 0.41 | 0.141 / 0.341 = 0.41 |

推导与实测吻合得很好。

最后一行需要解释：PyTorch 的 `nn.Linear` 默认用 U(−1/√n, 1/√n) 初始化权重（第 9 章 `MyLinear` 也是这样）。区间 [−a, a] 上均匀分布的方差是 a²/3，所以 σ_w² = 1/(3n)，比 Kaiming 小 6 倍。对浅网络无所谓，对 10 层的 ReLU 网络，信号每层缩小到 0.41 倍。（为什么"relu default"第 6 层以后停在 0.022 不再减小？因为偏置也是 U(−1/√n, 1/√n)，标准差约 0.036，当信号小到和偏置差不多时，输出主要由偏置决定。）

**tanh 的特殊之处**：tanh 把输出限制在 (−1, 1)，所以"large"初始化不会爆炸，而是让大部分神经元**饱和**（输出接近 ±1，标准差稳定在 0.84）。饱和区的导数接近 0，梯度同样传不过去。

### 归一化层

初始化只保证**开始时**各层信号的大小合适。训练中权重在变，各层的分布也在变。**归一化层**在每层强制把信号拉回均值 0、方差 1，从结构上解决这个问题。

**BatchNorm**（批归一化）：对每个特征，用**这一批样本**的均值和方差归一化。

```
输入 x：(B, d)
对每个特征 j：μ_j = (1/B) Σ_b x_{bj}，σ_j² = (1/B) Σ_b (x_{bj} − μ_j)²
x̂_{bj} = (x_{bj} − μ_j) / √(σ_j² + ε)
y_{bj} = γ_j · x̂_{bj} + β_j
```

**LayerNorm**（层归一化）：对每个样本，用**它自己所有特征**的均值和方差归一化。

```
对每个样本 b：μ_b = (1/d) Σ_j x_{bj}，σ_b² = (1/d) Σ_j (x_{bj} − μ_b)²
x̂_{bj} = (x_{bj} − μ_b) / √(σ_b² + ε)
y_{bj} = γ_j · x̂_{bj} + β_j
```

区别只在于**沿哪个方向求统计量**：

```
         特征 →
样本  [ x x x x ]   BatchNorm：沿着列（同一特征、不同样本）
 ↓    [ x x x x ]   LayerNorm：沿着行（同一样本、不同特征）
      [ x x x x ]
```

γ 和 β 是可学习的参数（初始为 1 和 0）。为什么归一化之后还要乘 γ、加 β？因为强制均值 0、方差 1 可能限制了表达能力（比如 ReLU 之前的值，模型也许希望它大部分为正）。有了 γ、β，模型可以自己决定最合适的尺度和偏移，必要时甚至可以学回原来的分布。

### 练习 11.5 和 11.6：LayerNorm 与 BatchNorm

```python
class MyLayerNorm(nn.Module):
    def __init__(self, d, eps=1e-5):
        super().__init__()
        self.eps = eps
        self.weight = nn.Parameter(torch.ones(d))
        self.bias = nn.Parameter(torch.zeros(d))

    def forward(self, x):
        mu = x.mean(-1, keepdim=True)
        var = ((x - mu) ** 2).mean(-1, keepdim=True)
        return (x - mu) / torch.sqrt(var + self.eps) * self.weight + self.bias
```

`keepdim=True` 让 mu 的形状是 (..., 1)，可以和 (..., d) 广播（第 1 章）。方差除以 d 而不是 d − 1（有偏估计），与 PyTorch 一致。

```python
class MyBatchNorm1d(nn.Module):
    def __init__(self, d, momentum=0.1, eps=1e-5):
        super().__init__()
        self.momentum, self.eps = momentum, eps
        self.weight = nn.Parameter(torch.ones(d))
        self.bias = nn.Parameter(torch.zeros(d))
        self.register_buffer("running_mean", torch.zeros(d))
        self.register_buffer("running_var", torch.ones(d))

    def forward(self, x):
        if self.training:
            mu = x.mean(0)
            var = x.var(0, unbiased=False)
            with torch.no_grad():
                n = x.shape[0]
                self.running_mean.mul_(1 - self.momentum).add_(self.momentum * mu)
                self.running_var.mul_(1 - self.momentum).add_(self.momentum * var * n / max(1, n - 1))
        else:
            mu, var = self.running_mean, self.running_var
        return (x - mu) / torch.sqrt(var + self.eps) * self.weight + self.bias
```

BatchNorm 有一个 LayerNorm 没有的问题：**评测时怎么办？** 评测时可能只有一张图，没法算"这一批"的统计量；而且我们希望一张图的预测结果不取决于和它一起送进来的其他图。解决办法：训练时顺便维护均值和方差的**滑动平均**（`running_mean`、`running_var`），评测时用它们代替批统计量。

- `self.training` 由 `model.train()` / `model.eval()` 设置。**这就是第 10 章 `evaluate` 里必须调用 `model.eval()` 的原因**；
- `register_buffer` 登记"缓冲区"：随 `state_dict` 保存、随 `.to(device)` 搬移，但不是参数，不会被优化器更新（第 9 章提到过）。测试检查了 `state_dict` 里有 4 项、`parameters()` 只有 2 项；
- 滑动平均的更新不需要梯度，放在 `torch.no_grad()` 里；
- 一个细节：归一化用有偏方差（除以 B），滑动平均里存的是无偏方差（除以 B − 1）。这是 PyTorch 的约定，测试 `test_batchnorm_matches_torch_train_and_eval` 对拍时会检查到它。

### BatchNorm 在训练和评测时的区别

```
    评测模式（用滑动平均）  256 张一起：准确率 93.0%；逐张单独送入与一起送入的预测一致率 100%
    训练模式（用这一批的统计）256 张一起：准确率 94.1%；只送 4 张：25%
```

- 评测模式下，每张图单独送入和一起送入，预测完全一致；
- 训练模式下，一批 256 张时统计量估计得准，结果正常；只送 4 张时，4 个样本的均值、方差和整体相差很大，准确率只有 25%。

**BatchNorm 的局限**：(a) 批太小时统计量不准（目标检测、大模型训练每张卡的批常常只有 1–4 张）；(b) 训练和评测行为不同，容易出错；(c) 不适合变长序列（不同样本的序列长度不同，"同一特征"的含义不清楚）。LayerNorm 对每个样本独立计算，没有这些问题。所以 **CNN 多用 BatchNorm，Transformer 和所有大语言模型都用 LayerNorm**（或它的简化版 RMSNorm：不减均值，只除以均方根，第 16 章）。

## 11.6 正则化：Dropout 与权重衰减

### Dropout

训练时，以概率 p 把每个神经元的输出置为 0，剩下的乘以 1/(1 − p)：

```
训练：  h' = h · mask / (1 − p)，mask 的每个元素以概率 1 − p 为 1
评测：  h' = h
```

**为什么要除以 1 − p**？保证期望不变：E[h'] = h · (1 − p) / (1 − p) = h。这样评测时不需要任何修正（这种写法叫 inverted dropout，PyTorch 的 `nn.Dropout` 就是这样）。

**为什么能减轻过拟合**？每次训练时随机关掉一半神经元，网络不能依赖任何一个特定的神经元（也不能依赖几个神经元之间精确的配合），被迫学到更冗余、更稳健的特征。也可以把它看成同时训练了指数多个共享参数的子网络，评测时取它们的平均。

### 权重衰减与 L2 正则

**L2 正则**在损失里加一项 ½ λ |w|²，惩罚大的权重。它的梯度是 λ w，所以梯度下降的更新变成

```
w ← w − lr · (g + λ w) = (1 − lr·λ) w − lr · g
```

每步先把权重缩小一点（乘以 1 − lr·λ），再沿梯度更新。所以 L2 正则也叫**权重衰减**（weight decay）。大的权重让模型对输入的小变化反应剧烈，输出更"自信"；限制权重大小，模型就更平滑、更不容易过拟合。

**对 SGD，"加 L2 正则"和"权重衰减"是同一件事。对 Adam 则不是**：

- **Adam + L2**（`decoupled=False`）：λw 加到梯度上，然后和梯度一起被 √v 除。梯度大的参数，√v 大，衰减项被除得很小；梯度小的参数，衰减反而被放大。衰减的力度变得不可控；
- **AdamW**（`decoupled=True`）：衰减直接作用在参数上（`p.mul_(1 − lr·wd)`），不经过 m 和 v。每个参数都按同样的比例衰减，与梯度大小无关。

Loshchilov 和 Hutter 在 2017 年指出了这个区别，AdamW 从此成为标准做法。注意两者的 weight_decay 数值**不可比**：Adam + L2 的 1e-3 和 AdamW 的 1e-3 力度完全不同。

## 11.7 梯度裁剪

### 问题：偶尔的巨大梯度

训练中偶尔会遇到一批数据让梯度变得非常大（损失地形上的"悬崖"）。一次巨大的更新就可能把参数推到很远的地方，甚至让后续计算溢出成 nan。

**梯度裁剪**：把所有参数的梯度拼成一个长向量，如果它的长度（L2 范数）超过阈值 max_norm，就把整个向量等比缩短到 max_norm。

```
total = √(Σ_所有参数 Σ g²)
若 total > max_norm：每个 g ← g · max_norm / total
```

注意是**整体**缩放，所有参数的梯度乘以同一个系数，所以梯度的**方向不变**，只是步子变小。

### 练习 11.4

```python
@torch.no_grad()
def clip_grad_norm(params, max_norm):
    grads = [p.grad for p in params if p.grad is not None]
    total = torch.sqrt(sum((g.double() ** 2).sum() for g in grads)).item()
    if total > max_norm:
        for g in grads:
            g.mul_(max_norm / (total + 1e-6))
    return total
```

- 用 float64 求平方和，避免几百万个数相加时的精度问题；
- 返回裁剪前的范数，训练时记录它是很好的健康指标：梯度范数突然飙升，往往预示着训练即将出问题；
- 调用位置：`loss.backward()` 之后、`opt.step()` 之前（第 10 章 `train_one_epoch` 里已经留好了）。

### 实验

第 7 部分：6 层 MLP，SGD lr = 0.3 + 动量 0.9（故意设得太大）：

```
  裁剪 None 梯度范数 中位数     0.95 最大 917935759607.62  损失出现 nan/inf 的步数 196  最后 50 步平均损失 nan  验证准确率   1.6%
  裁剪 5.0  梯度范数 中位数     1.03 最大      57.53  损失出现 nan/inf 的步数   0  最后 50 步平均损失 4.111  验证准确率   5.1%
  裁剪 1.0  梯度范数 中位数     1.68 最大       8.42  损失出现 nan/inf 的步数   0  最后 50 步平均损失 1.949  验证准确率  32.9%
```

- **不裁剪**：梯度范数的中位数只有 0.95，但某一步飙到 10¹²，之后 196 步都是 nan，训练彻底失败；
- **裁剪到 5.0**：避免了 nan，但学习率实在太大，模型没学到东西；
- **裁剪到 1.0**：能训练（32.9%，虽然远不如正常学习率）。注意它的梯度范数中位数（1.68）大于 1，说明**大部分步都被裁剪了**，此时裁剪相当于把学习率按比例调小。

梯度裁剪是"安全带"：它不能代替合适的学习率，但能防止偶尔的一次坏更新毁掉整个训练。大模型训练几乎都设 `max_grad_norm = 1.0`。

## 11.8 数值精度

### 三种浮点格式

浮点数由三部分组成：符号位、指数位（决定能表示多大、多小的数）、尾数位（决定精度，即有效数字的位数）。

| 格式 | 总位数 | 符号 | 指数 | 尾数 | 最大值 | 最小正规数 | eps（1 附近的间距） |
|---|---|---|---|---|---|---|---|
| float32 | 32 | 1 | 8 | 23 | 3.4 × 10³⁸ | 1.2 × 10⁻³⁸ | 1.2 × 10⁻⁷ |
| float16 | 16 | 1 | 5 | 10 | 65504 | 6.1 × 10⁻⁵ | 9.8 × 10⁻⁴ |
| bfloat16 | 16 | 1 | 8 | 7 | 3.4 × 10³⁸ | 1.2 × 10⁻³⁸ | 7.8 × 10⁻³ |

第 8 部分：

```
  torch.float32   ... 1 + 1e-3 = 1.001000  70000 → 70000.0  1e-8 → 1.000e-08
  torch.float16   ... 1 + 1e-3 = 1.000977  70000 → inf      1e-8 → 0.000e+00
  torch.bfloat16  ... 1 + 1e-3 = 1.000000  70000 → 70144.0  1e-8 → 1.001e-08
```

- **float16**：尾数 10 位，精度还行（1 + 10⁻³ 存成 1.000977，最近的可表示数）；但指数只有 5 位，**范围很小**：70000 超过最大值 65504 变成 inf，10⁻⁸ 太小变成 0；
- **bfloat16**（brain float，Google 提出）：指数和 float32 一样是 8 位，**范围与 float32 相同**，70000 和 10⁻⁸ 都能表示；但尾数只有 7 位，**精度很低**：1 + 10⁻³ 直接变成 1（eps 是 2⁻⁷ = 0.0078，10⁻³ 不到间距的一半）；70000 存成 70144（这个范围内相邻两个数相差 2¹⁶/2⁷ = 512，70000/512 = 136.7，最近的是 137 × 512 = 70144）。

**为什么神经网络能用这么低的精度？** 神经网络本身对噪声很稳健（SGD 本身就充满噪声），权重差个千分之几对结果影响不大。但范围不够（溢出成 inf、下溢成 0）会直接导致训练失败。所以 bfloat16 用"精度换范围"，更适合训练。

### 低精度的两个陷阱

**陷阱一：累加时小数被"吞掉"**

```
  把 1e-4 累加 10000 次（应为 1.0）：float16 得 0.2500，float32 得 1.0001
```

为什么停在 0.25？float16 在 [0.25, 0.5) 区间里相邻两个数的间距是 0.25 × 2⁻¹⁰ = 2.44 × 10⁻⁴。加 10⁻⁴ 不到间距的一半，结果四舍五入回 0.25，加多少次都不变。训练中，参数更新量（lr × 梯度，常常是 10⁻⁵ 量级）相对于参数本身（10⁻¹ 量级）就是这种情况。**所以优化器里的参数和状态（m、v）要用 float32 保存**，这叫"主权重"（master weights）。

**陷阱二：小梯度下溢**

```
  梯度 [3e-08, 1e-06, 0.001] 转成 float16：[5.96e-08, 1.01e-06, 0.0010004]
  先乘 1024（loss scaling）再转 float16、再除回：[2.998e-08, 1.0002e-06, 0.0010004]
```

3 × 10⁻⁸ 已经低于 float16 的最小正规数，只能用精度很差的"次正规数"表示，变成了 5.96 × 10⁻⁸（这是 float16 能表示的最小正数 2⁻²⁴，误差 100%）；更小的梯度会直接变成 0。**loss scaling** 的办法是：反向传播前把损失乘以一个大数 S（比如 1024），由链式法则所有梯度都放大 S 倍，就不会下溢了；更新参数前再除以 S。

S 取多大？太大会让大梯度溢出成 inf。PyTorch 的 `GradScaler` 动态调整：从 65536 开始，如果某步出现 inf，就跳过这一步并把 S 减半；连续若干步正常，就把 S 加倍。

**bfloat16 的范围和 float32 一样，不需要 loss scaling。** 这是现代 GPU 上 bfloat16 成为大模型训练首选的主要原因。

### 混合精度训练

**混合精度**（mixed precision）：前向和反向的矩阵乘法用 16 位（快、省显存），参数、优化器状态和一些对精度敏感的运算（softmax、LayerNorm、损失）用 32 位。PyTorch 用 `torch.autocast` 自动完成这种切换：

```python
scaler = torch.amp.GradScaler("cuda", enabled=(mode == "fp16"))   # 只有 fp16 需要
with torch.autocast("cuda", dtype=torch.bfloat16):                # 或 torch.float16
    loss = F.cross_entropy(model(xb), yb)
opt.zero_grad()
scaler.scale(loss).backward()        # loss × S（未启用时什么都不做）
scaler.step(opt)                     # 梯度 ÷ S；若有 inf 则跳过这一步
scaler.update()                      # 调整 S
```

（下面这段需要 NVIDIA GPU；没有 CUDA 时脚本打印"跳过混合精度训练的速度对比"。）

```
  混合精度训练（autocast），MLP [1024, 1024, 1024, 62]，批大小 256，200 步：
    fp32：0.58 ms/步  最后一步损失 0.1721  验证准确率 91.0%
    bf16：0.69 ms/步  最后一步损失 0.1846  验证准确率 90.9%
    fp16：0.85 ms/步  最后一步损失 0.1760  验证准确率 90.9%  最终 loss scale 65536
```

三种精度的准确率几乎相同。速度上，**这个小模型用混合精度反而没有更快**：每步只有零点几毫秒，主要花在启动 GPU 运算和类型转换上，而不是矩阵乘法本身（第 9 章：运算太小时 GPU 的优势发挥不出来）。这几个毫秒数在每次运行之间也有不小的波动。（又因为 GPU 被另一个服务占用了大部分显存，本节只能用小模型演示。）对于大模型，矩阵乘法占绝大部分时间，bf16 通常能快 2 倍左右，激活值的显存也减半。fp16 的 loss scale 一直保持在初始的 65536，说明这 200 步里没有溢出。

### 显存账（预告）

用 AdamW 和混合精度训练一个有 N 个参数的模型，每个参数大约要：

| 项目 | 字节 |
|---|---|
| float32 主权重 | 4 |
| float32 梯度 | 4 |
| Adam 的 m、v（float32） | 8 |
| 合计 | **16** |

一个 25 亿参数的模型，光这些就要 40 GB，还没算激活值。这就是为什么在一张消费级显卡上无法全量微调几十亿参数的模型，第 28 章的 LoRA（只训练很少的参数）和量化就是为此而生的。

## 11.11 真实世界对照

- **大模型训练配方**：几乎所有开源的大语言模型和 VLM 都用 AdamW（β₁ = 0.9，β₂ = 0.95 或 0.999）、预热 + 余弦（或线性）衰减、梯度裁剪 1.0、bf16 混合精度、权重衰减 0.1。β₂ 取 0.95 比默认的 0.999 更"健忘"，对梯度大小的变化反应更快，在大模型训练中更稳定；
- **SmolVLM / Qwen 的微调**：常见的微调配置里会看到 `learning_rate: 1e-4`（LoRA）或 `1e-5`（全量）、`warmup_ratio: 0.03`、`lr_scheduler_type: cosine`、`bf16: true`、`max_grad_norm: 1.0`；第 35 章自己写的循环用的也是 LoRA 学习率 1e-4、线性预热 5% 加余弦衰减、梯度裁剪 1.0。每一项本章都讲过；
- **归一化**：Qwen、Llama 系列用 RMSNorm 和"前置归一化"（pre-norm：先归一化再进子层，残差路径上不做归一化），这是 11.5 节"LayerNorm + 残差"的改良版，第 16 章详细讲；视觉编码器（ViT）用 LayerNorm；传统的 CNN（ResNet）用 BatchNorm；
- **初始化**：大模型通常用标准差 0.02 的正态分布初始化，并对残差分支的输出层再按层数缩小（比如乘以 1/√(2L)），防止 L 个残差分支加起来使输出过大——这正是 11.5 节"LN + 残差"第 100 步损失偏高的原因；
- **训练不稳定**：大模型训练中偶尔会出现"损失尖峰"（loss spike）。常见的应对是：跳过那批数据、从之前的 checkpoint 恢复并降低学习率。梯度范数曲线是监控的重点。

## 11.12 深入一步

### 为什么动量能加速：一个二次函数上的分析

在 f(w) = ½ λ w² 上，动量法的更新可以写成一个二阶递推：

```
v_{t+1} = μ v_t + λ w_t
w_{t+1} = w_t − lr · v_{t+1}
```

消去 v 得到 w_{t+1} = (1 + μ − lr λ) w_t − μ w_{t−1}。这是一个线性递推，收敛速度由特征方程 r² − (1 + μ − lr λ) r + μ = 0 的根决定。可以证明，对条件数为 κ 的二次函数，选择最优的 lr 和 μ 时，动量法每步的收缩因子约为 (√κ − 1)/(√κ + 1)，而普通梯度下降约为 (κ − 1)/(κ + 1)。κ = 25 时，前者是 4/6 = 0.67，后者是 24/26 = 0.92。达到同样精度所需的步数，与 √κ 成正比而不是与 κ 成正比。这就是动量法的理论优势。

### Adam 是一种对角预条件

二阶优化（牛顿法）用 Hessian 的逆乘以梯度：w ← w − H⁻¹ g，能一步把椭圆变成圆。但 Hessian 是 N×N 的矩阵，N 是参数个数（几十亿），根本存不下。Adam 只用对角线上的近似：用 √v（每个参数的梯度大小）代替对应的 Hessian 对角元。这在参数之间相关性不强时效果很好，代价只是每个参数多存一个数。

### BatchNorm 为什么有效，至今仍有争论

BatchNorm 最初的论文认为它减少了"内部协变量偏移"（每层输入的分布在训练中不断变化）。后来的研究表明，即使人为地加入分布偏移，BatchNorm 网络照样训练得好；它真正的作用更可能是**让损失地形更平滑**（梯度变化更平缓，所以能用更大的学习率）。另外，批内统计量引入的噪声也有轻微的正则化效果。深度学习里有不少这样"先发现有效，后来才慢慢理解"的技术。

| 初期不稳 | 前几步损失飙升 | 预热 | 11.4 |
| 深层信号消失/爆炸 | 损失卡在 ln K 或初始很大 | 合理初始化、归一化、残差 | 11.5 |
| 过拟合 | 训练好、验证差 | Dropout、权重衰减（作用有限）、更多数据 | 11.6 |
| 偶尔的巨大梯度 | 突然出现 nan | 梯度裁剪 | 11.7 |
| 显存/速度 | 显存不够、太慢 | 混合精度（bf16） | 11.8 |

## 11.14 本章小结

- 动量：v ← μv + g，在一致的方向上加速（有效学习率 lr/(1−μ)），在震荡的方向上相互抵消；
- Adam：m̂/√v̂，每个参数的步长约为 lr，与梯度大小无关；偏差修正让第一步就是 lr·sign(g)；
- AdamW：权重衰减直接作用在参数上，不被 √v 缩放；是大模型的默认优化器；
- 学习率：先预热、再衰减（余弦），后期小学习率让参数"停稳"；
- 初始化：Var(z) = n σ_w² E[h²]，所以 tanh 用 σ_w² = 1/n（Xavier），ReLU 用 2/n（Kaiming）；PyTorch 默认值对深层 ReLU 网络偏小；
- 归一化：BatchNorm 沿批，LayerNorm 沿特征；BatchNorm 训练和评测时行为不同；"归一化 + 残差"是训练深层网络的关键；
- Dropout 和权重衰减能减轻过拟合，但作用有限，比不上更多数据；
- 梯度裁剪防止偶尔的巨大梯度毁掉训练；
- bf16 与 float32 范围相同、精度低，不需要 loss scaling；fp16 范围小，需要 loss scaling；参数和优化器状态始终用 float32。

## 参考答案

1. 山谷两壁之间梯度方向来回变化（左、右、左……），累加进速度后相互抵消，不会越跳越大；沿谷底方向梯度一直指向同一边，速度越积越大，相当于在这个方向上用了更大的学习率。
2. 第一步 m₁ = (1−β₁)g，v₁ = (1−β₂)g²，修正后 m̂ = g，v̂ = g²，更新量 lr·g/(|g| + ε) ≈ lr·sign(g)。不修正时更新量是 lr·(1−β₁)g/√((1−β₂)g²) = lr·0.1/√0.001·sign(g) ≈ 3.16·lr·sign(g)。
3. Adam + L2 把 λw 加到梯度上，再被 √v 除，梯度大的参数衰减得少，梯度小的参数衰减得多，衰减力度不均匀、不可控。AdamW 把衰减直接作用在参数上（p ← p(1 − lr·λ)），不经过 m、v，每个参数按同样比例衰减。
4. BatchNorm 对每个特征沿批求统计量，LayerNorm 对每个样本沿特征求统计量。Transformer 处理变长序列、批常常很小，且希望每个样本的计算独立、训练和推理行为一致，LayerNorm 满足这些要求。
5. bf16：范围与 float32 相同（8 位指数），不会溢出/下溢，但精度低（7 位尾数）。fp16：精度稍高（10 位尾数），但范围小（最大 65504，最小正规数 6×10⁻⁵），梯度容易下溢。bf16 的范围足够表示很小的梯度，所以不需要放大损失。
6. 1/(1 − 0.95) = 20 倍。
7. Kaiming：√(2/1024) = 0.0442。默认：1/√(3 × 1024) = 0.0180（方差 a²/3，a = 1/32）。
8. 第 0 步：1e-3 × 1/100 = 1e-5；第 49 步：1e-3 × 50/100 = 5e-4；第 99 步：1e-3；第 550 步：progress = 450/900 = 0.5，lr = 0.5e-3 = 5e-4；第 1000 步：progress = 1，lr = 0。
9. 总范数 √(9 + 16 + 144) = √169 = 13。缩放系数 1/13，各部分范数变为 3/13 = 0.231、4/13 = 0.308、12/13 = 0.923（总范数 1）。
10. 5 × 10⁸ × 16 字节 = 8 × 10⁹ 字节 = 8 GB（还不包括激活值）。
11. `step` 在每轮开始时从 0 重新计数，所以每轮都会重新预热、重新从最大学习率开始衰减（而且永远到不了衰减的后半段）。应当用全局步数：`global_step = epoch * len(loader) + step`。
12. ```python
    def dropout(x, p, training):
        if not training or p == 0:
            return x
        mask = (torch.rand_like(x) >= p).float()
        return x * mask / (1 - p)
    ```
    训练时已经除以 1 − p，使输出的期望等于 x，所以评测时不需要任何缩放，直接返回 x。
13. `torch.no_grad()` 只是不记录计算图，不会改变 `model.training`。BatchNorm 仍处在训练模式：用这一批的统计量归一化，并更新滑动平均。应当先调用 `model.eval()`。
