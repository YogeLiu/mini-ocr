# 第 21 章　检测与版面分析

## 本章在全景图中的位置

到目前为止，我们的 OCR 都是在**已经裁好的**图上做的：第 10、12 章识别单个字符，第 13 章识别一行文字。真实的文档是一整页：标题、段落、公式、表格，单栏或双栏。要读一整页，有两条路：

1. **流水线**（pipeline）：先**检测**出每一行文字（或每一个区块）在哪里，按**阅读顺序**排好，再把每一行裁出来交给识别模型。PaddleOCR、Tesseract、很多商用 OCR 都是这个结构；
2. **端到端**：把整页图直接交给一个 VLM，让它按顺序写出全部文字（第 22 章起）。Xiaomi-OCR-0 和今天大多数"文档解析 VLM"走的是这条路。

本章把第一条路完整走一遍。即使最终用 VLM，检测和版面分析的知识也必不可少：

- VLM 的**定位**能力（"图里的红色方块在哪"、"这段文字的框是什么"）输出的就是框，评测用的就是本章的 IoU（第 23 章）；
- 文档解析的评测要比较区块、阅读顺序（第 33 章）；
- 训练 OCR VLM 的数据管线里，常常先用检测模型做版面切分、过滤和标注（第 34 章）；
- 流水线方法是端到端方法最重要的**对照组**：它快、可控，每一步的错误都看得见。

本章的内容：框的表示与 IoU、NMS、检测的评测指标 AP；一个最小的"中心点"检测器（CenterNet 的思路），在 MiniDoc 页面上同时检测文字行和版面区块；阅读顺序的 XY-cut 算法；最后把检测器接上第 13 章的 CRNN，做一个完整的整页 OCR，并把错误分解到每一步。

## 21.1 框

### 表示

一个轴对齐的矩形框有四个数，常见的写法有三种：

| 写法 | 含义 | 谁在用 |
|---|---|---|
| (x0, y0, x1, y1) | 左上角和右下角 | 本书、torchvision、COCO 的评测代码内部 |
| (x, y, w, h) | 左上角和宽高 | COCO 的标注文件 |
| (cx, cy, w, h) | 中心和宽高 | YOLO、CenterNet、DETR 的网络输出 |

坐标的单位也有讲究：**像素**（绝对坐标），或者除以图像宽高的**归一化坐标**（0–1）。VLM 输出框的时候用文字写出坐标，又多了一种：Qwen2-VL 把坐标归一化到 0–1000 的整数，Qwen2.5-VL 改成直接写原图的像素坐标（第 23 章会讨论这两种做法的利弊）。

本书的约定（第 2 章）：(x0, y0, x1, y1)，x1、y1 **不包含**，所以宽 = x1 − x0。读别人的代码和数据时，第一件事就是弄清它用哪种写法、包不包含右下角，这类错误不会报错，只会让指标莫名其妙地低。

### IoU

两个框重合得有多好？**交并比**（Intersection over Union）：

```
IoU(A, B) = 面积(A ∩ B) / 面积(A ∪ B) = 交集 / (面积 A + 面积 B − 交集)
```

交集也是一个矩形：左上角取两个框左上角的**较大**值，右下角取**较小**值；如果算出来宽或高是负的，说明不相交，交集为 0。

手算：A = (0, 0, 10, 10)，B = (5, 0, 15, 10)。交集 = (5, 0, 10, 10)，面积 5 × 10 = 50；并集 = 100 + 100 − 50 = 150；IoU = 1/3。

### 练习 21.1：`box_iou`

```python
def box_iou(a, b):
    area_a = (a[:, 2] - a[:, 0]) * (a[:, 3] - a[:, 1])
    area_b = (b[:, 2] - b[:, 0]) * (b[:, 3] - b[:, 1])
    lt = torch.maximum(a[:, None, :2], b[None, :, :2])              # (N, M, 2)
    rb = torch.minimum(a[:, None, 2:], b[None, :, 2:])
    wh = (rb - lt).clamp(min=0)
    inter = wh[..., 0] * wh[..., 1]
    return inter / (area_a[:, None] + area_b[None, :] - inter)
```

`a[:, None, :2]` 的形状是 (N, 1, 2)，`b[None, :, :2]` 是 (1, M, 2)，广播成 (N, M, 2)：一次算出所有 N × M 对的左上角（第 1 章的广播）。

### 细长的框很"娇气"

文字行是细长的：200 像素宽、16 像素高很常见。第 1 部分把这样一个框往下平移 k 个像素：

```
  一个 200×16 的文字行框，把它往下平移 k 个像素后与原框的 IoU：
    下移 1 像素：IoU = 0.882    （同样平移一个 100×100 的框：0.980）
    下移 2 像素：IoU = 0.778    （同样平移一个 100×100 的框：0.961）
    下移 4 像素：IoU = 0.600    （同样平移一个 100×100 的框：0.923）
    下移 8 像素：IoU = 0.333    （同样平移一个 100×100 的框：0.852）
```

平移 4 个像素（行高的 1/4），IoU 就从 1 掉到 0.6；同样平移一个 100×100 的框，IoU 还有 0.92。原因很直接：IoU 的变化取决于平移量相对于**框在平移方向上的边长**。文字行在竖直方向只有十几个像素，一点误差就是很大的比例。

后果：文字检测通常用 IoU ≥ 0.5 判断"检对了"，在更严格的 0.75 下，同一个检测器的分数会掉很多（21.8 节第 2 部分请你自己验证）。也有专门为文字设计的指标，比如按字符覆盖率而不是面积来算。

## 21.2 检测器的输出与 NMS

### 检测器输出什么

一个检测器对一张图输出一组**候选框**，每个框带一个类别和一个**分数**（置信度）。好的检测器对每个物体恰好输出一个高分框。但实际上，检测器往往在同一个物体附近输出好几个相近的框——相邻的格子、相邻的锚框都"觉得"自己看到了这个物体。

### 非极大值抑制

**NMS**（non-maximum suppression）去掉重复：

1. 按分数从高到低排序；
2. 取出分数最高的框，保留；
3. 删掉所有与它 IoU 超过阈值（常用 0.5）的框——它们被认为是同一个物体的重复检测；
4. 对剩下的框重复 2–3，直到没有框。

### 练习 21.2：`nms`

```python
def nms(boxes, scores, iou_thr=0.5):
    order = scores.argsort(descending=True)
    keep = []
    while len(order):
        i = order[0]
        keep.append(int(i))
        if len(order) == 1:
            break
        ious = box_iou(boxes[i][None], boxes[order[1:]])[0]
        order = order[1:][ious <= iou_thr]
    return torch.tensor(keep, dtype=torch.long)
```

最坏情况下是 O(n²) 次 IoU 计算，对几百个框不是问题。torchvision 提供了 `torchvision.ops.nms`，结果和这个一样，只是更快。

NMS 的阈值是个权衡：太低，挨得很近的两个真实物体（比如密集的文字行）会被误删一个；太高，重复的框删不干净。文字行上下相邻但几乎不重叠，所以文字检测里 NMS 的问题不大；人群、货架这类密集场景就麻烦得多。

## 21.3 怎样评测检测器

### 精确率与召回率

把一个预测框和真实框"配对"的规则：IoU ≥ 阈值，且这个真实框还没被别的（分数更高的）预测框配上。配上的叫 **TP**（真阳性），没配上的预测框叫 **FP**（假阳性：误检，或者对同一个物体的重复检测），没被任何预测配上的真实框叫 **FN**（漏检）。

```
精确率 precision = TP / (TP + FP)     预测出来的框里，有多少是对的
召回率 recall    = TP / (TP + FN)     真实的框里，有多少被找到了
```

两者此消彼长：把分数阈值调低，输出的框更多，召回率上升、精确率下降。只报告一个阈值下的数字，比较不出两个检测器的好坏。

### AP：精确率–召回率曲线下的面积

**AP**（average precision）把所有阈值都考虑进去：

1. 把所有图的所有预测框放在一起，按分数从高到低排序；
2. 依次处理，判断每个是 TP 还是 FP；
3. 处理到第 k 个时，算一次精确率和召回率，得到曲线上的一个点；
4. 把精确率改成"从这一点往后的最大值"（让曲线单调不增，消除锯齿）；
5. AP = 曲线下的面积 = Σ（召回率的增量 × 那一点的精确率）。

### 手算

两张图，共 3 个真实框；4 个预测（分数 0.9、0.8、0.7、0.6）：

| 预测 | 分数 | 判断 | 累计 TP | 精确率 | 召回率 |
|---|---|---|---|---|---|
| 图 0 的框 A | 0.9 | TP | 1 | 1/1 | 1/3 |
| 图 0 的框 A（重复） | 0.8 | FP（A 已经配过了） | 1 | 1/2 | 1/3 |
| 图 0 的空白处 | 0.7 | FP | 1 | 1/3 | 1/3 |
| 图 1 的框 C | 0.6 | TP | 2 | 2/4 | 2/3 |

单调化后的精确率（从后往前取最大）：1、1/2、1/2、1/2。召回率在第 1 个点增加 1/3（精确率 1），在第 4 个点增加 1/3（精确率 1/2），AP = 1/3 × 1 + 1/3 × 1/2 = 0.5。图 0 的第二个真实框始终没被找到，召回率最高只有 2/3，曲线下的面积因此少了一块。测试 `test_average_precision` 用的就是这个例子。

### 练习 21.3：`average_precision`

代码按上面的步骤实现，见 `miniocr/boxes.py`。几个细节：

- 匹配时要找"IoU 最大、且还没被匹配过"的真实框：把已匹配的真实框的 IoU 设成 −1；
- 重复检测算 FP。这正是 NMS 能提高 AP 的原因；
- 单调化用 `prec.flip(0).cummax(0).values.flip(0)`：翻转、求前缀最大值、再翻回来，就是"从这里往后的最大值"。

### mAP 与 COCO 指标

- **mAP**：对每个类别算 AP，再取平均；
- **AP@0.5**：IoU 阈值 0.5（PASCAL VOC 的传统）；**AP@0.75** 更严格；
- **COCO AP**（也写作 AP@[.5:.95]）：在 IoU = 0.50、0.55、……、0.95 这 10 个阈值上各算一次 AP 再平均，同时奖励"找得到"和"框得准"。

COCO 的官方实现还有一些细节（在召回率的 101 个等分点上取值、按物体大小分档等），数字和我们的实现略有差别，但思路完全相同。

## 21.4 检测器的家族

在动手之前，先了解一下检测器的主要设计（不必记住细节，知道它们各自在解决什么问题即可）：

| 家族 | 代表 | 思路 | 需要 NMS |
|---|---|---|---|
| 两阶段 | Faster R-CNN（2015） | 第一阶段在预设的**锚框**（不同大小、长宽比的模板框）上判断"有没有物体"，提出候选区域；第二阶段对每个候选区域裁出特征、精细分类和修正 | 是 |
| 单阶段 | YOLO、SSD、RetinaNet | 在特征图的每个位置、每个锚框上一次性预测类别和框的修正量。RetinaNet 提出了 **focal loss** | 是 |
| 无锚框 | FCOS、CenterNet（2019） | 不要锚框：每个位置直接预测"我是不是物体的中心"以及框的大小 | 是（CenterNet 用峰值提取代替了大部分 NMS） |
| 集合预测 | DETR（2020） | Transformer 输出固定数量（比如 100 个）的"查询"，每个查询预测一个框或"无物体"；训练时用匈牙利算法把预测和真实框一一配对 | 否 |

文字和文档领域的专用做法：

- **文字检测**：文字行细长、方向多变、可能弯曲。EAST 在每个像素上回归旋转框；**DBNet**（PaddleOCR 默认）做的是**分割**：预测每个像素"是不是文字"的概率图，用可微的二值化得到文字区域，再求轮廓。分割式方法天然能处理任意形状和弯曲文字；
- **版面检测**：把页面分成标题、段落、图、表、公式、页眉页脚等区块。常用通用检测器（YOLO 系列、DETR 系列）在版面数据集（PubLayNet、DocLayNet）上训练，比如 DocLayout-YOLO；
- **VLM 做检测**：直接让模型用文字输出框的坐标（第 23 章）。

本章实现 CenterNet 的简化版：结构简单、不需要锚框和匈牙利匹配，而且和第 23 章"在格子里定位"的思路相通。

## 21.5 一个中心点检测器

### 思路

在输入图下采样 4 倍的网格上，对每个类别预测一张**热图**：格子 (i, j) 的值是"这里有一个物体的中心"的概率。同时在每个格子上预测两组回归量：如果这里是中心，物体有多宽多高（**size**），以及中心在格子内的小数位置（**offset**，下采样丢掉的精度）。

推理时：在热图上找局部最大值（峰值），每个高于阈值的峰值就是一个物体，在那一格读出宽高和偏移，还原成框。

我们在 MiniDoc 页面上检测 4 类东西：文字行、标题区块、正文段落区块、公式区块。为了省计算，检测在半分辨率（192×288）上做，输出 48×72 的网格，每格对应原图 8×8 像素。

### 网络结构

```
输入 (1, 192, 288)
  stem：3×3 卷积，步长 2               → (16, 96, 144)      1/2
  编码器：4 级，每级池化 + 两个卷积块   → 1/4、1/8、1/16、1/32（宽 32、64、96、128）
  解码器：3 级，每级上采样 2 倍，与编码器同尺寸的特征拼接（跳跃连接），两个卷积块  → 1/16、1/8、1/4
  三个头（在 1/4 的特征上）：
    heat   (4, 48, 72)    每类一张热图（logits）
    size   (8, 48, 72)    每类一对 (log 宽, log 高)
    offset (2, 48, 72)    中心的小数偏移
```

为什么要编码到 1/32 再解码回来？一行文字可能 256 像素宽，模型要在行的**中心**估计出整行的宽度，中心那一格的感受野必须覆盖整行。1/32 那一级的感受野有两百多像素，解码器再把这种"全局"的信息和 1/4 那一级的"精确位置"拼起来。这种"先编码到很小、再解码回来、同尺寸的层之间用跳跃连接"的结构叫 **U-Net**（2015 年为医学图像分割提出，画出来像字母 U），在分割和密集预测任务里非常常见。

### 训练目标：高斯热图

最直接的目标是"中心那一格是 1，其余都是 0"。问题是：中心旁边的格子预测了 0.9，被当成和远处的背景一样的错误，这不合理——它离正确答案只差一格。

CenterNet 的做法是在中心周围画一个**高斯**"山丘"：

```
y(i, j) = exp(−( (j − cx)² / 2σx² + (i − cy)² / 2σy² ))
```

中心恰好是 1，越远越接近 0。σ 与物体的大小成正比（我们取宽、高各自的 1/6，再除以 stride；最小 0.5 格）。文字行很宽，所以横向的 σ 大，热图是一个横向拉长的椭圆。原始 CenterNet 用圆形的高斯（σ 由物体大小推算），对细长的文字行不太合适。

### 练习 21.5：`centernet_targets`

```python
for (x0, y0, x1, y1), k in zip(boxes.tolist(), labels.tolist()):
    bw, bh = x1 - x0, y1 - y0
    c = torch.tensor([(x0 + x1) / 2 / stride, (y0 + y1) / 2 / stride])     # 中心，以格子为单位
    cx, cy = min(int(c[0]), w - 1), min(int(c[1]), h - 1)                    # 中心所在的格子
    sx, sy = max(0.5, bw / stride / 6), max(0.5, bh / stride / 6)
    g = torch.exp(-((xs - cx) ** 2 / (2 * sx * sx) + (ys - cy) ** 2 / (2 * sy * sy)))
    heat[k] = torch.maximum(heat[k], g)                                       # 重叠处取最大值
    size[2 * k, cy, cx], size[2 * k + 1, cy, cx] = math.log(bw), math.log(bh)
    offset[0, cy, cx], offset[1, cy, cx] = c[0] - cx, c[1] - cy
    mask[k, cy, cx] = True
```

- 宽高回归的是 **log 宽、log 高**：框的大小从十几像素到几百像素，差几十倍。直接回归像素值时，大框的误差会主导损失；取 log 之后，"宽了 10%"无论大小框都是同样的误差；
- 重叠的物体在热图上取最大值，而不是相加（相加会超过 1）；
- 只在中心格（mask 为 True）上计算宽高和偏移的损失：其他格子没有"正确的宽高"可言。

### Focal loss

热图有 4 × 48 × 72 = 13,824 个格子，一页上的物体只有二十个左右。如果用普通的二分类交叉熵，损失被海量的背景格子主导：模型只要把所有格子都预测成接近 0，损失就很低，但什么也没检测到。

**Focal loss**（RetinaNet，2017）的想法：已经分对、而且很有把握的样本，降低它们的权重。CenterNet 的版本：

```
p = sigmoid(logit)
中心格（y = 1）：   −(1 − p)^α · log p                    α = 2
其他格：            −(1 − y)^β · p^α · log(1 − p)         β = 4
总损失 = 所有格子之和 / 中心格的个数
```

逐项理解：

- **(1 − p)^α**（正例）：p = 0.9 时权重 0.01，p = 0.1 时权重 0.81。已经找到的中心几乎不再贡献损失，没找到的贡献大；
- **p^α**（负例）：背景格预测 p = 0.01 时权重 10⁻⁴，几乎为 0。上万个"轻松"的背景格子加起来也不会淹没少数几个中心格；
- **(1 − y)^β**：中心附近的格子 y 接近 1，权重接近 0——预测了较高的概率也不怎么罚。这就是高斯目标的用处；
- 除以中心格的个数：损失的大小不随一页上物体的多少而变化。

还有一个初始化的小技巧：热图头的偏置初始化为 −log((1 − 0.01)/0.01) ≈ −4.6，使初始时每个格子的概率约为 0.01。如果初始概率是 0.5，第一步时上万个背景格子都会产生很大的损失，训练一开始就被搅乱。

宽高和偏移用 L1 损失，三项直接相加（`detector_loss`）。

### 解码：峰值就是物体

### 练习 21.6：`decode`

```python
p = torch.sigmoid(heat)
peak = p * (F.max_pool2d(p[None], 3, stride=1, padding=1)[0] == p)
scores, idx = peak.flatten().topk(min(k, peak.numel()))
```

`max_pool2d` 的 3×3 窗口、步长 1 让每个格子拿到自己邻域里的最大值；"等于邻域最大值"的格子就是局部峰值，其他格子乘以 0。这一步代替了大部分 NMS：同一个物体的热图是一座山，只有山顶一格会被保留。

然后在所有类别的峰值里取分数最高的 k 个，对每个峰值 (c, i, j)：

```
中心 = ((j + offset_x) · stride, (i + offset_y) · stride)
宽高 = exp(size[2c, i, j]), exp(size[2c + 1, i, j])
框   = (cx − 宽/2, cy − 高/2, cx + 宽/2, cy + 高/2)
```

测试 `test_targets_and_decode_roundtrip` 验证：用真实框生成目标，再把目标当成"完美的预测"解码，得到的框与原来的框完全一致。

## 21.6 版面分析与阅读顺序

### 版面分析

版面分析把一页分成有语义的**区块**：标题、正文段落、公式、表格、图、页眉页脚、脚注……每种区块后续的处理不同：正文交给文字识别，公式交给公式识别（输出 LaTeX，第 3 章），表格交给表格识别（输出 HTML/Markdown，第 25 章），图片可能跳过或者交给描述模型。

我们的检测器同时输出文字行和三种区块（标题、正文段落、公式）。

### 阅读顺序

检测器输出的框没有顺序。按什么顺序把它们的文字拼起来？

最简单的做法是**按 y 坐标排序**（从上到下）。单栏页面没问题，双栏页面就错了：左栏第一段、右栏第一段、左栏第二段……交错在一起。21.8 节第 4 部分会看到，在双栏页面上按 y 排序**从来**得不到正确的顺序（517 页里 0 页）。

### XY-cut

**XY-cut**（1984 年就有了）是一个递归的投影切分算法：

1. 把所有区块投影到 y 轴上（每个框变成一个区间 [y0, y1]），找区间之间的**空隙**——没有任何框覆盖的水平带；
2. 同样投影到 x 轴，找竖直的空隙；
3. 在空隙处把区块切成两组：上面的在前（或左边的在前），对每组递归；
4. 切不开时，组内按 (y, x) 排序。

**经典版本**先横切（在所有横向空隙处切开），切不开再竖切。问题是：双栏页面上，左栏和右栏的段落间隙可能**碰巧对齐**，横向投影上出现一条贯穿两栏的空隙，于是双栏被横着切成了几条，每条里再左右排序，顺序又交错了。

**改进的版本**（我们的练习）：每次只切一刀，沿着**最宽**的那个空隙。双栏页面上，栏间距（32 像素以上）通常比段落间距宽，所以先竖着把两栏分开，再在每一栏内部横切。标题横跨两栏，挡住了竖直的空隙，所以第一刀是标题下方的横切。

### 练习 21.4：`xy_cut`

```python
def xy_cut(boxes, min_gap=8):
    n = len(boxes)
    if n <= 1:
        return list(range(n))
    gy, cy = max_gap([(b[1], b[3]) for b in boxes])
    gx, cx = max_gap([(b[0], b[2]) for b in boxes])
    if max(gy, gx) < min_gap:
        return sorted(range(n), key=lambda i: (boxes[i][1], boxes[i][0]))
    axis, c = (1, cy) if gy >= gx else (0, cx)
    first = [i for i in range(n) if boxes[i][axis + 2] <= c]
    second = [i for i in range(n) if boxes[i][axis + 2] > c]
    return ([first[i] for i in xy_cut([boxes[j] for j in first], min_gap)]
            + [second[i] for i in xy_cut([boxes[j] for j in second], min_gap)])
```

`max_gap` 把区间按起点排序后扫一遍，记录"当前覆盖到哪里（end）"，下一个区间的起点减去 end 就是空隙。返回最宽的空隙和它的起点 c。切分时，右（下）边界不超过 c 的框归第一组。

递归调用返回的是**子列表里的下标**，要换回原来的下标（`first[i]`），这是最容易写错的地方。

### XY-cut 的局限

- 依赖"空隙"：栏间距窄、段落间距宽时会切错方向（21.8 节有一个失败的例子）；
- 不认识语义：图注应该跟着图、脚注应该放在最后、跨栏的图表插在中间……这些都需要知道区块的类型；
- 倾斜或弯曲的页面没有干净的投影空隙。

更强的方法是**学习**阅读顺序：LayoutReader（2021）用 Transformer 读入所有框的位置和文字，输出排列顺序。而端到端的 VLM 直接按顺序输出文字，阅读顺序是它在训练数据里**隐式**学会的——这也意味着训练数据的阅读顺序标注必须正确（第 34 章）。

## 21.7 流水线 OCR

把前面的部件串起来：

```
整页图
  │ 检测（半分辨率）：文字行框 + 区块框
  │ 文字行框做一次 NMS
  ▼
区块按 XY-cut 排序；每个文字行归到中心落在其中的区块，块内按 y 排序
  │
  ▼
逐行裁剪：以行框为中心取一条高 max(32, 1.6 × 框高) 的带子，缩放到高 32，补白到宽度 ≥ 256 且是 4 的倍数
  │
  ▼
第 13 章的 CRNN 识别每一行 → 按顺序用换行拼起来
```

**裁剪要和识别模型的训练数据一致**。第 13 章的 CRNN 是在"32 像素高、文字竖直居中、两边留白"的行图上训练的。裁剪时如果只裁墨迹的紧框，字会顶天立地，和训练时的样子不一样，识别率会下降。所以我们取比框高一些的带子（1.6 倍），并在框的左右各多留 4 个像素。标题的字更大（26–30 号），带子更高，缩放到 32 像素高后字号落到 CRNN 见过的范围附近。CRNN 是全卷积 + 双向 LSTM，宽度可以变，所以长标题不必截断。

**整页的评测**：把识别结果按阅读顺序用换行拼成一个字符串，与真实的整页文字计算 CER。这个数字把三种错误都算在内：

1. 识别错的字符；
2. 漏检的行（整行字符被删除）、多检的行（多出一行字符）；
3. 顺序错的行：两行交换位置，按编辑距离相当于删掉一行、再在别处插入一行，代价是两行字符数之和。

21.8 节分别测量"真实框 + 真实顺序"（只有识别错误）、"检测框 + XY-cut"（完整流水线）和"检测框 + 按 y 排序"三种情况，把整页的错误分解到每一步。这种**错误归因**是改进任何多步系统的第一步：先知道错误来自哪里，再决定改哪一步。

### 第 1 部分：IoU 与 NMS（几秒）

```
  5 个候选框（两行文字，各有几个重复的候选），分数 [0.9, 0.75, 0.6, 0.85, 0.5]
  IoU 矩阵：

    0.87  0.76  1.00  0.00  0.00
```

平移 IoU 的部分在 21.1 节。NMS 先选分数最高的 0 号（0.9），删掉和它 IoU > 0.5 的 1、2 号；剩下的 3、4 号里选 3 号（0.85），删掉 4 号。**手工跟着算法走一遍**，确认你的 `nms` 也是这个顺序。

### 第 2 部分：训练检测器（约 30–40 分钟）

在 3000 页上训练 2500 步（批 8），在 200 页测试集上对四类目标（文字行、标题、正文段落、公式）报告 AP@0.5、AP@0.75、召回率和精确率，并把第一张测试页的检测结果画到 `outputs/ch21/detect_example.png`。

**运行之前先预测**：

1. 损失的三部分（热图、宽高、偏移）里，哪个最大？训练中哪个降得最快？
2. 哪一类最难？文字行很多、很细；标题每页只有一个；公式区块形状各异。
3. AP@0.75 比 AP@0.5 低多少？对哪一类掉得最多？（回顾 21.1 节：细长的框对上下误差最敏感。）

**看什么**：

- 打开 `detect_example.png`，对照真实的版面看：漏掉的是哪些行？框是偏窄、偏宽，还是上下偏了？
- 如果所有类别的 AP 都接近 0，先检查热图的目标：用 `centernet_targets` 画出一张页面的热图，峰值应该正好落在每个框的中心；
- 最后一行"NMS 又删掉了几个框"：3×3 的最大池化只能去掉相邻格子的重复，相隔两格的重复峰值要靠框的 NMS。

### 第 3 部分：错误分析（几分钟，需要第 2 部分的模型）

统计漏检的文字行有多宽、误检的框和真实行的重叠情况，再把分数阈值从 0.1 调到 0.5，看召回率和精确率怎样此消彼长。

**预测**：漏检的行是更宽还是更窄？误检的框大多是"完全无中生有"，还是"和某个真实行部分重叠"？

**看什么**：如果漏检集中在很短的行（几个字符），说明这些行的中心点热图太小、太弱；如果误检多半和真实行部分重叠，说明问题在**宽高的回归**而不是"找不到"。两种问题的改法完全不同：前者调热图的高斯半径或加权，后者调宽高损失的权重或用更高的分辨率（选做题 7）。

### 第 4 部分：阅读顺序（约 1 分钟，用真实的区块框，不需要模型）

```
  用真实的区块框，1000 页中整页顺序完全正确的比例：
    单栏（483 页）：按 y 排序 100.0%   经典 XY-cut 100.0%   最宽空隙 XY-cut  98.1%
    双栏（517 页）：按 y 排序   0.0%   经典 XY-cut  42.2%   最宽空隙 XY-cut  85.5%
  一个失败的例子：正确顺序 [0, 1, 2, 3, 4, 5, 6]，XY-cut 给出 [1, 2, 3, 0, 4, 5, 6]；横向最宽空隙 32 像素，纵向（栏间）最宽空隙 41 像素
```

- **按 y 排序**在单栏上完美，在双栏上一页都排不对：左右两栏的段落按高度交错在一起；
- **经典 XY-cut**（每次在第一个足够宽的空隙处切）在双栏上只对了 42.2%：它常常先横着切，把左右两栏的上半部分切到一起；
- **最宽空隙 XY-cut**（每次选横、竖两个方向里最宽的那个空隙）提高到 85.5%。代价是单栏页面上有 1.9% 的页面反而排错了：单栏里偶尔某两段之间的横向空隙不是最宽的，切的方向和顺序就错了；
- **失败的例子**：这一页纵向的最宽空隙（41 像素）比横向的（32 像素）宽，算法先在纵向切了一刀，结果 0 号区块被排到了 1–3 号的后面。XY-cut 完全依赖"空隙的宽窄"这一个线索，版面稍有变化就会切错方向。这正是真实系统用模型学阅读顺序（选做题 9、21.6 节的 LayoutReader）的原因。

用 `python -m labs.ch21.detect_tour 4` 自己运行一遍，然后自己在 `part4_order` 里加两行代码，把失败的那一页连同区块框保存成图片，看看为什么这一页的纵向空隙比横向的宽、0 号区块在哪里。

### 第 5 部分：流水线 OCR（约 5 分钟，需要第 2 部分的检测器和第 13 章的 CRNN）

在 100 页上比较三种情况的整页 CER：用真实的行框（只有识别的错误）、检测框 + XY-cut 排序（完整流水线）、检测框 + 按 y 排序。

**预测**：三行的 CER 按什么顺序排？"按真实行框逐行识别"的 CER 会和第 13 章的 2.28% 接近吗？为什么可能更高？（提示：裁剪出来的行和第 13 章训练时的行图，在留白、高度、背景上有什么不同？）

**看什么**：三行之间的差就是**错误归因**：第一行是识别本身的错误，第二行减第一行是检测（漏检、多检、框不准）带来的，第三行减第二行是阅读顺序带来的。哪一步贡献的错误最多，就先改哪一步。

## 21.10 常见错误

| 现象 | 原因 | 怎么查 |
|---|---|---|
| AP 莫名其妙地低，可视化看着却对 | 框的格式搞混了（xywh 当成 xyxy，或坐标是归一化的） | 把预测框和真实框画在同一张图上 |
| 所有预测框都偏移半个格子 | 解码时忘了加 offset，或者中心的取整方式和目标不一致 | 用"完美预测"测试目标和解码的往返 |
| 训练一开始损失就是 nan | 热图头的偏置没有初始化成 −4.6，或者 log(p) 时 p = 0 | 初始化；clamp(p, 1e-4, 1 − 1e-4) |
| 检测器只输出很少的框 | 分数阈值太高，或者热图学得太"平" | 画出热图；降低阈值看召回率 |
| 同一行出现两个框 | 峰值提取的窗口太小，热图上一行有两个局部最大值 | 加一次框的 NMS |
| 整页 CER 远高于逐行 CER | 阅读顺序错了，或漏检整行 | 分别评测"真实框 + 真实顺序"和"检测框 + 真实顺序" |
| 裁出来的行识别很差 | 裁剪方式和识别模型的训练数据不一致（太紧、没留白、高度不对） | 把裁剪结果保存成图片，与训练样本对比 |

## 21.11 真实世界对照

- **PaddleOCR**（PP-OCR 系列）：DBNet 检测 + 方向分类 + CRNN/SVTR 识别，是最常用的开源流水线 OCR；PP-Structure 加上版面分析、表格识别。PaddleOCR-VL 则是它的 VLM 版本；
- **Tesseract**：最早的开源 OCR 引擎之一（HP 开发，后由 Google 维护），用传统的版面分析加 LSTM 识别；
- **版面分析数据集**：PubLayNet（36 万页科技论文，5 类区块）、DocLayNet（8 万页、11 类，覆盖金融、法律、专利等多种文档）；
- **文档解析工具**：MinerU、Marker、Docling 等把版面检测、阅读顺序、公式识别、表格识别串成一条流水线，输出 Markdown；它们是端到端 OCR VLM 最直接的对照组，也常被用来**生成** VLM 的训练数据（第 34 章）；
- **端到端 VLM**：GOT-OCR2、olmOCR、dots.ocr、PaddleOCR-VL、DeepSeek-OCR 等直接输出整页的结构化文本；其中一些仍然保留"先版面、后识别"的两阶段设计，只是两个阶段都由同一个 VLM 完成。

## 21.12 深入一步

### DETR 为什么不需要 NMS

DETR 输出固定 N 个预测（比如 100 个），训练时用**匈牙利算法**在预测和真实框之间找一个**一一对应**的最优匹配（代价 = 分类代价 + 框的 L1 + GIoU），没匹配上的预测的目标是"无物体"。因为每个真实物体只和一个预测匹配，其他预测如果也预测这个物体就会被惩罚，模型自己学会了"不重复"。代价是训练收敛慢，后续的 Deformable DETR、DINO 等做了大量改进。

### GIoU 与框的回归损失

IoU 本身可以作为损失（1 − IoU），但两个框不相交时 IoU 恒为 0，梯度也是 0，模型不知道该往哪边移。**GIoU** 加了一项：用包住两个框的最小矩形 C，GIoU = IoU − |C \ (A ∪ B)| / |C|，不相交时也有梯度。之后还有 DIoU、CIoU 等，分别加入中心距离、长宽比。我们的检测器回归 log 宽高和偏移，用 L1 损失，简单但不直接优化 IoU。

### 为什么文字检测常用分割

文字行的长宽比极端（可达 1:30）、方向任意、可能弯曲；一页上的行又密又多。基于框的检测器（尤其是锚框）很难覆盖这么多形状，而分割式方法只需要判断"每个像素是不是文字"，再用后处理连成区域，天然适应任意形状。DBNet 的"可微二值化"让阈值本身也可以学习，相邻行之间的缝隙更容易分开。

## 21.14 本章小结

- 框的表示要先弄清（xyxy / xywh / cxcywh、像素 / 归一化）；IoU = 交集 / 并集；细长的文字行对竖直方向的误差特别敏感；
- NMS 按分数贪心地去掉重叠的重复框；
- AP 把精确率–召回率曲线下的面积作为一个综合指标；COCO AP 在多个 IoU 阈值上平均；
- 中心点检测器在网格上预测中心热图、宽高和偏移；高斯热图让"差一格"不被当成完全错误，focal loss 让海量背景格子不淹没少数中心格；
- 阅读顺序的 XY-cut 沿空隙递归切分；"最宽空隙优先"比经典的"先横后竖"更适合双栏，但仍会在空隙不明显时失败；
- 流水线 OCR 的整页错误可以分解为识别、检测、排序三部分，错误归因是改进系统的第一步。

## 参考答案

1. IoU 的变化取决于平移量占框在平移方向上的边长的比例：4/16 = 25%，4/100 = 4%。
2. 太低：挨得很近的两个真实物体被当成重复，误删一个；太高：同一个物体的重复框删不掉。
3. 精确率和召回率随阈值此消彼长，不同的检测器在不同阈值下各有优劣。AP 对所有阈值积分，用一个数比较。
4. 中心旁边一格的预测离正确答案很近，不应该和远处的背景同等惩罚；高斯目标让损失随距离平滑变化，训练更稳定。
5. 中心附近的格子 y 接近 1，(1 − y)^β 接近 0，即使预测了较高的概率也几乎不罚。
6. 框的大小相差几十倍，直接回归时大框的误差主导损失；log 尺度上"宽 10%"对所有大小的框是同样的误差。
7. 左右两栏的段落间隙可能碰巧对齐，横向投影出现贯穿两栏的空隙，被横着切开后顺序交错。改进版每次沿最宽的空隙切一刀，栏间距通常最宽，所以先竖切；局限是当段落间距（尤其是公式块周围）比栏间距还宽时仍会切错方向，而且它不认识区块的语义。
8. 识别错误、检测错误（漏检、多检）、顺序错误。用"真实框 + 真实顺序"只测识别，"检测框 + 真实顺序"再加上检测，"检测框 + 算法排序"是完整流水线。
9. 交集 (10, 5, 20, 10)，面积 10 × 5 = 50；并集 200 + 200 − 50 = 350；IoU = 0.143。
10. 4 × 48 × 72 = 13,824 个格子，20 个中心格，占 0.14%。
11. 半分辨率上中心 = ((20 + 0.3) × 4, (10 + 0.6) × 4) = (81.2, 42.4)，宽高 (100, 8)，框 (31.2, 38.4, 131.2, 46.4)；乘以 2 回到原图：(62.4, 76.8, 262.4, 92.8)。
12. 两个框不相交时，宽或高是负数，两个负数相乘得到正的"交集"。要先把宽、高分别截断到 0。
13. 递归时传入的是子列表，返回的是子列表内部的下标（0、1、2……）；不换回就会把子列表的下标当成原列表的下标，顺序完全错乱。
14. 平坦区域的每个格子都等于邻域最大值，全部被当成峰值。实际中热图很少完全平坦；可以再配合分数阈值和 NMS 处理。
