# 第 19 章　视觉 Transformer（ViT）

## 本章在全景图中的位置

第四部分从这里开始：**视觉编码器**。

到第 18 章为止，我们有了一个能写字的语言模型（GPT）。要让它"看图说话"，还需要一个部件把图像变成语言模型能理解的向量序列——这就是**视觉编码器**（vision encoder），也叫**视觉塔**（vision tower）。第 22 章会把视觉编码器的输出接到 GPT 前面，组成我们自己的 VLM。

视觉编码器可以用第 12 章的 CNN，但今天几乎所有的 VLM（Qwen-VL、LLaVA、SmolVLM、InternVL……）用的都是 **ViT**（Vision Transformer，2020 年 Google 提出）。它的想法极其简单：

> 把图像切成一块一块的小方块（patch），每块当成一个"词"，交给 Transformer。

ViT 里没有新部件：切块是第 12 章的卷积（核大小等于步长），主体是第 15 章的非因果注意力和第 16 章的 Transformer 块。新问题只有两个：**二维的位置怎样编码**，以及**图像的分辨率和 token 数之间的权衡**。这两个问题在 OCR 里格外重要——文档图像大、文字小，token 数很容易上千。

本章在 ShapesWorld 上从零训练 ViT，并和 CNN 比较。第 20 章在 ViT 上做对比学习（CLIP/SigLIP），让它学到与文字对齐的视觉特征；第 24 章打开真实 VLM 的视觉塔，你会发现它和本章的 `ViT` 几乎一模一样。

## 学习目标

1. 说清"切块 + 线性层"与"核大小 = 步长的卷积"为什么完全等价，并用 reshape/permute 实现切块；
2. 画出 ViT 的结构，说清 CLS token 与平均池化两种汇总方式；

5. 知道换分辨率时位置编码怎么处理（插值、直接重算），并实测各自的效果；
6. 计算 ViT 的 token 数和计算量，理解 patch 大小、分辨率、注意力的平方代价之间的权衡；

## 19.1 图像怎样变成 token

### 切块

语言模型的输入是一串 token。图像是一个 (C, H, W) 的数组，怎样变成"一串"？

最直接的想法是把每个像素当成一个 token。64×64 的图就有 4096 个 token，注意力的分数矩阵是 4096² ≈ 1677 万个元素，每层每头都要算一次——太贵了。224×224 的图是 5 万个 token，根本算不动（第 15 章 15.10 节：注意力的代价与长度的平方成正比）。

ViT 的做法是把图切成 p × p 的小方块（**patch**），每块拉平成一个向量，当成一个 token：

```
64×64 的图，p = 8：

  ┌──┬──┬──┬──┬──┬──┬──┬──┐
  │ 0│ 1│ 2│ 3│ 4│ 5│ 6│ 7│      8 × 8 = 64 个 patch
  ├──┼──┼──┼──┼──┼──┼──┼──┤      第 i 行第 j 列的 patch 是第 i·8 + j 个 token
  │ 8│ 9│10│..│  │  │  │15│      每个 patch：3 个通道 × 8 × 8 像素 = 192 个数
  ├──┼──┼──┼──┼──┼──┼──┼──┤
  │  ...                  │
  └──┴──┴──┴──┴──┴──┴──┴──┘
```

64 个 token，分数矩阵只有 4096 个元素，是逐像素方案的 1/4096。代价是每个 token 内部的 8×8 个像素不再"互相注意"，它们只是被一起拉平、乘以同一个矩阵。

### 手算一个小例子

一张单通道 4×4 的图，p = 2：

```
 a b | c d
 e f | g h
 ----+----
 i j | k l
 m n | o p
```

切成 4 个 patch，按"先行后列"排序，每个 patch 按"先行后列"拉平：

```
patch 0（第 0 行第 0 列）：[a, b, e, f]
patch 1（第 0 行第 1 列）：[c, d, g, h]
patch 2（第 1 行第 0 列）：[i, j, m, n]
patch 3（第 1 行第 1 列）：[k, l, o, p]
```

注意 patch 0 不是 [a, b, c, d]：同一个 patch 的像素在原图的内存里**不是连续的**（a、b 之后紧跟的是另一个 patch 的 c、d）。所以不能直接 `reshape`，要先把维度拆开、换个顺序。

### 练习 19.1：`patchify`

```python
def patchify(x, p):
    B, C, H, W = x.shape
    h, w = H // p, W // p
    x = x.reshape(B, C, h, p, w, p)                 # 把 H 拆成 (h, p)、W 拆成 (w, p)
    x = x.permute(0, 2, 4, 1, 3, 5)                 # (B, h, w, C, p, p)
    return x.reshape(B, h * w, C * p * p)
```

逐步看形状（B = 1、C = 1、H = W = 4、p = 2）：

1. `reshape(1, 1, 2, 2, 2, 2)`：第 2 维是"第几个 patch 行"，第 3 维是"patch 内第几行"，第 4 维是"第几个 patch 列"，第 5 维是"patch 内第几列"。这一步只是给已有的下标换一种写法：像素 (行 r, 列 c) 变成 (r // 2, r % 2, c // 2, c % 2)，内存不动，所以可以直接 reshape；
2. `permute(0, 2, 4, 1, 3, 5)`：把"第几个 patch"的两维（patch 行、patch 列）放到前面，"patch 内部"的三维（通道、行、列）放到后面；
3. `reshape(1, 4, 4)`：前两维合并成 patch 编号 i·w + j，后三维合并成一个向量。因为 permute 之后内存不连续，这里的 reshape 会复制一份数据（第 9 章）。

### 切块 + 线性层 = 卷积

每个 patch 拉平后乘以一个 (C·p·p, d) 的矩阵 W、加上偏置 b，得到 d 维的 token 嵌入。这和第 12 章的卷积有什么关系？

一个 `nn.Conv2d(C, d, kernel_size=p, stride=p)`：

- 核的大小是 p × p，步长也是 p，所以相邻的窗口**恰好不重叠**、也不留空隙，窗口就是 patch；
- 每个输出通道 k 在每个窗口上算一次点积：核 W_k（形状 (C, p, p)）与窗口内的像素逐元素相乘再相加，加上偏置 b_k；
- 卷积的权重形状是 (d, C, p, p)。按 (C, p, p) 的顺序拉平，正好是 `patchify` 拉平每个 patch 的顺序。

所以两者**逐位相同**（只差浮点误差）。`PatchEmbed` 用卷积实现，因为它更快、也是真实模型的写法；测试 `test_patchify_equals_conv` 验证了两者的等价。第 12 章的自测题 11 从 im2col 的角度推导过同一件事。

参数量：3 · 8 · 8 · 128 + 128 = 24,704。对一个 4 层、d = 128 的 ViT 来说，patch 嵌入只占约 3%，参数大头在 Transformer 块里。

**patch 嵌入学到了什么？** 和第 12 章 CNN 的第一层卷积核类似：边缘、颜色、简单的纹理。区别是 ViT 只有这一层"卷积"，之后所有的空间组合都交给注意力。

## 19.2 整体结构

```
图像 (B, 3, 64, 64)
  │ PatchEmbed：Conv2d(3, d, 8, stride=8)，拉平
  ▼
patch token (B, 64, d)
  │ + 位置信息（19.3 节）
  │ 最前面拼一个可学习的 CLS token
  ▼
x (B, 65, d)
  │ × n_layer 个块：
  │     x = x + Attention(LayerNorm(x))      ← 非因果：每个 token 看所有 token
  │     x = x + MLP(LayerNorm(x))            ← GELU，中间维 4d
  ▼
LayerNorm
  │
  ├── 分类：取 CLS 的输出（或所有 patch 输出的平均）→ 线性层 → 类别
  └── VLM（第 22 章）：取所有 patch 的输出 (B, 64, d) → 连接器 → 语言模型
```

### 和 GPT 的块比较

| | GPT（第 16 章） | ViT（本章） |
|---|---|---|
| 注意力 | 因果：只看前面 | **非因果**：看全部 |
| 归一化 | RMSNorm | LayerNorm（原始 ViT、SigLIP、CLIP 的习惯；Qwen2.5-VL 起的视觉塔也改用 RMSNorm） |
| MLP | SwiGLU，中间维约 8d/3 | GELU，中间维 4d |
| 偏置 | 无 | qkv 和 MLP 都有偏置 |
| 位置 | 一维 RoPE | 可学习的表 / 二维正弦 / 二维 RoPE |
| 输入 | token 编号查表 | patch 嵌入（一个卷积） |
| 输出 | 下一个 token 的分布 | 每个 patch 一个向量 |

除了因果 mask 之外，这些差别都是"习惯"而不是"本质"：用 RMSNorm、SwiGLU 的 ViT 也能工作得很好。真实模型在这些选择上各不相同，第 24 章会逐一对照。

**为什么不需要因果 mask？** 语言模型要逐个预测下一个 token，位置 t 不能偷看 t + 1 的答案。ViT 是编码器，它一次看到整张图，没有"答案"可偷看，每个 patch 看所有 patch 是自然的（第 15 章自测题 3）。

### CLS token 与平均池化

分类时需要把 64 个 patch 的输出汇总成一个向量。两种做法：

1. **CLS token**（BERT 的做法，原始 ViT 沿用）：在序列最前面拼一个可学习的向量 `cls`。它不对应任何图像区域，经过若干层注意力后，它从所有 patch 收集信息。最后用它的输出做分类。这个 token 是"空白的提问者"：它的 q 学会了问"哪些 patch 对分类有用"；
2. **平均池化**：所有 patch 输出的平均。和第 12 章 CNN 的全局平均池化是同一个思路。SigLIP 用的是一个变体（注意力池化：一个可学习的查询对所有 patch 做一次交叉注意力，第 15 章 15.9 节）。

两者效果通常差不多。在 VLM 里，这两种汇总都**不用**：语言模型要看所有 patch 的输出，而不是一个汇总向量（第 22 章）。这也是为什么 `ViT.patch_tokens` 去掉 CLS、返回所有 patch 的输出。

### 练习 19.4：`ViT.encode`

```python
def encode(self, x):
    cfg = self.cfg
    t, (h, w) = self.patch(x)
    B, N, d = t.shape
    cos = sin = None
    if cfg.pos == "learned":
        t = t + interpolate_pos(self.pos, (cfg.grid(), cfg.grid()), (h, w))
    elif cfg.pos == "sincos":
        t = t + sincos_2d(h, w, d).to(t.device)
    elif cfg.pos == "rope2d":
        cos, sin = rope_2d(h, w, d // cfg.n_head, cfg.rope_base, device=t.device)
    if cfg.pool == "cls":
        t = torch.cat([self.cls.expand(B, 1, d), t], 1)
        if cos is not None:
            cos = torch.cat([torch.ones_like(cos[:1]), cos], 0)
            sin = torch.cat([torch.zeros_like(sin[:1]), sin], 0)
    for blk in self.blocks:
        t = blk(t, cos, sin)
    return self.ln(t), (h, w)
```

要点：

- 位置信息在拼 CLS **之前**加到 patch 上：CLS 不对应任何位置；
- 用 RoPE 时，CLS 的 cos = 1、sin = 0，也就是"转 0 度"。CLS 的 q 和 k 不旋转，它与 patch 之间的分数不随 patch 的位置系统性变化（patch 的 k 仍然被旋转了，CLS 看到的是带位置的 k）；
- `self.cls.expand(B, 1, d)` 不复制内存，B 张图共用同一个 CLS 向量，梯度会累加到这一个参数上；
- `self.pos` 和 `self.cls` 按 timm（最常用的 ViT 代码库）的习惯初始化为标准差 0.02。实测 patch 嵌入的输出（默认初始化）标准差约 0.45，所以位置信号起初只有它的 1/20 左右。第 15 章的教训是位置信号太弱时模型会学得很慢，而且不报错；这里的位置表是可学习的，梯度会让它长大。19.6 节第 7 部分检查了训练后位置表的大小。

## 19.3 二维的位置

### 没有位置会怎样

第 15 章 15.7 节证明了：没有位置信息的自注意力是**置换等变**的——打乱输入的顺序，输出也被同样地打乱，每个 token 的输出向量不变。CLS 的输出是对所有 patch 的加权平均，打乱 patch 后，它的输出**完全不变**。

对 ViT 来说，这意味着：**把图像的 64 个 patch 随机打乱拼成一张"拼图"，没有位置编码的 ViT 给出的结果和原图完全一样**。测试 `test_vit_position_matters` 验证了这一点：没有位置编码时，打乱前后 CLS 的输出相同；加了可学习的位置表或 RoPE 后就不同了。

所以没有位置的 ViT 能回答"图里有没有红色"、"有几个物体"（与位置无关的问题），但回答不了"最左边的物体是什么颜色"。19.6 节会实测。

（patch **内部**的空间结构还在：8×8 个像素按固定的顺序拉平，模型知道一个 patch 里墨迹在左上还是右下。它不知道的是 patch 和 patch 之间的相对位置。）

### 方法一：可学习的位置表

和第 15 章 `LookupNet` 一样：为每个位置学一个 d 维向量，加到 patch 嵌入上。

```python
self.pos = nn.Parameter(torch.randn(g * g, d) * 0.02)     # g = 64 / 8 = 8
t = t + self.pos
```

模型完全靠数据学出"位置 9 和位置 10 是邻居、位置 9 和位置 17 也是邻居"。原始 ViT、CLIP、SigLIP 都用它。训练好的 ViT 里，相邻位置的向量确实很相似（原始 ViT 论文的图 7 展示了这一点）。

**缺点：表的大小是固定的。** 训练时是 8×8 = 64 行，换成 96×96 的图（12×12 = 144 个 patch）就没有对应的行了。

### 换分辨率：插值

常用的补救是把表当成一张 d 通道、8×8 的"图"，用插值放大到 12×12：

```python
def interpolate_pos(pos, old_hw, new_hw):
    d = pos.shape[-1]
    g = pos.reshape(1, old_hw[0], old_hw[1], d).permute(0, 3, 1, 2)       # (1, d, 8, 8)
    g = F.interpolate(g, size=tuple(new_hw), mode="bicubic", align_corners=False)
    return g.permute(0, 2, 3, 1).reshape(new_hw[0] * new_hw[1], d)        # (144, d)
```

插值之后，新网格第 11 列（最右）的位置向量 ≈ 旧网格第 7 列（最右）的位置向量。也就是说，插值保留的是**相对的位置**（"在图的右边缘"），而不是绝对的距离（"离左边 88 个像素"）。

插值的效果取决于任务。物体的大小（以 patch 计）没变，但位置向量被"拉伸"了：模型训练时学到"位置向量相差这么多就是相隔 1 个 patch"，插值后同样的差别对应 1.5 个 patch。常见的做法是插值后在新分辨率上再微调一小段时间。

`F.interpolate` 的 `align_corners=False` 是把每个格子看成一个小方块、按方块中心对齐（第 2 章的缩放约定），这样 8×8 的格子均匀地铺满 12×12 的范围。

### 方法二：二维正弦编码

先看一维的**正弦编码**（sinusoidal encoding，Transformer 原论文 Vaswani 等 2017 的做法）：第 15 章用的是可学习的位置表，正弦编码则是一张**算出来、不训练**的表，位置 t 的第 2i 维是 sin(t·ω_i)，第 2i+1 维是 cos(t·ω_i)，ω_i = 10000^(−2i/d)。i 小的维度频率高、转得快，i 大的维度转得慢，和第 16 章 RoPE 用的是同一组频率。二维的做法是：**一半维度编码行号，另一半编码列号**。

```python
def sincos_2d(h, w, d):
    row = sincos_1d(h, d // 2)                      # (h, d/2)：行号的一维编码
    col = sincos_1d(w, d // 2)                      # (w, d/2)：列号的一维编码
    return cat([row[i], col[j]]) 对每个 (i, j)，按 i·w + j 排列 → (h·w, d)
```

（这里写的是思路；完整代码见 `miniocr/models/vit.py`，它用 `expand` 把 (h, d/2) 和 (w, d/2) 广播成 (h, w, d/2) 再拼接。）

同一行的 patch 前一半相同，同一列的 patch 后一半相同（测试 `test_sincos_and_interpolation`）。它没有参数，换分辨率时**直接按新的网格重新计算**：新网格第 11 列的编码就是"第 11 列"的编码，表示的是绝对的距离，不是相对的"右边缘"。这与插值正好相反，19.6 节会比较两者。

MAE（2021）、很多自监督的 ViT 用这种编码。

### 练习 19.2：`sincos_1d`、`sincos_2d` 与 `interpolate_pos`

在 `miniocr/models/vit.py` 里补完三个函数（它们在同一个练习块里）：

- `sincos_1d(n, d)`：上面的一维正弦编码，返回 (n, d)；
- `sincos_2d(h, w, d)`：按上面的思路拼接，返回 (h·w, d)，第 i·w + j 行是 patch (i, j) 的编码；
- `interpolate_pos(pos, old_hw, new_hw)`：上一小节"换分辨率：插值"的做法。把 (old_h·old_w, d) 变形成 (1, d, old_h, old_w) 的"图"，用 `F.interpolate(..., mode="bicubic", align_corners=False)` 缩放，再变回 (new_h·new_w, d)；网格相同时原样返回。

两个容易错的地方：`reshape` 之后要 `permute` 成通道在前（`F.interpolate` 把第 1 维当通道）；拉平时要先 `permute` 回 (1, h, w, d)，否则行列顺序会乱。`test_sincos_and_interpolation` 检查三件事：同一行的 patch 前一半相同、同一列的后一半相同；网格不变时 `interpolate_pos` 直接返回原来的张量（`is pos`）；全是常数的位置表插值后仍然是同一个常数。

### 方法三：二维 RoPE

第 16 章的 RoPE 把 q、k 的第 m 维和第 m + dh/2 维看成一个平面上的点，按位置 t 转过角度 t·θ_m。两个位置的点积只取决于 t_q − t_k。

二维的版本：**一部分平面按行号转，另一部分按列号转。** 设头维度 dh = 32，有 16 个平面。前 8 个平面按行号 i 转，后 8 个按列号 j 转，频率 θ_k = base^(−k/8)，k = 0 … 7：

```
ang = cat([i·θ_0, …, i·θ_7,  j·θ_0, …, j·θ_7])      长 16 = dh/2
cos, sin = cos(cat([ang, ang])), sin(cat([ang, ang]))   长 32 = dh，按 apply_rope 的"前后两半"约定
```

#### 为什么只依赖行差和列差

把 q 拆成 16 个二维分量 q⁽ᵐ⁾，k 同样。点积是各平面的点积之和：

```
q · k = Σ_m q⁽ᵐ⁾ · k⁽ᵐ⁾
```

第 16 章证明过：两个向量分别转过角度 α、β 之后，点积 R(α)q⁽ᵐ⁾ · R(β)k⁽ᵐ⁾ 只取决于 α − β。前 8 个平面的角度差是 (i_q − i_k)·θ_m，后 8 个是 (j_q − j_k)·θ_m。所以

```
score((i_q, j_q), (i_k, j_k)) = f(i_q − i_k, j_q − j_k)
```

只取决于**行差和列差**。测试 `test_rope_2d_relative` 验证：(3, 4) 对 (1, 2) 的分数等于 (4, 3) 对 (2, 1) 的分数（行差、列差都是 2）；行差 2、列差 0 的分数和行差 0、列差 2 的分数不同（模型分得清"上下"和"左右"）。

#### 练习 19.3：`rope_2d`

在 `miniocr/models/vit.py` 里补完 `rope_2d`。先在纸上写出 h = 1、w = 2、dh = 8 时的结果（只有 2 个频率 θ_0 = 1、θ_1 = base^(−1/2) = 0.1）：patch (0, 1) 的 ang 是 [0, 0, 1, 0.1]，重复一次后是 [0, 0, 1, 0.1, 0, 0, 1, 0.1]。再对照下面的参考实现，用 `test_rope_2d_relative` 检查。

```python
def rope_2d(h, w, dh, base=100.0, device=None):
    q = dh // 4
    theta = base ** (-torch.arange(q, dtype=torch.float32, device=device) / q)
    ii, jj = torch.meshgrid(torch.arange(h, device=device), torch.arange(w, device=device), indexing="ij")
    ang = torch.cat([ii.reshape(-1, 1).float() * theta, jj.reshape(-1, 1).float() * theta], -1)   # (h·w, dh/2)
    ang = torch.cat([ang, ang], -1)
    return ang.cos(), ang.sin()
```

- `meshgrid(..., indexing="ij")` 生成两个 (h, w) 的表：`ii[i, j] = i`、`jj[i, j] = j`。拉平后第 i·w + j 个元素正好是 patch (i, j) 的行号和列号；
- 返回的 cos、sin 直接交给第 16 章的 `apply_rope`，注意力的代码一行都不用改；
- Qwen2-VL / Qwen2.5-VL 的视觉塔用的就是这个构造：它的 `VisionRotaryEmbedding` 用 dim = 头维度/2 生成频率，行和列各用一份，拼起来后再 `cat((emb, emb))`。第 24 章会在真实的代码里核对。

#### 为什么 base 取 100

文字的 RoPE 用 base = 10000，因为句子可能有几千上万个 token，需要很慢的低频分量来区分很远的位置。我们的网格只有 8×8，行差最大是 7。base = 10000、8 个频率时，最慢的频率是 10000^(−7/8) ≈ 0.0003，转 7 格也只有 0.002 弧度——这些维度几乎不转，相当于浪费了。base = 100 时，频率从 1 到 100^(−7/8) ≈ 0.018，转 7 格的角度从 7 弧度到 0.12 弧度，各个频率都派得上用场。（Qwen2-VL 的视觉塔用 base = 10000，但它的网格大得多，也没有我们这样精打细算。）

RoPE 没有参数，任意大小的网格都能直接计算，**换分辨率时不需要插值**。它表示的是"相隔几个 patch"，与正弦编码一样是绝对的距离尺度。

## 19.4 token 数与计算量

### token 数

一张 H × W 的图，patch 大小 p，有 (H/p) · (W/p) 个 token。token 数与分辨率的**平方**成正比，与 patch 大小的平方成**反比**：

| 模型 | 分辨率 | patch | patch 数 | 送进语言模型的 token |
|---|---|---|---|---|
| 本章 | 64×64 | 8 | 64 | — |
| ViT-B/16 | 224×224 | 16 | 196 | — |
| SigLIP so400m/14 | 384×384 | 14 | 729 | 729（LLaVA 类模型直接用） |
| Qwen2.5-VL | 1008×1008 | 14 | 5,184 | 1,296（2×2 合并） |
| Qwen3-VL / Qwen3.5 | 1024×1024 | 16 | 4,096 | 1,024（2×2 合并） |

（19.6 节第 1 部分打印了这张表。）"2×2 合并"是把相邻的 4 个 patch 拼成一个 token 再送进语言模型（第 22 章），所以 Qwen3.5 每个视觉 token 对应 32×32 个像素。

一页 A4 文档扫描成 150 dpi 大约是 1240×1754 像素。按 Qwen3.5 的做法是 39 × 55 ≈ 2,100 个视觉 token、8,500 个 patch。视觉编码器要在 8,500 个 token 上做注意力，这就是 OCR 模型比"看图描述"模型贵得多的原因。

### 计算量

一个 ViT 块对 N 个 token 的计算量（只算矩阵乘法，一次前向）：

- 线性层（qkv、输出投影、MLP）：每个 token 2 × 12d² FLOP（qkv + o 是 4d²，MLP 是 8d²，每个参数一次乘加 = 2 FLOP），共 **24·N·d²**；
- 注意力分数和加权求和：QKᵀ 是 N × N × d 次乘加，乘 V 也是，共 **4·N²·d**。

两者之比是 4N²d / 24Nd² = **N / (6d)**：

- 本章 N = 64、d = 128：0.08，注意力部分只占约 8%；
- ViT-B/16 在 224×224：N = 196、d = 768：0.04；
- 一页文档 N = 8,500、d = 1,280（Qwen2.5-VL 视觉塔的宽度）：1.1，注意力部分超过一半；分辨率再翻倍，N 变成 4 倍，注意力的计算量变成 16 倍。

所以高分辨率时，注意力的平方代价成为瓶颈。真实模型的应对：

- **窗口注意力**：Qwen2.5-VL 的视觉塔大部分层只在 112×112 像素的窗口内做注意力，只有 4 层做全局注意力（第 24 章）；
- **切图**：把大图切成若干张固定大小的子图分别编码（LLaVA-NeXT、InternVL、SmolVLM 的做法）；
- **更大的 patch 或合并**：减少 token 数，代价是每个 token 覆盖的像素更多，小字可能看不清。

### 对 OCR 的意义

一个 token 覆盖 32×32 个像素时，一个 10 像素高的字符只占 token 的 1/3 高度，一个 token 可能包含 3–4 个字符的一部分。这对识别不是致命的（模型可以在 1280 维的向量里编码很多信息），但字太小时会出错。OCR 模型都有一个"最低分辨率"：低于它，小字就开始错。第 24 章用真实模型实测视觉 token 数（自己动手第 8 题让你测分辨率与 CER 的关系），第 33 章算一整页文档在不同分辨率下要多少视觉 token。

## 19.5 ViT 与 CNN

### 归纳偏置

第 12 章讲过，CNN 把三条关于图像的"先验知识"写进了结构：

1. **局部性**：每个卷积只看 3×3 的邻域，远处的像素要经过很多层才能互相影响；
2. **平移等变**：同一个卷积核扫过所有位置，"在哪里都认得"；
3. **层级**：池化让特征图逐层变小，感受野逐层变大，从边缘到部件到物体。

这些叫**归纳偏置**（inductive bias）：模型在见到数据之前就"相信"的东西。偏置对了，模型用更少的数据就能学好。

ViT 的归纳偏置少得多：

- patch 内部有局部性（8×8 的像素被一起处理），patch 之间没有：第一层的每个 patch 就能看到所有 patch；
- 没有平移等变：可学习的位置表让每个位置都不一样（RoPE 有一定的平移不变性：分数只依赖相对位置）；
- 没有层级：每一层的 token 数和维度都不变。

结果是：**数据少时 ViT 不如 CNN，数据多时 ViT 更好**。原始 ViT 论文的结论：只在 ImageNet（130 万张）上训练，ViT 比同等大小的 ResNet 差；在 JFT-300M（3 亿张）上预训练后，ViT 超过了 ResNet。归纳偏置是"免费的数据"，但它也是一种限制：数据足够多时，模型自己学到的规律比人写进去的更好。19.6 节第 5 部分在小规模上检验这个结论，结果并不简单：在我们的玩具任务上没有重现，原因见那里的分析。

### 为什么 VLM 都用 ViT

1. **统一的接口**：ViT 的输出就是一串 d 维的 token，和文字 token 一样，直接拼进语言模型的序列（第 22 章）。CNN 的输出是特征图，也可以拉平，但 ViT 更自然；
2. **能扩展**：Transformer 的大小、数据量、计算量都可以平滑地放大（第 18 章的缩放定律），视觉塔有 4 亿参数（SigLIP so400m）甚至 60 亿参数（InternViT-6B）；
3. **CLIP 预训练**：最好的视觉底座（CLIP、SigLIP）都是 ViT，在几十亿张图文对上训练过（第 20 章）。VLM 直接拿来用，不必从头训练；
4. **任意分辨率**：配合二维 RoPE，ViT 能直接处理任意大小、任意长宽比的图（Qwen2-VL 起的"原生分辨率"），这对文档 OCR 很重要：文档常常是长条形的。

CNN 并没有消失：很多 OCR 流水线的检测和识别模型（第 21 章）仍然用 CNN，因为它们快、对小数据友好；也有不少"卷积 + 注意力"的混合结构（比如在 ViT 前面加几层卷积做 stem，或 ConvNeXt 这类借鉴 Transformer 设计的 CNN）。

## 19.6 实验

以下都是 `python -m labs.ch19.vit_tour` 的输出（完整日志在 `outputs/ch19/run.log`），CPU 上运行。所有模型都训练 2000 步、批 128，用带预热的余弦学习率（第 11 章）；测试集是另外生成的 2000 张图，所有模型共用。训练时间受同一台机器上其他程序的影响，只看相对大小。

### 第 1 部分：切块

```
  patch  4×4 ：64×64 的图 →  256 个 token，每个 token 拉平后 3·4·4 =   48 维
  patch  8×8 ：64×64 的图 →   64 个 token，每个 token 拉平后 3·8·8 =  192 维
  patch 16×16：64×64 的图 →   16 个 token，每个 token 拉平后 3·16·16 =  768 维
  Conv2d(3, 128, kernel=8, stride=8) 的输出 (1, 64, 128)，网格 (8, 8)；与'切块 + 线性层'的最大差 1.2e-06
  patch 嵌入的参数：3·8·8·128 + 128 = 24,704
  注意力的计算量与 token 数的平方成正比：
    patch  4：N =  256，注意力分数矩阵 N² =  65,536 个元素（每头每层）
    patch  8：N =   64，注意力分数矩阵 N² =   4,096 个元素（每头每层）
    patch 16：N =   16，注意力分数矩阵 N² =     256 个元素（每头每层）
  真实模型：
    ViT-B/16（224×224）                                  196 个 patch，合并后   196 个视觉 token
    SigLIP so400m/14（384×384）                          729 个 patch，合并后   729 个视觉 token
    Qwen2.5-VL（patch 14，2×2 合并；1008×1008）            5,184 个 patch，合并后 1,296 个视觉 token
    Qwen3-VL / Qwen3.5（patch 16，2×2 合并；1024×1024）    4,096 个 patch，合并后 1,024 个视觉 token
```

- 把卷积的权重拷进线性层之后，"切块 + 线性层"和 `Conv2d(kernel=8, stride=8)` 的输出只差 1.2 × 10⁻⁶，这是浮点运算顺序不同带来的误差。两者是同一个运算，所以真实代码都直接用卷积实现 patch 嵌入；
- patch 从 8 减到 4，token 数变成 4 倍（64 → 256），注意力分数矩阵变成 16 倍。第 4 部分会看到训练时间也大致是这样增长的。

### 第 2 部分：ViT 与 CNN

```
  任务：数物体（4 类）
    CNN（宽 32，拉平）               参数   126,244  测试准确率 100.0%  （ 248 秒）
    ViT（patch 8，d 128，4 层）     参数   826,884  测试准确率  92.9%  （ 184 秒）
  任务：最左边物体的颜色（4 类）
    CNN（宽 32，拉平）               参数   126,244  测试准确率  96.2%  （ 167 秒）
    ViT（patch 8，d 128，4 层）     参数   826,884  测试准确率  98.1%  （ 182 秒）
```

两个任务的结果方向相反：

- **数物体**：CNN 100%，ViT 92.9%。ViT 的参数是 CNN 的 6.5 倍，结果反而差。数物体要先把属于同一个物体的像素"连起来"，再数有几块。物体的边长是 8–18 像素，会横跨 2–9 个 patch。CNN 的 3×3 卷积天然擅长找"连在一起的一块颜色"；ViT 要用注意力自己学"哪些 patch 属于同一个物体"，2000 步不够它学好。这是局部性偏置的一个具体好处；
- **最左边物体的颜色**：ViT 98.1%，CNN 96.2%。这个问题要比较整张图里所有物体的位置，是**全局**的问题。ViT 的第一层就能让任意两个 patch 交换信息；CNN 的感受野要经过好几层才覆盖全图，全局的比较主要靠最后拉平后的全连接层完成。

所以"ViT 好还是 CNN 好"取决于任务。VLM 选择 ViT，不是因为它在每个小任务上都更强，而是因为 19.5 节说的那几个理由：接口统一、能扩展、有 CLIP 预训练。

### 第 3 部分：位置编码

```
  任务：最左边物体的颜色
    位置 = none                  参数   818,692  测试准确率  67.5%  （ 179 秒）
    位置 = learned               参数   826,884  测试准确率  98.1%  （与前面相同的配置，不重复训练）
    位置 = sincos                参数   818,692  测试准确率  98.2%  （ 184 秒）
    位置 = rope2d                参数   818,692  测试准确率  98.6%  （ 209 秒）
  任务：数物体（不需要知道位置）
    位置 = none                  参数   818,692  测试准确率  91.6%  （ 196 秒）
```

- 去掉位置编码，"最左边"从 98% 掉到 67.5%；"数物体"几乎不受影响（92.9% → 91.6%）。这和 19.3 节的分析一致：没有位置，ViT 对 patch 的顺序是置换不变的，能数出几个，分不清谁在左边；
- 没有位置时为什么还有 67.5%，而不是瞎猜的 25%？第 8 部分会回答；
- 三种位置编码的差别都在 0.5 个百分点以内，在这个任务上没有实质区别。它们的区别要换分辨率才看得出来（第 6 部分）；
- 可学习的位置表多了 64 × 128 = 8,192 个参数（826,884 − 818,692），正弦编码和 RoPE 没有参数。

### 第 4 部分：patch 大小

```
    patch  4（256 个 token）      参数   833,028  测试准确率  98.2%  （1047 秒）
    patch  8（ 64 个 token）      参数   826,884  测试准确率  98.1%  （与前面相同的配置，不重复训练）
    patch 16（ 16 个 token）      参数   894,468  测试准确率  97.2%  （  56 秒）
```

- token 数每变成 4 倍，训练时间大约变成 3–6 倍：patch 16 用了 56 秒，patch 8 用了 182 秒，patch 4 用了 1047 秒。时间增长得比 4 倍还多，因为注意力部分是平方增长的；
- 准确率几乎不变：98.2% / 98.1% / 97.2%。我们的物体是 8–18 像素的纯色几何图形，16×16 的 patch 也看得清。**分辨率的需求由任务决定**。对文字就不一样了：一个 16×16 的 patch 可能装下两三个小字，细节更重要。第 24 章的自己动手第 8 题在 OCR 上做分辨率实验；
- patch 16 的参数反而最多：patch 嵌入的矩阵是 3·16·16 × 128，比 patch 8 的 3·8·8 × 128 大 4 倍。

### 第 5 部分：数据量

```
  训练集 1000 张：
    CNN                        参数   126,244  测试准确率  87.8%  （ 199 秒）
    ViT（learned）               参数   826,884  测试准确率  91.5%  （ 191 秒）
  训练集 4000 张：
    CNN                        参数   126,244  测试准确率  94.2%  （ 228 秒）
    ViT（learned）               参数   826,884  测试准确率  96.0%  （ 235 秒）
  训练集 16000 张：
    CNN                        参数   126,244  测试准确率  96.2%  （与前面相同的配置，不重复训练）
    ViT（learned）               参数   826,884  测试准确率  98.1%  （与前面相同的配置，不重复训练）
```

**这个实验没有重现"数据少时 ViT 不如 CNN"**：在 1000 张、4000 张、16000 张上，ViT 都比 CNN 高约 2–4 个百分点，差距在数据最少时反而最大。

如实记录这个结果，并分析为什么：

1. **任务**：19.5 节说的结论来自 ImageNet 这样的自然图像。那里的物体有纹理、有遮挡、背景复杂，局部性和平移等变是很有用的先验。我们的"最左边"任务是一个全局比较的问题，对 CNN 的偏置不友好（第 2 部分）；
2. **规模**：论文里的"数据少"是 130 万张，"数据多"是 3 亿张，模型是几亿参数。我们的 1000 张和 16000 张、80 万参数，不在同一个量级上；
3. **对照不对等**：我们的 CNN 只有 12 万参数，ViT 有 83 万。这里比的是"两个都训练 2000 步、大小合理的模型"，不是同等大小的模型。

数据从 1000 张增加到 16000 张，两个模型都提高了 7 个百分点上下（CNN 8.4、ViT 6.6），"数据越多越好"在两种结构上都成立。要真正看到归纳偏置的作用，可以换成 CNN 擅长的任务（比如数物体），或者做选做题 6（给 ViT 加卷积 stem）。

### 第 6 部分：换分辨率

```
  测试图是 96×96 的新场景（物体大小不变、画布更大）：patch 网格从 8×8 变成 12×12
    learned  64×64： 98.1%   96×96： 97.9%   （8×8 的表双三次插值到 12×12）
    sincos   64×64： 98.2%   96×96： 92.1%   （直接按 12×12 重新计算）
    rope2d   64×64： 98.6%   96×96： 98.2%   （直接按 12×12 计算旋转角）
  对照：同一批 96×96 测试图缩小到 64×64 后再测（物体变小了 1/3）：
    learned   96.0%
    rope2d    98.4%
```

模型只在 64×64 上训练过，测试时直接喂 96×96 的图，没有任何微调：

- **可学习的表 + 插值**：97.9%，几乎不掉。插值后，表的第 0 列仍然代表"最左边"，第 11 列代表"最右边"，表示的是**相对比例**。"最左边"这个问题只需要比较谁更靠左，相对比例就够了；
- **二维正弦**：掉到 92.1%。直接按 12×12 重新计算时，第 8–11 列的编码在训练时从没出现过（训练时只有第 0–7 列）。模型要面对没见过的位置向量，这叫**外推**（extrapolation），而插值只是在见过的范围内取中间值；
- **二维 RoPE**：98.2%，同样几乎不掉。RoPE 的分数只依赖两个 patch 的**行差和列差**。新图里出现了训练时没见过的大距离（最大列差从 7 变成 11），但"谁更靠左"仍然由列差的符号决定。这就是 Qwen2-VL 以来的视觉塔都用二维 RoPE 的原因：同一个模型可以直接处理任意大小、任意长宽比的图；
- **对照**：把 96×96 的图缩小到 64×64 再测，learned 掉到 96.0%，比直接在 96×96 上测（97.9%）还低。缩小会让物体变小、边缘模糊。所以"把所有图都缩放到训练分辨率"并不总是最好的做法，对小字更是如此。

### 第 7 部分：位置表学到了什么、CLS 在看哪里

```
  训练后：位置表的标准差 0.127（初始 0.020），patch 嵌入输出的标准差 0.613
  位置向量的余弦相似度：左右相邻 0.67，上下相邻 0.85，左右隔 4 格 -0.52，上下隔 4 格 0.82，任意两个位置平均 0.04
```

- 位置表的标准差从 0.02 长到了 0.127，是 patch 嵌入（0.613）的约 1/5，比初始时的 1/20 强多了。这印证了 19.2 节说的：位置表是可学习的，任务需要时梯度会让它长大；
- **位置表只学了"列"**：上下相邻的两个位置，余弦相似度是 0.85；上下隔 4 格，仍然有 0.82，几乎一样。左右隔 4 格，相似度是 −0.52，方向几乎相反。也就是说，同一列的位置向量都差不多，不同列的差别很大。原因是"最左边"只需要知道每个 patch 在第几**列**，行号没用，模型就没有去学它。**模型只学任务需要的东西。**如果换一个需要行号的任务（"最上面的物体"），表的结构会不一样。

### 第 8 部分：没有位置时的 67.5% 从哪来

```
     物体数   张数   无位置 ViT   learned ViT   '猜最多的颜色'的期望准确率
       1      496     100.0%       100.0%         100.0%
       2      504      64.1%        98.4%          65.8%
       3      475      54.7%        97.7%          54.0%
       4      525      51.6%        96.4%          55.4%
     全部    2000      67.5%        98.1%          68.8%
```

不知道位置时，最好的策略是"回答图里出现次数最多的颜色"：只有一个物体时一定对；两个物体颜色相同时一定对，不同时只能二选一……最后一列是这个策略的期望准确率。

无位置 ViT 的准确率在每一行都和这个策略相差不到 4 个百分点（全部 67.5% vs 68.8%）。也就是说，**没有位置的 ViT 学到的就是"猜最多的颜色"**，这已经是它在缺少信息时能做到的最好了。67.5% 不是"学会了一部分位置"，而是"在完全不知道位置时，统计上能猜对的部分"。

这种分析方法很有用：模型的准确率看起来不低时，先找一个"不需要关键信息也能达到的基线"来对照。第 23 章的幻觉评测、第 25 章的评测协议都会用到这个思路。

## 19.8 常见错误

| 现象 | 原因 | 怎么查 |
|---|---|---|
| 切块结果"错位"，patch 里的像素不连续 | 直接 reshape 而没有先拆维度、permute | 用"值 = 像素坐标"的图测试 patchify |
| 位置编码加了却没效果 | 位置向量相对 patch 嵌入太小，或者加到了 CLS 之后的错误位置 | 打印两者的标准差；检查形状 |
| 换分辨率时报形状不匹配 | 可学习的位置表行数固定 | 插值到新网格，或改用 sincos / RoPE |
| RoPE 的 ViT 训练不动 | 头维度不能被 4 整除，或者 cos/sin 的行数与 token 数（含 CLS）不一致 | 断言 cos.shape[0] == 序列长度 |
| 训练初期损失不降 | 学习率太大、没有预热；ViT 对优化设置比 CNN 敏感 | 加预热，降低学习率，加梯度裁剪 |
| 测试准确率远低于训练 | 数据太少，ViT 归纳偏置少，过拟合 | 数据增强、更多数据、更小的模型 |
| 注意力图全是均匀的 | 读的是第一层，或者模型根本没学会 | 看更深的层；先确认准确率 |

## 19.9 真实世界对照

- **原始 ViT**（Dosovitskiy 等，2020）：ViT-B/16（12 层、d = 768、8600 万参数）、ViT-L/16（24 层、d = 1024、3 亿）、ViT-H/14（32 层、d = 1280、6.3 亿）。可学习位置表 + CLS token；
- **DeiT**（2021）：只用 ImageNet 训练 ViT，靠强数据增强、正则化和"蒸馏 token"达到了与 CNN 相当的效果，说明"数据饥渴"可以部分用训练技巧弥补；
- **SigLIP so400m/14**：27 层、d = 1152，"形状优化"的宽度和深度，是很多开源 VLM 的视觉塔；
- **Qwen2-VL / Qwen2.5-VL 的视觉塔**：约 6.7 亿参数，patch 14，二维 RoPE，支持任意分辨率；Qwen2.5-VL 加入窗口注意力，归一化和 MLP 改用 RMSNorm 和 SwiGLU，和语言模型的风格统一；
- **Qwen3-VL / Qwen3.5**：patch 16，配合 2×2 合并每个视觉 token 对应 32×32 像素（第 24 章实测）；
- **patch 嵌入的 Conv3d**：Qwen2-VL 系列为了同时处理视频，patch 嵌入用的是核大小 (2, 14, 14) 的三维卷积，单张图像会被复制成两帧（`temporal_patch_size = 2`），第 24 章会看到。

## 19.10 深入一步

### ViT 学到了 CNN 的东西吗

研究表明（Raghu 等，2021），训练好的 ViT 浅层里，有些注意力头只看邻近的 patch（像卷积一样局部），有些头一开始就看全局；数据越多，越多的头学会了局部注意力。也就是说，**ViT 能从数据中学出卷积的归纳偏置**，但需要数据来"教"它；CNN 则是一开始就被"规定"了局部性。

### 为什么不用更小的 patch

patch 越小，token 越多，信息越细；但注意力的计算量与 token 数的平方成正比，patch 减半，token 变成 4 倍，注意力变成 16 倍。在 224×224 上，patch 16 是精度和计算的折中；VLM 里 patch 14–16 加上 2×2 合并，是视觉塔精度和语言模型序列长度之间的折中。对 OCR，更有效的做法通常是**提高输入分辨率**而不是减小 patch：同样的 patch 大小，分辨率翻倍，每个字符就覆盖更多的 patch。

### 掩码自编码器（MAE）

另一种不需要标签的 ViT 预训练方式：随机遮住 75% 的 patch，让模型从剩下的 25% 重建被遮住的像素。因为只把可见的 patch 送进编码器，训练很快。MAE 学到的特征擅长细节和定位，但和文字没有对齐；VLM 通常更偏好 CLIP 类的预训练（第 20 章），因为它的特征"懂"语言。

## 19.12 本章小结

- ViT 把图像切成 p×p 的 patch，每个 patch 拉平乘一个矩阵——等价于核大小 = 步长 = p 的卷积；
- 结构和 GPT 一样是 Transformer 块的堆叠，区别是**非因果**的注意力；分类用 CLS token 或平均池化，VLM 用所有 patch 的输出；
- 没有位置信息的 ViT 对 patch 的顺序是置换不变的：数得出物体，分不清左右；
- 二维位置编码有三种：可学习的表（换分辨率要插值）、二维正弦（直接重算）、二维 RoPE（一半维度按行转、一半按列转，分数只依赖行差和列差）；
- token 数与分辨率的平方成正比、与 patch 大小的平方成反比；注意力与线性层的计算量之比约为 N / 6d，高分辨率时注意力成为瓶颈；
- ViT 的归纳偏置比 CNN 少：大规模实验里数据少时不如 CNN、数据多时更好，但在具体任务上谁好取决于任务（我们的实验里 CNN 数物体更强，ViT 找最左边更强）；VLM 都用 ViT，因为它接口统一、能扩展、有 CLIP 预训练、能处理任意分辨率；
- 换分辨率时，插值的位置表和二维 RoPE 几乎不掉点，直接重算的二维正弦要外推，掉了 6 个百分点；
- 先找一个"不用关键信息也能达到"的基线再解读准确率：没有位置的 ViT 的 67.5% 正好是"猜最多的颜色"的水平。

## 参考答案

1. 核大小 = 步长 = p 时窗口恰好不重叠、无空隙，每个窗口就是一个 patch；每个输出通道在窗口上做的点积 = 拉平的 patch 乘以权重矩阵的一列。卷积权重 (d, C, p, p) 按 (C, p, p) 的顺序拉平，与 patchify 拉平 patch 的顺序一致。
2. 同一个 patch 的像素在内存里不连续（中间隔着其他 patch 的像素），直接 reshape 会把一行里相邻的若干个 patch 的同一行像素拼在一起。必须先把 H、W 拆成 (组, 组内)，permute 后再合并。
3. ViT 是编码器，不做逐个预测，没有"未来的答案"可偷看，每个 patch 看全部 patch 是合理的。
4. 能数（数物体不需要知道位置，只需要统计）；不能可靠地回答"最左边"（不知道 patch 之间的相对位置），只能靠"猜出现最多的颜色"之类的统计规律答对一部分。
5. 表的行数等于训练时的网格大小，新网格的 token 数不同就没有对应的行。插值后，新网格边缘的位置向量 ≈ 旧网格边缘的位置向量，表示的是"相对于整张图的比例位置"而不是绝对的像素距离。
6. 头维度 dh 组成 dh/2 个二维平面，前一半平面按行号旋转、后一半按列号旋转。每个平面上两个向量旋转后的点积只取决于旋转角之差，所以按行转的平面只依赖行差，按列转的只依赖列差。
7. CLS 不对应任何位置，转 0 度（cos = 1、sin = 0）让它的 q、k 不随位置变化。
8. CNN 有局部性、平移等变、层级结构的先验；ViT 只有 patch 内部的局部性。先验对的时候能节省数据，所以数据少时 CNN 更好；数据多时 ViT 不受先验限制，更灵活。
9. 448 / 14 = 32，32² = 1024 个 patch，合并后 256 个。
10. N/(6d) = 196 / 4608 = 0.043，注意力约占 4%；N = 4096 时 4096 / 4608 = 0.89，约占 47%。
11. 3 × 16 × 16 × 768 + 768 = 590,592。
12. ii、jj 是 (h, w) 的二维张量，直接乘以 (dh/4,) 的 theta 会按最后一维广播出错。要先拉平成 (h·w, 1)，乘出 (h·w, dh/4)，再拼接，最后还要按 apply_rope 的约定 cat([ang, ang])。
13. `F.interpolate` 要求输入是 (N, C, H, W)：通道在第 1 维、空间在最后两维。位置表变形后是 (1, h, w, d)，要把 d 挪到通道维。
14. 1 + h·w：第 0 行是 CLS 的（cos = 1、sin = 0），后面 h·w 行是 patch 的。
