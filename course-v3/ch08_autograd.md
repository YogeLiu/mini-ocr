# 第 8 章　自己写自动求导

## 本章在全景图中的位置

第 7 章的三个模型，梯度都是手推的。模型一复杂，手推就不现实了：一个 VLM 有几百层、几亿个参数，没有人能手推它的梯度。但第 5 章已经揭示了出路：**任何复杂的计算都是由简单运算一步步组成的，每个简单运算的导数都知道，链式法则把它们乘起来就行。** 把这件事交给计算机，就是**自动求导**（automatic differentiation，autograd）。

本章用一百多行 Python 写一个完整的自动求导引擎 `miniocr/nn/micrograd.py`，再用它搭一个多层感知机，训练它识别数字。写完以后，PyTorch 的 `loss.backward()` 对你来说就不再是魔法：第 9 章会看到，PyTorch 做的事情和我们的一模一样，只是每个节点是一个张量而不是一个数，并且用 C++/CUDA 实现。

## 学习目标

1. 能画出一个表达式的**计算图**，在图上做前向计算和反向传播；
2. 能为一个新运算写出它的局部导数（`_backward`），并用数值梯度验证；
3. 能解释为什么梯度要**累加**、为什么每步要**清零**、为什么要按**拓扑顺序的逆序**反向传播；
4. 能用自己的 `Value` 类搭出神经元、层和多层感知机，并训练它；
5. 能估算反向传播的代价，说出为什么"反向模式"适合神经网络。

## 8.1 计算图

### 把计算拆成小步

第 5 章的迷你神经元：

```
z = w·x + b
p = σ(z)
L = (p − y)²
```

再拆细一点，每一步只做一个最基本的运算：

```
t₁ = w · x            乘法
z  = t₁ + b           加法
p  = σ(z)             sigmoid
t₂ = p − y            减法
L  = t₂²              平方
```

把每个量画成一个节点，每个运算画成从输入指向输出的箭头，就得到一张**计算图**（computational graph）：

```
w ──┐
    (*)── t₁ ──┐
x ──┘          (+)── z ──(σ)── p ──┐
          b ───┘                   (−)── t₂ ──(²)── L
                              y ───┘
```

这是一张**有向无环图**（DAG，directed acyclic graph）：箭头有方向（从输入到输出），而且不会绕回来形成环——计算总是从已知的量算出新的量。

### 前向与反向

- **前向**（forward）：沿箭头方向，从输入算到输出 L。这就是普通的计算；
- **反向**（backward）：逆着箭头方向，从 `∂L/∂L = 1` 开始，一步步算出 L 对每个节点的导数。

反向时，每个节点只需要知道自己那一步运算的**局部导数**。比如 `z = t₁ + b`，局部导数是 `∂z/∂t₁ = 1`、`∂z/∂b = 1`。已知 `∂L/∂z` 后，由链式法则：

```
∂L/∂t₁ = ∂L/∂z · ∂z/∂t₁ = ∂L/∂z · 1
∂L/∂b  = ∂L/∂z · ∂z/∂b  = ∂L/∂z · 1
```

**每个运算只负责一件事：拿到输出的梯度，乘以自己的局部导数，交给自己的输入。** 整张图的梯度就这样一步步传回去。这就是**反向传播**（backpropagation）。

### 手算一遍

w = 0.5，x = 2，b = −0.3，y = 1（和第 5 章相同）。

**前向**：

| 节点 | 计算 | 值 |
|---|---|---|
| t₁ | 0.5 × 2 | 1.0 |
| z | 1.0 + (−0.3) | 0.7 |
| p | σ(0.7) | 0.6682 |
| t₂ | 0.6682 − 1 | −0.3318 |
| L | (−0.3318)² | 0.1101 |

**反向**（从 L 往回）：

| 节点 | 局部导数 | 梯度 = 上游梯度 × 局部导数 |
|---|---|---|
| L | — | 1 |
| t₂ | `∂L/∂t₂ = 2t₂` | 1 × 2 × (−0.3318) = −0.6636 |
| p | `∂t₂/∂p = 1` | −0.6636 |
| y | `∂t₂/∂y = −1` | 0.6636 |
| z | `∂p/∂z = p(1−p) = 0.2217` | −0.6636 × 0.2217 = −0.1471 |
| t₁ | 1 | −0.1471 |
| b | 1 | −0.1471 |
| w | `∂t₁/∂w = x = 2` | −0.1471 × 2 = −0.2943 |
| x | `∂t₁/∂x = w = 0.5` | −0.1471 × 0.5 = −0.0736 |

w 和 b 的梯度和第 5 章手算的完全一样。注意我们**顺便**得到了 L 对 x 和 y 的梯度——反向传播会算出图里**每个**节点的梯度。

## 8.2 Value：一个会记住"自己从哪来"的数

### 设计

我们写一个类 `Value`，它包装一个普通的数，并且记住四件事：

```python
class Value:
    def __init__(self, data, _prev=(), op=""):
        self.data = float(data)          # 值
        self.grad = 0.0                  # ∂L/∂(这个数)，反向传播后才有意义
        self._prev = tuple(_prev)        # 它是由哪些 Value 算出来的
        self._backward = lambda: None    # 反向时：把 self.grad 按局部导数分给 _prev
        self.op = op                     # 运算的名字，只用来打印
```

关键在于：**每次对 Value 做运算，都创建一个新的 Value，并让它记住输入是谁、以及反向时该做什么。** 这样，前向计算的同时，计算图就被自动记录下来了。

### 加法

```python
def __add__(self, other):
    other = other if isinstance(other, Value) else Value(other)   # 允许 Value + 3
    out = Value(self.data + other.data, (self, other), "+")

    def _backward():
        self.grad += out.grad            # ∂out/∂self = 1
        other.grad += out.grad           # ∂out/∂other = 1
    out._backward = _backward
    return out
```

逐行看：

- 定义了 `__add__`，`a + b` 就会调用 `a.__add__(b)`（第 1 章的特殊方法）；
- 如果 `other` 是普通的数，先包装成 Value；
- 新节点 `out` 的值是两者之和，`_prev` 记录了两个输入；
- `_backward` 是一个定义在 `__add__` 内部的函数。它能访问外面的 `self`、`other`、`out`——这种"记住了外部变量的内部函数"叫**闭包**（closure）。即使 `__add__` 已经返回，`out._backward` 被调用时仍然知道该把梯度传给谁；
- 加法的局部导数是 1，所以输入的梯度就是输出的梯度。

### 练习 8.1：乘法

`z = x · y` 的局部导数：`∂z/∂x = y`，`∂z/∂y = x`。

```python
def __mul__(self, other):
    other = other if isinstance(other, Value) else Value(other)
    out = Value(self.data * other.data, (self, other), "*")

    def _backward():
        self.grad += other.data * out.grad
        other.grad += self.data * out.grad
    out._backward = _backward
    return out
```

**直觉**：乘法的梯度是"交换"的——x 的梯度里有 y，y 的梯度里有 x。如果 x 是权重、y 是输入，那么权重的梯度正比于输入的大小：输入越大，这个权重对输出的影响越大。第 7 章 `∂L/∂W = Xᵀ(∂L/∂Z)` 里的 `Xᵀ`，就是这个"交换"在矩阵形式下的样子。

### 练习 8.2：一元函数

每个一元函数 `z = f(x)` 的局部导数就是 `f'(x)`：

| 运算 | 局部导数 | 写法 |
|---|---|---|
| `exp` | `eˣ = z` | `self.grad += out.data * out.grad` |
| `log` | `1/x` | `self.grad += (1.0 / self.data) * out.grad` |
| `tanh` | `1 − z²` | `self.grad += (1 - t * t) * out.grad` |
| `relu` | `x > 0 ? 1 : 0` | `self.grad += (1.0 if self.data > 0 else 0.0) * out.grad` |
| `x ** k`（k 是常数） | `k · x^(k−1)` | `self.grad += k * self.data ** (k - 1) * out.grad` |

注意 `exp` 和 `tanh` 用的是**输出**值 z 来算导数（`eˣ = z`，`1 − tanh² = 1 − z²`），省得重新计算。这是一个常见的技巧：前向时保存下来的中间结果，反向时直接用。代价是要把它们留在内存里——第 28 章会看到，训练大模型时**这些为反向保存的中间结果**（激活值）占了显存的大头。

### 组合出来的运算

减法、除法、取负、sigmoid 不需要自己的 `_backward`，它们可以由已有的运算组合出来：

```python
def __neg__(self):          return self * -1
def __sub__(self, other):   return self + (-other)
def __truediv__(self, other): return self * other ** -1      # 简化写法，见代码
def sigmoid(self):          return 1 / (1 + (-self).exp())
```

计算图会自动包含这些更基本的运算，梯度也就自动正确。演示第 1 部分打印了迷你神经元的完整计算图（`python -m labs.ch08.autograd_tour`）：

```
  L = 0.1101   dL/dw = -0.294268   dL/db = -0.147134   （第 5 章手算：-0.294268、-0.147134）
  这个小小的计算一共产生了 18 个节点：
     0     op=输入     data=   1.0000  grad=  -0.4434
     1  w  op=输入     data=   0.5000  grad=  -0.2943
     2  x  op=输入     data=   2.0000  grad=  -0.0736
     3     op=*      data=   1.0000  grad=  -0.1471
     4  b  op=输入     data=  -0.3000  grad=  -0.1471
     5  z  op=+      data=   0.7000  grad=  -0.1471
     6     op=输入     data=  -1.0000  grad=   0.1030
     7     op=*      data=  -0.7000  grad=   0.1471
     8     op=exp    data=   0.4966  grad=   0.2963
     9     op=输入     data=   1.0000  grad=   0.2963
    10     op=+      data=   1.4966  grad=   0.2963
    11     op=**-1   data=   0.6682  grad=  -0.6636
    12  p  op=*      data=   0.6682  grad=  -0.6636
    13  y  op=输入     data=   1.0000  grad=   0.6636
    14     op=输入     data=  -1.0000  grad=  -0.6636
    15     op=*      data=  -1.0000  grad=  -0.6636
    16     op=+      data=  -0.3318  grad=  -0.6636
    17  L  op=**2    data=   0.1101  grad=   1.0000
```

5 个"逻辑步骤"变成了 18 个节点：sigmoid 被拆成了取负（第 6、7 行：乘以 −1）、exp（第 8 行）、加 1（第 9、10 行）、求倒数（第 11 行）、乘以分子 1（第 0、12 行）；减法被拆成了乘 −1 再相加（第 14–16 行）。常数（−1、1）也是节点，它们也得到了梯度，只是没人用。和 8.1 节的手算表对照：w、x、b、z、p、y、L 的梯度完全一致。

**拆得细的好处是可靠**：只要每个最基本运算的导数是对的，任何组合都是对的。代价是节点多、慢。真实框架会给 sigmoid、softmax 这类常用的组合写一个"融合"的版本，直接用 `σ(1−σ)` 作为导数，节点少、更快、数值也更稳定（第 6 章"深入一步"）。

## 8.3 反向传播：拓扑排序

### 顺序为什么重要

调用一个节点的 `_backward` 时，它的 `grad` 必须已经是**最终值**——所有用到它的下游节点都已经把梯度传给它了。否则它往上游传的就是一个不完整的梯度。

看一个"菱形"的图：

```
         ┌─(×3)── b ──┐
x ─(×1)─ a              (×)── d
         └─(exp)─ c ──┘
```

a 被 b 和 c 两个节点用到。`∂d/∂a` 有两份：经过 b 的一份和经过 c 的一份。a 必须等两份都到齐了，才能往 x 传。

演示第 4 部分：

```
  d = (3a)·e^a，a = x·1，x = 2：正确的 dd/dx = 66.5015（= 3e² + 3·2·e² = 66.5015）
  错误顺序 (d, b, a, c) 得到 22.1672（= 3e² = 22.1672）：a 把梯度传给 x 时，c 那一份还没到
```

手算正确值：`d = 3a · eᵃ`，`dd/da = 3eᵃ + 3a·eᵃ`，a = 2 时 `= 3e² + 6e² = 9e² = 66.50`。错误的顺序里，a 在 c 之前反向，只把经过 b 的那份 `3e² = 22.17` 传给了 x。

### 拓扑排序

我们需要一个顺序，使得**每个节点都排在用到它的所有节点之后**（反过来说：每个节点排在它所有输入之后，然后把整个顺序倒过来）。这样的顺序叫**拓扑顺序**（topological order）。

### 练习 8.3：backward

```python
def backward(self):
    topo, visited = [], set()

    def build(v):
        if v not in visited:
            visited.add(v)
            for p in v._prev:          # 先把所有输入排好
                build(p)
            topo.append(v)             # 再排自己：保证自己在所有输入之后
    build(self)

    self.grad = 1.0                    # ∂L/∂L = 1
    for v in reversed(topo):           # 逆序：从 L 开始，每个节点都在用到它的节点之后被处理
        v._backward()
```

`build` 是一个**深度优先搜索**（DFS）：对每个节点，先递归处理它的所有输入，最后才把自己加进列表。所以列表里每个节点都排在它的输入之后。`visited` 集合保证每个节点只处理一次（菱形图里 a 会被 b 和 c 各访问一次，第二次直接跳过）。

**为什么逆序是对的？** 在 `topo` 中，一个节点 v 的所有"使用者"（以 v 为输入的节点）都排在 v 之后。逆序遍历时，它们都在 v 之前被处理，所以轮到 v 时，所有使用者都已经把梯度传给它了。

手动验证菱形图：`build(d)` → `build(b)` → `build(a)` → `build(x)`，x 入列；a 入列；b 入列；→ `build(c)` → a 已访问，c 入列；d 入列。`topo = [x, a, b, c, d]`，逆序 `[d, c, b, a, x]`：a 在 b 和 c 之后，正确。

> **递归深度**：Python 默认的递归深度上限约 1000。我们的 `build` 是递归的，计算图很深时（比如一个很长的循环）会报 `RecursionError`。真实框架用显式的栈来实现，没有这个限制。对本章的例子足够了。

## 8.4 两个经典 bug

### 梯度必须累加（+=）

如果一个节点被用了多次，它会从多个使用者那里收到梯度，**这些梯度要加起来**。这正是第 5 章多元链式法则的要求：x 通过多条路径影响 L 时，`∂L/∂x` 是各条路径之和。

演示第 2 部分：

```
  f = a·a + a，a = 3：自动求导 df/da = 7.0，手算 2a + 1 = 7
  用 = 代替 += 时，f = a·a 的 df/da = 3.0（应该是 2a = 6）：同一个节点作为两个输入，第二次赋值覆盖了第一次
```

`a * a` 时，`self` 和 `other` 是**同一个对象**。正确的写法里，`self.grad += a.data * 1` 和 `other.grad += a.data * 1` 各加一次 3，共 6；错误地用 `=` 时，第二次赋值覆盖了第一次，只剩 3。测试 `test_reused_node_accumulates` 专门检查这种情形。

在神经网络里，节点被多次使用是常态：同一个权重被批里的每个样本使用，同一个输入被下一层的每个神经元使用。

### 每步之前必须清零

累加带来一个后果：如果不清零，**第二次反向传播的梯度会加在第一次上面**。

```
  w = 1，第 0 次反向（不清零）：w.grad = 4.00（每次都应是 4(2w-1) = 4）
  w = 1，第 1 次反向（不清零）：w.grad = 8.00（每次都应是 4(2w-1) = 4）
  w = 1，第 2 次反向（不清零）：w.grad = 12.00（每次都应是 4(2w-1) = 4）
```

所以训练循环的每一步都是：**清零 → 前向 → 反向 → 更新**。

```python
def zero_grad(params):
    for p in params:
        p.grad = 0.0
```

PyTorch 也是这样设计的（`optimizer.zero_grad()`，第 9 章），而且"忘记清零"是 PyTorch 初学者最常见的 bug 之一：程序照常运行，只是梯度越来越大，训练表现得像学习率在不断变大。

**累加也有用处**：显存不够、批放不下时，可以把一批拆成几个小批，**分别**前向和反向、**不清零**，让梯度累加起来，最后更新一次。效果等价于一个大批。这叫**梯度累积**（gradient accumulation），第 18 章会用到。

## 8.5 用 Value 搭一个多层感知机

### 神经元、层、网络

```python
class Neuron:
    def __init__(self, n_in, rng, act="tanh"):
        s = 1.0 / math.sqrt(n_in)
        self.w = [Value(rng.uniform(-s, s)) for _ in range(n_in)]
        self.b = Value(0.0)
        self.act = act

    def __call__(self, x):
        z = sum((wi * xi for wi, xi in zip(self.w, x)), self.b)     # Σ w_i x_i + b
        return {"tanh": z.tanh, "relu": z.relu, "none": lambda: z}[self.act]()
```

- `__call__` 让对象可以像函数一样调用：`neuron(x)`；
- `sum(生成器, 起始值)`：从 `self.b` 开始，依次加上每个 `wi * xi`。每次加法都创建一个新的 Value，所以这一行就记录下了 `2 × n_in` 个节点；
- 权重初始化为 `[−1/√n_in, 1/√n_in]` 之间的均匀随机数。为什么要除以 √n_in？因为 z 是 n_in 项之和，项数越多，和的波动越大；除以 √n_in 让 z 的大小大致不随输入个数变化。第 11 章会详细推导。

### 练习 8.4：层与多层感知机

```python
class Layer:
    def __init__(self, n_in, n_out, rng, act="tanh"):
        self.neurons = [Neuron(n_in, rng, act) for _ in range(n_out)]
    def __call__(self, x):
        return [n(x) for n in self.neurons]
    def parameters(self):
        return [p for n in self.neurons for p in n.parameters()]

class MLP:
    def __init__(self, sizes, rng):
        self.layers = [Layer(a, b, rng, act="tanh" if i < len(sizes) - 2 else "none")
                       for i, (a, b) in enumerate(zip(sizes[:-1], sizes[1:]))]
    def __call__(self, x):
        for layer in self.layers:
            x = layer(x)
        return x
    def parameters(self):
        return [p for layer in self.layers for p in layer.parameters()]
```

一层是若干个神经元，它们接收同样的输入，各自输出一个数；网络是若干层串起来，上一层的输出是下一层的输入。**隐藏层**用非线性激活函数（这里是 tanh），**最后一层不加激活**——它输出 logits，交给交叉熵（第 6 章）。第 4 章说过，没有非线性激活，多层就等于一层。

`MLP([64, 16, 10])` 的参数个数：`64 × 16 + 16 + 16 × 10 + 10 = 1210`，和第 4 章的 `mlp_param_count` 一致。

一个样本的交叉熵损失 `cross_entropy_values` 也用 Value 写成，用到了第 6 章的减最大值技巧（最大值当作常数，不参与求导——因为 softmax 平移不变，它对结果没有影响，梯度也不需要经过它）。

### 训练

```python
for epoch in range(6):
    order = rng.permutation(len(Xtr))
    for s in range(0, len(order), bs):
        idx = order[s:s + bs]
        zero_grad(params)                                              # 1. 清零
        loss = sum((cross_entropy_values(net(list(Xtr[i])), int(ytr[i])) for i in idx),
                   Value(0.0)) / len(idx)                              # 2. 前向：一批的平均损失
        loss.backward()                                                # 3. 反向
        for p in params:
            p.data -= lr * p.grad                                      # 4. 更新
```

这四步就是**所有**神经网络训练循环的骨架。第 10 章的 PyTorch 版本会一一对应。

### 怎么读

1. **它能学**：6 轮之后测试准确率 100%。我们自己写的自动求导是对的；
2. **初始损失 2.585，比 ln 10 = 2.303 略高**：初始化的权重让 logits 不完全是 0，分布不是完全均匀的。这是可以接受的范围（第 6 章说的"远大于 ln K"才是问题）；
3. **一个样本的计算图有 4663 个节点**：`64 × 16` 个乘法、差不多同样多的加法、16 个 tanh、`16 × 10` 个乘法和加法、交叉熵的十几个节点……每个都是一个 Python 对象；
4. **极其慢**：每个样本 45 ms。第 7 章的 NumPy 代码每个样本只要约 3 微秒——快一万倍以上。原因是我们对**每个数**都创建一个 Python 对象，而 NumPy 对**整个数组**只做一次运算。

**解决方案很清楚：让计算图的每个节点是一个数组（张量），而不是一个数。** 一次矩阵乘法 `X @ W` 是一个节点，它的 `_backward` 就是第 7 章推导的 `∂L/∂W = Xᵀ(∂L/∂Z)`、`∂L/∂X = (∂L/∂Z)Wᵀ`。这正是 PyTorch 的设计，第 9 章开始使用。

## 8.7 常见错误

| 现象 | 原因 | 怎么查 |
|---|---|---|
| 某个参数的梯度总是只有正确值的一部分 | `_backward` 里用了 `=` 而不是 `+=` | 构造一个节点被重复使用的例子（`a * a`） |
| 梯度一步比一步大 | 每步之前没有清零 | 检查训练循环的第一步 |
| 梯度时对时错，取决于表达式的写法 | 反向的顺序不对（没做拓扑排序，或者没有逆序） | 用菱形图测试 |
| `RecursionError: maximum recursion depth exceeded` | 计算图太深，递归的 `build` 超出上限 | 改成显式栈；或者减小图的深度 |
| 修改了 `p.data` 之后梯度检查失败 | 数值梯度扰动参数后，没有重新做前向 | 每次扰动后重新构建计算图 |
| 对常数求导得到非零梯度，以为有 bug | 常数也是图里的节点，它们也会收到梯度，只是不被使用 | 正常现象 |

## 8.8 真实世界对照

- **PyTorch 的 autograd** 和本章的 `Value` 结构相同：每个张量有 `.grad`；由运算产生的张量有 `.grad_fn`（相当于我们的 `_backward` 加 `_prev`）；`loss.backward()` 做拓扑排序和逆序反向；梯度默认**累加**，所以要 `zero_grad()`。第 9 章会逐一对照；
- **叶子节点与 `requires_grad`**：PyTorch 只为标记了 `requires_grad=True` 的张量（参数）及其下游计算记录图，输入数据通常不需要梯度，可以省掉大量计算。我们的 Value 为每个节点都算了梯度（包括输入 x 和常数）；
- **冻结**：第 0 章说 VLM 的对齐阶段"冻结"视觉编码器和语言模型。在实现上，就是把这些参数的 `requires_grad` 设为 False：它们不收集梯度，也不更新。第 22、28 章会实测冻结能省多少显存和时间；
- **保存的中间结果**：`tanh`、`exp` 的反向需要前向的输出。一个大模型的前向会产生大量这样的中间结果，它们必须一直留在显存里，直到反向用完。第 28 章的**梯度检查点**（gradient checkpointing）用"反向时重新计算"换取"前向时不保存"，以时间换空间。

## 8.9 深入一步

### 反向模式为什么高效

设计算图有 n 个参数（输入）、1 个损失（输出）、总共 E 条边（运算）。

- **反向模式**：一次前向（E 次运算）+ 一次反向（每条边一次局部导数乘法，约 E 次），就得到了**所有** n 个参数的梯度。代价约是前向的 2–3 倍，**与 n 无关**；
- **数值梯度**（第 5 章）：每个参数 2 次前向，共 2nE；
- **前向模式**：从一个输入出发，沿着计算方向传播"这个输入的变化引起的变化"，一次得到所有输出对**这一个输入**的导数。n 个参数要做 n 次。

神经网络是"n 极大、输出只有 1 个"的情形，反向模式是唯一可行的选择。反过来，如果输入少、输出多（比如一个函数把 1 个数变成 1000 个数），前向模式更划算。

### 计算图里的"转置"

对线性运算 `z = Wx`（W 是矩阵），前向是"乘以 W"，反向是"乘以 Wᵀ"：`∂L/∂x = Wᵀ (∂L/∂z)`。这不是巧合：反向传播本质上是在计算**雅可比矩阵的转置**乘以梯度向量（向量-雅可比积，vector-Jacobian product）。每个运算只需要提供"给我输出的梯度，我返回输入的梯度"这个函数，而不需要真的构造雅可比矩阵——对一个 `(1024, 1024)` 的逐元素运算，雅可比矩阵有 10⁶ × 10⁶ 个元素，但向量-雅可比积只需要 10⁶ 次乘法。

### 广播的反向：求和

选做题 6 里会遇到：前向时，偏置 b（形状 `(K,)`）被广播加到 `(N, K)` 的每一行。反向时，b 的梯度是什么？b 的每个元素被用了 N 次（每一行一次），根据"多次使用要累加"，它的梯度是 `∂L/∂Z` 沿第 0 维的**求和**：`G.sum(0)`。这正是第 7 章 softmax 回归里 `∂L/∂b = G.sum(0)` 的来历。一般规则：**前向时被广播的维度，反向时要沿那一维求和**。PyTorch 内部自动处理了这件事。

## 8.10 横向对照：自动求导的几种实现方式

| 方式 | 怎么做 | 代表 | 特点 |
|---|---|---|---|
| 动态图（define-by-run） | 每次前向时现场记录计算图，用完就扔 | PyTorch、本章的 Value | 灵活，可以用普通的 Python 控制流（if、for），调试方便 |
| 静态图（define-then-run） | 先定义好整张图，再编译、反复执行 | 早期 TensorFlow | 可以做全局优化，但写起来不直观 |
| 函数变换 | 把"求梯度"看作一个把函数变成另一个函数的操作：`grad(f)` | JAX | 函数式风格，易于组合（求高阶导、向量化） |
| 编译 | 先像动态图一样写，再把它捕获、编译成高效的程序 | `torch.compile` | 兼顾灵活和速度 |

本书全程使用 PyTorch 的动态图，它的行为和本章的 Value 最接近。

## 8.11 本章小结

- 计算图：节点是值，边是运算；前向沿边算值，反向逆着边算梯度；
- 每个运算只需要知道自己的局部导数：拿到输出的梯度，乘以局部导数，交给输入；
- 加法把梯度原样传下去，乘法把梯度乘以"另一个输入"；
- 梯度必须**累加**（一个节点可能被多次使用）；每步之前必须**清零**；
- 反向必须按**拓扑顺序的逆序**进行（深度优先搜索得到拓扑顺序）；
- 训练循环四步：清零 → 前向 → 反向 → 更新；
- 标量版的自动求导正确但极慢（每样本 45 ms）；把节点换成张量就是 PyTorch；
- 反向模式的代价约是前向的 2–3 倍，与参数个数无关——这是训练大模型的基础。

## 参考答案

1. 链式法则把整体的导数分解为沿路径的局部导数之积。每个运算拿到"损失对我的输出的导数"后，乘以自己的局部导数，就得到"损失对我的输入的导数"，不需要知道图的其他部分。
2. 因为一个节点可能被多个运算使用，损失通过多条路径依赖它，它的总梯度是各条路径梯度之和。例子：`f = a * a`，用 `=` 时第二次赋值覆盖第一次，得到 a 而不是 2a。
3. 梯度在每步之间累加，越来越大，效果类似学习率不断增大：训练开始可能还正常，随后损失震荡、上升甚至变成 nan。
4. 反向模式一次前向加一次反向就得到所有参数的梯度，代价与参数个数无关；数值梯度对每个参数都要做两次完整的前向计算。
5. 前向：`ab = −2`，`bc = −4`，`f = −6`。反向：`∂f/∂a = b = −1`；`∂f/∂c = b = −1`；`∂f/∂b = a + c = 6`（两条路径之和）。
6. `∂f/∂w = (1 − tanh²(1)) · x = (1 − 0.58) × 2 ≈ 0.840`。
7. `784 × 128 + 128 + 128 × 10 + 10 = 101,770`。乘法节点约 `784 × 128 + 128 × 10 = 101,632` 个（每个权重与输入的乘积一个），再加上交叉熵里的少量乘法。
8. 两个错误：(a) 局部导数应该用对方的**值**（`other.data`、`self.data`），而不是对方的**梯度**；(b) 没有处理 `other` 是普通数字的情况（`Value * 3` 会因为 `3.data` 报错）。
9. ```python
   def __pow__(self, other):
       other = other if isinstance(other, Value) else Value(other)
       out = Value(self.data ** other.data, (self, other), "**")
       def _backward():
           self.grad += other.data * self.data ** (other.data - 1) * out.grad
           other.grad += out.data * math.log(self.data) * out.grad     # 要求 self.data > 0
       out._backward = _backward
       return out
   ```
10. 少了每步开始时的梯度清零（`zero_grad(net.parameters())`），梯度会在步与步之间累加。
