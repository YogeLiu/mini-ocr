## 16.1 整体结构

```
token 编号 (B, T)
  │ 嵌入：查表，每个 token 一个 d 维向量
  ▼
x (B, T, d)  ← 这条"主干"叫残差流
  │
  ├─ 第 1 块：x = x + Attn(RMSNorm(x))      注意力：从其他位置收集信息
  │           x = x + MLP(RMSNorm(x))       MLP：在每个位置内部加工信息
  ├─ 第 2 块：同上（参数不同）
  │   …
  ├─ 第 L 块
  ▼
RMSNorm → 线性层（与嵌入共享权重）→ logits (B, T, V)
```

**残差流**（residual stream）是理解 Transformer 的关键概念。x 从嵌入出发，一路向上流动，每个块不"替换"它，而是往上面**加**一点东西：注意力加上从别的位置收集来的信息，MLP 加上对当前信息的加工结果。最后一层的 x 包含了所有块的贡献，用来预测下一个 token。

这和第 11 章的残差网络是同一个思想：加法让梯度可以直接从输出流回任何一层，深层网络才训练得动。

### Pre-Norm 与 Post-Norm

原始 Transformer（2017）是 **Post-Norm**：x = Norm(x + Attn(x))，归一化在残差相加**之后**。GPT-2 起改成 **Pre-Norm**：x = x + Attn(Norm(x))，归一化只作用于支路的输入，残差流本身不被归一化。

Pre-Norm 的好处：残差流是一条"干净"的加法通路，从输出到嵌入的梯度路径上没有任何归一化层，深层也能稳定训练，对学习率和预热不那么敏感。Post-Norm 的每一层都要经过归一化，梯度在深层容易出问题，通常需要仔细的学习率预热。今天几乎所有大模型都用 Pre-Norm。

Pre-Norm 的残差流不断累加，越往上数值越大，所以最后要加一个归一化（`self.norm`）再接输出层。

## 16.2 RMSNorm

### 练习 16.1

```python
class RMSNorm(nn.Module):
    def __init__(self, d, eps=1e-6):
        super().__init__()
        self.eps = eps
        self.weight = nn.Parameter(torch.ones(d))

    def forward(self, x):
        return x * torch.rsqrt(x.pow(2).mean(-1, keepdim=True) + self.eps) * self.weight
```

```
RMSNorm(x) = x / √(mean(x²) + ε) · γ
```

与第 11 章的 LayerNorm 相比：

| | LayerNorm | RMSNorm |
|---|---|---|
| 减均值 | 是 | 否 |
| 除以 | 标准差 √(mean((x−μ)²) + ε) | 均方根 √(mean(x²) + ε) |
| 可学习参数 | γ 和 β | 只有 γ |

实验发现减均值这一步对效果几乎没有帮助，去掉它少一次求均值、少一组参数，速度快一些。Llama、Qwen 都用 RMSNorm。

- `torch.rsqrt` 是 1/√x，一次运算；
- 测试 `test_rmsnorm` 检查归一化后均方根为 1、均值**不**为 0。

## 16.3 RoPE：旋转位置编码

第 15 章说过，自注意力不知道顺序，要加位置信息。第 15 章用的是可学习的位置嵌入（加到输入上）。它有两个缺点：只能处理训练时见过的长度；位置信息混在残差流里，到了深层可能被冲淡。

**RoPE**（rotary position embedding，2021）换一种思路：不改输入，而是在计算注意力分数**之前**，把 q 和 k 按各自的位置旋转一个角度。

### 二维的情况

先看 dh = 2。把 q 看成平面上的一个点，位置 m 的查询旋转 mθ，位置 n 的键旋转 nθ：

```
R(α) = [[cos α, −sin α],
        [sin α,  cos α]]

q' = R(mθ) q,   k' = R(nθ) k
```

注意力分数：

```
q' · k' = (R(mθ) q)ᵀ (R(nθ) k) = qᵀ R(mθ)ᵀ R(nθ) k = qᵀ R(−mθ) R(nθ) k = qᵀ R((n − m)θ) k
```

用到了两个性质：旋转矩阵的转置是反向旋转 R(α)ᵀ = R(−α)；连续两次旋转等于角度相加 R(α) R(β) = R(α + β)。

结论：**分数只依赖 q、k 本身和相对位置 n − m**，与绝对位置无关。位置 5 的查询看位置 2 的键，和位置 13 看位置 10，只要内容相同，分数就相同。这正是语言需要的性质："前一个字符"的含义在句首和句中是一样的。

### 高维：多个频率

dh 维的向量分成 dh/2 对，每一对是一个二维平面，各自以不同的**频率**旋转：

```
θ_i = base^(−2i/dh),   i = 0, 1, …, dh/2 − 1
```

base = 10000、dh = 64 时，θ_0 = 1（每个位置转 1 弧度，约 57°），θ_31 = 10000^(−62/64) ≈ 1.3 × 10⁻⁴（转一圈要约 47000 个位置）。

为什么要多个频率？只用一个频率时，角度每 2π/θ 个位置就绕回来一次，模型分不清"相距 1"和"相距 1 + 2π/θ"。高频的维度对近距离敏感（相邻位置的角度差大），低频的维度能区分远距离。这和钟表用时针、分针、秒针表示时间是一个道理。

### "前后两半"的约定

哪两个维度组成一对？原始论文是相邻的 (0, 1)、(2, 3)……Llama 和 Qwen 的实现用的是 (0, dh/2)、(1, dh/2 + 1)……即前一半和后一半配对。两种约定数学上等价（只是维度的排列不同），但**加载预训练权重时必须用和训练时相同的约定**，否则模型完全失效。我们跟随 Qwen 的约定，第 24 章可以直接对照。

### 练习 16.2

```python
def rope_cache(T, dh, base=10000.0, device=None):
    inv = base ** (-torch.arange(0, dh, 2, dtype=torch.float32, device=device) / dh)    # (dh/2,)
    ang = torch.arange(T, dtype=torch.float32, device=device)[:, None] * inv[None]       # (T, dh/2)
    ang = torch.cat([ang, ang], -1)
    return ang.cos(), ang.sin()


def rotate_half(x):
    x1, x2 = x.chunk(2, -1)
    return torch.cat([-x2, x1], -1)


def apply_rope(x, cos, sin):
    return x * cos + rotate_half(x) * sin
```

验证 `apply_rope` 确实是旋转。取第 i 维（前一半）和第 i + dh/2 维（后一半），记为 (a, b)，角度 φ：

- 第 i 维：a · cos φ + (rotate_half 的第 i 维 = −b) · sin φ = a cos φ − b sin φ；
- 第 i + dh/2 维：b · cos φ + (rotate_half 的第 i + dh/2 维 = a) · sin φ = a sin φ + b cos φ。

正是 (a, b) 逆时针旋转 φ。整个运算是逐元素的乘法和加法，不需要构造旋转矩阵。

- `torch.cat([ang, ang], -1)`：第 i 维和第 i + dh/2 维用同一个角度；
- cos、sin 表只与位置和维度有关，模型创建时算一次，存成 buffer（`persistent=False`：不存进 state_dict，因为随时可以重算）；
- RoPE 只加在 q、k 上，**不加在 v 上**：位置只影响"看哪里"，不影响"取回什么"。

测试 `test_rope_rotation_and_relative_position` 检查三件事：旋转不改变向量长度；位置 (5, 2) 和 (13, 10) 的点积相同（相对距离都是 3）；位置 (5, 2) 和 (5, 4) 不同。

    drop = self.dropout if self.training else 0.0

        y = F.scaled_dot_product_attention(q, k, v, is_causal=True, dropout_p=drop)

    return self.o(y.transpose(1, 2).reshape(B, T, d))
```

与第 15 章的 `MultiHeadAttention` 相比：

- **一个大矩阵算 q、k、v**：`self.qkv` 是 d → 3d 的线性层，一次矩阵乘法得到三者，比三次小乘法快。`view(B, T, 3, h, dh)` 把 3d 维拆成"3 份 × h 个头 × dh 维"，`permute(2, 0, 3, 1, 4)` 变成 (3, B, h, T, dh)，解包成 q、k、v；
- **没有偏置**（`bias=False`）：现代大模型普遍去掉线性层的偏置，几乎不影响效果，参数和计算都少一点。（Qwen2 的 q、k、v 投影有偏置，Qwen3 去掉了；不同模型的选择不同，加载权重时要看清楚。）
- **`F.scaled_dot_product_attention`**：PyTorch 的融合实现，在 GPU 上会自动选择 FlashAttention（第 15 章），在 CPU 上也比手写的快。数学上和第 15 章的 `attention()` 完全相同；
- **RoPE 在拆头之后加**：每个头的 dh 维各自旋转。

## 16.5 SwiGLU

原始 Transformer 和 GPT-2 每个块里的 MLP 是 d → 4d → d 两个线性层，中间是 **GELU** 激活（`miniocr/nn/attention.py` 里的 `Block` 就是这种写法，第 15 章正文没有用到它）。GELU(z) = z · Φ(z)，Φ 是标准正态分布的累积分布函数：z 很大时 Φ ≈ 1、GELU ≈ z，z 很负时 Φ ≈ 0、GELU ≈ 0，可以看成 ReLU 的平滑版本。现代模型改用**门控**的 MLP：

```python
class SwiGLU(nn.Module):
    def __init__(self, cfg):
        super().__init__()
        f = cfg.ff_dim()
        self.gate = nn.Linear(cfg.d_model, f, bias=False)
        self.up = nn.Linear(cfg.d_model, f, bias=False)
        self.down = nn.Linear(f, cfg.d_model, bias=False)

    def forward(self, x):
        return self.down(F.silu(self.gate(x)) * self.up(x))
```

```
SwiGLU(x) = W_down · (silu(W_gate x) ⊙ W_up x)
silu(z) = z · σ(z)
```

- 两条支路：`up` 是普通的线性变换；`gate` 经过 silu 后逐元素地乘上去，决定每个维度"放行多少"。这和第 13 章 LSTM 的门是同一个思想；
- silu（也叫 swish）是 ReLU 的平滑版本：z 很大时 ≈ z，z 很负时 ≈ 0，在 0 附近平滑过渡，还允许少量负值通过；
- **中间维度为什么是 8d/3**：SwiGLU 有三个矩阵，普通 MLP 有两个。为了参数量相同，3 · d · f = 2 · d · 4d，f = 8d/3。我们取 8 × 256 / 3 = 682.7，向上取整到 64 的倍数得 704（对齐到 64 的倍数让矩阵乘法在硬件上更高效）。Qwen3-0.6B 的 d = 1024，f = 3072 = 3d，比 8d/3 略大。

为什么门控更好？经验结论：在同样参数量下，SwiGLU 的语言模型损失稳定地低一些。一种直觉是乘法让网络能表达"如果 A 且 B"这类交互，普通 MLP 只有加法和逐元素的非线性。

class Block(nn.Module):

### 练习 16.4：GPT 的前向

```python
def forward(self, idx=None, targets=None, inputs_embeds=None, caches=None, pos0=0, loss_mask=None):
    x = self.tok(idx) if inputs_embeds is None else inputs_embeds
    T = x.shape[1]
    assert pos0 + T <= self.cfg.block_size, f"序列长 {pos0 + T} 超过 block_size {self.cfg.block_size}"
    cos, sin = self.cos[pos0:pos0 + T], self.sin[pos0:pos0 + T]
    for i, b in enumerate(self.blocks):
        x = b(x, cos, sin, None if caches is None else caches[i])
    logits = self.head(self.norm(x))
    loss = None
    if targets is not None:
        if loss_mask is not None:
            targets = targets.masked_fill(~loss_mask, -100)
        loss = F.cross_entropy(logits.reshape(-1, logits.shape[-1]).float(), targets.reshape(-1), ignore_index=-100)
    return logits, loss
```

- **`inputs_embeds`**：第 22 章会把图像特征（已经变成 d 维向量）和文字的嵌入拼在一起直接送进来；
- **`pos0`**：RoPE 表从哪个位置开始取。整段输入时是 0；第 17 章用 KV cache 逐个生成时，新 token 的位置接在历史后面；
- **`targets` 中的 −100**：`F.cross_entropy` 的 `ignore_index` 约定，这些位置不计入损失。第 26 章做监督微调时，只在"回答"部分计算损失，提示部分标成 −100；
- **`.float()`**：混合精度训练时 logits 可能是 bf16，交叉熵在 float32 下计算更准确（第 11 章）；
- **训练目标**：targets 就是输入错开一位（第 18 章的 `get_batch`）。一次前向，T 个位置同时计算"预测下一个"的损失，这正是第 15 章因果 mask 的用武之地。

### 权重共享

```python
if cfg.tie_weights:
    self.head.weight = self.tok.weight
```

输出层（d → V）的权重矩阵是 V × d，嵌入矩阵也是 V × d。**权重共享**（weight tying）让它们是同一个矩阵：

- 嵌入：token v 的向量是第 v 行 e_v；
- 输出：token v 的 logit 是 h · e_v（最后一层的向量和 e_v 的点积）。

直觉：如果一个 token 的嵌入表示"它的含义"，那么预测它的时候，模型输出的向量应该和这个含义相近。共享省下 V × d 个参数：词表大时这很可观（Qwen3-0.6B 的嵌入有 1.56 亿参数，占 26%）。Qwen3 的小模型（0.6B、1.7B、4B）共享权重，大模型不共享。

`n_params()` 用 `self.parameters()` 求和，PyTorch 对同一个参数只返回一次，所以共享的矩阵只算一次。

### 初始化

```python
self.apply(self._init)                                 # 所有线性层和嵌入：N(0, 0.02²)
for n, p in self.named_parameters():
    if n.endswith("o.weight") or n.endswith("down.weight"):
        nn.init.normal_(p, 0.0, 0.02 / math.sqrt(2 * cfg.n_layer))
```

- 标准差 0.02 是 GPT-2 沿用下来的经验值（d = 768 时，约等于 1/√(3d)，与第 11 章的初始化分析一致）；
- 每个块往残差流里加两次（注意力和 MLP），L 层共 2L 次。残差支路的**输出层**（注意力的 `o` 和 MLP 的 `down`）再缩小 √(2L) 倍，使 2L 次相加的总方差不随层数增长。

## 16.7 数参数

演示第 1 部分（`python -m labs.ch16.gpt_tour 1`）：

```
  配置：词表 100，d = 256，4 层，4 个头（每头 64 维），SwiGLU 中间维 704，上下文 512
    嵌入            100 × 256 = 25,600（输出层与它共享，不另算）
    每层注意力      4 × 256² = 262,144（Wq、Wk、Wv、Wo，无偏置）
    每层 SwiGLU     3 × 256 × 704 = 540,672（gate、up、down）
    每层两个 RMSNorm 2 × 256 = 512
    合计            25,600 + 4 × 803,328 + 256（最后的 RMSNorm）= 3,239,168
  m.n_params() = 3,239,168  一致
```

词表是 100：可打印 ASCII 的 95 个字符、换行，加 4 个特殊符号（`<pad>`、`<bos>`、`<eos>`、`<img>`）。为什么用字符级而不是第 14 章的 BPE？

1. 我们的 VLM 最终要输出 OCR 的结果，字符级让 OCR 的错误直接对应到字符，CER 的计算也最直接；
2. 字符表固定（`text_vocab()` 不依赖语料），第 16 章预训练和第 22 章的 VLM 永远用同样的编号；
3. 序列长度：一行文字十几个字符，一个公式几十个字符，字符级完全够用。

真实模型用 BPE（第 14 章），词表 15 万，序列短得多。这是规模不同带来的不同选择。

**每层 80 万参数，SwiGLU 占 2/3**。这在大模型里也成立：MLP 的参数是注意力的两倍左右。

对照 Qwen3-0.6B（按它公开的 config.json 计算，不需要下载）：

```
  对照 Qwen3-0.6B（按它的 config.json 计算）：嵌入 155.6M，每层注意力 6.29M + SwiGLU 9.44M，
    28 层合计 440.5M，总计 596.0M ≈ 0.6B（与名字一致）；嵌入占 26%

Qwen3-0.6B 的注意力有一个特别之处：16 个头 × 每头 128 维 = 2048，**大于** d = 1024。所以 Wq 是 1024 × 2048，Wo 是 2048 × 1024。头的维度和 d 不必满足 h × dh = d。

## 16.8 初始化体检

第 2 部分（第 10 章的体检清单：初始损失应该约等于 ln V）：

```
  初始损失：预测下一个字符 4.629，随机目标 4.695，ln 100 = 4.605
  如果目标就是当前字符本身：2.662——明显更低。原因：输出层与嵌入共享权重，
  最后一层的向量 h_t 里有残差带来的 e(x_t)，logit_{x_t} = ⟨norm(h_t), e(x_t)⟩ ≈ ‖e‖²·缩放，比别的 logit 大。
  所以刚初始化的模型偏爱"重复当前字符"；训练很快就会改掉这个偏好
  各层输出（残差流）的标准差：[0.0243, 0.032, 0.0399, 0.0499]；嵌入初始化标准差 0.02
```

**初始损失 4.629 ≈ ln 100 = 4.605**：模型刚初始化时对每个字符几乎一视同仁。✓

**一个有趣的现象**：如果让模型预测"当前字符本身"（而不是下一个），损失只有 2.662，远低于 ln 100。

原因在权重共享。刚初始化时，各个块加到残差流上的东西很小，最后一层的 h_t 主要还是嵌入 e(x_t)。输出 logit_v = norm(h_t) · e_v。对 v = x_t，这是 e(x_t) 和（放大后的）自己的点积，等于 ‖e‖² 乘一个放大系数；对其他 v，是两个随机向量的点积，接近 0。所以"当前字符"的 logit 明显最大。RMSNorm 把 h 放大到均方根 1（原来只有 0.02 左右），放大了约 50 倍，使这个效应更明显。

这个偏好对预测下一个字符不利（下一个字符通常和当前字符不同），但影响不大（4.629 vs 4.605），训练开始几步就会被纠正。它提醒我们：**权重共享不只是省参数，它还给模型带来了一种结构上的先验**。

**残差流的增长**：4 层后从 0.024 增长到 0.050。每层加的量与嵌入同一数量级；没有 0.02/√(2L) 的缩放，这个增长会是 √8 ≈ 2.8 倍快。

（配置里的"上下文 512"是 RoPE 表的长度；训练只用长 256 的窗口。多出来的一半是为了 16.10 节的实验，也给第 22 章的 VLM 留了余地：图像特征拼在文字前面，序列会变长。）

## 16.9 预训练

### 数据与训练配置

`miniocr/train/lm.py` 的 `train_lm` 是一个完整的语言模型训练循环：

```python
def get_batch(ids, B, T, g, device="cpu"):
    s = torch.randint(0, len(ids) - T - 1, (B,), generator=g)
    off = torch.arange(T + 1)
    w = ids[s[:, None] + off]
    return w[:, :-1].to(device), w[:, 1:].to(device)
```

这是练习 16.5：从整个训练语料（一个长长的 token 序列）里随机截取 B 个长 T+1 的窗口，前 T 个是输入，后 T 个是目标（错开一位）。`s[:, None] + off` 是广播：(B, 1) + (T+1,) → (B, T+1) 的下标矩阵，一次取出所有窗口。

窗口可以从任何位置开始，也可以跨越两段文档的边界（中间是空行 `\n\n`）。这和真实的预训练一样：大模型也是把所有文档拼起来，切成固定长度的块。模型会学到"空行之后是新的一段"。

训练循环的其他部分都是前几章学过的：

- **AdamW**，β = (0.9, 0.95)（语言模型常用 0.95 而不是 0.999：v 对梯度变化的反应更快，训练更稳），权重衰减 0.1；
- **权重衰减只作用于矩阵**：`p.dim() >= 2` 的参数（线性层、嵌入）衰减，RMSNorm 的 γ 不衰减。γ 是缩放系数，把它往 0 拉没有道理；
- **学习率**：100 步线性预热到 3 × 10⁻³，然后余弦衰减到 3 × 10⁻⁴（第 11 章的 `warmup_cosine`）；
- **梯度裁剪** 1.0；
- **验证**：每 250 步在验证语料上取 20 个固定的批（固定种子，每次是同样的窗口）求平均损失。

训练语料是 `mixed_corpus(0, 20000)`：约 300 万个字符，前 4000 段就是第 14 章的训练语料。验证语料和第 14 章完全相同（`mixed_corpus(1, 400)`），所以 bits/char 可以直接比较。

### 结果

第 3 部分（CPU 上约 10 分钟）：

```
3. 预训练：3000 步 × 批 16 × 长 256 = 12.3M 个字符 token
    第   250 步  训练 1.8665  验证 1.3801 nat/字符 = 1.991 bits/字符
    第   500 步  训练 1.3222  验证 1.3071 nat/字符 = 1.886 bits/字符
    第  1000 步  训练 1.2742  验证 1.2820 nat/字符 = 1.850 bits/字符
    第  2000 步  训练 1.2388  验证 1.2522 nat/字符 = 1.807 bits/字符
    第  3000 步  训练 1.2231  验证 1.2397 nat/字符 = 1.789 bits/字符
  每个字符 token 平均被看了 4.1 遍
  对照：同样 2 万段训练的字符 5 元模型 2.187 bits/字符；第 14 章最好的结果（4000 段，BPE 3 元）2.404
```

（训练损失一栏是最近 250 步的平均。第 250 步的训练损失 1.87 高于验证损失 1.38，是因为它包含了最开始损失还很高的那些步。）

- **1.789 bits/字符**，比第 14 章最好的 n 元模型（2.404）低 0.6 bits，比同样数据训练的字符 5 元模型（2.187）低 0.4 bits。换算成困惑度：每个字符的"犹豫范围"从 2^2.187 = 4.6 个降到 2^1.789 = 3.5 个；
- **前 500 步就降到了 1.89**，之后进展缓慢。再训练 2500 步只降了 0.1；
- **训练损失和验证损失几乎相等**（1.223 vs 1.240）：没有过拟合。300 万个字符只被看了 4 遍，320 万参数的模型远没到记住训练集的程度。

**为什么停在 1.79？** 我们的语料是**随机**生成的：句子由 446 个常用单词均匀随机地组成（第 14 章 14.1 节）。下一个单词是哪个，本来就无法预测：从 446 个里均匀选一个，信息量是 log₂ 446 ≈ 8.8 bits；一个单词加上后面的空格平均约 5–6 个字符，平均到每个字符约 1.5 bits。加上数字（随机的）、公式里随机的变量和运算，语料本身的熵大约就在 1.5 bits/字符以上。我们的模型已经离这个下限不远了：它学会了单词的拼写、句子和表格的格式、LaTeX 的语法，剩下的是**无法学习的随机性**。

这是合成数据的特点。真实语言有丰富的结构（语法、语义、常识），大模型能把损失降得低得多，而且越大越低（第 18 章的缩放定律）。

## 16.10 RoPE 不能自动外推到更长的序列

训练时窗口长 256。如果给它更长的输入呢？第 3 部分把验证语料切成长 512 的块，统计每个位置的平均损失：

```
  按位置统计（116 个长 512 的块；训练时只见过位置 0–255）：
    位置 0–7: 2.314  位置 8–63: 1.710  位置 64–255: 1.751  位置 256–287: 1.767  位置 288–383: 3.305  位置 384–511: 4.933
  前 256 个位置（与训练相同的长度）平均 1.760 bits/字符；开头几个字符没有上下文，损失高
```

- **位置 0–7**：开头几个字符几乎没有上下文，损失高（2.31），这是正常的；
- **位置 8–255**：1.71–1.75，正常；
- **位置 256–287**：1.77，刚超出训练长度一点，还能应付；
- **位置 288–383**：3.31，显著变差；
- **位置 384–511**：4.93，比只看字符频率的 unigram 模型（第 14 章约 5.15）好不了多少。模型基本失效了。

为什么？16.3 节说 RoPE 让分数只依赖**相对**位置——那么位置 400 和位置 100 不应该一样吗？问题在于：位置 400 的查询会和位置 0–399 的所有键计算分数，其中**相对距离 257–400** 的那些，训练时从来没见过。最低频的维度在距离 400 时转过的角度，训练中从没出现过；模型对这些"没见过的旋转"给出的分数是随机的，可能把很大的权重分给很远处无关的位置，于是整个注意力乱了。

第一次实验我们用的是 128 的训练窗口，在 128 以外得到同样的结论（位置 160–255 损失 4.45）。这正是我们把训练窗口改成 256 的原因：VLM 的序列 = 图像特征 + 文字，必须在训练长度以内。

真实模型怎样处理更长的输入？

1. **用更长的序列训练**：最直接。Qwen3 预训练的大部分阶段用 4096 的长度，最后一个阶段延长到 32768；
2. **RoPE 缩放**：推理时把位置"压缩"（位置插值：所有角度乘以训练长度 / 目标长度），或者只压缩低频维度（NTK 缩放、YaRN），再用少量长文本微调。Qwen 用 YaRN 把上下文从 32K 扩展到 128K。

**教训**：模型只在训练分布之内可靠。"位置"也是分布的一部分。

## 16.12 对照实验

第 5 部分把几个设计各改一处，各训练 800 步（预训练的 1/4），比较验证损失：

```
    基线（RoPE、共享权重）          参数 3,239,168  验证 1.815 bits/字符  （103 秒）
    不加位置信息                 参数 3,239,168  验证 2.758 bits/字符  （97 秒）
    输出层不共享权重               参数 3,264,768  验证 1.811 bits/字符  （98 秒）
    2 层 × d 352            参数 3,055,712  验证 1.821 bits/字符  （78 秒）
    8 层 × d 176            参数 3,174,512  验证 1.807 bits/字符  （139 秒）
```

**不加位置信息**：2.758 bits，比基线差了近 1 bit，比第 14 章的字符 3 元模型（2.571）还差。没有位置信息，模型连"上一个字符是什么"都很难知道——上一个字符只是"所有之前的字符"之中的一个，模型分不出哪个是最近的。

但它也不是完全不知道顺序：比 unigram（5.15）好得多。因果 mask 打破了第 15 章说的置换对称：位置 t 能看到 t+1 个 token，一个"均匀看所有位置"的头，得到的平均值的"稀释程度"随 t 变化，模型可以从中间接推断出位置。研究发现，大模型不加任何位置编码（NoPE）也能工作得不错，正是这个原因。但对于需要精确局部信息的任务（比如拼写），显式的位置编码仍然重要得多。

**不共享权重**：1.811 vs 1.815，几乎没有区别。我们的词表只有 100，嵌入只占 0.8% 的参数，共享与否影响很小。词表 15 万时，共享能省下 1.5 亿参数（Qwen3-0.6B 的 26%），意义就大了。

**深度与宽度**：参数量大致相同时，8 层 × 176 维（1.807）略好于 4 层 × 256 维（1.815），2 层 × 352 维（1.821）略差。差别不大（0.01–0.02 bits），但方向和大模型的经验一致：在一定范围内，更深的模型效果更好——每一层都可以在前一层的基础上组合出更复杂的模式（16.13 节的括号匹配就需要多层配合）。代价是速度：8 层比 4 层慢 35%，因为层是串行计算的，而宽度可以并行。真实模型在两者之间折中：Qwen3-0.6B 是 28 层 × 1024 维。

## 16.13 注意力在看哪里

第 6 部分：在验证语料的 69 个公式里，找出所有"下一个字符是 `}`"的位置，看每个头分给**配对的** `{`（还没有关上的那个）多少权重。

### 第一次分析：看起来很好

```
  69 个验证公式里，下一个字符是 } 的位置共 289 个；配对的 { 平均在 2.9 个字符之前（67% 的情况就在 1–2 个字符之前）
  所有位置：每个头分给配对的 { 的平均权重：
    第 1 层  头0 0.01  头1 0.00  头2 0.67  头3 0.01
    第 2 层  头0 0.73  头1 0.74  头2 0.69  头3 0.67
    第 3 层  头0 0.00  头1 0.67  头2 0.08  头3 0.00
    第 4 层  头0 0.44  头1 0.04  头2 0.75  头3 0.80
```

16 个头里有 9 个把 0.67 以上的权重放在配对的 `{` 上。好像模型到处都是"括号匹配头"？

**不能这样下结论**。注意第一行：配对的 `{` 平均只在 2.9 个字符之前，67% 的情况就在 1–2 个字符之前（比如 `x^{2}`，预测 `}` 时配对的 `{` 就在前一个字符）。任何一个"看最近几个字符"或者"看最近的 `{`"的头，都会得到高分。这个统计**混淆**了两种完全不同的机制。

这是分析模型内部时最常见的陷阱：一个看起来支持你假设的统计量，可能用更简单的解释也能得到。

### 第二次分析：真正的考验

要区分"找最近的 `{`"和"找还没关上的 `{`"，需要两者不同的情况：**嵌套**。例如 `\frac{a^{2}}{b}`，生成第二个 `}`（关闭 `\frac` 的分子）时：

- 配对的是 `\frac` 后面的 `{`（还没关上）；
- `^{2}` 的 `{` 离得更近，但已经被关上了。

```
  真正的考验：嵌套的 67 个位置。每个头分给"配对的 {" / "更近但已关闭的 {"的平均权重：
    第 1 层  头0 0.02/0.07  头1 0.00/0.00  头2 0.00/0.16  头3 0.00/0.00
    第 2 层  头0 0.01/0.15  头1 0.28/0.00  头2 0.31/0.00  头3 0.00/0.75
    第 3 层  头0 0.00/0.00  头1 0.00/0.04  头2 0.00/0.07  头3 0.00/0.00
    第 4 层  头0 0.01/0.00  头1 0.17/0.00  头2 0.00/0.61  头3 0.50/0.01
```

现在看得清楚了：

- **第 2 层头 3**（0.00/0.75）和**第 4 层头 2**（0.00/0.61）：它们看的是**最近的** `{`，不管它关没关。在非嵌套的情况下它们恰好看对了，第一次分析里得了高分；
- **第 4 层头 3**（0.50/0.01）：在嵌套的情况下，它把一半的权重放在**配对的** `{` 上，几乎完全不看已经关闭的那个。这是一个真正的"找还没关上的括号"的头；
- **第 2 层头 1、头 2**（0.28/0.00、0.31/0.00）：也偏向配对的 `{`，程度弱一些；
- 第 1 层几乎没有头参与：要判断一个 `{` 有没有被关上，需要先知道它后面有没有对应的 `}`，这需要前面的层先处理过。所以这个能力出现在第 2 层及以后。

"找还没关上的括号"是一个需要计数的任务（数一下左括号和右括号），单个注意力头做不到精确的计数。模型实际上是把它分解给了几个头和几层：有的头标记"最近的 `{`"，有的头在此基础上跳过已经配对的。这和第 15 章的查表任务"两层配合"是类似的。

## 16.15 常见错误

| 现象 | 原因 | 怎么查 |
|---|---|---|
| 初始损失远大于 ln V | 初始化太大，logits 起伏大 | 检查初始化标准差；看初始 logits 的标准差 |
| 训练损失低得离谱、生成一塌糊涂 | 因果 mask 没生效，偷看了答案 | 第 15 章的"改动未来 token"测试 |
| 损失不降 | 目标没有错开一位（预测的是当前 token） | x 和 y 应该是同一个窗口错开一位 |
| 加载预训练权重后输出乱码 | RoPE 的维度配对约定不同（相邻 vs 前后两半） | 对照原模型的实现 |
| 长输入时输出突然变差 | 超出训练长度，RoPE 外推失败 | 按位置统计损失 |
| 共享权重后嵌入的梯度异常 | 手动初始化时分别初始化了 head 和 tok，后者覆盖前者 | 共享后只初始化一次 |
| 权重衰减把 RMSNorm 的 γ 拉向 0 | 对所有参数都做了衰减 | 只对 dim ≥ 2 的参数衰减 |
| 注意力分析"看起来很好" | 统计量被更简单的解释混淆 | 设计能区分两种假设的对照情况 |

| d | 256 | 1024 | 4096 |
| 头 | 4 × 64 | 16 × 128（查询），8 组键值 | 32 × 128，8 组键值 |
| MLP | SwiGLU，704 | SwiGLU，3072 | SwiGLU，14336 |
| 归一化 | RMSNorm（Pre） | RMSNorm（Pre），另加 QK-Norm | RMSNorm（Pre） |
| 位置编码 | RoPE，base 10⁴ | RoPE，base 10⁶ | RoPE，base 5 × 10⁵ |
| 词表 | 100（字符） | 151,936（字节级 BPE） | 128,256 |
| 共享权重 | 是 | 是 | 否 |
| 训练长度 | 256 | 4096 → 32768 | 8192 |
| 训练 token | 1230 万 | 约 36 万亿 | 约 15 万亿 |

结构几乎完全一样，差别在规模：Qwen3-0.6B 的参数是我们的 185 倍，训练 token 是我们的约 300 万倍。

RoPE 的 base 为什么越来越大？base 越大，最低频的维度转得越慢，模型能区分的距离越远。Qwen3 把 base 从 10⁴ 提高到 10⁶，配合长序列训练，支持更长的上下文。

**GPT 这个名字**：Generative Pre-trained Transformer。生成式（自回归地生成）、预训练（在大量无标注文本上预测下一个 token）、Transformer（本章的结构）。OpenAI 2018 年的 GPT 是 12 层、d = 768、上下文 512，Post-Norm、可学习的位置嵌入、GELU MLP。今天的结构改进（Pre-Norm、RMSNorm、RoPE、SwiGLU）都是之后几年逐步加入的。

## 16.17 深入一步

### 残差流的视角

把每个块看成往残差流"写入"信息的模块：注意力头从别的位置"读"信息写到当前位置，MLP 在当前位置"加工"信息。因为都是加法，最后一层的向量可以分解成"嵌入 + 每个块的贡献"之和。这个视角是机制可解释性研究（mechanistic interpretability）的基础：研究者用它找到了归纳头（第 15 章）、括号匹配、事实回忆等具体的电路。16.13 节就是这种研究的一个小例子。

### 为什么损失下降得这么快又这么慢

预训练曲线的典型形状：开始的几百步损失迅速下降（学会字符频率、常见的拼写），之后进入漫长的缓慢下降（学会更长距离的结构）。在我们的语料上，前 500 步就到了 1.89，之后 2500 步只降了 0.1——因为剩下的大部分损失是语料本身的随机性（16.9 节）。在真实的语言上，"慢慢下降"的阶段会持续非常久，每一点下降都对应着模型学会了某种新的知识或能力。

### 为什么不用 dropout

我们的 GPTConfig 默认 dropout = 0。大模型预训练通常也不用 dropout：数据量远大于模型能记住的量，每个样本只看一遍，不存在过拟合的问题（16.9 节：训练和验证损失几乎相等）。dropout 在小数据上的微调时才有用。

## 16.19 本章小结

- GPT = 嵌入 + L 个 Pre-Norm 块（注意力 + MLP，各带残差）+ 最后的归一化 + 输出层；
- 残差流是一条加法通路，每个块往上面写入信息；
- RMSNorm 只除以均方根，不减均值；
- RoPE 把 q、k 按位置旋转，使分数只依赖相对位置；多个频率区分不同的距离尺度；
- SwiGLU 用一条支路门控另一条，中间维约 8d/3；
- 权重共享让输出层和嵌入是同一个矩阵，刚初始化时会偏爱"重复当前 token"；
- 我们的 GPT 有 324 万参数，结构与 Qwen3 一致；Qwen3-0.6B 按同样的公式是 5.96 亿；
- 预训练 1230 万个 token，验证 1.789 bits/字符，比 n 元模型低 0.4–0.6 bits；接近随机语料本身的熵；
- 括号配对错误从 56% 降到 0%；
- RoPE 不能自动外推：超出训练长度后损失迅速变差；
- 不加位置信息时损失差了近 1 bit；
- 模型里有专门"找还没关上的括号"的注意力头，但发现它需要设计正确的对照分析。

## 参考答案

1. Post-Norm 在残差相加之后归一化：x = Norm(x + f(x))；Pre-Norm 只归一化支路输入：x = x + f(Norm(x))。Pre-Norm 的残差流是一条没有归一化的加法通路，梯度可以直接流到任何一层，深层训练更稳定，对学习率和预热不敏感。
2. 位置 m 的 q 旋转 mθ，位置 n 的 k 旋转 nθ：(R(mθ)q)ᵀ(R(nθ)k) = qᵀR(mθ)ᵀR(nθ)k = qᵀR(−mθ)R(nθ)k = qᵀR((n−m)θ)k，只依赖 n − m。
3. 单一频率每 2π/θ 个位置绕回一次，无法区分相差一个周期的距离；高频维度对近距离敏感，低频维度能区分远距离，组合起来可以唯一地表示很大范围的距离。
4. SwiGLU 有三个 d × f 的矩阵，普通 MLP 有两个 d × 4d 的矩阵。令 3df = 2 · d · 4d，得 f = 8d/3，两者参数量相同。
5. 刚初始化时各块的贡献很小，最后一层的向量主要是嵌入 e(x_t)；输出 logit_v = norm(h) · e_v，v = x_t 时是 e(x_t) 与自己（放大后）的点积，等于 ‖e‖² 乘放大系数，远大于和其他随机向量的点积。
6. 语料是随机单词组成的，下一个单词从 446 个中均匀选取，本身就有约 1.5 bits/字符的不可预测性；模型已经学会了拼写和格式，剩下的大部分是语料的随机性。
7. 位置 400 的查询要和距离 0–400 的键计算分数，其中距离 257 以上的相对位置在训练中从没出现过，模型对这些角度给出的分数是不可靠的，注意力被打乱。
8. 配对的 { 大多数时候就在 1–2 个字符之前，"看最近的字符"或"看最近的 {"的头也会得高分，统计量混淆了不同的机制。需要用嵌套的情况（最近的 { 已关闭）来区分。
9. 3 × 1024 × 3072 = 9,437,184；注意力 4 × 1024² = 4,194,304；约 2.25 倍。（Qwen3-0.6B 的注意力因为 h·dh = 2048 > d，实际是 6.29M，见 16.7 节。）
10. θ_63 = 10⁶^(−126/128) ≈ 1.24 × 10⁻⁶；转一圈 2π / θ ≈ 5.1 × 10⁶ 个位置。
11. 1.24 / ln 2 = 1.789 bits/字符；困惑度 e^1.24 = 3.46。
12. 2（k 和 v）× 4 层 × 256 × 4 字节 = 8192 字节/token；256 个 token 共 2 MB。
13. y[b, t] = x[b, t+1]：y 是 x 错开一位。因果 mask 保证位置 t 的输出只依赖 x[0..t]，所以位置 t 的输出可以合法地用来预测 x[t+1]；T 个位置同时计算，每个位置都是一个独立的"预测下一个"的任务。
14. `clone()` 复制了一份新的数据，`head.weight` 和 `tok.weight` 是两个独立的参数，训练后会变得不同，不是共享。正确写法是 `self.head.weight = self.tok.weight`（同一个 Parameter 对象）。
15. ```python
    @torch.no_grad()
    def loss_by_position(m, ids, L):
        xs = torch.stack([ids[s:s + L] for s in range(0, len(ids) - L - 1, L)])
        ys = torch.stack([ids[s + 1:s + L + 1] for s in range(0, len(ids) - L - 1, L)])
        lg = m(xs)[0]
        loss = F.cross_entropy(lg.reshape(-1, lg.shape[-1]), ys.reshape(-1), reduction="none")
        return loss.view(len(xs), L).mean(0)
    ```
