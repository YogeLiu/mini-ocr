# 第 22 章　搭一个 VLM

## 本章在全景图中的位置

所有零件都齐了：

- 第 16 章的 **GPT**：在文字、LaTeX、Markdown 的混合语料上预训练过，会"写字"；
- 第 19 章的 **ViT**，在第 20 章用 **CLIP** 预训练过：它的输出已经和文字的含义对齐；
- 第 17 章的**生成**：KV cache、贪心解码、`inputs_embeds`。

本章把它们拼成一个**视觉语言模型**（VLM），让语言模型"看着图写字"。核心问题有三个：

1. **结构**：视觉特征怎样交给语言模型？中间的**连接器**（connector，也叫投影器 projector、适配器 adapter）有哪几种做法，各有什么取舍？
2. **序列与标签**：图像、问题、答案怎样排成一条序列？哪些位置计算损失？
3. **训练方案**：为什么先"对齐"（只训连接器）、再"指令微调"（全部解冻）？直接一起训练、或者从零训练会怎样？

本章用 ShapesWorld 训练一个能描述图像、数物体、说出最左边物体颜色、判断"有没有某个物体"的 VLM，对照几种结构和训练方案；最后用**完全相同**的结构读文字行，把第 13 章的 CTC 识别换成"生成式 OCR"。第 23 章扩展任务（定位、多轮对话、指令数据），第 24 章打开真实的 Qwen、SmolVLM，你会发现它们和本章的 VLM 是同一个结构。

## 学习目标

1. 画出"视觉塔 + 连接器 + 语言模型"的结构，说清三类连接器（投影式、合并式、查询式）和交叉注意力式结构的区别与取舍；
2. 实现 2×2 合并（space-to-depth），理解它与 pixel shuffle 的关系；
3. 构造 VLM 的训练序列和标签：图像占位符、只在答案上计算损失；
4. 实现"把视觉 token 填进占位符"的嵌入拼接；
5. 理解两阶段训练（对齐 → 指令微调）的动机，并用实验验证；
6. 比较"用预训练的部件"和"从零训练"，比较冻结与解冻的选择；
7. 用同一个结构做生成式 OCR，与第 13 章的 CRNN 对比，说清两种方法各自的长处。

## 22.1 结构

### 三个部件

```
图像 (3, 64, 64)
  │ 视觉塔：ViT（第 19、20 章）
  ▼
patch 特征 (64, 128)          ← 每个 patch 一个 128 维向量，已经"懂"颜色、形状
  │ 连接器
  ▼
视觉 token (N_v, 256)          ← 维度与语言模型的词嵌入相同
  │ 放进序列里 <img> 占位符的位置
  ▼
[<bos>, 视觉 token × N_v, "Q: What color is the leftmost object?\nA: "] 的嵌入
  │ 语言模型：GPT（第 16 章）
  ▼
逐字生成 "red<eos>"
```

连接器有两个任务：

1. **对齐维度**：ViT 输出 128 维，GPT 的嵌入是 256 维；
2. **对齐"语言"**：ViT 的特征空间和 GPT 的词嵌入空间是各自训练出来的，毫无关系。连接器要把视觉特征"翻译"成 GPT 能理解的向量——让 GPT 把它们当成一种特殊的"词"。

### 投影式：LLaVA

最简单的连接器：每个 patch 过一个两层 MLP，token 数不变。

```python
class MLPProjector(nn.Module):
    def __init__(self, d_v, d):
        super().__init__()
        self.net = nn.Sequential(nn.Linear(d_v, d), nn.GELU(), nn.Linear(d, d))
```

LLaVA（2023）的第一版只用了一个线性层，LLaVA-1.5 换成两层 MLP，效果明显更好。CLIP ViT-L/14 在 336×336 上有 24 × 24 = 576 个 patch，每张图就是 576 个视觉 token。

优点是**信息不丢**：每个 patch 的特征原样（经过变换）交给语言模型。缺点是 **token 多**：语言模型的计算量与序列长度成正比（注意力部分是平方），高分辨率的文档图会有几千个视觉 token。

### 合并式：Qwen-VL 的 merger、pixel shuffle

在送进语言模型之前，把相邻的 2×2 个 patch **拼接**成一个向量，token 数变成 1/4：

```
原网格（4×4 个 patch，每个 d 维）       合并后（2×2 个 token，每个 4d 维）
 0  1 | 2  3                          [0,1,4,5]    [2,3,6,7]
 4  5 | 6  7               →
 ─────┼─────                          [8,9,12,13]  [10,11,14,15]
 8  9 |10 11
12 13 |14 15
```

拼接后再过 MLP 把 4d 映射到语言模型的维度。注意是**拼接**而不是平均：4 个 patch 的信息都保留在 4d 维的向量里，只是"打包"成一个 token。这个操作在图像处理里叫 **space-to-depth**（把空间维度挪到通道维度），在超分辨率网络里它的逆操作叫 pixel shuffle；VLM 文献里常把这个合并也叫 pixel shuffle（InternVL、SmolVLM），Qwen2-VL 叫 PatchMerger。合并比例可以更大：SmolVLM 为了极少的视觉 token 用了更激进的比例。

### 练习 22.1：`merge_2x2`

```python
def merge_2x2(x, hw):
    B, N, d = x.shape
    h, w = hw
    x = x.reshape(B, h // 2, 2, w // 2, 2, d)          # (B, 行组, 组内行, 列组, 组内列, d)
    x = x.permute(0, 1, 3, 2, 4, 5)                     # (B, 行组, 列组, 组内行, 组内列, d)
    return x.reshape(B, (h // 2) * (w // 2), 4 * d)
```

和第 19 章的 `patchify` 是同一个套路：把一个维度拆成"组"和"组内"，用 permute 把"组"的维度放到前面、"组内"的放到后面，再合并。测试 `test_merge_2x2` 用"值 = patch 编号"的输入检查合并后每个 token 恰好是 [0, 1, 4, 5] 这样的 2×2 小方块。

**Qwen2-VL 的一个细节**：它的 ViT 在送进 patch 嵌入之前，就把像素按 2×2 的小组重新排列好了，所以 merger 里只需要把**连续的 4 个** token 拼起来。效果和我们的 `merge_2x2` 相同，只是重排发生在更早的地方（第 24 章读 processor 时会看到）。

### 查询式：BLIP-2 的 Q-Former

另一种思路：不管图有多少 patch，都用**固定数量**的可学习"查询"向量去"问"图像，每个查询通过交叉注意力（第 15 章 15.9 节）从所有 patch 里提取信息：

```
查询 (N_q, d_v)，可学习
  │ × n_layer：
  │    查询之间的自注意力
  │    交叉注意力：q 来自查询，k、v 来自所有 patch
  │    MLP
  ▼
N_q 个视觉 token → 线性层 → 语言模型
```

BLIP-2（2023）用 32 个查询；Flamingo 的 Perceiver Resampler 是同样的思想（64 个 latent 向量）。

优点：**视觉 token 数固定且很少**，与分辨率无关。缺点：**信息瓶颈**——几十个向量要装下整张图的信息。对"描述一张照片"够用，对"读出一页文档上的每一个字"就不够了。这是近两年开源 VLM 普遍回到投影式、合并式的主要原因：OCR、文档、图表这些任务需要细节。22.5 节第 4 部分请你实测：查询数从 16 减到 4 时，哪些任务先坏掉。

#### 我们的 Q-Former 有多少参数

`miniocr/models/vlm.py` 的 `QFormer(d_v=128, d=256, n_query=16, n_layer=2)`，逐项数（第 4 章"参数量怎么数"）：

| 部分 | 怎么算 | 参数 |
|---|---|---|
| 查询 | 16 × 128 | 2,048 |
| 每层：3 个 LayerNorm | 3 × (128 + 128) | 768 |
| 每层：自注意力（q、k、v、o 四个 128 → 128 的线性层） | 4 × (128 × 128 + 128) | 66,048 |
| 每层：交叉注意力（同样的四个线性层） | 4 × (128 × 128 + 128) | 66,048 |
| 每层：MLP（128 → 512 → 128） | 128 × 512 + 512 + 512 × 128 + 128 | 131,712 |
| 两层合计 | 2 × 264,576 | 529,152 |
| 最后的 LayerNorm + 投影（128 → 256） | 256 + 128 × 256 + 256 | 33,280 |
| **合计** | | **564,480** |

和 22.5 节第 1 部分打印的数一致。它是 MLP 连接器（98,816）的 5.7 倍，但输出的视觉 token 只有 16 个，是 MLP 的 1/4。**参数多不等于信息多**：Q-Former 的参数花在"怎样从 64 个 patch 里挑出信息"上，最后能传给语言模型的仍然只有 16 × 256 个数。

#### Q-Former 不知道 patch 的顺序

交叉注意力里，每个查询对所有 patch 算分数、做 softmax、按权重求和。把 patch 的顺序打乱，k、v 的行跟着打乱，**结果完全不变**（求和与顺序无关）。所以 Q-Former 本身不知道哪个 patch 在左上角、哪个在右下角，位置信息只能来自 patch 向量本身——也就是 ViT 里加过的位置编码（第 19 章）。如果视觉塔的输出已经"忘掉"了位置（比如位置编码太弱），Q-Former 也救不回来。对比一下：MLP 和合并式连接器保留了 patch 的排列，语言模型还能从序列顺序里得到一部分位置信息。

这也是第 24 章讨论 M-RoPE 时的背景：**位置信息在 VLM 里要经过视觉塔、连接器、语言模型三道关，每一道都可能丢失**。

### 交叉注意力式：Flamingo、Llama 3.2 Vision

前三种都把视觉 token 放进语言模型的**输入序列**里（有时叫"早期融合"或 decoder-only 结构）。另一种做法是视觉特征**不进入序列**，而是在语言模型的层与层之间插入新的**交叉注意力层**，让文字 token 去"查"视觉特征：

```
文字 token → [LM 层] → [新的交叉注意力层：q = 文字，k, v = 视觉特征] → [LM 层] → …
```

Flamingo（2022）在冻结的语言模型里每隔几层插一个交叉注意力层，输出乘以一个初始化为 0 的门控系数 tanh(α)：训练开始时新层完全不起作用，语言模型的行为不变，然后慢慢"打开"。Llama 3.2 Vision 也是这个结构。

优点：序列不变长，语言模型的原有能力不受影响（可以完全冻结）。缺点：要改语言模型的结构；视觉信息只在插入的那几层进入。

### 取舍一览

| 结构 | 视觉 token 数 | 信息损失 | 改动语言模型 | 代表 |
|---|---|---|---|---|
| 投影式 | = patch 数（多） | 无 | 否 | LLaVA |
| 合并式 | patch 数 / 4（或更少） | 很少（拼接不丢信息，但 MLP 要压缩维度） | 否 | Qwen-VL、InternVL、SmolVLM |
| 查询式 | 固定（几十个） | 有瓶颈 | 否 | BLIP-2、早期的 Qwen-VL |
| 交叉注意力式 | 不占序列 | 视结构而定 | 是（插入新层） | Flamingo、Llama 3.2 Vision |

（第一代 Qwen-VL 用的是查询式的单层交叉注意力，把视觉 token 压到 256 个；Qwen2-VL 起改成了合并式。）

## 22.2 序列与标签

### 占位符

我们用字符表里预留的特殊符号 `<img>`（第 16 章 `TEXT_SPECIALS` 的第 4 个）作为**占位符**：序列里放 N_v 个 `<img>`，嵌入时把它们替换成视觉 token。

```
<bos><img><img>…<img>Q: What color is the leftmost object?\nA: red<eos>
```

为什么用占位符而不是直接把视觉向量拼在前面？

1. **位置灵活**：图像可以出现在序列的任何位置，多张图也只是多段占位符（第 23 章）；
2. **代码统一**：分词、批处理、补齐都只处理整数编号；只在最后一步（嵌入）区分图像和文字；
3. **真实模型都这样做**：Qwen2-VL 的序列里是 `<|vision_start|><|image_pad|>…<|image_pad|><|vision_end|>`，processor 根据图像大小算出要放多少个 `<|image_pad|>`（第 24 章）。

### 只在答案上计算损失

语言模型的训练目标是"预测下一个 token"。但在 VLM 的序列里：

- **视觉 token** 不是离散的 token，没有"下一个是什么"可以预测；
- **问题**是用户给的，模型不需要学会"提问"；
- **答案**才是要学的。

所以只在答案（以及结束符 `<eos>`）的位置计算损失，其他位置的标签设成 −100（`F.cross_entropy` 的 `ignore_index`，第 16 章）。

### 练习 22.2：`build_example`

```python
def build_example(vocab, n_img, question, answer):
    head = [vocab.stoi["<bos>"]] + [vocab.stoi["<img>"]] * n_img + vocab.encode("Q: " + question + "\nA: ")
    tail = vocab.encode(answer) + [vocab.stoi["<eos>"]]
    ids = head + tail
    targets = [-100] * (len(head) - 1) + tail + [-100]
    return ids, targets
```

对齐关系是最容易错的地方。targets[t] 是"在位置 t 应该预测的下一个 token"，即 ids[t + 1]。head 的最后一个字符（"A: " 末尾的空格）位于位置 len(head) − 1，它要预测答案的第一个字符。所以 targets 的前 len(head) − 1 个是 −100，接着是 tail（答案 + `<eos>`），最后一个位置（`<eos>` 本身）后面没有东西，补 −100。

为什么要学会预测 `<eos>`？生成时模型要自己决定"答完了"。不学 `<eos>`，模型回答完 "red" 之后会接着胡乱写下去。

### 补齐

一个批里的序列长短不一（描述比"red"长得多），右侧用 `<pad>` 补齐，标签补 −100。补齐位置在序列的**末尾**，因果注意力里前面的位置看不到它们，所以不影响前面的计算，也不计算损失。

用 `pad_batch` 把两条样本（2 个视觉 token，问题 "Hi" / "Hello"，答案 "x" / "yz"）拼成一批，实际的输出是（B = `<bos>`，I = `<img>`，E = `<eos>`，_ = `<pad>`，⏎ = 换行，· = −100）：

```
ids     BIIQ: Hi⏎A: xE____        第 0 条：14 个 token，补 4 个 <pad>
targets ···········xE·····
ids     BIIQ: Hello⏎A: yzE        第 1 条：18 个 token，最长，不补
targets ··············yzE·
```

对照着检查三点：targets 里的 `x` 正好在 ids 的 "A: " 那个空格的下面（位置 t 预测 ids[t + 1]）；`<eos>` 也要预测；补齐的 4 个位置的标签全是 −100。批的形状是 (2, 18)。

生成时情况不同：同一批的提示必须**等长**，否则最后一个位置不对齐。我们的 `answer` 函数按提示长度分组，同组的一起生成。真实的推理框架用左侧补齐加注意力 mask，或者干脆逐条处理。

### 练习 22.3：`VLM.embed`

```python
def embed(self, images, ids):
    emb = self.lm.tok(ids)                                   # (B, T, d)：文字嵌入（<img> 位置是占位符自己的嵌入，马上被替换）
    v = self.visual_tokens(images).to(emb.dtype)             # (B, N_v, d)
    mask = ids == self.img_id                                # (B, T)
    assert mask.sum(1).eq(v.shape[1]).all()
    emb = emb.clone()
    emb[mask] = v.reshape(-1, v.shape[-1])
    return emb
```

`emb[mask]` 用布尔下标选出所有 `<img>` 位置，顺序是"先第 0 条序列从左到右，再第 1 条……"，正好对应 `v.reshape(-1, d)` 的顺序（第 1 章的布尔下标）。断言检查每条序列的占位符个数是否等于视觉 token 数——个数对不上是 VLM 代码里最常见的 bug 之一，真实模型的代码里也有同样的检查。

替换之后，整条序列的嵌入交给 GPT：`self.lm(inputs_embeds=emb, targets=targets)`。语言模型本身一行都不用改。

### 位置编码

我们的 GPT 用一维 RoPE，视觉 token 就按序列里的顺序编号 1–64，丢掉了"第几行第几列"的二维信息（ViT 内部已经用过位置编码，所以每个视觉 token 自己"知道"它在哪里，问题不大）。Qwen2-VL 的 **M-RoPE** 给视觉 token 分配三维的位置（时间、行、列），第 24 章细讲。

## 22.3 训练方案

### 两个阶段

LLaVA 确立的标准做法：

**阶段 1：对齐预训练**（alignment / feature alignment pretraining）

- 冻结视觉塔和语言模型，**只训练连接器**；
- 数据：大量（图像, 描述）对，LLaVA 用了 55.8 万对；
- 目的：让连接器学会把视觉特征"翻译"成语言模型能理解的向量。

**阶段 2：指令微调**（visual instruction tuning）

- 解冻语言模型（LLaVA-1.5 仍然冻结视觉塔，后来的很多模型也解冻视觉塔，通常给它更小的学习率）；
- 数据：各种任务的问答、对话、OCR、图表……LLaVA-1.5 用了 66.5 万条；
- 目的：学会按指令回答各种问题。

### 为什么要先对齐

想一想阶段 1 之前的状态：连接器是随机初始化的，它输出的"视觉 token"对语言模型来说是一堆**乱码向量**，和它见过的任何词嵌入都不像。

如果这时直接解冻所有参数一起训练：

- 语言模型面对乱码输入，损失很大，梯度也很大；
- 大梯度流进语言模型，会**破坏**它预训练时学到的语言能力——它为了适应乱码而改变自己；
- 连接器还没学会翻译，语言模型已经被改坏了。

先只训练连接器，语言模型保持不变，相当于让连接器"学会说语言模型的语言"；等视觉 token 变得有意义了，再一起微调，梯度就温和得多。

阶段 1 只训练很少的参数（我们的 MLP 连接器约 10 万个，占全部的 2%），速度快，也不需要高质量的数据——描述数据最容易大量获得。22.5 节第 2 部分请你验证：**只训练连接器，冻结的 GPT 能不能描述图像**；第 3 部分比较跳过阶段 1、从零训练、冻结不同部分的效果。

### 学习率

阶段 1 只有连接器在学，可以用较大的学习率（我们用 1e-3）；阶段 2 解冻了预训练好的部件，学习率要小得多（3e-4），否则同样会破坏预训练学到的东西。真实模型的阶段 2 学习率通常在 1e-5 到 2e-5 量级，视觉塔还要更小。

### 真实模型的训练阶段

| 模型 | 阶段 |
|---|---|
| LLaVA-1.5 | ① 只训投影器（描述数据）② 训投影器 + LM（指令数据），视觉塔一直冻结 |
| Qwen2-VL | ① 只训 ViT（图文数据）② 全部解冻（更多、更杂的多模态数据）③ 冻结 ViT、训 LM（指令数据） |
| SmolVLM | 多个阶段，逐步提高分辨率、加入视频和文档数据 |

细节各不相同，但都遵循一个原则：**新加的、随机初始化的部件先单独训练；预训练好的部件小心地、用小学习率解冻**。

## 22.4 生成式 OCR

把任务换成"Read the text."，答案换成文字行的内容，同一个结构就成了 OCR 模型。和第 13 章的 CRNN + CTC 比较：

| | CRNN + CTC（第 13 章） | VLM（本章） |
|---|---|---|
| 输出方式 | 每一列独立预测一个字符或空白，再合并 | 自回归：逐个字符生成，每一步看着前面写过的内容 |
| 对齐假设 | 输出顺序 = 图像从左到右的顺序 | 没有任何假设 |
| 语言知识 | 几乎没有（每列独立） | 语言模型自带（预训练过） |
| 输出结构 | 只能输出一行字符 | 可以输出任意结构：多行、LaTeX、Markdown 表格、JSON |
| 速度 | 一次前向出全部结果 | 每个字符一次前向（有 KV cache） |
| 典型错误 | 字符替换、漏字 | 也会替换，还会**幻觉**（写出图里没有的内容）、**重复**（陷入循环）、提前结束 |

CTC 的"从左到右"假设对单行文字很合适，但它没法输出公式的二维结构（分式的分子分母、上下标）、表格的行列，也没法按阅读顺序输出整页。这就是 OCR 走向 VLM 的根本原因：**输出不再受限于图像的空间顺序**。代价是生成式模型特有的错误：它会"编"。22.5 节第 5 部分统计生成结果比真值明显更长或更短的比例，第 23 章 23.6 节会专门讨论幻觉（包括 OCR 里读出图里没有的字、重复输出同一段），重复和重复惩罚见第 17 章。

我们的 OCR 实验用第 20 章在单词图上 CLIP 预训练过的 ViT（二维 RoPE，所以 32×256 的行图不用改任何代码）和 2×2 合并连接器：128 个 patch 变成 32 个视觉 token。

## 22.5 实验

本节的实验由你来运行。默认只用 CPU：

```bash
python -m labs.ch22.vlm_tour             # 全部 6 个部分
python -m labs.ch22.vlm_tour 1           # 只看序列和参数（几秒，不训练）
python -m labs.ch22.vlm_tour 2 6         # 第 2 部分训练并保存主模型，第 6 部分读取它
```

需要先有三个模型：第 16 章的 `outputs/ch16/gpt_char.pt`、第 20 章第 2 部分的 `outputs/ch20/clip_shapes.pt`、第 20 章第 6 部分的 `outputs/ch20/clip_words.pt`（只有第 5 部分用）。第 2 部分保存的 `outputs/ch22/vlm_mlp_stage1.pt` 是第 23 章的起点，**至少要跑第 2 部分**。

每一步在 CPU 上大约 0.3–0.4 秒，一次 3500 步的训练约 20–25 分钟。第 3、4 部分各要训练 3–4 个模型，可以只挑你最关心的几个配置（在函数里注释掉其他的）。

### 第 1 部分：一条训练样本（几秒，不训练）

这一部分不训练，下面是完整输出的节选：

```
  计算损失的位置只有 4 个：答案的 3 个字符 + <eos>
  视觉 token：ViT 输出 (1, 64, 128) → MLP 连接器 → (1, 64, 256)，与文字嵌入（256 维）同一个空间
  参数：ViT 826,240  连接器 98,816  GPT 3,239,168
    连接器 MLP（LLaVA 式）                   参数   98,816  视觉 token  64 个
    连接器 2×2 合并（Qwen 式）                 参数  395,008  视觉 token  16 个
    连接器 Q-Former 16 个查询（BLIP-2 式）      参数  564,480  视觉 token  16 个
  描述任务的序列约 152 个 token，其中视觉 token 占 64 个：图像往往比文字长
```

前面还有逐个位置的表：位置 0 是 `<bos>`，1–64 是 `<img>`，然后是问题的每个字符，它们的"要预测的下一个 token"都是 −100；只有 "A: " 之后的位置才有真正的标签。**对照练习 22.2，确认标签是左移了一位的**：位置 105（输入是空格）要预测 "r"，位置 108（输入是 "d"）要预测 `<eos>`。

MLP 连接器有 98,816 个参数，占整个 VLM（约 416 万）的 2.4%。

### 第 2 部分：两阶段训练（约 25 分钟）

阶段 0：什么都不训练，直接评测；阶段 1：冻结 ViT 和 GPT，只训练连接器、只用描述数据，1500 步；阶段 2：全部解冻，四种任务各占 1/4，2000 步。每个阶段之后在四个任务上评测：描述（整句全对、CER）、数数、最左边的颜色、有没有。

**运行之前先预测**：

1. 阶段 0（连接器是随机的）会生成什么？是乱码，还是像样的英文？（提示：GPT 在第 16 章学过写英文。）
2. 阶段 1 只训练了 2% 的参数，而且只见过描述数据。它的描述能有多好？问它"How many objects?"这种没训练过的问题，它会回答什么？
3. 阶段 2 之后，四个任务里哪个最难？

**看什么**：

- 阶段 0 的输出说明了一件事：语言模型"不知道"视觉 token 是什么，它看到的是一串随机向量，只能按语言先验往下写；
- 阶段 1 后，如果描述的 CER 已经明显下降，就说明**冻结的 GPT 只靠一个小小的连接器，就能"读懂"视觉特征**，这是两阶段训练的出发点。被问到没训练过的问题时，它多半还是在"描述"：它只学过一种任务；
- 阶段 2 后，比较四个任务。数数和"最左边"需要的信息不一样（第 19 章第 2 部分：CNN 数得更好，ViT 找最左边更好），你的结果和第 19 章的结论一致吗？

### 第 3 部分：训练方案的对照（约 1.5 小时，4 个模型）

总步数都是 3500 步、同一份测试集：跳过阶段 1 直接全部训练、所有部件从零开始、冻结 ViT、冻结 GPT。

**预测**：从零训练会差多少？冻结 ViT 和冻结 GPT，哪个损失更大？跳过阶段 1 会不会反而更好（它在四种任务上多训练了 1500 步）？

**看什么**：如果"跳过阶段 1"和两阶段差不多，不要惊讶：我们的模型很小、数据很干净，阶段 1 的好处（保护语言模型不被随机的视觉 token 破坏）在大模型、杂乱的数据上更明显。**一个实验的结论只在它的条件下成立**，写结论时要带上条件。

### 第 4 部分：连接器（约 1.5 小时，3 个模型）

2×2 合并（16 个视觉 token）、Q-Former 16 个查询、Q-Former 4 个查询，和第 2 部分的 MLP（64 个视觉 token）比较。

**预测**：视觉 token 从 64 减到 16，哪个任务最先变差？Q-Former 只有 4 个查询时呢？描述要说出每个物体的大小、颜色、形状，4 个向量装得下吗？

**看什么**：把四种连接器的结果和"视觉 token 数"放在一起看。22.1 节说查询式连接器有**信息瓶颈**，这里是你亲眼看到它的地方。

### 第 5 部分：生成式 OCR（约 25 分钟）

用完全相同的结构读第 13 章的文字行：视觉塔换成第 20 章在单词图上预训练的 ViT，连接器用 2×2 合并（128 个 patch → 32 个视觉 token），训练 3000 步，和第 13 章 CRNN 的 CER 2.28%、整行全对 80.1% 比较。

**预测**：生成式 OCR 能赢过 CTC 吗？它的错误和 CTC 的错误有什么不同？（提示：CTC 每一列独立输出，生成式模型一个字一个字地写，可能多写或少写。）

**看什么**：最后一行统计"生成结果比真值长 3 个字符以上 / 短 3 个以上"的比例：这是生成式模型特有的错误（重复、漏掉一段）。CTC 几乎不会出现这种错误，因为它的输出长度被图像的宽度限制住了。

### 第 6 部分：语言模型在看哪些视觉 token（几分钟，需要第 2 部分的模型）

回答"最左边的物体是什么颜色"时，在要说出答案的那个位置上，语言模型每一层对 64 个视觉 token 的注意力怎样分布：400 张图里有 2–3 个物体的那些，按"最左物体的 token、其他物体的 token、背景"三类分别平均。

**看什么**：注意力是否集中在最左边那个物体所在的 patch 上，和第 19 章第 7 部分 CLS 的注意力图对照。和那里一样：**注意力大不等于"用了这个信息"**，只能作为一个线索。

## 22.7 常见错误

| 现象 | 原因 | 怎么查 |
|---|---|---|
| 断言失败：占位符个数与视觉 token 数不一致 | 换了连接器（合并、Q-Former）但构造序列时 N_v 没跟着改 | 由连接器类型计算 N_v，不要写死 |
| 训练损失很低，生成却是乱码 | targets 没有左移一位，模型学的是"复制当前 token" | 打印几个位置的 (输入, 标签) 对 |
| 生成停不下来 | 训练时没有监督 `<eos>` | 检查 targets 里是否包含 `<eos>` |
| 生成的答案总是同一个 | 只在答案上算损失，但答案太短、问题太少变化，模型忽略了图像 | 换图测试：答案变不变？ |
| 阶段 2 之后语言能力变差 | 学习率太大、没有先对齐 | 先只训连接器；降低学习率 |
| 冻结了却还在变 | 沿用了冻结前建的优化器：参数的 .grad 被清零成 0 而不是 None，优化器照样用旧的动量和权重衰减更新它 | 换阶段时重建优化器，只交给它 requires_grad 的参数；`zero_grad(set_to_none=True)` |
| 一批里提示长短不一，生成结果错位 | 右侧补齐后最后一个位置不是提示的结尾 | 按长度分组，或左侧补齐 + 注意力 mask |
| 推理时视觉 token 的数值范围不对 | 推理时的图像预处理（归一化）和训练时不一致 | 训练和推理用同一个预处理函数 |

## 22.8 真实世界对照

- **LLaVA 系列**：LLaVA（2023）→ LLaVA-1.5（MLP 投影器、更多学术数据）→ LLaVA-NeXT（高分辨率切图）→ LLaVA-OneVision（单图、多图、视频统一）。结构始终是"CLIP/SigLIP + MLP + 语言模型"；
- **Qwen-VL 系列**：Qwen-VL（查询式，256 个 token）→ Qwen2-VL（原生分辨率 ViT + 2D RoPE + 2×2 合并 + M-RoPE）→ Qwen2.5-VL（窗口注意力、绝对坐标）→ Qwen3-VL 与 Qwen3.5（第 24 章）；
- **SmolVLM**：面向小模型（256M–2.2B），用 pixel shuffle 大幅减少视觉 token，配合切图处理高分辨率；
- **InternVL**：大视觉塔（InternViT-6B）+ pixel shuffle + MLP；
- **BLIP-2 / InstructBLIP**：Q-Former，冻结视觉塔和语言模型；
- **Flamingo / IDEFICS / Llama 3.2 Vision**：交叉注意力式；
- **训练规模**：开源 VLM 的预训练数据从几百万到几十亿个图文样本不等，指令微调数据从几十万到几千万条。第 23 章讨论指令数据。

## 22.9 深入一步

### 视觉 token 和文字 token 真的"一样"吗

连接器把视觉特征映射到词嵌入的空间，但视觉 token 并不会变成某个具体的词。研究者把视觉 token 投到词表上看最近的词，往往得到一些不太相关的词，有时能看到和图像内容相关的词。更合理的理解是：视觉 token 落在嵌入空间里语言模型"能读懂"的区域，语言模型的注意力和 MLP 能从中提取信息，但它们是一种语言模型从没见过的新"词"。

### 为什么解冻视觉塔有时有用、有时有害

CLIP 视觉塔学到的是"和描述对齐"的特征，对颜色、物体类别很敏感，但对精确的位置、细小的文字不敏感（描述里很少提到）。如果下游任务需要这些信息（定位、OCR），解冻视觉塔让它适应是有用的；但如果数据太少或学习率太大，视觉塔会"忘掉"预训练学到的通用特征。所以常见的折中是：给视觉塔小得多的学习率，或者只解冻后面几层。

### 序列长度与计算量

VLM 一条样本的计算量大约是 6 × (视觉塔参数 × patch 数 + 语言模型参数 × 序列长度)（第 18 章）。视觉 token 占了序列的大头时，语言模型的计算量主要花在"读图"上。这是减少视觉 token（合并、查询、剪枝）成为研究热点的原因；但对 OCR，过度压缩会丢失文字细节——Xiaomi-OCR-0 这类模型要在 token 数和识别精度之间找平衡（第 34 章）。

## 22.11 本章小结

- VLM = 视觉塔 + 连接器 + 语言模型；连接器负责把视觉特征翻译成语言模型能读的向量；
- 投影式（LLaVA）不丢信息但 token 多；合并式（Qwen、InternVL、SmolVLM）用 space-to-depth 把 token 数降到 1/4；查询式（BLIP-2）token 数固定但有信息瓶颈；交叉注意力式（Flamingo）不占序列但要改语言模型；
- 序列里用占位符表示图像，嵌入时替换成视觉 token；只在答案和 `<eos>` 上计算损失；标签要左移一位；
- 两阶段训练：先冻结两端只训连接器（对齐），再解冻做指令微调；先对齐可以避免随机的连接器破坏语言模型；
- 预训练的视觉塔和语言模型让 VLM 用很少的数据就能学会；
- 同一个结构换成"读字"的数据就是生成式 OCR：输出不受图像空间顺序的限制，但会出现幻觉、重复等生成式模型特有的错误。

## 参考答案

1. 对齐维度（视觉特征维度 → 语言模型的嵌入维度）；对齐"语言"（把视觉特征翻译成语言模型能理解的向量）。
2. 投影式：不丢信息、简单，但 token 多；合并式：token 降到 1/4，拼接几乎不丢信息，是目前的主流；查询式：token 少且固定，但几十个查询装不下一页文档的细节。OCR 需要逐字的细节，信息瓶颈会直接导致错字、漏字。
3. 拼接。拼接保留了 4 个 patch 的全部信息（只是放在一个更宽的向量里），平均会把 4 个 patch 的内容混在一起，细节丢失。
4. 位置灵活（可以插在任何地方、支持多图）、代码统一（分词和批处理只处理整数）、与真实模型一致。
5. 只在答案和 `<eos>` 上计算。视觉 token 不是离散的 token，没有"下一个"可预测；问题是用户给的，模型不需要学会提问。
6. 随机初始化的连接器输出乱码向量，直接全部解冻时大梯度会流进语言模型，破坏预训练学到的语言能力。先对齐让视觉 token 有意义，再微调时梯度温和。
7. 参与。梯度要穿过冻结的语言模型才能传到连接器；只是冻结的参数自己不更新。
8. 优势：没有"从左到右"的对齐假设，可以输出任意结构，有语言知识；劣势：自回归慢，会幻觉、重复、提前结束。
9. 672 / 14 = 48，48² = 2304 个 patch，合并后 576 个。
10. LayerNorm(512)：1024；Linear(512, 512)：262,656；Linear(512, 256)：131,328；合计 395,008。
11. 1 + 64 + 26 + 40 + 1 = 132；计算损失的位置 41 个（答案 40 + `<eos>`）。
12. 没有左移一位：targets 的长度是 len(ids)，但 targets[len(head)] 对应的是 tail[0]，而位置 len(head) 上的输入正是 tail[0]，模型学的是"复制当前 token"。正确的做法是前面放 len(head) − 1 个 −100，最后补一个 −100。
13. 依赖布尔下标"按行优先"取元素的顺序，正好和 v 按批、按 token 展开的顺序一致。如果有一条序列少了一个占位符，被选中的位置总数比 v 的元素少一个，赋值会因为形状不匹配而报错（我们的断言会更早地给出清楚的错误信息）。
14. 这一段本身能工作：PyTorch 的 AdamW 跳过 .grad 为 None 的参数，冻结的参数从来没有梯度，不会被更新。隐患在换阶段时：如果阶段 1 结束后不重建优化器、直接 `set_trainable` 再冻结一部分，那些参数的 .grad 可能是之前留下的 0（`zero_grad(set_to_none=False)` 时），优化器会用旧的动量和权重衰减继续移动它们。稳妥的写法是每个阶段重建优化器，只交给它 requires_grad 为 True 的参数（`labs/ch22/vlm_tour.py` 的 `train` 就是这样做的）。
