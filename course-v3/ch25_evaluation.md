## 本章在全景图中的位置

前面 24 章里，我们已经算过很多"分数"：第 13 章 CRNN 的 CER 2.28%，第 21 章检测器的 AP，第 22 章 VLM 的描述准确率，第 23 章的 POPE，第 24 章真实模型的零样本 CER。每一次我们都相信了这些数字。

从本章开始，课程进入"训练真实模型、比较不同做法"的阶段（第 26–36 章）。每一个结论都要靠比较两个数字得出："加了这批数据，CER 从 3.1% 降到 2.9%""DPO 之后幻觉率降低了"。如果数字本身不可靠，结论就是错的。本章回答三个问题：

## 25.1 评测要回答一个问题

先看一个例子。两个 OCR 模型在同一批 1000 张收据上测试：

| | 模型 A | 模型 B |
|---|---|---|
| CER | 1.8% | 2.5% |
| 金额字段完全正确的比例 | 91% | 97% |

哪个更好？如果你要做一个"整理收据文字"的工具，A 更好：它错的字更少。如果你要做"自动记账"，B 更好：错一个数字的金额就是错的，B 在最关键的字段上更准；它多出来的错误可能都在不重要的地方（店名的标点、广告语）。

**指标是问题的翻译**。先问"这个模型要用来做什么、什么样的错误代价最大"，再选指标。一个评测至少要说清楚：

- **测什么能力**（读文字？理解版面？回答问题？）
- **在什么数据上**（什么分布、多少样本、怎么来的）
- **怎么打分**（用什么指标、比较之前做什么归一化）
- **数字有多准**（误差范围）

本章依次讨论这几件事。

## 25.2 文字的指标

### 编辑距离家族

第 13 章实现了编辑距离（Levenshtein 距离）：把预测变成参考答案最少需要几次插入、删除、替换。几乎所有文字识别的指标都从它出发：

| 指标 | 定义 | 范围 | 谁在用 |
|---|---|---|---|
| **CER**（字符错误率） | Σ 编辑距离 / Σ 参考答案的字符数 | 0 到 ∞（可以超过 100%） | 文字行识别、手写识别 |
| **WER**（词错误率） | 在"词"上算编辑距离，Σ / Σ 参考答案的词数 | 0 到 ∞ | 语音识别、整段文字 |
| **NED**（归一化编辑距离） | 编辑距离 / max(预测长度, 参考长度) | 0 到 1 | 文档解析（OmniDocBench 的文字指标） |
| **精确匹配** | 完全相同的比例 | 0 到 1 | 短字段：金额、日期、答案 |

几个要注意的地方：

**CER 可以超过 100%**：参考答案是 "ok"（2 个字符），预测是一大段 50 个字符的胡话，编辑距离接近 50，CER 就是 2500%。模型"不停地输出"时（第 24 章 SmolVLM 的零样本描述 CER 高达 142%）就会这样。NED 用两者中较长的长度做分母，永远不超过 1，更适合比较"可能输出很长的生成式模型"。

**语料级 vs 逐样本平均**：CER 的标准定义是"总编辑距离 / 总长度"（语料级，corpus-level）。另一种算法是先算每行的 CER 再平均（宏平均，macro-average）。两者可能差很多。第 1 部分的例子：一行 2 个字符全错、一行 24 个字符全对，语料级是 2 / 26 = 7.7%，逐行平均是 (100% + 0%) / 2 = 50%。语料级让长行的权重更大，逐行平均让每行一样重要。**两种都对，但要说清用的是哪一种**，否则数字无法比较。OmniDocBench 的 NED 是逐个样本算再平均的。

**WER 对空格敏感**："Total:$38.50" 少了一个空格，CER 只算 1 个错误，但切词之后 "Total:" 和 "$38.50" 变成了一个词 "Total:$38.50"，WER 算 2 个错误（1 次替换 + 1 次删除），4 个词里错了 2 个，WER 50%。

### BLEU

BLEU（Papineni 等，2002）来自机器翻译，衡量预测和参考答案有多少**相同的 n 元组**（连续 n 个词）：

1. 对 n = 1, 2, 3, 4，算**截断的 n 元组精确率** p_n：预测里每个 n 元组，最多按它在参考答案里出现的次数计数（防止 "the the the" 这种重复得分），除以预测的 n 元组总数；
2. **简短惩罚** BP：预测比参考答案短时（c < r），BP = exp(1 − r/c) < 1，防止"只输出几个最有把握的词"得高分；
3. BLEU = BP × (p₁ p₂ p₃ p₄)^(1/4)，即几何平均。

手算一个例子：参考答案 "the cat is on the mat"（6 个词），预测 "the the the"（3 个词），只看一元组：

- 预测里有 3 个 "the"，参考答案里 "the" 出现 2 次，截断后算 2 个；p₁ = 2/3；
- c = 3 < r = 6，BP = exp(1 − 6/3) = e⁻¹ = 0.368；
- BLEU-1 = 0.368 × 2/3 = 0.245。

BLEU 在 OCR 里用得不多（第 1 部分会看到原因），但在图像描述和一些文档转换的论文里（比如 Nougat）会出现。它的问题：

- **句子级的 BLEU 很不稳定**：一个 4 个词的句子只有一个 4 元组，错一个词，p₄ = 0，BLEU 就是 0。第 1 部分的表里，"错一个字符"的 BLEU-4 是 0，和"完全无关"一样；BLEU 原本是为"在整个语料上统计"设计的，单句用时要加平滑；
- **不关心字符**："38.50" 和 "38.80" 是完全不同的两个词，BLEU 不给部分分数。

### 比较之前的归一化

"total" 和 "Total"、全角的"（"和半角的"("、两个空格和一个空格，算不算错？这取决于任务，但**必须在评测协议里写清楚**。常见的归一化：

- 大小写：问答通常忽略，文字识别通常区分；
- 空白：多个空格合并成一个，去掉首尾空白；
- Unicode：全角 / 半角统一（NFKC 归一化），不同写法的同一个字符统一（比如 "é" 可以是一个字符，也可以是 "e" 加一个组合重音符号）；
- 标点：问答通常去掉句末的句号；
- 格式：Markdown 的 `**粗体**` 和纯文本 "粗体" 算不算一样？文档解析的基准通常先把 Markdown 转成纯文本再比较文字，表格和公式单独比较。

一个真实的教训：同一个模型在同一个基准上，不同论文报告的分数可能差好几个点，原因常常就是归一化不同。

## 25.3 问答的指标

### 精确匹配的问题

问："这张收据的总金额是多少？" 正确答案 "38.50"。模型回答：

- "38.50"：对；
- "$38.50"：对吗？
- "The total is 38.50."：对吗？
- "38.5"：对吗？

精确匹配全部判错（除了第一个）。实际中有三种办法：

1. **要求格式**：在提示里说"只回答数字"（第 24 章的零样本实验就是这样做的），然后精确匹配；
2. **包含匹配**：参考答案是预测的子串就算对。OCRBench 就是这样判分的。它对"啰嗦"的模型友好，但可能被"把所有可能的答案都说一遍"钻空子；
3. **容忍小的差别**：ANLS。

### ANLS

ANLS（Average Normalized Levenshtein Similarity，Biten 等，2019）是 ST-VQA、DocVQA、InfoVQA 的指标：

```
对每个问题：s = max over 正确答案 a of  { 1 − NED(预测, a)   如果 NED < 0.5
                                         { 0                  否则
ANLS = 所有问题的 s 的平均
```

- 先都转成小写、去掉首尾空白；
- 每个问题可以有多个正确答案（"12" 和 "twelve"），取最好的那个；
- NED < 0.5 时给部分分数：OCR 的小错（"Pari" vs "paris"，NED = 0.2）只扣一点；
- NED ≥ 0.5 时记 0：答非所问不给分（否则随便输出一个词也能得到一些分数）。

阈值 0.5 是一个折中：太宽松，错误答案也能得分；太严格，OCR 的小错就会被当成完全答错。第 1 部分的表里，"The answer is Paris" 的 ANLS 是 0：预测比答案长太多，NED 超过 0.5。ANLS 惩罚啰嗦。

### 练习 25.3：`anls`

在 `miniocr/metrics.py` 里实现 `anls(preds, answers, tau=0.5)`，`answers[i]` 是第 i 个问题的正确答案列表。测试检查了大小写（`Paris` 对 `paris` 得 1）、小错（`Pariss` 得 1 − 1/6）、阈值（`London` 得 0）和多个答案取最好。

### VQA 准确率

VQAv2 和 TextVQA 的每个问题有 10 个人给出的答案。人和人的答案不一样（"red"、"dark red"、"maroon"），所以准确率是：

```
VQA 准确率 = min(和预测相同的人数 / 3, 1)
```

至少 3 个人同意就算满分。第 1 部分的例子：10 个人里 4 个说 red、3 个说 dark red、2 个说 maroon、1 个说 brown，回答 "red" 或 "dark red" 得 1 分，"maroon" 得 2/3，"brown" 得 1/3。官方实现还要对"去掉一个人后的 10 种 9 人组合"取平均，并且做更多的归一化（数字、冠词、标点），本章只实现核心公式。

### 宽松准确率与模型裁判

- **宽松准确率**（relaxed accuracy，ChartQA）：数值答案与正确答案相差不超过 5% 就算对，因为从图表上读数本来就有误差；
- **模型裁判**（LLM-as-a-judge）：开放式的回答（"描述这张图"）没有唯一的正确答案，就让一个更强的语言模型按评分标准打分。它方便，但有自己的偏差：偏爱更长的回答、偏爱和自己风格相似的回答、对答案的顺序敏感。用它时要固定裁判模型和提示、报告裁判与人工打分的一致率。

## 25.4 公式：按渲染结果比较

### 字符串比较的两个问题

第 3 章讲过，同一个公式有很多种等价的 LaTeX 写法：`x^2` 和 `x^{2}`、`\frac{a}{b}` 和 `{a \over b}`、运算符两边加不加空格。第 2 部分的实验：300 个随机公式各写成一种随机的等价写法，**只有 33% 的字符串和规范写法相同**，平均 NED 是 0.128。按字符串打分，一个"完全正确"的模型也会被扣掉 13% 左右。

反过来，字符串差得少，不代表渲染出来差得少：把 `\frac{x^{2}+1}{y_{n}}` 里的 `x^{2}` 写成 `x_{2}`，21 个字符只差 1 个（NED 0.048），但 2 一个在右上、一个在右下，是完全不同的公式。

### 方法一：归一化后再比较

第 3 章的 `normalize`：解析成语法树，再按唯一的规范写法写回去。第 2 部分的 300 个公式，归一化后 100% 相同。这是最直接的办法，很多公式识别的论文也这样做。它的局限是：

- **需要一个完整的解析器**：真实的 LaTeX 有上千个命令，写法千变万化（`\left(` 和 `(`、`\dfrac` 和 `\frac`、`\mathrm{d}` 和 `d`、各种空白命令 `\,` `\quad`），很难穷尽；
- **解析失败怎么办**：模型输出了一个少了花括号的公式，解析器直接报错，只能给 0 分。

### 方法二：CDM

CDM（Character Detection Matching，Wang 等，2024）换了一个角度：**公式是给人看的，就比较看起来是否一样**。

1. 把预测和参考答案都用 LaTeX **渲染成图像**；
2. 找出图像里每个字符的位置（真实的 CDM 给每个字符涂上不同的颜色再渲染，从颜色里找出每个字符的框）；
3. 把两边的字符**配对**：同一个字符、位置一致才算配对成功；
4. 算 F1：

```
CDM = 2 × 配对成功的字符数 / (预测的字符数 + 参考的字符数)
```

还有一个更严格的版本 ExpRate@CDM：CDM = 1（完全正确）的公式所占的比例。

OmniDocBench 用 CDM 作为公式的主要指标。它的优点是对所有"渲染相同"的写法自动免疫，不需要穷举等价规则；缺点是要能渲染（无法渲染的预测得 0），而且渲染和配对都比字符串比较慢得多。

### 我们的简化版

第 2 章的渲染器在排版时就知道每个符号画在哪里（`layout` 返回的绘图命令里有每个字符的坐标和字号），所以不需要"涂颜色再找框"，直接拿到符号的位置：

```python
def symbols(latex, size=16):
    """LaTeX → [(符号, x 中心, y 中心, 字号)]，按 x 排序；分数线记作 "frac"，根号记作 "sqrt"。"""
```

配对是关键。如果要求两边的符号位置**完全一样**，预测在最前面多了一个字符，后面所有字符都向右平移了一格，就全部配不上。真实的 CDM 先用匈牙利算法做初步配对，再用 RANSAC 估计一个整体的变换、剔除不一致的配对。我们用一个简单些、思路相同的办法：

- 两边的符号都按横坐标排序；
- 做**最长公共子序列**（LCS，和第 13 章编辑距离是同一类动态规划）；
- 两个符号"相等"的条件：同一个符号、纵向位置相差不超过 1/4 个字号、字号相近。

横向用 LCS，允许整体错位；纵向和字号必须一致，所以上标和下标、分子和分母能区分开。

### 练习 25.4：`match_count`

在 `miniocr/eval/cdm.py` 里实现带二维约束的 LCS。测试检查了：等价写法得 1；`x_{2}` 和 `x^{2}` 得 0.5（x 配上了，2 没配上：2 × 1 / (2 + 2)）；预测少一个开头的字符时，后面的字符仍然能配上。

### 简化版的局限

第 2 部分的表里有一个值得注意的结果：在分式 `\frac{x^{2}+1}{y_{n}}` 里把上标写成下标，CDM 只有 0.429，而同样的错误放在分式外面（`x^{2}+1` → `x_{2}+1`）是 0.75。原因：分子里出现下标后，分子的"深度"变大了，排版时整个分子被抬高，分子里的**所有**符号都向上移动了，超过了 1/4 个字号的容差，全部配不上。

这正是真实的 CDM 要用 RANSAC 估计局部变换的原因。**渲染式的指标对"局部的整体平移"很敏感**，处理不好就会过度惩罚。这也提醒我们：用一个指标之前，要用几个手工构造的例子检查它的行为，看它是不是在测你想测的东西。

## 25.5 表格：树的编辑距离

### 表格的表示

表格识别的输出通常是 HTML（PubTabNet、OmniDocBench 都用 HTML）：

```html
<table>
  <tr><td>Name</td><td>Age</td></tr>
  <tr><td>bob</td><td>12</td></tr>
</table>
```

合并单元格用 `colspan`（跨几列）和 `rowspan`（跨几行）表示。也有用 Markdown、LaTeX、OTSL（一种专门为表格设计的精简标记）表示的，评测时通常先转成 HTML。

为什么不直接比较 HTML 字符串？第 3 部分的实验：两行顺序颠倒，表格的意思变了很多，HTML 字符串的 NED 只有 0.116；一格的文字全错，NED 只有 0.017。HTML 里大部分字符是标签（`<td>`、`</tr>`），文字只占一小部分，**字符串比较被标签"稀释"了**。

### 表格是一棵树

把 HTML 看成一棵树：

```
          table
         /     \
       tr       tr
      /  \     /  \
    td    td  td   td
  "Name" "Age" "bob" "12"
```

两棵树的**编辑距离**：把一棵树变成另一棵，最少需要几次操作：

- **删除**一个节点：它的子节点接到它的父节点上；
- **插入**一个节点；
- **改名**：改一个节点的标签（代价可以是 0 到 1 之间的数）。

**TEDS**（Tree-Edit-Distance-based Similarity，Zhong 等，2020，随 PubTabNet 提出）：

```
TEDS = 1 − 树的编辑距离 / max(两棵树的节点数)
```

改名的代价：两个都是 td 时，colspan / rowspan 不同记 1；相同则记两格文字的 NED（错一个字记一点，全错记 1）。其他节点（table、tr）标签相同记 0。

只比较结构、不管文字的版本叫 **TEDS-S**（S = structure）：td 的文字不计代价。它把"表格结构识别"和"单元格文字识别"分开评测。

手算：上面 2×2 的表有 7 个节点（1 个 table、2 个 tr、4 个 td）。预测把 "bob" 认成了 "bab"：只有一个 td 要改名，代价 NED("bab", "bob") = 1/3。TEDS = 1 − (1/3) / 7 = 0.952。TEDS-S = 1。

### 树的编辑距离怎么算

一般的有序树的编辑距离用 Zhang–Shasha 算法（1989）。它的思路和字符串的编辑距离一样是动态规划，只是"前缀"换成了"森林"（把树按后序遍历编号后，编号连续的一段节点组成的若干棵子树）：

1. 把两棵树按**后序**遍历（先子节点、后父节点）编号，记下每个节点的**最左叶子**的编号 l(i)；
2. 找出**关键根**（keyroots）：每个"最左叶子"相同的节点里，编号最大的那一个（根总是关键根）；
3. 对每一对关键根 (i, j)，用动态规划算森林距离 fd，顺便填好所有"以完整子树结尾"的子问题的答案 td；
4. td[最后][最后] 就是两棵整树的距离。

森林距离的递推（x、y 是两边森林里节点的个数，i₁、j₁ 是两边森林的最后一个节点）：

```
fd[x][y] = min( fd[x−1][y] + 删除代价,                 删除 i₁
                fd[x][y−1] + 插入代价,                 插入 j₁
                ① 若 i₁、j₁ 各自是一棵完整的子树（最左叶子正好是森林的起点）：
                   fd[x−1][y−1] + 改名代价(i₁, j₁)     并记下 td[i₁][j₁] = fd[x][y]
                ② 否则：
                   fd[l(i₁) 之前][l(j₁) 之前] + td[i₁][j₁] )   用已经算好的子树距离 )
```

两棵树分别有 n、m 个节点时，时间复杂度最坏是 O(n² m²)，对一般的树要好得多。一张 20×10 的表格大约有 220 个节点，Python 实现几秒内能算完；真实的评测工具用的是更快的 APTED 算法。

### 练习 25.5：`tree_edit_distance`

在 `miniocr/eval/teds.py` 里实现 Zhang–Shasha 算法。测试用的是原论文的例子：f(d(a, c(b)), e) 与 f(c(d(a, b)), e) 的距离是 2。HTML 的解析（`parse_table`）已经写好：它用 Python 自带的 `html.parser`，能容忍没闭合的标签，模型输出到一半就停了也能算分。

### 第 3 部分的结果

200 张随机表格，每种错误的平均分：

| 错误 | TEDS | TEDS-S | HTML 字符串 NED |
|---|---|---|---|
| 一格文字错一个字符 | 0.982 | 1.000 | 0.005 |
| 一格文字全错 | 0.941 | 1.000 | 0.017 |
| 两格被合并 | 0.881 | 0.881 | 0.078 |
| 少了一行 | 0.778 | 0.778 | 0.218 |
| 多了一列 | 0.800 | 0.800 | 0.169 |
| 两行顺序颠倒 | 0.700 | 0.945 | 0.116 |

- 文字错误只影响 TEDS，不影响 TEDS-S；结构错误两个都影响；
- **两行颠倒**的 TEDS 是 0.700，在所有错误里最低：两行的每一格文字都"错了"（被放到了另一行），代价很大。TEDS-S 却仍有 0.945，因为两行的结构（每行几格）通常一样，只有带合并单元格的行颠倒时结构才不同；
- HTML 字符串的 NED 和 TEDS 的排序不一致：一格文字全错的 NED（0.017）比两格合并（0.078）小很多，而它们的 TEDS 差得没那么多。

## 25.7 一个数字有多可信

### 测试集只是一个样本

第 13 章的 CRNN 在 2000 行测试集上的 CER 是 2.28%。如果再随机生成另外 2000 行（同样的分布），CER 会是多少？大概不会正好是 2.28%。**测试集是从"所有可能的文字行"里抽出的一个样本，测试集上的指标是对"真实错误率"的一个估计**，估计有误差。

第 6 章的公式：准确率 p 在 n 个独立样本上的标准差是 √(p(1−p)/n)。整行全对的比例 80.1%、n = 2000：标准差 √(0.801 × 0.199 / 2000) = 0.89%，95% 的区间大约是 ±1.96 × 0.89% = ±1.75%，即 78.4%–81.8%。

CER 不是简单的比例（分子是编辑距离、分母是字符数，每行的长度不同），没有这么简单的公式。这时用 bootstrap。

### bootstrap

bootstrap（Efron，1979）的思路：**把测试集当成总体**，从它里面有放回地抽 n 个样本，组成一个"新的测试集"，算一次指标。重复几千次，得到几千个指标值，它们的分布就近似于"换一批测试样本时指标的分布"。

```
重复 B = 2000 次：
    从 n 行里有放回地抽 n 行（有的行被抽到多次，有的一次也没有）
    CER* = 这 n 行的编辑距离之和 / 这 n 行的参考长度之和
95% 置信区间 = 2000 个 CER* 的 2.5% 分位数 到 97.5% 分位数
```

注意**每次重抽的单位是"行"**：一行的编辑距离和长度要一起抽，不能分开抽。如果测试样本之间有关联（同一页文档的多行、同一张图的多个问题），重抽的单位应该是"页"或"图"，否则区间会偏窄。

第 4 部分：CRNN 的 CER 2.28%，95% 区间 2.02%–2.55%；整行全对 80.1%，区间 78.4%–81.8%，和上面的公式算出来的一样。

### 练习 25.6：`bootstrap_ci`

在 `miniocr/eval/stats.py` 里实现 `bootstrap_ci(num, den)`。用 numpy 一次生成所有的下标：`rng.integers(0, n, size=(B, n))`，比写 Python 循环快几百倍。

### 测试集要多大

第 4 部分在不同大小的测试集上算区间宽度：

| n | CER | 95% 区间宽度 |
|---|---|---|
| 100 | 3.02% | 1.99% |
| 300 | 2.29% | 1.21% |
| 1000 | 2.20% | 0.65% |
| 2000 | 2.28% | 0.53% |

宽度大约和 1/√n 成正比：样本数变成 4 倍，区间宽度减半。100 行的测试集上，CER 可以从 2% 到 4%，**用 100 个样本比较两个 CER 相差 0.5% 的模型，毫无意义**。

### 配对比较

第 13 章的束搜索把 CER 从 2.28% 降到了 2.24%。这是真的改进吗？

看两个区间：束搜索 [1.98%, 2.50%]，贪心 [2.02%, 2.55%]，几乎完全重叠。按这个看法，"看不出差别"。

但这个比较方法是错的。两个区间各自包含了"测试集抽样"的波动：恰好抽到难的行，**两个系统都**变差；抽到容易的行，两个系统都变好。比较两个系统时，这部分波动是共同的，应该抵消掉。

**配对 bootstrap**：每次重抽同一组下标，两个系统在同一批行上算，记录它们的**差**：

```
重复 B 次：
    抽一组下标 idx
    差* = (Σ 系统 A 在 idx 上的编辑距离 − Σ 系统 B 在 idx 上的编辑距离) / Σ idx 上的参考长度
差的 95% 区间 = 差* 的 2.5% 到 97.5% 分位数
```

第 4 部分的结果：束搜索 − 贪心 = −0.04%，95% 区间 [−0.07%, −0.02%]，**整个区间都在 0 的左边**，2000 次重抽里 100% 的差都 ≤ 0。束搜索确实更好，只是好得很少。两个系统只有 26 行的输出不同，其余 1974 行完全一样，这 1974 行对差没有任何贡献，配对比较把它们的波动完全去掉了。

### McNemar 检验

对"对 / 错"类的指标（整行全对、问答准确率），配对比较的经典方法是 McNemar 检验。只有"一个对、一个错"的样本有信息：

- b₁₀ = A 对 B 错的样本数，b₀₁ = A 错 B 对的样本数；
- 如果两个系统一样好，这 b₁₀ + b₀₁ 个样本里，A 赢的次数应该服从 Binomial(b₁₀ + b₀₁, 0.5)；
- p 值 = 在这个二项分布下，出现"至少这么不平衡"的结果的概率（双侧）。

第 4 部分：束搜索对而贪心错的 9 行，反过来 2 行。11 个样本里 9 比 2，p = 0.065，**按通常的 0.05 标准不显著**。

同一对系统，CER 的配对 bootstrap 说"显著更好"，整行全对的 McNemar 说"不显著"。这不矛盾：CER 用到了每个字符的信息，统计上更敏感；整行全对只看 11 个有差别的行，信息太少。**选指标也是在选"能检测出多小的差别"**。

另一个对照：无 RNN − 有 LSTM，CER 差 +2.48%，区间 [+2.23%, +2.74%]；整行全对 67 比 401，p = 4.85 × 10⁻⁵⁹。这是一个毫无疑问的差别。

### 训练的随机性

上面的区间只考虑了**测试集的抽样**。还有另一种不确定性：**同样的配置、同样的数据，换一个随机种子重新训练**，模型就不一样（初始化、数据的顺序都变了）。第 6 部分让你用 3 个新的种子重新训练第 13 章的 CRNN（第 13 章的日志里一次训练约 10 分钟），在同一个测试集上比较。这个实验由你自己跑，25.11 节给出做法和读结果的方法。

这两种不确定性要分开看：

| 来源 | 回答的问题 | 怎么估计 |
|---|---|---|
| 测试集抽样 | "这个模型"在新数据上的错误率是多少 | bootstrap，一次训练就够 |
| 训练的随机种子 | "这个训练方法"能得到多好的模型 | 多个种子训练，看分布 |

比较两种**训练方法**（比如"加了数据增强"vs"没加"）时，后者往往更重要。一个常见的错误是：方法 A 跑了一次，方法 B 跑了一次，B 好 0.3%，就宣布 B 更好，但种子之间的波动可能就有 0.3%。第 26 章起，重要的结论都用多个种子。

### 多重比较

如果你试了 20 种改动，每种在测试集上和基线比较，即使所有改动都没用，按 p < 0.05 的标准，平均也会有 1 个"显著"。然后你选出它，写进论文。这叫**多重比较**问题，也是"在测试集上调参"的一种形式。办法：

- 用验证集做所有的选择，测试集只在最后用一次；
- 事先写好要比较什么（评测协议）；
- 比较很多次时，用更严格的阈值（Bonferroni 校正：阈值除以比较的次数）。

## 25.8 平均数背后：分桶与泄漏

### 分桶

一个总体的 CER 是所有错误的平均，它会掩盖问题集中在哪里。**分桶**（slicing）：按某个属性把测试集分组，每组单独算指标。第 5 部分的结果：

- **按行长**：整行全对的比例从短行的 90.2% 降到长行的 72.5%（行越长，越容易至少错一个字符），但 CER 几乎不变（2.1%–2.6%）。"整行全对"和"CER"对长度的依赖完全不同；
- **按词的类型**：全大写的词 CER 5.27%，是普通词（2.64%）的两倍；日期只有 0.76%。全大写的词只占训练数据的约 5%（第 13 章的数据生成器里，单词有 5% 的概率写成全大写），模型见得少。

分桶的结果直接告诉你**下一步该做什么**：要降低总体的 CER，最有效的是多加全大写的训练数据，而不是继续调模型。第 33 章做文档数据工程时会大量用到分桶。

常见的分桶维度：文字的长度、字号、字体；图像的分辨率、噪声、模糊；文档的类型（论文、收据、表格）；语言；内容的类型（文字、公式、表格）。

### 辛普森悖论

分桶还能避免一种严重的误判。假设模型 A 在每个分桶里都比 B 好，总体却比 B 差，这可能吗？可能，只要两个模型在**各分桶的样本数不同**。例如，A 在难的样本上测得多，B 在容易的样本上测得多。这叫辛普森悖论。比较两个系统时，一定要用**同一个测试集**，这也是配对比较的前提。

### 数据泄漏

**泄漏**（leakage）：测试集里的样本，或者和它们很像的样本，出现在了训练集里。模型"记住"了答案，测试分数虚高。

第 7 部分检查第 13 章的数据：测试集 2000 行里有 **253 行（12.7%）一字不差地出现在训练集里**。原因是随机生成的短行（一两个词）很容易重复：这 253 行平均只有 4.1 个字符。

模型在这些行上的表现：

| | 行数 | CER | 整行全对 |
|---|---|---|---|
| 训练集里出现过 | 253 | 1.82% | 92.5% |
| 没出现过、同样短（≤ 10 个字符） | 342 | 2.52% | 85.1% |

在长度相近的行里比较，见过的行明显更好：CRNN 的双向 LSTM 学到了训练集里的"文字规律"，对见过的整行有记忆。这一次泄漏的影响不大（去掉这 253 行，CER 是 2.29%；不去掉是 2.28%），因为重复的行很短、占的字符少。但在真实的大模型上，泄漏可以非常严重：

- **基准污染**（contamination）：大模型的预训练数据从互联网上抓取，很多公开的测试集（包括它们的答案）就在网上。一个在 DocVQA 测试集上"见过答案"的模型，分数不能说明它的能力；
- **近似重复**：训练集里有同一个文档的另一个版本（不同的扫描、裁剪、压缩），测试时等于见过；
- **模板重复**：同一个模板生成的表单，训练和测试只差填的内容。

检查方法：精确去重（哈希）；近似去重（图像的感知哈希、文字的 n 元组重叠，比如"13 元组重叠"是语言模型常用的污染检查）；按来源划分训练和测试（同一个文档、同一个作者、同一个模板只能在一边）。

## 25.10 评测协议

**评测协议**是一份在跑实验**之前**写好的文档，规定怎么评测。之后的每一章都按这个模板报告结果：

```markdown
## 评测协议：<模型或实验名称>

### 1. 要回答的问题
例：在 MiniDoc 文字行上，加入 1 万行全大写数据能否降低 CER，且不损害其他类型的词。

### 2. 数据
- 测试集：来源、大小、生成方式（种子）、与训练集的去重方法
- 验证集：用于所有超参数选择和早停；测试集只在最后运行一次
- 分桶：按行长、词的类型

### 3. 指标与归一化
- 主指标：语料级 CER（区分大小写；空白合并、去首尾空白）
- 次要指标：整行全对；各分桶的 CER
- 生成设置：贪心解码，max_new_tokens = 64

### 4. 不确定性
- 测试集抽样：bootstrap 95% 区间（2000 次，以"行"为单位重抽）
- 系统比较：配对 bootstrap（CER）、McNemar（整行全对）
- 训练的随机性：每个配置 3 个种子，报告平均和标准差

### 5. 判定标准（事先写好）
例：新方法的 CER 在 3 个种子上的平均值比基线低，且每个种子的配对差的 95% 区间都不包含 0，才算"更好"。

### 6. 已知的局限
例：测试集是合成数据，结论不一定迁移到真实扫描件。
```

第 5 条最容易被跳过，也最重要：**看到结果之后再决定"多大的差别算有意义"，几乎总会偏向你希望的结论。**

## 25.13 常见错误

| 现象 | 原因 | 怎么查 |
|---|---|---|
| 同一个模型，和论文报告的分数差好几个点 | 归一化不同（大小写、空白、Unicode、标点）；指标的实现不同（语料级 vs 逐样本平均） | 用官方的评测脚本；在协议里写清每一步 |
| CER 超过 100% | 模型输出了很长的胡话（停不下来、重复） | 看预测长度的分布；同时报告 NED；检查 EOS 和 max_new_tokens |
| 加了一个改动，测试集上好了 0.3%，换种子就没了 | 种子噪声比改动的效果大 | 多个种子；报告平均和标准差 |
| 测试分数很高，上线后很差 | 测试集与训练集泄漏；测试集与真实数据分布不同 | 去重；按来源划分；建一个"真实数据"的小测试集 |
| 模型答对了却被判错 | 精确匹配太严格（"$38.50" vs "38.50"） | 规定输出格式；用 ANLS 或包含匹配；人工检查一批"错误" |
| 模型答错了却被判对 | 包含匹配太宽松（把所有选项都说一遍） | 限制回答长度；用更严格的匹配 |
| 两个区间重叠，就说"没有差别" | 没有配对 | 配对 bootstrap 或 McNemar |
| 公式全对的模型被扣了很多分 | 按原始字符串比较，等价写法被当成错误 | 归一化后比较，或用 CDM |
| 表格的分数变化很小，但表格明显错了 | 用 HTML 字符串比较，被标签稀释 | 用 TEDS；分别报告 TEDS 和 TEDS-S |
| 在测试集上反复调参后，结果不能复现 | 对测试集过拟合（多重比较） | 只用验证集做选择；测试集只用一次 |

## 25.14 真实世界对照

- **官方评测脚本**：DocVQA、TextVQA、OCRBench、OmniDocBench 都有官方的评测代码（通常在 GitHub 上），归一化、匹配规则都在里面。比较时一定用同一份代码；VLMEvalKit、lmms-eval 是两个常用的"统一评测框架"，把几十个基准的数据和打分整合在一起；
- **CDM 的实现**：官方实现在 OmniDocBench 的仓库里，需要安装 LaTeX 来渲染；
- **TEDS 的实现**：PubTabNet 的官方代码用 `apted` 库（APTED 算法，比 Zhang–Shasha 快）；
- **人工评测**：对开放式的输出（描述、长文档的总结），自动指标和人的判断往往不一致。重要的结论要抽一批样本人工检查；
- **竞技场**：Chatbot Arena、OCR Arena 一类的平台让用户对两个匿名模型的回答投票，用 Elo / Bradley–Terry 模型排名。它测的是"人更喜欢哪个"，不是"哪个更正确"。

## 25.15 深入一步

### 百分位 bootstrap 的局限

本章用的是最简单的"百分位法"：直接取 bootstrap 分布的分位数。当指标的分布很偏（比如错误率接近 0，大多数重抽的错误率都是 0），或者样本很少时，它的区间可能不准。更精确的方法有 BCa（偏差校正和加速）bootstrap。实践中，样本数在几百以上、指标不在 0 或 1 附近时，百分位法足够了。

### 为什么不用 t 检验

两个系统的逐样本误差相减，再对差做 t 检验（配对 t 检验），也是一种做法。它假设差近似服从正态分布。OCR 的逐行编辑距离分布很偏（80% 的行是 0，少数行有好几个错误），而且 CER 是比值，不是平均值。bootstrap 不需要这些假设，所以更常用。

### 指标的"效度"

一个指标好不好，最终要看它和**真正关心的东西**是否一致。比如：CER 低的 OCR 模型，下游的问答一定更准吗？不一定：如果错误集中在数字上，CER 低但问答很差。研究指标的效度，常用的方法是收集人工判断，算指标与人工判断的相关性（比如 CDM 的论文就做了这样的比较，发现 CDM 比 BLEU、编辑距离更接近人的判断）。

## 25.17 本章小结

- 指标是问题的翻译：先问"什么错误代价最大"，再选指标；同一个错误，CER、WER、NED、BLEU 的看法可以完全不同；
- CER 有语料级和逐样本平均两种算法；CER 可以超过 100%，NED 不会；比较之前的归一化必须写清楚；
- 问答用 ANLS（容忍小错、惩罚答非所问）或 VQA 准确率（容忍人和人之间的分歧）；
- 公式要按渲染结果比较（CDM），否则等价写法会被当成错误；我们的简化版用"带二维约束的 LCS"配对符号，对局部的纵向平移敏感；
- 表格用树的编辑距离（TEDS），TEDS-S 只比结构；HTML 字符串的比较被标签稀释；
- 测试集上的数字是一个估计：用 bootstrap 给出置信区间；比较两个系统要配对；测试集小于几百个样本时，大部分"差别"都是噪声；
- 训练的随机种子是另一种不确定性，比较训练方法时往往比测试集抽样更重要；
- 分桶找出平均数掩盖的问题；检查测试集与训练集的重叠；评测协议要在看到结果之前写好。

| 字符错误率 | character error rate, CER | 总编辑距离 / 参考答案的总字符数 |
| 词错误率 | word error rate, WER | 词级的编辑距离 / 参考答案的总词数 |
| 归一化编辑距离 | normalized edit distance, NED | 编辑距离 / 两者中较长的长度 |
| 平均归一化编辑相似度 | ANLS | 1 − NED，NED ≥ 0.5 记 0，多个答案取最好 |
| 字符检测匹配 | Character Detection Matching, CDM | 渲染公式后按符号和位置配对，算 F1 |
| 树编辑距离相似度 | TEDS | 1 − 树的编辑距离 / 最大节点数 |
| 语料级 | corpus-level | 先把所有样本的分子、分母分别加起来再相除 |
| 宏平均 | macro-average | 先算每个样本（或每类）的指标再平均 |
| 自助法 | bootstrap | 有放回地重抽测试集，估计指标的波动 |
| 配对比较 | paired comparison | 两个系统在同一批样本上比较差，抵消样本难度的波动 |
| 分桶 | slicing / bucketing | 按属性分组后分别算指标 |
| 数据泄漏 | data leakage | 测试样本或其近似副本出现在训练数据里 |
| 基准污染 | benchmark contamination | 公开基准的题目和答案进入了预训练语料 |
| 多重比较 | multiple comparisons | 比较很多次，总会有"显著"的结果 |
| 评测协议 | evaluation protocol | 跑实验之前写好的评测规则 |

## 参考答案

1. CER 的分母是参考答案的长度，预测可以比参考长很多（插入很多字符），编辑距离就超过参考长度。模型可能输出很长的内容（生成式模型停不下来、重复）时，用 NED（分母是两者中较长的）更合适，它在 0 到 1 之间。
2. 语料级 = Σ 编辑距离 / Σ 长度，长样本的权重大；逐行平均 = 每行的 CER 的平均，每行权重相同，短行的错误影响更大。
3. 一个 4 个词的句子只有一个 4 元组，错一个词 p₄ 就是 0，几何平均也变成 0。BLEU 本来是在整个语料上统计的，单句要加平滑。
4. 阈值让"答非所问"得 0 分；否则任何一个随便的回答，只要和答案有几个字符相同，都能得到一些分数，多个错误答案的分数加起来会抬高总分。
5. 同一个公式有很多等价写法，按字符串比较会把正确的预测判错；字符串差得少不代表渲染出来差得少（上标 vs 下标）。归一化需要一个覆盖所有写法的解析器，解析失败只能给 0；CDM 要能渲染，渲染和配对慢，配对方法本身也会出错（比如对局部的平移敏感）。
6. TEDS-S 只比结构，单元格的文字不计代价。两行颠倒后，每一格的文字都和参考对不上（TEDS 扣很多分），但每行的格数通常一样（结构基本不变，TEDS-S 扣得少）。
7. 两个区间各自包含了"测试集抽样"的波动，而这部分波动对两个系统是共同的（难的样本对两个系统都难）。配对比较只看差，抵消了共同的波动，区间窄得多。
8. 测试集抽样：这一个训练好的模型，在新数据上的错误率是多少；训练种子：这个训练方法（配置）能得到多好的模型，结果有多稳定。
9. 比较很多次时，即使都没有真实的差别，也会有一些比较碰巧"显著"。避免：用验证集做选择、测试集只用一次；事先写好要比较什么；比较很多次时用更严格的阈值（如 Bonferroni 校正）。
10. 测试样本原样出现在训练集里（精确去重：哈希）；近似重复（同一文档的不同扫描、同一模板）（感知哈希、n 元组重叠、按来源划分）；公开基准进入预训练语料（检查 n 元组重叠，用发布时间晚于模型训练时间的新数据）。
11. 标准差 √(0.85 × 0.15 / 400) = 1.79%，95% 区间约 85% ± 3.5%。要 ±1%：1.96 × √(0.1275 / n) = 0.01，n ≈ 4900 道题。
12. 少了一个 "the"：编辑距离 1，WER = 1/6 = 16.7%。BLEU-1：预测 5 个词都在参考里（"the" 在参考里出现 2 次，预测里 1 次），p₁ = 5/5 = 1；c = 5 < r = 6，BP = exp(1 − 6/5) = 0.819；BLEU-1 = 0.819。
13. 1 个 table + 3 个 tr + 9 个 td = 13 个节点。改名代价 NED("13", "12") = 1/2，TEDS = 1 − 0.5 / 13 = 0.962。
14. (30 − 10)² / 40 = 10 > 3.84，p ≈ 0.0016（精确的二项检验 `mcnemar` 给出约 0.002），差别显著。
15. 编辑距离和长度被**分开**抽样了：分子来自一组行，分母来自另一组行，打乱了每行"错误数和长度"的对应关系。应该抽下标，用同一组下标同时取 errs 和 lens（`bootstrap_ci` 就是这样做的）。另外 `np.random.choice` 没有固定种子，结果不可复现。
16. 准备两个模型（有 / 没有数据增强）在**同一个测试集**上的逐行预测，算出每行的编辑距离 errs_a、errs_b 和参考长度 lens，调用 `paired_bootstrap(errs_a, errs_b, lens)`，看差的区间是否整个在 0 的一侧。更完整的做法是每个配置训练多个种子，对每个种子各做一次配对比较。
