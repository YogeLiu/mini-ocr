## 34.1 怎样读一篇技术报告

技术报告不是论文。它的主要目的是介绍一个发布的模型，所以通常：

- **结果很全**：几十个基准、和很多模型的对比；
- **方法讲清楚"做了什么"**：流程图、公式、数据来源；
- **超参数常常缺失**：学习率、批大小、数据配比、阈值，很多报告只给符号不给数值；
- **消融有限**：每个消融通常只跑一次，没有置信区间。

建议按三栏做笔记：

| 栏 | 记什么 | 例子（本报告） |
|---|---|---|
| 声称 | 作者对方法作用的解释 | "文字锚定建立了文字内容与空间位置的细粒度对齐" |
| 测量 | 有数字支持的结果 | Q-Mask 消融：OmniDocBench 总分 96.0241 → 96.3198 |
| 缺失 | 复现需要、报告没给的 | λ_seg、λ_MTP、学习率、组大小 G、ε_low / ε_high、各阶段的数据量 |

"声称"要和"测量"对上才算数；"缺失"决定你复现时要自己做多少实验。本章最后（34.8 节）汇总了这份报告的缺失清单。

## 34.2 全景：模型、推理和三个训练阶段

### 模型与推理

- **一个统一的 0.8B VLM**，从 Qwen3.5-0.8B 初始化（第 24 章拆过它：任意分辨率的 ViT、2×2 合并、M-RoPE、混合了线性注意力的语言模型）；
- **不同的任务用不同的指令**区分：区块文字识别、公式、表格、整页解析、关键信息抽取（KIE）、OCR 问答；
- **整页解析是两阶段的**（第 33 章）：
  1. 外部的版面检测器 PP-DocLayoutV3 找出区块；
  2. 模型逐块识别每个裁剪出来的区块；
  3. 再拼成整页的输出。

  0.8B 这个参数量**不含**版面检测器。

### 三个训练阶段

```
Qwen3.5-0.8B
   │  ① 文字锚定（Q-Mask，式 12）：TextAnchor-26M + 数据引擎的文档解析样本
   │       NTP + 掩码预测（Dice + CE）；阶段结束后去掉掩码解码器
   ▼
   │  ② OCR 持续预训练（CPT，式 13）：以文档解析为主，加 OCR 问答、描述、场景文字、手写、
   │       书法、化学式、图表等；NTP + MTP（保留底座的一个 MTP 头一起训练）
   ▼
   │  ③ Mix-RL（式 14、15）：DAPO 风格（token 级汇总、clip-higher、动态采样），不加 KL；
   │       难例由多因素挖掘挑出，再经更强的语言模型和人工复核
   ▼
Xiaomi-OCR-0
```

报告**没有**单独的 SFT 阶段：持续预训练本身就是在指令格式的数据上做的（"图像—指令—回答"的统一格式），从作用上看它就是一次大规模的 SFT（第 26 章）。

## 34.3 数据引擎：1.7 亿条样本从哪里来

报告第 2 节描述的语料约 1.7 亿条，统一成"图像—指令—回答"的格式。数据引擎有三个部分：三元组共识打标签、渲染引导的修正与评判、多因素挖掘；另外还有合成数据。

### 三元组共识（Ensemble Triplet Consensus，ETC）

**专家池**：8 个开源 OCR 模型，分别是 PaddleOCR-VL-1.6、MinerU2.5-Pro、GLM-OCR、dots.ocr、HunyuanOCR-1.5、TeleOCR、OvisOCR2、Qianfan-OCR。每个区块，8 个专家各读一遍，得到 y_1 … y_8。

**相似度** S：

- 文字用 1 − NED；
- 表格用 TEDS；
- 公式用 CDM。

都是第 25 章写过的指标。

专家 i 和其他专家的平均一致度（式 1）：

```
C_i = (1 / (N − 1)) · Σ_{j ≠ i} S(y_i, y_j)
```

在所有三人组合里，选组内两两一致度最高的那一组 T*，它的一致度（式 2）是三对的平均：

```
a(x) = (1/3) · Σ_{i<j, i,j ∈ T*} S(y_i, y_j)
```

伪标签取这一组的**中心点**（medoid，式 3）：和组内另外两个成员一致度之和最大的那个读法。按 a(x) 分三档（式 4）：

| 档 | 条件 | 处理 |
|---|---|---|
| 高 | a ≥ 0.9 | 直接收下 |
| 中 | 0.6 ≤ a < 0.9 | 送去修正 |
| 低 | a < 0.6 | 送去修正 |

**为什么是"三人组"而不是"多数票"**：第 33 章看到，长文本几乎不可能有两个模型读得一字不差，"完全相同才算一票"的多数投票会把大部分样本丢掉。三元组用连续的相似度，只要求"8 个人里有 3 个人读得很像"。这样既不需要所有人都同意（某些专家在某类文档上整体很差，不会拖累结果），又比"两个人一致"更难碰巧发生。

**手算一个例子**。4 个专家读同一行字，两两的 1 − NED 如下：

|  | y1 | y2 | y3 | y4 |
|---|---|---|---|---|
| y1 | 1 | 0.95 | 0.92 | 0.40 |
| y2 | 0.95 | 1 | 0.97 | 0.42 |
| y3 | 0.92 | 0.97 | 1 | 0.38 |
| y4 | 0.40 | 0.42 | 0.38 | 1 |

先算各专家的平均一致度：C_1 = (0.95 + 0.92 + 0.40) / 3 = 0.757，C_2 = 0.780，C_3 = 0.757，C_4 = 0.400，y4 明显是"离群的专家"。

再看四个三人组：

| 三人组 | 一致度 |
|---|---|
| {1, 2, 3} | (0.95 + 0.92 + 0.97) / 3 = 0.947 |
| {1, 2, 4} | (0.95 + 0.40 + 0.42) / 3 = 0.590 |
| {1, 3, 4} | 0.567 |
| {2, 3, 4} | 0.590 |

T* = {1, 2, 3}，a = 0.947，属于高档。组内的一致度之和分别是：y1：0.95 + 0.92 = 1.87，y2：0.95 + 0.97 = 1.92，y3：0.92 + 0.97 = 1.89。所以中心点是 y2，它成为伪标签。

第 33 章的 `triplet_consensus` 和 `tier` 就是这几个式子。第 1 部分把它用在第 33 章三个模型读 60 条真实公式的结果上（只有 3 个专家，三元组只有一种取法）。

### 渲染引导的修正与评判

中档和低档的区块不直接丢掉，而是交给一个专家池以外的大模型（Qwen3.5-122B-A10B）修正：

1. 用最一致的两个专家的读法作参考，给出初始读法（式 5）；
2. **渲染并核对**：把读法渲染出来（文字和表格用 HTML，公式用 LaTeX），让模型对照原图找出要改的地方，最多 T = 3 轮；改动的幅度小于一个按任务设定的阈值时提前停止（式 6–7，阈值报告未给出）；
3. 如果还没收敛，进入第二阶段：带着全部的核对历史"批评 → 修正 → 核对"（式 8），只有最后一次核对没有任何修改时才算通过；
4. 收敛的读法**作为一个新的候选加回专家池，重新做 ETC**；重新共识后进入高档的才自动收下，其余的扣下或交给人工核对。

两个设计值得注意：

- **修正模型的输出不直接当标签**，而是和专家们一起再投一次票。一个模型改出来的东西，必须得到其他专家的支持才算数；
- **渲染是核对的依据**。第 33 章的渲染校验是"画出来和原图逐像素比"，这里是"画出来给大模型看"，思路一样：把读法变回图像，才能和原图比较。

### 多因素挖掘

RL 和难例训练需要的不是"所有数据"，而是"值得学的数据"。报告用三个信号：

| 信号 | 含义 | 来源 |
|---|---|---|
| a_i | 专家一致度 | 上面的 ETC，越高说明标签越可信 |
| u_i | 模型自洽度 | 一个专家池以外的模型多次随机采样，读法之间越不一致，u 越低，说明模型越没把握 |
| 簇 | 内容的类别 | Qwen3-VL-Embedding 的特征做 K-Means（按任务类型分别聚类） |

**簇的名额**（式 9）：小簇按系数 ρ 过采样，避免大类（普通正文）挤掉小类（印章、竖排、化学式）。

**簇内的抽样权重**（式 10）：

```
P(i | k) = (a_i + ε)^(f_a/τ) · (1 − u_i + ε)^(f_u/τ)  /  Σ_{j ∈ 簇 k} (同样的式子)
```

a 高（标签可信）、u 低（模型不会）的样本权重大。τ 越小，权重越集中在少数样本上。

**难例候选**（式 11）：a_i ≥ τ_a 且 u_i ≤ τ_u。

ρ、f_a、f_u、τ、ε、τ_a、τ_u、簇数 K 的数值报告都没有给出。

### 练习 34.9：`sampling_weights`

```python
def sampling_weights(a, u, labels, f_a=1.0, f_u=1.0, tau=1.0, eps=1e-3):
    a, u, labels = np.asarray(a, float), np.asarray(u, float), np.asarray(labels)
    w = (a + eps) ** (f_a / tau) * (1 - u + eps) ** (f_u / tau)
    out = np.zeros_like(w)
    for k in np.unique(labels):
        m = labels == k
        out[m] = w[m] / w[m].sum()
    return out
```

第 2 部分给 8 个样本（两个簇）算了权重：

```
a = [0.98, 0.95, 0.92, 0.70, 0.40 | 0.99, 0.97, 0.60]
u = [0.95, 0.55, 0.30, 0.40, 0.20 | 0.90, 0.35, 0.10]
τ = 1.0：P(i | 簇) = [0.027, 0.23, 0.346, 0.226, 0.172 | 0.079, 0.496, 0.425]
τ = 0.5：P(i | 簇) = [0.003, 0.208, 0.472, 0.201, 0.117 | 0.014, 0.569, 0.417]
```

怎么读：

- 样本 0（a = 0.98，u = 0.95）：标签可信，但模型已经会了（每次都读得一样），权重最低；
- 样本 2（a = 0.92，u = 0.30）：标签可信、模型没把握，权重最高；
- 样本 4（a = 0.40，u = 0.20）：模型不会，但标签也不可信，权重中等。式 10 是乘积，两个因素都要好；
- τ 从 1 降到 0.5，样本 2 的权重从 0.346 升到 0.472，分布更集中。

### 合成数据

报告把合成分成两类：

- **覆盖驱动**：用模板生成长表格、合并单元格、少见的版面，用"材料驱动的仿真"生成书法、特殊字体、生僻字。补的是"数据里少见的类型"；
- **失败驱动**：以挖出来的难例为条件生成变体，重建后再和原样本比较。补的是"模型做错的类型"。这就是第 33 章说的定向合成。

质量控制包括规则校验、渲染一致性检查、去重、过滤。**划分按来源文档或页面**：验证集的组不进入训练、SFT 和任何合成的输入。这正是第 33 章强调的按组划分：如果合成的种子来自验证集，验证集就被"看过"了。

报告还描述了一个"合成配方验证"流程：把过滤后的定向数据按预设比例混入基础数据（排除验证集的组），在冻结的困难验证集上评测，并做回归检查。混合比例、增益、回归结果的数值都没有给出。

## 34.4 阶段一：文字锚定（Q-Mask）

### 想解决什么

一个 VLM 读字时，答案里的每个字应该"来自"图里的某个位置。如果模型只学"图 → 文字"的映射，它可能学会一些捷径：根据上下文猜词、根据版面猜内容。这正是第 23 章看到的幻觉的来源之一。

**文字锚定**的想法是：训练时除了让模型写出答案，还要它指出答案在图里的什么地方。这样，"答案里的内容"和"图里的位置"在表示里被绑在一起。

### Q-Mask 与 SSA 目标

Q-Mask 引入一个**按查询条件化的掩码解码器**：给定一个查询（比如"图里的 'Total' 在哪"），它预测一张空间掩码，和答案 token 一起监督。目标函数（式 12，空间监督对齐 SSA）：

```
L_SSA = λ_txt · L_NTP + λ_seg · (L_Dice + L_CE)
```

- L_NTP 是普通的下一个 token 预测；
- L_Dice + L_CE 监督掩码，CE 在这里是逐像素（或逐 token）的二元交叉熵。

训练数据是原有的 TextAnchor-26M 加上数据引擎产出的文档解析样本。**这一阶段结束后，掩码解码器被扔掉**，只保留视觉—语言主干。所以锚定是一种辅助训练：推理时没有任何额外开销。

报告没有给出的：λ_txt、λ_seg 的值；掩码在什么分辨率上计算；解码器接在模型的什么位置；TextAnchor-26M 的具体内容。

### 我们的简化版

我们的 VLM（第 22 章）的图是 64×64，一共 8×8 = 64 个视觉 token。锚定的标注从三种任务里来：

| 任务 | 掩码的来源 |
|---|---|
| 场景文字（text） | 单词的框 |
| 定位（ground，物体存在时） | 答案里的框 |
| 指代（refer） | 问题里的框 |

其他任务（描述、数数等）没有掩码，只算 NTP。

**掩码头**：

- 查询向量 q 取语言模型在"答案开始前最后一个位置"的隐藏状态。它已经看过图和问题，所以是"按查询条件化"的；
- 每个视觉 token 的隐藏状态是 v_j；
- 分数 s_j = (W_q q)·(W_k v_j) / √d_k + b。

一共只有两个 d × d_k 的矩阵和一个偏置。

### 练习 34.1：`box_to_grid_mask`

```python
def box_to_grid_mask(box, img_hw=(64, 64), grid_hw=(8, 8), min_cover=0.3):
    H, W = img_hw
    gh, gw = grid_hw
    ch, cw = H / gh, W / gw
    x0, y0, x1, y1 = box
    cover = torch.zeros(gh, gw)
    for r in range(gh):
        oy = max(0.0, min(y1, (r + 1) * ch) - max(y0, r * ch))
        for c in range(gw):
            ox = max(0.0, min(x1, (c + 1) * cw) - max(x0, c * cw))
            cover[r, c] = oy * ox / (ch * cw)
    m = (cover >= min_cover).float().flatten()
    if m.sum() == 0:
        m[int(cover.flatten().argmax())] = 1.0
    return m
```

一个框完全落在某个格子的中间、四个方向都只盖住格子的一部分时，可能没有任何格子达到 30%。这时取覆盖最多的那个格子，保证每个有标注的样本至少有一个前景 token。第 3 部分打印了一条场景文字样本的掩码：单词盖住了 8 个视觉 token（第 5、6 行的前 4 列）。

### 练习 34.2：Dice 损失

```python
def dice_loss(logits, target, eps=1.0):
    p = torch.sigmoid(logits.float())
    t = target.float()
    dice = (2 * (p * t).sum(-1) + eps) / (p.sum(-1) + t.sum(-1) + eps)
    return (1 - dice).mean()
```

Dice 系数是"预测与真值的重叠"除以"两者的平均大小"，和第 21 章的 IoU 是同一类指标。为什么 CE 之外还要它？第 3 部分算了一个例子：64 个 token 里有 3 个前景，模型把所有 token 都预测成背景（logit −5）：

```
CE 0.241，Dice 0.765
```

**CE 是对每个 token 平均的**。前景只占 3/64，全猜背景时，61 个背景 token 都"答对"了，平均损失很小。而 Dice 只看前景的重叠，全猜背景时重叠为 0，损失接近 1。第 3 部分的 32 条样本里，有掩码的样本前景平均只占 7.7% 的视觉 token。在这种极不平衡的情况下，CE 对每个前景 token 的梯度是 (p − 1) / 总 token 数，背景越多越被稀释；Dice 的分母是"预测的前景 + 真实的前景"，背景判对以后几乎不进入分母，前景的梯度不随背景的数量缩小（推导和数值例子见[附录 F.13](appendix_f_math.md)：背景从 61 个增加到 1021 个时，CE 对前景的梯度缩小到 1/16，Dice 只缩小到 1/2）。两者一起用是分割任务的常见做法：CE 让每个 token 的概率校准，Dice 保证前景不被忽略。

### 练习 34.3、34.4：掩码头与 SSA 损失

```python
def forward(self, query, vis):
    q = self.q(query)
    k = self.k(vis)
    return torch.einsum("bd,bnd->bn", q, k) / math.sqrt(self.d_k) + self.b


def ssa_loss(ntp, mask_logits, target, has_mask, lam_txt=1.0, lam_seg=0.5):
    if has_mask.any():
        ml, tg = mask_logits[has_mask], target[has_mask]
        dice = dice_loss(ml, tg)
        ce = F.binary_cross_entropy_with_logits(ml.float(), tg.float())
    else:
        dice = ce = ntp.new_zeros(())
    total = lam_txt * ntp + lam_seg * (dice + ce)
    return total, {"ntp": ntp.item(), "dice": dice.item(), "ce": ce.item()}
```

偏置 b 初始化为 −2（sigmoid(−2) ≈ 0.12），因为前景本来就少：一开始就让大多数 token 的概率偏低，前几步不会被大量的背景梯度主导。

第 3 部分在随机初始化的 VLM 上算了各项损失（32 条样本，其中 11 条有掩码）：

```
ntp 4.658  dice 0.854  ce 0.312  mtp 4.742       （ln 100 = 4.605）
mask 头 32,769 个参数，MTP 头 935,168 个参数，VLM 本身 4,164,224 个
```

NTP 和 MTP 的损失都接近 ln V（均匀猜），符合随机初始化的预期。掩码头只有 VLM 的 0.8%，训练后扔掉。

## 34.5 阶段二：OCR 持续预训练（NTP + MTP）

### 目标函数

```
L_CPT(θ) = −E_{(I, c, y)} [ Σ_t log π_θ(y_t | y_<t, I, c) ] + λ_MTP · L_MTP(θ)        （式 13）
```

I 是图像，c 是指令，y 是回答。第一项就是第 26 章的 SFT 损失（只在回答上算）。第二项是**多 token 预测**（multi-token prediction，MTP）：Qwen3.5 底座自带一个 MTP 头，报告保留它，和主干一起训练。λ_MTP 报告未给出。

数据以文档解析为主（区块和整页），另外有 OCR 问答、描述、场景文字、手写和书法、化学式、图表。各部分的比例、总 token 数、学习率报告都没有给出。

### MTP 头是什么

主干在位置 t 的隐藏状态 h_t 只用来预测下一个 token y_{t+1}。MTP 头（DeepSeek-V3 提出的形式）再往后看一步：

```
h'_t = Block( W · [RMSNorm(h_t) ; RMSNorm(e(y_{t+1}))] )
logits_{t+2} = head( RMSNorm(h'_t) )
```

- e(y_{t+1}) 是**真实的**下一个 token 的嵌入（训练时用教师强制，和主干一样）；
- Block 是一个完整的 Transformer 块（注意力 + MLP），也是因果的；
- head 和主干**共享**输出层。

它的作用：

1. **更密的监督**：每个位置多一个"往后两步"的预测目标，迫使 h_t 包含更多关于后文的信息；
2. **投机解码**：推理时，MTP 头可以作为"草稿模型"一次猜两个 token，主干验证。猜对时一次前向产出两个 token。

第 4 部分读了两个本机已有模型的配置：

```
Qwen3.5-0.8B：mtp_num_hidden_layers = 1，mtp_use_dedicated_embeddings = False
GLM-OCR：num_nextn_predict_layers = 1
```

两个都带一层 MTP 头（GLM-OCR 的模型卡也写明了用 MTP 损失训练）。`mtp_use_dedicated_embeddings = False` 说明 Qwen3.5 的 MTP 头和主干共用嵌入表，和我们的实现一样。

### 练习 34.5、34.6：MTP 头与损失

```python
def forward(self, lm, hidden, emb):
    x = self.proj(torch.cat([self.nh(hidden[:, :-1]), self.ne(emb[:, 1:])], -1))
    T1 = x.shape[1]
    x = self.block(x, lm.cos[:T1], lm.sin[:T1])
    return lm.head(self.norm(x))


def mtp_loss(mtp_logits, targets):
    tg = targets[:, 1:]
    if (tg != -100).sum() == 0:
        return mtp_logits.sum() * 0.0
    return F.cross_entropy(mtp_logits.reshape(-1, mtp_logits.shape[-1]).float(), tg.reshape(-1), ignore_index=-100)
```

对齐的细节：

- 主干的标签 targets[:, t] 是 y_{t+1}，所以 MTP 第 t 个预测的标签 y_{t+2} 就是 targets[:, t+1]；
- 在 VLM 里，图像位置的"输入嵌入"已经是视觉 token，所以 MTP 头用的是整条输入嵌入 emb，而不是 lm.tok(ids)。否则 `<img>` 占位符的嵌入会混进来；
- SFT 时答案以外的位置标签是 −100，MTP 的标签跟着移一位，自动只在答案上计算。

测试检查了因果性：改动第 5 个及以后的输入，MTP 的前 4 个输出不变。

## 34.6 阶段三：Mix-RL

### 目标函数

```
J(θ) = E[ (1 / Σ_i |o_i|) · Σ_i Σ_t min( r_{i,t} Â_i , clip(r_{i,t}, 1 − ε_low, 1 + ε_high) Â_i ) ]      （式 14）
```

和第 31 章的 DAPO 一致：

- **token 级汇总**：除以所有回答的 token 总数；
- **clip-higher**：ε_high > ε_low；
- **动态采样**：去掉组内奖励方差为 0 的组；
- **不加 KL 项**。

ε_low、ε_high、组大小 G、采样温度、学习率报告都只给了符号或没有提。

### 按任务路由的奖励

| 任务 | 奖励 |
|---|---|
| 区块解析 | 文字：编辑相似度（1 − NED）；表格：TEDS；公式：CDM |
| 整页解析 | MGAM 先把预测的元素和真值元素配对，再按类型算相似度，按真值里各模态的字符覆盖率加权（式 15） |
| KIE | 先检查 JSON 合法，再按实体和字段匹配；奖励是字段值的归一化编辑相似度，缺字段得 0 |
| OCR 问答 | ANLS |
| 所有任务 | 解析不了、格式不对、超长的输出得 0 |

式 15：R_doc = w_text · s_text + w_table · s_table + w_formula · s_formula，权重是各类型在真值里的字符占比。第 33 章的 `page_score` 是它的简化版：MGAM 允许一对多的拆分与合并，我们只做一对一的贪心配对。

### 练习 34.7：KIE 奖励

```python
def kie_reward(pred, ref):
    s = pred.strip()
    if s.startswith("```"):
        s = s.split("\n", 1)[1] if "\n" in s else ""
        s = s.rsplit("```", 1)[0]
    try:
        p = json.loads(s)
    except (json.JSONDecodeError, ValueError):
        return 0.0
    if not isinstance(p, dict):
        return 0.0
    fp, fr = _flatten(p), _flatten(ref)
    if not fr:
        return float(not fp)
    return float(np.mean([max(0.0, 1 - ned(str(fp[k]), str(v))) if k in fp else 0.0 for k, v in fr.items()]))
```

嵌套的字段（比如证件的 date.issue、date.expire）展平成"a.b"形式的键，每个真值字段一个分，缺了就是 0。只按真值的字段打分，多写的字段不扣分。这是一个设计选择，自测题 7 讨论它的后果。

### 练习 34.8：`mix_reward`

```python
def mix_reward(task, pred, ref, max_chars=2000):
    if len(pred) > max_chars:
        return 0.0
    if task in ("text", "formula", "table"):
        from ..rl.rewards import doc_reward
        return float(doc_reward(task, pred, ref))
    if task == "page":
        from ..eval.page import page_score
        blocks = parse_page(pred)
        return 0.0 if blocks is None else float(page_score(blocks, ref)[0])
    if task == "kie":
        return kie_reward(pred, ref)
    if task == "vqa":
        return float(anls([pred], [ref]))
    raise ValueError(task)
```

第 5 部分的例子：

```
text     0.923   'Total: $12.50'（真值 $12.60）
formula  1.000   '\frac{a}{b}+x^{2}'（真值 x^2：渲染一样）
formula  0.833   '\frac{a}{b}+x_{2}'（上标写成下标）
table    0.571   少了一行
page     1.000   两个区块都对
page     0.692   多写了一个区块（多写的字数算进分母）
page     0.000   没有按 "[类型] 内容" 的格式写
kie      0.667   三个字段对了两个，缺 date.expire
kie      0.000   JSON 不完整
vqa      1.000 / 0.000
text     0.000   超长（3000 个字符）
```

### 格式闸门在多任务 RL 里为什么重要

六种任务的奖励都在 [0, 1] 之间，格式不对一律 0。这有三个作用：

1. **防止投机**（第 29 章）：整页任务如果不检查格式，模型可能学会把所有文字堆成一段，丢掉结构也能拿到一部分文字分；
2. **超长 = 0**：RL 中模型容易越写越长（第 31 章 DAPO 的超长惩罚），对 OCR 来说，越写越长通常意味着重复或幻觉；
3. **让各任务的奖励可比**：组内标准化只在同一道题的回答之间比较，但监控时，各任务"满分 = 1、格式错 = 0"的含义一致，方便发现哪个任务在退步。

### Mix-RL 的数据与 MOPD 对照

RL 的数据是多因素挖掘出来的难例，再经过更强的语言模型过滤和人工复核。报告还比较了另一种整合多种能力的方法，MOPD（多教师在线蒸馏，引用的是另一篇论文，本报告没有展开它的损失和教师设置）：

| | 解析（OmniDocBench 总分） | 理解（OCR-VQA 总分） |
|---|---|---|
| MOPD | 96.7417 | 82.7 |
| Mix-RL | 96.8277 | 83.2 |

报告说 MOPD 用更少的计算达到了有竞争力的解析成绩，它的训练在分数开始波动时停止。

### 消融一：解析与理解数据的配比（报告表 10）

在三个阶段（分别用了全部解析数据的约 9%、29%、50%），比较只有区块数据、加入整页数据、再加入 OCR 问答数据：

| 阶段 | 只有区块 | + 整页 | + OCR 问答 |
|---|---|---|---|
| 早（9%） | 93.594 | — | 93.264（−0.330） |
| 中（29%） | 94.730 | 94.941（+0.211） | 95.580（+0.639；表格 TEDS +1.024） |
| 晚（50%） | 95.8432 | 95.8924 | 95.9673 |

报告的解读是：早期加入理解数据会稍微损害解析，中期以后有帮助。按第 32 章的思路，这是一个合理的故事：

- 早期模型的解析能力还没建立，理解数据分走了容量和梯度；
- 之后理解数据提供的"读懂内容"的能力反过来帮助解析，比如表格。

但要按第 25 章的标准打折扣：

- 每个格子是**单次运行**；
- OmniDocBench 的评测样本是有限的（约一千页量级），总分是多个子指标的组合；
- 0.2–0.3 个点的差别在没有种子方差和置信区间的情况下，**不能排除是噪声**；
- 晚期 95.8432 → 95.9673 只差 0.12。

比较稳的结论是"加入理解数据没有明显损害后期的解析"，而"早期有害、中期有益"的模式需要多个种子才能确认。第 8 部分让你在我们的 VLM 上做一个同样设计的小实验，并且多跑几个种子。

### 消融二：锚定与 Mix-RL（报告表 11）

- Q-Mask：96.0241 → 96.3198（+0.2957，公式 CDM +0.4931）；
- Mix-RL：96.4739 → 96.8277（+0.3538，表格 TEDS +0.7114，TEDS-S +0.5094）。

### 消融三：容量（报告表 12）

| | 4B 教师 | 0.8B（Mix-RL 后） | 差距 |
|---|---|---|---|

## 34.8 报告没说的：复现时缺什么

| 缺失 | 影响 | 怎样补 |
|---|---|---|
| λ_txt、λ_seg（式 12） | 锚定的强弱 | 第 6 部分：扫 λ_seg，看主任务是否受损 |
| λ_MTP（式 13） | MTP 的权重 | 第 7 部分：扫 λ_MTP。可以参考的起点：DeepSeek-V3 的报告用 λ = 0.3 训练前 10T 个 token，之后降到 0.1；第 7 部分的 0、0.3、1 就是围绕 0.3 取的 |
| 各阶段的数据量、配比、学习率 | 几乎所有结果 | 小模型上做配比扫描（第 32 章、第 8 部分），再推到大模型 |
| ε_low、ε_high、G、温度、RL 学习率 | RL 的稳定性 | 从第 31 章用的 DAPO 设置（ε_low = 0.2、ε_high = 0.28）开始，按第 31 章的监控清单调 |
| ETC 各档的样本数、修正的成功率 | 数据引擎的效率 | 自己的数据上统计（第 1 部分、第 33 章） |
| 挖掘的 ρ、f_a、f_u、τ、τ_a、τ_u、K | 难例的组成 | 先用 f = τ = 1，看挖出来的样本是不是"标签可信、模型不会" |
| 掩码解码器的结构、接在哪里 | 锚定的实现 | 我们的简化版：查询 = 答案前最后一个位置的隐藏状态 |
| TextAnchor-26M 的内容 | 锚定数据 | 用有框的任务（定位、场景文字）构造 |
| MGAM 的配对算法 | 整页奖励 | 一对一贪心（第 33 章）；需要时换匈牙利算法 |

这张表也说明了为什么"按报告复现"通常做不到数字上的一致：可以复现的是**结构**（哪些阶段、哪些损失、哪些奖励）和**定性结论**（锚定帮助公式、RL 帮助表格和理解），而不是 96.83。

### 第 1 部分：三元组共识用在真实读法上（实测）

作者在本机 CPU 上让 GLM-OCR、TexTeller、Qwen3.5-0.8B 各读了 60 条真实公式（OleehyO/latex-formulas 第 5 个分片，许可 openrail）。读法和这 60 条标注随仓库放在 `labs/ch34/data/`，你不需要下载模型就能复现这一部分。第 1 部分把它们当作 3 个专家，用式 1–4 打标签。相似度取"归一化之后按字符的 1 − NED"：报告对公式用 CDM，但我们的 CDM 只认第 3 章的小语法。归一化 `norm_formula` 剥掉外层的 `$$`、`\[ \]`，去掉 `\left`、`\right` 和间距命令，给单字符的上下标补花括号。

怎么读：

- **C_i 能分辨专家的好坏**。TexTeller 的平均一致度最低，和单独评测时它的准确率最低一致（作者在第 33 章的数据上实测，日志 `outputs/ch33/part3_8.log`：按记号归一化之后与标注完全相同的比例，GLM-OCR 41.7%、Qwen3.5 35.0%、TexTeller 33.3%）。中心点 60 条里有 47 条来自 GLM-OCR，因为它和另外两个都比较接近；

  - 一部分是写法差别，比如 `{\cal D}` 和 `\mathcal{D}`、`{1\over 2}` 和 `\frac{1}{2}`，渲染一样，字符串不同。所以报告对公式用 CDM，而不是字符串比较；

- **低档只有 2 条**，它们碰巧都对，这个 100% 没有统计意义；

## 34.11 常见错误

| 错误 | 症状 | 原因与修正 |
|---|---|---|
| 把报告的单次消融当作定论 | "Q-Mask 提升了 0.3 分"被当成可靠的结论 | 单次运行没有置信区间；复现时多个种子，或者只引用定性结论 |
| 掩码头的查询取错位置 | dice 不下降 | 查询应在答案开始前的最后一个位置（它看过图和问题）；取图像位置的隐藏状态就和查询无关了 |
| 视觉 token 的顺序和掩码的顺序不一致 | dice 下降很慢，可视化的掩码是"转置"的 | 两者都按行排列（第 22 章的 patchify 和 box_to_grid_mask） |
| 只用 CE 监督很小的掩码 | 掩码头全预测背景，CE 却很低 | 加上 Dice（第 3 部分：CE 0.241 vs Dice 0.765） |
| MTP 用 lm.tok(ids) 做下一个 token 的嵌入 | 图像位置混进了 `<img>` 占位符的嵌入 | 用整条输入嵌入 emb（图像位置已经是视觉 token） |
| MTP 的标签没有再移一位 | MTP 损失和 NTP 一样低 | MTP 第 t 个预测对应 targets[:, t+1] |
| 多任务奖励的尺度不一致 | 某个任务主导了训练 | 所有奖励放在 [0, 1]，格式错 = 0（34.6 节） |
| 共识标签直接来自修正模型 | 修正模型自己的偏差变成了标签 | 修正后的读法要加回专家池重新共识（34.3 节） |
| 合成的种子来自验证集 | 验证集的成绩虚高 | 按来源文档划分，验证集的组不进入任何合成的输入 |

## 34.13 本章小结

1. Xiaomi-OCR-0 = 数据引擎 + 三个训练阶段（Q-Mask 锚定 → NTP + MTP 持续预训练 → Mix-RL）+ 两阶段推理；
2. 数据引擎的核心是三元组共识：8 个专家里选最一致的 3 个，取中心点，按一致度分档。中低档交给"渲染 → 核对 → 修正"，修正的结果必须重新共识才算数；
3. 多因素挖掘按"标签可信 × 模型不会"给样本加权，按簇分配名额；
4. 锚定是一个训练后扔掉的辅助任务：Dice + CE 监督"答案在图里的位置"，Dice 对很小的前景敏感；
5. MTP 头从 h_t 和真实的 y_{t+1} 预测 y_{t+2}，提供更密的监督，也可以做投机解码；
6. Mix-RL 就是第 31 章的 DAPO 加上按任务路由的奖励，格式错、超长都是 0；
7. 读消融时要看是否单次运行、差距多大、有没有置信区间。容量消融说明解析靠数据、理解靠容量，RL 主要补理解；
8. 报告缺失大量超参数。可复现的是结构和定性结论，数字要靠自己的实验。

## 参考答案

1. Qwen3.5-0.8B → 文字锚定（L_SSA = λ_txt·L_NTP + λ_seg·(L_Dice + L_CE)，式 12；之后去掉掩码解码器）→ OCR 持续预训练（L_NTP + λ_MTP·L_MTP，式 13）→ Mix-RL（DAPO 式的裁剪目标、token 级汇总、无 KL，式 14；奖励按任务路由，式 15 等）→ Xiaomi-OCR-0。推理时，整页先由 PP-DocLayoutV3 做版面检测，再逐块识别、拼成整页。
2. 长文本几乎不会有两个模型读得一字不差，多数投票会丢掉大部分样本。三元组用连续的相似度，只要求 3 个专家读得很像，离群的专家被自动排除。会选错的情况：多个专家犯同样的错（比如都把某种特殊字体读成同一个错字，或者都用同一个模型蒸馏而来，错误相关），这时它们高度一致，却一致地错。
3. 修正模型也会犯错，而且它的错误和专家们的错误不一定相关。加回专家池重新共识，要求它的读法得到其他专家的支持，相当于再做一次独立核对。直接当标签会把修正模型自己的偏差引入数据。
4. 乘积要求两个条件同时满足：标签可信（a 高）且模型不会（u 低）。加权和会让"模型很不会但标签不可信"的样本也得到较高的权重，而这类样本训练的可能是错误标签。a = 0.4、u = 0.2 的样本：模型不会，但标签可信度低，应该少抽；在第 2 部分的例子里它的权重是 0.172，低于 a = 0.92、u = 0.30 的样本（0.346）。
5. 锚定训练改变了主干（视觉编码器、连接器、语言模型）的参数，使得它们的表示里"文字内容"和"空间位置"对齐。掩码解码器只是读出这种对齐的工具，去掉它不影响主干已经学到的表示。
6. 训练时用真实的 y_{t+1}（教师强制）让 MTP 头学"已知下一个 token 时，再下一个是什么"，和主干的训练方式一致，也避免主干的错误传给 MTP。投机解码时没有真实的 y_{t+1}，用主干刚预测的 token 代替；MTP 头的猜测要在下一步由主干验证，猜错就丢掉。
7. 模型可以输出一个包含大量字段、每个字段写各种可能值的 JSON，不会因为多写而扣分。如果某个字段名有多种写法，模型也可以每种都写一遍。修改：对多写的字段扣分（比如按字段算 F1：精确率 = 预测的字段里对的比例，召回率 = 真值字段里被找到的比例），或者限制输出长度（超长 = 0）。
8. 解析上 0.8B 和 4B 只差约 0.15，理解上差约 4.9：解析几乎不受容量限制，理解受容量限制。另外 RL 让理解从 78.1 升到 83.2，解析几乎不变。只有 0.8B 的预算时，解析主要靠数据质量和数量（数据引擎），理解的上限有限，可以用 RL 补一部分，但不要指望达到大模型的水平。
9. 三人组的一致度：{1,2,3}：(0.9 + 0.8 + 0.95) / 3 = 0.883；{1,2,5}：(0.9 + 0.85 + 0.88) / 3 = 0.877；{1,3,5}：(0.8 + 0.85 + 0.92) / 3 = 0.857；{2,3,5}：(0.95 + 0.88 + 0.92) / 3 = 0.917；含 4 的组都很低。T* = {2,3,5}，a = 0.917，高档。组内一致度之和：y2：0.95 + 0.88 = 1.83，y3：0.95 + 0.92 = 1.87，y5：0.88 + 0.92 = 1.80，中心点是 y3。
10. Σp·t = 4 × 0.5 = 2，Σp = 2 + 60 × 0.1 = 8，Σt = 4。dice = (2 × 2 + 1) / (8 + 4 + 1) = 5/13 = 0.385，损失 0.615。CE：前景每个 −ln 0.5 = 0.693，背景每个 −ln 0.9 = 0.105，平均 (4 × 0.693 + 60 × 0.105) / 64 = (2.773 + 6.322) / 64 = 0.142。CE 已经很低，Dice 仍然很高：背景上的 0.1 加起来让预测的总量是真值的两倍。
