# 第 33 章　文档解析系统与数据工程

## 本章在全景图中的位置

到第 32 章为止，我们的数据都是自己生成的：ShapesWorld 的场景、MiniDoc 的文字行、公式和页面。生成的数据有一个巨大的好处：**真值是精确的**，渲染器画了什么，标签就是什么。真实世界没有这种好事。一个要读懂论文、表格、票据的 OCR 模型，需要上亿条真实图像的标注，而人工标注一页文档要几分钟到几十分钟。Xiaomi-OCR-0 的报告里，训练语料约 1.7 亿条（第 34 章），这样的规模不可能靠人工完成。

所以真实的 OCR 项目里，**数据工程**往往比模型结构花的力气更多：

- 标签从哪里来？现成的开源数据集（要核对许可证），以及用现有的模型"预标注"（伪标签）；
- 伪标签不可信，怎样挑出可信的？多个模型互相印证（**共识**），把答案重新画出来和原图比（**渲染校验**）；
- 数据太多，怎样挑出值得训练的？模型自己没把握、而标签又可信的（**难例挖掘**），并且照顾到各种类型（**按簇配额**）；
- 进训练之前：**去重**（完全相同的、几乎相同的），**按组划分**（同一篇论文的公式不能一半在训练集、一半在验证集）。

本章先讲文档解析系统的两种结构（两阶段和端到端）和整页的评测方法，然后把上面这条"数据流水线"的每一步都实现一遍：在模拟的专家上测共识，在 MiniDoc 的公式上测渲染校验，在一个真实的开源公式数据集（本机缓存的 OleehyO/latex-formulas）上测清洗、去重和泄漏。第 34 章读 Xiaomi-OCR-0 的报告时，你会看到这些零件在真实系统里是怎样组合的。

本章第 1–5 部分不训练，数字都是实际跑出来的（日志在 `outputs/ch33/`）；第 6 部分（用不同来源的标签训练第 13 章的 CRNN）由你自己跑。

## 学习目标

学完本章，你应该能够：

1. 说出两阶段（版面检测 + 区块识别）和端到端（整页直接输出）两种文档解析结构各自的优缺点，算出它们在视觉 token 上的开销；
2. 实现整页解析的打分：区块配对、按模态打分、按字数加权；说出"多写的内容"为什么要扣分；
3. 实现多模型共识（两两一致度、三元组、中心点、分档），解释为什么**相关的错误**是共识最大的敌人；
4. 实现公式的渲染校验，说出它能发现和不能发现的错误；说出为什么一致度的度量必须对等价写法不敏感；
5. 实现自洽度、按簇配额抽样、MinHash 与 LSH 近似去重、按组划分；在真实数据上测出重复率和划分泄漏。

## 33.1 文档解析系统的两种结构

### 两阶段：先找区块，再逐个识别

第 21 章的流水线 OCR 就是两阶段的：

```
整页图 → 版面检测（找出标题、段落、公式、表格的框） → 排阅读顺序 → 每个框裁出来 → 识别 → 按顺序拼起来
```

今天的两阶段系统把第二步换成了一个 VLM：PaddleOCR-VL、MinerU 先用一个专门的版面检测模型找区块，再把每个区块交给 VLM，并用不同的提示词告诉它"这是表格，输出 HTML"或"这是公式，输出 LaTeX"。Xiaomi-OCR-0 也是这样：版面检测用外部的 PP-DocLayoutV3，报告里说的 0.8B 参数**不包括**这个检测器（第 34 章）。

### 端到端：整页直接输出

另一条路是把整页图直接交给 VLM，让它一次写出全部内容（按阅读顺序、带格式）：dots.ocr 等模型走的是这条路。版面分析和阅读顺序都在模型内部"隐式"地完成。

### 两种结构的对比

| | 两阶段 | 端到端 |
|---|---|---|
| 阅读顺序 | 规则或单独的模型（第 21 章） | 模型自己学，依赖训练数据里的顺序 |
| 每次输入 | 一个区块：图小、视觉 token 少 | 整页：图大、视觉 token 多 |
| 输出长度 | 短（一个区块的内容） | 长（整页几千个 token），生成是串行的 |
| 错误的来源 | 检测漏框、切错框，识别器看不到上下文 | 漏段、重复、阅读顺序乱、长输出的幻觉 |
| 并行 | 各区块可以并行识别 | 一页只能一个 token 一个 token 写 |
| 能用跨区块的上下文吗 | 不能（每个区块单独看） | 能 |
| 训练数据 | 区块级的标注就够 | 需要整页级的标注 |

很多端到端的系统**也**保留了"先版面、后识别"的思路，只是两件事都由同一个 VLM 完成（第 21 章 21.11 节）。两者之间没有绝对的优劣，目前的榜单上两种结构都有很强的模型。

### 第 1 部分：同一页，视觉 token 各要多少

用第 24 章的 `n_qwen_tokens`（Qwen3.5 的缩放规则：每 32 × 32 像素合成 1 个视觉 token），算一张 A4 纸在不同分辨率下的开销：

```
整页  72 dpi（ 595 ×  842 像素）     494 个视觉 token
整页 100 dpi（ 827 × 1169 像素）     962 个视觉 token
整页 150 dpi（1240 × 1754 像素）   2,145 个视觉 token
整页 200 dpi（1654 × 2339 像素）   3,796 个视觉 token
```

手算 150 dpi 这一行：`smart_resize` 把高 1754 取整到 32 的倍数 → 1760（55 × 32），宽 1240 → 1248（39 × 32）；55 × 39 = 2,145。

两阶段时，每个区块单独送进去（150 dpi 下的典型大小）：

```
一段正文（宽 16 厘米、8 行）  960 × 260    240 个视觉 token
一行公式                     700 ×  90     66 个视觉 token
一张 6 行的表格              960 × 330    300 个视觉 token
一个标题                     700 ×  60     84 个视觉 token
上面 4 个区块合计                         690（整页 150 dpi 是 2,145）
```

区块之间的空白、页边距不用编码，所以两阶段的视觉 token 总数通常比整页少。但要注意两点：

- **小区块会被放大**。标题 700 × 60 = 42,000 像素，小于默认的 `min_pixels` = 256 × 256 = 65,536，所以被放大到约 65,536 像素，得到 84 个 token，比按原大小算的（2 × 22 = 44 个）多。第 1 部分最后两行：一个 40 × 40 的单字在默认设置下也要 64 个 token，把 `min_pixels` 调到 32 × 32 才是 1 个。第 24 章讲过，Qwen 的模型卡建议按任务调整这两个参数；
- **视觉 token 少不等于快**。两阶段要多跑一个检测器，每个区块都要单独做一次预填充；端到端一次预填充，但输出要一口气写几千个 token。哪个快取决于页面的内容和部署方式。

### 另一条路：光学压缩

上面的数字都是 Qwen 的规则（32 × 32 像素一个 token）。还有一类模型把"每页要多少视觉 token"当作要优化的对象。DeepSeek-OCR（2025）用一个专门的编码器（先用局部窗口注意力处理高分辨率的图，再用卷积把 token 数压缩 16 倍，最后接全局注意力），把一整页压到几十到几百个视觉 token。它的报告把"文字 token 数 ÷ 视觉 token 数"叫作压缩比：报告称压缩比在 10 倍以内时，解码出的文字约 97% 正确；压缩到 20 倍时降到约 60%。

这和第 24 章的估算一致：在"刚好看得清"的分辨率下，一个视觉 token 大约携带一个文字 token 的信息；要压缩到 10 倍，编码器就必须学会比"把像素切块"更紧凑的表示。对数据工程来说，这件事的意义是：**视觉 token 的预算决定了你能用多高的分辨率、能塞多长的页面**，也就决定了训练数据要不要按页切块、切多大。

### 作者的一次实测：两阶段 vs 端到端

写作本章时，作者在 CPU 上用一个真实的文档 OCR 模型 GLM-OCR 读了 4 页 MiniDoc 页面（放大 2 倍），比较整页直接读（端到端）和按真值的版面框逐块读（两阶段）。这次测量的脚本没有收进仓库，日志在 `outputs/ch33/part3_8.log`：

```
页   栏  区块  真值词数 | 端到端：词级 NED  视觉 token  秒 | 两阶段（真值版面框）：词级 NED  视觉 token  秒
 1   2     5       68  |      0.706        1107     27 |            0.509               736     27
 2   1     4       29  |      0.422        1107     24 |            0.350               316     13
 3   2     7       55  |      0.965        1107     97 |            0.372               660     19
 4   1     3       33  |      0.415        1107     25 |            0.256               379     13
平均词级 NED：端到端 0.627，两阶段 0.372
```

只有 4 页、一个模型，不能当作两种结构优劣的结论，但两类错误都清楚地出现了：

- **端到端在双栏页上把两栏交错着读**：第 1 页的输出是"左栏第 1 行、右栏第 1 行、左栏第 2 行……"，第 3 页（双栏、7 个区块）的词级 NED 高达 0.965。阅读顺序是端到端模型要自己学的东西，GLM-OCR 显然没有在我们这种版式上学好；
- **两阶段的区块里出现了重复的行**：逐块读时，有的区块的输出把同一行写了两遍（`8253 25% many while ease 0` 出现两次）——小图被放大后，模型的生成陷入了重复（第 17 章的重复问题）；
- 两阶段用的是**真值**的版面框：真实系统里框来自检测器，会有漏框和切错，两阶段的成绩会比这里差。


## 33.2 整页的评测

### 为什么不能直接比字符串

整页解析的输出是一串区块（类型 + 内容）。把整页的输出拼成一个字符串、和真值算编辑距离，有两个问题：

1. **阅读顺序的小差别被放大**：两栏的页面，模型先写右栏再写左栏，每个字都对，但编辑距离几乎是 100%；
2. **不同的内容用不同的指标**：文字用 NED，公式用 CDM（写法不同、画出来一样的不扣分），表格用 TEDS（第 25 章）。

所以 OmniDocBench 等评测的做法是：先把预测的区块和真值的区块**配对**，再对每一对按类型打分，最后加权。

### 练习 33.8：`match_elements`

```python
def match_elements(pred, ref, sim=block_sim):
    cand = [(sim(pk, pc, rc), i, j) for i, (pk, pc) in enumerate(pred) for j, (rk, rc) in enumerate(ref) if pk == rk]
    cand.sort(key=lambda t: (-t[0], t[1], t[2]))
    used_p, used_r, out = set(), set(), []
    for s, i, j in cand:
        if s > 0 and i not in used_p and j not in used_r:
            used_p.add(i)
            used_r.add(j)
            out.append((i, j, s))
    return out
```

这是**贪心**配对：相似度最高的一对先配。它不保证总相似度最大（那需要匈牙利算法），但简单、可预测。真实的实现更复杂：一个预测区块可能对应真值里的两个区块（模型把两段合成了一段），Xiaomi-OCR-0 用的 MGAM 允许这种拆分与合并（第 34 章）。

`page_score` 在配对之后：

```
这一类的分数 = Σ_配上的对 相似度 × 真值的字数 / (这一类真值的总字数 + 这一类没配上的预测的字数)
总分 = Σ_类型 这一类的分数 × (这一类真值的字数 / 真值的总字数)
```

按字数加权，是 Xiaomi-OCR-0 整页奖励的做法（各模态按真值里的字符覆盖率加权）。分母里加上"没配上的预测的字数"，是为了让**多写**也扣分：否则模型可以多写一些区块"碰运气"而不受惩罚。

### 手算一页

真值有三个区块：`text "hello world"`（11 个字）、`formula "x^{2}"`（5 个字）、`text "abc"`（3 个字），共 19 个字。预测有三个文字区块：`"abc"`、`"hello world"`、`"extra"`。

1. 配对：类型相同的才比。预测 0（abc）和真值 2（abc）相似度 1；预测 1（hello world）和真值 0 相似度 1。这两对先配。预测 2（extra）想配的真值都被用掉了，没配上。公式没有预测，也没配上；
2. 文字：分子 = 1 × 11 + 1 × 3 = 14；分母 = 真值的文字 14 + 没配上的预测 "extra" 5 = 19；分数 14 / 19 = 0.737；
3. 公式：0；
4. 总分 = 0.737 × 14 / 19 + 0 × 5 / 19 = 0.543。

漏掉公式扣了 5 / 19 的分，多写的 "extra" 又让文字的分数从 1 降到 0.737。这个例子就是 `test_page_score`。

## 33.3 数据从哪里来

| 来源 | 例子 | 优点 | 问题 |
|---|---|---|---|
| 开源数据集 | 公式：UniMER-1M、im2latex-100K、OleehyO/latex-formulas；文档：OmniDocBench（只用于评测）、DocLayNet；场景文字：TextOCR | 有人工或半人工的标注 | 许可证各不相同；分布和你的任务不同；有错误和重复 |
| 从源文件反推 | arXiv 论文的 LaTeX 源码 → 渲染 → 图像与标签成对 | 标签精确、数量大 | 只有"渲染出来"的干净样式，没有扫描、拍照的退化 |
| 合成 | 本书的 MiniDoc；模板化的表格、票据；字体与退化的模拟 | 真值精确、可控 | 和真实图像有差距（"合成到真实的鸿沟"） |
| 伪标签 | 用现有的 OCR 模型（"专家"）给无标注的图像写答案 | 可以覆盖任意真实图像 | 标签有错；错误还和专家的毛病相关 |
| 蒸馏 | 大模型（教师）的输出当作小模型（学生）的标签 | 学生能学到教师的能力 | 学生的上限受教师限制；也会继承教师的错误 |

真实的大规模语料几乎都是这几种的混合。Xiaomi-OCR-0 的数据引擎把伪标签做到了极致：8 个现有的文档 OCR 模型当"专家"，用共识挑出可信的标签，用渲染校验修补不可信的，再针对模型的失败点定向合成（第 34 章）。

### 许可证

下载任何数据集之前，先看它的许可证，并且记录下来：

- 本章用的 OleehyO/latex-formulas 是 **openrail**，README 说它来自 arXiv 爬取的公式加上 im2latex-100K。openrail 类的许可证对用途有限制条款，用在商业产品里之前要读原文；
- arXiv 论文本身的许可证各不相同，"来自 arXiv"不等于"可以随意使用"；
- 用别人的模型生成伪标签，还要看那个模型的许可证是否允许"用它的输出训练其他模型"；
- 评测集（OmniDocBench、UniMER-Test）**只用于评测**，不能混进训练数据，否则分数就失去了意义（第 25 章）。

一个最低限度的做法：每个数据源一行，记下名称、版本（或下载日期）、许可证、用途（训练 / 评测）、条数、做过哪些过滤。这张表应该和训练配置放在一起。

## 33.4 多模型共识

### 思路

同一张图交给 n 个专家（不同的 OCR 模型），各写一个答案。如果其中几个专家的答案几乎一样，这个答案很可能是对的：不同的模型独立地犯同一个错误，概率很小。这就是**共识**（consensus）。

### 练习 33.1：`pairwise_agreement`

```python
def pairwise_agreement(preds, sim=text_sim):
    n = len(preds)
    A = np.eye(n)
    for i in range(n):
        for j in range(i + 1, n):
            A[i, j] = A[j, i] = sim(preds[i], preds[j])
    return A
```

相似度函数按内容的类型选：文字用 1 − NED，公式用 CDM，表格用 TEDS——和评测用的指标一致（Xiaomi-OCR-0 的做法）。

### 练习 33.2：`triplet_consensus`

```python
def triplet_consensus(preds, sim=text_sim, k=3):
    A = pairwise_agreement(preds, sim)
    n = len(preds)
    k = min(k, n)
    best, best_score = tuple(range(k)), -1.0
    for group in combinations(range(n), k):
        pairs = list(combinations(group, 2))
        score = float(np.mean([A[i, j] for i, j in pairs])) if pairs else 1.0
        if score > best_score + 1e-12:
            best, best_score = group, score
    medoid = max(best, key=lambda i: (sum(A[i, j] for j in best if j != i), -i))
    return medoid, best_score, best
```

两步：

1. **选三元组**：在所有三个专家的组合里（8 个专家有 C(8, 3) = 56 种），选组内两两一致度平均值最高的一组；
2. **取中心点**（medoid）：组内和另外两个最一致的那个答案，当作伪标签。

为什么取中心点而不是"平均"？答案是字符串，没法平均；中心点是"最不极端"的那个成员，它总是某个专家真实写出的答案，格式一定合法。

报告里的具体做法可能和这里不完全一样（比如怎样定义"一致度最高的三个专家"），这里实现的是最直接的一种理解。

### 手算一次

四个专家：`hello`、`hello`、`hallo`、`xyz`。

- 两两一致度：hello 和 hello 是 1；hello 和 hallo 编辑距离 1、长度 5，是 0.8；任何一个和 xyz 都是 0（编辑距离 5，长度 5）；
- 三元组：(0, 1, 2) 的平均是 (1 + 0.8 + 0.8) / 3 = 0.867；包含 3 号的组合最多是 (1 + 0 + 0) / 3 = 0.333。选 (0, 1, 2)；
- 中心点：0 号和另外两个的一致度之和 1 + 0.8 = 1.8，1 号也是 1.8，2 号是 1.6。0 和 1 平局，取下标小的 0。伪标签是 `hello`；
- 分档：0.867 在 0.6 到 0.9 之间，是**中档**。

### 分档

Xiaomi-OCR-0 按三元组的一致度分三档：≥ 0.9 是高档，直接收下；0.6–0.9 是中档，送去渲染校验（33.5 节）；< 0.6 是低档。只有高档直接进训练数据。

### 第 2 部分：8 个模拟的专家

我们没有 8 个真的 OCR 模型，所以**模拟**它们：每个专家在真值上按自己的方式犯错。8 个专家的设定：

| 专家 | 毛病 |
|---|---|
| A 很准 | 每个字 0.5% 的概率出错（替换、删除、插入各占三分之一） |
| B 准 | 1% |
| C 一般 | 2% |

另外，25% 的行是"难图"：在难图上所有专家的随机错误率乘以 6。这模拟了一个真实的现象：**难图对所有模型都难**，而 D 和 E 的错误还彼此相关（就像两个用相似数据训练出来的模型，在同样的图上犯同样的错）。

### 分档的效果

```

medium     77 行（ 3.9%）   伪标签整行全对  35.1%
low         0 行

难图   492 行：高档占  84.3%，高档里伪标签整行全对  87.5%
```

分档确实把可信的和不可信的分开了：高档 97.3% 是对的，中档只有 35.1%。中档的样本正是需要渲染校验或人工复查的那些。

但请仔细看最后两行：**高档里的错误全部来自难图**。易图上的高档 100% 正确；难图上的高档只有 87.5%。也就是说，"高一致度"在最需要它的地方（难图）最不可靠。原因有两个：

1. **1 − NED ≥ 0.9 对短行太宽松**。一行 16 个字，错 1 个字的一致度是 1 − 1/16 = 0.94，仍然是高档。三个专家各错不同的一个字，三元组的一致度约 0.88–0.94；中心点仍然带着一个错字。日志里的例子：真值 `own Rule door direct old`，伪标签 `own Ruls door direct old`，三元组是 A、B、F；
2. **相关的错误**。高档里错误的 52 个伪标签中，24 个的三元组里**同时有 D 和 E**。D 和 E 在难图上写出完全相同的错误答案，彼此一致度是 1，只要第三个专家和它们差不多，这个三元组的平均一致度就很高，中心点就是那个错误的答案。

把 E 去掉（只留一个有这种毛病的专家），高档的正确率从 97.3% 升到 98.0%，高档的比例从 96.2% 降到 95.7%：**少了一个专家，结果反而更好**。共识的前提是专家的错误彼此独立；两个"同门"的专家相当于一个专家投了两票。真实系统里选专家时，模型结构、训练数据的来源越不同越好。

### 真实的专家：作者的一次实测

模拟的专家能把机制讲清楚，但真实模型的错误是什么样的？写作本章时，作者在 CPU 上用三个真实的公式识别模型（GLM-OCR、TexTeller、Qwen3.5-0.8B）各读了 60 条真实公式（latex-formulas 的第 5 个分片）和 60 条 MiniDoc 公式。这次测量的脚本没有收进仓库，日志在 `outputs/ch33/part3_8.log`，三个模型在真实公式上的读法和标签在 `labs/ch34/data/`（第 34 章还会用到）：

```

  TexTeller                      33.3%          2.5 秒
  Qwen3.5                        35.0%          6.4 秒
```

几点观察：

- **写法差别先于识别差别**。三个模型的原始输出各有各的写法：GLM-OCR 写 `$$\n\sqrt {6 b} = b _ {1}\n$$`（带 `$$` 外壳、记号之间加空格），TexTeller 写 `\[\sqrt{6b}=b_{1}\]`，Qwen3.5 写 `$$\sqrt { 6 b } = b _ { 1 }$$`。不做归一化，没有一个读法能和标签"完全一致"。这也是 33.7 节的 `latex_key` 要去掉 `$$…$$`、`\[…\]` 外壳的原因；
- **真实公式上，"两个模型一致"远不如在 MiniDoc 上可靠**：收下的标签只有 52.3% 和数据集的标签完全一致。一部分是真的读错，一部分是数据集的标签本身和图不完全对应，还有一部分是归一化没能消除的等价写法（`\over` 和 `\frac`、`9^{x}_{2}` 和 `9_{2}^{x}`）。在真实数据上，"完全一致"这个标准太严，一致度需要像 CDM 那样对写法不敏感的度量；
- **渲染校验也有同样的盲点**：MiniDoc 上，有的读法渲染出来和原图的分数是 1.000，却是错的——把 `z^{z}` 读成了 `z^{2}`。在这个字体、这个字号下，上标位置的小号 z 和 2 几乎画得一样。这和第 3 部分"换一个符号是盲点"是同一个现象。

## 33.5 渲染校验

### 思路

对公式、表格这类有"渲染器"的内容，可以把候选答案**重新画出来**，和原图比较。画出来和原图一样，答案（在显示上）就是对的。它和共识互补：共识看"专家之间是否一致"，渲染校验看"答案和图像是否一致"，而且**不需要真值**。

Xiaomi-OCR-0 的做法更进一步：对中档的样本，用一个专家池之外的大模型（Qwen3.5-122B-A10B）做"修改 → 渲染 → 对照原图检查"，最多三轮；还不收敛的，再做一轮带历史的"批评 → 修改 → 检查"；仍然不收敛的放弃或送人工（第 34 章）。我们只实现最核心的一步：给一个候选答案打一个渲染一致度的分数。

### 练习 33.3：`render_score`

```python
def render_score(latex, img, size=16, thresh=128, shift=2):
    try:
        tree = parse(latex)
        H, W = img.shape
        pred, _ = render_formula(tree, np.random.default_rng(0), H=3 * H, W=3 * W, size=size)
    except (LatexError, ValueError):
        return 0.0
    a, b = ink_crop(pred, thresh), ink_crop(img, thresh)
    if a is None or b is None:
        return 0.0
    h, w = b.shape
    if abs(a.shape[0] - h) > 0.25 * h or abs(a.shape[1] - w) > 0.25 * w:
        return 0.0
    if abs(a.shape[0] - h) > shift or abs(a.shape[1] - w) > shift:
        a = resize_nearest(a, h, w)
    ap = np.pad(a, shift, constant_values=255).astype(float)
    B = _blur(255.0 - b)
    best = -1.0
    for dy in range(ap.shape[0] - h + 1):
        for dx in range(ap.shape[1] - w + 1):
            best = max(best, _ncc(_blur(255.0 - ap[dy:dy + h, dx:dx + w]), B))
    return best
```

逐步解释：

1. **渲染**：解析失败（格式不对）直接 0 分，和第 31 章的格式闸门一样。渲染在一张 3 倍大的白底上，保证放得下；
2. **裁到墨迹**：原图里公式的位置是随机的，渲染图里也是，所以先各自裁到墨迹的外接框，去掉位置的差别；
3. **大小检查**：外接框的高或宽相差超过 25%，说明结构明显不同（多了一项、少了一个分式），直接 0 分；
4. **平移搜索**：在 ±2 个像素的平移里找最好的对齐；
5. **比较**：墨迹强度（255 − 像素值）先做 3 × 3 的均值模糊，再算**归一化互相关**（NCC：两张图各自减去均值之后的余弦相似度）。模糊让比较对噪声和抗锯齿不那么敏感。

### 为什么要平移搜索：一个真实的调试过程

最初的版本没有第 4 步，直接比较两个裁好的外接框。规范写法（和原图完全相同的公式）本该得满分，结果有一部分得分明显偏低。原因是：原图加了噪声（每个像素加上标准差 0.05 × 255 ≈ 13 的高斯噪声），字形边缘有一些抗锯齿的灰色像素，亮度在阈值 128 附近。噪声让其中一个像素越过阈值，外接框就多出（或少了）一行或一列，两张图错开一个像素。对 1 像素宽的分数线和细笔画来说，错开一个像素就是"完全不重合"。

第 3 部分把这个对比也打印了出来（`shift=0` 就是不做平移搜索）：

```
候选                        个数   ≥ 0.99 的比例   中位数    最低
规范写法                     300        100.0%     0.998    0.995
规范写法（不做平移搜索）     300         97.3%     0.998    0.914
```

不做平移搜索时，2.7% 的正确答案会被当作"不一致"拒掉；做了之后，300 个正确答案的最低分是 0.995。这类"对齐偏一个像素"的问题在所有基于图像比较的方法里都会出现，值得记住。

### 第 3 部分：渲染校验能发现什么

300 个 MiniDoc 公式（第 3 章的生成器，level 3，噪声 0.05）。每个公式准备五种候选：规范写法、随机选的一种等价写法（`to_latex(tree, rng)`：省略花括号、交换上下标的顺序、`\over` 代替 `\frac`……），以及在语法树上制造的三种错误：

```
候选                 个数   ≥ 0.99 的比例   中位数    最低
规范写法              300        100.0%     0.998    0.995
等价的另一种写法      300        100.0%     0.998    0.995
换了一个符号          300          4.0%     0.941    0.622
上下标互换            240          0.8%     0.887    0.493
删掉一个元素          285          0.0%     0.524    0.000
等价写法和规范写法的 1 − NED：平均 0.811，76% 的不是 1
```

（"上下标互换""删掉一个元素"少于 300 个，是因为有的公式没有上下标，或者删不了。）

读这张表：

- **等价写法全部通过**。它们和规范写法的 1 − NED 平均只有 0.811：用文本指标衡量，这些正确的答案会被扣将近 20% 的分。渲染校验对写法不敏感，这正是 CDM 的思想（第 25 章）；
- **结构性的错误几乎都能发现**：删掉一个元素 0% 通过，上下标互换 0.8%；
- **换一个符号是盲点**：4.0% 通过。两个形状相近的符号（比如某些字体里的 1 和 7、b 和 6），渲染出来的差别小于噪声。真实系统里也一样：渲染校验能确认"结构对了"，确认不了"每个符号都对"，所以它和共识一起用，而不是替代共识。

用 0.99 作为阈值，在这 300 个公式上，不会误拒正确的答案，同时拒掉了 98.3% 的错误答案（825 个错误候选里通过了 12 + 2 + 0 = 14 个）。阈值是在这批数据上看出来的，换一种字体、换一种噪声都要重新校准。

### 第 3b 部分：一致度的度量要对等价写法不敏感

回到共识。公式的专家常常用不同的写法写同一个公式。如果一致度用原始 LaTeX 的 1 − NED，等价的写法会被当作"不一致"。第 3b 部分模拟了 5 个公式专家，每个专家用随机的等价写法输出，并且各有 5%–30% 的概率犯一个错误：

```
一致度的度量                高档     中档     低档    高档里伪标签正确
原始 LaTeX 的 1 − NED       53.4%    46.4%    0.2%       98.9%
归一化之后的 1 − NED       100.0%     0.0%    0.0%      100.0%
```

用原始字符串比较，将近一半的样本落进了中档：它们其实大多是对的，只是写法不同，却被送去做昂贵的渲染校验甚至人工复查。先归一化（第 3 章的 `normalize`）再比较，所有样本都进了高档，而且全部正确。

我们的迷你文法可以精确地归一化；真实的 LaTeX 做不到（第 4 部分会看到，真实公式没有一条能被我们的文法解析）。这就是 Xiaomi-OCR-0 用 **CDM** 而不是编辑距离衡量公式一致度的原因：CDM 比较的是渲染出来的符号和它们的位置，天然对写法不敏感。

## 33.6 难例挖掘

### 值得训练的样本

有了上亿条可信的标签，也不是每一条都值得训练。模型已经稳稳会做的样本，再训练一遍几乎没有收益（第 31 章：组内奖励全相同的题没有梯度）。最值得训练的是：**标签可信、而模型自己没把握**的样本。

- **标签可信**：专家一致度高（33.4 节）；
- **模型没把握**：用**自洽度**衡量。同一张图，模型在温度 1 下采样 G 次，回答两两之间的平均相似度。模型有把握时，G 次的回答几乎一样；没把握时，回答五花八门。

### 练习 33.4：`self_consistency`

```python
def self_consistency(samples, sim=text_sim):
    pairs = list(combinations(range(len(samples)), 2))
    if not pairs:
        return 1.0
    return float(np.mean([sim(samples[i], samples[j]) for i, j in pairs]))
```

手算：三个采样 `a`、`a`、`b`，三对的相似度是 1、0、0，自洽度 1/3。

`hard_candidates(agreement, consistency, tau_a, tau_u)` 选出"专家一致度 ≥ tau_a 且自洽度 < tau_u"的样本。Xiaomi-OCR-0 的报告用的就是这两个条件（阈值没有公开）。

注意自洽度不是准确率：模型可以**稳定地错**（G 次都写同一个错误答案，自洽度为 1）。这种样本用自洽度挑不出来，但专家一致度高而模型的答案和伪标签不同，可以挑出来。真实系统里会组合多种信号。

### 按簇配额

挑难例还有一个陷阱：按"难度"排序取前 k 个，挑出来的往往集中在一两种类型上（比如全是很长的公式，或者全是某一种字体）。训练数据的多样性反而下降了。

Xiaomi-OCR-0 的做法：先把样本按特征（他们用的是一个多模态嵌入模型的特征）用 K-means 聚类，每个簇分配名额，簇内再按权重抽。

### 练习 33.5：`quota_sample`

```python
def quota_sample(labels, weights, n, rng):
    labels = np.asarray(labels)
    weights = np.asarray(weights, dtype=float)
    clusters = sorted(set(labels.tolist()))
    size = {c: int((labels == c).sum()) for c in clusters}
    quota = {c: 0 for c in clusters}
    left = n
    while left > 0:
        open_ = [c for c in clusters if quota[c] < size[c]]
        if not open_:
            break
        share, extra = divmod(left, len(open_))
        for i, c in enumerate(open_):
            add = min(share + (1 if i < extra else 0), size[c] - quota[c])
            quota[c] += add
            left -= add
    ...  # 簇内按权重无放回地抽
```

手算：三个簇各有 5、2、10 个样本，要抽 9 个。第一轮每簇 3 个名额，但簇 1 只有 2 个，只能给 2，剩下 1 个名额；第二轮还有剩余样本的是簇 0 和簇 2，1 个名额按顺序给簇 0。最终 4、2、3。这是测试 `test_quota_sample` 的第一个例子。

## 33.7 清洗、去重与划分

### 第 4 部分：一个真实的公式数据集

OleehyO/latex-formulas 的 cleaned_formulas 有 552,340 条（6 个分片），我们读第 1 个分片的 92,057 条：

- **几乎每条都套着 `\begin{align*} … \end{align*}`**。这是数据集制作时加上的外壳，不是公式本身的内容。训练时要么统一去掉，要么统一保留；如果训练数据带外壳、评测数据不带，模型会在每个答案外面加上外壳，文本指标白白扣分（第 25 章的写法归一化问题）；

- **我们的玩具文法一条也解析不了**：真实公式用到希腊字母、`\left`、`\sum`、矩阵……这是一个提醒：本书的 MiniDoc 只覆盖了公式识别里最核心的二维结构，真实的公式识别要大得多的词表；
- **宽高比**：7.9% 的图宽高比超过 10。第 24 章的 `smart_resize` 对极端宽高比有限制（Qwen 要求长边 / 短边不超过 200）；宽高比极端的图在缩放后，字可能小到看不清。

### 精确去重


一个"清洗过的"数据集，仍然有 5% 的完全重复。用 `latex_key`（去掉 `$$…$$`、`\[…\]` 外壳和外层环境、`\displaystyle`、只影响间距的命令和空格，单个字符的上下标统一加花括号：`x^2` → `x^{2}`）规范化之后，又多找到 213 条。规范化的规则要覆盖你的数据**和模型输出**里出现的写法：GLM-OCR、TexTeller 这类模型的输出常带 `$$…$$` 或 `\[…\]` 外壳（第 34 章），不去掉的话，没有一个答案能和标签"完全一致"。

**一个静默错误**：`latex_key` 的第一版直接删掉了所有空格。这会把 `\wedge Y` 变成 `\wedgeY`——一个**不同的**（而且不存在的）命令名。LaTeX 里，命令名后面的空格是有意义的：它告诉 LaTeX 命令名到哪里结束。修正后的版本保留"命令名后面紧跟字母"的那个空格（测试 `test_minhash_lsh_and_keys` 的第二行）。这个错误不会让任何代码报错，只会让去重的结果悄悄地变差——如果用同样的函数清洗训练数据，还会让标签变错。

### 近似去重：MinHash 与 LSH

完全相同只是重复的一种。两条公式只差一个句号，算不算重复？对训练来说，它们几乎提供同样的信息；对评测来说，一条在训练集、一条在验证集，就是泄漏。

找近似重复，最直接的办法是两两比较。8.7 万条就有 38 亿对，太慢。标准的做法是 **MinHash + LSH**：

1. **shingles**：把每条字符串切成所有长度为 5 的子串，组成一个集合。两条字符串的相似度用集合的 **Jaccard 相似度** J = |A ∩ B| / |A ∪ B| 衡量；
2. **MinHash**：对一个随机的哈希函数 h，集合 A 的 MinHash 是 min_{x∈A} h(x)。关键性质：**两个集合的 MinHash 相等的概率正好等于它们的 Jaccard 相似度**。用 64 个不同的哈希函数，得到 64 位的签名；两个签名相同的位数比例，就是 J 的估计；
3. **LSH**（局部敏感哈希）：把 64 位签名切成 16 段、每段 4 位。任何一段完全相同的两条，成为候选对。只对候选对计算真正的 Jaccard。

### 练习 33.6：`minhash`

```python
def minhash(sh, n_hash=64):
    x = np.array([_h(e) for e in sh], dtype=np.int64)
    a, b = _AB[0, :n_hash, None], _AB[1, :n_hash, None]
    return ((a * x[None] + b) % _P).min(1)
```

每个元素先哈希成一个 32 位的整数 x，第 i 个哈希函数是 (a_i · x + b_i) mod P（P = 2³¹ − 1 是素数，a_i、b_i 是固定种子生成的随机数）。这是"通用哈希族"的标准构造，一次向量化就算出全部 64 个哈希值。

### 为什么 MinHash 相等的概率是 J

把 A ∪ B 的元素按哈希值排序（哈希函数是随机的，所以这是一个随机的排列）。A 的 MinHash 和 B 的 MinHash 相等，当且仅当 A ∪ B 里哈希值最小的那个元素**同时**在 A 和 B 里，也就是在 A ∩ B 里。随机排列下，最小的那个是 A ∪ B 中的任何一个元素的可能性都相同，所以概率 = |A ∩ B| / |A ∪ B| = J。

### LSH 的 S 曲线

一段 r = 4 位全部相同的概率是 J⁴；16 段里至少一段全相同的概率是

```
P(成为候选) = 1 − (1 − J^r)^b，r = 4，b = 16
```

手算三个点：

| J | J⁴ | (1 − J⁴)¹⁶ | P(成为候选) |
|---|---|---|---|
| 0.8 | 0.4096 | 0.5904¹⁶ ≈ 0.0002 | ≈ 1.00 |
| 0.5 | 0.0625 | 0.9375¹⁶ ≈ 0.356 | ≈ 0.64 |
| 0.3 | 0.0081 | 0.9919¹⁶ ≈ 0.878 | ≈ 0.12 |

相似的几乎一定成为候选，不相似的很少成为候选，中间是一条陡峭的 S 形曲线。调 r 和 b 可以移动这条曲线的位置：r 越大，曲线越往右（要更相似才成为候选）。

### 按组划分

更根本的解决办法是**按组划分**：同一篇论文、同一个文档、同一个模板生成的样本，属于同一个组，整组进训练集或者整组进验证集。同一篇论文里的公式，符号、记号、风格高度相似，即使不是近似重复，模型在训练时见过同一篇论文的其他公式，验证分数也会偏高。

## 33.8 定向合成

真实数据有覆盖不到的地方（罕见的字体、书法、化学式、特殊的表格结构），而模型的失败也有规律可循。**定向合成**就是针对这两点生成数据：

- **按覆盖合成**：常规的结构（表格、公式、版式）用模板生成；特殊的字体、书法用素材模拟；
- **按失败合成**：在验证集上诊断出模型失败的样本（比如嵌套很深的分式），生成它们的变体，混进 SFT 数据；然后在一个**冻结的**难例集上验证有没有改进。

本书的 MiniDoc 本身就是"按覆盖合成"：公式的 level 控制嵌套深度，页面有单栏和双栏。第 25 章的分桶错误分析告诉你模型在哪些桶上失败，那就是"按失败合成"的起点（自己动手第 4 题）。

合成数据的风险是**合成到真实的鸿沟**：模型学会了合成图的"特征"（比如渲染器特有的抗锯齿），在真实图上并没有变好。所以合成数据的效果一定要在真实的（或至少是另一种来源的）验证集上衡量。合成的样本同样要过质量闸门：规则检查、渲染一致性检查、去重。

## 33.11 常见错误

| 错误 | 症状 | 原因与修正 |
|---|---|---|
| 用相似的模型当多个专家 | 共识的高档里有一类错误特别多 | 相关的错误：专家的结构、训练数据越不同越好；去掉"同门"的专家 |
| 一致度用原始字符串比较公式 | 大量正确的样本落进中档 | 写法不同不代表内容不同：用 CDM 或先归一化 |
| 固定的一致度阈值用在不同长度的样本上 | 短行的高档里有错字 | 1 − NED ≥ 0.9 对 10 个字的行意味着允许 1 个错字；按长度调阈值或用完全一致 |
| 图像比较不做对齐 | 正确的答案被拒 | 噪声让外接框偏一个像素；做平移搜索 |
| 去重的规范化改变了内容 | 去重结果悄悄变差、标签被改错 | `\wedge Y` → `\wedgeY`；规范化函数要有测试，覆盖命令名和空格 |
| 只做精确去重 | 验证集分数偏高 | 末尾标点、空格不同的近似重复；用 MinHash + LSH |
| 随机划分 | 同一篇论文的公式在训练集和验证集里都有 | 按组划分；采集数据时保留来源信息 |
| 评测集混进训练数据 | 分数好得不真实 | 评测集只用于评测；对训练数据和评测集做一次近似去重的交叉检查 |
| 不记录许可证 | 发布时才发现某个数据源不能商用 | 每个数据源一行：名称、版本、许可证、用途、条数、过滤 |
| 合成数据只在合成的验证集上评测 | 合成数据"很有效"，真实场景没变好 | 用真实的（或另一来源的）验证集衡量 |

## 33.13 深入一步

### 独立专家的共识有多可靠

假设每个专家独立地以概率 p 读错一行，而且读错时写出的答案各不相同（错误不会碰巧一致）。三个专家都写出同一个答案，只可能是三个都读对了。所以"三个完全一致"的答案一定是对的，它发生的概率是 (1 − p)³。

现实中错误会碰巧一致：两个专家都把 l 读成 1。设两个专家在同一行上犯**同一个**错误的概率是 q。如果专家独立，q ≈ p² × (同一种错误的比例)，很小；如果专家相关（比如 D 和 E），q 可能接近 p。共识的可靠性取决于 q，而不是 p：**一个错误率高但"错得与众不同"的专家，比一个错误率低但和别人"错得一样"的专家更有用**。这和集成学习（ensemble）里"多样性比个体精度更重要"是同一个道理。

### 为什么第 2 部分里 k 越大越好，但收益递减

k 越大，三元组变成 k 元组，"碰巧一致"需要更多的专家同时出同样的错，越来越难；但 k 越大，组里也越容易包含差的专家（G、H），中心点被拉向它们。在我们的设定里，8 个专家中整行正确率超过 70% 的只有 A、B、D、E 四个（而且 D、E 的错误彼此相关），k = 5 之后基本到顶（96.0% → 96.2%）。

### 难例的另一面

难例挖掘挑出"模型没把握、标签可信"的样本。但"模型没把握"有两种原因：样本确实难（值得学），或者标签其实是错的、而专家们一致地错了（不值得学，还有害）。第 2 部分的 D、E 就是后一种情况：它们一致地错，一致度高；而你的模型如果读对了，会和伪标签"不一致"，看起来像是"模型没把握"。所以难例集需要额外的复查：Xiaomi-OCR-0 用一个更强的大模型和人工标注者复查挖出来的难例，再用于 RL（第 34 章）。

## 33.14 横向对照

| 做法 | 标签质量 | 成本 | 覆盖 | 适合 |
|---|---|---|---|---|
| 人工标注 | 最高（也有错） | 最高 | 受预算限制 | 评测集、难例集 |
| 源文件反推（LaTeX、HTML） | 精确 | 低 | 只有"干净的渲染图" | 公式、表格的大规模预训练 |
| 单个模型的伪标签 | 受这个模型的限制 | 低 | 任意图像 | 起步阶段 |
| 多模型共识 | 高（错误独立时） | 中（要跑 n 个模型） | 任意图像 | 大规模语料 |
| 共识 + 渲染校验 + 大模型修订 | 更高 | 高 | 任意图像 | 中档样本的补救 |
| 合成 | 精确 | 低 | 你想到的情况 | 补长尾、按失败补数据 |

## 33.15 本章小结

1. 文档解析有两种结构：两阶段（版面检测 + 区块识别）和端到端（整页直接输出）。两阶段的视觉 token 更少（第 1 部分：四个区块 690 个 vs 整页 2,145 个），但小区块会被放大到 min_pixels；
2. 整页评测要先配对区块、按类型打分、按字数加权，多写的内容也要扣分；
3. 多模型共识：两两一致度、选最一致的三元组、取中心点、按一致度分档。模拟实验里三元组的中心点 94.9% 整行全对，最好的单个专家只有 85.0%；
4. 共识最大的敌人是**相关的错误**：高档里将近一半（52 个里的 24 个）的错误来自两个"同门"的专家；去掉其中一个，结果反而更好。短行上 1 − NED ≥ 0.9 的阈值也太宽松；
5. 渲染校验不需要真值：等价写法全部通过，结构性错误几乎全被拒，单个符号的替换是盲点（4% 通过）。图像比较要做对齐（不做时 2.7% 的正确答案被拒）；
6. 一致度的度量必须对等价写法不敏感：公式用原始字符串比较时，46% 的样本落进中档，归一化后全部是高档；
7. 难例 = 标签可信 + 模型没把握（自洽度低）；按簇配额保证多样性（大矩阵从 8 条变成 125 条）；
8. 真实数据：一个"清洗过的"公式数据集仍有 5.1% 的完全重复；末尾标点不同的近似重复让随机划分的验证集有 1.7% 泄漏；规范化函数本身也可能引入静默错误；
9. 采集数据时保留来源信息，才能按组划分；每个数据源记录许可证和用途。

## 参考答案

1. 两阶段：每个区块小、视觉 token 少，可以并行识别，阅读顺序可控，错误容易定位；端到端：能用跨区块的上下文，不受检测错误的影响，部署只有一个模型。例子：一个跨两栏的表格、或者被版面检测切成两半的段落——两阶段的识别器各看一半，拼起来可能断句错误；端到端看到整页。另一个例子：脚注的编号和正文的引用对应，需要跨区块的上下文。
2. 整页字符串对阅读顺序极其敏感：两栏的顺序反了，每个字都对，编辑距离却接近 100%。而且不同的内容需要不同的指标（公式用 CDM，表格用 TEDS）。配对之后，每个区块用合适的指标打分，阅读顺序可以单独评测。
3. 专家的错误如果彼此独立，几个专家碰巧写出同一个错误答案的概率很小，所以"多个专家一致"的答案大多是对的；共识不需要知道哪个专家最准。失效：错误相关时（两个相似的模型在同一类图上犯同样的错），以及所有专家都不会的样本（难图上一致度普遍偏低，或者一致地错）。
4. 两个专家碰巧一致就够了：D 和 E 在难图上写出相同的错误答案，一致度 1，k = 2 时直接选中它们。多数投票至少要求"出现次数最多"，k = 3 要求第三个专家也接近。
5. 能发现：格式错误（解析不了）、结构性错误（少了一项、多了一个分式、上下标互换）。发现不了：形状相近的符号互换（第 3 部分 4% 通过）、渲染器本身不支持的内容；而且它只能用在有渲染器的内容上（公式、表格），对普通文字很难"渲染得和原图一样"（字体、版式都不同）。共识从另一个角度（专家之间）提供证据，两者的盲点不同。
6. 不一定。模型可以稳定地错：G 次采样都写同一个错误的答案，自洽度为 1。这种样本要用"模型的答案和可信的伪标签不同"来发现。
7. 难度最高的样本往往集中在一两种类型上（第 5 部分里，难度如果和长度相关，挑出来的都是最长的公式），训练数据的多样性下降，模型在其他类型上可能变差。配额保证每种类型都有样本；代价是最常见的类型被压低了比例（短公式从 36.1% 降到 12.5%），模型在最常见的情况上看到的样本变少。
8. 同一篇论文、同一个文档、同一个模板的样本高度相似（甚至近似重复：末尾标点不同的同一个公式），随机划分会把它们分到两边，模型在训练时"见过"验证集的内容，验证分数偏高。latex-formulas 没有提供每条公式来自哪篇论文的信息，所以没法分组——采集时就要保留来源。
9. smart_resize：高 1200 / 32 = 37.5 → 38 × 32 = 1216（四舍五入；37.5 按 Python 的 round 是 38），宽 900 / 32 = 28.125 → 28 × 32 = 896；像素数 1216 × 896 ≈ 109 万，在默认的 max_pixels（4096 × 4096）之内。token 数 = 38 × 28 = 1,064。（可以用 `n_qwen_tokens(1200, 900)` 验证。）
10. 两两：cat–cat 1，cat–car 1 − 1/3 = 0.667，任何一个和 dog：cat–dog、car–dog 的三个字母都不同，编辑距离 3，一致度 0。三元组 (0, 1, 2)：(1 + 0.667 + 0.667) / 3 = 0.778，中档。中心点：0 号 1 + 0.667 = 1.667，1 号同样 1.667，2 号 1.333；平局取 0 号，伪标签 `cat`。
11. r = 8、b = 8：J = 0.8 → 0.8⁸ = 0.168，(1 − 0.168)⁸ = 0.832⁸ ≈ 0.229，P ≈ 0.77；J = 0.5 → 0.5⁸ = 0.0039，(0.9961)⁸ ≈ 0.969，P ≈ 0.031。r = 4、b = 16 时分别是 ≈ 1.00 和 0.64。r = 8 更严格：J = 0.5 的几乎不成为候选，但 J = 0.8 的也有 23% 漏掉。
12. 只写了文字：文字的分数 = 1 × 4 / 4 = 1，表格 0；总分 = 1 × 4/40 + 0 × 36/40 = 0.1。只写了表格：表格 1，文字 0；总分 = 0 × 4/40 + 1 × 36/40 = 0.9。按字数加权：表格的内容多，漏掉表格扣得多。
13. 三个问题：(1) 用全部专家的一致度之和选中心点，差的专家（G、H）也参与"投票"，而不是只在最一致的那一组里选；(2) 返回的一致度 `A.mean()` 包含了对角线上的 1，而且是所有专家之间的平均，不能衡量"最一致的那几个专家"有多一致，分档会失真；(3) 只有 1 个专家时 A 是 [[1]]，一致度为 1，会被当作高档。
14. 删掉所有空格会把 `\alpha x` 变成 `\alphax`、`\wedge Y` 变成 `\wedgeY`：两个不同的公式可能被当作重复（比如 `\alpha x` 和真正写成 `\alphax` 的宏），去重结果悄悄出错。而且它没有去掉 `\begin{align*}` 外壳、`\,` 这类间距命令，有些真正的重复又找不到。用 `latex_key`，并且给它写测试。
15. 不会。`page_score` 只对真值里出现的类型计算分数（`for kind in sorted({k for k, _ in ref})`），真值里没有表格，多写的表格不进任何一类的分母。要扣分，可以对预测里出现、真值里没有的类型，把它们的字数加到总分的分母上：总分 = Σ_类型 (配上的 s × 真值字数) / (真值总字数 + 所有没配上的预测的字数)。这样多写的任何内容都会扣分。
