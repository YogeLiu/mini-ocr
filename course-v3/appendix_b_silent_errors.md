# 附录 B　静默错误清单

**静默错误**是指：程序不报错，损失照样下降，评测照样出数字，但结果是错的。报错的问题容易修：读报错信息，按附录 D 查。静默错误只能靠检查和对照才能发现。本书大部分"常见错误"表格里，最危险的就是这一类。

本附录分三部分：

1. **最危险的 30 个静默错误**：按训练流程排列，每条标出它在哪一章出现过，以及怎样用一个小实验把它查出来；
2. **每次训练前后的检查清单**：可以复印贴在旁边；
3. **各章常见错误总表**：由 `tools/appendix_tables.py` 从各章的"常见错误"表格自动汇总，既有静默的，也有报错的。

## 1. 最危险的 30 个静默错误

### 数据

| # | 错误 | 为什么不报错 | 怎样查出来 | 章 |
|---|---|---|---|---|
| 1 | 测试集和训练集重复（逐像素相同、归一化后相同、近似重复） | 两个集合都是合法的数据 | 精确去重、归一化后去重、MinHash 找近似重复；按组划分 | 10、33 |
| 2 | 数组的 x、y 写反：`img[x0:x1, y0:y1]` | 切出来的仍然是一块图 | 把框画到图上看（`draw_boxes`） | 2 |
| 3 | `uint8` 运算溢出：`a + b` 超过 255 会回绕 | NumPy 不检查溢出 | 先转 `float32` 或 `int32` 再算；打印最大最小值 | 2 |
| 4 | 训练和推理用了不同的缩放或归一化 | 两种预处理都能产出合法的张量 | 同一张图分别过训练和推理的预处理，逐元素比较 | 2、24 |
| 5 | 图像缩放或补边了，框没有跟着换算 | 框仍然是四个整数 | 把换算后的框画到处理后的图上 | 2、21 |
| 6 | 标签的归一化和评测的归一化不一致（空格、花括号、`\left`、字体命令） | 字符串照样能比较 | 抽 20 个"判错"的样本，人工看是写法不同还是真的错 | 3、25、33 |
| 7 | 清洗脚本的全局替换破坏了标注（如把公式里的 `\\[2mm]` 当成 `\[`） | 替换后的字符串仍然"像" LaTeX | 抽查被规则命中的样本；在标注中间搜索不该出现的环境名 | 33 |

### 模型与前向

| # | 错误 | 为什么不报错 | 怎样查出来 | 章 |
|---|---|---|---|---|
| 8 | 用 `*`（逐元素）代替 `@`（矩阵乘法），或权重是 `(d_out, d_in)` 却写成 `x @ W` | 方阵时形状完全对得上 | 用非方阵测试（d_in ≠ d_out） | 4、9 |
| 9 | 广播出错：`(N,)` 和 `(N, 1)` 相减得到 `(N, N)` | 广播是合法操作 | 每一步打印形状；`assert` 形状 | 1、4 |
| 10 | 注意力没有因果 mask | 一样能算出损失，而且损失很低 | 改动第 t 个之后的输入，位置 t 的输出不应该变 | 15、16 |
| 11 | 补齐的位置没有被 mask 掉（注意力或损失） | 补齐 token 也是合法的 token | 同一条样本单独跑和放进补齐的批里跑，比较输出 | 16、26 |
| 12 | 打包时两条样本能互相看见 | 注意力照常计算 | 打包前后，每条样本的损失应该逐位相同 | 26 |
| 13 | KV cache 的位置编号（`pos0`）不对 | 生成照常进行，只是质量变差 | 带缓存和不带缓存逐个生成，logits 应该逐位一致 | 17 |
| 14 | 视觉 token 的个数和占位符的个数不一致，或者顺序不对 | 布尔下标赋值只要元素个数相同就能执行 | `assert` 每条序列的占位符个数；改动一个 patch，看变化出现在哪个位置 | 22、24 |
| 15 | 评测时忘了 `model.eval()`（有 Dropout 或 BatchNorm 时） | 训练模式也能前向 | 同一个输入跑两次，输出应该完全相同 | 10、11 |

### 损失与训练

| # | 错误 | 为什么不报错 | 怎样查出来 | 章 |
|---|---|---|---|---|
| 16 | 标签没有错开一位（位置 t 预测 ids[t] 而不是 ids[t+1]） | 损失照常下降，降得很快 | 损失低得离谱；生成时只会复读 | 14、16 |
| 17 | SFT 时提示、补齐、视觉占位符也计算了损失 | 都是合法的 token | 打印每个位置的身份和权重（`chat_roles`、`sft_targets`） | 26 |
| 18 | 梯度累积时每个微批各自按 token 平均，再相加除以微批数 | 损失数值看起来正常 | 一个大批和两个微批的梯度应该相同 | 18、26 |
| 19 | 忘了 `zero_grad`，梯度在步之间累加 | 只是步长变大 | 打印每一步的梯度范数 | 9、10 |
| 20 | 先建优化器、后解冻参数（优化器只收了当时 `requires_grad` 的参数），新解冻的部分从来不更新 | 前向、反向都正常，梯度也算了，只是没人用 | 训练前后比较各部分参数的哈希：该变的有没有变 | 22、28 |
| 21 | LoRA 的 B 没有初始化为 0 | 一样能训练 | 训练第 0 步，加 LoRA 前后的输出应该完全相同 | 28 |
| 22 | 重新分词后再算对数概率（生成的 token 序列和分词得到的不同） | 两种 token 序列都合法 | 用生成时的 token id 直接算；比较两种算法的第一个 token | 27 |

### 偏好优化与 RL

| # | 错误 | 为什么不报错 | 怎样查出来 | 章 |
|---|---|---|---|---|
| 23 | 把 k1 = −log r 直接放进损失当 KL 惩罚：它的梯度期望为 0，起不到约束作用 | 损失里确实有一项 KL | 监控真实的 KL（用 k3 估计），看它是否在增长 | 29 |
| 24 | DPO 的参考模型在训练中被更新了（和策略共享参数） | 损失照常计算 | 训练前后参考模型的输出应该不变 | 30 |
| 25 | 组内奖励全相同的题目占了大部分（没有梯度） | 训练照常进行，只是很慢 | 监控 `zero_variance_fraction`；DAPO 的动态采样 | 29、31 |
| 26 | 按样本平均（GRPO 原版）带来长度偏差 | 损失数值正常 | 比较三种汇总方式下长回答和短回答的梯度份额 | 31 |
| 27 | 奖励被投机（格式对、内容错，或者重复输出拿部分分） | 奖励在上升 | 定期人工看采样；格式闸门；超长 = 0 | 29、31、34 |
| 28 | 只评测训练的任务，没发现其他能力的遗忘 | 训练的任务确实变好了 | 每次都评测没训练的任务，或者算探测 KL | 32 |

### 评测

| # | 错误 | 为什么不报错 | 怎样查出来 | 章 |
|---|---|---|---|---|
| 29 | 用单次运行、没有置信区间的小差别下结论 | 数字就是数字 | bootstrap 置信区间、配对检验、多个种子 | 25、26 |

## 2. 每次训练前后的检查清单

**训练前**

- [ ] 打印 3 条训练样本：图（存成 PNG 看一眼）、完整的 token 序列、每个位置的身份和权重；
- [ ] 训练集、验证集、测试集之间做过去重和按组划分，写下各自的条数；
- [ ] 用 1 个批过拟合：几百步内损失应该接近 0。降不下去，说明模型或数据有问题；
- [ ] 初始损失约等于 ln(类别数) 或 ln(词表大小)。差得远，检查初始化和标签；
- [ ] 固定种子，同样的命令跑两次，前 10 步的损失应该完全相同；
- [ ] 冻结的参数、LoRA 的初始状态、参考模型都检查过（第 20、21、24 条）。

**训练中**

- [ ] 记录损失、梯度范数、学习率；RL 再加奖励、没有梯度的组的比例、裁剪比例、KL、回答长度；
- [ ] 每隔一段，在固定的几条样本上生成，人工看输出。

**训练后**

- [ ] 在测试集上评测训练的任务和没训练的任务，给出置信区间；
- [ ] 抽 20 个错误样本人工分类：是模型错了、标签错了，还是评测的归一化有问题；
- [ ] 和起点模型、一个简单的基线比较；
- [ ] 记录命令、种子、数据版本、用时，写进附录 E 那样的表。

**第 1 章　Python 与 NumPy 从零**（[ch01_python_numpy.md](ch01_python_numpy.md)）

| 现象 | 原因 | 怎么查 / 怎么改 |
|---|---|---|
| `IndentationError` | 缩进不一致（混用了 Tab 和空格，或少了一层） | 编辑器设置为"Tab 转 4 个空格" |
| 改一个数组，另一个也变了 | 切片是视图 | 需要独立修改时 `.copy()` |
| 结果全是 0 或者被截断成整数 | 数组类型是整数：`np.array([1, 2]) / 1` 没问题，但 `a[0] = 0.5` 在整数数组里会变成 0 | 打印 `dtype`；创建时指定 `dtype=np.float32` |
| 广播"成功"了，但结果形状不是想要的 | `(N,)` 和 `(N, 1)` 混用，得到 `(N, N)` | 每行写出形状；关键处加 `assert` |
| `sum`、`mean` 得到的形状不对 | `axis` 写错 | 记住"axis=k 把第 k 维压扁" |
| 每次运行结果都不同 | 没固定种子，或用了全局的 `np.random` | 用 `rng = np.random.default_rng(seed)` 并传下去 |
| 字典遍历顺序和预期不同 | 依赖了插入顺序 | 需要确定的顺序时显式 `sorted` |

**第 2 章　图像就是数组**（[ch02_images_as_arrays.md](ch02_images_as_arrays.md)）

| 现象 | 原因 | 怎么查 / 怎么改 |
|---|---|---|
| 裁出来的区域不对，或者形状是 `(宽, 高)` | x、y 写反：写成了 `img[x0:x1, y0:y1]` | 记住"数组先行后列，y 在前"；打印 `crop(...).shape` 与 `(y1-y0, x1-x0)` 对比 |
| 框比字少一行或一列 | 把"含两端"的坐标当成了"右下不含"，或反之 | 统一用右下不含；`ink_box` 返回的是 `max + 1` |
| 图像出现奇怪的噪点、黑白颠倒的斑块 | `uint8` 做运算溢出，或者小数直接 `astype(np.uint8)` 没有 `clip` | 运算前先 `astype(np.float64)` 或 `int()`；转回前先 `np.clip(..., 0, 255)` |
| 颜色红蓝互换 | 用 OpenCV 读图（BGR），按 RGB 使用 | 用 `img[..., ::-1]` 转换；或者统一用 Pillow |
| 模型对缩放后的图效果明显变差 | 训练和推理用了不同的缩放方法、不同的像素中心约定，或不同的 mean/std | 把训练和推理的预处理写成**同一个函数**；对同一张图比较两边的输出数组 |
| 缩小后细笔画消失 | 用最近邻或不带抗锯齿的双线性做了大幅缩小 | 缩小用区域平均；PyTorch 的 `F.interpolate` 要设 `antialias=True` |
| 框画上去和字对不上 | 图缩放或补边了，框没有跟着换算 | 用 `draw_boxes` 把框画到**处理后**的图上肉眼检查 |
| Pillow 报错尺寸不对 | Pillow 用 `(宽, 高)`，NumPy 用 `(高, 宽)` | 调用 Pillow 的 `resize`、`Image.new` 时注意顺序 |

**第 3 章　文本、字符集与结构化输出**（[ch03_text_and_structured_output.md](ch03_text_and_structured_output.md)）

| 现象 | 原因 | 怎么查 / 怎么改 |
|---|---|---|
| `"\frac"` 打印出来少了一个字符，或者出现奇怪的控制字符 | Python 里 `\f` 是"换页符"转义，`"\frac"` 实际上是 `换页符 + "rac"` | 写成 `"\\frac"` 或 `r"\frac"`；用 `len()` 和 `repr()` 检查 |
| 读文件出现乱码 | 编码不对 | `open(path, encoding="utf-8")` |
| 解析器陷入死循环 | 某个分支既没有 `take` 也没有抛出异常，位置 `i` 不再前进 | 在循环里打印 `self.i` 和 `self.peek()`；检查每个分支是否都消耗了记号 |
| `parse(to_latex(t)) != t`，但打印出来"看起来一样" | 树的形状不同，比如 `("row", [("row", [a])])` 和 `("row", [a])` | 用 `print_tree` 打印两棵树逐层对比；检查 `_clean` |
| `x^2^3` 被接受了 | `item` 没有检查重复的上标 | 加检查；跑 `test_invalid_raises` |
| 归一化后两个"显然相同"的公式仍然不相等 | 它们的语法树确实不同（见 3.8 节），或者用到了文法之外的命令 | 打印两棵树；判断这是归一化的已知局限还是 bug |
| 评测分数和论文对不上 | 归一化规则不同（空格、花括号、`\left`、字体命令……） | 读评测代码，而不是只读论文的描述 |

### 第一部分　数学

**第 4 章　向量、矩阵与形状**（[ch04_vectors_matrices.md](ch04_vectors_matrices.md)）

| 现象 | 原因 | 怎么查 / 怎么改 |
|---|---|---|
| `matmul: Input operand 1 has a mismatch in its core dimension` | 内维不相等 | 写出两个形状，检查 `(n, k) @ (k, m)` 的 k |
| 结果形状对，但数值不对 | 用了 `*`（逐元素）而不是 `@` | 搜索代码里的 `*`，确认每一处的意图 |
| 权重是 `(d_out, d_in)` 却直接 `x @ W` | 形状约定不同（PyTorch 风格） | 方阵时不会报错，最危险；打印权重形状并对照文档 |
| 一维数组转置没有效果 | `(n,)` 的 `.T` 还是 `(n,)` | 用 `v[:, None]` 或 `v[None, :]` 变成二维 |
| 余弦相似度出现 `nan` | 有零向量 | 分母加 `eps` |
| 距离出现很小的负数或 `nan` | 展开式的灾难性抵消 | `np.maximum(…, 0)` |
| einsum 结果形状对但数值错 | 字母写错（比如把求和维写成了保留维） | 对小数组用循环版本对照 |

**第 5 章　导数、梯度与链式法则**（[ch05_derivatives_gradients.md](ch05_derivatives_gradients.md)）

| 现象 | 原因 | 怎么查 / 怎么改 |
|---|---|---|
| 数值梯度与手推梯度差一个固定的倍数（比如 2 倍） | 手推时漏了链式法则的某一段，或者损失定义里有平均/求和的差别 | 在单个样本、单个参数上逐段对比 |
| 数值梯度"差不多对"，误差 1e-3 | 用了 float32；或 h 太小/太大 | 梯度检查一律用 float64、h = 1e-5 |
| 数值梯度的结果和参数顺序有关 | 求完一个参数后没有恢复原值 | 检查"恢复"那一行；测试调用前后数组是否不变 |
| 梯度检查在某些点失败、其他点通过 | 函数有尖角（ReLU、max、abs），恰好在尖角附近 | 换一个远离尖角的检查点 |
| 梯度符号反了，训练时损失越来越大 | 手推时把 `y − p` 写成了 `p − y` | 先检查一个能直观判断方向的简单例子 |

**第 6 章　概率、交叉熵与最大似然**（[ch06_probability_cross_entropy.md](ch06_probability_cross_entropy.md)）

| 现象 | 原因 | 怎么查 / 怎么改 |
|---|---|---|
| 损失是 `nan` 或 `inf` | softmax 没有减最大值而溢出；或者先 softmax 再 log | 用 log-softmax；检查 logits 的最大值 |
| 初始损失远大于 ln K | 初始化时 logits 太大 | 打印第一步的 logits 的标准差（应接近 0） |
| 初始损失远小于 ln K | 标签泄漏进了输入；或者损失只在部分样本上算 | 检查数据管道 |
| 把 softmax 的输出又传给了 cross_entropy | PyTorch 的 `F.cross_entropy` 要求输入 **logits**，内部自己做 log-softmax；传概率进去相当于做了两次 softmax | 模型最后一层不要加 softmax（第 9、10 章） |
| softmax 沿错了维度 | `axis=0` 和 `axis=-1` 混淆 | 检查 `p.sum(axis=-1)` 是否全为 1 |
| 交叉熵看起来"不下降了"，停在某个值 | 可能已经接近数据的熵（无法再降）；也可能是 bug | 对比一个已知的下界（如 6.8 节的频率模型） |

### 第二部分　神经网络

**第 7 章　梯度下降：线性回归、逻辑回归与 softmax 回归**（[ch07_gradient_descent.md](ch07_gradient_descent.md)）

| 现象 | 原因 | 怎么查 / 怎么改 |
|---|---|---|
| 损失一开始就变大，然后变成 inf/nan | 学习率太大 | 从小的学习率（如 1e-3）开始，每次放大 3 倍，找到发散的临界点，取它的 1/3 到 1/10 |
| 损失下降得极慢 | 学习率太小；或者特征尺度相差太大（条件数大） | 标准化特征；看曲线是否还在稳步下降 |
| 梯度形状和参数不一样 | 手推时转置写错（`X @ r` 而不是 `X.T @ r`） | 先检查形状，再做数值梯度检查 |
| 梯度大了 N 倍或 2 倍 | 忘了除以 N（损失是平均还是求和），或 MSE 漏了因子 2 | 数值梯度检查会发现固定倍数的差异 |
| 训练准确率很高，测试准确率很低 | 过拟合；或测试集用了不同的预处理 | 确保训练和测试用同一个预处理函数和同一组统计量 |
| 测试准确率高得可疑 | 测试集和训练集用了相同的随机种子，样本重叠 | 训练、验证、测试用不同的种子 |
| 逻辑回归的损失出现 inf | 直接写 `np.log(sigmoid(z))`，z 很负时 σ 下溢为 0 | 用 `np.logaddexp` |

**第 8 章　自己写自动求导**（[ch08_autograd.md](ch08_autograd.md)）

| 现象 | 原因 | 怎么查 / 怎么改 |
|---|---|---|
| 某个参数的梯度总是只有正确值的一部分 | `_backward` 里用了 `=` 而不是 `+=` | 构造一个节点被重复使用的例子（`a * a`） |
| 梯度一步比一步大 | 每步之前没有清零 | 检查训练循环的第一步 |
| 梯度时对时错，取决于表达式的写法 | 反向的顺序不对（没做拓扑排序，或者没有逆序） | 用菱形图测试 |
| `RecursionError: maximum recursion depth exceeded` | 计算图太深，递归的 `build` 超出上限 | 改成显式栈；或者减小图的深度 |
| 修改了 `p.data` 之后梯度检查失败 | 数值梯度扰动参数后，没有重新做前向 | 每次扰动后重新构建计算图 |
| 对常数求导得到非零梯度，以为有 bug | 常数也是图里的节点，它们也会收到梯度，只是不被使用 | 正常现象 |

**第 9 章　PyTorch 基础**（[ch09_pytorch.md](ch09_pytorch.md)）

| 现象 | 原因 | 怎么查 / 怎么改 |
|---|---|---|
| `Expected all tensors to be on the same device` | 模型和数据不在同一个设备 | 每批数据都 `.to(DEV)`；模型 `.to(DEV)` |
| `expected scalar type Long but found Int` / `Float` | 标签不是 int64，或输入不是 float32 | `y.long()`、`x.float()` |
| `view size is not compatible with input tensor's size and stride` | 对不连续的张量用了 `view` | 用 `reshape`，或先 `.contiguous()` |
| 损失下降但效果很差 | 模型输出了 softmax 再传给 `F.cross_entropy` | 模型最后一层输出 logits |
| 显存越用越多直到 OOM | 把 `loss`（带计算图）存进了列表，计算图无法释放 | 记录用 `loss.item()` |
| 评测时显存不够 | 评测没有用 `torch.no_grad()`，记录了计算图 | 评测包在 `with torch.no_grad():` 里 |
| `Can't call numpy() on Tensor that requires grad` | 需要梯度的张量不能直接转 NumPy | `t.detach().cpu().numpy()` |
| GPU 测速结果小得不可思议 | 没有 `torch.cuda.synchronize()` | 计时前后同步，并先热身 |
| 每次运行结果不同 | 没有固定 `torch.manual_seed` 和 DataLoader 的 generator | 固定所有种子 |

**第 10 章　训练循环：单字符识别**（[ch10_training_loop.md](ch10_training_loop.md)）

| 现象 | 原因 | 怎么查 / 怎么改 |
|---|---|---|
| 验证准确率比训练准确率还高很多 | 训练时有 Dropout/增强；或训练损失是"边训练边记录"的 | 训练结束后用 `evaluate` 在训练集上重新评测 |
| 测试准确率高得不可思议 | 测试集与训练集重复；标签泄漏到输入 | 去重检查；打乱标签后再训练，准确率应降到随机水平 |
| 每次运行结果差很多 | 没有固定种子；验证集太小 | 固定 `torch.manual_seed` 和 DataLoader 的 generator；验证集每类至少 20 张 |
| 恢复"最好的参数"后结果和最后一轮一样 | 保存 `state_dict()` 时没有 `deepcopy` | 见 10.3 节 |
| 混淆矩阵的总数比样本数少 | 用了 `C[y, p] += 1` | 用 `np.add.at` |
| 评测的损失和训练时不一样 | 评测时最后一批小，用了简单平均 | 按样本数加权 |
| 改了模型后结果变好，但测试集已经看过很多次 | 测试集被当作验证集用了 | 只在最后看测试集；需要更多比较时扩大验证集 |
| 训练正常但某几类永远是 0% | 类别不均衡，或这几类的标签映射错了 | 检查 `np.bincount(y)`；看混淆矩阵的那几行 |

**第 11 章　优化与训练技巧**（[ch11_optimization.md](ch11_optimization.md)）

| 现象 | 原因 | 怎么查 / 怎么改 |
|---|---|---|
| 换成 Adam 后完全不收敛 | 沿用了 SGD 的学习率（如 0.1） | Adam 从 1e-3 开始试 |
| 微调预训练模型后效果比微调前还差 | 学习率太大，破坏了预训练的知识 | 微调用 1e-5–1e-4，加预热 |
| 深层网络损失一直停在 ln K | 梯度消失（初始化不当、没有归一化/残差） | 打印各层梯度范数 |
| 训练正常，评测结果很差且每次不同 | 忘了 `model.eval()`（BatchNorm/Dropout） | 评测前 `eval()`，训练前 `train()` |
| BatchNorm 模型批大小为 1 时报错或结果很差 | 训练模式下批统计量无意义 | 小批量场景用 LayerNorm / GroupNorm |
| 训练到一半损失突然变成 nan | 偶尔的巨大梯度；学习率太大；fp16 溢出 | 记录梯度范数；加梯度裁剪；换 bf16 |
| fp16 训练很多步被跳过 | loss scale 不断减半，梯度一直有 inf | 检查模型里是否有溢出的运算；换 bf16 |
| 调度器的学习率不对 | 每轮而不是每步更新了学习率；总步数算错 | 打印每步的学习率 |
| AdamW 的 weight_decay 抄了 Adam 的值 | 两者含义不同 | AdamW 常用 0.01–0.1 |

**第 12 章　卷积神经网络**（[ch12_cnn.md](ch12_cnn.md)）

| 现象 | 原因 | 怎么查 / 怎么改 |
|---|---|---|
| `Expected 4D input` / 通道数不匹配 | 输入少了通道维 (N, H, W)，或通道数与第一层的 `in_channels` 不同 | 灰度图要 `unsqueeze(1)` 成 (N, 1, H, W) |
| 线性层报形状错误 | 改了输入大小或网络结构后，拉平后的维数变了 | 打印最后一个特征图的形状；或用全局平均池化 |
| 输出比预期小一圈 | 3×3 卷积没加 `padding=1` | 用 `conv_out_size` 检查 |
| im2col 的结果是错的 | 窗口内的排列顺序与卷积核 `reshape` 的顺序不一致 | 与 `F.conv2d` 对拍 |
| 训练时显存不足 | 特征图太大：(B, C, H, W) 的激活值都要存下来做反向 | 减小批大小；早一点池化；第 11 章的混合精度、第 18 章的激活检查点 |
| 增强后准确率反而下降 | 增强破坏了与类别有关的信息（翻转、过大的平移/旋转） | 把增强后的图存下来看一看 |
| 每次运行结果略有不同 | cuDNN 选择了不确定性的算法 | `torch.backends.cudnn.deterministic = True` |
| 评测结果很差且不稳定 | 忘了 `model.eval()`（BatchNorm） | 见第 11 章 |

### 第三部分　序列与语言模型

**第 13 章　文字行识别：CNN + RNN + CTC**（[ch13_line_recognition_ctc.md](ch13_line_recognition_ctc.md)）

| 现象 | 原因 | 怎么查 / 怎么改 |
|---|---|---|
| 损失是 inf 或 nan | 某个样本的 T 不够长（标签太长或有很多重复字符） | 检查 T ≥ U + 重复对数；用 `zero_infinity=True` |
| 模型只输出空白，损失不降 | 训练初期的正常阶段；或学习率太小 | 多训练一会儿；检查学习率和预热 |
| 解码结果总是少了重复字母（"hello" → "helo"） | 折叠时先删空白再合并重复（顺序错了） | 必须先合并再删空白 |
| `F.ctc_loss` 报形状错误 | 输入必须是 (T, B, K)，不是 (B, T, K)；必须是 log_softmax 的输出 | 检查 permute 和 log_softmax |
| 空白的编号不一致 | 字符表里空白不是 0，但 `blank=0` | `Vocab` 的 specials 把空白放在第 0 位 |
| CER 算出来偏高 | 逐行算错误率再平均（短行权重过大） | 用总编辑距离 ÷ 总字符数 |
| 合成数据上 CER ≈ 0，实验结论却不可信 | 数据太干净，没有区分度 | 加噪声、形变；用更接近真实的数据 |

**第 14 章　分词与语言建模**（[ch14_tokenization_lm.md](ch14_tokenization_lm.md)）

| 现象 | 原因 | 怎么查 / 怎么改 |
|---|---|---|
| 编码后解码不等于原文 | 预切分丢了字符（正则没覆盖所有情况） | `"".join(pretokenize(s)) == s` 断言 |
| 同一个词在训练和使用时切法不同 | 编码没有按规则的先后顺序合并 | 与 `bpe_train` 的过程对照 |
| 交叉熵是 inf | 没有平滑，或词表大小 V 写错 | 检查 k > 0；V 必须包括所有可能的 token |
| 不同分词器的困惑度相差悬殊 | 困惑度按 token 计算，不可比 | 换算成 bits per char |
| n 越大验证损失越差 | 数据稀疏，过拟合 | 用验证集选 n 和 k |
| 加载真实分词器后结果多了 `<\|endoftext\|>` | 有的分词器默认在末尾加特殊 token | `encode(s, add_special_tokens=False)` |
| 中文的 token 数是字符数的 3 倍 | 分词器没在中文上训练，退回到字节 | 换用多语言分词器 |

**第 15 章　注意力**（[ch15_attention.md](ch15_attention.md)）

| 现象 | 原因 | 怎么查 / 怎么改 |
|---|---|---|
| 权重矩阵每行和不为 1 | softmax 沿错了维度（dim=-2） | `w.sum(-1)` 应全为 1 |
| 合并头时报错 "view size is not compatible" | transpose 后不连续 | 用 `reshape` 或先 `.contiguous()` |
| 头之间的结果混在一起 | 拆头时写成了 `view(B, h, T, dh)`（顺序错） | 必须先 `view(B, T, h, dh)` 再 `transpose(1, 2)` |
| 用了 `k.T` 而不是 `k.transpose(-2, -1)` | `.T` 反转所有维度 | 有批维时一定要指定交换的维度 |
| 训练损失低得出奇，生成时一塌糊涂 | 忘了因果 mask，训练时偷看了答案 | 改动未来 token，检查前面的输出是否变化 |
| mask 的含义反了 | 有的库 True 表示"屏蔽"，有的表示"可以看" | 查文档；我们和 `F.scaled_dot_product_attention` 都是 True = 可以看 |
| 整行都被 mask 掉，输出 nan | softmax 全是 −∞，0/0 | 保证每行至少有一个可以看的位置 |
| 模型学不会和顺序有关的任务 | 位置嵌入尺度太小或忘了加 | 检查 token 嵌入和位置嵌入的标准差 |
| d 很大时训练很慢、注意力很"尖" | 忘了除以 √d | 检查分数的标准差 |

**第 16 章　从零写 GPT**（[ch16_gpt.md](ch16_gpt.md)）

| 现象 | 原因 | 怎么查 / 怎么改 |
|---|---|---|
| 初始损失远大于 ln V | 初始化太大，logits 起伏大 | 检查初始化标准差；看初始 logits 的标准差 |
| 训练损失低得离谱、生成一塌糊涂 | 因果 mask 没生效，偷看了答案 | 第 15 章的"改动未来 token"测试 |
| 损失不降 | 目标没有错开一位（预测的是当前 token） | x 和 y 应该是同一个窗口错开一位 |
| 加载预训练权重后输出乱码 | RoPE 的维度配对约定不同（相邻 vs 前后两半） | 对照原模型的实现 |
| 长输入时输出突然变差 | 超出训练长度，RoPE 外推失败 | 按位置统计损失 |
| 共享权重后嵌入的梯度异常 | 手动初始化时分别初始化了 head 和 tok，后者覆盖前者 | 共享后只初始化一次 |
| 权重衰减把 RMSNorm 的 γ 拉向 0 | 对所有参数都做了衰减 | 只对 dim ≥ 2 的参数衰减 |
| 注意力分析"看起来很好" | 统计量被更简单的解释混淆 | 设计能区分两种假设的对照情况 |

**第 17 章　生成与 KV cache**（[ch17_generation.md](ch17_generation.md)）

| 现象 | 原因 | 怎么查 / 怎么改 |
|---|---|---|
| 用 cache 和不用 cache 结果不同 | RoPE 的位置没有用 pos0 偏移；或 cache 在 RoPE 之前存入 | 第 16 章的 `test_kv_cache_matches_full_forward` |
| 生成到一半报"超过 block_size" | 提示 + 生成长度超过 RoPE 表的长度 | 限制最大长度，或截断提示 |
| top-p 总是只留下一个 token | 用 `cum >= p` 而不是 `cum − p_自己 >= p` 判断 | 用 17.2 节的手算例子测试 |
| 重复惩罚让负的 logit 变大 | 对所有 logit 统一除以 penalty | 负数要乘以 penalty |
| 同一个种子两次生成结果不同 | 没有把 generator 传给 `multinomial`；或用了 GPU 的非确定性算子 | 显式传入 `torch.Generator` |
| 贪心生成陷入循环 | 贪心解码的固有问题 | 采样、重复惩罚、重复检测、限制长度 |
| 一批里有的行已经结束，还在生成 | 没有处理 eos | 用 done 标记，结束的行补 eos |

**第 18 章　训练工程**（[ch18_training_engineering.md](ch18_training_engineering.md)）

| 现象 | 原因 | 怎么查 / 怎么改 |
|---|---|---|
| 梯度累积后训练发散 | 每个小批的损失没有除以累积次数，梯度大了 n 倍 | 和不累积的大批比较梯度 |
| 梯度累积和大批结果不同 | 各小批的有效 token 数不同 | 用"总和 / 总有效 token 数" |
| 续训后损失突然跳高 | 没有恢复优化器状态 | 检查点里必须有 `opt.state_dict()` |
| 续训后学习率不对 | 没有恢复步数，调度从头开始 | 检查点里存步数 |
| 续训结果和不中断不一致 | 没有恢复随机数状态（数据顺序、dropout） | 保存 generator 的状态 |
| 显存估算偏低很多 | 只算了参数，忘了梯度、优化器状态和激活 | 16 字节/参数 + 激活 |
| `torch.load` 报错 "weights_only" | PyTorch 2.6 起默认只加载张量 | 对自己的文件用 `weights_only=False` |
| 训练速度远低于预期 | 批太小，硬件吃不饱 | 测不同批大小的吞吐 |

**第 19 章　视觉 Transformer（ViT）**（[ch19_vit.md](ch19_vit.md)）

| 现象 | 原因 | 怎么查 / 怎么改 |
|---|---|---|

**第 20 章　对比学习：CLIP 与 SigLIP**（[ch20_contrastive.md](ch20_contrastive.md)）

| 现象 | 原因 | 怎么查 / 怎么改 |
|---|---|---|
| 损失一直在 ln B 附近不动 | 忘了归一化，或者温度 s 太小（logits 差别太小） | 打印相似度矩阵的范围和 s |
| 损失下降但检索很差 | 图像和文字的配对在批里被打乱了（数据加载 bug） | 抽几对样本人工检查 |
| SigLIP 损失巨大（上百）且训练不稳 | 偏置没有初始化成 −10 | 打印初始损失，应约为 10 |
| SigLIP 出现 inf/nan | 用了 log(sigmoid(x)) 而不是 logsigmoid | 换成 `F.logsigmoid` |
| 文字编码器结果随补齐长度变化 | 注意力或平均时没有 mask 掉 `<pad>` | 同一句话补齐到不同长度对比输出 |
| 温度学到上限 100 后训练变得不稳定 | 温度过低，只有最难的负例有梯度 | 观察 s 的曲线；可以固定或调低上限 |
| R@1 偏低但看例子觉得模型是对的 | 数据里有重复的描述，"只有原配算对"太严格 | 同时报告"文字相同就算对"的口径 |

**第 21 章　检测与版面分析**（[ch21_detection_layout.md](ch21_detection_layout.md)）

| 现象 | 原因 | 怎么查 / 怎么改 |
|---|---|---|
| AP 莫名其妙地低，可视化看着却对 | 框的格式搞混了（xywh 当成 xyxy，或坐标是归一化的） | 把预测框和真实框画在同一张图上 |
| 所有预测框都偏移半个格子 | 解码时忘了加 offset，或者中心的取整方式和目标不一致 | 用"完美预测"测试目标和解码的往返 |
| 训练一开始损失就是 nan | 热图头的偏置没有初始化成 −4.6，或者 log(p) 时 p = 0 | 初始化；clamp(p, 1e-4, 1 − 1e-4) |
| 检测器只输出很少的框 | 分数阈值太高，或者热图学得太"平" | 画出热图；降低阈值看召回率 |
| 同一行出现两个框 | 峰值提取的窗口太小，热图上一行有两个局部最大值 | 加一次框的 NMS |
| 整页 CER 远高于逐行 CER | 阅读顺序错了，或漏检整行 | 分别评测"真实框 + 真实顺序"和"检测框 + 真实顺序" |
| 裁出来的行识别很差 | 裁剪方式和识别模型的训练数据不一致（太紧、没留白、高度不对） | 把裁剪结果保存成图片，与训练样本对比 |

### 第五部分　视觉语言模型

**第 22 章　搭一个 VLM**（[ch22_build_vlm.md](ch22_build_vlm.md)）

| 现象 | 原因 | 怎么查 / 怎么改 |
|---|---|---|
| 断言失败：占位符个数与视觉 token 数不一致 | 换了连接器（合并、Q-Former）但构造序列时 N_v 没跟着改 | 由连接器类型计算 N_v，不要写死 |
| 训练损失很低，生成却是乱码 | targets 没有左移一位，模型学的是"复制当前 token" | 打印几个位置的 (输入, 标签) 对 |
| 生成停不下来 | 训练时没有监督 `<eos>` | 检查 targets 里是否包含 `<eos>` |
| 生成的答案总是同一个 | 只在答案上算损失，但答案太短、问题太少变化，模型忽略了图像 | 换图测试：答案变不变？ |
| 阶段 2 之后语言能力变差 | 学习率太大、没有先对齐 | 先只训连接器；降低学习率 |
| 冻结了却还在变 | 沿用了冻结前建的优化器：参数的 .grad 被清零成 0 而不是 None，优化器照样用旧的动量和权重衰减更新它 | 换阶段时重建优化器，只交给它 requires_grad 的参数；`zero_grad(set_to_none=True)` |
| 一批里提示长短不一，生成结果错位 | 右侧补齐后最后一个位置不是提示的结尾 | 按长度分组，或左侧补齐 + 注意力 mask |
| 推理时视觉 token 的数值范围不对 | 推理时的图像预处理（归一化）和训练时不一致 | 训练和推理用同一个预处理函数 |

**第 23 章　VLM 的任务与指令数据**（[ch23_vlm_tasks.md](ch23_vlm_tasks.md)）

| 现象 | 原因 | 怎么查 / 怎么改 |
|---|---|---|
| 多轮对话里第二轮回答乱了 | 只监督了最后一轮，或者第二轮的 targets 错位 | 打印每个计算损失的位置的 (输入, 标签) |
| 模型复述用户的问题 | 用户的话也计算了损失 | 检查 targets 里用户部分是否都是 −100 |
| 推理效果比训练时差很多 | 推理时的模板和训练时不一致（少了换行、角色前缀不同） | 用同一个函数生成训练和推理的提示 |
| 定位输出格式错误（少括号、多逗号） | 坐标数据太少，或者生成被截断（max_new 太小） | 统计格式错误率；加大 max_new |
| 问不存在的物体也给出框 | 训练数据里没有"不存在"的样本 | 加入负样本（"none"） |
| 换一种问法就答错 | 每个任务只有一种问法 | 问题模板多样化 |
| 加了新任务，旧任务变差 | 任务之间干扰，或新任务数据占比太大 | 每个任务单独评测，调整配比 |
| 多图时视觉 token 填错了图 | 图像张量的顺序和占位符的顺序不一致 | 用"图像 = 常数"的测试检查每段占位符对应哪张图 |

**第 24 章　解剖真实的 VLM**（[ch24_real_vlm.md](ch24_real_vlm.md)）

| 现象 | 原因 | 怎么查 / 怎么改 |
|---|---|---|
| `AutoProcessor` 报"requires the Torchvision library" | Qwen3-VL 系列的视频处理器依赖 torchvision | 装 torchvision，或者像本章一样分开用分词器和 PIL 版的图像处理器 |
| 报"Image features and image tokens do not match" | 占位符没有展开，或者展开的个数与 `image_grid_thw` 不符 | 数一数 `input_ids` 里 image_token_id 的个数，与 `grid.prod() // 4` 比较 |
| 报"mm_token_type_ids is missing" | 自己组装输入时漏了这一项 | `mm_token_type_ids = (input_ids == image_token_id).int()` |
| 模型能跑，但回答和图无关 | mean/std 用错，或者图片通道顺序不对（BGR） | 打印 `pixel_values` 的范围和均值；用 `preprocessor_config.json` 的参数 |
| 小字读错，大字读对 | 视觉 token 太少，图被缩得太小 | 提高 `min_pixels` / `max_pixels`，或先把图放大 |
| 显存 / 内存爆掉 | 大图的视觉 token 太多（3000×4000 有 11,750 个） | 设 `max_pixels`；先算 token 数再推理 |
| 输出里有 `<think>` 一大段 | 打开了思考模式 | 聊天模板里 `enable_thinking=False`（默认） |
| 生成停不下来，或者在奇怪的地方停 | `eos_token_id` 不对；SmolVLM 的结束标记是 `<end_of_utterance>` | 检查 `generation_config.json`；解码时用 `skip_special_tokens` |
| 打印一行"falling back to its reference PyTorch implementation" | 没装 flash-linear-attention / causal-conv1d | 不是错误，结果正确，只是慢；需要速度时再装 |
| LLaVA-1.5 读长条形的图很差 | 它把图裁成中间的 336×336 | 换用原生分辨率或切子图的模型，或者先把图补成正方形（padding） |

### 第六部分　评测与监督微调

**第 25 章　评测**（[ch25_evaluation.md](ch25_evaluation.md)）

| 现象 | 原因 | 怎么查 / 怎么改 |
|---|---|---|
| 同一个模型，和论文报告的分数差好几个点 | 归一化不同（大小写、空白、Unicode、标点）；指标的实现不同（语料级 vs 逐样本平均） | 用官方的评测脚本；在协议里写清每一步 |
| CER 超过 100% | 模型输出了很长的胡话（停不下来、重复） | 看预测长度的分布；同时报告 NED；检查 EOS 和 max_new_tokens |
| 加了一个改动，测试集上好了 0.3%，换种子就没了 | 种子噪声比改动的效果大 | 多个种子；报告平均和标准差 |
| 测试分数很高，上线后很差 | 测试集与训练集泄漏；测试集与真实数据分布不同 | 去重；按来源划分；建一个"真实数据"的小测试集 |
| 模型答对了却被判错 | 精确匹配太严格（"$38.50" vs "38.50"） | 规定输出格式；用 ANLS 或包含匹配；人工检查一批"错误" |
| 模型答错了却被判对 | 包含匹配太宽松（把所有选项都说一遍） | 限制回答长度；用更严格的匹配 |
| 两个区间重叠，就说"没有差别" | 没有配对 | 配对 bootstrap 或 McNemar |
| 公式全对的模型被扣了很多分 | 按原始字符串比较，等价写法被当成错误 | 归一化后比较，或用 CDM |
| 表格的分数变化很小，但表格明显错了 | 用 HTML 字符串比较，被标签稀释 | 用 TEDS；分别报告 TEDS 和 TEDS-S |
| 在测试集上反复调参后，结果不能复现 | 对测试集过拟合（多重比较） | 只用验证集做选择；测试集只用一次 |

**第 26 章　VLM 的监督微调**（[ch26_sft.md](ch26_sft.md)）

| 现象 | 原因 | 怎么查 / 怎么改 |
|---|---|---|
| 模型复述用户的问题，或者回答前先写一遍问题 | 用户的话也计算了损失（权重 1） | 打印每个位置的 (输入, 标签, 权重)，看用户部分是否为 0 |
| 回答对了，但后面跟着一串多余的字 | `<eos>` 没有计算损失 | 检查回答末尾 `<eos>` 的标签；统计"以正确答案开头"的比例 |
| 短回答的任务学不会，长回答的任务很好 | 按 token 平均时，短回答的梯度份额太小 | 算每个任务的梯度份额（第 1 部分）；改用按样本平均或调配比 |
| 改了微批大小，结果就变了 | 梯度累积时按微批各自求平均 | 用整个大批的 token 总数归一化 |
| 打包后训练损失很低，测试很差 | 没有分块 mask，样本之间互相"偷看" | 检查打包与不打包的 logits 是否一致（第 1 部分） |
| 打包后出现 NaN | mask 里有整行都是 False 的位置（`<pad>`） | 每个位置至少能看自己 |
| 打包后视觉相关的任务全错 | 图像的顺序和占位符的顺序不一致 | 用"每张图是不同常数"的输入检查（`test_embed_packed_order`） |
| 两次实验的结论相反 | 只跑了一个种子，差别在噪声以内 | 至少 3 个种子；报告标准差或达到阈值步数的范围 |
| 训练集全对，测试集很差 | 数据太少，看了太多遍 | 在训练集和测试集上同时评测；减少步数或增加数据 |

**第 27 章　回答的对数概率**（[ch27_logprobs.md](ch27_logprobs.md)）

| 现象 | 原因 | 怎么查 / 怎么改 |
|---|---|---|
| 对数概率比均匀猜测还低很多 | 错位：logits 和 ids 没有错开一位，或者错开了两次 | 和模型的损失比较；和 −ln V 比较 |
| 生成的回答，算出来的概率却很低 | 把生成的文字重新分词，得到了不同的 token（比如丢了前导空格） | 直接用生成时的 token 编号打分（27.7 节） |
| 选择题的结果偏向某个候选 | 候选的 token 数不同（求和偏向短的）；或者写法和模型习惯的不一样（有没有空格） | 打印每个候选的 token；用模型自己生成时的写法 |
| bf16 下 DPO/GRPO 的比值很抖 | 对数概率的精度不够，两个接近的数相减 | log_softmax 用 fp32 |
| 熵出现 NaN | 用 p · log p，p = 0 时得到 0 × (−∞) | 用 log_softmax 得到 log p |
| 补齐后结果变了 | 左侧补齐（因果模型的前面位置能看到补齐的 token），或者 mask 没有排除补齐的位置 | 右侧补齐；mask 只覆盖回答 |
| 置信度很高但经常错 | 模型过度自信（SFT 后常见），或者用的分数和长度有关 | 画可靠性图、算 ECE；温度缩放 |
| 用总对数概率挑读错的行，效果特别好 | 读错的输出往往更长，总和越长越负：分数里混进了长度 | 加一个"只看长度"的对照分数 |

**第 28 章　显存、梯度检查点、LoRA 与冻结**（[ch28_memory_lora.md](ch28_memory_lora.md)）

| 现象 | 原因 | 怎么查 / 怎么改 |
|---|---|---|
| 估算偏小一半，一跑就 OOM | 以为 bf16 混合精度让显存减半 | 有 fp32 主权重和 fp32 优化器状态，静态内存仍是 16 字节/参数（28.2 节） |
| 只训连接器也 OOM | 以为冻结语言模型就不存它的激活值 | 梯度要穿过语言模型（28.3 节第 2 部分） |
| 刚装上 LoRA 损失就变了，从一个更差的起点出发 | LoRA 的 B 也随机初始化 | B 必须为 0（28.5 节第 5 部分的第一个检查） |
| LoRA 的参数 `requires_grad=False`，优化器里是空的，或者 backward 报错 | 冻结之后又装 LoRA，或者装两次 | `apply_lora` 最后重新打开所有 A、B（练习 28.2） |
| 冻结的参数仍然在优化器里，有 weight decay 的话照样会被改动 | 优化器在冻结之前建好 | 先设置 `requires_grad`，再用 `[p for p in params if p.requires_grad]` 建优化器 |
| LoRA 参数比预期多，视觉塔也被改了 | `target_modules` 匹配到视觉塔 | 对 `vlm.lm` 调用，或者用完整路径匹配；装好之后打印 `replaced` 检查 |
| 警告"None of the inputs have requires_grad"，梯度是 None | 检查点和 `use_reentrant=True` 一起用在冻结的前几层后面 | 用 `use_reentrant=False` |
| 推理也占很多内存 | 推理时忘了 `torch.no_grad()` | 没有 `no_grad` 时 autograd 照样保存激活值（第 2 部分最后一行的反面） |
| 数字比估算大很多，而且释放之后不下降 | 用 `nvidia-smi` 的数字判断模型用了多少显存 | 那是缓存分配器 reserved 的加上 CUDA 上下文（28.7 节）；看 `max_memory_allocated()` |

### 第七部分　偏好与强化学习

**第 29 章　强化学习基础**（[ch29_rl_basics.md](ch29_rl_basics.md)）

| 现象 | 原因 | 怎么查 / 怎么改 |
|---|---|---|
| 简单题的回答都被推高，难题都被压低 | 优势没有按组算，所有题目混在一起 | `view(-1, G)` 按组算；采样时同一道题的 G 个回答要连续排列 |
| 报错，或者梯度里多了奇怪的项 | 奖励带着梯度（或者 A 没有 `detach`） | 奖励和优势都是常数 |
| 损失上下乱跳，看不出趋势 | 用"损失"的数值判断训练的好坏 | 策略梯度的"损失"没有意义，看平均奖励和 KL |
| 内存爆炸 | 采样时没有 `no_grad` | 采样不需要梯度；梯度在重新算 logp 的那次前向里 |
| ρ 恒为 1，裁剪失效 | old_logp 在多步更新中被重新计算 | old_logp 采样后算一次，之后不变 |
| 第一步的 ρ 就不是 1 | 采样用温度 T，算 logp 用温度 1 | 两者用同一个温度 |
| KL 惩罚不起作用 | k1 直接放进损失 | 用 k3（或者把 KL 放进奖励） |
| 被投机而不自知 | 只看奖励，不看输出 | 每隔一段时间打印几个回答；同时看 KL 和其他任务的分数（第 32 章） |
| 奖励不动，大部分组没有梯度 | 题目太简单或太难 | 监控 `zero_variance_fraction`；按难度挑题（第 31 章） |

**第 30 章　偏好优化 DPO**（[ch30_dpo.md](ch30_dpo.md)）

| 现象 | 原因 | 怎么查 / 怎么改 |
|---|---|---|
| 损失一开始就很大或很小 | 训练开始时损失不是 0.693 | 策略和参考模型不一样（加载错了权重，或者参考模型开着 dropout） |
| 内存翻倍；参考模型被"训练" | 参考模型的对数概率带着梯度 | `no_grad` 里算，或者预先算好存下来 |
| 结果和推导不一致 | 用每个 token 平均的对数概率代替总和 | DPO 的推导是对整个回答的概率；平均是另一种方法（SimPO，30.12 节） |
| h 很负时出现 −inf、NaN | `torch.log(torch.sigmoid(h))` | 用 `F.logsigmoid` |
| 准确率接近 1，任务指标没变好 | 只看训练集的偏好准确率 | 确定性偏好下准确率必然趋向 1；要看验证集和任务指标 |
| margin 一直增大，模型输出变得奇怪 | 训练太多个 epoch | 过拟合确定性偏好（30.4 节）；1–3 个 epoch、β 大一些 |
| 模型学会了"写长"或"写短" | chosen 和 rejected 的长度系统性不同 | 控制长度（substitute 而不是 add），或者用长度归一化的方法 |
| 隐含奖励里混进了提示的差别 | chosen 和 rejected 的提示不同 | 同一条偏好数据的两个回答必须用同一个输入 |
| chosen 的概率在下降而不自知 | 只看 margin 不看 chosen 本身 | 记录 log π(y_w) − log π_ref(y_w) |

**第 31 章　GRPO 与可验证奖励**（[ch31_grpo.md](ch31_grpo.md)）

| 现象 | 原因 | 怎么查 / 怎么改 |
|---|---|---|
| 优势变成 NaN，模型输出全乱 | 奖励里混进了 `None` 或 NaN | 格式错误必须返回 0，不能返回 None；检查每个奖励函数的边界情况 |
| 训练几乎没效果 | 采样和打分的顺序对不上 | 第 i 个回答对应第 i // G 道题；打印几条核对 |
| clip_frac 永远是 0 | old_logp 在 μ 次更新中被重新计算 | old_logp 采样后算一次 |
| 正确的长回答被扣分，模型学会写短（写错） | 软超长惩罚的起点小于正常回答的长度 | 先统计正常回答的长度分布 |
| 一个任务涨、另一个跌，看不出来 | 只看总奖励 | 分任务记录 |
| 几步之后输出崩溃 | 学习率照搬 SFT 的 | RL 的学习率通常比 SFT 小 1–2 个数量级 |
| 几乎所有回答都是 0 分，组内没有方差 | 格式闸门和参考模型的写法不一致 | 先看参考模型怎样写，再决定闸门或做归一化 |
| 奖励涨得很快，其他任务大幅下降 | 用 β = 0 却没有其他约束 | 加重放（第 32 章）或者保留小的 β |

**第 32 章　遗忘与能力配比**（[ch32_forgetting.md](ch32_forgetting.md)）

| 现象 | 原因 | 怎么查 / 怎么改 |
|---|---|---|
| 以为模型全面变好了 | 只评测训练的任务 | 每次都评测没训练的任务，或者算探测 KL |
| "LoRA 忘得少"之类的错误结论 | 在同一个学习率下比较不同的更新方式 | 各自扫学习率，比前沿 |
| 旧任务（回答长）实际占了大部分梯度 | 重放比例只按样本算 | 说清楚按样本还是按 token，必要时按 token 配比 |
| 遗忘看起来很小 | 重放用的是测试集的样本 | 重放用训练数据，评测用测试集，两者不重叠 |
| 差别来自评测而不是方法 | 不同方法用不同的评测设置（比如采样 vs 贪心） | 所有方法用同一套评测（第 25 章的评测协议） |
| 忽略了 GRPO 一步的计算量是 SFT 的几倍 | 只报告"相同步数"的结果 | 同时报告用时或计算量 |
| 结论换个种子就反过来 | 单个种子下的小差别当作结论 | 多个种子，或者只报告数量级的差别 |

### 第八部分　文档 OCR 与真实世界

**第 33 章　文档解析系统与数据工程**（[ch33_doc_engine.md](ch33_doc_engine.md)）

| 现象 | 原因 | 怎么查 / 怎么改 |
|---|---|---|
| 共识的高档里有一类错误特别多 | 用相似的模型当多个专家 | 相关的错误：专家的结构、训练数据越不同越好；去掉"同门"的专家 |
| 大量正确的样本落进中档 | 一致度用原始字符串比较公式 | 写法不同不代表内容不同：用 CDM 或先归一化 |
| 短行的高档里有错字 | 固定的一致度阈值用在不同长度的样本上 | 1 − NED ≥ 0.9 对 10 个字的行意味着允许 1 个错字；按长度调阈值或用完全一致 |
| 正确的答案被拒 | 图像比较不做对齐 | 噪声让外接框偏一个像素；做平移搜索 |
| 去重结果悄悄变差、标签被改错 | 去重的规范化改变了内容 | `\wedge Y` → `\wedgeY`；规范化函数要有测试，覆盖命令名和空格 |
| 验证集分数偏高 | 只做精确去重 | 末尾标点、空格不同的近似重复；用 MinHash + LSH |
| 同一篇论文的公式在训练集和验证集里都有 | 随机划分 | 按组划分；采集数据时保留来源信息 |
| 分数好得不真实 | 评测集混进训练数据 | 评测集只用于评测；对训练数据和评测集做一次近似去重的交叉检查 |
| 发布时才发现某个数据源不能商用 | 不记录许可证 | 每个数据源一行：名称、版本、许可证、用途、条数、过滤 |
| 合成数据"很有效"，真实场景没变好 | 合成数据只在合成的验证集上评测 | 用真实的（或另一来源的）验证集衡量 |

**第 34 章　案例精读：Xiaomi-OCR-0**（[ch34_xiaomi_ocr.md](ch34_xiaomi_ocr.md)）

| 现象 | 原因 | 怎么查 / 怎么改 |
|---|---|---|
| "Q-Mask 提升了 0.3 分"被当成可靠的结论 | 把报告的单次消融当作定论 | 单次运行没有置信区间；复现时多个种子，或者只引用定性结论 |
| dice 不下降 | 掩码头的查询取错位置 | 查询应在答案开始前的最后一个位置（它看过图和问题）；取图像位置的隐藏状态就和查询无关了 |
| dice 下降很慢，可视化的掩码是"转置"的 | 视觉 token 的顺序和掩码的顺序不一致 | 两者都按行排列（第 22 章的 patchify 和 box_to_grid_mask） |
| 掩码头全预测背景，CE 却很低 | 只用 CE 监督很小的掩码 | 加上 Dice（第 3 部分：CE 0.241 vs Dice 0.765） |
| 图像位置混进了 `<img>` 占位符的嵌入 | MTP 用 lm.tok(ids) 做下一个 token 的嵌入 | 用整条输入嵌入 emb（图像位置已经是视觉 token） |
| MTP 损失和 NTP 一样低 | MTP 的标签没有再移一位 | MTP 第 t 个预测对应 targets[:, t+1] |
| 某个任务主导了训练 | 多任务奖励的尺度不一致 | 所有奖励放在 [0, 1]，格式错 = 0（34.6 节） |
| 修正模型自己的偏差变成了标签 | 共识标签直接来自修正模型 | 修正后的读法要加回专家池重新共识（34.3 节） |
| 验证集的成绩虚高 | 合成的种子来自验证集 | 按来源文档划分，验证集的组不进入任何合成的输入 |

**第 35 章　搬到真实模型**（[ch35_real_models.md](ch35_real_models.md)）

| 现象 | 原因 | 怎么查 / 怎么改 |
|---|---|---|
| 训练能跑，但效果差 | 照搬别的模型的 LoRA 目标 | Qwen3.5 只写 q/k/v/o 时只覆盖 6 / 24 层；训练前数一下覆盖了多少层 |
| 视觉塔也被训练了 | 用后缀选 LoRA 目标 | 视觉塔的层也叫 q_proj；用完整名字的列表 |
| 训练和推理的 token 序列不一致 | 提示和回答分别分词再拼接 | 用整段文字分词，再用前缀法定 mask |
| 回答的第一个 token 不算损失，或者提示的最后一个算了 | 不检查前缀 | `answer_mask_by_prefix` 不是前缀时报错 |
| 和模板的格式不一致 | 回答前少了空格（或多了） | 用 `apply_chat_template` 生成带回答的完整对话来确认 |
| 以为在复现 GRPO 原文，其实 β = 0、按 token 汇总 | 不看训练库的默认值 | 打印配置，逐项对照 |
| 提示也算损失 | SFT 用了默认的 `assistant_only_loss=False` | 打开 `assistant_only_loss` 或用提示 / 回答两列的格式 |
| 奖励全接近 0，学不动 | 在原始模型上直接做 GRPO | 先 SFT 学会格式，再 RL |
| 训练一开始就显存不足 | 不确认显存 | `nvidia-smi`；第 28 章的估算 |
| 合并之后效果变了 | 合并后的差别很大 | 检查 α/r 的缩放；fp32 下差别应该在 10⁻⁵ 量级 |

**第 36 章　毕业项目：完成一次完整的研究**（[ch36_capstone.md](ch36_capstone.md)）

| 现象 | 原因 | 怎么查 / 怎么改 |
|---|---|---|
| 种子噪声当成方法差异 | 两个配置用不同的种子，只跑一个 | 同一组种子，按种子配对，至少 3 个 |
| 区间过窄，低估不确定性 | 把多个种子的样本拼起来做一次 bootstrap | 每个种子单独比较，看方向一致性 |
| 测试分数偏乐观 | 在测试集上调参 | 只在验证集上做决定；`TestGuard` |
| 任何结果都显得"合理" | 跑完才写预测 | 预测写进记录表，带日期，事后不改 |
| 分不清"方法"和"多训练了几步" | 和 SFT 起点比较 DPO / GRPO | 对照用同样步数的继续 SFT |
| 桶之间的此消彼长被掩盖 | 只报告平均数 | 事先定好桶，报告每桶的区间 |
| 多次比较，假阳性 | 跑完再挑"差异最大的桶" | 桶事先定；事后发现的写进"下一步"，不写进结论 |
| 奖励投机 | 只看奖励曲线 | 同时看验证分数、输出长度、样例 |
| 泄漏，验证分数偏高 | 随机划分有近似重复的数据 | 按近似重复分组划分（第 33 章、第 5 部分） |
| 无法复现，无法纠错 | 结果表里的数找不到来源 | 每行带运行 id；模型文件、日志用同一个 id |
| 把实验能力不足当成结论 | "未观察到差异"写成"没有差异" | 同时报告区间，说明能检测的最小差异 |
