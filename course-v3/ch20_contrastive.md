# 第 20 章　对比学习：CLIP 与 SigLIP

## 本章在全景图中的位置

第 19 章的 ViT 是用**分类标签**训练的：它学会了"数物体"或"说出最左边物体的颜色"，但只会做这一件事。VLM 需要的视觉编码器要通用得多：用户可能问颜色、数量、位置、文字、关系……我们不可能为每种问题准备标签。

**对比学习**（contrastive learning）用另一种监督信号：**图和它的文字描述**。互联网上有几十亿张带说明文字的图片（网页的 alt 文字、新闻配图的说明），不需要人工标注。训练目标是：让配对的图和文字在向量空间里靠近，不配对的远离。2021 年 OpenAI 的 **CLIP** 用 4 亿对图文这样训练，得到的视觉编码器"什么都懂一点"，可以零样本地做分类、检索，并成为后来几乎所有 VLM 的视觉底座：

| VLM | 视觉编码器的来源 |
|---|---|
| LLaVA-1.5 | CLIP ViT-L/14（336×336） |
| PaliGemma、SmolVLM | SigLIP |
| Qwen2-VL | 用 DFN（一种 CLIP）的 ViT 初始化 |
| Qwen3-VL | 用 SigLIP 2 初始化 |

本章推导两种对比损失（CLIP 的 InfoNCE 和 SigLIP 的 sigmoid 损失），在 ShapesWorld 和 MiniDoc 上各训练一个视觉底座，做零样本分类和检索，并用"冻结特征 + 线性分类器"回答一个问题：**为什么视觉塔要单独预训练？** 第 22 章搭 VLM 时，会比较"用本章预训练的视觉塔"和"从零开始"。

## 学习目标

1. 说清对比学习的设定：双塔、共享的向量空间、正例与负例；
2. 推导 InfoNCE 损失及其梯度，理解它为什么会"拉近正例、推开难负例"；
3. 理解温度的作用，算出温度太高时损失的下限；
4. 推导 SigLIP 的 sigmoid 损失，说清偏置 b 初始化成 −10 的原因，以及它相对 CLIP 的工程优势；
5. 理解批大小（负例数量）对对比学习的影响，以及"假负例"问题；
6. 用文字向量做零样本分类和检索，计算 Recall@k；
7. 用线性探针（linear probe）评估视觉特征的通用性；
8. 知道检索式的"零样本 OCR"能做到什么、做不到什么。

## 20.1 设定：两座塔、一个空间

```
图像 ──→ 图像编码器（ViT）──→ 线性投影 ──→ 归一化 ──→ zi ∈ ℝ^D，‖zi‖ = 1
                                                              ╲
                                                               相似度 zi · zt = cos(夹角)
                                                              ╱
文字 ──→ 文字编码器（Transformer）─→ 线性投影 ──→ 归一化 ──→ zt ∈ ℝ^D，‖zt‖ = 1
```

- 两个编码器**不共享参数**，各自把图和文字变成一个向量；
- 线性投影把两边的维度对齐到同一个 D（本章 128）；
- **L2 归一化**后向量都在单位球面上，点积就是余弦相似度，取值在 [−1, 1]。

训练数据是 B 对 (图, 文字)。一个批里，第 i 张图和第 i 句话是配对的（**正例**），第 i 张图和第 j ≠ i 句话不配对（**负例**）。B 对数据就有 B 个正例和 B² − B 个负例，负例不需要任何额外的数据：**批里的其他样本就是负例**。

训练好之后：

- **检索**：给一句话，找最相似的图（以文搜图），或者反过来；
- **零样本分类**：把每个类别写成一句话（"a photo of a dog"），图像向量与哪句话最相似就是哪一类。分类器是用文字"写"出来的，不需要任何该类别的训练样本；
- **视觉底座**：去掉文字塔，图像编码器的输出（第 22 章用每个 patch 的输出，而不是汇总向量）交给 VLM。

### 本章的文字编码器

```python
class TextEncoder(nn.Module):
    def forward(self, ids):
        mask = ids != self.pad_id
        x = self.tok(ids) + self.pos[:ids.shape[1]]
        for b in self.blocks:
            x = b(x, mask=mask)
        x = self.ln(x)
        m = mask.unsqueeze(-1).float()
        return (x * m).sum(1) / m.sum(1).clamp(min=1)
```

字符级（第 16 章的 100 个字符的字符表），3 层非因果 Transformer（直接复用第 19 章的 `ViTBlock`），对真实字符的输出取平均。一个批里的句子长短不一，短的用 `<pad>` 补齐。补齐的位置不能参与计算，有两处要处理：

1. **注意力**：真实字符不应该"看"填充位置。第 19 章的 `ViTAttention` 为此加了 `mask` 参数，把填充位置的分数设成 −∞，softmax 后权重为 0；
2. **平均**：只对真实字符求平均（乘以 mask 再除以真实长度）。

测试 `test_text_encoder_ignores_padding` 验证：同一句话补齐到不同长度，输出完全相同。（CLIP 的文字编码器是因果的，取最后一个 token 的输出；做法不同，道理相同。）

## 20.2 InfoNCE：CLIP 的损失

### 从分类的角度看

把"第 i 张图配哪句话"看成一个 **B 选 1 的分类问题**：候选是批里的 B 句话，logits 是相似度乘以一个系数 s：

```
logit_ij = s · zi_i · zt_j               s = 1/τ，τ 叫温度
p(j | i) = exp(logit_ij) / Σ_k exp(logit_ik)
L_图→文 = −(1/B) Σ_i log p(i | i)        正确答案是 j = i
```

这就是第 6 章的 softmax 交叉熵，只是"类别"是批里的句子，每个批都不一样。反过来，"第 j 句话配哪张图"也是一个 B 选 1 的问题（对 logits 的列做 softmax）。CLIP 取两者的平均：

```
L = (L_图→文 + L_文→图) / 2
```

这叫 **InfoNCE**（noise-contrastive estimation 的一种，"info"来自它和互信息的关系）。

### 练习 20.1：`clip_loss`

```python
def clip_loss(zi, zt, logit_scale):
    logits = logit_scale * zi @ zt.T
    labels = torch.arange(len(zi), device=zi.device)
    return (F.cross_entropy(logits, labels) + F.cross_entropy(logits.T, labels)) / 2
```

`logits.T` 的第 j 行是第 j 句话对所有图的分数，所以对它按行做交叉熵就是"文→图"。

### 手算

第 1 部分构造了 3 张图、3 句话（向量是手写的）：

```
  余弦相似度 S = zi · ztᵀ（第 i 行是第 i 张图，第 j 列是第 j 句话；对角线是配对）：
    0.990  0.385  0.215
    0.217  0.929  0.680
    0.137  0.669  0.934
```

对角线最大，说明每张图都和自己的描述最像。但图 1 和文 2（0.680）、图 2 和文 1（0.669）也挺像——它们是彼此的**难负例**（hard negative）。

s = 1 时，第 0 行 softmax 后配对的概率是 e^0.990 / (e^0.990 + e^0.385 + e^0.215) = 2.691 / (2.691 + 1.470 + 1.240) = 0.498：

```
  s = 1/τ =     1：按行 softmax 后配对的概率 [0.498, 0.44, 0.451]，按列 [0.53, 0.425, 0.442]；CLIP 损失 0.7699
  s = 1/τ =    10：按行 softmax 后配对的概率 [0.997, 0.923, 0.934]，按列 [0.999, 0.927, 0.926]；CLIP 损失 0.0507
  s = 1/τ =   100：按行 softmax 后配对的概率 [1.0, 1.0, 1.0]，按列 [1.0, 1.0, 1.0]；CLIP 损失 0.0000
  随机猜的 CLIP 损失 = ln B = ln 3 = 1.0986
```

同样的相似度矩阵，s 越大损失越小：s 把相似度的差别"放大"了。s = 1 时，即使对角线明显最大，配对的概率也只有 0.44–0.53。这引出了温度的问题（20.3 节）。

### 梯度：拉近正例，推开难负例

对第 i 张图的图→文损失 ℓ_i = −log p(i | i) 求关于 zi_i 的梯度。第 6 章：softmax 交叉熵对 logits 的梯度是 p − y（预测的概率减去独热标签）。logit_ij = s · zi_i · zt_j 对 zi_i 的梯度是 s · zt_j。用链式法则：

```
∂ℓ_i / ∂zi_i = s · Σ_j (p(j|i) − [j = i]) · zt_j
             = s · ( Σ_j p(j|i) · zt_j  −  zt_i )
```

梯度下降沿负梯度方向走：

```
zi_i ← zi_i + η · s · ( zt_i  −  Σ_j p(j|i) · zt_j )
```

- **zt_i**：把图像向量拉向它的正例；
- **Σ_j p(j|i) · zt_j**：按 softmax 概率加权的"所有文字向量的平均"，把图像向量推离它。概率越大的负例（越像的、越难区分的）推得越用力，已经离得很远的负例（p ≈ 0）几乎没有影响。

当 p(i|i) → 1 时，加权平均 → zt_i，梯度 → 0：已经分对的样本不再贡献梯度。这和第 6 章交叉熵的性质一样。

（向量归一化之后还要把梯度投影到球面的切平面上，这一步由自动求导处理，不改变上面的直觉。）

### 与互信息的关系（选读）

可以证明，InfoNCE 给出图和文字之间互信息的一个下界：I(图; 文) ≥ ln B − L。B 越大，这个下界能达到的上限 ln B 越高。这是"批越大越好"的一个理论解释（20.4 节）。证明只用到交叉熵和熵的性质（第 6 章），写在[附录 F.15](appendix_f_math.md)，那里还有一个能精确算出互信息的数值例子。

## 20.3 温度

### 为什么需要温度

归一化之后相似度在 [−1, 1] 之间。如果直接用相似度当 logits（s = 1），logits 的差别最多只有 2。

算一个极端情况：B = 256，正例的相似度是最大值 1，其余 255 个负例都是最小值 −1。配对的概率最多是

```
p = e¹ / (e¹ + 255 · e⁻¹) = e² / (e² + 255) = 7.39 / 262.39 = 2.8%
```

**即使模型做到完美，损失也降不到 −ln 0.028 = 3.57 以下**。模型永远"不满意"，梯度一直在推所有负例，学不到"已经够好了"。（实际上 255 个向量不可能同时和一个向量夹角 180°，下限还要更高。）

乘以 s = 1/τ 把 logits 的范围放大到 [−s, s]。CLIP 的初始值 τ = 0.07（s ≈ 14.3）。

### 温度太低也不好

s 很大（τ 很小）时，softmax 接近 argmax：只有最难的那个负例有梯度，其他负例都被忽略；训练早期向量还很乱，最难的负例往往是噪声（比如描述几乎相同的另一张图），梯度方向不稳定。

### 让模型自己学

CLIP 把 log s 作为一个可学习的参数（学 log 而不是 s 本身，保证 s > 0，而且对数尺度上的更新更均匀），并把 s 限制在 100 以内防止训练不稳定：

```python
self.log_scale = nn.Parameter(torch.tensor(math.log(1 / 0.07)))
def scale(self):
    return self.log_scale.exp().clamp(max=100.0)
```

原始的 CLIP 训练结束时 s 达到了上限 100（τ = 0.01）。我们的小模型在第 2 部分里训练 3000 步后 s 约为 48（τ ≈ 0.021），还没碰到上限。20.7 节第 3 部分比较固定的 s = 1、14.3、100 和可学习的温度。

## 20.4 批大小与假负例

### 负例越多越好？

每个批的负例数是 B − 1。负例越多：

- 随机负例里出现"难负例"的机会越大，模型被迫学到更细的区分；
- InfoNCE 的互信息下界 ln B 越高。

CLIP 的批大小是 32,768。这带来了工程问题：相似度矩阵是 B × B（32768² ≈ 10 亿个元素）；更麻烦的是，批分布在几百块 GPU 上，每块 GPU 上的图要和**所有** GPU 上的文字算 softmax，所以每一步都要把所有 GPU 的嵌入向量收集起来（all-gather）。

### 假负例

批里的"负例"不一定真的不配对。ShapesWorld 只有一个物体的场景，描述只有 2 × 4 × 3 = 24 种（大小 × 颜色 × 形状）：一个批里很可能有两张"a small red circle"的图。按 InfoNCE 的定义，图 i 和文 j（内容完全相同）被当成负例，模型被要求把它们推开——这是不可能完成的任务，只会增加噪声。

真实数据也一样：网上有大量"a photo of a cat"。处理方法：

- 数据去重、用更具体的描述（真实的 CLIP 数据里每句话大多是独特的）；
- 评测时承认"文字相同就算对"。`recall_at_k` 的 `same` 参数就是为此准备的：同一句描述对应的所有图都算正确答案。20.7 节报告两种口径；
- 训练时把内容完全相同的负例 mask 掉（本章没有做，留作选做题）。

## 20.5 SigLIP：每一对单独判断

### 损失

2023 年 Google 的 **SigLIP** 换了一个角度：不做"B 选 1"，而是把每一对 (图 i, 文 j) 都当成一个独立的**二分类**——"它们配对吗？"

```
logit_ij = s · zi_i · zt_j + b
y_ij = +1（i = j）或 −1（i ≠ j）
L = −(1/B) Σ_i Σ_j log σ(y_ij · logit_ij)
```

y = +1 时 −log σ(logit) 是"应该配对"的二分类交叉熵；y = −1 时 −log σ(−logit) = −log(1 − σ(logit)) 是"不应该配对"的。用 y 乘 logit 把两种情况写成一个公式（第 6 章 σ(−x) = 1 − σ(x)）。

### 练习 20.2：`siglip_loss`

```python
def siglip_loss(zi, zt, logit_scale, logit_bias):
    logits = logit_scale * zi @ zt.T + logit_bias
    y = 2 * torch.eye(len(zi), device=zi.device) - 1
    return -F.logsigmoid(y * logits).sum() / len(zi)
```

`2 * eye − 1` 是对角线 +1、其余 −1 的矩阵。一定要用 `F.logsigmoid` 而不是 `torch.log(torch.sigmoid(...))`：logit = −50 时 σ = 2 × 10⁻²²，float32 还能表示；logit = −120 时 σ 下溢成 0，log 0 = −∞。`logsigmoid` 用 log σ(x) = −log(1 + e⁻ˣ) 的稳定写法计算（测试 `test_siglip_loss_by_hand` 检查了极端值）。

### 为什么偏置初始化成 −10

一个批有 B 个正例、B² − B 个负例，负例多得多。

**没有偏置**（b = 0）：初始时向量是随机的，相似度 ≈ 0，每一对的 logit ≈ 0，σ = 0.5，每一对的损失都是 ln 2。总损失 ≈ B² · ln 2 / B = B · ln 2：B = 256 时是 177，几乎全部来自负例。模型最开始的梯度几乎都在说"把所有东西推开"，而不是"把配对的拉近"。

**b = −10**：初始 logit ≈ −10，σ(−10) ≈ 4.5 × 10⁻⁵。负例的损失 −log σ(10) ≈ 4.5 × 10⁻⁵，几乎为 0；正例的损失 −log σ(−10) ≈ 10。总损失 ≈ (B · 10 + B² · 4.5 × 10⁻⁵) / B ≈ 10。这相当于先验地假设"大多数对都不配对"，训练一开始就把注意力集中在正例上。

第 1 部分的手算（同一个相似度矩阵）：

```
  SigLIP s = 10、b = -10：每一对的 σ(logit) =
    0.476  0.002  0.000
    0.000  0.330  0.039
    0.000  0.035  0.341
    损失 1.0026
  SigLIP s = 10、b = -5：每一对的 σ(logit) =
    0.993  0.241  0.055
    0.056  0.986  0.858
    0.026  0.844  0.987
    损失 1.4195
```

b = −10 时，即使相似度 0.99，配对的概率也只有 0.476：要让 σ 接近 1，s · cos + b 要远大于 0，需要 s 变大或 b 变大，这些都是可学习的。b = −5 时正例的概率很高，但难负例（图 1、文 2）的概率也到了 0.858，损失反而更大。SigLIP 学的是一个**绝对的阈值**："相似度超过 −b/s 才算配对"，而 CLIP 只在乎**相对的排序**。

### SigLIP 的优点

1. **每一对独立**：损失是 B² 项的和，没有 softmax 的分母。多 GPU 训练时不必一次收集所有嵌入，可以分块计算、逐块交换，显存和通信都省得多；
2. **小批时更好**：SigLIP 论文的实验，批大小在 16k 以下时 SigLIP 明显好于 CLIP；批大到 32k 以后两者接近，再增大批收益很小；
3. **输出可以解释成概率**：σ(logit) 是"配对的概率"，可以设阈值做判断，而 CLIP 的 softmax 概率取决于批里有哪些候选。

SigLIP 及其后继 SigLIP 2 是今天开源 VLM 最常用的视觉底座。

## 20.6 零样本分类与检索

### 零样本分类

把每个类别写成一句话，编码成文字向量，组成一个 K × D 的矩阵——它就是一个线性分类器的权重。

#### 练习 20.3：`zero_shot`

在 `miniocr/models/clip.py` 里补完 `zero_shot(zi, class_zt)`：zi 是 (N, D) 的图像向量，class_zt 是 (K, D) 的类别向量，都已经归一化，返回每张图最相似的类别编号 (N,)。只需要一行：相似度矩阵是 (N, K)，在类别那一维取 argmax。

```python
def zero_shot(zi, class_zt):
    return (zi @ class_zt.T).argmax(-1)
```

本章的类别是单个物体的 24 种组合："a small red circle"、"a large blue triangle"……和训练时的描述格式完全一致。真实的 CLIP 用"提示模板"（prompt template），比如"a photo of a {类别}."，并对几十个模板的向量取平均（prompt ensembling），能提高几个百分点。

**组合泛化**：训练集里去掉了所有包含"黄色三角形"的场景（但有黄色的圆、黄色的方块，也有红色、蓝色、绿色的三角形）。测试时让模型识别单独的黄色三角形：它从没在描述里见过"yellow triangle"这个组合。如果模型学到的是"颜色"和"形状"两个独立的概念，就能组合出来；如果它只是把每种组合当成一个整体来记，就做不到。20.7 节第 2 部分给出答案。

### 检索与 Recall@k

N 个查询、M 个候选，相似度矩阵 sim (N, M)。**Recall@k**：正确答案排在前 k 名的查询所占的比例。

手算一个 3 × 3 的例子（对角线是正确答案）：

```
sim = [[0.9, 0.2, 0.1],      查询 0：第 1 名是候选 0 ✓
       [0.8, 0.7, 0.3],      查询 1：第 1 名是候选 0 ✗，前 2 名 {0, 1} 里有 1 ✓
       [0.1, 0.6, 0.5]]      查询 2：第 1 名是候选 1 ✗，前 2 名 {1, 2} 里有 2 ✓
```

R@1 = 1/3，R@2 = 3/3 = 1。注意查询 1：它的正确答案得分 0.7 并不低，只是候选 0 对它来说也很像（0.8）。R@1 惩罚这种"被别人抢了第一"的情况，R@5、R@10 更宽容。

#### 练习 20.4：`recall_at_k`

在 `miniocr/models/clip.py` 里补完 `recall_at_k(sim, k, same=None)`。`same` 是 (N, M) 的布尔矩阵，`same[i, j]` 表示候选 j 对查询 i 算对；默认只有 j = i 算对。ShapesWorld 里有很多描述完全相同的场景，所以检索时要用 `same` 把"描述相同的其他图"也算对，否则这些"假负例"（20.4 节）会让 R@1 偏低。提示：用 `topk` 取前 k 名的下标，再用 `gather` 从 `same` 里取出它们是否算对。

```python
def recall_at_k(sim, k, same=None):
    if same is None:
        same = torch.eye(sim.shape[0], dtype=torch.bool, device=sim.device)
    top = sim.topk(k, dim=1).indices                       # (N, k)：每个查询的前 k 名
    return same.gather(1, top).any(1).float().mean().item()
```

`same.gather(1, top)` 取出每个查询的前 k 名"是否算对"，`any(1)` 判断其中有没有对的。随机猜的 R@1 = 1/M。

### 线性探针

怎样评价一个视觉编码器的特征"好不好"？最常用的方法是**线性探针**（linear probe）：**冻结**编码器，在它输出的特征上训练一个线性分类器（逻辑回归）。线性分类器能力很弱，所以准确率主要反映特征里是否已经"线性地"包含了这个信息。

## 20.9 常见错误

| 现象 | 原因 | 怎么查 |
|---|---|---|
| 损失一直在 ln B 附近不动 | 忘了归一化，或者温度 s 太小（logits 差别太小） | 打印相似度矩阵的范围和 s |
| 损失下降但检索很差 | 图像和文字的配对在批里被打乱了（数据加载 bug） | 抽几对样本人工检查 |
| SigLIP 损失巨大（上百）且训练不稳 | 偏置没有初始化成 −10 | 打印初始损失，应约为 10 |
| SigLIP 出现 inf/nan | 用了 log(sigmoid(x)) 而不是 logsigmoid | 换成 `F.logsigmoid` |
| 文字编码器结果随补齐长度变化 | 注意力或平均时没有 mask 掉 `<pad>` | 同一句话补齐到不同长度对比输出 |
| 温度学到上限 100 后训练变得不稳定 | 温度过低，只有最难的负例有梯度 | 观察 s 的曲线；可以固定或调低上限 |
| R@1 偏低但看例子觉得模型是对的 | 数据里有重复的描述，"只有原配算对"太严格 | 同时报告"文字相同就算对"的口径 |

## 20.10 真实世界对照

- **CLIP**（OpenAI，2021）：4 亿对图文，批大小 32,768，图像编码器有 ResNet 和 ViT 两类，最大的 ViT-L/14@336px。在 ImageNet 上零样本准确率 76.2%，与有监督训练的 ResNet-50 相当；
- **OpenCLIP**、**DFN**、**MetaCLIP**：开源复现与改进，主要改进在**数据**：更大的数据集（LAION-5B）、更好的数据过滤（DFN 用一个模型给图文对打分过滤）。Qwen2-VL 的视觉塔就是用 DFN 的 ViT 初始化的；
- **SigLIP**（Google，2023）与 **SigLIP 2**（2025）：sigmoid 损失；SigLIP 2 加入了定位、密集特征、多语言等训练目标，提供不同分辨率和动态长宽比的版本。so400m 是"形状优化"过的 4 亿参数 ViT；
- **视觉底座的选择**：VLM 往往直接用开源的 CLIP/SigLIP 权重，在 VLM 训练的后期再解冻微调。也有模型（Qwen2.5-VL）重新训练视觉塔以支持原生分辨率；
- **文档领域**：通用 CLIP 对文字不敏感（网页图文对里文字图片少、描述也不逐字对应）。OCR 导向的 VLM 通常会用大量文档、OCR 数据继续训练视觉塔，或者使用专门的视觉编码器。本章第 6 部分在单词图上训练的 CLIP 是这个思路的玩具版。

## 20.11 深入一步

### 为什么要归一化

如果不归一化，模型可以通过把所有向量变长来让 logits 变大、损失变小，而不是学会区分正负例。归一化把向量限制在单位球面上，"相似"只能通过方向来表达；温度 s 单独控制尺度。这样两件事分开：方向学"谁和谁像"，s 学"多有把握"。

### 对比学习的"均匀性"与"对齐性"

一个有用的视角（Wang & Isola, 2020）：对比损失同时优化两件事。**对齐性**（alignment）：正例对的向量靠近；**均匀性**（uniformity）：所有向量在球面上尽量均匀地散开，充分利用空间。只有对齐没有均匀，所有向量会塌缩到一个点（损失并不低，因为负例也一样近）；InfoNCE 的分母（负例项）正是在推动均匀性。

### 模态鸿沟

训练好的 CLIP 里，图像向量和文字向量并不混在一起，而是各自聚在球面的不同区域，中间隔着一段距离，这叫**模态鸿沟**（modality gap）。正例对的余弦相似度通常只有 0.3 左右，远小于 1。这不影响检索（只看相对排序），但说明"同一个空间"并不意味着图像向量可以直接当文字向量用。这也是 VLM 需要一个可训练的连接器的原因之一（第 22 章）。

## 20.13 本章小结

- 对比学习用"配对的图文"作监督，不需要类别标签；批里的其他样本就是负例；
- CLIP 的 InfoNCE：B 选 1 的交叉熵，按行、按列各一次；梯度把向量拉向正例、推离按概率加权的负例；
- 温度不能太高（损失有下限、学不会自信）也不能太低（只看最难的负例）；CLIP 让它可学习，上限 100；
- SigLIP 把每一对当成独立的二分类，偏置初始化为 −10 以应对负例远多于正例；它在小批时更好，分布式实现更省；
- 假负例（内容相同却被当成负例）会给训练加噪声，评测时要注意口径；
- 零样本分类、检索、线性探针从不同角度评价视觉特征；预训练的视觉塔比为单一任务训练的视觉塔更"通用"；
- 检索式的 OCR 只能在候选里挑，读不出新字符串，这引出第 22 章的生成式 VLM。

14. 为什么 `TextEncoder` 要对真实字符求平均，而不是取第一个或最后一个位置的输出？取最后一个位置时要注意什么？

## 参考答案

1. 批里其他样本的文字（或图像）。一个批的 B 对数据天然给出 B² − B 个不配对的组合。
2. L = (CE(s·zi ztᵀ, I) + CE(s·zt ziᵀ, I)) / 2。行方向是"每张图在批里找它的描述"，列方向是"每句话在批里找它的图"，两个方向都训练，两个编码器都得到对称的约束。
3. ∂ℓ/∂zi = s (Σ_j p_j zt_j − zt_i)。负梯度方向拉向 zt_i、推离 Σ p_j zt_j；p_j 越大（越难区分）的负例在加权平均里占比越大，推得越用力。
4. s = 1 时 logits 的范围只有 [−1, 1]，配对概率有上限（B = 256 时最多 2.8%），损失降不下去，模型一直在推所有负例。s 太大时 softmax 接近 argmax，只有最难的负例有梯度，训练早期不稳定。
5. 负例数量是正例的 B − 1 倍，没有偏置时初始损失被负例主导（约 B·ln2），梯度主要是"推开一切"。b = −10 让初始 σ ≈ 0，负例损失接近 0，初始损失约为 10，训练从正例开始。
6. SigLIP 每一对的损失独立，不需要 softmax 的分母（对整行求和），所以不必收集所有设备的嵌入，可以分块计算；小批时，CLIP 的 softmax 只有很少的候选，概率估计偏差大，SigLIP 不受影响。
7. 实际上配对（比如描述完全相同）却被当成负例。ShapesWorld 单个物体的描述只有 24 种，一个批里经常出现相同的描述。
8. 线性分类器能力弱，准确率主要反映特征本身是否已经包含该信息。三层 MLP 自己就能学到很多变换，准确率高说明不了特征好。
9. logits：正例 9，负例 1。p = e⁹ / (e⁹ + 3e¹) = 8103 / (8103 + 8.15) = 0.999；损失 −ln 0.999 = 0.0010。
10. 正例 logit = 9 − 5 = 4，损失 −log σ(4) = 0.0181；负例 logit = 1 − 5 = −4，损失 −log σ(4) = 0.0181。每行 1 个正例、3 个负例：总和 4 × (0.0181 × 4) = 0.290，除以 B = 4 得 0.0726。
11. 32768² × 4 字节 = 4.3 GB（实际实现中每块 GPU 只算自己那一部分的行）。
12. 缺少温度 s（logits 范围太小）、没有归一化（zi、zt 应先 L2 归一化）、只算了图→文一个方向。
13. 构造 same[i, j] = (描述 i == 描述 j)，取每行相似度最高的候选 j*，判断 same[i, j*]。
14. 非因果编码器里每个位置都看到了整句话，取平均最稳定；取第一个位置需要专门的 CLS token；取最后一个位置（CLIP 的做法，配合因果注意力）时要取**最后一个真实字符**的位置，而不是补齐后的最后一位。
