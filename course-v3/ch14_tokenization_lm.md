## 14.2 字符级分词

最简单的方案：每个字符一个 token。第 1 章的 `Vocab` 就是这样做的。

```
  词表 82 个（每个字符一个编号）；训练语料编码成 599,449 个 token，每个 token 1 个字符
  验证语料里有训练语料没见过的字符吗？没有
  '$\\frac{x^{2}}{y}$' → 17 个 token
```

**优点**：词表小；不会遇到"不认识的词"（只要字符见过）；分词规则简单，不需要训练。

**缺点**：序列长。`\frac` 这一个命令要 5 个 token，一个英文单词平均要 5–6 个。序列长带来两个问题：

1. **计算量**：第 15 章的注意力，计算量与序列长度的平方成正比。长度翻倍，计算量变成 4 倍；
2. **学习难度**：模型要先学会把字符拼成单词，才能学单词之间的关系。每个 token 携带的信息少，要预测的步数多。

另一个极端是**词级分词**：每个单词一个 token。序列短，但词表会非常大（英文有几十万个词形），而且总会遇到没见过的词（新词、拼写错误、人名），只能用一个"未知"符号代替，信息就丢了。

**子词分词**（subword tokenization）是两者的折中：常见的词是一个 token，罕见的词拆成几个片段，最坏情况退回到单个字符。现代语言模型几乎都用子词分词，最常见的算法是 **BPE**。

## 14.3 BPE：字节对编码

### 算法

BPE（byte pair encoding）原本是一种数据压缩算法，2016 年被引入机器翻译。训练过程：

1. 从单个字符开始，每个字符是一个符号；
2. 统计语料中所有**相邻符号对**的出现次数；
3. 把出现最多的一对合并成一个新符号，记下这条"合并规则"；
4. 重复 2–3，直到合并了预定的次数。

词表 = 初始字符 + 每次合并产生的新符号。合并 N 次，词表就增加 N 个。

### 手算一个经典例子

语料是 `low` × 5、`lower` × 2、`newest` × 6、`widest` × 3，用空格连起来。预切分（14.4 节）把它切成"块"，空格附在后一个单词前面：

```
' newest': 6   ' low': 4   ' widest': 3   ' lower': 2   'low': 1
```

（第一个 `low` 前面没有空格，所以单独是一种块。）

**第 1 次合并**。统计相邻对（乘以块的出现次数），几个最多的：

| 相邻对 | 来自 | 次数 |
|---|---|---|
| (e, s) | newest × 6 + widest × 3 | 9 |
| (s, t) | newest × 6 + widest × 3 | 9 |
| (w, e) | newest × 6 + lower × 2 | 8 |
| (l, o) | low × 1 + low × 4 + lower × 2 | 7 |
| (o, w) | 同上 | 7 |

(e, s) 和 (s, t) 并列第一，按字典序取 (e, s)。所有块里的 e s 合并成 es：` newest` 变成 (␣, n, e, w, es, t)。

**第 2 次**：(es, t) 出现 9 次（原来的 s t 都跟在 e 后面，已经变成了 es t），合并成 est。

**第 3、4 次**：(l, o) 和 (o, w) 各 7 次，先合并 lo，再合并 low。

`bpe_train(text, 8, verbose=True)` 的输出：

```
    第   1 次合并：'e' + 's' → 'es'（出现 9 次）
    第   2 次合并：'es' + 't' → 'est'（出现 9 次）
    第   3 次合并：'l' + 'o' → 'lo'（出现 7 次）
    第   4 次合并：'lo' + 'w' → 'low'（出现 7 次）
    第   5 次合并：' ' + 'low' → ' low'（出现 6 次）
    第   6 次合并：' ' + 'n' → ' n'（出现 6 次）
    第   7 次合并：' n' + 'e' → ' ne'（出现 6 次）
    第   8 次合并：' ne' + 'w' → ' new'（出现 6 次）
```

注意 est 是在 newest 和 widest 之间**共享**的片段：BPE 发现了"最高级后缀"，而我们从来没告诉它语法。

### 练习 14.2：训练 BPE

```python
def bpe_train(text, n_merges, verbose=False):
    words = Counter(pretokenize(text))
    syms = {w: tuple(w) for w in words}
    merges = []
    for step in range(n_merges):
        pairs = Counter()
        for w, c in words.items():
            s = syms[w]
            for a, b in zip(s, s[1:]):
                pairs[(a, b)] += c
        if not pairs:
            break
        best = min(pairs, key=lambda p: (-pairs[p], p))
        merges.append(best)
        new = best[0] + best[1]
        for w in words:
            if len(syms[w]) > 1:
                syms[w] = _merge(syms[w], best, new)
    return merges
```

- 不在整段文本上统计，而是先数出**每种块出现了几次**（`Counter`），对每种块只处理一次，再乘以次数。60 万字符的语料只有几千种块，这让训练快了几百倍；
- `min(pairs, key=lambda p: (-pairs[p], p))`：次数最多的；并列时取字典序最小的，保证每次运行结果相同；
- `_merge` 从左到右、不重叠地替换。例如 (a, a, a) 合并 (a, a) 得到 (aa, a)，而不是 (a, aa)。

这个实现每次合并都重新统计所有对，复杂度是 O(合并次数 × 块的总长度)。真实的实现（Hugging Face `tokenizers`）只更新受影响的对，能在几十 GB 的语料上训练几十万次合并。

### 练习 14.3：用 BPE 编码

学到规则后，怎样把一段新文字切成 token？

```python
def encode_chunk(self, chunk):
    s = tuple(chunk)
    while len(s) > 1:
        pairs = [(self.rank.get(p, math.inf), p) for p in zip(s, s[1:])]
        r, best = min(pairs)
        if r == math.inf:
            break
        s = _merge(s, best, best[0] + best[1])
    return list(s)
```

从字符开始，每次在当前所有相邻对中，找**训练时最早学到**的那一条规则（rank 最小）合并，直到没有可用的规则。

**为什么必须按规则的先后顺序？** 测试 `test_tokenizer_roundtrip_and_rank_order` 构造了一个例子：规则依次是 (b, c)、(a, b)。编码 "abc"：

- 按顺序：先看 (a, b) 的 rank 是 1、(b, c) 的 rank 是 0，先合并 bc，得到 (a, bc)，再没有可用的规则，结果 `a | bc`；
- 如果"从左到右能合并就合并"，会先合并 ab，得到 `ab | c`。

两种结果不同。训练时 bc 先被合并，说明在语料里 b 后面跟 c 比 a 后面跟 b 更常见；编码时必须重现训练时的合并过程，同一个词在训练和使用时才会被切成同样的 token。

前 100 次合并就把序列缩短了 28%，之后**收益递减**：从 1000 到 3000 次只缩短了 6%。（3000 次合并实际只产生了 2948 个新符号：所有块都已合并成一个符号后，就没有可以合并的了。我们的语料只有约 450 个单词，3000 次合并足以把它们全部变成整词。）

词表大小是一个权衡：大词表让序列短，但每个 token 的嵌入向量要单独学习（第 16 章），罕见 token 学得不好；输出层的大小也与词表成正比。真实模型的词表一般在 3 万到 25 万之间。

```
    ' the'         → [' the']
    ' mountain'    → [' mountain']
    ' Mountain'    → [' M', 'ountain']
    ' MOUNTAIN'    → [' M', 'OU', 'N', 'T', 'A', 'IN']
    ' zebra'       → [' ', 'z', 'e', 'b', 'r', 'a']
    '\\frac'       → ['\\frac']
    '|---|---|'    → ['|', '-', '-', '-', '|', '-', '-', '-', '|']
    '2024'         → ['2', '0', '2', '4']
```

- **大小写不同，分词完全不同**：` mountain` 是 1 个 token，` MOUNTAIN` 是 6 个。对语言模型来说，它们是毫无关系的两个序列，需要分别学习；
- **没见过的词**（zebra 不在单词表里）退回到单个字符，不会出现"未知"符号；
- 表格分隔行和数字没有被合并，原因在预切分。

## 14.4 预切分

### 为什么需要

如果直接在整段文本上做 BPE，可能会学到跨越单词边界的合并，比如 "e t"（"the" 的结尾 + 空格 + "the" 的开头），产生大量无意义的 token。所以 BPE 之前先用规则把文本切成**块**，合并只在块内进行。

### 练习 14.1

```python
_PAT = re.compile(r" ?[A-Za-z]+|[0-9]| ?\\[A-Za-z]+|\n| +(?=\S)| +| ?[^\sA-Za-z0-9]")

def pretokenize(text):
    chunks = _PAT.findall(text)
    assert "".join(chunks) == text, "预切分丢了字符"
    return chunks
```

正则表达式从左到右依次尝试几种模式：

| 模式 | 匹配 | 例子 |
|---|---|---|
| ` ?[A-Za-z]+` | 可选的一个空格 + 一串字母 | `The`、` cat` |
| `[0-9]` | **单个**数字 | `4`、`2` |
| ` ?\\[A-Za-z]+` | 可选的空格 + 反斜杠 + 字母（LaTeX 命令） | `\frac` |
| `\n` | 换行 | |
| ` +(?=\S)`、` +` | 连续的空格 | |
| ` ?[^\sA-Za-z0-9]` | 可选的空格 + 其他单个符号 | `{`、` $`、`\|` |

`"The cat 42\\frac{a}"` → `["The", " cat", " ", "4", "2", "\\frac", "{", "a", "}"]`。

**空格附在单词前面**：` cat` 而不是 `cat `。这样同一个词无论在句子的什么位置（除了开头），都是同一个块。GPT-2 首创了这个约定，Qwen 的分词器也一样（14.7 节会看到 `Ġdrive`，`Ġ` 就是空格）。

**数字拆成单个数字**：如果允许合并，"2024" 可能是一个 token，"2025" 是两个（"202" + "5"），"1999" 又是另一种切法。同一个数在不同上下文里的切法不一致，模型很难学会算术或复制数字。拆成单个数字后，每个数字都是一个 token，切法永远一致。Llama、Qwen 等模型都这样做。对 OCR 来说，这意味着发票上的金额、日期、电话号码都是逐个数字输出的，模型不会因为没见过某个数字组合而出错。

**我们的设计还有一个副作用**：每个标点都是单独的块，所以 `|---|` 和 `}{` 永远不会被合并。14.7 节会看到真实的分词器在这一点上做得更好。

## 14.5 n 元语法语言模型

### 语言模型是什么

**语言模型**给一个 token 序列 x₁, x₂, …, x_T 分配概率。由概率的链式法则：

```
p(x₁, …, x_T) = p(x₁) · p(x₂ | x₁) · p(x₃ | x₁, x₂) · … · p(x_T | x₁, …, x_{T−1})
```

所以语言模型只需要会做一件事：**给定前面的 token，预测下一个 token 的概率分布**。这正是第 16 章的 GPT 和所有 VLM 的训练目标（"下一个 token 预测"，第 0 章）。

衡量语言模型好坏的标准是它在测试文本上的**平均负对数似然**（交叉熵，第 6 章）：

```
H = −(1/T) Σ_t log p(x_t | x₁, …, x_{t−1})
```

越小越好。困惑度 = e^H：模型平均在"多少个选项里犹豫"。

### n 元语法

完整的历史 x₁…x_{t−1} 太长，无法直接统计。**n 元语法**（n-gram）做一个近似：只看前 n − 1 个 token。

```
p(x_t | x₁, …, x_{t−1}) ≈ p(x_t | x_{t−n+1}, …, x_{t−1})
```

- n = 1（unigram）：不看上下文，就是第 6 章的模型；
- n = 2（bigram）：只看前一个 token；
- n = 3（trigram）：看前两个。

概率用**计数**估计（第 6 章：最大似然估计就是频率）：

```
p(w | h) = count(h, w) / count(h)
```

h 是前 n − 1 个 token（上下文），count(h, w) 是"h 后面紧跟 w"出现的次数。

### 平滑

如果某个组合在训练语料里没出现过，最大似然估计给它的概率是 0，测试时只要遇到一次，log 0 = −∞，交叉熵就变成无穷大。**平滑**给每个组合加一点"虚拟计数"：

```
p(w | h) = (count(h, w) + k) / (count(h) + k · V)
```

V 是词表大小。分母加 k · V 是为了让概率之和仍为 1：Σ_w (count(h, w) + k) = count(h) + kV。

### 练习 14.4

```python
class NGramLM:
    def __init__(self, n, vocab_size, k=0.1):
        self.n, self.V, self.k = n, vocab_size, k
        self.ctx = defaultdict(int)          # count(h)
        self.joint = defaultdict(int)        # count(h, w)

    def _contexts(self, ids):
        pad = [-1] * (self.n - 1) + list(ids)
        for t in range(len(ids)):
            yield tuple(pad[t:t + self.n - 1]), ids[t]

    def fit(self, ids):
        for h, w in self._contexts(ids):
            self.ctx[h] += 1
            self.joint[(h, w)] += 1
        return self

    def logprob(self, h, w):
        num = self.joint.get((h, w), 0) + self.k
        return math.log(num / (self.ctx.get(h, 0) + self.k * self.V)) if num > 0 else -math.inf

    def cross_entropy(self, ids):
        return -sum(self.logprob(h, w) for h, w in self._contexts(ids)) / len(ids)
```

- 开头不足 n − 1 个 token 时，补特殊的"开始"符号（编号 −1）。第 16 章的 GPT 用 `<bos>` token 做同样的事；
- `defaultdict(int)`：没见过的键默认为 0；
- 上下文 h 从没见过时，count(h) = 0，概率变成 k / (kV) = 1/V，即**均匀分布**。这一点在 14.6 节会造成有趣的后果。

**手算**（测试的内容）：序列 [0, 0, 1]，unigram，V = 4，k = 1。p(0) = (2 + 1)/(3 + 4) = 3/7；p(3) = (0 + 1)/7 = 1/7，所以 cross_entropy([3]) = −ln(1/7) = 1.946。

**读法一：上下文越长，训练损失越低**。字符级从 1 元的 3.57 降到 5 元的 1.20。看的越多，猜得越准。

**读法二：上下文太长，验证损失反而升高（过拟合）**。字符 5 元的训练 1.20、验证 1.72，差距明显；BPE-1082 的 5 元模型，验证损失（4.57）甚至比 2 元（3.76）还差。原因是**数据稀疏**：可能的 5 元组合有 V⁴ 种上下文，绝大多数在训练语料里一次都没出现过，模型只能退回到平滑给的均匀分布。词表越大，这个问题越严重：BPE-1082 的可能上下文有 1082⁴ ≈ 1.4 × 10¹² 种，而训练语料只有约 29 万个 token。

**读法三：困惑度不能跨分词方式比较**。BPE-1082 的 3 元模型困惑度是 31.2，字符 3 元是 5.9，看起来字符级好得多。但两者预测的东西不同：BPE 的一个 token 平均有 2 个字符，每次要猜的东西更多。公平的比较要换算成**每个字符的信息量**：

```
bits per char = (每个 token 的 nat) × (token 数) / (字符数) / ln 2
```

总信息量（nat/token × token 数）是同一份文本的总编码长度，除以字符数就和分词方式无关了。按 bits per char，BPE-1082 的 3 元（2.404）**比**字符 5 元（2.487）**还好**：BPE 的一个 token 覆盖了更长的字符跨度：3 元的 BPE 看前 2 个 token，约 2 × 2.06 ≈ 4 个字符，和字符 5 元看的前 4 个字符差不多；但它一次预测的是一整个 token（约 2 个字符），整个窗口约覆盖 6 个字符，比字符 5 元的 5 个字符还多。

所有模型都远好于均匀分布（6.36 bits/char）：语言是高度可预测的。

### 平滑系数的影响

```
  平滑系数 k 的影响（字符 5 元）：
    k = 0.0     验证 inf nat/char（有没见过的 5 元组，概率为 0 → 无穷大）
    k = 0.0001  验证 2.001 nat/char
    k = 0.01    验证 1.724 nat/char
    k = 0.1     验证 1.781 nat/char
    k = 1.0     验证 2.278 nat/char
```

- k = 0：只要验证语料里有一个训练中没见过的 5 元组，交叉熵就是无穷大；
- k 太小：没见过的组合概率太低，遇到时代价太大；
- k 太大：见过的组合被"稀释"，好的估计被均匀分布拉平了；
- 最优 k 在中间，要在验证集上选（第 10 章：这是一个"用验证集做决定"的超参数）。

更好的平滑方法（Kneser-Ney、回退）在 2010 年以前是语言模型研究的核心，但都已被神经网络语言模型取代。

## 14.6 从 n 元模型采样

语言模型可以用来**生成**文字：从 p(x₁) 采样第一个 token，再从 p(x₂ | x₁) 采样第二个……（第 17 章详细讨论采样策略。）第 5 部分：

```
  字符 2 元：
    | |-043}{19 sate g 976509}{keacte k}}+ain--|
    | - hol faclar | 66}-| ghy}-\flldent sty
  字符 4 元：
    | Out which slow ofter | For |
    | - piece papersong.
    | Problem use is remember Rock gove?
    | Verb $\frac{c^{y}^{4}{z^{x}=6$$
  字符 7 元：
    | Out young strong her class Help |
    | |---|---|
    | | 936 | 719 | life differ.
    | Whole picture or!
    | xkp904KQ3ksAQXg0=gVuLIA6a9r:cV^u10,(S1n FN5E6=xJG\bb(WhmX-(BxNuMiOfBt9
```

- **2 元**：只有局部的字母组合像样（"sate"、"fr"），整体是乱码；
- **4 元**：大部分单词是对的，有表格、列表、公式的样子，但公式 `\frac{c^{y}^{4}{z^{x}=6$$` 的括号不配对，`$` 和 `$$` 混用；
- **7 元**：前几行几乎完全像训练语料（甚至可能是原样复制，第 10 章的"背答案"），**然后突然变成纯粹的乱码**。

```
  7 元模型继续生成 400 个字符：第一次遇到训练中没见过的 6 字符上下文是在第 191 个字符；之后的 209 个位置里上下文都没见过
```

原因：一旦采样到一个训练中没见过的 6 字符上下文，平滑给出的是**均匀分布**（14.5 节），于是随机挑一个字符；乱码构成的上下文更不可能见过，再也回不来了。这是 n 元模型的根本缺陷：**它不会泛化**。见过 "the cat" 和 "a dog"，它不会知道 "the dog" 也是合理的，因为每个上下文都是一个独立的计数，相互之间没有联系。神经网络语言模型（第 16 章）把 token 表示成向量，相似的 token 有相似的向量，从而能泛化到没见过的组合。

```
  4 元模型生成 300 个以 $$ 开头的片段，其中 96 个有结尾的 $$；花括号不配对的 54 个（56%）
```

**长距离依赖**：判断一个 `}` 该不该出现，需要知道前面打开了几个 `{`，而这可能在十几个字符之前。4 元模型只能看到前 3 个字符，所以生成的公式一半以上括号不配对。对 OCR 来说这是致命的：LaTeX 括号不配对就无法渲染。这需要能看到任意远上下文的模型——第 15 章的注意力。

## 14.7 真实的分词器

第 6 部分加载 Qwen3 的分词器（如果本机缓存里有；第 24 章会正式下载真实模型）：

```
  词表大小 151,669（我们的 BPE：1,082）
  'Point drive science small $\\frac{y}{n+7}+8-k$.\n| Name | 2024 |'
    → 27 个 token：Point|Ġdrive|Ġscience|Ġsmall|Ġ$\|frac|{|y|}{|n|+|7|}|+|8|-k|$|.Ċ|||ĠName|Ġ||Ġ|2|0|2|4|Ġ|
```

- **Ġ 表示空格，Ċ 表示换行**。Qwen 用的是**字节级 BPE**（byte-level BPE）：先把文本变成 UTF-8 字节（第 3 章），每个字节一个初始符号（256 个），在字节上做 BPE。为了显示方便，把不可见的字节映射成可见的 Unicode 字符，空格（字节 0x20）显示为 Ġ，换行（0x0A）显示为 Ċ。字节级的好处是**永远不会遇到没见过的字符**：任何文本都是字节序列；
- 数字也拆成单个数字（`2|0|2|4`），和我们的设计一样；
- 它会合并 `}{`、`.Ċ`（句号 + 换行）、`-k` 这类符号组合，因为它的预切分没有把每个标点分开。注意 `Ġ$\` 和 `frac` 是分开的：Qwen 的预切分规则和我们不同，`\frac` 不是一个整体。不同模型对 LaTeX 的切法差别很大，这会影响公式识别的序列长度。

```
    '中文识别' → 2 个 token：['中文', '识别']  （内部显示为 ['ä¸Ńæĸĩ', 'è¯ĨåĪ«']）
    '数学公式' → 2 个 token：['数学', '公式']  （内部显示为 ['æķ°åŃ¦', 'åħ¬å¼ı']）
    'x²' → 2 个 token：['x', '²']  （内部显示为 ['x', 'Â²']）
    '∑' → 1 个 token：['∑']  （内部显示为 ['âĪĳ']）
```

"中文" 的 UTF-8 是 6 个字节，内部显示成 6 个奇怪的字符 `ä¸Ńæĸĩ`，但它们被合并成了**一个 token**：Qwen 在大量中文数据上训练，常用词都有整词 token。如果一个分词器没在中文上训练过（比如我们的），中文会被拆成单个字节，一个汉字 3 个 token，序列长度暴增。这就是"多语言能力"在分词层面的体现。

```
  验证语料：Qwen3 21,912 个 token（2.73 字符/token），我们的 BPE-1000：28,978 个（2.06）
```

Qwen 在我们的语料上压缩率更高：词表大 140 倍，英文单词几乎都有整词，还能合并符号组合。

**分词对 VLM 做 OCR 的影响**：

1. **序列长度**：一页文档转成 Markdown 可能有几千个 token。分词越高效，生成越快、上下文越够用；
2. **评测**：OCR 的指标按字符计算（第 25 章的 CER），不受分词影响；但训练时的损失按 token 平均，不同分词器的损失不能直接比较（14.5 节）；
3. **特殊 token**：VLM 的分词器还有一些特殊 token，比如 `<|image_pad|>`（图像占位符，第 22 章）、`<|im_start|>`（对话的开始，第 23 章）。它们不由 BPE 产生，而是直接加进词表。

| 现象 | 原因 | 怎么查 |

## 14.10 真实世界对照

- **GPT-2 / GPT-4 / Qwen / Llama 3**：都用字节级 BPE，词表 5 万到 25 万。Qwen 系列的词表约 15 万，包含大量中文词；
- **SentencePiece**：Google 的分词库，把空格当作普通字符（显示为 ▁），不需要预切分，适合中日文这类没有空格的语言。T5、早期的 Llama 用它；
- **tiktoken / tokenizers**：OpenAI 和 Hugging Face 的分词库，用 Rust 实现，速度比本章的 Python 实现快几个数量级；
- **视觉 token**：VLM 里图像也被切成"token"（第 19 章的 patch），但它们是连续的向量，不经过分词器。一张图通常是几百到几千个视觉 token，往往比文字部分长得多。第 24 章会看到，压缩视觉 token 的数量是 VLM 效率优化的重点；
- **n 元模型的遗产**：n 元语法在 2010 年前统治了语音识别和机器翻译。今天它仍出现在一些地方：OCR 的后处理里用 n 元语言模型做束搜索打分（第 13 章的束搜索可以加上语言模型分数）；训练数据去重时用 n 元组重叠衡量相似度（第 33 章）；检测测试集污染时也用 n 元组匹配。

## 14.11 深入一步

### 交叉熵与压缩

香农的信源编码定理：用一个概率模型 q 给数据编码（比如算术编码），平均每个符号需要的比特数等于交叉熵 H(p, q)（以 2 为底）。所以 "bits per char" 字面上就是"用这个模型压缩这份文本，每个字符需要多少比特"。语言模型越好，压缩率越高。这也是为什么有人说"语言模型就是压缩器"。我们的最好模型约 2.4 bits/char，而 ASCII 编码是 8 bits/char，gzip 对英文一般能做到 2.5–3 bits/char。

### BPE 为什么从字节开始

早期的 BPE 从 Unicode 字符开始，但 Unicode 有十几万个字符，初始词表就很大，而且总有没见过的字符。字节级 BPE 只有 256 个初始符号，任何文本都能表示。代价是：一个罕见的汉字可能被拆成 3 个字节 token，单独一个字节没有意义，模型要学会把它们拼起来。另一个后果是：模型可能生成**不合法的 UTF-8 序列**（只输出了一个汉字的前两个字节）。解码时要处理这种情况（Hugging Face 会用 � 替换）。

### 为什么不直接用字符级

既然字符级没有"未知词"问题，也不需要训练，为什么大模型不用？除了序列长、计算量大，还有一个更深的原因：**每个位置的计算量是固定的**。Transformer 处理每个 token 时做同样多的计算。用字符级，模型在"写出 t-h-e 的第二个字母"这种几乎确定的事情上花的计算和"决定下一个词是什么"一样多。子词让每个 token 携带更多信息，计算用在更有意义的地方。也有研究尝试让模型自适应地决定"一个 token 多长"（比如字节级模型 + 动态分组），但还不是主流。

## 14.13 本章小结

- 分词把文字变成 token；字符级序列长，词级有未知词，子词（BPE）折中；
- BPE 反复合并最常见的相邻对；编码时必须按规则的先后顺序合并；
- 预切分限制合并的范围：空格附在单词前，数字拆成单个数字；
- 语言模型 = 预测下一个 token 的分布；用交叉熵衡量；
- n 元语法用计数估计条件概率，需要平滑；上下文越长训练损失越低，但数据稀疏导致过拟合；
- 困惑度不能跨分词方式比较，要换算成 bits per char；
- n 元模型不能泛化，也看不到远处的上下文（括号配对失败），这是注意力要解决的问题；
- 真实分词器（Qwen3）用字节级 BPE、15 万的词表，常用中文词是一个 token。

2. 为什么 BPE 编码时必须按合并规则的先后顺序？
3. 为什么要把数字拆成单个数字？
4. n 元模型的 n 越大，训练损失越低，为什么验证损失反而可能升高？
5. 为什么 7 元模型生成的文字会在某个位置之后突然变成乱码？

**计算**

6. 语料 `"aaabdaaabac"`，手算 BPE 的前 3 次合并（当作一个块，并列取字典序最小）。
7. bigram 模型，词表 {a, b}，训练序列 "aabab"，k = 0.5。计算 p(b | a) 和 p(a | b)。
8. 一个模型在 10000 个 token（对应 25000 个字符）上的交叉熵是 2.0 nat/token。它的困惑度和 bits per char 各是多少？
9. 词表 1000、trigram，可能的上下文有多少种？如果训练语料有 100 万个 token，平均每个上下文出现几次？
10. 一个分词器对英文平均每个 token 4 个字符，对中文（没有中文训练）每个汉字 3 个 token。一页 2000 个汉字的文档要多少 token？如果换成每两个汉字一个 token 的分词器呢？

**代码**

11. 写一个函数 `coverage(tok, text)`，返回 text 中有多少比例的块被编码成了**单个** token。
12. 下面的 bigram 交叉熵计算有什么问题？
    ```python

## 参考答案

1. 字符级序列长，计算量大，每个 token 信息少；词级词表巨大，会遇到未知词。BPE 让常见词是一个 token，罕见词拆成片段，最坏退回到字符，既控制了词表大小，又不会有未知词。
2. 训练时规则是按顺序学到的，后面的规则是在前面的规则已经合并过的语料上统计出来的。编码时只有重现同样的合并顺序，才能保证同一个词在训练和使用时被切成同样的 token；否则会出现训练中从未见过的切法。
3. 如果允许合并，同一个数在不同上下文里的切法不一致（2024 可能是 1 个 token，2025 是 2 个），模型难以学会数字的规律（复制、比较、算术）。拆成单个数字后切法永远一致。
4. 上下文越长，可能的组合越多，训练语料里出现过的比例越小（数据稀疏）。模型记住了训练语料里的具体组合（过拟合），遇到验证语料里没见过的上下文时只能退回到平滑的均匀分布。
5. 一旦采样到一个训练中没见过的 6 字符上下文，平滑给出均匀分布，模型随机选一个字符；这样形成的上下文更不可能见过，于是一直是均匀分布，变成乱码。n 元模型的上下文之间没有任何联系，不能泛化。
6. 相邻对：aa ×4（aaab 里 2 对，出现两次），ab ×2，bd ×1，da ×1，ba ×1，ac ×1。第 1 次合并 (a, a)：从左到右不重叠，aaab → (aa, a, b)，序列变成 aa a b d aa a b a c。第 2 次：(aa, a) ×2，(a, b) ×2，(b, d)、(d, aa)、(b, a)、(a, c) 各 1；并列取字典序最小：('a', 'b') < ('aa', 'a')（比较第一个元素 'a' < 'aa'），合并 (a, b)：aa ab d aa ab a c。第 3 次：(aa, ab) ×2，合并成 aaab。
7. 序列 a a b a b 的 bigram：(a, a) 1，(a, b) 2，(b, a) 1。count(a) 作为上下文 = 3，count(b) = 1（最后一个 b 后面没有 token）。p(b | a) = (2 + 0.5)/(3 + 1) = 0.625；p(a | b) = (1 + 0.5)/(1 + 1) = 0.75。（这里不计开头的 <s> 上下文。）
8. 困惑度 e² = 7.39。bits per char = 2.0 × 10000 / 25000 / ln 2 = 0.8 / 0.693 = 1.154。
9. 1000² = 10⁶ 种上下文；100 万个 token 平均每个上下文出现约 1 次，绝大多数上下文只见过一两次甚至没见过，估计非常不可靠。
10. 2000 × 3 = 6000 个 token；换成每两个汉字一个 token 后是 1000 个，短了 6 倍。
11. ```python
    def coverage(tok, text):
        chunks = pretokenize(text)
        return sum(len(tok.encode_chunk(c)) == 1 for c in chunks) / len(chunks)
    ```
12. (a) 没有平滑，遇到没见过的 bigram 会 KeyError 或 log 0；(b) 分母应为预测的 token 数 len(ids) − 1（第一个 token 没有被预测），或者在开头补 <s> 把第一个 token 也算进去；(c) 若用 `defaultdict`，`counts_ctx[a]` 可能为 0 导致除以 0。
13. 把返回值除以 `math.log(2)`：`return -sum(...) / len(ids) / math.log(2)`。
