# 第 26 章　VLM 的监督微调

## 本章在全景图中的位置

一个 VLM 的训练通常分成这几段：

```
视觉塔预训练（第 20 章）─┐
                          ├→ 对齐（只训练连接器，第 22 章）→ 监督微调 SFT（本章）→ 偏好优化 / 强化学习（第 29–31 章）
语言模型预训练（第 16 章）┘
```

第 22 章的"阶段 2"和第 23 章的"指令微调"其实已经是监督微调（supervised fine-tuning，SFT）：给模型看"问题 + 正确答案"，用交叉熵让它学会写出答案。那两章关心的是**结构**和**数据**：VLM 怎么拼、有哪些任务。本章把 SFT 本身拆开，逐个检查那些看起来理所当然、实际上都要做决定的细节：

1. **损失算在哪些位置？** 只算回答，还是连问题一起算？视觉占位符呢？
2. **损失怎样平均？** 一个批里有 3 个 token 的回答，也有 60 个 token 的回答，谁的分量重？
3. **`<eos>` 要不要学？** 不学会怎样？
4. **补齐浪费了多少？** 怎样把短样本**打包**进一条长序列，又不让它们互相"偷看"？
5. **数据量和步数**：同样训练 2000 步，300 条数据反复看和 3 万条数据各看一次，有什么不同？
6. **分辨率与视觉 token 数**：这是两个不同的旋钮，各自影响什么？
7. **种子**：同一个配置跑 5 次，学习曲线长得一样吗？为什么"平均曲线"会骗人？

这些决定在真实模型的训练代码里都是一两行配置（`train_on_prompt`、`packing`、`loss_reduction`……），但每一行都会改变训练出来的模型。第 30–36 章的 OCR 微调、偏好优化都建立在本章的 SFT 之上。

## 学习目标

学完本章，你应该能够：

6. 用多个种子画学习曲线，用"达到阈值的步数"而不是"平均曲线"描述训练的快慢。

## 26.1 SFT 是什么

SFT 的数据是一条条"输入 → 期望的输出"：

```
输入：  [图] What color is the leftmost object?
输出：  red
```

把它们按聊天模板（第 23 章）拼成一条 token 序列，让语言模型逐个预测下一个 token，**只在一部分位置上计算交叉熵**，然后反向传播、更新参数。它和第 16 章的语言模型预训练用的是**同一个损失、同一个训练循环**，区别只有三点：

| | 预训练（第 16 章） | SFT（本章） |
|---|---|---|
| 数据 | 大量无标注的连续文字 | 成对的"问题 → 答案"，通常少得多 |
| 在哪些位置算损失 | 每个位置 | 通常只在答案上 |
| 序列的边界 | 文字首尾相接，切成固定长度的窗口 | 每条样本是一个完整的对话，长短不一 |

第三点带来了补齐和打包的问题（26.5 节）。第二点带来"算在哪里""怎样平均"的问题（26.2、26.3 节）。

在 VLM 里，SFT 还要决定**训练哪些部分**：视觉塔、连接器、语言模型，冻结哪个、解冻哪个。第 22 章的第 3 部分比较过几种组合；第 28 章会加上 LoRA（只训练很少的新参数）。本章全部解冻，专心看损失和数据。

## 26.2 损失算在哪些位置

### 每个 token 的身份

把一条两轮对话的每个 token 标上身份（第 1 部分的实际输出，B = `<bos>`，E = `<eos>`，▒ = 视觉占位符，64 个只画 4 个）：

```
token BUser: ▒▒▒▒What color is the leftmost object?⏎Assistant: yellowEUser: Is there a yellow circle?⏎Assistant: yesE
身份  fffffff▒▒▒▒uuuuuuuuuuuuuuuuuuuuuuuuuuuuuuuuuuffffffffffffAAAAAAAffffffuuuuuuuuuuuuuuuuuuuuuuuuuffffffffffffAAAA
```

四种身份：

| 身份 | 包括 | 这条样本里有几个 |
|---|---|---|
| f 格式 | `<bos>`、"User: "、用户消息末尾的换行、"Assistant: " | 37 |
| ▒ 视觉 | `<img>` 占位符 | 64 |
| u 用户 | 用户消息的文字 | 59 |
| A 回答 | 助手消息的文字和它后面的 `<eos>` | 11 |

171 个 token 里，回答只有 11 个，**不到 7%**。这是 VLM 的 SFT 的常态：图像占了大部分长度，回答往往很短。

### 位置 t 的标签由 t + 1 的身份决定

语言模型在位置 t 预测 ids[t + 1]。所以"这个位置算不算损失"看的是**下一个 token** 的身份：

```
位置 t 的权重 = w(ids[t + 1] 的身份)
```

默认的权重：

- **回答**：1。这是我们要模型学会写的东西；
- **用户的话**：0（不学）或一个小的数（`prompt_weight`，26.2 节末尾讨论）；
- **格式**：和用户的话一样；
- **视觉占位符**：永远 0。`<img>` 是我们自己放进序列的，推理时也由我们放，模型不需要"预测下一个是不是 `<img>`"。更重要的是，占位符的位置在嵌入层已经被换成了视觉 token，"预测一个占位符"没有意义。

### 练习 26.1：`chat_roles`

```python
def chat_roles(vocab, messages, n_img):
    img = [vocab.stoi["<img>"]] * n_img
    ids, roles = [vocab.stoi["<bos>"]], [ROLE_FORMAT]

    def add(seq, role):
        ids.extend(seq)
        roles.extend([role] * len(seq))

    for m in messages:
        if m["role"] == "user":
            add(vocab.encode("User: "), ROLE_FORMAT)
            for i, p in enumerate(m["content"].split(IMAGE)):
                if i:
                    add(img, ROLE_IMAGE)
                add(vocab.encode(p), ROLE_USER)
            add(vocab.encode("\n"), ROLE_FORMAT)
        else:
            add(vocab.encode("Assistant: "), ROLE_FORMAT)
            add(vocab.encode(m["content"]) + [vocab.stoi["<eos>"]], ROLE_ANSWER)
    return ids, roles
```

拼法和第 23 章的 `apply_chat_template` 完全一样，只是每加一段 token，同时记下这段的身份。`add` 是一个**闭包**（定义在函数里面、能修改外面的 `ids` 和 `roles` 的小函数），让"加 token"和"记身份"永远一起发生，不会漏。

测试 `test_chat_roles_matches_template` 检查：`chat_roles` 的 ids 和 `apply_chat_template` 的完全相同；用默认权重（只算回答）得到的标签也和第 23 章的完全相同。**新写的代码先和旧代码在旧功能上对齐**，再加新功能，这是改训练代码时最可靠的做法。

### `sft_targets`：从身份到标签和权重

```python
def sft_targets(ids, roles, prompt_weight=0.0, format_weight=None, eos_id=None, train_eos=True):
    fw = prompt_weight if format_weight is None else format_weight
    w_of = {ROLE_ANSWER: 1.0, ROLE_USER: prompt_weight, ROLE_FORMAT: fw, ROLE_IMAGE: 0.0}
    targets, weights = [], []
    for t in range(len(ids) - 1):
        w = w_of[roles[t + 1]]
        if not train_eos and roles[t + 1] == ROLE_ANSWER and ids[t + 1] == eos_id:
            w = 0.0
        targets.append(ids[t + 1] if w > 0 else -100)
        weights.append(w)
    return targets + [-100], weights + [0.0]
```

两个输出：`targets` 和以前一样，不计算的位置是 −100；`weights` 是每个位置的浮点权重。权重为 0 的地方同时把标签设成 −100，这样即使有人只用 `targets`、忽略 `weights`，也不会算错位置。

### 要不要在提示上算损失

"只在回答上算损失"是最常见的做法，理由很直接：我们要模型学会**回答**，而不是学会**提问**。如果连用户的话一起学，模型的一部分容量和梯度会花在"预测用户会问什么"上；在真实数据里，用户的话往往比回答长得多，这部分的梯度甚至会压过回答。

但这不是唯一的选择。本课程上一版在一个两位数加法的玩具任务上实测过：对题目也算损失（哪怕只给 0.1 的权重），模型学会加法的速度快得多。一种解释是题目里的格式字符（`+`、`=`）提供了一个容易学的辅助任务，让模型更早学会"哪个位置是哪个操作数"。这个现象在别的任务上是否成立，要实验。第 2 部分请你在 ShapesWorld 的九种任务上检验：提示权重 0、0.1、1 各跑 3 个种子。

运行前想清楚：我们的提示几乎是**固定的模板**（"How many objects?"、"What color is the leftmost object?"……），模型很快就能背下来；而加法题目里的操作数是随机的。这两种情况下，"在提示上算损失"提供的信号有什么不同？

## 26.3 损失怎样平均

### 两种平均

一个批里有若干条样本，每条有若干个计算损失的位置。设第 b 条样本的第 t 个位置的交叉熵是 ce[b, t]，权重 w[b, t]。

**按 token 平均**（token-level，PyTorch `cross_entropy` 加 `ignore_index` 的默认行为）：

```
L_token = Σ_b Σ_t w[b,t]·ce[b,t]  /  Σ_b Σ_t w[b,t]
```

所有计算损失的 token 一样重要。回答长的样本 token 多，分量就重。

**按样本平均**（sample-level）：

```
L_b      = Σ_t w[b,t]·ce[b,t]  /  Σ_t w[b,t]        每条样本先求自己的平均
L_sample = (1/B') Σ_b L_b                           再对 B' 条"有计算损失位置"的样本取平均
```

每条样本一样重要，不管回答多长。

### 手算

两条样本，词表 4 个词，模型的输出全是均匀的（每个位置的交叉熵都是 ln 4 ≈ 1.386），只有第 1 条的那个位置只在两个词之间均匀（交叉熵 ln 2 ≈ 0.693）：

| 样本 | 计算损失的位置 | 每个位置的 ce |
|---|---|---|
| 0 | 3 个 | ln 4 = 1.386 |
| 1 | 1 个 | ln 2 = 0.693 |

```
L_token  = (3 × 1.386 + 0.693) / 4 = 1.213
L_sample = (1.386 + 0.693) / 2     = 1.040
```

按 token 平均时，样本 0 占了 3/4 的分量；按样本平均时，两条各占一半。测试 `test_sft_loss_by_hand` 就是这个例子。

### 在我们的数据上差多少

第 1 部分统计了九种任务的回答长度（每种 200 条，30% 是两轮对话）：

| 任务 | 序列长度（平均） | 回答的 token（平均） | 按 token 平均时占梯度的份额 |
|---|---|---|---|
| caption | 158.3 | 42.7 | 39.0% |
| refer | 144.0 | 22.5 | 20.5% |
| ground | 139.6 | 12.6 | 11.5% |
| compare | 203.9 | 9.9 | 9.0% |
| left | 137.9 | 6.7 | 6.1% |
| text | 121.7 | 4.7 | 4.3% |
| exists | 124.8 | 4.5 | 4.1% |
| count_color | 121.2 | 3.0 | 2.7% |
| count | 114.8 | 2.9 | 2.6% |

九种任务的**样本数相同**，但按 token 平均时，描述一种任务就占了 39% 的梯度，数数只占 2.6%——相差 15 倍。按样本平均时每种都是 11.1%。

哪个好？没有通用的答案：

- 按 token 平均让长回答"学得更细"：一条 40 个 token 的描述里每个 token 都需要信号；
- 按样本平均让短回答的任务不被淹没，但长回答里的每个 token 只分到很少的权重，一条 40 个 token 的回答和一条 3 个 token 的回答总权重相同，前者每个 token 的权重是后者的 1/13。

第 5 部分请你比较两种方式下各任务的结果。也可以折中：按 token 平均，但用**任务配比**（第 23 章）补偿短回答的任务，或者按 √(回答长度) 归一化。

### 练习 26.2：`sft_loss`

```python
def sft_loss(logits, targets, weights=None, mode="token"):
    B, T, V = logits.shape
    valid = targets != -100
    ce = F.cross_entropy(logits.reshape(-1, V).float(), targets.clamp(min=0).reshape(-1), reduction="none").view(B, T)
    w = valid.float() if weights is None else weights.float() * valid
    if mode == "token":
        return (w * ce).sum() / w.sum().clamp(min=1e-8)
    per = (w * ce).sum(1) / w.sum(1).clamp(min=1e-8)
    has = w.sum(1) > 0
    return per[has].mean() if has.any() else (w * ce).sum()
```

逐行：

- `reduction="none"` 让 `cross_entropy` 返回每个位置的损失，不求平均，形状 (B·T,)，再变回 (B, T)；
- `targets.clamp(min=0)`：−100 不是合法的类别编号，直接传给 `cross_entropy`（不带 `ignore_index`）会报错。先把它换成 0 算出一个无意义的数，后面乘以权重 0 把它消掉；
- `w = weights * valid`：即使调用者给了权重，标签是 −100 的位置也强制为 0；
- `clamp(min=1e-8)`：防止除以 0。一个批里**没有任何**计算损失的位置时（比如所有回答都被截断了），返回 `(w * ce).sum()`，它是 0，但仍然连着计算图，`backward()` 不会报错，只是梯度全为 0。

### 梯度累积时的陷阱

按 token 平均有一个容易犯的错（第 18 章）：做梯度累积时，如果每个微批**各自**按 token 平均、再把几个微批的损失相加除以微批数，结果**不等于**大批的按 token 平均。设两个微批各有 10 个和 100 个计算损失的 token：

```
大批：      (Σ₁ + Σ₂) / 110
各自平均：  (Σ₁/10 + Σ₂/100) / 2
```

后者让 10 个 token 的那个微批的每个 token 权重变成了前者的 5.5 倍。正确的做法是先数出整个大批的 token 总数，每个微批用 `Σ w·ce / 总数`。2024 年 Hugging Face 的 Trainer 就修过这个问题（增加了 `num_items_in_batch` 参数）。按样本平均没有这个问题，只要每个微批的样本数相同。

## 26.4 `<eos>`：学会什么时候停

推理时，模型逐个生成 token，生成 `<eos>` 就停下（第 17 章）。如果训练时 `<eos>` 不计算损失，模型从没学过"回答到这里结束"，它会一直写下去，直到达到 `max_new` 的上限。

`sft_targets(..., train_eos=False)` 把回答末尾的 `<eos>` 的权重设成 0，其余不变。第 4 部分用它训练一个模型，再统计三个数：

- **全对**：输出和真值完全相同；
- **以正确答案开头**：输出的开头和真值相同（后面可能跟着多余的字）；
- **平均输出长度**。

运行前先预测：数数任务（真值只有 1 个字符）的"全对"和"以正确答案开头"会差多少？模型在答案后面会写什么——重复答案、开始写下一轮"User:"，还是别的？

这个问题在真实模型里一样存在。Qwen 的模板用 `<|im_end|>` 结束每一轮，如果自己处理数据时忘了把它加进回答、或者把它的标签设成了 −100，微调后的模型就会"说个不停"。第 31 章的强化学习里，"没有以 `<eos>` 结束的回答"直接得 0 分，原因也在这里：它不是一个完整的回答。

## 26.5 补齐与打包

### 补齐浪费了多少

一个批里的样本长短不一，最常见的做法是右侧补齐到最长的那条（第 22 章）。第 1 部分随机抽了 50 批（每批 32 条，九种任务混合）：

```
补齐：每批 32 行 × 最长的那条（平均 207 个位置），<pad> 占 32.4%
```

将近 1/3 的计算花在了 `<pad>` 上。原因是长度差别大：count 平均 115 个 token，compare 平均 204 个，同一个批里只要有一条 compare，其他 31 条都要补到 204 左右。

### 打包的想法

把几条短样本**首尾相接**装进一条长序列（"箱子"），每个箱子长 `max_len`（我们用 512，等于 GPT 的 `block_size`）：

```
箱子 0：[样本 0（115 个）][样本 3（160 个）][样本 7（204 个）][pad × 33]
箱子 1：[样本 1（140 个）][样本 2（122 个）][样本 4（158 个）][样本 5（ 90 个）][pad ...]
```

第 1 部分在同样的 50 批上：

```
打包：每批平均 10.6 行 × 512，<pad> 占 17.4%；总位置数是补齐的 0.82 倍
```

`<pad>` 从 32.4% 降到 17.4%，总计算量少了 18%。剩下的 17.4% 来自"箱子装不满"：平均每条样本 140 个 token，一个 512 的箱子装 3 条后通常剩下几十个位置，第 4 条放不进去。更好的装箱算法（先排序、再找最合适的空位）能装得更满，但会打乱样本的顺序；样本越短、箱子越长，浪费越少。

### 两条样本不能互相看

直接把样本拼起来交给语言模型是**错的**：因果注意力让箱子里第 2 条样本的每个位置都能看到第 1 条样本的全部内容，包括它的图像和答案。模型可能学会"抄前一条样本的答案"，推理时（只有一条样本）就不灵了。

解决办法是给注意力一个**分块的 mask**：位置 i 只能看位置 j，当且仅当

```
j ≤ i              （因果）
seg[i] = seg[j]    （属于同一条样本）
```

`seg` 是每个位置属于箱子里的第几条样本（从 1 开始，`<pad>` 为 0）。画出来是沿对角线的一串下三角块：

```
        样本 1    样本 2
       ┌───────┬──────────┐
样本 1 │ ◣     │          │
       ├───────┼──────────┤
样本 2 │       │ ◣        │
       └───────┴──────────┘
```

### 练习 26.3：`pack`

```python
def pack(examples, max_len, pad_id):
    bins, cur, used = [], [], 0
    for k, e in enumerate(examples):
        n = len(e[0])
        assert n <= max_len
        if used + n > max_len:          # 当前箱子放不下：封箱，开新箱子
            bins.append(cur)
            cur, used = [], 0
        cur.append(k)
        used += n
    if cur:
        bins.append(cur)
    ...                                  # 按 bins 把 ids、targets、weights 填进 (B, max_len) 的张量
    #   seg：箱子里第 j 条样本的位置填 j + 1；pos：每条样本内部 0, 1, 2, …
```

这是最简单的"顺序装箱"（next fit）：只看当前箱子，放不下就开新的，不回头。测试 `test_pack_and_mask` 用 4 条长 3、4、2、5 的样本、`max_len = 8` 手算：

- 第 0 条（3）放进箱子 0，已用 3；第 1 条（4）：3 + 4 = 7 ≤ 8，放进去；
- 第 2 条（2）：7 + 2 = 9 > 8，封箱，开箱子 1；
- 第 3 条（5）：2 + 5 = 7 ≤ 8，放进箱子 1。

结果 `order = [[0, 1], [2, 3]]`，每个箱子剩 1 个 `<pad>`。

注意 targets 也是直接拼接的：每条样本最后一个位置的标签本来就是 −100（`sft_targets` 在末尾补了 −100），所以"第 1 条样本的最后一个位置预测第 2 条样本的第一个 token"这种跨样本的预测**不会**计算损失。

### 练习 26.4：`packed_mask`

```python
def packed_mask(seg):
    T = seg.shape[1]
    causal = torch.ones(T, T, dtype=torch.bool, device=seg.device).tril()
    same = (seg[:, :, None] == seg[:, None, :]) & (seg[:, :, None] != 0)
    eye = torch.eye(T, dtype=torch.bool, device=seg.device)
    return ((same & causal) | eye)[:, None]
```

- `seg[:, :, None] == seg[:, None, :]`：广播成 (B, T, T)，第 [b, i, j] 个元素表示位置 i 和 j 是否属于同一条样本（第 1 章的广播）；
- `& (seg[:, :, None] != 0)`：`<pad>` 不和任何位置算"同一条"；
- `| eye`：每个位置至少能看自己。没有这一项，`<pad>` 所在的行全是 False，softmax 的分母是 0，得到 NaN，NaN 会通过后面的层传染给整个批；
- `[:, None]`：加一个"头"的维度，(B, 1, T, T) 能广播到所有注意力头。

### 用打包的 mask 跑 GPT

第 16 章的 GPT 的 `forward` 只支持标准的因果注意力。我们不改它（它是你在第 16 章写的练习），而是在 `packed_lm_forward` 里逐层重复它的计算，只换掉两处：

```python
def packed_lm_forward(lm, x, seg, pos):
    mask = packed_mask(seg)
    cos, sin = lm.cos[pos][:, None], lm.sin[pos][:, None]          # (B, 1, T, dh)
    for blk in lm.blocks:
        a = blk.attn
        h = blk.n1(x)
        B, T, d = h.shape
        q, k, v = a.qkv(h).view(B, T, 3, a.h, a.dh).permute(2, 0, 3, 1, 4)
        q, k = apply_rope(q, cos, sin), apply_rope(k, cos, sin)
        y = F.scaled_dot_product_attention(q, k, v, attn_mask=mask)
        x = x + blk.drop(a.o(y.transpose(1, 2).reshape(B, T, d)))
        x = x + blk.drop(blk.mlp(blk.n2(x)))
    return lm.head(lm.norm(x))
```

- `lm.cos[pos]`：用 (B, T) 的位置表去查 (block_size, dh) 的 RoPE 表，得到 (B, T, dh)，每个位置有自己的旋转角；
- 其余每一行都和第 16 章的 `Block.forward`、`CausalSelfAttention.forward` 一一对应。读一遍，对照着找出每一行在原来的代码里是哪一行。

图像怎么办？箱子里每条样本有自己的图（compare 有两张）。`embed_packed` 把这一批所有的图**按它们的占位符在批里出现的顺序**排好，一次编码，再用布尔下标填进去（第 22 章的老办法：布尔下标按行优先的顺序填）。只要图像的顺序和占位符的顺序一致，就不会填错，测试 `test_embed_packed_order` 检查了这一点。

### 打包是否改变了结果

第 1 部分用一个随机初始化的小 VLM（不训练），同一批 8 条样本打包和不打包各跑一次：

```
8 条样本 → 3 行；回答 token 77 个 vs 77 个；logits 最大差 2.4e-07；损失 4.600939 vs 4.600939
```

逐元素相同（差别是浮点舍入）。**打包只改变计算的组织方式，不改变数学**。然后分别去掉打包的两个要素：

```
位置不重新编号（整行 0, 1, 2, …）     logits 最大差 2.4e-07
不用分块 mask（只有因果 mask）       logits 最大差 5.2e-02
两个都去掉                      logits 最大差 5.2e-02
```

分块 mask 是必需的；但**位置不重新编号也完全没有影响**。为什么？

回忆第 16 章：RoPE 下，位置 i 的 q 和位置 j 的 k 的点积只取决于 i − j。一条样本整体平移 s 个位置（从 s 开始编号，而不是从 0 开始），样本内任意两个位置的差不变，所以注意力分数不变；有了分块 mask，样本外的位置又看不到。两者合起来，平移对结果没有任何影响。

这个结论**只对相对位置编码成立**。如果语言模型用的是可学习的绝对位置表（GPT-2 的做法），位置 300 的向量和位置 0 的不一样，不重新编号就会改变结果。另外，重新编号还有一个实际的好处：每条样本的位置都不超过它自己的长度，不会因为装进了箱子的后半段而用到训练时很少见的大位置编号。所以实践中仍然总是重新编号。

### 真实框架怎么做

- **FlashAttention 的 varlen 接口**：不构造 T × T 的 mask，而是传入每条样本的起止位置（`cu_seqlens`，cumulative sequence lengths），在内核里只算块内的注意力。第 24 章 Qwen 的视觉塔用同样的接口区分不同的图；
- **Hugging Face 的 padding-free 训练**：把一个批的样本拼成一行，传入 `position_ids`（每条样本从 0 开始），注意力实现根据 position_ids 里"回到 0"的地方切分样本；
- 预训练的语言模型（第 16 章）通常**不加**分块 mask：文字首尾相接，中间放一个 `<eos>`，让模型自己学会"`<eos>` 之后是新的文档"。SFT 的样本之间没有关系，而且很短，互相看的影响更大，一般要加。

第 6 部分请你比较补齐和打包的速度与结果。注意：在 CPU 上，带 mask 的注意力可能比 `is_causal=True` 慢（PyTorch 对纯因果的情况有专门的快速路径），打包未必更快；在 GPU 上用 varlen 接口时，打包几乎总是更快。

## 26.6 数据量与步数

### 三种"公平"的对照

比较两种训练设置时，要先说清楚"在什么条件下比"：

| 对照方式 | 固定的量 | 回答的问题 | 例子 |
|---|---|---|---|
| 相同步数 | 参数更新的次数 | 训练预算一样时，哪种设置更好 | 本章大部分实验 |
| 相同样本数 | 模型见过的样本总数 | 数据的利用效率 | 打包 vs 补齐：同样的样本，打包用的计算更少 |
| 相同计算量 | 浮点运算总数（第 18 章） | 算力一样时，哪种更划算 | 大模型 vs 小模型；高分辨率 vs 低分辨率 |

这三种对照的结论可能完全不同。比如"高分辨率比低分辨率好"在相同步数下几乎总是成立（看到的信息更多），在相同计算量下就不一定（高分辨率每一步贵得多，同样的算力只能训练更少的步）。**报告结果时，一定要写清楚是哪一种对照**。

### 数据少、步数多会怎样

第 3 部分固定训练 2000 步（批 32，共 64,000 条样本次），训练集分别有 300、3,000、30,000 条和"无限"（每一步现场生成新样本）：

| 训练集 | 每条样本平均被看几遍 |
|---|---|
| 300 条 | 约 213 遍 |
| 3,000 条 | 约 21 遍 |
| 30,000 条 | 约 2 遍 |
| 无限 | 1 遍 |

除了测试集，第 3 部分还在**训练集本身**上评测。两者的差距就是过拟合（第 10 章）的程度。运行前先预测：

- 哪个任务最先出现"训练集全对、测试集很差"？（提示：哪个任务的答案空间最大？描述有几千种可能的组合，数数只有 3 种。）

## 26.7 分辨率与视觉 token 数

这是两个经常被混为一谈的旋钮：

- **分辨率**：图像有多少像素，决定了**有多少信息**可以看；
- **视觉 token 数**：视觉塔和连接器把图像变成多少个向量交给语言模型，决定了**语言模型能看到多少份**，也决定了序列的长度和计算量。

第 24 章的 Qwen3.5 两者绑在一起（每 32×32 像素一个 token）；SmolVLM 和 LLaVA 的 token 数和分辨率无关。我们的 VLM 也能把它们拆开，第 8 部分做三组：

| 设置 | 像素 | 视觉 token | 怎么做到 |
|---|---|---|---|
| A | 64×64（原图） | 64 | MLP 连接器，第 2 部分的设置 |
| B | 32×32 的信息，放大回 64×64 | 64 | 先缩小再放大：细节丢了，token 数不变 |
| C | 64×64（原图） | 16 | 2×2 合并连接器（第 22 章）：信息还在，但被压缩进更少的 token |

运行前先预测：

- B 和 C 都"变差了一点"，但哪个任务受 B 的影响大、哪个受 C 的影响大？（提示：场景文字要看 13 号字的笔画；数数只需要知道有几个色块。定位要输出精确到像素的坐标。）
- C 的序列短了 48 个 token，训练快了多少？（看第 8 部分打印的用时，或者自己加计时。）

对 OCR 来说，这两个旋钮的取舍是第 33 章的核心问题之一：一页文档要多少像素才看得清小字，又要多少视觉 token 才能把这些字"传"给语言模型。第 24 章估算过：在刚好看得清的分辨率下，一个视觉 token 大约携带一个文字 token 的信息量。

## 26.8 种子与学习曲线

### 一条曲线不说明什么

第 25 章区分过两种不确定性：测试集的抽样、训练的随机性。后者在**学习曲线**上最明显。SFT 的曲线经常是这样的形状：

```
准确率
 100% │                    ┌──────
      │                   ╱
  50% │                  │
      │                  │
   0% │──────────────────┘
      └──────────────────────────── 步数
                        ↑
                 "突然学会"的时刻
```

一段平台（模型在"猜"答案的分布，比如数数任务总说 2），然后在某一刻快速上升。这个时刻**因种子而异**：同样的配置，有的种子 400 步起飞，有的 1200 步。

### 平均曲线会骗人

假设 5 个种子分别在第 400、600、800、1000、1200 步从 0 跳到 100%（每条都是一个台阶）。把它们逐点平均：

| 步数 | 400 | 600 | 800 | 1000 | 1200 |
|---|---|---|---|---|---|
| 平均准确率 | 20% | 40% | 60% | 80% | 100% |

平均曲线是一条**平滑的斜坡**，看起来像"模型在 400 到 1200 步之间逐渐学会"。但没有任何一个种子是这样学的：每个种子都是突然学会的。只看平均曲线，你会对训练的动力学得出完全错误的结论。

更好的描述方式：

- **达到阈值的步数**（`steps_to`）：每个种子第一次达到 50%、80% 的步数，报告它们的中位数和范围；
- **把每条曲线都画出来**，而不只画平均；
- 比较两种设置时，比较"达到阈值的步数"的分布，而不是某一步的平均准确率。在平台期附近的某一步比较，结果几乎完全取决于哪些种子恰好已经起飞了。

### `steps_to`

```python
def steps_to(curve, threshold):
    for s, v in curve:
        if v >= threshold:
            return s
    return None
```

返回 `None` 表示在训练结束前没有达到。报告时要单独说明有几个种子没达到，不能把它们当成"训练结束的步数"混进平均。

第 7 部分只训练 count_color（按颜色数数）一种任务，5 个种子，每 100 步评测一次，打印每个种子的曲线和达到 50%、80% 的步数。

5. **梯度累积**：两个微批，计算损失的 token 分别有 30 和 90 个，损失之和分别是 15 和 27。正确的大批按 token 平均是多少？"各自平均再平均"是多少？

### 选做

6. **更好的装箱**：实现 first-fit decreasing（先按长度从大到小排序，每条样本放进第一个装得下的箱子），在第 1 部分的 50 批上比较 `<pad>` 的比例。
7. **按 √长度 归一化**：在 `sft_loss` 里加一个 `mode="sqrt"`：每条样本的损失 = Σ w·ce / √(Σ w)，再对样本求平均。它介于两种平均之间。用第 5 部分的设置比较三种方式。
8. **不加 mask 的打包**：把 `packed_lm_forward` 里的 mask 换成纯因果的，训练一个模型。它在测试集上（每次只有一条样本）变差了吗？用第 27 章的方法检查：箱子里第 2 条样本的答案，对第 1 条样本的图像的注意力有多大？
9. **位置编号的验证**：在第 1 部分的检查里，把语言模型换成一个用可学习绝对位置表的版本（在嵌入后加一个 `nn.Embedding(block_size, d)`），确认"位置不重新编号"这时会改变结果。

## 26.11 常见错误

| 现象 | 原因 | 怎么查 |
|---|---|---|
| 模型复述用户的问题，或者回答前先写一遍问题 | 用户的话也计算了损失（权重 1） | 打印每个位置的 (输入, 标签, 权重)，看用户部分是否为 0 |
| 回答对了，但后面跟着一串多余的字 | `<eos>` 没有计算损失 | 检查回答末尾 `<eos>` 的标签；统计"以正确答案开头"的比例 |
| 短回答的任务学不会，长回答的任务很好 | 按 token 平均时，短回答的梯度份额太小 | 算每个任务的梯度份额（第 1 部分）；改用按样本平均或调配比 |
| 改了微批大小，结果就变了 | 梯度累积时按微批各自求平均 | 用整个大批的 token 总数归一化 |
| 打包后训练损失很低，测试很差 | 没有分块 mask，样本之间互相"偷看" | 检查打包与不打包的 logits 是否一致（第 1 部分） |
| 打包后出现 NaN | mask 里有整行都是 False 的位置（`<pad>`） | 每个位置至少能看自己 |
| 打包后视觉相关的任务全错 | 图像的顺序和占位符的顺序不一致 | 用"每张图是不同常数"的输入检查（`test_embed_packed_order`） |
| 两次实验的结论相反 | 只跑了一个种子，差别在噪声以内 | 至少 3 个种子；报告标准差或达到阈值步数的范围 |
| 训练集全对，测试集很差 | 数据太少，看了太多遍 | 在训练集和测试集上同时评测；减少步数或增加数据 |

## 26.12 真实世界对照

- **只在回答上算损失**：LLaVA、Qwen-VL 系列的 SFT 默认如此；LLaMA-Factory 的 `train_on_prompt`、TRL 的 `completion_only_loss`（旧版用 `DataCollatorForCompletionOnlyLM`）是对应的开关。多轮对话里每一轮的回答都算损失；有的框架提供"只训练最后一轮"的选项；
- **视觉占位符的标签**：真实实现里 `<|image_pad|>` 的标签都设成 −100（Qwen2-VL 的训练脚本、LLaVA 的 `IGNORE_INDEX`）；
- **打包**：TRL 的 `SFTConfig(packing=True)`；padding-free 训练用 `position_ids` 和 FlashAttention 的 varlen 接口；LLaMA-Factory 的 `neat_packing` 是带分块 mask 的打包。不同版本的默认行为不同，用之前要看文档确认是否隔离了样本；
- **典型超参数**（公开报告）：LLaVA-1.5 的预训练（只训连接器）学习率 1e-3、批 256；指令微调学习率 2e-5、批 128、1 个 epoch。全参微调的学习率通常比预训练小一到两个数量级；
- **梯度累积的归一化**：2024 年 Hugging Face Transformers 修复了梯度累积时按微批平均导致的损失偏差（`num_items_in_batch`）；
- **多种子**：大模型的 SFT 很少报告多个种子（太贵），但 SFT 结果对数据顺序、学习率的敏感性有大量讨论。小规模实验里多种子几乎没有成本，没有理由不做。

## 26.13 深入一步

### 两种平均是两种样本权重

按 token 平均可以改写成按样本加权平均。设第 b 条样本有 n_b 个计算损失的 token（权重都是 1），它自己的平均损失是 L_b：

```
L_token = Σ_b Σ_t ce[b,t] / Σ_b n_b = Σ_b n_b·L_b / Σ_b n_b
```

即**每条样本的权重 ∝ n_b**。按样本平均是每条样本权重相同。`mode="sqrt"`（选做题 7）是权重 ∝ √n_b。所以"怎样平均"的问题等价于"长回答的样本该有多大的权重"，这和第 23 章的"任务配比"是同一个问题的两种说法：配比调整的是每种任务的**样本数**，平均方式调整的是每条样本的**权重**，两者相乘才是每种任务的实际梯度份额。

### 为什么"在提示上算损失"可能有帮助

把提示的权重设成 w，总损失是 L_answer + w·L_prompt。L_prompt 是一个**辅助任务**：预测用户会说什么。辅助任务有帮助的条件是：它和主任务共享有用的表示，而且容易学、能提供稳定的梯度。我们的提示是固定的模板，L_prompt 很快就降到接近 0，之后几乎不再提供梯度——这时 w 的大小基本不影响后期的训练。在提示内容多变（比如用户的问题里包含要读的文字、要回答的数字）时，L_prompt 一直有信号，影响才会持续。

反过来，在提示上算损失的风险是：模型学会了"生成提示"的分布，推理时可能在回答后继续写一个新问题。`<eos>` 的训练能防止大部分这种情况。

### 打包和 batch 大小

打包后，一个"批"里的样本数不再固定：同样 32 行，补齐时是 32 条样本，打包时可能是 100 条。所以打包时通常改用"每批的 token 数"来描述批的大小。如果按 token 平均损失，每一步的梯度对应的 token 数大致恒定；如果按样本平均，打包后每步的有效样本数变多了，学习率可能需要相应调整。我们的第 6 部分保持"每步 32 条样本"不变，只是把它们装进更少的行，所以两种方式每一步的数学完全相同，只有计算方式不同。

## 26.14 横向对照

| 决定 | 选项 | 优点 | 缺点 | 常见于 |
|---|---|---|---|---|
| 在哪里算损失 | 只算回答 | 目标清楚，梯度都给回答 | 提示里的信号浪费了 | 绝大多数 VLM 的 SFT |
| | 提示加小权重 | 可能加速早期训练 | 多一个超参数；可能学会生成提示 | 部分 LLM 的 SFT 研究 |
| 怎样平均 | 按 token | 简单，长回答学得细 | 短回答的任务被淹没；梯度累积要小心 | PyTorch、Hugging Face 的默认 |
| | 按样本 | 每条样本一样重要 | 长回答的每个 token 权重小 | 部分框架的选项 |
| 怎样组批 | 补齐 | 简单，不需要 mask | 浪费计算（我们的数据上 32%） | 小规模实验 |
| | 打包 + 分块 mask | 浪费少 | 需要 mask 或 varlen 内核 | 大规模 SFT |
| | 打包、不加 mask | 最简单 | 样本互相看 | 语言模型预训练 |

## 26.15 本章小结

- SFT 和预训练用同一个交叉熵、同一个训练循环，区别在于数据是成对的问答、损失只算在一部分位置、样本有边界；
- 每个 token 有身份（格式、视觉、用户、回答）；位置 t 的权重由 ids[t + 1] 的身份决定；视觉占位符永远不算损失；
- 按 token 平均时样本的权重 ∝ 回答长度；在我们的九种任务上，描述占 39% 的梯度、数数占 2.6%；按样本平均时都是 11.1%；梯度累积时要用整个大批的 token 数归一化；
- 必须学 `<eos>`，否则模型不知道在哪里停；
- 补齐在我们的数据上浪费 32.4% 的位置；打包把它降到 17.4%；打包必须用分块 mask，样本内位置的重新编号在 RoPE 下不影响结果，但对绝对位置编码是必需的；
- 比较训练设置时说清楚是相同步数、相同样本数还是相同计算量；
- 学习曲线常常是"平台 + 突然上升"，起飞时刻因种子而异；平均曲线会把台阶抹成斜坡，用"达到阈值的步数"描述训练的快慢。

## 参考答案

1. 语言模型在位置 t 输出的是对 ids[t + 1] 的预测。"这个位置要不要学"取决于它要预测的 token 是不是我们希望模型生成的东西，也就是 ids[t + 1] 的身份。
2. 占位符是我们放进序列的，推理时也由我们放，不需要模型生成；而且它的嵌入已经被换成了视觉 token，"预测占位符"没有意义。
3. 按 token 平均：回答长的样本（每条样本的权重 ∝ 回答的 token 数）；按样本平均：回答短的样本相对变重（每条一样）。
4. 各自平均时每个微批的权重相同，与它有多少 token 无关，token 少的微批里每个 token 的权重被放大。按样本平均时，只要每个微批的样本数相同，"各自平均再平均"就等于整批的按样本平均。
5. 全对接近 0（输出后面总有多余的字），以正确答案开头的比例接近正常模型的全对率。
6. 没有分块 mask，后面的样本能看到前面样本的图像和答案，模型可能学会抄；推理时只有一条样本，抄不到。`<pad>` 位置如果一个都不能看，softmax 的分母是 0，产生 NaN 并传染给整个计算。
7. RoPE 的注意力分数只取决于位置差；样本整体平移，样本内的位置差不变，分块 mask 又挡住了样本外的位置。可学习的绝对位置表（或正弦绝对位置编码直接加在输入上）下，不同的位置有不同的向量，平移会改变结果。
8. 相同步数：训练预算（更新次数）一样时谁更好；相同计算量：花同样的算力谁更好。例：高分辨率每一步贵 4 倍，相同步数下它更好，相同计算量下它只能训练 1/4 的步数，可能更差。
9. 每个种子可能在不同的时刻突然学会，逐点平均把台阶抹成斜坡，看起来像"逐渐学会"。应该报告每个种子达到阈值的步数（中位数、范围），并画出每条曲线。
10. 按 token：51 / 60 = 85%；按样本：1/4 = 25%。
11. 每个箱子装 2 条（400），第 3 条放不下，所以要 3 个箱子：[200, 200]、[200, 200]、[200]。总位置 3 × 512 = 1536，有效 1000，`<pad>` 占 536 / 1536 = 34.9%。补齐：5 × 200 = 1000 个位置，没有 `<pad>`（所有样本一样长）。长度相同的样本打包反而更浪费。
12. 4 个种子达到了：300、500、500、900 步（中位数 500）；1 个种子在 1500 步内没有达到。不能把第 5 个种子当成 1500 或 2000 步混进平均。
13. 三个问题：没有分块 mask（样本互相看）；位置没有分开（对 RoPE 没关系，对绝对位置编码有问题）；`[:max_len]` 会把最后一条样本截断一半，它的答案可能被切掉；而且 targets 的处理也没有（跨样本边界的预测会被当成正常位置计算损失）。
14. 每个微批各自按 token 平均，再按微批数平均，不等于整个大批的按 token 平均（26.3 节）。正确做法：先数出所有微批计算损失的 token 总数 N，每个微批的损失用 Σ w·ce / N，再相加。
