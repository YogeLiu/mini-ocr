# 第 13 章　文字行识别：CNN + RNN + CTC

## 本章在全景图中的位置

第 10、12 章我们识别的是**单个字符**：一张 32 × 32 的图，里面恰好一个字符，输出 62 类之一。真实的 OCR 面对的是**一整行文字**：一张 32 × 256 的图，里面有十几个字符，挤在一起，宽窄不一。

最直接的想法是"先切开，再识别"：找出每个字符的位置，切成单字图，用第 12 章的 CNN 分别识别。早期的 OCR 确实这样做，但它非常脆弱：字符粘连（`rn` 看起来像 `m`）、断裂、倾斜时，切分就会出错，而切错了后面的识别再好也没用。

本章学习的方法完全不切分：

1. 一个 CNN 把整行图像变成从左到右的一串"列特征"；
2. 一个 RNN（循环神经网络）沿着这串特征看上下文；
3. 一个叫 **CTC** 的损失函数，在**不知道每个字符在哪一列**的情况下训练整个模型。

这套结构叫 **CRNN**（2015 年），直到今天仍是很多实用 OCR 系统的识别器（PaddleOCR、Tesseract 4 及以后）。它是"经典 OCR"的顶点。学完本章你会看到它的能力，也会看到它的根本限制——这些限制正是后来改用 VLM 逐 token 生成的原因（第 15、22 章）。

## 学习目标

1. 说清序列识别的核心困难：输入和输出的对齐未知；
2. 理解 CTC 的"路径"和"折叠"，说清空白符号的两个作用；
3. 手算一个小例子的 CTC 概率，并用前向算法（动态规划）在对数空间里实现它，与 PyTorch 对拍；
4. 实现贪心解码和前缀束搜索，知道贪心为什么不总是最优；
5. 写出最简单的循环神经网络，理解 LSTM 的门和双向 RNN；
6. 搭建 CRNN，理解每一层的形状；
7. 实现编辑距离和字符错误率（CER）；
8. 训练一个文字行识别器，读懂它的错误、它学到的对齐，以及 CTC 的限制。

## 13.1 问题：对齐未知

### 一行文字

演示第 1 部分（`python -m labs.ch13.ctc_tour 1`）渲染了一行文字：

```
  文字 'Will 1100 mil fill it'（存到 outputs/ch13/line_example.png）
  每个字符的墨迹框（x0, x1）和宽度：
   W:86-104  i:104-108  l:108-113  l:113-118  1:122-133  1:133-144  0:144-155  0:155-166  m:170-186  ...
  19 号字的前进宽度（像素）：i 4.0  l 5.0  m 16.0  1 11.0  W 18.0  . 4.0  0 11.0
  CRNN 每 4 个像素输出一个时间步：图宽 256 → T = 64 步；这一行有 21 个字符。哪几步对应哪个字符？——训练数据里没有这个信息
```

几个事实：

- **宽度不固定**：`m` 宽 16 像素，`i` 只有 4 像素，相差 4 倍。不能把图等分成 21 份；
- **位置不固定**：这一行从 x = 86 开始，另一行可能从 x = 5 开始；
- **训练标签只有文字**：我们知道这张图写的是 "Will 1100 mil fill it"，但不知道 `W` 占第几列到第几列。手工标注每个字符的位置非常昂贵，真实数据集几乎都只有文字标签。

### 模型输出一串分布

CRNN 的 CNN 部分把 32 × 256 的图变成 64 个"列"，每列对应原图宽 4 像素的一条（感受野更宽，见 13.7 节）。对每一列，模型输出一个 K 类的概率分布（K = 字符数 + 1，多出的一类见下文）。

于是问题变成：模型输出 64 个分布，标签是 21 个字符。**怎样计算损失？**

如果知道"第 22–26 列是 W，第 27 列是 i……"，就可以对每一列做第 6 章的交叉熵。但我们不知道。**CTC**（Connectionist Temporal Classification，2006 年）的回答是：**把所有可能的对齐方式都考虑进去，把它们的概率加起来**。

## 13.2 CTC：路径与折叠

### 路径

一条**路径**是给每个时间步选一个类别，得到长度为 T 的序列。比如 T = 6 时，`hheell` 是一条路径。路径的概率是各步概率的乘积（假设各步独立，给定图像）：

```
p(路径) = p_1(h) · p_2(h) · p_3(e) · p_4(e) · p_5(l) · p_6(l)
```

### 折叠

路径怎样变成文字？规则叫**折叠**（collapse）：

1. 合并相邻的重复字符：`hheell` → `hel`；
2. 删掉空白。

问题来了：`hello` 有两个 `l`，合并重复会把它们合成一个。所以 CTC 引入一个特殊的**空白**符号（blank，写作 ε 或 `-`），规则改为：

1. **先**合并相邻的重复；
2. **再**删掉空白。

`hhe-l-lo` → 合并 → `he-l-lo` → 删空白 → `hello`。两个 `l` 之间隔着一个空白，合并时不会被合在一起。

几个例子（ε 是空白）：

| 路径 | 合并重复 | 删空白 | 结果 |
|---|---|---|---|
| `aaεbb` | `aεb` | `ab` | ab |
| `aεab` | `aεab` | `aab` | aab |
| `εεεa` | `εa` | `a` | a |
| `aaaa` | `a` | `a` | a |
| `εεεε` | `ε` | | （空） |

**空白的两个作用**：

1. **分隔重复字符**：要输出 `ll`，路径里两个 `l` 之间必须有空白；
2. **填充**：64 步要输出 21 个字符，多出来的时间步可以填空白。字符之间的空隙、字符和字符的过渡区域，都可以输出空白。

### 练习 13.1：折叠

```python
def collapse(path, blank=0):
    out, prev = [], None
    for p in path:
        if p != prev and p != blank:
            out.append(p)
        prev = p
    return out
```

一次扫描同时完成两步：当前符号和前一个**不同**（不是重复）且**不是空白**时才输出。注意 `prev = p` 在每一步都执行，包括空白：所以 `[1, 0, 1]` 中第二个 1 的 prev 是 0，不等于 1，会被输出。

### CTC 损失

一个文字 y 的概率是**所有折叠后等于 y 的路径**的概率之和：

```
p(y | x) = Σ_{路径 π: collapse(π) = y} Π_t p_t(π_t)
```

CTC 损失 = −log p(y | x)。最小化它，就是让"所有能产生正确答案的路径"的总概率尽量大。模型不需要知道哪条路径是"对的"，只要正确答案的总概率高就行。

## 13.3 手算 CTC

T = 3 步，类别 {ε, a, b}，标签 "ab"。每步的概率：

```
        ε     a     b
t=0:  0.5   0.4   0.1
t=1:  0.3   0.3   0.4
t=2:  0.6   0.1   0.3
```

3 步、3 类，共 3³ = 27 条路径。哪些折叠后是 "ab"？

- 必须有 a 在 b 前面，a 和 b 之间不能有别的字符；
- 每个位置是 ε、a 或 b。

逐一检查，共 5 条：

```
    路径 εab  概率 0.5 × 0.3 × 0.3 = 0.0450
    路径 aεb  概率 0.4 × 0.3 × 0.3 = 0.0360
    路径 aab  概率 0.4 × 0.3 × 0.3 = 0.0360
    路径 abε  概率 0.4 × 0.4 × 0.6 = 0.0960
    路径 abb  概率 0.4 × 0.4 × 0.3 = 0.0480
  共 5 条路径（27 条中）折叠后是 "ab"，总概率 0.2610，CTC 损失 −ln 0.2610 = 1.3432
  前向算法：1.3432   F.ctc_loss：1.3432
```

（第 2 部分的输出。）`ctc_brute_force` 就是这样枚举的，只能用于很小的例子：T = 64、K = 73 时路径数是 73⁶⁴ ≈ 10¹¹⁹。

**标签 "aa"**：

```
  标签 "aa"：只有 1 条路径（aεa），概率 0.0120——两个 a 之间必须隔一个空白
```

`aaa`、`aaε`、`εaa` 都折叠成 "a"。3 步里要输出两个 a，唯一的办法是 `aεa`：0.4 × 0.3 × 0.1 = 0.012。这说明**相邻的相同字符需要额外的时间步**：输出 U 个字符至少需要 U + (相邻重复的对数) 步。

## 13.4 前向算法

### 思路

枚举所有路径不可行，但很多路径共享前缀。比如 abε 和 abb 的前两步都是 `ab`，枚举时 0.4 × 0.4 被算了两遍；T 更长时，同一个前缀会被成千上万条路径重复计算。**动态规划**（dynamic programming）的做法是：把"前 t 步走到某个状态"的所有路径的概率先加起来存好（这是一个小问题的答案），算第 t + 1 步时直接用它，而不再回头展开每一条路径。

**扩展标签**：在标签的每个字符前后插入空白。"ab" → l' = [ε, a, ε, b, ε]，长度 S = 2U + 1 = 5。任何一条合法路径，都是在 l' 上从左往右"走"：每一步要么停在原地，要么前进一格，在某些条件下可以跳过一格。

**状态**：α[t][s] = 前 t+1 个时间步、恰好走到 l' 第 s 个位置的所有路径的概率之和。

**转移**：在时间 t 处于位置 s，时间 t−1 可能在哪里？

1. 同一个位置 s（停留：重复同一个符号）；
2. 位置 s − 1（前进一格）；
3. 位置 s − 2（跳过中间的空白）——只有当 l'[s] 不是空白、并且 l'[s] ≠ l'[s−2] 时才允许。

第 3 条的两个条件：

- l'[s] 是空白时不能跳：从字符跳到下一个空白没有意义，跳过的是字符而不是空白；
- l'[s] = l'[s−2] 时不能跳：比如 "aa" 的 l' = [ε, a, ε, a, ε]，从第一个 a（s = 1）跳到第二个 a（s = 3），中间没有空白，路径会变成 `aa`，折叠后只有一个 a。这正是 13.3 节"aa 需要空白隔开"的规则。

**递推**：

```
α[t][s] = (α[t−1][s] + α[t−1][s−1] + [允许时] α[t−1][s−2]) · p_t(l'[s])
```

**初始**：路径可以以空白或第一个字符开始：α[0][0] = p_0(ε)，α[0][1] = p_0(y₁)，其余为 0。

**结果**：路径可以以最后一个字符或最后的空白结束：p(y) = α[T−1][S−1] + α[T−1][S−2]。

### 手算 α 表

l' = [ε, a, ε, b, ε]，用 13.3 节的概率：

**t = 0**：α = [0.5, 0.4, 0, 0, 0]。

**t = 1**（概率 ε 0.3、a 0.3、b 0.4）：

| s | l'[s] | 来源 | α[1][s] |
|---|---|---|---|
| 0 | ε | α[0][0] = 0.5 | 0.5 × 0.3 = 0.15 |
| 1 | a | α[0][1] + α[0][0] = 0.9 | 0.9 × 0.3 = 0.27 |
| 2 | ε | α[0][2] + α[0][1] = 0.4 | 0.4 × 0.3 = 0.12 |
| 3 | b | α[0][3] + α[0][2] + α[0][1]（b ≠ a，可以跳）= 0.4 | 0.4 × 0.4 = 0.16 |
| 4 | ε | α[0][4] + α[0][3] = 0 | 0 |

**t = 2**（概率 ε 0.6、a 0.1、b 0.3），只需要最后两个位置：

- s = 3（b）：α[1][3] + α[1][2] + α[1][1] = 0.16 + 0.12 + 0.27 = 0.55，× 0.3 = 0.165；
- s = 4（ε）：α[1][4] + α[1][3] = 0 + 0.16 = 0.16，× 0.6 = 0.096。

p("ab") = 0.165 + 0.096 = **0.261**，与枚举的结果一致。

验证一下 0.165 的含义：以 b 结尾的路径 εab（0.045）+ aεb（0.036）+ aab（0.036）+ abb（0.048）= 0.165。✓

**复杂度**：每个时间步更新 S 个状态，每个状态最多 3 个来源，总共 O(T · S)。T = 64、S = 2 × 28 + 1 = 57 时只有约 11000 次运算，而枚举要 10¹¹⁹ 次。

### 练习 13.2：在对数空间里实现

真实的 T 很大，概率连乘会下溢（第 6 章）。所以在对数空间里计算：乘法变加法，加法变 logsumexp。

```python
def ctc_forward(log_probs, target, blank=0):
    T = len(log_probs)
    ext = [blank]
    for y in target:
        ext += [y, blank]
    S = len(ext)
    NEG = -math.inf
    alpha = [NEG] * S
    alpha[0] = float(log_probs[0][blank])
    if S > 1:
        alpha[1] = float(log_probs[0][ext[1]])
    for t in range(1, T):
        new = [NEG] * S
        for s in range(S):
            cands = [alpha[s]]
            if s >= 1:
                cands.append(alpha[s - 1])
            if s >= 2 and ext[s] != blank and ext[s] != ext[s - 2]:
                cands.append(alpha[s - 2])
            new[s] = _logsumexp(*cands) + float(log_probs[t][ext[s]])
        alpha = new
    ll = _logsumexp(alpha[S - 1], alpha[S - 2]) if S > 1 else alpha[0]
    return -ll
```

- 概率 0 对应 log 0 = −∞，用 `-math.inf` 表示。`_logsumexp` 在所有输入都是 −∞ 时返回 −∞（避免 −∞ − (−∞) = nan）；
- 只保留上一个时间步的 α（一维数组），内存 O(S)；
- 空标签（target = []）时 S = 1，只能全是空白；
- T 不够长时，最后两个位置的 α 都是 −∞，返回 +∞（第 6 部分会看到）。

测试 `test_ctc_forward_matches_brute_force_and_torch` 在 4 组随机的小例子上，与枚举和 `F.ctc_loss` 都一致（相对误差 < 10⁻⁶）。

### 梯度

训练需要 ∂损失/∂log_probs。CTC 的梯度可以用类似的**后向**递推（β，从右往左）配合 α 求出：时间 t 输出符号 k 的"后验概率"是所有经过 (t, k) 的路径的概率之和除以总概率，梯度就是 softmax 的输出减去这个后验（和第 6 章交叉熵的梯度"p − y"形式相同，只是 y 换成了软的后验）。PyTorch 的 `F.ctc_loss` 已经实现了前向和后向，我们直接用它训练；手写的 `ctc_forward` 用来理解和对拍。

## 13.5 解码

训练好之后，给一张图，模型输出 T 个分布。怎样得到文字？

### 练习 13.3：贪心解码

每一步取概率最大的类别，得到一条路径，再折叠：

```python
def greedy_decode(log_probs, blank=0):
    return collapse(list(np.asarray(log_probs).argmax(-1)), blank)
```

13.3 节的例子：每步最大的是 ε(0.5)、b(0.4)、ε(0.6)，路径 `εbε` → "b"，这条路径的概率是 0.5 × 0.4 × 0.6 = 0.12。但文字 "b" 的概率是所有折叠成 "b" 的路径之和：εbε、bbε、εbb、bbb、εεb、bεε，加起来 0.279。把 27 条路径全部按折叠结果加起来，前三名是：

```
"b"   0.279
"a"   0.276
"ab"  0.261
```

这个例子里贪心碰巧选中了最可能的文字，但只领先 "a" 0.003。重点是：**贪心找的是最可能的一条路径，不是最可能的文字**。两者可以不同，下面就是一个例子。

### 贪心不等于最优

一个更清楚的例子（第 2 部分的最后一行）：两步，类别 {ε, a}，每步 p(ε) = 0.6、p(a) = 0.4。

- 贪心：每步都选 ε，路径 εε → 空字符串，概率 0.6 × 0.6 = 0.36；
- 文字 "a"：路径 aε（0.24）、εa（0.24）、aa（0.16），总和 **0.64**。

"a" 的概率是空字符串的近两倍，但它被分散在三条路径上，每条都不如 εε。

### 前缀束搜索

要找最可能的**文字**，需要把折叠成同一个文字的路径合并。**前缀束搜索**（prefix beam search）在每个时间步维护最多 beam 个"前缀"（已经折叠好的部分输出），以及每个前缀的两个概率：

- p_b：以空白结尾的路径的总概率；
- p_nb：以非空白结尾的路径的总概率。

为什么要分开记？因为下一个符号如果和前缀的最后一个字符相同，结果取决于路径以什么结尾：

- 以非空白结尾（比如路径是 `…a`），再来一个 a → 合并，前缀不变；
- 以空白结尾（`…aε`），再来一个 a → 新的 a，前缀多一个字符。

### 练习 13.4

```python
for prefix, (pb, pnb) in beams.items():
    total = _logsumexp(pb, pnb)
    for k in range(K):
        p = lp[t, k]
        if k == blank:
            add(prefix, b=total + p)                  # 加空白：前缀不变，现在以空白结尾
        elif prefix and k == prefix[-1]:
            add(prefix, nb=pnb + p)                   # 重复且前面是非空白：合并
            add(prefix + (k,), nb=pb + p)             # 重复但前面是空白：新字符
        else:
            add(prefix + (k,), nb=total + p)          # 新的字符
beams = dict(sorted(nxt.items(), key=lambda kv: -_logsumexp(*kv[1]))[:beam])
```

`add` 把概率累加（logsumexp）到下一步的表 `nxt` 里：不同的旧前缀可能产生同一个新前缀，它们的概率要相加——这就是"合并路径"。最后按 p_b + p_nb 保留最好的 beam 个。

用上面两步的例子手算（beam 足够大）：

- t = 0：空前缀 () 的 p_b = 1。加 ε → () 的 p_b = 0.6；加 a → (a) 的 p_nb = 0.4；
- t = 1：
  - 从 ()（p_b 0.6）：加 ε → () p_b += 0.36；加 a → (a) p_nb += 0.24；
  - 从 (a)（p_nb 0.4）：加 ε → (a) p_b += 0.24；加 a（重复，前面非空白）→ (a) p_nb += 0.16；
- 结果：() = 0.36，(a) = 0.24 + 0.24 + 0.16 = **0.64**。束搜索给出 "a"，与输出一致。

测试 `test_greedy_and_beam` 检查了这个例子。

在 CTC 里，束搜索还有一个重要用途：可以在每次前缀增加字符时乘上一个**语言模型**的概率（比如第 14 章的 n 元模型），让"bOok"这种不像单词的结果被压低。这叫**浅融合**（shallow fusion），是 CTC 系统弥补"各步独立"缺陷的常用方法。

## 13.6 循环神经网络

### 为什么需要上下文

CNN 每一列的感受野是有限的。识别一个模糊的字符时，看看左右的字符往往很有帮助：`0` 和 `O` 形状几乎一样，但在 "1100" 里是数字，在 "BOOK" 里是字母；小写 `o` 和大写 `O` 只差大小，要和同一行的其他字符比较才知道。

**循环神经网络**（RNN）沿着序列逐步处理，用一个"状态"向量记住看过的内容。

### Elman RNN

最简单的 RNN：

```
h_t = tanh(x_t W_ihᵀ + b_ih + h_{t−1} W_hhᵀ + b_hh)
```

- x_t：第 t 步的输入（CNN 的第 t 列特征）；
- h_{t−1}：上一步的状态；
- 新状态 h_t 由当前输入和上一步状态共同决定；所有时间步共用同一组 W（又是权重共享）。

### 练习 13.6

```python
def forward(self, x, h0=None):
    h = x.new_zeros(x.shape[1], self.d_h) if h0 is None else h0
    outs = []
    for t in range(x.shape[0]):
        h = torch.tanh(x[t] @ self.weight_ih_l0.T + self.bias_ih_l0 + h @ self.weight_hh_l0.T + self.bias_hh_l0)
        outs.append(h)
    return torch.stack(outs), h
```

参数名和 `nn.RNN` 相同，所以可以把 `nn.RNN` 的权重直接加载进来对拍（测试 `test_my_rnn_matches_torch`）。`x.new_zeros` 创建一个与 x 同设备、同类型的全零张量。

### 梯度消失与 LSTM

h_t 对 h_{t−k} 的导数是 k 个雅可比矩阵的乘积，每个都包含 W_hh 和 tanh 的导数（≤ 1）。k 大时，这个乘积要么趋于 0（梯度消失），要么爆炸（第 11 章）。所以 Elman RNN 很难学到超过十几步的依赖。

**LSTM**（长短期记忆，1997 年）引入一个额外的"细胞状态" c_t 和三个**门**：

```
f_t = σ(x_t W_f + h_{t−1} U_f + b_f)        遗忘门：保留多少旧记忆
i_t = σ(x_t W_i + h_{t−1} U_i + b_i)        输入门：写入多少新内容
o_t = σ(x_t W_o + h_{t−1} U_o + b_o)        输出门：输出多少
g_t = tanh(x_t W_g + h_{t−1} U_g + b_g)     候选的新内容
c_t = f_t ⊙ c_{t−1} + i_t ⊙ g_t
h_t = o_t ⊙ tanh(c_t)
```

关键是 c_t = f_t ⊙ c_{t−1} + …：这是一个**加法**更新（和第 11 章的残差连接是同一个思想）。只要遗忘门 f_t ≈ 1，信息和梯度就能沿着 c 几乎无损地传很多步。σ 是 sigmoid，输出在 (0, 1) 之间，表示"开多少"。

LSTM 的参数是 Elman RNN 的 4 倍（4 组 W、U、b）。PyTorch 的 `nn.LSTM` 已经高度优化，我们直接使用。

### 双向

识别第 t 个字符时，右边的字符和左边的一样有用。**双向 RNN** 用两个 RNN：一个从左到右，一个从右到左，把两者在每一步的状态拼起来。CRNN 用 2 层双向 LSTM，每个方向 128 维，输出 256 维。

## 13.7 CRNN

### 结构

```python
self.cnn = nn.Sequential(conv_block(1, 32), nn.MaxPool2d(2),          # (32, 16, W/2)
                         conv_block(32, 64), nn.MaxPool2d(2),         # (64, 8, W/4)
                         conv_block(64, 128), nn.MaxPool2d((2, 1)),   # (128, 4, W/4)
                         conv_block(128, c))                          # (c, 4, W/4)
self.rnn = nn.LSTM(c, hidden, num_layers=2, bidirectional=True)
self.head = nn.Linear(2 * hidden, n_classes)

def forward(self, x):
    f = self.cnn(x).mean(dim=2)                  # (B, c, T)
    f = f.permute(2, 0, 1)                       # (T, B, c)
    if self.rnn is not None:
        f, _ = self.rnn(f)
    return F.log_softmax(self.head(f), dim=-1)
```

形状逐层追踪（输入 (B, 1, 32, 256)）：

| 层 | 输出形状 | 说明 |
|---|---|---|
| conv_block(1, 32) | (B, 32, 32, 256) | 3 × 3 卷积 + BN + ReLU（第 12 章），尺寸不变 |
| MaxPool2d(2) | (B, 32, 16, 128) | 高、宽减半 |
| conv_block(32, 64) | (B, 64, 16, 128) | |
| MaxPool2d(2) | (B, 64, 8, 64) | 宽度到 W/4 = 64 |
| conv_block(64, 128) | (B, 128, 8, 64) | |
| MaxPool2d((2, 1)) | (B, 128, 4, 64) | **只缩高度**，保持宽度方向的分辨率 |
| conv_block(128, 128) | (B, 128, 4, 64) | |
| mean(dim=2) | (B, 128, 64) | 对剩下的 4 行求平均，高度压成 1 |
| permute(2, 0, 1) | (64, B, 128) | 时间维在前：`nn.LSTM` 和 `F.ctc_loss` 的默认约定 |
| LSTM（双向） | (64, B, 256) | |
| Linear + log_softmax | (64, B, 73) | 每步 73 类的对数概率 |

几点设计：

- **为什么宽度只缩 4 倍**：T = 64 步要容纳最多约 30 个字符，加上重复字符之间的空白。缩 8 倍只剩 32 步，长行和有重复字母的行就放不下了（第 6 部分）；
- **为什么高度压成 1**：文字行是一维的序列，高度方向的信息（字符的形状）被卷积提取到通道里；
- **感受野**：按第 12 章的递推，最后一层每个位置的感受野是 26 像素宽（水平方向：3 → 4 → 8 → 10 → 18 → 18 → 26），覆盖 2–3 个字符。所以即使不用 RNN，每列也能看到一点上下文；
- **73 类**：`LINE_CHARSET` 的 72 个字符（大小写字母、数字、空格和 `.,:-'%$()`）加上空白（编号 0）。

参数 918,825 个，其中 LSTM 659,456 个（两层双向，每个方向 4 组门）。去掉 LSTM（`rnn="none"`）只剩 250,025 个。

### 批处理

```python
class CTCCollate:
    def __call__(self, batch):
        xs = torch.stack([b[0] for b in batch])
        texts = [b[1] for b in batch]
        ids = [self.vocab.encode(t) for t in texts]
        targets = torch.tensor([i for seq in ids for i in seq], dtype=torch.long)
        lengths = torch.tensor([len(seq) for seq in ids], dtype=torch.long)
        return xs, targets, lengths, texts
```

一批里的文字长短不一。`F.ctc_loss` 接受一种紧凑的格式：所有标签**首尾相接**成一个一维张量，另给一个长度张量。这样不需要补齐。

```python
def ctc_batch_loss(log_probs, targets, lengths):
    T, B, _ = log_probs.shape
    input_lengths = torch.full((B,), T, dtype=torch.long)
    return F.ctc_loss(log_probs, targets, input_lengths, lengths, blank=0, reduction="mean", zero_infinity=True)
```

- `input_lengths`：每个样本的时间步数，这里都是 64；
- `reduction="mean"`：先把每个样本的损失除以**它的标签长度**，再对批求平均。所以损失的单位是"每个字符的 nat"，长行和短行的权重相当；
- `zero_infinity=True`：如果某个样本的 T 不够长（不可能产生这个标签），损失是 +∞，梯度会变成 nan 污染整个模型。这个选项把这种样本的损失和梯度置 0。我们的数据生成保证了文字放得下，但这是一个好的安全措施。

## 13.8 评测：编辑距离与 CER

### 编辑距离

预测 "helo"、正确答案 "hello"，错了多少？逐位比较（h=h、e=e、l=l、o≠l、缺一位）会高估错误：只是漏了一个 l。正确的度量是**编辑距离**（Levenshtein 距离）：把一个字符串变成另一个最少需要几次插入、删除、替换。

动态规划：D[i][j] = a 的前 i 个字符变成 b 的前 j 个字符的最小代价。

```
D[i][0] = i（删除 i 个），D[0][j] = j（插入 j 个）
D[i][j] = min(D[i−1][j] + 1,                       删除 a[i−1]
              D[i][j−1] + 1,                       插入 b[j−1]
              D[i−1][j−1] + (a[i−1] ≠ b[j−1]))     替换（相同则不花代价）
```

手算 "kitten" → "sitting"（经典例子，答案 3：k→s 替换，e→i 替换，末尾插入 g）。

### 练习 13.5

```python
def edit_distance(a, b):
    prev = list(range(len(b) + 1))
    for i in range(1, len(a) + 1):
        cur = [i] + [0] * len(b)
        for j in range(1, len(b) + 1):
            cur[j] = min(prev[j] + 1, cur[j - 1] + 1, prev[j - 1] + (a[i - 1] != b[j - 1]))
        prev = cur
    return prev[-1]


def cer(preds, refs):
    return sum(edit_distance(p, r) for p, r in zip(preds, refs)) / max(1, sum(len(r) for r in refs))
```

- 只保留两行（`prev` 和 `cur`），内存 O(len(b))；
- **CER**（字符错误率）= 所有样本的编辑距离之和 ÷ 所有参考答案的字符数之和。注意是"总和除以总和"，不是"每行的错误率再平均"：后者会让短行的权重过大（一个 2 字符的行错 1 个就是 50%）；
- CER 可以超过 100%：预测比答案长很多时（模型"胡言乱语"），插入的次数可以超过答案的长度；
- **整行全对率**（exact match）：完全正确的行占多少。它比 CER 严格得多：CER 2% 时，一行 16 个字符，每行出错的概率约 1 − 0.98¹⁶ ≈ 28%。

`align_ops` 回溯 D 表，给出具体的操作序列，用来统计"哪个字符被认成了哪个"。

第 25 章会系统地讨论 OCR 的评测：CER、WER（按单词算）、公式和表格的专门指标，以及评测的陷阱。

## 13.9 实验：训练一个文字行识别器

### 数据

`LineDataset` 用 `miniocr/data/text.py` 里的 `sample_line_text` 随机拼出一行文字（单词、数字、价格 `$838.16`、日期 `09-07-2006`、百分比，最多 28 个字符），渲染成 32 × 256 的灰度图。

**第一版数据太简单了**。最初我们用干净的渲染图（单一字体、黑字白底、没有噪声）训练：8 轮之后测试 CER 是 **0.00%**，去掉 LSTM 也是 0.00%。模型完美，但什么也说明不了：第 5 部分想比较"有没有上下文"，两边都是 0 错误。这和第 10 章遇到的问题一样——合成数据太干净，实验就失去了区分度。

所以现在的数据加了"拍摄"效果（`distort_line`）：旋转 ±2°、像斜体一样的错切 ±0.35、纵向缩放 ±15%、0–1.2 像素的模糊、墨迹浓度降到 60%–100%，再加标准差 0.15 的高斯噪声。行图很扁（256 × 32），旋转稍大一点两端就出界，所以角度比单字符的 ±12° 小得多。这样的图人眼仍然能读，但模型要费点力气。

### 训练

第 3 部分：2 万行训练、1000 行验证、2000 行测试；AdamW + OneCycle（第 11 章），批大小 32，10 轮，梯度裁剪 1.0。

```
  训练 20000 行  验证 1000 行  测试 2000 行（渲染用时 17.6 秒）；平均 16.2 个字符/行；字符表 73 类（含空白）
  参数 918,825；初始损失 23.915
    第 1 轮  训练损失 4.3621  验证 CER 28.63%  整行全对   6.2%
    第 2 轮  训练损失 0.4649  验证 CER 11.16%  整行全对  37.5%
    第 3 轮  训练损失 0.1927  验证 CER  6.44%  整行全对  53.4%
    第 5 轮  训练损失 0.0708  验证 CER  3.40%  整行全对  72.5%
    第 8 轮  训练损失 0.0213  验证 CER  2.53%  整行全对  77.6%
    第 10 轮  训练损失 0.0148  验证 CER  2.39%  整行全对  78.2%
  用时 598 秒
  测试集：CER 2.28%  整行全对 80.1%
```

**初始损失 23.9**。粗略估计：如果每步都是均匀分布，一条路径的概率是 (1/73)⁶⁴，−ln 后是 64 · ln 73 ≈ 275；按标签长度平均（演示用第一批的平均长度，约 15 个字符；初始损失也是在第一批上算的）约 18.5。实际还要减去 ln(合法路径的条数)/U，所以均匀分布时应该低于 18.5。实测 23.9 更高，说明刚初始化的模型输出**不是**均匀的：BatchNorm 后的特征经过 LSTM 和线性层，logits 有一定的随机起伏，某些类别被随机地偏爱，而正确的类别没有被偏爱。这在 CTC 里很常见，第 1 轮就会降下来。

**第 1 轮之后损失从 23.9 降到 4.4，第 2 轮降到 0.46**。CTC 训练常见的一个现象是开始的一小段时间模型只输出空白（因为空白在每条路径里都占多数，最容易提高概率），然后突然学会输出字符。我们的 OneCycle 学习率前 5% 是预热，模型在第 1 轮内就跨过了这个阶段。

**验证 CER 稳定下降到 2.4%，训练损失却继续降到 0.015**：训练损失和验证 CER 之间的差距说明模型开始记住训练集的细节（第 10 章的过拟合），不过验证 CER 还在缓慢改善，没有回升。

**测试 CER 2.28%，整行全对 80.1%**。按 13.8 节的估算，CER 2% 的每行出错概率约 28%，实测 20%：错误不是均匀分布的，集中在一部分难读的行上。

### 错在哪里

```
  错误的例子（预测 | 正确），共 398 行：
    '$838.16 page It 991 room'       | '$838.16 page it 991 room'
    'fo Her could between,'          | 'to Her could between,'
    'put Hurr street next'           | 'put Hard street next'
    '$225.24 story sod.'             | '$225.24 story was'
    'Lesa few'                       | 'Less few'
    'fist $196.56'                   | 'first $198.50'
  最常见的编辑操作（S 替换 正确→预测，D 漏掉，I 多出）：D'l'×22  D'r'×20  S'8'→'9'×16  D'i'×15  D','×15  I'i'×14  D'.'×14  S'5'→'6'×12  S'a'→'e'×11  S'e'→'a'×11
```

- **漏掉窄字符**（D'l'、D'r'、D'i'、D','、D'.'）是最多的错误。这些字符只有 4–5 像素宽，加上模糊和斜切后，常常和相邻字符融在一起。这正是 CTC 结构的弱点之一：一个时间步覆盖 4 像素，窄字符只在一两个时间步上有"证据"；
- **形近的数字和字母**（8↔9、5↔6、a↔e）：模糊后的笔画细节丢失；
- `'fist'` vs `'first'`、`'Lesa'` vs `'Less'`：模型不知道 "fist" 不在单词表里（其实 fist 是个真实单词，但不在我们的语料里）。CTC 的输出没有语言模型约束，13.5 节说的"束搜索 + 语言模型"可以修正这类错误。

**束搜索**：

```
  前缀束搜索（beam=8）：CER 2.24%  整行全对 80.5%  与贪心结果不同的行 26 行；用时 113.8 秒（Python 实现，很慢）
```

只改变了 26 行，CER 从 2.28% 降到 2.24%。训练好的 CTC 模型的输出非常"尖"（下一节），一个文字的概率几乎集中在一条路径上，贪心和束搜索的结果很少不同。束搜索真正的价值在于结合语言模型。

### 模型自己学会了对齐

第 4 部分看模型在一张图上每个时间步的输出（图存在 `outputs/ch13/peaky.png`）：

```
  文字 'Five 2024 rocks'，64 个时间步的贪心路径（· 表示空白）：
    F······························iv··e·  2·0··2··4· r·o··c·k··s···
  非空白的时间步 16 个 / 64；解码结果 'Five 2024 rocks'
  空白概率 > 0.9 的时间步占 70%；非空白步上最大概率的平均 0.999
  字符的墨迹中心（像素）与它被输出的时间步 × 4：
    F:118/2  i:126/126  v:133/130  e:144/142  2:158/150  0:170/158  2:180/166  4:192/178  r:204/190  o:213/198  c:224/202  k:234/210  s:244/222
```

几个观察：

1. **尖峰行为**（peaky）：64 步里只有 16 步输出字符，其余全是空白；输出字符的那一步，概率平均 0.999。CTC 训练出的模型几乎总是这样：每个字符只在**一个**时间步上以极高的概率出现。原因是这样的路径最"便宜"：空白可以吸收所有过渡区域，模型不需要精确地决定一个字符占几步；
2. **大致按位置对齐**：i、v、e、2、0……被输出的位置和它们的墨迹中心基本对应。训练数据里从来没有字符位置的信息，模型自己学会了"在字符出现的地方输出它"；
3. **但对齐并不精确**：越往右，输出越提前（s 的墨迹中心在 244，输出在 222）。CTC 只要求输出**顺序**正确，不要求时间步和像素一一对应。双向 LSTM 能看到右边的内容，可以"提前"输出；
4. **最奇怪的是 F**：它的墨迹在 x = 118，却在时间步 0（x ≈ 2）就被输出了——那里是一片空白背景。模型学到了一个"捷径"：一行的第一个字符可以在序列的最开头输出，反向 LSTM 把右边 30 个时间步之外的信息传了过来。这完全符合 CTC 的规则（顺序没错），只是不像人类的直觉。

这说明：**CTC 的对齐是模型自己发明的，不保证和图像位置对应**。如果需要字符的位置（比如在图上画出每个字的框），不能直接从 CTC 的尖峰位置读出来，至少对双向 RNN 的模型不行。

### 上下文有多重要

第 5 部分训练一个去掉 LSTM 的版本：CNN 的每一列直接接线性层，每列独立分类，只靠 CNN 26 像素的感受野获取上下文。

```
  无 RNN：参数 250,025，每轮验证 CER 17.56% 12.36% 7.51% 6.82% 5.92% 5.35% 5.22% 4.96% 4.84% 4.72%
  测试 CER：无 RNN 4.76%   双向 LSTM 2.28%
    无 RNN    形近字符对之间的替换错误：o/O 21  s/S 16  w/W 22  c/C 7  l/I 5  0/O 0
    双向 LSTM  形近字符对之间的替换错误：o/O 3  s/S 1  w/W 1  c/C 1  l/I 1  0/O 0
    （测试集里 o 1386 个、O 69 个、s 958 个、S 110 个）
```

- 去掉 LSTM，CER 翻了一倍多（2.28% → 4.76%）；
- 差别最集中在**大小写形状相同的字母**上：o/O、s/S、w/W、c/C。它们的形状完全一样，只有大小不同。而大小是相对的：字号在 16–22 之间随机，一个 22 号的 o 和一个 16 号的 O 差不多大。要判断大小写，必须和同一行的其他字符比较——"它比旁边的字母高还是一样高"。无 RNN 的模型只能看到 26 像素宽的范围，常常不够；LSTM 能看到整行，o/O 的错误从 21 降到 3；
- 0/O（数字零和字母 O）在两个模型里都几乎没有错：在我们的字体里它们的形状本来就不同（0 更窄）。

回顾第 10、12 章：单字符模型在 o/O、s/S 上错得最多（第 10 章的混淆矩阵里 O→o 是第一名）。单独一个字符，不看上下文，**根本无法**区分大小写的 o 和 O。文字行识别比单字符识别"更容易"的一面，正是有了上下文。

## 13.10 CTC 的限制

第 6 部分：

```
   1 个字符（至少需要  1 步，T = 64）：预测 '9'
   7 个字符（至少需要  7 步，T = 64）：预测 'abc 123'
  23 个字符（至少需要 23 步，T = 64）：预测 'the cat sat on a mat ok'
  46 个字符（至少需要 91 步，T = 64）：预测 'lill'
  T = 5 步时，标签 "aaa" 至少需要 5 步（a ε a ε a）：损失 5.493；"aaaa" 需要 7 步：损失 inf
```

1. **长度上限**：46 个 i（45 对相邻重复）至少需要 46 + 45 = 91 个时间步，而模型只有 64 步，**不可能**输出正确答案，损失是无穷大。T 必须大于"标签长度 + 相邻重复的对数"。这是选择 CNN 下采样倍数时的硬约束；
2. **分布外的输入**：单独一个字母 "a" 被认成了 '9'。训练数据平均每行 16 个字符，几乎没有只有一个字符的行；模型（尤其是双向 LSTM）习惯了"一行里有很多字符"的上下文，遇到极短的行就出错。任何模型在训练分布之外都不可靠（第 10 章）；
3. **结构上的限制**——这是最根本的：
   - CTC 要求**输出顺序与图像从左到右的顺序一致**（单调对齐）。公式 `\frac{a}{b}` 的 a 在 b 的**上方**，`x^{2}` 的 2 在 x 的右上方，LaTeX 的书写顺序和空间位置不是单调对应的；
   - CTC 假设**各时间步的输出相互独立**（给定图像）。它没有办法保证括号配对，也不知道前面已经输出了什么；
   - CTC 只能处理**一行**。多行文字、表格、版面，都需要先用别的方法切成单行（第 21 章的检测）。

这就是为什么现代 OCR 走向了自回归的 VLM：模型逐个 token 地写出 Markdown 或 LaTeX，每一步都看着整张图（交叉注意力或拼接，第 15、22 章）和已经写出的内容（因果自注意力），不再有单调对齐和独立性的限制。代价是慢——必须一个一个地生成（第 17 章）。

## 13.12 常见错误

| 现象 | 原因 | 怎么查 |
|---|---|---|
| 损失是 inf 或 nan | 某个样本的 T 不够长（标签太长或有很多重复字符） | 检查 T ≥ U + 重复对数；用 `zero_infinity=True` |
| 模型只输出空白，损失不降 | 训练初期的正常阶段；或学习率太小 | 多训练一会儿；检查学习率和预热 |
| 解码结果总是少了重复字母（"hello" → "helo"） | 折叠时先删空白再合并重复（顺序错了） | 必须先合并再删空白 |
| `F.ctc_loss` 报形状错误 | 输入必须是 (T, B, K)，不是 (B, T, K)；必须是 log_softmax 的输出 | 检查 permute 和 log_softmax |
| 空白的编号不一致 | 字符表里空白不是 0，但 `blank=0` | `Vocab` 的 specials 把空白放在第 0 位 |
| CER 算出来偏高 | 逐行算错误率再平均（短行权重过大） | 用总编辑距离 ÷ 总字符数 |
| 合成数据上 CER ≈ 0，实验结论却不可信 | 数据太干净，没有区分度 | 加噪声、形变；用更接近真实的数据 |

## 13.13 真实世界对照

- **CRNN（2015）**：本章结构的原型，VGG 式 CNN + 双向 LSTM + CTC；
- **Tesseract 4 及以后**：开源 OCR 引擎，识别器是 LSTM + CTC；
- **PaddleOCR（PP-OCR 系列）**：工业界最常用的开源 OCR 之一，"检测 + 识别"两阶段，识别器从 CRNN 演进到 SVTR（用 Transformer 式的混合块代替 CNN + LSTM），损失仍然是 CTC，因为它快、可以并行解码；
- **语音识别**：CTC 最早就是为语音设计的（2006 年 Graves），音频帧和文字的对齐同样未知。后来出现了 RNN-T、注意力编码器-解码器（Whisper）等；
- **今天的 VLM OCR**（Qwen-VL、Xiaomi-OCR 等）不用 CTC，而是自回归地生成，能直接输出整页的 Markdown、LaTeX 和表格。但在需要速度的场景（手机上实时识别、海量文档的预处理），CTC 识别器仍然被大量使用。第 21 章会搭一个"检测 → 裁剪 → CTC 识别"的流水线 OCR，作为 VLM 的对照组。

## 13.14 深入一步

### CTC 的条件独立假设

CTC 定义 p(路径 | x) = Π_t p_t(π_t | x)：给定图像，各步的输出相互独立。这并不意味着模型"看不到上下文"——每一步的分布 p_t 是由整个图像（通过 LSTM）计算出来的。它的意思是：第 t 步**输出了什么**，不影响第 t+1 步的分布。所以 CTC 模型不能根据"我刚才写了 `{`"来决定之后写 `}`。自回归模型（第 16 章）没有这个限制。

### CTC 与 HMM

如果你学过语音识别中的隐马尔可夫模型（HMM），会发现 CTC 的前向算法就是 HMM 的前向算法：扩展标签 l' 是状态序列，"停留、前进一格、跳一格"是状态转移，p_t(l'[s]) 是发射概率。区别在于 CTC 的转移概率都是 1（不学习），所有信息都在神经网络输出的发射概率里。

### 为什么尖峰

一个直觉的解释：对于一个字符占 5 个时间步的区域，"输出 1 次字符 + 4 次空白"和"输出 5 次字符"都是合法的路径。但空白在**所有**区域都可以使用（字符之间、字符和字符的过渡），模型提高空白的概率能同时帮助很多位置。久而久之，空白占据了绝大多数时间步，每个字符缩成一个尖峰。

### 注意力解码器与 CTC 的结合

2017–2020 年的一些 OCR 和语音系统同时使用 CTC 和注意力解码器：编码器的输出既送给 CTC 损失，也送给一个自回归的注意力解码器，两个损失加权相加。CTC 帮助编码器学到单调的对齐（训练更快、更稳），解码器负责灵活的输出。这是从 CTC 走向纯自回归模型的过渡形态。

## 13.16 本章小结

- 文字行识别的核心困难是对齐未知：字符宽度、位置不固定，标签只有文字；
- CTC 把所有可能的对齐（路径）都考虑进去：路径折叠（先合并重复、再删空白）后等于标签，概率求和；
- 空白有两个作用：分隔重复字符、填充多余的时间步；
- 前向算法用动态规划在 O(T · S) 内计算 CTC 概率，在对数空间里实现；
- 贪心解码找最可能的路径，前缀束搜索找最可能的文字；
- RNN 沿序列传递状态，LSTM 用门和加法更新缓解梯度消失；双向 RNN 两个方向都看；
- CRNN = CNN（列特征）+ 双向 LSTM（上下文）+ CTC；
- CER = 总编辑距离 ÷ 总字符数；
- 在加了噪声和形变的数据上，CRNN 达到 CER 2.28%；去掉 LSTM 后翻倍，差别集中在需要上下文才能区分的大小写字母；
- CTC 训练出的模型输出是尖峰状的，对齐由模型自己发明，不一定对应图像位置；
- CTC 不能处理非单调的结构（公式、表格）和多行，这是走向自回归 VLM 的原因。

## 参考答案

1. 字符会粘连（rn 像 m）、断裂、倾斜，切分本身很难，切错了识别也会错；而且切分需要知道每个字符的位置，训练数据只有文字标签。
2. 分隔相邻的重复字符；填充多余的时间步（字符之间的空隙、过渡区域）。没有空白时，"ll" 中两个 l 相邻会被合并成一个，"hello" 无法输出。
3. 如果先删空白再合并，`lεl` 会变成 `ll` 再合并成 `l`，空白就失去了分隔作用。
4. 贪心找的是概率最大的**单条路径**；一个文字的概率是很多条路径之和，可能分散在很多条概率都不大的路径上，总和却超过贪心路径对应的文字。例子：两步 p(ε) = 0.6，贪心得到空（0.36），"a" 的总概率是 0.64。
5. LSTM 的细胞状态用加法更新 c_t = f ⊙ c_{t−1} + i ⊙ g，遗忘门接近 1 时信息和梯度可以几乎无损地传很多步；Elman RNN 每步都要乘 W_hh 并经过 tanh，梯度连乘后指数衰减或爆炸。
6. o/O、s/S 形状相同只是大小不同，而字号是随机的，必须和同一行的其他字符比较才能判断大小写，需要超过 26 像素感受野的上下文；0 和 O 在这个字体里形状本来就不同，不需要上下文。
7. CTC 要求输出顺序与图像从左到右单调对应，而公式的 LaTeX 顺序与空间位置不单调（分子在分母上方、上标在右上方）；CTC 还假设各步输出条件独立，无法保证括号配对。
8. l' = [ε, a, ε, a, ε, b, ε]（下标 0–6）。允许跳过的位置：s = 3（a，但 l'[1] = a 相同，**不允许**）；s = 5（b，l'[3] = a 不同，允许）。所以只有 s = 5 可以从 s − 2 跳过来。
9. 最少 2 步（ab）。T = 4 时，路径是在 a 前、a 和 b 之间、b 后插入空白，以及重复 a、b，枚举得 15 条（例如 abεε、aabε、εaab……）。可以用 `ctc_brute_force(np.full((4, 3), 1/3), [1, 2])` 验证路径条数。
10. 3。k→s（替换）、e→i（替换）、末尾插入 g。
11. CER = 50 / 2000 = 2.5%。逐行平均时那一行的错误率是 100%，单独贡献 1% 的平均 CER（100% / 100 行），而在总和法里它只贡献 2/2000 = 0.1%。

    def ctc_feasible(target, T):
        repeats = sum(a == b for a, b in zip(target, target[1:]))
        return T >= len(target) + repeats
    ```
13. 它先删空白再合并重复，`[1, 0, 1]` 会变成 `[1]` 而不是 `[1, 1]`，空白失去了分隔作用。
