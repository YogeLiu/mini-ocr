# 第 32 章　遗忘与能力配比

## 本章在全景图中的位置

第 26–31 章一直在让模型在某些任务上变得更好：SFT 教它按格式回答，DPO 让它少说图里没有的东西，GRPO 让它读文字更准。每一次训练都只看训练的那几个任务。一个自然的问题是：**模型原来会的东西，还在吗？**

答案经常是"不完全在"。在新任务上微调之后，模型在没训练的任务上变差，这叫**遗忘**（forgetting）；变差得很厉害时叫**灾难性遗忘**（catastrophic forgetting）。对 VLM 来说，最典型的情形是：

- 专门做 OCR 训练之后，模型的描述、问答、定位能力下降；
- 视觉方面的训练（大量的图文数据）让语言模型本身的能力（写作、推理）下降；
- RL 在少数几个任务上把奖励推得很高，模型的输出格式在其他任务上也变了。

所以真实的 VLM 训练几乎都在 OCR 数据里混入通用数据，在 RL 里混入多种任务。**混多少、怎样混**，就是本章说的**能力配比**。第 34 章的 Xiaomi-OCR-0 报告里有大量这类设计：持续预训练的数据配比、Mix-RL 的任务配比。

本章分三件事：

1. **怎样测量遗忘**：有标签的任务指标、语言模型的困惑度、不需要标签的探测 KL；
2. **怎样公平地比较**：不同方法、不同超参数之间，用帕累托前沿而不是单个数字；
3. **怎样减少遗忘**：重放（配比）、冻结与 LoRA、KL 约束、更小的更新；以及从同一个起点出发，继续 SFT、RFT、DPO、GRPO 各自"学到多少、忘掉多少、花了多少"。

第 1–3 部分不训练（第 1 部分用的是 v2 版课程实测的数据，第 3 部分给权重加噪声而不是训练），数字都是实际跑出来的（日志在 `outputs/ch32/`）；第 4、5 部分的训练由你自己跑。

## 学习目标

学完本章，你应该能够：

1. 用三种方式测量遗忘：没训练的任务的指标、通用文本的困惑度、探测 KL；解释探测 KL 和困惑度变化的关系；
2. 实现帕累托前沿，用它比较"新任务学得多少"和"旧能力保留多少"的权衡；说出为什么"同一个学习率下的比较"会误导；
3. 解释遗忘的来源（共享参数、更新的大小），列出四类对策并说出各自的代价；
4. 实现重放（按比例混入旧任务的样本）和拒绝采样微调（RFT）；
5. 设计"同一起点、同一批题"的方法对照，按步数、样本数、计算量三种口径报告结果。

## 32.1 怎样测量遗忘

### 三种测法

| 测法 | 需要什么 | 测的是什么 | 缺点 |
|---|---|---|---|
| **没训练的任务的指标** | 每个任务的测试集和标签 | 我们关心的能力有没有下降 | 只能测你想到的任务 |
| **通用文本的困惑度** | 一段模型没训练过的通用文字 | 语言模型本身的能力 | 和具体的任务能力不一定对应 |
| **探测 KL** | 一组输入，不需要标签 | 模型的输出分布离起点有多远 | 不区分"变好"和"变坏" |

第一种最直接：第 31 章第 5 部分里，caption 没有参与 RL，它在训练前后的分数差就是遗忘的一种测量。我们在每一章都用 `quick_eval` 评测六个任务，就是为了随时看到这一点。

### 探测 KL

在一组固定的探测输入（比如九种任务各几个样本，用真值答案当作"回答"）上，比较新模型和起点模型在每个回答位置上的输出分布：

```
探测 KL = 平均_位置 KL( p_起点 ‖ p_新 ) = 平均_位置 Σ_v p_起点(v) · log( p_起点(v) / p_新(v) )
```

和第 29 章不同，这里两个模型的完整分布都有（词表只有 100 个），可以精确计算，不需要采样估计。

方向的选择：期望对**起点模型**求，衡量"起点模型会写的东西，新模型还认不认"。如果新模型把起点模型认为很可能的 token 变得很不可能，这个 KL 会很大。

### 练习 32.4：`probe_kl`

```python
@torch.no_grad()
def probe_kl(logits_new, logits_base, mask):
    lb = F.log_softmax(logits_base.float(), -1)
    ln = F.log_softmax(logits_new.float(), -1)
    kl = (lb.exp() * (lb - ln)).sum(-1)
    m = mask.float()
    return ((kl * m).sum() / m.sum()).item()
```

### 手算一个位置

词表只有三个 token。某个回答位置上，起点模型的分布 p_起点 = [0.7, 0.2, 0.1]，新模型 p_新 = [0.5, 0.3, 0.2]，真值是第 1 个 token。

```
KL(p_起点 ‖ p_新) = 0.7·ln(0.7/0.5) + 0.2·ln(0.2/0.3) + 0.1·ln(0.1/0.2)
                  = 0.7 × 0.3365 + 0.2 × (−0.4055) + 0.1 × (−0.6931)
                  = 0.2355 − 0.0811 − 0.0693 = 0.0851
KL(p_新 ‖ p_起点) = 0.5·ln(0.5/0.7) + 0.3·ln(0.3/0.2) + 0.2·ln(0.2/0.1) = 0.0920
```

三点值得注意：

- 求和里有负的项（新模型给第 2、3 个 token 的概率比起点高），但总和一定 ≥ 0，只有两个分布完全相同时才等于 0；
- 两个方向的数不一样（0.0851 vs 0.0920），KL 不是对称的。差别在分布接近时很小，分布差得远时可能很大（自己动手第 3 题）；
- 这个位置的交叉熵从 −ln 0.7 = 0.357 涨到 −ln 0.5 = 0.693，涨了 0.336，比 KL 大得多。单个位置上两者没有固定关系；只有在很多位置上平均、而且真值大致按 p_起点 分布时，两者才接近（下面第 3 部分）。

### 怎样准备一个遗忘评测集

真实项目里，评测遗忘的集合要在训练**之前**就定好，而不是看到结果之后再挑：

1. **覆盖你不想丢的能力**：对 OCR 专门化来说，至少包括描述、问答、数数、定位这类"通用 VLM 能力"，以及一段纯文本（测语言模型本身）；
2. **和训练数据不重叠**：重放用的是训练集，评测用测试集（32.9 节的常见错误）；
3. **固定解码设置**：贪心、同样的最大长度、同样的提示模板（第 25 章）；
4. **每个任务足够多的样本**：第 25 章的置信区间告诉你，100 个样本时 ±10% 左右的差别都可能是噪声；
5. **同时记录探测 KL**：它便宜、连续、不需要标签，可以在训练过程中每隔一段就算一次，画出"离起点多远"随步数的曲线；任务指标只在几个检查点上算。

本章的 `quick_eval`（六个任务各 100 个样本）加上 64 条探测样本，就是这样一个最小的版本。

### 第 3 部分：探测 KL 和困惑度是什么关系

用第 16 章的字符级 GPT，给它的每个权重张量加上高斯噪声（标准差 = σ × 这个张量自己的标准差），然后在 15 段、每段 256 个字符的验证文字上，同时算探测 KL（相对加噪声之前的模型）和困惑度。这不是训练，只是用一种可控的方式"破坏"模型：

```
起点的困惑度 3.506
噪声 σ      探测 KL     困惑度    困惑度的变化
0.0          0.0000     3.506       +0.0%
0.01         0.0001     3.507       +0.0%
0.02         0.0004     3.510       +0.1%
0.05         0.0022     3.520       +0.4%
0.1          0.0091     3.550       +1.3%
0.2          0.0374     3.663       +4.5%
```

两者一起变化，而且数量上很接近：σ = 0.2 时，探测 KL 是 0.0374，困惑度的对数变化是 log(3.663 / 3.506) = 0.0438。

这不是巧合。困惑度的对数就是交叉熵 CE = E_数据[−log p]。如果起点模型已经很接近数据的分布（p_起点 ≈ p_数据），那么

```
CE_新 − CE_起点 = E_数据[ log p_起点 − log p_新 ] ≈ E_{p_起点}[ log p_起点 − log p_新 ] = KL(p_起点 ‖ p_新)
```

**探测 KL 近似于"在起点模型擅长的数据上，困惑度的对数涨了多少"**，但它不需要标签：任何输入都可以拿来当探测集。两者的差别（0.0374 vs 0.0438）来自"起点模型不完全等于数据"。

这也说明了 KL 在 RL 里的意义：第 29 章的 KL 约束 β·KL(π‖π_ref) 是在直接限制"模型离起点有多远"，也就间接限制了遗忘。（方向不同：RL 里是 KL(π‖π_ref)，这里是 KL(p_起点‖p_新)。两者在两个分布接近时差不多，第 29 章第 3 部分 (c)。）

## 32.2 公平比较：帕累托前沿

### 一个数不够

一次训练有两个结果：新任务的分数（越高越好）、遗忘的程度（越小越好）。比较两种方法时，如果 A 的新任务分数更高、遗忘也更多，谁更好？没有答案，取决于你更在乎哪个。

但有一种情况是有答案的：如果 A 在两项上**都不比 B 差、且至少一项更好**，就说 A **支配**（dominate）B。不被任何点支配的点组成**帕累托前沿**（Pareto front）。前沿上的点之间没有绝对的好坏，只有取舍；前沿之外的点"在两项上都可以被改进"，可以直接淘汰。

### 练习 32.1：`pareto_front`

```python
def pareto_front(points):
    out = []
    for i, (a, b) in enumerate(points):
        if not any((a2 >= a and b2 >= b) and (a2 > a or b2 > b) for j, (a2, b2) in enumerate(points) if j != i):
            out.append(i)
    return out
```

两个指标都是"越大越好"。困惑度是越小越好，用的时候取负号（或者取 −log 困惑度）。完全相同的两个点互不支配，都在前沿上（测试检查了这一点）。

### 第 1 部分：v2 版课程的实测数据

v2 版课程第 21 章做过一个实验：第 10 章的字符级 GPT（在 Python 代码上预训练）去学两位数加法，用"留出的代码文本的困惑度"衡量遗忘，比较全参数、LoRA、只训最后两层，各扫几个学习率，再加两个"重放"的点。这些是那一版实际测出来的数字（单个种子）：

| 设置 | 加法准确率 | 代码困惑度（起点 4.51） |
|---|---|---|
| 全参数 1e-4 | 21.0% | 15.89 |
| 全参数 3e-4 | 50.5% | 40.52 |
| 全参数 1e-3 | 55.5% | 2828.16 |
| LoRA r=8 3e-4 | 13.7% | 16.86 |
| LoRA r=8 1e-3 | 63.5% | 160.18 |
| LoRA r=8 3e-3 | 93.8% | 6629.59 |
| 只训最后两层 3e-4 | 66.6% | 9.08 |
| 只训最后两层 1e-3 | 92.0% | 1459.96 |
| 全参数 1e-3 + 重放 | 98.6% | 6.71 |
| LoRA r=8 3e-3 + 重放 | 85.3% | 4.62 |

`pareto_front` 的结果：

```
没有重放的 8 个点：前沿上的点
  LoRA r=8 3e-3          加法准确率  93.8%   代码困惑度  6629.59
  只训最后两层 3e-4      加法准确率  66.6%   代码困惑度     9.08
  只训最后两层 1e-3      加法准确率  92.0%   代码困惑度  1459.96
全部 10 个点：前沿上的点
  全参数 1e-3 + 重放     加法准确率  98.6%   代码困惑度     6.71
  LoRA r=8 3e-3 + 重放   加法准确率  85.3%   代码困惑度     4.62
```

读这两行：

- **没有重放时**，前沿上有三个点，代表三种取舍：学得少、几乎不忘（66.6%、9.08）；学得多、忘得很严重（92–94%、1460–6630）。全参数的三个点都不在前沿上：在这个实验里，每一个全参数的点都被某个"只训最后两层"或 LoRA 的点支配；
- **同一个学习率下的比较会误导**：只看 3e-4 这一列，LoRA（13.7%、16.86）比全参数（50.5%、40.52）"学得少、忘得也少"，似乎 LoRA 更保守。但 LoRA 在 3e-3 时学到 93.8%，遗忘比全参数的任何一个点都严重。LoRA 的有效更新幅度和全参数不同，同一个学习率意味着不同大小的更新。**公平的比较是比前沿，而不是比同一个超参数下的点**；
- **加上重放的两个点支配了前面所有的点**：98.6% 和 6.71，两项都比没有重放的任何点好。重放不是"在两者之间取舍"，而是把整个前沿往好的方向推。

（这是单个种子、一个小模型、一个玩具任务的结果。数量级的差别，比如困惑度 9 和 2828，是可信的；66.6% 和 63.5% 这样接近的数字，不能当作差别的证据，第 25 章。）

## 32.3 为什么会遗忘

### 共享的参数

模型只有一套参数，所有任务共用。在新任务上训练，梯度只告诉参数"怎样对新任务更好"，不管旧任务。每一步更新都会改变旧任务的输出，只是改变的方向是随机的（相对于旧任务而言）。小的随机改变一般让旧任务变差：模型在旧任务上已经接近一个好的解，在好的解附近随便走一步，大多是往上坡走。

所以遗忘的程度和**更新走了多远**密切相关：学习率越大、步数越多，走得越远，忘得越多。v2 的表里，全参数从 1e-4 到 1e-3，代码困惑度从 15.89 涨到 2828。探测 KL 就是"走了多远"的一种度量（在输出空间里，而不是参数空间里）。

### 为什么 VLM 更容易遗忘

- **数据分布差别大**：OCR 数据（文字行、文档）和通用 VLM 数据（照片、问答）在图像和文字两方面都很不一样，专门在一种上训练，模型的视觉表示和语言输出都会偏向它；
- **输出格式的遗忘**：很多"遗忘"其实是格式的变化。只训练 OCR，模型可能对任何问题都开始输出图里的文字，而不是回答问题。这种遗忘有时只需要很少的数据就能恢复，所以有人称之为"表面的"遗忘；
- **小模型更严重**：参数少，能"同时记住"的东西少，任务之间的干扰更大。

### 一个有争议的假说：在线 RL 遗忘得更少

最近有研究（Shenfeld 等，2025，"RL's Razor"）报告：在达到相同的新任务成绩时，在线 RL 比 SFT 遗忘得更少。他们给出的解释是：在线 RL 在模型自己的采样上学习，倾向于找到"离起点最近"（KL 最小）的解；而 SFT 把模型拉向一个固定的、可能离起点很远的分布（标注者的写法）。

这个结论依赖于"达到相同的新任务成绩"这个比较方式，也依赖于具体的任务和超参数。v2 版课程的实验里，小学习率下所有方法都没有遗忘、无从比较，大学习率下 GRPO 直接训练崩溃，也没能检验它。第 5 部分给了你一个在 VLM 上检验它的机会：同时记录新任务的成绩和探测 KL，看在相同的成绩下谁的 KL 更小。**这是一个值得保持怀疑、可以自己实验的问题**。

## 32.4 减少遗忘的四类办法

| 办法 | 做什么 | 代价 |
|---|---|---|
| **重放 / 配比** | 新任务的数据里混入旧任务的数据 | 需要旧任务的数据；新任务分到的梯度变少 |
| **冻结 / LoRA** | 只更新一部分参数（第 28 章） | 新任务能学到的有限；不保证不忘（v2 的 LoRA 3e-3） |
| **KL 约束** | 损失里加上离起点的 KL（第 29 章） | 需要参考模型；β 要调 |
| **更小的更新** | 更小的学习率、更少的步数、早停 | 新任务学得少 |

另外两种了解即可：

- **模型合并**：训练完之后，把新模型和起点模型的权重做加权平均（θ = α·θ_新 + (1 − α)·θ_起点，WiSE-FT 等），α 从 0 到 1 扫一遍，就得到一条前沿。很便宜，往往很有效；
- **正则化参数的变化**：EWC 等方法给"对旧任务重要的参数"更大的惩罚，在大模型上用得不多。

### 重放

最简单、通常也最有效。每个批里，一部分样本来自新任务，一部分来自旧任务：

### 练习 32.2：`mixed_batch`

```python
def mixed_batch(rng, B, ratio, make_new, make_old):
    n_old = int(round(ratio * B))
    items = [(make_old(rng), True) for _ in range(n_old)] + [(make_new(rng), False) for _ in range(B - n_old)]
    order = rng.permutation(B)
    return [items[i][0] for i in order], [items[i][1] for i in order]
```

重放的比例（ratio）是一个需要调的超参数：

- 比例太小，起不到"复习"的作用；
- 比例太大，新任务分到的梯度太少，学得慢；
- 还要注意第 26 章的教训：按 token 平均时，回答长的样本分到的梯度多。旧任务里有描述（回答 30–40 个 token），新任务是场景文字（回答 5 个 token 左右），**同样 30% 的重放比例，按 token 算，旧任务可能占到梯度的大半**。重放的"比例"要说清楚是按样本还是按 token。

## 32.5 能力配比

把重放推广一步：训练数据本来就是多种任务的混合，每种任务占多少，就是**配比**（data mixture）。配比是训练一个通用 VLM 时最重要的设计之一，也是最难的：

- **任务之间有互补也有冲突**。数数和定位都需要找到物体，可能互相帮助；OCR 的"把看到的字都写出来"和问答的"只回答被问的"在输出格式上冲突；
- **最优配比依赖于模型的大小和训练的阶段**。第 23 章的温度采样（按数据量的 1/T 次方分配）是一种常用的起点；
- **配比的实验很贵**：每种配比都要完整训练一次。真实的报告里通常只扫少数几个点，或者在小模型上扫、再推到大模型上。

一个配比实验的标准做法：

1. 固定总的训练量（步数或 token 数）；
2. 改变某一类数据的比例（比如 OCR 数据占 10%、30%、50%、70%）；
3. 每个点同时测"这类任务的成绩"和"其他任务的成绩"；
4. 画前沿，选一个符合你的需求的点；
5. 多个种子，至少在你要选的那几个点上（第 25、26 章）。

第 4 部分就是这样一个实验（加上不同的更新方式），在我们的 VLM 上。

## 32.6 同一起点，四种继续训练的方法

### 设定

你有一个 SFT 之后的模型，在场景文字上的准确率还不够高。拿到一批场景文字的题目，四种继续训练的方式：

| 方法 | 做什么 | 需要什么 |
|---|---|---|
| **继续 SFT** | 用真值答案继续做 SFT | 真值答案 |
| **RFT**（拒绝采样微调） | 模型自己采样，保留读对的，把它们当答案做 SFT | 判断对错的程序 |
| **DPO** | 模型自己采样，读得最好的和最差的组成一对（第 30 章） | 打分的程序 |
| **GRPO** | 在线采样，用 1 − NED 当奖励（第 31 章） | 打分的程序 |

### 练习 32.3：`rft_select`

```python
def rft_select(rewards, G, threshold=1.0, k=1):
    r = rewards.float().view(-1, G)
    out = []
    for g in range(r.shape[0]):
        order = sorted(range(G), key=lambda i: (-r[g, i].item(), i))
        out += [g * G + i for i in order if r[g, i] >= threshold][:k]
    return out
```

### 手算一次挑选

两道题，每道题 G = 4 个回答，奖励（1 − NED）是：

```
第 0 题：[1.0, 0.8, 1.0, 0.5]      全局下标 0, 1, 2, 3
第 1 题：[0.6, 0.9, 0.7, 0.4]      全局下标 4, 5, 6, 7
```

- `threshold=1.0, k=1`：第 0 题有两个完全读对的（下标 0、2），奖励相同，下标小的在前，取 0；第 1 题没有完全读对的，一个也不取。结果 `[0]`。**一个批 2 道题，只剩 1 条训练样本**；
- `threshold=0.8, k=2`：第 0 题按奖励排序是 0（1.0）、2（1.0）、1（0.8），取前两个 `0, 2`；第 1 题只有下标 5（0.9）过线。结果 `[0, 2, 5]`。

第一种情况说明了 RFT 的一个实际问题：**每步实际的批大小是变化的**，取决于模型自己能读对多少题。模型越弱，每步能用的样本越少；模型完全不会的题永远进不了训练数据。第 5 部分的 `rft_batch` 在一条也没挑出来时，退回到一条真值样本，免得这一步空转；你在记录表里要记下"平均每步用了几条"（运行前预测第 3 题）。

降低阈值（接受"差不多读对"的回答）能多拿到样本，代价是把模型自己的错误也当作答案学进去：0.8 的回答里有错字，RFT 会让模型更倾向于写出这个错字。

RFT 也叫"拒绝采样"或"STaR 式"的自训练：只保留通过检查的样本，把它们当作新的 SFT 数据。它介于 SFT 和 RL 之间：数据来自模型自己（像 RL），训练用的是 SFT 的损失（只学好的，不罚坏的）。

和继续 SFT 比，RFT 的"答案"是模型自己写的。当答案唯一时（场景文字的答案就是那个单词），读对的回答和真值完全相同，RFT 就等于"只在模型有时能读对的题上做 SFT"。当答案不唯一时（描述、推理过程），RFT 学的是模型自己的写法，可能比标注者的写法更"顺手"，这是它遗忘更少的一种可能原因。

### 统一的形式：同一个原语，不同的加权

四种方法的损失看起来各不相同，但它们的梯度都可以写成同一个形式（DeepSeekMath 的报告第 5.2.1 节把它叫作统一范式）：

```
∇θ J = E_(q,o)~D [ Σ_t  GC(q, o, t) · ∇θ log πθ(o_t | q, o_<t) ]
```

- `log πθ(o_t | q, o_<t)` 就是第 27 章的"回答部分每个 token 的对数概率"，四种方法共用这一个原语；
- `D` 是回答 o 从哪里来；
- `GC`（梯度系数，gradient coefficient）决定每个 token 的对数概率往上推还是往下压、推多大力。

（各方法对 Σ_t 的平均方式不同：按 token 平均、按样本平均或者直接求和，第 26、31 章讲过。这里先不管它，只看 GC。）

| 方法 | 回答从哪里来（D） | 梯度系数 GC | 本书的位置 |
|---|---|---|---|
| 继续 SFT | 真值答案 | 常数 1：每个 token 都往上推 | 第 26 章 |
| RFT | 模型自己离线采样，只保留通过检查的 | 通过的为 1，没通过的为 0（等于丢掉） | 本节 |
| DPO | 模型自己离线采样的一对：chosen o_w、rejected o_l | o_w 的 token 为 β·σ(β(ρ_l − ρ_w))，o_l 的 token 取相反数；ρ = log πθ(o) − log π_ref(o) | 第 30 章 |
| GRPO | 当前策略在线采样的一组 G 个回答 | 组内标准化的优势 A_i = (r_i − 组均值) / 组标准差；加 KL 时还有 KL 项的梯度 | 第 29、31 章 |

用这张表可以把"四种方法差在哪里"说得很具体：

- **SFT 和 RFT 只往上推，从不往下压**（GC ≥ 0）。它们只能让模型更像某些回答，不能让它远离错误的回答；
- **DPO 和 GRPO 有负的 GC**：rejected 的回答、低于组均值的回答被往下压。这是它们能"纠正"模型自己的错误的原因，也是似然位移（第 30 章：chosen 的概率也可能下降）和奖励投机的来源；
- **数据来源决定了"离起点多远"**：RFT、DPO、GRPO 的回答都来自模型自己，推的是模型本来就会写的东西；SFT 的真值答案可能是模型很不习惯的写法。这和 32.3 节"在线 RL 遗忘得更少"的假说有关。

**手算 DPO 的系数**：β = 0.1，chosen 的 ρ_w = 0.5（策略给它的对数概率比参考模型高 0.5），rejected 的 ρ_l = −0.2。β(ρ_l − ρ_w) = 0.1 × (−0.7) = −0.07，σ(−0.07) = 0.4825，GC = 0.1 × 0.4825 ≈ 0.048。chosen 的每个 token 乘 +0.048，rejected 的每个 token 乘 −0.048。如果策略已经把两者分得很开（ρ_w − ρ_l 很大），σ 趋于 0，这一对几乎不再产生梯度：DPO 自动把注意力放在还没分开的那些对上。

**手算 GRPO 的系数**：一组 4 个回答，奖励 1、0、0、1。组均值 0.5，无偏标准差 √((4 × 0.25) / 3) ≈ 0.577（`group_advantages` 用的是无偏标准差）。优势 ±0.5 / 0.577 ≈ ±0.866：读对的两个回答的每个 token 乘 +0.866，读错的两个乘 −0.866。如果 4 个回答的奖励全相同，优势全为 0，这组题对梯度没有贡献（第 31 章）。

### 预算：同样一步，算的量不同

第 2 部分按场景文字任务的实测长度（序列平均 121.7 个 token，其中 64 个视觉 token，回答平均 4.7 个 token）估算了每种方法一步的计算量。约定：反向 ≈ 2 次前向；生成每个 token 是一个 token 的前向（KV cache）：

```
继续 SFT（批 32）                         11,686   是继续 SFT 的  1.0 倍
RFT（采 32 × 4，SFT ≤ 32 条）             27,267   是继续 SFT 的  2.3 倍
DPO 离线（16 对）                         15,581   是继续 SFT 的  1.3 倍
DPO 在线（16 对，每步采 16 × 4）          23,371   是继续 SFT 的  2.0 倍
GRPO（8 题 × 8，μ = 2）                   70,114   是继续 SFT 的  6.0 倍
```

再实测一次采样和一次训练的耗时（随机权重、同样结构的 VLM，CPU）：

```
64 条回答各生成 5 个 token 用 138 毫秒；同样 64 条完整序列的一次前向 + 反向用 359 毫秒；比值 0.38，按 token 数估算的比值 0.33
```

估算和实测接近，采样稍贵一些（逐个 token 生成、每一步都有固定开销）。回答越长，这个差距越大：生成是串行的，训练的前向是并行的。

**所以"同样训练 200 步"对四种方法并不公平**：GRPO 一步的计算量是继续 SFT 的 6 倍。报告结果时要说清楚用的是哪种口径：

- **相同的优化器步数**：每种方法都更新 200 次。比较的是"每次更新的质量"；
- **相同的计算量**：给每种方法同样多的 token 次前向。GRPO 只能更新约 1/6 的次数；
- **相同的样本数**：每种方法都看同样多的题目。

三种口径的结论可以完全不同。第 5 部分用相同的步数，记录表里请你也记下用时，自己换算成另外两种口径。

## 32.9 常见错误

| 错误 | 症状 | 原因与修正 |
|---|---|---|
| 只评测训练的任务 | 以为模型全面变好了 | 每次都评测没训练的任务，或者算探测 KL |
| 在同一个学习率下比较不同的更新方式 | "LoRA 忘得少"之类的错误结论 | 各自扫学习率，比前沿 |
| 重放比例只按样本算 | 旧任务（回答长）实际占了大部分梯度 | 说清楚按样本还是按 token，必要时按 token 配比 |
| 重放用的是测试集的样本 | 遗忘看起来很小 | 重放用训练数据，评测用测试集，两者不重叠 |
| 不同方法用不同的评测设置（比如采样 vs 贪心） | 差别来自评测而不是方法 | 所有方法用同一套评测（第 25 章的评测协议） |
| 只报告"相同步数"的结果 | 忽略了 GRPO 一步的计算量是 SFT 的几倍 | 同时报告用时或计算量 |
| 单个种子下的小差别当作结论 | 结论换个种子就反过来 | 多个种子，或者只报告数量级的差别 |

## 32.11 深入一步

### 遗忘的是"能力"还是"格式"

很多研究发现，微调后看起来丢失的能力，用很少的数据就能恢复，说明知识本身还在，只是"怎样把它表达出来"的方式被覆盖了。区分两者的一个办法就是选做题 6：少量数据的恢复实验。另一个办法是用似然打分（第 27 章）代替生成：如果模型给正确答案的似然仍然最高，只是生成时写成了别的格式，那它没有忘记这个知识。

### 稳定性与可塑性

"学新东西"（可塑性）和"不忘旧东西"（稳定性）是一对基本的矛盾，所有对策都是在两者之间找平衡。重放之所以有效，是因为它把"旧东西"也变成了"正在学的东西"，不再需要在两者之间取舍——代价是要有旧数据，并且要多算。

### 规模的作用

大模型通常比小模型遗忘得少（能同时容纳更多的能力），但这不意味着大模型不需要配比：真实的报告里，几十亿参数的模型在专门训练后仍然会在通用基准上掉分。

## 32.13 本章小结

1. 遗忘：在新任务上训练后，没训练的任务变差。测法：没训练的任务的指标、通用文本的困惑度、探测 KL；
2. 探测 KL 不需要标签，近似于"在起点模型擅长的数据上，困惑度的对数涨了多少"（第 3 部分：0.0374 vs 0.0438）；
3. 一次训练有两个结果，比较时用帕累托前沿；同一个学习率下的比较会误导（v2 的数据：LoRA 3e-4 看起来更保守，3e-3 却忘得最多）；
4. 遗忘和更新走了多远密切相关；四类对策：重放 / 配比、冻结 / LoRA、KL 约束、更小的更新；重放常常能把整个前沿往好的方向推；

## 参考答案

1. 任务指标：直接、可解释，但只能测想到的、有标签的任务。困惑度：只需要通用文字，但和具体任务能力不一定对应。探测 KL：不需要标签、任何输入都行、很便宜，但不区分变好和变坏（离起点远不一定是坏事），也不能告诉你哪个能力受损。
2. 困惑度的对数变化是 E_数据[log p_起点 − log p_新]；当起点模型很接近数据的分布时，它近似于 E_{p_起点}[log p_起点 − log p_新] = 探测 KL。如果起点模型离数据很远（比如探测的是它本来就不擅长的文字），或者新模型在这些数据上**变好了**（困惑度下降，KL 仍然为正），两者会差得很远。
3. A 和 B 在前沿上（互不支配）；C 被 A 支配（80 ≥ 75 且 60 ≥ 55）。
4. 同一个学习率对 LoRA 和全参数意味着不同大小的更新（LoRA 的有效更新小得多），所以"忘得少"可能只是"走得少"，新任务也学得少。要比的是"在学到同样多时谁忘得少"，也就是比前沿。v2 的数据里，LoRA 在 3e-3 时忘得比任何全参数的点都多。
5. 重放把旧任务也变成了正在训练的任务，不再需要在两者之间取舍；而且（在 v2 的实验里）额外的旧任务数据还起到了稳定训练的作用，新任务也学得更好。它的代价不是"新任务变差"，而是需要旧数据和更多的计算。
6. 当答案唯一时（场景文字），模型读对的回答和真值完全相同，RFT 等于"只在模型能读对的题上做继续 SFT"。答案不唯一时（描述、推理），RFT 学的是模型自己的写法，和标注者的写法不同；RFT 也学不到模型完全不会的题。
7. GRPO 一步要采样 64 个回答，再做多次前向和反向，计算量约是继续 SFT 一步的 6 倍。相同的步数下 GRPO 用了多得多的计算，对其他方法不公平；反过来，如果用相同的计算量，GRPO 只能更新约 1/6 的次数。
8. 用少量通用数据做恢复训练：恢复得很快说明遗忘的主要是格式；或者用似然打分代替生成：正确答案的似然仍然最高，说明知识还在。
9. round(0.3 × 32) = 10 条旧任务、22 条新任务。旧任务 10 × 30 = 300 个回答 token，新任务 22 × 5 = 110 个。按 token 平均时，旧任务占 300 / 410 ≈ 73% 的梯度份额：按样本 30%，按 token 73%。
10. 采样之后：old_logp 一次前向（1）、参考模型一次前向（1）、μ = 2 次"前向 + 反向"（每次 3，共 6）。β = 0、μ = 1：生成 64 × (117.0 + 4.7) = 7,789，加 64 × 121.7 × (1 + 3) = 31,155，共 38,944，是继续 SFT（11,683）的约 3.3 倍。（第 2 部分里继续 SFT 的数是 11,686，差别来自四舍五入的长度。）
11. 每三步中只有一步全是旧任务，其他两步全是新任务：模型在新任务的两步里照样被拉走，旧任务的那一步像是被拉回来，训练会来回震荡，而且每一步的梯度都只代表一种任务。重放应该在**每个批**里按比例混合（`mixed_batch`）。
12. mask 全为 1：视觉占位符、提示、补齐的位置都算进去了。补齐位置的输出没有意义，提示位置的分布和任务能力关系不大。应该只在回答的位置上算（第 4 部分用的是 `p["weights"] > 0`）。
