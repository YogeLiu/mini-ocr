# TexPixel 项目

**题目：基于 VLM 的公式图片转 LaTeX：评测、微调与错误分析。**

这个目录只放说明和空白模板。你自己的数据、脚本、结果和写好的报告放在别处（见“目录建议”）。

开始时只盯一类主要错误，例如分式或上下标。后面再扩展到矩阵、长公式或混有中文的文本。

## 怎么走

1. 第 0 章定尺子：建评测集，跑基线，交 M0。
2. 第一部分学训练和实验方法，然后写数据提案 R1。
3. 第二部分从零训练 LaTeX 语言模型，交 M1。
4. 第三部分在 OCR 后纠错任务上比较提示、SFT/LoRA、DPO、GRPO，写中期报告 R2。
5. 第四部分看图：第 31 章从零写小公式 OCR，交 M2；第 33 章微调真实 VLM，写 R3；第 36 章写最终报告 R4。

每份交付只回答一个问题：比起上一步，这一步的改动带来了什么，花了多少钱，证据够不够。

## 数据状态

| 用途 | 来源 | 状态 |
|---|---|---|
| 验证集、测试集、微调数据 | TexPixel 中你有权使用的样本 | **待你确认数量和使用权** |
| LaTeX 语料（第二部分） | OleehyO/latex-formulas 的 `cleaned_formulas`，约 55 万条，只用公式文本；由 `miniocr/data/latex_corpus.py` 分组划分（latex-v1） | 许可 openrail，来源 arXiv 与 im2latex-100K；只在本地使用，不分发 |
| OCR 后纠错（第三部分） | 在干净公式上人工加噪：`postcorrect-v1`（18.1.3 节） | 合成数据，和真实 OCR 错误有差距，报告里要写明 |
| 主训练集（第 31 章及以后） | 开源公式图片数据集的原图（latex-v1 划分）；LaTeX 渲染的合成数据是可选实验 | 开源数据，不是 TexPixel 数据 |

**使用权由你自己确认。** 按 0.10.2 节，每张图都要说得清从哪里来、凭什么能用，说不清的不放进来。

**确认之前，不要把任何真实图片或标签放进仓库。** 这段时间可以照常做：

- 第 0 章 lab 第 1–5 节的演示集实验；
- 第二到第四部分用开源数据和合成数据的实验。

M0 的正式步骤（第 0 章 lab 第 6 节）要等确认以后才开始，时间表上的 M0 跟着后移。还没有 TexPixel 数据时，R1 把这一项写成“待确认”，其他报告写清实际用的是哪份数据。开源数据或合成数据上的结果，不能写成 TexPixel 的结果，也不能和 TexPixel 上的成绩直接比（31.9 节）。

## 评测代码

评测脚本由你在 M0 里自己搭（第 0 章 lab 第 6 节），指标不用重写，直接调用 `miniocr/eval/`：`metrics.py`（CER、完全匹配等）、`latex_norm.py`（规范化）、`render.py`（可编译率、渲染一致率）、`analysis.py`（区间和配对比较）。文本后纠错用 `postcorrect_eval.py`。

## 对照实验的规则

### 比较的条件

- 同一个验证集、同一个测试集、同一个评测脚本。
- 每个结果都记录模型版本、图片处理、提示词、生成参数、随机种子。
- 一次只改一个变量。同时改了几个，就写明混杂（5.7 节、27.8 节）。
- 事先写下预测，再运行（13.5.7 节）。
- 两个方案比较时，在同一批样本上逐条配对（22.3 节）。

### 验证集和测试集

规则以 0.10.1 节为准：

- **验证集**用来做决定：调参、选模型、看错例、提假设，都在这里做，可以反复用。
- **测试集**是留出集：选型冻结后，预先登记的候选可以各评一次，只报告数字和置信区间，不据此改任何设置。
- 开发期不看测试集的错例。最终报告定稿后，才可以解封做错例分析。
- 如果已经根据测试集改了设置，在报告里写明，并补一份新的、从来没看过的测试集。

每份报告都要有一张“测试集使用记录”，写明登记了哪些候选、何时评的、是否依据结果改过设置。

### 指标

按 0.9.3 节声明面板，不要只报一个数：

| 交付 | 任务 | 面板 |
|---|---|---|
| M0 | 图片 → LaTeX | OCR 主任务面板：完全匹配（规范化后）、CER_token、CER（按字符）、可编译率、渲染一致率（同时报能判断的样本数） |
| M1 | 生成 LaTeX | bits/byte 和可编译率（mathtext 近似，13.9 节），不用 OCR 面板 |
| R2 | 带噪 LaTeX → LaTeX | 文本后纠错面板：EM_norm、CER、改坏、fix_rate；parse_rate 只作诊断，要和标准答案的可解析率一起读 |
| M2、R3 | 图片 → LaTeX | OCR 面板的精简版：EM_norm、CER、parse_rate，可另列 EM_raw、截断条数 |
| R4 | 全部方法 | 按任务分两张表，分别用文本后纠错面板和 OCR 精简版，不跨表排名（36.9.1 节） |

比例用 Wilson 区间，CER 用 bootstrap 区间，两个方案的差用配对区间（22.2、22.3、31.6 节）。

评测协议可以根据验证集错例升级：规则升级版本号，所有候选用新版重算，最终测试另行安排，不和旧协议下的数字混比（0.10.5 节）。已经冻结的结果不改。

### 数字的来源

报告里每个数字都标来源：

| 标签 | 含义 | 要写什么 |
|---|---|---|
| 数学结论 | 可以从公式或别的数字算出来 | 公式，或算式 |
| 本项目观察 | 你在自己的设备上实测的 | 设备、脚本、输出文件 |
| 论文报告 | 作者写的，你没有复现 | 论文、版本、表号或节号 |
| 待验证 | 来自文档或估算，还没实测 | 打算怎样验证 |

作业和里程碑的门槛都待校准。门槛由你第一次完整训练后只依据验证集确定，写在评测试集之前。
