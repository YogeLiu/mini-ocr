# 第 35 章 蒸馏与合成数据

## 本章导读

到第 34 章为止，我们改进模型靠的都是人给的标签：SFT 用参考答案，GRPO 用参考答案算奖励。可是参考答案很贵。如果手边有一个更强的模型，能不能让它来出题、写答案，再拿这些答案去教一个小模型？

这就是**蒸馏**（distillation）。强模型叫**教师**（teacher），小模型叫**学生**（student）。教师造出来的标签叫**伪标签**（pseudo label），用伪标签拼成的训练集是**合成数据**（synthetic data）的一种。第 36 章的技术报告里也能见到这一步：PaddleOCR-VL 让大模型修正伪标签，Xiaomi-OCR-0 用多个专家的共识造标签。

先说结论：

1. **蒸馏有两种。**一种只用教师写出来的答案当标签，叫**序列级蒸馏**；另一种对齐教师在每个位置上的整个概率分布，叫 **logit 级蒸馏**。后者信息更多，但要求教师和学生用同一张词表。本章的教师 Qwen3-VL-2B 和学生 SmolVLM-256M 词表不同，所以真实实验只能做序列级。
2. **教师不可靠，质检是必需品。**我们的教师在 192 张训练图上 EM_norm 只有 0.094；一套规则质检后剩 109 条，通过的这部分 EM_norm 升到 0.138，CER 从 0.138 降到 0.094（本项目观察，见 35.8 节）。质检有用，但通过的标签里大多数仍和参考不完全一致。
3. **本章的两轮实验都是负结果。**主实验里，学生训练 600 步后，"只用原始数据"和"加入蒸馏数据"两组的 val EM 都是 0，CER 分别是 0.926 和 1.035；val 选中原始组，test 上 EM 0、CER 0.931（本项目观察，RTX 4090（租用），64 条，seed 35）。补充实验把原始图放大到 5000 张，教师换成第 33 章微调后的模型，每组训 3000 步，跑两个种子，四组 val EM 仍只有 0/500 或 1/500，CER 都在 0.84 以上；蒸馏组在种子 35 上明显更差，在种子 36 上分不出差别（本项目观察，val 500 条，35.8.8 节）。学生还没学会读公式，EM 处在地板上；CER 能区分部分设置（如种子 35），但差异不跨种子稳定，而且两臂还改了数据组成和曝光，所以不能单独归因于标签质量。
4. **负结果也要会读、会写。**怎样判断是"方法没用"还是"信号不够"，怎样把结论说到恰好的程度，35.9 和 35.10 节专门讲。

学完本章，你能做到：

1. 区分序列级蒸馏和 logit 级蒸馏，写出两者的目标函数，说清各自需要什么、丢掉了什么。
2. 推导温度 T 下 KL 蒸馏的梯度，解释为什么要乘 T²，并在 3 个类别上手算一遍。
3. 说明教师和学生词表不同时，为什么不能逐位置算 KL。
4. 为伪标签设计规则质检（长度、截断、可解析、与参考的渲染比对），并说出它会放过什么、会误杀什么。
5. 分析教师的错误怎样传给学生，用"标签混合"的眼光解释学生学到了什么。
6. 设计"只用原始数据"对"加入蒸馏数据"的对照实验，指出哪些变量没有控制住。
7. 读一个负结果：先排除流程错误，再看指标有没有分辨率，最后看规模和信号够不够，写出恰好的结论。

> **回顾：KL 散度与温度（第 3 章）。**交叉熵 $H(q,p)=-\sum_k q_k\ln p_k$，熵 $H(q)=-\sum_k q_k\ln q_k$，两者之差是 KL 散度 $\mathrm{KL}(q\Vert p)=\sum_k q_k\ln(q_k/p_k)\ge 0$（3.5.4 节）。$q$ 固定时，最小化交叉熵和最小化 KL 是一回事。softmax 的输入除以一个数 $T$（温度）：$T$ 越大分布越平，$T$ 越小越尖。对 logits 求交叉熵的梯度是 $\partial H/\partial z=p-q$（3.6 节）。KL 不对称，$\mathrm{KL}(q\Vert p)\neq\mathrm{KL}(p\Vert q)$，第 3 章的习题 H5 算过一次。
>
> **回顾：配对比较（第 22、34 章）。**两个模型在同一批题上比较时，EM 用 McNemar 检验，只看一个对、一个错的不一致对（22.3.8 节、34.8.3 节）；CER 用配对 bootstrap，每次重抽同一组题，分别算两个模型的 CER 再取差（22.3 节）。区间重叠不等于没有差别（22.3.1 节）。

## 35.1 本章的实验在做什么

整个实验是一条流水线，五步，对应 tour 的五个部分：

```text
部分 1  KL 机制演示     同词表的随机 logits，验证 masked_kl 的实现（不涉及真实模型）
部分 2  教师造标签     Qwen3-VL-2B-Instruct 读 192 张训练图，写出 LaTeX
部分 3  规则质检       长度 / 截断 / 可解析 / 与训练参考的渲染比对 → 109 条通过
部分 4  学生对照       SmolVLM-256M + LoRA，两组：
                         original：256 张图 + 人工参考标签
                         distill ：同样 256 张 + 109 张图的教师标签
                       各训练 600 步，在同一个 64 条 val 上评
部分 5  冻结与 test    只按 val 选一组，只登记这一组，评一次 test
```

主实验之后还有一轮放大规模的补充实验（35.8.8 节），只用 val，没有再评 test。

几个设计要点，后面各节会展开：

- **教师没看参考答案。**它只看图片和一句固定的提示（lab 第 2 节）。
- **教师的图被故意弄模糊了一点。**训练图先缩到 0.75 倍再放回原尺寸，模拟"教师面对的图比较差"。这一点会成为对照实验里没控制住的变量之一（35.7 节）。
- **质检用到了训练集的参考标签。**所以这是"有参考的标签增强"实验，不能冒充"完全无标注的蒸馏"（35.5 节）。
- **两组的总步数相同。**distill 组多出来的数据不是"白送"的，它挤掉了一部分原始数据的曝光次数（35.6 节）。

教师是**零样本**的 Qwen3-VL-2B-Instruct，没有加载第 33 章的 LoRA 适配器（本项目观察，`runs/teacher/teacher.json` 里只有基座快照，没有适配器路径）。第 33 章测过它的零样本 val EM_norm 是 5/100，LoRA 后是 10/100。它比学生强得多，但离"可靠"还很远。

**本章用的面板。**本章用第 0 章 0.9.3 节 OCR 主任务面板的精简版：正文的表列 EM_norm、CER、parse_rate 和截断条数，评测 JSON 里另有 EM_raw。面板里的渲染一致率和 CER_token 本章没有报告，因为 `score_postcorrect` 只按字符算 CER、只调用 `can_parse`、不比较渲染图。35.5 节的渲染比对只用来筛选训练用的伪标签，比的是训练参考和教师输出，不是这个面板指标。

## 35.2 两种蒸馏：序列级与 logit 级

### 35.2.1 动机

教师读完一张图，手里其实有两样东西：

1. **它写出来的那串 LaTeX。**比如 `x^{2}+1`。
2. **它在每个位置上的"犹豫"。**写第二个 token 时，它可能 80% 想写 `^`、15% 想写 `_`、5% 想写别的。

第一样东西是一个答案；第二样东西是一整张概率表。用哪一样来教学生，就是两种蒸馏的分界线。

### 35.2.2 直觉：抄答案，还是抄思路

想象你在跟一位学霸学数学。

- **抄答案**：学霸把每道题的最终答案给你，你照着记。这就是**序列级蒸馏**。简单，什么人都能给，但你看不到他在哪里犹豫过。
- **抄思路**：学霸告诉你"这一步我 80% 觉得该这样走，15% 觉得该那样走"。这就是 **logit 级蒸馏**。信息多得多，连"错误答案之间谁更像对的"都告诉你了。Hinton 等人把这些小概率里的信息叫作**暗知识**（dark knowledge）。

代价也很清楚：抄思路要求你们**用同一种语言记笔记**。学霸说"第 3 号选项 15%"，你得知道他的第 3 号就是你的第 3 号。这件事在 35.4 节会成为真问题。

### 35.2.3 推导

记输入为 $x$（这里是一张公式图加提示），输出序列为 $y=(y_1,\dots,y_L)$。教师给出分布 $q(\cdot\mid x)$，学生给出 $p_\theta(\cdot\mid x)$。

**最理想的目标**是让学生的整句分布贴近教师的整句分布：

$$
\mathcal L_{\text{seq-KL}}(\theta)=\mathrm{KL}\big(q(\cdot\mid x)\,\Vert\,p_\theta(\cdot\mid x)\big)
=\underbrace{\sum_{y} q(y\mid x)\ln q(y\mid x)}_{\text{与 }\theta\text{ 无关}}\;-\;\sum_{y} q(y\mid x)\ln p_\theta(y\mid x).
$$

第一项是教师分布的负熵，不依赖 $\theta$，丢掉。剩下的是整句交叉熵：

$$
\mathcal L(\theta)=-\sum_{y} q(y\mid x)\ln p_\theta(y\mid x).
$$

麻烦在于求和：$y$ 是所有可能的 token 序列，数量随长度指数增长，不可能逐个枚举。两种蒸馏是对这个求和的两种近似。

**近似一：只留教师最可能的那一句（序列级）。**Kim 和 Rush（2016）的做法是用教师的 beam search 或贪心解码结果 $\hat y$ 代替整个分布，即令 $q(y\mid x)\approx\mathbb 1[y=\hat y]$：

$$
\mathcal L_{\text{seq}}(\theta)\approx-\ln p_\theta(\hat y\mid x)=-\sum_{t=1}^{L}\ln p_\theta(\hat y_t\mid \hat y_{<t},x).
$$

第一个约等号是把指示函数代进上一式：除了 $y=\hat y$ 那一项，其余各项的权重都是 0，求和只剩一项。第二个等号用链式法则把整句概率拆成逐位置条件概率的乘积，取对数后乘积变成求和。

这就是**把教师的输出当标签做 SFT**。和第 19、21、33 章的 SFT 完全一样，只是标签换成了教师写的。

$\hat y$ 只是众数的近似。贪心每一步取条件概率最大的 token，写出来的整句不一定是概率最高的那句：第 14 章 14.7.4 节的玩具模型里，贪心得到的句子概率 0.2268，最可能的整句是概率 0.30 的空公式；第 31 章 31.5.4 节的例子里是 0.20 对 0.36（数学结论）。beam search 搜得更广，同样不保证找到众数。

**近似二：逐位置对齐分布（logit 级）。**把整句分布按链式法则拆开，在一条给定的前缀（通常是参考答案或教师输出）上，逐位置要求学生的下一个 token 分布贴近教师的：

$$
\mathcal L_{\text{tok}}(\theta)=\sum_{t=1}^{L}\mathrm{KL}\big(q(\cdot\mid y_{<t},x)\,\Vert\,p_\theta(\cdot\mid y_{<t},x)\big).
$$

每一项都是一个 $|V|$ 维的 KL，$|V|$ 是词表大小。Kim 和 Rush 把它叫作 word-level KD。它保留了教师在每个位置上的全部概率，但只在一条前缀上看，没有覆盖教师可能走的其他路径。

两者的对比：

| | 序列级（伪标签） | logit 级（逐位置 KL） |
|---|---|---|
| 从教师拿什么 | 一串文本 | 每个位置的 $\lvert V\rvert$ 维 logits |
| 训练损失 | 普通交叉熵（SFT） | KL，通常带温度 T |
| 教师要不要在线 | 不用，生成一次存盘即可 | 训练时每步都要教师前向，或者事先存下巨大的 logits |
| 词表要求 | 无，文本可以重新分词 | 必须相同（35.4 节） |
| 能闭源 API 当教师吗 | 能 | 一般不能，API 通常不给完整 logits（待验证，取决于服务） |
| 丢掉的信息 | 教师的犹豫、次优答案 | 教师在其他前缀上的行为 |

### 35.2.4 数字例子：三句话的玩具分布

假设对某张图，所有可能的输出只有三句。下面把每一句当成一个类别来算，这是**整句分类**的教学模型，不涉及逐 token 生成。教师和学生的分布是：

| 句子 | 教师 $q$ | 学生 $p$ |
|---|---|---|
| `x^2` | 0.6 | 0.2 |
| `x_2` | 0.3 | 0.5 |
| `x2` | 0.1 | 0.3 |

**完整的整句交叉熵**：

$$
-(0.6\ln 0.2+0.3\ln 0.5+0.1\ln 0.3)=0.6\times1.6094+0.3\times0.6931+0.1\times1.2040=1.2940
$$

（数学结论）。减去教师的熵 $H(q)=0.8979$，KL 是 0.3961（数学结论）。

**序列级近似**：只留教师最可能的一句 `x^2`，损失只有一项 $-\ln 0.2=1.6094$（数学结论）。它只把学生往 `x^2` 推，完全不管 `x_2` 和 `x2` 之间谁更像。

现在换一个教师：它把概率给成 0.3 / 0.6 / 0.1，最可能的一句变成了**错的** `x_2`。序列级蒸馏会让学生只学 `x_2`；logit 级蒸馏至少还会告诉学生"`x^2` 也有 0.3"。教师留下的那一句错了，学生在这张图上收到的监督就全是错的，35.6 节接着讨论这种错误怎样传递。

### 35.2.5 对照代码

序列级蒸馏在代码里几乎看不见，因为它就是换了标签的 SFT。`tour.py` 的 `training_pool` 把两种来源的数据拼进一个池子：

```python
pool=[dict(r,label=r["target"],scale=1.,origin="original") for r in base]
if args.arm=="distill":
    ...
        if r["accepted"]: pool.append(dict(r,label=r["pred"],origin="teacher"))
```

`label` 字段要么是参考答案 `target`，要么是教师的预测 `pred`。之后的 `encode` 和训练循环对两种来源一视同仁：用学生自己的 processor 把 `label` 重新分词，用 `answer_labels` 遮掉提示，只在答案和 EOS 上算交叉熵（这一步和第 33 章 33.2 节的 label mask 是同一件事）。

logit 级蒸馏对应 `masked_kl`，35.3 节逐行讲。

### 35.2.6 常见错误

- **以为序列级蒸馏"不是蒸馏"。**它丢掉了教师的概率，但它确实在近似整句 KL。第 36 章 PaddleOCR-VL 的"自动标注"就属于这一类。
- **把教师的采样输出和贪心输出混用。**采样一次得到的是 $q$ 的一个随机样本，贪心或 beam 得到的是（近似）众数。两者都是合法的近似，但含义不同，报告里要写清用的是哪一种。本章教师用贪心（lab 第 2 节）。
- **以为 logit 级总比序列级好。**Kim 和 Rush 在机器翻译上报告过序列级蒸馏优于逐词蒸馏（论文报告，见 35.16 节精读），原因之一是学生不必去拟合教师在每个位置上的长尾概率。哪个更好要实测。

## 35.3 温度与 T²：logit 蒸馏的推导

### 35.3.1 动机

教师训练得越好，它的分布就越尖。比如它对某个位置给出 [0.97, 0.02, 0.01]，几乎就是 one-hot。用这样的分布去教学生，和直接给 one-hot 标签差别不大，暗知识被埋在 0.02 和 0.01 里，几乎不产生梯度。

Hinton 等人的办法是**升温**：教师和学生的 logits 都除以 $T>1$ 再做 softmax，把分布摊平，让小概率"浮上来"。但升温会带来一个副作用：梯度变小了。T² 就是用来补这个副作用的。

### 35.3.2 直觉：调亮暗部

把教师的分布想成一张照片。$T=1$ 时亮的地方很亮，暗的地方几乎全黑。升温就像调高"暗部亮度"，暗处的细节（次优选项谁比谁更可能）露出来了。

可是整张照片也变灰了：教师和学生的分布都更平，两者之间的差距也被压小，学生收到的纠正力度跟着变弱。乘 $T^2$ 就是把纠正力度调回原来的量级。

### 35.3.3 推导

记教师 logits 为 $v$，学生 logits 为 $z$，都是 $C$ 维。温度 $T$ 下：

$$
q_i=\frac{e^{v_i/T}}{\sum_j e^{v_j/T}},\qquad p_i=\frac{e^{z_i/T}}{\sum_j e^{z_j/T}}.
$$

蒸馏损失定义为

$$
\mathcal L_T=T^2\cdot\mathrm{KL}(q\Vert p)=T^2\sum_i q_i\big(\ln q_i-\ln p_i\big).
$$

**第一步：对学生 logits 求梯度。**$q$ 不依赖 $z$，所以只有 $-\sum_i q_i\ln p_i$ 这一项有梯度。第 3 章 3.6 节推过：交叉熵对 softmax 输入的梯度是 $p-q$。这里 softmax 的输入是 $u=z/T$，先对 $u_j$ 求导得 $p_j-q_j$，再乘 $\partial u_j/\partial z_j=1/T$，链式法则多出一个 $1/T$：

$$
\frac{\partial}{\partial z_j}\Big(-\sum_i q_i\ln p_i\Big)=\frac1T\,(p_j-q_j).
$$

乘上 $T^2$：

$$
\boxed{\;\frac{\partial\mathcal L_T}{\partial z_j}=T\,(p_j-q_j)\;}
$$

**第二步：看 $T$ 很大时会怎样。**$T$ 很大时 $v_i/T$ 很小，用 $e^u\approx1+u$：

$$
q_i\approx\frac{1+v_i/T}{C+\sum_j v_j/T}.
$$

再假设每个样本的 logits 均值为零（$\sum_j v_j=\sum_j z_j=0$，softmax 对整体平移不变，总能这样假设），分母里的 $\sum_j v_j/T$ 就是 0，得到 $q_i\approx\frac1C(1+v_i/T)$，$p_i$ 同理，$p_i\approx\frac1C(1+z_i/T)$。两式相减，$\frac1C$ 那一项抵消：

$$
p_j-q_j\approx\frac{z_j-v_j}{C\,T},\qquad\frac{\partial\mathcal L_T}{\partial z_j}=T(p_j-q_j)\approx\frac{z_j-v_j}{C}.
$$

两个结论（数学结论，Hinton et al. 2015 第 2.1 节）：

1. **高温下 $p-q$ 本身大约按 $1/T$ 缩小**，再乘链式法则的 $1/T$，不加修正的 KL 梯度大约按 $1/T^2$ 缩小。乘 $T^2$ 把这部分抵消，让梯度量级大致不随温度变化。注意这是高温近似：不加修正的精确梯度是 $(p-q)/T$，而 $p$、$q$ 本身也随 $T$ 变，所以换温度时各分量不会统一缩小同一个倍数（35.3.4 节的表里能看到）。只有在同一个 $T$ 下比较“乘与不乘”，两者才精确相差 $T^2$ 倍。
2. **高温极限下，KL 蒸馏退化成"让学生 logits 逼近教师 logits"的平方损失**，梯度 $\frac1C(z-v)$ 正是 $\frac{1}{2C}\lVert z-v\rVert^2$ 的梯度。损失值本身也趋近 $\frac{1}{2C}\lVert z-v\rVert^2$（logits 先减去各自的均值），35.3.4 节的例子里能看到这个趋势。

实际训练里，蒸馏损失往往和普通交叉熵加权混合：

$$
\mathcal L=\alpha\,\mathrm{CE}(y,\,p^{(T=1)})+(1-\alpha)\,T^2\,\mathrm{KL}(q^{(T)}\Vert p^{(T)}).
$$

如果忘了 $T^2$，在同一个温度下，第二项的梯度就精确地小了 $T^2$ 倍，调高温度就等于悄悄压低了它的权重，$\alpha$ 的含义跟着变了。乘上 $T^2$，两项的相对量级大致不随 $T$ 漂移，调 $T$ 时 $\alpha$ 不至于需要大幅重调；但升温也改变了分布的形状，换温度后 $\alpha$ 仍值得在验证集上复查一下。

一个容易忽略的细节：**如果只用 KL 一项、优化器是 Adam，乘不乘 $T^2$ 对更新的影响很小。**Adam 用梯度的二阶矩做归一化，整体乘一个常数，分子分母一起放大，更新几乎不变（数学结论，忽略 $\epsilon$ 项）。$T^2$ 起作用的场合是和别的损失相加，或者用 SGD 这类对梯度尺度敏感的优化器。

**方向。**这里用的是 $\mathrm{KL}(q\Vert p)$，教师在前，叫**前向 KL**。它在 $q_i>0$ 而 $p_i\to0$ 的地方惩罚极重，逼学生"把教师认为可能的都照顾到"，所以叫 mode-covering（覆盖众数）。反过来的 $\mathrm{KL}(p\Vert q)$ 叫反向 KL，学生可以只盯住教师的一个众数，叫 mode-seeking。两者都合法，结果不同，35.11 节的 GKD 就是在两者之间插值。

两个名字的来历，逐项看一眼就清楚。前向 KL 的每一项是 $q_i\ln(q_i/p_i)$：教师给了 $q_i>0$ 的类别，学生的 $p_i$ 越接近 0，这一项越大，$p_i\to0$ 时趋于无穷，所以学生不敢漏掉教师的任何一个可能选项。反向 KL 的每一项是 $p_i\ln(p_i/q_i)$：学生自己给 0 概率的类别，这一项也趋于 0（$p\ln p\to0$），漏掉教师的某个众数不会招来无穷大的惩罚。代价仍然有，但只来自其余类别：比如教师 $q=(0.5,0.5)$，学生 $p=(1,0)$，反向 KL 是 $\ln2\approx0.693$，有限，而前向 KL 是无穷大（数学结论）；反过来，学生在教师认为几乎不可能的地方放概率，$q_i\to0$ 会让这一项很大。所以反向 KL 下，学生宁可只押教师的一个众数，也不往教师的低概率区放东西。还要注意一点：学生如果能精确取到 $p=q$，两种 KL 的最小值都是 0，结果一样；只有学生表达能力不够、取不到 $p=q$ 时，两种方向才会把学生推向不同的折中。

### 35.3.5 对照代码

`miniocr/train/distill.py` 的 `masked_kl`：

```python
def masked_kl(student, teacher, mask, temperature=2.0):
    if temperature <= 0 or student.shape != teacher.shape or mask.shape != student.shape[:-1]:
        raise ValueError("temperature/shape invalid; vocabulary must be identical")
    s = torch.log_softmax(student.float() / temperature, -1)
    t = torch.log_softmax(teacher.detach().float() / temperature, -1)
    terms = (t.exp() * (t-s)).sum(-1)
    weights = mask.to(terms.dtype)
    return (terms * weights).sum() / weights.sum().clamp_min(1) * temperature**2
```

逐行对照推导：

- **形状。**logits 是 `[B, L, V]`，mask 是 `[B, L]`。形状检查只能挡住"维度不一样"，挡不住"维度一样但含义不一样"（35.4 节）。
- **`.float()`。**bf16 下做 log-softmax 精度不够，先转 fp32（第 3 章 3.3 节的数值稳定问题）。
- **`teacher.detach()`。**教师不参与训练。如果传进来的教师 logits 带着计算图（比如教师前向时忘了 `no_grad`），不 detach 的话反向传播会一路流进教师，教师的参数会算出梯度，白白多一份反向计算和显存。要让教师参数被改动，还得把它们放进执行更新的优化器；tour 部分 1 的优化器只有 `[student]`，所以那里的教师不会变。但梯度流进教师本身就是浪费，也容易在别处被误更新，所以要切断。测试 `test_kl_matches_distribution_definition_and_detaches` 专门检查 `t.grad is None`。
- **`t.exp() * (t-s)`。**这就是 $q_i(\ln q_i-\ln p_i)$，在最后一维求和得到每个位置的 KL。用 log 形式算，避免 $q_i\to0$ 时 $0\cdot\ln0$ 出 nan。
- **mask 和分母。**只在答案位置上算，分母是有效 token 数 `weights.sum()`，不是 `B*L`。`clamp_min(1)` 让全被遮掉的批次返回 0 而不是 nan（`test_empty_mask_and_equal_logits`）。
- **`* temperature**2`。**就是推导里的 $T^2$。

tour 部分 1 用 8×6 个位置、11 个类别的随机 logits，前两个位置遮掉，$T=2$，用 Adam 优化学生 50 步。实测损失从 0.4189 降到 0.00073，教师没有梯度（本项目观察，`runs/smoke/kl.json`，RTX 4090（租用），fp32，seed 35）。**这只说明实现是对的：同一词表下，学生能把教师分布拟合到几乎重合。**它不说明任何真实 VLM 学会了 OCR，lab 第 1 节也明确这样标注。

### 35.3.6 常见错误

- **忘了乘 $T^2$。**现象：调高温度后，蒸馏项的作用莫名其妙地变弱；和 CE 混合时最佳 $\alpha$ 随 $T$ 漂移。发现方法：固定 logits，打印不同 $T$ 下梯度的范数。
- **只给教师升温，学生不升温。**两边分布被摊平的程度不一样，KL 的最小值不再在 $z=v$ 处。测试里两边都除以同一个 `temperature`。
- **方向写反。**`F.kl_div(input, target)` 计算的是 $\mathrm{KL}(\text{target}\Vert\text{input})$，第一个参数要传**学生的 log 概率**。写反了就从前向 KL 变成反向 KL。本章代码不用 `F.kl_div`，直接写公式，避免这个坑。发现方法：用 3 类 logits 手算前向、反向两个值，和代码输出对照。
- **教师没有 detach。**现象是多一份反向计算和显存；教师参数如果也在优化器里，还会被更新。发现方法：断言 `teacher.grad is None`。
- **分母用 `B*L`。**提示越长、padding 越多，损失被稀释得越厉害，不同批次之间不可比。
- **评测时也用 $T>1$。**温度是训练时的工具。生成和评测按正常的 $T=1$（或贪心）进行。

## 35.4 词表不一致时为什么只能做序列级

### 35.4.1 动机

既然 logit 级蒸馏信息更多，为什么本章的真实实验不用它？因为本章的教师和学生用的是两套不同的词表：SmolVLM-256M 的词表大小是 49,280（本项目观察，本地缓存的 `config.json`），Qwen3-VL 的词表约 15 万（待验证，第 33 章 33.4 节按 151,936 估算，尚未对照其 config）。

### 35.4.2 直觉：两本编号不同的字典

逐位置 KL 要求"教师的第 $i$ 号 token"和"学生的第 $i$ 号 token"是同一个东西。两本字典编号不同，就好比教师说"我 15% 想选第 1234 号"，而学生字典里第 1234 号是另一个字。逐号比较毫无意义。

更糟的是，就算你能把字符串一一对上，**两边切词的位置也不一样**。

### 35.4.3 推导：两种对不齐

逐位置 KL $\sum_t\mathrm{KL}(q_t\Vert p_t)$ 隐含两个假设：

1. **坐标对齐**：对每个 $t$，$q_t$ 和 $p_t$ 定义在同一个集合 $V$ 上，第 $i$ 维代表同一个字符串。
2. **位置对齐**：第 $t$ 个位置在两边代表同一段文本。

两个词表不同时，两条都不成立。

**坐标不对齐**：$q_t\in\Delta^{|V_T|-1}$，$p_t\in\Delta^{|V_S|-1}$（$\Delta$ 表示概率单纯形），两个分布不在同一个空间里，KL 根本没有定义。就算 $|V_T|=|V_S|$ 恰好相等，第 $i$ 维的含义也不同，算出来的数字没有意义。

**位置不对齐**：同一串 `\frac{a}{b}`，一个分词器可能切成 `\frac`、`{a`、`}{`、`b}` 四段，另一个切成 `\`、`frac`、`{`、`a`、`}{`、`b`、`}` 七段（**示意**，不是这两个模型实际的切法）。教师序列长 4，学生序列长 7，"第 2 个位置"在两边分别是 `{a` 和 `frac`。

而**文本是两边唯一共享的接口**。教师生成文本，学生用自己的分词器重新切，然后做普通交叉熵，两条假设都不需要。所以在不做额外对齐工作的前提下，异构教师和学生之间能直接做的就是序列级蒸馏。

跨分词器的 logit 蒸馏不是不可能，但需要额外的对齐方法，把两边的分布映射到可比较的空间。TRL 的实验模块里有一个 GOLD 训练器，提供 `use_uld_loss` 等跨分词器选项（本项目观察：本地 trl 1.15.0 源码中存在这些配置项；具体算法与效果待验证）。本书不展开。

### 35.4.4 数字例子：词表大小不同时会发生什么

假设你硬把两边的 logits 截到同样长度再算 KL。Smol 有 49,280 维，取 Qwen 的前 49,280 维。形状对上了，`masked_kl` 不会报错；但 Qwen 的第 $i$ 号 token 和 Smol 的第 $i$ 号 token 毫无关系，你在强迫学生把概率放到一些随机字符串上。损失照样会下降，因为学生总能去拟合任何给定的分布，只是学到的东西对 OCR 毫无用处。

所以 tour 部分 1 只用"同词表的随机 logits"做演示：它验证的是机制，不涉及真实模型。

### 35.4.5 对照代码

`masked_kl` 的第一行：

```python
if temperature <= 0 or student.shape != teacher.shape or mask.shape != student.shape[:-1]:
    raise ValueError("temperature/shape invalid; vocabulary must be identical")
```

形状不同就报错（`test_empty_mask_and_equal_logits` 里用 7 维对 4 维验证过）。但请注意：**形状相同是必要条件，不是充分条件。**同一个模型家族的不同尺寸（比如同一系列的 0.5B 和 1.5B）通常共享分词器，这才是 logit 蒸馏的典型场景。TRL 1.15.0 的 `DistillationTrainer` 在初始化时也只比较两个模型的 `vocab_size`，不一致就报错，并提示去用 GOLD 做跨分词器蒸馏（本项目观察，本地源码 `trl/trainer/distillation_trainer.py`）。

### 35.4.6 常见错误

- **截断或补零让形状对上。**损失能降，学不到东西。上面讲过。
- **只比 `vocab_size`。**两个词表大小相同、内容不同时，大小检查发现不了。保险的做法是比较两个分词器把同一段文本切出来的 token id 是否一致。
- **序列级蒸馏时忘了重新分词。**教师输出要用**学生的** processor 和对话模板重新编码。本章 `encode` 对每个 `label` 都重新走学生的 `apply_chat_template`，`answer_labels` 还会检查提示前缀和完整序列是否对齐。

## 35.5 伪标签的质检

### 35.5.1 动机

教师会犯错。在本章的 192 张训练图上，零样本教师的 EM_norm 是 0.094（18/192），CER 0.138，有 15.1% 的输出 mathtext 解析不了（parse_rate 0.849），3 条写到 192 个 token 的上限被截断（本项目观察，`runs/teacher/teacher.json`）。

把这 192 条不加筛选地混进训练集，等于给学生发一本错误不少的参考书。质检就是在入库之前，把明显的坏标签挡在门外。

### 35.5.2 直觉：门卫只能查证件，查不了人品

规则质检像一个门卫。他能查"有没有证件"（非空）、"证件是不是被撕了一半"（截断）、"证件格式对不对"（能被解析）、"照片像不像本人"（和参考渲染出来的图像不像）。但他没法判断一个证件齐全、照片也挺像的人是不是真的好人。

所以质检有两种错：

- **放过坏标签**（假阳性）：能解析、渲染出来也差不多，但把 `\preceq` 写成了 `\leq`。
- **挡住好标签**（假阴性）：意思完全对，只是写法不同，渲染差异超过阈值；或者参考本身有问题。

### 35.5.3 推导：五步检查

`quality_check` 依次做五步（lab 第 3 节）：

1. **抽取公式**：去掉解释文字和定界符，得到 `pred`。
2. **长度**：$0<\mathrm{len}(\text{pred})\le384$。空输出和过长输出直接拒绝。
3. **未截断**：生成写到上限 `max_new_tokens` 的拒绝。截断的公式几乎一定是残缺的。
4. **可解析**：matplotlib 的 mathtext 能把它渲染出来。
5. **渲染比对**（仅当参考也能渲染时）：把参考和预测用同一个渲染器画成二值墨迹图，计算

$$
d=\frac{\lvert A\oplus B\rvert}{\lvert A\cup B\rvert},
$$

$A$、$B$ 是两张图上有墨迹的像素集合，$\oplus$ 是异或（只在一边有墨迹的像素）。$d\le0.65$ 通过。参考不能被 mathtext 渲染时，比对结果记为 **unknown**，不算失败也不算成功，标签保留。

最终：**长度合格、未截断、可解析，并且渲染比对不是"失败"**，才通过。

几个必须说清的边界：

- **第 5 步用到了训练集的参考答案。**真正无标注的场景里，你手里没有参考，这一步做不了。所以本章是"有参考的标签增强实验"，lab 第 3 节专门声明这一点。val 和 test 上从不做参考质检。
- **渲染比对比较的是"参考渲染图"和"预测渲染图"**，不是和原始 PNG 比。原图的字体、粗细、噪声和 mathtext 都不一样，直接比没有意义。
- **mathtext 只支持 TeX 数学的一个子集**（第 34 章 34.4 节讲过，`\begin{array}`、对齐符 `&` 等可能不支持）。"可解析"是"mathtext 能画"，不是"LaTeX 能编译"，更不是"写对了"。
- **0.65 是一个很宽的阈值。**它是有意设宽的，为的是保留一部分教师错误，好观察错误怎样传给学生（`quality_check` 的文档字符串里写明了）。

### 35.5.4 数字例子

**先算一个渲染差。**参考图有墨迹的像素 100 个，预测图 90 个，两者重合 70 个。只在参考上的 30 个，只在预测上的 20 个：

$$
d=\frac{30+20}{100+90-70}=\frac{50}{120}=0.417\le0.65\quad\Rightarrow\text{通过（数学结论）}.
$$

如果预测少画了一个大号求和符号，重合只剩 40 个、预测 60 个：$d=\frac{60+20}{100+60-40}=\frac{80}{120}=0.667$，刚好被拒。阈值附近的判定对"差了多大一块"很敏感，但对"差的是哪一块"毫无感知：漏一个求和条件和漏一个句号，可能得到相近的 $d$。

**再看本章的真实漏斗**（本项目观察，`runs/teacher/quality.json`；拒绝原因由同一文件逐条统计）：

| | 条数 |
|---|---|
| 教师输出 | 192 |
| 拒绝：只因渲染差 > 0.65 | 53 |
| 拒绝：只因不可解析 | 27 |
| 拒绝：不可解析且截断 | 1 |
| 拒绝：长度不合格且截断 | 1 |
| 拒绝：只因截断（可解析） | 1 |
| **通过** | **109** |
| 其中渲染比对为 unknown | 43 |

拒绝共 83 条。原因有重叠，所以"截断 3 条""不可解析 29 条"这样的分项不能直接相加。

`quality.json` 的汇总字段 `render_unknown` 是 73：它是"没有得到渲染比对结果"的条数，包括通过的 43 条，以及被拒的 30 条：其中 29 条因为长度不合格或不可解析，根本没进入比对；另 1 条可解析但被截断，它进入了比对，只是参考渲染不出来，结果是 unknown（`quality_check` 只在“有参考且预测可解析”时比对，并不按截断跳过；截断只影响最终是否通过）。所以这个 73 既不表示"73 条因无法判定被拒"，也不表示"73 个参考一定无法渲染"。

质检前后对比（本项目观察，`runs/teacher/quality.json` 的 `all_metrics` 与 `accepted_metrics`；拒绝子集由同一文件离线重算）：

| 子集 | 条数 | EM_norm | CER | parse_rate |
|---|---|---|---|---|
| 全部 | 192 | 0.094（18） | 0.138 | 0.849 |
| 通过 | 109 | 0.138（15） | 0.094 | 1.000 |
| 拒绝 | 83 | 0.036（3） | 0.189 | 未单列 |

质检确实把好标签往通过一侧集中：18 条完全正确的里有 15 条通过；通过子集的 CER 比拒绝子集低一半。但通过的 109 条里，有 94 条和参考在规范化后仍不一致（数学结论：109 − 15）。

这 94 条都是错的吗？不是。把固定前 6 条通过和前 6 条拒绝的样本逐条看过以后（`runs/teacher/audit.png`、`audit_samples.json`，本项目观察，非随机抽样，不能估计总体比例）：

- **真错被放过**：教师把上标 `+` 写成 `\dagger`、漏掉 `\max` 下的约束；漏掉求和条件 `(q,10)=1`。
- **写法差异被算成不一致**：`\mathrm{R}` 写成 `R`、少一个句末句点。
- **好标签被误杀**：参考开头有对齐符 `&`、末尾有句点，教师没写，渲染差 0.928 被拒。
- **数据本身有问题**：有一张原图里印着渲染出来的 `beginalign*1ex` 片段，参考也不正常。

再对比一下：教师的 EM_raw 只有 1/192，EM_norm 是 18/192（本项目观察，`teacher.json`）。教师的写法（空格、花括号的习惯）和参考很不一样，规范化抹掉了大部分差异。学生如果学教师的标签，也会学到这套写法。

### 35.5.5 对照代码

```python
def quality_check(raw, reference=None, *, max_chars=384, render_tolerance=.65, truncated=False):
    pred = extract_formula(raw)
    length_ok = 0 < len(pred) <= max_chars
    parses = can_parse(pred) if length_ok else False
    comparison = compare_render(reference, pred, tol=render_tolerance) if reference is not None and parses else {}
    match = comparison.get("image_match")
    accepted = length_ok and parses and not truncated and match is not False
    return dict(pred=pred, accepted=accepted, length_ok=length_ok, parses=parses,
                truncated=truncated, render_match=match, pixel_diff=..., render_reference=...)
```

- `parses = can_parse(pred) if length_ok else False`：长度不合格时不再尝试解析，`parses` 直接记 False。所以"长度不合格"的那 1 条也被算进了 29 条不可解析。
- `compare_render(...) if reference is not None and parses else {}`：预测不可解析时不做比对，`match` 是 None。
- `match is not False`：注意是 `is not False`，不是 `is True`。None（unknown）会通过。这是有意的设计：参考渲染不了不是教师的错。
- 返回值保留每条的理由和 `pixel_diff`，所以质检结果也是一份审计记录。`audit.png` 和 `audit_samples.json` 按固定前缀抽 6 条通过、6 条拒绝，不按教师对错挑选。

测试 `test_quality_rules_and_false_positive` 把门卫的盲区写成了断言：`quality_check('y', 'x', render_tolerance=1)` 会通过。阈值放到 1，任何可解析的错误都能过。

### 35.5.6 常见错误

- **把"通过质检"当成"正确"。**通过子集 EM_norm 只有 0.138。质检降低了错误率，不是消灭错误。
- **把 unknown 当成失败丢掉，或者当成正确。**两者都会改变数据分布。丢掉 unknown，会系统性地丢掉 mathtext 不支持的那类公式（矩阵、多行对齐），学生就更少见到它们。发现方法：按结构分桶统计质检前后的分布。
- **把截断样本从评测分母里删掉。**本章教师的 3 条截断保留在整体指标里。只评"没截断的"会让教师看起来更好。报告时单列截断数，并保留在分母里。
- **只看通过率，不看样本。**109/192 这个数字说不出放过了什么、误杀了什么。至少要固定前缀抽几条通过、几条拒绝，用眼睛看。
- **在 val/test 上用参考做质检。**那是用答案筛选考卷，评测就失效了。本章的 `training_pool` 会拒绝任何 `split != "train"` 的伪标签（`test_training_pool_prevents_overlap_and_nontrain`）。

## 35.6 教师错误的传递

### 35.6.1 动机

质检后还剩 94 条和参考不一致的伪标签。它们会怎样影响学生？学生会把它们原样背下来，还是会被"淹没"在原始数据里？

### 35.6.2 直觉：两个老师，一个学生

想象一个学生同时跟两位老师学写公式。张老师（人工参考）写 `\mathrm{R}`，李老师（教师模型）写 `R`。如果学生 70% 的时间跟张老师、30% 跟李老师，他会写哪个？

如果他只能交一个答案（贪心解码），他大概率写张老师的。但如果某类图片**只有李老师教过**，他就只会李老师那一套，包括李老师的错误。

### 35.6.3 推导：一个整句分类的教学模型

先做一个简化：把学生的输出当成一次**整句分类**，每句话是一个类别，学生给每一句一个概率。真实的生成是逐 token 进行的，这个模型只用来讲清标签混合的道理，它和逐 token 贪心的差别放在本小节最后说。

设某一类输入 $x$（比如"含有正体 R 的公式"）在训练中出现时，标签以概率 $1-w$ 来自参考 $y^{\mathrm{ref}}$，以概率 $w$ 来自教师 $y^{\mathrm{T}}$。这里上标 $\mathrm{T}$ 是 teacher 的缩写，和 35.3 节的温度 $T$ 无关。学生最小化期望交叉熵：

$$
\min_p\;\;-(1-w)\ln p(y^{\mathrm{ref}}\mid x)-w\ln p(y^{\mathrm{T}}\mid x).
$$

在 $p(y^{\mathrm{ref}})+p(y^{\mathrm{T}})\le1$ 的约束下，最优解是 $p(y^{\mathrm{ref}})=1-w$，$p(y^{\mathrm{T}})=w$（数学结论，和第 3 章"交叉熵在 $p=q$ 时最小"是同一件事）。手推一遍：分给其他句子的概率不降低损失，最优时两句的概率加起来是 1；记 $a=p(y^{\mathrm{ref}})$，则 $p(y^{\mathrm{T}})=1-a$，损失 $-(1-w)\ln a-w\ln(1-a)$ 对 $a$ 求导得 $-\frac{1-w}{a}+\frac{w}{1-a}$，令它为 0 解出 $a=1-w$（这是 $0<w<1$ 的情形；$w$ 取 0 或 1 时最优解落在端点，结果仍是 $a=1-w$）。也就是说，在这个模型里，一个足够强的学生会把标签的混合比例学成自己的输出分布。

交答案时，学生取概率最大的那一句，相当于多数票：

- $w<0.5$：学生写参考的写法；
- $w>0.5$：学生写教师的写法。

于是有三条推论：

1. **随机错误容易被稀释。**教师在不同图片上犯不同的错，每种错误的 $w$ 都很小，投票时被压下去。
2. **系统性错误最危险。**如果教师**每次**都把句末句点丢掉、都把 `\preceq` 读成 `\leq`，而这类图片的标签大多来自教师，$w$ 就会超过 0.5，学生把错误当成正确写法。
3. **只有教师覆盖的图片，$w=1$。**本章 distill 组的 109 张图只有教师标签，学生在这些图上学到的就是教师的输出，对错都照单全收。

这些推论要带着模型的限制读。真实的贪心不比较整句，而是逐 token 取最大，写出的句子不一定是整句众数（第 14 章 14.7.4 节、第 31 章 31.5.4 节）。只有两句候选时，学生在第一个分叉的 token 上看到的比例就是 $w$ 和 $1-w$，结论和整句模型相同。候选更多时，共用同一段开头的几种写法会在分叉处合计概率，贪心可能走进这条分支，所以推论 1 的"稀释"有条件：各种错误写法在和参考分叉的位置上，合计不能占多数。

此外，学生容量有限，学不到精确的混合比例；不同图片之间还会互相泛化。这个框架给出的是一个假设：伪标签里系统性的偏差比随机噪声更容易传给学生（待验证：本章实验没有单独检验）。

### 35.6.4 数字例子：本章的曝光账

两组都训练 600 步、每步累积 4 个样本，总曝光 2,400 次（数学结论）。实际分配（本项目观察，`runs/*/training.json` 的 `exposures`）：

| 组 | 训练池 | 原始数据曝光 | 教师标签曝光 |
|---|---|---|---|
| original | 256 | 2,400 | 0 |
| distill | 365 = 256 + 109 | 1,681 | 719 |

算几个比例（数学结论）：

- distill 组的教师曝光占 $719/2400=30.0\%$，和教师标签在池子里的占比 $109/365=29.9\%$ 一致，说明洗牌是均匀的。
- 原始数据在 original 组平均每张被看 $2400/256=9.4$ 遍，在 distill 组只有 $1681/256=6.6$ 遍。加入伪标签挤掉了约 30% 的原始数据曝光。
- 教师标签里，按规范化字符串和参考不一致的占 $94/109=86\%$。所以 distill 组约 $30\%\times86\%\approx26\%$ 的曝光，用的是和参考字符串不同的标签（其中有真错，也有只是写法不同的）。

再看错误传递诊断（本项目观察，`runs/*/error_transfer.json`；只用训练图，是诊断不是泛化指标）：从 94 条"通过质检但和参考不一致"的伪标签里按固定前缀取 12 条，让两组学生各读一遍：

| 组 | 完全复制教师输出 | 写对参考 |
|---|---|---|
| original | 0 / 12 | 0 / 12 |
| distill | 1 / 12 | 0 / 12 |

distill 组复制的那一条，参考是 `P(h_1\preceq X)-P(h_2 \preceq X)=P(h_1 \preceq X \preceq h_2)`，教师把三个 `\preceq` 都读成了 `\leq`，学生原样写出了教师的版本。这是一个语义错误，被宽松质检放过，又被学生在训练图上背了下来。

其余 11 条，distill 学生既没复制教师，也没写对，输出多半是不相干的结构，比如反复写 `\sum` 直到上限。所以这一轮实验里，学生的主要问题是还没学会读图，而不是学了教师的错。12 条的样本太小，1/12 也不能说明复制率是多少。

### 35.6.5 对照代码

`tour.py` 部分 4 的末尾：

```python
wrong=[r for r in json.loads((args.teacher_dir/"quality.json").read_text())["rows"]
       if r["accepted"] and normalize_latex(r["pred"])!=normalize_latex(r["target"])]
for r in wrong[:args.audit_n]:
    p=predict(args,model,processor,r,r["scale"])
    observations.append(dict(..., copies_teacher=normalize_latex(p["pred"])==normalize_latex(r["pred"]),
        correct=normalize_latex(p["pred"])==normalize_latex(r["target"])))
```

- 取的是"通过且不一致"的样本，按固定顺序取前 `audit_n` 条，不挑。
- 两组都读同样的 12 张图。对 original 组来说这些图没见过，对 distill 组来说是训练图。所以两组的复制率**不是可比的泛化指标**，只是"distill 组有没有背下教师的错"的线索。
- 用规范化后的完全一致判定"复制"。教师错得不完整、学生学了一半，这里统计不到；复制率为零也不代表教师没有造成更细的影响（lab 第 4 节）。

### 35.6.6 常见错误

- **只看伪标签的平均错误率，不看错误的结构。**同样 86% 不一致，系统性偏差和随机写法差异对学生的影响完全不同。
- **把"规范化不一致"全当成教师错误。**35.5 节的抽查显示，其中不少只是写法差异。
- **用同一个教师去评测学生。**学生学了教师的写法，教师当然觉得它好。第 36 章 36.7.4 节会在技术报告里遇到同样的问题。
- **忽略曝光被挤占。**加了伪标签后结果变差，可能只是原始数据看得不够，不一定是伪标签有毒。记录并报告 `exposures`。

## 35.7 对照实验的设计（概括）

第 22 章和第 33 章讲过对照实验的原则：同一个 val、同一个 test、同一个评测脚本，只按 val 选择；选型冻结后，预先登记的候选可以各评一次 test，不据此改任何设置（第 0 章 0.10.1 节）。本章登记的只有 val 选中的那一组。这里只列出本章特有的几点。

**控制住了的：**两组从同一个 SmolVLM 基座、同一个随机种子初始化 LoRA；rank 16、学习率 2e-4、600 个优化步、有效 batch 4、只在语言模型的 q/k/v/o 投影上挂 LoRA；val、test 和生成配置完全相同（lab 第 4 节）。

**没有控制住的：**distill 组相对 original 组同时改变了三件事。

1. **数据量**：训练池从 256 变成 365，原始数据曝光少了 30%。
2. **标签来源**：多出来的 109 条是教师写的，不是人写的。
3. **图片质量**：这 109 张图是教师读过的 0.75 倍降质图，学生训练时也用的是降质图。

所以就算 distill 组赢了，也不能说"赢在教师的知识"。要单独归因，需要更细的对照，例如"同一批图配人工标签"对"同一批图配教师标签"（lab 第 4 节提到可以追加，本轮没做）。

**选择规则事先固定**（`summarize.py`）：val 上 CER 最低者胜；CER 相同比 EM；再相同选 original。`selection.json` 记录选择结果和选中适配器的 SHA256。tour 部分 5 在评 test 前读取 `selection.json`，核对传入的适配器正是被选中的那一臂、SHA256 也一致，否则拒绝运行（有三类拒绝情况的测试）。锁只防止同一输出目录重复评测（`test_existing_final_lock_blocks_before_model_load`）。本章的 test 数字产生于这项检查加入之前，当时"先选择后测试"靠 `finish_gpu.sh` 的执行顺序保证。

|---|---|---|---|---|
| original | 0/64 | 0.926（0.836～1.032） | 0.422（0.309～0.544） | 11 |
| distill | 0/64 | 1.035（0.925～1.167） | 0.594（0.471～0.705） | 16 |

按事先固定的规则，CER 低者胜，**选中 original**（`runs/selection.json`）。

三个观察：

- **EM 都是 0。**64 条里一条都没写对。
- **CER 都接近或超过 1。**CER 可以大于 1：它是"编辑次数 / 参考字符数"，学生写出一长串无关内容时，插入操作的次数会超过参考的长度。distill 组的 16 条截断，就是 16 条写到 192 个 token 才停的输出。
- **distill 组 parse_rate 更高、CER 更差。**一个可能的解释是：教师标签全都通过了"可解析"检查，学生学到了"写得能被解析"这个性质，但没学到"写得对"（待验证：区间重叠，单种子，不足以下结论）。这和第 34 章"parse_rate 升、CER 也升（变差）"的背离相似：训练里强调什么，学生就可能往哪边走。

### 35.8.5 选中组的 test（64 条）

选中的 original 组：EM_norm 0/64，CER 0.931（95% bootstrap 0.833～1.052），parse_rate 0.516，截断 10（本项目观察，`runs/final/final_test.json`）。和它在 val 上的表现一致。本章登记的候选只有这一组，所以只评了这一次；distill 组没有 test 数字，两组的比较全部在 val 上。按第 0 章 0.10.1 节的规则，预先登记的候选可以各评一次，只登记一组是本章实验的选择，不是规则的限制。test 只报数字，不据此改任何设置；开发期不看它的错例，最终报告定稿后才可以解封。

$T=2$、50 步，损失 0.4189 → 0.00073，教师无梯度（本项目观察，`runs/smoke/kl.json`）。只验证实现，见 35.3.5 节。

主实验的负结果有一个明显的嫌疑：数据太少，训练太短。补充实验把规模放大，在 val 上重做对照；test 没有再用（本项目观察，RTX 4090（租用），bf16，`supp/summary.json`、`supp/teacher/`，设置见 lab 补充实验一节）。

**改了什么。**

- 教师换成了第 33 章**微调后**的 Qwen3-VL-2B（主实验是零样本）。批量推理，生成 5000 张图，纯生成 1737.7 s。
- 学生的 LoRA rank 从 16 提到 64，可训练参数 7,372,800；每臂训 3000 步，跑两个种子（35、36）。
- original 臂用 5000 张真标签图；distill 臂再加上 3115 条通过质检的伪标签图。两臂的总曝光都是 6000。
- 两臂都在同一批 500 条 val 上评。

**教师和质检。**

| 集合 | n | EM_norm | CER | parse_rate |
|---|---:|---:|---:|---:|
| 全部教师输出 | 5000 | 0.130 | 0.093 | 0.741 |
| 质检通过 | 3115 | 0.171 | 0.071 | 1.000 |

（本项目观察。）

质检通过率 62.3%，留下的数据确实更干净，和 35.5 节主实验的方向一致。但人工抽看固定前缀的样本（`supp/teacher/audit_review.json`）也发现了假阳性：`D_x^α y` 被改成 `D_x^{α y}` 仍然通过，希腊字母丢了粗体也通过。质检只是一道筛子，不是真值。

**学生。**

| 臂 / 种子 | EM_norm | CER [95% CI] | parse_rate | 截断 / 500 |
|---|---:|---|---:|---:|
| original / 35 | 0.002 | 0.841 [0.796, 0.882] | 0.658 | 88 |
| distill / 35 | 0.000 | 1.006 [0.947, 1.061] | 0.654 | 158 |
| original / 36 | 0.002 | 0.864 [0.823, 0.912] | 0.614 | 112 |
| distill / 36 | 0.002 | 0.861 [0.816, 0.915] | 0.748 | 91 |

（本项目观察。）

配对差按 distill − original 计，同一批 val bootstrap 2000 次（本项目观察）。这就是第 22 章 22.3 节的配对 bootstrap：每次重抽同一组 val 题，两臂在这组题上的 CER 相减，所以题目难易的波动在差值里抵消了。

- **种子 35：** CER +0.166 [+0.108, +0.225]，蒸馏臂明显更差。
- **种子 36：** CER −0.003 [−0.059, +0.055]，分不出差别；parse +0.134 [+0.086, +0.182]。

**读法。**

- **原始训练图多了约 20 倍、步数多了 5 倍，学生还是几乎读不出公式。** 四组 EM 都只有 0/500 或 1/500，CER 都在 0.84 以上。学生还没学会这项任务，也就是 35.10 节说的"信号不足"。CER 并不是完全分不开：种子 35 的配对差 +0.166 [+0.108, +0.225] 已经能区分这一个种子下的两种训练设置；但另一个种子不重复这个方向，而且两臂除了标签来源还改了数据组成，所以只能说"收益不稳定，不能归因于标签质量"。至于原因，256M 参数的容量、视觉部分冻结、只训 LoRA、训练预算，都是嫌疑，本实验没有把它们隔离开（待验证）。
- **两个种子的结论不一致。** 只跑种子 35，你会写"蒸馏明显更差"；只跑种子 36，你会写"分不出差别"。
- **种子 36 的 parse_rate 涨了 0.134，EM 和 CER 没有跟着变好，**所以不能算 OCR 变好。一个可能的解释是：伪标签全部是可解析的，学生学到的是"写得像能解析的样子"，不是"读得对"（待验证：没有做隔离这一点的对照）。

所以这一节的结论和 35.9 节的读法一致：这是一个**在本设置下**的负结果，不能推广成"蒸馏没用"。低 EM 本身并不让对照失效（CER 配对差照样能比）；本实验不能归因于标签质量，原因是数据组成与原始数据曝光混在一起（主实验还多了教师图片降质这一项；补充实验教师用原图，没有这个混杂），且结果跨种子不稳。一个有用的下一步是先让 original 臂自己学会这项任务（解冻视觉部分、换更大的学生，或者训练更久），这样 EM 也有分辨率，数据来源的差异更容易读出来；同时控制曝光与数据组成。

## 35.9 负结果怎样读、怎样报告

### 35.9.1 动机

实验做完，两组都是 0。很多人的第一反应是"蒸馏没用"，第二反应是把这次实验藏起来。两种反应都不对。负结果和正结果一样有信息，前提是你读得出它在说什么、没在说什么。

### 35.9.2 直觉：体温计坏了，还是病人没发烧

读数是 0，有三种可能：

1. **体温计坏了**：流程有 bug，比如 label mask 错位、学生根本没收到梯度。
2. **体温计量程不够**：指标在这个水平上没有分辨率，好一点和差一点都显示 0。
3. **病人真的没发烧**：方法在这个设定下确实没有效果。

只有排除了前两种，才能谈第三种。而第三种也只能说"在这个设定下"。

### 35.9.3 推导：四步读法

**第一步：排除流程错误。**逐项核对：

- label mask：探针样本提示 94 个 token 被遮掉，答案 125 个参与训练（本项目观察，`training.json` 的 `mask_check`）；`answer_labels` 还检查了提示前缀对齐。
- 可训练参数：只有语言模型的 LoRA，1,843,200 个，断言确认。
- 梯度：训练循环里每步检查有限且非零，否则报错。
- loss 在下降（35.8.3 节）；正式训练前先跑了 20 步冒烟，loss 从 2.151 降到 1.936（本项目观察，`runs/smoke/training.json`）。

这些都正常，说明学生确实在学，"体温计坏了"的可能性很小。

**第二步：看指标有没有分辨率。**EM 是 0/64。0/64 的 95% Wilson 区间上界是 0.057（数学结论）：意思是：按这种方法反复抽样构造的区间，约 95% 会覆盖真实 EM；它不是"真实 EM 有 95% 概率低于 5.7%"的参数概率陈述。两组都在地板上，EM 无法区分它们。换成配对比较也一样：两组在每一题上都错，一个对、一个错的不一致对是 $b=c=0$，McNemar 检验无从做起（数学结论，和第 34 章 34.8.4 节 GRPO 对起点的情形相同）。CER 还有一些分辨率，但两组的 bootstrap 区间重叠（0.836～1.032 对 0.925～1.167），而且主实验没有做同样本的配对比较（待验证：配对差值的区间没有算）。

**第三步：看规模和信号。**学生的基线本身就不会读公式（CER > 0.9）。蒸馏能起作用的前提，是学生能从数据里学到东西；当 256 张原始图都没把学生教会时，再加 109 张，很难看出区别。补充实验放大到 5000 张后，基线仍然 CER 0.84 以上（35.8.8 节）。35.10 节展开。

**第四步：写出恰好的结论。**能说的：

- 在 SmolVLM-256M、LoRA r16、600 步、256 张原始图的设定下，加入 109 条经质检的零样本教师伪标签，**没有观察到** val 上的提升；CER 的方向对 distill 组不利，但区间重叠。
- 两组 EM 都为 0，学生在这个规模下没有学会转写公式。
- 在 LoRA r64、3000 步、5000 张原始图的补充设定下，两个种子都没有给出 CER 上的收益：种子 35 明显变差，种子 36 分不出差别。
- 教师比学生强得多（CER 0.138 对 0.926），但教师自身的 EM_norm 只有 0.094。这两个 CER 不在同一批图上：教师的是 192 张训练图（0.75 倍降质），学生的是 64 条 val，图的难度、分布和质量都可能不同，所以这既不是配对比较，也不是同一分布上的比较，只能当旁证。要确认谁强、强多少，得在同一批图上评两者。

不能说的：

- "蒸馏无效。"主实验只有单种子、64 条 val；补充实验也只有两个种子、一种学生，而且两轮的基线都没学会任务，推不出普遍结论。
- "伪标签有害。"主实验的 distill 组同时少了 30% 原始曝光、多了降质图；补充实验的 distill 组同样挤占了原始曝光，都无法单独归因。
- "教师错误传给了学生。"1/12 的复制是个案。

### 35.9.4 数字例子：多大的差异才看得出来

假设两组的真实 EM 都在 10% 左右，想知道 val 要多大才能看出差异。两组独立时，差值的标准误约为

$$
\mathrm{SE}\approx\sqrt{\frac{2p(1-p)}{n}}.
$$

$p=0.1$、$n=64$：$\mathrm{SE}=\sqrt{0.18/64}=0.053$，粗略需要差值超过 $2\times0.053\approx0.11$ 才算明显，也就是 EM 从 10% 涨到 21%。$n=500$：$\mathrm{SE}=0.019$，差值超过约 0.04 就能看出（数学结论，非配对、粗略估计）。两组在同一批 val 上评测时，两个模型在同一题上的对错通常正相关，用配对比较需要的样本会少一些（第 22 章 22.3.3 节），所以这里的估计偏保守。

单组的区间也一样：6/64 的 Wilson 区间是 0.044～0.190，宽 0.146；50/500 是 0.077～0.129，宽 0.053（数学结论）。**val 从 64 条扩到 500 条，区间宽度大约缩到三分之一。**补充实验用 500 条 val，就是这个原因。

### 35.9.5 对照代码：怎样把负结果写进报告

本章的产物结构本身就是一份报告模板：

- `selection.json`：选择规则、时间、两组 val 指标、选中适配器的 SHA256。选择规则在结果出来之前就写定了。
- `final_test.json` + `final_test.lock`：选中组的 test 记录；锁防止在同一输出目录重复评测。
- `quality.json`：每条伪标签的通过与否和理由。
- `error_transfer.json`：标注了 `scope: "train diagnostic only"`，读者不会把它当成泛化指标。
- `metrics.csv` 和 `comparison.png`：两组并排，带截断数。

写 R4 时，负结果的一段至少包括：设定（规模、步数、种子）、数字与区间、流程检查清单、没控制住的变量、能说与不能说、下一步要验证的假设。

### 35.9.6 常见错误

- **不报负结果。**以后读你报告的人（包括你自己）会重复这个实验。
- **从负结果推出普遍结论。**"本设定下未观察到提升"和"方法无效"是两句话。
- **负结果之后去看 test 找原因。**开发期不看 test 错例，错例分析在 val 上做；最终报告定稿后才可以解封。
- **换了一堆设置再跑，挑一个好看的报。**这是在 val 上过拟合。要追加实验，先写下假设，再改一个变量。
- **把 loss 下降当成学会了。**两组 loss 都降了，EM 仍是 0。第 33 章的 Qwen3.5 也给过同样的教训。

## 35.10 规模与信号

### 35.10.1 动机

35.9 节的第三步说"规模和信号不够"。这句话很容易变成万能借口：任何失败都可以说"数据不够"。这一节把它说得具体一点：什么是信号，信号从哪来，怎样判断不够。

### 35.10.2 直觉：老师的嗓门和学生的耳朵

蒸馏要起作用，需要三样东西同时到位：

1. **老师比学生强**（有东西可教）。
2. **老师说的话大多是对的**（信号比噪声多）。
3. **学生听得进去**（学生有能力从这么多数据里学会任务）。

本章第 1 条满足：教师 CER 0.138，学生 0.926（两者不在同一批图上，严格说只是旁证，见 35.9.3 节第四步）。第 2 条勉强：通过质检的标签 CER 0.094，大部分字符是对的，但完全一致的只有 14%。第 3 条**不满足**：学生用 256 张人工标注没学会，放大到 5000 张也没学会（35.8.8 节），说明瓶颈在学生这一侧。

### 35.10.3 推导：增量能有多大

把学生在某个设定下的错误率记为 $e(D)$，$D$ 是训练数据。加入伪标签 $D'$ 后的变化

$$
\Delta=e(D)-e(D\cup D')
$$

大致取决于两件事：$D'$ 带来的新信息有多少（新图片、新结构），以及 $D'$ 的噪声会让学生偏多少。第一项和 $|D'|$ 的大小、和 $D$ 的差异有关；第二项和伪标签的错误率、错误的系统性有关（35.6 节）。

当学生处在"什么都还没学会"的阶段时，两组都没有多少正确答案可比。用 EM 算错误率，$e(D)$ 和 $e(D\cup D')$ 都贴着最差值（EM 贴着 0，这就是后面说的"地板"），$\Delta$ 接近零，分不开两组。CER 没有上限（35.8.4 节），它还会动，但这时的差异可能只反映写多写少、有没有一路写到截断，不一定反映谁读得更准；35.8.8 节的两个种子就给出了不一致的 CER 差异。地板限制的是 EM 这一个指标的信息量，并不使 CER 对照失效；但要把差异解释成"读得更准"，让基线学生离开地板会有很大帮助。

这是一个分析框架，不是数学定理。本章放大到 5000 张、3000 步仍没有离开地板，多大的规模才够，本章回答不了（待验证）。

### 35.10.4 数字例子：本章离"够"有多远

几个可以直接算的量（数学结论，基于本项目观察的设置）：

| 量 | 主实验 | 补充实验（lab 补充实验一节） |
|---|---|---|
| 原始训练图 | 256 | 5,000 |
| 教师标注图 | 192（通过 109） | 5,000 |
| 优化步 × 累积 | 600 × 4 = 2,400 次曝光 | 3,000 × 2 = 6,000 次曝光 |
| LoRA rank | 16 | 64 |
| val 条数 | 64 | 500 |
| 种子 | 1 | 2 |
| 教师 | 零样本，0.75 倍降质图 | 第 33 章的 LoRA 适配器，原图 |

主实验里，每张原始图平均被看 9.4 遍，学生见过的不同公式只有 256 种。补充实验把原始图的数量放大约 20 倍，原始组每张只看约 1.2 遍（6,000 / 5,000），蒸馏组的池子更大、每张看得更少，更接近"见得多、背得少"。这样放大以后学生仍然没有学会，结果见 35.8.8 节。

补充实验同时改了步数、rank、教师和推理设置，它和主实验之间的差异不能归因于单一因素（lab 补充实验一节明确这样声明）。它回答的是"放大以后，两组的差异能不能看出来"，不是"哪个因素起了作用"。

### 35.10.5 对照代码

规模相关的开关都在 `tour.py` 的命令行参数里：`--n-train`、`--n-teacher`、`--n`（val 条数）、`--steps`、`--accum`、`--rank`、`--seed`、`--batch-size`（只影响推理批量）。补充实验通过 `supp_suite.py` 串起来，`--val-only` 保证不碰 test（`test_val_only_blocks_test_before_creating_outputs`）。

### 35.10.6 常见错误

- **一失败就说"数据不够"，却不说多少才够。**要么给出一个可以检验的预测（例如"扩到 5,000 张后，基线 CER 应低于某个值"），要么承认不知道。
- **只放大伪标签，不放大原始数据。**基线没离开地板时，你分不清增益来自"更多数据"还是"教师的知识"。补充实验两边同时放大到 5,000。
- **放大规模时同时改一堆东西，然后把差异归因给其中一个。**对照表里要列出每组改了什么。
- **规模放大了，val 没放大。**64 条 val 撑不起小差异的判断（35.9.4 节）。

## 35.11 在线策略蒸馏（概括）

序列级和逐位置 KL 都有一个共同的问题：学生在训练时看到的前缀，来自教师或参考答案；生成时看到的前缀，却是它自己写出来的。学生一旦在某一步写偏，后面就进入了训练时从没见过的状态，错误越滚越大。这叫**暴露偏差**（exposure bias），第 31 章 31.4.6 节在小公式 OCR 上见过它。

**在线策略蒸馏**（on-policy distillation）的思路是：让**学生自己生成**，再请教师在学生写出的每个位置上给出分布，用 KL 把学生往教师那边拉。学生在"自己会犯的错"上得到纠正。Agarwal 等人（2024）的 GKD 把它形式化：用一个比例 $\lambda$ 决定多少样本来自学生自己生成，用一个系数 $\beta$ 在前向 KL、反向 KL 和 JSD 之间插值（论文报告，见 35.16 节精读）。

它需要的条件比本章更苛刻：教师要在线、要给出完整 logits、词表要和学生一致。本章的异构教师和学生做不到，所以列为进阶阅读。

## 35.14 和真实框架的对应

| 本章 | 真实框架 |
|---|---|
| 序列级蒸馏：先离线生成伪标签，再 SFT | 最直接的对应是 TRL 的 `SFTTrainer`，数据集里的答案换成教师输出（第 33 章的训练方式）。TRL 1.15.0 的 `trl.experimental.gkd.GKDConfig` 有一个 `seq_kd` 开关，文档说它"可以看作在教师生成的输出上做 SFT"；但读本地源码 `gkd_trainer.py` 可以看到，打开后是**训练时在线**让教师生成，损失仍然走 `generalized_jsd_loss`（要用教师 logits），不是纯交叉熵，也要求同一词表 |
| `masked_kl`：$T^2\cdot$ 前向 KL，答案位置平均 | `GKDTrainer.generalized_jsd_loss(student_logits, teacher_logits, labels, beta, temperature)`：`beta=0` 时是 $\mathrm{KL}(\text{teacher}\Vert\text{student})$（前向），`beta=1` 是反向，中间是广义 JSD；用 `labels != -100` 做 mask，按有效 token 平均。**没有 $T^2$ 因子**；`compute_loss` 调用它时没有传 `temperature`，所以损失按 $T=1$ 计算，`GKDConfig.temperature`（默认 0.9）只用于采样（本项目观察，本地 trl 1.15.0 源码） |
| 教师 detach | `GKDTrainer.compute_loss` 里教师在 `torch.no_grad()` 下前向，并设为 `eval()` |
| 词表必须一致 | TRL 1.15.0 顶层的 `trl.DistillationTrainer` 初始化时比较两边的 `vocab_size`，不同就报错，并建议用 GOLD 做跨分词器蒸馏；`trl.experimental.gold` 有 `use_uld_loss` 等选项（算法细节待验证） |
| 35.11 在线策略蒸馏 | `GKDConfig.lmbda`（默认 0.5）：以这个概率让学生自己生成，再用教师 logits 计算损失。`trl.DistillationTrainer` 是完全在线的，文档写明学生自己生成补全，`beta` 默认 1.0（反向 KL），`temperature` 默认 1.0，同时用于生成和损失（本项目观察，本地 `distillation_config.py`） |
| 质检 `quality_check` | 没有通用的框架对应。各家技术报告各写各的（第 36 章） |
| transformers | 本地 transformers 5.19.0 源码里没有检索到专门的蒸馏 Trainer（本项目观察）。常见写法是继承 `Trainer`、重写 `compute_loss`，在里面算教师前向和 KL（待验证：不同教程写法不一） |

TRL 的实验模块（`trl.experimental.*`）接口变化很快，以上以本地安装的 trl 1.15.0 为准。读源码时搜 `generalized_jsd_loss`、`seq_kd`、`lmbda`、`vocab_size` 这些名字，比记行号可靠。

## 35.15 小结

蒸馏是让强模型给弱模型当老师：序列级蒸馏只拿教师写出的答案做 SFT，相当于用这一句代替教师的整句分布，对词表没有要求；logit 级蒸馏逐位置对齐分布，信息更多，但要求同一词表，升温后要乘 $T^2$ 让梯度量级不随温度变化。

伪标签必须质检，本章的规则把零样本教师的 192 条输出筛到 109 条，CER 从 0.138 降到 0.094，但通过的标签大多仍和参考不完全一致，宽松阈值既会放过真错也会误杀好标签。在整句分类的教学模型里，学生会把标签的混合比例学成自己的分布，交答案时取多数，所以教师的系统性错误可能比随机错误更容易传下去；真实的贪心逐 token 取最大，写出的不一定是整句众数。

本章两轮实验都是负结果。主实验两组学生 val EM 都是 0，CER 0.926 对 1.035，选中组 test CER 0.931（本项目观察，RTX 4090（租用），64 条，seed 35）。补充实验放大到 5000 张、3000 步、两个种子，四组 val EM 仍只有 0/500 或 1/500，蒸馏组在种子 35 上明显更差，在种子 36 上分不出差别（本项目观察，val 500 条）。读法是"学生还没离开地板，这组设置下看不到稳定收益，也不能归因于标签质量"，不能推广成"蒸馏无效"。

复习时抓住下面几条：

- **序列级蒸馏**：用教师的贪心或 beam 输出 $\hat y$ 代替教师的整句分布，损失 $-\sum_t\ln p_\theta(\hat y_t\mid\hat y_{<t},x)$，就是标签换成教师输出的 SFT。教师输出要用学生自己的 processor 重新分词（35.2.3 节、35.4.6 节）。
- **带温度的 KL**：$\mathcal L_T=T^2\,\mathrm{KL}(q^{(T)}\Vert p^{(T)})$，对学生 logits 的梯度是 $T(p-q)$。不乘 $T^2$ 时梯度是 $(p-q)/T$，同一 $T$ 下精确小 $T^2$ 倍；高温且 logits 去均值后，梯度趋近 $\frac1C(z-v)$，损失趋近 $\frac{1}{2C}\lVert z-v\rVert^2$。3 类例子 $v=[3,1,0]$、$z=[1,1,0]$ 中，$T^2\cdot$KL 在 $T=1,2,4$ 时是 0.3797、0.4887、0.4911（35.3 节）。
- **前向与反向 KL**：前向 $\mathrm{KL}(q\Vert p)$ 在教师有概率、学生给 0 的地方罚得极重，学生要覆盖教师的所有可能（mode-covering）；反向 $\mathrm{KL}(p\Vert q)$ 对学生漏掉的众数只给有限的代价，学生可以只押一个（mode-seeking）。学生能取到 $p=q$ 时两者都在 $p=q$ 取最小值 0。`F.kl_div(input, target)` 算的是 $\mathrm{KL}(\text{target}\Vert\text{input})$。
- **词表**：逐位置 KL 要求坐标对齐和位置对齐，形状相同只是必要条件；异构教师和学生之间能直接做的是序列级（35.4 节）。
- **质检**：长度合格、未截断、mathtext 可解析，并且渲染比对不是失败才通过；渲染差 $d=\lvert A\oplus B\rvert/\lvert A\cup B\rvert\le0.65$，参考渲染不出来时记 unknown 并保留。质检用到了训练参考，val 和 test 上不做（35.5 节）。
- **标签混合**：某类输入的标签以比例 $w$ 来自教师时，整句分类模型的最优解是 $p(y^{\mathrm{T}})=w$，$w>0.5$ 时学生写教师的写法；只有教师标注的图上 $w=1$。加伪标签还会挤掉原始数据的曝光（35.6 节）。
- **读负结果**：先排除流程错误，再看指标分辨率（0/64 的 Wilson 上界 0.057；两组 EM 都是 0 时不一致对为 0，基于 EM 对错的配对比较也没有信息，CER 的配对差仍可能有信息），再看规模和信号，最后写出只限本设定的结论（35.9 节）。
- **最常见的错误**：忘了乘 $T^2$ 或把 KL 方向写反；把通过质检当成正确；从一个单种子、基线在地板上的负结果推出"蒸馏无效"。
