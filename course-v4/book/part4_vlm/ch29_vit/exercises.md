## 答案与提示

**29-C1.** patch 嵌入 = 核大小 p、步长 p、padding 0、输入通道 C、输出通道 D 的卷积，再把 (B, D, g_h, g_w) 展平、转置成 (B, N, D)。窗口不重叠、无缝隙。

**29-C2.** 对的部分：一个 patch 确实被压成一个 D 维向量，当 C·p² > D 时有零空间，一些像素图案会被看不见。不对的部分：线性投影的权重可以不均匀，不是求平均；1 像素的线可以由某些权重专门响应。真正的平均损伤发生在**送进 ViT 之前的图像缩放**里（第 27、28 章）。

**29-C3.** 图片没有先后顺序，每个 patch 都应能利用全图。误加因果 mask 后，按行优先排列，左上角第一个 patch 前面只有 CLS，所以它只能看到 CLS 和自己；而 CLS 在第 0 位，只能看自己，最后用 CLS 分类时它什么都没看到。

**29-C4.** 表的行数等于训练网格的 token 数 + 1，换分辨率后行数对不上。CLS 不对应任何格子，混进网格插值会让它被邻近格子"污染"，同时让空间网格的形状错位。

**29-C5.** 归纳偏置是结构里事先写死的假设。CNN：局部性、权重共享（平移等变）、层级/池化。ViT：patch 内的局部性、所有 patch 共享投影（整 patch 平移时 token 内容不变）。此外行优先的位置表排列、patch 网格本身也是先验，所以"没有偏置"不对。

**29-C6.** CNN 一开始就"知道"邻近像素要一起看，所以早期学得快；ViT 的位置表从随机开始，要从数据里学出邻接关系，前期慢。数据和步数够了，ViT 用全局注意力追上；在这个规模下两者打平（种子间、区间重叠），并没有看到明显反超。

**29-C7.** 准确率只看 argmax 对不对；交叉熵是 −log p(正确类)。过拟合时模型对 val 上答错的样本给出极自信的错误答案，p(正确类) 接近 0，CE 暴涨，压过了答对样本增多带来的下降。于是按 CE 选出的 checkpoint 可能是几乎没训练的模型，用它比较架构的准确率就不公平。要按准确率比较，应事先把选择规则定为 val 准确率并重新冻结。

**29-C8.** 一个汇总向量放不下"哪个字符在哪里、在分式线上方还是下方"这类细节；生成 LaTeX 时语言模型需要逐步回头查看图的不同位置，这要靠全部 patch token（第 31 章）。

**29-H1.** (a) 14×14，N = 196，含 CLS 197。(b) 768·3·16·16 + 768 = 589,824 + 768 = 590,592。(c) (1, 197, 768)，197·768 = 151,296。(d) 3·256 = 768；768 − 768 = 0，零空间至少 0 维（E 可以满秩）。

**29-H2.** (a) (1, 2, 4)；token 0 = [1, 2, 5, 6]，token 1 = [3, 4, 7, 8]。(b) 核展平为 [1, 0, 0, 1]：token 0 = 1 + 6 + 0.5 = 7.5，token 1 = 3 + 8 + 0.5 = 11.5。(c) 先列后行时 token 0 = [1, 5, 2, 6]，与 [1, 0, 0, 1] 点积 = 1 + 6 + 0.5 = 7.5，碰巧一样，因为这个核关于主对角线对称，行列互换后不变。换成不对称的核 [[0, 1], [0, 0]]（展平 [0, 1, 0, 0]）就不同了：正确顺序得 2 + 0.5 = 2.5，错误顺序得 5 + 0.5 = 5.5。教训：对拍要用随机权重，不能用特殊的核。

**29-H3.** (a) ⌈40/16⌉ = 3，⌈300/16⌉ = 19；下补 3·16 − 40 = 8，右补 19·16 − 300 = 4；N = 57。(b) ⌈40/8⌉ = 5，⌈300/8⌉ = 38（304 − 300 = 4 列补白）；N = 190，约 3.33 倍（补白让它不是整 4 倍）。(c) (a)：4·4·58² = 53,824 字节；(b)：4·4·191² = 583,696 字节；比值约 10.8。

**29-H4.** (a) 旧 16×16，新 (448/14)×(336/14) = 32×24；257 行 → 769 行。(b) 32·24 = 768，√768 ≈ 27.7，取整 27，27² = 729 ≠ 768，reshape 直接报错；即使碰巧能开方（例如新网格 16×36 = 576 = 24²），也会排成 24×24，左右和上下的位置全乱而不报错。正确做法是由高宽分别除以 p 得到网格。

**29-H5.**
```text

0 0 1 1
2 2 3 3
2 2 3 3
```
最近邻是阶梯状的，不会冲出原范围 [0, 3]，相邻新格可能完全相同（模型分不清它们的位置）；双三次是平滑过渡，相邻新格各不相同，但在边界附近会冲出原范围。

**29-H6.** 一个 block：LN 2·64 两个 = 256；qkv 64·192 + 192 = 12,480；proj 64·64 + 64 = 4,160；MLP 64·256 + 256 = 16,640 与 256·64 + 64 = 16,448；合计 49,984，两个 99,968。其余部分：嵌入 1,088 + CLS 64 + 位置表 4,160 + 最终 LN 128 + 分类头 1,560 = 7,000。合计 7,000 + 99,968 = 106,968。

**29-H7.** 8 像素 = 2 个 patch。原 (i, j) 的内容出现在 (i, j + 2)，j ≤ 5；原第 6、7 列移出画面；新网格第 0、1 列全白。平移 6 像素不是 4 的整数倍，每个新 patch 由两个旧 patch 各一部分拼成，不能一一对应。

**29-D1.** permute 成 (B, g_h, g_w, pH, pW, C)，patch 内顺序变成 (u, v, c)，而卷积权重按 (c, u, v) 展平。C = 1 时两种顺序完全相同，所以灰度测试查不出。用 C ≥ 2 的输入和随机权重，与 `F.conv2d` 写法对拍（本章测试用 C = 2、3）。

**29-D2.** 230 不能被 16 整除，卷积式 patch 嵌入向下取整：230 // 16 = 14，网格和 224 一样是 14×14，位置表形状完全对得上，所以没有任何报错，只是最右、最下 6 像素被悄悄丢掉。5×7 的图配 p = 4，卷积输出网格 1×1，说明右边 3 列、下边 1 行被丢了。修复：先补白到可整除，或缩放到可整除，或像本书一样默认报错。

**29-D3.** 旧网格 8×8 是方形，第一行没问题。8×18 = 144 = 12²，新网格被当成 12×12：位置表插值到 145 行，行数恰好对上 patch token 数，不报错；但 patch token 按 8 行 18 列排，位置表按 12 行 12 列排，第 13 个 patch（第 0 行第 12 列）拿到的是"第 1 行第 0 列"的位置，空间关系全乱。12×16 = 192，√192 ≈ 13.86 取 13，插值出 169 + 1 行，和 193 个 token 相加时形状不符而报错。改法：由图像高宽分别除以 p 得到 (g_h, g_w)，显式传入 old_grid 和 new_grid（本章 `interpolate_positions` 的接口）。

**29-D4.** 先查注意力里有没有因果 mask（`masked_fill` 或 `is_causal=True`）。测试：随机打乱 token 顺序 perm，检查 `block(x[:, perm])` 是否等于 `block(x)[:, perm]`；有因果 mask 时不等。原因见 29-C3：CLS 在第 0 位只能看自己，它的输入对所有图片都相同，所以分类输出与图片无关，只能学到类别先验。

**29-D5.** CNN 低数据组标准差 24 个百分点，其中种子 1 按 val CE 选中第 1 步（准确率 4.11%），拉低了均值；其余两个种子 CNN 反而更高。结论受 checkpoint 选择规则支配。本章冻结的 CE checkpoint 结果保留，不补评 test。后续实验应事先约定按 val 准确率选，将协议版本化，重算全部候选，另行安排最终测试；冻结后预先登记的候选各评一次，不据此改设置（正文 §29.9.4、第 0 章 §0.10.1）。还应增加种子数。

**29-D6.** 用的是最后一个 token，也就是网格右下角的 patch。双向注意力下这个 patch 也能看到全图，所以仍能学到一些东西；但它同时要代表右下角的局部内容，而且没有 CLS 那样"专职汇总"的角色，通常更差。

**29-W1–W4.** 对照正文 29.2.2、29.2.4、29.5.4、29.3.1。29-W1 的形状：(1, 3, 8, 12) → (1, 3, 2, 4, 3, 4) → (1, 2, 3, 3, 4, 4) → (1, 6, 48)。29-W3：(1, 25, D) → CLS (1, 1, D) + 空间 (1, 24, D) → (1, 4, 6, D) → (1, D, 4, 6) → (1, D, 7, 10) → (1, 70, D) → (1, 71, D)。
