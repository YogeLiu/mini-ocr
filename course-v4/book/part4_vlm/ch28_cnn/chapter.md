# 第 28 章 卷积与 CNN

## 本章导读

第 5 章里，我们把卷积网络当黑盒用过一次：两层卷积、两次池化、一个全连接层，就能把 24 类公式符号分得不错。这一章打开这个黑盒。

先看一组本章实测的数字。同一批 24 类合成符号图（32×32 像素），两个参数量差不多的模型，各训练 5000 步、3 个种子：

| 模型 | 参数量 | 验证准确率（3 种子均值） | 测试准确率（3 种子均值） |
|---|---:|---:|---:|
| 两隐藏层 MLP | 80,808 | 80.16% | 81.60% |
| 两层卷积的 CNN | 84,408 | 93.69% | 94.61% |

（参数量是数学结论；准确率为本项目观察，RTX 4090（租用），fp32，3 个种子 × 5000 步，验证集、测试集各 3840 张，文件 `outputs/book/ch28/gpu/final/training.json`、`final_test.json`。检查点按验证 CE 最低选取，这个选择的后果见 28.9.3 节。）

参数差不多，准确率差了十几个百分点。差距来自结构，CNN 把两条关于图片的常识直接写进了网络：**有用的信息是局部的**，**同一个图案出现在哪里都是同一个图案**。

可同一组模型还有另一面。把验证图先缩小 4 倍、再放大回 32×32，CNN 的准确率从 93.69% 掉到 49.13%，MLP 掉到 53.39%（本项目观察，同上，不重新训练）。卷积擅长看局部细节，细节一旦被下采样抹掉，它也无能为力。视觉编码器看不清小下标，这是根源之一。

本章的结论先放在这里：

1. 卷积就是拿一个小窗口在图上滑，每到一处做一次加权求和。窗口里的权重（卷积核）在所有位置共享。
2. 输出边长 = ⌊(H + 2p − k) / s⌋ + 1。这个公式数的是窗口能放下几次。
3. 卷积的反向只有三条规则：db 是 dY 的求和；dW 是输入和 dY 的互相关；dX 是把每个 dY 乘上卷积核"撒"回输入窗口，**重叠处要累加**。
4. 每多一层卷积，一个输出能看到的输入范围就扩大一圈；步长和池化让后面的层扩大得更快。递推式是 r ← r + (k − 1)·j，j ← j·s。
5. 连续的 2×2 平均池化把 1 像素宽的细线每次压淡一半。几次之后，小字和分式线在数值上就和白纸差不多了，后面的层再强也找不回来。
6. BatchNorm 按通道在一整批里求均值方差，所以训练时一张图的输出受同批别的图影响；推理时改用训练中攒下的滑动平均。LayerNorm 只看单个样本，没有这个问题。

**学完本章，你能做到：**

1. 手算一个小矩阵的卷积，说清卷积核、步长、padding，并推导输出尺寸公式。
2. 从零实现卷积的前向和反向，推导 dX、dW、db，用数值梯度检查。
3. 计算一个网络的理论感受野和跳距，解释它为什么逐层扩大。
4. 解释连续下采样为什么损伤小字和细线，并读懂本章的像素损伤实验。
5. 说清 BatchNorm 的作用、训练与推理的差别，以及它和 LayerNorm 的区别。
6. 读懂 CNN 与 MLP 的对照实验，说出它的结论适用到哪里为止。

> **回顾（第 2 章）：** 反向传播就是链式法则：每个节点把上游梯度乘局部导数传给输入；一个变量被用了几次，它的梯度就是几份贡献之和（代码里写 `+=`）。数值梯度检查用中心差分 [f(x+h) − f(x−h)] / (2h) 当标准答案，去核对解析梯度。

## 28.1 为什么看图要用卷积

### 28.1.1 动机：MLP 看图的两个毛病

第 5 章的符号图是 32×32 的灰度图。最直接的办法是把它拉平成 1024 个数，送进全连接层（MLP）。本章的 MLP 第一层有 72 个神经元，光这一层就有 1024 × 72 + 72 = 73,800 个参数（数学结论）。

这个设计有两个毛病。

**第一，每个神经元都盯着整张图。** 判断"这里有没有一条竖线"，只需要看一个小邻域，可全连接层的每个神经元都要给 1024 个像素各配一个权重。大部分权重在做无用功，还容易学到"第 300 号像素有墨迹 → 第 7 类"这种死记硬背的规则。

**第二，同一个图案换个位置就得重新学。** 符号往右挪 3 个像素，拉平后的向量几乎全变了。MLP 不知道"左上角的竖线"和"右下角的竖线"是同一种东西，只能靠数据把每个位置都教一遍。

### 28.1.2 直觉：拿着手电筒扫图

卷积的做法像拿着一个小手电筒在黑屋子里找东西。手电筒每次只照亮 3×3 的一小块（**局部连接**）；你脑子里只有一套"竖线长什么样"的标准（**权重共享**），照到哪儿都拿这套标准去比。比完一处，挪一步再比。最后得到一张"哪里像竖线"的地图，叫**特征图**（feature map）。

想找多种图案，就准备多个手电筒（多个卷积核），每个输出一张特征图。

本章 CNN 的第一层有 24 个 3×3 的卷积核，参数只有 1 × 24 × 3 × 3 + 24 = 240 个（数学结论），却能在 32×32 的每个位置上都做检测。

### 28.1.3 代价：参数省了，计算没省

权重共享省的是**参数**，不是**计算**。第一层卷积在 32×32 个位置各做一次 9 元素的加权求和，每个核约 9,216 次乘法（数学结论：32 × 32 × 9）。本章实测里 CNN 每个种子的训练时间是 13.6 到 18.6 秒，MLP 是 8.6 到 11.3 秒；PyTorch 记录的显存峰值 CNN 约 273 MiB，MLP 约 23 MiB（本项目观察，RTX 4090（租用），batch 256，5000 步，含评估和存检查点；共享机器，时间只能粗看）。显存差别主要来自 CNN 每层要存下整张特征图供反向使用：第一层输出就有 256 × 24 × 32 × 32 ≈ 629 万个数（数学结论），而 MLP 的隐藏层只有 256 × 72 个。

> **停下来想一想：** 一个 3×3 卷积核在 32×32 的图上滑动（padding = 1，步长 1）。它一共被用了多少次？如果每个位置都用独立的权重，参数会是多少？

## 28.2 卷积的前向：手算一个小矩阵

### 28.2.1 定义

先看最简单的情况：一个通道的输入 X（H×W），一个卷积核 K（k×k），偏置 b。输出 Y 在位置 (i, j) 的值是：

```text
Y[i, j] = Σ_{p=0}^{k-1} Σ_{q=0}^{k-1} K[p, q] · X[i + p, j + q] + b
```

用话说：把核的左上角放到 X 的 (i, j)，对应位置相乘，全部加起来，再加 b。

严格说，数学里的"卷积"要先把核上下左右翻转，上面这个不翻转的版本叫**互相关**（cross-correlation）。深度学习框架（包括 PyTorch 的 `Conv2d`）算的都是互相关，大家仍然叫它卷积。核是学出来的，翻不翻转只是换一种记法：学出来的核正好是翻转版而已。本书说"卷积"都指互相关。

### 28.2.2 手算：用一个竖线检测器扫一条竖线

输入是 4×4 的图，第 1 列（从 0 数）有一条竖线，墨迹记为 1，白纸记为 0：

```text
X (4×4)              K (3×3)，竖线检测器        b = 0
0 1 0 0              -1  2 -1
0 1 0 0              -1  2 -1
0 1 0 0              -1  2 -1
0 1 0 0
```

核的意思很直白：中间一列是墨迹就加分，两边是墨迹就扣分。

窗口能放在 2×2 个位置上（4 − 3 + 1 = 2），所以 Y 是 2×2。

**Y[0, 0]：** 窗口盖住第 0 到 2 行、第 0 到 2 列。每一行都是 `0 1 0`，与 `-1 2 -1` 逐个相乘再相加：0·(−1) + 1·2 + 0·(−1) = 2，三行共 6。

**Y[0, 1]：** 窗口盖住第 0 到 2 行、第 1 到 3 列。每一行是 `1 0 0`，乘积和为 1·(−1) + 0·2 + 0·(−1) = −1，三行共 −3。

第 1 行的两个位置与第 0 行完全一样（每行图案相同）。

```text
Y (2×2)
 6  -3
 6  -3
```

竖线正好在窗口中间时得 6，在窗口左边缘时得 −3。这张 2×2 的地图告诉我们竖线在哪儿。（数学结论；用 `conv_forward` 在 CPU 上复跑结果相同。）

### 28.2.3 多通道、多个核：四维张量的形状

真实的输入有多个通道（RGB 是 3 个，中间层可能有 48 个），也要用多个核。规则只有两条：

1. **一个核要覆盖所有输入通道。** 输入有 C 个通道时，一个核的形状是 C×k×k，每个通道一片，各自做加权求和后**加在一起**，得到一张特征图。
2. **有几个核，就有几个输出通道。** F 个核输出 F 张特征图。

再加上一批 N 张图，张量形状就是：

| 张量 | 形状 | 本书的叫法 |
|---|---|---|
| 输入 X | (N, C, H, W) | NCHW |
| 权重 W | (F, C, kH, kW) | OIHW：输出通道、输入通道、高、宽 |
| 偏置 b | (F,) | 每个输出通道一个 |
| 输出 Y | (N, F, H', W') | |

公式变成：

```text
Y[n, f, i, j] = Σ_c Σ_p Σ_q W[f, c, p, q] · X[n, c, i·s + p, j·s + q] + b[f]
```

这里 s 是步长（下一节讲），X 是已经补过 padding 的输入。

参数量 = F × C × kH × kW + F（数学结论）。本章 CNN 第二层从 24 个通道到 48 个通道、核 3×3：48 × 24 × 3 × 3 + 48 = 10,416。

### 28.2.4 常见错误

- **把 C 和 F 的位置搞反。** PyTorch 的权重是 (out, in, kH, kW)。现象：形状报错，或者 C 和 F 恰好相等时不报错但结果全错。发现：和 `F.conv2d` 对拍一次。
- **忘了多个输入通道要相加。** 现象：输出多出一维，或者只用了第一个通道。发现：用一个 C = 2 的小例子，第二个通道放非零值。

## 28.3 步长、padding 与输出尺寸

### 28.3.1 为什么要控制尺寸

上一节 4×4 的图只得到 2×2 的输出，边缘一圈丢了。连续几层下来图会越缩越小，边上的像素也只被窗口扫到一两次。另一方面，有时我们又**希望**图变小，好让后面的层省计算、看得更广。控制这两件事的旋钮是 **padding** 和**步长**（stride）。

- **padding p：** 在输入四周各补 p 圈 0。
- **步长 s：** 窗口每次挪 s 格，而不是 1 格。

### 28.3.2 推导输出尺寸公式

只看一维（高和宽各算一次）。补过 padding 后，输入长度是 H + 2p。窗口长 k，起点可以是 0, s, 2s, …，最后一个起点必须让窗口不出界：

```text
起点 m·s 满足 m·s + k ≤ H + 2p
⇒ m ≤ (H + 2p − k) / s
```

第二行是把不等式两边同时减去 k、再除以 s（s > 0，不等号方向不变）。m 只能取整数，所以最大的 m 是 ⌊(H + 2p − k) / s⌋；m 从 0 数起，个数还要再加 1，所以一共有

```text
H' = ⌊(H + 2p − k) / s⌋ + 1
```

个位置，这是输出尺寸公式（数学结论）。向下取整的意思是：最后剩下的不够一个窗口的边角料直接扔掉。

如果核里的元素之间隔开 d − 1 个空位（**空洞卷积**，dilation = d），k 个元素之间有 k − 1 个间隔，每个间隔跨 d 格，核实际覆盖的长度就是 d(k − 1) + 1。把公式里的 k 换成它即可：

```text
H' = ⌊(H + 2p − d(k − 1) − 1) / s⌋ + 1
```

d = 1 时两式相同。本章代码用的是这个通用版本。

### 28.3.3 数值例子

仍用 28.2.2 节的 4×4 竖线图和 3×3 核：

| 设置 | 计算 | 输出 |
|---|---|---|
| s = 1, p = 0 | ⌊(4 + 0 − 3)/1⌋ + 1 = 2 | 2×2 |
| s = 1, p = 1 | ⌊(4 + 2 − 3)/1⌋ + 1 = 4 | 4×4 |
| s = 2, p = 1 | ⌊(4 + 2 − 3)/2⌋ + 1 = 2 | 2×2 |

（数学结论。）p = 1 时的 4×4 输出是（`conv_forward` CPU 复跑）：

```text
-2  4 -2  0
-3  6 -3  0
-3  6 -3  0
-2  4 -2  0
```

第一行和最后一行的值变小了，因为窗口有一行落在补的 0 上。s = 2, p = 1 时，输出是这张 4×4 里第 0、2 行与第 0、2 列交叉的四个数：`-2 -2 / -3 -3`。也就是说，步长为 2 等于先按步长 1 算完，再隔一个取一个，推导反向时会用到这一点。

两个常用的经验配方（数学结论）：

- **k = 3, p = 1, s = 1：** 尺寸不变（"same"）。本章 CNN 的两个卷积层都是这样。
- **k = 2, p = 0, s = 2：** 尺寸减半，2×2 池化就是这个几何。

奇数边长时向下取整会悄悄扔掉一行：57 行的图做 2×2、步长 2 的池化，得到 ⌊(57 − 2)/2⌋ + 1 = 28 行，最后一行没参与计算（数学结论）。本章 lab 第 3 部分的下采样就是为了避免这一点，先在右边和下边补白纸，凑成 2 的幂的倍数再池化。

### 28.3.4 对照代码：`output_size`

```python
def output_size(size, kernel, stride=1, padding=0, dilation=1):
    ...
    if min(size, kernel, stride, dilation) < 1 or padding < 0:
        raise ValueError("invalid convolution geometry")
    result = (size + 2 * padding - dilation * (kernel - 1) - 1) // stride + 1
    if result < 1:
        raise ValueError("kernel exceeds padded input")
    return result
```

逐行看（`miniocr/nn/cnn.py`）：

- 第一个检查拒绝零或负的尺寸、步长。步长为 0 会让除法出错，负 padding 没有意义。
- `//` 是 Python 的整除，对非负数就是向下取整，对应公式里的 ⌊ ⌋。用上面的例子：`output_size(4, 3, 2, 1)` = (4 + 2 − 2 − 1) // 2 + 1 = 3 // 2 + 1 = 2。
- 结果小于 1 说明核比补过的输入还大，直接报错，而不是返回 0 或负数让后面的代码莫名其妙地崩。

### 28.3.5 常见错误

- **用 `/` 不用 `//`。** 现象：得到 2.5 这样的小数，`np.empty` 报类型错误。
- **以为 padding 只补一边。** 公式里是 2p。现象：步长为 1 时输出比 PyTorch 小 p。发现：和 `nn.Conv2d` 的输出形状比一下。
- **忘了取整丢掉的边角。** 现象：奇数尺寸的图最右一列或最下一行的笔画在下采样后凭空消失。发现：用 17×19 这种奇数尺寸的图做测试（本章测试 `test_downsampling_thin_line_and_odd_size` 就是这样做的）。

## 28.4 从零实现卷积前向

### 28.4.1 思路

公式里有 n、f、c、i、j、p、q 七个下标。最笨的写法是七重循环，又慢又难读。`conv_forward` 只对输出位置 (i, j) 循环，每个位置一次性取出所有样本、所有通道的窗口，用 `einsum` 和所有核做乘加。

### 28.4.2 对照代码逐行讲

```python
def conv_forward(x, weight, bias, stride=1, padding=0):
    if x.ndim != 4 or weight.ndim != 4 or x.shape[1] != weight.shape[1]:
        raise ValueError("expected NCHW and OIHW with matching channels")
    n, _, h, w = x.shape
    filters, _, kh, kw = weight.shape
    ...
    oh = output_size(h, kh, stride, padding)
    ow = output_size(w, kw, stride, padding)
    xp = np.pad(x, ((0, 0), (0, 0), (padding, padding), (padding, padding)))
    out = np.empty((n, filters, oh, ow), dtype=np.result_type(x, weight, bias))
    for i in range(oh):
        for j in range(ow):
            patch = xp[:, :, i*stride:i*stride+kh, j*stride:j*stride+kw]
            out[:, :, i, j] = np.einsum("nchw,fchw->nf", patch, weight) + bias
    return out, (x.copy(), weight.copy(), stride, padding)
```

用 28.2.2 节的数字走一遍。把 4×4 的 X 写成 (1, 1, 4, 4)，核写成 (1, 1, 3, 3)，b 写成 (1,)，s = 1，p = 0。

1. **形状检查。** `x.shape[1]` 和 `weight.shape[1]` 都是 1，通过。
2. **`oh`、`ow`。** 都是 `output_size(4, 3, 1, 0)` = 2。
3. **`np.pad`。** 只在最后两维（H、W）补，N 和 C 不补。p = 0 时 `xp` 就是 `x`。
4. **`out`。** 形状 (1, 1, 2, 2)。dtype 取三个输入里精度最高的，梯度检查要用 float64，不能被悄悄降成 float32。
5. **循环 i = 0, j = 0。** `patch = xp[:, :, 0:3, 0:3]`，形状 (1, 1, 3, 3)，每行是 `0 1 0`。
6. **`einsum("nchw,fchw->nf")`。** 对 c、h、w 三个下标相乘求和，保留 n 和 f。结果形状 (1, 1)，值 6。加 `bias`（形状 (1,)，按 f 广播）后写入 `out[:, :, 0, 0]`。
7. **i = 0, j = 1。** `patch = xp[:, :, 0:3, 1:4]`，每行 `1 0 0`，得 −3。窗口的起点是 `i*stride`，就是 28.3.2 节的起点 m·s。
8. **返回缓存。** 反向要用到 x 和 weight，所以复制一份存起来。复制是为了防止调用者之后原地改了数组，让反向拿到错的值（梯度检查就会原地扰动输入）。

### 28.4.3 和高效实现的关系

实际的框架不会这样逐位置循环。常见做法是 **im2col**：把所有窗口展开成一个大矩阵的列，卷积就变成一次大矩阵乘法；或者用 cuDNN 里针对 GPU 优化的算法。本章的手写版只用来理解和做梯度检查，lab 的训练部分用 `nn.Conv2d`，A5 机制层要求的是手写版本。

### 28.4.4 常见错误

- **窗口起点写成 `i` 而不是 `i*stride`。** 现象：stride = 1 时全对，stride = 2 时输出错。发现：测试一定要包含 stride > 1 的几何。
- **在 N 或 C 维也做了 padding。** 现象：`einsum` 报形状不匹配，或者多出一个全零通道。
- **忘了 `bias` 的广播维。** 偏置要加在 f 维上，每个输出通道一个，不是每个位置一个。

## 28.5 卷积的反向：推导 dX、dW、db

### 28.5.1 先猜：一个像素的梯度有几项

训练要梯度。给定上游梯度 dY = ∂L/∂Y（形状和 Y 相同），要求 dX、dW、db。

先猜：输入里的一个像素 X[1, 1]，它的梯度和几个输出有关？28.2.2 节的 3×3 核在 4×4 图上滑动，X[1, 1] 被 4 个窗口都盖住了。第 2 章说过，一个变量被用了几次，梯度就是几份贡献之和。所以 dX[1, 1] 应该是 4 项相加。卷积反向最容易在这里出错。

### 28.5.2 推导

为了看清楚，先只写单样本、单通道、单个核、步长 s、输入已经补过 padding 的情况：

```text
Y[i, j] = Σ_p Σ_q W[p, q] · X[i·s + p, j·s + q] + b
```

链式法则：L 对某个量的导数，等于所有用到它的 Y[i, j] 的贡献之和，每一份是 dY[i, j] 乘以 Y[i, j] 对它的局部导数。

**db**，每个 Y[i, j] 里 b 的系数都是 1：

```text
db = Σ_i Σ_j dY[i, j]
```

**dW**，Y[i, j] 里 W[p, q] 的系数是 X[i·s + p, j·s + q]：

```text
dW[p, q] = Σ_i Σ_j dY[i, j] · X[i·s + p, j·s + q]
```

步长 s = 1 时，这和前向的形状一模一样：拿 dY 当核，在 X 上做一次互相关。s > 1 时要小心：相邻的 dY[i, j] 在 X 上相隔 s 格，所以得先在 dY 的元素之间插入 s − 1 个零（等价于把 dY 当作 dilation = s 的核），再做互相关，只保留前 k 个结果（数学结论）。一维小例子：X = [1, 2, 3, 4, 5]、核长 2、s = 2、dY = [1, 2]，正确的 dW = [1·1 + 2·3, 1·2 + 2·4] = [7, 10]，因为 Y[1] 的窗口起点是 1·2 = 2，读的是 X[2]、X[3]。直接拿 [1, 2] 去做步长 1 的互相关，等于以为 Y[1] 读的是 X[1]、X[2]，前两项算成 [1·1 + 2·2, 1·2 + 2·3] = [5, 8]。

**dX**，反过来问：X[a, b] 出现在哪些 Y[i, j] 里？当 a = i·s + p、b = j·s + q 时，系数是 W[p, q]。所以

```text
dX[a, b] = Σ_{(i,j,p,q) : i·s+p = a, j·s+q = b} dY[i, j] · W[p, q]
```

直接按这个式子求和不好写：对每个 (a, b) 都要先解出哪些 (i, p) 满足 i·s + p = a。换个角度：**遍历每个输出位置 (i, j)，把 dY[i, j] · W 整块"撒"回它当初读的那个窗口。**两种写法加的是同一批 dY[i, j] · W[p, q]，每一项都加到位置 (i·s + p, j·s + q) 上，只是把求和的循环顺序换了：原式外层循环 (a, b)，撒回去的写法外层循环 (i, j)。每个窗口都撒一遍，重叠的地方自然累加起来。撒回去的过程也等价于把 dY 补零后和翻转的核做一次全卷积（full convolution），步长大于 1 时还要先在 dY 里插零，末尾没被任何窗口读到的输入位置梯度补 0。代码里不必这么绕。

最后把多样本、多通道补回来：

```text
db[f]          = Σ_n Σ_i Σ_j dY[n, f, i, j]
dW[f, c, p, q] = Σ_n Σ_i Σ_j dY[n, f, i, j] · X[n, c, i·s + p, j·s + q]
dX[n, c, ·, ·] += Σ_f dY[n, f, i, j] · W[f, c, ·, ·]   （对每个 (i, j)，加到对应窗口上）
```

dW 对 n 求和，因为同一组权重被批里的每张图都用了一次。dX 对 f 求和，因为同一个输入像素被每个核都读了一次。

如果前向做了 padding，上面的 X 是补过的 Xp，算出来的是 dXp。补的那圈 0 不是真正的输入，最后把 dXp 中间的 H×W 裁出来就是 dX（数学结论：补的 0 是常数，它们的梯度直接丢掉）。

### 28.5.3 手算一个完整例子

换一个更小的例子，所有值都不同，方便核对。单样本、单通道，s = 1，p = 0：

```text
X (3×3)        W (2×2)       b = 0.5
1 2 0           1 -1
0 1 3           2  0
2 1 0
```

**前向**，Y 是 2×2：

```text
Y[0,0] = 1·1 + 2·(−1) + 0·2 + 1·0 + 0.5 = −0.5
Y[0,1] = 2·1 + 0·(−1) + 1·2 + 3·0 + 0.5 =  4.5
Y[1,0] = 0·1 + 1·(−1) + 2·2 + 1·0 + 0.5 =  3.5
Y[1,1] = 1·1 + 3·(−1) + 1·2 + 0·0 + 0.5 =  0.5
```

**上游梯度**，设 L = Σ Y ⊙ G，G 是一个随便取的 2×2 矩阵。L 是 Y 各元素的加权和，Y[i, j] 的系数就是 G[i, j]，所以 dY = G：

```text
dY = 1  0
     2 −1
```

**db** = 1 + 0 + 2 − 1 = **2**。

**dW**，s = 1，直接用 dY 在 X 上做互相关：

```text
dW[0,0] = 1·X[0,0] + 0·X[0,1] + 2·X[1,0] − 1·X[1,1] = 1 + 0 + 0 − 1 = 0
dW[0,1] = 1·X[0,1] + 0·X[0,2] + 2·X[1,1] − 1·X[1,2] = 2 + 0 + 2 − 3 = 1
dW[1,0] = 1·X[1,0] + 0·X[1,1] + 2·X[2,0] − 1·X[2,1] = 0 + 0 + 4 − 1 = 3
dW[1,1] = 1·X[1,1] + 0·X[1,2] + 2·X[2,1] − 1·X[2,2] = 1 + 0 + 2 − 0 = 3
```

**dX**，从全零的 3×3 开始，对每个输出位置把 dY[i, j]·W 撒回窗口：

```text
(0,0) 撒 1·W 到左上：   (0,1) 撒 0·W：         (1,0) 撒 2·W 到左下：  (1,1) 撒 −1·W 到右下：
 1 −1  0                什么也不加              0  0  0                0  0  0
 2  0  0                                        2 −2  0                0 −1  1
 0  0  0                                        4  0  0                0 −2  0
```

四块加起来：

```text
dX =  1 −1  0
      4 −3  1
      4 −2  0
```

核对中心那个数。X[1, 1] 在四个窗口里，按窗口 (0,0)、(0,1)、(1,0)、(1,1) 的顺序，它在窗口里的位置分别是 (1,1)、(1,0)、(0,1)、(0,0)，系数分别是 W[1,1] = 0、W[1,0] = 2、W[0,1] = −1、W[0,0] = 1，再各乘对应的 dY，所以 dX[1,1] = 1·0 + 0·2 + 2·(−1) + (−1)·1 = −3。四份贡献相加，和 28.5.1 节猜的一样。

以上全部是数学结论；用 `conv_backward` 和 `numerical_gradient` 在 CPU 上复跑，三个梯度与手算一致。

**步长为 2 时怎么办？** 规则不变，只是窗口起点隔 2 格。窗口不重叠时（比如 2×2 核、步长 2），每个输入像素只被读一次，dX 里不会出现累加；窗口重叠时（3×3 核、步长 2）照样累加。28.3.3 节说步长 2 等于按步长 1 算完再隔一个取一个，反向时就等于被扔掉的那些位置梯度为 0。

### 28.5.4 对照代码：`conv_backward`

```python
def conv_backward(dout, cache):
    x, weight, stride, padding = cache
    kh, kw = weight.shape[-2:]
    ...  # 检查 dout 形状与前向输出一致
    xp = np.pad(x, ((0, 0), (0, 0), (padding, padding), (padding, padding)))
    dxp, dw = np.zeros_like(xp), np.zeros_like(weight)
    for i in range(dout.shape[2]):
        for j in range(dout.shape[3]):
            a, b = i * stride, j * stride
            g = dout[:, :, i, j]
            dw += np.einsum("nf,nchw->fchw", g, xp[:, :, a:a+kh, b:b+kw])
            dxp[:, :, a:a+kh, b:b+kw] += np.einsum("nf,fchw->nchw", g, weight)
    return dxp[:, :, padding:padding+x.shape[2], padding:padding+x.shape[3]], dw, dout.sum((0, 2, 3))
```

用 28.5.3 节的数字：`x` 形状 (1, 1, 3, 3)，`weight` (1, 1, 2, 2)，`dout` (1, 1, 2, 2)。

1. **重新补 padding。** 前向缓存里存的是没补的 `x`，这里补一遍得 `xp`。p = 0 时不变。
2. **`dxp`、`dw` 初始化为全零。** 这一步是累加的前提。
3. **循环到 (i, j) = (1, 0)。** 窗口起点 `a, b = 1, 0`。`g = dout[:, :, 1, 0]`，形状 (N, F) = (1, 1)，值 2。
4. **`dw +=`。** `einsum("nf,nchw->fchw")` 对 n 求和，把 2 乘上窗口 `xp[:, :, 1:3, 0:2]` = `[[0,1],[2,1]]`，得 `[[0,2],[4,2]]`，加进 dW。四个位置都加完，dW 就是 28.5.3 节的 `[[0,1],[3,3]]`。
5. **`dxp[...] +=`。** `einsum("nf,fchw->nchw")` 对 f 求和，得 2·W = `[[2,−2],[4,0]]`，加到 `dxp` 的第 1 到 2 行、第 0 到 1 列。这里的 `+=` 就是 28.5.2 节的撒回去、重叠处累加。
6. **裁掉 padding。** 写成 `padding:padding+H`，而不是 `p:-p`：p = 0 时 `0:-0` 是空切片，会返回空数组。
7. **db。** `dout.sum((0, 2, 3))` 对 N、H、W 求和，保留 F 维：1 + 0 + 2 − 1 = 2。

### 28.5.5 数值梯度检查

手算一个例子只能证明这个例子对。要证明代码对，用第 2 章的中心差分：对 x、w、b 的**每一个坐标**分别加减 ε = 1e-5，看 L 变了多少，和解析梯度比。

`numerical_gradient` 要求 float64，扰动后用 `finally` 恢复原值，保证一个坐标的扰动不会漏到下一个坐标。

lab 第 1 部分用三组几何 (s, p) = (1, 0)、(1, 1)、(2, 1)，输入 2×2×4×5，核 3×2×2×3（矩形核），对全部 357 个坐标做中心差分（数学结论：每组 x 有 80 个、w 有 36 个、b 有 3 个，共 119 个，三组 357 个），再与 PyTorch 的 `F.conv2d` 前后向对拍：

| 检查 | 结果 |
|---|---|
| 中心差分 vs 解析梯度，最大绝对误差 | 6.879e-10 |
| 中心差分 vs 解析梯度，最大相对误差 | 5.351e-09 |
| 前向 vs `F.conv2d`，最大绝对误差 | 1.776e-15 |
| 反向 vs PyTorch autograd，最大绝对误差 | 2.220e-15 |

（本项目观察：租用 RTX 4090 主机的 CPU，float64，数据种子 28，0 训练步，`final/part1.json`、`final/gradients.csv`。本地 CPU 用默认种子 0 复跑，同样 357 个坐标，最大绝对误差 7.869e-10、最大相对误差 7.144e-09，量级一致。）

怎么读这些数：一般函数的中心差分有 O(ε²) 量级的截断误差（数学结论，第 2 章 2.8 节的泰勒展开；O(ε²) 说的是随 ε 缩小的速度，不是说误差的数值就等于 ε²）。但这里的检查目标 `(conv_forward(...) * dy).sum()` 对每个被扰动的坐标都是仿射函数（卷积对 x、w、b 各自都是线性的），三阶导数为零，精确算术下中心差分根本没有截断误差（数学结论）。实测的 1e-10 左右差别来自浮点舍入，再被差分时两个相近数相减放大，所以可以视为一致。和 PyTorch 对拍的 1e-15 是浮点舍入的量级，说明两边算的是同一个东西。如果相对误差到了 1e-3 以上，几乎肯定是代码错了。

### 28.5.6 常见错误

| 错误 | 现象 | 怎样发现 |
|---|---|---|
| `dxp[...] = ...` 写成赋值而不是 `+=` | dX 在窗口重叠处偏小；stride = 2、2×2 核时窗口不重叠，反而对 | 用 stride = 1 的几何做梯度检查 |
| 裁 padding 写成 `dxp[:, :, p:-p, p:-p]` | p = 0 时返回空数组 | 测试必须包含 p = 0 |
| dW 忘了对 n 求和（只用了第一张图） | 批大小 1 时对，批大小 2 时错 | 梯度检查用 N ≥ 2 |
| 窗口起点忘乘 stride | stride = 1 对、stride = 2 错 | 几何里放一组 stride = 2 |
| 梯度检查用 float32 | 相对误差 1e-3 量级，分不清是代码错还是精度不够 | `numerical_gradient` 直接拒绝非 float64 |
| 只用正方形的核和图 | 把 kh、kw 或 H、W 写反也测不出来 | 用 4×5 的输入和 2×3 的核 |

lab 和测试的几何都特意选了矩形核、非正方形输入、N = 2、包含 p = 0 和 stride = 2，就是为了让上面每一种错误都暴露出来。

## 28.6 感受野：一个输出能看到多大一块

### 28.6.1 为什么要看得更广

第一层 3×3 卷积的每个输出只看到 3×3 的输入。一个字符通常比 3×3 大得多，3×3 的窗口只能看到它的一小段笔画。网络要认出整个字符，后面的层必须看得更广。一个输出单元依赖的输入区域叫它的**感受野**（receptive field）。

### 28.6.2 直觉：两层叠起来看到多大

第二层的一个单元看第一层的 3×3 个单元，而第一层的每个单元又各自看输入的 3×3。两层叠起来，第二层单元间接看到了输入的 5×5（中心那块被重复看了好几次）。先只看一维：第二层的一个单元读第一层第 0、1、2 号单元，它们在输入上分别覆盖第 0 到 2、1 到 3、2 到 4 个像素，合起来是第 0 到 4 个像素，共 5 个。

如果中间夹了一个步长 2 的池化，池化后相邻的两个单元在输入上隔 2 个像素，下一层看 3 个相邻单元，就等于在输入上跨出更远。步长让感受野**加速**扩大。

### 28.6.3 推导递推公式

记第 l 层：

- r_l：一个单元在输入上的感受野边长；
- j_l：这一层相邻两个单元在输入上隔多少像素，叫**跳距**（jump）。

输入层 r_0 = 1、j_0 = 1。

第 l 层（核 k_l，步长 s_l）的一个单元看上一层连续 k_l 个单元。这 k_l 个单元中，相邻两个在输入上隔 j_{l−1}，首尾两个就相距 (k_l − 1)·j_{l−1}；每个单元自己又覆盖 r_{l−1} 宽。从第一个单元感受野的左端量到最后一个单元感受野的右端，长度是首尾的距离加上一个单元自己的宽度，也就是 r_{l−1} + (k_l − 1)·j_{l−1}。跳距的递推更直接：这一层相邻两个单元在上一层隔 s_l 个单元，上一层每个单元在输入上隔 j_{l−1}，相乘就是 j_l。所以

```text
r_l = r_{l−1} + (k_l − 1) · j_{l−1}
j_l = j_{l−1} · s_l
```

（数学结论。）空洞卷积把 k_l 换成 d(k_l − 1) + 1。padding 不改变感受野的大小，只改变它的位置（边缘单元的感受野有一部分落在补的 0 上）。

### 28.6.4 数值例子：本章的 CNN

本章 CNN 是"3×3 卷积 → 2×2 池化 → 3×3 卷积 → 2×2 池化"，输入 32×32。池化也是一个局部窗口，用同一个公式：

| 层 | k, s, p | 输出边长 | 感受野 r | 跳距 j |
|---|---|---:|---:|---:|
| 输入 | | 32 | 1 | 1 |
| conv 3×3 | 3, 1, 1 | 32 | 1 + 2·1 = 3 | 1 |
| maxpool 2×2 | 2, 2, 0 | 16 | 3 + 1·1 = 4 | 2 |
| conv 3×3 | 3, 1, 1 | 16 | 4 + 2·2 = 8 | 2 |
| maxpool 2×2 | 2, 2, 0 | 8 | 8 + 1·2 = 10 | 4 |

（数学结论；lab 第 2 部分用 `receptive_field` 和 `output_size` 输出相同的 32→32→16→16→8、感受野 10、跳距 4，见 `final/geometry.csv`。）

最后得到 8×8 个位置、每个位置 48 个通道的特征。每个位置看到输入的 10×10，相邻位置隔 4 个像素。然后 `Flatten` + 全连接层把 8×8 个位置全部连起来，所以整个分类器的输出依赖全部 32×32 个像素。不要把"10×10"说成整网的感受野，它只是最后一张特征图上单个位置的感受野。

另一个经典结论：三个 3×3、步长 1 的卷积叠起来，感受野是 3 → 5 → 7，和一个 7×7 卷积一样大（数学结论）。但单通道时参数是 3 × 9 = 27 对 49，中间还多了两次非线性。VGG 网络主要堆叠 3×3 小核，理由就在这里（见 28.10 节）。

### 28.6.5 对照代码：`receptive_field`

```python
def receptive_field(layers):
    field, jump, center = 1, 1, .5
    rows = []
    for kernel, stride, padding, dilation in layers:
        ...  # 检查几何合法
        effective = dilation * (kernel - 1) + 1
        center += ((effective - 1) / 2 - padding) * jump
        field += (effective - 1) * jump
        jump *= stride
        rows.append(dict(field=field, jump=jump, center=center))
    return rows
```

- `field, jump = 1, 1`：输入层 r_0 = 1、j_0 = 1。
- `field += (effective - 1) * jump`：r_l = r_{l−1} + (k − 1)·j_{l−1}。注意它用的是**更新前**的 `jump`，所以这一行必须写在 `jump *= stride` 之前。用上表第二行：池化时 `jump` 还是 1，field = 3 + 1·1 = 4；之后 jump 才变成 2。
- `center` 记第一个输出单元的感受野中心在输入上的坐标（像素中心从 0.5 开始），用来看 padding 把感受野往外推了多少。本章 CNN 最后一层第一个单元的中心是 2.0（数学结论，`geometry.csv`）：10×10 的感受野有一部分落在补的白边上。

### 28.6.6 理论感受野不等于有效感受野

上面算的是**理论**感受野：输入里这一块之外的像素，改了也不影响输出。但这一块里的像素影响并不均匀，中心像素经过的路径最多，边缘像素的路径少得多。训练后的网络实际"在乎"的区域往往比理论值小（待验证：本章没有测量有效感受野）。

### 28.6.7 常见错误

- **先更新 jump 再加 field。** 现象：池化层之后感受野多算。用本章 CNN 检查：错的写法会让最后一层得 13 而不是 10。
- **把池化层漏掉。** 池化也是一个窗口，也扩大感受野、也乘跳距。
- **把最后一张特征图的感受野当成整网的。** 后面接全连接或全局池化时，整网输出看的是整张图。

> **停下来想一想：** 把本章 CNN 的两个池化都去掉（只保留两层 3×3 卷积），最后一层感受野和跳距各是多少？假设一个字符 20 像素宽，为了让一个单元看到整个字符，要叠多少层 3×3 卷积？

## 28.7 连续下采样为什么损伤小字和细线

### 28.7.1 下采样的代价

感受野要扩大，又不想叠几十层，最省事的办法就是下采样：池化或步长 2 的卷积，每次把边长减半。本章 CNN 两次池化，跳距从 1 变成 4。代价是什么？

第 27 章已经看到，缩小图片时细线会变淡甚至消失。这一节把同一个道理用到网络内部：下采样就是在网络里缩图，而且通常要缩好几次。

### 28.7.2 推导：每次平均池化，1 像素的线淡一半

取一条横着的、1 像素粗、足够长的线（墨迹 1，白纸 0），做一次 2×2 平均池化。每个 2×2 的块里正好有 2 个墨迹像素、2 个白纸像素，平均值 0.5。

再做一次，相当于对原图做 4×4 平均：每块 16 个像素里有 4 个是线，平均 0.25。一般地，做 n 次后（这里用 n 表示池化次数，免得和卷积核大小 k 混淆），每个 2^n × 2^n 块里有 2^n 个线像素：

```text
线的对比度 = 2^n / 4^n = 1 / 2^n
```

（数学结论。）2 次后 0.25，3 次后 0.125。这和线落在块的什么位置无关，因为 1 像素粗的线总是完整地落在某一行块里。

2 像素粗的线就和位置有关了：如果两行正好落在同一个块里，一次池化后还是 1.0；如果跨在两个块的边界上，两边各得 0.5（数学结论，CPU 复跑核对）。这就是第 27 章说的"相位"问题。

如果后面用"像素值 > 0.5 才算墨迹"来判断，1 像素的线在第一次平均池化后就正好卡在 0.5，已经不算墨迹了。

最大池化（max pooling）对**深色墨迹**能保住细线：块里只要有一个墨迹像素，最大值就是 1。本章 CNN 用的就是最大池化。但它也有代价：间隔 1 像素的两条细线（比如 `=` 号在很小字号下）会被并成一团，位置信息照样丢了（数学结论）。

注意两条 1 像素线中间隔一行空白，至少占 3 行，不可能落在同一个 2×2 块里；合并的原因是空白那一行被吃掉了：纵向截面 `[1, 0, 1, 0]` 做核 2、步长 2 的最大池化得到 `[1, 1]`，两条线来自不同窗口，但输出里两个相邻位置都是墨迹，中间的空隙消失了。而且网络中间的特征图不一定是墨迹为正的，最大池化保住的是某个特征的响应，不是笔画本身。

### 28.7.6 常见错误

- **只看整图 MSE 或 PSNR。** 白纸占多数，指标好看，笔画却没了。要看前景。
- **以为放大回去就恢复了。** 最近邻或双线性放大只是复制或插值，不会凭空长出丢掉的笔画。lab 放回原尺寸只是为了逐坐标比较。
- **奇数尺寸直接池化。** 最后一行、一列被向下取整扔掉（28.3.3 节）。
- **把像素损伤当识别率报告。** 像素指标只说明信息变少了，模型能否识别要另外测。

## 28.8 BatchNorm

### 28.8.1 BatchNorm 解决什么问题

网络越深，中间特征的数值越容易忽大忽小：某一层输出整体偏大或偏小，下一层的 ReLU 可能几乎全开或几乎全关，全关时梯度传不回去；尺度层层连乘下来，梯度也容易爆炸或消失。第 9 章用 LayerNorm 解决 Transformer 里的这个问题。在 CNN 里，最常见的做法是 **BatchNorm**（批归一化，Ioffe & Szegedy 2015）。

它的作用可以概括成三条（来自文献，本章没有用训练实验验证）：

1. 让每一层的输入保持在大致固定的尺度，可以用更大的学习率、对初始化不那么敏感。
2. 统计量来自一批随机样本，带一点噪声，有轻微的正则化效果。
3. 原论文把动机解释为减少"内部协变量偏移"；后来的研究（Santurkar et al., 2018）认为它主要是让损失曲面更平滑。为什么有效，至今仍有讨论。

本章的 CNN 没有用 BatchNorm，所以这些作用本章**没有测**。本章实测的是它的**机制**：算得对不对，训练和推理有什么不同。

### 28.8.2 公式：每个通道一套统计量

输入 X 形状 (N, C, H, W)。对每个通道 c，把这一批里所有图、所有位置的值放在一起（共 N·H·W 个数），求均值和方差：

```text
μ_c  = mean over (n, h, w) of X[n, c, h, w]
σ²_c = mean over (n, h, w) of (X[n, c, h, w] − μ_c)²        （除以 N·H·W，有偏）
X̂[n, c, h, w] = (X[n, c, h, w] − μ_c) / √(σ²_c + ε)
Y[n, c, h, w] = γ_c · X̂[n, c, h, w] + β_c
```

γ、β 是每个通道一对的可学习参数，让网络在需要时把标准化撤回去：对某一组固定的统计量，取 γ_c = √(σ²_c + ε)、β_c = μ_c，Y 就正好等于 X。训练时每批的 μ、σ² 都在变，γ、β 却是跨批共享的，所以这只说明网络有能力学回原来的尺度，不是每一批都能精确还原。ε 防止除以 0，默认 1e-5。

为什么对 H、W 也一起求？因为卷积在所有位置共享同一个核，同一通道在不同位置是同一种特征，应该用同一套统计量。

**训练和推理不一样。** 训练时用当前这一批的 μ、σ²，同时维护一份滑动平均：

```text
running_mean ← (1 − m) · running_mean + m · μ
running_var  ← (1 − m) · running_var  + m · σ²_unbiased      （σ² 乘 n/(n−1)，n = N·H·W）
```

m 是 momentum，默认 0.1，表示**新观测**的权重。推理时（eval 模式）不再看当前批，直接用 running_mean、running_var。这样同一张图不管和谁放在一批，输出都一样。

注意两个方差不一样：标准化用有偏方差（除以 n），running_var 存无偏方差（除以 n − 1）。这是 PyTorch 的约定，手写时要对齐，否则和 `nn.BatchNorm2d` 对拍会差一点点。

### 28.8.3 手算：两张图、一个通道

形状 (N, C, H, W) = (2, 1, 1, 2)。γ = 1，β = 0，running_mean 初值 0，running_var 初值 1，m = 0.1。

```text
图 0：[1, 3]
图 1：[5, 7]
```

**训练模式**，通道 0 的 4 个值是 1, 3, 5, 7。

- μ = 4
- σ²（有偏）= (9 + 1 + 1 + 9) / 4 = 5
- 输出 = (x − 4) / √5 = [−1.342, −0.447]、[0.447, 1.342]
- running_mean = 0.9 · 0 + 0.1 · 4 = 0.4
- running_var = 0.9 · 1 + 0.1 · (5 · 4/3) = 0.9 + 0.667 = 1.567

**切到推理模式，同一批再算一次。** 现在用 running 统计：输出 = (x − 0.4) / √1.567 = [0.479, 2.077]、[3.675, 5.273]。

和训练时差了很多。只训练了一步，running 统计离真实统计还很远。"模型刚训练几步，eval 结果一塌糊涂"，常见原因就是这个：running 统计要攒足够多的批才可靠。

**换掉同伴**，回到训练模式（新建一层），把图 1 换成 [15, 17]，图 0 不变。通道的 4 个值是 1, 3, 15, 17，μ = 9，σ² = 50。图 0 的输出变成 (1 − 9)/√50 = −1.131、(3 − 9)/√50 = −0.849，而原来是 −1.342、−0.447。图 0 自己一个像素都没动，输出却变了。

**LayerNorm 对照**，LayerNorm 对单个样本的 (C, H, W) 求统计。图 0 是 [1, 3]，μ = 2、σ² = 1，输出 [−1, 1]；不管图 1 是 [5, 7] 还是 [15, 17]，图 0 的输出都是 [−1, 1]。

（以上为数学结论；用 `ManualBatchNorm2d` 和 `nn.LayerNorm` 在 CPU 上复跑，结果与手算一致，保留 3 位小数。）

### 28.8.4 BatchNorm 和 LayerNorm 的区别

| | BatchNorm2d | LayerNorm（用在 CNN 特征上时） |
|---|---|---|
| 统计哪些值 | 每个通道：所有 N、H、W | 每个样本：所有 C、H、W（或只对 C） |
| 一张图的输出受同批别的图影响吗 | 训练时受影响，推理时不受 | 不受 |
| 训练和推理行为一样吗 | 不一样，推理用 running 统计 | 一样 |
| 有额外状态吗 | running_mean、running_var | 没有 |
| 批很小时 | 统计量噪声大，效果变差 | 不受批大小影响 |
| 常见用途 | CNN（ResNet 等） | Transformer、ViT、语言模型 |

一个容易混的点：LayerNorm 用在 CNN 特征上时，可以只对通道维 C 归一化（每个位置单独一套统计，ConvNeXt 就是这样用的），也可以对 (C, H, W) 一起。本章实验用的是后者。

### 28.8.5 实测：批同伴对输出的影响

lab 第 4 部分把 28.8.3 节的实验放大：一批 8 张图，形状 (8, 3, 6, 5)。固定第一张（anchor），把其他 7 张整体加 5，比较 anchor 的输出变化：

| 模式 | BatchNorm：anchor 输出的平均绝对变化 | LayerNorm：同上 |
|---|---:|---:|
| train | 2.366321 | 0 |
| eval | 0 | 0 |

同时，手写的 `ManualBatchNorm2d` 和 `nn.BatchNorm2d` 对拍：前向最大误差 4.768e-07、dx 4.768e-07、dweight 5.722e-06、running_var 5.960e-08。

（本项目观察，RTX 4090（租用），CUDA fp32，N = 8、C = 3、H = 6、W = 5，0 训练步，`final/part4.json`、`final/normalization.csv`。fp32 下 1e-7 到 1e-6 的误差是舍入量级。本地 CPU 用默认种子 0 复跑，随机输入不同，BN train 变化为 2.293，eval 和 LN 同样为 0。）

BatchNorm 训练时有批依赖，eval 时没有；LayerNorm 从来没有。这个实验只说明统计依赖，**不**说明哪个分类效果更好。

### 28.8.6 对照代码：`ManualBatchNorm2d.forward`

```python
def forward(self, x):
    ...
    if self.training:
        count = x.numel() // x.shape[1]
        if count <= 1:
            raise ValueError("BatchNorm training needs more than one value per channel")
        mean = x.mean((0, 2, 3))
        var = ((x - mean[None, :, None, None]) ** 2).mean((0, 2, 3))
        with torch.no_grad():
            self.running_mean.lerp_(mean.detach(), self.momentum)
            self.running_var.lerp_(var.detach() * count / (count - 1), self.momentum)
            self.num_batches_tracked.add_(1)
    else:
        mean, var = self.running_mean, self.running_var
    normalized = (x - mean[None, :, None, None]) * torch.rsqrt(var[None, :, None, None] + self.eps)
    return normalized * self.weight[None, :, None, None] + self.bias[None, :, None, None]
```

用 28.8.3 节的数字（x 形状 (2, 1, 1, 2)）：

- `count = 4 // 1 = 4`，即每个通道 N·H·W = 4 个值。只有 1 个值时方差恒为 0、无偏修正要除以 0，所以直接报错。
- `x.mean((0, 2, 3))`：对 N、H、W 求均值，保留 C，得 `[4.]`。这一行的轴决定了它是 BatchNorm；换成 `(1, 2, 3)` 就成了对每个样本求，变成 LayerNorm 式的统计。
- `var`：有偏方差 `[5.]`。
- `lerp_(new, m)` 计算 `old + m·(new − old)` = `(1 − m)·old + m·new`，也就是滑动平均。running_var 用 `var * 4/3` 做无偏修正：0.9 + 0.1 · 6.667 = 1.567。
- `torch.no_grad()`：running 统计只是记账，不能参与求导。
- `else` 分支：eval 模式用 running 统计。
- `mean[None, :, None, None]`：把 (C,) 变成 (1, C, 1, 1)，才能沿 N、H、W 广播。

反向没有手写，交给 autograd。均值和方差都依赖每个输入，所以 BN 的 dx 公式比卷积复杂（选做练习 28.5）。

`self.training` 由 `model.train()` / `model.eval()` 切换。

### 28.8.7 常见错误

| 错误 | 现象 | 怎样发现 |
|---|---|---|
| 推理时忘了 `model.eval()` | 同一张图单独推理和放在批里推理结果不同；running 统计还在被测试数据改写 | 同一张图换不同的同伴各推理一次，输出应完全相同 |
| 以为 `torch.no_grad()` 会切换 eval | `no_grad` 只关梯度，BN 仍用批统计，还会更新 running 统计 | 推理前后比较 running_mean 是否变了 |
| 归一化轴写成 (1, 2, 3) | 成了逐样本归一化，和 `nn.BatchNorm2d` 对不上 | 对拍 |
| running_var 用有偏方差 | 每一步并入的本批方差少了 n/(n−1) 因子（不是整个 running_var 差一个倍数），n 小时明显；28.8.6 节的例子里正确值 1.567，错误值 0.9 + 0.1 · 5 = 1.4 | 对拍 running_var |
| 把 momentum 理解成旧值的权重 | running 统计几乎不更新或更新太猛 | 手算一步 |
| 批太小（如 2）还用 BN | 训练不稳定，train 和 eval 差距大 | 改用 GroupNorm/LayerNorm，或增大批 |

## 28.9 CNN 与 MLP：符号分类上的实测对比

### 28.9.1 实验设计

这一节把第 5 章的符号分类器重做一次，回答一个问题：**参数量相当时，卷积结构本身带来多少好处？**

- **数据：** 第 5 章的受控合成符号，24 类、每类 400 个来源、每个来源 4 张，共 38,400 张 32×32 灰度图。按来源组 80/10/10 划分：训练 30,720、验证 3,840、测试 3,840，三个集合没有共享来源组。数据种子 28，划分种子 0。
- **CNN：** conv(1→24, 3×3) → ReLU → maxpool → conv(24→48, 3×3) → ReLU → maxpool → Linear(48·8·8 → 24)。和第 5 章宽度 24 的 SymbolCNN 是同一个结构。
- **MLP：** Linear(1024 → 72) → ReLU → Linear(72 → 72) → ReLU → Linear(72 → 24)。
- **训练：** 同样的数据、取批顺序（按种子配对），AdamW、lr = 0.001、weight_decay = 0.0001、batch 256、5000 步、fp32，无额外增广。种子 0、1、2。
- **选模型：** 每个模型、每个种子只按验证集交叉熵最低选检查点；全部写入冻结文件后，这六个预先登记的模型才对测试集各评一次，不看测试集错例，也不据此改设置。

参数量（数学结论，和 `training.json` 记录一致）：

```text
CNN：conv1 (1·9 + 1)·24 = 240；conv2 (24·9 + 1)·48 = 10,416；fc (3072 + 1)·24 = 73,752；合计 84,408
MLP：(1024 + 1)·72 = 73,800；(72 + 1)·72 = 5,256；(72 + 1)·24 = 1,752；合计 80,808
```

两者差 4.5%，接近但不相等；计算量（FLOPs）差得更多。所以这是参数量相当的对照，不是严格等参数、等计算量的对照。

### 28.9.4 下采样后的识别率

28.7 节测的是像素。这里直接测识别：拿已经选定的模型（不重新训练），把验证图做 2^k 倍平均池化、再最近邻放回 32×32，看准确率：

| 模型 | 原图 | 2× | 4× | 8× |
|---|---:|---:|---:|---:|
| MLP | 80.16% | 79.53% | 53.39% | 17.64% |
| CNN | 93.69% | 89.50% | 49.13% | 17.17% |

（本项目观察，RTX 4090（租用），CUDA fp32，验证集 3840 张，3 个种子的均值，`final/training.json` 中的 `degradation`。随机猜的准确率是 1/24 ≈ 4.17%，数学结论。）

逐列看：

1. **2× 时 CNN 掉了 4.2 个百分点，MLP 只掉 0.6 个。** CNN 依赖的细节在第一次平均池化里就受了损。
2. **4× 时 CNN 反而低于 MLP。** 三个种子都是这样：CNN 为 46.64%、50.63%、50.13%，MLP 为 52.99%、54.87%、52.32%。
3. **8× 时两者都接近崩溃**，均值只差 0.47 个百分点，种子之间的波动（MLP 16.02% 到 19.30%，CNN 16.54% 到 17.53%）比这个差距还大，不能说谁更好。

一种可能的解释：训练图都是清晰的，CNN 学会了依赖细笔画和边缘这些局部细节，它们也是下采样最先抹掉的；MLP 本来就更依赖墨迹的大致分布，模糊后反而损失较小。这只是假设（待验证）。一个验证办法是训练时加入随机下采样增广，看 CNN 在 4× 上能不能追回来（练习 28.6）。

这和项目直接相关：在清晰图上更强的模型，不一定在模糊图上更强。像素放回原尺寸后形状完全正常，模型却已经认不出来了。

### 28.9.5 结论的适用范围

在这份受控合成数据、这个配置下，参数相当的两层 CNN 比两隐藏层 MLP 准确率高 13 个百分点左右，三个种子一致，测试区间不重叠。这不等于 CNN 在任何任务上都胜过 MLP，也不能说明这个差距能搬到真实公式 OCR 上（本章没有训练公式识别模型）。参数量不完全相等，计算量更不相等。没有增广，下采样鲁棒性的结论只适用于在清晰图上训练这一设定。

## 28.10 经典 CNN 架构的演进（概括）

这部分只需要知道每一代改了什么、为什么改：

| 网络 | 论文年份 | 关键想法 |
|---|---|---|
| LeNet-5（LeCun 等） | 1998 | 卷积 + 池化 + 全连接的基本套路，用于手写数字 |
| AlexNet（Krizhevsky 等） | 2012 | 更深更宽、ReLU、Dropout、GPU 训练，在 ImageNet 上大幅领先 |
| VGG（Simonyan & Zisserman） | 2014/2015 | 主要用 3×3 小核堆叠（28.6.4 节的感受野论证），结构规整 |
| GoogLeNet / Inception（Szegedy 等） | 2015 | 一层里并联多种尺寸的核，用 1×1 卷积降通道省计算 |
| ResNet（He 等） | 2016 | 残差连接（第 9 章的"在原稿上批改"），让上百层也能训练；大量使用 BatchNorm |
| ConvNeXt（Liu 等） | 2022 | 借鉴 ViT 的设计（大核、LayerNorm、更少的归一化层），重新把纯 CNN 做到与 ViT 相当 |

（年份为论文发表年份；表中都是文献中的说法，本章没有复现。）

ResNet 的基本单元是这样的：

- **基本块：** 3×3 卷积 → BN → ReLU → 3×3 卷积 → BN，再加上输入（残差），最后 ReLU。卷积后面紧跟 BN，所以卷积不需要偏置（BN 会减掉均值，偏置被抵消）。
- **下采样：** 每个阶段开头用步长 2 的卷积把边长减半、通道加倍；残差那条路用 1×1、步长 2 的卷积对齐形状。
- **瓶颈块：** 更深的版本用 1×1（降通道）→ 3×3 → 1×1（升通道），省计算。

整体上，一个 ResNet 从 224×224 的输入开始，经过一个步长 2 的卷积、一个步长 2 的池化和三次阶段间的步长 2 下采样，最后一层的跳距是 32（数学结论：2⁵ = 32）。这又是 28.7.5 节说的像素变粗：一个 32×32 的格子就是最后一层的一个位置。

## 28.13 和真实框架的对应

以下按本地 PyTorch 2.14.1 的函数签名核对。

**`torch.nn.Conv2d(in_channels, out_channels, kernel_size, stride=1, padding=0, dilation=1, groups=1, bias=True, padding_mode='zeros')`。**

- `weight` 形状 (out_channels, in_channels / groups, kH, kW)，`bias` 形状 (out_channels,)，和本章 OIHW 一致。算的是互相关。
- `kernel_size`、`stride`、`padding`、`dilation` 可以是整数或 (高, 宽) 二元组。输出尺寸就是 28.3.2 节的公式，高宽各算一次。
- `padding` 还可以是字符串 `'valid'`（等于 0）或 `'same'`（保持尺寸，只支持 stride = 1）。
- `padding_mode` 可选 `'zeros'`、`'reflect'`、`'replicate'`、`'circular'`。本章只用补 0。
- `groups` > 1 时通道分组各自卷积；`groups = in_channels` 就是逐通道（depthwise）卷积。
- 后面接 BatchNorm 时，通常写 `bias=False`。

**`torch.nn.functional.conv2d(input, weight, bias=None, stride=1, padding=0, dilation=1, groups=1)`。** 函数版，权重自己传。本章测试和 lab 第 1 部分用它对拍。注意它的 `bias` 默认是 `None`，而 `nn.Conv2d` 默认带偏置。在 CUDA 上 cuDNN 可能选非确定性算法，lab 设了 `torch.backends.cudnn.deterministic = True` 并关了 TF32。

**`torch.nn.BatchNorm2d(num_features, eps=1e-05, momentum=0.1, affine=True, track_running_stats=True)`。**

- `num_features` 就是通道数 C。统计轴 (N, H, W)。
- `momentum` 是新观测的权重，和本章一致；设成 `None` 时改用累计平均（所有批等权）。
- `affine=False` 时没有 γ、β。
- `track_running_stats=False` 时不维护 running 统计，**eval 模式下也用当前批的统计**。
- 训练时标准化用有偏方差，`running_var` 存无偏方差；`num_batches_tracked` 计数。
- `model.train()` / `model.eval()` 切换 `self.training`；`torch.no_grad()` 不会切换。

**池化。** `nn.MaxPool2d(kernel_size, stride=None, padding=0, ..., ceil_mode=False)`，`stride` 默认等于 `kernel_size`；`ceil_mode=False` 就是向下取整，核和步长都是 2 时奇数边会扔掉最后一行。`F.avg_pool2d` 同理。lab 第 3 部分用 `F.avg_pool2d` 做下采样。

## 28.14 小结

卷积用一个在图上滑动、处处共享的小核做加权求和，权重共享省的是参数，不是计算。它的反向是三条规则，其中 dX 要把每个窗口的贡献累加回去；用 float64 的中心差分可以把手写实现核对到 1e-10 量级。叠层、池化和步长让感受野逐层扩大，代价是网络的像素越来越粗：每次 2×2 平均池化让 1 像素的细线淡一半，本章实测真实公式缩 2 倍就有约四分之三的前景像素跌到阈值以下。BatchNorm 按通道在整批上标准化，训练时有批依赖、推理时用滑动平均，LayerNorm 则只看单个样本。在受控符号分类上、只用清晰图训练时，参数相当的 CNN 比 MLP 高约 13 个百分点，但 4 倍下采样后反而不如 MLP，所以清晰图上的强弱不能直接搬到模糊的小字上。

复习时抓住下面几条：

- **前向**：Y[n, f, i, j] = Σ_c Σ_p Σ_q W[f, c, p, q] · X[n, c, i·s + p, j·s + q] + b[f]，X 是补过 padding 的输入。框架算的是不翻转核的互相关。权重形状 (F, C, kH, kW)，参数量 F·C·kH·kW + F。
- **输出尺寸**：H' = ⌊(H + 2p − d(k − 1) − 1)/s⌋ + 1，d = 1 时就是 ⌊(H + 2p − k)/s⌋ + 1，数的是窗口能放下几次。k = 3、p = 1、s = 1、d = 1 时尺寸不变。向下取整会扔掉不够一个窗口的边角，奇数边长做 2×2、步长 2 的池化会丢掉最后一行。
- **反向**：db[f] 是 dY[n, f, ·, ·] 对 n、i、j 求和；dW[f, c, p, q] = Σ_n Σ_i Σ_j dY[n, f, i, j] · X[n, c, i·s + p, j·s + q]，s = 1 时就是拿 dY 在 X 上做互相关，s > 1 时相当于先在 dY 的元素之间插 s − 1 个零再互相关，只取前 k 个结果；dX 对每个 (i, j) 把 Σ_f dY[n, f, i, j] · W[f, c] 加回它读过的窗口，重叠处累加，有 padding 时最后裁掉补的那圈。
- **感受野**：r_l = r_{l−1} + (k_l − 1)·j_{l−1}，j_l = j_{l−1}·s_l，从 r_0 = j_0 = 1 开始，r 用的是更新前的跳距。池化也算一层，padding 只改感受野的位置、不改大小。本章 CNN 最后一层 r = 10、j = 4，这是单个位置的感受野，不是整网的。
- **下采样**：足够长的 1 像素线经过 n 次 2×2 平均池化，对比度是 1/2^n。最大池化能保住深色细线，但会把间隔 1 像素的两条线并成一片。评价时看前景像素，不看整图 MSE，像素损伤也不等于识别率。
- **BatchNorm**：每个通道在 (N, H, W) 上求 μ、σ²，标准化用有偏方差，running_var 存无偏方差（乘 n/(n − 1)）；running ← (1 − m)·running + m·新值，m = 0.1 是新值的权重。推理前要 `model.eval()`，`torch.no_grad()` 不会切换。LayerNorm 对单个样本求统计，训练和推理行为一样。
- **最常见的错误**：dX 用赋值代替 `+=`（窗口重叠时才暴露，比如 stride = 1）；裁 padding 写成 `p:-p`，p = 0 时得到空数组；先更新跳距再加感受野，本章 CNN 会算成 13；推理时忘了 `model.eval()`。
