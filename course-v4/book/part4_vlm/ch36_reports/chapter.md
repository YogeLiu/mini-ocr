# 第 36 章 读技术报告，写最终报告

## 本章导读

学完前面的章节，你已经亲手写过注意力、GPT、LoRA、DPO 和 GRPO 的损失，搭过一个小公式 OCR，也拆开过 Qwen3.5。现在拿起一份前沿 OCR 模型的技术报告，其中大部分模块和训练阶段书里都讲过，不同的是规模、组合方式，以及报告写得有多详细。书里没讲的那些，列在 36.8 节。

本章做三件事。

1. **学一套读报告的方法。**先画模块图，再填训练阶段表，然后查评测口径，最后列一张"报告没说什么"的清单。
2. **用这套方法读四份报告**：GLM-OCR、PaddleOCR-VL、Xiaomi-OCR-0、olmOCR 2。每个模型拆成一张模块图和一张训练阶段表，每个阶段都标出对应本书哪一章。
3. **写 R4 最终报告**（36.9）：把你自己的 TexPixel 项目当成一份小技术报告来写。

学完本章，你应该能：

1. 画出四个模型各自的模块图和训练阶段；
2. 指出每个阶段用了书里哪一章的方法；
3. 说出这些报告里你还不理解的部分，把它们列成后续的学习方向；
4. 读到一个"第一名"的分数时，先问清楚它是在什么测试集、什么口径下得到的；
5. 按评测协议写完 R4：两张结果表、test 的一次性评测、错例分析和下一步方案。

**定位：**本章是概括章，没有实验，也没有新的推导。重点放在 36.1 的读法、36.2 到 36.5 的拆解，以及 36.7 列出的警惕事项。

**数字的标签。**本章的数字有四种来源，每个都会标出来：

- **论文报告**：报告作者自己写的分数或设置。我们没有复现，只是转述。
- **本项目观察**：本书第 22 到 35 章的实测结果，除个别 CPU 复算外都在租用的 RTX 4090 上完成。每处都标出对应的章节，或 `course-v4/outputs/book/chNN/gpu/` 下的结果文件。
- **数学结论**：可以从别的数字算出来的。
- **待验证**：我们没有读到原文、或原文没写清楚的。

**一个提醒。**四份报告都会更新版本。本章转述的是 2026 年 10 月能读到的版本（每节开头给出 arXiv 号和版本），数字以你读到的原文为准。

## 36.1 怎样读一份技术报告

技术报告不用从第一页读到最后一页。它是一份"我们做了什么、得了多少分"的声明，读它是为了回答四个问题：

1. **模型长什么样？**输入经过哪些模块变成输出，每块多大？
2. **怎样训出来的？**分几个阶段，每阶段用什么数据、什么损失、训哪些参数？
3. **分数可信吗？**在哪个测试集、什么口径下评测，和谁比？
4. **报告没说什么？**哪些细节缺了，以至于你没法复现？

### 36.1.1 三遍读法

**第一遍（15 分钟）：只看摘要、架构图、主结果表、结论。**读完能用一句话说出"这个模型是什么、主打什么、分数多少"。

**第二遍（1 到 2 小时）：读方法部分，边读边填两张表。**一张是模块图，一张是训练阶段表（格式见 36.1.2）。遇到看不懂的公式，先跳过，在页边标个问号。

**第三遍（按需）：读评测和消融。**这一遍要带着怀疑：测试集是谁建的？对照模型的分数是作者重跑的，还是抄别人论文的？消融的差距比随机波动大吗？

### 36.1.2 两张表，一张清单

**模块图**用文字或 ASCII 画，从输入画到输出。每个方框写三样东西：名字、大小（参数量或输出形状）、从哪里初始化。

**训练阶段表**每行一个阶段，固定五列：

| 阶段 | 数据 | 损失 / 目标 | 训练哪些参数 | 本书对应 |
|---|---|---|---|---|

最后一列是本章的重点。把一个阶段对应到书里的某一章，就说明你已经掌握了这一步的基础机制（书里做的是缩小版，不等于能复现完整的工业训练）。对应不上的，就是你的后续学习方向（36.8）。

**缺失清单**记下报告没说清的东西：学习率、步数、数据配比、奖励里的权重、测试集是否去重……清单越长，复现越难，分数也越要打个问号。

### 36.1.3 三栏笔记

读的时候，每段话归到三栏之一：

| 报告说了什么 | 对应本书哪一章 | 报告没说什么 |
|---|---|---|
| "最后一阶段用 GRPO，按任务给奖励" | 第 24、25、34 章 | 组大小？KL 系数？奖励的组合权重？ |

> **停下来想一想：**第 25 章你自己做过 GRPO。如果要你复现一份报告的 RL 阶段，最少需要知道哪几个超参数？把它们写下来，再去对照下面四份报告各写了几个。

## 36.2 GLM-OCR

**来源：**"GLM-OCR Technical Report"，Zhipu AI 与清华大学，arXiv:2603.10910（本章读的是 v2，https://arxiv.org/html/2603.10910v2）；代码在 github.com/zai-org/GLM-OCR。

**概要：**一个 0.9B 的文档 OCR 模型，先用版面模型切块，再并行识别每块；特色是 MTP（多 token 预测）带来的解码加速。

### 36.2.1 模块图

```text
整页图片
   │
   ▼
PP-DocLayout-V3（外部版面模型）── 把页面切成段落、表格、公式等区块
   │
   ▼ 每个区块并行送进去
┌──────────────── GLM-OCR Core（约 0.9B）────────────────┐
│ 区块图 ─► CogViT 视觉编码器（约 0.4B）                 │
│              │                                         │
│              ▼                                         │
│         轻量连接器：投影到语言模型宽度，作为前缀 token │
│              │                                         │
│              ▼                                         │
│         GLM 语言解码器（约 0.5B）─► 文本 / LaTeX / 表格│
│              └─ MTP 辅助头（参数共享）                 │
└────────────────────────────────────────────────────────┘
   │
   ▼
合并与后处理：恢复阅读顺序，输出 Markdown / JSON

信息抽取（KIE）任务：整张图 + 提示词直接进模型，不切块
```

参数量都是论文报告。连接器只写了"轻量"和"投影成前缀 token"，有没有像第 32 章 Qwen 那样做 2×2 合并，论文没说（待验证）。

**和本书的对应：**"视觉编码器 → 连接器 → 语言模型，视觉向量当前缀"就是第 31 章小 OCR 的结构，也和第 32 章拆开的 Qwen3.5 同一类。

### 36.2.2 MTP：一次预测好几个 token

普通语言模型一步只出一个 token（第 7 章）。MTP 额外挂几个头，让模型同时猜后面几个 token。推理时把这些猜测当草稿，主干一次检查、接受一段，这就是第 14.10 节讲的**投机解码**的思路，只不过草稿来自模型自己的辅助头。

论文报告：训练时预测 10 个 token，推理时平均每步生成 5.2 个，吞吐提高约 50%。辅助头之间共享参数，各自负责不同的未来偏移。

注意两件事：

- **MTP 会不会影响识别准确率，取决于接受规则。**按第 14.10 节的接受-拒绝规则抽样，输出分布不变（第 14 章的数学结论，那里只验证了单个 token）；换成别的规则就没有这个保证。GLM-OCR 具体用哪种规则，我们读到的部分没写清楚（待验证）。
- 第 32 章 32.4 节你见过：Qwen3.5 的 safetensors 里也有一个 `mtp.*` 头，加载成 `AutoModelForImageTextToText` 时没有用到。

### 36.2.3 训练阶段

| 阶段 | 数据（论文报告） | 损失 / 目标 | 训练哪些参数 | 本书对应 |
|---|---|---|---|---|
| 1 视觉编码器训练 | 图文对、定位与检索数据 | MIM（遮挡图像建模）+ CLIP 式对比 + 从更大的内部 ViT 蒸馏 | 视觉编码器 | ViT：第 29 章；CLIP：第 30 章；蒸馏：第 35 章（蒸馏类型待验证）；MIM：书里没有，见 36.8 |
| 2.1 预训练 | 图文、文档解析、定位、VQA | 接上 GLM-0.5B 联合训练（损失形式未写明，按惯例应是下一个 token 交叉熵，待验证） | 论文未写明 | 下一个 token 预测：第 7、13 章；拼接视觉前缀：第 31 章 |
| 2.2 带 MTP 的预训练 | 文档解析、定位、VQA | 加入 MTP 目标 | 论文未写明 | 第 14.10 节、第 32.4 节 |
| 3 SFT（保留 MTP） | 文本、公式、表格识别，KIE | 监督微调 | 论文未写明 | SFT 与 label mask：第 19、21 章；VLM 的 SFT：第 33 章 |
| 4 强化学习 | 从 SFT 模型采样，按难度分层 | GRPO，按任务给奖励 | 论文未写明 | 第 24、25、34 章 |

**第 4 阶段的奖励**（论文报告，Table 2），值得和第 25 章的分层奖励对照：

| 任务 | 主奖励 | 附加检查 |
|---|---|---|
| 文本 | 归一化编辑距离 | 重复惩罚 |
| 公式 | CDM | 结构是否合法 |
| 表格 | TEDS | 标签是否闭合 |
| KIE | 字段级 F1 | JSON 能否解析；缺字段、重复字段扣分 |
| 全局 | 无 | 重复比例惩罚、结构损坏惩罚 |

它和第 25 章、第 34 章的"先查格式、再看内容"是同一个思路。第 25 章的机制检查发现：只查"能不能解析"的奖励，会给单字符 `x`、复制输入、解释文字这样的探针打满分（本项目观察，`outputs/book/ch25/gpu/mechanism/part1.json`）。GLM-OCR 的附加检查可以读成在防这一类投机（这是我们的读法）。

### 36.2.4 主要结果（论文报告）

- OmniDocBench v1.5 总分 94.62（Table 4），在其评测的模型里最高。子分数：文本编辑距离 0.040，公式 CDM 93.90，表格 TEDS 93.96。
- 它在文本编辑距离（0.035）和公式 CDM（94.21）两项上不如 PaddleOCR-VL-1.5，论文表里照实列出了。
- 论文 §6 自己写了局限：两阶段流水线的误差传递、跨页和不规则多栏的阅读顺序、低分辨率和畸变图片、复杂公式、少见语言。

**缺失清单（节选）：**连接器结构、各阶段可训练参数、学习率和步数、数据的具体来源和配比、GRPO 的组大小和 KL 系数、测试集去重。

## 36.3 PaddleOCR-VL

**来源：**"PaddleOCR-VL: Boosting Multilingual Document Parsing via a 0.9B Ultra-Compact Vision-Language Model"，Cheng Cui 等（百度 PaddlePaddle 团队），arXiv:2510.14528（本章读的是 v3，https://arxiv.org/html/2510.14528v3；最新为 v4）；代码在 github.com/PaddlePaddle/PaddleOCR。

**概要：**版面和识别彻底分开，各训各的。版面部分是一个检测器加一个排阅读顺序的指针网络，识别部分是 0.9B 的 VLM。这份报告的数据构建和训练超参数写得最详细。

### 36.3.1 模块图

```text
整页图片
   │
   ▼
PP-DocLayoutV2（版面）
   ├─ RT-DETR：检测并分类版面元素
   └─ 指针网络（6 层 Transformer）：给元素排阅读顺序
   │
   ▼ 区块
┌──────────── PaddleOCR-VL-0.9B ────────────┐
│ 区块图 ─► NaViT 式视觉编码器               │
│           （原生分辨率，从 Keye-VL 初始化）│
│              │                             │
│              ▼                             │
│         2 层 MLP（GELU，merge size 2）     │
│              │                             │
│              ▼                             │
│         ERNIE-4.5-0.3B（加 3D-RoPE）       │
│              ─► 文本 / OTSL 表格 / LaTeX / │
│                 Markdown 表格（图表）      │
└────────────────────────────────────────────┘
   │
   ▼
按阅读顺序拼成整页
```

**和本书的对应：**

- "原生分辨率 + merge size 2 + MLP"几乎就是第 32 章 32.2 和 32.5 节里 Qwen 的 processor 与 merger：按面积缩放，相邻 patch 合并后再投影。
- 3D-RoPE 对应第 32 章 32.7 节的 M-RoPE，原理在第 10 章。
- 视觉编码器的参数量论文没单独给（待验证）。

### 36.3.2 训练阶段

| 阶段 | 数据（论文报告） | 损失 / 目标 | 训练哪些参数 | 本书对应 |
|---|---|---|---|---|
| 版面 1 | 2 万多张样本，100 个 epoch | 检测（RT-DETR），从 PP-DocLayout_Plus-L 初始化 | 检测器 | 书里没有讲目标检测，见 36.8 |
| 版面 2 | 同上，200 个 epoch | 指针网络排序，Generalized Cross Entropy 损失；AdamW，常数学习率 2e-4 | 只训指针网络，检测器冻结 | 冻结与 AdamW：第 4、20 章；指针网络：书里没有 |
| VLM 1 对齐预训练 | 2900 万样本，1 个 epoch | 下一个 token 预测；学习率 5e-5 → 5e-6，序列长度 16384，batch 128 | 全部参数 | 第 13、31 章；学习率调度：第 13 章 |
| VLM 2 指令微调 | 270 万样本，2 个 epoch | SFT，四类任务：OCR、表格（OTSL）、公式（LaTeX）、图表（Markdown 表）；学习率 5e-6 → 5e-7 | 全部参数（§2.2.2） | 第 19、21、33 章 |
| 强化学习 | 我们读到的部分没有提到 | 未说明 | 未说明 | （待验证） |

最大分辨率在两阶段分别写作 1280×28×28 和 2048×28×28，看起来是"最多多少个 28×28 的块"的像素预算写法，和第 32 章 Qwen 的 `max_pixels` 是同一类东西（具体含义待验证）。

### 36.3.3 数据：自动标注 + 难例挖掘 + 合成

这部分写得很具体，可以照着学（论文报告，§3 与论文的附录 A）：

1. **自动标注：**先用 PP-StructureV3 出伪标签，再让 ERNIE-4.5-VL 和 Qwen2.5-VL 这样的大模型修正，最后过滤幻觉。
2. **难例挖掘：**建一个评测引擎，把文本分成 23 类、表格 20 类、公式 4 类、图表 11 类，找出模型弱的类别。
3. **定向合成：**对弱类别，用字体、CSS、XeLaTeX、浏览器渲染造数据。

对应本书：第 35 章的"教师造标签 + 规则质检"、第 22 章的分桶评测、第 12 章的数据清洗。第 35 章还提醒过，教师本身可能很弱：我们的 Qwen3-VL-2B 教师在 192 张训练图上 EM_norm 只有 0.094，规则质检后只剩 109 条可用（本项目观察，`outputs/book/ch35/gpu/runs/teacher/teacher.json`、`quality.json`）。PaddleOCR-VL 用"小模型出初稿、大模型修正"，可以看成在应对"单个教师不可靠"这个问题。

### 36.3.4 主要结果（论文报告）

- OmniDocBench v1.5 总分 92.86；文本编辑距离 0.035，公式 CDM 91.22，表格 TEDS 90.89。
- olmOCR-Bench 总分 80.0 ± 1.0。
- 推理吞吐：A100 上 1.6184 页/秒，论文称比 MinerU2.5 高 53.1%。

**要留意：**一部分元素级评测用的是作者自建的 in-house 测试集，它们和训练数据出自同一条流水线，论文没有说明如何留出（36.7 节细说）。

## 36.4 Xiaomi-OCR-0

**来源：**"Xiaomi-OCR-0 Technical Report"，Xin Chen、Anan Du、Feng Feng 等（报告署名 SeerRay Team，通讯作者为小米邮箱），arXiv:2609.36136（v1，2026-09-28，https://arxiv.org/abs/2609.36136）；模型卡在 https://huggingface.co/SeerRay-Lab/Xiaomi-OCR-0，Apache-2.0。

**概要：**从 Qwen3.5-0.8B 出发，用"多专家共识"的数据引擎造了约 1.7 亿条样本，经过"文字锚定 → 持续预训练 → 混合任务 RL"三阶段训成。它是四个模型里和本书关系最近的一个：起点就是你在第 26、32、33 章用过的 Qwen3.5-0.8B。

### 36.4.1 模块图

```text
（报告评测用的方式）整页 ─► PP-DocLayoutV3 ─► 区块 ─┐
（模型卡说也可以）整页直接输入 ─────────────────────┤
                                                     ▼
┌────────── Xiaomi-OCR-0（0.8B，Qwen3.5-0.8B 初始化）──────────┐
│ 视觉塔 ─► merger（2×2 合并 + 投影）─► 语言模型 ─► 输出       │
│                                         └─ 1 个 MTP 头（沿用底座）│
│ 只在阶段 1 存在：Q-Mask 掩码解码器（阶段 1 结束后去掉）        │
└───────────────────────────────────────────────────────────────┘
                                                     │
                                                     ▼
                                          按区块拼成整页输出
```

报告只说"从 Qwen3.5-0.8B 初始化"，没有另列结构细节；模型卡的架构标签是 `qwen3_5`。所以图里"视觉塔 → merger → 语言模型"取自第 32 章对 Qwen3.5 的拆解，是我们的推断（待验证于原文）。

**参数量的小坑：**报告写 0.8B，模型卡的 safetensors 统计约 0.9B。第 26 章实测 Qwen3.5-0.8B 加载后是 852,985,920 个参数（本项目观察，`outputs/book/ch26/gpu/main/val.json`）；第 32 章 32.4 节说明过，safetensors 文件里还多一个模型加载时不用的 `mtp.*` 头。不过这个解释并不充分：852,985,920 按一位小数四舍五入本身就是 0.9B，所以"0.8B"更可能只是模型名里的标签，名称不保证统一舍入；报告对此没有解释（待验证）。另外，报告注明 0.8B **不含**外部版面检测器。

### 36.4.2 训练阶段

| 阶段 | 数据（论文报告） | 损失 / 目标（论文报告） | 本书对应 |
|---|---|---|---|
| 0 数据引擎 | 约 1.7 亿条 OCR 相关样本 | 多专家共识、渲染校验、难例挖掘、合成（见 36.4.3） | 教师标注与质检：第 35 章；去重与分组：第 5、12 章；分桶：第 22 章 |
| 1 文字锚定（Q-Mask） | TextAnchor-26M + 数据引擎的解析数据 | L = λ_txt·L_NTP + λ_seg·(L_Dice + L_CE)：下一个 token 预测，加一个"文字在图上哪里"的掩码预测 | NTP：第 7 章；交叉熵：第 3 章；Dice 与掩码解码器：书里没有，见 36.8 |
| 2 OCR 持续预训练 | 文档解析（区块与整页）为主，加 OCR 问答、描述、场景文字、手写、书法、化学式、图表 | L = L_NTP + λ_MTP·L_MTP，保留并训练底座自带的 MTP 头 | 第 13 章（预训练）；Eq. 13 只对输出 token 求和，相当于第 19 章的 label mask（报告没有明说"mask"）；第 14.10 节（MTP 与投机解码） |
| 3 Mix-RL | 难例：挖掘后再经更强的语言模型过滤和人工复核 | 基于 GRPO 的 DAPO 式目标：token 级汇总、clip-higher（上下裁剪界分开）、动态采样；**不加 KL** | GRPO：第 25、34 章；裁剪：第 24.6 节；KL 与 k3：第 24.5 节；token 级 vs 序列级汇总：第 24.10 节、第 25 章 |

各阶段训练哪些参数、λ 取多少、学习率多少，报告我们读到的部分都没写（待验证）。

**Mix-RL 的奖励按任务路由**（论文报告，§3.3）：区块解析用文本编辑相似度、表格 TEDS 或公式 CDM；整页解析先对齐区块，再按真值字符覆盖率加权；KIE 先查 JSON 合法，再按实体和字段匹配；OCR 问答用 ANLS。解析不了、违反格式、超长的输出一律 0 分。

**"不加 KL"值得停一下。**第 24 章讲过，KL 是把策略拴在参考模型附近的绳子；第 25 章的 GRPO 用了 β = 0.04。DAPO 的做法是去掉这根绳子，靠裁剪和动态采样维持稳定。报告没有给"加 KL / 不加 KL"的消融，所以这个选择的收益我们没法从报告里判断。

**它还比了另一条路：**MOPD（多教师在线蒸馏）。论文报告 Mix-RL 解析 96.8277、理解 83.2，MOPD 是 96.7417 和 82.7，后者计算更省；MOPD 的训练在分数开始波动时停止。在线蒸馏在第 35 章只列为进阶阅读。

### 36.4.3 数据引擎：三元组共识

这是报告的核心贡献（论文报告，§2）。

1. **专家池：**8 个开源 OCR 模型各读一遍同一区块，包括 PaddleOCR-VL-1.6、MinerU2.5-Pro、**GLM-OCR**、dots.ocr、HunyuanOCR-1.5、TeleOCR、OvisOCR2、Qianfan-OCR。
2. **相似度：**文本用 1 − NED，表格用 TEDS，公式用 CDM。
3. **选三元组：**按每位专家和其他专家的平均一致度排名，取前三位组成三元组，报告特意说明这不是在所有三人组合里穷举最一致的一组；组内两两相似度的均值记作 a(x)；伪标签取组内的"中心点"（和另外两个最像的那个读法）。
4. **分档：**a ≥ 0.9 为高，0.6 ≤ a < 0.9 为中，a < 0.6 为低。
5. **渲染校验：**中低档交给 Qwen3.5-122B-A10B（不在专家池里）修正：把读法渲染出来和原图比，最多 3 轮，再走"批评、修正、校验"三步。**修正结果必须重新共识，只有重新共识后进入高档的才自动接受。**

**和本书的对应：**这一步只拿专家写出的读法当标签，按第 35 章的分法属于序列级蒸馏，规模大得多。第 35 章用一个教师、一套规则质检，渲染比对的对象是训练参考；这里用 8 个专家互相比对选出三元组，再把读法渲染出来和原图比。第 35 章实测过单个教师的问题有多大（教师 EM_norm 0.094，本项目观察）。书里没有做过多教师实验，共识能把错误压低多少，只能看报告自己的说法。

**还有一点：**GLM-OCR 和 PaddleOCR-VL 既是 Xiaomi-OCR-0 的"老师"，又是它在主结果表里的对手。36.7 节会回到这一点。

### 36.4.4 主要结果与消融（论文报告）

| Real5-OmniDocBench 总分 | 95.24 | 五种真实退化（拍照、扫描等）下第一 |

**消融（论文报告）：**

**怎样读这些消融：**Mix-RL 带来约 0.35 分（数学结论：96.8277 − 96.4739 = 0.3538）。这够不够大？要看同一配置换个种子会波动多少，而报告我们读到的部分没给种子数和区间。对照第 25 章：在我们的文本后纠错上，GRPO 的点估计比第 22 章 SFT 参照高 1.0 个百分点，配对 bootstrap 区间 [0.2, 2.0]（本项目观察，n = 500，`outputs/book/ch25/gpu/runs/ch25/main3/comparison.json`）；但不一致对只有 5/0，这时百分位区间偏乐观，精确 McNemar 双侧 p=0.0625，第 25 章只把它算作"方向向好、证据不足"。连 500 题上的 1 个百分点都难下结论，0.35 分在 OmniDocBench 上是否显著，要靠区间说话。

## 36.5 olmOCR 2

**来源：**"olmOCR 2: Unit Test Rewards for Document OCR"，Jake Poznanski、Luca Soldaini、Kyle Lo（Allen Institute for AI），arXiv:2510.19817（v1，https://arxiv.org/html/2510.19817v1）；Ai2 博客 https://allenai.org/blog/olmocr-2。

**概要：**一个 7B 的端到端整页 OCR 模型。结构上沿用已有模型，新意在奖励：把"OCR 对不对"写成一组二值单元测试，测试通过的比例就是 RL 的奖励。

### 36.5.1 模块图

```text
PDF 页面
   │  渲染成图片（最长边 1288 px，第一版是 1024 px）
   ▼
┌──── olmOCR-2-7B（从 Qwen2.5-VL-7B-Instruct 微调）────┐
│ 视觉编码器 ─► 连接器 ─► 语言模型                      │
└───────────────────────────────────────────────────────┘
   │
   ▼
整页文本：开头是元数据（主要语言、旋转校正等），然后是正文
（表格用 HTML，公式用 LaTeX）

没有外部版面模型：版面、阅读顺序、识别一次完成
```

内部结构沿用 Qwen2.5-VL，论文没有展开（待验证）。

### 36.5.2 训练阶段

| 阶段 | 数据（论文报告） | 损失 / 目标 | 本书对应 |
|---|---|---|---|
| 1 SFT | olmOCR-mix-1025：267,962 页，来自 10 万多份 PDF，1 个 epoch | 监督微调 | 第 19、21、33 章 |
| 2 RL | olmOCR2-synthmix-1025：2,186 页、30,381 个单元测试，1 个 epoch，一台 8×H100 | GRPO（Hugging Face TRL 实现），每页采样 28 条，KL β = 0.01 | 第 24、25、34 章；TRL：第 21 章（SFT）、第 25 章（GRPO） |
| 3 模型汤 | 6 个不同随机种子的 RL 模型（3 个 token 级、3 个序列级重要性采样） | 权重取平均 | 书里没有，见 36.8 |

**奖励**（论文报告，§3.2）：主奖励是"通过的单元测试比例"，0 到 1；另有两个格式奖励：以 EOS 结尾（二值）、开头输出元数据（0 到 1）。

和本书对比：第 25 章同样调用 TRL 的 GRPOTrainer，显式写了 `loss_type='grpo'`。第 34 章的循环是手写的，没有调用 TRL；它按整批 token 平均，接近 TRL 默认的 `dapo`，差别是分母只算有效组的 token（34.11 节）。三者用的都是可验证奖励。区别在于我们的分层奖励是"能解析 → 规范化后相等 → 编辑距离"，而 olmOCR 2 把"对"拆成很多条可以单独判对错的小测试。

### 36.5.3 单元测试从哪里来

1. 采样真实 PDF 页面，例如数学多的 arXiv 论文；
2. 让通用 VLM（Claude Sonnet 4）分三步把页面重写成语义 HTML：分析版面、写 HTML、对照原图修改。论文报告每页约 0.12 美元；
3. 从 HTML 里自动生成测试：页眉页脚变成"不应出现"的测试，KaTeX 公式变成公式测试，抽样的表格单元格变成表格测试。

测试的类型（§2）：文本出现、文本不出现、自然阅读顺序、表格、公式（用 KaTeX 渲染比较）、基础稳健性（比如重复 n-gram、非目标语言字符）。

**公式测试为什么用渲染比较？**第 0 章讲过：同一个公式有很多种正确的 LaTeX 写法，字符串相等太严，渲染一致更公平。第 32 章则让你亲眼看到字符串口径怎样误伤：Qwen3.5 在 180 条 val 上，正式口径只命中 11 条；双方都忽略句末标点后是 59 条。新增的 48 条里，逐条核对确认有 46 条是模型抄对了标点、被提取规则删掉了，另 2 条是模型自己写错或漏写了标点（本项目观察，`outputs/book/ch32/gpu/val_format_diagnostic.json`；46 条由 `main/qwen35_val_original.json` 逐条复算，见第 32 章 32.9 节）。

### 36.5.4 主要结果（论文报告）

- olmOCR-Bench 总分 82.4 ± 1.1；第一版 olmOCR 是 68.2。
- 分项里"老扫描件"只有 47.7，是明显的弱项。
- 论文 Table 3 把 68.2 → 82.4 拆成一步步的改进（动态温度、更好的提示词、新训练器、调大图片、换 Qwen2.5-VL、合成数据 + RLVR + 模型汤……）。这种"贡献分解表"可以在你的 R4 里模仿（36.9.2）。
- 对照表里一些模型的分数是"作者自报"而非 Ai2 重跑，论文有注明。

**读这张表的三个要点。**

1. **结构趋同。**四个都是"视觉编码器 → 连接器 → 语言模型"，也就是第 31 章你从零写过的形状。差别主要在规模和初始化来源。

## 36.7 读报告时最该警惕的事

报告里的每个分数，都是模型、测试集、评测口径、对照选择四者共同的产物，只看模型那一项就会被误导。下面四件事，本书的实验里都出现过。

### 36.7.1 测试集是谁建的

**要问：**测试集是公开的、第三方建的，还是作者自己建的？和训练数据是不是出自同一条流水线？

**在四份报告里：**

- **olmOCR-Bench 是 olmOCR 团队自己建的**，而且它的评测方式（二值单元测试）和 RL 的奖励是同一套框架。这不等于作弊，但意味着"在这个基准上高分"和"把奖励刷高"高度相关。第 34 章见过类似的信号：可解析既是奖励的一档，也是评测指标，GRPO 让 4 条输出变得可解析，这 4 条的编辑距离却没有一条变好。奖励和评测越像，越要查模型学到的是不是"测试的形状"。
- **PaddleOCR-VL 的一部分元素级评测是 in-house 测试集**，由和训练数据相同的流水线产出，论文没说怎样留出。
- **Xiaomi-OCR-0 的 KIE 用内部数据**，外人无法复现。不过它写明了自己的验证集不是独立测试集，最终结论看公开基准，这一点做得好。

**和本书的联系：**第 5 章、第 22 章反复强调"val 做决定，test 只报告"。第 22 章的模拟显示，在 test 上挑 20 次，就能凭空造出约 0.038 的"提升"（本项目观察，模拟真值 0.7、n = 500，`outputs/book/ch22/gpu/analysis.json` 的 `peeking`）。公开基准用久了，整个领域都在上面挑模型，它也就慢慢变成了大家共用的"验证集"。

### 36.7.2 评测口径

**要问：**指标的定义是什么？版本是哪个？预处理（提取、规范化）怎样做？

**在四份报告里：**

- OmniDocBench 有 v1.0、v1.5、v1.6，总分的定义和题目都可能变。不同版本的分数不能直接比（36.6）。
- 公式用 CDM（渲染后按字符配对）还是编辑距离，结论可能不同。PaddleOCR-VL 在 OmniDocBench v1.0 上还报告了公式编辑距离，和 v1.5 的 CDM 口径不同。
- PaddleOCR-VL 把自己在 v1.0 英文表格上偏低的分数归因于基准的标注错误，但论文没给核查证据。"基准有错"可能是真的，也可能是解释。

**和本书的联系：**

- **第 22 章：**`parse_rate` 看起来是"模型输出合法 LaTeX 的比例"，但干净的参考答案本身只有 58.6% 能被我们的 mathtext 子集解析；SFT 的 95 条 `unparsable` 里，有 63 条的参考答案本身也解析不了（本项目观察，第 22 章 22.6.4 节）。这个指标和这个标签量到的，有很大一部分是**评测器的覆盖范围**，不是模型的错误率。
- **第 26、32 章：**`extract_formula` 会删掉模型输出末尾的标点，而 arXiv 公式的标签本身常带逗号句号。Qwen3.5 在 180 条 val 上的命中，按正式口径是 11 条，双方都忽略句末标点后是 59 条，其中新增的 48 条里有 46 条经逐条核对确是提取规则误删（本项目观察，`outputs/book/ch32/gpu/val_format_diagnostic.json`）。同一份输出，换个口径分数差五倍多。Qwen3-VL-2B 也一样：提取公式后、规范化前的 EM_raw 只有 0.006（180 条中 1 条），规范化后 EM_norm 是 0.072（13 条）（本项目观察，第 32 章 32.8.4 节）。

读报告时，如果口径只写了指标名、没写预处理，就把它记进缺失清单。

### 36.7.3 只报对自己有利的基准

**要问：**对照模型是怎样选的？用的是哪个版本？分数是作者重跑的，还是从别人论文抄来的？有没有自己输掉的基准？

**在四份报告里：**

- 每份报告的主表都是自己挑的基准、自己挑的对手。GLM-OCR 对比的是 PaddleOCR-VL-1.5，不是 36.3 节读的 0.9B 初版；olmOCR 2 表里的部分分数是对方自报的。
- 四份报告也都写出了自己偏弱的地方：GLM-OCR 在文本和公式两项输给 PaddleOCR-VL-1.5，PaddleOCR-VL 报了自己在 v1.0 英文表格上偏低的分数（36.7.2），Xiaomi-OCR-0 在 OmniDocBench v1.6 和 Wild 上输给 TeleOCR，olmOCR 2 的"老扫描件"只有 47.7。读主表时先找这些格子。
- 消融常常不写种子数和区间（36.4.4）。差 0.3 分是不是噪声，报告往往不回答。

**和本书的联系：**本书好几个"负结果"都是如实写出来的：

- **第 25 章：**GRPO（分层奖励）的点估计比 SFT 参照高 1.0 个百分点（5/0 不一致对，精确 McNemar p=0.0625，证据不足；参照是第 22 章旧实现的历史输出，不是合并快照的零步输出），但没有超过"继续 SFT"（+1.4，val EM_norm 69.2% 对 68.8%）；三条线的差距只有两三条样本（本项目观察，n = 500，`outputs/book/ch25/gpu/runs/ch25/main3/comparison.json`）。加上两个训练种子后，继续 SFT 三次都排第一，均值 69.13% 对两种奖励的 68.40%，但同时重采样种子和样本时区间仍含零，只算探索性证据（本项目观察，`outputs/book/ch25/gpu/supp/seed-summary.json`）。这也不是等算力的对照：GRPO 的训练循环约是继续 SFT 的 36 倍（数学结论，25.8.4 节）。
- **第 34 章：**VLM 上的 GRPO 在 val 上 EM_norm 和起点一样是 0.10，CER 反而从 0.137 升到 0.154；parse_rate 从 0.65 升到 0.69，但这不能当作识别变好的证据（本项目观察，n = 100，34.7.2 节）。继续 SFT 也没有胜过起点，它和 GRPO 的训练时长差约 17.7 倍；这个循环是手写的，每步的组数和 G 也和第 25 章不同，两章的倍数不能直接比。补充实验训到 600 步、去掉 tier-1 奖励，在 500 条 val 上仍没有看得出的识别收益（本项目观察，单种子，34.7.7 节）。第 25、34 章的奖励都带着已知的验证器缺陷，标准答案也拿不到满分，修好之后的结果本书没有测过。
- **第 35 章：**主实验两组学生的 val EM 都是 0，CER 从 0.926（只用原始数据）变成 1.035（加入蒸馏数据），方向不利，但区间重叠（本项目观察，n = 64，`outputs/book/ch35/gpu/runs/selection.json`）。按 val 选中原始组，它的 test CER 是 0.931；蒸馏组没有登记 test，两组的比较全在 val 上（本项目观察，n = 64，`outputs/book/ch35/gpu/runs/final/final_test.json`）。补充实验放大到 5000 张原始图、3000 步、两个种子，四组 val EM 仍只有 0/500 或 1/500，CER 都在 0.84 以上；蒸馏组在种子 35 上明显更差，在种子 36 上分不出差别（本项目观察，val n = 500，`outputs/book/ch35/gpu/supp/summary.json`）。学生还没学会读公式，这组结果不能推广成"蒸馏无效"。

报告里很少看到这样的表，"RL 没赢过 SFT"不好写进摘要。这几章说明方法的收益取决于设置：报告里 RL 带来的提升，到了你的数据、你的规模上，不一定还在。

### 36.7.4 合成数据和伪标签的泄漏

**要问：**训练数据和测试集有没有去重？合成数据的"种子"有没有来自测试集？伪标签是不是由被比较的模型生成的？

**在四份报告里：**

- 在我们读到的部分里，**四份报告都没有专门讨论训练数据和公开基准之间的重叠检查。**这不代表有泄漏，只代表你没法从报告里确认没有（待验证）。
- Xiaomi-OCR-0 的做法值得学：按来源文档分组划分，验证集的组（含近重复和合成衍生品）不进入任何合成的输入。这就是第 5 章"先分组、再划分"和第 12 章"按规范键去重"的放大版。
- olmOCR 2 的合成数据从真实 arXiv 页面出发，而 olmOCR-Bench 里也有 arXiv 类别。有没有重叠，论文我们读到的部分没回答。这是一个好问题，可以写进你的读书报告。
- Xiaomi-OCR-0 的伪标签来自 8 个专家，其中有 GLM-OCR 和 PaddleOCR-VL。用对手的输出当老师、再和对手比，本身合法，但它说明"超过老师"需要额外的解释：是共识过滤掉了老师各自的错误，还是只在某些基准上学到了老师们共同的写法？

**和本书的联系：**第 22 章做过近重复检查，并强调它只能给出**下界**：只查了训练集参考答案，查不到基座模型的预训练数据（本项目观察，第 22 章 22.5 节）。读报告时也一样：作者说"我们去重了"，你要问"拿什么去重、和什么比"。

> **停下来想一想：**第 35 章的教师在训练图上 EM_norm 只有 0.094（本项目观察）。如果把它的标签直接混进训练集，又用同一个教师去评测学生，会发生什么？这和 Xiaomi-OCR-0"用对手当老师"有什么相同、有什么不同？

## 36.8 你还不理解的部分 → 后续学习方向

读完四份报告，一定会碰到书里没讲的东西。这很正常：本书只教到能读懂报告骨架的程度。下面按"在哪里遇到 → 它是什么 → 去哪里学"列出来。

| 在哪份报告里 | 没讲到的内容 | 简单解释 | 后续方向 |
|---|---|---|---|
| PaddleOCR-VL | 目标检测（RT-DETR） | 在图上找出每个元素的框和类别 | DETR 系列论文；目标检测课程（如 CS231n 的检测部分） |

| GLM-OCR | MIM（遮挡图像建模） | 遮住部分 patch，让 ViT 还原 | MAE 等自监督视觉预训练；第 30.11 节是入口 |
| GLM-OCR、Xiaomi-OCR-0 | MTP 的训练和接受规则 | 一次预测多个 token 并用于加速解码 | 第 14.10 节投机解码；DeepSeek-V3 等报告里的 MTP 部分 |
| Xiaomi-OCR-0 | DAPO 的完整细节 | 去掉 KL、上下裁剪界分开、过滤全对或全错的组 | DAPO 论文（见精读）；第 24.10、25.7 节的 `loss_type` |
| Xiaomi-OCR-0 | 在线策略蒸馏（MOPD） | 学生自己生成，教师给每个 token 打分 | 第 35 章的进阶阅读 |
| olmOCR 2 | 模型汤（权重平均） | 几个种子训出的模型，权重直接平均 | Model Soups（Wortsman 等，2022） |
| 四份都有 | TEDS、CDM、ANLS 的细节 | 表格树编辑距离、渲染后字符配对、问答的模糊匹配 | 第 0 章的 CDM 选读；OmniDocBench 论文（见精读） |
| 四份都有 | 千万到上亿样本的训练怎样分到多卡 | 数据并行、ZeRO、FSDP | 第 16.12 节的概括；DeepSpeed ZeRO、PyTorch FSDP 文档（本书不展开） |
| PaddleOCR-VL | 序列长度 16384 的注意力怎样省显存 | 分块计算、online softmax | FlashAttention 论文（本书不展开）；第 8 章的 T² 代价 |
| GLM-OCR、PaddleOCR-VL | 吞吐数字（页/秒）怎样得到 | 连续批处理、PagedAttention | 第 15 章的 PagedAttention 概括；vLLM 的文档和论文（本书不展开） |

**怎样用这张表：**不要一次全学。先挑和你的项目最相关的一两项。对 TexPixel 公式识别来说，建议先学 CDM（换一个更公平的公式指标）和 DAPO（如果你还想再试 RL）。

## 36.9 写 R4 最终报告

R4 是整个 TexPixel 项目的收尾。读过四份技术报告再看 R4，它就是一份你自己的小技术报告，而且要比它们更诚实：你有完整的负结果，有区间，有成本。

### 36.9.1 R4 必须回答的问题

R4 要回答六件事：

1. **全部方法的对比：**提示词基线、SFT/LoRA、DPO、GRPO、蒸馏，以及第 33 章的 VLM LoRA。按任务分成下面的文本后纠错、图像 OCR 两张表；
2. **GRPO 和蒸馏的结果**，包括负结果；
3. **仍然存在的错误：**按桶分析，开发期只看 val 的错例（test 错例的时机见 36.9.3）；
4. **总成本：**GPU 小时、人工时间；
5. **局限；**
6. **下一步：**该加数据、调图像、继续训练，还是换模型？说出理由。

**表一：文本后纠错**（第三部分，第 0 章 0.9.3 节的文本后纠错面板：EM_norm、CER、改坏、fix_rate）。下面写的是书中数字对应的队列，你填 R4 时要写自己实际用的队列。

**这两张表里现有的数字不能直接排名。**两张表的任务不同，一个修文本，一个读图。同一张表里，队列大小、抽取口径、模型、图像设置和训练量也各不相同。举个例子：第 32、33 章的 test 是同一批 100 条（`sample_ids_sha256` 相同），模型都是零样本的 Qwen3-VL-2B，第 32 章得 11/100，第 33 章得 4/100，两次之间至少像素预算不同（本项目观察，`outputs/book/ch32/gpu/remote_runs/final/qwen3vl_test_original.json`、`outputs/book/ch33/gpu/remote_runs/final_test/test_baseline.json`）。第 22、23、25 章共用 val 前 500 条，可以放在一起看，但第 25 章 25.9 节说过，DPO 的 β 是在 val 上选的，训练数据和步数也不同，算不上对等的对照。这里和表一里的 β 是第 23 章 DPO 损失里乘在对数概率比上的系数。它在推导上来自 KL 约束目标，含义和 36.4、36.5 节 GRPO 里的 KL 系数 β 一样（越大越贴近参考模型），但 DPO 和 GRPO 的损失形式不同，两边的 β 数值不能直接比较。

要统一比较，需要**共同队列**：把要比的候选在同一批样本 ID 上重新生成预测，用同一个评测脚本算分。这相当于开发一版新协议（0.10.5 节）：规则升级版本号，所有候选重算，最终测试另行安排，不和旧数字混比。本书没有做这一步，所以书里也没有跨章的总排名。没有共同队列时，只写相对同一起点的配对比较，比如第 25 章各条链相对 SFT 参照的配对差。注意这个"起点"只是近似：第 23、25 章的参照是第 22 章旧实现的历史输出，不是合并后实际起点在同一设置下的零步输出，所以配对差里还混着合并与精度路径的变化，不能全部算作训练的贡献。

### 36.9.2 从技术报告借来的四个写法

1. **模块图 + 训练阶段表。**把你最终选中的系统画出来，阶段表的最后一列写"对应本书哪一章、哪个脚本"。
2. **贡献分解表**（学 olmOCR 2 的 Table 3）：从零样本基线开始，每一行只加一个改动，写出 val 上的变化和区间。不能做成逐行累加的，就分开写"相对同一起点"的对照，并确认这个起点真的是训练起点在同一设置下的零步输出。
3. **输掉的格子放进主表**（学 36.7.3）：哪个方法没赢、在哪个桶上变差，照实写。
4. **缺失清单反过来用：**把你自己的报告当成别人的来读，列出"读者想复现还缺什么"，再补齐（种子、学习率、像素预算、提示词、提取规则、测试集评了几次）。

### 36.9.3 评测协议的最后一步

按第 0 章 0.10.1 节的规则，选型冻结后，预先登记的候选可以各评一次 test，开发期不看 test 错例。R4 定稿、所有设置冻结以后，才解封测试集做完整的错例分析，这一步不再改任何设置。如果在任何一份报告里根据测试集的结果改过设置，在 R4 里写明，并补一份新的留出测试集。

## 36.10 常见错误

| 错误 | 现象 | 怎样避免 |
|---|---|---|
| 横着比不同版本基准的分数 | "Xiaomi-OCR-0 96.83 比 GLM-OCR 94.62 高" | 先核对基准名和版本；不同版本不比 |
| 把作者自报的对照分数当成复现结果 | 以为表里所有模型都在同一条件下评测 | 看表注：哪些是重跑、哪些是引用 |
| 只看总分 | 没发现某个子项（如老扫描件 47.7）很差 | 总分拆成子分数，再找输掉的格子 |
| 把单次消融的小差距当成结论 | "Mix-RL 提升 0.35，所以 RL 一定有用" | 问种子数和区间；对照第 22、25 章的 bootstrap |
| 把报告的方法收益直接搬到自己的项目 | 期待 GRPO 在 TexPixel 上也明显赢 | 记住第 25、34 章的负结果：收益取决于设置 |
| 把"论文没写"当成"没有做" | "PaddleOCR-VL 没用 RL" | 写成"我们读到的部分没有提到（待验证）" |
| 把推断写成事实 | "Xiaomi-OCR-0 的视觉塔是 xxx 层" | 来自底座的推断要标出来源和"待验证" |
| 模块图只画名字，不写大小和初始化 | 图看起来完整，却答不出"哪部分最贵" | 每个方框写名字、大小、从哪里初始化 |
| 忽略推理方式 | 把两阶段系统的分数和端到端模型直接比 | 记下是否用了外部版面模型，以及它算不算进参数量 |
| 写 R4 时在 test 上做决定 | 看了 test 错例再改提示词或设置 | 开发期只看 val；预先登记的候选各评一次 test，R4 定稿后才解封错例（36.9.3） |

## 36.11 小结

读技术报告的目标是回答四个问题：模型长什么样、怎样训出来、分数可信吗、报告没说什么，对应的工具是模块图、训练阶段表、口径核查和缺失清单。模块图的每个方框写名字、大小、从哪里初始化；训练阶段表固定五列（阶段、数据、损失、训练哪些参数、本书对应），最后一列对不上的，就是 36.8 的后续学习方向。GLM-OCR、PaddleOCR-VL、Xiaomi-OCR-0、olmOCR 2 的结构都是第 31 章那种"视觉编码器 → 连接器 → 语言模型"，报告着力写的是怎样造标签（伪标签修正、多专家共识、合成）和怎样定义"对"（编辑距离、CDM、单元测试），也就是第 22、25、35 章的主题。报告里的每个分数都是模型、测试集、口径和对照选择共同的产物：测试集是谁建的、版本和预处理是什么、输掉的格子在哪、训练和测试有没有去重，这四问一个都不能省。最常见的两个错误是横着比不同版本基准的分数，以及把来自底座的推断当成报告写明的事实。

分数要会自己验算。OmniDocBench 从 v1.5 起，总分 = ((1 − 文本编辑距离) × 100 + 公式 CDM + 表格 TEDS) / 3，三项各占三分之一，阅读顺序不进总分（36.6）。版本一变，题目和定义都可能变，所以 v1.5 和 v1.6 的总分不能直接比。

本书自己的实验说明，口径和设置能轻易改变结论。第 22 章的 `unparsable` 里，多数题的参考答案本身也解析不了；第 32 章的标点规则误伤了抄对的答案。第 25 章继续 SFT 在三个种子上都排第一，但只算探索性证据，算力也不相等；第 34 章 GRPO 和继续 SFT 都没有胜过起点，补充实验也没有看得出的识别收益，这两章的奖励都带着已知的验证器缺陷。第 35 章两轮蒸馏都是负结果，学生还没学会读公式，不能推广成"蒸馏无效"。语言模型这条线上，第 13 章的完整训练、消融和规模实验由你自己完成，正文没有给出结果，那张表要靠你来填。

写 R4 时，把你的项目当成一份小技术报告来写，并且比它们更诚实。文本后纠错和图像 OCR 分两张表，现有数字不能跨章排名；想排名，就先建共同队列。test 始终冻结：选型在 val 上定好，预先登记的候选各评一次 test，R4 定稿前不看 test 错例。
