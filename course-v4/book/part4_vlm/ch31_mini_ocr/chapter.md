# 第 31 章　从零搭一个小公式 OCR

## 本章导读

到上一章为止，你手里有两样东西：一只"眼睛"（第 29 章的 ViT，把图切成 patch 变成一串向量），一支"笔"（第 11 章的 GPT，一个字一个字往下写）。这一章把它们接起来，做出全书第一个**端到端**的公式 OCR：喂进去一张公式图片，吐出来一串 LaTeX。

它很小：约 587 万个参数，全部随机初始化，没有任何预训练。在开源短公式子集上，它的 test EM_norm 是 0.472（本项目观察，RTX 4090（租用），train 100000 张、10000 步、训练种子 31，test 500 张，`outputs/book/ch31/gpu/train100k/final_test.json`）。也就是说，一半左右的公式它能一字不差地读对（规范化以后）。这个数字不算漂亮，但每一个零件你都亲手写过、都能拆开看。第 32、33 章换成真实 VLM 时，你会拿它当对照：大模型多做的每一件事，都可以问一句"我的小模型缺的是不是这个"。

这一章相当于 CS231n 的"Transformer 图像描述"作业，只不过输出的是 LaTeX。

**学完能做到：**

1. 画出 ViT 编码器 → 连接器 → GPT 解码器的数据流，写出每一步的形状，算出参数量。
2. 说清本章用的接口（视觉 token 前缀拼接）和交叉注意力的区别，以及为什么这里选前缀拼接。
3. 正确构造 teacher forcing 的输入、标签和损失 mask，第一步 loss 应该是多少心里有数。
4. 写出带 KV cache 的贪心解码，说清束搜索在这里怎样接上。
5. 用第 22 章的口径（EM_norm、CER、Wilson 区间、bootstrap 区间）评测，做到"val 选模型，选型冻结后才碰 test"。

## 31.1 全景：一张图怎样变成一串字节

### 31.1.1 动机

第 30 章的 CLIP 能在一堆候选里挑出和图最配的那段 LaTeX，但它写不出候选之外的公式。OCR 要的是**生成**：图上是什么，就写出什么。生成需要一个自回归的语言模型，而这个语言模型得能"看见"图。

所以本章的问题只有一个：**怎样让 GPT 在写每一个字节之前，都能看到图片？**

### 31.1.2 直觉：先看一遍，再边看边写

想象你在抄黑板上的一个公式。你先扫一眼全貌（编码器），在脑子里留下一份"笔记"（视觉 token），然后低头一个字符一个字符地写（解码器），写的时候随时抬头对照笔记。

本章的做法是把这份笔记**直接摊在要写的句子前面**。GPT 看到的序列是

```
[视觉 token × 320] [BOS] [字节 1] [字节 2] …
```

它不需要知道前面那 320 个"词"来自图片。它只觉得这句话开头很长，而它要学会：读完这段开头以后，接着写出正确的 LaTeX。

### 31.1.3 全景表：每一步的形状

下表是正式实验【G100k】的配置：批量 B，画布 32×160，patch p = 4，宽度 D = 256，最长 64 字节。

| 步骤 | 代码（`formula_ocr.py`） | 形状 | 说明 |
|---|---|---|---|
| 输入图片 | — | (B, 1, 32, 160) | 灰度"墨迹"图，背景 0、墨迹接近 1 |
| 切 patch 并投影 | `patch_embed(images, self.patch_weight)` | (B, 320, 256) | 320 = (32/4)·(160/4)；第 29 章 |
| 加位置表 | `+ self.pos` | (B, 320, 256) | 学习式，每个 patch 一个向量 |
| ViT 双向块 × 3 | `self.vision(...)` | (B, 320, 256) | 视觉 token 互相看，没有因果 mask |
| 连接器 | `self.connector(...)` | (B, 320, 256) | 逐 token 的两层 MLP，个数不变 |
| 文字嵌入 | `self.gpt.tok(inputs)` | (B, 65, 256) | BOS + 最多 64 个字节（含补齐） |
| 拼接 | `torch.cat((visual, ...), dim=1)` | (B, 385, 256) | 385 = 320 + 65 |
| GPT 因果块 × 4 | `self.gpt(inputs_embeds=...)` | (B, 385, 259) | 259 是字节词表大小 |
| 只留文字部分 | `logits[:, self.prefix_length:]` | (B, 65, 259) | 视觉位置的输出丢掉 |

320、385、65 都是数学结论。注意 GPT 的 `block_size` 设成 `prefix_length + max_length + 1` = 385，正好装下最长的序列（`formula_ocr.py` 第 53 行）。

### 31.1.4 参数从哪里来

参数量可以手算（数学结论）。记 D = 256：

| 模块 | 公式 | 参数 |
|---|---|---|
| patch 投影 | D·1·p² = 256·16 | 4,096 |
| 位置表 | 320·D | 81,920 |
| ViT 块 × 3 | 每块：两个 LayerNorm 4D，qkv D·3D+3D，proj D²+D，MLP D·4D+4D+4D·D+D，合计 789,760 | 2,369,280 |
| 连接器 | LayerNorm 2D，两个线性层 2(D²+D) | 132,096 |
| 字节嵌入（与输出层共享） | 259·D | 66,304 |
| GPT 块 × 4 | 每块：两个 RMSNorm 2D，注意力 4D²，SwiGLU 3·D·704，合计 803,328 | 3,213,312 |
| 最后的 RMSNorm | D | 256 |
| **合计** | | **5,867,264** |

SwiGLU 的中间维 704 来自第 11 章的取整规则 64·⌈(8·256/3)/64⌉。合计和 `frozen.json` 记录的 5867264 一致【G100k】。patch 改成 8 时，patch 投影变成 256·64 = 16,384，位置表变成 80·256 = 20,480，总数少 49,152，正好是【G20k-p8】记录的 5818112。

从这张表能看出两点。第一，视觉部分（patch 投影、位置表和 ViT，约 246 万）加上连接器（约 13 万），和语言部分（约 328 万）差不多大，和真实 VLM 里"语言模型远大于视觉编码器"的比例很不一样。第二，词表只有 259，嵌入层几乎不占参数；第 32 章的真实模型词表十几万，嵌入层动辄上亿参数。

## 31.2 数据管线：图文对、划分与字节 tokenizer

### 31.2.1 动机

数据管线要回答三个问题，每一个答错都会让后面的数字失去意义：

1. **图从哪里来，怎样变成固定形状的张量？** 公式有长有短，模型要的是 (1, 32, 160)。
2. **怎样划分 train/val/test？** 同一个公式换个空格写两遍，一份进 train、一份进 test，test 分数就是假的。
3. **文字怎样变成 token？** 词表决定了模型能写出什么、写错时错成什么样。

### 31.2.2 直觉

- **图**：先把纸边的空白裁掉，再按比例缩放到能塞进 32×160 的框里，空出来的地方补 0。就像把不同大小的照片放进同一个相框：不拉伸，留白边。
- **划分**：先按"规范化以后长得一样"把公式分组，**一组只能整体去一个地方**。这跟考试防作弊一样：同一道题的两个版本不能一个当练习题、一个当考题。
- **token**：直接用 UTF-8 字节。`\frac` 是 5 个 token，`x` 是 1 个。好处是没有"词表外"的字符，坏处是序列长、一个 LaTeX 命令要分好几步写完。

### 31.2.3 推导

**(1) 图像的缩放比例。** 设裁掉白边后墨迹区域高 h、宽 w。画布 32×160，四周各留 2 像素，可用区域 28×156。等比缩放要求两个方向都放得下：

$$s = \min\left(\frac{28}{h},\ \frac{156}{w}\right),\qquad h' = \mathrm{round}(s\,h),\quad w' = \mathrm{round}(s\,w).$$

然后居中：上边距 ⌊(32 − h')/2⌋，左边距 ⌊(160 − w')/2⌋。宽高比 160/32 = 5，公式通常更宽，所以多数公式受宽度限制，**长公式的字会被压得很小**，第 27、29 章担心的"小字"问题就出在这里。

**(2) 划分为什么要"先划分、再挑样本"。** 本章沿用第二部分的 latex-v1 协议（`latex_corpus.standard_split`）：在**完整语料**上按规范化键分组，按 SHA-256(seed, 键) 排序，先填满 val 和 test 各约 5000 条，其余进 train。之后才筛"非空、UTF-8 不超过 64 字节"的公式，并按 parquet 的固定顺序取前 N 条。

顺序不能反。如果先从语料里抽 20000 条再划分，那么"一组"的成员会随抽样变化，换个 N 就换了一套 val。按现在的顺序，**train_n 只决定取 train 的多长前缀**，20k 和 100k 两次实验用的是同一份 val 和 test（本项目观察，两份 val 张量的 MD5 相同）。这让 31.7 节的规模对照可以直接比。

**(3) 字节词表。** 规定

$$\text{PAD}=0,\qquad \text{字节 } b \mapsto b+1\ (b=0,\dots,255),\qquad \text{BOS}=257,\qquad \text{EOS}=258,$$

词表大小 259（数学结论）。字节整体加 1，是为了把 0 让给 PAD。

### 31.2.4 小数字例子

**一张宽公式。** 裁边后墨迹 h = 40、w = 300：s = min(28/40, 156/300) = min(0.7, 0.52) = 0.52，缩放后 h' = round(20.8) = 21，w' = 156。上边距 ⌊11/2⌋ = 5，左边距 ⌊4/2⌋ = 2。字高从 40 像素变成 21 像素。

**一张短公式。** h = 40、w = 80：s = min(0.7, 1.95) = 0.7，h' = 28，w' = 56，上边距 2，左边距 52。这回受高度限制，左右留了大片空白。

**一个公式的 token。** 取 `x^2`，最长 6 字节：

| 字符 | `x` | `^` | `2` |
|---|---|---|---|
| ASCII | 120 | 94 | 50 |
| token = 字节 + 1 | 121 | 95 | 51 |

这组数字（`x^2`，max_length = 6）后面三节会一直用。

### 31.2.5 对照代码

`contrastive_pairs.py` 的 `image_tensor`（第 20–34 行）就是推导 (1)：

- 第 22–25 行：找出墨迹大于 0.05 的行和列，裁出包围盒；全白图直接报错（这类图被跳过）。
- 第 27 行：`scale = min((h-4)/ink.shape[0], (w-4)/ink.shape[1])`，即 min(28/h, 156/w)。
- 第 28–29 行：双线性缩放到 (round(w·s), round(h·s))，至少 1 像素。
- 第 32–33 行：居中放进全 0 画布。对宽公式例子，`top, left = 5, 2`。

`open_pairs`（第 55–101 行）是推导 (2)：

- 第 69 行：`standard_split(n_train=None)` 在完整语料上划分。
- 第 71–72 行：`membership` 记下每条公式属于哪个划分，同时滤掉超过 64 字节的。
- 第 80–86 行：逐行读 parquet；划分已满就跳过；同一个规范化键只留第一张图（`seen`）。
- 第 63–64 行：请求 test 却没有 `allow_test=True` 时直接报错。test 图片在最终评测之前**根本不解码**。

`targets_for`（`formula_ocr.py` 第 14–24 行）是推导 (3)，下一节再细讲。注意第 20–21 行：**超长就报错，绝不截断**。截断会造出"没有结尾的公式"，再在后面补一个 EOS，就等于教模型"写到一半就停"。

### 31.2.7 概括：合成数据与渲染

本章正式实验的训练数据是开源原图（lab 第 0 节），不是"把 LaTeX 渲染成图片"的合成数据。代码里保留了一个渲染对照 `rendered_pairs`（第 104–127 行）：三个模板 `{a}x+{b}`、`\frac{a}{b}`、`x^{a}+{b}`，a、b 取 1–99，共 3·99·99 = 29,403 个公式（数学结论），按哈希分桶成 8:1:1。它只用于 CPU/MPS 上的流程检查，**结果不能和开源数据混报**。渲染工具的选型（mathtext、真 LaTeX、字体与噪声控制）留给项目阶段，这里不展开。

### 31.2.8 常见错误

| 错误 | 现象 | 怎样发现 |
|---|---|---|
| 先抽样再划分 | 换个 train_n，val 分数莫名跳动 | 断言 val 的键集合与 train_n 无关；比较两次 val 张量的哈希 |
| 按原串而不是规范化键去重 | test 分数偏高 | 统计 train/test 规范化键的交集，必须为空（tour 部分 2、5 都有这条断言） |
| 截断超长公式再补 EOS | 模型常在长公式中途停下 | `targets_for` 遇到超长直接报错，不要绕过 |
| 拉伸而不是等比缩放 | 分式线变粗、上标变形 | 把 `pairs.png` 里的图和公式并排看 |
| 缓存目录复用 | 改了样本数却读到旧张量 | `prepare_pairs` 会比对条数与来源，不一致报错；换配置就换 `--data-dir` |

## 31.3 接口：视觉 token 怎样进入解码器

### 31.3.1 动机

视觉编码器给出 320 个向量，GPT 只认"token 嵌入"。中间这一步怎样接，决定了整个模型的结构。第 26 章 26.8 节列了两种办法：

- **前缀拼接**：视觉 token 经过连接器后，接在文字嵌入的前面，一起送进同一个因果 Transformer。
- **交叉注意力**：解码器每一层多一个子层，查询来自文字，键和值来自视觉 token（第 9 章的 Encoder-Decoder）。

**本章用前缀拼接**；交叉注意力只作对比，想试可以当扩展自己做（第 26 章 26.8.4 节）。理由很实际（lab 第 1 节）：

1. 第 11 章的 GPT **一行不用改**，靠 `inputs_embeds` 入口就能接进来。
2. 因果 mask 和 KV cache 已经在第 11、15 章验证过，直接复用，不用再验证一个新的交叉注意力子层。
3. 这和第 32 章要拆的真实 VLM（LLaVA 式、Qwen 系列）是同一种结构，学完可以直接对照。

### 31.3.2 直觉：把笔记抄在作文纸最前面

交叉注意力像是"写作文时旁边摊着一本参考书，随时翻"。前缀拼接像是"把参考书的要点抄在作文纸的最前面几行，然后接着往下写"。后者看起来土，但对 GPT 来说，前面几行和自己写的字没有区别，注意力机制本来就能回头看任何一行。

连接器的作用是"翻译格式"：ViT 输出的向量住在视觉空间里，连接器把它搬到 GPT 的嵌入空间。本章两边宽度都是 256，看起来不用搬；但两边是**职责不同的模块**（ViT、连接器和 GPT 都随机初始化，用同一个 OCR 损失端到端一起训练），加一个两层 MLP 给模型一个专门在两种表示之间调整的地方（练习 31.1）。

### 31.3.3 推导：谁能看见谁

设视觉前缀长 P，文字部分（BOS + 字节 + 补齐）长 L，拼接后长 S = P + L。GPT 的每一层都用因果 mask：位置 i 可以看位置 j 当且仅当 j ≤ i。于是：

- **文字位置**（i ≥ P）能看到**全部** P 个视觉 token，以及自己之前的文字。于是写每个字节时，整张图都在视野里。
- **视觉位置**（i < P）在 GPT 里只能看到排在自己前面的视觉 token。这看起来是个缺陷，但视觉 token 在进 GPT 之前已经过 3 层**双向** ViT，彼此充分交流过了。GPT 里的因果限制只影响"视觉 token 在 GPT 里还能再加工多少"。

位置编码也要想清楚。ViT 部分用学习式位置表 `self.pos`（每个 patch 一个，按行优先排列）。进了 GPT，整个序列再按 0, 1, …, S − 1 加 RoPE：视觉 token 占 0…319，BOS 在 320，第 k 个字节在 320 + k。所以**同一个视觉 token 带着两套位置信息**：ViT 里的二维网格位置（被展平成一维编号），GPT 里的一维 RoPE 位置。

**代价。** 每层注意力的分数矩阵大小（数学结论，正式配置，每头）：

| 结构 | 计算 | 分数个数 |
|---|---|---|
| 前缀拼接 | S² = 385² | 148,225 |
| 交叉注意力 | 文字自注意力 65² + 交叉 65·320 | 25,025 |

前缀拼接多算约 5.9 倍，而且 320 个视觉 token 在 GPT 的每一层都要过一遍前馈网络。图片越大、视觉 token 越多，这笔账越贵，真实 VLM 要做"视觉 token 合并"（第 32 章），这是原因之一。在本章的尺寸上，这点代价换来"零改动复用"，值得。

> **停下来想一想：** 如果把 GPT 的 mask 改成"视觉前缀内部全可见、文字部分仍因果"（常叫 prefix-LM），哪些位置的计算会变？会不会让文字位置"偷看未来"？（提示：只改 i < P 且 j < P 的那一块；文字位置 i ≥ P 能看的集合不变。这是选做练习 31.8。）

## 31.4 teacher forcing 训练与损失 mask

### 31.4.1 动机

模型要学的是条件概率 p(公式 | 图)。按链式法则拆成逐字节的预测：

$$p(y_1,\dots,y_n,\text{EOS}\mid I) = \prod_{t=1}^{n+1} p(y_t \mid I, y_{<t}),\qquad y_{n+1}=\text{EOS}.$$

训练时我们手里有正确答案，所以每一步的"前文" y<t 直接用答案里的，不用模型自己生成的。这就是 **teacher forcing**：老师把正确的前半句递给你，你只负责猜下一个字。这样一条样本只要一次前向，就能同时训练所有位置。

难点不在思想，在**对齐**：哪个位置的输出要和哪个标签比，哪些位置根本不该算 loss。

### 31.4.2 直觉：填空练习册

把序列想成一本填空练习册。前 P 页印的是图片（只读材料，没有空要填）；接下来每一页上写着"到目前为止的正确答案"，页脚有一个空，要填"下一个字符"。最后几页是补齐的白纸，也没有空。

- 视觉页：没有空 → 标签 −100。
- BOS 页：空里填第一个字节。
- 第 k 个字节的页：空里填第 k + 1 个字节；最后一个字节的页填 EOS。
- 补齐页：没有空 → 标签 −100。

### 31.4.3 推导

记文字部分的输入为 x = (BOS, y₁, …, yₙ, PAD, …)，长 L = max_length + 1；标签为 ℓ = (y₁, …, yₙ, EOS, −100, …)。即

$$\ell_t = x_{t+1}\ (t < n),\qquad \ell_n = \text{EOS},\qquad \ell_t = -100\ (t > n).$$

（下标从 0 开始：x₀ = BOS。）拼接视觉前缀以后，完整标签是 P 个 −100 再接上 ℓ。GPT 的 loss 是

$$\mathcal{L} = -\frac{1}{N}\sum_{b}\sum_{t:\ \ell_{b,t}\neq -100} \log p_\theta(\ell_{b,t}\mid I_b,\ x_{b,0..t}),\qquad N = \#\{(b,t): \ell_{b,t}\neq -100\}.$$

这是**按 token 平均**（第 3 章）：长公式贡献更多项。

**为什么补齐不会污染有效位置？** 补齐都在后面。因果 mask 下，位置 t 只看 0…t，而有效位置 t ≤ n 之前没有任何补齐，所以补齐的嵌入是什么都不影响有效位置的 logits。所以本章**不需要单独的 padding mask**（第 8 章讲过的那种）。测试 `test_visual_and_padding_loss_are_excluded` 把补齐位置的输入全换成 100，断言有效位置的 logits 和 loss 都不变。

**第一步的 loss 应该是多少？** 随机初始化时输出接近均匀分布，每个计入位置的交叉熵约为

$$-\log\frac{1}{259} = \ln 259 \approx 5.557 \quad\text{（数学结论）}.$$

如果第一步明显低于它，先怀疑标签没错位（第 11 章 11.8 节）。

### 31.4.4 小数字例子

继续用 `x^2`、max_length = 6、P = 80：

| 文字位置 t | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|---|
| 序列下标 | 80 | 81 | 82 | 83 | 84 | 85 | 86 |
| 输入 x | 257 (BOS) | 121 (`x`) | 95 (`^`) | 51 (`2`) | 0 | 0 | 0 |
| 标签 ℓ | 121 | 95 | 51 | 258 (EOS) | −100 | −100 | −100 |

完整标签长 87：前 80 个是 −100，后 7 个如上。计入 loss 的只有 N = 4 个位置，所以

$$\mathcal{L} = -\tfrac14\left[\log p(121\mid\cdot)+\log p(95\mid\cdot)+\log p(51\mid\cdot)+\log p(258\mid\cdot)\right].$$

注意下标 79（最后一个视觉位置）的输出**没有被使用**。预测第一个字节的是 BOS 所在的下标 80。这样训练和生成完全一致：生成时我们送进 [视觉; BOS]，读最后一个位置的 logits，也就是 BOS 的位置。

再看 tour 部分 1 的例子：两条公式 `x` 和 `\frac{1}{2}`（11 字节），计入的位置数 N = (1 + 1) + (11 + 1) = 14（数学结论），和 `smoke/part1.json` 的 `supervised_tokens` 14 一致。

实测的第一步 loss：

- 【CPU 复跑】tour 默认小配置、种子 31、这两条公式：5.532。
- `smoke/part1.json`（GPU 冒烟，同样的小配置）：5.531。
- 【G100k】第 1 步（batch 64，计入 2870 个位置）：5.569（`logs/ch31_100k_stdout.log`）。

都贴着 ln 259 ≈ 5.557。

- 第 106 行：每步从训练集**有放回**地随机抽 64 条。所以 10000 步一共抽 640,000 条，对 20k 训练集约等于 32 遍，对 100k 约等于 6.4 遍（数学结论）。31.7 节会用到这个数。

- 第 118 行：梯度裁剪到范数 1。

AdamW、预热、余弦衰减、梯度裁剪都是第 4、16 章的内容，这里不再展开。

### 31.4.6 teacher forcing 的代价：暴露偏差

训练时前文永远正确；生成时前文是模型自己写的。一旦写错一个字节，后面的每一步都处在训练时没见过的状态里，错误可能越滚越大。这叫**暴露偏差**（exposure bias，第 3 章提过）。31.8 节你会看到一类表现：有 16 条 val 输出一直写到 65 字节上限也没停下来【G100k】。本章不处理它；第 34 章的强化学习从另一个角度对付"按整句打分"的问题。

### 31.4.7 常见错误

| 错误 | 现象 | 怎样发现 |
|---|---|---|
| 标签等于输入（没错位） | 第一步 loss 明显低于 5.557，训练 loss 很快接近 0，生成全是复读 | 断言 `inputs[:, 1:n+1] == labels[:, :n]`；看第一步 loss |
| 错位两次（数据端错一次，又在模型里错一次） | loss 降不下去，生成错一位 | 本书 GPT 不内部错位，测试锁定了这个约定 |
| 视觉位置没设 −100 | 视觉位置被要求预测某个标签，loss 偏高、梯度方向混乱 | `test_visual_and_padding_loss_are_excluded` 手算只含有效位置的交叉熵并对拍 |
| 补齐标签用 0 而不是 −100 | 模型学会"EOS 之后接一串 PAD"，loss 偏低，计入位置数虚高 | 打印 `labels.ne(-100).sum()`，应等于 Σ(nᵢ + 1) |
| 漏了 EOS | 生成永远不停，总是写到上限 | 看标签最后一个有效值是不是 258 |

## 31.5 解码：贪心、KV cache 与束搜索

### 31.5.1 动机

训练完，手里只有一张图。我们要一个字节一个字节地把公式"问"出来，直到模型说 EOS。第 14 章讲过两类策略：**搜索**（找概率高的那一条，贪心、束搜索）和**采样**（温度、top-p）。OCR 答案唯一，用搜索。

### 31.5.2 直觉

贪心是"每一步都写最有把握的那个字符"。它快，但可能被一步之差带偏：比如第一个字节在 `\` 和 `a` 之间犹豫，选了 `a`，后面就再也回不到 `\alpha`。束搜索是"同时保留 B 份草稿，每一步把所有草稿的所有续写放在一起比，只留总分最高的 B 份"。

KV cache 则是第 15 章的老朋友：视觉前缀和已经写好的字节，它们的 k、v 每一步都一样，算一次存起来就行。

### 31.5.3 推导

**贪心。** 第 t 步：

$$\hat y_t = \arg\max_{v \notin \{\text{PAD},\text{BOS}\}}\ p_\theta(v \mid I, \text{BOS}, \hat y_{<t}).$$

把 PAD 和 BOS 排除在外，是因为它们在训练标签里从不出现，生成它们没有意义。遇到 EOS 就停。最多 max_length + 1 = 65 步（含 EOS）。

**位置编号。** 预填充送入 [视觉; BOS]，长 P + 1，占用位置 0…P。第 t 步（t 从 0 开始）新写的字节送进去时，位置是

$$\text{pos}_0 = P + 1 + t.$$

正式配置下 P = 320：第一个生成的字节在位置 321。第 64 步（第 65 个 token）选出后循环就结束，不再送入，所以最大用到位置 320 + 64 = 384，正好是 `block_size` − 1（数学结论）。

**束搜索。** 序列的分数是累计 log 概率 Σ log p(ŷₜ | …)。每步把 B 条存活草稿全部扩展，按累计分数留前 B 条；遇到 EOS 的草稿移出束、不再扩展。B = 1 时它就是贪心（第 14 章 14.7 节）。累计 log 概率天然偏爱短序列，所以最终排序可以除以长度惩罚 ((5 + |y|)/6)^α（第 14 章 14.8 节）。

### 31.5.4 小数字例子

**一个两步的玩具。** 假设第一步 p(a) = 0.5，p(b) = 0.4；接 a 之后最好的是 EOS，概率 0.4；接 b 之后最好的是 EOS，概率 0.9。

| 路径 | 概率 | log 概率 |
|---|---|---|
| a, EOS | 0.5 × 0.4 = 0.20 | −1.609 |
| b, EOS | 0.4 × 0.9 = 0.36 | −1.022 |

贪心第一步选 a，最后得到 0.20 的路径；B = 2 的束搜索两条都留着，第二步发现 b 那条总分更高，选 0.36（数学结论）。

**本章模型的预填充形状。** 小配置 P = 80、批量 2：预填充输入 (2, 81, 32)，输出 logits (2, 81, 259)，取最后一行 (2, 259) 选第一个字节；之后每步只送 (2, 1) 个 token，`pos0` 依次是 81、82、…

### 31.5.5 对照代码：`generate`

`formula_ocr.py` 第 70–92 行：

- 第 73–75 行：步数默认 max_length + 1；超过上下文就报错，而不是悄悄截断。
- 第 76–79 行：**预填充**。编码图片，拼上 BOS，一次性送进 GPT，同时把每层的 k、v 写进 `caches`。
- 第 83 行：取最后一个位置的 logits，把 PAD、BOS 设成 −∞。
- 第 84 行：`argmax` 就是贪心。`masked_fill(done, EOS)`：已经结束的样本继续"写" EOS，保证批里各行步数一致。
- 第 85–86 行：所有样本都结束，或到了步数上限，就停。
- 第 87 行：只送入新 token，`pos0=self.prefix_length+1+t`，即推导里的公式。
- 第 89–91 行：截到第一个 EOS；token 减 1 还原成字节；用 `errors='replace'` 解码，模型写出非法 UTF-8 时不会崩。

`test_cached_generation_matches_full_prefix` 不用缓存、每步重算整个前缀，和 `generate` 的结果逐字比较。`pos0` 差一位、缓存没清，这个测试都会失败。

### 31.5.6 束搜索怎样接上

本章的实验**只用了贪心**，所有【G…】数字都是贪心解码的结果。第 14 章在 `miniocr/decoding.py` 写过一个与模型无关的 `beam_search(step_fn, prompt, max_new, beam, eos, alpha)`，只要给它一个 `step_fn`：输入若干条等长前缀，返回每条下一个 token 的 log 概率。对一张图，可以这样包一层：

```python
@torch.no_grad()
def step_fn(prefixes):                               # prefixes: k 条等长的 token 列表，都以 BOS 开头
    idx = torch.tensor(prefixes)                      # (k, t)
    logits, _ = model(image.expand(len(prefixes), -1, -1, -1), idx)   # (k, t, 259)
    last = logits[:, -1].float()                      # (k, 259)
    last[:, [PAD, BOS]] = -float('inf')               # 与 generate 的约束一致
    return last.log_softmax(-1)                       # 屏蔽后重新归一化

best = beam_search(step_fn, [BOS], max_new=65, beam=4, eos=EOS)
```

顺序要注意：先屏蔽 PAD、BOS，再 log_softmax，和第 14 章 `tour.py` 的写法相同。这两个 token 在不同前缀上占的概率不一样。如果先 log_softmax 再屏蔽，每步留下的概率之和小于 1，而且各前缀少得不一样：一条前缀只因为把概率分给了本来就不许选的 PAD、BOS 就被扣分，累计分数的排序会被这部分概率带偏，束搜索可能留错草稿。贪心只取最大值，屏蔽的先后不影响选出的 token，所以 `generate` 和 `beam=1` 都不受影响。

这个写法每步重算整个前缀，没有用 KV cache，慢但简单。【CPU 复跑】作者用测试里的极小模型（宽度 16、各 1 层、最长 16 字节，种子 31）和 3 张随机图核对过：`beam=1` 的结果和 `generate` 完全一致。这段代码不在 tour 里，束搜索在本章模型上能带来多少提升**待验证**（选做练习 31.5）。

### 31.5.7 常见错误

| 错误 | 现象 | 怎样发现 |
|---|---|---|
| `pos0` 少加 1（忘了 BOS 占一个位置） | 缓存生成和整段重算结果不同，质量下降 | `test_cached_generation_matches_full_prefix` |
| 没禁止 BOS | 一旦生成 BOS（257），转字节时得到 256，`bytes(...)` 直接抛 `ValueError: bytes must be in range(0, 256)`，还没到 UTF-8 解码这一步 | 看第 83 行是否把 PAD、BOS 的分数设成 −∞；用极小模型强制生成一次 BOS 复现报错 |
| EOS 之后继续收集 token | 输出尾巴上挂着乱码 | 看第 89–90 行是否截到第一个 EOS |
| 批里有样本提前结束就整批停 | 长公式被截短 | 用 `done.all()` 而不是 `done.any()` |
| 用采样评测 OCR | 同一张图两次结果不同，EM 抖动 | 评测固定贪心或束搜索，记录生成参数 |

## 31.6 评测口径

### 31.6.1 动机

loss 下降不等于会读公式。我们要的是和第 0、22 章同一把尺子量出来的数，并且清楚每个数**能说明什么、不能说明什么**。本章用第 0 章 0.9.3 节 OCR 主任务面板的精简版。评测复用第 18 章的 `score_postcorrect`（`tour.py` 第 42–47 行），只保留和 OCR 有关的五项：n、EM_raw、EM_norm、CER、parse_rate；31.8 节另列了写到上限没停的条数。后纠错特有的 broken/fix rate 在这里没有意义，删掉了。面板里的渲染一致率和 CER_token 本章没有报告，因为 `score_postcorrect` 只按字符算 CER、只调用 `can_parse`、不比较渲染图。

### 31.6.2 直觉

- **EM_raw**：逐字符完全一样。太苛刻：`x^2` 和 `x^{2}` 排出来一模一样，却算错。
- **EM_norm**：先用第 0 章的规范化器统一写法（去空格、补花括号、删间距命令、统一同义命令），再比。这是本章的主指标。
- **CER**：字符错误率，衡量"差多少"。一条公式错一个字符和错一半，EM 都是 0，CER 能区分。
- **parse_rate**：输出能被 mathtext 子集解析的比例。它只说"语法上像个公式"，**不说对不对**。

### 31.6.3 推导

**CER 的定义。** 先把参考和预测都规范化成 token，再把 token 拼成字符序列（第 0 章的"规范 token 拼接字符"）。语料级 CER 是

$$\text{CER} = \frac{\sum_i d(\text{ref}_i, \text{pred}_i)}{\sum_i |\text{ref}_i|},$$

d 是编辑距离。分子分母各自求和，长公式权重大。预测比参考长很多时，编辑距离可以超过参考长度，所以 **CER 可以大于 1**。

**区间。** 比例（EM、parse_rate）用 Wilson 95% 区间（第 18 章）：

$$\frac{\hat p + \frac{z^2}{2n}}{1+\frac{z^2}{n}} \pm \frac{z}{1+\frac{z^2}{n}}\sqrt{\frac{\hat p(1-\hat p)}{n}+\frac{z^2}{4n^2}},\qquad z=1.96.$$

CER 是比值，没有简单公式，用 1000 次有放回 bootstrap、种子 0、取 2.5% 和 97.5% 分位（第 22 章）。这些区间**只描述 500 张子集的抽样波动**，不包括训练种子、数据选择、设备差异带来的变化。

**选择协议。** 训练中每 500 步，在 val 的**前 100 张**上算一次 CER，最低的存成 `best.pt`（平局取较早的）。训练结束后加载它，在**完整 val 500** 上评一次，写进 `frozen.json`（冻结）。按第 0 章 0.10.1 节的规则，选型冻结后，预先登记的候选可以各评一次 test，只报数字和区间，不据此改任何设置。本章只有【G100k】走到这一步，两个 20k 运行只读到 val。

### 31.6.4 小数字例子

**EM 与 CER。** 参考 `x^2` 规范化为 `x ^ { 2 }`，拼成字符 `x^{2}`，长 5。

| 预测 | EM_raw | EM_norm | 编辑距离 |
|---|---|---|---|
| `x^{2}` | ✗ | ✓ | 0 |
| `x_2` → `x_{2}` | ✗ | ✗ | 1 |

两条参考 `x^2`（长 5）和 `x^2+1`（长 7），预测 `x_2` 和 `x^{2}`：距离 1 + 2 = 3，CER = 3/12 = 0.25（数学结论；作者用 `miniocr.eval.metrics.error_rate` 核对过）。

CER 大于 1 的真实例子：CPU 渲染对照里，宽度 32 的小模型只训练了 40 步，在 20 张 val 上 CER 是 7.86（本项目观察，CPU，渲染对照，train 128、40 步、种子 31，`local_cpu_control.log`）。还没学会停，输出远比参考长。

**Wilson 区间手算。** 最终 test 上 EM_norm 是 236/500，p̂ = 0.472：

- 1 + z²/n = 1 + 3.8416/500 = 1.00768
- 中心 = (0.472 + 0.00384)/1.00768 ≈ 0.4722
- 半宽 = 1.96/1.00768 × √(0.472·0.528/500 + 3.8416/10⁶) ≈ 1.9451 × 0.02241 ≈ 0.0436
- 区间 ≈ [0.429, 0.516]

和 `final_test.json` 记录的 [0.429, 0.516] 一致【G100k】。

### 31.6.5 对照代码

- `tour.py` 第 51–57 行 `evaluate`：按批调用 `model.generate`，然后 `score`。注意第 55 行：评测也在 bf16 autocast 下做。
- 第 42–47 行 `score`：把每条样本包装成 `PostCorrectExample`，参考和"源"都填公式本身（OCR 没有噪声源文本），只留五项汇总。

### 31.6.6 常见错误

## 31.7 实验结果：样本数对照

### 31.7.1 动机

第一次正式训练用了 20000 张图，结果很难看：完整 val 上 EM_norm 只有 0.012【G20k-p4】。是模型太小、patch 太粗、训练太短，还是数据太少？这一节看两个维度的对照：patch 4 对 patch 8，20k 对 100k。

### 31.7.2 直觉：背答案和学方法

只做 20 套练习题、每套做 32 遍，你会把答案背下来，换一套新题就不会了。做 100 套、每套 6 遍，背是背不下来的，只好学方法。训练集大小和"每条样本被看了几遍"是绑在一起的：**步数和 batch 固定时，样本少就意味着重复多**。

### 31.7.3 推导：遍数

每步抽 B = 64 条，共 10000 步，总共抽 640,000 次（有放回）。平均每条样本被看到的次数是 640,000 / N（数学结论）：

| train_n | 平均遍数 |
|---|---|
| 20,000 | 32 |
| 100,000 | 6.4 |

所以下面的对照**同时改变了两件事**：数据多样性和重复次数。要把它们分开，得做"固定遍数"或"固定步数、改 N"的多点实验，本章没有做（待验证）。

### 31.7.4 结果

三次正式训练，模型结构、步数、batch、学习率都相同，完整 val 500 上的结果（本项目观察，各运行的 `frozen.json`）：

### 31.7.5 这算不算"规模曲线"？

严格说不算。只有两个样本量，而且遍数也跟着变了。它能支持的结论是："在这个模型和 10000 步的预算下，20k 不够，100k 明显好得多。"它**不能**支持"误差随数据按某个幂律下降"之类的说法，也不能告诉你 200k 会不会更好。要画曲线，至少需要 3–4 个样本量（例如 20k、50k、100k、200k），最好每个点跑 2–3 个训练种子（待验证，选做练习 31.6）。

## 31.8 错误分析：看没看图，错在哪里

### 31.8.1 动机

0.454 的 val EM_norm 意味着一半多的公式读错了。下一步改什么——更高分辨率？更大模型？更多数据？——取决于错误**从哪里来**。第 26 章提出的问题是：**是视觉没看清，还是语言模型"脑补"了？**

本节的工具都只用 val（tour 部分 4，lab 第 4 节）。开发期不看 test 的错例，最终报告定稿后才可解封。

### 31.8.2 直觉：给模型换图，看它怎么反应

想知道一个学生抄公式时到底看没看黑板，最简单的办法是动黑板：

- **遮住中间一块**：如果他还能写对，说明在背；如果中间那段写乱了，说明在看。
- **换成别人的黑板**：如果他还写原来的答案，说明在背。
- **擦成空白**：他写出来的就是"什么都没看见时的默认答案"，那是他的语言习惯。

再加一个工具 **saliency**：对某个输出 token 的 log 概率求对输入像素的梯度。梯度大的像素，是"稍微改一点就会明显改变这个 token 把握"的地方。

### 31.8.3 推导：每个干预能说明什么

设 f 是"图 → 贪心输出"这个函数。它是**确定性的**：同一张图永远得到同一个输出（忽略批内的浮点差异）。由此可以直接推出两件事（数学结论）：

1. **全白图**：500 张全白图是同一个输入，所以 500 条输出必然是同一个字符串。
2. **循环错配**：第 i 个位置喂的是第 i − 1 张图（`images.roll(1, 0)`），所以错配后第 i 条输出必然等于原图第 i − 1 条输出。错配的预测集合只是原图预测集合的一个**重排**，于是 parse_rate 必然和原图一样。EM 却没有这样的必然：错配后第 i 条算对，当且仅当原图第 i − 1 条输出恰好等于第 i 条参考。即使相邻两条参考不同，上一张图的错误输出也可能碰巧命中（参考 `[a, b]`、原图输出 `[b, a]` 时，错配后第 2 条就是对的）。所以错配 EM 是多少只能实测，不能推导。

所以错配实验的 parse_rate 和原图一样，**不能**拿来证明"语言先验能产生合法公式"，它只是把原图的输出换了个位置。这个实验提供的是一个参照："答非所问"时的 CER 有多高。

遮挡不同。`occluded[:, :, :, 60:100] = 0` 把宽 160 的画布中间 40 列清零。在 patch 4 下，这是 40 个 patch 列中的第 15–24 列，即 8 × 10 = 80 个视觉 token（数学结论）。这些 token 的 patch 嵌入变成 0，只剩位置向量。输出怎样变，取决于模型怎样理解"一片空白"。

**saliency 的含义与局限。** `token_saliency` 计算

$$S_{h,w} = \left|\frac{\partial \log p_\theta(y_t \mid I, y_{<t})}{\partial I_{h,w}}\right|,$$

前文 y<t 是 teacher forcing 给的正确答案。所以它是**局部线性敏感度**：只描述"在这张图附近、在正确前文下"的情况，和自由生成时模型实际依赖什么不一定相同。亮区不等于原因（第 26 章 26.3 节）。

### 31.8.4 结果

**四种条件（val 500，同一检查点，贪心；`analysis100k/controls.json`）【G100k】：**

| 条件 | EM_norm | CER [95% 区间] | parse_rate |
|---|---|---|---|
| 原图 | 0.454 | 0.124 [0.109, 0.140] | 0.902 |
| 中央遮挡 40 列 | 0.000 | 0.454 [0.436, 0.472] | 0.700 |
| 循环错配 | 0.000 | 0.969 [0.948, 0.992] | 0.902 |
| 全白图 | 0.000 | 0.887 [0.880, 0.893] | 0.000 |

以下几点是作者对 `controls.json` 和 `error_cases.json` 的逐条统计（本项目观察，【G100k】，val 500）：

- **错配的输出和推导完全一致：** 500/500 条错配输出等于原图上一条的输出。CER 0.969 可以当作"写了一个无关公式"的水平。
- **白图的输出：** 500 条都是同一个字符串 `\tagge&\\\tau&\ast&\ast`，不能解析。这就是模型在"什么也没看见"时的默认输出，看起来像训练数据里对齐环境的碎片。
- **遮挡后，模型把空白读成了空格命令。** 319/500 条遮挡输出含 `\quad` 或 `\qquad`，而参考里只有 11 条含有。例如参考 `ds^2_L = - N^2(t) dt^2 + a^2 (t) d \Omega_3^2,`，遮挡后输出 `ds^2_L = -N \qquad \qquad +a^2(t) d\Omega_3^2,`：两端读对了，中间的空白被"如实"写成了大间距。这说明模型在读图：它看见中间有一大片空白，就写了一大段空白。
- 遮挡使 EM 归零、CER 从 0.124 升到 0.454，这是"模型依赖图像中部"的直接证据。

**按长度分桶（val 500，原图）【G100k】：**

| 参考字节数 | 条数 | EM_norm | CER |
|---|---|---|---|
| ≤ 24 | 46 | 0.674 | 0.129 |
| 25–40 | 131 | 0.565 | 0.086 |
| 41–52 | 180 | 0.433 | 0.109 |
| 53–64 | 143 | 0.308 | 0.161 |

EM 随长度单调下降。这有两个可能的原因，各自对应一条可检验的假设：(a) 长公式缩放后字更小（31.2.4 节的宽公式例子，字高从 40 像素压到 21 像素），视觉上更难；(b) 序列越长，暴露偏差越可能累积。最短一桶只有 46 条，没有给区间，这只是线索。另外，含 `\frac` 的 77 条 EM_norm 0.390，不含的 423 条 0.466。

**错在哪里：编辑距离与"看不见的差别"。** 原图上读错的 273 条里：

- 编辑距离为 1 的 38 条，为 2 的 26 条，合计 64 条"只差一两个字符"；距离 6 及以上的 167 条。
- 有 14 条在一个放宽的诊断口径下能匹配：删掉对齐符 `&`，把 `\ldots` 视同 `\dots`，再像第 22 章的 `em_ignoring_final_punct` 那样去掉句末标点（【CPU 复算】作者在 `controls.json` 的原图结果上复算）。其中 10 条只差 `&`（排版时不可见）或 `\dots`/`\ldots`（渲染相同），差别在图上看不出来。例如参考 `\sum_{k=1}^{n}k\gamma_{k} &= \frac{n(n+1)}{2}`，输出 `\sum_{k=1}^n k\gamma_k = \frac{n(n+1)}{2}`。这 10 条的问题出在标签：标签里有图上不存在的信息。另外 4 条必须去掉句末标点才能匹配，比如参考以 `dt\quad .` 结尾、输出只有 `dt`；句末的逗号和句号是印在图上的，这 4 条算不算模型读错，要回去看图才能定。这只是诊断口径，不证明数学等价，官方指标仍然是 EM_norm。
- 同一个道理也解释了 EM_raw 和 EM_norm 的巨大差距（0.092 对 0.454）：val 参考里 7.8% 的字节是空格（1715/21994），作者怎样敲空格，图上看不出来。模型的一部分容量被花在了"猜作者的空格习惯"上。
- 16 条输出正好 65 字节，即一直写到上限也没生成 EOS。例如参考 `G^K\,=\,G^0+G^0K^RG^0+…`，输出 `c^{-6}_i-c^6c+c^6p^6c^2c^2c^6c^8c^2…`，进入了复读。这类错误更像解码一侧的问题（31.4.6 节的暴露偏差）。
- 原图输出中有 49 条不能解析，其中 10 条却是 EM_norm 正确的：参考本身就超出了 mathtext 子集。再次说明 parse_rate 不是正确率。

**几条典型的视觉混淆。** 下面是作者从 val 错例里挑的，只用来说明分类方法，不代表比例：

| 参考 | 原图输出 | 初步归类 |
|---|---|---|
| `\breve{M}^{r}(x,t,k)=…` | `\hat{M}^{}(x,t,k)=…` | 小重音符号看错（视觉） |
| `\ddot{x}+\frac{1}{x}\dot{x}^2…` | `\dot x + \frac{1}{x}\dot x^2…` | 两点读成一点（视觉） |
| `u_{tt}-c^2 u_{xx}=0 .` | `u_{tt}-c^2u_{xxx}=0.` | 多写一个下标字符（视觉或语言，待人工看图） |
| `\log(N!) = N\log(N) - N + O(\log(N)).` | `\log(N)=N\log(N)-N+O(\log(N)).` | 漏了 `!`（视觉：小符号） |

要把"待人工看图"的那类分清楚，需要回到预处理后的 32×160 图片上看那个符号还剩几个像素（lab 第 4 节）。

**saliency（val 第 0 张，`analysis100k/saliency.npz`）【G100k】。** 参考是 `z_k = (z_{1,k}, z_{2,k})\in Z, \ \ \ \ k=1,..., K,`，共 50 字节。tour 取了三个位置：0（目标字节 `z`）、3（目标字节是一个**空格**）和 50（EOS）。作者对三张梯度图按列求和、算质心：

| 位置 | 目标 | 梯度质心所在列（共 160 列） | 左三分之一占比 | 右三分之一占比 |
|---|---|---|---|---|
| 0 | `z` | 52.7 | 0.597 | 0.236 |
| 3 | 空格 | 61.0 | 0.516 | 0.243 |
| 50 | EOS | 103.7 | 0.224 | 0.552 |

写第一个字节时，敏感区偏左；判断"该结束了"时，敏感区移到右侧。这和"从左往右读"的直觉一致。但这是**一张图、三个位置**，只能当描述，不能当结论。位置 3 的目标是空格，图上没有对应的墨迹，它的梯度照样有分布，这也提醒你：saliency 亮的地方，不一定是"这个 token 画在那里"。

### 31.8.6 怎样把这些证据组织成错例表

结合第 22 章 22.6 节的错例分类表，本章建议的分类顺序是：

1. **标签不可见**：差别在图上看不出来（`&`、`\dots`/`\ldots`、空格）。先剔出来，单独计数。只差句末标点的要先看图：标点印在图上，漏读就是模型的错。
2. **解码失控**：写到上限没停、复读。看输出长度。
3. **视觉混淆**：小符号、重音、上下标。回看预处理后的图，看那个符号还剩几个像素；在 val 上遮住它，看输出是否改变。
4. **结构错误**：上下标挂错、分式嵌套错。
5. **说不清**：原图错、遮挡后还错，不能直接归因于视觉编码器。

遮挡、错配、白图都是**分布外**的输入，它们证明"模型整体上依赖图像"，但不是逐条错例的病因诊断器。

### 31.8.7 常见错误

| 错误 | 现象 | 怎样发现 |
|---|---|---|
| 用错配实验的 parse_rate 论证"语言先验" | 错配和原图 parse_rate 一模一样，却被当成新发现 | 先推导：确定性模型下错配只是重排 |
| 把 saliency 亮区当成原因 | "模型看的是这里"的断言 | 对亮区做遮挡，看输出是否真的改变 |
| 开发期看 test 的错例 | 不自觉地按 test 调设置 | `part5` 不导出 test 错例；只在 val 上分析 |
| 不剔除"标签不可见"的错 | 高估模型的视觉错误 | 先用规范化 + `&`/`\dots` + 句末标点诊断过一遍 |
| 只看平均数 | 看不出"长公式差、短公式好" | 按长度、结构分桶（第 22 章 22.4 节） |

## 和真实框架的对应

| 本章 | Hugging Face transformers 与相关模型 |
|---|---|
| `FormulaOCR`：ViT → 连接器 → GPT，前缀拼接 | `VisionEncoderDecoderModel` 把任意视觉编码器和任意文本解码器接起来，但走的是**交叉注意力**：解码器配置 `add_cross_attention=True`，每层多一个查询来自文字、键值来自编码器输出的子层 |
| `targets_for` 在数据端错开一位 | `VisionEncoderDecoderModel` 接收 `labels`，在内部把它右移生成 `decoder_input_ids`（以 `decoder_start_token_id` 开头）；−100 同样表示不计入 loss（细节以源码为准，待验证） |
| 字节词表，259 个 token | TrOCR、Donut、Nougat 都用子词词表（BPE / SentencePiece），一个 LaTeX 命令常常是一个 token |
| 随机初始化 | TrOCR 用预训练的图像 Transformer（BEiT/DeiT）初始化编码器、预训练的文本模型（RoBERTa/MiniLM）初始化解码器；Donut 和 Nougat 用 Swin Transformer 编码器 + BART 系列解码器 |
| `generate`：贪心 + KV cache | `model.generate(pixel_values, num_beams=…)`，支持束搜索、长度惩罚、`no_repeat_ngram_size` 等 |
| 32×160 固定画布 | Nougat 处理整页 PDF 图像（高分辨率），Donut 处理整张文档图；真实 VLM 用动态分辨率（第 32 章） |
| 前缀拼接这种接口 | LLaVA 式 VLM（含第 32 章的 Qwen 系列）：视觉 token 经 MLP 投影后拼进语言模型的输入序列，和本章同构 |

结构上可以这样记：**TrOCR、Donut、Nougat、im2latex 都是"编码器 + 带交叉注意力的解码器"**，本章和第 32 章的 VLM 是"视觉前缀 + decoder-only 语言模型"。两类结构做的是同一件事：让写每个 token 时都能看到整张图。

## 小结

本章把第 29 章的 ViT 和第 11 章的 GPT 用一个两层 MLP 连接器、一次沿序列轴的拼接接了起来，整个模型约 587 万参数，GPT 一行没改。训练用 teacher forcing：输入是 BOS 加字节，标签是字节加 EOS，视觉前缀和补齐都标 −100，第一步 loss 应贴近 ln 259 ≈ 5.557；推理用带 KV cache 的贪心解码，新 token 的位置是 P + 1 + t。数据按完整语料先分组划分、再取前缀，所以 20k 和 100k 共享同一份 val/test：20k 时模型背下了训练集（val EM_norm 0.012），100k 时 val EM_norm 0.454、test 0.472 [0.429, 0.516]（本项目观察，RTX 4090（租用），单种子）。遮挡让 EM 归零、空白被读成 `\quad`，说明模型确实在看图；错配和白图的结果有一部分是确定性模型的必然，先推导再解读；还有一部分错误源于标签里有图上看不见的信息。
