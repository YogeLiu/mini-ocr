## 答案与提示

**31-C1.** 生成时我们送入 [视觉; BOS]，读**最后一个位置**的 logits 来选第一个字节，那个位置就是 BOS。训练时把第一个字节的标签放在 BOS 位置，训练和生成用的是同一个位置。若改放到最后一个视觉位置，生成时就不该送 BOS，而要从视觉前缀最后一个位置直接读，且 BOS 嵌入失去作用。

**31-C2.** 补齐都在有效 token 之后；因果 mask 下位置 t 只看 0…t，所以有效位置看不到任何补齐。左补齐时，有效位置能看到前面的补齐，嵌入会被混进去，就需要 padding mask，而且 RoPE 的位置编号也会被补齐推后。

**31-C3.** (a) 没有本质区别：两种结构下文字位置都能看到全部视觉 token。(b) 前缀拼接每层算 (P + L)² 个分数，交叉注意力算 L² + L·P；本章是 148,225 对 25,025。(c) 前缀拼接里，视觉 token 先过 ViT，再在 GPT 的每一层被继续更新；交叉注意力里，视觉 token 只在编码器里更新，解码器各层读的是同一份编码器输出（每层有自己的 k、v 投影）。

**31-C4.** (1) 和完整语料的划分不再一致：抽样子集里的 train 公式，可能在完整语料划分里属于 val/test（反之亦然），和用完整划分的其他章节、其他实验一比就是泄漏。注意，只要抽样后仍调用本项目按规范化键分组的划分函数，同一组不会被拆到子集内部的 train 和 test；组内泄漏要额外违反分组规则才会出现。(2) 划分随抽样变化，换一个 train_n 就可能换一套 val/test 成员，不同样本量的实验不可比。

**31-C5.** 640,000 次抽样，20k 约 32 遍、100k 约 6.4 遍。20k 的样本被反复看到，模型背下了训练集（训练 loss 近 0），泛化差；100k 重复少，背不下来，只好学到更通用的规律。不能单独说明多样性：遍数也同时变了，要分开得做固定遍数或多点实验。

**31-C6.** 不一定。(1) CER 和 EM 衡量的东西不同：CER 降低可能来自"很多公式少错几个字符"，EM 要求整条全对；(2) 100 张子集的抽样波动大，选出的检查点在 500 张上未必最好；(3) 选择时 CER 严格变小才更新，平局取较早的步，与 EM 无关。

**31-C7.** 模型是确定性的，错配后第 i 条输出就是原图第 i − 1 条输出（实测 500/500），预测集合只是重排，parse_rate 必然相同，不提供关于语言先验的新信息。错配实验能告诉你"写了一个无关公式时 CER 有多高"（0.969），并确认输出完全由图片决定。真正反映"没看到图时的默认输出"的是白图实验。

**31-C8.** 第一个字节通常对应公式的最左侧，梯度应偏左；EOS 要判断"已经写完"，应更依赖右端（本章 val 第 0 张：质心列 52.7 对 103.7，本项目观察，单张图）。saliency 是 teacher-forced 前文下的局部梯度，只描述"像素微小变化对这个 token 概率的影响"，不等于自由生成时的依赖，更不是因果证据；要验证需要做遮挡等干预。

**31-C9.** 主要是空格等纯写法信息（val 参考中 7.8% 的字节是空格）。【CPU 复算】规范化后新增算对的 181 条里，102 条只差空格；其余差在间距命令（`\,`、`\quad` 等）、单个 token 外的花括号（`x_{1}` 对 `x_1`）、同义命令（`\dfrac` 对 `\frac`）和尺寸命令（`\big` 对 `\Big`）上，这些正是规范化器会抹掉的差别。它们大多读不出来，只能猜作者习惯；模型的一部分容量和 loss 花在了预测这些不可见的字节上。（`&` 和 `\dots`/`\ldots` 也看不出来，但规范化器保留它们，这类差别会让 EM_raw 和 EM_norm 同时判错，解释不了两者的差距。）

**31-H1.** patch 4：P = 320，S = 385，`block_size` = 385。patch 8：P = 80，S = 145，`block_size` = 145。

**31-H2.** (a) LN 4·128 = 512；qkv 128·384 + 384 = 49,536；proj 16,384 + 128 = 16,512；MLP 128·512 + 512 + 512·128 + 128 = 131,712。合计 198,272。(b) 中间维 384；2·128 + 4·128² + 3·128·384 = 256 + 65,536 + 147,456 = 213,248。(c) 2·128 + 2·(128² + 128) = 256 + 33,024 = 33,280。

**31-H3.** `inputs` = [[257, 98, 96, 50, 0, 0], [257, 93, 113, 106, 0, 0]]；`labels` = [[98, 96, 50, 258, −100, −100], [93, 113, 106, 258, −100, −100]]。（`a`=97、`_`=95、`1`=49、`\`=92、`p`=112、`i`=105，各加 1。）N = 4 + 4 = 8。期望 loss ≈ ln 259 ≈ 5.557。

**31-H6.** `x^2` → `x^{2}`（5 字符），`x^{3}` 距离 1；`a+b`（3 字符）对 `a+b+c` 距离 2。CER = 3/8 = 0.375。两条 EM_norm 都是错（0/2）。

**练习 31.1 追问.** 两层 MLP 的线性部分是 2(256² + 256) = 131,584，加 LayerNorm 512；单个线性层是 65,792。少 66,304。

**练习 31.3 追问.** bf16 下 log_softmax 的精度差，梯度会更噪；tour 的 saliency 也在 float32 下计算（`part4.json` 的 `saliency_precision`）。

**31-D1.** 标签没错位（标签等于输入），模型学会"复制当前 token"。断言 `inputs[:, 1:n+1] == labels[:, :n]`；第一步 loss 明显低于 5.557 也是信号。

**31-D2.** 梯度"全为 0"（而不是 `None`）、输出又与图无关，最可能是连接器输出被乘了 0，或者某处把视觉特征换成了与图无关的常量：梯度照常回传但数值是 0，GPT 也看不到图，模型只能学"无条件的公式语言模型"，loss 停在语言模型的水平。要和另一类错误区分开：视觉特征被 `detach()`，或 `encode_image` 被 `torch.no_grad()` 包住，上游参数的 `.grad` 通常是 `None`；而且随图变化的特征值还在，GPT 仍能利用随机 ViT 给出的特征，输出不会完全与图无关，只是视觉一侧学不到东西。

**31-D3.** 生成循环里的 `pos0`：写成了 `P + t`，漏了 BOS 占的那个位置。第一个字节由预填充直接给出，所以总是对的。

**31-D4.** 标签那一行：应为 `[b+1 for b in raw] + [EOS]`，长度 n + 1。漏了 EOS，模型从未学过停止，总写到 65 步上限。

**31-D5.** (1) 划分：train/val/test 的规范化键是否两两不相交，是否先划分再取前缀；(2) 是否按 test 结果选过检查点或调过参（看 `TEST_STARTED.json` 的时间、实验记录）；(3) 数据缓存是否混用（`--data-dir` 与配置是否对应）。

**31-D6.** 64 × 65 = 4160，所有位置都被计入了。补齐位置要预测 PAD，这很容易，拉低了平均 loss。模型学会"EOS 之后接 PAD"；本章的 `generate` 禁止生成 PAD，所以影响被部分掩盖，但有效位置的梯度被稀释了。

**31-D7.** parse_rate 只说明语法合法，不说明内容来自哪里；EM 降为 0 恰恰说明模型依赖被遮挡的那部分图像。31.8.4 节观察到 319/500 条遮挡输出含 `\quad`/`\qquad`（参考里只有 11 条）：模型把中间的空白"读"成了大间距，这是在看图的表现，不是靠语言模型脑补。遮挡是分布外输入，不能据此评价视觉编码器在正常图上的强弱。
