## 答案与提示

**30.1** 负例是同一批里别人的配对：第 i 张图和第 j ≠ i 段文。不需要额外标注，只要批里的图文配对正确。

**30.2** 归一化把向量长度锁成 1，分数只反映方向。不归一化时模型可以把某些向量拉得很长，让它和谁的点积都大，loss 也能下降，但检索变得没有意义。

**30.3** 只算行时，每张图都要在所有文里找对自己的文，但不约束"每段文也要在所有图里找对自己的图"，可能出现几张图争同一段文的不对称解。对称损失两个方向都约束；检索时两个方向的指标也都会更均衡。

**30.4** （a）对：softmax 平移不变。（b）错：每格 sigmoid 看的是绝对值，加常数等于改了偏置。（c）这要分开说：温度不改变**同一个模型**的排序；但用不同温度**训练**出来的是不同模型，R@1 当然可能不同（本章实测 B = 32 的 CLIP 是 0.568 对 0.586）。（d）错：对所有候选加同一个数，排序不变。

**30.5** 太大：余弦只在 [−1, 1]，softmax 不够尖，损失有降不下去的地板，梯度一直在推已经排对的样本。太小：P 接近 one-hot，梯度集中在最难的一两个负例上，再乘 1/τ 被放大，训练容易不稳、对错标样本敏感。

**30.6** τ 会趋向 0（logit_scale 趋向无穷大）。数据可分时，每个正例在自己的行和列里都严格高于所有负例，∂L/∂s = Σ G_ij c_ij < 0，梯度下降一直增大 s。（只是大多数正例领先还不够，正文 30.5.6 有反例。）可分的训练数据上损失随 τ 单调下降，没有内部最优点，所以需要截断。

**30.7** 单种子；学习率没有随批量调；固定的是样本数而不是步数，B = 128 只走了 2048 步、最佳步都在最后一步，可能没训够；只试了两个批量；数据是一个短公式子集、图库固定为 512。

**30.8** 每格的 sigmoid 损失只依赖自己的分数，可以把 B×B 矩阵切块、逐块直接相加，不需要像 CLIP 那样跨块合并每行、每列的 softmax 归一化量，多卡时可以分块交换文本特征。本章实现没有利用：仍在单卡上显式建整个 B×B 矩阵，也没测吞吐量。

**30.9** 图库多大？哪个方向（图→文还是文→图）？另外最好还问：是 val 还是只评一次的 test。

**30.10** 检索只能从已有的候选里挑，图库外的公式给不出来；文本向量是整段的摘要，不能逐字节还原 LaTeX；对比损失只要求"分得开"，不要求保留每个上下标的精确信息。

**30.11** 不能。本章实测 `Q^2=H` 的最近图像邻居是 `f = e^g`，余弦 0.837（本项目观察，`final/near_duplicates.json`），两者内容完全不同，只是都是短等式、排版轮廓像。近邻只能作为人工审阅的候选。

**30.12** （a）S = C。（b）行：0.6922、0.9208、0.7840；列：0.6435、0.9119、0.8395。（c）行平均 0.7990，列平均 0.7983，L_CLIP = 0.7987，比 τ = 0.5 时大。这个 C 每个正例都已排第一，放大倍数越小，正例越不突出，损失越大。

**30.13** （a）G_31 = (0.1153 + 0.1171)/6 = 0.0387；G_33 = (0.5712 − 1 + 0.5217 − 1)/6 = −0.1512。（b）0.0571 − 0.1785 + 0.1207 = −0.0007，接近但不等于 0。行项部分每行和为 0；列项是按列归一化的，同一行的三个列项来自三列不同的 softmax，和不一定为 0。（c）∂L/∂C_22 = G_22 / τ = −0.1785 × 2 = −0.3570。

**30.14** （a）log 4 = 1.3863。（b）4·log 2 = 2.7726。（c）b = −log 3 = −1.0986；L = log 4 + 3·log(4/3) = 1.3863 + 0.8630 = 2.2493。

**30.15** (1,2)：S + b = 0.6 − 0.6931 = −0.0931，负例，损失 log(1 + e^(−0.0931)) = 0.6477；梯度 σ(−0.0931)/3 = 0.4767/3 = 0.1589。(3,3)：S + b = 1.6 − 0.6931 = 0.9069，正例，损失 log(1 + e^(−0.9069)) = 0.3392；梯度 (σ(0.9069) − 1)/3 = (0.7124 − 1)/3 = −0.0959。

**30.16** τ = 1：2.518；τ = 0.2：0.190；τ = 0.07：约 0.00002（数学结论）。τ = 1 下即使完美也降不到 2.5 以下。

**30.17** （a）行 1：0.6 > 0.5，正例第 2；行 2：第 1；行 3：0.8 > 0.4，正例第 2；行 4：第 1。i2t R@1 = 2/4 = 0.5，R@2 = 1。（b）列 1 [0.5, 0.2, 0.1, 0.0]：第 1；列 2 [0.6, 0.7, 0.2, 0.1]：第 1；列 3 [0.1, 0.3, 0.4, 0.3]：第 1；列 4 [0.0, 0.1, 0.8, 0.9]：第 1。t2i R@1 = 1，R@2 = 1。（c）不变，除以正数不改变排序。

**30.18** 1/512 ≈ 0.00195，5/512 ≈ 0.0098，10/512 ≈ 0.0195。一致：0.002 就是 1/512（本项目观察，`final/frozen.json` 的 `baseline`）。

**30.19** B = 32：8192 步，每步 992 个负例对，共 8126464。B = 128：2048 步，每步 16256 个，共 33292288。比值 33292288 / 8126464 = 4.097，约 (B − 1) 之比 127/31。大批量见过的负例对总数多约 4 倍，更新次数却少 4 倍。

**30.20** （a）两项都是行平均 0.5833，返回 0.5833，而正确值是 0.5828。（b）对称矩阵的行和列完全一样，两种写法结果相同。（c）用一个非对称矩阵（如 C / 0.5）和 `F.cross_entropy` 双向写法对拍，或直接断言返回 0.5828。

**30.21** loss 一直贴着 log 64，说明模型完全没学到区分。可能：（1）图文两边配对错乱，检查 `pairs.png` 或在批里打印对应的图和文；（2）梯度没传回去（`detach`、`no_grad`、参数没进优化器），检查第一步每个参数的 `.grad`；（3）温度用错，比如把 `logit_scale` 当 τ 设成 0.07，放大倍数约 1，检查 `scores` 的数值范围是否只在 [−1, 1] 附近。

**30.22** （a）`.mean()` 除以 B²，正确版本除以 B，差 B 倍。（b）梯度整体缩小 B 倍。用 SGD 时，这相当于学习率除以 B，B = 128 比 B = 32 再小 4 倍。但本章用的是 AdamW：一阶矩除以二阶矩的平方根，会把恒定的梯度缩放几乎抵消掉（CPU 单步复算：参数初值 1、lr = 0.001，损失乘 1/32 和 1/128 后分别更新到 0.99899900032 和 0.99899900128）。所以 AdamW 下主要后果不是"学得慢"，而是损失数值偏小 B 倍；只有梯度小到和 eps 可比时，或与梯度裁剪（本章阈值 1）相互作用时才会改变更新。（c）`test_normalization_shift_permutation_and_extremes` 断言零分数时损失为 B·log 2，错误版本给出 log 2；参考实现对拍也会失败。

**30.23** HF 存的是 log(1/τ)，填 0.07 等于放大倍数 e^0.07 ≈ 1.07。检索排序只看余弦，和放大倍数无关，所以零样本 R@1 不变；但训练时 softmax 太平，损失有接近 log B 的地板（30.5.3），降不下去。正确的写法是填 log(1/0.07) ≈ 2.659。

**30.24** b = 0 时初始每格预测概率约 0.5，而负例比正例多 B − 1 倍，负例的梯度压倒性地把所有分数往下压，正例也被一起拖下去。修复：把偏置初始化为 −log(B − 1)，让零分数时偏置梯度为零（本章做法），或用 SigLIP 论文的较负初始值。

**30.25** 用 test 挑配置，test 不再是没见过的数据，0.62 是偏高的估计；应只用 val 选择、test 只评一次。val 0.95 和 test 0.62 差距很大，还要怀疑 val 和训练集有泄漏（同一公式跨划分）或 val 图库比 test 小；报告也没写图库大小和方向。

**30.26** 单靠"不稳定"解释不了。在 N×N、对角线一一配对的评测里，只要每一行的平局被排成**同一个**排列（不管稳定与否），恰好一个查询命中第一名，R@1 = 1/N（全零矩阵 `stable=False` 时 N = 12、32、512 都如此，本项目复算）。要虚高，必须是各行破平局方式不同：例如"相同"的分数其实差一点浮点舍入、不同行走了不同的排序路径，或评测协议变了。这时 R@1 取决于数值细节和实现，而不是模型，会让一个完全坍缩的模型看起来"比随机好"，掩盖训练失败。
