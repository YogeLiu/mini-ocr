## 答案与提示

**27.1** H 是行数，W 是列数，C 是每个像素的数值个数（RGB 为 3）。图片文件和显示设备按像素存储，所以库给出 HWC，一个像素的三个通道相邻；卷积要在每个通道的二维平面上滑动，CHW 让同一通道的整张平面相邻，便于按通道计算。

**27.2** `permute` 只改 stride，结果不连续。`view` 要求新形状能用现有 stride 表示，不连续的张量常常做不到，这时会报错（例如把换轴后的 `(3, H, W)` 摊平成一维）；但也不是一律报错，合并 H、W 两维恰好可以；部分自定义内核或 `.numpy()` 之后的操作也可能按错误顺序读数据。

**27.3** 可逆的仿射变换不改变信息量，丢掉的笔画不会因为换个刻度回来；但模型的权重是在某个刻度上学出来的，刻度不同，输入就落到它没见过的分布上。

**27.4** 最近邻和不抗锯齿的双线性是抽样，面积是平均。抽样只读少数几个源位置，细线恰好不在这些位置上就整条消失，挪一个像素又可能完整保留。

**27.5** 不矛盾。二值保留问"这条线上的像素还够不够黑（< 0.5）"，面积缩放把线摊成了浅灰，没过阈值；连续墨迹问"平均还剩多少黑"，墨水总量还在。

**27.6** letterbox 牺牲画布利用率：5:1 的公式只占画布约五分之一高，字变小。拉伸牺牲字形：每个字横向被压到约五分之一（相对于纵向），字母变得又高又瘦，可能和别的符号混淆。

**27.7** 同时改了：公式区域的像素数；视觉 token 总数（16 → 144）；缩小与放大的比例（128 几乎全是缩小，384 有 66% 是放大）。这些因素捆在一起，一次对照分不开谁起作用。

**27.8** 它的 token 数和输入形状都固定，变的只有"512×512 是从多少原始像素放大来的"，所以能单独看像素信息的影响。但它在这个任务上 CER 全部大于 1，几乎不会转写，成绩差异里噪声和"胡编"的成分很大。

**27.9** 违反"只在验证集上做选择，不根据测试集结果改设置"的协议（第 0 章 §0.10.1）。选型冻结后，预先登记的候选可以各评一次；本章只评选中的一个配置。按测试集结果换配置，测试集就成了验证集，报出的成绩偏乐观；如果真的换了，要在报告里写明并另补一份新的留出测试集。

**27.10** 1. 形状 `(3, 1, 2)`：R = [[10, 40]]，G = [[20, 50]]，B = [[30, 60]]。2. 内存顺序 10, 20, 30, 40, 50, 60，每 2 个一段："R" = [[10, 20]]，"G" = [[30, 40]]，"B" = [[50, 60]]，三个"通道"都混了。3. HWC stride (6, 3, 1)；permute 后 (1, 6, 3)；contiguous 后 (2, 2, 1)。

**27.11** 1. 0 → −1.000；64 → 64/255 = 0.251 → −0.498；255 → 1.000。2. 纯黑 (0 − 0.485)/0.229 ≈ −2.118，纯白 ≈ 2.249。3. [−1, 1] → (z − 0.5)/0.5 → [−3, 1]。（实际上默认 processor 还会先乘 1/255，范围会更离谱，见 27.21。）

**27.12** s = 2。1. 取 floor((j + 0.5) × 2) = 1, 3, 5, 7 号，结果 [1, 1, 1, 1]，线没了。2. u = 2j + 0.5 = 0.5, 2.5, 4.5, 6.5，分别在 (0,1)、(2,3)、(4,5)、(6,7) 间各半：[1, 0.5, 1, 1]。3. 每 2 个平均：[1, 0.5, 1, 1]。4. 都没有：0.5 不小于 0.5。注意 2 倍整数缩小时双线性和面积恰好相同；比例越大，两者差别越大（对照正文 8 → 2 的例子）。可用练习 27.5 的脚本核对。

**27.13** s = 5/3。第 0 行覆盖 [0, 5/3)：(1, 2/3) / (5/3) → (0.6, 0.4, 0, 0, 0)。第 1 行覆盖 [5/3, 10/3)：(1/3, 1, 1/3) / (5/3) → (0, 0.2, 0.6, 0.2, 0)。第 2 行覆盖 [10/3, 5)：(2/3, 1) / (5/3) → (0, 0, 0, 0.4, 0.6)。每行和为 1。测试 `test_area_constant_and_integrated_ink` 检查的就是这类性质。

**27.14** 1. scale = 10/7；rh = round(3 × 10/7) = round(4.29) = 4，rw = 10；top = (10 − 4)//2 = 3，下方 3 行。2. rh = round(2.86) = 3；top = (10 − 3)//2 = 3，下方 10 − 3 − 3 = 4 行，多出的一行在下。两种情况都是测试 `test_letterbox_padding_and_identity_metric` 的内容。

**27.15** 1. `min_pixels = 1024`：128×128 不变，4×4 = 16 个。`min_pixels = 65536`：面积 16384 不够，放大 √(65536/16384) = 2 倍到 256×256，8×8 = 64 个。2. 高 32 → 32，宽 298 → round(9.31) × 32 = 288；面积 9216 ≥ 1024，不再缩放；patch 网格 2×18，视觉 token 2×18/4 = 9。3. 公式区域 14×128 = 1792 像素，约 1.75 个 token 的面积。

**练习 27.1–27.4** 参考实现就在 `miniocr/data/image_tensors.py` 对应标记下；自己先写，再跑测试，最后对照。常见卡点：27.1 忘了 `.copy()` 导致 NumPy 只读警告；27.3 区间右端点写成 `pixels` 而不是 `pixels + 1`；27.4 用 `round` 算 `top` 导致奇数留白放到了上面。

**练习 27.6** 提示：边长越小，"+ 变 −"越早出现；DPI 减半时原图本身就更小，同样的边长缩小比例更小，保留率可能更高；但原图里的线条也可能更细。这只是猜测，以你自己的输出为准。

**27.16** `reshape` 不换轴，只是把内存每 H×W 个数切一段，通道和空间位置全混。改成 `torch.from_numpy(arr).permute(2, 0, 1).contiguous().float() / 255`。

**27.17** `mean` 形状 `(3,)` 按广播从最后一维对齐到 W。宽度 W = 3 的图不报错，结果是按**列**减均值，三个通道的统计量被用到了三列上；宽度 W = 1 的图也不报错，输出被广播成宽 3，形状悄悄变了。（如果三个通道的 mean、std 恰好相同，例如都是 0.5，按列减和按通道减结果完全一样，这个错误就藏起来了，所以单元测试要用不等的统计量。）不报错的错误最危险，因为它会悄悄进入实验。修正：`mean[:, None, None]`。

**27.18** 在 Qwen 的 processor 里，`shortest_edge` 和 `longest_edge` 是 `smart_resize` 的最小、最大**面积**（像素数），不是边长。设成 448 意味着面积上限只有 448 像素；而 `smart_resize` 缩小时每边至少保留一个 factor（本章是 32），所以图最后被缩到 32×32 = 1024 像素左右，例如 128×128 → 32×32（数学结论，按本地 transformers 5.19.0 源码复算）。要把面积限制在约 448×448 以内，应设 `longest_edge` 约为 448 × 448 = 200704，`shortest_edge` 保持一个较小的面积下限。注意这是**面积**上限，不保证长、宽都不超过 448：一张长条公式的宽可以远超 448。

**27.19** 画布是 0，也就是黑色。白底公式上下多了两大块黑区。把处理后的图存下来看一眼就知道。改成 `torch.ones`。

**27.20** 不抗锯齿的双线性只看两个邻居，缩小约 4.7 倍时细线是否被采到取决于它的位置（相位依赖）。修正：用 `antialias=True`；或用面积缩放；或者干脆少缩一些（换更大的目标尺寸、先裁掉留白）。

**27.21** 一是 processor 默认 `do_rescale=True`，会再乘 1/255，[−1, 1] 被压成约 [−0.004, 0.004]；二是 `do_normalize=True` 会再归一化一次。正确做法：要么传原始图片让 processor 全权处理，要么把 `do_rescale`、`do_normalize` 关掉并确认你的变换和它完全一致。

**27.22** 问题：这次对照同时改变了视觉 token 数（16 → 144）、公式区域像素数和缩小/放大比例，不能把收益只归因于分辨率；而且只有 200 张验证图，没有区间。改写示例："在原图验证集（n=200）上，Qwen3.5-0.8B 从 letterbox128 换到 letterbox384，CER 从 0.844 降到 0.292；这次改变同时增加了公式像素和视觉 token 数（16 → 144），两者的贡献尚未分开。"

**闭卷 6** 信息在缩小时已经丢失，放大补不回；processor 还会再缩放一次，实际输入和你以为的不同；处理后的图（如最近邻的锯齿）不像训练分布；看不清时模型会胡编，自回归生成把错误放大成长串输出。
