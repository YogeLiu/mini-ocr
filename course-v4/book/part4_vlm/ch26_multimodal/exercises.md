## 答案与提示

### 一、概念题

**1.** 参考定义：表示 = 每种模态变成什么样的向量；对齐 = 两种模态的哪些部分互相对应；推理 = 组合多步证据得出结论（OCR 里是公式的结构）；生成 = 产出另一种模态的内容，包括格式、长度、何时停；迁移 = 一处学到的本领用到别处；量化评估 = 怎样测量和理解模型的行为。例子自己举，能指出公式里的具体符号或具体输出字段即可。

**2.**
- (a) 主要是**生成**（输出格式不合要求），也可能是**量化评估**问题：`a / b` 和 `\frac{a}{b}` 意思相同、写法不同。实验：对比参考写法分布，或渲染后人工看。
- (b) **对齐**：每个字符都对，归属的位置错了。实验：遮挡上标区域，看输出哪一部分变化；第 31 章 saliency。
- (c) **生成**：没有及时停下。实验：看 `length_capped` 和输出是否循环；调大上限或换解码设置对照。
- (d) **推理**（语言先验盖过视觉证据）。实验：构造一批"故意写错"的公式图，统计模型"改对"的比例；第 33 章给错的图做视觉依赖对照。
- (e) **量化评估**：原始输出有逗号、抽取后丢了，是评测规则的问题，不是模型的问题。（如果原始输出本来就漏了逗号，那就是识别错误。）实验：对照 `raw` 和 `extracted` 两个字段，换抽取规则重算（练习 26.4），不用重跑模型。

**3.** processor 先把图缩放到面积预算内（65536 到 262144 像素），再按 16×16 切块、2×2 合并，token 数 = 缩放后面积 / 1024。公式内容不参与这个计算。所以一张很长、很密的小图，和一张只有 `Q^2=H` 的小图，都只拿到 64 个左右的 token；长公式里每个 token 要"管"更多的符号，细节更容易丢。

**4.** 它的输入和权重都是随机的，没有经过任何训练，热图的深浅只是随机数的样子。要证明依据，需要干预：遮住或扰动图上的某一块，看对应的输出 token 是否改变；梯度型的 saliency（第 31 章）只提供局部敏感性的线索，还需用遮挡实验核实（正文 §26.3.3）。

**5.** K 和 V 两个投影层。它们的输入宽度是 Dv，输出宽度是 Dt，同时完成了"连接器"的工作。

**6.** 不矛盾。OCR 需要**结构推理**：判断横线是分数线还是减号、上下标管到哪里、求和的上下限是哪些。它不能做**语义推理**：不能计算、不能纠正图上的内容。例如图上 `1+1=3` 必须原样输出。

**7.** 0/3（原输出）说明模型的输出格式和参考不一致（多了 `$$`）；3/3（抽取后规范化 EM）说明公式内容在空格、分组的层面上和参考一致；0/3（mathtext 像素）说明这个渲染器对带空格的写法排版不同，不说明内容错了。如果只报一个数，报 3/3 比较能反映内容，但必须同时写明抽取规则和规范化口径，并说明样本只有 3 张、是人工挑的教学图。

**8.** 至少有：公式难度不同（验证集 65% 是长公式，还有矩阵）；图像风格和尺寸不同（论文字体、原图高 19–107 像素）；参考写法不同（作者原样的空格命令、末尾标点等，评测规则会放大这些差别）；样本选取不同（3 张人工挑选 vs 文件顺序前 100 张）。这不是配对实验，不能得出因果结论。

### 二、手算题

**1.** 四舍五入：高 73 → 64，宽 97 → 96，面积 6144 < 65536，要放大。倍数 √(65536 / 7081) ≈ 3.042。新高 ⌈73 × 3.042 / 32⌉ × 32 = ⌈6.94⌉ × 32 = 224；新宽 ⌈97 × 3.042 / 32⌉ × 32 = ⌈9.22⌉ × 32 = 320。网格 224/16 × 320/16 = 14 × 20 = 280 个 patch，合并后 70 个 token，和实测一致（本项目观察：网格 `[1, 14, 20]`）。

**2.** (a) 每个 token 管 32×32 = 1024 像素。最少 65536 / 1024 = 64，最多 262144 / 1024 = 256（数学结论）。(b) 面积 1,200,000 超上限，缩小倍数 √(1,200,000 / 262144) ≈ 2.140。新高 ⌊600 / 2.140 / 32⌋ × 32 = 8 × 32 = 256，新宽 ⌊2000 / 2.140 / 32⌋ × 32 = 29 × 32 = 928。网格 16 × 58 = 928，合并后 232 个 token（数学结论，可用 `smart_resize(600, 2000)` 验证）。

**3.** (a) 77 + 36 = 113，和实测输入总 token 一致。(b) 113 + 37 = 150。(c) 154 + 36 = 190。注意视觉 token 翻倍不会让生成长度必然改变。

**4.** (a) vision `[8,64,32]` → 投影 `[8,64,48]`；text `[8,32,48]`；拼接 `[8,96,48]`。(b) 32 × 48 + 48 = 1584。(c) 所有 96 行都能看前 64 列：96 × 64 = 6144；文字区下三角：32 × 33 / 2 = 528；共 6672 个 True（总数 9216）。

**5.** (a) Q `[8,32,48]`；K、V 各 `[8,64,48]`；分数和权重 `[8,32,64]`；输出 `[8,32,48]`。(b) 48 × 48 + 32 × 48 + 32 × 48 = 2304 + 1536 + 1536 = 5376。(c) 8 × 32 × 64 = 16384。

**6.** V=78：拼接 114² = 12996；交叉 36² + 36 × 78 = 1296 + 2808 = 4104。V=256：拼接 292² = 85264；交叉 1296 + 9216 = 10512。视觉 token 越多，差距越大。

**7.** 分数全是 0，softmax 后每个权重 1/3。输出是平均值 [(1+3+5)/3, (0+4+2)/3] = [3, 2]。

**8.** 编辑距离每条 4，共 12；参考共 17 + 26 + 32 = 75 个字符；CER = 12 / 75 = 0.16，和 `controlled.json` 一致。

**1.** (a) 第 1 轴长度 6 和 5 不等，`torch.cat` 沿第 2 轴拼接时报尺寸不匹配。(b) V=T 时不报错，得到 `[B, 5, Dt+Dt]`，语义错误：把视觉和文字"缝"在了同一个位置上。`test_prefix_preserves_text_and_projects_width` 检查输出是 `[2,11,4]` 并且后 5 个位置等于原文字，会失败。

**3.** 形状不变，不报错。出问题的是权重的归一化方向：每个视觉位置的权重在文字轴上和为 1，而不是每个文字位置在视觉轴上和为 1。检查 `weights.sum(-1)` 是否全为 1 就能一眼看出；测试里有这条断言，也会和 `scaled_dot_product_attention` 对拍失败。

**4.** `render` 返回 255 表示墨迹。不反转时，墨迹变成白色、背景变成黑色；`ImageOps.expand` 加的 16 像素边框仍是白色。结果是"白框里一块黑底白字"。

只看前两个条件，**抓不住**它：`(image[:16] == 255).all()` 查的是上方白边，仍然成立；`image.min() < 50` 只要求有深色像素，黑底也满足。本项目在本地 CPU 上试过：图 1 不反转时两个条件都通过，边框以内纯白像素的比例从约 0.85 降到约 0.04（本项目观察，`render(..., dpi=160)`）。完整测试会在测试文件第 81 行失败：`assert (content>240).mean()>.5`（本项目观察，变异实验）。这一行补上了盲区：`content` 是去掉 16 像素白边后的内容，要求其中白色像素占多数。这个阈值只针对白底稀疏的公式教学图，内容密集或背景不同的图不能照搬。教训：只有前两个条件时，测试的名字叫"极性"，也不等于它真的测了极性。

**5.** `controlled.jsonl` 里图 1 的 `score.em_norm` 是 true，`score.ed_char` 是 0，抽取后内容在规范化层面和参考一致。0.951 反映的是 mathtext 对 `x ^ { 2 }` 和 `x^2` 排版不同（本地渲染尺寸 85×18 对 71×21），是渲染器的怪癖。真正的 TeX 在数学模式忽略空格，排出来一样（这一点本章没有用 TeX 引擎验证）。

**6.** (a) 97×73 得 70 个；95×76：四舍五入为 64×96，面积 6144，放大倍数 √(65536 / 7220) ≈ 3.013，新高 ⌈76 × 3.013 / 32⌉ × 32 = 8 × 32 = 256，新宽 ⌈95 × 3.013 / 32⌉ × 32 = 9 × 32 = 288，网格 16 × 18 = 288，合并后 72 个（数学结论）。(b) 两台机器的字体环境不同，mathtext 渲染出的图尺寸不同。(c) 先核对图片的 SHA 和尺寸（`rendered.json` 里都有），确认输入是同一张图，再比较输出。
