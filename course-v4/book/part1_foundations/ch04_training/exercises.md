## 答案与提示

### 概念题要点

- **C1.** 训练模式、取数据、前向算 loss、清零、反向、裁剪、设学习率、更新、记录（正文 4.1.2 节）。最容易忘的是清零和 train/eval 切换：不清零时 SGD 先降后升、失控；忘了 eval 时验证结果偏低且每次不同（4.12.2、4.12.3 节）。
- **C2.** 每个方向每步乘以 1 − ηλ_i，要收敛必须 |1 − ηλ_i| < 1，最陡方向给出 η < 2/λ_max。最平缓方向的因子是 1 − ηλ_min ≥ 1 − 2λ_min/λ_max，条件数 λ_max/λ_min 越大，这个因子越接近 1，越慢。
- **C3.** 方向一致的分量累积速度（极限放大 1/(1 − μ) 倍），来回振荡的分量互相抵消。不成立之处：μ 不是物理量，每步只"踢"一次。μ 太大时惯性太大，在谷里来回荡停不下来（4.3.4 节，μ = 0.99 用了 672 步）。
- **C4.** m 估计梯度的均值，v 估计梯度平方的均值。从 0 开始使 E[m_t] = (1 − β₁ᵗ)E[g]，偏小，要除以 1 − β₁ᵗ。t 大时 β₁ᵗ → 0，修正不再起作用；v 的修正持续约几千步。
- **C5.** 第 1 步 m̂ = g、v̂ = g²，m̂/√v̂ = sign(g)（|g| 远大于 ε 时）。于是每个有梯度的参数同时移动 η，方向却只来自一批数据的估计。预热让最初这些平均步幅最大、最整齐的步子乘上小学习率（4.6.4 节）。注意这不是"每个参数的步长都在第 1 步最大"：正文第 7 部分第 100 步的最大 |Δθ|/η 是 1.771。
- **C6.** 陡缓方向沿坐标轴、各坐标梯度尺度差别大时优势最大。主轴斜着（比如旋转 45°）时，每个坐标都混着陡缓成分，优势减弱：正文里（起点跟着一起转）从 71 步变成 98 步，而梯度下降和动量的步数一步不差。
- **C7.** SGD：θ − η(g + λθ) = (1 − ηλ)θ − ηg。Adam：λθ 进入 m、v，被除以 √v̂，梯度大的参数衰减弱。梯度恒为 0 的参数：Adam + L2 的衰减与 λ 无关，开头每步约减少 η，之后 θ 变小、步子也越来越小（4.5.4 节）；AdamW 每步乘以 1 − ηλ。
- **C8.** 预热：避免初期大而不可靠的步子破坏模型，让你能用更大的峰值学习率。余弦衰减：后期减小学习率以减小噪声。Post-LN 成功的两种做法：加 100 步预热；或者不预热但把学习率降到 3 × 10⁻³。（Pre-LN 是改结构，也成功。）
- **C9.** 全局一起缩才能保持整体方向不变。每步都在裁剪说明阈值太小，或者学习率、初始化有问题，裁剪在掩盖问题。
- **C10.** Var(y) = n σ² E[x²]；ReLU 使 E[x²] 只有输入方差的一半，所以 σ² 取 2/n 补回来。不能简单说"Adam 步长与梯度大小无关"：|g| 远小于 ε 时 Adam 的步长约 η·g/ε，也几乎不动。σ = 0.01 时大部分权重梯度在 10⁻¹⁵ 到 10⁻¹¹，只有 0.42% 的参数（主要是靠近输出的偏置）|g| 超过 ε，这些参数按 η 的步幅更新；正文给出的解释（待验证）是它们变大后，前面各层的梯度跟着变大，网络从输出端逐层"解冻"。SGD 的步长正比于梯度，这些参数也只挪 η·|g|，解冻不起来（4.8.4 节）。
- **C11.** 只把所有子模块的 `training` 设为 False，影响 Dropout、BatchNorm 等。不冻结参数，不关梯度。`torch.no_grad()` 关梯度记录、省内存，不改变 Dropout 行为。评测时两者都要。
- **C12.** 模型、优化器状态、步数、随机数状态（含取数据的生成器）。换设备、GPU 非确定性算子、换软件版本、可能还有换线程数或批量大小时做不到（4.10.4 节）。
- **C13.** 能查出：loss 写错、梯度断了、优化器没在更新、输出维度错。查不出：标签错位、数据泄漏，因为网络能背下任何标签。
- **C14.** 排序时错开一位只改变类别交界处的 3 个标签；打乱后每个标签都换成了一个无关样本的标签，等于随机标签。

### 手算题答案

- **H1.** 第 1 步 g = (2, 50)，θ = (2 − 0.02, 0.5 − 0.5) = (1.98, 0)。第 2 步 g = (1.98, 0)，θ = (1.9602, 0)。y 的因子 1 − 0.01 × 100 = 0，一步归零。
- **H2.** 第 1 步 v = (2, 50)，θ = (1.98, 0)。第 2 步 g = (1.98, 0)，v = (1 + 1.98, 25) = (2.98, 25)，θ = (1.9502, −0.25)。第 3 步 g = (1.9502, −25)，v = (1.49 + 1.9502, 12.5 − 25) = (3.4402, −12.5)，θ = (1.915798, −0.125)。注意第 2 步 y 的梯度是 0，惯性仍把它推到了 −0.25。
- **H3.** 第 1 步 m̂ = g，v̂ = g²，步长 = 0.1 × sign(g) = (0.1, −0.1)，所以 θ 变化 (−0.1, +0.1)。第 2 步 m = 0.19g，m̂ = 0.19g/0.19 = g；v = 0.001999g²，v̂ = g²；步长仍是 (0.1, −0.1)。梯度恒定时 m̂ = g、v̂ = g² 对所有 t 成立，每步步长都是 η × sign(g)。
- **H4.** (a) 由 θ_t = θ_{t−1} − ηv_t 得 v_t = (θ_{t−1} − θ_t)/η。代入 θ_{t+1} = θ_t − η(μv_t + λθ_t) = θ_t − μ(θ_{t−1} − θ_t) − ηλθ_t，整理即得。(b) 记 a = 1 + μ − ηλ，条件 1 − a + μ > 0 即 ηλ > 0；1 + a + μ > 0 即 ηλ < 2(1 + μ)；|μ| < 1 已满足。(c) η < 2 × 1.9/100 = 0.038，与表中 μ = 0.9 的稳定上限 0.0380 一致。
- **H5.** 第 0 步 0.01 × 1/20 = 0.0005；第 19 步 0.01；第 110 步 p = 90/180 = 0.5，0.005；第 155 步 p = 0.75，0.01 × ½(1 + cos(3π/4)) = 0.01 × 0.1464 = 0.001464。
- **H6.** √(1 + 4 + 4 + 16) = 5。max_norm = 2.5 时因子 0.5：[0.5, 1, 1] 和 [2]（实际乘的是 2.5/(5 + 10⁻⁶)，略小一点点）。max_norm = 10 时不变。
- **H7.** (1 − 10⁻⁴)¹⁰⁰⁰⁰ ≈ e^{−1} ≈ 0.368。Adam + L2 第 1 步 m̂/√v̂ = sign(θ)，走 η = 10⁻³。但"1000 步归零"不对：梯度只剩 λθ，θ 变小时梯度跟着变小，而 v 还记着从前较大的梯度，m̂/√v̂ 降到 1 以下，步子越走越小。实算（本项目观察，第 6 部分）：第 1000 步 θ 还有 0.2577，这一步只走了 0.467η；第一次 |θ| < 10⁻³ 是第 2722 步。
- **H8.** Xavier σ = √(1/512) ≈ 0.0442；Kaiming σ = √(2/512) = 0.0625。σ = 0.01 时 Var = 512 × 10⁻⁴ = 0.0512，标准差约 0.226。10 层后约 0.226¹⁰ ≈ 3.5 × 10⁻⁷。
- **H9.** 以 0.2 的概率输出 0，以 0.8 的概率输出 5/0.8 = 6.25。期望 0.8 × 6.25 = 5。推理模式输出 5。
- **H10.** 输入是概率，各在 [0, 1] 内。正确类 logit 为 a、其余为 b 时 loss = −ln(e^a/(e^a + (K − 1)e^b))，a 越大、b 越小越好，最优 a = 1、b = 0（这需要正确类概率为 1，其余为 0），得 −ln(e/(e + K − 1)) = ln(e + K − 1) − 1。K = 3：ln(4.7183) − 1 ≈ 0.5514；K = 10：ln(11.7183) − 1 ≈ 1.4612。

- **4.2** 参考正文 4.5.5 节。L2 用 `g = g + λp`，不要用 `+=` 改动 `p.grad`。
- **4.3** 参考正文 4.6.3 节。
- **4.4** 参考正文 4.7.2 节。
- **4.5** `torch.get_rng_state()`、`g.get_state()` 返回张量，记得 `clone()`。
- **4.6** `os.replace(tmp, path)`；`torch.load(..., weights_only=False)` 只用于自己保存的文件。
- **4.7** `[p for n, p in model.named_parameters() if p.dim() >= 2]`。对比时先 `copy.deepcopy` 模型，给两份参数赋上同样的 `.grad`，各自 `step()` 一次再比较。
- **4.8** `LambdaLR(opt, lambda s: warmup_cosine(s, T, W, 1.0, min_lr / base_lr))`。构造 LambdaLR 时它会先把学习率设成第 0 步的值；之后每次 `opt.step()` 后调用 `sched.step()`，下一步就用下一个值。两种写法实际用到的学习率序列相同。

### 调试题答案

- **D1.** 学习率在 `step()` 之后才设，每一步用的是上一步的学习率，第 0 步用构造时的默认值。不报错。把设学习率移到 `opt.step()` 之前。检查：记录每步 `step()` 时的 `opt.lr`，和 `warmup_cosine(step, …)` 比较。
- **D2.** 裁剪放在 `step()` 之后，裁剪的是已经用过的梯度，不起作用；下一步又会被 `zero_grad` 清掉。不报错。把裁剪移到 `backward()` 和 `step()` 之间。检查：在 `step()` 前打印全局范数，应该 ≤ 1。
- **D3.** `torch.optim.Adam` 的 `weight_decay` 是 L2 形式，会被 √v̂ 扭曲（4.5.3 节）。不报错，正则效果和预期不同。改用 `torch.optim.AdamW`。检查：对一个梯度恒为 0 的参数跑几步，AdamW 下它应该每步乘以 1 − ηλ。
- **D4.** 差一：检查点存的是"已完成的步数"，续训应从 `range(step, total)` 开始，这里跳过了一步。不报错，少训一步，学习率调度也错开一步。检查：续训对拍，比较最终参数是否逐位一致。
- **D5.** 评测时切成了 `eval()`，之后没有切回 `train()`，从第 1 次评测以后的训练全都没有 Dropout。不报错，正则效果减弱。在每步训练开头调用 `model.train()`，或评测后立刻切回。检查：在训练步里断言 `model.training`。
- **D6.** 只存了模型参数，没有优化器状态、步数和随机数状态。续训后 Adam 从第 1 步重新开始（步子突然变大），调度从头预热，数据顺序也变了。loss 曲线会在续训处跳一下。改用 `save_checkpoint`。检查：续训对拍。
