## 2. 实验一：亲手做一次中断续训

**问题：** 自己写一个训练脚本，在第 300 步"拔电源"，然后在一个**新的 Python 进程**里续训，能逐位一致吗？

**预测：** 写下你认为必须保存哪几样东西，以及你预计会在哪一步出错。

**运行：**

1. 复制 `tour.py` 里的 `train_loop`，改成每 100 步调用一次 `save_checkpoint(path, model, opt, step + 1, generators={"data": g})`。
2. 跑 `python my_train.py --steps 500`，同时在另一个终端里运行到第 300 步左右时按 Ctrl+C。
3. 加一个 `--resume` 选项：先 `load_checkpoint`，再从返回的步数开始循环。续训到 500 步，保存最终参数。
4. 再跑一次不中断的 500 步，用 `torch.equal` 比较两份最终参数。

**观察：** 逐位一致吗？如果不一致，从下面开始排查：学习率是不是从对的步数接着算的；`range` 的起点差不差一；有没有在加载之后又调用了 `torch.manual_seed`；模型里有没有 Dropout。

**记录：** 你的检查点里存了什么；第一次尝试的结果；最终怎样修好的。

## 3. 实验二：预热在 MLP 上有没有用

**预测：** 写下你的预测，以及你认为学习率多大时差别最明显。

**运行：** 用 `tour.py` 里的 `mlp(hidden=128, depth=8, seed=s)` 和 `train_loop(model, steps=600, lr=lr, warmup=w, wd=0.0, clip=0, seed=s, opt=Adam(model.parameters(), lr=lr))`，对 lr ∈ {1e-2, 3e-2, 1e-1}、w ∈ {0, 60}、种子 0–4 各跑一次。每次约 1 秒。

## 4. 实验三：在山谷里调参

**问题：** 4.3.4 节说对二次函数，最优动量系数是 ((√κ − 1)/(√κ + 1))²。换一个条件数，这个公式还准吗？

**预测：** 把山谷改成 f = ½(x² + 400y²)，κ = 400。算出理论最优 μ，并预测梯度下降和最优动量各要多少步。

**运行：** 把 `tour.py` 里的 `A_DIAG` 改成 `(1.0, 400.0)`，学习率网格相应缩小 4 倍（`LR_GRID`、`WIDE_GRID` 都除以 4），运行第 2、3 部分。

第 3 部分最后一行"理论最优（Polyak）"会按 `A_DIAG` 自动算出 μ* = ((√κ − 1)/(√κ + 1))² 和 η* = (2/(√λ_max + √λ_min))²（κ = 400 时是 (19/21)² ≈ 0.8186 和 (2/21)² ≈ 0.00907，数学结论），并给出两个步数：用 η* 跑的步数，以及 μ* 配网格里最好的学习率的步数。

**观察：** 固定的 μ 表 {0, 0.5, 0.67, 0.9, 0.99} 里最快的是哪一个；理论最优那一行要多少步；梯度下降最快要多少步。

**记录：** 区分两件事："给定网格里最快的 μ"和"理论最优 μ*"。理论值保证的是渐近收敛率最快，到达 ‖θ‖ < 10⁻³ 要几步还和起点有关，两者不一定完全一致。κ = 100 和 κ = 400 时，梯度下降和 μ* 的步数之比各是多少。理论上梯度下降的步数大约随 κ 增长，最优动量随 √κ 增长，你的数据符合吗？

## 5. 故障演练：一个"还行"的训练

**场景：** 同学给你一份训练脚本，用 AdamW，验证集正确率 99%，看起来没有问题。但你注意到训练 loss 在第 100 到 300 步之间停在 0.19 附近不动，然后又突然下降。

**请按下面的步骤排查**，每一步写下你看到了什么：

1. 用 SGD 重新训练，**同时去掉预热和裁剪**：`train_loop(m, lr=0.05, warmup=None, clip=0, zero_grad=False, opt=SGD(m.parameters(), lr=0.05))`。观察 loss 曲线。（正文第 13 部分：这样设置时第 600 步 loss 4.041。）注意三件事一起变了：优化器、预热、裁剪。`train_loop` 每一步都会用自己的 `lr` 参数覆盖优化器的学习率，所以 `lr=0.05` 必须传给 `train_loop`；只换优化器、循环保持默认（lr = 10⁻²、预热 50 步、裁剪 1.0）的话，第 600 步 loss 是 0.671，看不出异常（本项目观察，第 13 部分）。
2. 给 `train_loop` 传 `norms=[]`，记录每一步裁剪前的梯度范数。在不裁剪的 SGD 里，范数是不是随步数一直变大？再在原来的 AdamW 设置（裁剪 1.0）下记录一次：范数为什么不会无限变大，被裁剪的步数却多得反常？（正文 4.12.2 节有数字。）
3. 在循环里找 `zero_grad`。

**要总结的教训：** Adam 和梯度裁剪会掩盖"梯度一直累加"这类错误，最终结果还行，代码却是错的。用 SGD 做一次健全性检查，常常能让隐藏的 bug 现形。
