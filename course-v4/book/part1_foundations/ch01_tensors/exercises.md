## 答案与提示

### 概念题要点

- **C1.** shape 是每一维的长度，dtype 是每个元素的类型和字节数，device 是数据所在的设备。相加时：形状要能广播；dtype 不同时 PyTorch 会按规则提升（比如 int64 + float32 → float32）；device 必须相同，否则报错。
- **C2.** (N, 1, D) 和 (1, M, D) 维数相同，不用补 1。逐维：N 对 1 → N，1 对 M → M，D 对 D → D。结果 (N, M, D)，[i, j, :] 是 A[i] − B[j]：第 0 维是 A 的点，第 1 维是 B 的点，第 2 维是坐标。
- **C3.** 没有。被拉长那一维的 stride 被设成 0，沿它走多少步都读同一个数（正文 1.2.4 节，`a.expand(3, 4).stride()` 是 (1, 0)）。只有运算结果是真正分配内存的张量。
- **C4.** 广播只比较各维的长度，不知道每一维代表什么。例：每行除以行和写成 `m / m.sum(1)`，方阵时 (N,) 对上了列，不报错但结果错；(N,) 的预测和 (N, 1) 的标签相减得到 (N, N)。
- **C5.** 广播写法简单、精确，但中间张量 (N, M, D) 很大；展开写法不产生 (N, M, D)，额外内存是 N·D + M·D + N·M 量级，用矩阵乘法所以快，但两个大数相减有舍入误差。数据离原点远（||a||² 很大）、用 float32 时，可能出现负数（正文 1.10 节：对角线最小 −0.50）。
- **C6.** `*` 逐元素，两个 (B, T, D) 相乘得到 (B, T, D)。`@` 对最后两维做矩阵乘法，(T, D) @ (T, D) 要求 D = T，否则报错；想要每对 token 的点积应写 `x @ y.transpose(-2, -1)`，得到 (B, T, T)。
- **C7.** 按"最后一维变得最快"的顺序读，恰好是内存从头到尾的顺序，就叫连续。转置后读的顺序在内存里间隔忽大忽小，长度 12 的一维形状没法用一个固定的 stride 表示，所以 view 报错（view 能不能成功看的是目标形状和 stride 是否兼容，不连续的张量有时也能 view，比如 1.6.2 节的 `z[:, :, 0].view(-1)`）；reshape 在这种情况下复制一份，因此不和 x 共用存储。
- **C8.** 一般优先 reshape，目标形状的元素个数相同时，它能在需要时复制以适应输入布局。需要"共用存储、不复制"的保证时用 view，报错正好提醒你这里会复制。
- **C9.** transpose 之后形状是 (B, n·d, T)，最后一维是 token。`reshape(B, n, T, d)` 按读取顺序重新切，切口横跨了 n·d 和 T 两维，一个"token 向量"里混进了不同 token 的数。错的是这个 reshape，不是 transpose 本身：`h.transpose(1, 2).view(B, n, d, T).transpose(2, 3)` 只切 n·d 这一维，结果是对的（正文 1.6.4 节）。先 view 再 transpose 推荐，是因为在原位置拆时 n·d 就是最后一维，不用操心切口。einops 的 `b t (n d) -> b n t d` 明确写出拆的是哪一维，拆和挪在一个模式里完成。
- **C10.** B 是第几条序列，T 是第几个位置，V 是词表里的哪个 token。softmax 沿 V（`-1`）。argmax(-1) 的形状是 (B, T)。
- **C11.** permute(2, 0, 1) 得到 (C, H, W)，再加批量维 [None]。uint8 只有 0–255，运算中容易溢出，也不能求梯度；网络也更喜欢小范围的浮点输入，所以转成 float32 并缩放到 [0, 1]。
- **C12.** 张量是规整的格子，每一维长度固定。办法：补白到这一批里最大的尺寸；把所有图缩放到固定尺寸（会变形或失真）；按长宽比分组，让同一批的图大小接近；固定高度、宽度补白。第 27、31 章会比较这些方法。

### 手算题答案

### 编程题提示

- **1.1** 先把短的形状左边补 1（`(1,) * k + a`），再用 `zip` 逐维比较。0 维形状 `()` 补完就是全 1。
- **1.2** 正文 1.3.3 节。
- **1.3** 正文 1.3.4 节。别忘了 `[:, None]` 和 `[None, :]`，以及最后的 `clamp_min(0)`。`A ** 2` 是 (N, D)、`B ** 2` 是 (M, D)，这不违反要求；要避免的只是 (N, M, D)。
- **1.4** 正文 1.8.1 节。`torch.arange` 要放在和 idx 相同的设备上。越界检查要先判断 `idx.numel() > 0`，空张量没有 min。
- **1.5** 正文 1.9.3 节。`.float()` 之后记得 `.contiguous()`；`batch_to_image` 里先 `clamp(0, 1)`，乘 255 后 `round()` 再转 uint8，否则 0.999 × 255 会被截断成 254。
- **1.6** `split_heads`：`x.view(B, T, n, d).transpose(1, 2)`；`merge_heads`：`x.transpose(1, 2).reshape(B, T, n * d)`。对 `split_heads` 的输出再 transpose，正好恢复原来的连续布局，这时 view 也能成功；但对一个连续的 (B, n, T, d) 张量 transpose 后，(n, d) 两维在内存里不相邻，合并成 n·d 和 stride 不兼容，view 报错。reshape 两种输入都能处理，所以合并用 reshape（第 8 章的常见错误表里也有这一条）。
- **1.7** `A / A.norm(dim=1, keepdim=True).clamp_min(1e-8)`，B 同理，然后 `An @ Bn.T`。分母要和 `F.cosine_similarity` 一样用 eps = 1e-8 兜底：直接除以范数，零向量会得到 NaN；`[1e-10, 0]` 对 `[1, 0]` 也会算出 1，而对拍函数给出约 0.01。对拍代码里 (N, 1, D) 和 (1, M, D) 广播成 (N, M, D)，cosine_similarity 沿 `dim=-1` 归约，得到 (N, M)。
- **1.8** 用正文 1.9.2 节的办法：算每一行深色像素的比例，找比例最大的行。具体行号取决于你的 matplotlib 版本，自己跑出来填。

### 调试题答案

- **D1.** pred (B, 1) 和 y (B,) 广播成 (B, B)，loss 变成所有样本两两之差的均值。不报错，模型照样训练但目标错了。改成 `pred.squeeze(1) - y` 或 `pred - y[:, None]`。检查：`assert pred.shape == y.shape`。
- **D2.** view 不改变元素的读取顺序，只是把 R, G, B, R, G, B… 这条直线重新切成 3 × H × W，每个"通道"里混着三种颜色。不报错，图片变成花纹。改成 `img.permute(2, 0, 1)[None]`。检查：取一个像素，`x[0, c, i, j] == img[i, j, c] / 255`（练习 1.5 的测试就是这样做的）。
- **D3.** `counts.sum(1)` 形状 (N,)，广播时对上了列，第 j 列除以第 j 行的和。方阵不报错。改成 `counts.sum(1, keepdim=True)`。检查：`probs.sum(1)` 全为 1。
- **D4.** softmax 沿了 T 这一维，变成"每个 token 在各位置上的分布"。不报错。改成 `softmax(-1)`。检查：`probs.sum(-1)` 全为 1。
- **D5.** uint8 加法溢出，亮度超过 195 的像素加 60 后超过 255，绕回成很暗的值，白底变黑。改成 `(img.float() + 60).clamp(0, 255).to(torch.uint8)`。检查：处理后白色像素仍然是 255。
- **D6.** `squeeze()` 不写维度，会去掉所有长度为 1 的维。B = 1 时批量维也被去掉，x 变成 (H, W)，`x[:, None]` 得到 (H, 1, W)。Conv2d 把三维输入当成没有批量维的 (C, H, W)，于是 H 被当成**通道数**：卷积层的输入通道数不等于 H 时报错，碰巧相等时不报错，但输出也少了批量维。改成 `squeeze(1)`。检查：用 B = 1 的输入跑一次，断言输入是四维、输出的第 0 维等于 B。
