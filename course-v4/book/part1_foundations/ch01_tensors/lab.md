## 2. 实验一：先算形状，再运行

**问题：** 你能不能在运行之前，准确说出每个运算的结果形状？

**预测：** 在记录表里写下下面每一行的结果形状；会报错的写"报错"，并说出是哪一维对不上。

下面这块有几行故意会报错，整块运行会停在第一个报错处。写完预测后，在交互环境里逐行运行。

```python
import torch
x = torch.zeros(4, 1, 3)
y = torch.zeros(5, 1)
z = torch.zeros(2, 3, 4)
x + y                              # ?
x + torch.zeros(3)                 # ?
x + torch.zeros(4)                 # ?
z @ z.transpose(-2, -1)            # ?
z @ z                              # ?
z.sum(1).shape, z.sum(1, keepdim=True).shape    # ?
z.permute(2, 0, 1).reshape(4, -1).shape         # ?
z[:, None, :, None].shape                        # ?
```

**运行：** 把这段代码粘进 Python，逐行打印 `.shape`。

**观察：** 哪一行和你的预测不同？用正文 1.2.3 节的三步规则重新推一遍。

## 3. 实验二：两两距离的内存和速度

**问题：** 正文 1.3.4 节说，广播写法的中间张量随 N·M·D 增长。实际的用时也这样增长吗？

**预测：** 固定 D = 64，N = M 依次取 250、500、1000、2000。N 每翻一倍，两种写法的用时各变成几倍？广播写法在 N = 2000 时中间张量多大？（用 N·M·D·4 字节算。）

**运行：** 在 `tour.py` 的 `part3_pairwise` 里，把计时那一段的 `torch.randn(1000, 64)` 改成循环：

```python
for N in (250, 500, 1000, 2000):
    X, Y = torch.randn(N, 64), torch.randn(N, 64)
    # 下面照原来的写法，对两种函数各计时 10 次
```

然后运行 `python -m book.part1_foundations.ch01_tensors.tour 3`。每个 N 跑 3 次，记录中位数。

**观察：** 两种写法的用时、两者的倍数。N 翻倍时，广播写法的用时是不是接近 4 倍？展开写法呢？

**思考：** 把 D 从 64 改成 512，N = M = 1000，哪种写法的用时变化更大？为什么？（提示：广播写法的中间张量和 D 成正比；展开写法里 `A @ B.T` 和两项平方求和的计算量都和 D 有关，但不产生 (N, M, D) 的中间张量。）

## 4. 实验三（可选）：跨设备对照

**这个实验需要 Mac（MPS）或 NVIDIA GPU（CUDA）。没有的话跳过，只看作者的 CPU 输出。**

**问题：** 同样的计算换到 GPU 上，结果还和 CPU 完全一样吗？快多少？

**预测：** 第 10 部分在 2000 × 3000 个点对上算距离。在 GPU 上，两种写法和 float64 答案的最大差会比 CPU 上的 4.4e-05、5.2e-05 大还是小？用时各快几倍？

**运行：**

```bash
python -m book.part1_foundations.ch01_tensors.tour 1 10 --device mps     # Mac
python -m book.part1_foundations.ch01_tensors.tour 1 10 --device cuda    # NVIDIA GPU
```

**观察：**

- 第 1 部分：`z.device` 显示的设备；`z.cpu()` 搬回来是否和 x 相等。
- 第 10 部分：用时、最大差、"结果在"哪个设备。

**思考：**

- 结果不完全相同是正常的：不同设备上的矩阵乘法用不同的算法和求和顺序，舍入误差也不同。CUDA 上 float32 矩阵乘法默认可能用 TF32（一种更低精度的格式），误差会更大。什么时候这种差异会成为问题？
- 脚本计时前调用了 `synchronize(DEVICE)`。GPU 是异步执行的：Python 发出命令后立刻返回，计算还在排队。去掉 synchronize，测到的用时会怎样？自己试一试。

## 5. 实验四：渲染你自己的公式

**问题：** 不同公式渲染出来的张量形状有什么规律？结构（分数线、根号、上下标）在张量里是什么样子？

**预测：** `\frac{a}{b}` 的形状是 (48, 29, 3)（本项目观察，tour 第 8 部分）。猜一猜 `\frac{a+b}{c}`、`x^{2}`、`\sqrt{x}`、`\sum_{i=1}^{n} i` 的 H 和 W 各比它大还是小。

**运行：**

```python
from book.part1_foundations.ch01_tensors.tour import render_formula
for tex in (r"\frac{a}{b}", r"\frac{a+b}{c}", r"x^{2}", r"\sqrt{x}", r"\sum_{i=1}^{n} i"):
    img = render_formula(tex)
    g = img.float().mean(-1)                   # (H, W) 灰度
    print(tex, tuple(img.shape))
    for row in g:
        print("".join("#" if v < 128 else "." for v in row.tolist()))
```

**观察：** 每个公式的 (H, W, C)；字符画里分数线、根号、上下标的样子。把 `fontsize` 从 24 改成 48，形状怎样变？

**思考：** 同样是"x 的平方"，`x^2` 和 `x^{2}` 渲染出来的张量一样吗？（第 0 章讲过它们的 LaTeX 字符串不同、数学含义相同。）这对"用渲染后图片是否一致"做评测指标意味着什么？

## 6. 故障演练：静默的广播

**场景：** 你写了一个小回归模型，输出 `pred` 形状 (B, 1)，标签 `y` 形状 (B,)。loss 一直在下降，但降到一个不小的值就不动了，预测值都挤在标签均值附近。

**请按下面的步骤排查**，每一步写下你看到了什么：

1. 在算 loss 的地方打印 `pred.shape`、`y.shape`、`(pred - y).shape`。（tour 第 9 部分 (a)：(4,) 和 (4, 1) 相减得到 (4, 4)。）
2. 手算一个小例子：pred = [[1], [2]]，y = [1, 2]。正确的均方误差是多少？写错的是多少？
3. 想一想：最小化"所有样本两两之差"的均值，最优的预测是什么？为什么预测会挤在均值附近？
4. 加上 `assert pred.shape == y.shape`，修好代码。

**要总结的教训：** 形状错误最危险的不是报错，而是不报错。凡是两个张量逐元素运算、结果又要被 `mean()` 或 `sum()` 压成一个数的地方，都值得加一个形状断言。
