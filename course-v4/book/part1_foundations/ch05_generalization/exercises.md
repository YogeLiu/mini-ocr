## 答案与提示

### 概念题要点

- **C1.** 训练集算梯度、更新参数；验证集做决定（调参、选模型、错例分析）；测试集只报告。验证集被用来挑选过，被挑中的设置一部分是因为和这份验证集"合得来"，所以分数偏乐观（5.1.2、5.8.2 节）。
- **C2.** (a) 允许。(b) 选型冻结后，预先登记的候选各评一次，只报告数字和置信区间、不据此改设置，才允许。(c) 不允许：看测试集错例并据此决定改进方向，就是在用测试集做决定。(d) 如果只是重读已记录的数字且不据此改设置，允许；如果是重新评测，需遵守选型冻结后预先登记的候选各评一次的规则。开发期不看测试集错例，最终报告定稿后才可解封（5.1.3 节）。(e) 不允许：这既是依据测试集结果做的决定，又把测试集变成了验证集；正确做法是写明，并补一份新的留出测试集。
- **C3.** 完全重复（同一张图存了两份）→ 按内容哈希去重；近重复（同一公式截了两次）→ 按来源或规范化后的 LaTeX 分组，事后做近重复检测；同一来源（同一篇论文）→ 按来源分组；预处理泄漏（用全部数据算均值）→ 只用训练集估计任何统计量；增广泄漏 → 先划分再增广。答出其中三种即可。
- **C4.** 不说明。随机划分的训练集覆盖了更多来源，所以模型略好；但它的验证分数虚高了约 14 个百分点，你对模型的**估计**是错的，用它比较方案时还可能奖励"记来源"的配置（5.3.4、5.3.6 节）。泄漏的危害是让测量失真，而不是让模型变差。
- **C5.** 组的大小不同时，样本数的比例会偏离 `fractions`。组大小悬殊、组数少时最严重（比如一个大来源占了一半数据）。缓解：按样本数贪心地分配组；把特别大的组拆分前先确认不会泄漏；或者报告实际的样本数比例。
- **C6.** 按结构模板分组（把具体字母替换成占位符后的 LaTeX）。按来源分组时，同一种结构（比如 `\frac{□}{□}`）在很多来源里都有，训练集和测试集里会有大量相同结构，测不出结构泛化（5.4.6 节）。
- **C7.** 它只比较每个格子和这张图自己的平均值的大小关系，整体乘一个正数再加一个常数，大小关系不变。弱点：8×8 太粗，丢掉了很多细节，区分不了"同一个符号的不同来源"，在大池子里误报很多。
- **C8.** 多重比较：每张验证图要和 7680 张训练图比，每次都有一点误判的机会，累积起来就很可能至少碰上一次（类似生日问题）。校准：要在"池子"条件下测误报率。本章的合成数据里来源标记就是真相，可以在分组划分上跑一遍，检出率就是误报率；真实数据里来源不相交不代表没有跨来源的重复，要用人工核验过的非重复样本来估计误报率，再抽查被标出的样本。
- **C9.** 需要。近重复检测会漏掉组内抖动大的样本（本章像素距离只抓到 73.6% 的同源泄漏），漏掉的照样让分数虚高。反过来，分组划分也需要近重复检测来体检：组定义得不够粗时（例如同一公式出现在两个来源），只有检测能发现。
- **C10.** 欠拟合：训练 loss 高、和验证 loss 差距小。处理：训练更久或调大学习率；换更大更合适的模型。过拟合：训练 loss 很低、差距大、验证 loss 上升。处理：加数据、加增广、加正则（权重衰减、Dropout）、早停、减小模型（5.6 节）。
- **C11.** 模型对大多数样本越来越对（准确率涨），同时对少数答错的样本越来越自信（交叉熵涨）。对分类任务，早停应该看你最终关心的指标，通常是验证准确率；但"越来越自信地答错"说明模型输出的概率不可信（5.6.4 节）。
- **C12.** 固定种子让实验可以复现，解决的是"别人（或三个月后的自己）能否得到同样的数字"。它没有解决"这个数字有多少运气成分"：换一个种子，结果可能差得和你要测的效应一样大（5.7.3 节，种子 0 和种子 6 给出相反结论）。要用多个种子估计波动。
- **C13.** 从多个候选里按某份数据挑出最好的，挑出来的那个在这份数据上的分数会偏乐观，因为它的"好"里有一部分是运气。选择集越小、候选越多，虚高越大（5.8.2 节：n = 100 时 +0.036，n = 960 时 +0.001）。所以测试集只能用来报告，不能用来挑。
- **C14.** 一张原图的多个增广版本彼此是近重复，和同一来源的样本一样。先增广、再按样本随机划分，会把它们拆到两边，造成泄漏。本章按来源分组划分，同一来源的样本都在同一边，没有这个问题。用增广扩充训练数据时，最稳妥的做法是先按原图或来源划分，再只在训练集内部增广（5.10 节、实验手册第 7 节）。

### 手算题答案

- **H1.** (a) 组数 4，切点 round(0.5 × 4) = 2、round(0.75 × 4) = 3。训练集组 [3, 0]，验证集组 [2]，测试集组 [1]。(b) 组 3 有 4 个样本、组 0 有 3 个，训练集 7 个；验证集（组 2）1 个；测试集（组 1）2 个。比例 0.7 / 0.1 / 0.2，和 0.5 / 0.25 / 0.25 差得很多，因为组的大小不同。
- **H2.** (a) 四个 2×2 块的平均：左上 (0.9+0.8+0.7+0.6)/4 = 0.75，右上 (0.1+0.0+0.2+0.1)/4 = 0.10，左下 (0.0+0.1+0.2+0.1)/4 = 0.10，右下 (0.9+0.8+0.7+0.6)/4 = 0.75。平均 0.425。哈希 [True, False, False, True]。(b) 不变：每个格子变成 0.5x + 0.3，平均值也变成 0.5m + 0.3，大小关系不变。(c) 左右翻转后，四块变成 [0.10, 0.75, 0.75, 0.10]，哈希 [False, True, True, False]；和原图每一位都不同，汉明距离 4。
- **H3.** (a) A、B 不同的位：第 2、4 位，距离 2；A、C：第 1 位，距离 1；B、C：第 1、2、4 位，距离 3。(b) a·(1−b) = [1,0,1,1]·[0,0,0,1] = 1；(1−a)·b = [0,1,0,0]·[1,1,1,0] = 1；合计 2。
- **H4.** (a) √(0.85 × 0.15 / 400) = √0.000319 ≈ 0.0179；95% 区间 0.85 ± 1.96 × 0.0179 ≈ 0.85 ± 0.035，即 [0.815, 0.885]。(b) 1.96 × √(0.1275 / n) = 0.015 → n = 0.1275 × (1.96/0.015)² ≈ 0.1275 × 17073 ≈ 2177 张，约 2200 张。(c) 更宽。同一来源的图会一起对、一起错，有效样本数更接近 40 个来源，而不是 400 张。

### 编程题提示

- **5.1** 参考正文 5.4.2 节。`np.unique` 已经排好序；用 `np.random.default_rng(seed).permutation(uniq)` 打乱组；切点用模块里的 `_cut`；`np.isin(groups, part)` 找出属于这些组的样本。

### 调试题答案

- **D1.** 打乱和切分的对象是**样本**（`len(groups)`），不是组，`uniq` 根本没用上，等于随机划分。不报错，同一组的样本会被拆开。改成打乱 `uniq`、按组切、再收集样本。测试：检查各集合的组编号集合两两不相交（`test_group_split_disjoint_and_complete`）。
- **D2.** 标准化的均值和标准差是在全部数据（含验证集、测试集）上算的，测试集的信息流进了预处理。不报错，影响通常很小但原则上是泄漏。改成先划分，只用训练集算 `mean`、`std`，再用它们去变换三个集合。检查：每个"从数据学出来"的量，追溯它用了哪些下标。
- **D3.** 用测试集挑配置，还把挑出来的分数当最终结果报告。不报错，分数偏乐观（赢家诅咒）。改成在验证集上挑，挑完冻结设置，再在测试集上评一次。检查：训练和调参的代码里不应该出现 `te`。
- **D4.** 取批用的是全局随机数（`torch.randint` 没传 `generator`），打印那行也消耗全局随机数。同一个种子训练两次结果相同（代码一样，消耗的随机数一样）；但删掉打印那两行以后，后面每一批取到的样本都会变，结果就和原来不同了。也就是说，一行看似无关的调试代码改变了实验。改成取批用单独的 `torch.Generator().manual_seed(seed)`（正文 5.7.2 节）。检查：加一行无关的随机调用，参数应该仍然和原来完全相同。
- **D5.** 结论错了。分组划分下没有任何同源样本，在本章的合成数据上（来源就是真相），43.8% 是哈希检测器的误报率（多重比较，正文 5.5.4 节）。应当拿这个数当作误报的基线，或者换用更精细的度量（本章的像素距离在分组划分下只误报 3.5%），并抽查被标出的样本。
