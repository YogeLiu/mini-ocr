## 2. 实验一：溢出的边界在哪里

**问题：** 正文说 fp16 下 e^z 在 z > 11.09 时溢出。那么 naive softmax 在 fp16 下，logits [11.0, 0] 和 [11.2, 0] 哪个会出 nan？bf16（另一种 16 位格式）下 [12, 10, 8] 会不会出 nan？

**预测：** 写下你对三种情况（fp16 [11.0, 0]、fp16 [11.2, 0]、bf16 [12, 10, 8]）的预测。提示：bf16 的指数位和 fp32 一样多，尾数位更少。

**运行：**

```python
import torch
from miniocr.nn.losses import naive_softmax, softmax
for z, dt in (([11.0, 0.0], torch.float16), ([11.2, 0.0], torch.float16), ([12.0, 10.0, 8.0], torch.bfloat16)):
    t = torch.tensor(z, dtype=dt)
    print(dt, z, "e^z =", t.exp().tolist(), "naive =", naive_softmax(t).tolist(), "稳定 =", softmax(t).tolist())
print(torch.finfo(torch.bfloat16))
```

**观察：** 哪些情况出了 inf 或 nan；bf16 的最大值和 eps（相邻两个数的相对间隔）各是多少；bf16 的稳定 softmax 和 fp32 的 [0.8668, 0.1173, 0.0159] 差多少。

**思考：** bf16 几乎不会溢出，为什么混合精度训练里 loss 仍然常常放在 fp32 里算？（提示：看精度，不看范围。第 16 章会细讲。）

## 3. 实验二：梯度检查到底有多灵敏

**问题：** 正文 3.9.5 节显示，解析梯度的一列放大 1% 时相对误差是 5.0e-03。如果只放大 0.01% 呢？如果把梯度里的 `/ N` 忘了呢？

**预测：** 写下你预测的两个相对误差的数量级。

**运行：** 在你自己的脚本里复制 `tour.py` 第 8 部分 (a) 的代码，然后加上：

```python
bad = dW.clone(); bad[:, 0] *= 1.0001
print("放大 0.01%：", rel_error(bad, num))
N = Xd.shape[0]
bad = Xd.T @ (softmax(Xd @ Wc) - F.one_hot(yd, 3).double()) + 2 * 0.1 * Wc     # 忘了除以 N
print("忘了除以 N：", rel_error(bad, num))
```

**观察：** 两个相对误差。再把 `numerical_gradient` 的 h 改成 1e-3 和 1e-7 各跑一次，看"放大 0.01%"还能不能被发现。

**记录：** 一张小表：故意的错误 × h → 相对误差。

**思考：** 如果你的梯度只在某个很少出现的分支上写错了（比如只有 `reg > 0` 时才走的代码），梯度检查一定能发现吗？要怎样设计检查的输入？

## 4. 实验三：学习率扫描

**问题：** 正文用学习率 0.1 训练了 300 步。学习率 0.01、1.0、10、100 时会怎样？

**预测：** 对每个学习率，预测 300 步后的训练 loss 大概多少，曲线是平滑下降、很慢、还是震荡或发散。

**运行：** 在你的脚本里调用 `tour.py` 的 `make_blobs`、`add_bias`、`train_softmax`：

```python
import math, torch
from book.part1_foundations.ch03_softmax_ce.tour import make_blobs, add_bias, train_softmax
g = torch.Generator().manual_seed(0)
X, y = make_blobs(100, g); X = add_bias(X)
for lr in (0.01, 0.1, 1.0, 10.0, 100.0):
    W, hist = train_softmax(X, y, lr, 300, 1e-3)
    print(f"lr={lr:<6} 第 0/10/100/300 步 loss: {hist[0]:.4f} {hist[10]:.4f} {hist[100]:.4f} {hist[300]:.4f}  有 nan: {any(math.isnan(h) for h in hist)}")
```

**观察：** 每个学习率的 loss 序列；有没有 nan；画出五条曲线（纵轴用对数刻度）。

**思考：** 学习率很大时有没有出现 nan？如果没有，想一想为什么：softmax 交叉熵的梯度每个分量在 [−1, 1] 之间（正文 3.6.5 节），而本章的 softmax 是稳定写法。如果把 `softmax_loss_vectorized` 里的 softmax 换成 `naive_softmax`，学习率 100 时会怎样？试一试。

**问题：** 正文 3.8.2 节只看了初始 loss。初始化太大，除了初始 loss 高，对训练还有什么影响？

**预测：** W 的初始标准差分别取 0.01、1、10，学习率都是 0.1，训练 300 步。哪个最终 loss 最低？哪个前几步下降最快？

**运行：** 修改 `train_softmax` 的初始化（复制一份到你的脚本里，加一个 `init_std` 参数），在点云数据上跑三次，记录第 0、10、50、300 步的 loss 和训练正确率。

**观察：** 初始 loss 和 ln 3 的差距；最终 loss；正确率的变化。

**思考：** 点云数据的三类大体可以用直线分开，但有少量点重叠（训练正确率到不了 100%，剩下的误差不是优化问题），大初始化在这里可能"看不出问题"。在螺旋数据上再试一次，结果会不同吗？真实的深层网络里，大初始化还会造成什么问题？（第 4 章讲初始化。）

## 6. 实验五（进阶，选做）：按 token 平均和按序列平均会训练出不同的模型吗

这个实验没有标准答案。

**问题：** 正文 3.7.5 节说两种平均方式给 token 分配的权重不同。在训练中，这会不会让模型在短序列和长序列上的表现不同？

**设计：** 构造一个序列分类的玩具任务：每个序列由 1 到 20 个随机 token 组成，每个位置的目标是"当前 token 加 1 再对 V 取模"（一个简单的映射，用一个嵌入层 + 线性层就能学）。再人为加点难度：长度 ≤ 3 的序列用另一种映射（加 2）。这样短序列和长序列的规则不同，而且短序列的 token 总数很少。

**步骤：**

1. 分别用 `cross_entropy`（按 token）和 `sequence_mean_cross_entropy`（按序列）训练同样的模型，同样的步数。
2. 在验证集上，分别统计短序列（≤ 3）和长序列的 token 正确率。

**预测：** 哪种平均方式在短序列上更好？

**记录：** 两种方式 × 两类序列的正确率。思考：如果你的 TexPixel 数据里短公式很多、长公式很少（或者反过来），你会选哪种？

## 7. 故障演练：loss 停在一个奇怪的数上

**场景：** 你训练一个 10 类分类器。loss 从 2.30 开始下降，但降到 1.46 附近就再也不动了；训练正确率却已经到了 99%。

**请按下面的步骤排查**，每一步写下你看到了什么：

1. 先给 loss 曲线标刻度（正文 3.8.5 节）：ln 10 = 2.3026 是起点。1.46 是哪条参考线？（提示：正文 3.10 节的表。）
2. 打印传给 loss 函数的张量：它的每一行加起来是不是 1？最小值是不是 ≥ 0？
3. 找到多余的那次 softmax，去掉，再训练一次。（第 9 部分的输出：C = 10 时错误写法的下限是 1.4612。）

**要总结的教训：** loss 停在一个"整齐"的数上时，先算一算它是不是某个可以推出来的值（ln C、H(类别频率)、错误写法的下限）。很多 bug 会留下这样的"指纹"。
