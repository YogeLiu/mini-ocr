## 2. 实验一：手算，再让机器检查

**问题：** 2.6 节的网络里，如果把输入换成 x1 = 1、x2 = 3，其余参数和目标不变，每个梯度是多少？

**预测：** 先在纸上完整算一遍前向和反向，填出和正文 2.6.4 节一样的表。特别注意：两个隐藏神经元的 relu 还都开着吗？

**运行：** 在 Python 里：

```python
from book.part1_foundations.ch02_backprop.tour import NET, two_layer_values
v = two_layer_values(dict(NET, x1=1.0, x2=3.0))
v["L"].backward()
for k in ("z1", "z2", "yhat", "L"):
    print(k, v[k].data)
for k in ("w11", "w12", "b1", "w21", "w22", "b2", "v1", "v2", "c", "x1", "x2"):
    print(k, v[k].grad)
```

**观察：** 你的手算和机器的结果哪里不同？如果不同，是前向错了还是反向错了？找出第一个出错的节点。

**记录：** 你最容易在哪一步出错（符号、relu 开关、忘了加另一条路径……）。

## 3. 实验二：步长表

**问题：** 正文 2.8.5 节的表用的是 f(w) = (tanh(1.5w) − 0.3)²。换一个函数，最佳步长还在同一个位置吗？

**预测：** 对 f(w) = e^(3w) 在 w = 2 处（f 的值约为 403），中心差分 float64 的最佳步长比 1e-6 大还是小？提示：看 2.8.4 节总误差公式里的 |f| 和 |f‴|。

**运行：** 把 `tour.py` 第 6 部分里的 `f64`、`f32`、`exact` 和 `w0` 换掉（`math.exp(3 * w)`、`torch.exp(3 * w)`、`3 * math.exp(3 * w0)`、`w0 = 2.0`），运行 `python -m book.part1_foundations.ch02_backprop.tour 6`。

**观察：** 三列的最小值分别出现在哪个 h；和理论最佳步长 (3ε|f|/|f‴|)^(1/3) 比较。

**记录：** 换函数之后，"h 取 1e-5 左右"这条经验还适用吗？

## 4. 实验三：埋一个 bug，看梯度检查能不能抓住

**问题：** 正文 2.8.6 节埋了两个 bug。还有哪些 bug，梯度检查能抓住？有没有它抓不住的？

**运行：** 仿照第 6 部分 `bad_tanh` 的写法，临时替换 `Value` 的一个方法，然后计算相对误差的最大值。依次试：

1. relu 的反向写成 `self.grad += out.grad`（忘了开关）；
2. 乘法的反向把 `self.grad += other.data * out.grad` 写成 `self.grad += self.data * out.grad`；
3. 加法的反向写成 `self.grad += out.grad` 和 `other.grad = out.grad`（只有一处用了 `=`）；
4. `numerical_grad` 里忘了 `xs[i] = old` 这一行（这次是改检查工具，而不是改 `Value`）。

对 1 号 bug，网络要用 relu 激活才有意义：`MLP([2, 4, 4, 1], seed=1, act="relu")`。

**预测：** 每个 bug 的最大相对误差是多少量级？哪个可能"侥幸"通过检查？

**观察：** 3 号 bug 在 tanh 的 [2, 4, 4, 1] 网络上能被抓住吗？如果抓不住，想一想：这个网络里有没有"同一个变量被加法用两次"的情况？`Neuron` 里 `sum(..., self.b)` 的累加顺序会不会让 `=` 恰好不出错？

**记录：** 每个 bug 一行：bug、预测、实测最大相对误差、是否被抓住、原因。

**要总结的教训：** 梯度检查只能检查你喂给它的那张图。一个 bug 要被抓住，测试用的计算图必须真的经过有问题的路径。所以测试里要专门构造 `x * x`、`x + x` 这样的例子（见 `test_same_variable_used_twice_accumulates`）。

## 6. 故障演练：忘记清零

**场景：** 你从网上抄了一段训练代码，跑起来前几十步 loss 降得比你自己的代码还快，可是一百多步以后 loss 开始上升，最后比开始时还高。

**请按下面的步骤排查**，每一步写下你看到了什么：

1. 先做受控检查：固定参数，对同一批数据连续调用两次前向和 `backward()`。正确的代码两次 `.grad` 相同；忘了清零则第二次正好翻倍。
2. 再看每一步所有参数梯度的范数（第 8 部分的 `gnorm`）。第 8 部分那次实验里，不清零时它从 0.433 一路涨到 5.911；但这只是那次的现象，历史梯度可以相互抵消，范数不一定单调增大（正文 2.9.6 节的反例），所以它只能作旁证。
3. 在训练循环里找 `zero_grad` 或 `p.grad = None`。它在 `backward()` 之前被调用了吗？
4. 加上清零，再跑一次，对比第 50 步和第 200 步的损失。

**要总结的教训：** 训练早期的"改进"不一定是真的改进。确认是否忘了清零，靠"固定参数、重复反向"的受控检查，而不是只看某一次训练里梯度范数的走向。
