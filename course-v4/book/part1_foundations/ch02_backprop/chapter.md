# 第 2 章 导数、计算图与反向传播

## 本章导读

训练一个神经网络，每一步只做两件事：**算出每个参数该往哪边调、调多少；然后调一点点。** 前一件事叫"求梯度"，后一件事叫"更新参数"。第 4 章会专门讲更新；这一章只讲求梯度，回答的问题是：

> 一个模型有成千上万个参数，损失是这些参数经过很多步运算得到的一个数。怎样又快又准地算出损失对**每一个**参数的导数？

答案是**反向传播**（backpropagation）：把计算拆成一张图，从输出往回走，每经过一个节点就乘上它的局部导数。所有深度学习框架都靠它求梯度，PyTorch 里你写的 `loss.backward()`，背后做的就是这件事。

这一章先亲手算一遍，再亲手写一个只有一百多行的自动求导引擎，并用它训练一个小分类器。

**学完本章，你能做到：**

1. 手算一个两层小网络的前向和反向，写出每个中间量的值和梯度。
2. 解释链式法则在计算图上怎样变成"从输出往回逐个节点相乘"。
3. 解释为什么一个变量被用了两次，它的梯度要相加。
4. 自己写一个标量自动求导引擎（`miniocr/autograd.py` 里的 `Value`），支持加、乘、幂、tanh、relu，并用它训练一个小网络。
5. 用数值梯度（有限差分）检查解析梯度，知道步长怎样选、相对误差多大算正常。
6. 说清 PyTorch 里 `requires_grad`、`backward()`、`.grad` 和梯度清零分别做了什么，以及忘记清零会发生什么。

## 2.1 问题：参数该往哪边拧

### 2.1.1 一个旋钮

先看一个最小的模型。它只有一个参数 w，预测值是 ŷ = w·x。手上只有一个样本：x = 2，正确答案 y = 3。用平方误差衡量预测得好不好：

```
L(w) = (w·x − y)² = (2w − 3)²
```

L 叫**损失**（loss），越小越好。现在 w = 0.5，预测 ŷ = 1，损失 L = (1 − 3)² = 4。

把 w 想象成收音机上的一个旋钮，L 是杂音的大小。我们想把杂音调小，问题是：**往哪边拧？拧多少？**

最直接的办法是"试一下"：把 w 拧一点点，看 L 怎么变（实验脚本第 1 部分）：

| w 增加 | 新的 L | L 的变化 | 变化 ÷ 增加量 |
|---|---|---|---|
| 0.1 | 3.240000 | −0.760000 | −7.6000 |
| 0.01 | 3.920400 | −0.079600 | −7.9600 |
| 0.001 | 3.992004 | −0.007996 | −7.9960 |

（本项目观察，第 1 部分；这几个数也可以用纸笔算出来。）

两个发现：

- **L 变小了**，说明 w 应该往大里拧。
- **"变化 ÷ 增加量"越来越接近 −8。** 这个极限值就是导数 dL/dw。

用求导公式直接算：dL/dw = 2(w·x − y)·x = 2 × (1 − 3) × 2 = −8（数学结论）。这里用到了 2.4 节才讲的链式法则；不想用它的话，可以先把 L 展开成 4w² − 12w + 9，逐项求导得 8w − 12，代入 w = 0.5，结果同样是 −8。负号的意思是"w 增大，L 减小"，所以要把 w 调大。数值 8 的意思是"在当前位置，w 每增加一点点，L 就减少大约 8 倍那么多"。

### 2.1.2 一百万个旋钮

只有一个旋钮时，"试一下"完全够用。可是神经网络有很多旋钮：本章最后训练的小网络有 105 个参数，第 11 章的 GPT 有几百万个，真实的大模型有几十亿个。

"试一下"的代价是：**每个参数都要单独试，每试一次就要把整个模型重新算一遍。** 如果每个参数往左、往右各试一次（2.8 节会讲为什么要两边都试），N 个参数就要算 2N 遍。

实验脚本第 1 部分在 4 个样本上比较了两种做法。下表用同样的计时循环重复 5 轮（本项目观察，CPU，5 轮中位数，括号里是 5 轮的最小到最大值，`outputs/book/ch02/timing_repeats/`）：

| 网络 | 参数个数 | "试一下"要算几遍 | "试一下"用时（ms） | 反向传播用时（ms） | 慢多少倍（每轮比值的中位数） |
|---|---|---|---|---|---|
| MLP [2, 8, 8, 1] | 105 | 210 | 221（215 到 256） | 0.91（0.47 到 0.94） | 约 240 |
| MLP [2, 16, 16, 1] | 337 | 674 | 5492（5363 到 5809） | 1.88（1.84 到 1.94） | 约 2900 |

两种做法算出来的梯度是一致的（最大相对误差分别是 1.0e-08 和 8.9e-08，2.8 节会解释这个误差多大算正常）。但是参数变成约 3 倍时，"试一下"的用时增长了约 25 倍（中位数，5 轮在 21 到 27 倍之间），而反向传播只增长了约 2 倍（中位数，有 1 轮到 4 倍）。

为什么差这么多？"试一下"的总工作量 = 参数个数 × 每遍的工作量，两个因子都随网络变大而变大。把每遍的工作量也看成和参数个数成正比，粗算是 (337/105)² ≈ 10 倍（数学结论），实测更大。代码能确认，每遍都要建一张完整的 `Value` 图，创建对象和闭包，但这些开销各占多少没有测，多出来的部分来自哪里还说不清。计时受机器负载影响，倍数每次运行都不一样，但"差了几个数量级"这个结论不会变。

按这个比例推下去，几百万个参数的模型用"试一下"根本算不完。

### 2.1.3 我们想要什么

我们想要一种方法：

1. **一次就算出所有参数的导数**，而不是一个一个地试。
2. **算得准**，不受"试多大一步"的影响。
3. **不用手推公式**。模型结构一改，手推的公式就得重推，这不现实。

反向传播同时做到了这三点。它不需要为每个参数各算一遍，总代价大约只是"前向算一遍"的几倍。模型变大时前向本身会变贵，反向也跟着变贵，但"反向是前向的几倍"这个倍数不随参数个数增长。下面就一步一步把它造出来。

"试一下"也没有被淘汰。它慢，但几乎不会写错，所以留下来专门检查反向传播写得对不对，也就是 2.8 节的数值梯度检查。

## 2.2 导数：局部的放大倍数

这一节是回顾。你在微积分课上学过的公式，本章只用到很少几条，下面集中列一张表。公式不用背，要记住的是导数的**含义**。

### 2.2.1 导数的含义

> **导数 f′(x) 是一个放大倍数：在 x 附近，输入变化一点点 Δx，输出大约变化 f′(x)·Δx。**

用 2.1.1 节的例子：在 w = 0.5 附近，w 变化 0.001，L 大约变化 −8 × 0.001 = −0.008；实测是 −0.007996（第 1 部分）。

这句话里最容易被忽略的是"**在 x 附近**"和"**大约**"。导数只描述一个很小的邻域。w 加 0.1 时，L 实际变化 −0.76，而按 −8 倍估算是 −0.8，已经差了 5%。差的那部分来自曲线的弯曲。把 w = 0.5 + Δw 代进 L = (2w − 3)²，括号里是 2Δw − 2，平方后是 4Δw² − 8Δw + 4，再减去原来的 L = 4：

```
L(w + Δw) − L(w) = −8Δw + 4Δw²
```

Δw 很小时，Δw² 小得可以忽略，变化几乎就是 −8Δw；Δw 大了，Δw² 那一项就不能忽略了（数学结论）。所以导数只是一个局部的结论，2.6.5 节会看到，步子迈得太大，按导数预测的"损失会下降"可能完全落空。

### 2.2.2 偏导数和梯度

函数有多个输入时，比如 f(a, b)，**偏导数** ∂f/∂a 的意思是：只让 a 变一点点，b 保持不动，f 变化的倍数。

把所有偏导数排成一个向量，就是**梯度**：

```
∇f = [∂f/∂a, ∂f/∂b, …]
```

对神经网络来说，"输入"就是所有参数，"输出"就是损失 L。梯度的每个分量告诉我们一个参数该往哪边拧、它对损失的影响有多敏感。本章说"求梯度"，指的就是求出 ∂L/∂(每一个参数)。

本书的记号约定：一个量 u 的梯度 ∂L/∂u，在代码里存放在 `u.grad` 中，正文里有时也简写成 "u 的梯度"。它永远是**最终损失**对 u 的导数，而不是 u 对它的输入的导数。后者叫**局部导数**。

> **回顾：本章用到的求导公式**
>
> | 函数 | 导数 | 备注 |
> |---|---|---|
> | c（常数） | 0 | |
> | x^n | n·x^(n−1) | n 可以是负数或小数，比如 1/x = x^(−1) 的导数是 −x^(−2) |
> | e^x | e^x | 第 3 章用 |
> | ln x | 1/x | 第 3 章用 |
> | tanh x | 1 − tanh²x | 用输出表示：若 t = tanh x，则导数是 1 − t² |
> | relu(x) = max(0, x) | x > 0 时为 1，x < 0 时为 0 | x = 0 处不可导，约定取 0 |
> | sigmoid σ(x) = 1/(1 + e^(−x)) | σ(x)(1 − σ(x)) | |
>
> | 法则 | 公式 |
> |---|---|
> | 和 | (f + g)′ = f′ + g′ |
> | 积 | (f·g)′ = f′·g + f·g′ |
> | 链式法则 | 若 y = f(u)，u = g(x)，则 dy/dx = (dy/du)·(du/dx) |
>
> 参考：任何一本微积分教材的"导数"一章；CS231n 课程笔记 "Derivatives, Backpropagation, and Vectorization"。

2.4 节会看到，整个反向传播就是把表里最后一行的链式法则在一张图上反复使用。

## 2.3 计算图

### 2.3.1 把计算拆成小步

做菜时，一道复杂的菜可以拆成一张流程图：洗菜、切菜、焯水、炒、调味……每一步只做一件简单的事，前一步的产出是后一步的原料。

数学表达式也一样。看这个式子：

```
L = (a·b + c)²，其中 a = 2，b = −3，c = 10
```

我们把它拆成三步，给每个中间结果起个名字：

```
d = a · b        乘法
e = d + c        加法
L = e²           平方
```

画成图（箭头表示"数据从哪里流向哪里"）：

```
a ──┐
    (×)── d ──┐
b ──┘         (+)── e ──(²)── L
c ────────────┘
```

这就是一张**计算图**（computational graph）。图里有两种东西：

- **节点**：每个数是一个节点，比如 a、d、L。
- **运算**：每个运算把几个输入节点变成一个输出节点，比如 (×) 把 a、b 变成 d。

没有输入的节点（a、b、c）叫**叶子**（leaf）。在神经网络里，叶子就是参数和输入数据。最后那个节点 L 叫**根**，通常就是损失。

计算图的**箭头不会绕回来**：d 由 a、b 算出，就不可能反过来参与计算 a。这样的图叫"有向无环图"（DAG）。2.7 节写代码时会用到这个性质。

### 2.3.2 前向：从左往右算值

沿着箭头的方向，从叶子算到根，叫**前向计算**（forward pass）。每个节点都等它的输入算好了再算（实验脚本第 2 部分）：

```
d = a · b = 2 × (−3) = −6
e = d + c = −6 + 10 = 4
L = e²   = 4² = 16
```

前向计算你天天都在做，写 `L = (a * b + c) ** 2` 就是。计算图只是把这个过程画了出来。

### 2.3.3 每个节点只管自己的局部导数

现在换一个角度看图里的每个运算。每个运算都是一个很简单的函数，它的导数我们一眼就能写出来。这叫**局部导数**（local derivative）：输出对它直接的输入的导数。

| 运算 | 局部导数 | 在本例中的值 |
|---|---|---|
| d = a · b | ∂d/∂a = b，∂d/∂b = a | ∂d/∂a = −3，∂d/∂b = 2 |
| e = d + c | ∂e/∂d = 1，∂e/∂c = 1 | 1，1 |
| L = e² | ∂L/∂e = 2e | 8 |

注意两点：

1. **每个运算只需要知道自己的输入和输出**，不需要知道整张图长什么样。乘法节点不关心 a 是从哪里来的，也不关心 d 后面还要经过几步才到 L。
2. **局部导数的值依赖于前向计算的结果**。∂d/∂a = b = −3，要先知道 b 的值；∂L/∂e = 2e = 8，要先算出 e = 4。所以前向计算时要把这些值**留着**，反向时才用得上。训练比推理更占内存，这是一个主要原因（第 16 章）。

我们要求的是 ∂L/∂a、∂L/∂b、∂L/∂c，也就是损失对叶子的导数。下一节讲怎样用局部导数把它们拼出来。

## 2.4 链式法则：从输出往回逐个节点相乘

### 2.4.1 一条链：放大倍数相乘

先看最简单的情况：一条没有分叉的链。

```
y = (3x + 1)²，在 x = 1 处
拆开：u = 3x + 1，y = u²

x ──(×3, +1)── u ──(²)── y
```

前向：u = 4，y = 16。局部导数：du/dx = 3，dy/du = 2u = 8。

链式法则说：

```
dy/dx = (dy/du) · (du/dx) = 8 × 3 = 24
```

为什么是相乘？用 2.2.1 节"放大倍数"的含义来想：x 变化一点点 Δx，u 就变化 3Δx；u 变化 3Δx，y 就变化 8 × 3Δx = 24Δx。两级放大串起来，总的放大倍数就是两个倍数的乘积。

实验脚本第 2 部分验证：x 从 1 变成 1.001，y 从 16 变成 16.024009，变化 0.024009，约等于 24 × 0.001 = 0.024（本项目观察）。

**类比：换汇。** 你手上有人民币，想知道它值多少日元，但只查得到两个汇率：1 人民币 = 0.14 美元，1 美元 = 150 日元。那么 1 人民币 = 0.14 × 150 = 21 日元。汇率沿着换汇的链条相乘，导数沿着计算的链条相乘。

和换汇不同的是，导数是局部的：dy/du = 2u，u 不同，"汇率"就不同，所以必须先做前向算出 u，才知道这一级的倍数。

### 2.4.2 在图上往回走

现在回到 2.3 节的图 L = (a·b + c)²。我们要算 ∂L/∂a、∂L/∂b、∂L/∂c。

思路是：**从根出发，逆着箭头往回走。每到一个节点，就算出 L 对它的导数。** 这个导数我们记作该节点的"梯度"。

**第 0 步：起点。** L 对自己的导数当然是 1：

```
∂L/∂L = 1
```

**第 1 步：经过平方节点，到达 e。** 平方节点的局部导数是 2e = 8：

```
∂L/∂e = ∂L/∂L × ∂L/∂e（局部） = 1 × 8 = 8
```

平方节点的输出就是 L 本身，所以它的局部导数 dL/de 恰好就是我们要的 ∂L/∂e。这里仍然写成"1 × 局部导数"，是为了和后面每一步的格式一样。意思是：e 增加一点点，L 增加约 8 倍那么多。

**第 2 步：经过加法节点，到达 d 和 c。** 加法节点对两个输入的局部导数都是 1：

```
∂L/∂d = ∂L/∂e × ∂e/∂d = 8 × 1 = 8
∂L/∂c = ∂L/∂e × ∂e/∂c = 8 × 1 = 8
```

**第 3 步：经过乘法节点，到达 a 和 b。** 乘法节点的局部导数是"对方的值"：

```
∂L/∂a = ∂L/∂d × ∂d/∂a = 8 × b = 8 × (−3) = −24
∂L/∂b = ∂L/∂d × ∂d/∂b = 8 × a = 8 × 2   = 16
```

结果：∂L/∂a = −24，∂L/∂b = 16，∂L/∂c = 8。实验脚本第 2 部分用 PyTorch 算了同一个式子，三个梯度完全一样（本项目观察）。

把这个过程画在图上，前向的值写在箭头上方，反向的梯度写在下方（方括号里）：

```
 2 [−24]
a ──┐  −6 [8]
    (×)──── d ──┐  4 [8]       16 [1]
b ──┘           (+)──── e ──(²)──── L
−3 [16]         │
c ──────────────┘
10 [8]
```

**规律：每个节点的梯度 = 它下游节点的梯度 × 连接它们的局部导数。** 下游节点的梯度又叫**上游梯度**（upstream gradient）。叫"上游"，是因为在反向传播里梯度是从 L 那一头流过来的，L 那一头是梯度的源头。本书以后都这样叫：

```
本节点的梯度 = 上游梯度 × 局部导数
```

剩下的都是工程问题：按什么顺序走、分叉了怎么办、怎样让计算机自动做。

**停下来想一想：** 不看上面的结果，自己用这个规律算一遍 ∂L/∂b。然后用"试一下"验证：把 b 从 −3 改成 −2.999，L 变成多少？是不是大约增加了 16 × 0.001？

### 2.4.3 类比：沿着流水线往回分摊"责任"

想象一条生产线：原材料（a、b、c）经过几道工序（乘、加、平方），最后出来一件产品（L）。质检发现产品的某个指标偏高了，厂长想知道：**每一种原材料该为此负多少"责任"**，下次该怎么调整用量？

厂长不需要懂每道工序的全部细节。他只需要让每个工位回答一个本地问题："我的输入变一点，我的输出变多少？"这就是局部导数。然后从最后一个工位开始往前问：

- 最后一个工位（平方）说："我的输入 e 每多 1，产品指标多 8。" 于是 e 被分到 8 份"责任"。
- 加法工位说："我的两个输入各多 1，我的输出都多 1。" 于是它把自己拿到的 8 份责任原样转给 d 和 c。
- 乘法工位说："a 每多 1，我的输出多 b = −3；b 每多 1，我的输出多 a = 2。" 于是 a 分到 8 × (−3) = −24，b 分到 8 × 2 = 16。

责任从产品那一端沿着流水线往回传，每经过一个工位，就按这个工位的局部敏感度放大或缩小。这个类比帮你记住了"往回传"和"逐站相乘"，但它有三处不准确：

1. **"责任"加起来不等于 100%。** 生活里分摊责任，大家的份额加起来是全部。梯度没有这个约束：本例中 a、b、c 的梯度是 −24、16、8，加起来是 0，跟 L = 16 没有任何关系。梯度可以很大、可以是 0、可以是负的。
2. **梯度衡量的是对微小变化的敏感度，不是功劳。** 一个原料对最终结果的贡献可能很大，但如果它所在的那一段曲线是平的（比如 tanh 输入很大时，见 2.4.4 节），它的梯度就接近 0。
3. **负的"责任"是有用的信息。** a 的梯度是 −24，意思是"a 增大，L 会减小"。如果我们想让 L 变小，就应该**增大** a。

### 2.4.4 几种节点的固定模式

反向传播时，每种运算处理上游梯度 g 的方式是固定的。记住下面几个模式，读别人的代码、排查梯度问题都会快很多（第 2 部分打印了这张表）：

| 运算 | 输入怎样分到梯度 | 外号 |
|---|---|---|
| z = x + y | x、y 都拿到 g | 分发器：原样复制给每个输入 |
| z = x · y | x 拿到 g·y，y 拿到 g·x | 交换器：乘以"对方"的值 |
| z = x^n | x 拿到 g·n·x^(n−1) | 放大器：乘以局部斜率 |
| z = relu(x) | x > 0 时拿到 g，否则拿到 0 | 开关：要么全部通过，要么全部挡住 |
| z = tanh(x) | x 拿到 g·(1 − z²) | 阀门：输入的绝对值越大，开口越小 |

tanh 这个"阀门"的开口随输入变化（第 2 部分，数学结论，数值是计算结果）：

| tanh 的输入 | tanh 的输出 | 局部导数 1 − tanh² |
|---|---|---|
| 0 | 0.0000 | 1.0000 |
| 1 | 0.7616 | 0.4200 |
| 2 | 0.9640 | 0.0707 |
| 3 | 0.9951 | 0.0099 |

输入为 3 时，局部导数只剩 0.0099，上游梯度经过这里会被缩小约 100 倍。这叫**饱和**（saturation）。一个神经元如果总是工作在饱和区，它前面的参数就几乎拿不到梯度，学得很慢。第 8 章"为什么除以 √d"、第 4 章"初始化"，都和避免饱和有关。

relu 的"开关"也有类似的问题：输入为负时梯度是精确的 0。如果一个 relu 神经元对所有样本的输入都是负的，它这一步就拿不到梯度；只要它的输入不会因为别的途径改变（比如上游表示不经由其他分支更新、参数也没有动量或权重衰减之类的其他更新来源），它就会一直关着，再也学不动。这是一种风险，不是必然：共享上游的网络里，别的路径可能把它的输入推回正半轴。2.6.6 节会亲眼看到一个被关掉的 relu。

### 2.4.5 为什么从后往前，而不是从前往后

链式法则是乘法，乘法满足交换律。那为什么非要从 L 往回走？从 a 往前走不行吗？

可以，这叫**前向模式**（forward mode）求导：从某一个输入出发，沿着箭头一路乘过去，最后得到 L 对**这一个输入**的导数。问题是，想要 L 对所有输入的导数，就得对每个输入各走一遍。N 个参数走 N 遍，和 2.1.2 节的"试一下"一样，代价和参数个数成正比。

从 L 往回走叫**反向模式**（reverse mode）。从唯一的输出 L 出发走一遍，沿途就把 L 对**所有**节点的导数都算出来了。差别在于每个节点记的是什么：反向模式里，每个节点记 ∂L/∂(这个节点)，图里只有一个 L，所以每个节点算一次就够，它的所有输入都接着用它；前向模式里，每个节点记 ∂(这个节点)/∂(某一个输入)，换一个输入，整张图就得重算一遍。

| | 前向模式 | 反向模式 |
|---|---|---|
| 走一遍得到什么 | 所有输出对**一个输入**的导数 | **一个输出**对所有输入的导数 |
| 适合 | 输入少、输出多 | 输入多、输出少 |

神经网络训练恰好是"输入极多（所有参数）、输出只有一个（损失）"，所以用反向模式。走一遍反向的代价和走一遍前向是同一个量级，因为每个运算的局部导数都很便宜。省下的是"为每个参数各走一遍"，总计算量仍会随模型变大（2.1.3 节，数学结论）。常见的经验说法是反向的代价约为前向的 2 倍左右，具体取决于运算（待验证）。2.1.2 节表里反向传播只用了约 0.91 ms 和约 1.88 ms（5 轮中位数，随机器负载波动），原因就在这里。

代价是内存：反向模式要先做完前向，并把所有中间值留着（2.3.3 节），等反向时再用。

## 2.5 同一个变量用了两次：梯度相加

到目前为止，图里每个节点只被用了一次。真实的计算里，一个变量经常被用好几次。这时候梯度该怎么算？

### 2.5.1 最简单的例子

看最简单的例子：

```
f = x · x，在 x = 3 处
```

画成图，x 同时连到乘法节点的两个输入上：

```
x ──┬──(×)── f
    └───┘
```

按 2.4.4 节的"交换器"规则，乘法节点给第一个输入 g·(第二个输入) = 1 × 3 = 3，给第二个输入 g·(第一个输入) = 1 × 3 = 3。

x 的梯度是 3 还是 6？

我们知道 f = x²，导数是 2x = 6。正确答案是 6。两个输入各分到 3，x 同时是这两个输入，所以 x 的梯度是 3 + 3 = 6。

用"试一下"验证：f(3.001) − f(3) = 0.006001，约等于 6 × 0.001（第 3 部分）。

### 2.5.2 推导

为什么是相加？我们换个写法，把"同一个 x 的两次使用"拆成两个变量：

```
f = p · q，其中 p = x，q = x
```

现在让 x 变化一点点 Δx。p 和 q 都跟着变化 Δx。f 的变化有两个来源。按 2.2.2 节，每个偏导数只描述"单独动一个输入"时 f 的变化；几个输入同时动一点点时，f 的总变化近似等于各自引起的变化之和，这就是下面第一行：

```
Δf ≈ (∂f/∂p)·Δp + (∂f/∂q)·Δq        （多元函数的一阶近似）
   = (∂f/∂p)·Δx + (∂f/∂q)·Δx
   = (∂f/∂p + ∂f/∂q)·Δx
```

所以：

```
df/dx = ∂f/∂p + ∂f/∂q = q + p = 3 + 3 = 6
```

这是**多元链式法则**（数学结论）：

> 如果 x 通过好几条路径影响 L，那么 ∂L/∂x 等于每条路径贡献的梯度之和。

每条路径的贡献，就是沿这条路径把局部导数乘起来。2.4 节的"逐站相乘"管一条路径；本节的"相加"管多条路径的汇合。两者合在一起，就是完整的链式法则。

**再看一个例子：** g = x·y + x，在 x = 2、y = 5 处。x 有两条路径到 g：

- 经过乘法：贡献 1 × y = 5；
- 直接经过加法：贡献 1 × 1 = 1。

所以 ∂g/∂x = 5 + 1 = 6，和直接求导 ∂g/∂x = y + 1 = 6 一致（数学结论；第 3 部分验证）。

### 2.5.3 类比：两份兼职

你同时打两份工，一份时薪 3 元，一份时薪 3 元（每份工的"敏感度"）。如果两份工的工时都同步多 1 小时，你的总收入多 6 元，不是 3 元。

和打工不同的是，计算图里同一个变量的两次使用永远同步变化，没法"只多上一份工"，所以梯度总是两份之和。两处的贡献也可能符号相反、互相抵消，最后加起来等于 0，就像一份工赚钱、一份工亏钱。

### 2.5.4 写进代码：+= 而不是 =

这个结论决定了自动求导代码里的一个符号。每个运算在反向时把梯度"交给"它的输入，必须写成**累加**：

```python
self.grad += other.data * out.grad      # 对
self.grad  = other.data * out.grad      # 错：第二条路径会覆盖第一条
```

写成 `=` 会怎样？实验脚本第 3 部分临时把加法和乘法的反向改成 `=`，再算一遍（本项目观察）：

| 式子 | 正确梯度 | 用 += | 写成 = |
|---|---|---|---|
| f = x·x，x = 3 | 6 | 6 | 3 |
| g = x·y + x，x = 2，y = 5 | 6 | 6 | 5 |

写成 `=` 的结果是**错的，而且不报错**。第二个例子更危险：结果是 5 还是 1，取决于两条路径哪一条先被处理，换个写法顺序就会变。

既然要累加，就必须有个起点：每次反向之前，梯度要从 0 开始。这引出了一个所有框架都有的步骤，**梯度清零**。2.7.7 节和 2.9.4 节会详细讲。

### 2.5.5 神经网络里到处都是分叉

在神经网络里，同一个变量被用多次是常态：

- **一个输入被好几个神经元用到。** 2.6 节的网络里，输入 x1 同时进入两个隐藏神经元，它的梯度就是两份之和。
- **一个参数被一批样本共用。** 一次训练同时算 100 个样本的损失再取平均，每个参数在 100 个样本的计算里各用了一次。它的梯度是 100 份梯度之和（再除以 100）。
- **残差连接**（第 9 章）：y = x + f(x)，x 既直接走到 y，又经过 f 走到 y。
- **权重共享**（第 11 章）：GPT 的输入嵌入和输出层常常共用同一个矩阵。卷积核（第 28 章）在图片的每个位置上共用。
- **注意力**（第 8 章）：同一个 x 乘以三个矩阵，分别变成 q、k、v，x 被用了三次。

所以只要把 `+=` 写错，几乎所有网络的梯度都会错。

## 2.6 手算一个两层网络

现在把前面的规则用到一个神经网络上。网络很小，数字也选得很简单，目的是让你**每一步都能用纸笔算出来**。请准备好纸笔，跟着算一遍，不要只看。

### 2.6.1 网络和数字

网络结构：输入 2 维，一个隐藏层有 2 个神经元（relu 激活），输出层 1 个神经元（不加激活），损失是平方误差。

```
          隐藏层                    输出层
x1 ──┬──→ z1 = w11·x1 + w12·x2 + b1 ──relu──→ a1 ──┐
     │                                              ├──→ ŷ = v1·a1 + v2·a2 + c ──→ L = (ŷ − y)²
x2 ──┴──→ z2 = w21·x1 + w22·x2 + b2 ──relu──→ a2 ──┘
```

（x1、x2 都同时连到两个隐藏神经元，图里只画了示意。）

**形状：** 输入 x 形状 (2,)；隐藏层权重 W1 形状 (2, 2)，第 i 行是第 i 个隐藏神经元的两个权重；偏置 b 形状 (2,)；隐藏层输出 a 形状 (2,)；输出层权重 v 形状 (2,)；偏置 c、预测 ŷ、损失 L 都是标量。参数一共 4 + 2 + 2 + 1 = 9 个（数学结论）。

**数字**（实验脚本第 4 部分的 `NET`）：

| 名字 | 值 | 含义 |
|---|---|---|
| x1, x2 | 2, 1 | 输入 |
| w11, w12, b1 | 1, −1, 0.5 | 隐藏神经元 1 的权重和偏置 |
| w21, w22, b2 | 0.5, 1, −1 | 隐藏神经元 2 的权重和偏置 |
| v1, v2, c | 1, −1, 0.5 | 输出神经元的权重和偏置 |
| y | 2 | 目标值 |

为什么用 relu 而不用 tanh？只是为了让数字保持整洁：relu 的导数只有 0 和 1。习题 H3 给了一个 tanh 版本，要用计算器。

### 2.6.2 前向

从左往右，一个节点一个节点地算：

**隐藏神经元 1：**

```
z1 = w11·x1 + w12·x2 + b1 = 1×2 + (−1)×1 + 0.5 = 2 − 1 + 0.5 = 1.5
a1 = relu(z1) = relu(1.5) = 1.5
```

**隐藏神经元 2：**

```
z2 = w21·x1 + w22·x2 + b2 = 0.5×2 + 1×1 + (−1) = 1 + 1 − 1 = 1
a2 = relu(z2) = relu(1) = 1
```

**输出和损失：**

```
ŷ = v1·a1 + v2·a2 + c = 1×1.5 + (−1)×1 + 0.5 = 1
e = ŷ − y = 1 − 2 = −1
L = e² = 1
```

前向结果汇总（第 4 部分）：

| z1 | a1 | z2 | a2 | ŷ | e | L |
|---|---|---|---|---|---|---|
| 1.5 | 1.5 | 1 | 1 | 1 | −1 | 1 |

模型预测 1，正确答案是 2，预测偏小了。直觉上，我们希望梯度告诉我们"怎样让 ŷ 变大"。

### 2.6.3 反向

从 L 出发往回走。每一步都用同一个规则：**本节点的梯度 = 上游梯度 × 局部导数；被多条路径用到的节点，把各路的梯度加起来。**

**第 1 步：损失层。** L = e²，局部导数 2e：

```
∂L/∂L = 1
∂L/∂e = 1 × 2e = 2 × (−1) = −2
```

e = ŷ − y，对 ŷ 的局部导数是 1：

```
∂L/∂ŷ = −2 × 1 = −2
```

**解读：** ∂L/∂ŷ = −2 是负数，意思是"ŷ 变大，L 变小"。和直觉一致：预测偏小，应该变大。

**第 2 步：输出层。** ŷ = v1·a1 + v2·a2 + c。加法把 −2 原样分给三项；每个乘法再"交换"：

```
∂L/∂c  = −2 × 1  = −2
∂L/∂v1 = −2 × a1 = −2 × 1.5 = −3
∂L/∂v2 = −2 × a2 = −2 × 1   = −2
∂L/∂a1 = −2 × v1 = −2 × 1    = −2
∂L/∂a2 = −2 × v2 = −2 × (−1) = 2
```

**解读：** ∂L/∂a2 = 2 是正数。a2 通过一个负权重 v2 = −1 连到输出，a2 变大会让 ŷ 变小、L 变大。所以"责任"的符号翻转了。

**第 3 步：relu。** relu 是开关：z > 0 时梯度原样通过。z1 = 1.5 > 0，z2 = 1 > 0，两个开关都开着：

```
∂L/∂z1 = ∂L/∂a1 × 1 = −2
∂L/∂z2 = ∂L/∂a2 × 1 = 2
```

**第 4 步：隐藏层的参数。** z1 = w11·x1 + w12·x2 + b1，加法分发、乘法交换：

```
∂L/∂w11 = ∂L/∂z1 × x1 = −2 × 2 = −4
∂L/∂w12 = ∂L/∂z1 × x2 = −2 × 1 = −2
∂L/∂b1  = ∂L/∂z1 × 1  = −2
```

隐藏神经元 2 同理：

```
∂L/∂w21 = ∂L/∂z2 × x1 = 2 × 2 = 4
∂L/∂w22 = ∂L/∂z2 × x2 = 2 × 1 = 2
∂L/∂b2  = ∂L/∂z2 × 1  = 2
```

**第 5 步：输入（梯度相加）。** 训练时我们不改输入，所以 ∂L/∂x 用不上。但它很好地展示了 2.5 节的规则：x1 同时被两个隐藏神经元用到，有两条路径：

```
∂L/∂x1 = ∂L/∂z1 × w11 + ∂L/∂z2 × w21 = (−2)×1 + 2×0.5 = −2 + 1 = −1
∂L/∂x2 = ∂L/∂z1 × w12 + ∂L/∂z2 × w22 = (−2)×(−1) + 2×1 = 2 + 2 = 4
```

如果只算一条路径，比如只算第一项，∂L/∂x1 就成了 −2，错了一倍。

为什么说 ∂L/∂x "用不上"却还要会算？因为在更深的网络里，这一层的"输入"就是上一层的输出 a，它的梯度要继续往回传给上一层的参数。每一层都在做同一件事：收到输出的梯度，算出参数的梯度和输入的梯度，再把输入的梯度交给前一层。第 31 章做 saliency 分析时，我们还会直接用 ∂L/∂(输入图片) 看模型在关注图片的哪里。

### 2.6.4 汇总

全部结果（第 4 部分）：

| 节点 | 前向值 | 梯度 ∂L/∂· |
|---|---|---|
| L | 1 | 1 |
| e | −1 | −2 |
| ŷ | 1 | −2 |
| c | 0.5 | −2 |
| v1 | 1 | −3 |
| v2 | −1 | −2 |
| a1 | 1.5 | −2 |
| a2 | 1 | 2 |
| z1 | 1.5 | −2 |
| z2 | 1 | 2 |
| w11 | 1 | −4 |
| w12 | −1 | −2 |
| b1 | 0.5 | −2 |
| w21 | 0.5 | 4 |
| w22 | 1 | 2 |
| b2 | −1 | 2 |
| x1 | 2 | −1 |
| x2 | 1 | 4 |

**停下来想一想：** 看 w11 和 w21 的梯度，一个是 −4、一个是 4。梯度下降要沿负梯度方向走，所以 w11 会变大、w21 会变小。用前向的公式想一想：这两个改动是不是都会让 ŷ 变大？

### 2.6.5 走一步：损失真的降了吗

梯度算出来了，按第 4 章会详细讲的**梯度下降**更新参数：

```
新参数 = 旧参数 − 学习率 × 梯度
```

学习率取 0.02（第 4 部分）：

| 参数 | 旧值 | 梯度 | 新值 |
|---|---|---|---|
| w11 | 1 | −4 | 1.08 |
| w12 | −1 | −2 | −0.96 |
| b1 | 0.5 | −2 | 0.54 |
| w21 | 0.5 | 4 | 0.42 |
| w22 | 1 | 2 | 0.96 |
| b2 | −1 | 2 | −1.04 |
| v1 | 1 | −3 | 1.06 |
| v2 | −1 | −2 | −0.96 |
| c | 0.5 | −2 | 0.54 |

用新参数再做一次前向：z1 = 1.74，z2 = 0.76，ŷ = 1.655，损失 L 从 1 降到 0.1192（本项目观察，第 4 部分；也可以手算验证）。预测从 1 向目标 2 靠近了一大截。

**一阶近似的预测。** 按 2.2.1 节"导数是放大倍数"，每个参数 θ 变化 Δθ，损失大约变化 Σ(梯度 × Δθ)，所有参数的贡献相加（2.5.2 节）。沿负梯度走一步时 Δθ = −学习率 × 梯度，代进去，每一项都变成 −学习率 × 梯度²，所以损失大约下降：

```
学习率 × Σ(每个梯度的平方) = 0.02 × (16 + 4 + 4 + 16 + 4 + 4 + 9 + 4 + 4) = 0.02 × 65 = 1.3
```

预测下降 1.3，实际下降 0.88（数学结论 + 本项目观察，第 4 部分）。预测甚至超过了损失本身（损失不可能小于 0），说明这一步已经大到让"线性近似"明显失准了。

**步子太大会怎样？** 把学习率换成 0.1（第 4 部分）：新参数下 z2 = −0.2 < 0，隐藏神经元 2 的 relu 被关掉了；ŷ = 4.21，冲过了目标；损失从 1 **升到** 4.884。

2.2.1 节说过导数是局部的：梯度只保证"往这个方向走一小步，损失会下降"，不保证走一大步也会下降。学习率怎样选，是第 4 章的主题。

### 2.6.6 变体：关掉的 relu

把 w21 改成 −1、目标 y 改成 3，其余不变（第 4 部分）：

```
z2 = (−1)×2 + 1×1 + (−1) = −2，a2 = relu(−2) = 0
ŷ = 1×1.5 + (−1)×0 + 0.5 = 2，e = −1，L = 1
```

反向时，∂L/∂a2 = −2 × v2 = 2，仍然不是 0。但 relu 的开关关着，到 z2 就被挡住了：

```
∂L/∂z2 = 2 × 0 = 0
∂L/∂w21 = ∂L/∂w22 = ∂L/∂b2 = 0
∂L/∂v2 = −2 × a2 = −2 × 0 = 0
```

隐藏神经元 2 的全部参数、以及连接它的 v2，梯度都是 0，这一步什么都学不到。如果对**所有**训练样本 z2 都是负的，在这个例子里（第一层、输入是固定的原始数据、纯梯度下降）这个神经元就永远学不动了，这叫**死亡 relu**（dying ReLU）。更深的网络里，输入来自可训练的上游表示，别的路径的更新可能让它重新激活，所以死亡 relu 应理解为风险，而不是一定不可逆。这也是 2.4.3 节说的第二处不准确：神经元 2 对结果当然"有关系"（它决定了 a2 = 0），但它的梯度是 0。

### 2.6.7 三方对拍

手算容易出错，怎样确认上面每个数都对？实验脚本第 4 部分用三种独立的方法算了同一个网络：

1. **我们自己的 Value 引擎**（2.7 节要写的）：梯度和 2.6.4 节的表完全一致。
2. **PyTorch autograd**：9 个参数和 x1、x2 的梯度，与 Value 的最大差 0.0e+00（本项目观察）。这里 PyTorch 用的是 float64，而这些数恰好都能在二进制浮点数里精确表示，所以差是精确的 0。
3. **数值梯度**（2.8 节要讲的"试一下"）：与 Value 的最大相对误差 2.9e-11（本项目观察）。

三种方法的原理完全不同，却给出了同样的答案。以后你写任何新的梯度代码，都应该这样对拍。

对拍用的 PyTorch 代码长这样（`tour.py` 里的 `two_layer_torch`）：

```python
t = {k: torch.tensor(val, dtype=torch.float64, requires_grad=(k != "y")) for k, val in NET.items()}
z1 = t["w11"] * t["x1"] + t["w12"] * t["x2"] + t["b1"]
z2 = t["w21"] * t["x1"] + t["w22"] * t["x2"] + t["b2"]
a1, a2 = torch.relu(z1), torch.relu(z2)
yhat = t["v1"] * a1 + t["v2"] * a2 + t["c"]
L = (yhat - t["y"]) ** 2
L.backward()
print(t["w11"].grad)       # tensor(-4., dtype=torch.float64)
```

`requires_grad=True` 告诉 PyTorch"这个数要算梯度"，`L.backward()` 做反向传播，结果存在每个叶子的 `.grad` 里。2.9 节会逐个解释这几个开关。

## 2.7 自己写一个自动求导引擎

手算一个 9 参数的网络已经要写满一页纸。我们需要让计算机自动完成 2.6 节做的事。本节写一个**标量自动求导引擎**：一个叫 `Value` 的类，它像普通的数一样可以加减乘除，但会默默记下每一步计算，最后一行 `L.backward()` 就能算出所有梯度。

代码在 `miniocr/autograd.py`，思路来自 Andrej Karpathy 的 micrograd。整个引擎的核心只有一百行左右。

### 2.7.1 Value 存什么

回想 2.4 节反向传播需要什么：

- 每个节点的**值**（局部导数要用）；
- 每个节点的**梯度**（反向时一路累加）；
- 每个节点是**由谁算出来的**（反向时要知道往哪里传）；
- 每个运算的**局部导数规则**（怎样把梯度传给输入）。

`Value` 就存这四样东西：

```python
class Value:
    def __init__(self, data, _prev=(), op="", label=""):
        self.data = float(data)           # 值：前向计算的结果
        self.grad = 0.0                   # 梯度：∂L/∂(这个数)，backward 之后才有意义
        self._prev = tuple(_prev)         # 由哪些 Value 直接算出来（计算图里的入边）
        self._backward = lambda: None     # 怎样把 self.grad 传给 _prev 里的节点
        self.op = op                      # 产生它的运算名，只用来打印
        self.label = label                # 可选的名字，只用来打印
```

叶子节点（参数、输入）的 `_prev` 是空的，`_backward` 什么也不做。每做一次运算，就生成一个新的 `Value`，它的 `_prev` 指向输入，`_backward` 是一个闭包，记住了"怎样把梯度传回去"。**图是在前向计算时顺手建起来的**，不需要事先声明。PyTorch 也是这样做的，这种方式叫"动态图"或"边运行边定义"（define-by-run）。

### 2.7.2 加法

```python
def __add__(self, other):
    other = other if isinstance(other, Value) else Value(other)   # (1)
    out = Value(self.data + other.data, (self, other), "+")       # (2)

    def _backward():                                              # (3)
        self.grad += 1.0 * out.grad
        other.grad += 1.0 * out.grad
    out._backward = _backward                                     # (4)
    return out
```

逐行解释：

**(1)** 允许 `Value + 3` 这样的写法：普通的数被包成一个叶子 `Value`。

**(2)** 前向：算出值，记下两个输入。

**(3)** 反向规则：加法是"分发器"，两个输入的局部导数都是 1，上游梯度 `out.grad` 原样累加给它们。用 `+=` 的原因在 2.5.4 节讲过。

**(4)** 把规则挂在输出节点上。注意 `_backward` 是一个**闭包**：它记住了 `self`、`other`、`out` 三个对象。等到反向传播时调用 `out._backward()`，它会读取那时的 `out.grad`，写进那时的 `self.grad` 和 `other.grad`。

### 2.7.3 乘法、幂、tanh、relu

下面四个运算是练习 2.1 和 2.2 要你自己写的。结构和加法完全一样，只有局部导数不同。

**乘法**（练习 2.1）：交换器。

```python
def __mul__(self, other):
    other = other if isinstance(other, Value) else Value(other)
    out = Value(self.data * other.data, (self, other), "*")

    def _backward():
        self.grad += other.data * out.grad
        other.grad += self.data * out.grad
    out._backward = _backward
    return out
```

**幂**（练习 2.2）：只支持指数是普通的数。

```python
def __pow__(self, k):
    assert isinstance(k, (int, float)), "只支持常数次幂"
    out = Value(self.data ** k, (self,), f"**{k}")

    def _backward():
        local = 0.0 if k == 0 else k * self.data ** (k - 1)
        self.grad += local * out.grad
    out._backward = _backward
    return out
```

k = 0 要单独处理：x⁰ 恒等于 1，导数是 0（数学结论）。如果照搬公式，x = 0 时会去算 0 ** −1，Python 直接抛出 `ZeroDivisionError`。PyTorch 对 x = 0 处的 x⁰ 也给出梯度 0。

**tanh**（练习 2.2）：利用 tanh 的导数可以用输出表示，1 − t²。前向已经算出 t，反向直接用，不必再算一次 tanh。

```python
def tanh(self):
    t = math.tanh(self.data)
    out = Value(t, (self,), "tanh")

    def _backward():
        self.grad += (1.0 - t * t) * out.grad
    out._backward = _backward
    return out
```

**relu**（练习 2.2）：开关。x = 0 处不可导，我们约定导数取 0，和 PyTorch 一致。

```python
def relu(self):
    out = Value(self.data if self.data > 0 else 0.0, (self,), "relu")

    def _backward():
        self.grad += (1.0 if self.data > 0 else 0.0) * out.grad
    out._backward = _backward
    return out
```

每个 `_backward` 里都乘了 `out.grad`，也就是"上游梯度 × 局部导数"中的"上游梯度"。2.8.6 节会看到，漏乘它是一个典型错误，而数值梯度检查能立刻抓住它。

### 2.7.4 组合运算：减法和除法不需要新代码

有了加、乘、幂，减法和除法都可以拼出来：

```python
def __neg__(self):              # −x = x × (−1)
    return self * -1

def __sub__(self, other):       # x − y = x + (−y)
    return self + (-other)

def __truediv__(self, other):   # x / y = x × y^(−1)
    return self * (other ** -1 if isinstance(other, Value) else 1.0 / other)

def __radd__(self, other):      # 3 + x
    return self + other

def __rmul__(self, other):      # 3 * x
    return self * other

def __rsub__(self, other):      # 3 - x（2.10 节的合页损失 1 - y·s 要用它）
    return Value(other) - self

def __rtruediv__(self, other):  # 3 / x
    return Value(other) / self
```

它们**不需要自己的 `_backward`**。`x − y` 在图里会变成两个节点：先一个乘法（y × (−1)），再一个加法。反向传播自动经过这两个节点，梯度自然就对了。只要基本运算的局部导数写对了，任何由它们组合出来的运算，梯度都自动正确。

代价是图会多出一些节点。2.6 节的网络里，`ŷ − y` 就生成了一个常数 −1 的叶子和一个额外的乘法节点。整个网络的计算图一共有 30 个节点，其中叶子 13 个：2 个输入、9 个参数、目标 y，以及减法生成的常数 −1（本项目观察，第 5 部分）。

`__radd__`、`__rmul__`、`__rsub__`、`__rtruediv__` 处理数字在左边的情况。Python 计算 `3 * x` 时，先调用 `int.__mul__(3, x)`，发现 int 不认识 Value，返回 NotImplemented，再调用 `x.__rmul__(3)`。2.10 节用 Python 内置的 `sum()` 累加 Value 时也依赖它：`sum` 从整数 0 开始加，第一步就是 `0 + Value`。

### 2.7.5 backward：拓扑排序

现在每个节点都知道怎样把梯度传给自己的输入。剩下的问题是：**按什么顺序调用各个节点的 `_backward`？**

规则很明确：**一个节点调用 `_backward` 之前，它的梯度必须已经收齐。** 也就是说，所有用到它的下游节点都已经把梯度传给它了。

满足这个要求的顺序，正好是**拓扑顺序的逆序**。拓扑顺序是指：每个节点都排在它所有输入的后面（"先有输入，后有输出"）。倒过来，每个节点就都排在所有用到它的节点的后面。

用深度优先搜索得到拓扑顺序：

```python
def backward(self):
    topo, visited = [], set()

    def build(v):                         # (1)
        if v not in visited:
            visited.add(v)
            for p in v._prev:
                build(p)
            topo.append(v)                # (2)
    build(self)
    for v in topo:                        # (3)
        if v._prev:
            v.grad = 0.0
    self.grad += 1.0                      # (4)
    for v in reversed(topo):              # (5)
        v._backward()
```

逐行解释：

**(1)** `build` 从根出发递归。`visited` 保证每个节点只处理一次。一个节点被用了好几次（比如 2.5 节的 x），图里有好几条路通向它，但它只该在 `topo` 里出现一次。

**(2)** 关键：**先**递归处理完所有输入，**再**把自己加进 `topo`。所以任何节点都排在它的输入后面。

**(3)** 把中间节点的梯度清零，2.7.7 节解释为什么。

**(4)** 起点 ∂L/∂L = 1。这里写 `+=`：根是中间节点时，第 (3) 步已经把它清零，结果就是 1；根本身是叶子时（比如直接调用 `x.backward()`），它也要和别的叶子一样累加（2.7.7 节），连续调用两次得到 2，和 PyTorch 一致。

**(5)** 逆序调用每个节点的 `_backward`。

用 L = (a·b + c)² 走一遍（第 5 部分，本项目观察）：

```
拓扑顺序：a → b → d → c → e → L
逆序调用：L → e → c → d → b → a
```

这个顺序可以照着代码推出来。`build(L)` 先递归进 L 唯一的输入 e；e = d + c，`_prev` 是 (d, c)，所以先进 d；d = a · b，`_prev` 是 (a, b)，a、b 是叶子，依次加入 `topo`；d 的输入处理完，d 加入；回到 e，再处理 c，c 加入；最后 e、L 依次加入。

轮到 d 时，用到 d 的只有 e，而 e 已经在前面处理过了，d 的梯度已经收齐。轮到 a、b 时也一样。c 和 d 谁先谁后无所谓，它们互不依赖；拓扑顺序一般不唯一，任何一种都可以。

### 2.7.6 顺序错了会怎样

如果不倒过来，直接按拓扑顺序（a → b → d → c → e → L）调用 `_backward`，会得到什么？实验脚本第 5 部分试了一下（本项目观察）：

```
a.grad = 0，b.grad = 0，c.grad = 0（正确是 −24、16、8）
```

全是 0。一步步看：a、b 是叶子，`_backward` 什么也不做；轮到 d 时，e 还没把梯度传过来，d 的梯度是 0，它交给 a、b 的也是 0；c 是叶子；轮到 e 时，L 还没把梯度传过来，e 的梯度也是 0，交给 d、c 的还是 0；最后轮到 L，它把 1 × 8 = 8 交给 e。可是 e 早就处理过了，这份梯度再也传不下去。

在更复杂的图里，顺序错误不一定得到全 0，而是"部分路径的梯度丢失"，看起来像是正常的数，更难发现。这类错误要靠数值梯度检查（2.8 节）来抓。

**递归深度。** `build` 是递归的，Python 默认的递归深度上限是 1000（本项目观察，第 5 部分打印了 `sys.getrecursionlimit()`）。实验脚本把 5000 次加法串成一条链再调用 `backward`，得到 `RecursionError: maximum recursion depth exceeded`（本项目观察，第 5 部分）。本章的网络最长的链只有一两百个节点，不会碰到这个限制。如果你想处理更深的图，可以把 `build` 改写成用显式栈的循环（练习 2.8）。PyTorch 的反向传播是用 C++ 写的，没有这个问题。

### 2.7.7 叶子累加、中间节点重算

`backward` 第 (3) 步把中间节点（有 `_prev` 的节点）的梯度先清零，但**不碰叶子**。为什么这样设计？

**中间节点的梯度只是这一次反向传播的草稿纸。** 如果不清零，在同一张图上调用两次 `backward`，第二次时中间节点还带着第一次的梯度，再往下传就会越滚越大，结果是错的，而且错得没有规律。

**叶子的梯度会累加，这是故意的，和 PyTorch 一样。** 实验脚本第 5 部分在 2.6 节的网络上连续调用两次 `backward`：w11 的梯度从 −4 变成 −8（本项目观察）。正好是两次梯度之和。

累加有用处：比如显存放不下一大批样本，可以分几小批分别 `backward`，梯度自动加在一起。要和一次算一大批完全一样，有一个条件：本章的损失是样本的**平均**，所以每个小批的平均损失要先乘以"这个小批的样本数 ÷ 总样本数"再 `backward`。原因是，N 个样本分成若干小批、第 k 批有 n_k 个时，总平均 = Σ (n_k / N) × 第 k 批的平均（数学结论）。不缩放的话，累加得到的是各小批平均梯度之和，K 个等大的小批会把梯度放大 K 倍。第 16 章的"梯度累积"就是这样做的。

累加也带来一个义务：**每次训练迭代开始前，必须把参数的梯度清零。** 否则这一步的梯度会和以前所有步的梯度加在一起。`miniocr/autograd.py` 提供了一个小函数：

```python
def zero_grad(params):
    for p in params:
        p.grad = 0.0
```

忘记调用它会怎样？2.9.6 节会做实验。

### 2.7.8 用 Value 重算 2.6 节

现在可以把 2.6 节的手算交给 `Value` 了（`tour.py` 里的 `two_layer_values`）：

```python
from miniocr.autograd import Value

x1, x2 = Value(2.0), Value(1.0)
w11, w12, b1 = Value(1.0), Value(-1.0), Value(0.5)
w21, w22, b2 = Value(0.5), Value(1.0), Value(-1.0)
v1, v2, c = Value(1.0), Value(-1.0), Value(0.5)

z1 = w11 * x1 + w12 * x2 + b1
z2 = w21 * x1 + w22 * x2 + b2
a1, a2 = z1.relu(), z2.relu()
yhat = v1 * a1 + v2 * a2 + c
L = (yhat - 2.0) ** 2

L.backward()
print(w11.grad, w21.grad, x1.grad)     # -4.0 4.0 -1.0
```

代码和 2.6.1 节的公式几乎一模一样。前向就是正常写算式；`L.backward()` 一行完成了 2.6.3 节整整一页的手算。测试 `test_two_layer_network_matches_chapter_and_torch` 检查这里的每一个梯度都和 2.6.4 节的表一致。

## 2.8 数值梯度检查

### 2.8.1 为什么需要检查

反向传播的代码有一个讨厌的性质：**写错了通常不报错。** 2.5.4 节的 `=` 代替 `+=`、2.7.6 节的顺序错误、漏乘一个 `out.grad`、局部导数的公式写错……程序都能正常运行，打印出的梯度看起来也像模像样。训练时 loss 可能照样下降，只是降得慢一些、停得高一些，你很可能以为是超参数没调好。

所以我们需要一个**独立的**方法来核对梯度。2.1 节的"试一下"恰好合适：它慢，但原理极其简单，几乎不可能写错。用它当标准答案，去检查反向传播算出的"解析梯度"，这就叫**梯度检查**（gradient check）。

### 2.8.2 有限差分

"试一下"的正式名字是**有限差分**（finite difference）。有两种常用写法：

```
前向差分：f′(x) ≈ [f(x + h) − f(x)] / h
中心差分：f′(x) ≈ [f(x + h) − f(x − h)] / (2h)
```

h 叫**步长**。前向差分只往右试一步；中心差分左右各试一步，用两点连线的斜率近似切线的斜率。

中心差分要多算一次 f，却准得多。为什么？下面用泰勒展开说明。

### 2.8.3 截断误差：泰勒展开

> **回顾：泰勒展开**
>
> 函数在 x 附近可以展开成多项式：f(x + h) = f(x) + h·f′(x) + (h²/2)·f″(x) + (h³/6)·f‴(x) + …。h 越小，后面的项越小。

**前向差分的误差。** 把泰勒展开代进前向差分：

```
[f(x + h) − f(x)] / h = [h·f′ + (h²/2)·f″ + (h³/6)·f‴ + …] / h
                      = f′ + (h/2)·f″ + (h²/6)·f‴ + …
```

和真正的 f′ 相比，多出来的部分以 (h/2)·f″ 为主。误差和 h 成正比，记作 O(h)。h 缩小 10 倍，误差缩小约 10 倍（数学结论）。

**中心差分的误差。** 把 h 换成 −h，得到 f(x − h) 的展开：

```
f(x + h) = f + h·f′ + (h²/2)·f″ + (h³/6)·f‴ + …
f(x − h) = f − h·f′ + (h²/2)·f″ − (h³/6)·f‴ + …
```

两式相减，偶数次项（f、f″）正好抵消：

```
f(x + h) − f(x − h) = 2h·f′ + (h³/3)·f‴ + …
[f(x + h) − f(x − h)] / (2h) = f′ + (h²/6)·f‴ + …
```

误差以 (h²/6)·f‴ 为主，和 h² 成正比，记作 O(h²)。h 缩小 10 倍，误差缩小约 100 倍（数学结论）。

这种因为"只取了泰勒展开的前几项"而产生的误差，叫**截断误差**（truncation error）。照这个分析，h 似乎越小越好。可实际并非如此。

### 2.8.4 舍入误差：h 不是越小越好

计算机里的浮点数只有有限的精度。float64 大约能保留 16 位有效数字，float32 只有 7 位左右。衡量精度的量叫**机器精度** ε：1 和比 1 大的下一个可表示的数之间的差。float64 的 ε = 2.2e-16，float32 的 ε = 1.2e-7（本项目观察，第 6 部分打印；也是 IEEE 754 标准规定的值）。

**类比：用一把只有厘米刻度的尺子量两张纸的厚度差。** 每张纸厚度都只能读到最近的厘米，两张纸差 0.1 毫米，读数却完全一样，差为 0。量的东西越接近，测量误差占的比例就越大。

有限差分恰好是在做这件事：h 很小时，f(x + h) 和 f(x − h) 非常接近，两者相减会损失大量有效数字。每个 f 值都带着约 ε·|f| 的舍入误差，相减后再除以 2h，误差被放大成大约 ε·|f| / h（数学结论，量级估计）。

**总误差 = 截断误差 + 舍入误差：**

```
中心差分：总误差 ≈ (h²/6)·|f‴| + ε·|f| / h
```

第一项随 h 减小而减小，第二项随 h 减小而增大。两项相当时总误差最小，此时 h 的量级是 ε^(1/3)（数学结论：对 h 求导令其为 0，得 h = (3ε|f|/|f‴|)^(1/3)，常数因子在 1 附近时就是 ε^(1/3) 的量级）。同理，前向差分的最佳步长是 √ε 的量级。

| | float64 | float32 |
|---|---|---|
| 机器精度 ε | 2.2e-16 | 1.2e-7 |
| 前向差分最佳步长 ≈ √ε | 1e-8 | 3e-4 |
| 中心差分最佳步长 ≈ ε^(1/3) | 6e-6 | 5e-3 |

（数学结论；float64 前向和两种精度的中心差分由第 6 部分计算打印，float32 前向差分一格是 √(1.2e-7) 的手算值。）

### 2.8.5 实测：步长和误差的表

理论说完了，实测一下。函数选一个单个神经元的损失：

```
f(w) = (tanh(1.5w) − 0.3)²，在 w = 0.7 处
解析导数 = 2(tanh(1.05) − 0.3)·(1 − tanh²(1.05))·1.5 = 0.5619483204
```

h 从 1e-1 一直减小到 1e-12，分别用 float64 的前向差分、float64 的中心差分、float32 的中心差分估计导数，算出和解析导数的相对误差（相对误差的定义见 2.8.6 节）。结果如下（本项目观察，第 6 部分）：

| 步长 h | 前向差分 float64 | 中心差分 float64 | 中心差分 float32 |
|---|---|---|---|
| 1e-1 | 6.3e-02 | 8.1e-03 | 8.1e-03 |
| 1e-2 | 5.8e-03 | 7.9e-05 | **7.9e-05** |
| 1e-3 | 5.7e-04 | 7.9e-07 | **4.5e-05** |
| 1e-4 | 5.7e-05 | 7.9e-09 | 8.7e-05 |
| 1e-5 | 5.7e-06 | 7.9e-11 | 1.0e-03 |
| 1e-6 | 5.7e-07 | **7.8e-12** | 2.0e-02 |
| 1e-7 | 5.7e-08 | 1.3e-09 | 5.7e-02 |
| 1e-8 | **2.1e-08** | 1.4e-08 | 1.0e+00 |
| 1e-9 | 1.0e-07 | 1.5e-09 | 1.0e+00 |
| 1e-10 | 9.7e-08 | 3.4e-07 | 1.0e+00 |
| 1e-11 | 1.1e-06 | 3.6e-06 | 1.0e+00 |
| 1e-12 | 8.3e-05 | 4.1e-05 | 1.0e+00 |

（加粗的是每一列的最小值附近。）

读这张表：

- **前向差分（第 2 列）**：h 从 1e-1 到 1e-7，h 每缩小 10 倍，误差缩小约 10 倍，正是 O(h)。最好的结果在 h = 1e-8 附近，约 2e-8，和理论最佳步长 √ε ≈ 1e-8 吻合。再往小，舍入误差占上风，误差反而变大。
- **中心差分 float64（第 3 列）**：h 从 1e-1 到 1e-5，h 每缩小 10 倍，误差缩小约 100 倍，正是 O(h²)。最好的结果在 h = 1e-6 附近，约 1e-11，比前向差分的最好结果准了三个数量级。理论最佳步长 6e-6 落在 1e-5 和 1e-6 之间。h 更小时误差不再规则地变化，而是忽大忽小，这是舍入误差的典型特征。
- **中心差分 float32（第 4 列）**：最好也只有 5e-5 左右，在 h = 1e-2 到 1e-3 之间，和理论最佳步长 5e-3 吻合。h ≤ 1e-8 时相对误差变成 1.0，也就是数值导数等于 0：h 比 0.7 附近 float32 能分辨的最小间隔（约 6e-8）还小，w + h 在 float32 里**就等于 w**，分子是 0。
- h = 1e-1 和 1e-2 时，中心差分 float64 和 float32 一模一样：这时截断误差远大于舍入误差，精度高低没有影响。

**结论：**

1. **用中心差分，用 float64，h 取 1e-5 到 1e-6。** `numerical_grad` 的默认值是 h = 1e-5，误差约 1e-10 量级，对检查梯度绰绰有余。
2. **千万不要在 float32 下做梯度检查。** 最好的情况也只有 1e-4 到 1e-5 的相对误差，分不清"算对了但有浮点误差"和"有个小 bug"。PyTorch 里做梯度检查时，先把模型和数据转成 `torch.float64`；`torch.autograd.gradcheck` 的默认容差是按双精度设计的，所以也建议用 float64 输入；它并不拒绝 float32，但会给出警告，而且低精度下正确的代码也可能检查不通过。
3. **h 不是越小越好。** 很多初学者的直觉是"h 取 1e-12 一定更准"，表里 h = 1e-12 时中心差分的误差是 4e-5，比 h = 1e-5 差了五个数量级。

### 2.8.6 相对误差多大算正常

有了数值梯度 n 和解析梯度 a，怎样判断它们一致？

直接看差 |a − n| 不行。梯度本身可能是 1000，也可能是 0.001，同样差 0.01，前者几乎完全一致，后者错了十倍。所以要看**相对误差**：

```
相对误差 = |a − n| / max(|a|, |n|)
```

分母取两者中较大的绝对值，这样它总在 0 到 1 之间（a、n 同号时），而且 a、n 互换结果不变。第 3 章的 3.9.4 节会用另一种常见写法，分母取 |a| + |n|。因为 max(|a|, |n|) ≤ |a| + |n| ≤ 2·max(|a|, |n|)，两种写法最多差 2 倍（数学结论）。下面的阈值只看量级，两种写法都可以用；记录结果时写明用的是哪一种。

**多大算正常？** CS231n 课程笔记给了一组经验规则（来自 CS231n "Neural Networks Part 3" 的 Gradient Checks 一节；是经验值，不是定理，待你在自己的网络上验证）：

| 相对误差 | 判断 |
|---|---|
| > 1e-2 | 梯度很可能是错的 |
| 1e-2 ～ 1e-4 | 可疑，要查 |
| 1e-4 ～ 1e-7 | 函数有折点（relu 等）时通常可以接受；全是光滑函数（tanh 等）时仍偏高 |
| < 1e-7 | 正常 |

另外，网络越深，误差会逐层积累，相对误差会自然变大一些。

实验脚本第 6 部分在一个 [2, 4, 4, 1] 的 tanh 网络（37 个参数，5 个样本，平方损失）上做了检查，并故意埋了两个 bug（本项目观察）：

| 实现 | 37 个参数中最大的相对误差 | 中位数 |
|---|---|---|
| 正确 | 2.3e-09 | 5.0e-11 |
| tanh 的导数写成 1 − x²（用了输入而不是输出） | 7.3e-01 | 2.6e-02 |
| 幂的反向忘了乘 `out.grad` | 8.0e-01 | 8.0e-01 |

正确实现的最大相对误差约 2.3e-9，两个 bug 的误差都在 1e-1 量级，差了八个数量级。梯度检查的结果通常就是这样：要么非常小，要么非常大，中间地带很少。

这张表还有两个细节：

- **tanh 的 bug，中位数只有 2.6e-02。** 最后一层的参数不经过任何 tanh 的反向，它们的梯度是对的，把中位数拉低了。所以要看最大值，不能只看平均值或中位数。
- **幂的 bug，所有参数的误差都恰好是 0.8。** 损失是 5 个平方项之和再乘以 1/5，每个平方节点的上游梯度是 0.2。漏乘它，所有梯度都变成正确值的 5 倍，相对误差 = (5 − 1)/5 = 0.8（数学结论）。一个整齐的误差往往提示"漏了一个常数因子"。

### 2.8.7 两个陷阱：折点和接近 0 的梯度

**陷阱一：折点。** relu 在 0 处有个折点，导数从 0 突然跳到 1。如果 x 离折点比 h 还近，x − h 和 x + h 就落在折点的两侧，差分算出来的既不是 0 也不是 1（第 6 部分，本项目观察）：

| x | 解析导数 | 数值导数（h = 1e-5） | 相对误差 |
|---|---|---|---|
| 2e-6 | 1 | 0.6000 | 4.0e-01 |
| 0.5 | 1 | 1.0000 | 1.8e-12 |

x = 2e-6 时，数值导数 = [relu(1.2e-5) − relu(−0.8e-5)] / 2e-5 = 1.2e-5 / 2e-5 = 0.6（数学结论）。这不是反向传播的错，是检查方法本身在折点附近失效了。在有 relu 或合页损失的网络上做梯度检查时，偶尔有一两个参数误差很大，先看看是不是有中间量恰好落在折点附近。一个简单的办法是只检查少量样本，或者用光滑的激活函数和损失做检查。

**陷阱二：两个梯度都接近 0。** 解析梯度恰好是 0（比如 relu 关着），数值梯度因为舍入误差得到 1e-11，相对误差 = 1e-11 / 1e-11 = 1.0（第 6 部分）。解析 1e-9、数值 1.1e-9，相对误差约 0.09。这两种情况其实都完全正常。所以当两个梯度的绝对值都很小（比如都小于 1e-8）时，要改看**绝对误差** |a − n|。`rel_error` 的分母里有一个 `eps=1e-12` 防止除以 0，但它不能解决这个问题，需要你自己判断。

### 2.8.8 代码

`miniocr/autograd.py` 里的两个函数（练习 2.4）：

```python
def numerical_grad(f, xs, h=1e-5):
    xs = [float(x) for x in xs]                   # (1)
    grads = []
    for i in range(len(xs)):
        old = xs[i]
        xs[i] = old + h
        fp = f(xs)
        xs[i] = old - h
        fm = f(xs)
        xs[i] = old                               # (2)
        grads.append((fp - fm) / (2 * h))
    return grads


def rel_error(a, b, eps=1e-12):
    if isinstance(a, (list, tuple)):              # (3)
        return max((rel_error(x, y, eps) for x, y in zip(a, b)), default=0.0)
    return abs(a - b) / max(abs(a), abs(b), eps)
```

**(1)** 复制一份，不改动调用者传进来的列表。

**(2)** 一定要把这一维还原。忘了还原，后面每一维都是在一个错误的点上求导，结果全错，而且不报错。

**(3)** 列表的相对误差取各分量的最大值。理由见 2.8.6 节：要看最大值。注意这里假定两个列表等长：`zip` 遇到较短的一方就停，多出来的分量会被悄悄忽略，比如 `rel_error([1., 999.], [1.])` 返回 0.0。漏掉了某个参数的梯度时，它会显示“完全一致”。自己用时最好先 `assert len(a) == len(b)`。

`f` 必须是一个"只吃 float、吐 float"的普通函数。检查一个用 `Value` 搭的网络时，可以这样包装（第 6 部分的写法）：

```python
P = model.parameters()

def f(vals):
    for p, v in zip(P, vals):
        p.data = v                      # 把参数设成 vals
    return loss_fn(model).data          # 只要前向的值

vals = [p.data for p in P]
num = numerical_grad(f, vals)
f(vals)                                 # 把参数恢复成原值
loss = loss_fn(model)
zero_grad(P)
loss.backward()
print(rel_error([p.grad for p in P], num))
```

### 2.8.9 梯度检查的做法清单

1. 用 float64。
2. 用中心差分，h = 1e-5 左右。
3. 用很小的网络、很少的样本：数值梯度要做 2N 次前向，N 大了算不完（2.1.2 节）。也可以只随机抽查一部分参数。
4. 关掉一切随机性：后面会学到的 dropout、数据增强等，两次前向必须算的是同一个函数。
5. 看相对误差的**最大值**；两个梯度都接近 0 时看绝对误差。
6. 误差大时，先排除折点：换成光滑的激活函数和损失再查一次。
7. 每写一个新的运算或新的层，都做一次梯度检查。梯度检查是写 `_backward` 时的单元测试。

## 2.9 PyTorch 的 autograd

我们的 `Value` 只能处理标量，速度也慢，但它和 PyTorch 的自动求导（autograd）在原理上是同一回事。这一节把 PyTorch 里几个最常用的开关和 `Value` 对应起来。弄清楚它们各自做了什么，以后遇到"梯度是 None""梯度越来越大""backward 报错"这类问题，你就知道该往哪里查。

### 2.9.1 requires_grad：开始记账

```python
x = torch.tensor(3.0, requires_grad=True)
w = torch.tensor(2.0)                       # 默认 requires_grad=False
y = w * x
z = y ** 2
```

`requires_grad=True` 的意思是："**这个张量要算梯度，凡是用到它的运算，都请记下来。**" 就像告诉会计"这笔钱要记账"。

记账的结果可以直接看到（第 7 部分，本项目观察）：

| 张量 | requires_grad | grad_fn | is_leaf |
|---|---|---|---|
| x | True | None | True |
| w | False | None | True |
| y = w·x | True | MulBackward0 | False |
| z = y² | True | PowBackward0 | False |

- **`requires_grad` 会传染**：只要有一个输入需要梯度，输出就需要梯度。y 的输入里有 x，所以 y 也需要。
- **`grad_fn`** 就是 `Value` 里的 `_backward` 加 `_prev`：它记录了"这个张量是用什么运算、由哪些张量算出来的"。`MulBackward0` 表示"由乘法得到，反向时按乘法的规则传梯度"。
- **`is_leaf`**：用户直接创建的张量是叶子。模型的参数都是叶子。

不需要梯度的张量（比如输入数据、w），PyTorch 不会为它们计算和累积梯度，省时间也省内存。但要分清两件事："算不算它的梯度"和"存不存它的值"。算 x 的梯度要用到 w 的值（y = w·x，∂y/∂x = w），所以 w 的值仍然会被保存下来，留给反向使用。

### 2.9.2 backward()：从一个标量往回算

```python
z.backward()
print(x.grad)    # tensor(24.)
print(w.grad)    # None
```

`z.backward()` 做的事和 `Value.backward()` 一样：从 z 出发，按拓扑逆序调用每个 `grad_fn`，把梯度**累加**到每个 `requires_grad=True` 的叶子的 `.grad` 里。

本例中 z = (w·x)² = w²x²，dz/dx = 2w²x = 2 × 4 × 3 = 24（数学结论；第 7 部分实测 x.grad = 24）。w 不需要梯度，所以 w.grad 是 None。

`backward()` 有几个规矩（第 7 部分全部实际触发了一遍，本项目观察）：

**规矩一：只能对标量调用。** 对一个形状为 (2,) 的张量调用 `backward()`，报错：

```
RuntimeError: grad can be implicitly created only for scalar outputs
```

原因：反向传播的起点是 ∂L/∂L = 1，这要求 L 是一个数。损失总是一个标量，所以训练时不会碰到这个问题。如果确实要从一个向量出发，需要自己传入起点的梯度，比如 `v.backward(torch.ones_like(v))`。

**规矩二：图用完就扔。** 对同一个 z 再调用一次 `backward()`，报错：

```
RuntimeError: Trying to backward through the graph a second time (or directly access saved tensors after they have already been freed).
```

为了省内存，PyTorch 做完一次反向就释放了图里保存的中间值（2.3.3 节说过，反向要用前向的中间值）。本例的平方和乘法要用这些保存值，所以第二次失败；有些运算（比如加法）的反向不需要保存值，第二次可能不报错，但不要依赖这一点。确实要反向两次，第一次要写 `backward(retain_graph=True)`。这时 x.grad 从 24 变成 48，**累加**了（第 7 部分）。我们的 `Value` 没有释放图，所以可以直接调用两次，效果和 `retain_graph=True` 一样（2.7.7 节）。

**规矩三：图里必须有需要梯度的东西。** 对一个由普通张量算出来的结果调用 `backward()`，报错：

```
RuntimeError: element 0 of tensors does not require grad and does not have a grad_fn
```

这个错误在实践中很常见，通常是因为忘了设 `requires_grad`，或者在 `torch.no_grad()` 里算了损失（2.9.5 节）。

### 2.9.3 .grad：只有叶子才有

`backward()` 之后，梯度存在叶子的 `.grad` 属性里。**中间结果的 `.grad` 默认是 None**（第 7 部分：y.grad 是 None，并且 PyTorch 发出一条警告）。原因还是省内存：训练时我们只需要参数的梯度来更新参数，中间结果的梯度用完就可以扔掉。

如果调试时想看某个中间结果的梯度，在 `backward()` 之前对它调用 `y.retain_grad()`。

`.grad` 的形状和张量本身完全一样。一个 (768, 768) 的权重矩阵，它的 `.grad` 也是 (768, 768)，每个位置是损失对这个元素的偏导数。

对比我们的 `Value`：每个节点都有 `grad`，中间节点也保留着（反正是标量，不占什么内存），所以 2.6 节可以把 ∂L/∂z1、∂L/∂a2 都打印出来。

### 2.9.4 梯度会累加，所以要清零

和 `Value` 一样，PyTorch 的 `backward()` 把梯度**加到** `.grad` 上，而不是覆盖。原因在 2.7.7 节讲过：方便把一大批样本拆成几小批分别反向（第 16 章的梯度累积）。

所以每一步训练都要先清零。PyTorch 里有三种写法：

```python
optimizer.zero_grad()           # 最常用：清零优化器管理的所有参数（第 4 章）
model.zero_grad()               # 清零模型的所有参数
for p in params: p.grad = None  # 手写：设成 None
```

对于这一步会收到梯度的参数，设成 None 和设成 0 的效果一样：下一次 `backward()` 时，`.grad` 为 None 的参数直接拿到新梯度，为 0 的参数在 0 上累加，结果相同。两者只在"这一步没有收到梯度"的参数上不同：`.grad` 是 None，优化器会跳过它；`.grad` 是 0，带动量或权重衰减的优化器（第 4 章）仍然会更新它。设成 None 还省掉了"把一个大张量逐个元素写成 0"的工作。近年的 PyTorch 版本里 `zero_grad()` 默认就是设成 None（参数 `set_to_none=True`，待验证：以你所用版本的文档为准）。

第 7 部分演示了手写清零：`x.grad = None` 之后，打印 `x.grad` 是 None。

**一个训练步的标准顺序：**

```python
optimizer.zero_grad()    # 1. 清零
loss = compute_loss()    # 2. 前向，建图
loss.backward()          # 3. 反向，梯度累加进 .grad（因为刚清零，所以就是这一步的梯度）
optimizer.step()         # 4. 用 .grad 更新参数
```

清零放在第 1 步还是第 4 步之后都可以，只要保证每次 `backward()` 之前 `.grad` 是空的。

### 2.9.5 no_grad 与 detach：暂停记账

有些计算不需要梯度，比如在验证集上评测、手动更新参数。这时可以暂停记账：

```python
with torch.no_grad():
    q = x * 2            # q.requires_grad 为 False，不建图
```

第 7 部分验证了：`torch.no_grad()` 里算出的 q，`requires_grad` 是 False；`x.detach()` 返回的张量，`requires_grad` 也是 False（本项目观察）。

- **`torch.no_grad()`**：一段代码里的所有运算都不记账。评测、生成文本时都用它，省内存、也更快。
- **`x.detach()`**：返回一个和 x 共享数据、但"断开了计算图"的张量。梯度不会从它流回 x。第 8 章 `MultiHeadAttention` 保存注意力权重时就用了 `w.detach()`：只是存下来看，不参与反向传播。

**手动更新参数时一定要用 `no_grad`：**

```python
with torch.no_grad():
    for p in params:
        p -= lr * p.grad
```

如果不加，`p -= ...` 这个运算本身也会被记进图里，而且 PyTorch 会因为"对需要梯度的叶子做原地修改"而报错。

### 2.9.6 忘记清零会怎样

最后做一个实验：故意不清零梯度。

**最简单的现象**（第 8 部分，本项目观察）：同一个样本 x = 2、y = 3，模型 ŷ = w·x，w 固定为 0.5 不更新，连续调用 4 次 `backward()`，不清零：

| 第几次 backward | w.grad |
|---|---|
| 1 | −8 |
| 2 | −16 |
| 3 | −24 |
| 4 | −32 |

每一次的真实梯度都是 −8（2.1.1 节），`.grad` 里却是它们的和。

**训练时的现象。** 第 8 部分用 PyTorch 在 moons 数据上（2.10.1 节）训练一个 [2, 8, 8, 1] 的 tanh 网络，学习率 0.5，对比"每步清零"和"从不清零"（本项目观察，CPU）：

| 第几步 | 每步清零：损失 | 准确率 | `.grad` 的范数 | 从不清零：损失 | 准确率 | `.grad` 的范数 |
|---|---|---|---|---|---|---|
| 0 | 0.9964 | 58.0% | 0.433 | 0.9964 | 58.0% | 0.433 |
| 10 | 0.2942 | 86.0% | 0.080 | 0.4788 | 87.0% | 1.481 |
| 50 | 0.2575 | 88.0% | 0.114 | 0.2282 | 95.0% | 3.054 |
| 100 | 0.0918 | 96.0% | 0.180 | 0.5551 | 78.0% | 4.637 |
| 200 | 0.0046 | 100.0% | 0.142 | 5.0841 | 77.0% | 5.911 |

（`.grad` 的范数是所有参数梯度的平方和再开方，衡量梯度整体有多大。）

读这张表：

- **每步清零**：梯度范数一直在 0.1 左右，损失稳步下降，200 步时训练准确率 100%。
- **从不清零**：`.grad` 是从第 0 步到现在所有梯度的累加，范数越来越大，到第 200 步约为 5.9，是正常值的四十多倍。损失先降后升，最后到 5.08，比初始值还高。
- **注意第 50 步**：不清零的版本准确率 95%，反而**比正确版本的 88% 还高**。累加的梯度像一个没有刹车的"惯性"，早期恰好推着参数冲得更快。但它停不下来，最终冲过头。

有些 bug 在训练早期看起来像是"改进"。如果你只跑了 50 步就下结论，会以为不清零效果更好。判断一个改动是否有效，要看完整的训练曲线，并且先确认代码是对的。

还要提醒一句：上面"范数越来越大、最后发散"是这一次 moons 实验的现象，不是必然规律。历史梯度方向相反时会相互抵消，累加后的范数不一定增大。比如 L = w²/2，w 从 1 开始，学习率 1，不清零时 `.grad` 依次是 1、1、0、−1（数学结论）。所以排查"是不是忘了清零"，最可靠的是受控检查：固定参数，对同一批数据连续调用两次前向和 `backward`，正确的代码两次 `.grad` 相同，忘了清零则第二次正好翻倍。

"惯性"这个说法不只是比喻。不清零时，第 t 步用来更新的是 g₁ + g₂ + … + g_t，这和第 4 章要学的**动量**（momentum）很像，区别是动量会让旧梯度按比例衰减（比如每步乘以 0.9），而这里旧梯度永远不衰减（数学结论）。没有衰减的动量很容易不稳定。

### 2.9.7 Value 与 PyTorch 对照

| 概念 | 我们的 `Value` | PyTorch |
|---|---|---|
| 一个可求导的数 | `Value(3.0)` | `torch.tensor(3.0, requires_grad=True)` |
| 哪些量要算梯度 | 所有 Value 都算 | 只有 `requires_grad=True` 的，以及由它们算出来的 |
| 记录"由谁算出、怎样反向" | `_prev` + `_backward` | `grad_fn` |
| 反向传播 | `L.backward()` | `L.backward()` |
| 遍历顺序 | 递归 DFS 做拓扑排序 | C++ 引擎按依赖关系调度 |
| 梯度存在哪里 | 每个节点的 `.grad`（中间节点也有） | 只有叶子的 `.grad`；中间结果要 `retain_grad()` |
| 叶子梯度累加 | 是 | 是 |
| 反向后释放图 | 否，可以反复 backward | 是（释放保存的中间值），再次 backward 一般要 `retain_graph=True` |
| 清零 | `zero_grad(params)` | `optimizer.zero_grad()` 或 `p.grad = None` |
| 暂停记账 | 无（直接改 `.data`） | `torch.no_grad()`、`detach()` |
| 数据类型 | 一个 Python float（float64） | 任意形状的张量，默认 float32 |

最后一行是最大的区别：PyTorch 的每个节点是一整个张量，一次矩阵乘法就是一个节点；我们的每个节点是一个数，一次矩阵乘法要拆成成千上万个节点。2.10.5 节会看到这对速度的影响。

## 2.10 用 Value 训练一个小分类器

引擎写好了，梯度也检查过了。现在用它从头训练一个真正的分类器。

### 2.10.1 数据：自己生成 moons

我们用一个经典的二维玩具数据集：**两个交错的半月形**（moons）。上面的月牙标签为 +1，下面的月牙标签为 −1。两个月牙互相咬合，没法用一条直线分开，所以模型必须学会一条弯曲的边界。

数据完全自己生成（`tour.py` 里的 `make_moons`），不需要下载任何东西：

```python
def make_moons(n, noise=0.1, seed=0):
    rng = random.Random(seed)
    X, Y = [], []
    for i in range(n):
        t = rng.uniform(0.0, math.pi)                   # 半圆上的角度
        if i % 2 == 0:                                  # 上面的月牙：单位圆的上半部分
            px, py, lab = math.cos(t), math.sin(t), 1
        else:                                           # 下面的月牙：翻转并平移
            px, py, lab = 1.0 - math.cos(t), 0.5 - math.sin(t), -1
        X.append([px + rng.gauss(0.0, noise) - 0.5, py + rng.gauss(0.0, noise) - 0.25])
        Y.append(lab)
    return X, Y
```

几点说明：

- 偶数下标是上面的月牙，奇数下标是下面的月牙，两类各占一半。
- 每个点加了标准差 0.1 的高斯噪声，让边界不那么干净。
- 最后整体平移 (−0.5, −0.25)，让数据大致以原点为中心。不平移时数据的 x 坐标在 −1 到 2 之间，神经元的输入整体偏大，更容易落进 2.4.4 节说的 tanh 饱和区，训练可能会变慢（待验证：这个对比没有放进 tour，留给你在实验四的"进一步"一项里自己测）。

训练集 100 个点（种子 0），另外生成 200 个点做测试集（种子 1）。测试集只用来最后看一眼模型对没见过的点表现如何，训练过程中不碰它。第 9 部分还生成了 200 个点做验证集（种子 2）：实验四里调学习率等设置时，比较的是验证准确率，设置定下来以后才看一次测试准确率。第 5 章会系统地讲为什么要这样划分。

### 2.10.2 模型和损失

**模型：** 用 `Value` 搭的多层感知机 `MLP([2, 8, 8, 1])`：输入 2 维，两个各 8 个神经元的 tanh 隐藏层，输出 1 个数 s（叫"打分"）。s > 0 判为 +1 类，s < 0 判为 −1 类。

参数个数：第一层 2×8 + 8 = 24，第二层 8×8 + 8 = 72，输出层 8 + 1 = 9，一共 105 个（数学结论）。

`MLP` 由 `Layer` 组成，`Layer` 由 `Neuron` 组成（练习 2.5）：

```python
class Neuron:
    def __init__(self, n_in, rng, act="tanh"):
        s = 1.0 / math.sqrt(n_in)
        self.w = [Value(rng.uniform(-s, s)) for _ in range(n_in)]   # (1)
        self.b = Value(0.0)
        self.act = act

    def __call__(self, x):
        z = sum((wi * xi for wi, xi in zip(self.w, x)), self.b)     # (2)
        if self.act == "tanh":
            return z.tanh()
        if self.act == "relu":
            return z.relu()
        return z

    def parameters(self):
        return self.w + [self.b]


class Layer:
    def __init__(self, n_in, n_out, rng, act="tanh"):
        self.neurons = [Neuron(n_in, rng, act) for _ in range(n_out)]

    def __call__(self, x):
        return [n(x) for n in self.neurons]                         # (3)

    def parameters(self):
        return [p for n in self.neurons for p in n.parameters()]


class MLP:
    def __init__(self, sizes, seed=0, act="tanh"):
        rng = random.Random(seed)
        n = len(sizes) - 1
        self.layers = [Layer(a, b, rng, act if i < n - 1 else "none")   # (4)
                       for i, (a, b) in enumerate(zip(sizes[:-1], sizes[1:]))]

    def __call__(self, x):
        for layer in self.layers:
            x = layer(x)
        return x[0] if len(x) == 1 else x

    def parameters(self):                                           # (5)
        return [p for layer in self.layers for p in layer.parameters()]
```

**(1)** 权重从 [−1/√n_in, 1/√n_in] 里均匀随机取。为什么要按 1/√n_in 缩放？同样是为了不让 tanh 一开始就饱和（第 4 章 4.8 节讲初始化时详细推导）。

**(2)** `sum(..., self.b)` 从偏置开始累加 w_i·x_i。这里 x 可以是普通的 float（第一层），也可以是 Value（后面的层），`Value * float` 两种情况都能处理。

**(3)** 同一个输入 x 被这一层的每个神经元都用了一次。这是 2.5.5 节说的分叉：反向时，x 的梯度是 8 个神经元传回来的梯度之和。我们不需要为此写任何特殊代码，`+=` 自动处理。

**(4)** 最后一层不加激活，直接输出打分。

**(5)** 三个类都有 `parameters()`，把所有 `Value` 参数收集成一个列表，训练循环靠它清零和更新。

**损失：合页损失（hinge loss）。**

```
单个样本：ℓ = max(0, 1 − y·s)
整批：    L = (ℓ₁ + ℓ₂ + … + ℓ_N) / N
```

怎样理解：y·s > 0 表示分对了；y·s ≥ 1 表示"分对了，而且有把握"，这时损失为 0，不再推它；否则损失是 1 − y·s，y·s 越小损失越大：在这个区域里损失对 y·s 的导数是 −1，y·s 每增大 1，损失就线性减小 1，直到 y·s 达到 1 为止。它用 relu 就能写出来：`(1 - y * s).relu()`。

第 3 章会讲分类任务最常用的**交叉熵损失**，它需要 exp 和 log，那时再给 `Value` 加上这两个运算（练习 2.7）。这一章只用我们已有的五种运算。

```python
def hinge_loss(model, X, Y):
    scores = [model(x) for x in X]
    losses = [(1 - y * s).relu() for s, y in zip(scores, Y)]
    return sum(losses) * (1.0 / len(X)), scores
```

### 2.10.3 训练循环

```python
X, Y = make_moons(100, seed=0)
m = MLP([2, 8, 8, 1], seed=0)
P = m.parameters()

for step in range(101):
    loss, scores = hinge_loss(m, X, Y)    # 1. 前向：建图，算损失
    zero_grad(P)                          # 2. 清零
    loss.backward()                       # 3. 反向：算出 105 个梯度
    for p in P:                           # 4. 更新：沿负梯度走一步
        p.data -= 1.0 * p.grad
```

这四步就是所有神经网络训练的骨架。第 4 章会把第 4 步换成更聪明的优化器，第 11 章以后会把模型换成 Transformer，但骨架不变。

注意第 4 步改的是 `p.data`，不是 `p` 本身。如果写成 `p = p - lr * p.grad`，只是让循环变量 p 指向了一个新的 Value，模型里的参数根本没变。这和 PyTorch 里要用 `p -= ...`（原地修改）而且要包在 `no_grad` 里，是同一个道理。

每一步都调用 `hinge_loss` 重新做前向，所以每一步都会**新建一张计算图**。旧的图在 Python 里没有引用了，会被自动回收。PyTorch 也是这样：每次前向建一张新图，`backward()` 之后释放。

一步的计算图有多大？第 9 部分统计：第 1 步的计算图有 21708 个节点（本项目观察）。100 个样本、每个样本的前向要做约 100 次乘法和差不多同样多的加法，再加上 tanh、损失，就有两万多个节点。每个节点都是一个 Python 对象。

### 2.10.5 为什么这么慢

约 24.3 秒训练 101 步，每步约 0.24 秒（本项目观察，第 9 部分，随机器负载波动）。作为对照，第 8 部分用 PyTorch 训练**同样结构**的网络、同样 100 个点，201 步只用了约 0.035 秒，每步约 0.2 毫秒（本项目观察，CPU，随机器负载波动）。两者差了三个数量级以上。（两个实验的初始化和学习率不同，这里只比较速度。）

原因不在算法：两者做的是同一种反向传播。差别在于**每个节点有多"大"**：

- `Value` 的每个节点是一个数。一个 (100, 8) 乘 (8, 8) 的矩阵乘法被拆成 6400 次乘法、6400 个 Python 对象、6400 次 Python 函数调用。Python 每做一次这样的小操作都有几十到几百纳秒的"管理开销"（量级估计，待验证）。
- PyTorch 的一个节点是一整个张量。同样的矩阵乘法只是一个节点、一次函数调用，里面的 6400 次乘法交给用 C++ 写的、经过高度优化的数值库，一口气算完。

所以从第 3 章开始，我们改用张量。但原理和本章一模一样：张量上的每个运算也有自己的 `_backward`，只是局部导数从"一个数"变成了"一个矩阵"（比如矩阵乘法的反向要用到转置，习题 C10 会让你想一想）。

## 2.11 常见错误

| 错误 | 现象 | 原因 | 怎样发现 |
|---|---|---|---|
| 反向里用 `=` 代替 `+=` | 不报错，被用了多次的变量梯度偏小 | 后一条路径覆盖了前一条（2.5.4 节） | 梯度检查；测试 x·x 的梯度是否为 2x |
| 反向顺序不对 | 不报错，部分梯度是 0 或偏小 | 节点的梯度还没收齐就往下传了（2.7.6 节） | 梯度检查 |
| 局部导数写错 | 不报错，梯度错 | 比如 tanh 的导数用了输入而不是输出（2.8.6 节） | 梯度检查，看最大相对误差 |
| 漏乘上游梯度 `out.grad` | 不报错，梯度差一个常数倍 | 只写了局部导数（2.8.6 节） | 梯度检查；误差"很整齐" |
| 忘记清零梯度 | 不报错；训练曲线异常，2.9.6 节那次是先快后发散 | 梯度不断累加（2.9.6 节） | 固定参数、对同一批数据把清零、前向和 `backward` 照原样跑两次，看第二次 `.grad` 是否翻倍 |
| 更新时写 `p = p - lr * p.grad` | 参数不变，损失不降 | 只是让局部变量指向了新对象 | 打印更新前后的某个参数 |
| PyTorch 里不加 `no_grad` 就更新参数 | 报错 "a leaf Variable that requires grad is being used in an in-place operation" | 更新操作本身被记进了图 | 更新放进 `with torch.no_grad():` |
| 中间结果的 `.grad` 是 None | 想看梯度却拿到 None | 非叶子默认不保存梯度（2.9.3 节） | 在 `backward()` 前调用 `retain_grad()` |
| 对同一张图 `backward()` 两次 | 反向要用保存值时报错 "Trying to backward through the graph a second time" | 图里保存的中间值在第一次反向后被释放（2.9.2 节） | 每步重新前向；确实需要时用 `retain_graph=True` |
| 在 float32 下做梯度检查 | 正确的代码也有 1e-4 量级的误差 | 舍入误差太大（2.8.5 节） | 改用 float64 |
| 梯度检查的步长太小 | 误差反而变大 | 舍入误差随 h 减小而增大（2.8.4 节） | h 取 1e-5 左右 |
| 数值梯度忘了还原参数 | 梯度检查全错 | 后面各维在错误的点上求导 | 检查 `numerical_grad` 调用前后参数是否相同 |
| relu 网络的梯度检查偶尔误差大 | 个别参数相对误差 0.1 量级 | 中间量落在折点附近（2.8.7 节） | 换光滑函数再查，或换几个样本 |
| 很深的图 `backward()` 报 RecursionError | Python 报错 | 递归 DFS 超过默认深度 1000（2.7.6 节） | 把拓扑排序改成显式栈 |

## 2.12 和真实框架的对应

| 本章 | PyTorch |
|---|---|
| `Value(3.0)` | `torch.tensor(3.0, requires_grad=True)`；模型参数用 `nn.Parameter`，默认 `requires_grad=True` |
| `_prev` + `_backward` | `tensor.grad_fn`，以及 `grad_fn.next_functions`（指向输入的 `grad_fn`） |
| `Value.backward()` | `loss.backward()`；底层是 `torch.autograd.backward` |
| `zero_grad(params)` | `optimizer.zero_grad()`（默认把 `.grad` 设为 None） |
| 叶子梯度累加 | 同样累加；第 16 章用它做梯度累积 |
| `numerical_grad` + `rel_error` | `torch.autograd.gradcheck(f, inputs)`：自动比较数值梯度和解析梯度；默认容差按双精度设计，建议用 float64 输入 |
| 每个运算写自己的 `_backward` | `torch.autograd.Function`：自定义运算时写 `forward` 和 `backward` 两个静态方法 |
| 直接修改 `p.data` 来更新 | `with torch.no_grad(): p -= lr * p.grad`，或者交给 `optimizer.step()` |

如果你想看 PyTorch 里一个运算的反向规则是怎样写的，PyTorch 源码里的 `tools/autograd/derivatives.yaml` 文件按运算列出了几乎所有的反向公式（待验证：文件位置以你所看的 PyTorch 版本为准）。读几行就能看出，它们和 2.7.3 节的 `_backward` 是同一个模式。

## 2.13 小结

- **导数是局部的放大倍数**：输入变一点点，输出大约变化"导数 × 变化量"。它只在一个小邻域里成立，步子太大就会失准。
- **计算图**把一个复杂的计算拆成很多简单的节点。前向沿箭头算值，并把中间值留着；每个节点只需要知道自己的局部导数。
- **链式法则在图上就是"本节点的梯度 = 上游梯度 × 局部导数"**，从损失往回一个节点一个节点地乘。几种运算的模式是固定的：加法把上游梯度原样分给每个输入，乘法给每个输入乘上"对方"的值，relu 要么放行要么挡住。从后往前走一遍，就得到损失对所有参数的导数，不需要为每个参数各走一遍，总代价和一次前向同量级。
- **一个变量被用了多次，梯度要相加**：∂L/∂x 等于每条路径的贡献之和。代码里体现为 `+=`；也因此每步训练前要把参数的梯度清零。
- **反向的顺序是拓扑顺序的逆序**：用深度优先搜索先放输入、再放自己，得到拓扑顺序，倒过来调用 `_backward`，保证每个节点往下传之前梯度已经收齐。
- **数值梯度检查**是写反向传播时的单元测试：中心差分 [f(x + h) − f(x − h)] / (2h)，用 float64、h 约 1e-5；相对误差 |a − n| / max(|a|, |n|)，正确实现通常在 1e-7 以下，bug 通常在 1e-2 以上。要看最大值，注意折点和接近 0 的梯度。h 不是越小越好：太小时舍入误差占上风。
- **PyTorch** 里，`requires_grad` 开始记账，`backward()` 从一个标量往回算并把梯度累加进叶子的 `.grad`，`zero_grad()` 清零；忘记清零时 `.grad` 是历史梯度之和；2.9.6 节那次实验里梯度范数越积越大，训练先快后发散。
- **最常见的两个错误都不报错**：反向里把 `+=` 写成 `=`，被用了多次的变量只剩一条路径的梯度，靠梯度检查抓；忘记清零，梯度不断累加，靠受控检查来抓：固定参数，对同一批数据把训练步里的清零、前向和 `backward` 照原样跑两次，正确的代码两次 `.grad` 相同，忘了清零则第二次正好翻倍（2.9.6 节）。

**术语表：** 导数（derivative）、偏导数（partial derivative）、梯度（gradient）、损失（loss）、计算图（computational graph）、叶子节点（leaf）、前向计算（forward pass）、反向传播（backpropagation）、局部导数（local derivative）、上游梯度（upstream gradient）、链式法则（chain rule）、多元链式法则、拓扑排序（topological sort）、前向模式与反向模式（forward / reverse mode）、饱和（saturation）、死亡 relu（dying ReLU）、有限差分（finite difference）、中心差分（central difference）、截断误差（truncation error）、舍入误差（round-off error）、机器精度（machine epsilon）、相对误差（relative error）、梯度检查（gradient check）、梯度清零、合页损失（hinge loss）。
