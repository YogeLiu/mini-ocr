## B.1 动机

本附录沿用 FlashAttention 论文的记号：N 是序列长度（第 8 章的 T），D 是一个头的维度，Q、K、V、O 都是 N × D。注意力要算一张 N × N 的分数表 S，再算一张同样大的权重表 P。N = 1024 时，每张表约一百万个数。

这两张表只在中间用一下，最后要的只是 N × D 的输出 O。可是标准算法把它们整张写进显存，再整张读出来。GPU 的计算单元很快，显存相对慢，这些来回搬运可能比计算本身还费时间。

能不能不存这两张表？

## B.2 直觉

想象你在一摞很长的答卷里找最高分，并按分数加权求平均。

标准做法：先把每张卷的分数抄到一个大本子上，再翻本子算权重，再翻一遍算平均。

分块做法：手边的小桌子只放得下几张卷。一次拿几张，算完就把卷子放回去，桌上只留三个数：目前的最高分、目前的权重和、目前的加权和。

这样不需要大本子。难点在于 softmax 要知道所有分数才能归一化，而分块时后面的分数还没看到。online softmax 解决这个问题。

## B.3 推导

### B.3.1 online softmax

对一行 q，维护三个量：目前的最大值 m，目前的和 l = Σ exp(sⱼ − m)，未归一化的输出 o = Σ exp(sⱼ − m) vⱼ。

新来一块分数 s，块内的 v 记作 vⱼ：

```text
m_new = max(m_old, max(s))
α     = exp(m_old − m_new)
l_new = α · l_old + Σ exp(sⱼ − m_new)
o_new = α · o_old + Σ exp(sⱼ − m_new) vⱼ
```

旧的量是按 m_old 算的，换成 m_new 要乘 α，因为 exp(s − m_new) = exp(s − m_old) · exp(m_old − m_new)。

全部处理完，输出 = o / l。分子分母同乘一个常数，softmax 不变，所以结果和一次算完相同（数学结论）。

这个归一化方法来自 Milakov 和 Gimelshein（2018）。FlashAttention 把它用到注意力上。

### B.3.2 分块

把 Q 按行切成每块 Bᵣ 行，把 K、V 按行切成每块 B_c 行。外层走 Q 的块，内层走 K、V 的块。S 和 P 只存在于快速存储，算完就丢。

### B.3.3 计数模型

下面的次数按 `tour.py` 里的实现数出来，假设是：

- 两级存储。慢速存储（显存）无限大。快速存储（SRAM）能放 M 个标量。
- Q、K、V、O 在慢速存储，运算只在快速存储里做。
- 一个标量进出慢速存储一次，记一次访问。不算缓存行、突发传输和并行度。只算前向。
- 标准注意力：S、P 放不下快速存储时，各写回一次、读出一次。Q、K、V 只读一遍，这对标准注意力有利。
- FLOPs：一次乘加算 2；除、减、exp、比较各算 1。因果 mask 不省计算。

**标准注意力**，读 Q、K、V 共 3ND，写 O 为 ND，S、P 各写一次读一次共 4N²：

标准访问 = 4ND + 4N²（数学结论）

**分块**，外层共 N/Bᵣ 块。每块读 Qᵢ，再把 K、V 完整读一遍（2ND），所以 K、V 一共读 (N/Bᵣ) · 2ND = 2N²D/Bᵣ 次。Q 读一遍、O 写一遍，合计 2ND：

分块访问 = 2ND + 2N²D / Bᵣ（数学结论，Bᵣ 整除 N）

K、V 被反复读，这是分块付出的代价。Bᵣ 越大，重读越少。

快速存储要放 Qᵢ、Oᵢ、K_c、V_c、S、P、m、l：

需要容量 = 2BᵣD + 2B_cD + 2BᵣB_c + 2Bᵣ

容量够时取 Bᵣ 约为 M/D 的量级，代入 2N²D/Bᵣ，访问次数约为 N²D²/M 的量级。这要求 M 不超过 ND 的量级（Bᵣ 不能超过 N），这时 2N²D/Bᵣ 是主项，2ND 可以忽略。这和论文给的渐近结果一致：标准 Θ(ND + N²)，FlashAttention Θ(N²D²/M)（论文报告；定理的前提以原文为准）。

**FLOPs**，按同一套计数：

- 标准 = 4N²D + 6N²
- 分块 = 4N²D + 5N² + (5 + 2D)N²/B_c + ND

主项 4N²D 完全相同（数学结论）。分块多了每块每行的缩放，少了 P 的逐元素除法。相减得到：当 (5 + 2D)/B_c + D/N > 1 时，分块的 FLOPs 更多。

所以**它省的是显存访问，不是计算量。** 计算量基本不变，常常还略多。

## B.4 数值例子

### B.4.1 输出对拍

N = 64，D = 8，float64（本项目观察，第 1 部分）。手写标准注意力和 `F.scaled_dot_product_attention` 的最大差是 3.9 × 10⁻¹⁶。分块取 (Bᵣ, B_c) = (1,1)、(4,4)、(8,16)、(16,8)、(64,64)、(5,7)，与标准注意力的最大差都不超过 5.6 × 10⁻¹⁶；加因果 mask 时不超过 6.7 × 10⁻¹⁶。

### B.4.2 online softmax 手算

分数 [1, 2, 3, 0]，每块两个（数学结论，第 2 部分）：

| 处理到 | m | l |
|---|---:|---:|
| 第一块 [1, 2] | 2 | e⁻¹ + 1 = 1.367879 |
| 第二块 [3, 0] | 3 | e⁻¹ · 1.367879 + 1 + e⁻³ = 1.553002 |

第二块把最大值从 2 改成 3，旧的 l 乘 α = e⁻¹。前两个位置的结果是 0.087144、0.236883，和一次 softmax 相同。

### B.4.3 N = 16，D = 4，Bᵣ = B_c = 4

手算（数学结论，第 3 部分，计数器结果相同）：

| | 标准 | 分块 |
|---|---:|---:|
| 读 | 704 | 576 |
| 写 | 576 | 64 |
| 访问合计 | 4·64 + 4·256 = **1280** | 2·64 + 2·256·4/4 = **640** |
| FLOPs | 4096 + 1536 = **5632** | 4096 + 1280 + 13·64 + 64 = **6272** |

访问是标准的 0.5 倍，FLOPs 是标准的 1.11 倍。快速存储峰值 104 个标量。

### B.4.4 块大小扫描

N = 64，D = 8。标准注意力访问 18,432 次，FLOPs 155,648（数学结论，第 4 部分）：

| Bᵣ, B_c | 访问 | 访问比 | FLOPs 比 | 快速存储峰值 |
|---|---:|---:|---:|---:|
| 1, 1 | 66,560 | 3.61 | 1.53 | 36 |
| 4, 4 | 17,408 | 0.944 | 1.115 | 168 |
| 8, 8 | 9,216 | 0.5 | 1.046 | 400 |
| 16, 16 | 5,120 | 0.278 | 1.012 | 1,056 |
| 32, 32 | 3,072 | 0.167 | 0.994 | 3,136 |
| 64, 64 | 2,048 | 0.111 | 0.986 | 10,368 |

三点：

- 块太小时，访问比标准还多。K、V 被重读太多次。
- 除了块极小的第一行，FLOPs 比都接近 1。
- 最后两行低于 1，来自 P 的逐元素除法被省掉（除法移到了输出上），和分块本身无关。

### B.4.5 给定快速存储容量

`choose_blocks` 在 2 的幂里搜索放得下的块大小（数学结论，第 5 部分）：

| N, D | M | Bᵣ, B_c | 分块访问 | 标准访问 | 访问比 | FLOPs 比 |
|---|---:|---|---:|---:|---:|---:|
| 64, 8 | 256 | 8, 2 | 9,216 | 18,432 | 0.5 | 1.253 |
| 64, 8 | 1,024 | 32, 4 | 3,072 | 18,432 | 0.167 | 1.115 |
| 64, 8 | 4,096 | 64, 16 | 2,048 | 18,432 | 0.111 | 1.012 |
| 64, 8 | 16,384 | 64, 64 | 2,048 | 2,048 | 1 | 0.986 |
| 1024, 64 | 65,536 | 256, 32 | 655,360 | 4,456,448 | 0.147 | 1.012 |
| 1024, 64 | 262,144 | 1024, 32 | 262,144 | 4,456,448 | 0.059 | 1.012 |

M 只是教学取值，不代表某款 GPU。M = 16,384 那行，S、P 都放得下快速存储，两种算法访问相同，分块没有优势。

### B.4.6 反向与重算

反向需要 P。不存的话，就在反向时重算一遍，思路和 16.8 的梯度检查点相同。

用 `SavedTensors` 数保存量（单位是字节），D = 8，Bᵣ = B_c = 8（本项目观察，第 6 部分）：

| N | 标准 | 分块，直接用 autograd | 分块加重算 |
|---:|---:|---:|---:|
| 32 | 16,384 | 49,408 | 8,192 |
| 64 | 49,152 | 177,152 | 16,384 |
| 128 | 163,840 | 667,648 | 32,768 |

这三个 N 上，标准恰好等于 8N² + 256N，重算恰好等于 256N。前者里的 8N² 对应 float64 的 P；重算没有 N² 项。三种写法的梯度差都不超过 1.4 × 10⁻¹⁵。

直接用 autograd 跑分块，保存得反而最多，因为每块的中间结果都被留下了。这个实验只用 checkpoint 演示重算。真实内核手写前向和反向（待验证，以所用版本的代码为准）。

## B.5 代码

核心是 `tile_row`，算一个外层块。去掉计数后：

```python
m = torch.full((Br,), -math.inf, dtype=q_i.dtype)
l = torch.zeros(Br, dtype=q_i.dtype)
o = torch.zeros(Br, D, dtype=q_i.dtype)
for j in range(0, N, Bc):
    k_j, v_j = k[j:j+Bc], v[j:j+Bc]
    s = q_i @ k_j.T/math.sqrt(D)
    if mask_i is not None:
        s = s.masked_fill(~mask_i[:, j:j+Bc], -math.inf)
    m, l, o = online_softmax_update(s, m, l, o, v_j)
return o/l.unsqueeze(-1)
```

更新函数对应 B.3.1 的公式：

```python
m_new = torch.maximum(m_old, s.amax(-1))
safe_m = torch.where(m_new > -math.inf, m_new, torch.zeros_like(m_new))
weights = torch.where(s > -math.inf, (s-safe_m.unsqueeze(-1)).exp(), torch.zeros_like(s))
alpha = torch.where(m_old > -math.inf, (m_old-safe_m).exp(), torch.zeros_like(m_old))
return m_new, alpha*l_old+weights.sum(-1), alpha.unsqueeze(-1)*o_old+weights @ v
```

`safe_m` 处理一整块都被 mask 挡住的情况。这时 m 还是 −inf，直接相减会得到 inf − inf = NaN。

这是教学实现：Python 循环，不做并行，也不跳过 mask 全挡住的块。它的 CPU 速度没有参考价值。实际使用时调 `F.scaled_dot_product_attention`，由 PyTorch 选后端（待验证，取决于版本和设备）。

## B.6 常见错误

| 错误 | 现象 | 怎样发现 |
|---|---|---|
| 换最大值时忘了乘 α | 输出错，换块大小结果也变 | 用多种块大小和标准注意力对拍 |
| 全挡住的块没处理 | NaN | 加因果 mask 对拍（B.4.1） |
| 以为它减少了计算量 | 用 FLOPs 估算提速，估不出来 | 看 B.3.3：主项相同 |
| 块取得太小 | 访问比标准还多 | B.4.4 的第一行 |
| 用 float32 对拍，以为分块实现错了 | 差值停在舍入误差量级 | 换 float64 再比 |
| 直接 autograd 就以为省了显存 | 保存量比标准还大 | 用 `SavedTensors` 数（B.4.6） |

## B.7 小结

- 分块注意力用 online softmax，每行只留 m、l、o 三个量，不把 S、P 写回显存。最大值从 m_old 变成 m_new 时，旧的 l 和 o 都要乘 α = exp(m_old − m_new)，最后输出 o / l。输出和标准注意力一致，float64 下差在 10⁻¹⁵ 以内。
- 本书的计数模型里，标准访问 4ND + 4N²，分块访问 2ND + 2N²D/Bᵣ（多出来的是 K、V 被每个外层块重读）。块越大访问越少，块太小反而比标准更多。
- FLOPs 的主项都是 4N²D。它省的是显存访问，不是计算量。
- 反向要靠重算，直接用 autograd 拿不到这份节省。
- 最常见的错误：换最大值时忘了乘 α；整块被 mask 挡住时 m 仍是 −inf，不处理就出 NaN。
