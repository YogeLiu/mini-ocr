# 第 12 章实验手册：预训练数据

## 0. 准备

在 `course-v4/` 下运行：

```bash
CUDA_VISIBLE_DEVICES="" python -m book.part2_lm.ch12_pretrain_data.tour
CUDA_VISIBLE_DEVICES="" python -m pytest -q book/part2_lm/ch12_pretrain_data
```

模块名后可指定一个或多个部分号，范围为 1–10。各部分可独立运行：

```bash
CUDA_VISIBLE_DEVICES="" python -m book.part2_lm.ch12_pretrain_data.tour 4
CUDA_VISIBLE_DEVICES="" python -m book.part2_lm.ch12_pretrain_data.tour 10
CUDA_VISIBLE_DEVICES="" python -m book.part2_lm.ch12_pretrain_data.tour --small 6
CUDA_VISIBLE_DEVICES="" python -m book.part2_lm.ch12_pretrain_data.tour 1 2 5 6 --sample 5000 --seed 1
```

默认 `--sample 20000`，取 `load_formulas(seed=...)` 打乱后的前缀；默认 `--seed 0` 控制探索抽样和 MinHash。标准划分仍固定为 `latex-v1`、协议种子 0，分词器仍只用标准训练集。`--small` 主动使用 `SAMPLE_FORMULAS` 并警告；缺少本地 parquet 时也警告并自动降级。样例仅供流程检查，不能代替真实语料结论。

脚本只使用 CPU，设置 OMP、MKL、OpenBLAS 与 PyTorch 为两条计算线程；HF 离线，不联网、不下载、不训练模型。第 9 部分训练的是 BPE 合并表。token 缓存在运行时创建的 `outputs/book/ch12/` 下；当前版本使用终端直方图与概率表，不生成图片，后续绘图也应放在该目录。正式与样例文件分别以 `train`、`sample_train` 为前缀。再次运行会重写对应 token 文件，不缓存过期的分词器。

### 数据口径

| 部分 | 输入与上限 | token 口径 |
|---|---|---|
| 1、2、8 | 探索样本，默认前 20000 条 | 规范键按空格切分；第 2 部分另报规范化前 LaTeX token 数 |
| 3 | 全语料；已有规范键打乱后取 2000、20000、100000、全部的嵌套前缀；另读同快照原文列作 strip 基线 | 规范键分组；不编码 BPE |
| 4 | 指定公式对及 240 对受控随机集合 | 公式对取规范 token 的 3-gram；随机集合直接作 shingle 集 |
| 5、6 | 探索样本先精确去重；第 6 部分取前至多 2000 条及较短的 2000 条分别暴力核验 | 规范 token 的 3-gram 集合 |
| 7 | 探索样本前至多 2000 条 | 弱语法检查和 mathtext 解析 |
| 9 | 标准 train 前至多 20000 条，2000 次 BPE 合并 | 每条 BOS…EOS，uint16 小端 |
| 10 | 完整探索样本（默认 20000 条）处理至弱语法检查；mathtext 另取剩余样本前至多 2000 条作子集估计 | 规范 token；不借用第 9 部分 BPE |

`load_formulas` 已执行 `clean_formula`，所以第 10 部分的清洗步骤可能没有删除。第 3 部分的原串基线只保留清洗后非空的记录，与后两层使用相同分母。第 3 部分审计标准 train 前 20000 条、完整 val/test 的规范键交集；测试集不参与模型训练或评测。原串随机划分反例将与标准 val 相同数量的行留出，其余全部作为训练；这只是泄漏机制演示，与标准审计的训练条数不同。

`is_well_formed` 是弱语法检查；`can_parse` 使用 matplotlib mathtext，只支持 LaTeX 子集。两者都不是语义正确性的裁判。第 7、10 部分共享按原文缓存的解析结果，完整运行和单独运行的数字应一致，用时会因共享计算不同而改变。

所有输出中的比例均为 0–1，浮点数保留四位小数。保留完整日志、命令、种子、实际条数与每部分用时；不要将样例统计或运行前的预测写成真实结果。

## 1. 语料探索（12.1）

**做什么：** 比较字符长度与规范 token 长度的五个分位点，画规范 token 长度的终端直方图；统计命令频率、只出现一次的命令种数，以及分式、上下标、环境、伸缩括号、文本、汉字和矩阵类结构比例。查看极长、极短、花括号不配对及可疑文本样例。

**预测题：** 运行前预测 p99 与 p50 的差距。频率最高的命令是否也最容易被编译器拒绝？极长公式一定是坏数据吗？

**读哪些输出行：** `长度口径`、`规范token区间`、`命令频率前20`、`仅出现一次的命令种数`、`结构`、`异常类型`。例子会截断，截断文本不能直接用于合法性判断。

**对照代码：** [tour.py](tour.py) 的 `part1`、`structures`、`balanced_braces`；[latex_norm.py](../../../miniocr/eval/latex_norm.py) 的 `tokenize_latex`。

**怎样读结果：** 直方图按条数计数，结构标签可重叠，所以结构比例不要求相加为一。“只出现一次”指当前抽样范围；增大样本可能改变长尾统计。异常类别只是检查线索，不自动删除。

## 2. 规范化（12.2）

**做什么：** 对照空格、花括号、上下标、同义命令、伸缩括号与间距的规范键；统计 token 总数变化，以及原串不同却落入同一规范键的组数。用两个缺右花括号的写法观察真实回退行为。

**预测题：** `x^2` 规范化后会变长还是变短？`x^2_i` 与 `x_i^2` 的键会相同吗？解析失败后 `\dfrac` 还会统一为 `\frac` 吗？

**读哪些输出行：** `原串` 与 `规范键`、`长度变化率`、`原串不同但键相同组数`、`盲区原串` 与 `等于清洗原串`。

**对照代码：** `tour.part2`；[latex_corpus.py](../../../miniocr/data/latex_corpus.py) 的 `normalization_key`；`latex_norm.py` 的逐 token 规则、解析与序列化。

**怎样读结果：** 长度变化比较的是 token 数，增加可能来自显式补齐参数花括号。统计的是组数，不是删除条数。语法失败时 `normalization_key` 退回清洗原串，与 `normalize_latex` 的逐 token 回退不同；不要混用两个口径。

## 3. 精确去重（12.3）

**做什么：** 在全语料上比较原串 strip、清洗、规范键三种重复数，打印最大的规范键组。复用已算好的全语料规范键，以探索种子打乱后，比较前 2000、20000、100000、全部条目的规范键重复条数与比例；不足上限时按实际长度截断，相同长度只打印一次。核验标准划分三个两两交集，再构造按行随机划分的泄漏反例。

**预测题：** 先写下三层去重各会删除多大比例，预测它们是否必然单调。只随机打乱行顺序，能避免等价公式进入验证集吗？

**读哪些输出行：** `去重口径`、`重复条数`、`组大小`、`全语料三级计数用时秒`、`规模效应前缀条数`、`规范键重复条数`、`规范键重复比例`、`标准划分比较`、`规范键交集`、`泄漏验证样本数`。核对两个实验打印的训练规模。

**对照代码：** `tour.raw_formulas`、`part3`、`Experiment.split`；[dedup.py](../../../miniocr/data/dedup.py) 的 `exact_key`、`exact_dedup`；`latex_corpus.standard_split`。

**怎样读结果：** SHA-256 为规范键提供固定长度标识，不增加语义能力。稳定去重保留首次原文，不输出规范化后的字符串。标准协议将完整规范键组分配到同一集合；此处零交集是对指定子集的实测，协议本身对完整训练集也保证分组不跨界。随机划分的泄漏数按验证样本条数计，不按不同键计。

规模表的重复条数为 `n - 不同规范键数`，比例的分母为当前前缀 n。小样本可能只删除少量记录；随着样本增大，同组成员更容易同时出现，因此不能用小样本重复率代表全语料。随机前缀的实测比例不保证每一步都单调上升。这里重新打乱的是已有键，顺序可能与探索样本不同，也不受 `--sample` 上限影响；不重新解析公式。

## 4. MinHash 原理验证（12.4）

**做什么：** 比较四类公式对的精确 Jaccard 与 k=16、64、256 的签名估计。再生成交集大小不同的受控随机集合，统计估计误差，对照 `sqrt(J*(1-J)/k)` 的均方根。

**预测题：** k 增大四倍，理论标准差怎样变化？一对公式的误差是否每次都会随 k 单调变小？为什么用 token shingle 而不是字符切片？

**读哪些输出行：** `左shingle数`、`右shingle数`、`精确J`、`估计k...`、`有符号误差均值`、`绝对误差均值`、`误差标准差`、`理论均方根标准差`。

**对照代码：** `tour.part4`；`dedup.MinHasher`，尤其练习 `12.1`。先把每个 shingle 的稳定 blake2b 64 位哈希 mod p 得到 x，再广播计算 `(k, m)` 哈希矩阵，最后按行取最小值。`_hashes` 直接计算 `(a[:, None] * x[None, :] + b[:, None]) % P`；测试用 Python 任意精度整数独立核验随机系数及边界值。

这里选梅森素数 `p = 2**31 - 1`：`0 <= x < p`、`1 <= a < p`、`0 <= b < p`，所以 `a*x+b < 2**62`，乘加结果放得进 uint64，无需拆位模乘。31 位值域足够本章规模的近似候选筛选，但不保证无碰撞：理想均匀假设下，单对不同 shingle 的碰撞概率约为 `1/p`，m 个不同 shingle 的期望碰撞对数约为 `m*(m-1)/(2*p)`。这是概率量级说明，并非实测数字；最终删除仍须原始 shingle 集合的精确 Jaccard 核验。一次构造矩阵的临时内存为 `O(k*m)`，适用于本章公式长度；超长文本应另考虑分块。

**怎样读结果：** Jaccard 比较集合，丢失频次与部分顺序。空集对空集约定为一；空集签名全为 uint64 最大值。随机对使用人造集合以覆盖多个 J 区间，不冒充真实语料相似度分布。通用哈希并非严格的独立随机排列，理论曲线是近似参照；不同 k 的实验也不要求共用全部系数。

## 5. LSH 取舍（12.5）

**做什么：** 固定 k=128，比较 `(b,r)=(32,4)、(16,8)、(8,16)` 的近似阈值、四个相似度处的理论命中率和实测候选数量。候选使用同一批真实样本的签名。

**预测题：** 固定 `b*r`，增加 b、减少 r，阈值向哪边移动？候选数和漏召回风险各怎样变化？

**读哪些输出行：** `理论阈值`、`命中概率s...`、`实际候选对数`、`暴力对数`。计算候选与全部两两比较的比例。

**对照代码：** `tour.part5`；`dedup.lsh_candidates` 的练习 `12.2`，以及 `lsh_probability`、`lsh_threshold`。

**怎样读结果：** `(1/b)**(1/r)` 是近似转折点，不是一个硬截断；真正的候选概率是 `1-(1-s**r)**b`。`b*r<k` 时只用签名前若干行；大于 k 必须报错。实现没有截断大桶，极端同质语料仍可能产生二次数量的候选。

## 6. 近重复去重（12.6）

**做什么：** 先规范键精确去重，再以 n=3、k=128、b=16、r=8、阈值 0.8 运行近重复去重。LSH 仅提候选，精确 Jaccard 核验后用并查集合簇。打印真实簇、人造语义反例，并在前至多 2000 条上暴力找全真对，计算召回。样本更多时，另外选字符长度较短的 2000 条作诊断；该选择不依据 LSH 命中。

**预测题：** 假阳性候选会不会直接导致删除？若 A 接近 B、B 接近 C，能否断定 A 接近 C？相同结构但右端数值不同的等式适合自动合并吗？

**读哪些输出行：** `候选对数`、`核验通过对数`、`假阳性数`、`簇数`、`非单例簇数`、`删除条数`、`计时来源`、`签名用时秒`、`LSH+核验用时秒`、`near_dedup完整用时秒`、`暴力对数`、`LSH漏对数`、`召回率`。

**对照代码：** `tour.part6`；`dedup.near_dedup` 的候选核验与并查集。

**怎样读结果：** `簇数`包含单例簇；每簇保留最早的输入下标，顺序稳定。核验通过对数不等于删除条数。召回只针对打印的暴力子集；没有真对时不定义召回。较短公式子集的分布与随机前缀不同，不能将其召回推广到全部语料。人造反例被明确标出，不声称来自语料。精确 Jaccard 能排除候选误报，却不能区分数学含义；连通分量还会放大相似链的影响。

计时在 `near_dedup` 内记录：签名用时含 shingle 构造，LSH+核验用时含并查集合簇，两者之和为完整近重复流程用时。完整 tour 的第 5 部分先执行这段流程，第 6 部分复用其结果及首次实际计时，并明确打印来源；单独运行第 6 部分则现场计算。这里不含规范键精确去重和暴力召回诊断；`第 6 部分用时秒` 是该部分自身的实际墙钟耗时，不能与已在第 5 部分消耗的流程用时再次相加。

## 7. 能否编译过滤（12.7）

**做什么：** 在同一批至多 2000 条上比较弱语法检查与 mathtext，打印 2×2 交叉表；按矩阵、文本或汉字、别名或省写分类检查失败率。另用已知合法 LaTeX 和缺花括号的坏串核验。

**预测题：** `pmatrix`、`\le`、`\frac12` 会被哪种检查拒绝？若删除全部 mathtext 失败项，保留下来的结构分布会向哪边偏移？

**读哪些输出行：** `弱检查通过率`、`mathtext通过率`、四行交叉计数、各类 `mathtext失败率`、`人造核验例`。

**对照代码：** `tour.part7`、`Experiment.parse`；`latex_norm.is_well_formed` 与 [render.py](../../../miniocr/eval/render.py) 的 `can_parse`。

**怎样读结果：** 类别可重叠，分母是各类实际条数；零条时不报告假造的失败率。弱检查通过但 mathtext 拒绝的真实样本不一定合法；已知合法的误删证据来自明确标注的人造例子。工具支持不全导致的结构偏差，不能解释成该类语料质量差。

## 8. 数据混合（12.8）

**做什么：** 按规范 token 长度中位数与矩阵标记分成短公式 A、长公式或矩阵 B。用 B 的 token 配额 0%、10%、30%、50% 计算期望条数、平均长度、矩阵占比、命令分布到 B 的 TV 距离与重复 epoch。

**预测题：** 若 B 平均更长，30% 的条数配额对应的 token 配额会高于还是低于 30%？增加 B 的 token 配额是否必然改善模型？

**读哪些输出行：** 两源条数和 token 总数、`B的token配额`、`B的期望条数占比`、`若按条数混合同一比例_B实际token占比`、`命令TV距离`、两个 `重复epoch`。

**对照代码：** `tour.part8` 的期望条数 `预算*token配额/源平均长度`，命令频数加权与归一化。

**怎样读结果：** 混合是确定性加权计算，期望条数可以是小数；token 预算固定为两源原有规范 token 总数。重复 epoch 等于分配 token 数除以可用 token 数，超过一表示上采样。TV 的目标源 B 是教学选择；无命令时不定义距离。所有指标描述数据，没有训练证据就不能声称模型效果改善。

## 9. token 文件与缓存键（12.9）

**做什么：** 用标准训练集训练 BPE，把逐条 BOS…EOS 序列拼接成小端 uint16 文件；只读 memmap 读回并逐编号核对。更换分词器和数据版本分别触发 `StaleCacheError`，再观察绕过校验直接错解码的结果。错误分词器只取原训练列表前半、至多 1000 次合并，同时展示编号越界与编号未越界但文本错乱两种情况；样例合并不足时用更少合并。

**预测题：** 两个词表大小一样但合并顺序不同的分词器能共用文件吗？只检查文件长度能发现这种错误吗？错误分词器会总是输出乱码，还是也可能直接越界？

**读哪些输出行：** `BPE合并`、`词表`、`token总数`、`文件字节数`、`每token字节`、`cache_key前16位`、`memmap读回一致`、两种 `捕获异常`、`直接错解码` 与共有编号对照。

**对照代码：** `tour.part9`；[token_file.py](../../../miniocr/data/token_file.py) 的 `cache_key`、`write_token_file`、`load_token_file`；[latex_lm.py](../../../miniocr/data/latex_lm.py) 的 `train_tokenizer`、`encode_formulas`。

**怎样读结果：** 摘要包含合并规则及顺序、特殊符号及顺序、预分词规则、数据版本和格式版本；不能仅依赖词表大小。数据版本由调用者维护，内容变化必须升级版本。元数据还记录公式数、原文 UTF-8 字节数、dtype 和字节序。文件大小须恰好为 token 数乘二；大小校验不能检测等长损坏。空文件无法 memmap，因此空语料返回只读空数组。BOS/EOS 不计入原文 UTF-8 字节数。

## 10. 数据报告（12.10）

**做什么：** 从完整探索样本（默认 `--sample 20000`）开始，依次清洗去空、规范键去重、近重复合簇、弱语法检查。近重复参数与第 6 部分一致：n=3、k=128、b=16、r=8、阈值 0.8，使用同一探索种子。每一步报告剩余量、删除量与比例、规范 token 总数、平均长度、矩阵与文本比例，并打印本步删除例子。随后只取弱语法检查后前至多 2000 条作 mathtext 硬过滤子集示范，单列子集条数、删除条数与比例、子集剩余量及删除例子。

**预测题：** 哪一步删得最多？哪一步最可能改变矩阵占比？若最后平均长度缩短，是否足以说明数据更好？

**读哪些输出行：** `报告原始样本数` 和每行 `步骤`，重点对照 `本步删除比例`、`token总数`、`矩阵比例`、`文本比例` 与 `本步删除代表`。另看 `子集示范`、`子集来源`、`子集条数`、`子集删除比例`、`子集剩余条数` 和 `探索样本最终剩余条数`。

`子集阶段=过滤前/过滤后` 两行按主报告相同口径列出 mathtext 子集的规范 token 总数、平均长度、矩阵比例和文本比例，便于比较过滤前后的分布。

**对照代码：** `tour.part10` 的流水线与内部 `report`，再追踪前述去重和解析模块。

**怎样读结果：** 主报告删除比例的分母是上一步剩余条数，不是最初条数；各步比例不能直接相加。mathtext 的删除比例只以子集条数为分母，子集为空时不定义比例。它不改变主报告在弱语法检查后的最终剩余条数，也不估算全样本删除量。前缀选择和前序过滤会影响结构分布，按子集比例外推不可靠；mathtext 自身的支持范围还会造成有损过滤偏差。独立运行第 10 部分会自行计算相同流程，不依赖前面部分的打印，也不训练分词器或模型；完整 tour 可复用第 5、6 部分的近重复结果及第 7 部分的解析缓存。
