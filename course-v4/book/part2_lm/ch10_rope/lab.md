# 第 10 章实验手册：位置编码与 RoPE

## 0. 准备

在 `course-v4/` 下运行：

```bash
CUDA_VISIBLE_DEVICES="" python -m book.part2_lm.ch10_rope.tour
CUDA_VISIBLE_DEVICES="" python -m pytest -q book/part2_lm/ch10_rope
```

模块名后可指定部分号，例如 `3 4 5`。全部运算在 CPU 上，使用两条计算线程。只读本地数据，不联网、不下载、不安装、不保存模型权重。缺少语料缓存时，共享工具会警告并降级为内置样例；此时数字只能验证流程。图片写入 `outputs/book/ch10/distance_base.png`，再次运行第 7 部分会覆盖它。

默认对照用同一个 GPT：一层、维度 64、两个头、训练上下文 64、批量 64、600 步、学习率 0.0030、种子 0。AdamW 权重衰减 0.0100，fp32，无预热、无梯度裁剪。共同参数用相同初值，各模型抽取相同目标批次。学习式位置额外增加一张可训练表，不能声称三者参数量完全相等。默认长窗口评测为 128；四分钟预算针对默认完整 tour，改大模型或评测窗口会增加用时。

### 数据与评测口径

直接使用 `miniocr/data/latex_lm.py`。在 `latex-v1` 标准训练集前 20000 条上训练 2000 次合并的 BPE，加入 BOS/EOS；只评测 val 前 2000 条，测试集不参与。训练均匀抽取目标，每条公式单独添加边界，不跨公式。每个内容 token 和 EOS 都作为一次验证目标，BOS 只作条件并从输出分布中屏蔽。

长公式逐目标滑窗，每次保留最近的 context 个输入，不截断目标；窗口内位置从零开始。右侧补齐不影响此前真实位置的因果注意力。`last_logits` 只投影最后一个真实位置，测试与完整 GPT 前向对拍。

`nat/token = 总 NLL / 目标数`；`bits/byte = 总 NLL / (ln(2) × 原文字节数)`。原文字节不含 BOS/EOS，不按公式等权平均。不同窗口评测完全相同的目标及字节，较长窗口会提供更多上文，因此窗口对照同时含有“更多内容”与“超出训练位置范围”的影响。

### 数学结论与实验边界

无 mask、无位置的自注意力对输入置换等变；输出集合相同，不代表同一位置的输出相同。因果 mask 会提供隐式顺序信息，不能由第 1 部分推断所有无位置 GPT 都完全不知道顺序。

正弦编码自身的点积只依赖距离，但经过任意 q/k 投影后，位置项未必仍有这个性质；内容和位置还产生两项交叉项。RoPE 的相对位置结论针对固定 q、k 的旋转点积。实际深层模型中的 q、k 也受上文影响，不能把它解读为任意两段文本只要距离相同就有相同分数。

本书的“前后两半”把 `(i, i+dh/2)` 配成平面；“相邻两维”把 `(2i, 2i+1)` 配成平面。维度置换后数学等价，迁移模型时须对每个头的 q/k 投影输出通道作相应置换，不能直接换一个旋转函数。

第 7 部分画的是全 1 向量的点积振荡核。“平均意义上的上界式衰减”不是逐个距离、逐对 q/k 的单调保证。图上会出现反弹，甚至负值；不应把曲线当成所有内容分数的严格上界。增大 base 让低频旋转更慢，最高频保持不变，不能据此保证模型能处理更长文本。

第 8 部分用连续边界 L 和 4L 比较相位，实际长度 L 的最后位置为 L−1。超出训练角度范围指未取模相位及距离的覆盖变化，不是三角函数无定义。位置插值把所有位置除以倍率，同时压缩相邻位置差；增大 base 对不同频率的影响不同。

公共 GPT 仍会检查 `block_size`。本章的 `PositionGPT.set_context` 对 RoPE/无位置重建数值表，解除这个实现限制；它没有增加训练或插入未知权重。学习式表不会被静默扩展或循环使用。数值上可运行与验证质量保持是两件事，所有训练结论仅代表一次种子的短训观察。

## 3. 实验一：base 与 LaTeX 验证

**预测：** base 从 100 增加到 10000、再到 1000000，哪些频率变化最大？先看第 7 部分，再写下验证 loss 的预测，并说明为什么单凭振荡曲线无法决定胜负。

**运行：**

```bash
CUDA_VISIBLE_DEVICES="" python -m book.part2_lm.ch10_rope.tour 9 --modes rope --base 100
CUDA_VISIBLE_DEVICES="" python -m book.part2_lm.ch10_rope.tour 9 --modes rope --base 10000
CUDA_VISIBLE_DEVICES="" python -m book.part2_lm.ch10_rope.tour 9 --modes rope --base 1000000
```

**观察：** 三次都从头训练；只改变 base，其他配置及目标批次不变。分别比较上下文 64 与 128 的完整验证。不要把训练区间均值当作训练集全量结果。

**记录：** 记录 base、训练时间、两种验证指标及外推差值。若差异很小，换种子重复，再判断是否稳定。实验一组命令的总耗时不属于单次默认 tour 的预算。

## 4. 实验二：训练上下文 32，评测 32/64/128

**预测：** 更多上文一定改善验证吗？学习式位置能否直接评测超过表长的输入？先写下 RoPE、学习式、无位置三种方案可能的行为。

**运行：**

```bash
CUDA_VISIBLE_DEVICES="" python -m book.part2_lm.ch10_rope.tour 9 --context 32 --eval-contexts 32 64 128
```

**观察：** 每种方案只训练一次，再改变评测窗口，不在长窗口上继续训练。RoPE/无位置扩展数值表；学习式超过训练表长会明确报告无法评测。比较相同目标的 nat/token 与 bits/byte，并看外推减训练窗口的差值。更长输入既包含未训练的位置，也增加条件信息，不能将所有变化只归因于 RoPE 相位。

**记录：** 无法评测填写“位置无定义”，不要填零或伪造 loss。记录窗口大小、指标、时间及是否发生质量下降。

## 5. 实验三：只转一半维度

**预测：** 一半平面不旋转后，哪些点积分量不再含位置？是否可能在内容匹配与相对位置之间取得不同效果？

**运行：**

```bash
CUDA_VISIBLE_DEVICES="" python -m book.part2_lm.ch10_rope.tour 9 --modes rope --partial 1.0
CUDA_VISIBLE_DEVICES="" python -m book.part2_lm.ch10_rope.tour 9 --modes rope --partial 0.5
```

**观察：** 本章每头维度为 32，完整方案旋转 16 对，半旋转保留前 8 对 `(i,i+16)`，其余设 cos=1、sin=0。频率沿用完整 32 维的网格，不按 16 维重算；这种定义会优先保留较快的频率，实验结论也依赖这个选择。两种方案参数量相同。

**记录：** 记录旋转比例、实际旋转平面、频率定义、验证指标和长窗口差值。不要把半旋转与“把 cos/sin 随意切掉一半”混淆。

## 6. 故障演练：KV cache 的 pos0 写成零

**预测：** 旧 k 已带有历史位置，新 token 的 q/k 如果重新用位置零，哪些相对距离会错？正确缓存的输出应当和哪种计算一致？

**运行：**

```bash
CUDA_VISIBLE_DEVICES="" python -m book.part2_lm.ch10_rope.tour 10
CUDA_VISIBLE_DEVICES="" python -m pytest -q book/part2_lm/ch10_rope/test_ch10_rope.py -k cache_position_offset
```

脚本先用两份独立缓存预填同一段历史，再分别给新 token 正确位置与 `pos0=0`。正确位置为历史 token 数，整段前向作为参考。测试既要求正确缓存对齐整段，也要求故障产生可检测差异。若亲手练习，在自己的副本中将 `cache_diagnostic` 的 `right` 调用改为 `pos0=0`，上述测试应该失败；恢复后应转绿。无需修改公共生成代码。

**观察：** 检查最大 logits 差及乘一百万的误差；不要因为四位小数显示零就判为完全一致。bf16 演示先量化频率，再在 bf16 中乘位置和计算三角函数，与 fp32 缓存比较。这里的误差包含频率量化、乘法和三角函数舍入；即使位置 4096、8192 本身可精确表示，角度仍会失真。

**记录：** 记录错误行、历史长度、正确 pos0、两种 logits 差、失败断言与修复结果。第 15 章再展开完整缓存解码。
