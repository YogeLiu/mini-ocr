# 第 10 章 位置编码与 RoPE

## 本章导读

先做一个小实验。把公式 `a^{2}` 的第 0 个字符和第 3 个字符对调，得到 `2^{a}`。这是两个完全不同的公式：一个是"a 的平方"，一个是"2 的 a 次方"。可是把它们送进一层没有位置信息、也没有 mask 的自注意力，输出只是跟着输入**换了个顺序**，内容一模一样（10.1 节）。注意力分不清这两个公式。

原因很简单：注意力的打分只看两个 token 像不像，不看它们站在哪里。第 9 章的块靠一张可学习的位置嵌入表把位置加进去，而注意力收到的 `cos`、`sin` 被设成了"什么也不做"。这一章就来填上这两个参数。

本章的主角是 **RoPE**（Rotary Position Embedding，旋转位置编码）。它把位置 t 编码成一个角度，再把 q 和 k 转过这个角度。两个向量各转各的，点积只剩下角度差，也就是相对距离。

Qwen、Llama 等现在的主流开源模型都用 RoPE（待验证，第 17 章 17.10 节的对照表列出了 Qwen3）；GPT-2 用的则是学习式位置嵌入。本书的项目两种都会遇到，第 17 章会把 GPT-2 和 Qwen 放在一起对照。

推导和实现之外，10.9 节在 LaTeX 上对比了三种位置方案。这个单层模型的短训练里，RoPE 和不加位置几乎打平，学习式明显落后，超出训练长度的评测也几乎没受到考验。这些结果能说明什么，那一节再细读。

**学完本章，你能做到：**

1. 说出绝对位置编码（学习式、正弦式）的做法和局限（10.1、10.2 节）。
2. 推导 RoPE：二维旋转 → 每对维度一个频率 → 点积只取决于相对位置（10.3、10.4 节）。
3. 实现 RoPE，说清"前后两半"和"相邻两维"两种约定，以及混用会怎样（10.5 节，练习 10.1）。
4. 解释为什么只对 q、k 加 RoPE，不对 v 加（10.6 节）。
5. 说出 base 变大的效果，以及它和长上下文扩展的关系（10.7、10.8 节）。

## 10.1 注意力为什么需要位置

### 10.1.1 一个实验：a^{2} 和 2^{a}

脚本第 1 部分把 `a^{2}` 的 5 个字符各配一个随机的 8 维向量，组成 X，形状 (5, 8)。再按置换 `[3, 1, 2, 0, 4]` 重排，也就是对调第 0 个和第 3 个字符，得到 `2^{a}`。两条序列分别送进同一个无位置、无 mask 的单头自注意力，比较输出：

```text
置换等变 Y(PX) 与 P Y(X)最大差=0.0000；差值乘一百万=0.1788
```

（本项目观察，CPU，第 1 部分。）最大差 1.788 × 10⁻⁷，是 fp32 的舍入误差。也就是说，先打乱再算，等于先算再打乱。每个字符拿到的输出和它在哪个位置无关，只和序列里有哪些字符有关。

这就是第 8 章讲过的**置换等变**（permutation equivariance）。注意它说的是"输出跟着输入一起换位置"，不是"每个位置的输出都相等"。

### 10.1.2 为什么会这样

8.9.2 节用置换矩阵 P 一步步推过：打乱输入后，分数矩阵变成 P S Pᵀ，按行 softmax 只让结果跟着重排，再乘 PV 时 PᵀP = I 消去中间的置换。结论是 Attn(PX) = P · Attn(X)（数学结论）。整个推导里没有任何一步用到位置编号。注意力就像一个只看名单、不看座位号的会议主持人：谁和谁说话只取决于名字配不配，换座位不改变任何对话。

对公式识别来说这是致命的。`a^{2}` 和 `2^{a}`，`\frac{a}{b}` 和 `\frac{b}{a}`，字符一样、顺序不同，意思完全不同。我们必须把"座位号"告诉模型。

### 10.1.3 因果 mask 带来的"隐式位置"

语言模型不是无 mask 的。8.9.4 节已经看到，加上因果 mask 以后，置换等变不再成立：第 t 个位置只能看 0…t，不同位置能看到的 token 数不同，这本身就漏出了一点位置信息。比如一个头如果均匀地看所有可见位置，第 t 个位置分到每个 token 的权重是 1/(t+1)。只要序列里有一个可以辨认的参照，比如开头一个和其他 token 都不同的起始符，它在输出里所占的份量就是 1/(t+1)，模型可以从这里数出自己在第几个。如果所有可见的 v 都一样，输出就是这个 v 本身，什么也数不出来。所以第 1 部分的结论**不能**直接套到带因果 mask 的 GPT 上。完全不加位置编码的 GPT 叫 NoPE（No Position Embedding），它并非完全不知道顺序。

> **停下来想一想**
>
> 一个**单层**、无位置编码、带因果 mask 的 GPT，只用最后一个位置预测下一个 token。把前面的历史 token 任意打乱（最后一个 token 不动），它的预测会变吗？
>
> 提示：最后一个位置的输出是 Σⱼ wⱼ vⱼ，wⱼ 只取决于 qₜ 和 kⱼ。这个和式对 j 的顺序敏感吗？10.9 节的实验结果会用到这个答案。

## 10.2 绝对位置编码：学习式与正弦式

最直接的办法：给每个位置 t 准备一个向量 pₜ，加到 token 嵌入上，xₜ ← xₜ + pₜ。"绝对"的意思是 pₜ 只看 t 本身。按 pₜ 从哪来，分两种。

### 10.2.1 学习式：一张可训练的表

**做法。** 建一张表 `nn.Embedding(T_max, d)`，第 t 行就是 pₜ，和其他参数一起训练。GPT-2 就是这么做的，它的表叫 `wpe`，有 1024 行（待验证，第 17 章核对）。

**优点。** 简单，什么都不假设，模型想学成什么样都行。

**局限。**

- **表多长，就只能处理多长。** 训练表只有 T_max 行，位置 T_max 根本没有向量。脚本第 2 部分建了一张 4 行的表，请求位置 4：

  ```text
  学习式表长=4；请求位置=4；异常=IndexError: index out of range in self
  ```

  （本项目观察，CPU，第 2 部分。）位置 4 根本没有定义，谈不上效果变差。第 9 部分的 LaTeX 实验里，训练上下文 64 的学习式模型就无法在 128 的窗口上评测（10.9 节）。
- **每个位置单独学。** 位置 37 学到的东西不会自动迁移到位置 38。很靠后的位置在训练里出现得少，就学得差。
- **参数要花钱。** 表有 T_max × d 个参数。第 9 部分的学习式模型比 RoPE 模型多 202048 − 197952 = 4096 = 64 × 64 个参数，正好是一张 64 行、64 维的表（本项目观察，CPU，第 9 部分；差值是数学结论）。

### 10.2.2 正弦式：用不同频率的波写位置

原始 Transformer（Vaswani 等，2017，第 3.5 节）不训练位置表，而是用公式算：

```text
PE(t, 2i)   = sin(t · ωᵢ)
PE(t, 2i+1) = cos(t · ωᵢ)        ωᵢ = 10000^(−2i/d)，i = 0, 1, …, d/2 − 1
```

每一对维度 (2i, 2i+1) 是一个以频率 ωᵢ 转动的"指针"：i = 0 时 ω = 1，每走一个位置转 1 弧度，转得飞快；i 越大转得越慢。这像一块有很多根指针的钟：秒针区分相邻位置，时针区分远处的位置。

d = 8 时，四个频率是 1、0.1、0.01、0.001（数学结论）。脚本第 2 部分打印了前四个位置的编码：

```text
位置=0；八维位置编码=[0.0000, 1.0000, 0.0000, 1.0000, 0.0000, 1.0000, 0.0000, 1.0000]
位置=1；八维位置编码=[0.8415, 0.5403, 0.0998, 0.9950, 0.0100, 0.9999, 0.0010, 1.0000]
位置=2；八维位置编码=[0.9093, -0.4161, 0.1987, 0.9801, 0.0200, 0.9998, 0.0020, 1.0000]
位置=3；八维位置编码=[0.1411, -0.9900, 0.2955, 0.9553, 0.0300, 0.9996, 0.0030, 1.0000]
```

（本项目观察，CPU，第 2 部分。）看第一对维度：(sin 1, cos 1) = (0.8415, 0.5403)，(sin 2, cos 2) = (0.9093, −0.4161)，变化很大；最后一对几乎不动。

**一个漂亮的性质：PE 自己的点积只看距离。** 计算位置 m 和 n 的编码的点积：

```text
PE(m)·PE(n) = Σᵢ [sin(mωᵢ) sin(nωᵢ) + cos(mωᵢ) cos(nωᵢ)]
            = Σᵢ cos((n − m) ωᵢ)              （用 cos(a−b) 的恒等式）
```

第二行用的是先修框里的 cos(a − b) = cos a cos b + sin a sin b，取 a = mωᵢ、b = nωᵢ，得到 cos((m − n)ωᵢ)；cos 是偶函数，所以它也等于 cos((n − m)ωᵢ)。结果只含 n − m（数学结论）。d = 8、距离 3 时，点积 = cos 3 + cos 0.3 + cos 0.03 + cos 0.003 = −0.9900 + 0.9553 + 0.9996 + 1.0000 ≈ 1.9649。脚本验证了两组位置：

```text
正弦点积；位置甲=2；位置乙=5；距离=3；点积=1.9649
正弦点积；位置甲=10；位置乙=13；距离=3；点积=1.9649
```

（本项目观察，CPU，第 2 部分。）距离相同，点积相同。

### 10.2.3 问题出在"加"上

那正弦编码是不是已经解决了相对位置？没有。因为注意力里点积的不是 PE 本身，而是**加了 PE 的输入经过投影之后**的 q 和 k。把加法展开：

```text
qₘ · kₙ = (xₘ + pₘ) W_q · (xₙ + pₙ) W_k
        = xₘW_q·xₙW_k  +  xₘW_q·pₙW_k  +  pₘW_q·xₙW_k  +  pₘW_q·pₙW_k
          内容×内容        内容×位置        位置×内容        位置×位置
```

四项各有问题：

- 中间两项把**内容**和**绝对位置**搅在一起。
- 最后一项 pₘ W_q W_kᵀ pₙᵀ 中间夹了一个任意矩阵 W_q W_kᵀ，一般不再只依赖 n − m。PE 自己的好性质被投影破坏了。

脚本第 2 部分用随机的内容向量和随机投影算了这四项（m = 2，n = 5）：

```text
内容×内容=-18.2198；内容×位置=6.6357；位置×内容=7.4988；位置×位置=2.3516
展开四项之和=-1.7338；直接 q·k=-1.7338
```

（本项目观察，CPU，第 2 部分。）四项加起来确实等于直接算的 q·k。位置的影响散落在三项里，没有一项是干净的"相对距离"。

**我们想要的是什么？** 一个函数 f，使得 f(q, m) · f(k, n) **只**依赖 q、k 和 n − m。这样，同一段 `\frac{a}{b}` 无论出现在公式开头还是中间，内部的注意力分数都一样。这个性质叫"平移不变"。

正弦编码里其实已经有线索：每一对 (sin tω, cos tω) 就是一个转到角度 tω 的单位向量。正弦编码把这个**转动的向量加到内容上**；RoPE 换了个思路，**直接把内容向量转动**。

> **概括：其他相对位置方法**
>
> - **T5 相对位置偏置**（Raffel 等，2020）：不改 q、k，直接给分数加一个只依赖距离（分桶后）的可学习标量 b(n − m)。
> - **ALiBi**（Press 等，2022，"Train Short, Test Long"）：不加任何位置向量，给每个头的分数加一个线性惩罚 −s·(m − n)，距离越远扣分越多，每个头的斜率 s 不同（按几何级数取）。论文主打"短训长测"的外推能力。
> - 这两种都是在**分数上加偏置**；RoPE 是**旋转 q、k**，让点积本身带上相对位置。本书不实现它们，有兴趣可读原论文。

## 10.3 二维旋转：RoPE 的核心

先只看二维，d 维的 RoPE 都是这一节的推广。

### 10.3.1 直觉：两个指针，看夹角

把二维向量 q = (q₀, q₁) 想成钟面上的一根指针。位置 m 的 token，把 q 逆时针转 mθ；位置 n 的 token，把 k 转 nθ。θ 是固定的"每走一步转多少"。

点积衡量的是两根指针的长度乘夹角余弦。两根指针各自转了多少无所谓，**夹角只变了 (n − m)θ**。

### 10.3.2 旋转矩阵

把向量逆时针转 α 弧度，就是乘一个旋转矩阵：

```text
R(α) = [ cos α   −sin α ]
       [ sin α    cos α ]

R(α) · (x₀, x₁) = (x₀ cos α − x₁ sin α,  x₀ sin α + x₁ cos α)
```

它有三个性质，下面都要用（都是数学结论）：

1. **转置就是反着转**：R(α)ᵀ = R(−α)。转置把右上角的 −sin α 和左下角的 sin α 对调，得到 [cos α, sin α; −sin α, cos α]（分号隔开两行）。又因为 cos(−α) = cos α、sin(−α) = −sin α，这正是 R(−α)。
2. **转两次等于转角度之和**：R(α) R(β) = R(α + β)。把两个矩阵乘开，左上角是 cos α cos β − sin α sin β = cos(α + β)，左下角是 sin α cos β + cos α sin β = sin(α + β)，其余两格同理。这两个和角公式就是先修框里的恒等式把 b 换成 −b。
3. **不改变长度**：‖R(α) x‖ = ‖x‖。由前两条，R(α)ᵀ R(α) = R(−α) R(α) = R(0) = I，所以 ‖R(α) x‖² = xᵀ R(α)ᵀ R(α) x = xᵀ x。

### 10.3.3 推导：点积只剩角度差

定义 RoPE 在二维的版本：

```text
f(q, m) = R(mθ) q
f(k, n) = R(nθ) k
```

一步一步算点积：

```text
f(q, m) · f(k, n) = (R(mθ) q)ᵀ (R(nθ) k)
                  = qᵀ R(mθ)ᵀ R(nθ) k          （(AB)ᵀ = BᵀAᵀ）
                  = qᵀ R(−mθ) R(nθ) k          （性质 1）
                  = qᵀ R((n − m)θ) k           （性质 2）
```

最后一行只含 n − m：位置 m 和 n 各自的绝对值消失了，只剩相对距离，满足 10.2.3 节对 f 的要求。

再把 qᵀ R(α) k 展开成标量，写成 α = (n − m)θ：

```text
qᵀ R(α) k = q₀(k₀ cos α − k₁ sin α) + q₁(k₀ sin α + k₁ cos α)
          = (q₀k₀ + q₁k₁) cos α + (q₁k₀ − q₀k₁) sin α
```

第一项括号里是原来的点积，第二项括号里是二维的"叉积"。距离为 0 时 α = 0，分数就是原来的点积，旋转没有任何影响。

**换个角度看：复数。** RoPE 论文用复数写这个推导，分三步就能对上上面的矩阵写法。

第一步，乘 e^{iα} 就是转 α。把 (x₀, x₁) 看成复数 x₀ + i x₁。欧拉公式给出 e^{iα} = cos α + i sin α，乘开并用 i² = −1，得到 (x₀ + i x₁)(cos α + i sin α) = (x₀ cos α − x₁ sin α) + i (x₀ sin α + x₁ cos α)。实部和虚部正好是 10.3.2 节 R(α)(x₀, x₁) 的两个分量。所以 f(q, m) = q e^{imθ}，这里 q 指复数 q₀ + i q₁。

第二步，二维点积可以写成 Re[conj(z) · w]。conj 是共轭，把虚部变号。设 z = a + ib，w = c + id，conj(z) · w = (a − ib)(c + id) = (ac + bd) + i(ad − bc)，实部 ac + bd 正是 (a, b) · (c, d)。

第三步，代入。conj(q e^{imθ}) = conj(q) e^{−imθ}，因为共轭只把 i 换成 −i。于是 f(q, m) · f(k, n) = Re[conj(q) e^{−imθ} · k e^{inθ}] = Re[conj(q) k e^{i(n−m)θ}]：同底数相乘时指数相加，e^{−imθ} 和 e^{inθ} 合成 e^{i(n−m)θ}，绝对位置 m、n 就此消失。把 Re[conj(q) k e^{iα}] 乘开，得到的正是上面的 (q₀k₀ + q₁k₁) cos α + (q₁k₀ − q₀k₁) sin α，两种写法完全等价。

### 10.3.4 数值例子

取 q = (1, 0)，k = (0.6, 0.8)，θ = 0.5。两组位置：(m, n) = (2, 5) 和 (10, 13)，距离都是 3。

**第一组，m = 2，n = 5。**

- q 转 mθ = 1 弧度：R(1)(1, 0) = (cos 1, sin 1) = (0.5403, 0.8415)。
- k 转 nθ = 2.5 弧度：cos 2.5 = −0.8011，sin 2.5 = 0.5985。
  - 第一个分量：0.6 × (−0.8011) − 0.8 × 0.5985 = −0.4807 − 0.4788 = −0.9595
  - 第二个分量：0.6 × 0.5985 + 0.8 × (−0.8011) = 0.3591 − 0.6409 = −0.2818
- 点积：0.5403 × (−0.9595) + 0.8415 × (−0.2818) = −0.5184 − 0.2371 = −0.7556。

**用公式直接算。** α = 3 × 0.5 = 1.5，q₀k₀ + q₁k₁ = 0.6，q₁k₀ − q₀k₁ = −0.8：

```text
0.6 cos 1.5 − 0.8 sin 1.5 = 0.6 × 0.0707 − 0.8 × 0.9975 = 0.0424 − 0.7980 = −0.7556
```

两条路得到同一个数。用复数写法也能核对：q = 1，k = 0.6 + 0.8i，Re[(0.6 + 0.8i)(cos 1.5 + i sin 1.5)] = 0.6 cos 1.5 − 0.8 sin 1.5 = −0.7556（数学结论）。脚本第 3 部分算了两组：


## 10.4 推广到 d 维：每对维度一个频率

### 10.4.1 切成 d/2 个平面

一个头的 q 有 dh 维（本书默认 dh 是偶数）。把它切成 dh/2 对，每对是一个二维平面，各自转动。如果先把每一对的两维排在一起（相邻排列），写成矩阵就是一个分块对角矩阵：

```text
R_t = diag( R(tθ₀), R(tθ₁), …, R(tθ_{dh/2−1}) )      （坐标按 (0,1)(2,3)… 相邻排列时）
```

本书默认的"前后两半"顺序下，同一个变换写成

```text
R_t = [ C_t  −S_t ]      C_t = diag(cos tθ₀, …, cos tθ_{dh/2−1})
      [ S_t   C_t ]      S_t = diag(sin tθ₀, …, sin tθ_{dh/2−1})
```

两种写法只差一个坐标重排（10.5.5 节）。无论哪种写法，每个平面只管自己那一对维度，平面与平面互不干扰。点积本来就是逐维相乘再相加，可以按维度对分组来加；每一组都是一个二维点积，满足 10.3.3 节的推导。所以整个点积是各平面点积之和：

```text
(R_m q) · (R_n k) = Σᵢ qᵢᵀ R((n − m)θᵢ) kᵢ       （qᵢ、kᵢ 是第 i 对维度）
```

每一项都只依赖 n − m，所以总和也只依赖 n − m（数学结论）。R_t 是正交矩阵，所以旋转不改变 q、k 的长度。

至于"哪两维配成一对"，有两种常见约定，10.5 节专门讲。本书默认把第 i 维和第 i + dh/2 维配成一对。

### 10.4.2 频率怎么选

如果每对都用同一个 θ，等于只有一根指针。每过大约 2π/θ 个位置，指针就转回差不多的方向，相隔约一圈的位置角度非常接近，很难区分。整数位置一般不会严格重合，但会近似重复。而且所有平面提供的是同一种尺度的信息。办法和正弦编码一样，用一串几何级数的频率：

```text
θᵢ = base^(−2i/dh)，  i = 0, 1, …, dh/2 − 1，  base 默认 10000
```

- i = 0：θ₀ = 1，最快，每步转 1 弧度。
- i 增大：频率按几何级数变小。
- 第 i 对转一圈需要的位置数叫**波长**：λᵢ = 2π / θᵢ = 2π · base^(2i/dh)。

dh = 8、base = 10000 时（本书配对 (i, i+4)）：

```text
维度对=(0,4)；频率θ=1.0000；波长=6.2832
维度对=(1,5)；频率θ=0.1000；波长=62.8319
维度对=(2,6)；频率θ=0.0100；波长=628.3185
维度对=(3,7)；频率θ=0.0010；波长=6283.1853
```

（本项目观察，CPU，第 4 部分；这些值也可以直接从公式推出。）最快的一对 6 个多位置就转一圈，适合分辨紧挨着的是谁；最慢的一对要 6000 多个位置才转一圈，适合分辨大概隔了多远。

### 10.4.3 实测：共同平移不改变分数

脚本第 4 部分随机取一对 8 维的 q、k，放在位置 2 和 5，然后把两个位置同时往后挪 1、100、1000：

```text
偏移=1；原点积=2.6400；平移点积=2.6400
相对位置性质最大差=0.0000；差值乘一百万=0.0000
偏移=100；原点积=2.6400；平移点积=2.6400
相对位置性质最大差=0.0000；差值乘一百万=0.0000
偏移=1000；原点积=2.6400；平移点积=2.6400
相对位置性质最大差=0.0000；差值乘一百万=1.1921
```

（本项目观察，CPU，第 4 部分。）偏移 1000 时出现了 1.19 × 10⁻⁶ 的差，这是 fp32 的舍入：角度变大以后，算 cos、sin 时的相对误差会体现到结果上。数学上严格相等，实现上差一点点。测试 `test_relative_position` 因此用了容差。

要注意这个性质的范围：它说的是**固定的 q、k** 换个绝对位置，分数不变。在真实的深层模型里，q、k 本身由上文算出来，上文不同 q、k 也不同。所以不能理解成"任意两段文本只要距离相同，分数就相同"。

## 10.5 实现与两种配对约定

这一节对照代码逐行讲，数值例子用脚本第 5 部分的那组数字：dh = 8，q = [1, 2, 3, 4, 5, 6, 7, 8]，位置 t = 3，base = 10000。

### 10.5.1 两种配对

把 dh 维切成 dh/2 对，有两种切法：

| 约定 | 第 i 对 | dh = 8 时的配对 | 谁在用 |
|---|---|---|---|
| **前后两半** | (i, i + dh/2) | (0,4) (1,5) (2,6) (3,7) | 本书；HF transformers 里的 Llama、Qwen（待验证） |
| **相邻两维** | (2i, 2i + 1) | (0,1) (2,3) (4,5) (6,7) | RoFormer 论文的写法；Meta 原版 LLaMA 代码用复数实现（待验证） |

两种约定在数学上**一样好**：都满足相对位置性质，都保持长度。区别只在于第 i 个频率作用在哪两维上。它们的关系是一个固定的维度置换，10.5.5 节会讲。

为什么很多实现选前后两半？一个常见的解释是它能用整块切片实现，不用跨步取数（`x[..., 0::2]`）再交错拼回去，代码更简单。

### 10.5.2 推导向量化的写法

对第 i 对 (a, b) = (xᵢ, x_{i+dh/2})，转角 φᵢ = tθᵢ。下面两行就是 10.3.2 节的 R(φᵢ) 作用在 (a, b) 上：

```text
a' = a cos φᵢ − b sin φᵢ
b' = a sin φᵢ + b cos φᵢ
```

现在把所有对一起写。把 x 切成前一半 x₁ = (x₀ … x_{dh/2−1}) 和后一半 x₂ = (x_{dh/2} … x_{dh−1})。上面两行变成：

```text
前一半：x₁' = x₁ ⊙ cos φ − x₂ ⊙ sin φ
后一半：x₂' = x₂ ⊙ cos φ + x₁ ⊙ sin φ
```

（⊙ 是逐元素乘，φ = (φ₀, …, φ_{dh/2−1})。）拼起来：

```text
[x₁', x₂'] = [x₁, x₂] ⊙ [cos φ, cos φ]  +  [−x₂, x₁] ⊙ [sin φ, sin φ]
```

于是只需要两样东西：

- 一个把 [x₁, x₂] 变成 [−x₂, x₁] 的函数，叫 `rotate_half`；
- 把 cos φ、sin φ **各复制一次**拼成 dh 维的表，前一半和后一半用同一组角度。

最终公式：**x' = x ⊙ cos + rotate_half(x) ⊙ sin**。

### 10.5.3 代码逐行讲

代码在 `miniocr/models/gpt.py`，是练习 10.1 要你实现的三个函数。

```python
def rope_cache(T, dh, base=10000.0, device=None):
    if dh <= 0 or dh % 2:
        raise ValueError("RoPE 的 dh 必须是正偶数")
    inv = base ** (-torch.arange(0, dh, 2, dtype=torch.float32, device=device) / dh)    # (dh/2,)
    ang = torch.arange(T, dtype=torch.float32, device=device)[:, None] * inv[None]       # (T, dh/2)
    ang = torch.cat([ang, ang], -1)
    return ang.cos(), ang.sin()
```

用 T = 4、dh = 8 走一遍：

- **第一个 if**：dh 必须是正偶数，否则凑不成对。dh = 7 会直接报错（10.10 节）。
- **`inv`**：`torch.arange(0, 8, 2)` 是 [0, 2, 4, 6]，除以 8 得 [0, 0.25, 0.5, 0.75]，于是 inv = 10000^(−[0, 0.25, 0.5, 0.75]) = [1, 0.1, 0.01, 0.001]，形状 (4,)。注意指数里是 **2i/dh**，arange 的步长 2 就是这个"2"。
- **`ang`**：位置 [0, 1, 2, 3] 变成列 (4, 1)，乘行 (1, 4)，广播成 (4, 4)，第 t 行第 i 列是 t·θᵢ。第 3 行是 [3, 0.3, 0.03, 0.003]。
- **`cat`**：复制一份接在后面，变成 (4, 8)。第 3 行是 [3, 0.3, 0.03, 0.003, 3, 0.3, 0.03, 0.003]。这就是 10.5.2 节的 [φ, φ]。
- **返回** cos、sin，形状都是 (T, dh) = (4, 8)。角度和三角函数都在 **fp32** 里算，10.10 节会说为什么。

第 3 行的数值：

```text
cos[3] = [-0.9900, 0.9553, 0.9996, 1.0000, -0.9900, 0.9553, 0.9996, 1.0000]
sin[3] = [ 0.1411, 0.2955, 0.0300, 0.0030,  0.1411, 0.2955, 0.0300, 0.0030]
```

（数学结论：cos 3 = −0.9900，sin 3 = 0.1411，cos 0.3 = 0.9553，sin 0.3 = 0.2955，以此类推。）

```python
def rotate_half(x):
    if x.shape[-1] <= 0 or x.shape[-1] % 2:
        raise ValueError("RoPE 的 dh 必须是正偶数")
    x1, x2 = x.chunk(2, -1)
    return torch.cat([-x2, x1], -1)
```

- `chunk(2, -1)` 沿最后一维切成前后两半：x1 = [1, 2, 3, 4]，x2 = [5, 6, 7, 8]。
- 拼成 [−x2, x1] = [−5, −6, −7, −8, 1, 2, 3, 4]。
- 一个小检查：rotate_half 做两次等于取负，rotate_half(rotate_half(x)) = −x。相当于转 90° 两次等于转 180°。测试 `test_rotate_half_values_and_square` 检查了这一点。

```python
def apply_rope(x, cos, sin):
    return x * cos.to(x.dtype) + rotate_half(x) * sin.to(x.dtype)
```

逐维算 q ⊙ cos[3] + rotate_half(q) ⊙ sin[3]：

| 维 | q | cos | rotate_half(q) | sin | 结果 |
|---|---|---|---|---|---|
| 0 | 1 | −0.9900 | −5 | 0.1411 | 1×(−0.9900) + (−5)×0.1411 = −1.6956 |
| 1 | 2 | 0.9553 | −6 | 0.2955 | 1.9107 − 1.7731 = 0.1376 |
| 2 | 3 | 0.9996 | −7 | 0.0300 | 2.9987 − 0.2100 = 2.7887 |
| 3 | 4 | 1.0000 | −8 | 0.0030 | 4.0000 − 0.0240 = 3.9760 |
| 4 | 5 | −0.9900 | 1 | 0.1411 | −4.9500 + 0.1411 = −4.8088 |
| 5 | 6 | 0.9553 | 2 | 0.2955 | 5.7320 + 0.5910 = 6.3231 |
| 6 | 7 | 0.9996 | 3 | 0.0300 | 6.9969 + 0.0900 = 7.0868 |
| 7 | 8 | 1.0000 | 4 | 0.0030 | 8.0000 + 0.0120 = 8.0120 |

（表中末位按 4 位小数四舍五入。）对照 10.5.2 节：第 0 维和第 4 维是一对 (a, b) = (1, 5)，转了 3 弧度：a' = 1·cos 3 − 5·sin 3 = −1.6956，b' = 1·sin 3 + 5·cos 3 = −4.8088。脚本第 5 部分打印的正是这一行：

```text
同一输入q=[1.0000, 2.0000, 3.0000, 4.0000, 5.0000, 6.0000, 7.0000, 8.0000]；位置=3；
前后两半输出=[-1.6956, 0.1376, 2.7887, 3.9760, -4.8088, 6.3231, 7.0868, 8.0120]
```

（本项目观察，CPU，第 5 部分。）第 3、7 维几乎没动：它们的频率是 0.001，3 个位置只转了 0.003 弧度。

**形状。** 在注意力里，x 是 (B, h, T, dh)，cos、sin 是 (T, dh)。逐元素乘时，(T, dh) 从右往左对齐，自动广播到所有 batch 和所有头。每个头用同一张表，因为频率只和头内维度有关。

`.to(x.dtype)` 只在最后把**已经算好的 cos、sin 值**转成激活的精度（例如 bf16），角度本身从不在低精度里算。

### 10.5.4 接进注意力

在 `CausalSelfAttention.forward` 里只有一行：

```python
q, k = apply_rope(q, cos, sin), apply_rope(k, cos, sin)
```

它的位置很讲究：

- 在**拆成多头之后**（q、k 已经是 (B, h, T, dh)），因为频率是按头内维度 dh 定的。
- 在 **Q/K norm 之后**（如果有的话，第 17 章 Qwen3 会用到）。
- 在**写入 KV cache 之前**。缓存里存的是已经转好的 k，以后不用再转。
- **v 不转**，10.6 节讲为什么。

`GPT` 在 `__init__` 里调用一次 `rope_cache(block_size, d_model // n_head, rope_base)`，把结果存成 buffer。前向时按 `self.cos[pos0:pos0 + T]` 切出这一段位置。`pos0` 是这段输入第一个 token 的位置编号，平时是 0；用 KV cache 逐个生成时，新 token 的 `pos0` 要接在历史后面（10.10 节）。`cfg.rope = False` 时，表被换成 cos = 1、sin = 0，`apply_rope` 原样返回输入，这就是第 9 章"什么也不做"的那两个参数。

还有一个变体叫 **partial RoPE**：只转一部分平面，其余平面 cos = 1、sin = 0。本章的 `PositionGPT` 支持它，做法和实验见 `lab.md` 第 5 节（实验三）。

### 10.5.5 两种约定的关系：一个维度置换

**等价。** 把"前后两半"的向量按索引 [0, 4, 1, 5, 2, 6, 3, 7] 重排，原来的配对 (0,4)、(1,5)… 就变成了相邻的 (0,1)、(2,3)…。于是：

```text
相邻实现( q[p] ) = 前后实现( q )[p]，   p = [0, 4, 1, 5, 2, 6, 3, 7]
```

脚本第 5 部分验证了这一点，并验证两种实现各自都满足相对位置性质：

```text
前后两半转相邻的索引置换=[0, 4, 1, 5, 2, 6, 3, 7]
置换后的两种实现最大差=0.0000；差值乘一百万=0.0000
前后两半平移最大差=0.0000；差值乘一百万=0.0000
相邻两维平移最大差=0.0000；差值乘一百万=0.0000
```

（本项目观察，CPU，第 5 部分。）

**不等价。** 但如果不重排，直接把同一个 q 交给两种实现，结果完全不同：

```text
相邻两维输出=[-1.2722, -1.8389, 1.6839, 4.7079, 4.8178, 6.1473, 6.9760, 8.0210]
```

（本项目观察，CPU，第 5 部分。）比如相邻约定把 (q₀, q₁) = (1, 2) 当作一对转 3 弧度：1·cos 3 − 2·sin 3 = −1.2722。而前后约定把 (1, 5) 当作一对。

**混用会怎样？** 设想一个模型按"前后两半"训练好，你却用"相邻两维"的函数加载它。权重里第 0 维和第 4 维本来是一对，现在第 0 维被拉去和第 1 维配对，频率也张冠李戴。脚本第 5 部分用 q = [1, …, 8]、k = [3, −1, 2, 0, 1, −2, 4, 1]，位置 2 和 5：

```text
权重通道未重排；训练约定分数=22.1226；混用约定分数=37.6519；绝对差=15.5293
```

（本项目观察，CPU，第 5 部分。）同一对 q、k，分数差了 15.5293。整个模型每一层、每一个头都这样错下去，输出会是乱码。

更麻烦的是，混用不会报错，相对位置测试也查不出来，因为两种约定各自都满足相对位置性质（上面两行"平移最大差 = 0"）。只测"平移不变"的单元测试，换哪种约定都会通过。要抓住这个错误，必须和一个**独立写成的参考公式**逐元素对拍。本章测试 `test_matches_independent_2d_rotation` 用 Python 标量 cos、sin 一对一对地转，不调用被测函数；`test_oracle_rejects_common_mistakes` 专门确认相邻约定会被判错。

**迁移权重时怎么办？** 不能只换一个旋转函数，要把每个头的 q、k 投影矩阵的**输出通道**按置换重排。HF 把 Meta 原版 LLaMA 权重转成自己的格式时就做了这种重排（待验证，本书不做这项核对）。v 不转，所以 v 的投影不用动。

## 10.6 为什么只转 q 和 k

### 10.6.1 位置只该影响"看谁"，不该影响"拿到什么"

注意力分两步：先用 q、k 打分，决定**看谁**；再按权重把 v 加起来，决定**拿到什么**。

两个位置只在打分时见面：分数 qₘ · kₙ 同时含有 m 和 n，旋转的角度在这里抵消成 n − m。v 不参与打分，没有人和它抵消角度。

### 10.6.2 推导：转 v 会留下绝对位置

只转 q、k 时，位置 m 的输出是

```text
yₘ = Σₙ wₘₙ vₙ，   wₘₙ = softmax_n( qᵀ R((n − m)θ) k / √dh )
```

权重只依赖相对距离，v 是原样的内容，所以整个输出只依赖相对布局。把整段序列往后挪 s 个位置，每个 wₘₙ 都不变，输出也不变。

如果把 v 也转了，vₙ 换成 R(nθ) vₙ：

```text
yₘ = Σₙ wₘₙ R(nθ) vₙ
```

每个 vₙ 按它**自己的绝对位置** n 转。整段平移 s 以后，权重 wₘₙ 不变，每个 vₙ 改转 R((n + s)θ)。由性质 2，R((n + s)θ) = R(sθ) R(nθ)，而 R(sθ) 和 n 无关，可以提到求和号外面：Σ wₘₙ R((n + s)θ) vₙ = R(sθ) yₘ，输出整体多转了 sθ。没有任何东西能把这个 R(sθ) 抵消掉。后面的输出投影 W_o、残差流、前馈网络都不知道这个向量被转过，同一个内容会因为出现的位置不同而变成不同的向量。

### 10.6.3 实测

脚本第 6 部分取同一段 6 个 token 的随机 q、k、v，带因果 mask，分别从绝对位置 0 和 50 开始放（相对布局相同）：

```text

也转v的注意力输出最大差=2.5195；差值乘一百万=2519547.7009
```

（本项目观察，CPU，第 6 部分。）只转 q、k 时，两次输出只差 1.341 × 10⁻⁷，是舍入误差；也转 v 时差 2.5195，和随机向量本身的大小相当。

## 10.7 远程衰减与 base

### 10.7.1 RoPE 论文说的"远程衰减"

RoPE 论文（Su 等，第 3.4.3 节）论证了一个性质：随着相对距离增大，旋转后点积的某个上界会变小。直觉是：距离越远，不同频率的平面转过的角度越杂乱，各平面的贡献正负相消，加起来就小。很多资料把它说成"RoPE 让远处的 token 分数衰减"。

这句话要小心理解。它是一种平均意义上的上界衰减，**不是**"对任意 q、k，分数随距离单调下降"。

### 10.7.2 一个可以手算的特例：全 1 向量

取 q = k = 全 1 向量。每一对平面 (1, 1) 与转过 α 的 (1, 1) 的点积是：

```text
(1, 1) · R(α)(1, 1) = (1, 1) · (cos α − sin α, sin α + cos α) = 2 cos α
```

所以总分数是一个只和距离 Δ 有关的函数：

```text
s(Δ) = Σᵢ 2 cos(Δ · θᵢ)，   i = 0 … dh/2 − 1
```

Δ = 0 时每项都是 2，s(0) = dh（数学结论）。

dh = 64 时，脚本第 7 部分打印了几个距离的值，并把 0…1024 的曲线画成图 `outputs/book/ch10/distance_base.png`：

| 距离 Δ | base = 10000 | base = 1000000 |
|---|---|---|
| 0 | 64.0000 | 64.0000 |
| 1 | 61.8337 | 62.3692 |
| 16 | 38.7456 | 45.3376 |
| 64 | 27.8122 | 41.4518 |
| 128 | 18.1666 | 29.5995 |
| 512 | 11.8636 | 27.0581 |
| 1024 | 16.8273 | 34.4017 |

（本项目观察，CPU，第 7 部分。）

两件事值得看：

1. **大体趋势是下降，但不单调。** base = 10000 时，从 512 到 1024 分数反而从 11.8636 涨回 16.8273。打开图片会看到一路上下振荡，局部还会出现反弹。这条曲线是一个**振荡核**，不是严格单调的衰减曲线。
2. **这只是一个特例。** 对具体的 q、k，分数可以随距离变大，也可以为负。由 ‖q‖ ‖k‖ 给出的通用上界根本不随距离变化。所以"远程衰减"不能当作对所有内容分数的保证。

### 10.7.3 base 变大，发生了什么

θᵢ = base^(−2i/dh)。base 变大时：

- **i = 0 不变**：θ₀ = base⁰ = 1，最快的那根指针速度不变（数学结论）。
- **其余频率（i > 0）都变慢**，i 越大慢得越多，这些平面的波长都变长；最快平面的波长始终是 2π。

于是上表里 base = 1000000 那一列整体下降得更慢：距离 64 时还有 41.4518，而 base = 10000 时已经掉到 27.8122（本项目观察，CPU，第 7 部分）。直觉上，更多平面还没转开，各平面贡献相消得慢。

这对长上下文意味着：慢平面的波长变长，同一段长度里转过的角度变小，远处的位置之间更不容易转回原处撞车。很多长上下文模型把 base 调大，这是原因之一。Qwen3-0.6B 的配置里 base（在配置里叫 `rope_theta`）取 1000000（来源是 Qwen3-0.6B 的本地 config，见第 17 章 17.10 节）。

不过有两点限制：

- base 变大**不保证**模型能处理更长的文本。它只改变角度怎么随位置变化，模型能否真的利用更长的上文、质量能否保持，都要实测。
- base 变大的代价是慢平面的分辨率变低：相邻位置在这些平面上几乎转不出差别。

base 对验证 loss 的影响，请在 `lab.md` 第 3 节（实验一）自己测。单看振荡曲线，决定不了谁的 loss 更低。

## 10.8 长上下文扩展：插值与改 base

### 10.8.1 问题：没见过的角度

训练长度为 L 时，第 i 对平面见过的角度范围是 [0, (L−1)θᵢ]。快平面早就转了很多圈，一圈上的角度被采样得很密；**慢平面可能连一圈都没转完**。推理时位置超过 L，慢平面就转到了训练时从来没见过的角度。cos、sin 当然有定义，可模型没学过在这些角度上该怎么打分。

算一下量级（数学结论）。dh = 64、base = 10000 时，最慢的频率是

```text
θ_min = 10000^(−62/64) ≈ 1.3335 × 10⁻⁴，  波长 2π / θ_min ≈ 47117 个位置
```

训练长度 4096 时，最慢平面最多转约 4096 × 1.3335 × 10⁻⁴ ≈ 0.546 弧度，连一圈的十分之一都不到。超过 4096 的部分它都没见过。

### 10.8.2 两种办法

**位置插值**（Position Interpolation，PI；Chen 等，2023）：想把长度扩到 s 倍，就把所有位置除以 s，m → m/s。这样 0…sL−1 这些位置被压进连续区间 [0, L) 以内，最后一个位置映射到 L − 1/s，只比训练最大位置 L − 1 多一点；大部分新位置落在训练过的整数位置**之间**，属于"插值"而不是"外推"。（要严格不超过 L − 1，可以改用 m(L−1)/(sL−1)。）代价是相邻位置的角度差也缩小了 s 倍：最快平面原来相邻差 1 弧度，s = 4 时只剩 0.25 弧度，模型分辨紧挨着的是谁变难了。所以通常还要在长文本上再微调一段。

**增大 base**：频率按 base^(−2i/dh) 变，增大 base 让慢平面变慢、快平面基本不动（θ₀ 恒为 1）。这正好是我们想要的：慢平面被压缩，快平面保持分辨率。想让最慢的频率恰好缩小 s 倍（要求 dh > 2；dh = 2 时只有 θ₀ = 1 这一个频率，改 base 动不了它），解方程 base'^(−(dh−2)/dh) = base^(−(dh−2)/dh) / s。两边同除以 base^(−(dh−2)/dh)，得到 (base'/base)^(−(dh−2)/dh) = 1/s，再两边取 −dh/(dh−2) 次方：

```text
base' = base · s^(dh/(dh−2))
```

dh = 64、s = 4 时，base' = 10000 × 4^(64/62) ≈ 41829（数学结论）。社区里叫它 "NTK-aware" 缩放。后来的 YaRN（Peng 等，2023）对不同频率分段处理，并调整注意力温度（待验证，本书不展开）。

### 10.8.3 实测：最慢平面的角度

脚本第 8 部分只算数、不训练。dh = 64，训练长度 L = 64，扩到 4L = 256，看最慢平面在位置 L 和 4L 的角度。这里用连续的位置边界 L、4L 来比，实际长度 L 的最后一个位置编号是 L − 1：

| 方法 | base | 位置除数 | 在 L = 64 的角度 | 在 4L = 256 的角度 |
|---|---|---|---|---|
| 原始 | 10000 | 1 | 0.0085 | 0.0341 |
| 位置插值 | 10000 | 4 | 0.0021 | 0.0085 |
| 增大 base | 1000000 | 1 | 0.0001 | 0.0004 |

（本项目观察，CPU，第 8 部分；这些值也可由 Lθ_min/除数直接推出。）

- 原始方案在 256 处转到 0.0341，超出了训练时见过的 [0, 0.0085]。
- 位置插值除以 4，256 处正好回到 0.0085，没有超出连续边界的训练范围。
- base 调到 1000000，最慢平面的频率变成原来的约 1/87（100^(62/64) ≈ 86.6，数学结论），256 处只有 0.0004，也在训练范围以内。但这只说明**最慢平面**。其他平面压缩得少，最快平面（θ₀ = 1）完全不压缩：它在 256 处的未取模相位仍是 256，远超训练边界 64。所以增大 base 只能让一部分低频平面回到原来的角度范围，其余平面仍在"外推"（快平面早已转过很多圈，各个角度大多见过）。另外，直接给一个按 base = 10000 训练好的模型换 base，等于把 i > 0 的所有频率都换了，质量能否保持要实测。

两种办法都不保证"不训练就能保持质量"。位置插值让所有平面的角度落回连续的训练范围；增大 base 只对低频平面做到这一点。真实效果要靠实验，有的方法不微调也能用，有的需要在长文本上再微调一段（待验证）。`lab.md` 第 4 节（实验二）让你用训练上下文 32 的模型评测 32、64、128 的窗口。

> **概括：ALiBi 的外推思路**
>
> ALiBi 不用旋转，只在分数上减去 s·距离。距离再远，惩罚只是线性变大，没有"没见过的角度"这个问题，所以论文报告它外推较好（待验证）。代价是它强制远处分数变低，模型较难精确取回很远的信息。

## 10.9 在 LaTeX 上对比三种位置方案

### 10.9.1 实验设置

脚本第 9 部分在第 7 章的 LaTeX 语料上训练三个一样的小 GPT，只换位置方案：

- **rope**：本章的 RoPE；
- **learned**：学习式位置嵌入表（和 GPT-2 同类），注意力里不转；
- **none**：不加任何位置信息（NoPE）。

共同配置：1 层，维度 64，2 个头（每头 dh = 32），训练上下文 64，批量 64，600 步，学习率 0.003，AdamW，种子 0；共同参数初值相同，抽样的训练目标也相同（本项目观察，CPU，第 9 部分）。参数量：rope 和 none 都是 197952，learned 多一张 64 × 64 的表，是 202048。训练、评测口径见 `lab.md` 第 0 节。

### 10.9.2 结果

| 方案 | 评测上下文 64：val nat/token | bits/byte | 评测上下文 128：val nat/token | bits/byte | 128 减 64 |
|---|---|---|---|---|---|
| rope | 4.5633 | 3.2908 | 4.5632 | 3.2907 | −0.0001 |
| learned | 4.8683 | 3.5108 | 无法评测 | 不适用 | 不适用 |
| none | 4.5657 | 3.2926 | 4.5665 | 3.2932 | 0.0008 |

（本项目观察，CPU，第 9 部分。）三种模型训练各约 6.3 到 6.4 秒，差距不足以比较快慢。learned 在 128 上无法评测，脚本报告"学习式位置无定义：请求长度 128 超过训练表长 64"。按规则，这里不填数字，也不填零。

### 10.9.3 怎样读这张表

**第一，rope 和 none 几乎一样。** 4.5633 对 4.5657，只差 0.0024 nat/token。这不说明位置编码没用。回想 10.1.3 节的思考题：单层、无位置的模型，最后一个位置的输出是 Σⱼ wⱼ vⱼ，wⱼ 只由当前 token 的 q 和各个 kⱼ 决定，和 j 的顺序无关。所以单层 NoPE 模型的预测只取决于当前 token 是谁，加上前面出现过哪些 token、各出现几次，完全不看顺序（数学结论）。它和 RoPE 打成平手，很可能说明这个只有 1 层、只训练 600 步的模型，主要靠的还是出现过哪些 token，还没学会怎样利用顺序（这是推测，待验证）。单层 RoPE 原则上已经能区分历史的不同排列；要弄清它为什么在这里没有拉开差距，可以换种子、加深模型或延长训练再比较。第 13 章的消融实验有 `no_position`、`learned_position` 两个变体，由你自己完成。

**第二，learned 明显落后。** 4.8683 比 rope 高 0.305 nat/token。可能的原因有几个：64 行位置向量要从随机初值一行一行学；位置向量加在输入上，和内容混在一起（10.2.3 节）。但这只是一次种子的短训练，这些解释都是待验证的假设。你可以换种子重跑，看差距是否稳定。

**第三，"外推"在这里几乎没有考验。** rope 从 64 扩到 128，nat/token 只变了 −0.0001。可是验证集平均每条公式只有 119750 / 2000 ≈ 59.9 个目标（数学结论），大部分公式根本不足 64 个 token，换成 128 的窗口什么也没变。而且 dh = 32 的最慢平面在这么短的长度里也几乎不转。这个数字只能说明扩展数值表后能运行、没有变坏，不能说明 RoPE 外推很强。另外，窗口变长同时增加了可见的上文，所以差值里混着更多内容和超出训练位置两种影响（`lab.md` 第 0 节）。

**第四，训练区间的 loss 不是验证成绩。** 脚本每 150 步打印一次区间平均训练 loss。最后 150 步，rope 是 4.7131，learned 是 5.0009，none 是 4.6591（本项目观察，CPU，第 9 部分）。它们来自训练中途、只覆盖抽到的批次，排名可以和验证不同，不要拿来代替上表。

## 10.10 常见错误

脚本第 10 部分把几种典型错误跑了一遍。

### 10.10.1 KV cache 的位置没有接上

**现象。** 第 15 章会用 KV cache 逐个生成 token：历史 token 的 k、v 存在缓存里，新 token 只算自己。新 token 的位置应该是历史长度。如果忘了传 `pos0`，它会被当成位置 0，新 q、k 按位置 0 旋转，而缓存里的旧 k 带着真实位置。新 token 和缓存里旧 token 之间的相对距离全错了。

**实测。** 脚本用 8 个 token 的序列，先把前 7 个写进缓存，再算第 8 个。正确的 `pos0` 是 7：

```text
正确KV cache与整段logits最大差=0.0000；差值乘一百万=0.0298
新token错误pos0=0与正确logits最大差=0.0003；差值乘一百万=316.5305
```

（本项目观察，CPU，第 10 部分。）错误只造成 3.165 × 10⁻⁴ 的差，看上去很小。原因是这个模型没训练过，权重很小，注意力接近均匀分布，位置错了影响也不大。训练好的模型对位置敏感得多，同样的错误后果会严重得多（待验证，第 15 章 15.9 节在随机模型上量了这个错误，没有量训练好的模型）。所以小差值不代表没错。

**怎样发现。** 永远拿整段一次前向做参考，和缓存逐个生成的 logits 对拍。正确实现的差值应在 fp32 舍入范围内（这里是 2.98 × 10⁻⁸）。测试 `test_cache_position_offset` 同时检查正确缓存能对齐、错误缓存能被抓出来。故障演练见 `lab.md` 第 6 节。

### 10.10.2 在 bf16 里算角度

**现象。** 为了省事，把频率表和位置都转成 bf16 再相乘。bf16 只有 8 位有效二进制数字，位置 4096 乘一个频率，结果的舍入误差可以超过 1 弧度。

**实测。** dh = 64，频率量化成 bf16，再在 bf16 里乘位置、算三角函数，和 fp32 比较：

```text
位置=4096；fp32与bf16角度最大误差=1.7896；cos最大误差=0.7043；sin最大误差=1.3905
位置=8192；fp32与bf16角度最大误差=3.5792；cos最大误差=1.5714；sin最大误差=1.2364
```

（本项目观察，CPU，第 10 部分。）角度错 3.58 弧度，cos 错 1.57，而 cos 的取值范围总共才 [−1, 1]。到这个程度，位置信息已经被打乱了。注意位置 4096、8192 本身在 bf16 里可以精确表示，误差来自频率的量化、乘法和三角函数的舍入。

**怎样发现。** 在长位置上（几千以上）拿 fp32 的表对拍。正确做法是 `rope_cache` 那样：角度、cos、sin 全在 fp32 里算，最后才在 `apply_rope` 里转成激活的 dtype。

### 10.10.3 把 RoPE 加在 v 上

**现象。** 模型能训练，但同一段内容放在不同绝对位置，输出不同（10.6 节）。

**实测。** 第 10 部分复用第 6 部分的演示：起始位置 0 和 50，输出最大差 2.5195（本项目观察，CPU，第 10 部分）。

**怎样发现。** 做平移测试：同一段输入，起始位置挪一挪，只转 q、k 时注意力输出应在舍入误差内相等。测试 `test_value_rotation_breaks_shift_invariance`。

### 10.10.4 两种约定混用

**现象。** 加载别人训练好的权重，不报错，输出却是乱码；自己写的平移测试照样通过。见 10.5.5 节，分数差可达 15.5293（本项目观察，CPU，第 5 部分）。

**怎样发现。** 和独立参考实现逐元素对拍；加载预训练模型时，和官方实现对拍一小段 logits（方法见第 17 章 17.7 节）。

### 10.10.5 其他常见错误

| 错误 | 现象 | 怎样发现 |
|---|---|---|
| 频率指数写成 `arange(dh//2) / dh`（漏了 2） | 频率衰减变慢，和预训练模型对不上；平移测试仍通过 | 和 θᵢ = base^(−2i/dh) 的手算表对拍；`test_frequency_exponent_and_repeated_halves` |
| 只乘 cos，忘了 `rotate_half(x) * sin` | 不再是旋转，长度改变 | 检查范数是否保持；`test_oracle_rejects_common_mistakes` |
| cos、sin 表用 `repeat_interleave` 而不是 `cat` | 表按相邻约定排，旋转按前后约定配对，一对的两维拿到不同角度，不再是旋转 | 范数检查；和独立参考对拍 |
| dh 是奇数 | 凑不成对 | `rope_cache` 直接报错：`头维度=7；异常=ValueError: RoPE 的 dh 必须是正偶数`（本项目观察，CPU，第 10 部分） |
| 在拆头之前对 (B, T, d) 加 RoPE | 频率按 d 而不是 dh 算，每个头拿到的频率网格不对 | 检查 `apply_rope` 收到的最后一维是 dh |
| 学习式位置超过表长 | `IndexError` 或被静默截断 | 显式检查长度；本章 `PositionGPT.set_context` 会明确报错 |

## 10.12 小结

- **注意力需要位置**：无位置、无 mask 的自注意力对输入置换等变，Attn(PX) = P · Attn(X)，分不清 `a^{2}` 和 `2^{a}`；因果 mask 只漏出一点隐式位置信息，所以要用位置编码明确告诉它。
- **绝对位置编码**把 pₜ 加到输入上。学习式是一张 T_max × d 的表，超过表长的位置没有定义；正弦式 PE(t, 2i) = sin(tωᵢ)、PE(t, 2i+1) = cos(tωᵢ)，自身点积 Σᵢ cos((n − m)ωᵢ) 只看距离，但加到内容上、经过 q/k 投影后，q·k 拆成四项，这个性质就没了。
- **RoPE 的二维推导**：位置 t 的向量转 tθ。由 R(mθ)ᵀ R(nθ) = R(−mθ) R(nθ) = R((n − m)θ)，得到 f(q, m) · f(k, n) = qᵀ R((n − m)θ) k，展开是 (q₀k₀ + q₁k₁) cos α + (q₁k₀ − q₀k₁) sin α，α = (n − m)θ。复数写法是 Re[conj(q) k e^{i(n−m)θ}]，e^{−imθ} 和 e^{inθ} 相乘只剩角度差。这个性质说的是固定的 q、k 一起平移，分数不变。
- **d 维与频率**：dh 维切成 dh/2 个平面，总点积是各平面点积之和，所以仍只依赖 n − m。频率 θᵢ = base^(−2i/dh)，波长 λᵢ = 2π/θᵢ，快平面分辨近处，慢平面分辨远处。
- **实现**只有一行：x ⊙ cos + rotate_half(x) ⊙ sin，其中 rotate_half([x₁, x₂]) = [−x₂, x₁]；cos、sin 表在 fp32 里算并复制成两半，在拆头之后、写入 KV cache 之前作用在 q、k 上。"前后两半"和"相邻两维"只差一个维度置换；混用不报错、平移测试也查不出，只能靠独立参考对拍。
- **只转 q、k，不转 v**：位置只该影响"看谁"。转了 v，整段平移 s 会让输出多转 R(sθ)，带上绝对位置。
- **base 与长上下文**：base 变大时 θ₀ = 1 不变，其余平面变慢。位置插值把位置 m 换成 m/s；NTK-aware 缩放取 base' = base · s^(dh/(dh−2))（dh > 2），让最慢的频率恰好缩小 s 倍。两者都不保证不训练就能变长。"远程衰减"是平均意义上的上界趋势，不是单调保证，全 1 向量的例子里分数就会反弹。
- **最常见的错误都不报错**：KV cache 里新 token 忘了传 pos0，它和缓存里旧 token 之间的相对距离全错，在未训练的模型上差值很小，不代表没错；在 bf16 里算角度，位置到几千时角度误差能超过 1 弧度。前者和整段一次前向对拍，后者在长位置上和 fp32 的表对拍。
- 在 1 层、600 步、单种子的 LaTeX 短训练上，rope 和不加位置几乎打平（4.5633 对 4.5657 nat/token），learned 落后（4.8683），且无法在超过表长的 128 窗口上评测（本项目观察，CPU，第 9 部分）。这个规模的实验分不出 RoPE 的好处，也考验不了外推。
