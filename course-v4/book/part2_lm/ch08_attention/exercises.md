## 答案与提示

### 概念题要点

- **C1.** 必须完全匹配；结果是跳变的（命中或不命中），没有梯度。软查找用相似度代替完全匹配，用 softmax 加权平均代替"取一个"，处处可导。
- **C2.** 见正文 8.3.4 节："我想找什么"和"我能被怎样找到"不同（q = k 时每个 token 和自己的分数总是 q·q ≥ 0，不能变成负数，想少看自己只能抬高别人的分数）；"按什么匹配"和"取回什么"不同（查表任务按键匹配、取回值）。
- **C3.** 每个查询要把自己的注意力分配给所有键，权重之和应该等于 1，所以沿键的方向归一化。做错不会报错，形状也对，只是结果错了。
- **C4.** 点积的方差是 d，标准差是 √d，要把标准差变成 1，所以除以 √d。方差为 σ² 时，点积方差是 dσ⁴，应除以 √d · σ²（见 H7）。
- **C5.** −∞ 让 e^{−∞} = 0，权重恰好为 0；−10 只会让权重很小但不为 0，信息仍会泄漏。−1e9 在 fp32 下效果和 −∞ 几乎一样，而且整行被遮时不会产生 NaN（得到均匀分布）；−∞ 在整行被遮时会得到 0/0 = NaN。fp16 下 −1e9 超出了能表示的范围（最大 65504）：对 fp16 的分数调用 `masked_fill(..., -1e9)` 会直接报溢出错误；先建一个 fp32 张量再转成 fp16，−1e9 会变成 −inf。所以练习 8.4 用 `torch.finfo(dtype).min`。
- **C6.** 遮的是键。补齐位置不应该被任何查询取信息；而补齐位置自己作为查询时的输出不进 loss，看什么都无所谓。
- **C7.** 无关，4(d² + d)。好处是可以并行地问多个问题，各头关注不同的信息；代价是每个头的维度 d/h 变小。
- **C8.** 一个 token 的 d 维在内存里是连续的，先 view 可以把它正确地切成 h × d_h；先 `transpose(1, 2)` 再 `reshape(B, h, T, d_h)` 会切错维度；先转置也可以，但必须仍沿 d 维拆头（正文 8.8.3 节）。合并时，transpose 后的步长不能直接用 view 合并头维，reshape 会在需要时复制数据。
- **C9.** 自注意力对输入置换等变（正文 8.9.2 节）。`a^b` 和 `b^a`、`\frac{a}{b}` 和 `\frac{b}{a}` 会得到同一组向量，模型无法区分。
- **C10.** 计算量的核心部分约 4T²d，权重矩阵内存 ∝ T²，都和 T 的平方成正比。高分辨率图片切出的视觉 token 很多，平方增长会让计算和显存迅速变大，所以 VLM 要压缩视觉 token。
- **C11.** 自注意力的 q、k、v 来自同一个序列；交叉注意力的 q 来自一个序列，k、v 来自另一个序列。打乱键值序列，输出完全不变：权重的列被打乱，v 的行也按同样方式打乱，二者相乘后抵消。
- **C12.** 模型可能停在了平台解上（实验手册实验三）。构造简单基线（随机、众数等），看模型的预测和哪个一致；同时用小批量过拟合检查代码是否正确。
- **C13.** (a) MLP 的输入只有最后 8 个 token，窗口外的 token 根本不进入计算，换成什么输出都一模一样，这是结构决定的。(b) 377 对远距离配对里只有 357 对的左括号在 64 个 token 的窗口内，另外 20 对仍在窗口外，变化为 0；357 ÷ 377 = 0.9469，正好等于非零比例。这次运行中窗口内的全变，窗口外的全不变；后者是结构保证的，前者只是观察（浮点下溢或舍入可能让可见 token 的影响恰好消失）。(c) 在实数运算里，softmax 只有输入为 −∞ 时输出才是 0。没被 mask 的位置权重总是正数，换掉它会改变它的值（直接改变加权平均）和键（改变分数和 softmax 分母）。所以只要 token 可见，输出通常都会变化。变化不为 0 只说明存在信息通路，不说明模型学会了用它；何况平均变化只有 0.0018，约为平均概率 0.1764 的 1%。
- **C14.** (a) 不能。理由：输出是权重 × 值的加和，权重小但值向量可能很大，只看权重看不到贡献；替换 token 会同时改变键和值，还会通过 softmax 分母影响其他位置，权重和"换掉它的影响"是两个不同的量；多层模型中，某层位置 j 的表示已混入别处信息（本例只有一层，但这条在一般情况下成立）。不过，权重低于均匀分配至少说明它没有像查表任务那样"盯着"左括号。(b) 做干预实验：替换左括号（或换成别的定界符），看 `right` 位置的概率怎样变；同时设置对照（比如替换同样距离的一个无关 token），比较两种替换的影响。
- **C15.** (a) 每步目标数不同（MLP 256，注意力 128），总训练量注意力只有一半；参数量不同（856,146 对 312,018）；结构不同（MLP 有带非线性的隐藏层，注意力模型除 softmax 外从取回向量到 logits 都是线性的）；只训练 1200 步，验证 loss 仍在下降；只有一个种子。(b) 少了残差连接（每个位置的输出只有加权平均，要保留自身信息必须和别处抢权重）、前馈网络（取回信息后缺少非线性加工）、归一化（层数多时稳定数值尺度），以及多层（括号配对可能需要不止一步）。这些都是可能原因，要用第 9 章以后的实验检验。

### 手算题答案

- **H1.** 分数 [2, 0] / √2 = [1.4142, 0]；权重 = [e^1.4142, 1] / (e^1.4142 + 1) = [0.8044, 0.1956]；输出 = 0.1956 × 10 = 1.956。
- **H2.** e^分数 = [16.9184, 69.5885, 286.2599]，和 372.7668；权重 [0.0454, 0.1867, 0.7679]；o3 = 0.0454 × [1, 1] + 0.1867 × [2, 1] + 0.7679 × [2, 2] = [1.9546, 1.7679]。
- **H3.** (a) 点积 [2, −2, 0]，除以 √2 得 [1.4142, −1.4142, 0]；权重 [0.7679, 0.0454, 0.1867]；输出 0.7679 × 1 + 0.0454 × 2 + 0.1867 × 3 = 1.4188。(b) 只剩前两个：权重 [0.9442, 0.0558, 0]；输出 1.0558。(c) q = [1, 1] 和 k3 = [1, −1] 正交，点积为 0。
- **H4.** 4 × (1024² + 1024) = 4,198,400；32 个头时不变。
- **H5.** 8 × 12 × 1024² × 4 字节 = 384 MiB；T = 4096 时是 16 倍，6 GiB。
- **H6.** 核心 4T²d = 4 × 2048² × 768 ≈ 12.9 GFLOPs；投影 8Td² = 8 × 2048 × 768² ≈ 9.7 GFLOPs；核心更大。两部分相等时 T = 2d = 1536。
- **H7.** 每一项 q_i k_i 均值 0，方差 E[q_i²]E[k_i²] = σ⁴；d 项之和的方差 dσ⁴，标准差 √d · σ²。应除以 √d · σ²。
- **H8.** 因果 mask 是下三角。补齐 mask 每行都是 [F, F, T, T]。相与后：

  ```
  行 0  F F F F
  行 1  F F F F
  行 2  F F T F
  行 3  F F T T
  ```

  第 0、1 行全是 False，会产生 NaN。这两行是补齐位置作为查询的行。
- **H9.** (a) bits/token = 4.1448 ÷ ln 2 = 4.1448 ÷ 0.6931 = 5.980；每 token 平均字节 = 239,566 ÷ 119,750 = 2.0006；bits/byte = 5.980 ÷ 2.0006 = 2.989。(b) 困惑度 = e^4.1448 ≈ 63.10。(c) 不会。同一个分词器、同一份验证集时，每 token 平均字节数是同一个常数，bits/byte 只是 nat/token 乘以一个固定系数（1 ÷ (ln 2 × 2.0006)），排序不变。只有比较不同分词器时，两者才可能给出相反的结论（第 7 章 7.10 节）。

- **8.5** 交叉注意力里，打乱 kv 相当于右乘 Pᵀ 打乱分数的列、左乘 P 打乱 V 的行：A Pᵀ P V = A V。
- **8.6** 先构造 (B, T) 的 keep，再写成 `causal_mask(T) & keep[:, None, None, :]`（正文 8.7.2 节的表）；用 `~mask.any(-1)` 找出全 False 的行，把这些行的对角线置为 True。

### 调试题答案

- **D1.** softmax 沿了 `-2`，变成每一列和为 1。不报错，形状也对，但模型效果差。改成 `softmax(-1)`。测试：`weights.sum(-1)` 应全为 1；和 SDPA 对拍。
- **D2.** 先 transpose 再 reshape，切开的不是每个 token 的 d 维，数据错乱。不报错。改成先 `view(B, T, h, dh)` 再 `transpose(1, 2)`。测试：和 `nn.MultiheadAttention` 对拍。
- **D3.** mask 的含义用反了：把"可以看"的位置设成了 −∞。因果 mask 时，前面各行反而只能看未来；最后一行原本能看所有位置，现在被全部设成 −∞，得到 NaN。补齐 mask 时则只看补齐位置。改成 `masked_fill(~mask, ...)`。测试：因果时检查 `w[..., 0, 0] == 1`（第 0 行只能看自己），并检查输出里没有 NaN。
- **D4.** 除以 d 而不是 √d，分数过小，softmax 接近均匀分布，模型很难学会集中注意力。不报错。改成 `/ math.sqrt(d)`。测试：和 SDPA 对拍。
- **D5.** 第 5 个位置参数是 `dropout_p`，传 True 等于 dropout 概率为 1，输出全为 0。改成 `is_causal=True` 关键字。测试：输出不应全为 0；和手写的因果注意力对拍。
- **D6.** 输入多放了一个 token：`ids[:target + 1]` 把 `right` 本身也喂了进去。最后一个查询变成了 `right` 自己，它对应的是"预测 `right` 的下一个 token"，而且这时模型已经看到了答案，它的注意力分布不能说明"猜 `right` 时看哪里"。如果再拿这个位置的输出去算 `right` 的概率，就更错了。不报错。改成 `x = torch.tensor([[bos] + ids[:target]])`，最后一个查询是 `right` 前面那个输入位置；左括号在 `[bos] + ...` 里的下标是 `source + 1`，这一点原代码是对的。测试：检查输入长度等于 `target + 1`（BOS 加上 `right` 之前的 `target` 个 token），并检查 `x[0, source + 1] == ids[source]`。
- **D7.** 分母用了窗口总长 `x.shape[1]`，把右侧补齐的位置也算成"可见"。补齐的键被 mask 掉，权重为 0，不应计入。短窗口时这会把均匀基线算得偏小，让模型的权重看起来"高于均匀"。不报错。改成 `uniform = 1.0 / lengths.float()`。测试：构造一行 `lengths = 3` 的窗口，检查均匀基线是 1/3，并检查模型权重在补齐位置上全为 0、每行可见位置的权重和为 1。
