# 第 11 章　搭建 GPT 与初始化

## 本章导读

零件都齐了。第 8 章有了因果多头注意力，第 9 章把注意力和前馈网络装进了一个 Pre-Norm 块，第 10 章给注意力配上了 RoPE。这一章把它们拼成一个完整的语言模型：GPT。

拼起来只要十几行代码。难的是另一件事：怎样在训练之前就知道它拼对了。

一个装错的 GPT 通常不会报错。形状全对，loss 照样下降，有时还降得特别漂亮。第 11.8 节会看到一个例子：标签忘了错开一位，训练 loss 350 步就掉到 0.0759；可是换成正确的评测，验证 nat/token 是 12.8650，比闭着眼睛均匀乱猜（ln 2258 ≈ 7.7222）还差得多（本项目观察，CPU，第 7 部分）。

所以本章有两条线：

1. **搭起来**：完整前向（11.1–11.2）、参数量（11.3）、输出层和嵌入共享权重（11.4）。
2. **查一遍**：初始 loss 应该约等于 ln V（11.5）；残差支路的输出层按 1/√(2L) 缩小初始化（11.6）；能把一个固定批次背下来（11.7）；认出两类"低得可疑"的 loss（11.8）。

最后用一个"概括"框扫一眼真实模型的配置（11.9），再汇总常见错误（11.10）。

**和项目的关系。** 这个 GPT 就是 TexPixel 项目里的 LaTeX 语言模型：给它前半个公式，它预测下一个 token。第 13 章给出完整的训练流程，实验由你自己完成。到第 31 章，同一个类会变成 OCR 模型的**解码器**：图片编码器输出的视觉特征通过 `inputs_embeds` 参数送进来，后面的块、归一化和输出层一行不改。

**本章的数字从哪里来。** 正文里每个"本项目观察"的数字，都来自本书作者在 CPU（两个线程）上完整运行一次本章脚本：

```bash
CUDA_VISIBLE_DEVICES="" python -m book.part2_lm.ch11_gpt.tour
```

整个脚本用时约 47–48 秒（本项目观察，CPU，tour 全部部分），用时类数字会随机器负载变化。后面每个数字都注明脚本部分号。实验的具体做法、对照边界和记录表在 `lab.md`，正文只引用它的部分号。

> **回顾：本章要用到的先修知识**
>
> - **交叉熵**（第 3 章、第 7 章）：正确类别的概率是 p，这一步的 loss 是 −ln p。均匀猜 V 个类，loss 就是 ln V。
> - **错开一位**（第 7 章 7.2 节）：输入 x = 序列[:-1]，目标 y = 序列[1:]。位置 t 的目标是第 t+1 个 token。
> - **因果注意力**（第 8 章）：第 t 个位置只能看 0…t。`F.scaled_dot_product_attention` 的布尔 mask 里 True 表示"可以看"。
> - **Pre-Norm 块**（第 9 章 9.6 节）：`x = x + Attn(n1(x))`，`x = x + MLP(n2(x))`；一个块的参数是 4d² + 3df + 2d。最后一个块后面还要再接一个归一化（第 9 章 9.8 节）。
> - **RoPE**（第 10 章）：位置靠旋转 q、k 注入，cos、sin 表是缓冲区（buffer），不是参数。
> - **评测口径**（第 7 章）：词表 2258（含 BOS、EOS），验证集前 2000 条公式，119,750 个预测目标，原文 239,566 个字节（本项目观察，CPU，第 7 部分）。

## 11.1 从部件到模型

### 11.1.1 一张图看完 GPT

先给结论。GPT 就是四步：

```text
token 编号 idx (B, T)
    │  ① 词嵌入：查表
    ▼
x (B, T, d)
    │  ② N 个 Pre-Norm 块（每块内部：注意力 + 前馈，各带残差）
    ▼
x (B, T, d)
    │  ③ 最后的 RMSNorm
    ▼
h (B, T, d)
    │  ④ 输出层：乘一个 V × d 矩阵
    ▼
logits (B, T, V)
```

一个日常类比：把 GPT 想成一条流水线。①是"入场登记"，把每个 token 编号换成一张 d 维的卡片；②是 N 道工序，每道工序在卡片上"补写"一点东西（残差：不擦掉重写，只往上加）；③是"整理格式"，把卡片的尺度拉回统一大小；④是"打分"，拿卡片和词表里每个 token 比一比，给出 V 个分数。

这里没有位置嵌入。位置信息在每个注意力层里由 RoPE 注入（第 10 章），所以①只有一张表。

### 11.1.2 本书的默认配置

`GPTConfig` 的类默认值是词表 2048、上下文 256；本章脚本 `Experiment.model(book=True)` 把词表换成实际分词器的大小、上下文换成 128，其余用默认值。本章大部分实验用的就是这一组，本书称为"本书配置"（`lab.md` 第 0 节）：

| 符号 | 含义 | 值 |
|---|---|---|
| V | 词表大小 | 2258 |
| T_max | 最长上下文 `block_size` | 128 |
| L | 层数 `n_layer` | 4 |
| h | 头数 `n_head` | 4 |
| d | 模型维度 `d_model` | 256 |
| f | SwiGLU 中间维 `ff_dim()` | 704 |
| — | 输出层与嵌入共享 `tie_weights` | True |

V = 2258 是本次训练出的 BPE 词表大小（本项目观察，CPU，第 1 部分）。f = 704 是算出来的，11.3 节会算。

### 11.1.3 每一步的形状

第 1 部分给本书配置的每个模块挂上 hook，送进一批 B = 2、T = 16 的 token，打印每个模块的输出形状（本项目观察，CPU，第 1 部分）：

| 模块 | 输出形状 |
|---|---|
| 词嵌入 `tok` | (2, 16, 256) |
| 块 1 … 块 4 | 每个都是 (2, 16, 256) |
| 最后归一化 `norm` | (2, 16, 256) |
| 输出层 `head` | (2, 16, 2258) |

一路上只有最后一步改变了最后一维。其余每一步进出都是 (B, T, d)。"残差流"就是这个样子：一条宽度为 d 的传送带从头走到尾，每个块往上面加东西。

注意最后一个张量有多大：每个位置 2258 个分数，而隐藏状态只有 256 维，前者是后者的约 8.8 倍（数学结论）。小模型里，logits 往往是最大的那个激活张量。第 16 章讲显存时会回到这一点。

## 11.2 前向一步步

### 11.2.1 动机：forward 要负责哪些事

`GPT.forward` 要做的不只是"跑一遍网络"。它还要：

- 接受 token 编号，也接受现成的向量（第 31 章拼视觉特征时用）；
- 知道这批 token 的第一个位置编号是几（第 15 章 KV cache 逐个生成时用）；
- 给了目标就算 loss，并且允许某些位置不计入 loss。

我们一项一项来。

### 11.2.2 推导：从 idx 到 loss

设输入是 idx ∈ {0,…,V−1}^{B×T}，目标是 y，形状相同。

**第 1 步：查表。** x⁽⁰⁾ = E[idx]，E 是 V × d 的嵌入矩阵。形状 (B, T) → (B, T, d)。

**第 2 步：取位置表。** 这批 token 的位置是 pos0, pos0+1, …, pos0+T−1。从预先算好的 cos、sin 表（形状 (T_max, dh)）里切出这 T 行。所以必须满足 pos0 + T ≤ T_max。

**第 3 步：过 L 个块。** 对 l = 1…L：

```text
x ← x + Attn_l(RMSNorm(x))      ← 位置在这里注入
x ← x + MLP_l(RMSNorm(x))
```

**第 4 步：最后归一化。** h = RMSNorm(x⁽ᴸ⁾)。

**第 5 步：输出层。** logits = h Wᵀ，W 是 V × d。共享权重时 W 就是 E（11.4 节）。形状 (B, T, d) → (B, T, V)。

**第 6 步：交叉熵。** 把 logits 摊平成 (B·T, V)，目标摊平成 (B·T,)，对每一行算 −log softmax(logits)[y]，再对**计入的位置**取平均：

```text
loss = (1 / |S|) · Σ_{(b,t)∈S} [ log Σ_j exp(z_{b,t,j}) − z_{b,t,y_{b,t}} ]
```

S 是计入 loss 的位置集合：目标不等于 −100，并且 loss_mask 为 True。

有一件事 forward **不做**：它不会替你把目标错开一位。传进来的 y 必须已经是"下一个 token"。11.8 节会看到，这条约定一旦和数据端对不上，后果有多严重。

### 11.2.3 数值例子

用一个小到能手算的例子走一遍第 6 步。设 B = 1、T = 3、V = 5、d = 4：

```text
idx     = [[1, 3, 4]]            (1, 3)
x       = E[idx]                 (1, 3, 4)
……经过块、归一化……
h                                (1, 3, 4)
logits  = h Wᵀ                   (1, 3, 5)
y       = [[3, 4, 2]]            (1, 3)     ← 已经错开一位：位置 0 的目标是 idx 的下一个 token 3
```

假设位置 0 的 logits 是 z = [0, 1, 0, 2, 0]，目标是 3。这一行的 loss：

```text
log Σ exp(z) = log(e⁰ + e¹ + e⁰ + e² + e⁰)
             = log(1 + 2.7183 + 1 + 7.3891 + 1)
             = log(13.1074) = 2.5732
loss₀ = 2.5732 − z₃ = 2.5732 − 2 = 0.5732
```

（数学结论。）

如果把位置 1 的目标设成 −100，或者 loss_mask[0, 1] = False，那么 S 只有位置 0 和 2，平均时分母是 2，不是 3。

### 11.2.4 对照代码逐行讲

下面是 `miniocr/models/gpt.py` 里的 `GPT.forward`（练习 11.2 要你自己写出来）：

```python
def forward(self, idx=None, targets=None, inputs_embeds=None, caches=None, pos0=0, loss_mask=None):
    x = self.tok(idx) if inputs_embeds is None else inputs_embeds          # (1)
    T = x.shape[1]
    assert pos0 + T <= self.cfg.block_size, f"序列长 {pos0 + T} 超过 block_size {self.cfg.block_size}"  # (2)
    cos, sin = self.cos[pos0:pos0 + T], self.sin[pos0:pos0 + T]           # (3)
    for i, b in enumerate(self.blocks):
        x = b(x, cos, sin, None if caches is None else caches[i])          # (4)
    logits = self.head(self.norm(x))                                       # (5)
    loss = None
    if targets is not None:
        if loss_mask is not None:
            targets = targets.masked_fill(~loss_mask, -100)                # (6)
        loss = F.cross_entropy(logits.reshape(-1, logits.shape[-1]).float(),
                               targets.reshape(-1), ignore_index=-100)     # (7)
    return logits, loss
```

用上面的数字逐行对：

- **(1)** idx 形状 (1, 3)，查表得到 (1, 3, 4)。如果调用方直接给了 `inputs_embeds`（形状 (1, 3, 4)），就跳过查表。第 31 章正是靠这一行把图片特征"假装"成 token 嵌入送进来。
- **(2)** pos0 = 0、T = 3，要求 3 ≤ block_size。注意是 **pos0 + T**，不是 T：用 KV cache 生成到第 126 个位置时，新来的一个 token 的 T 只有 1，但它的位置是 126。超出时第 9 部分打印的异常是 `AssertionError: 序列长 129 超过 block_size 128`（本项目观察，CPU，第 9 部分）。
- **(3)** 切出位置 0、1、2 的 cos、sin，每个形状 (3, dh)。所有块共用这一份。
- **(4)** 依次过每个块。每块的 forward 就是第 9 章 9.6 节写的两次 Pre-Norm 残差。`caches` 是第 15 章的事，这里传 None。
- **(5)** 先 `self.norm`，再 `self.head`。(1, 3, 4) → (1, 3, 5)。这一行最容易漏掉 `self.norm`，11.10 节会看到漏了之后发生什么。
- **(6)** 把 loss_mask 为 False 的位置改成 −100。`masked_fill` 返回新张量，**不改调用方的 targets**——测试 `test_loss_mask_and_ignore_index` 专门检查了这一点。
- **(7)** 摊平成 (3, 5) 和 (3,)，在 float32 里算交叉熵（bf16 训练时 logits 可能是 bf16，log-sum-exp 在低精度里容易丢精度），`ignore_index=-100` 让被屏蔽的位置既不进分子也不进分母。

**BOS 的约定从这一章起变了。** 第 7 章 7.6.1 节的 MLP 在训练、评测、采样三处都屏蔽 BOS 这一类。从本章起，训练和评测分开处理（`lab.md` 第 0 节"数据与评测口径"）：

- **训练**：BOS 作为**目标**被忽略（loss_mask = y ≠ BOS），但 forward 输出的仍是全部 V 个类别的分数，softmax 的分母里有 BOS，这一类没有被屏蔽。
- **评测**：沿用第 7 章的口径，BOS 只作条件，它的输出被屏蔽，概率只在其余 V−1 个类别上分配。

"忽略 BOS 目标"和"屏蔽 BOS 输出"是两个操作。这个变化有三点影响。第一，训练 loss 的初始参照点是 ln V，屏蔽后的参照点是 ln(V−1)，11.5 节会看到两种算法的初始 loss 只差万分之几。第二，训练 loss 和验证 nat/token 不是完全相同的量：对同一组 logits，屏蔽 BOS 相当于把其余类别的概率按同一比例放大，目标的 −ln p 只会变小或不变（数学结论）；训练之后两者因此差多少，本章没有单独测量。第三，因为评测口径没变，验证成绩仍能和第 7 章的基线放在同一张表里，但两边的训练做法多了这一处差别。生成时 forward 同样不替你屏蔽，这件事由调用方负责，第 14 章的生成代码就是这样做的。

### 11.2.5 常见错误

| 错误 | 现象 | 怎样发现 |
|---|---|---|
| 漏了最后的 `self.norm` | 形状全对，初始 loss 也正常（11.10.1 节解释为什么） | 和独立参考实现对拍：`test_gpt_reference_rejects_missing_norm_and_residual` |
| 只检查 T ≤ block_size，不加 pos0 | 带 cache 生成时位置表切片越界或悄悄切短 | `test_block_size_boundary_includes_pos0` |
| 在 forward 里再错开一次目标 | 模型学的是"隔一个预测"，loss 高低方向不定 | `test_next_token_loss_uses_supplied_shifted_targets_without_second_shift` |
| 用 `targets[~loss_mask] = -100` 原地改 | 调用方的标签被改坏，下一次复用同一批数据时出错 | 测试检查 targets 前后相等 |

## 11.3 参数量公式

### 11.3.1 动机：为什么要会手算

"这个模型有多大？"是你对任何模型问的第一个问题。它决定显存、训练时间、能吃多少数据（第 13 章的 scaling 规律就以参数量为横轴）。

手算参数量还有一个更实际的用处：它相当于一个免费的单元测试。公式算出来和 `n_params()` 对不上，说明代码里多了或少了某个矩阵。

### 11.3.2 直觉：参数都住在哪里

参数只住在三类地方：

1. **表**：词嵌入 V × d。
2. **矩阵**：注意力的 4 个、前馈的 3 个，每个块一套。
3. **归一化的 γ**：每个 RMSNorm 一个长度 d 的向量。

不住参数的地方同样重要：RoPE 的 cos、sin 表是 `register_buffer` 注册的缓冲区，不参与训练，不算参数；所有线性层都没有偏置；共享权重时，输出层没有自己的矩阵。

### 11.3.3 一步一步推导

**词嵌入。** V 个 token，每个一行 d 维：**V·d**。

**注意力。** q、k、v、o 四个投影。普通多头注意力里 h·dh = d，所以每个都是 d × d，没有偏置：**4d²**。注意它和头数无关（第 8 章 8.8.4 节）。

**前馈（SwiGLU）。** gate 和 up 是 d → f，down 是 f → d：**3df**。

**块内两个归一化。** 每个 γ 长度 d：**2d**。

**最后归一化。** **d**。

**输出层。** 共享时 **0**；不共享时再加 **V·d**。

加起来（数学结论）：

```text
N = V·d + L·(4d² + 3df + 2d) + d          （共享权重）
N = 2·V·d + L·(4d² + 3df + 2d) + d        （不共享）
```

**中间维 f 从哪里来。** `ff_dim()` 的规则是：f ≈ 8d/3，再向上取整到 64 的倍数。为什么是 8/3？SwiGLU 有三个矩阵，经典 GELU MLP 只有两个（d → 4d → d，共 8d²）。让 3df = 8d²，就得 f = 8d/3，两种前馈的参数量相同（第 9 章 9.5 节）。取整到 64 的倍数是为了让矩阵乘法在硬件上更整齐。

**一个好记的近似。** 把 3df ≈ 8d² 代进去，忽略 2d 这种小项，每块约 **12d²**。所以非嵌入参数约 **12·L·d²**。第 13 章讨论 scaling 时，常用的就是"非嵌入参数量"。

### 11.3.4 数值例子：手算本书配置

V = 2258，d = 256，L = 4。

先算 f：

```text
8 × 256 / 3 = 682.67
682.67 / 64 = 10.67  →  向上取整 11
f = 11 × 64 = 704
```

再逐项算：

| 项目 | 公式 | 计算 | 参数量 |
|---|---|---|---|
| 词嵌入 | V·d | 2258 × 256 | 578,048 |
| 每块注意力 | 4d² | 4 × 65,536 | 262,144 |
| 每块前馈 | 3df | 3 × 256 × 704 | 540,672 |
| 每块两个归一化 | 2d | 2 × 256 | 512 |
| 每块合计 | | 262,144 + 540,672 + 512 | 803,328 |
| L 个块 | | 4 × 803,328 | 3,213,312 |
| 最后归一化 | d | | 256 |
| 输出层（共享） | 0 | | 0 |
| **总计** | | 578,048 + 3,213,312 + 256 | **3,791,616** |

（以上都是数学结论。）

几个比例：

- 嵌入占 578,048 / 3,791,616 ≈ 15.2%。
- 每块里前馈占 540,672 / 803,328 ≈ 67.3%，和第 9 章 9.6.2 节"一个块的大头在前馈"一致。
- 近似式 12Ld² = 12 × 4 × 65,536 = 3,145,728，比精确的非嵌入参数 3,213,568 少约 2%：f 被向上取整到 704（比 682.67 大），归一化也没算进去。

不共享时多一个 V·d：3,791,616 + 578,048 = 4,369,664。

### 11.3.5 对照代码

第 2 部分逐项打印公式值，再和代码实测对拍（本项目观察，CPU，第 2 部分）：

```text
项目=词嵌入；参数量=578048
项目=每块注意力；参数量=262144
项目=每块前馈；参数量=540672
项目=每块两个归一化；参数量=512
项目=最后归一化；参数量=256
中间维=704；公式总数=3791616；n_params实测=3791616；不共享增加=578048
不共享实测=4369664；实测增加=578048
```

每一项都和上表对上。代码这边，`n_params` 只有两行：

```python
def n_params(self, non_embedding=False):
    n = sum(p.numel() for p in self.parameters())     # 共享的权重只算一次
    return n - self.tok.weight.numel() if non_embedding else n
```

关键在 `self.parameters()`：PyTorch 遍历参数时会**按对象去重**。`head.weight` 和 `tok.weight` 是同一个 Parameter 对象，只被数一次。缓冲区（cos、sin）不在 `parameters()` 里，也不会被数到。

`non_embedding=True` 减掉嵌入表。共享时这正好是"所有不在嵌入表里的参数"：3,791,616 − 578,048 = 3,213,568（数学结论）。

`tour.py` 里的 `parameter_terms` 把同一个公式写成逐项字典，测试 `test_parameter_formula` 在三组配置、共享和不共享两种情况下都检查"公式 = n_params"。

### 11.3.6 常见错误

- **用 `state_dict()` 数参数。** `state_dict` 按名字列出张量，共享的矩阵会以 `tok.weight` 和 `head.weight` 两个名字各出现一次。第 9 部分实测：`parameters()` 去重计数 3,791,616，`state_dict` 计数 4,369,664，多算了 578,048，恰好是 V·d（本项目观察，CPU，第 9 部分）。
- **把 f 当成 4d。** 那是 GPT-2 的 GELU MLP。SwiGLU 是三个矩阵、f ≈ 8d/3。
- **把 RoPE 表算进参数。** 它们是缓冲区。用 `parameters()` 数就不会犯这个错，手写公式时容易犯。
- **把 GQA（几个 q 头共用一组 k、v，第 15 章）也套 4d²。** k、v 的输出维度变成 h_kv·dh，公式要改。本章的 `parameter_count` 遇到 GQA 或 Q/K norm 会直接抛 `ValueError`，不硬算。

## 11.4 输出层与嵌入共享权重

### 11.4.1 动机

本书配置里，嵌入表有 578,048 个参数。输出层如果单独一个矩阵，又是 578,048 个。两个矩阵形状一样，都是 V × d。能不能只要一个？

能。这叫**权重共享**（weight tying）：输出层直接用嵌入矩阵。GPT-2、本地 Qwen3.5-0.8B 配置（11.9 节）都这样做。

### 11.4.2 直觉：同一本"词典"，两种查法

把嵌入矩阵 E 的第 i 行 eᵢ 看成"token i 的名片"。

- **输入端**：看到 token i，就把它的名片 eᵢ 拿出来。这是"按编号查名片"。
- **输出端**：模型算出一个向量 h，要问"h 最像哪个 token？"最直接的办法是拿 h 和每张名片做点积：zᵢ = eᵢ · h。点积大，说明像。这是"按内容找名片"。

两端都在说"token i 在这个 d 维空间里长什么样"，用同一本名片册很自然。

共享还有一个好处，和稀有 token 有关。输入端只有**真正出现**的 token 才会被查表、才有梯度；输出端每一步都对**全部** V 个类别算 softmax，每一行都有梯度。共享以后，一个在输入里很少出现的 token，它的名片也能靠输出端每一步得到更新。

### 11.4.3 推导：梯度是两条路径之和

共享以后，loss 通过两条路依赖同一个矩阵 E：

```text
路径 A（嵌入）：E → x⁽⁰⁾ = E[idx] → …… → loss
路径 B（输出）：E → logits = h Eᵀ → loss
```

多元微积分的链式法则说：一个变量通过几条路影响结果，总导数就是各条路的导数之和。所以（数学结论）：

```text
∂loss/∂E = ∂loss/∂E |路径A + ∂loss/∂E |路径B
```

两条路各自是什么样子？

- **路径 B**：设 g = ∂loss/∂z = softmax(z) − onehot(y)（每个位置一个长度 V 的向量）。logits = h Eᵀ，所以对 E 的梯度是 gᵀ h 的形式：**每一行**都有贡献，第 i 行是 gᵢ·h，再对所有位置求和（取平均时还要除以位置数）。
- **路径 A**：查表的梯度只落在被查到的行上。位置 t 的输入是 token k，就把 ∂loss/∂x⁽⁰⁾_t 加到第 k 行。没出现的行，这条路贡献为 0。

PyTorch 不需要你做任何事：同一个 Parameter 在计算图里被用了两次，autograd 自动把两份梯度加到同一个 `.grad` 上。

### 11.4.4 数值例子

取 V = 3、d = 2，嵌入矩阵

```text
E = [[1, 0],     ← token 0
     [0, 1],     ← token 1
     [1, 1]]     ← token 2
```

一个位置：输入 token 2，经过网络得到 h = [2, −1]，目标 y = 0。

**路径 B。** logits z = E h = [2·1 + (−1)·0, 0·2 + 1·(−1), 2 + (−1)] = [2, −1, 1]。

```text
softmax 的分母 = e² + e⁻¹ + e¹ = e² · (1 + e⁻³ + e⁻¹) = e² · 1.4177
p = [1/1.4177, 0.0498/1.4177, 0.3679/1.4177] = [0.7054, 0.0351, 0.2595]
loss = −ln 0.7054 = ln 1.4177 = 0.3490
g = p − onehot(0) = [−0.2946, 0.0351, 0.2595]
```

输出路径对 E 的梯度是 g 的每个分量乘 h：

```text
第 0 行：−0.2946 × [2, −1] = [−0.5892,  0.2946]
第 1 行： 0.0351 × [2, −1] = [ 0.0702, −0.0351]
第 2 行： 0.2595 × [2, −1] = [ 0.5190, −0.2595]
```

三行都有梯度，包括输入里根本没出现的 token 0 和 token 1。

**路径 A。** 假设反传回来，嵌入输出处的梯度是 ∂loss/∂x⁽⁰⁾ = [0.1, −0.2]（这个数取决于中间的网络，这里只是假设值）。输入是 token 2，所以只有第 2 行得到 [0.1, −0.2]。

**相加。** 共享矩阵的梯度：

```text
第 0 行：[−0.5892,  0.2946]
第 1 行：[ 0.0702, −0.0351]
第 2 行：[ 0.5190 + 0.1, −0.2595 − 0.2] = [0.6190, −0.4595]
```

（数学结论；路径 A 的数值是假设的。）

### 11.4.5 对照代码

共享只要一行，在 `GPT.__init__` 里：

```python
self.tok = nn.Embedding(cfg.vocab_size, cfg.d_model)
...
self.head = nn.Linear(cfg.d_model, cfg.vocab_size, bias=False)
if cfg.tie_weights:
    self.head.weight = self.tok.weight             # 输出层与嵌入共享同一个矩阵
```

为什么形状对得上？`nn.Embedding(V, d)` 的权重是 (V, d)；`nn.Linear(d, V)` 的权重按 PyTorch 约定是 (输出, 输入) = (V, d)，前向算 x Wᵀ。两者正好同形状，可以直接共享（数学结论）。

这一行做的是**让两个属性指向同一个对象**，不是复制数值。第 3 部分检查了这件事，并做了一个小对照：先建一个 1 层、d = 32 的共享模型，再建一个不共享的模型，把共享模型的数值原样拷进去（此时两个矩阵数值相同但是两个独立参数），用同一批数据各反传一次（本项目观察，CPU，第 3 部分）：

```text
head.weight is tok.weight=True；data_ptr相同=True；节省参数=72256
嵌入路径梯度范数=1.4122；输出路径梯度范数=1.4124；共享梯度范数=1.9651；两路和最大差=0.0000；两路之和等于共享梯度=True
```

读一下这几行：

- `is` 为 True：同一个 Python 对象。`data_ptr` 相同：同一块内存。
- 节省 72,256 = 2258 × 32 = V·d（数学结论）。本书配置 d = 256 时节省 578,048（11.3 节）。
- 不共享模型里，`tok.weight.grad` 只有路径 A，`head.weight.grad` 只有路径 B；两者之和与共享模型的 `.grad` 逐元素相等。这就是 11.4.3 节的公式。
- 两路范数相加不等于 1.9651：向量相加不是范数相加。1.4122² + 1.4124² ≈ 3.989，而 1.9651² ≈ 3.862，说明两个梯度几乎正交、略带负相关（数学结论，由上面的观察值算出；习题二会让你算夹角）。

还有一个初始化细节。`self.apply(self._init)` 会依次访问 `tok`（Embedding）和 `head`（Linear），两者都按 std = 0.02 初始化。共享时同一个矩阵被初始化了两次，后一次覆盖前一次。两次分布相同，所以无害。不过对共享矩阵的任何操作都同时作用在两端，下面的第一个错误就出在这里。

### 11.4.6 常见错误

- **共享之后，又单独初始化输出层。** 例如 `nn.init.normal_(model.head.weight, std=0.2)`。你以为只改了输出层，其实嵌入也一起变了。第 9 部分实测：嵌入是否改变 = True，最大差 0.9739（本项目观察，CPU，第 9 部分）。正确做法是按 `named_parameters()` 遍历唯一参数初始化（`tour.py` 的 `reinitialize`）。
- **用 `state_dict` 数参数**：多算 V·d（11.3.6 节）。
- **保存和加载时丢了共享关系。** `state_dict` 里两个名字各存一份数值；如果加载后用 `head.weight = nn.Parameter(...)` 重新赋值，共享就断了，之后两个矩阵各自训练。检查方法：加载后断言 `model.head.weight is model.tok.weight`（测试 `test_weight_storage_and_counting`）。

## 11.5 训练前的检查：初始 loss ≈ ln V

### 11.5.1 动机

你写完了模型，准备训练。第 1 步的 loss 应该是多少？

如果你心里没有一个数，就没法判断第 1 步打印出来的 7.76 是正常还是异常。这一节给你这个数：**ln V**，并解释为什么实际会略大一点、大多少算异常。

### 11.5.2 直觉：什么都不懂，就该均匀猜

刚初始化的模型什么都没学到。对它来说，下一个 token 是 2258 个里的哪一个，都一样可能。最诚实的回答是均匀分布：每个 token 概率 1/V。这时交叉熵是

```text
loss = −ln(1/V) = ln V
```

V = 2258 时，ln V = 7.7222（数学结论）。

一个好的初始化应该让模型**接近**这个状态：不确定，但也不乱自信。如果一开始 loss 远大于 ln V，说明模型很自信地给出了错误答案——它得先花一段训练把这份"错误的自信"降下来，才开始学真正的东西。

### 11.5.3 推导：为什么略大于 ln V，大多少

初始 logits 是一堆小随机数，并不精确为 0。设一个位置的 V 个 logits 独立地服从 N(0, σ²)，且和目标无关。

**第 1 步：期望 loss。**

```text
E[loss] = E[ log Σ_j exp(z_j) ] − E[z_y]
```

z_y 和其他 logits 同分布，均值 0，第二项为 0。

**第 2 步：近似第一项。** V 很大时，Σ_j exp(z_j) ≈ V · E[exp(z)]（大数定律）。正态分布的矩母函数给出 E[exp(z)] = exp(σ²/2)。所以

```text
E[loss] ≈ ln(V · e^{σ²/2}) = ln V + σ²/2
```

这个近似在 σ 比较小时成立（数学结论，近似）。

还要提醒一个隐藏的假设：logits 和目标无关、彼此独立。共享权重时这并不严格成立——h 里含有当前 token 自己的嵌入，当前 token 那一类的 logit 会系统性地偏大（11.8.2 节会估计它的大小）。本书配置里残差流经过 4 个块后，嵌入只占其中一小部分，这一项的影响不大，下面的实测会和估计对得上；但把嵌入的初始化 std 调大时，它会变成主角（习题调试 11.1）。

**第 3 步：σ 由谁决定。** 最后的 RMSNorm 把每个位置的向量拉到 RMS ≈ 1（γ 初始为 1），记作 h，每个分量的平方平均约为 1。输出层每个元素独立地按 std = s 初始化。于是

```text
z_i = Σ_{k=1}^{d} W_{ik} h_k
Var(z_i) = Σ_k h_k² · s² = d · 1 · s²
σ = s · √d
```

（数学结论。）

**第 4 步：代入本书配置。** s = 0.02，d = 256：

```text
σ = 0.02 × √256 = 0.02 × 16 = 0.32
E[loss] ≈ 7.7222 + 0.32² / 2 = 7.7222 + 0.0512 = 7.7734
```

这就是"略大于 ln V"的来源，大约多 0.05。

**σ 大了会怎样？** σ² 一旦比 ln V 大，大数定律的近似就失效：分母被最大的那几个 exp(z_j) 主导，loss ≈ max_j z_j − z_y，**近似和 σ 成正比**。比例系数是 V 个标准正态变量最大值的期望，V = 2258 时约 3.47（数学结论，数值积分）。

### 11.5.4 实测

第 4 部分在一批验证数据（8 × 64）上算初始 loss，比较三种初始化（本项目观察，CPU，第 4 部分）：

| 初始化 | 原始 loss | 屏蔽 BOS 后 loss | logits 标准差 | 理论 σ = s√d |
|---|---|---|---|---|
| 本书：std 0.02，残差输出缩放 | 7.7634 | 7.7628 | 0.3253 | 0.32 |
| 全部矩阵 std 0.2，不缩放 | 12.4185 | 12.4182 | 3.1966 | 3.2 |
| 全部矩阵 std 1.0，不缩放 | 53.8261 | 53.8261 | 15.9786 | 16 |
| 独立输出层置零 | 7.7222 | — | 0.0000 | 0 |

对照 ln V = 7.7222、ln(V−1) = 7.7218（同一部分打印）。

逐行读：

- **本书初始化**：logits 标准差 0.3253，和理论值 0.32 吻合。loss 7.7634，比 ln V 大 0.0412，和估计的 0.0512 同一量级。合格。
- **std 0.2**：σ 变成 10 倍，loss 12.4185，比 ln V 大了近 5。这时 σ² ≈ 10.2 已经超过 ln V，小 σ 近似不再可靠。
- **std 1.0**：loss 53.8261。53.8261 / 15.9786 ≈ 3.37，和"loss 约为 σ 的 3.47 倍"同一量级（由观察值算出）。模型对随机答案极度自信。
- **输出层置零**：所有 logits 都是 0，softmax 精确均匀，loss 精确等于 ln V。这是一个很好的"零点校准"。这里用的是**不共享**的输出层，否则把输出层清零会连嵌入一起清零（`lab.md` 第 0 节"对照边界"）。

**BOS 两种口径**：原始 loss 包含 BOS 这一类的概率，屏蔽 BOS 后分母少一类，参照点从 ln V 变成 ln(V−1)，两者差 0.0004（数学结论）。实测两种 loss 只差万分之几。做初始 loss 检查时，原始 loss 对 ln V、屏蔽后对 ln(V−1)，别混着比。

### 11.5.5 对照代码

第 4 部分的核心只有几行：

```python
logits, loss = candidate(x, y, loss_mask=y != exp.bos)     # 训练口径：BOS 目标不计入
masked = logits.clone()
masked[..., exp.bos] = -torch.inf                            # 验证口径：BOS 不是候选
adjusted = F.cross_entropy(masked[y != exp.bos], y[y != exp.bos])
print(... math.log(exp.vocab) ..., math.log(exp.vocab-1) ...)
```

你在自己的训练脚本里只需要做一件事：**训练开始前，打印第一批的 loss 和 ln V，放在同一行。**练习 11.4 会让你把它写成一个函数。

### 11.5.6 怎样读一个不对劲的初始 loss

| 初始 loss | 可能原因 |
|---|---|
| ≈ ln V + 0.0x | 正常 |
| 比 ln V 大好几 | logits 太大：初始化 std 太大；或共享后又把输出层按大 std 初始化 |
| ≈ 11.14（ln V / ln 2） | 用了以 2 为底的对数，或把 loss 换算成了 bit（数学结论：7.7222 / 0.6931 ≈ 11.14） |
| ≈ ln V 的几百、几千倍 | 交叉熵用了 `reduction="sum"`，没除以位置数 |
| 明显**小于** ln V | 先查标签是否等于输入（11.8.2 节）。共享权重的模型天生偏向"输出当前 token"，所以数据里如果有大量重复 token，正确错位时第 1 步也可能低于 ln V；排除标签错误后再看数据 |

## 11.6 初始化与残差缩放：1/√(2L)

### 11.6.1 动机：残差流会越堆越大

回忆第 9 章：Pre-Norm 块是 `x = x + f(Norm(x))`。残差不擦掉重写，只能往上加；加的数可以是负的，抵消一部分。L 个块，每块两个支路（注意力和前馈），残差流一共被加了 2L 次。

每次加的东西是一个随机初始化的支路输出，正负都有，但方差会累积（11.6.3 节）：加得越多，残差流越大。模型越深，这个问题越明显。GPT-2 论文的做法是：**把残差支路最后那个线性层的初始化缩小 √N 倍**，N 是残差层的数目。本书和 nanoGPT 一样取 N = 2L。

### 11.6.2 直觉：往同一个杯子里倒水

把残差流想成一个杯子。每个支路往里倒一勺水，勺子大小随机。倒 8 勺和倒 64 勺，杯子里的水显然不一样多。

如果希望不管倒多少勺，总水量都差不多，最简单的办法是：勺数越多，每一勺越小。勺数是 2L，那么每一勺的"方差"就缩小 2L 倍，也就是"标准差"缩小 √(2L) 倍。

### 11.6.3 推导

**第 1 步：写出残差流。** 把 L 个块的 2L 个支路依次编号 1…2L：

```text
x_{2L} = x_0 + b_1 + b_2 + … + b_{2L}
```

b_i 是第 i 个支路的输出。

**第 2 步：做一个简化假设。** 假设各个 b_i 互相独立、均值为 0、方差都是 v，并且和 x_0 独立。那么方差相加（数学结论）：

```text
Var(x_{2L}) = Var(x_0) + 2L · v
```

方差随深度**线性**增长，标准差随 √(2L) 增长。

**第 3 步：支路输出的尺度由谁决定。** 每个支路的最后一层是一个线性层：注意力的 `o`，前馈的 `down`。支路输出 b = W · u，u 是这一层的输入。Pre-Norm 让支路的输入先经过归一化，u 的尺度不随残差流变化。所以 b 的标准差和 W 的初始化 std **成正比**，方差和 std² 成正比。

**第 4 步：缩放。** 把这两个矩阵的 std 从 s 改成 s / √(2L)，每个支路的方差从 v 变成 v / (2L)：

```text
Var(x_{2L}) = Var(x_0) + 2L · v / (2L) = Var(x_0) + v
```

总增量和层数无关了（数学结论，在独立假设下）。

**为什么只缩放 `o` 和 `down`？** 因为只有它们的输出直接加进残差流。q、k、v、gate、up 的输出还要经过注意力或门控，再由 `o`、`down` 投影回来。缩放最后一层，就控制了"倒进杯子的那一勺"。

**为什么是 2L 不是 L？** 每个块有两个残差支路，各加一次。GPT-2 论文写的是"残差层数 N"，没有明说 N 等于什么；nanoGPT 和本书取 2·n_layer。这是一个约定。第 13 章的消融实验有去掉残差缩放的变体，由你自己跑。

### 11.6.4 数值例子

std 基础值 s = 0.02：

| L | 2L | √(2L) | `o`、`down` 的 std |
|---|---|---|---|
| 4 | 8 | 2.8284 | 0.02 / 2.8284 = 0.007071 |
| 12 | 24 | 4.8990 | 0.004082 |
| 32 | 64 | 8 | 0.0025 |

（数学结论。）

在独立假设下，以 L = 4 为例：不缩放时 8 个支路各贡献方差 v，共 8v；缩放后每个 v/8，共 v。

### 11.6.5 实测：逐层 RMS

第 5 部分用 d = 64，L = 4、8、16、32，各建一个模型。缩放版是 `GPT` 的默认初始化；不缩放版把同一个模型的 `o`、`down` 乘回 √(2L)，于是两者用的是**同一组随机方向**，只差尺度（`lab.md` 第 0 节"对照边界"）。送进同一批 token，记录嵌入输出和每个块之后残差流的 RMS（本项目观察，CPU，第 5 部分）：

| L | 嵌入 RMS | 最后一块之后：缩放 | 最后一块之后：不缩放 |
|---|---|---|---|
| 4 | 0.0200 | 0.0214 | 0.0368 |
| 8 | 0.0198 | 0.0210 | 0.0522 |
| 16 | 0.0201 | 0.0216 | 0.0988 |
| 32 | 0.0198 | 0.0212 | 0.1393 |

缩放版不管多深，最后都停在 0.021 附近；不缩放版从 0.0368 一路涨到 0.1393，32 层时是缩放版的约 6.6 倍（由观察值算出）。

以 L = 4 为例，逐层看：

```text
缩放：  [0.0200, 0.0203, 0.0206, 0.0209, 0.0214]
不缩放：[0.0200, 0.0224, 0.0258, 0.0307, 0.0368]
```

两个提醒：

1. **独立假设只给方向，不给精确数。** 实测的增长幅度和"方差线性相加"并不严格吻合：不同支路的输出并不独立（它们读的是同一条残差流），而且这里只用了一批固定 token。别拿上表去拟合 √(2L)。
2. **RMS 不保证逐层单调**，这里看的是最后归一化**之前**的残差流，不是 logits。最后的 RMSNorm 会把尺度拉回 1，所以残差流大一点不会直接让初始 loss 爆炸。缩放的意义在于让不同深度的模型在训练起点处于相近的状态；它对训练曲线有多大影响，本章不回答；第 13 章给出消融实验的做法，实验由你自己完成。

嵌入 RMS 约 0.02，正是嵌入表的初始化 std（数学结论：每个元素 std 0.02，RMS 就约 0.02）。共享权重时，这张表同时决定了 11.5 节的 logits 尺度。

### 11.6.6 对照代码

`GPT.__init__` 最后几行：

```python
self.apply(self._init)                                   # 所有 Linear、Embedding：N(0, 0.02²)
for n, p in self.named_parameters():                     # 残差支路的输出层再缩小 √(2L)
    if n.endswith("attn.o.weight") or n.endswith("mlp.down.weight"):
        nn.init.normal_(p, 0.0, 0.02 / math.sqrt(2 * cfg.n_layer))
```

和 11.6.4 节对一下：L = 4 时，`blocks.0.attn.o.weight`、`blocks.0.mlp.down.weight` 到 `blocks.3.…` 这 8 个矩阵的 std 是 0.007071，其余矩阵 0.02，RMSNorm 的 γ 是 1。

用 `endswith` 按名字匹配，所以名字改了，缩放就悄悄失效。最直接的检查是建好模型后打印每个矩阵的实际 std：`o`、`down` 应约为 0.02/√(2L)，其他矩阵约为 0.02。

`tour.py` 另有一个重新初始化的辅助函数 `reinitialize`，测试 `test_reinitialization_preserves_tie_and_scales_only_residual_outputs` 检查的是**它**：缩放版和不缩放版用同一个随机种子重新初始化后，**只有**这两类矩阵相差 √(2L) 倍，其他参数完全相同，且共享关系还在。注意这个测试会覆盖构造器的初始化，所以它不能证明 `GPT.__init__` 里的缩放是对的。

### 11.6.7 常见错误

- **缩放了错误的层**（比如 q、k、v 或 up）。现象不明显，模型照样能训。只能靠建好模型后逐个检查参数名和实际 std。
- **用 `model.apply(init)` 重新初始化之后，忘了重做残差缩放。** `apply` 会把所有 Linear 恢复成 std 0.02，缩放丢了。
- **用 `apply` 重新初始化共享模型时，以为输出层和嵌入是两个矩阵。** 同一个矩阵被访问两次，只要两次分布一样就无害；分布不一样时，后访问的那次说了算。按 `named_parameters()` 遍历唯一参数最稳妥（`tour.py` 的 `reinitialize`）。

## 11.7 过拟合一个批次

### 11.7.1 动机：先确认它"能学"

初始 loss 对了，只说明起点对。它能不能往下走？一个便宜的检查是：**拿一个固定的小批次反复训练，看 loss 能不能降到接近 0。**

道理很简单。一个几十万参数的模型，背下 8 条 64 个 token 的序列应该毫无困难。如果连这都做不到，首先怀疑代码：梯度没传过去、优化器没更新、学习率是 0、loss_mask 全是 False……

不过"降不到接近 0"不**必然**是代码错误。还有两种合法原因：一是学习率或步数不合适；二是批次里有"冲突"——同样的前文后面跟着不同的 token（比如好几条公式都以 `\frac{` 开头），因果模型对相同前文只能给出同一个分布，loss 有一个降不掉的下限。排除这两点之后，还降不下去，就基本是代码问题了。

### 11.7.2 实测

第 6 部分：2 层、d = 128、上下文 64，参数量 715,648；固定一个 8 × 64 的批次，AdamW，学习率 0.003，训练 200 步（本项目观察，CPU，第 6 部分）：

| 训练步 | 当前批次 loss |
|---|---|
| 1 | 7.7369 |
| 10 | 4.1020 |
| 50 | 0.0293 |
| 100 | 0.0069 |
| 200 | 0.0031 |

第 1 步的 loss 是第一次更新**之前**算的，所以它也是一个初始 loss：7.7369，接近 ln V = 7.7222。50 步就背得差不多了，200 步后 0.0031。训练用时 2.6191 秒。

### 11.7.3 这个低 loss 不是坏信号

这里 loss 低是**我们故意的**：同一批数据反复看，模型记住了它。它不说明模型能泛化，也不需要拿验证集去评。它只回答一个问题："整条训练链路能不能把 loss 往下推？"

要把它和 11.8 节区分开：11.8 节的低 loss 出现在**每一步都换新数据**的正常训练里，那才是警报。

### 11.7.4 LaTeX 冒烟检查

最后再用真实数据短训一次，确认"训练 → 全量验证"这条链路能走通。第 8 部分：1 层、d = 64、上下文 32、批量 16，参数量 197,952，训练 200 步，然后在全部验证目标上评测（本项目观察，CPU，第 8 部分）：

| 模型 | val nat/token | bits/byte |
|---|---|---|
| LaTeX 小 GPT，200 步 | 4.9334 | 3.5577 |
| 第 7 章 MLP（上文 8）基线 | 3.8124 | 2.7493 |

小 GPT 没有超过第 7 章的基线，这不必惊讶：它只有 1 层、只训了 200 步，训练用时 0.9171 秒。这里要确认的只是：loss 从 7.7457 降了下来，评测用了 119,750 个目标、239,566 个字节，口径和第 7 章一致。完整训练在第 13 章，由你自己完成；训练预算、上下文、参数量都不同，这一行不能用来比较架构好坏。

`lab.md` 实验一到三（第 3–5 节）让你在这个设置上改初始化 std、改共享、改深度和宽度，自己跑出结果填进记录表。

## 11.8 两类"低得可疑"的 loss

### 11.8.1 动机

正常训练时，每一步都是没见过的新批次。这种情况下，loss 有一个合理的下限：语言本身就有不确定性，"x^" 后面可以是 2、也可以是 {n}。如果训练 loss 低得远超你的预期，第一反应不应该是高兴，而是**怀疑模型作弊了**。

语言模型作弊的方式只有一种：在预测第 t+1 个 token 时，看到了第 t+1 个 token。它有两条常见的门路：

1. **标签没错开**：目标就是输入本身，答案直接写在当前位置。
2. **因果 mask 失效**：注意力能看到后面的位置，答案在下一个位置。

第 7 部分把三组模型放在一起训练：正常、标签未错位、全可见 mask。三组的配置（2 层、d = 96、4 头、上下文 16、批量 16、350 步）、初始参数和抽样随机种子都相同（`lab.md` 第 0 节）。训练完以后，**全部用正确的错位目标和正确的因果 mask 评测**（本项目观察，CPU，第 7 部分）：

| 模型 | 第 1 步 loss | 第 350 步 loss | 正确评测 val nat/token | bits/byte |
|---|---|---|---|---|
| 正常 | 7.7412 | 3.9487 | 4.1911 | 3.0224 |
| 标签未错位 | 6.1764 | 0.0759 | 12.8650 | 9.2776 |
| 全可见 mask | 7.7344 | 0.7108 | 6.0800 | 4.3846 |

两种故障的训练 loss 都远低于正常，正确评测却都更差。标签未错位那一组更离谱：12.8650 比均匀猜测的 7.7222 还高。下面分开讲。

### 11.8.2 第一类：标签没错开一位

**怎样发生。** 正确的做法（第 7 章 7.2 节）：

```text
序列   = [BOS, a, b, EOS]
x      = 序列[:-1] = [BOS, a, b]
y      = 序列[1:]  = [a, b, EOS]       位置 t 的目标是下一个 token
```

错误的写法让 y = x = [BOS, a, b]。形状完全一样，`F.cross_entropy` 不会报任何错。

**为什么 loss 会掉下去。** 位置 t 的目标就是位置 t 的输入。模型只要"把自己看到的抄出去"。这在 GPT 里简直不费吹灰之力：残差流从嵌入 e_{x_t} 开始，一路加加减减，最后乘输出层。共享权重时输出层就是嵌入表，logit_i = eᵢ · RMSNorm(h)，而 h 里本来就有 e_{x_t}。

**一个更早的信号：第 1 步就低于 ln V。** 上表里，标签未错位组在**第一次更新之前**的 loss 就是 6.1764，比正常组的 7.7412 低 1.5648（本项目观察，CPU，第 7 部分；两组的模型初值和输入批次相同，差别只在目标）。随机初始化的模型凭什么猜得比均匀还准？可以估一下（数学结论，粗略近似）：

- 假设 h 只有嵌入 e_{x_t}，RMSNorm 后变成 e_{x_t} / RMS(e)，RMS(e) ≈ s = 0.02；
- 正确 token 的 logit ≈ e_{x_t} · e_{x_t} / s = d·s² / s = d·s = 96 × 0.02 = 1.92；
- 其他 token 的 logit 仍是 std ≈ s√d = 0.196 的小随机数。

所以 loss 大约比 ln V + σ²/2 低 1.92。实测只低了 1.5648，因为 h 里不只有嵌入：两个块的支路输出也加了进去。尤其在靠前的位置，注意力只在很少几个位置上取平均，支路输出不算小，冲淡了"自己"那一份。估计和实测方向一致、量级一致。

由此得到一条排查规则：共享权重的模型，如果第 1 步的 loss 就明显低于 ln V，先怀疑目标等于输入。这只是"先怀疑"，不是定论：同样的复制偏好意味着，如果数据里下一个 token 常常等于当前 token（大量重复），正确错位时第 1 步的 loss 也可能低于 ln V。排查顺序是先查错位断言，再看数据。

**训练后发生了什么。** 350 步后训练 loss 0.0759。模型学会的是"抄当前 token"。到了正确评测，它要预测下一个 token，却把当前 token 当成答案，几乎总是错，而且错得很自信，于是 val nat/token 12.8650，比均匀猜还差。第 7 章 7.10 节在 MLP 上见过同样的现象。

**怎样发现。**

1. 在数据管道里断言：`assert torch.equal(x[:, 1:], y[:, :-1])`。这一行能挡住绝大多数错位错误。
2. 第 1 步的 loss 对照 ln V（共享权重时，明显偏低就是信号）。
3. 用一条独立写的、正确的评测管道评测，不要用训练脚本里的那份数据处理。

**和 Hugging Face 的约定相反。** 本书的 `GPT.forward` **不在内部错位**，数据端错开一次就够了。Hugging Face 的 `*ForCausalLM` 让你传 `labels = input_ids`，模型内部再错开（待验证，第 19 章 19.3.3 节会再讲这个约定）。两种约定混用会出两种错：

- 数据端没错开、模型内部也不错开 → 目标等于输入，就是本节的故障，loss 低得可疑。
- 数据端错开了、模型内部又错开一次 → 位置 t 的目标变成第 t+2 个 token。预测任务错了，但 loss 往哪个方向变**没有保证**：对 LaTeX 这样的文本，隔一个预测通常更难，loss 多半偏高（本章未实测，待验证）；可对 `a, b, a, b, …` 这种交替序列，第 t+2 个 token 就等于当前 token，loss 反而可能更低。所以不能靠 loss 高低来判断，要靠测试锁定约定。

测试 `test_next_token_loss_uses_supplied_shifted_targets_without_second_shift` 锁定了本书的约定：forward 拿到的 y 直接用，不再错位。

### 11.8.3 第二类：因果 mask 失效

**怎样发生。** 位置 t 的注意力本该只看 0…t。如果 mask 失效，它能看到 t+1。而 t+1 处的输入正是位置 t 的目标。答案就在隔壁。

常见的失效方式：

- 根本没传 mask，也没设 `is_causal=True`；
- 用了 `triu` 而不是 `tril`，方向反了；
- **布尔 mask 的语义弄反**：`F.scaled_dot_product_attention` 的布尔 mask 里 True 表示"可以看"，而 `masked_fill(mask, -inf)` 里 True 表示"屏蔽掉"。把一种写法的 mask 原样交给另一种，结果全错；
- 带 KV cache 时 mask 的偏移没算对（本书用 `tril(past)`，第 15 章细讲）。

`tour.py` 的 `visible_future` 用一个上下文管理器临时把每个注意力层换成"全部可见"的版本（mask 全为 True），出了 `with` 就恢复。

**为什么训练 loss 没有降到 0。** 全可见组 350 步后训练 loss 0.7108，没有像标签未错位组那样掉到 0.0759。有两个原因。第一，不是每个位置都能抄：输入有 T 个 token，前 T−1 个位置的答案就在输入里的下一个位置，可最后一个位置的目标在输入窗口之外，没有答案可抄，只能老老实实预测（`lab.md` 第 0 节："除最后一位外都可能泄漏"）。所以光靠复制，不能保证整个 loss 接近 0：末位的那一份要靠预测（或记忆）去降。第二，"抄隔壁"比"抄自己"难：模型得学会让注意力集中到下一个位置上，这需要借助 RoPE 的相对位置信息、需要优化。上表的训练曲线是 7.7344 → 5.6865（第 10 步）→ 4.1483（第 50 步）→ 2.5076（第 100 步）→ 1.2360（第 200 步）→ 0.7108（第 350 步）（本项目观察，CPU，第 7 部分），一路比正常组降得快。全可见不等于优化器立刻学会复制；低到什么程度取决于训练多久；末位那一份没有捷径可抄。

**训练后发生了什么。** 恢复正确的因果 mask 去评测，模型习惯的"隔壁答案"没了，val nat/token 6.0800，比正常组的 4.1911 差。

**怎样发现：改未来，看过去。** 因果模型有一个可以直接检验的性质：**改动位置 ≥ c 的 token，位置 < c 的 logits 一个比特都不应该变。**`tour.py` 的 `future_difference` 就做这件事：

```python
@torch.no_grad()
def future_difference(model, x):
    changed = x.clone()
    cut = x.shape[1]//2
    changed[:, cut:] = (changed[:, cut:]+17) % model.cfg.vocab_size   # 只改后半段
    return (model(x)[0][:, :cut]-model(changed)[0][:, :cut]).abs().max().item()
```

用一个 T = 16 的例子：cut = 8，把位置 8–15 的 token 都换掉，比较位置 0–7 的 logits。第 7 部分实测（本项目观察，CPU，第 7 部分）：

```text
全可见mask：改未来token后过去logits是否变化=True；最大差=16.2462
恢复因果mask后过去logits最大差=0.0000
```

正确的模型最大差精确为 0；mask 失效时 logits 差到 16 以上。这个检查不用训练、不用数据，一秒钟跑完，应该写进每个模型的测试。有一个前提：两次前向必须是确定性的。先调用 `model.eval()`（或确认 dropout 为 0），否则 dropout 的随机性本身就会让两次输出不同。`torch.no_grad()` 只关梯度，不关 dropout。本章的 `test_causality_and_fault_detection` 在 manual 和 sdpa 两种注意力实现上都检查了它，并确认注入故障后它确实会报警。

### 11.8.4 三种"低 loss"放在一起

| 现象 | 数据 | 是否正常 | 检查方法 |
|---|---|---|---|
| 固定批次 loss → 0.0031（11.7 节） | 同一批反复训练 | 正常，故意的 | 不需要；降不下去才是问题 |
| 训练 loss 0.0759，第 1 步就低于 ln V | 每步新数据，y = x | 故障 | 断言 `x[:, 1:] == y[:, :-1]` |
| 训练 loss 0.7108，正确评测 6.0800 | 每步新数据，mask 失效 | 故障 | 改未来、看过去 |

训练 loss 只能告诉你模型把训练目标学得怎么样，不能告诉你训练目标对不对。后者要靠数据断言、因果测试和独立的评测管道。

## 11.10 常见错误

前面各节已经讲过各自的错误。这里补一个第 9 部分专门演示的，再给一张索引表。

### 11.10.1 漏了最后的归一化，初始 loss 却正常

第 9 部分拿本书配置，把 4 个块的输出直接送进输出层，跳过 `self.norm`（本项目观察，CPU，第 9 部分）：

```text
忘final norm：残差RMS=0.0563；归一化后RMS=0.9998；logits最大差=2.5197
```

残差流的 RMS 只有 0.0563。不归一化，送进输出层的向量比正常小了约 18 倍（0.9998 / 0.0563，由观察值算出），logits 跟着缩小，几乎全是 0，softmax 几乎均匀——**初始 loss 反而更接近 ln V**。初始 loss 检查完全看不出问题，可是 logits 和正确实现的最大差有 2.5197。

这个错误还会让模型对深度很敏感：第 9 章 9.8 节看到，不加最后归一化时，输出层面对的输入尺度随层数变化。

怎样发现：和独立参考实现对拍。`test_gpt_reference_rejects_missing_norm_and_residual` 把最后归一化的 γ 设成非 1 的值，确保"漏了归一化"和"写死成无参数归一化"都会被抓住。

## 11.12 小结

- **GPT = 词嵌入 → L 个 Pre-Norm 块 → 最后归一化 → 输出层**，除最后一步外形状都是 (B, T, d)；位置由 RoPE 在注意力里注入，forward 只算 loss、不替你错位。
- **参数量 N = V·d + L(4d² + 3df + 2d) + d**，不共享再加 V·d；本书配置手算 3,791,616，和 `n_params()` 一致；每块约 12d²。
- **共享权重**让输出层直接用嵌入矩阵，省 V·d 个参数，梯度是嵌入路径和输出路径之和。
- **训练前先查初始 loss**：应约等于 ln V；logits 标准差 σ = s√d，小 σ 时多出约 σ²/2；本书配置 7.7634 对 ln V = 7.7222。**残差支路输出层按 1/√(2L) 缩小**，让残差流的增长和深度无关。
- **训练 loss 低得可疑时，先怀疑作弊**：标签没错开、因果 mask 失效都会让训练 loss 很低、正确评测很差；用数据断言和"改未来、看过去"测试去抓。

**术语表：** GPT、残差流、词嵌入、输出层（LM head）、logits、`inputs_embeds`、pos0、`block_size`、参数量、非嵌入参数、缓冲区（buffer）、权重共享（weight tying）、初始 loss、ln V、logits 标准差、残差缩放、过拟合一个批次、冒烟测试、标签错位、因果 mask、信息泄漏、"改未来、看过去"测试。
