## 13.1 一次完整的预训练：从 token 流到检查点

### 13.1.1 动机

第 11 章的训练只是"冒烟"：几百步，没有调度，没有续训，loss 降了就算数。预训练不一样。它跑得久，所以要能中断后接着跑；它的曲线要能复盘，所以每一步都要记日志；它的结果要和别人比，所以验证口径要固定。

这一节先看清整个脚本的骨架。后面几节再逐个放大其中的部件。

### 13.1.2 全景：一步训练做了什么

先给结论。`miniocr/train/pretrain.py` 里的 `train_pretrain` 每一步做六件事：

1. 按调度算出这一步的学习率；
2. 从训练 token 流里随机截出一批窗口；
3. 前向、算 loss（忽略 BOS 目标）、反向；
4. 计算全局梯度范数，超过阈值就等比缩小（梯度裁剪）；
5. AdamW 更新参数；
6. 写一行日志。每隔 `eval_every` 步，再做一次验证并保存检查点。

画成一条流水线：

```text
token 文件 ──get_batch──▶ (x, y) ──GPT──▶ loss ──backward──▶ 梯度
                                                        │
          warmup_cosine(step) ──▶ lr                    ▼
                                    └────────▶ 裁剪 → AdamW 更新
                                                        │
                    每 eval_every 步：验证 nat/token、bits/byte → 日志 → 检查点
```

### 13.1.3 数据：一条长长的 token 流

训练数据是把每条公式加上 BOS、EOS，首尾相接拼成的一条一维 token 流。`get_batch`（`miniocr/train/lm.py`）随机选 B 个起点，每个起点截 T+1 个 token：前 T 个是输入 x，后 T 个是目标 y。

```python
def get_batch(ids, B, T, g, device="cpu"):
    s = torch.randint(0, len(ids) - T, (B,), generator=g)          # 上界不含：s 最大取 len(ids) − T − 1
    off = torch.arange(T + 1)
    w = ids[s[:, None] + off]
    return w[:, :-1].to(device), w[:, 1:].to(device)
```

这和第 7 章的做法不同。第 7 章 7.2.3 节每条公式单独处理、公式之间不拼接，理由是拼接后上一条公式的结尾会变成下一条的上文。拼接流把这个问题带了回来：窗口跨过公式边界时，注意力能看到上一条公式的结尾。换来的好处是所有窗口一样长，不用补齐。本章接受这个代价，而且只在训练时这样做，评测仍然逐公式、从 BOS 开始（13.1.4 节）。窗口里的 BOS 标出了新公式的开头，但模型会不会因此忽略边界之前的内容，拼接比不拼接差多少，本书没有测（待验证）。

第 12 章 12.1.2 节说过，比上下文长的公式要滑窗。滑窗只用在评测上。训练时不用专门处理：随机截窗会从不同起点把长公式切开，只是不保证每个位置被覆盖的次数相同。

拼接还带来一个小问题：窗口跨过公式边界时，某个位置的目标是下一条公式的 BOS。BOS 不是模型该"预测"的东西：评测协议里 BOS 只作条件。所以训练时用 `loss_mask = y != bos` 把这些目标去掉，和第 11 章一致。

第 1 部分打印了数据的基本账目（本项目观察，CPU，第 1 部分）：

| 项目 | 数值 |
|---|---|
| 训练公式条数（标准训练集前缀） | 20000 |
| 训练 token 流长度（含 BOS、EOS） | 1,189,263 |
| 词表大小 V | 2258 |
| ln V | 7.7222 |
| 验证公式条数 | 2000 |
| 验证目标数（内容 token + EOS） | 119,750 |
| 验证原文 UTF-8 字节数 | 239,566 |
| 每个验证目标平均对应字节数 | 2.0006 |

训练流在第一次运行时写成 token 文件（`outputs/book/ch13/train-n20000`），之后每次只校验、读取。第 1 部分还故意换了一个数据版本去读它，读取被拒绝，报"缓存不匹配：数据版本"。拒绝它的是第 12 章 12.9 节的缓存键。

### 13.1.4 验证：为什么口径要钉死

验证用的是第 11 章的协议：val 前 2000 条公式，逐公式评测，报告 nat/token 和 bits/byte。

拿最后一行换算一下。假设验证 loss 是 ℓ nat/token，那么

$$\text{bits/byte} = \ell \times \frac{119750}{239566} \times \frac{1}{\ln 2} = \ell \times 0.72115.$$

（数学结论，由第 1 部分的分母计算。）例如 ℓ = 5.4689 时，bits/byte = 3.9439，与第 3 部分的输出一致。

这个系数只对 latex-v1 成立。本章脚本固定用 latex-v1；如果你自己换分词器做对照（第 6 章 6.10 节），要按新分词器的目标数重算分母，并且只比 bits/byte。

训练途中的验证（周期验证）为了省时间，默认只用前 200 条公式；训练最后一步才用完整的 2000 条。**这两种验证点不能画在同一条线上直接比**：分母不同，公式难度分布也略有不同。日志里每条验证记录都带着 `eval_formulas`、`eval_tokens`、`eval_bytes` 三个字段，读曲线前先看它们。

### 13.1.5 训练前的检查：初始 loss

第 11 章讲过：刚初始化的模型输出接近均匀分布，loss 应约等于 ln V。第 1 部分在默认小模型（2 层、d = 64）上测得初始 loss 7.7399，ln V = 7.7222（本项目观察，CPU，第 1 部分）。多出来的 0.018 来自 logits 不完全为零（第 11 章 11.6 节）。

**每次长训练前都看一眼这个数。** 它偏离 ln V 很多，说明初始化或输出层有问题，后面的几千步都白跑。`train_pretrain` 在开始时自动打印它，并写进 `config.json`。

### 13.1.6 代码：训练循环的核心

下面是 `train_pretrain` 主循环的核心部分（省略了日志和检查点）：

```python
for step in range(start+1, end+1):
    lr = warmup_cosine(step-1, cfg.steps, cfg.warmup, cfg.lr, cfg.min_lr)      # ①
    for group in opt.param_groups:
        group["lr"] = lr
    opt.zero_grad(set_to_none=True)
    batches = [get_batch(train_ids, cfg.batch//cfg.accum, cfg.context, g, cfg.device)
               for _ in range(cfg.accum)]                                       # ②
    counts = [int((y != bos).sum()) for _, y in batches]
    valid = sum(counts)
    for (x, y), count in zip(batches, counts):
        with autocast(cfg.device, DTYPES[cfg.amp]):
            loss = model(x, y, loss_mask=y != bos)[1] * (count/valid)            # ③
        scaler.scale(loss).backward()
    scaler.unscale_(opt)
    grad = float(torch.nn.utils.clip_grad_norm_(model.parameters(), cfg.clip or math.inf))  # ④
    scaler.step(opt)                                                             # ⑤
    scaler.update()
```

逐行看：

- **①** 调度用的是"从 0 开始的索引"：日志里的第 1 步对应 `warmup_cosine(0, ...)`。13.2 节专门讲这个函数。
- **②** 梯度累积：把一批拆成 `accum` 个小批。生成器 `g` 有固定种子，所以"第几步取到哪批数据"完全由步数决定。这是续训能逐位一致的前提（13.4 节）。
- **③** 每个小批的 loss 乘以 `count/valid`：本小批的有效目标数占全部有效目标数的比例。因为 BOS 被屏蔽，不同小批的有效目标数可能不一样。按比例加权，累积出来的梯度才等于"整批一起算"的梯度（第 16 章会再讲累积的三种写法）。
- **④** `clip_grad_norm_` 返回**裁剪前**的全局梯度范数，日志里记的就是它。`cfg.clip = 0` 表示不裁剪（用无穷大当阈值），但范数照样记录。
- **⑤** `scaler` 是混合精度的 GradScaler，只在 fp16 时才起作用（第 16 章）。fp32 和 bf16 时它什么也不做。

优化器是 AdamW(β₁ = 0.9, β₂ = 0.95)。第 4 章 4.5.5 节的 `AdamW` 对所有参数一视同仁；这里用 `_param_groups`（`miniocr/train/lm.py`）把参数分成两组，矩阵参数做权重衰减，归一化层的 γ 不做：

```python
def _param_groups(model, wd):
    decay = [p for p in model.parameters() if p.requires_grad and p.dim() >= 2]    # 矩阵做权重衰减
    other = [p for p in model.parameters() if p.requires_grad and p.dim() < 2]     # 归一化的 γ 不做
    return [{"params": decay, "weight_decay": wd}, {"params": other, "weight_decay": 0.0}]
```

### 13.1.7 三套建议配置

每个训练任务都给了 CPU、MPS、CUDA 三套建议配置（`pretrain.PRESETS`），用 `--preset` 选择。它们全部是**待校准**的：本书没有替你跑过完整训练，不知道它们要跑多久、能到多低。

## 13.2 学习率调度：warmup 与 cosine

### 13.2.1 动机

学习率是预训练里最敏感的超参数。太小，训练慢得让人着急；太大，loss 跳来跳去，甚至变成 NaN。更麻烦的是，**同一个学习率在训练的不同阶段好坏不同**：开头嫌大，中段正好，结尾又嫌大。

所以几乎所有 LLM 预训练都不用固定学习率，而是用一条曲线：先用几百步从很小线性升到峰值（**warmup，预热**），再沿余弦曲线慢慢降到一个较小的值（**cosine decay，余弦衰减**）。这一节解释为什么两头都要"慢"。

### 13.2.2 直觉：下山的步子

想象你在大雾里下山，只能根据脚下的坡度决定往哪走、走多远。

- **刚出发时**，你对地形一无所知，脚下的坡度信息也很不可靠。这时迈大步，很可能一脚踩空。先小步试探，摸清坡度再加速，这就是 warmup。
- **到了谷底附近**，大步会让你在两侧山壁之间来回弹，永远落不到最低点。这时要把步子收小，这就是衰减。

两件事的原因不同：warmup 是因为**开头的信息不可靠**，衰减是因为**结尾的噪声太大**。下面分别把它们说精确。

### 13.2.3 为什么要 warmup：Adam 的第一步

第 4 章 4.4.4 节手算过 Adam 的第一步：偏差修正之后 m̂ = g、v̂ = g²，与 β₁、β₂ 取值无关，所以

$$\Delta\theta = -\,\text{lr}\cdot\frac{g}{|g|+\varepsilon} \approx -\,\text{lr}\cdot\operatorname{sign}(g).$$

（数学结论。）只要 |g| 远大于 ε，每个参数都移动约 lr 那么远，梯度只决定方向。（这里忽略权重衰减；|g| 和 ε 同量级时步长变小，梯度为 0 的坐标不动。）第 4 章 4.6.4 节由此讲了预热的理由，这里带上本章模型的数字。本章的模型权重按标准差 0.02 初始化，残差支路的输出层再缩小 √(2L)，2 层模型是 0.01。如果峰值学习率 3×10⁻³ 从第一步就用上，那么：

- 普通权重一步改变约 3×10⁻³ / 0.02 = 15% 的典型大小；
- 残差输出层一步改变约 3×10⁻³ / 0.01 = 30%。

（数学结论。）而这一步的方向来自一个随机初始化的模型、一批数据，可靠程度很低。

第 2 部分实测了这件事（本项目观察，CPU，第 2 部分）：在初始化的 2 层模型上做一次 AdamW 更新（关掉权重衰减），每个参数张量的"平均 |Δθ| / lr"在 0.9974 到 1.0000 之间。把 loss 乘以 100（梯度也乘以 100）再做一次，比值都在 0.99996 到 1.0000 之间。梯度放大 100 倍，第一步的步长几乎不变。

> **停下来想一想：** loss 不乘 100 时，比值为什么略小于 1，而乘 100 后变成 1.0000？提示：看分母里的 ε。

第一步之后，Adam 的 v 是梯度平方的指数移动平均，大约平均最近 1/(1 − β₂) 步。β₂ = 0.95 时约 20 步（数学结论）。在这之前，v 的估计只基于很少几个样本，很不稳定；某个坐标的 v 偶然很小，这个坐标的步子就会很大。warmup 让学习率在这段时间里保持很小，等 v 估计稳定了再放开。

这是 warmup 的一个常见解释，不是唯一的解释。还有研究从 Post-LN 结构的梯度分布（Xiong et al., 2020）和 Adam 自适应项的方差（Liu et al., 2019, RAdam）等角度分析。第 4 章 4.6.4 节的排序任务上，Pre-LN 不预热也能学会；本章的 Pre-Norm GPT 是否如此，本书没有测，你可以把它作为一个消融来做（13.5.8 节）。

### 13.2.4 为什么要衰减：噪声的地板

再看训练后期。每一步的梯度是从一小批数据估计出来的，带着噪声。可以把一次更新写成

$$\theta \leftarrow \theta - \text{lr}\cdot(\nabla L + \text{噪声}).$$

真实梯度 ∇L 在谷底附近趋于 0，噪声却不会消失。于是参数停在一个以最低点为中心、大小和学习率有关的"抖动区"里。学习率越大，抖动区越大，平均 loss 就越高。把学习率降下来，抖动区缩小，loss 还能再降一截。

所以很多预训练曲线有一个共同特点：训练末尾，学习率降下来的时候，loss 会再多降一些。这是一个常见现象，不是本书测出来的结论。第 4 章 4.6.5 节的螺旋 MLP 上，预热加余弦和恒定学习率看不出差别；长训练上差多少，要看你自己的完整训练。曲线上有没有这一截、有多明显，请在 lab 的记录表里写下来。

### 13.2.5 推导：warmup_cosine 的公式

第 4 章的 `warmup_cosine(step, total_steps, warmup_steps, base_lr, min_lr=0.0)` 分三段（step 从 0 开始）：

$$
\text{lr}(s)=
\begin{cases}
\text{base} \cdot \dfrac{s+1}{W}, & s < W \\[2mm]
\text{min} + (\text{base}-\text{min})\cdot\tfrac12\bigl(1+\cos(\pi p)\bigr),\quad p = \dfrac{s-W}{S-W}, & W \le s < S \\[2mm]
\text{min}, & s \ge S
\end{cases}
$$

其中 W 是 warmup 步数，S 是总步数。

几个性质（都是数学结论，假设 0 < W < S；W = 0 时没有 warmup 段，直接从 base 开始衰减；W = S 时整段都是 warmup，s ≥ S 才停在 min）：

1. **两段在 s = W 处接上**：warmup 最后一步 s = W − 1 时 lr = base；衰减第一步 s = W 时 p = 0，cos 0 = 1，lr = base。
2. **余弦段两头平、中间陡**：对 p 求导，dlr/dp = −(base − min)·(π/2)·sin(πp)，在 p = 0 和 p = 1 处为 0。开头不会突然掉，结尾平稳落地。
3. **衰减段的平均学习率**约为 (base + min)/2，因为 cos(πp) 在 [0, 1] 上积分为 0。这是把 p 看成连续变量的结论；实际的更新是离散的 s = W, …, S − 1，共 M = S − W 步，精确平均是 (base + min)/2 + (base − min)/(2M)，M 很大时多出的一项可以忽略。
4. **半程**（p = 1/2）lr = (base + min)/2。

### 13.2.6 数值例子

取一个"完整训练示例"：S = 5000，W = 200，base = 3×10⁻³，min = 3×10⁻⁴。手算几个点：

- s = 0：lr = 3×10⁻³ × 1/200 = 1.5×10⁻⁵。
- s = 199：lr = 3×10⁻³ × 200/200 = 3×10⁻³。
- s = 1250：p = 1050/4800 = 0.21875，cos(0.21875π) = 0.7730，lr = 3×10⁻⁴ + 2.7×10⁻³ × 0.5 × 1.7730 = 2.6936×10⁻³。
- s = 2500：p = 2300/4800 = 0.47917，cos(0.47917π) = 0.0654，lr = 3×10⁻⁴ + 2.7×10⁻³ × 0.5327 = 1.7383×10⁻³。
- s = 4999：p = 4799/4800，lr 几乎等于 min = 3×10⁻⁴。

第 2 部分逐点打印了这条调度，并画成 `outputs/book/ch13/schedule.png`，和上面的手算一致（数学结论，第 2 部分可复核）。衰减段 4800 步的平均学习率是 (base + min)/2 + (base − min)/(2 × 4800) = 1.65×10⁻³ + 2.8×10⁻⁷ ≈ 1.6503×10⁻³（数学结论）。

注意 s = 2500 时 lr 已经比半程值 1.65×10⁻³ 稍高，因为半程在 s = 200 + 2400 = 2600，不在 2500。

### 13.2.7 常见错误

- **warmup 太短或没有**：可能出现开头几十步 loss 剧烈震荡、梯度范数很大，甚至 NaN。本章的 GPT 上会不会这样，本书没有测（13.5.8 节的 `--warmup 0`）。看学习曲线下半图（lr 与梯度范数）的最左端。
- **总步数写错**：调度按 `cfg.steps` 算。中途把训练"再延长 1000 步"，等于换了一条调度曲线，后半段学习率会突然跳高。13.4 节的续训会专门防这个错误。
- **min_lr 设成 0 又在结尾评测**：最后几百步几乎不更新，浪费算力，但不算错误。设成峰值的十分之一是常见做法（待验证：不同项目的选择不同）。
- **把调度的"索引步"和日志的"更新步"混了**：本书的约定是第 k 次更新用 `warmup_cosine(k−1, ...)`。差一位不会让训练失败，但对拍时会对不上。

## 13.3 读懂学习曲线

### 13.3.1 动机

训练结束，你手里有一条曲线。同样是"最后 loss 到了某个数"，曲线的形状能告诉你很多：训练是否稳定？是不是该多训一会？模型是在学规律，还是在背数据？

这一节把一条典型的预训练曲线分成几段，每段讲它在发生什么、该看什么。这些分段来自常见经验，不是本书的完整训练结果；本书自己的曲线只有 13.3.8 节的 60 步冒烟，你的完整训练曲线要由你来对照。第 4 部分会把你的日志画成 `learning_curves.png`：上图是逐步训练 loss（浅色）、滑动平均（深色）、验证 loss（圆点）和 ln V 虚线；下图是学习率和裁剪前的梯度范数。

### 13.3.2 第 0 段：起点在 ln V

第 0 步，loss ≈ ln V = 7.7222。这一点在 13.1.5 节已经查过。曲线如果不从这里出发，先别往下看，回去查初始化。

### 13.3.3 第 1 段：几十步内暴跌——先学会"频率"

开头几十步，loss 从 7.7 迅速掉下去。这时模型在学最容易的东西：**哪些 token 常见**。`{`、`}`、`^`、`_` 这样的 token 出现得很多，只要把它们的概率调高，loss 就大幅下降。

这个阶段有一个可以算出来的"路标"：一个只知道 token 频率、完全不看上下文的模型（一元模型），在验证集上的交叉熵。第 1 部分算出了它，以及一个只看前一个 token 的二元模型（本项目观察，CPU，第 1 部分）：

| 路标 | 验证 nat/token | bits/byte |
|---|---|---|
| 均匀分布（屏蔽 BOS 后，ln 2257） | 7.7218 | 5.5686 |
| 一元模型（只学频率，加一平滑） | 5.4233 | 3.9110 |
| 二元模型（只看前一个 token，加一平滑） | 4.3596 | 3.1439 |

第一行是数学结论：验证时 BOS 被屏蔽，均匀分布只在其余 2257 个类别上，所以是 ln 2257 = 7.7218，比 ln V 小一点；bits/byte 用 13.1.4 节的系数 0.72115 换算。后两行是本项目实测的统计量。

这些数字给曲线画上了刻度。粗略地说：验证 loss 降到一元模型那一行，模型至少做到了'只按频率猜'的水平；降到二元模型以下，它超过了本章这个加一平滑的二元基线。换一种平滑方法的二元模型可能更低（第 7 章 7.6.3 节最好的计数 bigram 是 4.0132 nat/token），所以这不能证明模型用上了更长的上下文。loss 相同不等于模型用的信息相同，这只是刻度，不是诊断。我们预期一个训练充分的 GPT 明显低于二元模型（待验证：由你的完整训练给出）。如果完整训练跑完，验证 loss 还在二元模型附近，先查一遍代码和数据。

再往下还有一个刻度：第 7 章 7.6.3 节上文 8 的 MLP，同样的验证口径下是 2.7493 bits/byte（本项目观察，第 7 章）。你的 GPT 要和这个基线比，比的是最终验证点（2000 条公式）。比较结果填在 lab 的实验记录里，正文不提供。

第 3 部分的冒烟训练只有 60 步（2 层、d = 64、上下文 32、批量 16），验证 loss 在第 20、40、60 步分别是 5.5871、5.5163、5.4689 nat/token（本项目观察，CPU，第 3 部分；前两个点用前 200 条公式，最后一个点用 2000 条）。对照路标：60 步后的 5.4689 和一元模型的 5.4233 差不多，还远高于二元模型的 4.3596。一个合理的猜测是：冒烟模型主要学到了频率，还没怎么用上上下文（待验证：要确认，得做打乱上下文之类的对照）。60 步只够走完第 1 段，这些数只说明流程跑通，不代表模型能到哪里。

### 13.3.4 第 2 段：漫长的缓慢下降

暴跌之后，曲线变平，进入一段很长的缓慢下降。模型在学越来越难的规律：`\frac` 后面要跟两组花括号；`\left(` 要和 `\right)` 配对；上标里常出现什么。每学会一条规律，loss 只降一点点。

这一段常常近似是幂律：L − L∞ 和步数之间是 a·s^(−α) 的关系，在**双对数坐标**（横轴、纵轴都取对数，纵轴取 L − L∞）上接近一条直线。13.7 节的规模规律就是这个现象的系统版本。

这段曲线有两个读法：

- **斜率还明显向下**：继续训练还有收益。下次可以多给几步，或者用更大的学习率。
- **几乎水平**：要么模型容量到头了（换大模型），要么学习率太大、卡在了噪声地板上（13.2.4 节）。区分方法是看第 3 段。

### 13.3.5 第 3 段：末尾的"再降一截"

学习率按余弦降到最低的那几百步，loss 往往会再降一截（13.2.4 节）。如果你看到了这一截，说明之前的平台至少有一部分是噪声地板，不是容量极限。

由此可知，用余弦调度的训练，中途的 loss 不能代表"如果在这里停下来"的 loss。在第 2500 步时，学习率还很高，loss 被噪声抬高了；如果当初把总步数设成 2500，同一位置的 loss 通常会更低（Hoffmann et al., 2022 报告过这类现象；你可以用 13.7.5 节阶梯实验里不同 frac 的终点自己检验）。13.7 节做规模拟合时，这一点会变得非常重要。

### 13.3.6 训练 loss 与验证 loss 的差距

上图同时有训练 loss 和验证 loss。两者的差距怎么读？

先排除两个**与模型无关**的原因：

1. **任务口径不同**：训练是在拼接流上随机截窗，窗口开头没有完整的上文；验证是逐公式、从 BOS 开始。训练时 softmax 里还包括 BOS 这个类别，验证时 BOS 被屏蔽。所以训练 loss 和验证 loss 本来就不是同一个量，差一点不奇怪。
2. **验证前缀不同**：周期验证 200 条、最终验证 2000 条（13.1.4 节）。

排除这两点以后，再看**变化趋势**：

- 训练 loss 继续降、验证 loss 不降反升：**过拟合**。模型在背训练集。
- 两者一起降、差距稳定：健康。

什么时候容易过拟合？看 **epoch 数**：处理的 token 位置数 ÷ 训练流长度。13.1.7 节算过，MPS 预设大约要把 20000 条公式的训练流读 17 遍。读这么多遍，验证 loss 中途回升是可能的。如果你看到了回升，把它记下来，再用更大的 `--n-train` 重跑一次对照。

### 13.3.7 尖峰与 NaN

**尖峰**（spike）是 loss 突然跳高、几步后又落回去。`summarize_log` 把"超过此前 50 步滑动中位数 1.5 倍"的步记为尖峰（这个阈值是本书的约定，不是标准）。尖峰常见的原因：

- 学习率太大，尤其是 warmup 刚结束、学习率刚到峰值时；
- 某一批数据很反常（例如一条特别长、全是罕见 token 的公式）；
- 混合精度的数值问题（第 16 章）。

**看下图的梯度范数**：尖峰前梯度范数是否先升高？如果是，梯度裁剪会帮上忙；如果裁剪阈值已经频繁被触发（范数长期远高于阈值），学习率偏大是要优先排查的原因之一（待验证：梯度范数还受 loss 尺度和参数化影响），用一个更小的学习率做短对照来确认。

**NaN** 一旦进入参数或优化器状态，就会一直传播下去，不会自己消失。（fp16 的 GradScaler 会跳过梯度含 NaN/inf 的那一步，参数没被污染时训练还能继续，这是另一回事。）`summarize_log` 报告第一个出现非有限值的步。从那一步之前最近的检查点、用更小的学习率重新开始，是大规模训练里的标准做法（13.10 节）。

### 13.3.8 冒烟曲线

第 4 部分对冒烟训练的日志运行了 `summarize_log`（本项目观察，CPU，第 4 部分）：初始 loss 7.7399，最低验证 5.4689（第 60 步），末次训练 − 验证 = −0.0381，没有尖峰，没有非有限值。训练 loss 比验证 loss 还低一点点。这 60 步里模型只处理了 30,720 个 token 位置，约 0.026 个 epoch。这么小的差值不足以判断过拟合；13.3.6 节说的口径差别是一种可能的解释，但没有做对照，属于待验证。

### 13.3.9 常见错误

- **把周期验证点和最终验证点连成一条线**，看到末尾"跳了一下"就下结论。先看 `eval_formulas`。
- **只看训练 loss**。训练 loss 低可能是背下来了，也可能是泄漏（13.11 节）。
- **用线性横轴看全程**。前 1% 的暴跌把后面的变化压成一条平线。看后段时用对数横轴，或者只画后 90%。
- **不画梯度范数**。很多问题在 loss 上看不出来，梯度范数先报警。

## 13.4 检查点与续训：让中断无害

### 13.4.1 动机

几小时的训练，被断电、被系统更新、被你自己按了 Ctrl-C，都很正常。我们要的是：**中断以后接着跑，结果和从没中断过一模一样。**

第 4 章讲过要存哪五样东西：模型参数、优化器状态、当前步数、随机数状态、数据读到哪里。`train_pretrain` 都存了，还多存了 GradScaler 状态、"最近一段训练 loss 的累计"（让中断前后的训练 loss 平均值接得上），以及日志文件当时的字节长度。

### 13.4.2 对拍：逐位一致

第 3 部分做了一次对拍（本项目观察，CPU，第 3 部分）：同一配置，一次从头训到 60 步；另一次训到 30 步存盘，**丢掉内存里的模型**，重新建一个模型，从检查点续训到 60 步。两次的最终验证都是 5.4689 nat/token、3.9439 bits/byte，参数的最大差为 0。

参数差恰好为 0，不是"很小"。这在 CPU 上是可以做到的：同样的数据、同样的运算顺序，浮点结果就逐位相同。MPS 和 CUDA 上有些算子不保证确定性，能不能逐位一致要你自己测（lab 的完整训练节有记录表）。

### 13.4.3 调度器的状态：最容易漏的一项

本书的调度器没有自己的状态：学习率完全由"当前步数"和"总步数"算出来。所以续训时只要**步数恢复对了、总步数没改**，调度就自动对了。

两种常见的错法：

**错法一：步数没恢复。** 只加载了模型和优化器，循环又从第 1 步开始。学习率会重新 warmup。第 3 部分算出了续训后头几步的学习率（本项目观察，第 3 部分，只计算学习率、不训练）：

| 续训后的更新步 | 正确的 lr | 调度从头开始的 lr |
|---|---|---|
| 31 | 1.8844×10⁻³ | 5.0000×10⁻⁴ |
| 32 | 1.8067×10⁻³ | 1.0000×10⁻³ |
| 33 | 1.7285×10⁻³ | 1.5000×10⁻³ |
| 34 | 1.6500×10⁻³ | 2.0000×10⁻³ |
| 35 | 1.5715×10⁻³ | 2.5000×10⁻³ |

错误的那一列先偏低，几步后就**超过**正确值并继续往峰值爬。在一个已经训练了大半的模型上重新冲到峰值学习率，loss 往往会跳起来。

**错法二：总步数改了。** "已经训了 5000 步，再加 1000 步吧"，把 `steps` 改成 6000 再续训。余弦曲线被拉长，第 5001 步的学习率不再是最低值，而是按 6000 步重新算出来的、高得多的值。

`train_pretrain` 在续训时检查检查点里的完整配置（总步数、warmup、学习率、批量、上下文、种子、模型配置、数据版本和内容摘要），任何一项不一致就报错。第 3 部分故意把 `steps` 从 60 改成 61 再续训，得到（本项目观察，第 3 部分）：

```text
续训配置不一致：training.steps；检查点=60；请求=61
```

想延长训练怎么办？诚实的做法是承认这是一次新实验：要么从头用新的总步数训练，要么换一种允许延长的调度（13.10 节的 WSD）。

### 13.4.4 日志也要"续"

检查点在第 30 步，日志可能已经写到了第 33 步（第 31–33 步写完日志，还没来得及存检查点就断了）。续训从第 31 步重新跑，日志里第 31–33 步就会出现两次。`train_pretrain` 的做法是：检查点里记下每个日志文件当时的字节长度，续训时先把日志截断到这个长度，再接着写。同一种记录的步数永远不会重复。

### 13.4.5 原子写入

检查点先写到 `checkpoint.pt.tmp`，写完再用 `os.replace` 改名。在同一个文件系统上，改名是原子操作：其他进程看到的要么是旧文件，要么是写完的新文件。所以进程在写到一半时崩溃或被杀掉，旧检查点不会被半截文件替换（第 4 章 4.10 节）。如果还要防断电，需要在改名前后对文件和目录调用 fsync，本书的代码没有做这一步。

## 13.5 组件消融：怎样做一个可信的对照实验

### 13.5.1 动机

第 9–11 章讲了 RMSNorm、RoPE 和残差缩放为什么要这样设计，但没有测出它们各值多少：第 10 章 10.9 节那个 1 层、600 步的短实验里，rope 和 none 几乎打平。在**你的**数据、**你的**规模上，它们有多大作用？回答它的办法是**消融**（ablation）：去掉或替换一个部件，其他一切不变，看结果变化多少。

消融的道理很简单，做好却不容易。最常见的结局是：跑了六个变体，每个跑一次，看到 bits/byte 差了 0.01，就写"去掉 X 让模型变差"。这个结论很可能是噪声。

### 13.5.2 可以消融的部件

本章给 `GPTConfig` 加了几个开关（默认值保持原来的行为，第 11 章的代码和测试不受影响）。第 5 部分列出了六个变体，并打印了参数量和同一批数据上的初始 loss（本项目观察，CPU，第 5 部分，2 层、d = 64、上下文 32 的模型）：

| 变体 | 改了什么 | 参数量 | 非嵌入参数量 | 初始 loss |
|---|---|---|---|---|
| baseline | 无 | 251,328 | 106,816 | 7.7399 |
| no_position | `pos_emb="none"` | 251,328 | 106,816 | 7.7398 |
| learned_position | `pos_emb="learned"` | 253,376 | 106,816 | 7.7420 |
| layernorm | `norm="layernorm"` | 251,648 | 107,136 | 7.7398 |
| no_resid_scale | `resid_scale=False` | 251,328 | 106,816 | 7.7429 |
| untied | `tie_weights=False` | 395,840 | 251,328 | 7.7180 |

参数量的差别都能手算（数学结论）：

- 学习式位置多一张 T × d = 32 × 64 = 2048 的表。它算"嵌入"，所以非嵌入参数不变（Kaplan 的口径，13.6 节）。
- LayerNorm 比 RMSNorm 每层多一个 β 向量。2 层 × 2 个 + 最后 1 个 = 5 个归一化层，多 5 × 64 = 320。
- 不共享权重，输出层多一个 V × d = 2258 × 64 = 144,512 的矩阵，总参数多出 57.5%。

初始 loss 都在 ln V 附近，说明这些开关都没有把初始化弄坏。**初始 loss 不能预示最终谁好**：untied 的初始 loss 略低，只是因为独立初始化的输出层让 logits 的分布略有不同。

### 13.5.3 代码：开关怎样实现

以学习式位置为例。`GPT.__init__` 里：

```python
if cfg.rope and cfg.pos_emb == "learned":
    self.pos = nn.Embedding(cfg.block_size, cfg.d_model)
...
if not cfg.rope or cfg.pos_emb != "rope":   # cos = 1、sin = 0：旋转角为 0，apply_rope 什么也不做
    cos, sin = torch.ones_like(cos), torch.zeros_like(sin)
```

`forward` 里，token 嵌入之后加上位置嵌入：

```python
x = x + self.pos(torch.arange(pos0, pos0 + T, device=x.device))
```

用的是 `pos0` 起始的位置编号，所以 KV cache 逐个生成时（第 15 章）位置也是对的。这一点有测试检查：学习式位置下，分两段前向和整段前向的结果一致。

另外两个开关更简单：`norm="layernorm"` 时，把 `n1`、`n2`、`norm` 三处的 `RMSNorm` 换成 `nn.LayerNorm`（属性名不变）；`resid_scale=False` 时，残差支路输出层的初始化标准差用 0.02，而不是 0.02/√(2L)。

### 13.5.4 设计原则一：只改一个东西

"只改一个"比听起来难。改一个部件，往往会悄悄带动别的东西：

- **参数量**：untied 多了 57.5% 的参数。它如果更好，是因为"不共享"本身，还是因为参数多了？要分开，可以再加一个"共享、但把 d 调大到参数量相同"的对照。
- **随机数**：多一个模块，初始化时就多消耗一段随机数，后面的参数初值也跟着变了。所以即使种子相同，变体和基线的共有权重也不是逐元素相同的。这是另一个"噪声来源"，下一条原则处理它。
- **最佳学习率**：学习率是为基线调的。去掉残差缩放后，同一个学习率可能偏大。只用基线的学习率比较，结论可能是"这个学习率下 X 更差"，而不是"X 更差"。更公平的做法是给每个变体扫 3 个学习率，各取最好的。

### 13.5.5 设计原则二：先量出噪声有多大

同一个配置，换一个种子再训一次，最终的 bits/byte 不会完全一样。两个种子的差别，就是"什么都没改也会有的差别"。

规则是：

> **变体和基线的差，如果没有明显大于种子之间的差，就不下结论。**

具体做法：基线至少跑两个种子，得到 b₁、b₂；变体也跑两个种子，得到 v₁、v₂。比较平均差 (v₁ + v₂)/2 − (b₁ + b₂)/2 与种子间的差 |b₁ − b₂|、|v₁ − v₂|。前者只有后者那么大，就写"差别在噪声范围内"。两个种子只能粗略估计噪声。要更有把握，就跑更多种子。这件事第 5 章讲过，本章只是把它用在训练上。

### 13.5.6 设计原则三：同预算、同数据、同评测

- **同预算**：相同的步数、批量、上下文，即相同的训练 token 数。注意参数量不同的变体计算量也不同（13.6 节）。如果你在意"同算力"，要另外说明。
- **同数据顺序**：同一个种子决定同样的取批顺序。
- **同评测**：最终都用 val 前 2000 条、bits/byte。

`tour 5 --run` 按这三条逐个训练所有变体，并写出汇总 CSV（`variant`、`seed`、`val_nat_per_token`、`bits_per_byte`、`delta`）。lab 第 5 节和"完整消融"小节有命令和空白记录表；这张表书里不替你填。

### 13.5.7 设计原则四：先写预测

运行之前，把你的预测写下来：每个变体会变好还是变差？差多少？为什么？事后看结果再"解释"，什么结果都能编出道理；事前写下预测，结果才能检验你的理解。

下面是一些可以帮你形成预测的线索（都是待验证的预期，不是本书的结论）。`no_position`、`learned_position` 对应第 10 章 10.9 节的 none、learned，只是模型和预算换了：

- **no_position**：因果注意力本身就泄露了一点位置信息（位置 t 只能看到 t 个 token），有研究报告没有位置编码的因果语言模型也能学到一些位置信息（Haviv et al., 2022）。但 LaTeX 的配对结构（括号、`\left`/`\right`）很依赖相对位置。
- **learned_position**：在训练长度内可能和 RoPE 差不多；但它不能处理超过 `block_size` 的位置（第 10 章）。
- **layernorm**：RMSNorm 的提出者报告两者效果相近、RMSNorm 更省计算（Zhang & Sennrich, 2019）。在你的规模上差别可能落在噪声里。
- **no_resid_scale**：主要影响训练初期的稳定性；层数越多越明显。2 层模型上可能看不出来。
- **untied**：参数多了，可能更好；但词表不大、数据不多时，多出来的参数也可能只是更容易过拟合。

### 13.5.8 还可以消融训练过程

部件以外，训练过程也能消融：去掉 warmup（`--warmup 0`）、去掉梯度裁剪（`clip=0`）、不衰减（min_lr = lr）。原则一样：只改一个，量出噪声，先写预测。

## 13.6 计算量：6ND

### 13.6.1 动机

要比较"大模型少数据"和"小模型多数据"，得先有一把统一的尺子。这把尺子是**训练计算量** C，单位是浮点运算次数（FLOPs）。它有一个非常好用的估算公式：

$$C \approx 6ND,$$

N 是参数量，D 是训练的 token 数。这一节把 6 推出来，再讲清 N 该数哪些参数。

### 13.6.2 推导：前向 2，反向 4

考虑一个线性层 y = xW，W 的形状是 (d_in, d_out)，参数量 P = d_in·d_out。

**前向。** 对一个 token，x 是长 d_in 的向量。y 的每个分量是 d_in 次乘法、d_in 次加法（严格说是 d_in − 1 次加法，量级上记作 d_in）。y 有 d_out 个分量，所以一共约 2·d_in·d_out = **2P** 次浮点运算。

**反向。** 要算两样东西：

- 对输入的梯度 ∂L/∂x = (∂L/∂y)Wᵀ：形状和前向一样的矩阵乘法，约 2P；
- 对权重的梯度 ∂L/∂W = xᵀ(∂L/∂y)：外积，d_in × d_out 个元素，每个一次乘法一次加法（累加到批上），约 2P。

反向合计约 **4P**。

**一个 token 的训练**（前向 + 反向）约 6P。整个模型由许多线性层组成，P 加起来就是 N；D 个 token 就是 6ND。（数学结论。）

### 13.6.3 N 数哪些参数

不是所有参数都参与矩阵乘法：

- **输入嵌入**是查表：按编号取出一行，没有乘法。
- **输出层**是一次完整的矩阵乘法 (d → V)，每个 token 都要做一次。共享权重时，它和嵌入是同一个矩阵，在 `n_params()` 里只算一次，**但计算量要算**。
- **归一化层的 γ** 只有逐元素乘法，量很小。

所以"计算量口径"的 N 是：总参数 − 输入嵌入 + 输出层（共享时把输出层加回来）。第 16 章会用到的 `memory.matmul_params` 就是它。本章的阶梯模型都共享权重，于是这个口径正好等于总参数。

另一个常用口径是 Kaplan et al.（2020）的**非嵌入参数**：去掉词嵌入和位置嵌入。他们发现用非嵌入参数画规模曲线，不同形状的模型落在同一条线上更整齐（Kaplan et al., 2020, §3.2、图 6）。Hoffmann et al.（2022）则用总参数。

口径的差别在小模型上很大。第 6 部分打印了本章的模型阶梯（本项目观察，第 6 部分；参数量是数学结论，并与 `n_params()` 对拍）：

| 名字 | L | d | 头数 | 总参数 = matmul 参数 | 非嵌入参数 | 每 token 训练 FLOPs（6N） |
|---|---|---|---|---|---|---|
| tiny | 2 | 64 | 4 | 251,328 | 106,816 | 1,507,968 |
| small | 3 | 96 | 4 | 549,216 | 332,448 | 3,295,296 |
| medium | 4 | 128 | 4 | 1,142,144 | 853,120 | 6,852,864 |
| large | 6 | 192 | 6 | 3,090,240 | 2,656,704 | 18,541,440 |
| xl | 8 | 256 | 8 | 7,004,928 | 6,426,880 | 42,029,568 |

tiny 里，输出层 2258 × 64 = 144,512 个参数，占 matmul 参数的 57.5%；到 xl 只占 8.3%（数学结论）。**同一组实验，用两种口径拟合出来的指数会不一样**。报告规模规律时，必须写清用的是哪个 N。

### 13.6.4 数值例子：手算 medium 的一个 epoch

以 medium 为例，先核对参数量。d = 128，SwiGLU 中间维 f = 64·⌈(8·128/3)/64⌉ = 64·⌈5.33⌉ = 384。每块 4d² + 3df + 2d = 65,536 + 147,456 + 256 = 213,248；4 块是 852,992；加最后的归一化 128，得非嵌入参数 853,120；再加 V·d = 2258 × 128 = 289,024，得总参数 1,142,144。和表一致。

训练一个 epoch，D = 1,189,263：

$$C = 6 \times 1{,}142{,}144 \times 1{,}189{,}263 \approx 8.15\times10^{12}\ \text{FLOPs}.$$

（数学结论。）

### 13.6.5 6ND 没算什么

6ND 只数了"参数 × token"的乘法。注意力里还有两次和序列长度有关的矩阵乘法：QKᵀ 和"权重 × V"。Kaplan et al.（2020, §2.1, 表 1）把前向计算量写成

$$C_\text{forward} \approx 2N + 2\,n_\text{layer}\,n_\text{ctx}\,d_\text{attn}.$$

第二项与第一项之比约为 n_layer·n_ctx·d / N。medium、上下文 128 时是 4 × 128 × 128 / 1,142,144 ≈ 5.7%（数学结论）。上下文不长时，6ND 足够用；上下文变长，这一项会变大。第 6 部分的 `attention_extra_ratio` 列用当前配置的上下文算这个比例：默认冒烟配置上下文是 32，medium 那一行是 0.0143；换成 `--preset mps`（上下文 128）就是上面的 5.7%。

### 13.6.6 从计算量到时间

计算量本身不是时间。换算公式是

$$\text{时间} \approx \frac{6ND}{\text{设备峰值 FLOPs/秒} \times \text{MFU}}.$$

MFU（model FLOPs utilization）是实际利用到的比例。小模型的矩阵太小，喂不饱设备，MFU 往往很低。第 16 章会教你用日志里的 `tok_per_sec` 反推自己设备的 MFU。本章不写任何设备的耗时：等你跑过再填。

## 13.7 规模规律与拟合

### 13.7.1 动机

把 13.6 节的五个模型都训一遍，每个模型在训练过程中都能得到一串 (计算量 C, 验证 loss L) 点。把它们画在一张图上，你大概会看到：**大模型起步慢（同样计算量下 loss 更高），但能走得更低。**所有曲线下方有一条"包络线"，它告诉你：给定计算量 C，能达到的最低 loss 是多少。

Kaplan et al.（2020）发现，这条包络线、以及 loss 随 N、随 D 的变化，都近似是**幂律**，这种关系叫规模规律。它的价值在于**可以外推**：用一组小实验拟合出曲线，就能预测更大的实验大概能到哪里，再决定值不值得花钱。

### 13.7.2 幂律长什么样

纯幂律 L = a·C^(−α)。两边取对数：

$$\log L = \log a - \alpha \log C.$$

在双对数坐标里是一条直线，斜率是 −α。C 每翻 10 倍，L 乘以 10^(−α)。

作为参照，Kaplan et al.（2020, §1.2）报告的指数是：L 对非嵌入参数 N 的 α_N ≈ 0.076，对数据量 D 的 α_D ≈ 0.095，对最优分配下计算量的 α_C ≈ 0.050。这些数针对的是他们的网页文本和模型，**不能拿来预测本项目**，只是让你对"指数通常很小"有个感觉：C 翻 10 倍，loss 只乘以 10^(−0.05) ≈ 0.89。

### 13.7.3 为什么要加 L∞

纯幂律有个毛病：C 趋于无穷时，L 趋于 0。这不可能。语言本身有不确定性：同样的上文，下一个 token 可能有好几种合理写法（`x^2` 后面可以接 `+`、`=`、`}`……）。再大的模型也消除不了这部分熵。所以更合理的形式是

$$L(C) = a\cdot C^{-\alpha} + L_\infty,$$

L∞ 是**不可约损失**（irreducible loss），a·C^(−α) 是可以靠算力消除的部分。

不加 L∞ 会怎样？第 7 部分在**合成数据**上做了实验（本项目观察，第 7 部分，合成数据）：用 a = 25、α = 0.3、L∞ = 1.5 生成 40 个无噪声的点，C 从 10² 到 10⁸。

| 拟合方式 | a | α | L∞ |
|---|---|---|---|
| 真值 | 25 | 0.3 | 1.5 |
| 带 L∞ 的拟合 | 25.0000 | 0.3000 | 1.5000 |
| 纯幂律拟合（忽略 L∞） | 9.6250 | 0.1110 | — |

忽略 L∞，α 被估成 0.111，不到真值的一半。原因是：L∞ > 0 时，log L 对 log C 不是直线，而是一条越来越平的曲线（L 接近 L∞ 时，log L 几乎不再变）。用直线去拟合一条变平的曲线，斜率自然被压小。

### 13.7.4 推导：怎样拟合

拟合分两层。

**内层：固定 L∞，拟合 a 和 α。** 令 y = log(L − L∞)，u = log C。模型变成直线 y = b − αu，b = log a。最小二乘的闭式解是

$$\alpha = -\frac{\sum_i (u_i-\bar u)(y_i-\bar y)}{\sum_i (u_i-\bar u)^2}, \qquad b = \bar y + \alpha\bar u.$$

（数学结论：一元线性回归的斜率和截距。）

**外层：搜索 L∞。** L∞ 必须在 [0, min L) 内，否则 log(L − L∞) 没有定义。对每个候选 L∞，用内层解出 a、α，算出预测值，再算原始 loss 空间里的均方误差。在一维上找让误差最小的 L∞：先在 257 个等距网格点上粗找，再在最好的点附近用黄金分割法细化。

外层为什么在原始 loss 空间比误差，而不在 log(L − L∞) 空间？因为不同的 L∞ 对应不同的 y，它们的误差不在同一个尺度上，不能直接比较。

代码就是这个思路（`miniocr/train/scaling.py`）：

```python
def fit_power_law(x, y):
    u, v = np.log(x), np.log(y)
    slope = np.dot(u-u.mean(), v-v.mean()) / np.dot(u-u.mean(), u-u.mean())
    intercept = v.mean() - slope*u.mean()
    return dict(a=float(np.exp(intercept)), alpha=float(-slope), ...)

def fit_power_law_offset(x, y):
    def candidate(offset):
        fit = fit_power_law(x, y-offset)                        # 内层：闭式解
        pred = fit["a"] * x**(-fit["alpha"]) + offset
        return dict(..., residual=float(np.mean((pred-y)**2)))  # 原始空间误差
    grid = np.linspace(0, np.min(y)*(1-1e-10), 257)              # 外层：先粗网格
    ...                                                          # 再黄金分割细化
```

### 13.7.5 计算量前沿：用哪些点拟合

规模拟合的对象不是某一个模型的曲线，而是所有模型曲线下方的包络，叫**计算量前沿**（compute frontier）。`compute_frontier` 的做法是：把 log C 分成若干区间，每个区间里只保留 loss 最低的那个实测点。它不插值、不造点、不强制单调。

这里有一个陷阱，和 13.3.5 节有关。**余弦调度跑到一半时的 loss，比"总步数就设成这么多"时的 loss 高**，因为那时学习率还没降下来。如果拿每个模型训练途中的验证点去构造前沿，所有中间点都被系统性抬高，拟合出来的曲线就偏了。Hoffmann et al.（2022）指出，余弦周期长于实际训练步数会高估中间点的 loss，这是他们的结论与 Kaplan et al.（2020）不同的原因之一。

所以本章的阶梯实验这样设计：每个模型按总步数的几个比例（默认 0.25、0.5、1），**各自完整地跑一遍 warmup + cosine**，只取每次训练最后的标准验证点（2000 条公式）。五个模型、三个比例，一共 15 个点，每个点都是"在这个计算量下认真训完"的结果。第 6 部分 `--run` 负责训练，第 7 部分读取这些点、算前沿、拟合 L(C) 并画图。lab 的"阶梯训练与拟合"小节有命令和空白记录表，还会事先打印总预算，让你知道要跑多久之前先心里有数。

### 13.7.6 拟合的局限

- **点少、范围窄**：5 个模型的 N 只跨了约 28 倍（7,004,928 / 251,328，数学结论）。在这么窄的范围里，L∞ 和 α 很难同时定准：L∞ 稍大一点、α 稍大一点，可能拟合得一样好。拟合出的 L∞ 不要当成"LaTeX 的真实熵"。
- **外推有风险**：拟合范围外几个数量级的预测，只能当粗略参考。
- **重复数据**：如果大模型的预算让它把训练集读了很多遍，它的点会受过拟合影响，偏离幂律。看每个点对应的 epoch 数。

## 13.8 Chinchilla：给定计算量，怎样分配参数和数据

### 13.8.1 动机

现在回答本章开头的问题：手里有固定的算力 C，该训多大的模型、读多少数据？

两个极端都不好。模型太小，读再多数据也学不会复杂的规律；模型太大，计算量都花在了"每个 token 都要过一遍大模型"上，读不了几个 token。中间有一个最优点。Hoffmann et al.（2022）把它算了出来，他们的模型叫 Chinchilla，所以这个结论常被叫作 Chinchilla 规律。

### 13.8.2 设定

Hoffmann et al.（2022, §3.3）用这样一个形式描述 loss 与 N、D 的关系：

$$L(N, D) = E + \frac{A}{N^\alpha} + \frac{B}{D^\beta}.$$

三项各有含义：

- **E**：不可约损失，和 13.7 节的 L∞ 是同一个意思；
- **A/N^α**：模型太小造成的损失，N → ∞ 时消失；
- **B/D^β**：数据太少（训练不足）造成的损失，D → ∞ 时消失。

约束是计算量固定：

$$6ND = C.$$

问题：在约束下，N 取多少时 L 最小？

### 13.8.3 推导

**第一步：用约束消去 D。** D = C/(6N)，代入：

$$L(N) = E + A N^{-\alpha} + B\left(\frac{C}{6N}\right)^{-\beta} = E + A N^{-\alpha} + B\left(\frac{6}{C}\right)^{\beta} N^{\beta}.$$

现在 L 只是 N 的函数。第二项随 N 增大而减小，第三项随 N 增大而增大：一个嫌 N 小，一个嫌 N 大。

**第二步：求导，令导数为零。**

$$\frac{dL}{dN} = -\alpha A N^{-\alpha-1} + \beta B \left(\frac{6}{C}\right)^{\beta} N^{\beta-1} = 0.$$

两边乘以 N：

$$\alpha A N^{-\alpha} = \beta B \left(\frac{6N}{C}\right)^{\beta} = \beta B\, D^{-\beta}.$$

最后一步用了 6N/C = 1/D。于是：

$$\boxed{\ \alpha\cdot\frac{A}{N^\alpha} = \beta\cdot\frac{B}{D^\beta}\ }$$

最优点上，"模型太小"那一项乘以 α，等于"数据太少"那一项乘以 β。直观地说：把一点算力从数据挪给模型，模型项减少的量，正好等于数据项增加的量。两边边际收益相等。

**第三步：解出 N。** 从 αA N^(−α) = βB (6/C)^β N^β 得

$$N^{\alpha+\beta} = \frac{\alpha A}{\beta B}\left(\frac{C}{6}\right)^{\beta}.$$

令 G = (αA / (βB))^{1/(α+β)}，则

$$N_\text{opt} = G\left(\frac{C}{6}\right)^{\frac{\beta}{\alpha+\beta}}, \qquad D_\text{opt} = \frac{C}{6N_\text{opt}} = G^{-1}\left(\frac{C}{6}\right)^{\frac{\alpha}{\alpha+\beta}}.$$

（数学结论。）这是最小值：在驻点上，L''(N*) = αA(α + β)·N*^(−α−2) > 0。注意不能说"两项都是凸的"：β < 1 时第三项 N^β 对 N 是凹的；但在驻点处二阶导数仍为正，而且驻点唯一，所以它就是全局最小。

**第四步：读指数。** N_opt ∝ C^a，D_opt ∝ C^b，

$$a = \frac{\beta}{\alpha+\beta}, \qquad b = \frac{\alpha}{\alpha+\beta}, \qquad a + b = 1.$$

a + b = 1 是约束 6ND = C 决定的：N 和 D 的乘积要等于 C/6。如果 α ≈ β，那么 a ≈ b ≈ 1/2：算力翻倍，模型和数据各放大约 √2 倍。

### 13.8.4 数值例子

Hoffmann et al.（2022）第三种方法（§3.3）拟合的系数（具体数值见其附录 D.2 的式 (10)）是 E = 1.69，A = 406.4，B = 410.7，α = 0.34，β = 0.28。这组数来自他们的网页文本数据和模型，只用来演示公式，不代表本项目。

先算指数：a = 0.28/0.62 = 0.4516，b = 0.34/0.62 = 0.5484。

再手算 C = 10²¹ FLOPs：

1. αA = 0.34 × 406.4 = 138.18；βB = 0.28 × 410.7 = 115.00；比值 1.2016。
2. G = 1.2016^{1/0.62} = e^{0.18363/0.62} = e^{0.29618} = 1.3447。
3. C/6 = 1.6667×10²⁰，(C/6)^{0.4516} = e^{0.4516 × 46.5625} = e^{21.028} ≈ 1.3565×10⁹。
4. N_opt = 1.3447 × 1.3565×10⁹ ≈ 1.824×10⁹（约 18 亿参数）。
5. D_opt = 1.6667×10²⁰ / 1.824×10⁹ ≈ 9.136×10¹⁰（约 900 亿 token）。
6. D/N ≈ 50。

第 8 部分对一串预算打印了闭式解，并用独立的 log N 网格搜索核对，N 的相对误差都在 0.12% 以内（网格间距造成的，数学结论，第 8 部分可复核）：

| C（FLOPs） | N_opt | D_opt | D/N |
|---|---|---|---|
| 10¹⁸ | 8.06×10⁷ | 2.07×10⁹ | 25.7 |
| 10²¹ | 1.82×10⁹ | 9.14×10¹⁰ | 50.1 |
| 10²⁴ | 4.13×10¹⁰ | 4.04×10¹² | 97.7 |

### 13.8.5 "每个参数 20 个 token"从哪来

你可能听过一句口诀："训练 token 数应该是参数量的 20 倍左右。"上表的 D/N 却从 25.7 变到 97.7，不是常数。怎么回事？

首先，D/N = D_opt/N_opt ∝ C^{b−a}。只要 α ≠ β，比值就随算力变化；这组系数里 α > β，所以算力越大，越偏向多给数据（数学结论）。

其次，Hoffmann et al.（2022）用了三种方法估计最优分配，得到的 N 指数分别约为 0.50、0.49、0.46（他们的表 2）。前两种方法更接近"N、D 等比例增长"，D/N 大致恒定。他们按这个结论训练的 Chinchilla 模型是 700 亿参数、1.4 万亿 token，正好约 20 token/参数。"20 倍"这句口诀来自这里。第三种方法（就是上面用的参数化拟合）给出的比值随规模变化更明显。

所以"20 倍"是一个经验参照，不是定律。可以带走的结论是 a ≈ b ≈ 1/2：模型和数据应该一起增长。

### 13.8.6 和 Kaplan 的分歧

Kaplan et al.（2020, §6）得到的结论很不一样：N_opt ∝ C^{0.73}，也就是算力增加时主要应该加大模型，数据只需要少量增加。按 Kaplan 的结论训练的大模型（例如 GPT-3 时代的模型）普遍"数据不够"。

Hoffmann et al.（2022）认为，分歧的一个来源就是 13.7.5 节的陷阱：Kaplan 等人的训练中，学习率调度的长度没有随训练 token 数调整，中途点的 loss 被高估，最优分配的估计因此产生偏差。Hoffmann 等人为每个预算单独设置余弦周期，结论就变了。这也是本章阶梯实验坚持"每个预算完整跑一遍调度"的原因。

### 13.8.7 对本项目意味着什么

第 8 部分也把这组外部系数用在了 10¹⁵、10¹⁶、10¹⁷ 这样的小预算上（D/N 分别约 13、16、21）。**这远在原拟合范围之外**，而且系数是网页文本上拟合的，不能据此选本项目的模型大小。

能用于本项目的是方法：

1. 用阶梯实验得到自己的点（13.7.5 节）；
2. 拟合自己的 L(N, D)，或者从前沿上读出每个 C 对应的最优 N、D，再分别拟合它们随 C 的变化（只拟合一维的 L(C) 不够：它没有分开参数和数据各自的作用）；
3. 再用本节的公式算出自己的最优分配。

还有一点：Chinchilla 最优只管"训练算力最省"。模型训好以后要反复推理，小模型推理便宜。所以实际项目经常故意训一个比 Chinchilla 最优更小的模型，多读很多数据（"过度训练"）。TexPixel 最后要部署 OCR 模型，推理成本同样重要。

> **停下来想一想：** 如果 β 比 α 大很多，算力增加时应该主要加模型还是加数据？用 a = β/(α+β) 验证你的直觉。

## 13.9 loss 之外：可编译率

### 13.9.1 动机

bits/byte 衡量的是"模型对真实公式的概率估计准不准"。它很敏感，但它不直接回答另一个问题：模型自己写出来的公式，能用吗？

一个模型可能在每个位置都给出不错的概率，生成时却经常忘了闭合花括号。反过来，两个 bits/byte 差不多的模型，生成的公式合法率可能差不少。所以 M1 和 A2 都要求再报一个指标：**生成公式的可编译率**。

### 13.9.2 定义和它的近似

可编译率 = 生成的公式里能被 LaTeX 编译的比例。

本机没有安装 LaTeX，正式评测的渲染器还没选定。本书用 `miniocr.eval.render.can_parse`（matplotlib 的 mathtext）近似"能编译"（第 0 章 0.7 节）。第 12 章 12.7 节讲过它的盲区：mathtext 不支持矩阵类环境，也不认识一些合法命令。所以本节报告的严格说是"**mathtext 可解析率**"。

### 13.9.3 先量参考上限

在看模型之前，先问：**真实的验证公式本身**能被 mathtext 解析的比例是多少？第 9 部分算了（本项目观察，CPU，第 9 部分）：

| 桶 | 条数 | 可解析 | 比例 | 95% 区间 |
|---|---|---|---|---|
| 全部（val 前 2000 条） | 2000 | 1199 | 0.5995 | [0.5779, 0.6208] |
| 含矩阵类环境 | 186 | 0 | 0.0000 | [0.0000, 0.0202] |
| 不含矩阵类环境 | 1814 | 1199 | 0.6610 | [0.6389, 0.6824] |

一个**完美模仿真实分布**的模型，它的 mathtext 可解析率也只有 0.60 左右，因为真实数据本身就有约 40% 不能被 mathtext 解析。其中 186 条是矩阵类环境（mathtext 一概拒绝），另外 615 条不含矩阵的公式也失败了（例如用了 mathtext 不认识的命令，第 12 章 12.7 节）。所以：

- 模型的可解析率不该和 1.0 比，要和这个参考值比。
- 报告时最好分桶：矩阵桶里 mathtext 什么也说明不了。
- 换成真正的 LaTeX 编译器后，这张表要重做。

参考值也不是模型的严格上界：模型可能偏爱写简短、简单的公式，可解析率反而高于真实数据。这时它只是更单调。所以可解析率要和 bits/byte 一起看，不能单独用。

### 13.9.4 置信区间：Wilson 区间

只生成 50 条，比例的不确定性很大。本书用 **Wilson 区间**，而不是常见的 p̂ ± 1.96√(p̂(1−p̂)/n)。原因是后者在 p̂ 接近 0 或 1 时很糟：0 成功时它给出 [0, 0]，好像我们确定比例就是 0。Wilson 区间是

$$\frac{\hat p + \frac{z^2}{2n} \pm z\sqrt{\frac{\hat p(1-\hat p)}{n} + \frac{z^2}{4n^2}}}{1 + \frac{z^2}{n}}, \qquad z = 1.96.$$

上表矩阵桶 0/186 的区间是 [0, 0.0202]：0 次成功，但真实比例仍可能到 2% 左右。

### 13.9.5 生成的口径

`sample_report` 从 BOS 开始采样，禁止生成 BOS，遇到 EOS 停止，最多生成 `block_size` 个 token。没遇到 EOS 就被截断的样本**也计入分母**，同时单独报告"以 EOS 结束的条数"。截断的串能解析，也不代表它是一个完整的正确公式。

采样方式会显著影响可解析率：温度低，模型更保守，合法率往往更高、多样性更低。第 14 章会系统地比较解码方式。本章固定温度 1.0（从模型分布本身采样），这样可解析率反映的是模型分布本身。

第 9 部分用冒烟检查点（60 步）生成了 50 条，可解析 4 条，比例 0.08，区间 [0.0315, 0.1884]，只有 17 条以 EOS 结束（本项目观察，CPU，第 9 部分）。样例都是乱码，例如 `" Ltaumathfrak((rightarrow0k"`。冒烟模型只训练了几十步，这个数只证明流程跑通，不是任何意义上的模型结果。你的完整训练模型的结果填在 lab 末尾"实验记录"表里（命令见 lab"完整训练与曲线"小节，它会同时运行第 9 部分）。

## 13.10 概括：大规模预训练的工程细节

> **概括：大规模预训练还要处理什么**
>
> 下面这些内容本书不实操，只讲思路，供你读技术报告时对照。
>
> - **数据管道**：几十 TB 的 token 文件分片存放，多进程预取；记录每个样本被读过几次，保证可复现。数据混合比例按 token 配额定（第 12 章 12.8 节）。
> - **分布式训练**：数据并行、张量并行、流水线并行、ZeRO/FSDP 把参数、梯度、优化器状态切到多张卡上（本书不展开）。
> - **混合精度**：bf16 计算、fp32 主权重（第 16 章）。
> - **loss 尖峰的处理**：自动检测尖峰，回退到之前的检查点，跳过出问题的那段数据，或者临时降低学习率再继续。
> - **数值稳定技巧**：例如对 logits 的大小加一个小惩罚（z-loss）、对 q、k 做归一化（QK-norm，第 17 章的 Qwen3 就用了），减少注意力 logits 过大造成的不稳定。
> - **超参数迁移**：在小模型上调好学习率，用 μP 等参数化方法迁移到大模型，避免在大模型上反复调参。
> - **其他调度**：WSD（warmup–stable–decay）先长时间保持峰值学习率，最后一小段快速衰减。好处是总步数不必事先定死：要延长训练，从 stable 段的检查点接着跑即可，正好避开 13.4.3 节"改总步数"的问题。
> - **批量大小**：很多训练在开头用较小的批量，再逐步增大。
>
> 这些做法的具体效果因模型和数据而异，本书不给数字（待验证）。

## 13.11 常见错误

下面按"现象 → 原因 → 怎样发现"整理本章的常见错误。

### 13.11.1 学习率过大

**现象：** loss 降得很快，然后停在一个偏高的位置来回震荡，或者突然跳高，甚至 NaN；梯度范数持续升高。

第 10 部分做了一个小演示（本项目观察，CPU，第 10 部分）：同一个 tiny 模型（上下文 16、批量 8）、同样的随机取批顺序、恒定学习率（没有 warmup 和衰减）、不裁剪梯度，分别用三个学习率各训练 60 步：

| 学习率 | 最后 10 步平均 loss | 第 10 步 loss | 第 60 步梯度范数 |
|---|---|---|---|
| 3×10⁻³ | 5.4159 | 6.4454 | 0.8941 |
| 3×10⁻² | 5.4502 | 6.2731 | 0.4354 |
| 3 | 53.7496 | 105.0548 | 11.1138 |

第一，在这个配置、这个种子下，学习率放大 10 倍，60 步内的 loss 几乎看不出差别。所以只跑几十步，未必能区分两个学习率；长训练里它们差多少，要你自己测（待验证）。第二，放大 1000 倍时 loss 冲到 100 以上，远远**高于** ln V = 7.7222。loss 高于均匀分布，说明正确的 token 拿到的概率比"瞎猜"还低得多：模型被推到了一个很差的地方，比没学会还糟。60 步内没有出现 NaN，已打印的梯度范数在 9.8 到 20.1 之间。所以 NaN 不是学习率过大的唯一表现；loss 超过 ln V 同样是警报。

**怎样发现：** 看学习曲线下半图的梯度范数；对比两三个学习率的短训练。

### 13.11.2 续训时调度器没恢复

**现象：** 续训后 loss 先跳高，再慢慢降回来；学习率曲线在续训点出现一个新的 warmup，或者末尾学习率没有降到最低。

**原因与发现：** 见 13.4.3 节。看日志里 lr 那一列在续训点是否连续。`train_pretrain` 会拒绝改了总步数的续训。

### 13.11.3 验证集泄漏导致 loss 低得可疑

**现象：** 验证 loss 比训练 loss 还低很多，或者低于你对这个规模的合理预期；但生成的公式质量和这个 loss 不相称。

**原因：** 验证公式（或它的等价写法）混进了训练集。第 12 章讲过，原串不同、规范化后相同的公式也算泄漏。

第 10 部分用规范键交集检查了这件事（本项目观察，CPU，第 10 部分）：标准划分下，训练前缀（20000 条）和 val 前 2000 条的规范键交集是 0；人为把 50 条训练公式混入"验证集"后，交集变成 50。

**怎样发现：** 训练前做一次规范键交集检查（`leakage_overlap`）；把交集作为数据报告的一项。

### 13.11.4 混用评测口径

**现象：** 曲线最后一个验证点"突然跳了一下"；或者和别人比 nat/token，结论反了。

**原因：** 周期验证（200 条）和最终验证（2000 条）分母不同；nat/token 依赖分词器。

**怎样发现：** 读每条验证记录的 `eval_formulas`、`eval_tokens`、`eval_bytes`；跨分词器只比 bits/byte。

### 13.11.5 用未完成调度的中间点做规模拟合

**现象：** 拟合出的前沿和最优分配都有偏差；中途点的 loss 偏高，越早停下的点偏得越多。

**原因：** 13.7.5 节、13.8.6 节。

**怎样发现：** 检查拟合用的每个点是不是一次完整调度的终点。

### 13.11.6 忽略 L∞

**现象：** 双对数图上点明显弯曲（越来越平），直线拟合的残差（log L − log L预测）呈"两端为正、中间为负"的规律；α 偏小。

**怎样发现：** 同时拟合带 L∞ 和不带 L∞ 的版本，把两者的预测都放到原始 loss 空间里算残差再比较（第 7 部分打印的两个 `residual` 一个在 log 空间、一个在原始空间，不能直接比）。

### 13.11.7 6ND 里的 N 数错

**现象：** 小模型的计算量被低估一半以上；不同口径的规模曲线指数对不上。

**原因：** 忘了共享权重的输出层也要做矩阵乘法；或者混用了非嵌入参数和总参数。

**怎样发现：** 写清用的是哪种 N；用 `parameter_counts` 同时打印三种口径。

### 13.11.8 单种子消融

**现象：** 消融表里每个差别都"有意义"，但换一个种子排序就变了。

**怎样发现：** 至少两个种子；差别和种子间差同量级时不下结论（13.5.5 节）。

### 13.11.9 可编译率不看参考上限

**现象：** 可解析率"只有 0.5 多"，以为模型很差；或者某个模型可解析率特别高，以为它更好。

**怎样发现：** 先量真实数据的参考值并分桶（13.9.3 节）；和 bits/byte 一起看。

## 13.13 小结

本章给的是方法：下面的结论来自推导、冒烟运行和外部论文。LaTeX GPT 的完整训练、消融和规模拟合结果由你完成，填进 lab 的记录表。

- **一次完整的预训练** = warmup + cosine 调度、梯度裁剪、定期按固定口径验证（nat/token 与 bits/byte）、可逐位一致续训的检查点、每步日志；续训时步数和总步数都不能变。
- **warmup** 是因为 Adam 第一步每个参数（|g| ≫ ε 时）都移动约 lr、早期二阶矩估计不稳；**衰减**是为了缩小梯度噪声造成的抖动区；所以余弦调度的中途 loss 不等于"在那里停下"的 loss。
- **读学习曲线**：典型形状是起点 ln V，先暴跌到"只学频率"的路标，再沿近似幂律缓慢下降，末尾随学习率衰减再降一截；看梯度范数找尖峰原因，看 epoch 数判断过拟合，先排除口径差异。
- **消融要可信**：只改一个、同预算同数据同评测、至少两个种子、事前写预测；差别不大于种子间差就不下结论。
- **C ≈ 6ND**；规模规律用 L = a·C^(−α) + L∞ 拟合计算量前沿（每个点都要是完整调度的终点）。在 6ND = C 约束下最小化 E + A/N^α + B/D^β，最优点满足 αA/N^α = βB/D^β，N_opt ∝ C^{β/(α+β)}：模型和数据应一起增长。
