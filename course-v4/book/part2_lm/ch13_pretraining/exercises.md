## 答案与提示

**13.1** BOS 只作条件，评测协议不预测它；窗口跨公式边界时，某个位置的目标是下一条公式的 BOS，模型根本没法从上文知道"这条公式该结束、下一条要开始"之外的东西，而且这个目标和验证任务无关。不去掉的话，训练任务里多了一类验证中不存在的目标，两者口径差得更远。BOS 目标是比较"容易"的（EOS 之后总是 BOS），不去掉往往会把训练 loss 拉低，差距通常变大；但方向取决于数据，严格说应实测。

**13.2** warmup：开头 Adam 的二阶矩估计不可靠，第一步里梯度不太小（|g| ≫ ε）的参数都移动约 lr，需要小步试探。衰减：后期梯度噪声让参数在最低点附近抖动，降低学习率缩小抖动区。前者是"信息不可靠"，后者是"噪声太大"。

**13.3** 一般预期 ℓ > ℓ′：第 2500 步时前者的学习率还在 1.7×10⁻³ 左右，后者已降到 min_lr，噪声抖动更小。规模拟合如果用前者这样的中间点，会系统性高估"小数据量"下的 loss，使计算量前沿和最优分配的估计产生偏差（13.7.5、13.8.6 节）。这是预期，你可以用阶梯实验的 frac 设计检验。

**13.4** 几个与过拟合无关的原因及方向：(1) 训练是随机截窗，窗口开头的位置缺上文，验证从 BOS 开始逐公式评测：让训练 loss 偏高。(2) 训练 softmax 含 BOS 类别、验证屏蔽 BOS：同样的目标，训练 loss 偏高一点。(3) 训练 loss 是最近一段的平均，而模型一直在变好，验证用的是段末的模型：训练 loss 偏高。(4) 周期验证只用前 200 条，这 200 条可能比训练数据平均更难或更容易：方向不定。(5) 训练 loss 来自少数随机批，有抽样波动：方向不定。排除这些之后再看趋势。

**13.5** 参数量不同（untied 多 57.5%），收益可能来自参数多；只有一个种子，差别可能是噪声；学习率只为基线调过；如果只比较了一个规模，结论不能推广。

**13.6** 不同口径在小模型上差别很大，拟合出的指数随之不同，别人无法复现或对照。tiny 的 matmul 参数 251,328，非嵌入参数 106,816，前者是后者的 2.35 倍。

**13.7** C → ∞ 时 L → 0，意味着无限算力能把语言的不确定性完全消除，这不可能。L∞ 是不可约损失：数据本身的熵（同样的上文有多种合理续写），再大的模型也降不下去。

**13.8** 把一点点计算量从"数据"挪给"模型"：模型项的下降率和数据项的上升率在最优点上相等。用对数导数说：模型项对 log N 的导数是 −αA/N^α，数据项对 log D 的导数是 −βB/D^β；约束下 d log N = −d log D，最优时两者绝对值相等。

**13.9** 真实验证公式本身只有 0.5995 能被 mathtext 解析（实测，第 9 部分）：801 条失败里，186 条是矩阵类环境（mathtext 一概拒绝），615 条是其他原因。完美模仿真实分布的模型也只能到约 0.60。高于参考值可能意味着模型偏爱写短而简单的公式，多样性差；要和 bits/byte 一起看。

**13.10** 无状态设计：只要步数和总步数恢复正确，调度就自动正确；要防的是改总步数。有状态设计：必须同时保存和加载调度器的状态（`scheduler.load_state_dict`），漏了就会从头 warmup。

**13.11** f = 64·⌈(8·96/3)/64⌉ = 64·⌈4⌉ = 256。每块 4d² + 3df + 2d = 36,864 + 73,728 + 192 = 110,784；3 块 332,352；加最后归一化 96，非嵌入 332,448；加 V·d = 216,768，总参数 549,216。

**13.12** 4.0 × 119,750 / 239,566 / ln 2 = 4.0 × 0.72115 ≈ 2.8846 bits/byte。

**13.13** s = 0：3×10⁻³ × 1/6 = 5×10⁻⁴；s = 5：3×10⁻³；s = 6：p = 0，3×10⁻³；s = 30：p = 24/54 = 0.4444，cos(0.4444π) = cos 80° = 0.1736，lr = 3×10⁻⁴ + 2.7×10⁻³ × 0.5868 = 1.8844×10⁻³；s = 59：p = 53/54，cos(0.9815π) = −0.9983，lr ≈ 3×10⁻⁴ + 2.7×10⁻³ × 0.00085 ≈ 3.02×10⁻⁴。

**13.14** 错误：索引步 0，5×10⁻⁴。正确：索引步 30，约 1.88×10⁻³。错误序列是 5×10⁻⁴、1×10⁻³、1.5×10⁻³、2×10⁻³……，正确序列约 1.88、1.81、1.73、1.65……×10⁻³（逐渐下降）。续训后第 4 次更新时错误值 2×10⁻³ 第一次超过正确值（约 1.65×10⁻³）。和第 3 部分的表一致（那里保留四位小数）。

**13.15** |Δθ|/lr = |g|/(|g| + ε)：g = 1 时约 1；10⁻⁴ 时 0.9999；10⁻⁸ 时 0.5；10⁻¹⁰ 时约 0.0099。梯度很小的坐标被 ε "压住"，所以平均比值略小于 1；loss 乘以 100 后所有梯度乘以 100，ε 的影响缩小 100 倍，比值变成 1.0000。

**13.16** D = 20 × 7,004,928 = 140,098,560。6ND = 6 × 7,004,928 × 140,098,560 ≈ 5.888×10¹⁵ FLOPs。约 117.8 个 epoch。这说明在 20000 条的训练集上按"20 倍"训 xl，会重复读一百多遍；要么扩大训练集，要么接受过拟合风险。

**13.17** tiny：2 × 32 × 64 / 251,328 ≈ 1.6%。xl：8 × 128 × 256 / 7,004,928 ≈ 3.7%。

**13.18** d log L / d log C = −α·aC^(−α)/L。C = 10²：aC^(−α) = 25 × 10^(−0.6) = 6.280，L = 7.780，斜率 ≈ −0.242。C = 10⁸：aC^(−α) = 25 × 10^(−2.4) = 0.0995，L = 1.5995，斜率 ≈ −0.0187。局部斜率从 −0.24 变到 −0.02，曲线越来越平；直线拟合取的是一个"平均斜率"，远小于真正的 α = 0.3。

**13.19** G = (αA/(βB))^{1/(α+β)} = 2^{1/0.75} = 2^{4/3} ≈ 2.520。a = 0.25/0.75 = 1/3。C/6 = 10¹²，(10¹²)^{1/3} = 10⁴。N_opt ≈ 25,198；D_opt = 10¹²/25,198 ≈ 3.969×10⁷；D/N ≈ 1575。6 × 25,198 × 3.969×10⁷ ≈ 6.0×10¹² = C。

**13.20** Kaplan：N × 10^{0.73} ≈ 5.37 倍，D × 10^{0.27} ≈ 1.86 倍。Chinchilla：N、D 各 × 10^{0.5} ≈ 3.16 倍。

**13.21** p̂ = 0，n = 50，z² = 3.8416。中心 = (0 + 3.8416/100)/(1 + 3.8416/50) = 0.038416/1.076832 ≈ 0.0357；半宽 = 1.96 × √(3.8416/10000)/1.076832 ≈ 0.0357。区间 [0, 0.0714]（代码用更精确的 z = 1.95996，得到 0.0713）。普通公式给出 [0, 0]，好像我们确定比例是 0，显然不合理；Wilson 区间承认 50 条样本下真实比例仍可能到 7% 左右。

**练习 13.1** 注意三点：分母是验证目标数（内容 token + EOS），不含 BOS；平滑的 V 要去掉 BOS 类别；bits/byte 的字节数只用对应的 2000 条原文。

**练习 13.2** 斜率 = Σ(u − ū)(v − v̄)/Σ(u − ū)²，α = −斜率，a = exp(v̄ − 斜率·ū)。

**练习 13.3** 网格要覆盖最优点两侧几个数量级；相对误差来自网格间距。加密网格时误差的上界变小，但具体误差不保证单调（新网格不一定包含旧网格的点）。

**13.22** (a) 峰值学习率太大，参数在噪声地板之上来回跳。(b) 裁剪只限制每步梯度的长度，而 Adam 的更新步长主要由学习率决定（自适应归一化后每个坐标约 lr 量级）；范数长期远高于阈值说明一直在裁剪，裁剪救不了步长，学习率偏大是首要怀疑对象（还要用对照确认）。(c) 用两三个更小的峰值学习率各跑几百步短训练，比较 loss 和梯度范数；第 10 部分就是这种对比的缩小版。

**13.23** (a) 随机打乱按原串划分，规范化后相同的公式会同时出现在训练和验证里（第 12 章：约一成验证公式泄漏）；越训越会背，验证 loss 越"好"。(b) 用 `pretrain.leakage_overlap`（或 `normalization_key` 求交集）检查规范键交集；标准划分应为 0。(c) 改用 `standard_split`：先按规范键分组，再整组划分。

**13.24** (a) 续训时步数没有恢复，调度从头 warmup，在训练后期把学习率重新冲到峰值。(b) 检查点保存步数，续训从保存的步数之后继续；配置不一致时拒绝续训。(c) 很可能是续训时改了总步数（例如从 5000 改成更大的数），余弦曲线被拉长，同一步的学习率变高。

**13.25** 先看最后一个点的 `eval_formulas`：周期验证用前 200 条，最终验证用 2000 条，分母和难度分布都不同。要判断衰减的效果，比较同一口径的点，或者用阶梯实验里不同 frac 的终点。

**13.26** 小模型的点来自余弦调度的中途（学习率还很高），loss 被系统性高估，计算量前沿和由它得到的最优分配都会有偏差；他的"优先加大模型"结论没有可靠依据。Hoffmann et al.（2022）认为调度长度不随训练 token 数调整，是他们与 Kaplan et al.（2020）结论不同的原因之一。应该为每个预算单独设置完整的调度（本章 `--ladder-fracs`）。

**13.27** 见 `miniocr/train/optim.py` 的 `warmup_cosine`；关键是 progress 的分母 max(1, total − warmup)，以及 step ≥ total 时返回 min_lr。

**13.28** m₁ = (1 − β₁)g，v₁ = (1 − β₂)g²；m̂₁ = g，v̂₁ = g²；Δθ = −lr·g/(|g| + ε) ≈ −lr·sign(g)（|g| ≫ ε 时）。

**13.29** 前向：每个输出分量 d_in 次乘加，共 2P。反向：对输入的梯度是一次同样大小的矩阵乘法（2P），对权重的梯度是外积并在 token 上累加（2P）。输出层每个 token 都要做 d × V 的矩阵乘法，共享权重也要算；输入嵌入是查表，没有乘法。

**13.30** 见 13.8.3 节。a + b = β/(α+β) + α/(α+β) = 1，来自 N·D = C/6：两个量的对数之和固定，增长率之和必须是 1。
