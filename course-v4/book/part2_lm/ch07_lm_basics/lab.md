## 0. 准备

在仓库根目录进入课程目录，使用已有环境：

```bash
cd course-v4

CUDA_VISIBLE_DEVICES="" python -m pytest -q book/part2_lm/ch07_lm_basics
```

模块名后可以写部分号，只运行对应实验。相关部分会自动准备依赖，例如单独运行换算部分也会训练需要的模型。进程内复用数据和模型；每次新进程都重新训练 BPE 和模型，不读旧权重。

脚本始终在 CPU 上计算，只读取本地 LaTeX 缓存，不联网、不下载。没有缓存时使用内置公式，并打印降级提示。也可以用 `--small --steps 20` 快速检查流程；小样例不能支持真实效果结论。`--threads` 可以调整 CPU 线程数，默认值见下方实测配置。

输出目录是 `outputs/book/ch07/`：

- `mlp_loss.png`：各窗口 MLP 的训练损失和固定验证子集损失。
- `metrics.json`：本次参数、计数模型的平滑选择、MLP 最终指标、训练记录和总用时。

同名文件会被覆盖。比较不同实验时，保留终端日志并另存图片和指标文件。本章不保存语料或训练权重。

### 数据和评测口径

沿用第 6 章的 `latex-v1` 标准划分。规范化相同的公式在同一个集合。只用训练集学习模型和 BPE，只用验证集选平滑参数和做诊断，不评测测试集。正式实验用固定验证集的前缀，实际条数见原始输出。

每条公式单独补边界。预测首 token 时，固定窗口左边补满 BOS；最后预测一次 EOS。BOS 只提供条件，不属于输出类别；因此加 k 平滑的分母是 `上文计数 + k × (词表大小−1)`。计数模型和 MLP 都采用这个口径。玩具矩阵中的 BOS 列恒为零。

所有最终 loss 都是“各位置 NLL 的总和 / 预测目标总数”，不按公式等权平均。预测目标包括 EOS，但原文 UTF-8 字节数不包括任何特殊符号。bits/byte 使用这一组目标数和字节数。第 6 章的 unigram 演示没有加入 EOS，所以不要把两个章节的数字当作同口径直接比较。

中途的 MLP 验证曲线采用固定种子的验证目标子集，最终指标则完整遍历本章验证公式。训练损失是两次打印之间各批 loss 的平均。已有 `get_batch`、`eval_loss` 面向整段 GPT 目标；这里用独立公式的固定窗口与单目标评测，避免跨公式取上文和漏掉首 token。单位换算复用了 `miniocr.train.lm.bits_per_byte`。

采样使用固定种子、温度为一、不截断候选，遇 EOS 停止，到长度上限截断。花括号配平只检查未转义 `{}` 的前缀深度和最终深度，空串也算配平；它不是语法正确率，更不是公式语义正确率。采样可能包含无效 UTF-8，解码时显示替换字符。

### 怎样读这些结果

计数模型随阶数增加，在训练集上越来越好，验证集却在 bigram 后变差。这不是“更长上文一定没用”。这里没有回退或插值；未见上文只能给均匀概率，低频上文的加 k 平滑也会摊薄概率。每个阶数都独立在同一组候选 k 中选最佳值，不保证任何数据上的训练损失都严格单调。

MLP 共享嵌入和隐藏层，不必给每个完整上文单独存一张计数表。但训练步数、优化和参数量仍会影响结果。这里只是一个预算有限的基线，不能把一次运行当成架构优劣的普遍结论。loss 改善也不意味着生成公式的括号或语法已经正确。

### 远距离诊断的边界

脚本在完整验证公式上编码，按 UTF-8 字节偏移定位成对的 `\left(` 和 `\right)`，用栈处理嵌套的 `\left/\right`。命令名后必须不是英文字母，避免将 `\leftarrow`、`\rightarrow`、`\leftrightarrow` 等命令误作括号命令。只保留 `right` 字母恰好构成一个完整 token 的位置，不重新编码截断的前缀。切成多个 token 的目标会被排除；本次纳入数见输出，诊断不是全体公式的无偏估计。

距离定义为“左圆括号所在 token 和 right 目标之间的 token 数”。如果距离为 d，模型至少需要 d+1 个上文位置才看得到左圆括号；还需要更长窗口才能看到前面的完整 left 命令。分桶边界是描述性分组，不是精确的可见性分界。

不同距离的局部语法与出现频率不同，所以某个模型在远距离桶里概率高，并不能证明它记得左括号。脚本还取一个窗口外配对，只替换远处左圆括号所在的 token，保持临近目标的 token 完全相同。模型给出的概率不变，这是固定窗口看不到远处信息的直接展示。该控制是在 token 序列上做的结构演示，替换后的序列不保证是合法 LaTeX。

### RNN 演示的边界

顺序演示使用随机输入。梯度演示则特意使用零输入、零初态和按谱半径缩放的随机正交矩阵，让 tanh 保持在线性点，便于看到梯度连乘的消失、保持和爆炸。输出额外给出梯度范数的常用对数，避免很小的数被四位小数舍入成零后无法区分。

真实非零输入会使 tanh 饱和，所以谱半径大于一不保证梯度爆炸。计时里的并行操作只是一次各位置投影，不是完整注意力；两者计算量与功能不同。这部分只建立直觉，不训练 RNN，也不据此宣布任何架构的速度比。

## 3. 实验一：窗口从短变长

**预测：** 只看很短上文时，哪些局部结构还能猜中？窗口变长，验证 loss 会一直下降吗？参数量和计算量会怎样变化？先写预测，尤其说明窗口外的配对信息能否进入模型。

**运行：**

```bash
CUDA_VISIBLE_DEVICES="" python -m book.part2_lm.ch07_lm_basics.tour 6 7 --contexts 1 3 8 16
```

保持训练步数、嵌入维度、隐藏层维度、数据、BPE 和采样设置相同。默认随机种子固定；模型初始化使用“种子加窗口长度”，批次抽样使用同一个种子。窗口不同会改变模型参数形状；同一随机种子并不等于逐个参数初始化相同。

**观察：** 对照全量验证指标、参数量、配平比例和曲线。诊断部分固定比较 bigram 与两种默认 MLP 窗口，不会自动对全部新增窗口做分桶。辨别“窗口变长提供了新信息”和“参数量同时增加”这两个变化。

**记录：** 填写记录表，保存曲线。写出收益从哪里开始变小，哪些信息仍在最大窗口之外。如果想判断优化是否充分，可单独增加步数并记录为第二组实验。

## 4. 实验二：嵌入与隐藏层大小

**预测：** 更大的嵌入是否有助于共享 token 的相似性？更大的隐藏层会怎样影响训练与验证差距？固定步数是否对更大模型公平？

**运行：**

## 5. 实验三：训练公式的数量

**预测：** 数据变多，计数模型与共享参数的 MLP 谁受益更明显？如果训练步数固定，更多数据是否一定更好？

**运行：**

```bash

CUDA_VISIBLE_DEVICES="" python -m book.part2_lm.ch07_lm_basics.tour 4 6 --n-train 20000
```

两次都在标准训练集同一前缀上重新训练 BPE，BPE 使用的条数保持默认预算，只改变语言模型读取的训练前缀。较小模型训练集以外的 BPE 训练文本仍属于训练划分，绝不来自验证或测试集。这样控制了分词器变量；本实验研究的是“语言模型数据量”，不是“整个流程只获得这么多文本”。

验证集前缀、哈希划分种子和数据快照必须保持不变。bigram 会读完给定训练集；MLP 固定步数随机抽取目标，增加语料也会减少平均重复暴露次数。如果还想比较充分训练的效果，要把增加步数作为另一个实验，并记录计算预算。

**观察：** 比较 bigram 与 MLP 的全量验证 nat/token 和 bits/byte；看训练与验证差距有没有缩小。不要把更大数据集上的未收敛误认为模型不会从数据中受益。

**记录：** 保留两组实验的 BPE 训练条数、模型训练条数、验证目标数和字节数，检查比较口径是否一致。写清观察是固定步数下的结果。

## 6. 故障演练：把输入本身当答案

**预测：** 如果目标不向后错一位，训练 loss 能否很快接近零？这种模型能否预测真正的下一个 token？忘掉 EOS 后，什么机制还能让采样停止？

**运行：**

```bash
CUDA_VISIBLE_DEVICES="" python -m book.part2_lm.ch07_lm_basics.tour 2 10
CUDA_VISIBLE_DEVICES="" python -m pytest -q book/part2_lm/ch07_lm_basics
```

错误目标演示只在固定小批次上训练，令目标等于上下文最后一个 token；随后在正确错位的全量验证目标上评测，并打印采样。不要把它的低训练 loss 当成正确任务的成绩。

忘记 EOS 的对照使用明确打印的玩具循环和零平滑，隔离“训练时没有终止目标”这个原因。两种设定除了是否添加 EOS 之外相同；没有 EOS 时只能靠最大长度截断。它不是本章 LaTeX 模型的实测终止率。

**观察：** 对照错误目标下的低 loss 与正确目标下的高验证 loss。再看两种分词器的 nat/token 与 bits/byte：词表和 token 长度不同，不能拿每 token 的 loss 直接判输赢。最后找出零平滑时让验证 loss 变成无穷的原因。

**记录：** 贴上错误训练、正确验证、终止率和跨分词器指标的关键行。手写一个输入与目标错位样本。修复原则是统一训练与评测任务、显式预测 EOS、使用同口径单位，并处理未见事件；参考代码中的故障演示是有意保留的，无需删除。
