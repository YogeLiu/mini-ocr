# 第 7 章 语言模型基础

> 语言模型只做一件事：猜下一个 token。这一章看清楚这件事本身，再看几种简单做法为什么不够好。

## 本章导读

上一章我们把公式变成了一串整数。这一章要回答：**拿到这串整数以后，模型到底在学什么？**

答案只有一句话：**给定前面的 token，预测下一个 token 的概率分布。** 这就是"语言模型"（language model）。GPT、Qwen 这些大模型，训练时做的也是这一件事。

在写 Transformer 之前，我们先用两种简单的方法做语言模型：数数（n-gram），然后用一个小神经网络（固定窗口的 MLP）。它们的成绩是后面衡量 GPT 用的**基线**，它们各自的毛病则说明了为什么需要注意力。

**学完这一章，你能做到：**

1. 用链式法则把一条公式的概率写成逐个 token 的条件概率之积，并算出它的对数概率（7.1 节）。
2. 说清"输入和目标错开一位"是什么意思，写出构造训练样本的代码（7.2 节，练习 7.1）。
3. 实现一个二元（bigram）语言模型，并计算它的困惑度（7.3 到 7.4 节，练习 7.2、7.3）。
4. 解释 n-gram 为什么记不住远处的上下文，以及 n 变大为什么反而更差（7.5 节）。
5. 写出固定窗口的 MLP 语言模型，说出它比 n-gram 强在哪里、又被什么限制（7.6 到 7.7 节，练习 7.4）。
6. 换算困惑度、nat/token、bits/token 和 bits/byte（7.8 节）。
7. 说清 RNN 怎样逐步记住前文，以及它为什么难以并行、容易遗忘（7.9 节，只讲直觉）。

**本章是中等级别。** 重点是错位构造样本和困惑度；RNN 和 LSTM 只讲直觉，用来引出第 8 章的注意力。

## 7.1 链式法则：一条公式的概率

### 7.1.1 从整条到逐个

语言模型想要的，是一条公式（一个 token 序列）的概率：

$$P(x_1, x_2, \ldots, x_T)$$

直接估计这个联合概率是做不到的。公式的组合千变万化，几乎每条都是新的，你没法数一数它出现了几次。

概率论里的**链式法则**给了一个出路：任何联合概率都可以拆成一串条件概率的乘积。

$$P(x_1, \ldots, x_T) = P(x_1) \cdot P(x_2 \mid x_1) \cdot P(x_3 \mid x_1, x_2) \cdots P(x_T \mid x_1, \ldots, x_{T-1})$$

用连乘符号写：

$$P(x_1, \ldots, x_T) = \prod_{t=1}^{T} P(x_t \mid x_{<t})$$

其中 $x_{<t}$ 表示第 $t$ 个之前的所有 token，也就是 $x_1, \ldots, x_{t-1}$。$t = 1$ 时它是空的，7.1.2 节会给它补一个开头。

这条公式来自条件概率的定义。把回顾框里的 $P(B \mid A) = P(A, B) / P(A)$ 两边乘以 $P(A)$，得到 $P(A, B) = P(A) \cdot P(B \mid A)$：联合概率等于先发生 A 的概率，乘以已知 A 时再发生 B 的概率。以 $T = 3$ 为例，先把 $x_1, x_2$ 当作 A、$x_3$ 当作 B，再对 $P(x_1, x_2)$ 用一次同样的拆法：

$$P(x_1, x_2, x_3) = P(x_1, x_2) \cdot P(x_3 \mid x_1, x_2) = P(x_1) \cdot P(x_2 \mid x_1) \cdot P(x_3 \mid x_1, x_2)$$

更长的序列就是把这一步反复用下去。

这个分解是精确的，没有任何近似（数学结论）。它把一个看不到边的问题，变成了反复做同一件事：已知前文，猜下一个。这就像接龙游戏：不用一下子想出整句话，每次只想下一个词。

### 7.1.2 边界：`<|bos|>` 和 `<|eos|>`

链式法则有两个边界问题：

- **第一个 token 的"前文"是什么？** 我们在每条公式前面加一个 `<|bos|>`，让第一个 token 也有个可以依赖的东西。$P(x_1)$ 就变成了 $P(x_1 \mid \texttt{<|bos|>})$，意思是"一条公式以 $x_1$ 开头的概率"。
- **公式什么时候结束？** 我们在末尾加一个 `<|eos|>`，并且**要求模型预测它**。这样模型才学得会"什么时候该停"，概率才是对完整的一条公式算的，而不只是对一个开头算的。

### 7.1.3 手算一条公式

拿最简单的公式 `x^{2}` 来算。编码以后加上边界，token 序列是（本项目观察，tour 第 1 部分）：

```text
<|bos|>  x  ^{  2  }  <|eos|>
 2256   120 258 50 125  2257
```

`^{` 是第 6 章学到的合并 token。

我们用一个**二元模型**（bigram）来估计条件概率：它假设下一个 token 只取决于前一个 token。7.3 节会详细讲它怎样训练，这里用的是 7.3.4 节的加一平滑版本，先看结果。每个位置的条件概率是：

| 位置 | 上文 | 目标 | 条件概率 | 对数概率 |
|---|---|---|---|---|
| 1 | `<\|bos\|>` | `x` | 0.0091 | −4.6972 |
| 2 | `x` | `^{` | 0.0112 | −4.4934 |
| 3 | `^{` | `2` | 0.1598 | −1.8338 |
| 4 | `2` | `}` | 0.0787 | −2.5416 |
| 5 | `}` | `<\|eos\|>` | 0.0609 | −2.7983 |

（本项目观察，tour 第 1 部分）

读一读这张表：

- 位置 3：`^{` 后面跟 `2` 的概率是 0.16，相当高。上标里最常见的就是平方。
- 位置 1：公式以 `x` 开头的概率只有 0.0091。可能的开头太多了。

**整条公式的概率**是五个条件概率的乘积：

$$0.0091 \times 0.0112 \times 0.1598 \times 0.0787 \times 0.0609 \approx 7.8 \times 10^{-8}$$

一个极小的数。公式稍微长一点，概率就会小到计算机存不下（第 3 章讲过的下溢）。所以实践中我们永远用**对数概率**：乘积变成求和。

$$\ln P = -4.6972 - 4.4934 - 1.8338 - 2.5416 - 2.7983 = -16.3643$$

再取负号，除以预测的 token 数，得到**每 token 平均负对数似然**（NLL）：

$$\text{NLL} = 16.3643 / 5 = 3.2729 \text{ nat/token}$$

分母是 5，不是序列长度 6：`<|bos|>` 只当上文、不被预测，`<|eos|>` 要被预测，所以一共 5 个预测目标，正好是表里的 5 行。

它和第 3 章的交叉熵 loss 是同一个量：每个位置都是一个"在 2257 个候选里选对一个"的分类问题，loss 是正确答案概率的负对数，最后取平均。所以语言模型的训练，就是在所有位置上做分类、最小化平均交叉熵。

> **停下来想一想：** 为什么"可预测的类别数"是 2257，而不是词表大小 2258？（提示：哪个 token 永远不会作为预测目标？）

### 7.1.4 困惑度

NLL 的单位是 nat，不太直观。另一个常用的指标是**困惑度**（perplexity）：

$$\text{PPL} = e^{\text{NLL}}$$

上面这条公式的困惑度是 $e^{3.2729} = 26.39$（本项目观察，tour 第 1 部分）。

困惑度可以这样理解：它相当于模型在每一步平均在多少个候选里犹豫。

举个例子。如果模型每一步都给正确答案 1/26 的概率，NLL 就是 $-\ln(1/26) = \ln 26$，困惑度 $e^{\ln 26}$ 正好是 26，就像在 26 个等可能的选项里瞎猜。所以困惑度 26 的意思是：模型的不确定程度，相当于每步在 26 个选项里均匀地猜。

把 NLL 的定义代进去，还能得到一个等价写法。$T$ 个预测目标的整条概率是 $P$ 时，$\text{NLL} = -\ln P / T$，所以

$$\text{PPL} = e^{-\ln P / T} = \left(\frac{1}{P}\right)^{1/T}$$

也就是每一步给正确答案的概率，取倒数以后的几何平均。用上面那条公式核对：$\bigl(1 / (7.8 \times 10^{-8})\bigr)^{1/5} \approx 26.4$，和 26.39 对得上（数学结论，差别来自 $7.8 \times 10^{-8}$ 的舍入）。

困惑度越低越好。最低是 1（每步都 100% 确定且正确）。一个完全不懂的模型，对 2257 个候选均匀猜测，困惑度就是 2257。均匀猜测并不是最差的情况：一个模型如果总是很自信地猜错，困惑度可以比 2257 还高，7.10 节就有这样的例子。

## 7.2 错开一位：怎样构造训练样本

### 7.2.1 一条公式，很多个样本

链式法则告诉我们，一条长度为 $T$ 的序列，包含了 $T$ 个"已知前文，猜下一个"的问题。所以训练时，一条公式能拆出很多个训练样本。

看第 6 章那条公式（本项目观察，tour 第 2 部分）：

```text
原文:      \frac{a+b}{\sqrt{x^2+1}}
token id: [2256, 92, 268, 123, 97, 43, 98, 325, 407, 123, 120, 94, 50, 43, 49, 291, 2257]
```

把它变成样本有两种常见的方式。

### 7.2.2 方式一：整段错位（GPT 用的方式）

取一段长度为 $T$ 的窗口当输入 $X$，把**同一段往后挪一位**当目标 $Y$：

```text
X = ids[i   : i+T]
Y = ids[i+1 : i+T+1]
```

$T = 8$ 时，第一个样本是：

```text
X = [2256, 92, 268, 123, 97, 43, 98, 325]
Y = [  92, 268, 123, 97, 43, 98, 325, 407]
```

$X$ 和 $Y$ 逐位对齐：$X$ 的第 1 个位置（`<|bos|>`）对应的目标是 $Y$ 的第 1 个位置（`92`，也就是 `\`）；$X$ 的第 2 个位置对应的目标是 `268`（`frac`）……

模型在第 $t$ 个位置做预测时，**只能看 $X$ 的前 $t$ 个 token**。这样，一个长度为 8 的窗口就同时提供了 8 个训练样本：

| 位置 | 能看到的输入 | 要预测的目标 |
|---|---|---|
| 1 | `2256` | `92` |
| 2 | `2256, 92` | `268` |
| 3 | `2256, 92, 268` | `123` |
| …… | …… | …… |
| 8 | 前 8 个 | `407` |

"只能看前 $t$ 个"靠的是第 8 章要讲的因果 mask。整段错位加上因果 mask，是 GPT 训练效率高的一个重要原因：一次前向就得到 $T$ 个位置的 loss。

### 7.2.3 方式二：固定窗口

n-gram 和本章的 MLP 模型，每次只看最近的固定 `context` 个 token。样本是"前 `context` 个 token → 下一个 token"。

`context = 3` 时，前 5 个样本是（本项目观察，tour 第 2 部分）：

| 样本 | 上下文 | 目标 |
|---|---|---|
| 1 | `[2256, 2256, 2256]` | `92` |
| 2 | `[2256, 2256, 92]` | `268` |
| 3 | `[2256, 92, 268]` | `123` |
| 4 | `[92, 268, 123]` | `97` |
| 5 | `[268, 123, 97]` | `43` |

开头不够 3 个 token 怎么办？用 `<|bos|>` 在左边补齐。补进去的 `<|bos|>` 只当上文，不当目标。另外，**每条公式单独处理，公式之间不拼接**，否则模型会把上一条公式的结尾当成下一条的上文。

### 7.2.4 代码

整段错位（练习 7.1 的一部分），参考实现在 `miniocr/models/ngram.py`：

```python
def make_examples(ids, context):
    ids = torch.as_tensor(ids, dtype=torch.long)
    if len(ids) <= context:                              # 不够一个样本
        return ids.new_empty((0, context)), ids.new_empty((0, context))
    windows = ids.unfold(0, context + 1, 1)              # 每个窗口长 context+1
    return windows[:, :-1].clone(), windows[:, 1:].clone()
```

这里的 `context` 就是 7.2.2 节的窗口长度 $T$。`unfold(0, context + 1, 1)` 沿第 0 维、以步长 1 取出所有长度为 `context + 1` 的窗口，形状是 `(样本数, context + 1)`。每个窗口去掉最后一个就是 $X$，去掉第一个就是 $Y$，正好错开一位。

固定窗口的版本 `make_window_examples` 直接复用它，只保留 $Y$ 的最后一列：`return x, y[:, -1]`。它不会自动补 `<|bos|>`，调用方要先在每条公式前面补上 `context` 个 `<|bos|>`。

代码很短，却很容易写错。7.10 节会看到：如果目标没有错开（$Y = X$），模型会学会"抄当前输入"，训练 loss 几乎降到 0，但它什么也没学会。

## 7.3 bigram：最简单的语言模型

### 7.3.1 马尔可夫假设

链式法则里，第 $t$ 个 token 的条件概率要依赖前面**所有**的 token。这太多了。最简单的近似是假设：**下一个 token 只取决于前一个 token。**

$$P(x_t \mid x_1, \ldots, x_{t-1}) \approx P(x_t \mid x_{t-1})$$

这叫**马尔可夫假设**（Markov assumption），用这个假设的模型叫**二元模型**（bigram），因为它只看"两个一组"的 token。

类比：这就像一个记性极差的人接龙，他只记得别人刚说的最后一个词。

### 7.3.2 怎样估计：数数

二元模型的条件概率，可以直接从训练数据里数出来：

$$P(b \mid a) = \frac{\text{count}(a, b)}{\text{count}(a)}$$

意思是：在所有 `a` 出现的地方，后面紧跟着 `b` 的比例。分母 $\text{count}(a)$ 数的是 `a` 当上文的次数，也就是 `a` 后面还跟着一个 token 的次数。这就是**最大似然估计**（数学结论：在训练集上，这个估计让数据的似然最大）。

### 7.3.3 手算：一个玩具例子

用一个只有两种内容 token（`0` 和 `1`）的玩具语料，三条序列（本项目观察，tour 第 3 部分）：

```text
序列 1:  0 1 0 1 1 0
序列 2:  1 0 1 1 0
序列 3:  0 1 1 0 1 0
```

每条前面加 BOS、后面加 EOS。数所有相邻对，得到**计数矩阵**（行是上文，列是下一个 token）：

| 上文 ↓ \ 下一个 → | `0` | `1` | BOS | EOS |
|---|---|---|---|---|
| `0` | 0 | 5 | 0 | 3 |
| `1` | 6 | 3 | 0 | 0 |
| BOS | 2 | 1 | 0 | 0 |
| EOS | 0 | 0 | 0 | 0 |

自己验证几个格子：
- BOS 行：三条序列分别以 `0`、`1`、`0` 开头，所以 BOS→0 是 2 次，BOS→1 是 1 次。
- `0` → EOS：三条序列都以 `0` 结尾，所以是 3 次。
- BOS 列全是 0：BOS 永远不会作为"下一个"出现。
- EOS 行也全是 0：EOS 后面没有东西，它从不当上文，所以下面的概率表里没有这一行。

每行除以行和，得到**条件概率矩阵**：

| 上文 | P(`0`) | P(`1`) | P(BOS) | P(EOS) |
|---|---|---|---|---|
| `0` | 0.0000 | 0.6250 | 0.0000 | 0.3750 |
| `1` | 0.6667 | 0.3333 | 0.0000 | 0.0000 |
| BOS | 0.6667 | 0.3333 | 0.0000 | 0.0000 |

比如 `0` 行：`0` 一共做了 8 次上文（5 + 3），后面跟 `1` 的有 5 次，所以 P(`1` | `0`) = 5/8 = 0.625。

### 7.3.4 零概率问题和平滑

注意 `0` 行的第一格：P(`0` | `0`) = 0。训练语料里从没出现过 `0 0`。

现在假设验证集里有一条序列包含 `0 0`。模型给它的概率是 0，对数概率是 $-\infty$，loss 是**无穷大**（本项目观察，tour 第 3 部分：未见相邻对 `(0, 0)` 的 loss = inf）。一个位置的 loss 无穷大，整个验证集的平均 loss 也是无穷大。

没在训练集里见过，不等于不可能。最简单的补救叫**加 k 平滑**：给每个计数都加上一个小数 $k$。

$$P(b \mid a) = \frac{\text{count}(a, b) + k}{\text{count}(a) + k \cdot V}$$

其中 $V$ 是可预测的类别数。分母加 $kV$ 是为了让每行的概率和仍然是 1（数学结论：分子一共多加了 $V$ 个 $k$）。

$k = 1$ 时叫**加一平滑**（也叫拉普拉斯平滑）。玩具例子里可预测的类别是 `0`、`1`、EOS 三个（BOS 不会被预测），所以 $V = 3$。`0` 行变成：

$$P(\texttt{0} \mid \texttt{0}) = \frac{0 + 1}{8 + 3} = \frac{1}{11} = 0.0909$$

$$P(\texttt{1} \mid \texttt{0}) = \frac{5 + 1}{11} = 0.5455, \qquad P(\text{EOS} \mid \texttt{0}) = \frac{3 + 1}{11} = 0.3636$$

和 tour 第 3 部分的输出一致。现在 `0 0` 的 loss 是 $-\ln(1/11) = 2.3979$，有限了。

平滑的代价是：从常见的组合那里借走一点概率，分给没见过的组合。$k$ 越大，借得越多。$k$ 取多少合适？这是一个超参数，要在**验证集**上选。

现在回到 7.1.3 节，验算位置 1 的数字：在训练集里，`<|bos|>` 一共出现 20,000 次（每条公式一次），后面跟 `x` 的有 202 次，可预测类别有 2257 个，$k = 1$：

$$P(x \mid \texttt{<|bos|>}) = \frac{202 + 1}{20000 + 2257} = \frac{203}{22257} = 0.0091$$

## 7.4 bigram 在 LaTeX 上

### 7.4.1 选平滑参数

在训练集 2 万条公式上训练 bigram，平滑参数 $k$ 取四个值，在验证集上比较（本项目观察，tour 第 4 部分）：

| $k$ | 验证 nat/token | 验证困惑度 | 验证 bits/byte |
|---|---|---|---|
| 1 | 4.3596 | 78.22 | 3.1439 |
| 0.1 | 4.0285 | 56.18 | 2.9051 |
| **0.01** | **4.0132** | **55.33** | **2.8941** |
| 0.001 | 4.0990 | 60.28 | 2.9560 |

$k = 0.01$ 最好。加一平滑（$k = 1$）明显太大了：词表有两千多个类别，每个上文都给全部 2257 个类别各加 1，相当于凭空多出两千多次"假观测"，常见组合的概率被稀释得厉害。$k$ 太小（0.001）也不好，没见过的组合概率太低，一旦遇到就付出很大的 loss。

和上一章的 unigram 对比一下：unigram（不看任何上文）在同样的验证集上是 5.4230 nat/token、bits/byte 3.9108（本项目观察，tour 第 4 部分）。**只多看一个 token，bits/byte 就从 3.91 降到了 2.89。**

### 7.4.2 训练集和验证集的差距

最好的 bigram 在训练集上是 3.7078 nat/token，在验证集上是 4.0132（本项目观察，tour 第 4 部分）。训练集更低，这是正常的：模型的计数就是从训练集来的，对训练集更熟。差距 0.3 说明已经有一点过拟合。下一节会看到，模型越复杂，这个差距越夸张。

### 7.4.3 让它写几条公式

语言模型不只能打分，还能**生成**：从 `<|bos|>` 出发，按条件概率抽一个 token，把它当新的上文，再抽下一个……直到抽到 `<|eos|>`。

最好的 bigram 写出来的公式（本项目观察，tour 第 4 部分）：

```text
\hat{sgn)~.
\lim_{2}^i=1\}
\left(\vec{Re}\sum_{pe})\\&=\min\{ \rho u_j})
```

局部看有模有样：`\lim_`、`\left(\vec{`、`\sum_{` 都是真实的 LaTeX 片段。但整体是一团乱麻，括号对不上，`\hat{sgn)` 用圆括号关了一个花括号。

统计 200 条采样，**花括号 `{}` 配平的只有 11%**，而真实验证公式是 100%（本项目观察，tour 第 4 部分）。原因在于 bigram 只记得前一个 token，它根本不知道前面开了几个括号。

> 花括号配平只是一个粗略的检查，配平了不代表公式合法，但没配平一定不合法。第 13 章会介绍更严格的"可编译率"。

## 7.5 n 变大，为什么反而更差

### 7.5.1 自然的想法：多看几个

bigram 只看 1 个 token 太短了。那就多看几个：三元模型（trigram）看前 2 个，四元模型看前 3 个。一般地，**n 元模型看前 n−1 个 token。**

$$P(x_t \mid x_{<t}) \approx P(x_t \mid x_{t-n+1}, \ldots, x_{t-1})$$

估计方法不变，还是数数加平滑。开头不够 $n-1$ 个 token 时，和 7.2.3 节一样用 `<|bos|>` 在左边补齐。

### 7.5.2 实测：越看越差

n 从 1 到 4，每个都在验证集上选最好的 $k$（本项目观察，tour 第 5 部分）：

| n | 最佳 $k$ | 训练 nat/token | 验证 nat/token | 验证困惑度 | 验证中"上文没见过"的比例 | 不同上文种数 |
|---|---|---|---|---|---|---|
| 1 | 0.1 | 5.4257 | 5.4230 | 226.57 | 0.0000 | 1 |
| 2 | 0.01 | 3.7078 | **4.0132** | **55.33** | 0.0000 | 2,030 |
| 3 | 0.01 | 2.9964 | 4.5116 | 91.07 | 0.0479 | 91,758 |
| 4 | 0.01 | 2.7767 | 5.7148 | 303.32 | 0.2757 | 356,113 |

从这张表里能读出四点：

- **训练集上，n 越大越好**：从 5.43 一路降到 2.78。看得越多，对训练数据记得越牢。
- **验证集上，n = 2 最好**。n = 3 变差，n = 4 差得更多，甚至不如 unigram。
- **"上文没见过"的比例飞涨**：n = 3 时，验证集里约 5% 的位置，它的前 2 个 token 组合在训练集里从未出现；n = 4 时这个比例超过了 27%。
- **不同上文的种数爆炸**：bigram 只有 2030 种上文，四元模型有 35 万种。

这就是第 5 章讲过的**过拟合**，而且是一种特别典型的形式，叫**数据稀疏**（data sparsity）。上文每多一个 token，可能的组合就乘以词表大小（约两千）。2 万条公式根本覆盖不了这么多组合。大部分四元组在训练集里只出现一两次，甚至一次都没有；对没见过的上文，模型只能退化成均匀猜测：这时 $\text{count}(a) = 0$，每个计数也都是 0，加 k 平滑的公式给出 $(0 + k) / (0 + kV) = 1/V$，每个类别一样大。

一个类比：你想通过"前三个字"来猜下一个字。如果你只读过一本书，大部分"三字组合"你都没见过，遇到就只能瞎猜。只看前一个字反而更靠谱，因为每个字你都见过很多次。

> **说明：** 这里的 n-gram 没有用任何高级技巧。真实的 n-gram 系统会用**回退**（backoff，没见过三元组就退回去用二元）和**插值**（interpolation，把几种 n 的预测加权混合），效果好得多。我们故意不用，是为了让稀疏问题暴露出来。

### 7.5.3 n-gram 的根本问题

数据稀疏背后，有一个更根本的问题：n-gram 不会"举一反三"。

在 n-gram 看来，上文 `\alpha +` 和 `\beta +` 是两个毫不相干的组合，各数各的。即使模型见过一千次 `\alpha + 1`，它对 `\beta + 1` 也一无所知。可是人一眼就能看出 `\alpha` 和 `\beta` 很像，都是希腊字母、都当变量用。

要让模型"举一反三"，需要一种表示方式，让相似的 token 有相似的表示。下一节的神经网络就做这件事。

## 7.6 固定窗口的 MLP 语言模型

### 7.6.1 思路：用向量代替计数

2003 年，Bengio 等人提出了一个想法：**给每个 token 一个可学习的向量（嵌入），再用神经网络从上文的向量预测下一个 token。**

结构很简单（练习 7.4）：

```text
上文 3 个 token id        [92, 268, 123]
        │  查嵌入表（每个 token → 64 维向量）
        ▼
3 个向量拼成一个 192 维向量
        │  线性层 + tanh（隐藏层 256 维）
        ▼
        │  线性层
        ▼
2258 维的 logits  →  屏蔽 BOS  →  softmax  →  下一个 token 的概率
```

嵌入（embedding）第一次出现，先说清它是什么。嵌入表是一个参数矩阵，行数是词表大小，列数是嵌入维度，这里是 $2258 \times 64$，第 $i$ 行就是 token $i$ 的向量。查嵌入表就是按 token id 取出对应的那一行，效果和用 one-hot 向量乘这个矩阵一样，但不用真的做乘法。这些向量一开始是随机的，和其他权重一起靠梯度下降学出来。

图里有一步容易漏：**屏蔽 BOS**。输出层有 2258 维，对应完整词表，但 BOS 永远不是预测目标（7.2 节）。标签里不出现 BOS，并不会让模型自动给它零概率：softmax 总会给每一维分一点。所以参考实现在 softmax 之前把 BOS 那一维的 logit 设成 $-\infty$，这样概率只在 2257 个允许的类别上分配。

本章的实验在**训练、评测、采样三处**都遵守这个约定。训练时屏蔽、采样时忘了屏蔽，就可能采出一个 BOS；评测时不屏蔽，算出来的 loss 就和 n-gram 不在同一个口径上（n-gram 只在 $V-1 = 2257$ 个可预测类别上分配概率）。注意本节起 $V$ 指完整词表大小 2258，比 7.3.4 节加 k 平滑公式里的 $V$（可预测类别数 2257）多一个 BOS。三处都屏蔽只是本章的做法：第 11 章起，GPT 训练时不再屏蔽 BOS 这一类，评测仍然屏蔽，那一章会说明这个变化和它的影响。

用第 1 章的形状语言写，batch 大小为 $B$、上文长度为 $C$、嵌入维度为 $d$：

| 步骤 | 形状 |
|---|---|
| 输入 token id | $(B, C)$ |
| 查嵌入表 | $(B, C, d)$ |
| 拼接 | $(B, C \cdot d)$ |
| 隐藏层 | $(B, 256)$ |
| 输出 logits | $(B, V)$ |

代码只有几行：

```python
class MLPLM(nn.Module):
    def __init__(self, vocab_size, context=3, embed_dim=64, hidden_dim=256):
        super().__init__()
        self.context = context
        self.embedding = nn.Embedding(vocab_size, embed_dim)
        self.hidden = nn.Linear(context * embed_dim, hidden_dim)
        self.output = nn.Linear(hidden_dim, vocab_size)

    def forward(self, x):                               # x: (B, C)
        embedded = self.embedding(x).flatten(1)          # (B, C, d) → (B, C*d)
        return self.output(torch.tanh(self.hidden(embedded)))   # (B, V)
```

`flatten(1)` 把第 1 维以后的维度展平，就是"把 C 个向量首尾拼接"。参考实现还会检查输入形状是不是 `(B, context)`，这里省略了。

训练就是第 4 章的训练循环，loss 是第 3 章的交叉熵，算在屏蔽 BOS 之后的 logits 上。`forward` 本身只返回原始 logits，屏蔽交给调用方，tour 里由一个小函数统一处理。

### 7.6.2 为什么它能"举一反三"

靠的是嵌入。训练时，如果 `\alpha` 和 `\beta` 经常出现在相似的位置（后面都跟 `+`、`_`、`^`），梯度会把它们的嵌入向量推到相近的地方。之后，模型从 `\alpha +` 学到的规律，会自动迁移一部分到 `\beta +` 上，因为两者的输入向量很接近。

这是 n-gram 做不到的。n-gram 的表示是一个个孤立的计数格子，格子之间没有任何关系。

另一个好处：**参数量不随上文长度爆炸。** 四元 n-gram 要存 35 万种上文的计数；MLP 把上文从 3 加到 8，参数量只是从 774,226 增加到 856,146（本项目观察，tour 第 6 部分），因为只有第一个线性层的输入维度变了。可以按层手算一遍：嵌入表 $2258 \times 64 = 144{,}512$；隐藏层权重 $(C \cdot 64) \times 256$ 加 256 个偏置；输出层 $256 \times 2258 + 2258 = 580{,}306$。$C = 3$ 时隐藏层是 $192 \times 256 + 256 = 49{,}408$，三项加起来正好 774,226。$C$ 从 3 变成 8，多出来的只有 $5 \times 64 \times 256 = 81{,}920$ 个隐藏层权重，正好是两个参数量之差（数学结论）。

### 7.6.3 实测

上文长度取 3 和 8 各训练一个，嵌入 64 维、隐藏层 256 维，AdamW，学习率 3e-3，batch 256，各训练 1200 步（本项目观察，tour 第 6 部分）：

| 模型 | 参数量 | 验证 nat/token | 验证困惑度 | 验证 bits/byte |
|---|---|---|---|---|
| unigram | 不适用 | 5.4230 | 226.57 | 3.9108 |
| bigram（最好的计数模型） | 不适用 | 4.0132 | 55.33 | 2.8941 |
| MLP，上文 3 | 774,226 | 3.8710 | 47.99 | 2.7916 |
| MLP，上文 8 | 856,146 | **3.8124** | **45.26** | **2.7493** |

MLP 都超过了 bigram。**上文从 3 加到 8，MLP 继续变好**，这和 n-gram 正好相反：n-gram 多看几个就被稀疏拖垮，MLP 却能从更长的上文里得到好处。

不过，改进幅度并不大：bits/byte 从 2.89 降到 2.75。每个 MLP 在 CPU 上只训练了约 7 秒，步数很少，更多的训练应该还能更好，实验手册的实验一、二会让你调。

生成的公式也好了一点。200 条采样里，花括号配平的比例，上文 3 是 14%，上文 8 是 16%（bigram 是 11%）。还是远远不够。

这些就是本书的**基线**：上文 8 的 MLP 在验证集上 bits/byte = 2.7493。第 13 章的实验由你自己完成：你训练出的 GPT 就和这个数比，正文不提供完整训练的结果。

## 7.7 窗口外的东西，它看不到

### 7.7.1 一个诊断：`\left(` 和 `\right)`

LaTeX 里，`\left` 必须和后面的某个 `\right` 配对。右边的定界符不一定是圆括号，`\left(x\right.` 也合法（`.` 表示不可见的右定界符）。这个诊断只挑最常见的一种子集：`\left(` … `\right)`。模型走到 `\right` 的位置时，如果它"记得"前面开过一个 `\left(`，就应该给 `right` 这个 token 比较高的概率。

我们在验证集里找出 526 对能稳定定位的 `\left(` … `\right)`，按**左圆括号所在的 token** 和 `right` 这个 token 之间隔了多少个 token 分桶（只保留 `right` 恰好是一个完整 token 的位置），看三个模型在 `right` 位置给出的平均概率（本项目观察，tour 第 7 部分）：

| 间隔 | 样本数 | bigram | MLP 上文 3 | MLP 上文 8 |
|---|---|---|---|---|
| ≤ 3 | 26 | 0.0535 | 0.1895 | **0.5702** |
| 4 到 8 | 123 | 0.0945 | 0.0986 | **0.2962** |
| > 8 | 377 | 0.1111 | 0.1652 | 0.1881 |

先说清楚"看得见"的条件：间隔 $d$ 数的是两者之间夹着的 token 数，所以从 `right` 往回数，左圆括号所在的 token 是第 $d+1$ 个。模型至少要有 $d+1$ 个上文位置才看得到它；要看到前面完整的 `\left` 命令还得更长。所以上文 8 的模型，在间隔 8 时已经看不到左圆括号了，间隔 4 到 8 这一桶并不全在它的窗口里。分桶只是描述性的分组，不是精确的可见性分界。

看 MLP 上文 8 那一列：间隔 ≤ 3 时概率 0.57，间隔 4 到 8 时 0.30，间隔超过 8 时 0.19。趋势和"离得越远越看不见"是吻合的。

但这只是**吻合**，不是证明。不同间隔的公式，局部写法和出现频率本来就不一样：长括号里的内容更复杂，`\right` 前面的 token 也不同。概率下降可能有一部分来自这些差别，不能单凭分桶平均数说"就是因为左括号掉出了窗口"。要回答"模型到底用没用窗口外的信息"，需要一个更干净的**控制实验**。

### 7.7.2 控制实验：换掉窗口外的东西

取一对间隔足够远的配对，把**窗口之外**那个左圆括号所在的 token 换成别的 token，`right` 附近的 token 一个都不动，看模型在 `right` 位置的概率变了多少（本项目观察，tour 第 7 部分）：

| 模型 | 概率的变化 |
|---|---|
| bigram | 0.0000 |
| MLP，上文 3 | 0.0000 |
| MLP，上文 8 | 0.0000 |

一点都没变。这不是近似，是结构决定的：固定窗口模型的输入里根本就没有窗口外的 token，无论那里写的是什么，输出都一模一样。替换后的序列不一定是合法 LaTeX，这没关系，我们只是在 token 序列上检查模型依赖什么。

所以这个实验说明**输出不依赖窗口外的信息**，并不说明上面分桶表里的下降**全部**由此造成。

窗口开大一点可以缓解这个局限，但有两个问题：

- 窗口开到多大？公式可能有几百个 token，括号可能跨越很远。
- 窗口每开大一格，第一层的参数就增加 $d \times 256$ 个；而且每个位置都有一套**专属的**权重，第 3 个位置学到的规律，没法直接用到第 30 个位置上。

我们需要一种机制：不管多远，想看哪个位置就能直接看到，并且对每个位置用同一套规则。第 8 章的注意力就是这样的机制。

## 7.8 换算：nat、bit、困惑度和 bits/byte

到这里我们已经用过好几种指标。它们都从同一个量 nat/token 换算出来，bits/byte 还要再用上字节数。

以 MLP 上文 8 为例（本项目观察，tour 第 8 部分）：

| 指标 | 值 | 怎样从 nat/token 换算 |
|---|---|---|
| nat/token | 3.8124 | （原始量） |
| bits/token | 5.5001 | nat/token ÷ ln 2 |
| 困惑度 | 45.2579 | $e^{\text{nat/token}}$ |
| bits/byte | 2.7493 | bits/token ÷ 每 token 平均字节数 |
| 每 token 平均字节数 | 2.0006 | 字节数 ÷ token 数 |

两条换算规则各用了一步：

- **nat 换成 bit**：nat 是以 $e$ 为底的对数，bit 是以 2 为底的对数。换底公式 $\log_2 p = \ln p / \ln 2$ 说明，同一个概率的负对数，以 bit 计等于以 nat 计除以 $\ln 2 \approx 0.6931$。
- **每 token 换成每 byte**：设评测文本一共有 $N$ 个预测目标、$B$ 个字节。总 bit 数是 bits/token $\times N$，摊到每个字节上就是 bits/token $\times N / B$，也就是除以每 token 平均字节数 $B / N$。

验算一下：$3.8124 / 0.6931 = 5.500$；$5.500 / 2.0006 = 2.749$。都对得上。困惑度也可以从 bit 算：$2^{\text{bits/token}} = e^{\text{nat/token}}$，$2^{5.5001} \approx 45.26$，和表里一致（数学结论）。

**手算例子：** 一个模型 nat/token = 2.0，分词器每个 token 平均 3.0 个字节。

- bits/token = 2.0 / 0.6931 = 2.885
- bits/byte = 2.885 / 3.0 = 0.9618

（本项目观察，tour 第 8 部分的手算例子。）

什么时候用哪个？

- **同一个分词器下比较模型**：nat/token、困惑度都可以，它们是单调对应的。
- **不同分词器之间比较**：只能用 bits/byte（第 6 章 6.10 节）。7.10 节有一个反面例子。
- **和别人的论文比较**：先弄清对方用的是哪个指标、哪个分词器、哪个数据集。三者有一个不同，数字就不能直接比。

## 7.9 RNN 的直觉

> 这一节只讲直觉，不要求实现。目的是理解第 8 章的注意力为什么出现。

### 7.9.1 想法：带着记忆往前走

固定窗口的问题是"窗口外的看不到"。另一种思路是：**让模型一边读、一边把读过的东西压缩进一个"记忆"里，带着它往前走。** 这就是**循环神经网络**（RNN，recurrent neural network）。

最简单的 RNN 每一步做这样的计算：

$$h_t = \tanh(W h_{t-1} + U x_t)$$

- $x_t$ 是第 $t$ 个 token 的嵌入；
- $h_t$ 是第 $t$ 步的**隐藏状态**，就是"记忆"；
- $W$ 和 $U$ 是两个矩阵，**每一步都用同一套**。

形状上，设嵌入维度是 $d$、隐藏状态维度是 $H$：$x_t$ 是 $d$ 维向量，$h_t$ 是 $H$ 维向量，$U$ 是 $H \times d$，$W$ 是 $H \times H$。开头的 $h_0$ 一般取全零向量。

然后用 $h_t$ 预测下一个 token，做法和 MLP 的输出层一样：一个线性层把 $h_t$ 映射成词表大小的 logits。理论上，$h_t$ 依赖 $h_{t-1}$，$h_{t-1}$ 又依赖 $h_{t-2}$……所以从开头到现在的每个 token 都能影响 $h_t$，没有窗口限制。不过 $h_t$ 只是一个 $H$ 维向量，前文的信息是压缩进去的，不可能原样全部保留。

类比：读一本小说，你不会记住每一个字，而是在脑子里维护一个"剧情摘要"，每读一句就更新一下摘要。

### 7.9.2 问题一：只能一步一步算

$h_t$ 必须等 $h_{t-1}$ 算完才能算。长度 256 的序列，就要串行地算 256 步，没法并行。

tour 第 9 部分做了一个粗略的计时：同样的 batch 32、长度 256、隐藏维度 32，RNN 逐步循环的前向约 1.9 毫秒，而"对所有位置同时做一次投影"约 0.27 毫秒（本项目观察，计时随机器负载波动）。后者只是代表"可以并行"的计算方式，不是完整的注意力，两者的计算量和功能都不同，这个数字只用来建立"串行慢"的直觉。在 GPU 上，这个差距一般会更明显，因为 GPU 擅长的正是大量并行（本章没有在 GPU 上测）。

### 7.9.3 问题二：记忆会消失

更麻烦的问题出在训练上。要让第 50 步的 loss 影响第 1 步的计算，梯度要从 $h_{50}$ 一路反向传到 $h_1$，中间要连乘 49 次 $W$（第 2 章的链式法则）。为什么是乘 $W$：对 $h_t = \tanh(W h_{t-1} + U x_t)$ 求 $h_t$ 对 $h_{t-1}$ 的导数，先过 tanh，再过 $W h_{t-1}$，得到 tanh 的导数（一个对角矩阵）乘以 $W$。反向传播时，梯度每往回走一步，就要先乘上 tanh 的导数，再乘一次 $W^\top$（两者的顺序一般不能交换）。

连乘的后果，取决于每一步把梯度放大还是缩小。在一个控制实验里，我们取一个随机**正交矩阵** $Q$，它只旋转或翻转向量，不改变向量的长度，它的转置也一样。令 $W = \rho Q$，$\rho$ 取 0.5、1.0、1.5。这样每乘一次 $W$，梯度的长度恰好乘以 $\rho$。看梯度传回第 0 步时还剩多少（本项目观察，tour 第 9 部分）：

| 步数 | $\rho = 0.5$ | $\rho = 1.0$ | $\rho = 1.5$ |
|---|---|---|---|
| 1 | 0.5 | 1.0 | 1.5 |
| 5 | 0.031 | 1.0 | 7.6 |
| 10 | 0.00098 | 1.0 | 57.7 |
| 20 | 约 $10^{-6}$ | 1.0 | 3325 |
| 50 | 约 $10^{-15}$ | 1.0 | 约 $6.4 \times 10^{8}$ |

在这个设定下：

- $\rho$ 小于 1：梯度指数级**消失**。50 步以后只剩 $10^{-15}$，远处的 token 对训练几乎没有影响，模型学不会长距离的依赖。
- $\rho$ 大于 1：梯度指数级**爆炸**，训练直接崩溃。
- 只有恰好等于 1 才平稳，但这几乎不可能一直保持。

表里的数恰好是 $\rho^T$，这依赖三个刻意的简化：$W$ 是缩放后的正交矩阵、输入和初态为零、tanh 停在线性区（导数为 1）。**换成一般的矩阵，结论就不能照搬。** 比如 $W = \mathrm{diag}(1, 0.5)$ 的谱半径（特征值绝对值中最大的那个）是 1，但第二个坐标方向上的梯度照样按 $0.5^T$ 衰减。

一般情形下，梯度经过的是每一步的 Jacobian（也就是上面那个导数：tanh 的导数乘以 $W$）的连乘，tanh 饱和时导数接近 0，还会额外压小梯度；谱半径大于 1 也不一定爆炸（Pascanu 等人 2013 年对此有细致分析）。但"许多个矩阵连乘，很容易整体缩到 0 或者涨到无穷"这个直觉，在一般情形下仍然适用。

### 7.9.4 LSTM 和之后

1997 年提出的 **LSTM**（长短期记忆网络）给 RNN 加了"门"，让梯度可以沿着一条几乎不衰减的通路传播，大大缓解了遗忘问题。在 2017 年之前，LSTM 是语言模型的主流。

但串行计算的问题，LSTM 解决不了。2017 年的 Transformer 换了一条路：不再把历史压缩进一个记忆向量，而是让每个位置直接去查看所有之前的位置。任意两个位置之间只隔一步，没有连乘；所有位置可以同时计算。下一章就讲这种注意力。

| 模型 | 能看多远 | 能否并行 | 远处的梯度 |
|---|---|---|---|
| n-gram | n−1 个 token | 可以 | 不涉及（不用梯度） |
| 固定窗口 MLP | 窗口大小 | 可以 | 窗口外为 0 |
| RNN / LSTM | 理论上无限 | 不能，要逐步算 | 连乘，容易消失或爆炸 |
| 注意力（第 8 章） | 整个上下文 | 可以 | 任意两个位置一步直达 |

## 7.10 常见错误

| 错误 | 现象 | 本项目观察（tour 第 10 部分） |
|---|---|---|
| 目标没错开一位（$Y = X$） | 训练 loss 迅速降到接近 0，模型实际只学会了"抄当前输入" | 训练 loss 第 1 步 7.73、第 20 步 0.065、第 100 步 0.0012；在正确的预测任务上，验证 nat/token 是 10.19，比均匀猜测（ln 2257 ≈ 7.72）还差；采样出 `\\\\\\…alphaalphaalpha` 这样不断重复的东西 |
| 训练时不加 `<\|eos\|>` | 生成停不下来 | 玩具对照：加 EOS 时 200 条采样只有 1% 采到最大长度；不加 EOS 时 100% 采到最大长度 |
| 用 nat/token 比较不同分词器 | 得出相反结论 | 0 次合并的 bigram：2.7888 nat/token、4.0570 bits/byte；2000 次合并的 bigram：4.0132 nat/token、2.8941 bits/byte。按 nat/token 前者"更好"，按 bits/byte 后者明显更好 |
| 平滑为 0 | 验证 loss 是无穷大 | $k = 0$ 时全量验证 nat/token = inf |
| 公式之间直接拼接 | 模型把上一条公式的结尾当成下一条的上文 | 见 7.2.3 节；本章实现每条公式单独处理 |

第一行最容易骗人：训练 loss 异常快地掉到接近 0 时，要先怀疑，再高兴。在真实的公式语料上，下一个 token 本身有不确定性（`x` 后面可以是 `+`、`^`、`_`……），总体期望 loss 的下限大于 0（第 3 章 3.5.4 节）。验证集是有限样本，这个下限管不到它的具体数值；但模型没见过验证集，验证 loss 也不该接近 0，真出现了就先查是否泄漏。

训练 loss 接近 0 本身倒不一定是 bug。语料是确定性的（比如只有一条公式 `x^2`，每一步的下一个 token 都唯一），或者模型反复看同一个小批次、把训练集背了下来，训练 loss 都可以接近 0。所以看到这种曲线，按顺序查三件事：

1. $X$ 和 $Y$ 是不是错开了一位（标签泄漏）；
2. 是不是一直在同一个小批次上训练；
3. 验证 loss 怎么样。训练接近 0、验证很差，就是背答案（第 5 章的过拟合）。

> **为什么"抄输入"的模型在正确任务上比瞎猜还差？** 它学会了把概率几乎全部压在"当前输入的那个 token"上。而在正确的任务里，下一个 token 恰好等于当前 token 的情况很少，所以它几乎每次都给正确答案一个极小的概率，loss 很大。一个自信的错误，比诚实的不知道付出的代价更高（第 3 章 3.5 节）。

## 7.11 小结

1. **语言模型就是"已知前文，预测下一个 token"。** 链式法则 $P(x_1, \ldots, x_T) = \prod_t P(x_t \mid x_{<t})$ 把整条序列的概率精确地拆成逐个 token 的条件概率之积；`<|bos|>` 只当上文，`<|eos|>` 要预测。训练就是在每个位置上做分类、最小化平均交叉熵。
2. **样本要错开一位**：$X = $ `ids[i:i+T]`，$Y = $ `ids[i+1:i+T+1]`。训练 loss 接近 0 时，先查这里。
3. **n-gram 靠数数**，加 k 平滑 $P(b \mid a) = (\text{count}(a, b) + k) / (\text{count}(a) + kV)$（$V$ 是可预测类别数）避免零概率，$k$ 在验证集上选。n 变大时数据迅速变稀疏：在本章 2 万条训练公式、不用回退和插值的设定下，bigram 是最好的计数模型。
4. **MLP 用嵌入代替计数**，相似的 token 可以共享规律，参数量也不随上文长度爆炸；本章实验里上文从 3 加到 8，MLP 仍在变好，没有被稀疏拖垮。但它的窗口外是一片盲区：换掉窗口外的 token，输出一点都不变。
5. **几种指标都从 nat/token 换算**：bits/token = nat/token ÷ ln 2，困惑度 = $e^{\text{nat/token}}$（相当于每步在多少个选项里均匀地猜），bits/byte = bits/token ÷ 每 token 平均字节数。同一分词器下比哪个都行，跨分词器只能比 bits/byte。
6. **RNN 用一个不断更新的记忆**摆脱了固定窗口，但只能串行计算，梯度也会在连乘中消失或爆炸。这些问题，引出了第 8 章的注意力。
7. **最常见的错误**是目标没错开（训练 loss 很快接近 0，验证却比均匀猜测还差），以及拿 nat/token 比较不同分词器。

本章的基线：上文 8 的 MLP，验证 bits/byte = 2.7493。
