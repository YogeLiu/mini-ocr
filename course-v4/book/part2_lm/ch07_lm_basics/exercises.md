## 答案

### 概念题

**C1.** 链式法则是精确的。bigram 的近似发生在把 $P(x_t\mid x_{<t})$ 换成 $P(x_t\mid x_{t-1})$ 这一步，也就是马尔可夫假设。

**C2.** 加 `<|eos|>` 并预测它，模型才能学会"什么时候结束"，给出的才是"恰好是这样一条完整公式"的概率。不加的话，算出来的只是"以这些 token 开头"的概率：`x^{2}` 的概率会包含所有以 `x^{2}` 开头、后面还有更多内容的公式。生成时模型也停不下来（7.10 节）。

**C3.** `<|bos|>` 只是人为加在开头的边界符，它从不会出现在"下一个"的位置上，所以不作为预测目标。可预测的类别就是全部 2258 个 token 去掉 `<|bos|>`，共 2257 个。

**C4.** 困惑度等于"模型的不确定程度相当于在多少个等可能的选项里瞎猜"。困惑度为 1，表示模型每一步都以概率 1 给出了正确答案，完全确定且完全正确。

**C5.** 因为 $Y$ 是 $X$ 往后挪一位，窗口里每个位置 $t$ 都对应一个目标 $Y_t$，而它的上文就是 $X$ 的前 $t$ 个 token。要保证模型在位置 $t$ 只能看到前 $t$ 个 token，不能偷看后面的（否则答案就在输入里），这靠第 8 章的因果 mask 实现。

**C6.** 拼接以后，一条公式的开头会以上一条公式的结尾为上文，模型学到的是"跨公式"的虚假关系，比如某种结尾后面总跟某种开头。验证时每条公式单独处理，训练和评估的条件不一致。正确做法是每条公式单独加边界、单独切样本。

**C7.** 分子给 $V$ 个可能的下一个 token 各加了 $k$，一共多出 $kV$，分母也要加 $kV$，每行概率之和才等于 1。如果只加 $k$，每行概率之和会大于 1，不再是合法的概率分布，算出来的 loss 也没有意义（会偏低）。

**C8.** 词表有 2257 个可预测类别，$k=1$ 等于给每个上文凭空加了 2257 次"假观测"，常见组合的真实计数被稀释，概率被拉向均匀分布。如果词表只有 4 个 token，每个上文只多 4 次假观测，相对于真实计数影响很小，$k=1$ 可能就很合适。

**C9.** 上文的可能组合数随 n 指数增长（每多一个 token 乘以词表大小）。n 越大，训练集里每种上文出现的次数越少，模型越来越像在"背训练集"，所以训练 loss 降低。但验证集里大量上文在训练集里根本没出现过（n=4 时超过 27%），只能退化成均匀猜测，验证 loss 反而升高。

**C10.** n-gram 把每种上文当作一个孤立的计数格子，`\alpha +` 和 `\beta +` 之间毫无关系。MLP 用可学习的嵌入向量表示每个 token，出现在相似位置的 token 会被训练成相近的向量，从一个 token 学到的规律能部分迁移到相似的 token 上。

**C11.** MLP 的参数只有第一个线性层随上文长度线性增长（每多一个位置多 $d\times256$ 个参数），嵌入表和输出层不变。n-gram 要为每种出现过的上文组合单独存计数，组合数随上文长度指数增长。

**C12.** 固定窗口模型的输入只有窗口内的 token，窗口外的 token 根本不进入计算。不管窗口外写的是什么，输入张量都完全相同，输出自然完全相同。这和模型学得好不好无关，是结构决定的。

**C13.** 梯度从第 $t$ 步传回第 1 步，要连乘 $t-1$ 个 Jacobian（$W$ 乘上 tanh 的导数）。每一步若整体把梯度缩小，乘积指数级趋于 0（远处的 token 对训练没有影响）；若整体放大，乘积指数级爆炸。只有每一步都恰好保持长度才稳定，这很难做到。7.9.3 节的表里梯度恰好是 $\rho^T$，是因为特意用了缩放的正交矩阵、零输入和线性区的 tanh；一般矩阵不能只看谱半径。

**C14.** RNN 的 $h_t$ 依赖 $h_{t-1}$，必须一步一步串行地算。注意力让每个位置直接计算它和所有之前位置的关系，任意两个位置之间只隔一步，不需要把信息一路接力传过去；所有位置的计算互不依赖，可以同时进行。

**C15.** 先怀疑目标没有错开一位（$Y=X$），模型在抄当前输入。再查是不是一直在同一个小批次上训练、模型是不是把训练集背了下来，然后看验证 loss。训练 loss 接近 0 本身不一定是 bug（确定性语料或背下来的小训练集都能做到），总体期望 loss 的下限不限制有限验证集的具体数值；模型没见过验证集，验证 loss 若接近 0，应先查是否泄漏（7.10 节）。

**C16.** 同一个分词器、同一个验证集时，困惑度可以直接比较。分词器不同时必须用 bits/byte，因为每个 token 装的字节数不同，每 token 的 loss 含义不同。

### 手算题

**H1.** 概率 = 0.5 × 0.4 × 0.25 = 0.05。对数概率之和 = ln 0.05 = −2.9957。预测了 3 个 token（a、b、eos），NLL = 2.9957 / 3 = 0.9986。困惑度 = $e^{0.9986}$ ≈ 2.714（也等于 $0.05^{-1/3}$）。

**H2.**
(a) 两条序列是 `BOS a b a EOS` 和 `BOS b b EOS`。

| 上文 \ 下一个 | a | b | EOS |
|---|---|---|---|
| a | 0 | 1 | 1 |
| b | 1 | 1 | 1 |
| BOS | 1 | 1 | 0 |

(b) `a` 做了 2 次上文，后面跟 `b` 1 次、跟 `a` 0 次。$P(b\mid a)=1/2$，$P(a\mid a)=0$。
(c) 可预测类别 $V=3$（a、b、EOS）。$P(a\mid a)=(0+1)/(2+3)=0.2$。`b` 做了 3 次上文：$P(b\mid b)=(1+1)/(3+3)=1/3$，$P(\text{eos}\mid b)=(1+1)/(3+3)=1/3$。

**H3.** 每个位置给正确答案的概率都是 1/2257，nat/token = ln 2257 ≈ 7.7217，困惑度 = 2257。

**H4.**
- 嵌入表：2258 × 64 = 144,512。
- 输出层：256 × 2258 + 2258 = 580,306。
- $C=3$ 的隐藏层：(3 × 64) × 256 + 256 = 49,408。合计 774,226。
- $C=8$ 的隐藏层：(8 × 64) × 256 + 256 = 131,328。合计 856,146。

两者都和 tour 第 6 部分一致。

**H5.** $2258^3 \approx 1.15 \times 10^{10}$ 种。356,113 / (1.15 × 10¹⁰) ≈ 3.1 × 10⁻⁵，约十万分之三。绝大部分可能的上文从未出现过。

**H6.** nat/token = ln 20 ≈ 2.9957。bits/token = 2.9957 / 0.6931 ≈ 4.3219。bits/byte = 4.3219 / 2.5 ≈ 1.7288。

**H7.**
(a) BOS 不预测，15 个内容 token 和 EOS 都要预测，共 16 个目标。
(b) 加边界后长度为 17。窗口需要 $T+1=9$ 个连续 token，起点可以是第 0 到第 8 个位置，共 17 − 8 = 9 个窗口。

**H8.** $0.9^{30} \approx 0.042$，只剩约 4%。$1.1^{30} \approx 17.4$，放大了约 17 倍。

### 编程题提示

- **7.1：** 可以用 `unfold`，也可以用列表推导式加切片。注意序列长度不足 `context + 1` 时要返回形状正确的空张量。
- **7.2：** 计数时，`<|bos|>` 只出现在上文里，`<|eos|>` 只出现在目标里。分母的 $V$ 是可预测类别数（不含 BOS）。
- **7.3：** 都是一行公式，注意 bits/byte 要除以每 token 的字节数。
- **7.4：** 嵌入 → `flatten(1)` → 线性层 → tanh → 线性层。测试会检查初始 loss 约等于 ln V：如果你的初始化让 logits 很大，这个测试会失败。
- **7.5：** 插值不会让没见过的三元上文退化成均匀分布，它会退回 bigram 和 unigram 的估计。
- **7.8：** 参照 tour 第 7 部分的写法。

### 调试题

**D1.** $Y$ 没有错开一位，模型的任务变成了"输出当前输入的 token"，答案就在输入里，loss 很快接近 0。在正确的"预测下一个"任务上，这个模型几乎把所有概率压在当前 token 上，而下一个 token 很少等于当前 token，所以 loss 会很大，甚至比均匀猜测还差（7.10 节：10.19 对 7.72）。修复：`Y = ids[i+1:i+T+1]`。

**D2.** 要区分"完整词表"（2258 个）和"允许输出的类别"（2257 个，不含 `<|bos|>`）。按这段代码，对完整 2258 个 token 求和仍然等于 1，问题在于它给永远不会出现的 `<|bos|>` 分了 $k / (C(a) + 2258k)$ 的正概率。只在 2257 个允许的类别上求和，结果就小于 1：所有真正可能出现的 token 都被轻微低估，loss 偏高，和其他实现（分母用 $V-1$）的结果对不上。

修复要**两步一起做**：`b == bos_id` 时返回 0；分母改成 `self.k * (self.vocab_size - 1)`。只改分母、不把 BOS 置零，对完整词表求和反而会大于 1。

**D3.** 训练时，公式的开头以上一条公式的结尾（和一个空格）为上文；验证时，公式的开头以 `<|bos|>` 为上文。模型在训练中从没见过"`<|bos|>` 后面是公式开头"这种情况。另外拼接时没有 `<|eos|>`，模型学不会结束。修复：每条公式单独加 BOS/EOS，单独切样本。

**D4.** 没有。`make_window_examples` 不会自动补边界，窗口要凑满 3 个上文，前 3 个 token 都只当上文，不当目标；末尾也没有 EOS。修复：`ids = [bos] * 3 + tok.encode(formula) + [eos]`。

**D5.** 用测试集选超参数，测试集就变成了验证集，它上面的分数会偏乐观，不再是对新数据的无偏估计。以后应该在验证集上选 $k$，选型冻结后，预先登记的候选可在测试集上各评一次，不据此改任何设置；开发期不看测试集错例，最终报告定稿后才可解封（第 0 章 §0.10.1）。

但这一次已经污染了：原测试集看过之后，再"最后评一次"也不再无偏。补救是：如实披露之前用测试集选过 $k$；改在验证集上选定并冻结设置；再找一份**新的、没看过的留出测试集**报告最终结果。

**D6.** 先问：两个模型是不是用同一个分词器、同一个验证集、同一个评测口径（是否预测 EOS、是否预测 BOS）？只要有一项不同，困惑度就不能直接比较。分词器不同时，要换成 bits/byte。

### 闭卷手写

对照 7.1.1 节、7.3.4 节、7.2.4 节和 7.8 节检查。第 3 题：`X = ids[i:i+T]`，`Y = ids[i+1:i+T+1]`。第 5 题的要点：固定窗口外的 token 完全不进入计算；RNN 只能串行计算，梯度在连乘中消失或爆炸。
