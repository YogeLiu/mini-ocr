## 答案与提示

**14.1** softmax、除以正数 T、把非最大值设成 −∞ 都不改变最大值的位置，所以 argmax 不变。重复惩罚会改变各 logit 的相对大小（例如把最大的那个除以 penalty 后，它可能不再最大），所以能改变贪心结果。top-k 永远保留最大值（k ≥ 1 时第 1 名一定在集合里；最大值并列时，并列项全部保留，argmax 仍取第一个），所以单独的 top-k 在任何情况下都不会改变贪心结果；这道题的后半问是个陷阱。

**14.2** top-k：保留分数最高的 k 个（本书含并列）。top-p：按概率从大到小，保留累计概率首次达到 p 的最小前缀。模型有把握时，少数几个 token 就凑够 p，核小；没把握时要很多个，核大。LaTeX 例子：`\frac` 之后几乎只能接 `{`，top-k = 50 会放进 49 个不该出现的 token；而公式开头可以是很多种符号，top-k = 5 可能太少。

**14.3** T → 0：退化为贪心（最大值唯一时）。T → ∞：均匀分布。最大两个相等时，T → 0 的极限是在这两个之间各 0.5——仍然是随机的，不等于 argmax 取第一个。

**14.4** 越接近精确搜索（找全局概率最高的序列）。如果模型给"坏"序列（例如空公式）的概率比"好"序列高，搜索得越彻底越容易找到坏序列。搜索没有出错，它准确地找到了模型认为最好的；错在模型的概率与任务质量不一致（模型错误），或者在"概率最高 = 最好"这个目标上。

**14.5** 累计 log 概率每多一个 token 就加一个 ≤ 0 的项，只减不增。贪心不比较整条序列，每步只比较当前这一步的候选；14.7.4 节第一步 x 的 0.7 大于 EOS 的 0.3，贪心选了 x，之后再也不回头看 `<eos>` 那条路。

**14.6** (a) 贪心或束搜索（可加轻微重复惩罚）：答案唯一，要最可能的那一个。(b) 温度 + top-p 等采样：要多样性；贪心从 BOS 出发只能产生一条公式。(c) 温度采样：GRPO 的学习信号来自组内奖励的差异。不要求 8 个候选互不相同（例如 4 条相同的对、4 条相同的错也有差异），但如果 8 条完全一样，（确定性）奖励就一样，没有组内相对奖励信号（若启用 KL 正则，该项仍可能产生更新）；温度让组内更有机会出现奖励差异。

**14.7** 不会。接受-拒绝保证输出分布恰好是 p，与 q 无关（只要 q 在抽中的 token 上概率为正——它是从 q 抽出来的，自然如此）。草稿模型的好坏影响接受率，也就影响速度。

**14.8** 解码方式是评测设置的一部分。例如模型 A 容易复读、模型 B 容易提前结束：用贪心 + 重复惩罚时 A 可能占优；用 α = 0 的束搜索时 B 的空输出变多，排序又可能反过来。

**14.9** (a) [0.8310, 0.1125, 0.0414, 0.0152]。(b) 累计 [0.8310, 0.9434, …]，第 2 个之前的累计 0.8310 < 0.9，保留；第 3 个之前 0.9434 ≥ 0.9，去掉。核 {0, 1}，归一化后 [0.8808, 0.1192, 0, 0]。(c) 概率 [0.5793, 0.2131, 0.1293, 0.0784]，累计 [0.5793, 0.7924, 0.9216, 1.0]；第 3 个之前 0.7924 < 0.9 保留，第 4 个之前 0.9216 ≥ 0.9 去掉，核里 3 个，归一化后 [0.6285, 0.2312, 0.1402, 0]。(d) 先 top-p 只保留 {0, 1}，再除以 2：exp(1.5) 与 exp(0.5) 归一化，得 [0.7311, 0.2689, 0, 0]。错误顺序少保留了 token 2。（数值可用 `top_p_filter`、`apply_temperature` 复核。）

**14.10** (a) [1.5 / 1.5, −0.5 × 1.5, 0.2] = [1.0, −0.75, 0.2]。(b) −0.5 / 1.5 = −0.3333，比 −0.5 大，概率变大（惩罚变奖励）。(c) 一次：`gather` 读原值，重复的索引写回同一个变换值。

**14.12** (a) β = min(0.5,0.2) + min(0.3,0.5) + min(0.2,0.3) = 0.2 + 0.3 + 0.2 = 0.7。(b) max(0, p − q) = [0.3, 0, 0]，归一化为 [1, 0, 0]。(c) P(0) = q(0)·min(1, 0.5/0.2) + (1 − β)·1 = 0.2 + 0.3 = 0.5。

**14.13** 一元组：7 个，不同的 {a, b, c} 3 个，distinct-1 = 3/7 ≈ 0.4286。二元组：第一条 (a b)(b a)(a b)，第二条 (a b)(b c)，共 5 个，不同的 3 个，distinct-2 = 3/5 = 0.6。首尾相连会多出一个跨样本的 (b a)，变成 3/6 = 0.5。跨样本的二元组不是模型写出来的，不该计入。

**14.14** 记 β = 1/T，Z = Σ exp(β z_i)，μ = E_p[z]。H = −Σ p_i log p_i = −Σ p_i (β z_i − log Z) = log Z − β μ。d log Z / dβ = μ，dμ/dβ = E[z²] − μ² = Var。于是 dH/dβ = μ − μ − β·Var = −β Var。dβ/dT = −1/T²，所以 dH/dT = −β Var · (−1/T²) = Var / T³ ≥ 0。

**14.18** EOS 自循环概率为 1，log 概率不变（−1.2040），但长度被虚增到 4，GNMT 惩罚 1.5，得分 −1.2040 / 1.5 = −0.8026，高过 `x ^ 2 <eos>` 的 −0.9891。α = 0 时返回 `<eos> <eos> <eos> <eos>`，log 概率和正确的 `<eos>` 相同，看起来"只是多几个 EOS"——bug 仍在，只是被掩盖了。测试：断言送进 step_fn 的前缀没有以 EOS 结尾的。

**14.19** `logits[prev]` 用 (B, t) 的整数张量去索引 (B, V) 的张量，索引的是**第 0 维（行）**，取出的是整行 logits 而不是每行里对应的列；B = 1 时还可能因为编号超出行数而报错，或者悄悄改错了行。应该用 `gather(1, prev)` / `scatter(1, prev, …)` 沿词表维操作。

**14.20** (1) 默认运行用的是 150 步冒烟模型，输出里明说"只证明流程跑通，数字不代表质量"。(2) 束搜索只有 10 条，采样 50 条，样本量和提示子集都不同。(3) 10 条里 1 条可解析，Wilson 区间 [0.0179, 0.4042]；50 条里 3 条，区间 [0.0206, 0.1622]，两个区间大幅重叠，不能下结论。(4) 没换种子重复，也没看样例和长度（可解析可能只是因为写得短）。
