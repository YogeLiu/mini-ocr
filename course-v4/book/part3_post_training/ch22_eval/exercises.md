## 答案与提示

### 概念题

**22-C1.** B 变大不会让区间系统性变窄，只是让区间端点更稳定（减小蒙特卡洛误差，正文 22.2.6 节：换种子端点晃约 0.004）。n 变大才让区间变窄，半宽约按 $1/\sqrt n$ 缩小：n 从 500 到 2000，区间约缩一半。B 管"重抽本身的随机性"，n 管"抽样波动"。

**22-C2.** 两个模型对错高度正相关时会这样，见 22-H3：两个 Wilson 区间重叠，配对区间 [0.021, 0.099] 不含 0。共同的题目难度让两个分数一起晃，分别算区间把这份晃动算了两遍；配对相减把它抵消了。

**22-C3.** 它是在"真实差等于观测差"的世界里重抽得到的 $\bar d^*\le 0$ 的比例；p 值要在"真实差等于 0"（原假设）的世界里算。两者构造不同，只在某些条件下数值接近，所以本书只把它当描述性数字（正文 22.3.8 节）。

**22-C4.** 桶是题目的属性。按输出分，模型把分式写丢的题会从"分式"桶跑掉，留在桶里的多是写对了分式的题，所以"分式"桶的 EM 会**偏高**，弱项被掩盖（22-D4 是同一个问题）。

**22-C5.** 一、LSH 会漏召回（J = 0.8 的对约漏 5%）；二、只比了 train 的前 20000 条。第二个可以用算力消除（全量比较约 2 分钟，命中从 2 条变成 25 条）。第一个可以通过增加段数或直接两两精确比较来降低，但代价随数据量平方增长；而"阈值以下的相似"（比如 J = 0.7）根本不在检查范围内，这是定义上的限制。另外还有第三层——基座预训练数据——无论多少算力都查不了。

**22-C6.** 不一样。(a) 是绝对分数，污染可能让它整体偏高；(b) 是同一基座上两种方法的差值，污染对两边都有影响，差值受影响较小（但不为零：SFT 可能更善于"唤起"背过的公式）。

**22-C7.** 互斥让各类加起来等于总数，便于比较和画表；优先级让"外层问题"先暴露。丢失的是"一条输出同时有多个毛病"的信息。例如一条输出既带了 `$` 包装、里面又把上标写成了下标，它只会被记为 format，substitution 这一类就少算了一条。所以修好外层问题后，内层的类别会"冒出来"，不能把它误读成"模型变差了"。

**22-C8.** 用 val 挑选时，被选中的是"val 上运气好"的那个；它在 test 上的运气和 val 上的运气独立，所以 test 分数的期望仍是真值。被选中模型的 **val** 分数则有偏：它正是 k 个里的最大值，偏差约 $\sigma c_k$，和"在 test 上挑最好"完全同理（第 21 章 val 0.655 → test 0.615 就是这个方向）。

**22-C9.** 不矛盾。EM 只看对错，SFT 多对了 148 题；CER 是总和之比，对少数灾难性失败（重复循环一题就占 SFT 总编辑距离的 18.8%）极其敏感，所以区间很宽。报告里两个都写，并写明 CER 差异不确定的原因，指向下一步要处理的重复循环问题。

**22-C10.** 改边界就是在若干种分桶方式之间做选择，而选择的依据是 test 的结果。这和"看 k 个模型的 test 分数挑最好"是同一回事：被选中的那种分桶，带着 test 上的运气。

### 编程题提示

- **22.1** `x[rng.integers(0, x.size, (samples, x.size))].mean(axis=1)` 一行就是核心。逐位相等要求：同样用 `np.random.default_rng(seed)`、同样一次生成 (samples, n) 的下标矩阵、同样用 `np.quantile` 的默认插值。
- **22.2** 对齐用 `ids = [e.id for e in val]`，再 `[p[i] for i in ids]`。按 id 对齐后，文件行序怎么打乱都不影响结果，这正是对齐的意义。只有打乱已经评分的逐题得分数组（跳过对齐）才会破坏配对：2×2 表的四格会变成近似"独立"的样子，配对差的点估计不变（均值不依赖顺序），但配对失去了作用，区间会变宽。对 SFT 与 3-shot 这一对只略宽（两者对错本来就几乎不相关，正文 22.3.6 节）；换成 SFT 与照抄，变宽会明显得多。
- **22.3** 分子分母必须用同一组下标；"两边相同时区间为 (0, 0)"是最好的单元测试。SFT 最大的一题编辑距离 272，占总和 1447 的 18.8%（本项目观察，重新计数）。
- **22.4** 一条带两种噪声的题会在两行各出现一次，所以各行总数之和（538）大于有错样本数 337，这是正常的。最强模式见正文 22.6.5 节。
- **22.5** 组内题目要整组带入；不同组大小不同，所以每次重抽的样本总数不一定是 500，这是允许的。
- **22.6** σ 与 $1/\sqrt{n_{\text{test}}}$ 成正比，4 倍样本让 σ 减半，偏差 $\sigma c_k$ 也减半；$c_k$ 不随 n 变。模拟中 k = 20 的偏差为 0.019（本项目观察，本地 CPU）。
- **22.7** 漏洞举例：如果参考答案里本来就有 `$`，模型再额外用 `$...$` 把整条公式包起来，问题名同样是 `dollar_wrapped`，集合差为空，会被漏判。更稳妥的办法是比较包装本身（例如首尾是否多出定界符），而不只比较问题名的集合。
- **22.8** 最高的一对只差末尾一个句号（另有几处空格不同）。规范化不删句末标点，所以两者的规范键不同，按规范键分组的划分把它们分到了两边，精确检查也认为它们不同。命中组 19/25 = 0.76 [0.566, 0.885]，未命中组 320/475 = 0.674 [0.630, 0.714]。

### 调试题

**22-D1.** a 和 b 用了两组独立的下标，配对变成了不配对，共同难度没有被抵消。测试：`paired(x, x)` 的区间必须是 (0, 0)；他的版本会给出非零区间。修法：先 `d = b - a`，再只对 d 重抽（或两边用同一个 `idx`）。

**22-D2.** 他算的是逐题 CER 的平均，短公式错一个字符就占很大比例，统计量变了。本书的 CER 是语料级"总编辑距离 / 总参考长度"（第 18 章 18.2 节）。bootstrap 应对分子、分母用同一组下标分别求和再相除。

**22-D3.** 两份文件的行顺序可能不同（合并、分批生成都可能改变顺序），第 i 行不再是同一道题。`tour.py` 部分 3 先读成 `{id: raw}` 字典，断言 id 集合等于 val 的 id，再按 val 的顺序取出。

**22-D4.** 按输出分桶，SFT 把分式写丢、写坏的题离开了"分式"桶，剩下的自然更容易对，0.80 是选择出来的。桶必须按参考答案定义。

**22-D5.** 问题：只查了精确重叠（而分组划分按构造就保证它为 0）；没做近重复检查；只用了 3.7% 的 train；没提基座预训练数据。改写示例："本语料内 val 与 train 的规范键精确重叠为 0；MinHash/LSH 近重复（Jaccard ≥ 0.8）对全量 train 命中 25/500（下界），剔除后结论不变；无法检查基座模型的预训练数据。"

**22-D6.** 这份报告根据 test 的错例改了设置，test 已不再是留出集。按第 0 章 0.10.1 节：在报告里写明这件事，0.640 不能作为无偏的 test 结果；补一份新的、从未看过的留出测试集。选型冻结后，预先登记的候选可在新集上各评一次，只报告数字和区间，不据此改任何设置。开发期的错例分析只在 val 上做，test 错例要等最终报告定稿后才可解封（正文 22.6 节的 script_shift 发现就是在 val 上得到的）。

**22-D7.** 不是 bug，是蒙特卡洛误差，量级约千分之几（正文 22.2.6 节）。修法：固定种子，保证可复现；报告保留两位小数；不要拿第三位小数的差别下结论。
