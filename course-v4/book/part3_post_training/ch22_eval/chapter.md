## 22.1 一个数字有多可靠

### 22.1.1 val 只是一次抽样

先说结论：val 上的 0.678 是模型在这 500 道题上的准确率，不能直接当成模型的准确率。

你真正关心的是模型在所有可能遇到的公式上表现如何。这个总体你拿不到，只能抽一部分出来考。考 500 道题，对了 339 道，0.678 是对真实准确率 p 的一个**估计**。换另外 500 道同分布的题，答对的数会变，可能是 330，也可能是 350。

这种换一批题就会变的波动，叫**抽样波动**。置信区间要描述的就是它。

### 22.1.2 波动有多大：一个公式

每道题对或错，可以看成一次抛硬币，正面概率是 p。n 道题的正确率 $\hat p$ 的标准差是

$$\mathrm{SE}(\hat p)=\sqrt{\frac{p(1-p)}{n}}$$

（数学结论：n 次独立伯努利试验的均值方差为 p(1−p)/n。）

代入 p = 0.678、n = 500：

$$\sqrt{\frac{0.678\times 0.322}{500}}=\sqrt{\frac{0.218316}{500}}\approx 0.0209$$

正态近似的 95% 区间是 $\hat p\pm 1.96\,\mathrm{SE}$，即 0.678 ± 0.041，约 [0.637, 0.719]（数学结论）。

一个经验规则由此而来：区间半宽约等于 $1/\sqrt n$ 量级。n 从 500 涨到 2000，区间缩到一半；想再缩一半，要 8000 条。样本数和精度之间是平方关系，很贵。

### 22.1.3 Wilson 区间回顾，以及它管不到的地方

第 18 章用的 Wilson 区间是上面正态近似的改进版：在 p 接近 0 或 1、n 较小时更可靠。SFT 的 339/500，Wilson 95% 区间是 [0.636, 0.717]（本项目观察，`analysis.json`），和上面的正态近似几乎一样。

但 Wilson 只管**比例**。下面这些量它都管不了：

- **CER**：总编辑距离 ÷ 总参考字符数，是两个和之比，不是对的题占几成。
- **两个模型的差**：EM_A − EM_B 的区间怎么算？两个模型做的是同一批题，误差不独立。
- **任何你以后会发明的指标**：中位数、F1、"渲染后的像素相似度"……

每种都推一遍公式，既累又容易错。下一节的 bootstrap 给出一个通用办法：用计算代替推导。

> **停下来想一想：**零样本的 EM_norm 是 0/500。点估计是 0，你能说零样本永远做不对吗？Wilson 区间的上界是多少？（答案：$1.96^2/(500+1.96^2)\approx 0.0076$，数学结论；与 `analysis.json` 一致。）

## 22.2 bootstrap 置信区间

### 22.2.1 总体拿不到，就拿样本当总体

上一节的公式依赖一个前提：你知道统计量的分布长什么样。比例的分布是二项分布，好推。CER 的分布就难推了：它是一个比值，分子分母都随抽到的题变化，而且每道题的编辑距离分布很不规则（22.3.7 节会看到一道题贡献了 SFT 总编辑距离的近两成）。

bootstrap 的想法是 Efron 在 1979 年提出的，简单到让人不太放心：既然拿不到总体，就把手里这 n 个样本当成总体；从里面有放回地再抽 n 个，算一次统计量；重复很多次，看统计量怎么晃。

### 22.2.2 尝汤

厨师想知道一大锅汤咸不咸，舀一勺尝。可这一勺尝出来的咸度有多准？理想的做法是舀很多勺分别尝，看结果差多少。但锅已经端走了，手里只剩这一勺。

bootstrap 的做法是：把这一勺当成一个缩小版的锅，从里面一滴一滴有放回地取，凑出一勺，尝一次；再凑一次，再尝一次……这些假勺子之间的差别，近似反映了真勺子之间的差别。

前提是：**这一勺本身要能代表这锅汤**。勺子太小（n 太小）或者舀的方式有偏（样本不独立、不同分布），bootstrap 也救不了。

### 22.2.3 推导：三步

设样本是 $x_1,\dots,x_n$，统计量是 $\hat\theta=s(x_1,\dots,x_n)$，例如均值。

**第一步：用经验分布代替真实分布。**真实分布 F 未知。经验分布 $\hat F$ 是在 n 个样本上各放 1/n 概率的离散分布。从 $\hat F$ 抽一个点，等价于从 n 个样本里等概率挑一个，这就是**有放回抽样**。

**第二步：在 $\hat F$ 上重演一遍"抽样 → 算统计量"。**从 $\hat F$ 抽 n 个点得到 bootstrap 样本 $x^*_1,\dots,x^*_n$，算 $\hat\theta^*=s(x^*_1,\dots,x^*_n)$。重复 B 次，得到 $\hat\theta^*_1,\dots,\hat\theta^*_B$。

落到本章的评测上，一个样本 $x_i$ 就是一道题的得分（或这道题的编辑距离和参考长度）。重抽的是**题目的下标**：每次重抽相当于换一张由原来 500 道题拼成的新卷子，有的题出现两次，有的题没出现。模型不重新跑，每道题的输出和得分都是原来那一份，变的只是哪些题进了这张卷子。

核心近似是：

$$\hat\theta^*-\hat\theta\ \text{在}\ \hat F\ \text{下的分布}\ \approx\ \hat\theta-\theta\ \text{在}\ F\ \text{下的分布}$$

左边我们能算（重抽就行），右边是我们想要的（估计的误差）。这叫**插入原理**（plug-in principle）：凡是需要 F 的地方，都换成 $\hat F$。

**第三步：从 B 个 $\hat\theta^*$ 读区间。**最简单的读法是**百分位区间**：取第 2.5 和第 97.5 百分位，作为 95% 区间。本书代码用的就是它。

几点说明（均为数学结论或标准结果）：

- 每个 bootstrap 样本里，某个原始样本**一次都没被抽到**的概率是 $(1-1/n)^n\to e^{-1}\approx 0.368$。所以每次重抽大约有 63% 的原始样本出现，有的出现多次。
- 百分位区间在统计量分布对称、无偏时表现好。分布偏斜时，有更好的变体（BCa 区间，见 22.9 节），本书不展开。
- B 决定的是**蒙特卡洛误差**，不是抽样误差。B 再大，区间也不会因此变窄，它只会更稳定地逼近在这 n 个样本上的理想 bootstrap 区间。区间宽度由 n 决定。

### 22.2.4 手算：5 道题、3 次重抽

5 道题的对错是

$$x=[1,0,1,1,0],\qquad \hat\theta=\bar x=3/5=0.6$$

下标是 0 到 4。我们用 `np.random.default_rng(0).integers(0, 5, (3, 5))` 生成 3 行重抽下标（这是代码实际会抽到的，下一小节对照）：

| 重抽 | 抽到的下标 | 对应的值 | 均值 |
|---|---|---|---|
| 1 | 4, 3, 2, 1, 1 | 0, 1, 1, 0, 0 | 2/5 = 0.4 |
| 2 | 0, 0, 0, 0, 4 | 1, 1, 1, 1, 0 | 4/5 = 0.8 |
| 3 | 3, 4, 2, 3, 4 | 1, 0, 1, 1, 0 | 3/5 = 0.6 |

注意第 2 次：下标 0 被抽了 4 次，下标 1、2、3 一次都没抽到。这就是有放回。

三个均值排序为 [0.4, 0.6, 0.8]。`np.quantile` 默认线性插值：第 q 分位落在排序后的位置 $q(B-1)$ 上。

- 2.5%：位置 $0.025\times 2=0.05$，在 0.4 和 0.6 之间走 5%：$0.4+0.05\times0.2=0.41$。
- 97.5%：位置 $0.975\times 2=1.95$，在 0.6 和 0.8 之间走 95%：$0.6+0.95\times0.2=0.79$。

区间是 [0.41, 0.79]（数学结论）。B = 3 当然太少，这里只为手算。

**B 足够大时会怎样？**这 5 道题里有 3 个 1，重抽 5 次中抽到 1 的个数 K 服从 Binomial(5, 0.6)。可以精确算出（数学结论）：

- P(K = 0) = 0.4⁵ ≈ 0.010，P(K ≤ 1) ≈ 0.087 > 0.025，所以 2.5% 分位是 K = 1，即均值 0.2；
- P(K = 5) = 0.6⁵ ≈ 0.078 > 0.025，所以 97.5% 分位是均值 1.0。

理想的 bootstrap 区间是 [0.2, 1.0]。代码用 B = 2000 跑出的正是 (0.2, 1.0)（本项目观察，本地 CPU，seed 0）。5 道题的区间宽到几乎没用，n 太小就是这样。

### 22.2.5 对照代码：`bootstrap_mean`

`miniocr/eval/analysis.py`：

```python
def bootstrap_mean(values, *, samples=1000, seed=0):
    x = np.asarray(values, dtype=float)
    if x.size == 0:
        return dict(value=None, interval=(None, None), samples=samples, seed=seed)
    if samples == 0:
        return dict(value=float(x.mean()), interval=(None, None), samples=0, seed=seed)
    rng = np.random.default_rng(seed)
    means = x[rng.integers(0, x.size, (samples, x.size))].mean(axis=1)
    return dict(value=float(x.mean()), interval=tuple(float(v) for v in np.quantile(means, [.025, .975])),
                samples=samples, seed=seed)
```

逐行对照 22.2.4 节：

- `x = np.asarray(...)`：x = [1, 0, 1, 1, 0]。
- 空样本返回 `None` 而不是 0：没有题就没有分数，返回 0 分会被误读成全错。
- `rng = np.random.default_rng(seed)`：**固定种子**。同一组输入、同一个 seed，区间每次都一样，报告才能复现。测试 `test_bootstrap_interval_contains_mean_and_is_seeded` 检查的就是这一点。
- `rng.integers(0, x.size, (samples, x.size))`：一次生成 B × n 的下标矩阵。samples=3、n=5、seed=0 时，三行正是表里的 [4,3,2,1,1]、[0,0,0,0,4]、[3,4,2,3,4]。
- `x[...]`：花式索引，把下标换成值，形状仍是 (3, 5)。
- `.mean(axis=1)`：每行求均值，得到 [0.4, 0.8, 0.6]。
- `np.quantile(means, [.025, .975])`：得到 (0.41, 0.79)。

在本地运行 `bootstrap_mean([1, 0, 1, 1, 0], samples=3, seed=0)`，返回 `value=0.6, interval=(0.41, 0.79)`（本项目观察，本地 CPU），与手算一致。

lab 第 1 部分的机制检查用的是另一组小数据 [0, 0, 1, 1]，你可以照同样的步骤手算再对照。

**CER 怎么办？**CER 是总编辑距离 ÷ 总参考长度，不是逐题均值。`score_postcorrect` 里的做法是：每次重抽 n 个下标，**分子、分母用同一组下标各自求和，再相除**。重抽的单位仍然是一道题，只是统计量换了。22.8 节的常见错误表还会提到这一点。

### 22.2.6 实测：SFT 的区间

把 bootstrap 用在 SFT 的 500 条逐题 EM_norm 上（B = 1000，seed 0）：

| 方法 | 区间 | 来源 |
|---|---|---|
| 正态近似 | [0.637, 0.719] | 数学结论（22.1.2 节） |
| Wilson | [0.636, 0.717] | 本项目观察，`analysis.json` 的 `em_norm` |
| 百分位 bootstrap | [0.638, 0.718] | 本项目观察，`analysis.json` 的 `em_norm_bootstrap` |

三种方法在 n = 500、p ≈ 0.68 时几乎一致。对比例，bootstrap 没有带来新东西，只是和公式互相印证。它的用处在公式够不着的地方，比如 CER：SFT 的 CER 是 0.026，bootstrap 区间 [0.017, 0.040]（本项目观察）。注意这个区间**不对称**：点估计离下界 0.009，离上界 0.014。CER 的分布有长尾（少数题错得很离谱），百分位区间自动反映了这种偏斜，正态近似做不到。

**换种子会怎样？**对同一组 SFT 逐题结果，换 seed 0、1、2 各跑 1000 次，得到 [0.638, 0.718]、[0.640, 0.720]、[0.634, 0.718]；B = 10000 时是 [0.636, 0.718]（本项目观察，重新计数）。端点在千分位上晃动约 0.004，这就是 B = 1000 的蒙特卡洛误差。所以报告区间时保留两位小数就够了，第三位小数不要拿来比较。

把面板的四项放在一起，就是三种输出在这 500 道 val 上的完整成绩（本项目观察，`analysis.json` 的 `summary`）。比例带 Wilson 95% 区间，CER 带 bootstrap 区间（B = 1000，seed 0）；改坏的分母是 163 条无错输入，fix_rate 的分母是 337 条有错输入：

| 方法 | EM_norm | CER | 改坏 | fix_rate |
|---|---|---|---|---|
| 零样本 | 0/500 = 0.000 [0.000, 0.008] | 1.162 [1.097, 1.244] | 163/163 = 1.000 [0.977, 1.000] | 0/337 = 0.000 [0.000, 0.011] |
| 严格 3-shot | 24/500 = 0.048 [0.032, 0.070] | 0.148 [0.125, 0.171] | 151/163 = 0.926 [0.876, 0.957] | 12/337 = 0.036 [0.020, 0.061] |
| SFT | 339/500 = 0.678 [0.636, 0.717] | 0.026 [0.017, 0.040] | 11/163 = 0.067 [0.038, 0.117] | 187/337 = 0.555 [0.502, 0.607] |

### 22.2.7 bootstrap 什么时候会失灵

bootstrap 不是万能的。项目里会碰到三种情况。

**一、全对或全错时，区间塌成一个点。**零样本 500 题全错，每次重抽也全是 0，bootstrap 区间是 [0, 0]（本项目观察，`analysis.json`）。它等于在说完全没有不确定性，这显然不对：Wilson 区间是 [0, 0.0076]。分桶后更常见：严格 3-shot 在矩阵/数组桶里 0/37，bootstrap 给 [0, 0]，Wilson 给 [0, 0.094]（数学结论）。**比例为 0 或 1 时，用 Wilson，不用百分位 bootstrap。**

**二、n 太小。**22.2.4 节的 5 道题已经展示过：区间宽到没有信息量。更糟的是，n 很小时经验分布连可能的取值都覆盖不全，bootstrap 区间往往偏窄。

**三、样本不独立。**bootstrap 默认每道题是独立抽出来的。我们的 val 不完全是这样：后纠错数据会给同一条干净公式造多个带噪版本。这 500 条 val 里只有 468 个不同的规范化目标，有 53 条和别的题共享同一个目标（15 组两条、1 组三条、5 组四条）（本项目观察，重新计数）。共享目标的题，对错往往一起变化。

解决办法是**按组重抽**（cluster bootstrap）：重抽的单位是一个目标公式连同它的所有带噪版本，不再是单条。按规范化目标分组重抽 1000 次，SFT 的 EM_norm 区间是 [0.633, 0.719]，比逐条重抽的 [0.638, 0.718] 略宽（本项目观察，重新计数）。这里重复不多，差别很小；如果你的 TexPixel 测试集里同一页文档切出了几十张公式图，差别就可能很大。练习 22.5 让你自己实现它。

## 22.3 配对 bootstrap：两个模型差多少

### 22.3.1 区间重叠不等于没有差别

第 18 章立了一条底线：**区间重叠时，不说谁更好。**这条规则是保守的，它能防止你吹嘘，但会让你错过真实的差别。

原因在于：两个模型做的是**同一批题**。有的题很难，两个模型都错；有的题很简单，两个都对。这部分题目难度在两个模型的分数里是共同的，它让两个分数一起上下晃。分别算两个区间，等于把这份共同的晃动算了两遍。

正确的做法是**先逐题相减，再看差值的区间**。

### 22.3.2 两个学生考同一张卷子

比较两个学生，一种办法是让他们各考一张不同的随机卷子，比总分。另一种办法是让他们考**同一张**卷子，逐题看谁对谁错。

第二种公平得多：卷子难不难，对两个人一样。有信息量的只有一个对、一个错的那些题。两人都对、都错的题，在比较里互相抵消。

### 22.3.3 配对为什么更准

设第 i 题上模型 A、B 的得分是 $a_i,b_i\in\{0,1\}$，差值 $d_i=b_i-a_i$。差的估计是

$$\bar d=\bar b-\bar a=\frac1n\sum_i d_i$$

它的方差（数学结论，方差的展开公式）：

$$\mathrm{Var}(\bar d)=\frac{\mathrm{Var}(b)+\mathrm{Var}(a)-2\,\mathrm{Cov}(a,b)}{n}$$

如果把两组当成独立的（不配对），就等于假装 Cov = 0：

$$\mathrm{Var}_{\text{不配对}}=\frac{\mathrm{Var}(b)+\mathrm{Var}(a)}{n}$$

两个模型在同一批题上，对错通常**正相关**（难题一起错），Cov > 0，所以配对的方差更小、区间更窄。相关越强，收益越大。

对 0/1 得分还有一个好用的化简。$d_i$ 只取 −1、0、1，$d_i^2$ 在两者不一致时为 1、一致时为 0，所以

$$\mathrm{Var}(d)=E[d^2]-(E[d])^2=\frac{\text{不一致的题数}}{n}-\bar d^{\,2}$$

只要数出一张 2×2 表，就能算。

这个式子也说明了配对为什么更灵敏。两个模型都对或都错的题，d = 0，对差 $\bar d$ 没有任何贡献；差和它的波动只取决于不一致的那些题。不配对的算法把每个模型各自的波动（主要来自题目难度）都算进了误差，配对的算法在逐题相减时就把这部分抵消了。

**配对 bootstrap** 就是把 22.2 节的方法用在 $d_i$ 上：**两个模型用同一组下标重抽**，算差的均值，重复 B 次取百分位。它不需要上面的公式，但会自动用上共同难度被抵消这件事。

### 22.3.4 手算：5 道题

模型 A、B 在 5 道题上的得分：

| 题 | 0 | 1 | 2 | 3 | 4 |
|---|---|---|---|---|---|
| A | 1 | 0 | 1 | 0 | 0 |
| B | 1 | 1 | 1 | 0 | 1 |
| d = B − A | 0 | 1 | 0 | 0 | 1 |

$\bar a=0.4$，$\bar b=0.8$，$\bar d=0.4$。

用和 22.2.4 节**同一组**重抽下标（seed 0）：

| 重抽 | 下标 | d 的值 | 均值 |
|---|---|---|---|
| 1 | 4, 3, 2, 1, 1 | 1, 0, 0, 1, 1 | 0.6 |
| 2 | 0, 0, 0, 0, 4 | 0, 0, 0, 0, 1 | 0.2 |
| 3 | 3, 4, 2, 3, 4 | 0, 1, 0, 0, 1 | 0.4 |

排序 [0.2, 0.4, 0.6]，按 22.2.4 节的插值，区间是 [0.21, 0.59]（数学结论）。三次重抽里没有一次 $\bar d^*\le 0$。

A 和 B 用的是**同一组下标**。第 2 次重抽把第 0 题抽了 4 次，那么 A 的第 0 题、B 的第 0 题都各被抽 4 次。如果两个模型各抽各的下标，同一张卷子就变成了两张卷子，配对就失效了。

B = 2000 时，代码给出区间 (0.0, 0.8)，`p_b_not_better = 0.0805`（本项目观察，本地 CPU）。这个比例可以精确核对：$\bar d^*\le 0$ 只可能在 5 次都抽到 d = 0 的题时发生，而 d = 0 的题占 3/5，所以概率是 $(3/5)^5\approx 0.078$（数学结论）。模拟值 0.0805 与它相差约 0.003，在 B = 2000 的蒙特卡洛误差以内。

### 22.3.5 对照代码：`paired_bootstrap_diff`

```python
def paired_bootstrap_diff(a, b, *, samples=1000, seed=0):
    a, b = np.asarray(a, dtype=float), np.asarray(b, dtype=float)
    if a.shape != b.shape or a.ndim != 1 or a.size == 0:
        raise ValueError("配对比较要求两个等长一维非空数组")
    d = b - a
    ...
    rng = np.random.default_rng(seed)
    means = d[rng.integers(0, d.size, (samples, d.size))].mean(axis=1)
    return dict(diff=float(d.mean()),
                interval=tuple(float(v) for v in np.quantile(means, [.025, .975])),
                p_b_not_better=float((means <= 0).mean()), n=int(d.size), samples=samples, seed=seed)
```

- 形状检查：两个数组必须等长。等长还不够，**第 i 个元素必须是同一道题**。函数没法替你检查这一点，所以 `tour.py` 的部分 3 先断言三份预测的 id 集合都等于 val 的 id，再按 val 的顺序取出（`preds[name] = [p[i] for i in ids]`）。
- `d = b - a`：先逐题相减。之后的重抽只在 d 上做，同一组下标自动成立。手算例子里 d = [0, 1, 0, 0, 1]。
- 重抽和取分位与 `bootstrap_mean` 一模一样。samples=3、seed=0 时，`means` 是 [0.6, 0.2, 0.4]，区间 (0.21, 0.59)。
- `p_b_not_better`：重抽中 $\bar d^*\le 0$ 的比例。它是描述性的数字，**不是严格意义上的 p 值**（22.3.8 节说为什么）。

两个边界情况由测试守着：两个模型输出完全相同时，d 全为 0，区间必须是 (0, 0)（`test_paired_difference_of_identical_outputs_is_zero`）；B 全对、A 全错时，差是 1，区间 (1, 1)（`test_paired_difference_direction`）。

### 22.3.6 实测：SFT 与三个对照

先看 SFT 与严格 3-shot 的 2×2 表（本项目观察，重新计数；总数与 `analysis.json` 的 24/500、339/500 一致）：

| | SFT 对 | SFT 错 |
|---|---|---|
| **3-shot 对** | 20 | 4 |
| **3-shot 错** | 319 | 157 |

只有 319 + 4 = 323 道不一致的题在起作用。差是 (319 − 4)/500 = 0.630（数学结论）。

用 22.3.3 节的公式手算：

- $\mathrm{Var}(d)=323/500-0.630^2=0.646-0.3969=0.2491$
- $\mathrm{SE}=\sqrt{0.2491/500}\approx 0.0223$
- 正态 95% 区间：0.630 ± 0.044，约 [0.586, 0.674]

（以上为数学结论。）配对 bootstrap 给出的是 [0.584, 0.672]（本项目观察，`analysis.json` 的 `paired.sft_minus_strict_3shot`），两者吻合。

如果不配对呢？$\mathrm{Var}(a)=0.048\times0.952=0.0457$，$\mathrm{Var}(b)=0.678\times0.322=0.2183$，SE = $\sqrt{(0.0457+0.2183)/500}\approx 0.0230$（数学结论）。只比配对的 0.0223 大一点点。为什么配对在这里帮助不大？因为 3-shot 几乎全错，两个模型的对错几乎不相关：Cov = 20/500 − 0.048 × 0.678 ≈ 0.0075，很小。

两个模型水平接近、对错高度相关时，配对的效果最明显。看 SFT 和「照抄」（输出 = 带噪输入，不需要模型；本项目观察，重新计数，照抄 EM_norm 191/500 = 0.382）：

| | SFT 对 | SFT 错 |
|---|---|---|
| **照抄对** | 179 | 12 |
| **照抄错** | 160 | 149 |

- 差：(160 − 12)/500 = 0.296
- 配对：$\mathrm{Var}(d)=172/500-0.296^2=0.2564$，SE ≈ 0.0226
- 不配对：$\mathrm{Var}(a)+\mathrm{Var}(b)=0.382\times0.618+0.2183=0.4544$，SE ≈ 0.0301

（以上为数学结论。）配对把标准误缩小了约四分之一。原因是 Cov = 179/500 − 0.382 × 0.678 ≈ 0.099，相关很强：照抄能对的题（大多是本来无错或只多了空格的输入），SFT 也基本能对。配对 bootstrap 区间是 [0.252, 0.340]（本项目观察，重新计数）。

把三个比较放在一起（EM_norm，SFT − 对照）：

| 对照 | 配对差 | 95% 区间 | 来源 |
|---|---|---|---|
| 零样本 | +0.678 | [0.638, 0.718] | `analysis.json` |
| 严格 3-shot | +0.630 | [0.584, 0.672] | `analysis.json` |
| 照抄 | +0.296 | [0.252, 0.340] | 重新计数 |

三个区间都远离 0。结论清楚：**在这 500 道 val 上，SFT 的 EM_norm 明显高于三个对照。**

### 22.3.7 同一对模型，换个指标就看不清了

还是 SFT 对照抄，这次比 CER（越低越好）。照抄 0.034 [0.028, 0.042]，SFT 0.026 [0.017, 0.040]（本项目观察，SFT 来自 `analysis.json`，照抄为重新计数）。两个区间大幅重叠。

做配对 bootstrap（同一组下标同时重抽两边的编辑距离和参考长度，再各自相除，再相减）：照抄 − SFT = 0.0084，95% 区间 [−0.0039, 0.0162]，包含 0（本项目观察，重新计数，B = 1000，seed 0）。

EM 上差了 0.30，CER 上却分不出高下。为什么？把 SFT 每道题的编辑距离排个序就明白了：500 道题的编辑距离总和是 1447，其中**一道题就贡献了 272**（18.8%），前 10 道题贡献了 45%（本项目观察，重新计数）。那道题的参考答案只有 43 个字符，SFT 却输出了 346 个字符：它掉进了重复循环，把 `{(Av, v)}` 写了几十遍，直到 `max_new_tokens` 把它截断。

CER 是总和之比，对这种灾难性失败很敏感。一道题的循环就能让总 CER 涨一截，bootstrap 抽到它几次、没抽到它几次，CER 就大起大落，区间自然宽。EM 只看对错，一道题再离谱也只扣 1/500。

两个指标结论不一致时，不要挑好看的那个报，要去看是什么样的样本造成了分歧。这里的分歧指向一个具体问题：重复循环，它会成为 22.6 节的一条假设。

### 22.3.8 统计检验（概括）

你在论文里会看到「p < 0.05」「差异显著」这样的说法。这里只说够用的部分，细节见精读。

- **原假设检验**的思路是：假设两个模型其实一样好，算在这个假设下看到这么大或更大差距的概率，即 p 值。p 小，说明一样好这个假设和数据不太相容。
- 0/1 得分的配对比较，经典检验是 **McNemar 检验**，它只用 2×2 表里那两个不一致的格子（例如 160 和 12）。**置换检验**（随机交换每道题上 A、B 的得分）也常用。McNemar 的算法见下面的手算。
- 本书的 `p_b_not_better` 是 bootstrap 分布在 0 左边的比例。它和单侧 p 值在某些条件下数值相近，但构造方式不同：bootstrap 在"真实差 = 观测差"的世界里重抽，检验要在"真实差 = 0"的世界里算。所以本书只把它当描述性数字。
- **多重比较**：比较 20 组，每组用 5% 的门槛，即使 20 组其实都没有差别，平均也会有 1 组显著，纯属巧合。22.4 节的分桶和 22.7 节的窥视，都是这个问题的不同面孔。

**手算 McNemar。**记 2×2 表里 A 对 B 错的题数为 $n_{10}$，A 错 B 对的为 $n_{01}$。两个都对、都错的题对两个模型的差没有贡献（22.3.3 节），所以检验只看不一致的 $n_{10}+n_{01}$ 道题。如果两个模型其实一样好，每道不一致的题偏向 A 和偏向 B 的机会各占一半；再假设题与题之间相互独立，$n_{01}$ 就服从 Binomial$(n_{10}+n_{01},\ 1/2)$。题数多时用卡方近似，统计量是

$$\chi^2=\frac{(n_{01}-n_{10})^2}{n_{01}+n_{10}}$$

它和自由度为 1 的卡方分布比较，大于 3.84 就对应双侧 p < 0.05（这是不带连续性校正的版本）。

- 22.3.4 节的 5 道题：不一致的只有第 1、4 题，都是 B 对 A 错，$n_{10}=0$，$n_{01}=2$。精确二项检验的双侧 p 值是 $2\times(1/2)^2=0.5$（数学结论）。B 的分数高出一倍，但只有两道不一致的题，这点证据远远不够。
- SFT 对照抄：$n_{10}=12$（照抄对、SFT 错），$n_{01}=160$，$\chi^2=148^2/172\approx 127.35$（数学结论），远大于 3.84。

和 bootstrap 一样，McNemar 也假设题目相互独立。本章 val 里同一目标的几个带噪版本对错相关（22.2.7 节），直接套标准 McNemar 是忽略这层相关的近似；相关多时，应该像按组重抽那样按组处理。

本书的做法是报告差值和它的配对区间，让读者自己看区间离 0 有多远，不只报一个显著或不显著。

## 22.4 分桶评测：模型弱在哪里

### 22.4.1 平均数会藏东西

0.678 是 500 道题的平均。它可能来自"每类题都对七成"，也可能来自"简单题全对、某类难题全错"。这两种情况，下一步该做的事完全不同。

**分桶**就是把 val 按某个属性切成几组，每组单独算指标。好的分桶能把模型的弱项从平均数里拽出来。

### 22.4.2 三种桶

本章用了三种切法：

**公式类型**（`formula_bucket`，按**参考答案**判断，互斥）：

```python
def formula_bucket(target):
    if _MATRIX.search(target):   # \begin{matrix|pmatrix|...|array|cases}
        return "矩阵/数组"
    if _FRAC.search(target):     # \frac、\dfrac、\tfrac、\over
        return "分式"
    if _SCRIPT.search(target):   # ^ 或 _
        return "上下标"
    return "其他"
```

一条公式常常同时有分式和上下标。为了让每条只进一个桶（各桶计数加起来等于 500），代码按**优先级**判断：先看矩阵，再看分式，再看上下标。所以上下标桶的真实含义是：有上下标，但没有分式和矩阵。读桶名时要记住这一点。

为什么按参考答案而不是按模型输出分桶？因为桶是**题目**的属性。如果按输出分，模型把分式写丢了，这道题就从分式桶跑到别的桶去了，你正好会漏掉最想看的错误。

**长度**（`length_bucket`）：参考答案字符数 < 30、30 到 59、≥ 60。边界事先写死，不根据数据分位数调。

**噪声类型**：第 18 章的六种合成错误（`confusable`、`drop_brace`、`command_typo`、`missing_arg`、`script_shift`、`extra_space`）。它只适用于 337 条有错样本，而且**不互斥**：其中 201 条带了两种错（本项目观察，重新计数），会同时进两个桶。`score_postcorrect` 的 `by_error_type` 给出每个桶的 fix_rate 和 Wilson 区间。

### 22.4.3 实测：公式类型与长度

SFT 的 EM_norm（本项目观察，`analysis.json`，bootstrap 95% 区间）：

| 桶 | 题数 | EM_norm | 区间 |
|---|---|---|---|
| 上下标 | 266 | 0.677 | [0.617, 0.729] |
| 分式 | 187 | 0.668 | [0.594, 0.738] |
| 矩阵/数组 | 37 | 0.703 | [0.541, 0.838] |
| 其他 | 10 | 0.800 | [0.500, 1.000] |
| 短（< 30） | 22 | 0.727 | [0.545, 0.909] |
| 中（30 到 59） | 82 | 0.683 | [0.585, 0.780] |
| 长（≥ 60） | 396 | 0.674 | [0.629, 0.720] |

先看区间宽度。矩阵桶 37 题，区间宽约 0.30；上下标桶 266 题，宽约 0.11。用 22.1.2 节的公式验算：$2\times1.96\sqrt{0.21/37}\approx 0.30$，$2\times1.96\sqrt{0.21/266}\approx 0.11$（数学结论）。题数少 7 倍，区间宽 $\sqrt{7}\approx 2.7$ 倍。

再看结论：**七个桶的区间全部互相重叠。**按公式类型和长度切，看不出 SFT 有哪类明显的弱项。

注意措辞，这张表**不能**说明长度对 SFT 没有影响。短公式只有 22 题，区间从 0.55 到 0.91，真实差别即使有 10 个点，这么少的样本也看不出来。正确的说法是：「在这 500 道 val 上，没有证据表明各类公式、各档长度的 EM_norm 不同；小桶的样本太少，不足以排除差别。」

还有一个数据特点：500 道 val 里 396 道（79%）参考答案不少于 60 个字符（本项目观察）。长度分档的边界是按人觉得什么算长定的，不是按这份数据定的，所以桶极不均衡。这本身就是一条发现：如果 TexPixel 的真实图片多是短公式，那 val 的长度分布就不代表真实场景。

### 22.4.4 实测：噪声类型

换一种切法，画面就变了。SFT 在各噪声类型上的 fix_rate（本项目观察，`analysis.json` 的 `by_error_type`，Wilson 95% 区间）：

| 噪声类型 | 含这类噪声的题 | 改对 | fix_rate | 区间 |
|---|---|---|---|---|
| extra_space | 97 | 71 | 0.732 | [0.636, 0.810] |
| confusable | 102 | 61 | 0.598 | [0.501, 0.688] |
| command_typo | 121 | 72 | 0.595 | [0.506, 0.678] |
| drop_brace | 99 | 39 | 0.394 | [0.303, 0.492] |
| script_shift | 89 | 30 | 0.337 | [0.247, 0.440] |
| missing_arg | 30 | 8 | 0.267 | [0.142, 0.444] |

这里出现了**不重叠**的区间：`script_shift` 的上界 0.440 低于 `confusable` 的下界 0.501，也远低于 `extra_space` 的下界 0.636。

所以 SFT 的弱项要按错误类型看，按公式外形切看不出来：

- `extra_space`（多了空格）最容易，部分原因是规范化本来就会抹掉空格（第 18 章 18.2.1 节）。
- `confusable`（形近字符，如 l 和 1）和 `command_typo`（命令拼错，如 `\Slgma`）中等：错的地方一眼看上去就不对，模型有线索。
- `script_shift`（上标变下标或反过来）、`drop_brace`（丢了花括号）、`missing_arg`（丢了一个参数）最难。

`script_shift` 难，有一个直观的理由：`x^{2}` 和 `x_{2}` **都是合法的 LaTeX**。命令拼错了，不认识这个命令本身就是信号；上下标换了位置，字面上毫无破绽，只能靠数学上哪个更说得通来判断。一个 0.6B 的模型，又只做了 400 步 SFT（第 21 章选中的 checkpoint），做不到这一点并不奇怪。这还只是猜测，要用实验检验，22.6 节会把它写成一条可检验的假设。

### 22.4.5 读分桶的三条规矩

**一、先看题数，再看分数。**10 题的桶得 0.8，不说明任何事。

**二、桶多了，总会有一个看起来很极端的。**本章切了 4 + 3 + 6 = 13 个桶。即使模型在所有桶上真实水平完全一样，13 个各自带 95% 区间的估计里，有一两个偏得离谱也不奇怪（这正是 22.3.8 节的多重比较）。所以分桶发现的弱项是**假设**，不是结论；要在新数据或新实验上再验证一次。噪声类型那张表之所以可信一些，是因为差距大（0.34 对 0.73），而且有一个事先就说得通的机制。

**三、桶的定义事先写好。**看到结果再调桶的边界（比如把 50 字符改成 45，差距就显著了），和 22.7 节的反复看 test 是同一种错误。`length_bucket` 的边界写死在代码里，就是为了防这个。

## 22.5 基准泄漏的近似检查

### 22.5.1 开卷考试

如果 val 里的某道题在训练集里出现过，模型答对它可能只是背过，不一定会做。这叫**泄漏**（leakage）或**污染**（contamination）。泄漏会让分数虚高，而且你很难从分数本身看出来。

第 12 章 12.3.5 节演示过一个极端例子：直接在原串上随机留出验证集，结果 10.64% 的验证公式在训练集里有同伴（本项目观察，第 12 章）。

### 22.5.2 三层泄漏

按多像才算泄漏，可以分三层：

| 层次 | 例子 | 本章能不能查 |
|---|---|---|
| 完全相同（规范化后） | `\frac{a}{b}` 和 `\frac {a}{b}` | 能，精确比较规范键 |
| 近似相同 | 只差一个句号、一个下标 | 能，但只能给下界（MinHash/LSH） |
| 基座模型的预训练数据 | Qwen3 预训练时见过 arXiv 上的这条公式 | **不能**，我们拿不到它的训练数据 |

### 22.5.3 精确检查：按构造就是 0

`check_no_leak` 对 train 和 val 的目标公式各算一遍规范键集合，求交集大小。

本章的结果是交集为 0（本项目观察，`analysis.json`，用 train 前 20000 条作参考）。这其实在意料之中：第 6 章的 `standard_split` 是**先按规范键分组、再整组分配**的，同一个规范键不可能同时出现在 train 和 val（数学结论，由划分的构造保证）。这一步检查的意义是**确认代码真的这么做了**：构造上保证的东西，也要实测一次，防止有人改了划分代码。

### 22.5.4 近重复检查：MinHash + LSH

精确检查抓不住几乎一样的公式。第 12 章的工具正好用上：把每条公式切成规范化 token 的 3-gram（shingle），用 Jaccard 相似度衡量两条公式有多像，用 MinHash 签名 + LSH 分段快速找候选对，再对候选对算精确的 Jaccard。

`near_overlap(reference, queries, threshold=0.8)` 做的就是这件事，只是它只关心 val 中的一条和 train 中的一条之间的配对，train 内部、val 内部的配对一律跳过。

它给出的是**下界**，有两个原因：

**一、LSH 会漏。**本章用 16 段、每段 8 行。一对 Jaccard 恰好为 J 的公式成为候选的概率是 $1-(1-J^8)^{16}$（数学结论，第 12 章 12.5.3 节的 S 曲线）。J = 0.8 时，这个概率是 0.947：恰好卡在阈值上的对，约有 5% 会被漏掉。

**二、只比了一部分 train。**`tour.py` 默认只取 train 的前 20000 条作参考（`--train-ref-n`），而 train 一共有 542339 条（本项目观察）。只比了 3.7%。

### 22.5.5 实测：20000 条与全量

**用前 20000 条 train**（lab 第 3 部分的默认设置）：精确重叠 0 条；近重复命中 2 条 val（本项目观察，`analysis.json`）。

这 2 条值得细看（本项目观察，重新计数）。它们其实是**同一条公式**的两个带噪版本（val 里同一目标出现了两次，见 22.2.7 节），在 train 中匹配到的也是同一条公式（train 里它也出现了两次）。两条公式出自同一段推导：val 的是 $[r_{31},r_{32}]=\dots$，train 的是 $[r_{21},r_{32}]=\dots$，结构相同，下标和张量因子的位置互换，Jaccard 0.80，正好在阈值上。SFT 两条都答对了。

**用全部 542339 条 train**（同一个函数，本地 CPU 约 2 分钟；本项目观察，重新计数，不是 lab 的默认设置）：近重复命中 **25 条** val，占 5.0%；其中 24 个不同的目标公式。命中对的最高 Jaccard 是 0.9865。

再看那条 0.9865 的命中：val 的目标和 train 中的一条公式**只差末尾一个句号**（以及逗号后的几个空格）。规范化不删句末标点，所以精确检查认为它们是两条不同的公式，分组划分把它们分到了两边。精确检查抓不住的正是这种情况。

**泄漏让分数虚高了多少？**把 500 道 val 分成有近重复命中和没有命中两组（本项目观察，重新计数）：

| 组 | 题数 | SFT EM_norm | Wilson 95% 区间 |
|---|---|---|---|
| 有近重复 | 25 | 19/25 = 0.76 | [0.566, 0.885] |
| 无近重复 | 475 | 320/475 = 0.674 | [0.630, 0.714] |

有近重复的组分数高一些，但区间重叠，25 题太少，不能断定。更有用的是一个**界**：即使把这 25 题全部剔除，SFT 的 EM_norm 也只从 0.678 变成 0.674，差 0.004，远小于区间半宽 0.04（数学结论，由表中计数算出）。

所以可以写进报告的结论是：**在本语料内部，val 与 train 的近重复约占 5%（下界）；剔除它们不改变本章的任何比较结论。**

### 22.5.6 查不到的那一层

Qwen3-0.6B 的预训练数据里有没有这些公式？很可能有一部分：我们的语料来自 arXiv 和 im2latex-100K，都是公开数据（待验证：Qwen3 没有公开逐条训练数据）。

我们无法直接检查，但有两点可以说：

- **它影响的是所有方法，不只是 SFT。**零样本、3-shot、SFT 用的是同一个基座。所以 SFT 比提示好多少，这个**差值**受它影响较小；SFT 的绝对分数能代表真实 OCR 场景，这句话则要打折扣。
- **任务形式不同。**基座见过的是干净公式，我们考的是"把带噪公式改回来"，噪声是我们用固定种子合成的。背过干净公式确实能帮助纠错，但不等于背过考题。

报告里要老实写出这一层的局限。TexPixel 项目用自己拍的真实图片做 test，是对这个问题最好的缓解。

## 22.6 错例分类表

### 22.6.1 从错了多少到错在哪

分桶告诉你哪类题弱，错例分类告诉你**错成了什么样**。前者像体检报告上哪项指标偏高，后者像拍片子看病灶长什么样。只有看到具体的错，才能提出具体的改法。

规矩只有一条，第 0 章 0.10.1 节和第 5 章 5.1.3 节已经定好：**开发期的错例分析只在 val 上做。**test 的错例要等最终报告定稿后才可解封。

### 22.6.2 标签与优先级

`error_class(target, source, pred, is_clean)` 给每条输出打**一个**标签，按下面的顺序判断，命中即停：

| 顺序 | 标签 | 条件 | 含义 |
|---|---|---|---|
| 1 | correct | 规范化后与参考相同 | 对了 |
| 2 | format | `format_issues(pred)` 非空 | 带解释文字、`$`、代码围栏等包装 |
| 3 | unparsable | mathtext 解析失败 | 语法坏了（或解析器不支持，见 22.6.4） |
| 4 | unchanged | 输出 = 带噪输入，而输入有错 | 该改的没改 |
| 5 | over-correction | 输入本来无错，却被改了 | 改坏 |
| 6 | missing / extra / substitution | 按规范 token 对齐，只有删除 / 只有插入 / 只有替换 | 漏写 / 多写 / 写错 |
| 7 | mixed | 以上编辑操作混合 | 多种错误 |

为什么要**互斥加优先级**？因为一条输出可能同时有好几个毛病。互斥能让各类加起来等于总数，方便比较；代价是每条只记了最先命中的那个毛病。顺序的设计原则是：**越外层、越容易修的问题排越前。**格式问题排第一，因为一条带了 "Here is the corrected formula:" 的输出，里面的公式对不对已经不重要了，先得让它只输出公式。

手算一条（lab 第 1 部分的机制检查之一）：参考 `x+y`，输入 `x y`（有错，`is_clean=False`），输出 `x-y`。

1. 规范化后 `x-y` ≠ `x+y`，不是 correct。
2. 没有解释文字、没有 `$`，不是 format。
3. `x-y` 能解析，不是 unparsable。
4. 输出 ≠ 输入，不是 unchanged。
5. 输入有错，不是 over-correction。
6. 对齐 token：`x`=`x`，`+`→`-` 是替换，`y`=`y`。只有替换，标为 **substitution**。

`tour.py` 部分 1 里有 8 条这样的例子，覆盖了除 unparsable 和 mixed 以外的每个标签，并断言结果；`test_error_labels_cover_format_and_unparsable` 补上了 unparsable。

### 22.6.3 实测：三种方法的错例表

（本项目观察，`analysis.json` 的 `error_table`，各 500 条。）

| 方法 | correct | format | unparsable | unchanged | over-corr. | missing | extra | subst. | mixed |
|---|---|---|---|---|---|---|---|---|---|
| 零样本 | 0 | 499 | 0 | 0 | 0 | 0 | 0 | 0 | 1 |
| 严格 3-shot | 24 | 347 | 71 | 3 | 20 | 6 | 2 | 8 | 19 |
| SFT | 339 | 13 | 95 | 6 | 5 | 2 | 5 | 26 | 9 |

从左往右读，三种方法的主要病灶一目了然：

- **零样本**几乎全部是 format。它不按要求只输出公式，比如把 `I_\Sigma(A)=\{\dots\}` 改写成带 Unicode 符号 `Σ₁`、`∈` 的文本。
- **严格 3-shot** 仍以 format 为主（347 条）。重新计数发现，其中 339 条的问题包含 `dollar_wrapped`，即公式被 `$...$` 包起来（本项目观察）。这正是第 21 章 21.8.3 节说的：本章按**原始输出**评分，不做抽取，`$` 包装就算错。（第 18 章的 3-shot 数字是抽取后的口径、在 2000 条上算的，两者不能直接比。）
- **SFT** 的 format 只剩 13 条，主要剩下 unparsable（95）和 substitution（26）。

SFT 把格式这个外层问题基本解决了，剩下的是内容问题。这和第 19 到 21 章的预期一致：SFT 首先教会的是**输出的形状**。

### 22.6.4 先抽查标签，再相信表格

错例表是启发式标签，不是人工金标准。**在根据它下结论之前，每类至少抽几条看看。**本章抽查发现了两个问题。

**问题一：SFT 的 13 条 format 全是误报。**逐条看这 13 条（本项目观察，重新计数），没有一条带解释文字或代码围栏。它们被标为 format，是因为**参考答案本身**就会触发 `format_issues`：

- 公式里本来就有 `\mbox{if $x_i \ge 0$}` 这样的内嵌 `$`，触发 `dollar_wrapped`；
- 公式里有 `\otimes dX_r` 这样「命令名 + 空格 + 字母」的片段，被 `[A-Za-z]{2,}\s+[A-Za-z]{2,}` 当成了英文单词，触发 `has_explanation`。

500 条参考答案中，有 38 条自己就会触发 `format_issues`（本项目观察，重新计数）。所以 SFT 的 format 真实数量接近 0，这 13 条实际上是内容错误。

**问题二：unparsable 一半以上是解析器的问题。**unparsable 用的是 matplotlib mathtext 的子集解析，不是真正的 LaTeX 编译。500 条参考答案里只有 293 条（58.6%）能被它解析（本项目观察，重新计数；与 lab 第 5 部分一致）。SFT 的 95 条 unparsable 中，有 63 条的**参考答案本身也解析不了**（本项目观察，重新计数）。对这 63 条，unparsable 只说明题目含矩阵、`\\`、`\text`、`\left` 之类 mathtext 不认识的结构，不说明模型写坏了。真正参考能解析、输出解析不了的只有 32 条。

所以第一个要修的是评测器，不是模型：把 `format_issues` 改成与参考答案对比后多出来的包装才算，把 mathtext 换成真正的 LaTeX 编译或渲染比较，然后再读这两列。

### 22.6.5 交叉表：标签 × 噪声类型

把 22.4.4 节的噪声类型和错例标签交叉起来，看最弱的两类错误错成了什么样（SFT，本项目观察，重新计数；一条带两种噪声的题在两行各计一次）：

| 噪声类型 | 题数 | correct | unparsable | substitution | format | 其他 |
|---|---|---|---|---|---|---|
| script_shift | 89 | 30 | 26 | **19** | 6 | 8 |
| drop_brace | 99 | 39 | **50** | 3 | 6 | 1 |

两个清楚的模式：

- **SFT 全部 26 条 substitution 里，有 19 条的题含 script_shift。**看几条：输入 `(\pi N)_{1/3}`（上标被改成了下标），SFT 原样保留 `_{1/3}`，只修好了同一题里的另一处错；输入 `\Delta a_{\prirne}`，SFT 把拼错的 `\prirne` 修成了 `\prime`，却没把 `_` 改回 `^`。模型会修看起来不对的地方，对看起来没毛病的上下标位置无动于衷。
- **drop_brace 的题有一半落进了 unparsable。**例如参考 `\frac1{2\pi\sqrt{-1}}\int\dots`，输入同时丢了一个 `}`、多了一处空格；SFT 删掉了多余的空格，却没把 `}` 补回来，括号不配对，解析失败。补括号要判断该在哪里闭合，这比删空格难得多。

### 22.6.6 从错例到假设

「模型还有 161 条错」没法指导下一步，错例分析要产出的是**下一步实验的假设**。一条好的假设要写清楚四件事：观察、猜测的原因、可检验的预测、怎样在 val 上检验。

**假设 1（评测器）。**观察：SFT 的 13 条 format 全是误报，unparsable 中 63/95 的参考本身就解析不了。猜测：现有的 format 和 parse 判断不适合本数据。预测：改用相对参考多出的包装判定 format、改用真正的 LaTeX 编译判定可解析后，SFT 的 format 降到接近 0，unparsable 降到 32 左右。检验：只改评测器，不重新生成，在已有逐条输出上重算。**这条应该最先做**，否则后面每张错例表都被它污染。

**假设 2（script_shift）。**观察：script_shift 的 fix_rate 0.337，最低档之一；19/26 的 substitution 与它有关。猜测：上下标错位字面上合法，SFT 数据里这类例子不够，模型没学会判断。预测：在 SFT 数据里提高 script_shift 的比例（或者第 23 章用改对的版本对原样保留的版本构造偏好对），script_shift 桶的 fix_rate 上升，其他桶不下降。检验：在**同一批 val** 上，对 script_shift 桶的 89 题做配对 bootstrap。

**假设 3（重复循环）。**观察：一道题的重复循环贡献了 SFT 总编辑距离的 18.8%；SFT 有 4 条输出被 `max_new_tokens` 截断（本项目观察，`generation-summary.json` 的 `capped`）。猜测：贪心解码在长公式上偶尔陷入循环。预测：加重复惩罚，或者输出长度超过输入两倍就停，CER 明显下降、EM 几乎不变。检验：CER 与 EM 都做配对 bootstrap；同时检查有没有题因此被截短。

**假设 4（改坏）。**观察：163 条无错输入中，SFT 改坏了 11 条（改坏率 0.067 [0.038, 0.117]，`analysis.json`）。第 21 章 21.8.3 节看过几条：把 `C_o` 改成 `C_0` 之类。猜测：模型学会了看着像 OCR 错误的地方就改。这一条暂时排在后面：11 条太少，先攒更多例子。

注意，所有假设的检验都写的是 **val**。下一节讲为什么。

> **停下来想一想：**假设 2 说「其他桶不下降」。如果你在 6 个噪声桶上都做配对 bootstrap，有一个桶的区间刚好不含 0、方向是下降，你该怎么解读？（提示：22.4.5 节规矩二。）

## 22.7 评测协议：val 做决定，test 只报告

### 22.7.1 规则

第 0 章 0.10.1 节和第 5 章 5.1.3 节的评测协议，落到操作上是这样：

- **val**（开发集）可以反复用：调参、选模型、看错例、提假设，全在这里。
- **test**（留出集）在选型冻结后，预先登记的候选可以各评一次，只报数字和区间，**不根据结果改任何设置**。开发期不看 test 错例，最终报告定稿后才可解封做错例分析。

各评一次本身不造成偏差，选择已经在 val 上定了；偏差来自按 test 分数做决定，下面模拟的就是这件事。本章只用了 val，test 一次都没碰。第 21 章 21.8.4 节在 checkpoint 选定、配置冻结之后，才在 test 上评了一次。

下面用一个模拟实验把反复看 test 的代价算出来。

### 22.7.2 考前看了答案

假设你有 20 个模型，**真实水平完全一样**，都是 0.7。你把 20 个都放到 test 上考一遍，挑分数最高的那个报告。

每个模型在 500 道 test 上的分数会因为抽样波动上下浮动（22.1.2 节算过，标准差约 0.02）。20 个里最高的那个，**一定是运气最好的那个**。你报告的数字是 0.7 加上最好的那份运气。

这就是**选择偏差**：用来做选择的数据，不能再用来评估被选中的东西。用 test 做选择，test 分数就起了 val 分数的作用，不再是无偏的估计。

### 22.7.3 最大值的期望

把每个候选的 test 分数近似为独立的正态变量：

$$\hat p_j\sim\mathcal N(p,\ \sigma^2),\qquad \sigma=\sqrt{\frac{p(1-p)}{n}},\quad j=1,\dots,k$$

报告其中的最大值，它的期望是

$$E\Big[\max_j \hat p_j\Big]=p+\sigma\,c_k$$

其中 $c_k$ 是 k 个独立标准正态变量最大值的期望（数学结论，与 p、n 无关，可由数值积分算出）：

| k | 1 | 2 | 5 | 10 | 20 |
|---|---|---|---|---|---|
| $c_k$ | 0 | 0.564 | 1.163 | 1.539 | 1.867 |

k = 2 时有闭式解 $c_2=1/\sqrt\pi\approx 0.564$。$c_k$ 随 k 增长，但增长得很慢（k 很大时与 $\sqrt{2\ln k}$ 同阶）。

代入 p = 0.7、n = 500：$\sigma=\sqrt{0.21/500}\approx 0.0205$（数学结论）。于是看 k 次挑最好的偏差约为：

| k | 2 | 5 | 10 | 20 |
|---|---|---|---|---|
| 预测偏差 $\sigma c_k$ | +0.012 | +0.024 | +0.032 | +0.038 |

（数学结论，正态近似。）

### 22.7.4 模拟实验

`peeking_simulation` 用二项分布直接模拟这件事，不做正态近似。设定：k 个候选真实准确率都是 0.7，val 和 test 各 500 题，重复 2000 次。比较两种报告方式：

- **val 选择**：在 val 上挑分数最高的候选，报告它在 test 上的分数。
- **test 挑最好**：k 个候选都看 test，报告最高的 test 分数。

结果（本项目观察，`analysis.json` 的 `peeking`；纯模拟，不代表任何真实模型；对应 lab 第 4 部分）：

| k | val 选择：报告值 | test 挑最好：报告值 | test 挑最好：偏差 | 正态近似预测 |
|---|---|---|---|---|
| 1 | 0.700 | 0.700 | 0.000 | 0 |
| 2 | 0.700 | 0.711 | +0.011 | +0.012 |
| 5 | 0.700 | 0.723 | +0.023 | +0.024 |
| 10 | 0.699 | 0.731 | +0.031 | +0.032 |
| 20 | 0.699 | 0.738 | +0.038 | +0.038 |

两件事：

**一、val 选择是无偏的。**无论 k 多大，用 val 挑出来的那个，它的 test 分数平均仍是 0.700。因为 val 上的运气和 test 上的运气是独立的：在 val 上走运，不意味着在 test 上也走运。

**二、在 test 上挑，偏差随 k 稳定增长，而且和推导吻合。**k = 20 时偏差 +0.038，接近一个标准误的两倍。回想 22.1.2 节：n = 500 的 95% 区间半宽约 0.04。看 20 次 test，就能凭空造出一个区间半宽那么大的提升，而这 20 个模型的真实水平一模一样。

这个偏差在真实项目里只会更隐蔽：你未必挑了 20 个模型，但你可能根据 test 改了一次提示词、调了一次阈值、换了一次分桶边界，每一次都是在 test 上做了一次选择。

### 22.7.5 对照代码：`peeking_simulation`

```python
for k in looks:
    val = rng.binomial(n_val, true_accuracy, size=(trials, k)) / n_val
    test = rng.binomial(n_test, true_accuracy, size=(trials, k)) / n_test
    picked_by_val = test[np.arange(trials), val.argmax(axis=1)]
    best_of_test = test.max(axis=1)
```

- `rng.binomial(n_val, 0.7, size=(trials, k)) / n_val`：一次生成 2000 × k 个 val 准确率。每个都是 500 次、成功概率 0.7 的二项分布除以 500。所有候选的真值都是 0.7，这是模拟的前提。
- `test = ...`：独立地再生成一份 test 准确率。和 val 用同一个 rng 依次抽取，所以两份相互独立。
- `val.argmax(axis=1)`：每次试验里，val 分数最高的候选是哪个。
- `test[np.arange(trials), val.argmax(axis=1)]`：取出**被 val 选中的那个候选**的 test 分数。这一行就是 val 做决定、test 只报告。
- `test.max(axis=1)`：直接取 test 分数最高的。这一行就是在 test 上挑。

测试 `test_peeking_bias_grows_with_looks` 换了一个真值（0.6）检查同样的两件事：k = 1 时偏差接近 0，k 最大时偏差明显为正。

### 22.7.6 项目里的真实例子

第 21 章就发生过一次温和的版本。四个 checkpoint 在 val 前 200 条上的 EM_norm 是 128、131、127、128，按规则选中了 131 的第 400 步；之后在 test 前 200 条上评一次，得到 123/200 = 0.615（本项目观察，第 21 章 21.8.4 节）。

val 0.655，test 0.615。这里**被选择污染的是 val 分数**：0.655 是四个里最高的，带着四选一的运气（按 22.7.3 节，若四个候选真实水平相同且互相独立，k = 4、n = 200、p ≈ 0.65 时偏差约为 $\sqrt{0.65\times0.35/200}\times c_4\approx 0.034\times1.03\approx 0.035$，数学结论，正态近似，$c_4\approx1.029$。四个 checkpoint 来自同一次训练、对错高度相关，实际偏差应小于这个数）。test 没有参与选择，0.615 是更诚实的估计。两者的差距在区间之内，不能把它全部归于选择偏差，但方向完全符合。

所以 R2 报告的主结果要写 test 的那个数，不写 val 上挑出来的那个。

### 22.7.7 连评测本身都有噪声

最后一个小观察。本章 val 前 500 条的前 200 条，就是第 21 章用的那 200 条（本项目观察，重新计数，id 完全一致）。同一个 step-400 adapter，本章重新生成后在这 200 条上对了 130 条，第 21 章是 131 条（本项目观察，重新计数；第 21 章数字见 21.8.2 节）。

同样的模型、同样的题、同样的贪心解码，差了一条。可能的原因是两次运行的 batch 组成或 GPU 浮点累加顺序不同，bf16 下个别 token 的 logit 打平时选了不同的词（待验证，本章没有逐 token 比对）。

这一条的差别远小于区间宽度，不影响任何结论。但它提醒你两件事：比较两个模型时，**要在同一次运行里重新生成基线**，不要抄旧表；以及为什么 `environment.json` 要把精度、batch size、库版本、val 的 ID 哈希全部写下来（lab 第 0 部分）。

## 22.8 常见错误

| 错误 | 现象 | 怎样发现 |
|---|---|---|
| 配对比较时两个模型各自重抽下标 | 差值区间比应有的宽，明显的改进被说成不确定 | 两个模型输出完全相同，差值区间应为 (0, 0)；跑一下就知道 |
| 两个预测文件的题目顺序不一致 | 配对差像随机数，甚至符号不稳 | 先断言 id 集合与顺序一致（`tour.py` 部分 3 的做法） |
| 把各自的 bootstrap 区间当成模型之间的显著性 | 两个区间略有重叠就说没差别，或略不重叠就说显著 | 一律做配对差 |
| 比例为 0 或 1 时用百分位 bootstrap | 区间塌成 [0, 0] | 计数为 0 或 n 时改用 Wilson |
| CER 的 bootstrap 先算每题 CER 再平均 | 算出来的是逐题 CER 的均值，和报告的语料级 CER 不是一个量 | 分子分母用同一组下标各自求和再相除；点估计应与 `score_postcorrect` 一致 |
| 忽略样本之间的相关（同一目标多个版本） | 区间偏窄 | 数一下不同目标的个数；按组重抽对比 |
| 按模型输出分桶 | 出错的题从它本该在的桶里跑掉，弱项被掩盖 | 桶函数的参数只能是参考答案 |
| 分桶后只报分数不报题数 | 10 题的桶被当成重要发现 | 表里必须有题数和区间 |
| 看到结果再调桶边界 | 某个桶的差距刚好显著 | 边界写死在代码里，改动要在报告中说明 |
| 只用部分 train 做近重复检查，却写成「无泄漏」 | 报告的泄漏率偏低（本章：2/500 对 25/500） | 写明参考集的规模；结论写成下界 |
| 不抽查错例标签就下结论 | 把评测器的误报当成模型的错误 | 每类抽几条看原文 |
| 开发期在 test 上看错例、调设置 | test 分数偏乐观，且看不出来 | test 只存汇总；第 21 章的守卫代码 |
| 只报 B = 1000 的区间的第三位小数并拿来比较 | 换个种子结论就变 | 换两个种子看端点晃多少 |

## 22.10 小结

一个评测数字只是一次抽样的结果：bootstrap 把换一批题会怎样变成可以计算的区间，比较两个模型时要在同一批题上逐题相减再重抽。分桶能把平均数背后的弱项拽出来：本章按公式类型看不出差别，按噪声类型却发现 SFT 最不会修上下标错位和丢失的括号。泄漏检查只能给出下界，要写清楚查了什么、没查什么。错例表是用来提出假设的，先抽查标签，本章第一个该修的是评测器本身。所有决定都在 val 上做，test 只报告；在 test 上挑 20 次，就能凭空造出约 0.04 的提升。

复习时抓住下面几条：

- **抽样波动**：n 道独立的 0/1 题，$\mathrm{SE}(\hat p)=\sqrt{p(1-p)/n}$，正态 95% 区间是 $\hat p\pm1.96\,\mathrm{SE}$。区间半宽是 $1/\sqrt n$ 量级，想把它缩一半要 4 倍的题。比例为 0 或 1、或 n 较小时用 Wilson 区间。
- **bootstrap**：把手里的 n 道题当总体，有放回地重抽 n 个题目下标，模型输出不重跑，在新卷子上算一次统计量；重复 B 次，取第 2.5 和第 97.5 百分位。区间宽度由 n 决定，B 只决定蒙特卡洛误差。CER 这类比值要让分子、分母用同一组下标各自求和再相除。它在三种情况下会失灵：计数为 0 或 n 时区间塌成一点，改用 Wilson；n 太小；样本不独立（同一目标的多个带噪版本），这时按组重抽。
- **配对比较**：$d_i=b_i-a_i$，$\mathrm{Var}(\bar d)=[\mathrm{Var}(a)+\mathrm{Var}(b)-2\,\mathrm{Cov}(a,b)]/n$。同一批题上两个模型的对错通常正相关（Cov > 0），配对把共同的题目难度抵消掉，区间更窄；协方差为 0 时两种算法一样，为负时配对反而更宽。对 0/1 得分，$\mathrm{Var}(d)=\text{不一致题数}/n-\bar d^{\,2}$。配对 bootstrap 让两个模型用同一组下标重抽。`p_b_not_better` 只是描述性数字，不是 p 值。
- **McNemar 检验**：只看不一致的两格 $n_{10}$、$n_{01}$，原假设下每道不一致的题偏向哪边各占一半；$\chi^2=(n_{01}-n_{10})^2/(n_{01}+n_{10})$ 大于 3.84 对应双侧 p < 0.05，不一致的题很少时用精确二项检验。
- **分桶**：按参考答案分，边界事先写死，表里必须有题数和区间。桶多了总有一个看起来极端的（多重比较），分桶发现的弱项是假设，要在新实验上再验证。
- **泄漏**：规范键精确重叠在本章按划分构造为 0，也要实测确认；MinHash + LSH 的近重复检查给的是下界（LSH 会漏，参考集可能只取了一部分）；基座的预训练数据查不到，要在报告里写明。
- **评测协议**：val 用来调参、选模型、看错例；test 冻结，选型冻结后预先登记的候选各评一次，不根据 test 改任何设置，最终报告定稿前不看 test 错例。k 个真实水平相同、分数相互独立的候选在 test 上挑最好，期望偏差约为 $\sigma c_k$，p = 0.7、n = 500、k = 20 时约 +0.038；候选之间对错相关时偏差更小。
- **最常见的错误**：配对比较时两个模型各自重抽下标，或两个预测文件的题目顺序不一致；比例为 0 时用百分位 bootstrap；看 test 分数做选择。
