## 答案与提示

**概念 17.1** 不是卷积，是一个对每个位置做相同线性变换的层。和 `nn.Linear` 计算同一个函数 y = xW + b。`Conv1D` 存 W，形状 (in, out)，算 `x @ W + b`；`nn.Linear` 存 Wᵀ，形状 (out, in)，算 `x @ weight.T + b`。

**概念 17.2** `parameters()` 的结果 124,439,808 是参数量。`state_dict()` 按名字列出，`lm_head.weight` 和 `transformer.wte.weight` 是同一个张量，被算了两次，多出 V·d = 38,597,376，得到 163,037,184。

**概念 17.3** 检查名字一一对应、形状一一相同。检查不出：方阵（attn.c_proj，768 × 768）忘了转置；q、k、v 切分顺序错；用错激活函数（这根本不涉及权重）。

**概念 17.4** （a）dropout 在训练模式下随机置零，两边每次输出都不同；（b）bf16/fp16 的舍入误差比 fp32 大几个数量级，会掩盖小 bug；（c）SDPA 等融合实现的运算顺序和显式矩阵乘不同，多一个误差来源（通常仍在容差内，但排查时少一个变量更好）。

**概念 17.5** 不能。logits 误差 0.075，相对最大 |logit| 是 4.8 × 10⁻⁴，比正确转换大约一千倍（tour 第 4、10 部分）。它在这段输入的贪心解码上没改变 argmax，但换输入、换采样、或者在此基础上微调，差异都可能显现。模型是用 tanh 近似训练的，就应该用 tanh 近似推理。

**概念 17.6** `n_embd`：张量形状不符，加载失败。`layer_norm_epsilon`（改变归一化的数值）、`activation_function`（换激活函数）会改变输出。注意前提是"构造之前改"：对一个已经加载好的模型直接改 `model.config` 的字段，不会重建 LayerNorm 或激活模块，输出不变。`attn_pdrop` 在 eval 下不起作用；`task_specific_params` 只是生成的默认建议；`summary_type` 属于序列分类头，语言模型头不用。

**概念 17.7** 位置 t 的信息是 `wpe` 的第 t 行，表只有 1024 行，第 1025 个位置没有对应的向量。RoPE 没有表，位置是按公式算出的旋转角度，任意位置都能算；但训练长度之外效果不一定好（第 10 章）。

**概念 17.8** 见正文 17.10 节：RoPE（相对位置、无固定表、可配合长文本训练拉长上下文）、RMSNorm（更省、效果相当）、SwiGLU（同参数量效果更好）、GQA（KV cache 更小）、Q/K norm（稳定训练）、无偏置（简化）、大词表（17.9 节样本上中文和代码的 token 数约减半）。

**手算 17.3**
1. x @ W_c = [1·1 + 2·0, 1·0 + 2·1, 1·2 + 2·1, 1·1 + 2·0, 1·0 + 2·2, 1·3 + 2·1] = [1, 2, 4, 1, 4, 5]，加偏置得 [1, 2, 4, 1, 5, 6]。q = [1, 2]，k = [4, 1]，v = [5, 6]。

3. q 片是单位阵，转不转置都一样，q 仍是 [1, 2]——这个例子里忘了转置"碰巧"没事。这正说明对拍要用一般的随机权重，不要用特殊结构的矩阵（单位阵、对称阵）做测试。

**调试 17.1** `view` 按内存顺序（行优先）重新解释数据。(768, 2304) 的权重在内存里是一行一行存的，`view(3, 768, 768)` 把前 768 × 768 个数——也就是前 256 行（每行 2304 个数）——当成第一片。真正的 q 片是"所有 768 行的前 768 列"，两者完全不同，但形状都是 (768, 768)，所以 strict 加载照样通过。偏置是一维的，`view(3, 768)` 恰好就是按顺序切成三段，所以是对的，这反而让人误以为切分逻辑没问题。改法：`q_w, k_w, v_w = w.split(d, dim=-1)`（沿输出维切），再各自转置；或者先转置再切：`w.T.split(d, dim=0)`。

**调试 17.2** 误差约 10⁻¹、从第一个块就开始，又不改变 top-1，说明是一个"小而系统"的差异：(1) GELU 用了精确式——检查 `activation`；(2) LayerNorm 的 eps 用错（例如 1e-6）——打印 `ln_1.eps`；(3) 注意力缩放用了 1/√d 而不是 1/√head_dim——这个通常误差更大，会改变 top-1。逐个换回去重新对拍，看哪个让误差回到 10⁻⁵。

**调试 17.3** 长度 1 时注意力矩阵是 1 × 1，softmax 后恒为 1，输出等于 v 的投影，与 q、k 无关，所以 q、k 互换看不出来。v 和 q 互换能看出来，因为输出直接取决于 v。测试至少用几个 token。

**调试 17.4** 应该保留**最后**的 token（生成要接着结尾写），而不是最前面的；并且要给生成留位置：用本章的 `generate_greedy` 生成 n_new 个 token 时，输入最多保留最后 1024 − n_new 个（它不做滑窗，总长超过 1024 会报错）。另一种做法是自己写滑窗生成，每步只把最近 1024 个 token 送进模型。无论哪种，模型都看不到更早的内容；需要更长上下文就要换模型。

**调试 17.5** 旧版本的 state_dict 里还保存着每层的 `attn.bias`（因果 mask，1 × 1 × 1024 × 1024）和 `attn.masked_bias` 缓冲区，它们不是参数，但会被 `state_dict()` 列出来。tour 第 1 部分打印的"state_dict 中非参数元素"在本项目的版本下是 0（本项目观察：transformers 5.19.0）。
