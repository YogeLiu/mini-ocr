## 答案与提示

**18-1** 基础模型只会续写下一个 token；指令模型经过后训练，看到对话格式会以助手身份回答。指令模型也能用直接续写格式调用（它仍是一个语言模型），但权重是后训练过的，所以分数不能当作基础模型的分数（18.3.3 节）。

**18-2** 无错样本用来测"会不会把对的改坏"。全是有错样本时，改坏率的分母为 0，根本算不出来，"宁可错改"的倾向就没有专门的指标去量。一种偷懒策略是：不管输入是什么，都输出一个简单、规整、mathtext 一定能解析的公式，这会抬高可解析率；但 EM_norm 和 CER 会立刻暴露它（内容全错，编辑距离很大）。另一种是"每条都动一点"，例如看到 `_` 就猜成 `^`：它在 CER 上会因为新增错误被扣分，但没有无错样本时，你无法单独看出它"把对的改坏"的倾向有多强。混入无错样本以后，改坏率会直接量出这一点。

**18-3** 数学结论：照抄的预测等于输入，无错样本的输入等于目标，所以规范化后一定相等，改坏数为 0。改坏率是比例，不能低于 0，所以没有方法能比照抄更低，只能持平。

**18-4** 可解析率只问"mathtext 能不能解析"，不问"对不对"。模型倾向于输出更简单、更常见的写法，顺手丢掉了 mathtext 不支持的结构，所以更容易解析，但内容已经不对了。它适合发现"语法完全坏掉"的输出（如花括号不配对），不能说明改得对。

**18-5** 每种提示的测试分数 = 真实水平 + 随机波动。挑 20 个里最大的，挑中的往往是随机波动最正的那一个，所以最大值的期望高于真实水平（选择偏差）。测试集一旦参与了挑选，就不再是独立的留出集。

**18-6** 参考：(1) 分布：真实错误随图片质量和位置集中出现，合成噪声独立均匀；若真实数据错误更密集，合成分数偏高。(2) 种类：真实 OCR 有整段漏识、结构错误，合成数据没有；这类难错缺席，合成分数偏高。(3) 可恢复性：`script_shift` 这类改不回来的错在合成数据里比例固定；若真实数据里这种错更少，合成分数可能偏低。言之成理即可。

**18-7** $z^2/n=3.8415/500=0.007683$。123/500：$\hat p=0.246$，$\tilde p=(0.246+0.003842)/1.007683=0.2479$，$w=1.96\sqrt{0.0003710+0.0000038}/1.007683=0.0377$，区间约 [0.210, 0.286]。191/500：$\hat p=0.382$，$\tilde p=(0.382+0.003842)/1.007683=0.3829$，$w=1.96\sqrt{0.0004722+0.0000038}/1.007683=0.0424$，区间约 [0.340, 0.425]。不重叠（0.286 < 0.340），可以说在这 500 条上直接续写的 EM_norm 低于照抄（严格的配对检验见第 22 章）。若只有 20 条，4/20 的区间是 [0.081, 0.416]，7/20 是 [0.181, 0.567]，大面积重叠，就分不清了。以上区间都与 tour 打印的一致。

**18-8** (a) $\hat p=0$ 时 $\tilde p = \frac{z^2/2n}{1+z^2/n}$，$w=\frac{z\cdot z/2n}{1+z^2/n}$，上界 $\tilde p + w = \frac{z^2/n}{1+z^2/n}=\frac{z^2}{n+z^2}$。(b) n=7：$3.8415/10.8415\approx0.354$，"0/7"只说明真实改坏率大概不超过 35%，非常粗。n=630：$3.8415/633.8415\approx0.0061$，上界约 0.6%，已经相当精确。

**18-9** (a) 先要"没被预留"（概率 0.8），再要六种都没抽中（$0.6\times0.7\times0.65\times0.7\times0.7\times0.7\approx0.0936$），联合概率 $0.8\times0.0936\approx0.0749$。(b) $0.2+0.0749\approx0.275$（数学结论）。(c) 多出来的部分来自"抽中了类型但这条公式上没有可施加的位置"（规则 3），以及极少数加噪后恰好与原文相同而被记为无错的情形。

**18-10** (a) $(551.79-88.79)/3\approx154.3$。(b) $(40960-256-253)/154.3\approx262$ 个。粗算的原因：每个示例的长度不同，平均值不代表最坏情况；配置上限也不等于模型在这个长度上仍然好用（待验证）；CPU 上的时间和内存也会先成为瓶颈。(c) 说明多出的时间和更长的上下文有关，而不是因为生成更多：少样本的提示长约 6.3 倍，生成的 token 却更少。更长的上下文既增加开头处理提示（prefill）的时间，也让之后生成每个 token 时的注意力计算变多；tour 只记录了总生成时间，两部分各占多少需要分阶段测量才能回答。

**18-11** (a) 编辑距离 1，CER = 1/117 ≈ 0.0085。(b) 同样是 1 次删除，≈ 0.0085。(c) 规范化会去掉 token 之间的空白，编辑距离为 0，CER = 0。这就是照抄在 `extra_space` 样本上"改对"的原因（18.2.1 节）。

**练习 18.1 提示** 照抄：`[e.source for e in examples]`；标准答案：`[e.target for e in examples]`；也可以直接用 `copy_baseline` / `oracle_baseline` 核对。

**练习 18.2 提示** 规则纠错器只会动这两种拼写，所以它的改坏率应接近 0；fix_rate 取决于子集里这两种错误有多少（多数 `command_typo` 是随机字母替换，不在规则表里）。

**练习 18.3 提示** 若只在数学定界符外去标点，目标以句号结尾、模型也输出了句号的样本不会再被抽取器改坏，18-16 中的那几条应恢复。规则是在验证集上定的，这是允许的；它从此固定，测试集只在定稿时用它评一次。

**18-12** 没有传 `enable_thinking=False`，Qwen3 模板默认开启思考。看 `text` 的末尾：关闭时以预填的 `<think>\n\n</think>\n\n` 结尾，开启时停在 `<|im_start|>assistant\n`。

**18-13** 开头会有两个 `<s>`，模型看到的输入和训练时的格式不同，输出可能变差。检查方法：打印 `ids[0, :5]` 并 `convert_ids_to_tokens`。`generate_greedy` 对模板字符串一律用 `add_special_tokens=False` 编码。Qwen3-0.6B 的 `bos_token` 是 `None`，tokenizer 不会自动加 BOS，所以碰巧不重复。

**18-14** (1) 在测试集上选提示，测试分数带有选择偏差；(2) 只报点估计，没有区间，"优于其他 11 种"没有根据。补救：在报告里写明根据测试集改过设置；改在验证集上选提示；按 0.10.1、5.1.3 节补一份新的留出测试集，选型冻结后，预先登记的候选在新集上各评一次并给出区间，不据此改设置；开发期间不看 test 错例，最终报告定稿后才可解封。

**18-15** val 前 4 条恰好都是有错样本（本项目观察：第 5 条才是第一条无错样本），改坏率的分母是 0，无法计算。`null` 表示"没有数据，不知道"，0 表示"测过了，一条都没改坏"。填 0 是把"不知道"说成了"很好"。

**18-16** 目标以句号（或逗号）结尾，模型的输出也带着这个标点，原始输出完全正确；抽取器去掉了末尾的孤立标点，反而改坏。GPU 运行里逐条检查：少样本 + 格式约束的 49 条全是这种情况；续写格式的 88 条里有 84 条是。验证：在 `--out` 保存的 JSONL 里筛出 `pred` 规范化后等于 `target`、`extracted` 不等于的样本，看两者的差别是否只有末尾的标点。

**18-17** 防止评测题进入提示（泄漏）。硬塞进去后，若示例恰好是某些验证题本身或近似题，模型可以照抄示例答案，分数虚高；它测的是"抄提示"的能力，不是纠错能力。

**18-18** 见 18.4 节：固定数据和划分（否则不同人测的不是同一批题）；先定指标和抽取规则（否则会挑对自己有利的指标）；固定解码（否则分不清是提示的差别还是随机性）；只在验证集上做决定（否则测试分数偏高）；记录成本（否则无法和训练方法公平比较）；给出区间（否则会把噪声当成差别）。

**18-19** 见 18.3.2 节的渲染文本：`<|im_start|>system\n…<|im_end|>\n<|im_start|>user\n…<|im_end|>\n<|im_start|>assistant\n<think>\n\n</think>\n\n`，模型从最后的 `</think>\n\n` 之后开始生成。

**18-20** 改坏率 = 无错样本中预测（规范化后）≠ 目标的条数 / 无错样本数；fix_rate = 有错样本中预测（规范化后）= 目标的条数 / 有错样本数。一个方法可以"改对很多但也改坏很多"，合在一起的 EM 会掩盖这种取舍。分母为 0 时报告"无法计算"（`None`），不能报 0。
