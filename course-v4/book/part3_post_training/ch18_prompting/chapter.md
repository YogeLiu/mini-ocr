**学完本章，你能做到：**

> **回顾**（本章用到的旧工具）
> - **规范化与泄漏**：`normalize_latex` 把规则覆盖到的等价写法变成同一个串；latex-v1 划分按规范键分组，规范键相同的公式不会跨集合。规范化器没覆盖的等价写法仍可能被分开（0.10.3 节）。（第 0、6、12 章）
> - **贪心解码**：每一步取概率最大的 token，结果确定、可复现。（第 14 章）
> - **mathtext 可解析率与 Wilson 区间**：用 `can_parse` 近似"能否编译"；比例的 95% 区间用 Wilson 区间。（第 13、14 章）
> - **CER**：语料级字符错误率 = 编辑距离之和 / 参考长度之和。（第 0 章）

## 18.1 任务数据：合成的 OCR 后纠错

### 18.1.1 任务是什么

OCR 后纠错的输入是一个 OCR 系统认出来的 LaTeX，可能有错；输出是改正后的 LaTeX。比如：

| 输入（带噪） | 输出（干净） | 错在哪里 |
|---|---|---|
| `\alpha+\bata` | `\alpha+\beta` | 命令拼错 |
| `x^2}` | `x^{2}` | 丢了一个花括号 |
| `x_{2}` | `x^{2}` | 上标认成了下标 |

后纠错只看文字，不看图片。这很像校对员拿着一份打字稿挑错：他看不到原稿，只能凭"这里不像正常的公式"来判断。这也决定了它的上限——有些错，光看文字根本改不回来（`x_{2}` 本身是合法公式，凭什么说它该是 `x^{2}`？）。

### 18.1.2 为什么用合成数据

理想的数据是"真实 OCR 输出—人工校对答案"对。我们没有足够多的这种数据，而且要它有三个麻烦：要先跑一个 OCR 系统；要有人逐条校对；不同 OCR 系统的错误各不相同，换一个系统数据就过时了。

合成数据走另一条路：拿干净公式，人为加上 OCR 式的错误。干净公式就是答案，不用校对；错误类型和比例都能控制；想要多少有多少。代价是它和真实错误的分布不一样，18.1.5 节专门说。

### 18.1.3 怎样造：六种错误

数据模块是 `miniocr/data/postcorrect.py`，版本名 `postcorrect-v1`。它在每个干净公式上按下表加噪：

| 类型名 | 模拟什么 | 例子（目标 → 输入） |
|---|---|---|
| `confusable` | 形近字符认错 | `l → 1`、`O → 0`、`\times → x` |
| `drop_brace` | 丢一个花括号 | `x^{2} → x^2}` |
| `command_typo` | 命令名里的字母认错 | `\beta → \bata`、`\sum → \surn`（`m` 认成 `rn`） |
| `missing_arg` | 漏掉一个参数 | `\frac{a}{b} → \frac{a}` |
| `script_shift` | 上下标互换 | `x^{2} → x_{2}` |
| `extra_space` | 多出空格 | `x+y → x+  y` |

上表的例子来自 tour 第 1 部分。加噪的规则是：

1. 先以 `clean_fraction`（默认 0.2）的概率决定这条样本"不加错"。
2. 否则，每种错误类型各掷一次硬币（概率在 `NoiseConfig.rates` 里，每类可单独调），抽中的类型打乱顺序，最多施加 `max_errors`（默认 2）处。
3. 抽中的类型在这条公式上找不到位置（比如没有 `\frac` 就不能漏参数），就跳过。
4. 每施加一处，记下类型、位置、改前、改后。第 22 章按错误类型分桶，靠的就是这份记录。

**为什么要保留无错样本？** 真实的 OCR 输出大部分是对的。一个模型如果"见什么都改"，在全是错的数据上看起来很勤快，到了真实场景就会把对的改坏。无错样本就是专门抓这种毛病的，对应 18.2 节的"改坏率"。

**为什么要确定性？** 每条样本的随机种子由"版本名、seed、划分名、公式、它在划分里的序号"的 SHA-256 决定。所以同一条公式无论你先造还是后造、造 100 条还是 5000 条，加的噪声都一样。"val 前 100 条"因此是一个固定的子集，你和同学跑出来的是同一批题。

### 18.1.4 继承划分，不跨集合泄漏

后纠错数据不重新划分，直接继承第 6 章定义、第 12 章 12.3.5 节核验过的 latex-v1：train 542,339 条、val 5,001 条、test 5,000 条（本项目观察，tour 第 1 部分）。latex-v1 按规范键分组，所以 tour 第 1 部分按 `normalization_key(target)` 检查三个集合两两的交集，结果都是 0。

少样本提示要用的示例，一律从 **train** 里取（`few_shot_pool`），`miniocr/prompting.py` 发现示例不是 train 的就直接报错。把验证集的题当示例塞进提示，等于考试前把答案发给考生。

val 全集的实际统计（本项目观察，tour 第 1 部分，5,001 条）：

| 统计 | 值 |
|---|---|
| 无错样本比例 | 0.311 |
| 每条平均错误数（含无错样本） | 1.11 |
| 含 `confusable` 的样本 | 1,230 |
| 含 `command_typo` 的样本 | 1,185 |
| 含 `extra_space` 的样本 | 964 |
| 含 `script_shift` 的样本 | 942 |
| 含 `drop_brace` 的样本 | 916 |
| 含 `missing_arg` 的样本 | 324 |

无错比例 0.311 比配置的 0.2 高，原因有两个：一是没被预留为无错的样本，六种类型的硬币也可能一个都没抽中（加噪分支内概率约 0.094，乘上未被预留的 0.8，联合概率约 0.075，数学结论，见习题 18-9）；二是第 3 条规则，抽中的类型在这条公式上不适用就跳过，有的样本一处错也没加上。`missing_arg` 最少，因为它只能用在 `\frac`、`\sqrt` 这类命令上。

### 18.1.5 合成噪声的局限

**在合成数据上的分数，不能直接当成"在真实 OCR 上的分数"。** 理由有三条。

- **分布不同。** 真实 OCR 的错误跟图片有关：字小、模糊、上标贴得近，错得就多；长公式后半段错得比前半段多；错误常常成片出现。我们的噪声是按固定概率独立撒的，跟图片毫无关系。
- **种类不全。** 真实 OCR 还会整段漏掉、结构认错（把矩阵认成几行文字）、多认出不存在的符号。这些我们都没有模拟。
- **有的错改不回来，有的错太好改。** `x^{2}` 被换成 `x_{2}` 以后仍是合法公式，纯文本模型没有理由改它；而 `\surn` 这种拼写错，任何见过 LaTeX 的模型都能一眼认出来。真实数据里两类错误的比例和我们的不同，所以总分也会不同。

那为什么还用？因为本部分的目的是**学会后训练的方法**：怎样构造监督信号、怎样比较方法、怎样分析错例。这些方法在合成数据上学，和在真实数据上学是同一套。第四部分有了自己的公式 OCR 以后，你就能拿到真实的 OCR 输出，再来检验这里的结论。

> **停下来想一想：** 如果把 `clean_fraction` 设成 0，模型最"聪明"的偷懒策略是什么？哪个指标会让这种偷懒原形毕露？

## 18.2 指标：怎样给"改错"打分

第三部分从本章开始用第 0 章 0.9.3 节定下的**文本后纠错面板**，必报 EM_norm、CER、改坏率、fix_rate，详细定义和两个基线锚点都在这一节。

评测模块是 `miniocr/eval/postcorrect_eval.py`，核心函数 `score_postcorrect(examples, preds)`。它一次给出下面这些指标，其中 EM_raw 不是必报项，可解析率（parse_rate）是可选的诊断项，要和标准答案的可解析率一起读：

| 指标 | 定义 | 回答什么问题 |
|---|---|---|
| EM_raw | 预测与目标逐字符相同的比例 | 一字不差吗？ |
| EM_norm | `normalize_latex` 后相同的比例 | 写法不同但意思一样，算对 |
| CER | 规范化字符的编辑距离之和 / 目标长度之和 | 差多少？（越低越好） |
| 改坏率 | 在**输入本来正确**的样本里，预测（规范化后）≠ 目标的比例 | 会不会把对的改错？ |
| fix_rate | 在**输入有错**的样本里，EM_norm 的比例 | 错的改回来了多少？ |
| 可解析率 | 预测能被 mathtext 解析的比例 | 语法过不过关？ |

每个比例都给出成功数、分母和 Wilson 95% 区间；CER 给固定种子、1000 次重抽的 bootstrap 区间。改坏率的分母只是无错样本，样本少时分母可能是 0，这时函数返回 `None`，不是 0。

本章 18.5.2、18.5.4 节的表报全了四个必报项。18.6 节的小实验只列要讨论的几项：18.6.4 节没有列 fix_rate，18.6.5 节没有列改坏率和 fix_rate。

### 18.2.1 两个锚点：照抄与标准答案

在看任何模型之前，先算两个不需要模型的分数：

- **照抄（copy）**：预测 = 输入，什么都不改。
- **标准答案（oracle）**：预测 = 目标。

照抄是**底线**：一个连照抄都比不过的方法，不如不用。标准答案告诉你 EM、CER、改坏率、fix_rate 这些**正确性指标**的理想值；它的可解析率只是这份数据的参考值，不是可解析率的上限（18.5.3 节会看到错误的输出也能比它更"可解析"）。

val 全集上的结果（本项目观察，tour 第 2 部分，5,001 条，不需要模型）：

| 指标 | 照抄 | 标准答案 |
|---|---|---|
| EM_raw | 0.311 [0.299, 0.324] | 1.000 |
| EM_norm | 0.359 [0.346, 0.372] | 1.000 |
| CER | 0.0373 [0.0351, 0.0394] | 0 |
| 改坏率（分母 1,557） | 0 | 0 |
| fix_rate（分母 3,444） | 0.069 [0.061, 0.078] | 1.000 |
| 可解析率 | 0.343 [0.330, 0.356] | 0.599 [0.586, 0.613] |

这张表里有三个值得停下来看的数字。

**第一，照抄的 CER 只有 0.0373。** 一条 val 公式平均 117 个字符（本项目观察），而平均只有约 1 处小错，所以带噪输入和答案本来就很像。所以一个方法哪怕只是把公式重新排版一下，CER 都可能比照抄还差。后纠错是"少动为妙"的任务。

**第二，照抄的 fix_rate 不是 0，而是 0.069。** tour 第 2 部分按错误类型分桶：这 238 条全落在 `extra_space` 桶里，其他五种错误类型的照抄 fix_rate 都是 0。多出的空格在规范化时被抹掉了，只带这种错的样本，照抄也"改对了"。EM_raw 和 EM_norm 的差别就在这里。另外，"有错"是按原串定义的，有些错在规范化口径下根本不算错。

**第三，标准答案的可解析率只有 0.599。** 4 成干净公式 mathtext 解析不了（mathtext 只支持 LaTeX 的一个子集，不认识 `\begin{array}` 之类的环境）。所以看可解析率时，参照物是标准答案的 0.599，不是 1；而且它只说明语法，不说明对错。

> **停下来想一想：** 照抄的改坏率是 0，这是数学结论还是实测结论？任何方法的改坏率能比照抄更低吗？

## 18.3 基础模型与指令模型

### 18.3.1 两种模型

**基础模型**（base model）是预训练的直接产物，就是第 13 章那种"预测下一个 token"的模型，只不过大得多。你给它一段文字，它接着往下写。问它"请改正这个公式"，它可能接着写出第二个问题，因为网上的文字里，一个问题后面常常跟着另一个问题。

**指令模型**（instruct / chat model）是在基础模型上做了后训练（SFT、偏好优化、强化学习，第 19–25 章的内容）的模型。它学会了一种对话格式：看到"用户说了什么"，就以"助手"的身份回答。

本章用的 Qwen3-0.6B 属于后者。更准确地说，它是一个**混合思考**的后训练模型：同一个模型既能先写一段 `<think>…</think>` 推理再回答（思考模式），也能直接回答（非思考模式）。它的模型卡元数据里写着 `base_model: Qwen/Qwen3-0.6B-Base`，说明另有一个基础版本；本章没有下载它，所以书里不对 Base 版做任何断言。

### 18.3.2 chat template：消息变成了什么文本

指令模型的"对话"其实还是一串 token。负责把消息列表拼成这串 token 的规则叫 **chat template**，它存在 tokenizer 的配置里，用 `tokenizer.apply_chat_template` 调用。

下面是 tour 第 3 部分的真实输出（本项目观察）。消息是一条 system 指令加一条 user 输入 `\frac{a}{b}`，`enable_thinking=False`：

```text
<|im_start|>system
Correct OCR errors in the following LaTeX formula.<|im_end|>
<|im_start|>user
\frac{a}{b}<|im_end|>
<|im_start|>assistant
<think>

</think>

```

一共 33 个 token。逐段看：

- `<|im_start|>` 和 `<|im_end|>` 是特殊 token，标出每条消息的起止。角色名（system、user、assistant）就写在 `<|im_start|>` 后面。
- 最后一行 `<|im_start|>assistant` 加换行，是 `add_generation_prompt=True` 加上的，意思是"轮到助手说话了"。但模型并不是从这里开始生成，因为后面还跟着一段属于输入的内容。
- 末尾那个空的 `<think>\n\n</think>\n\n` 最容易看漏。关掉思考后模板里仍然有 think：模板**替模型预先填好一个空的思考块**，模型从 `</think>\n\n` 之后开始生成，直接写答案。

把 `enable_thinking` 换成 `True`，模板在 `assistant\n` 处就结束了，一共 29 个 token，少了预填的 4 个 token。这时模型会自己先写 `<think>`，再写一大段推理。对一个只想要一行公式的任务，这既慢又难解析，所以本章一律关闭。

还有一个细节：这个 tokenizer 的 `bos_token` 是 `None`（本项目观察）。模板拼好的字符串已经带了所有需要的特殊 token，所以再编码时要用 `add_special_tokens=False`。对 Qwen3 来说这一步碰巧不会出错；换成一个模板里已经写了 BOS、tokenizer 又会自动加 BOS 的模型，就会出现两个 BOS。`generate_greedy` 统一这样编码。

### 18.3.3 两种调用方式

既然对话只是一串 token，你也可以不用模板，直接写一段让模型续写的文字。本章把这叫"直接续写格式"：

```text
Correct OCR errors in the following LaTeX formula.
Noisy: <示例输入 1>
Corrected: <示例答案 1>
...
Noisy: <待改公式>
Corrected:
```

模型在 `Corrected:` 后面续写，遇到第一个换行就停。这是使用基础模型的标准姿势。用 chat 模板则是使用指令模型的标准姿势。tour 第 4 部分在同样的三条示例、同样的 val 子集上比较了两种方式，结果见 18.5.4 节。注意：两种方式用的都是同一份 Qwen3-0.6B 后训练权重，这个对比**不是**基础模型和指令模型的对比，不能由它推出"基础模型更适合这个任务"。

## 18.4 建立基线的流程

提示词怎么写，人人都有心得；基线可不可信，要看流程。我们的流程分六步。

### 18.4.1 第一步：固定数据和划分

数据版本写死：`postcorrect-v1`，噪声 seed=0，划分继承 latex-v1。评测子集是 val 的**前 n 条**，不是随机抽的 n 条。"前 n 条"在固定 seed 下永远是同一批题，换台机器、换个日子都一样。

### 18.4.2 第二步：先定义指标，再看结果

指标就是 18.2 节那张表，在看任何模型输出**之前**就定下来。先看结果再挑指标，等于射完箭再画靶子。

还要先定"怎样从模型输出里取答案"。模型可能回一句客套话再给公式，也可能给公式包上 `$…$`。本章同时报告两种口径：**原始输出直接评分**，和经过一个简单抽取器 `extract_formula` 之后再评分。抽取器的规则可以在验证集上看着错例改进（18.6.1 节），但同一次比较里所有方法必须用同一版规则重新评分，而且在评测试集之前冻结。

### 18.4.3 第三步：固定解码

一律用贪心解码，`do_sample=False`。理由很简单：同一个输入，贪心每次给出同一个输出，两次运行的差别只来自提示的差别。

要说明的是，Qwen3 的模型卡建议非思考模式用采样（temperature=0.7、top_p=0.8、top_k=20，待验证：这是官方推荐值，本章没有比较过）。我们为了可复现选择贪心，代价是分数可能和官方推荐设置下的不同。这种取舍要写进记录。

生成长度也要固定上限：每批 `min(256, 2×最长源公式 token 数 + 32)`。改错不应该让公式长一倍，所以这个上限是宽松的；碰到上限的条数会单独打印。

### 18.4.4 第四步：只在验证集上做决定

选哪个提示、示例取几条、抽取器怎么写，所有决定都只看 val。测试集按 0.10.1、5.1.3 节的协议：选型冻结后，预先登记的候选各评一次，只报告数字，不据此改任何设置；开发期间不看它的错例。

这条规则写进了代码：`evaluate(predict_fn, split="test")` 不加 `allow_test=True` 就直接抛出异常，在读任何数据之前（tour 第 10 部分）。这是一道"防手滑"的栅栏。

为什么这么严格？设想你试了 20 种提示，每次都看测试分数，挑最高的那个。即使 20 种提示真实水平完全一样，挑出来的最高分也会比真实水平高——你挑中的是运气最好的那一个。测试集被你"用"过以后，就不再是留出集了。

### 18.4.5 第五步：记录成本

提示方法不训练，但不是免费的。每次调用都要记：

- **提示 token 数**：少样本的示例越多，每次调用要处理的 token 越多。
- **生成 token 数**和**用时**：模型话越多越慢。
- **设备、dtype、线程数**：同样的实验在不同机器上用时可以差十倍。

本章的用时有两套：CPU（fp32、2 线程、batch_size=4）的独占测量，和 GPU（RTX 4090 租用、bf16、batch_size=32）上与其他任务共享时的测量。两者都不能推广到别的设备，GPU 的用时还偏大。

### 18.4.6 第六步：给出区间

在 20 条上测出 7 条对，你能说"准确率 35%"吗？只能说"点估计 0.35，95% Wilson 区间 [0.181, 0.567]"（数学结论；这是默认 CPU tour 里照抄的 EM_norm）。区间宽到接近 0.4，是因为 20 条太少。换到 2000 条上（GPU 运行里照抄是 725/2000，点估计 0.3625），区间收窄到 [0.342, 0.384]（数学结论）：样本数增加 100 倍，区间宽度大约缩小到十分之一。

再看一个极端情况：20 条里 0 条对。点估计是 0，但 Wilson 区间的上界是

$$\frac{z^2}{n+z^2} = \frac{1.96^2}{20+1.96^2} = \frac{3.8415}{23.8415} \approx 0.161$$

（数学结论；当成功数为 0 时 Wilson 区间下界为 0，上界化简成这个式子）。也就是说，"0/20"只能告诉你真实比例大概不超过 16%，不能说明它就是 0。n 加到 2000，上界会降到约 0.0019（数学结论）。

CER 不是比例，没法套 Wilson 公式，所以用 bootstrap：从 n 条样本里有放回地重抽 n 条，算一次语料级 CER；重复 1000 次，取第 2.5 和第 97.5 百分位。第 22 章会详细讲 bootstrap，以及怎样用"配对"比较两个方法。

本章所有比较都守一条底线：区间重叠时，不说谁更好。

## 18.5 三种提示的基线

### 18.5.1 三种提示

三种提示的文字都是 `miniocr/prompting.py` 里的常量，全部用 chat 模板、关闭思考：

- **零样本**（`zero_shot`）：system 消息是 "Correct OCR errors in the following LaTeX formula."，user 消息就是带噪公式。
- **少样本 k=3**（`few_shot`）：同样的 system 消息，后面接 3 轮"user 给带噪公式、assistant 给干净公式"的示范对话，最后才是待改的公式。示例由 `few_shot_pool(3)` 从 train 中确定性选取，都是有错样本。
- **少样本 + 格式约束**（`few_shot_strict`）：在少样本的 system 消息后追加 "Return only the corrected LaTeX formula. Do not explain. Do not add $ delimiters or Markdown code fences."

少样本的示范对话有两个作用：告诉模型"任务长什么样"，也告诉模型"答案的格式长什么样"——示范里的 assistant 只回一行公式，不说别的话。

### 18.5.2 结果

本节和 18.6 节的模型结果来自一次 GPU 运行：**本项目观察，RTX 4090 48GB（租用），bf16，batch_size=32，贪心**；主实验（tour 第 2、5、6、7 部分）用 val 前 2000 条，第 4、8、9 部分用 val 前 500 条（`--n 2000 --sub-n 500`，命令见 lab 0 节）。提示方法的指标是经 `extract_formula` 抽取后的口径；比例写成"成功数/分母"，方括号是 Wilson 95% 区间，CER 的方括号是 bootstrap 95% 区间。

| 方法 | EM_norm | CER | 改坏率 | fix_rate | 可解析率 |
|---|---|---|---|---|---|
| 照抄 | 725/2000 [0.342, 0.384] | 0.041 [0.037, 0.045] | 0/630 [0, 0.006] | 95/1370 [0.057, 0.084] | 700/2000 |
| 零样本 | 113/2000 [0.047, 0.067] | 0.148 [0.139, 0.158] | 562/630 [0.865, 0.914] | 45/1370 [0.025, 0.044] | 1479/2000 |
| 少样本 k=3 | 130/2000 [0.055, 0.077] | 0.137 [0.127, 0.147] | 553/630 [0.850, 0.901] | 53/1370 [0.030, 0.050] | 1518/2000 |
| 少样本 + 格式约束 | 152/2000 [0.065, 0.088] | 0.136 [0.126, 0.147] | 527/630 [0.806, 0.863] | 49/1370 [0.027, 0.047] | 1392/2000 |

|---|---|---|---|---|
| 零样本 | 88.8 | 99.4 | 608 秒 | 0.30 秒 |

用时这两列要打折扣看：运行期间同一张卡上还跑着其他章节的实验，GPU 利用率一直被占满，用时比独占时长得多（同一配置在开跑前的 64 条探测里，每条只要 0.17–0.21 秒）。所以 GPU 用时只能说明"量级"，不能用来比较三种提示谁更省。比较成本时请看 token 数，或者看 CPU 上的独占测量：默认 tour（val 前 20 条，CPU fp32，2 线程）里，零样本每条 7.2 秒，两种少样本 9.9 秒和 9.5 秒（本项目观察）。

**学习者怎样复现。** 没有 GPU 也能走完全部流程：默认 `tour` 在 CPU 上只取 val 前 20 条，全程约 25 分钟（本项目观察，本机 CPU 两线程）。20 条的区间很宽，比如照抄的 EM_norm 是 7/20 [0.18, 0.57]，三种提示都是 0/20 [0, 0.16]，只够检查流程；想得到上表这样窄的区间，需要在 GPU 上用 `--n` 放大（lab 0 节有命令）。

### 18.5.3 怎样读这张表

**结论一：三种提示都远远不如照抄。** 照抄的 EM_norm 区间是 [0.342, 0.384]，最好的提示是 [0.065, 0.088]；CER 0.041 对 0.136 以上；改坏率 0 对 0.8 以上。每一项的区间都隔得很远。在这 2000 条上，"什么都不改"明显比"让 Qwen3-0.6B 改"好。连提示方法最擅长的 fix_rate（把有错的改对），照抄也不输：照抄靠规范化"白捡"了 95 条只带多余空格的样本，三种提示只改对了 45–53 条。

**结论二：输的根源是改坏。** 630 条本来正确的输入，被改坏了 527–562 条。把无错样本上的改动按规范化 token 逐条对齐统计，模型不是在"改错"，而是在"重写"：最常见的是**去掉公式末尾的句号或逗号**（18.6.2 节专门讨论），其次是删掉对齐用的 `&` 和换行 `\\`、增删花括号，零样本还会插入原文没有的 `\frac`（本项目观察，对 GPU 运行保存的逐条输出做的统计）。有错的样本上它也会自由发挥，比如带噪输入里的 `\Slgma_{q+1}`，少样本把它改成了原文没有的 `\mathcal{G}_\mu^{q+1}`，而不是 `\Sigma_{q+1}`。一个 0.6B 的通用模型没有学过"只动错的地方，别的地方一个字符都别碰"。

**结论三：格式约束少改坏了一些，但三种提示的差别远小于它们和照抄的差别。** 2000 条让区间窄到可以看出一点差别：少样本 + 格式约束的改坏率 [0.806, 0.863] 和零样本的 [0.865, 0.914] 不重叠；EM_norm 的区间则刚好擦边（[0.065, 0.088] 对 [0.047, 0.067]），CER 三者重叠。所以能说的只有：在这 2000 条上，加了格式约束的少样本提示比零样本少改坏了一些。这是同一批题上的比较，严格的结论要用第 22 章的配对 bootstrap。至于"哪个提示好到可以用"——没有一个。

**结论四：可解析率高不等于改得好。** 三种提示的可解析率在 0.70–0.76，比标准答案的 0.600 还高，区间互不重叠。可它们 EM_norm 都不到 0.08。原因是模型倾向于写"更规整、更常见"的 LaTeX，顺手扔掉了 mathtext 不认识的结构。可解析率只能用来发现"语法完全坏掉"，不能用来说明"改得对"。

这些结论都只针对 val 前 2000 条、Qwen3-0.6B、本章的三条提示、bf16 和贪心解码。换大模型、换提示、换采样，结果都可能不同；不要推广成"提示词没用"。

### 18.5.4 直接续写 vs chat 模板

tour 第 4 部分把同样的指令和同样的 3 条 train 示例，分别包装成"直接续写格式"和 chat 模板，在 val 前 500 条上比较（本项目观察，RTX 4090 租用，bf16，`--sub-n 500`）。下表是原始输出直接评分的口径（续写格式已在第一个换行处截断）；照抄一行是同一批 500 条上的锚点（tour 第 2 部分，`--n 500`，不需要模型）：

| 调用方式 | EM_norm | CER | 改坏率 | fix_rate |
|---|---|---|---|---|
| 照抄 | 191/500 [0.340, 0.425] | 0.034 [0.028, 0.042] | 0/163 | 28/337 [0.058, 0.117] |
| 直接续写 | 123/500 [0.210, 0.286] | 0.074 [0.058, 0.091] | 82/163 [0.427, 0.579] | 42/337 [0.094, 0.164] |
| chat 模板（少样本） | 6/500 [0.006, 0.026] | 0.149 [0.131, 0.166] | 158/163 [0.930, 0.987] | 1/337 [0.001, 0.017] |

续写格式比 chat 模板好得多：EM_norm、CER、改坏率的区间都不重叠。看输出就明白：在 `Noisy: … / Corrected:` 的格式里，模型大体是把输入抄一遍再动几个字符；在 chat 模板里，它以"助手"的身份重新排版了整个公式。但续写格式仍然不如照抄：EM_norm 和 CER 都更差，而且改坏了一半无错样本。它的 fix_rate（42/337）点估计比照抄（28/337）高，说明它确实改对了一些错，但两个区间重叠，500 条还说不清。

还有一个插曲：续写格式的输出经过抽取器以后，EM_norm 从 123/500 掉到 49/500，改坏率从 82/163 升到 133/163。逐条检查，抽取器在 88 条上把本来正确的输出改错了，其中 84 条只是去掉了末尾的标点，而目标恰好以句号或逗号结尾（18.6.2 节）。

### 18.5.5 填进 R2 的第一行

项目报告 R2 的结果表，第一行就是本章的提示基线。一行要写清楚这些东西，缺一样别人就没法复现或比较：

- 数据：`postcorrect-v1`、噪声 seed、评测子集（val 前多少条；本章 GPU 运行是 2000 条）。
- 方法：模型快照、提示常量名、调用方式（chat 模板、`enable_thinking=False`）、示例来源和数量。
- 解码：贪心，生成上限规则。
- 指标：EM_norm、CER、改坏率（带分母）、可解析率，都带区间；注明是否经过抽取器。
- 成本：设备、dtype、批大小、平均提示与生成 token、每条用时（GPU 若与别的任务共享，要注明用时不可比）。
- 对照：同一子集上照抄和标准答案的分数。

测试集的数字要等选型冻结：预先登记的候选用 `allow_test=True` 各评一次，再填进来。lab.md 末尾有一张空表，就是这一行的模板。

## 18.6 提示基线的局限

上一节的结果已经说明"不训练"不够用。这一节换个角度：除了分数低，提示方法本身还有哪些毛病？后面章节的训练方法会解决或缓解其中一些。本节的数字都来自 18.5.2 节那次 GPU 运行（RTX 4090 租用，bf16）。

### 18.6.1 输出格式不稳定

我们要的是"一行公式"。模型给的是什么？tour 第 6 部分统计了 val 前 2000 条的原始输出（同一条输出可以同时有几种问题；"解释/多行"是启发式判断，会有误报）：

| 提示 | 空输出 | 解释/多行 | 包了 `$` | 代码围栏 | think 块 |
|---|---|---|---|---|---|
| 零样本 | 0 | 1993 | 1953 | 17 | 0 |
| 少样本 k=3 | 0 | 618 | 1846 | 0 | 0 |
| 少样本 + 格式约束 | 0 | 240 | 1416 | 0 | 0 |

零样本的典型输出是"The OCR errors in the LaTeX formula have been corrected as follows:"开头，接一个 `$$…$$` 块，有时再来一句"Let me know if you need further assistance!"。少样本的示范对话把解释压下去了不少，但 `$` 照包不误。明确写上"不要加 `$`"之后，2000 条里仍有 1416 条包了 `$`：提示词能改变格式的倾向，但不能保证格式。

所以我们需要一个抽取器兜底。`extract_formula` 的规则是：去掉 think 块和代码围栏；如果有 `$$…$$`、`\[…\]`、`\(…\)`、`$…$` 包着的片段，且片段外只有空白和 `,` `.` `;` `。` 这几个标点，就把所有片段拼起来，否则只取第一个片段；没有定界符时，丢掉像自然语言的行，把剩下的行拼起来；最后去掉末尾一个孤立的 `.`、`,`、`;` 或 `。`。

抽取前后的变化（tour 第 6 部分，val 前 2000 条）：

| 提示 | 可解析率 抽取前 → 后 | EM_norm 抽取前 → 后 | 抽取修好 | 抽取改坏 |
|---|---|---|---|---|
| 零样本 | 0.003 → 0.740 | 0 → 0.057 | 113 | 0 |
| 少样本 k=3 | 0.043 → 0.759 | 0.010 → 0.065 | 124 | 14 |
| 少样本 + 格式约束 | 0.166 → 0.696 | 0.046 → 0.076 | 109 | 49 |

"抽取修好"指原始输出判错、抽取后判对；"抽取改坏"反过来。抽取器把可解析率从几乎为 0 拉到七成左右，说明大部分输出里**确实有一个公式**，只是被包装埋住了。但它也改坏了不少：少样本 14 条、加格式约束的 49 条，逐条检查全都是同一个原因——模型的输出本来规范化后和目标完全相同，抽取器却把末尾的句末标点（句号、逗号之类）去掉了（本项目观察，对保存的逐条输出的统计）。加了格式约束以后，原始输出本来就判对的更多（92 条，少样本只有 20 条），被这条规则误伤的也就更多。抽取器还有别的盲区，比如公式里有 `\mbox{if $x>0$}` 这种"文字里嵌公式"的写法时，它会把里面的 `x>0` 当成答案取走。

抽取器本身也会出错，所以 18.4.2 节要求两种口径都报。它的规则是在验证集上看着错例定下来的，这符合 0.10.1 节的协议；定下来以后就固定，测试集只用最终版本评。

### 18.6.2 句末标点：一个口径问题

上面的"抽取改坏"还牵出一个影响更大的问题。latex-formulas 的公式来自 arXiv 论文，很多是行内公式，连着句子的标点一起被截了下来。val 全集 5,001 条目标里，2,391 条以句号结尾、1,224 条以逗号结尾，合计约 72%（本项目观察，tour 第 1 部分）。

模型很"懂事"：它觉得公式后面不该有句号，顺手删了；抽取器也删。结果在 EM_norm 口径下全算错。为了看清影响有多大，tour 第 6 部分加了一个**诊断**：把目标和预测规范化后末尾的 `.`、`,`、`;` 都去掉再比较（val 前 2000 条）：

| 方法 | 官方 EM_norm | 忽略句末标点的 EM_norm（诊断） | 改坏中仅差句末标点 |
|---|---|---|---|
| 照抄 | 725/2000 [0.342, 0.384] | 725/2000 [0.342, 0.384] | 0 / 0 |
| 零样本 | 113/2000 [0.047, 0.067] | 452/2000 [0.208, 0.245] | 201 / 562 |
| 少样本 k=3 | 130/2000 [0.055, 0.077] | 472/2000 [0.218, 0.255] | 199 / 553 |
| 少样本 + 格式约束 | 152/2000 [0.065, 0.088] | 522/2000 [0.242, 0.281] | 234 / 527 |

忽略句末标点以后，提示方法的分数涨到原来的三倍多到四倍；改坏的样本里，36%–44% 只差句末标点。即使这样，三种提示仍然明显在照抄之下，区间不重叠；其余 56%–64% 的改坏和标点无关，是真的改动了公式内容或结构。

那要不要把官方指标改成"忽略句末标点"？本章的回答是：**不在这里改。** 指标要在看结果之前定；看了结果觉得哪个指标对自己有利就换哪个，正是 18.4.2 节警告的"射完箭再画靶子"。正确的做法是把它记成一条验证集上的发现，写进 R2 的局限；如果你认为句末标点确实不该算错，就在下一份报告**开始之前**修改指标定义，给它记一个新版本，所有方法（包括照抄）用新定义重新评一遍。练习 18.3 让你走一遍这个流程。

### 18.6.3 示例占用上下文

少样本的每个示例都要占提示的位置。tour 第 7 部分只用 tokenizer 数了一下（val 前 2000 条，chat 模板）：

| k | 提示平均 token | 提示最长 token |
|---|---|---|
| 0 | 88.8 | 253 |
| 1 | 193.8 | 358 |
| 3 | 551.8 | 716 |
| 5 | 817.8 | 982 |
| 8 | 1221.8 | 1386 |

示例对每条待改公式都一样，所以每多一个示例，提示就多出一个固定的长度。k=3 时，每个示例平均约 154 个 token（(551.8 − 88.8)/3，数学结论），三个示例让提示长了 6 倍多。Qwen3-0.6B 的配置写的上下文上限是 40,960 个 token，离用满还很远。但"放得下"不等于"用得起"：CPU 上的独占测量里（默认 tour，val 前 20 条），少样本每条平均 9.9 秒、零样本 7.2 秒，而少样本生成的 token 反而更少（63.7 对 93.7）。更长的上下文伴随着更高的总耗时：那 460 多个示例 token 既要在开头处理一遍，生成每个新 token 时注意力也要多看这么多位置。两部分各占多少，本章没有分阶段测量（待验证）。不管怎样，每一次调用都要为示例重新付一遍钱。

微调则是把示例"烧进"权重里：训练一次，以后每次调用都只需要零样本那么短的提示。

### 18.6.4 对措辞敏感

三条意思几乎一样的零样本指令，换着用会怎样？tour 第 8 部分在 val 前 500 条上做了这个小实验（本项目观察，RTX 4090 租用，bf16，`--sub-n 500`，抽取后口径）：

| system 指令 | EM_norm | CER | 改坏率 |
|---|---|---|---|
| Correct OCR errors in the following LaTeX formula. | 29/500 [0.041, 0.082] | 0.150 [0.132, 0.168] | 147/163 |
| Repair OCR mistakes in this LaTeX expression. | 30/500 [0.042, 0.084] | 0.132 [0.114, 0.153] | 146/163 |
| Recover the correct LaTeX formula from this OCR transcription. | 26/500 [0.036, 0.075] | 0.217 [0.194, 0.242] | 149/163 |

EM_norm 和改坏率三者几乎一样；CER 却明显分成两档：第三条指令的 CER 区间和前两条完全不重叠，点估计高出 0.07–0.09。只换了几个词，模型输出的"改动幅度"就变了一大截（第三条里的 "Recover" 似乎让模型更敢于大改，这只是一个猜测，本章没有验证）。

严格地说，这是**同一批 500 道题**上的比较：同一道难题，三条指令都会做错，三个分数是相关的。各自算区间再看是否重叠不是正确的检验方法；不过在这里区间分得这么开，第三条指令 CER 更高很可能是真的差别，严格的确认要用第 22 章的配对 bootstrap。

本章能确定的是：**提示的措辞是一个会影响结果的超参数**，和学习率一样要固定、要记录；只试一种措辞就下的结论，换一种措辞可能就不成立。

### 18.6.5 示例的选择和顺序

少样本的示例换个顺序、换一组，结果会变吗？tour 第 9 部分在 val 前 500 条上比较了三种情况（本项目观察，RTX 4090 租用，bf16，`--sub-n 500`）：原来的 3 条示例、同样 3 条倒过来排、用 `seed=1` 从 train 另选的 3 条。

| 示例 | EM_norm（抽取后） | CER（抽取后） | CER（原始输出） | 可解析率（抽取后） | 平均提示 token |
|---|---|---|---|---|---|
| 原顺序 | 26/500 [0.036, 0.075] | 0.151 [0.130, 0.174] | 0.149 [0.131, 0.166] | 368/500 | 552.7 |
| 逆序 | 28/500 [0.039, 0.080] | 0.150 [0.129, 0.174] | 0.149 [0.130, 0.169] | 365/500 | 552.7 |
| 另一组 | 22/500 [0.029, 0.066] | 0.178 [0.159, 0.198] | 0.179 [0.162, 0.196] | 279/500 | 649.7 |

只倒顺序，几乎没有变化：EM_norm、CER、可解析率都在误差范围内。换一组示例，变化就大了：原始输出的 CER 区间和原顺序不重叠（抽取后口径则稍有交叠），可解析率从 368/500 掉到 279/500，区间也不重叠。新的一组示例本身更长（提示平均多了约 97 个 token）；为什么它让输出更难解析，本章没有分析。

要注意分寸：这只是一次比较，只试了两种变化，不能推出"示例顺序不重要"或"示例越长越差"这类规律。它说明的是：**少样本基线的分数里，有一部分是"恰好选了哪几条示例"带来的。**报告少样本结果时，要写明示例的来源、选取规则和顺序；条件允许时，换几组示例各跑一次，看分数的波动有多大。

## 18.7 提示工程技巧（概括）

提示工程的技巧很多，这里只列几条常用的，每条一句话说清它在做什么。它们都可以在本章的流程里当成"一个新的提示方法"来测：固定子集、同样的指标、同样的解码，和已有的行比较。

- **把角色和规则放进 system 消息。** 指令模型通常在后训练时见过 system 消息，规则放这里比混在用户输入里更稳定（待验证：本章没有对比过放置位置）。
- **示例要像考题。** 少样本示例应和待解决的输入同类、同长度范围。本章的示例是从 train 里确定性取的有错样本，没有挑选。
- **按相似度选示例。** 对每个输入，从训练集里找最像的几条当示例（检索增强的少样本）。代价是每个输入的提示都不同，要先建索引，且一定只能在 train 里检索。
- **明确输出格式。** 说清"只输出公式、不要解释、不要加 `$`"，并准备一个抽取器兜底。18.6.1 节说明了光靠说是不够的。
- **约束解码。** 用语法或正则限制模型只能生成合法格式的 token（许多推理框架支持"结构化输出"）。它从根上解决格式问题，但不会让内容更对。
- **思维链。** 让模型先推理再回答。Qwen3 的思考模式就是内置的思维链；对改错这种"看一眼就该知道"的任务，它主要增加的是延迟（待验证：本章没有在思考模式下测分数）。
- **多次采样再投票。** 采样几次，选出现最多的答案（self-consistency）。成本翻几倍，而且放弃了贪心的可复现性。

## 18.8 常见错误

**1. 没关 thinking。** 现象：输出以一大段 `<think>` 推理开头，生成 token 数和用时暴涨，抽取器拿不到公式或拿错。原因：`apply_chat_template` 的 `enable_thinking` 默认是 `True`。怎样发现：打印渲染后的提示，看末尾有没有预填的空 `<think>\n\n</think>`（18.3.2 节）；统计输出里 `think_block` 的计数。

**2. 特殊 token 加了两遍。** 现象：提示开头出现两个 BOS 或两个起始标记，分数莫名其妙变差。原因：模板字符串已含特殊 token，编码时又用了默认的 `add_special_tokens=True`。Qwen3 的 `bos_token` 是 `None`，碰巧不会重复；换模型就会。怎样发现：把编码后的前 5 个 token 打印出来看。

**3. 在测试集上调提示。** 现象：报告里的测试分数比后续任何新数据上的分数都高。原因：你挑的是"在测试集上运气最好"的提示。怎样发现：回看实验记录，凡是根据测试分数改过的设置都要标出来；按 5.1.3 节补一份新的留出集。代码层面，`evaluate(split="test")` 不加 `allow_test=True` 会直接报错。

**4. 示例取自验证集。** 现象：少样本分数虚高，尤其是示例恰好和某些验证题很像时。怎样发现：检查示例的 `split` 字段；`miniocr/prompting.py` 遇到非 train 示例会直接报错。

**5. 只报点估计。** 现象："零样本 CER 0.135，少样本 0.080，少样本更好"（默认 CPU tour 的 20 条）。这两个数的 bootstrap 区间大面积重叠，这句话没有根据；到了 2000 条上，两者是 0.148 和 0.137，区间仍然重叠（18.5.2 节）。怎样发现：每个比例都带上成功数、分母和区间。

**6. 忘了和照抄比。** 现象：报告一个"CER 0.13"就以为模型在改错，其实同一子集上照抄的 CER 只有 0.041（18.5.2 节）。怎样发现：每张结果表的第一行都放照抄和标准答案。

**7. 采样解码却不固定种子。** 现象：同一个提示跑两遍分数不同，比较不同提示时分不清是提示的差别还是随机性。本章用贪心避开这个问题；要用采样，就得固定种子并多跑几次。

**8. 把抽取后的分数当成模型的分数。** 抽取器能把 `$x$.` 剥成 `x`，也能把多行公式截断或拼错。两种口径都要报，并说明抽取规则。

## 18.10 小结

不训练、只改提示词是最便宜的基线，但数据、划分、指标、解码、抽取规则同样要先固定，只在验证集上做决定，每个数字都带区间和成本。本部分的后纠错数据是在 latex-v1 上合成的 OCR 式噪声，它的错误分布和真实 OCR 不同。在 val 前 2000 条上（RTX 4090 租用，bf16），Qwen3-0.6B 的三种提示在 EM_norm、CER 和改坏率上都远不如"什么都不改"的照抄：它会重写公式的排版，把本来正确的输入改坏。第 19–21 章接着用监督微调处理这个问题，本章的表格是项目报告 R2 的第一行。
