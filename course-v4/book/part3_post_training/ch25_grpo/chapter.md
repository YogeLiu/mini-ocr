# 第 25 章　GRPO

## 本章导读

第 24 章烧好了四块砖：策略梯度、基线与优势、KL 估计、PPO 裁剪。这一章把它们砌成一面墙：**GRPO**（Group Relative Policy Optimization，组相对策略优化）。它是 DeepSeekMath 提出、后来被 DeepSeek-R1 带火的那个算法，也是今天用"可验证奖励"做强化学习时最常见的起点。

GRPO 的想法很短：同一道题让模型答 G 遍，每个答案和同组的平均分比，高于平均的多做一点，低于平均的少做一点。不需要价值网络，不需要奖励模型，只要一个能打分的程序。

公式识别正好有这样的程序：输出能不能解析、格式干不干净、和标准答案是否一致，全都能自动检查。所以本章用第 22 章的 OCR 后纠错任务，在 Qwen3-0.6B 上真跑一次 GRPO，并且**故意**再跑一次有缺陷的奖励，看模型会不会钻空子。

先把结论放在这里，后面一条一条讲清楚：

- **GRPO = PPO 裁剪目标 + 组内基线 + k3 KL 惩罚。**组内均值替代了价值网络（数学结论，25.1 节）。
- **组内优势有两处偏差。**均值里含自己，梯度缩成 $(G-1)/G$ 倍；除以组内标准差，会放大"几乎全对或几乎全错"的题（数学结论，25.2 节）。
- **组内奖励全相同（例如全对、全错）时，奖励项没有梯度**，只剩 KL 项的梯度。本项目分层奖励的有效组只有 33.75%，只看解析的奖励只有 14.875%（本项目观察，RTX 4090（租用），100 步，每步 8 组 × 8 个采样，seed 0，25.6 节）。
- **`loss_type` 决定长短回答怎样分摊损失。**TRL 1.15.0 的默认值是 `'dapo'`，不是 `'grpo'`；本项目代码显式写了 `loss_type='grpo'`（25.7 节）。
- **奖励有漏洞，探针一测就知道。**只看解析的奖励给单字符 `x`、复制输入、加解释文字都打满分；分层奖励给这些输出 0.1（本项目观察，CPU，lab 第 1 部分，25.5 节）。
- **验证器自己有缺陷，本章的实验保留着这个缺陷。**800 条训练提示里有 310 条，正确答案也只得 0 分（本项目观察，CPU 复跑，25.4.5 节）。这组训练是一次历史实验，它的顺序和第 22 章建议的“先修评测器”相反；25.4.5 节分开写实际顺序和推荐流程。
- **本项目里 GRPO 没有胜过继续 SFT。**val EM_norm：分层奖励 68.8%，只看解析 68.6%，继续 SFT 69.2%；三者只差 2～3 条样本（本项目观察，RTX 4090（租用），val n=500，seed 0，25.8 节）。加上另外两个训练种子后，继续 SFT 三次都排第一，均值 69.13% 对两种奖励的 68.40%；同时重采样种子和样本时区间仍含零，只算探索性证据（本项目观察，25.8.7 节）。

**本章用的面板。**本章用第 0 章 0.9.3 节定义的文本后纠错面板，四项都在 25.8.3 节的主表里，可以和第 23 章 23.8.3 节对照。改坏和 fix_rate 来自各运行 `val-metrics.json` 的 `broken_rate`、`fix_rate` 字段，SFT 起点来自 `outputs/book/ch22/gpu/analysis.json`；汇总文件 `comparison.json` 没有这两项。可选诊断项 parse_rate 本章也没有列。

## 25.1 从 PPO 到 GRPO：甩掉价值网络

### 25.1.1 动机：四个大模型太贵了

用 PPO 做 RLHF，显存里要同时放四个模型（第 23 章 23.2.4 节）：

| 模型 | 作用 | 要不要训练 |
|---|---|---|
| 策略 | 生成回答 | 训练 |
| 参考模型 | 算 KL，拴住策略 | 冻结 |
| 奖励模型 | 给回答打分 | 冻结 |
| 价值模型 | 估计"这道题平均能拿多少分"，当基线 | 训练 |

公式识别不需要奖励模型：一个程序就能打分。剩下最碍事的是价值模型。它和策略一样大，还要自己训练；而且对"只在最后给一个分数"的任务，"读到一半就预测最终得分"本身就很难学（第 24 章 24.4.4 节）。

### 25.1.2 直觉：同一张卷子，跟班级平均分比

想象老师判卷。要知道一个学生"这次考得好不好"，有两种办法：

- **办法一（价值网络）**：先训练一个"预测这道题平均分"的助教，再拿学生的分数和助教的预测比。
- **办法二（GRPO）**：让同一个学生把同一张卷子做 8 遍，每一遍和这 8 遍的平均分比。

办法二不需要助教。代价是每道题要做 8 遍——对语言模型来说，就是同一个提示采样 G 个回答。采样确实贵，但比训练一个和策略一样大的价值模型省事。

基线的作用在第 24 章已经讲过：它不改梯度的期望，只降方差。同组平均分就是"这道题、这个模型，平均能拿多少分"的一个现成估计，也就是 $V(x)$ 的蒙特卡洛估计（24.3.8 节）。

### 25.1.3 推导：GRPO 的目标

记号：提示 $x$；从旧策略 $\pi_{\mathrm{old}}$ 采样 $G$ 个回答 $y_1,\dots,y_G$；第 $i$ 个回答有 $L_i$ 个 token，奖励 $R_i$。

**第一步：组内优势。**每个回答的所有 token 共用同一个优势：

$$\hat A_i=\frac{R_i-\mathrm{mean}(R_1,\dots,R_G)}{\mathrm{std}(R_1,\dots,R_G)+\epsilon_{\mathrm{num}}}$$

$\epsilon_{\mathrm{num}}$ 是防止除零的小数，本项目和 TRL 都取 $10^{-4}$。

**第二步：逐 token 的比率。**

$$r_{i,t}(\theta)=\frac{\pi_\theta(y_{i,t}\mid x,y_{i,<t})}{\pi_{\mathrm{old}}(y_{i,t}\mid x,y_{i,<t})}$$

**第三步：裁剪代理目标减 KL。**DeepSeekMath 写出的 GRPO 目标是（Shao et al., 2024，§4.1）：

$$J(\theta)=\frac1G\sum_{i=1}^G\frac1{L_i}\sum_{t=1}^{L_i}\Big[\min\big(r_{i,t}\hat A_i,\ \mathrm{clip}(r_{i,t},1-\varepsilon,1+\varepsilon)\hat A_i\big)-\beta\,k3_{i,t}\Big]$$

其中 k3 的比值是 $\rho_{i,t}=\pi_{\mathrm{ref}}/\pi_\theta$（在第 $i$ 个回答的第 $t$ 个 token 上）：

$$k3_{i,t}=\rho_{i,t}-\log\rho_{i,t}-1$$

损失就是 $-J$。和 PPO 比，只改了三处：

1. **优势从组内算**，不来自价值网络和 GAE。
2. **KL 直接进损失**，而不是像经典 RLHF 那样从奖励里减掉。
3. **先对一条回答的 token 求平均（$\frac1{L_i}$），再对 G 条回答求平均。**这个"先平均"后面会惹麻烦（25.7 节）。

### 25.1.4 一步训练的全流程

```text
取 P 个提示
  └─ 每个提示采样 G 个回答（温度 > 0，否则 G 个回答一模一样）
       └─ 奖励函数逐个打分 R_i
            └─ 组内算优势 Â_i（同组共享均值和标准差）
                 └─ 策略、参考模型各算一遍逐 token 对数概率
                      └─ 裁剪目标 − β·k3，按 loss_type 聚合
                           └─ 反传，更新 LoRA 参数
```

本项目每步 $P=8$ 个提示、$G=8$ 个采样，一步共 64 条回答（本项目设置，lab 第 2 部分）。

> **停下来想一想：**如果采样温度设成 0（贪心），同一个提示的 G 个回答会怎样？优势会怎样？（答案：G 个回答完全一样，奖励相同，优势全为 0，奖励项一点梯度都没有，只剩 KL 项。数学结论。）

## 25.2 组内优势

### 25.2.1 动机：分数本身说明不了好坏

一道简单题，8 个回答拿了 0.9、1.0、1.0……；一道难题，8 个回答拿了 0.1、0.0、0.1……。如果直接用奖励当权重，简单题的每个回答都被"鼓励"，难题的每个回答都几乎不动。我们想知道的是：在这道题上，这个回答比同伴好还是差？

### 25.2.2 直觉：相对名次

减去组均值，就是把"绝对分数"换成"比同伴高多少"。再除以组内标准差，就是把"高多少分"换成"高几个标准差"，有点像把每道题的成绩都换算成 z 分数。

### 25.2.3 推导

对一组奖励 $R_1,\dots,R_G$：

$$\mu=\frac1G\sum_jR_j,\qquad \sigma=\sqrt{\frac1G\sum_j(R_j-\mu)^2},\qquad \hat A_i=\frac{R_i-\mu}{\sigma+\epsilon_{\mathrm{num}}}$$

两个性质，都是数学结论：

1. **组内优势之和为 0**：$\sum_i(R_i-\mu)=0$，除以同一个正数不改变这一点。所以每组里总有"被鼓励的"和"被压低的"，除非全部为 0。
2. **奖励全相同时，优势全为 0**：$R_i-\mu=0$，分母只剩 $\epsilon_{\mathrm{num}}$，结果仍是 0。这就是 25.6 节"无效组"的来源。

本项目的手写版用**总体标准差**（除以 $G$）；TRL 用**样本标准差**（除以 $G-1$）。$G=8$ 时两者差 $\sqrt{8/7}\approx1.069$ 倍，TRL 的优势整体小约 6.5%（数学结论）。忽略 $\epsilon_{\mathrm{num}}$ 时只是整体缩放，方向不变；组内差异极小、$\sigma$ 和 $\epsilon_{\mathrm{num}}$ 同量级时，比值会偏离这个常数。

### 25.2.4 手算：G = 4 的一组

拿 25.4 节会用到的四个回答（标准答案、复制输入、单字符 `x`、空串），分层奖励给出：

$$R=[1.0,\ 0.1,\ 0.1,\ 0.0]$$

逐步算（数学结论，CPU 复核）：

| 步骤 | 计算 | 结果 |
|---|---|---|
| 均值 | $(1.0+0.1+0.1+0.0)/4$ | $\mu=0.3$ |
| 偏差 | $R-\mu$ | $[0.7,\ -0.2,\ -0.2,\ -0.3]$ |
| 方差 | $(0.49+0.04+0.04+0.09)/4$ | $0.165$ |
| 标准差 | $\sqrt{0.165}$ | $\sigma=0.40620$ |
| 优势 | 偏差 ÷ $(\sigma+10^{-4})$ | $[1.7229,\ -0.4922,\ -0.4922,\ -0.7384]$ |

读这张表：标准答案被大力鼓励；复制输入和单字符 `x` 被压低；空串压得最狠。四个数加起来是 0。

如果只减均值、不除标准差（Dr. GRPO 的做法，25.2.7 节），优势就是偏差本身 $[0.7,-0.2,-0.2,-0.3]$。

### 25.2.5 对照代码

`miniocr/train/grpo.py` 的练习 25.1 区域：

```python
def group_advantages(rewards, group_size, *, scale=True, eps=1e-4):
    if group_size < 1 or rewards.numel() % group_size:
        raise ValueError('rewards 的长度必须是 group_size 的整数倍')
    r = rewards.float().view(-1, group_size)
    centered = r - r.mean(dim=1, keepdim=True)
    if not scale:
        return centered.reshape(-1)
    return (centered / (r.std(dim=1, unbiased=False, keepdim=True) + eps)).reshape(-1)
```

用上面那组数逐行走一遍：

- 输入 `rewards = [1.0, 0.1, 0.1, 0.0]`，形状 `[4]`；`group_size=4`。
- 第一行检查长度能被 G 整除。真实训练里 `rewards` 形状是 `[P*G]`，本项目是 `[64]`。
- `view(-1, group_size)` 变成 `[1, 4]`（真实训练是 `[8, 8]`）。**约定：同一个提示的 G 个回答是连续存放的。**
- `r.mean(dim=1, keepdim=True)` 得 `[[0.3]]`；`centered` 得 `[[0.7, -0.2, -0.2, -0.3]]`。
- `scale=False` 时直接展平返回，即 Dr. GRPO 的版本。
- `r.std(..., unbiased=False)` 得 `0.40620`，加 `eps` 后相除，得 `[1.7229, -0.4922, -0.4922, -0.7384]`。

测试 `test_group_advantages_are_zero_mean_and_zero_for_constant_groups` 检查的正是 25.2.3 节的两条性质。

### 25.2.6 偏差一：均值里含着自己

第 24 章 24.3.8 节证明过：用"含自己的批均值"做基线，梯度期望是 $\frac{B-1}{B}\nabla J$。GRPO 的组均值就是这种基线，$B=G$。

$G=8$ 时缩成 0.875 倍，$G=4$ 时缩成 0.75 倍（数学结论）。方向没错，相当于学习率小了一点，不会把训练带偏。想要严格无偏，就换成 leave-one-out：$R_i-\frac1{G-1}\sum_{j\ne i}R_j$。RLOO 就是这样做的。代数上它等于 $\frac{G}{G-1}(R_i-\mu)$，和 GRPO 的"只减均值"只差一个常数倍（数学结论）。

### 25.2.7 偏差二：除以标准差，放大"几乎没差别"的组

除以 $\sigma$ 时，每道题的权重变成了 $1/\sigma$。$\sigma$ 小，权重就大。看三组（数学结论，CPU 复核）：

| 组内奖励 | $\sigma$ | 优势 |
|---|---:|---|
| $[1,0,0,0]$ | 0.433 | $[1.732,-0.577,-0.577,-0.577]$ |
| $[1,1,1,0]$ | 0.433 | $[0.577,0.577,0.577,-1.732]$ |
| $[0.11,0.10,0.10,0.10]$ | 0.00433 | $[1.693,-0.564,-0.564,-0.564]$ |

第三行最可怕：四个回答几乎一样，奖励只差 0.01（可能只是打分程序的一点噪声），**优势却和第一行"一个全对、三个全错"差不多大**。除以标准差把"芝麻大的差别"放大成了"西瓜大的信号"。

Liu et al.（2025）把这叫做**题目难度偏差**（question-level difficulty bias）：太简单（几乎全对）和太难（几乎全错）的题，$\sigma$ 都小，被过度加权。他们提出的 Dr. GRPO 干脆不除标准差，只减均值。TRL 用 `scale_rewards='none'` 打开这个做法。

为什么 DeepSeekMath 还要除？好处是**不同题目的梯度尺度一致**：不管奖励是 0/1 还是 0～0.5，优势都在差不多的范围里，学习率好调。代价就是上面这种放大。本项目用的是 `scale_rewards='group'`（TRL 默认，除以组内标准差）。

分层奖励里也可能出现这种组。0.1 + 0.4·gain 这一档是连续值，两个回答只差一个字符，gain 可能只差 0.02。只要组里其他回答也都挤在附近，$\sigma$ 很小，这 0.02 的差别会被放大成接近 ±1.7 的优势（数学结论；本项目没有统计这类组有多少，待验证）。

### 25.2.8 常见错误

- **分组的维度弄错。**把 `[P*G]` 按 `view(G, P)` 重排，"组"就变成了"不同提示的第 k 个采样"。现象：优势不再是"同题比较"，训练信号几乎是噪声。发现方法：构造一个"一组全是 1、一组全是 0"的输入，检查优势是否全为 0。
- **按整个 batch 而不是按组减均值。**难题里的回答全被压低，简单题里的全被鼓励，又回到了"不比同伴、只比绝对分"。发现方法：检查每组优势之和是否为 0。
- **以为"总体标准差 vs 样本标准差"会改变方向。**它只是整体缩放。拿手写版和 TRL 对拍时，要么改成同一种，要么比较"优势的比值"。
- **忘了 eps。**全相同的组里 $\sigma=0$，$0/0$ 得 NaN，一个 NaN 就能毁掉整个 batch 的梯度。发现方法：日志里 loss 或 grad_norm 变成 nan。

## 25.3 裁剪目标与 KL 惩罚

### 25.3.1 动机：两条绳子

有了优势，梯度方向就有了。剩下两个问题：

- **一步别迈太大。**同一批样本如果要用好几次，策略走远了优势就不准了。这由 PPO 的裁剪管（第 24 章 24.6 节）。
- **整体别跑太远。**为了刷分，模型可能跑到一个和 SFT 起点面目全非的地方。这由 KL 惩罚管（第 23、24 章）。

裁剪是"每一步的短绳"，KL 是"拴在起点的长绳"。

### 25.3.2 逐 token 的损失

把 25.1.3 节的目标拆到每个 token 上，第 $i$ 个回答第 $t$ 个 token 的损失是：

$$\ell_{i,t}=-\Big[\min\big(r_{i,t}\hat A_i,\ \mathrm{clip}(r_{i,t},1-\varepsilon,1+\varepsilon)\hat A_i\big)-\beta\,k3_{i,t}\Big]$$

一条回答的损失是 $\frac1{L_i}\sum_t\ell_{i,t}$，整批再对回答取平均。裁剪的四种情形和第 24 章 24.6.3 节完全一样：**只有往有利方向走过头时，梯度才为 0。**

KL 这一项对 $\log\pi_\theta$ 的导数是（数学结论）：

$$\frac{\partial\,k3}{\partial\log\pi_\theta}=1-\rho,\qquad \rho=\frac{\pi_{\mathrm{ref}}}{\pi_\theta}$$

$\pi_\theta$ 比参考模型大（$\rho<1$），导数为正，梯度下降会把它往下拉；反过来往上拉。这就是"绳子"。

### 25.3.3 手算一：刚采完样的第一步，损失是 0，梯度不是

继续用 25.2.4 节的那组回答，$\hat A=[1.7229,-0.4922,-0.4922,-0.7384]$。给它们定一组长度：

$$L=[2,\ 3,\ 1,\ 2]\quad(\text{共 8 个有效 token},\ N=4\ \text{条回答})$$

刚采完样，还没更新：$\pi_\theta=\pi_{\mathrm{old}}$，所以每个 $r_{i,t}=1$。再假设策略还在起点：$\pi_\theta=\pi_{\mathrm{ref}}$，所以 $\rho=1$、k3 $=0$。

每个 token 的损失就是 $-\hat A_i$；每条回答的平均也是 $-\hat A_i$；四条再平均：

$$\text{loss}=-\frac14(1.7229-0.4922-0.4922-0.7384)=0$$

**损失恰好是 0**，因为组内优势之和为 0（数学结论；CPU 复跑得 $3\times10^{-8}$，是浮点误差）。

但梯度不是 0。对第 $i$ 条回答的任一 token，$\partial\,\text{loss}/\partial\log\pi_\theta=-\hat A_i/(L_i\cdot N)$：

| 回答 | $\hat A_i$ | $L_i$ | 每个 token 的梯度 | 梯度下降后 |
|---|---:|---:|---:|---|
| 1 标准答案 | 1.7229 | 2 | $-1.7229/8=-0.2154$ | 概率上升 |
| 2 复制输入 | −0.4922 | 3 | $0.4922/12=0.0410$ | 概率下降 |
| 3 单字符 | −0.4922 | 1 | $0.4922/4=0.1231$ | 概率下降 |
| 4 空串 | −0.7384 | 2 | $0.7384/8=0.0923$ | 概率下降 |

（数学结论，CPU 复核。）这张表有两个要点：

1. **GRPO 的损失值本身没有意义。**它在第一步恒为 0（KL 为 0 时），之后也一直在 0 附近。本项目 TRL 日志的 `train_loss` 是 $2.18\times10^{-6}$（分层奖励）和 $6.68\times10^{-6}$（只看解析）（本项目观察，`train-summary.json`）。别拿它判断训练好坏，看奖励、有效组和 KL。
2. **回答 2 和回答 3 的优势相同，每个 token 的梯度却差 3 倍**，只因为长度不同。记住这一点，25.7 节要用。

### 25.3.4 手算二：更新几步之后

假设策略已经动了一点（为了演示，比率取得很大）。参考模型仍是起点，所以 $\rho=1/r$：

| 回答 | 各 token 的 $r$ | 说明 |
|---|---|---|
| 1（$\hat A>0$） | $[1.0,\ 1.5]$ | 第 2 个 token 往有利方向走过头了 |
| 2（$\hat A<0$） | $[1.0,\ 1.0,\ 1.0]$ | 没动 |
| 3（$\hat A<0$） | $[1.1]$ | 坏回答的概率反而涨了一点 |
| 4（$\hat A<0$） | $[0.5,\ 1.0]$ | 第 1 个 token 往有利方向走过头了 |

先算三个 k3（$\rho=1/r$，k3 $=1/r+\ln r-1$，数学结论）：

| $r$ | 1.5 | 1.1 | 0.5 |
|---|---:|---:|---:|
| k3 | 0.0721 | 0.0044 | 0.3069 |

再逐条算损失（$\varepsilon=0.2$，$\beta=0.04$）：

- **回答 1。**token 1：$r=1$，损失 $-1.7229$。token 2：$\min(1.5\times1.7229,\ 1.2\times1.7229)=2.0675$（裁剪项被选中），减 $0.04\times0.0721=0.0029$，损失 $-2.0646$。平均 $-1.8937$。
- **回答 2。**三个 token 都是 $0.4922$，平均 $0.4922$。
- **回答 3。**$r=1.1$ 在 $[0.8,1.2]$ 里，不裁剪：$1.1\times(-0.4922)=-0.5415$，减 $0.04\times0.0044$，损失 $0.5416$。
- **回答 4。**token 1：$\min(0.5\times(-0.7384),\ 0.8\times(-0.7384))=-0.5907$（裁剪项被选中），减 $0.04\times0.3069=0.0123$，损失 $0.6030$。token 2：$0.7384$。平均 $0.6707$。

$$\text{loss}=\frac14(-1.8937+0.4922+0.5416+0.6707)=-0.0473$$

梯度（对 $\log\pi_\theta$，数学结论，CPU 复核）：

| token | 梯度 | 来源 |
|---|---:|---|
| 回答 1，token 1 | −0.2154 | 裁剪目标（未裁剪） |
| 回答 1，token 2 | **+0.0017** | **只剩 KL**：裁剪切断了策略梯度，KL 轻轻往回拉 |
| 回答 2，每个 token | +0.0410 | 裁剪目标 |
| 回答 3 | +0.1363 | 裁剪目标 0.1354 + KL 0.0009 |
| 回答 4，token 1 | **−0.0050** | **只剩 KL**：已经压够了，KL 把它往回抬 |
| 回答 4，token 2 | +0.0923 | 裁剪目标 |

两个裁剪的 token 都只剩下 KL 的那一点梯度：往有利方向走过头，策略梯度就停了。这批 token 的平均 k3 是 $0.3834/8=0.0479$；8 个 token 里有 2 个 $|r-1|>0.2$，裁剪比例 0.25。

### 25.3.5 对照代码

`miniocr/train/grpo.py` 的练习 25.2 区域，用手算二的数字逐行看：

```python
def grpo_loss(logp_new, logp_old, logp_ref, advantages, mask, *, epsilon=.2, beta=.04):
    ...
    mask = mask.float()
    adv = advantages.detach().float().unsqueeze(1)
    ratio = torch.exp(logp_new - logp_old.detach())
    surrogate = torch.minimum(ratio * adv, ratio.clamp(1 - epsilon, 1 + epsilon) * adv)
    log_ref_over_new = logp_ref.detach() - logp_new
    kl = torch.exp(log_ref_over_new) - log_ref_over_new - 1
    per_token = -(surrogate - beta * kl)
    lengths = mask.sum(dim=1).clamp(min=1)
    per_sequence = (per_token * mask).sum(dim=1) / lengths
    ...
    return per_sequence.mean(), diagnostics
```

- 输入形状：`logp_new/old/ref` 都是 `[N, T] = [4, 3]`（T 取最长回答的长度 3，短回答用 padding 补齐）；`advantages` 是 `[4]`；`mask` 是 `[[1,1,0],[1,1,1],[1,0,0],[1,1,0]]`。
- `adv` 先 `detach`，再 `unsqueeze(1)` 变成 `[4, 1]`，广播到每个 token：**一条回答的所有 token 共用同一个优势。**
- `ratio = exp(new - old)`：old 要 `detach`，它是采样时的常数。手算二里 `ratio = [[1.0,1.5,·],[1,1,1],[1.1,·,·],[0.5,1.0,·]]`（`·` 是 padding 位置，值无所谓）。
- `surrogate` 一行就是 PPO 的 $\min(rA,\mathrm{clip}(r)A)$，不写 `if`。
- `log_ref_over_new = ref - new` 就是 $\log\rho$；`kl` 就是 k3。注意 `logp_new` **没有** detach，KL 的梯度从这里流回去。
- `per_token = -(surrogate - beta*kl)`：取负，变成要最小化的损失。
- `(per_token * mask).sum(dim=1) / lengths`：padding 位置乘 0，再除以**每条回答自己的** token 数 `[2,3,1,2]`。这就是 25.1.3 节的 $\frac1{L_i}$，也就是 TRL 的 `loss_type='grpo'`。
- `per_sequence.mean()`：四条回答再平均，得 $-0.0473$。

诊断字典里 `kl_mean=0.0479`、`clip_fraction=0.25`、`ratio_mean=1.0125`（数学结论，CPU 复核）。注意 `clip_fraction` 统计的是所有 $|r-1|>\varepsilon$ 的 token，**不管方向**；TRL 的 `clip_ratio/region_mean` 只统计梯度真正为 0 的两格（$A>0,r>1+\varepsilon$ 和 $A<0,r<1-\varepsilon$）。手算二里两个越界 token 恰好都在"梯度为 0"的格子里，所以两种口径一样；回答 3 若取 $r=1.3$，两者就不一样了。

三个测试分别对应三件事：`test_clipping_saturates_in_advantage_direction`（$r=1.5$、$A=1$ 时梯度为 0），`test_kl_is_zero_when_policy_equals_reference`，以及 tour 部分 1 里负优势、$r=0.5$ 的对称情形。

### 25.3.6 为什么本项目的裁剪比例恒为 0

本项目两条 GRPO 训练，TRL 日志里的 `clip_ratio/region_mean` 全程 100 步都是 0（本项目观察，`training-statistics.json`）。不是 bug。

原因在 TRL 1.15.0 的源码里（`grpo_trainer.py`）：生成一批回答后，如果 `gradient_accumulation_steps` 是 `steps_per_generation × num_iterations` 的整数倍，TRL 不单独计算 `old_per_token_logps`，而是令 `old = per_token_logps.detach()`。本项目 `num_iterations=1`（默认）、`steps_per_generation` 默认等于累积步数 4，正好对齐。于是：

$$r_{i,t}=\exp(\log\pi_\theta-\mathrm{detach}(\log\pi_\theta))\equiv1$$

比率恒为 1，永远落不出 $[0.8,1.2]$，裁剪永远不会触发（数学结论）。**一批样本只用一次时，GRPO 就退化成"带组内基线和 KL 的 REINFORCE"。**裁剪只在 `num_iterations>1`（同一批样本更新多次）或生成和更新错位时才起作用。

这也解释了 `train_loss` 为什么这么小：比率恒为 1，裁剪项整步平均等于 $-\mathrm{mean}(\hat A)=0$，损失只剩 $\beta\cdot$KL。$0.04\times4.69\times10^{-5}=1.9\times10^{-6}$，和日志的 $2.18\times10^{-6}$ 同一量级（KL 全程均值来自 `training-statistics.json`，本项目观察；两者的平均口径不完全相同，所以不严格相等）。

### 25.3.7 常见错误

- **old 或 ref 没有 detach。**现象：KL 和比率的梯度从不该走的地方回传，训练不稳，或者显存莫名增大。发现方法：检查 `logp_old.requires_grad` 和 `logp_ref.requires_grad` 都是 False。
- **把 KL 的方向写反。**写成 `log_new - log_ref`，k3 就变成了另一个方向 KL 的估计，而且 $\rho$ 的位置也换了。发现方法：策略和参考相同时两者都是 0，测不出来；要在 $\pi_\theta\ne\pi_{\mathrm{ref}}$ 的点上和手算比，例如手算二里 $r=0.5$ 时 k3 应为 0.3069。
- **以为裁剪比例为 0 说明 ε 设大了。**先看是不是 `num_iterations=1` 且对齐，那样比率恒为 1。
- **用 loss 曲线判断收敛。**GRPO 的 loss 在 0 附近抖，没有"下降"可言。

## 25.4 可验证奖励的设计

### 25.4.1 动机：公式能自动检查

DeepSeek-R1 这一类工作选数学题和编程题，不是巧合：答案能被程序检查。公式识别也能：

1. **能不能解析？**用 matplotlib 的 mathtext 试着解析。
2. **格式干不干净？**有没有多余的解释文字、代码围栏、美元符号、think 块。
3. **内容对不对？**规范化后和标准答案逐字比较，或者算编辑距离。

把这三层叠起来，就是**分层奖励**。

### 25.4.2 直觉：先过门槛，再比内容

分层奖励像考试的评分细则：交白卷 0 分；卷面潦草、夹着草稿（格式问题）只给一点卷面分；写得工整但答错，按"比原来改进了多少"给部分分；完全正确给满分。

为什么要"部分分"？因为全对全错的二值奖励太稀疏：一道难题 8 个回答全错，组内没有差别，奖励项就没有梯度（25.6 节）。部分分让"改对了一半"也比"一点没改"好，组内更容易拉开差距。

### 25.4.3 两个奖励函数

`miniocr/eval/rewards.py`，source 是带噪输入，target 是标准答案：

```python
def layered_reward(completion, source, target):
    if not completion.strip() or not can_parse(completion):
        return 0.0
    if format_issues(completion):
        return 0.1
    if normalize_latex(target) == normalize_latex(completion):
        return 1.0
    base = sample_error_rate(target, source)
    if base <= 0:
        return 0.1
    pred = sample_error_rate(target, completion)
    gain = min(1.0, max(0.0, (base - pred) / base))
    return 0.1 + 0.4 * gain


def parse_only_reward(completion, source, target):
    return 1.0 if completion.strip() and can_parse(completion) else 0.0
```

逐行：

- 空串或解析失败：0。
- 能解析但有格式问题：0.1。它和"干净但毫无改进"同分，低于任何有改进的干净输出，鼓励模型"只输出公式"。
- 规范化后完全一致：1.0。
- `base` 是输入本身的错误率；`base <= 0` 说明输入已经正确，而输出却和标准答案不一致（上一行没返回），说明模型把对的改坏了，只给 0.1。
- 其余情况：`gain` 是"错误率降低了多少比例"，截在 $[0,1]$。没改进或改坏了，gain 为 0，得 0.1；改进越多分越高，**但最多 0.5**，和"完全正确"的 1.0 之间留了一道明显的台阶。

`parse_only_reward` 是**故意写坏的对照**：能解析就满分，不看内容。它的作用是当靶子：看模型会不会钻空子。

### 25.4.4 手算：四个回答的打分

取 tour 部分 1 的例子：输入 `\frac{a}{b}+c`，标准答案 `\frac{a}{b}+d`。

| 回答 | 文本 | 分层奖励 | 只看解析 | 分层奖励走到哪一行 |
|---|---|---:|---:|---|
| 标准答案 | `\frac{a}{b}+d` | 1.0 | 1.0 | 规范化一致 |
| 复制输入 | `\frac{a}{b}+c` | 0.1 | 1.0 | 没改进，gain = 0 |
| 单字符 | `x` | 0.1 | 1.0 | 能解析、无格式问题，但错误率更高，gain = 0 |
| 空串 | （空） | 0.0 | 0.0 | 空 |

（本项目观察，CPU，`mechanism/part1.json`；本地 CPU 复跑 tour 部分 1 一致。）

这就是 25.2.4 节那组 $R=[1.0,0.1,0.1,0.0]$。换成只看解析的奖励，同一组变成 $R=[1,1,1,0]$，优势是：

$$\hat A=[0.577,\ 0.577,\ 0.577,\ -1.732]$$

单字符 `x` 和标准答案拿到了一模一样的正优势，梯度会把"输出 `x`"和"输出正确答案"推得一样高。

### 25.4.5 验证器自己也会出错：解析器的漏报

分层奖励有个隐藏前提：**正确答案一定能被 mathtext 解析。**这不成立。mathtext 只支持 TeX 数学的一个子集，很多合法的 LaTeX（例如某些环境和宏）它不认识。

本书在本地 CPU 上对训练用的 800 条提示统计了一下（本项目观察，CPU 复跑，train offset 4096 起 800 条，data seed 0，不加载模型）：

| 统计 | 条数 |
|---|---:|
| 标准答案能被 mathtext 解析 | 490 / 800 |
| 标准答案本身拿到分层奖励 1.0 | 470 / 800 |
| 标准答案本身拿到分层奖励 0 | **310 / 800** |

也就是说，**38.75% 的提示上，即使模型一字不差地答对，也只能拿 0 分。**另有 20 条标准答案能解析，却被格式检查当成"夹了解释文字"，只得 0.1。val 的 500 条标准答案里，能解析的是 293 条。

这些题上会发生什么？正确答案得 0；一个碰巧能解析的错误答案却可能得 0.1 以上。奖励在这些题上可能给反信号，可验证奖励有多可靠，取决于验证器有多可靠。

**本章的训练是一次保留已知缺陷的历史实验。**第 22 章 22.6.4 节查出 mathtext 漏报和格式误报，22.6.6 节把"先修评测器"排在最前面。本章的实际做法没有走这一步：奖励的第一层仍然用 mathtext，格式检查也没有改，训练前没有在标准答案上统计，上表是训练结束后补算的。奖励冻结在训练时的样子，不事后改训练目标，所以本章所有 GRPO 数字都带着这个缺陷。它会怎样影响结果，本项目没有做对照实验（待验证）。

推荐流程和这个顺序相反：先修评测器，在标准答案上跑一遍奖励函数，处理好拿不到满分的提示，再开始训练。一个自然的修正是把"标准答案不能解析"的提示从 GRPO 训练集里滤掉，或者改用完整的 TeX 编译做第一层。

### 25.4.6 常见错误

- **分层之间没有台阶。**例如"部分正确"最高能到 0.9，模型会满足于差不多对。本项目让部分分最多 0.5、全对 1.0，就是留台阶。发现方法：画出奖励分布直方图，看 1.0 附近是否有一个明显的峰。
- **没在标准答案上跑一遍奖励函数。**这是最便宜、也最容易忘的检查：标准答案应该拿满分。本项目 310/800 的漏报，一行代码就能查出来。
- **格式检查误报。**正则启发式会把合法公式里的英文单词当成"解释文字"。发现方法：同上，在标准答案上统计被判为格式问题的比例。
- **在不同奖励之间比较 reward 的大小。**分层奖励末段 0.36，只看解析末段 0.55，不能说后者"学得更好"：两个分数的定义完全不同。

## 25.5 奖励投机与探针

### 25.5.1 动机：模型只优化你写下的东西

第 24 章 24.7 节，小 GPT 为了"首尾是 `$`"的奖励，学会了只输出 `$$$$$$$$`。模型没有恶意，它只是在优化你写下的函数。**奖励投机**（reward hacking）就是：奖励涨了，任务没有变好。

### 25.5.2 直觉：先当一回作弊的学生

防作弊最好的办法，是先自己想想怎么作弊。在训练之前，手写几个"明显无用但可能骗到分"的输出，喂给奖励函数，看它给几分。这些输出叫**探针**（probe）。

### 25.5.3 静态探针：训练之前就能做

`hack_probes(source, target)` 返回六个固定输出。tour 部分 1 把它们分别喂给两个奖励（本项目观察，CPU，`mechanism/part1.json`）：

| 探针 | 文本（输入 `\frac{a}{b}+c`） | 分层奖励 | 只看解析 |
|---|---|---:|---:|
| empty | （空） | 0.0 | 0.0 |
| single_symbol | `x` | 0.1 | **1.0** |
| copy_source | `\frac{a}{b}+c` | 0.1 | **1.0** |
| copy_with_prose | `Here is the corrected formula: \frac{a}{b}+c` | 0.1 | **1.0** |
| repeat_source | 输入重复三遍 | 0.1 | **1.0** |
| gold_answer | `\frac{a}{b}+d` | 1.0 | 1.0 |

只看解析的奖励被四种作弊全部骗过；分层奖励给它们都是 0.1，远低于标准答案的 1.0。测试 `test_parse_only_reward_is_hackable_by_trivial_output` 和 `test_layered_reward_levels` 只把其中几行固定成了断言：空串得 0、标准答案得 1.0、加解释得 0.1、复制输入在分层奖励下低于 0.5、单字符 `x` 只看解析得 1.0 而分层奖励低于 0.5。`repeat_source` 和整张表的其余分数没有断言，以 `part1.json` 为准。

写探针的原则：每一种你能想到的"便宜答案"都应该拿低分；如果某个探针拿了高分，先修奖励，再训练。

### 25.5.4 动态探针：训练之后看输出

静态探针证明"有漏洞"，不证明"模型钻了"。训练后要在 val 输出上统计（tour 部分 5）：

- **复制输入**：输出和带噪输入一字不差。
- **过短或空**：少于 4 个字符。
- **能解析但不精确匹配**：parse_only 奖励会给满分、但其实是错的输出。

本项目结果（本项目观察，RTX 4090（租用），val n=500，seed 0，`comparison.json`）：

| 运行 | 复制输入 | 少于 4 字符 | 能解析但不对 |
|---|---:|---:|---:|
| SFT 起点 | 176 | 未汇总 | 未汇总 |
| GRPO 分层奖励 | 173 | 0 | 54 |
| GRPO 只看解析 | 167 | 0 | 61 |
| 继续 SFT | 174 | 0 | 53 |

三个口径不互斥。另外，"复制输入"不等于作弊：val 里有一部分输入本身就是干净的，原样输出正是正确答案。

### 25.5.5 这次没有观察到崩塌

**只看解析的奖励有漏洞，但这次训练没有把模型推向单字符或空输出。**短输出计数是 0，平均输出长度两条 GRPO 都是 59.0 token 左右（本项目观察，`training-statistics.json`）。能解析但不对的输出多了 7～8 条（61 对 53、54），方向符合预期，但只差几条，不能当作投机的证据。

为什么没崩？以下是推断，没有做对照实验（待验证）：

1. **走得太少。**100 步、学习率 $5\times10^{-6}$、LoRA 只加在 q/v 上，末段 KL 只有 $3.2\times10^{-4}$（本项目观察）。策略离 SFT 起点很近，还没走到能"发现"单字符这条捷径的地方。
2. **探索太少。**TRL 记录的平均 token 熵只有 0.023 左右（本项目观察，`trainer-history.json` 的 `entropy`）。SFT 后的模型非常笃定，温度 1.0 下也很少采出 `x` 这种离谱的回答，而模型采不到的作弊方式，梯度也推不过去。
3. **有效组太少。**只看解析的有效组只有 14.875%，大部分组没有奖励项梯度（25.6 节）。

第 24 章的小 GPT 从随机初始化出发，崩到了只输出 `$`，那个实验没有检查原因（24.7.4 节）。两次实验的模型、奖励和步数都不同，不能直接归因。这个反差只是提示：同一个有漏洞的奖励，危险程度可能取决于模型能不能采到漏洞（待验证）。训练再久一点、温度再高一点，结论可能完全不同（待验证；25.8.7 节的补充种子仍是 100 步，没有回答这一点）。本章也没有做有无 KL 的对照，KL 能不能挡住投机，这里不作回答。

### 25.5.6 常见错误

- **只看训练 reward 上升就说"学到了"。**只看解析的 reward 从首 10 步均值 0.4625 涨到末 10 步 0.5484（本项目观察），但 val EM 并没有比分层奖励好。要同时看 val 的任务指标和投机统计。
- **把"有漏洞"说成"已投机"。**静态探针只证明前者。
- **探针太少。**只测空串，漏掉"复制输入""加解释"这些更隐蔽的。经验：每一层奖励至少配一个专门攻击它的探针。

## 25.6 有效组比例

### 25.6.1 动机：一半以上的计算在空转

25.2.3 节说过：组内奖励全相同，优势全为 0。这组 G 个回答生成了、打分了、前向反向都跑了，**对策略梯度的贡献却是 0**（KL 项除外）。TRL 把这类组的比例记作 `frac_reward_zero_std`；**有效组比例 = 1 − frac_reward_zero_std**。

### 25.6.2 直觉

全对的题，模型已经会了，学不到新东西；全错的题，模型一次都没蒙对，不知道往哪边改。只有"有对有错"的题才有信息量。

### 25.6.3 推导：二值奖励的情形

设奖励只有 0、1 两档，某道题上模型答对的概率是 $p$，G 个采样独立。全组相同的概率是（数学结论）：

$$P(\text{无效})=p^G+(1-p)^G$$

### 25.6.4 手算

$G=8$：

| $p$ | $p^8$ | $(1-p)^8$ | 无效概率 | 有效概率 |
|---:|---:|---:|---:|---:|
| 0.5 | 0.0039 | 0.0039 | 0.0078 | 99.2% |
| 0.8 | 0.1678 | 0.0000 | 0.1678 | 83.2% |
| 0.9 | 0.4305 | 0.0000 | 0.4305 | 57.0% |

$p=0.9$ 时，$G=4$ 的有效概率只有 $1-0.6561-0.0001=34.4\%$，$G=16$ 升到 $1-0.1853=81.5\%$（数学结论）。**$p\ge0.5$ 之后，模型越强，有效组越少**（$p<0.5$ 时反过来，答对率升高有效组变多：$G=8$ 时 $p=0.1,0.3,0.5$ 分别是 57.0%、94.2%、99.2%）；**组越大，有效组越多。**这是"G 取多大"的主要考量之一。

真实奖励不止两档，但道理一样：只要 G 个回答落进同一档，就是无效组。而且对 LLM 来说，G 个采样**并不独立于"会不会"**：模型笃定时，G 个回答干脆一字不差，必然同分。

### 25.6.5 对照日志

TRL 1.15.0 在 `grpo_trainer.py` 里这样算（节选）：

```python
std_rewards = nanstd(rewards.view(-1, num_generations), dim=1)
std_rewards = std_rewards.repeat_interleave(num_generations, dim=0)
...
is_std_zero = torch.isclose(std_rewards, torch.zeros_like(std_rewards))
self._metrics[mode]["frac_reward_zero_std"].append(is_std_zero.float().mean().item())
```

- `view(-1, num_generations)` 和我们的 `group_advantages` 一样按组重排。
- `nanstd` 是样本标准差（25.2.3 节）。
- `repeat_interleave` 把每组的标准差复制 G 份，所以 `is_std_zero` 的均值是"按回答数"算的比例；每组大小相同，它等于"按组数"算的比例。

本项目一步 8 组。分层奖励第 1 步 `frac_reward_zero_std=0.75`，即 8 组里只有 2 组有效（本项目观察，`trainer-history.json`）。

### 25.6.6 本项目观察

本项目观察，RTX 4090（租用），100 步，每步 8 提示 × 8 采样，温度 1.0，seed 0（`training-statistics.json`、`training-curves.csv`）：

| 运行 | 有效组（100 步均值） | 首 10 步 | 末 10 步 | 有效组为 0 的步数 |
|---|---:|---:|---:|---:|
| GRPO 分层奖励 | 33.75% | 43.75% | 33.75% | 2 |
| GRPO 只看解析 | 14.875% | 13.75% | 16.25% | 28 |

换成组数（数学结论，由上表均值算出）：分层奖励平均每步 $8\times0.3375=2.7$ 组有信号，100 步共约 270 组；只看解析每步约 1.2 组，100 步约 119 组，而且有 28 步整步没有策略梯度。

为什么只看解析的有效组更少？推断（待验证）：能不能被 mathtext 解析，主要取决于**这道题的公式本身**（25.4.5 节，标准答案就有 310/800 解析不了），同一道题的 8 个回答往往一起能解析、或一起不能，于是全 1 或全 0。分层奖励多了"格式"和"部分分"两档，更容易拉开差距。

再加上 25.5.5 节的低熵（平均 token 熵约 0.022～0.023），可以这样理解这张表：SFT 之后的模型对大多数题已经很笃定，8 个回答常常几乎一样，GRPO 能从中挤出的信息非常有限。

### 25.6.7 怎样提高有效组比例（概括）

- **加大 G。**直接有效，但生成成本线性增加。
- **提高采样温度。**更多样，但回答质量下降。
- **动态采样。**DAPO（Yu et al., 2025）的做法：采样后把全对、全错的组扔掉，继续采，直到凑满一个 batch 的有效组。
- **选题。**把模型已经稳定全对、或从来没对过的题移出训练集。
- **修奖励。**像 25.4.5 节那样，正确答案拿 0 分的题本来就该滤掉。

### 25.6.8 常见错误

- **不看这个指标。**reward 曲线看起来正常，但有效组只有 10%，相当于 batch 小了 10 倍。发现方法：每次 GRPO 训练都把 `frac_reward_zero_std` 画出来。
- **以为无效组"对训练没影响"。**它们仍然贡献 KL 梯度，而且在 `loss_type='dapo'` 下仍然占着分母里的 token 数，把有效组的梯度稀释了（25.7 节）。
- **以为有效组越多越好就无脑升温度。**温度太高，回答变成乱码，奖励的"有对有错"变成"有乱码有正常"，学到的是"别乱码"，而不是"改对公式"。

## 25.7 `loss_type`：grpo、dapo、dr_grpo

### 25.7.1 动机：同样的 token 损失，平均的方式不同

每个 token 都有了损失 $\ell_{i,t}$。最后一步是把它们合成一个数。看起来是小事，实际上它决定了**长回答和短回答怎样分摊梯度**。DAPO 和 Dr. GRPO 两篇论文都专门讨论了这一步；TRL 1.15.0 的默认值也不是 `'grpo'`（25.7.6 节）。

### 25.7.2 三个公式

记 $N$ 为一批回答数，$L_i$ 为第 $i$ 条的有效 token 数，$L_{\max}$ 为 `max_completion_length`（本项目 160）：

| `loss_type` | 聚合公式 | 每个 token 的权重 |
|---|---|---|
| `grpo` | $\frac1N\sum_i\frac1{L_i}\sum_t\ell_{i,t}$ | $\frac1{N\,L_i}$，和自己所在回答的长度有关 |
| `dapo` | $\frac{1}{\sum_iL_i}\sum_i\sum_t\ell_{i,t}$ | $\frac1{\sum_iL_i}$，整批所有 token 一视同仁 |
| `dr_grpo` | $\frac{1}{N\,L_{\max}}\sum_i\sum_t\ell_{i,t}$ | $\frac1{N\,L_{\max}}$，一个固定常数 |

（公式按 TRL 1.15.0 `grpo_trainer.py` 的实现整理。`dapo` 的分母是整个累积 batch 的有效 token 数。）

### 25.7.3 推导：`grpo` 的长度偏差

在 `grpo` 下，第 $i$ 条回答所有 token 的梯度加起来是 $\frac{\hat A_i}{N}\cdot\frac1{L_i}\sum_t\nabla\log\pi_\theta(y_{i,t})$。也就是说，整条回答的对数概率梯度被乘上了 $\frac1{L_i}$。

- $\hat A_i>0$（好回答）：越短，每个 token 被推得越用力。模型被鼓励**答对时说短话**。
- $\hat A_i<0$（坏回答）：越长，每个 token 被罚得越轻。模型被纵容**答错时说长话**。

Liu et al.（2025）称之为**回答长度偏差**（response-level length bias），并认为它是 R1-Zero 类训练中"错误回答越来越长"的原因之一。`dapo` 和 `dr_grpo` 都去掉了 $\frac1{L_i}$：同样的优势，每个 token 的权重相同。

### 25.7.4 手算：同一组回答，三种聚合

继续用 25.3.3 节的数字（$r\equiv1$、KL 为 0），$\hat A=[1.7229,-0.4922,-0.4922,-0.7384]$，$L=[2,3,1,2]$，$N=4$，$\sum L_i=8$。为了手算，把 $L_{\max}$ 取成 3（真实训练是 160）。

每个 token 的梯度大小 $|\hat A_i|\times$权重（数学结论）：

| 回答 | $\hat A_i$ | $L_i$ | `grpo`：$\frac{1}{4L_i}$ | `dapo`：$\frac18$ | `dr_grpo`：$\frac1{12}$ |
|---|---:|---:|---:|---:|---:|
| 1 | 1.7229 | 2 | 0.2154 | 0.2154 | 0.1436 |
| 2 | −0.4922 | 3 | **0.0410** | 0.0615 | 0.0410 |
| 3 | −0.4922 | 1 | **0.1231** | 0.0615 | 0.0410 |
| 4 | −0.7384 | 2 | 0.0923 | 0.0923 | 0.0615 |

看回答 2 和回答 3：优势一样，都是坏回答。`grpo` 下长的那条每个 token 只罚 0.0410，短的那条罚 0.1231，差 3 倍。`dapo` 和 `dr_grpo` 下两者相同。

`dapo` 和 `dr_grpo` 的区别在于分母：`dapo` 用这批实际的 token 数，每批不同；`dr_grpo` 用固定常数，梯度尺度随回答变长而变大。在同一批之内，两者只差一个常数倍。

### 25.7.5 对照 TRL 源码

TRL 1.15.0 `grpo_trainer.py` 的聚合部分（节选）：

```python
if self.loss_type in ["grpo", "sapo"]:
    loss = ((per_token_loss * mask).sum(-1) / mask.sum(-1).clamp(min=1.0)).mean()
    ...
elif self.loss_type == "dr_grpo":
    loss = (per_token_loss * mask).sum() / (per_token_loss.size(0) * self.max_completion_length)
    ...
elif self.loss_type in ["cispo", "dapo", "vespo"]:
    normalizer = inputs["num_items_in_batch"].clamp(min=1.0) / self.accelerator.num_processes
    ...
    loss = (per_token_loss * mask).sum() / normalizer
```

- `grpo` 一行和我们 `grpo_loss` 最后两行一模一样：先 `.sum(-1) / mask.sum(-1)`（每条回答除以自己的长度），再 `.mean()`。
- `dr_grpo` 的分母是 `size(0) * max_completion_length`，即 $N\,L_{\max}$。
- `dapo` 的分母 `num_items_in_batch` 是整个累积 batch 的有效 token 数。

### 25.7.6 本项目为什么显式写 `loss_type='grpo'`

**TRL 1.15.0 里 `GRPOConfig.loss_type` 的默认值是 `'dapo'`**（本地安装包 `grpo_config.py` 核对；远程 trl 1.15.0 的 dataclass 默认值也确认是 `'dapo'`，见 `recovery-audit.json`）。名字叫 GRPOTrainer，默认跑的却不是论文里的 GRPO 聚合方式。TRL 文档对 `'grpo'` 的说明是"不推荐，有长度偏差"。

本项目 `tour.py` 的 `make_policy_trainer` 显式写了 `loss_type='grpo'`，理由是**让手写的 `grpo_loss` 和框架用同一个口径**，方便对照和教学。代价是长度偏差。本项目两条 GRPO 的平均输出长度 59.0 token，首 10 步 62.8、末 10 步 59.8 和 59.7（本项目观察，`training-statistics.json`），100 步内没有看到"越来越长"；但步数太少，不能据此说长度偏差不存在。

这里的记录有一处限制：种子 0 的三条链没有保存完整的 Trainer 配置，`train-summary.json` 里也没有 `loss_type` 字段。"用的是 `grpo`"的依据是恢复这组运行时检查的远程代码（`recovery-audit.json` 的 `remote_code_loss_type`），不是当时的配置快照。现在的 tour.py 每次训练都保存 `train-config.json` 和摘要里的 `loss_type`。

读别人的报告也一样。如果里面只写了"用 TRL GRPOTrainer 训练"，没写 `loss_type`，你不能确定他用的是论文里的 GRPO：要看 TRL 版本和配置，在 1.15.0 下不写就是 `dapo`。

### 25.7.7 常见错误

- **不写 `loss_type`，以为跑的是 GRPO。**发现方法：打印 `trainer.args.loss_type`，并把它存进实验记录。
- **手写损失和框架对拍时，聚合口径不同。**每个 token 的损失都对，合起来就是对不上。先统一 `loss_type`。
- **用 `dr_grpo` 却把 `max_completion_length` 设得很大。**梯度尺度被常数整体压小，相当于学习率小了很多。
- **忽视长度变化。**每次 GRPO 训练都要画 `completions/mean_length` 和截断比例 `completions/clipped_ratio`；本项目截断比例是 3.05% 和 3.06%（本项目观察）。

## 25.8 实测：为什么 GRPO 没有胜过 SFT

操作步骤见 lab 第 2–4 部分和第 6 部分的记录表，这里只讲怎样读结果。

### 25.8.1 设置

本项目观察，RTX 4090（租用，48GB），seed 0，单次运行（来源：lab 第 6 部分、`train-summary.json`）：

- **起点**：Qwen3-0.6B，第 21 章 step-400 SFT adapter 经第 23 章合并得到的 `sft-merged`。参考模型就是它本身（关闭 LoRA）。
- **三条链，各 100 步**，LoRA r=16、alpha 32、q_proj+v_proj，学习率 $5\times10^{-6}$，FP32 参数加 bf16 autocast：
  1. **GRPO 分层奖励**：每步 8 提示 × 8 采样（microbatch 16 × 累积 4），温度 1.0，输出上限 160 token，β=0.04，ε=0.2，`loss_type='grpo'`，`scale_rewards='group'`；共 800 条提示，每步用新提示。
  2. **GRPO 只看解析**：除奖励外完全相同。
  3. **继续 SFT**：同样 800 条候选提示，监督换成标准答案，batch 8 × 累积 1；编码过滤后保留 795 条。
- **评测**：val n=500，贪心，最多 192 新 token；EM_norm 区间是 1000 次样本级 bootstrap（seed 0）；配对差是该运行减第 22 章 SFT 预测。

第三条链回答"奖励训练是否比继续监督更好"。只和 SFT 起点比，任何多训练 100 步的方法都可能"赢"。

两点不对等要记住：GRPO 用 800 条、SFT 用 795 条，有效样本集不严格相同；两者也不是等生成 token、等算力的对照，训练循环差约 36 倍（25.8.4 节）。所以本章说"继续 SFT 对照"时，指同起点、同样 100 步、同一批候选提示，不指同预算。两条 GRPO 的奖励都带着 25.4.5 节的验证器缺陷。

### 25.8.2 训练曲线怎样读

本项目观察，`training-statistics.json`（"首 10 步""末 10 步"指第 1–10、91–100 步均值）：

| 运行 | reward 首 10 → 末 10 | KL 末 10 步 | 有效组 | 平均长度 | 裁剪比例 |
|---|---|---:|---:|---:|---:|
| 分层奖励 | 0.3016 → 0.3589 | $6.08\times10^{-5}$ | 33.75% | 58.99 | 0 |
| 只看解析 | 0.4625 → 0.5484 | $3.20\times10^{-4}$ | 14.875% | 58.99 | 0 |

曲线图见 `outputs/book/ch25/gpu/training-curves.png`。按 lab 第 4 部分的顺序读：

1. **reward 上升了，但不能读成"固定题集上进步了这么多"。**每步换一批新提示，题目难度本身在变。
2. **KL 非常小。**$10^{-5}$～$10^{-4}$ 量级，策略几乎没有离开 SFT 起点。只看解析的 KL 大约是分层奖励的 5 倍，说明有缺陷的奖励推得更"猛"一些。
3. **裁剪比例为 0** 是 25.3.6 节的数学结论，不是 ε 的问题。
4. **长度基本没变。**

### 25.8.3 val 结果

本项目观察，RTX 4090（租用），val n=500，seed 0（`comparison.json`、各 `val-metrics.json`；SFT 起点的 CER、改坏和 fix_rate 来自 `outputs/book/ch22/gpu/analysis.json`）。改坏和 fix_rate 写成比例和计数：

| 运行 | val EM_norm（95% 区间） | 答对条数 | 与 SFT 起点配对差（百分点，95% 区间） | val CER | 改坏 | fix_rate |
|---|---|---:|---|---:|---:|---:|
| SFT 起点（第 22 章） | 67.8% [63.8, 71.8] | 339 | — | 0.0257 | 6.7%（11/163） | 55.5%（187/337） |
| GRPO 分层奖励 | 68.8% [64.8, 72.8] | 344 | +1.0 [+0.2, +2.0] | 0.0250 | 6.7%（11/163） | 57.0%（192/337） |
| GRPO 只看解析 | 68.6% [64.4, 72.4] | 343 | +0.8 [−0.2, +2.0] | 0.0248 | 7.4%（12/163） | 57.0%（192/337） |
| **继续 SFT（val 选中）** | **69.2% [65.0, 73.0]** | 346 | +1.4 [+0.6, +2.4] | 0.0298 | 6.7%（11/163） | 57.6%（194/337） |

（SFT 起点的 339/500 来自第 22 章；这里 67.8% 的区间是 bootstrap，第 22 章用的 Wilson 区间是 [63.6, 71.7]，两种方法不能混称。）

四行之间，改坏最多差 1 条，fix_rate 最多差 7 条。这两列没有算配对区间，这点差距不能算作改善。

`comparison.json` 只存了各链相对起点的配对差。三条链**直接两两比较**的配对差，是用同一个 `paired_bootstrap_diff` 在 CPU 上对已有预测另算的（本项目观察，CPU 复算，1000 次，seed 0）：

| 比较 | 配对差（百分点，95% 区间） | 只有前者对 | 只有后者对 |
|---|---|---:|---:|
| 继续 SFT − GRPO 分层奖励 | +0.4 [−0.4, +1.2] | 3 | 1 |
| 继续 SFT − GRPO 只看解析 | +0.6 [−0.2, +1.6] | 4 | 1 |

读这两张表：

- **三条链都比起点好一点。**分层奖励和继续 SFT 的配对差区间不含 0；只看解析的区间含 0。
- **三条链之间几乎分不开。**继续 SFT 和分层奖励在 500 题里只有 4 题结论不同（3 比 1）；区间都含 0。"继续 SFT 最高"只是选型规则的结果，不是"SFT 显著更好"。
- **两个指标不一致。**按 EM_norm 继续 SFT 最高；按 CER，只看解析最低（0.0248），继续 SFT 反而最高（0.0298）。和第 23 章一样，事先定好"按哪个指标选"很重要。本项目事先定的是 val EM_norm。

### 25.8.4 为什么没有胜过 SFT

先给结论：在这个任务、这个预算下，GRPO 能拿到的学习信号比继续 SFT 少得多，而成本高得多。下面的理由，前三条有数据支撑，第四条是推断（待验证），第五条是这组实验的限制。

**一、信号稀疏。**继续 SFT 的每条样本都直接给出"正确答案的每个 token"。GRPO 每步 8 道题里平均只有 2.7 道有梯度，而且每道题只告诉模型"这几个回答比同组平均好或差"，不告诉它正确答案长什么样（25.6.6 节，本项目观察）。

**二、验证器漏报。**800 条训练提示里有 310 条，正确答案在分层奖励下也只得 0 分（25.4.5 节，本项目观察，CPU 复跑）。这些题上，GRPO 最好的情况是没有信号，最坏的情况是在鼓励错误答案。SFT 不受影响，它直接用标准答案。这是本章保留下来的已知缺陷，修好之后的结果本项目没有测过。

**三、几乎没离开起点。**末段 KL 在 $10^{-5}$～$10^{-4}$ 量级，平均 token 熵约 0.022（本项目观察）。模型很笃定，采样很少探索出新东西；100 步、小学习率下，策略只挪动了一点点。三条链的 EM 结论在 500 题里只有 4～5 题不同（25.8.3 节），也印证了这一点。

**四、任务本身更适合 SFT（推断）。**OCR 后纠错有唯一的标准答案，而且我们手里就有，这是监督学习擅长的情形。强化学习的优势通常出现在**没有标准答案可模仿**、或者**正确答案有很多种写法**、需要模型自己探索的任务上（例如长推理链）。DeepSeekMath 自己也观察到 RL 主要提升 Maj@K、而不怎么提升 Pass@K，即 RL 更多是在"把已经会的答案排到前面"（Shao et al., 2024，§5.2）。

**五、种子少、样本小（限制）。**种子 0 的差别都在 2～3 条样本上，bootstrap 只衡量"换一批 val 题"的不确定性，不衡量"换一个训练种子"的不确定性。25.8.7 节补了两个种子，一共也只有三个。

**成本对比**（本项目观察，`train-summary.json`、`val-metrics.json`）：

| 运行 | 训练循环（秒） | val 生成（秒） | 训练 PyTorch 峰值显存（allocated） |
|---|---:|---:|---:|
| GRPO 分层奖励 | 1499.6 | 189.1 | 13.37 GiB |
| GRPO 只看解析 | 1495.1 | 188.3 | 13.38 GiB |
| 继续 SFT | 42.1 | 310.7 | 未记录 |

GRPO 的训练循环是继续 SFT 的约 36 倍（1499.6 / 42.1，数学结论）。时间主要花在生成上：每步要采 64 条回答。训练循环只计 `trainer.train()` 本身；当时同一张卡上还有其他任务并发，这些数字不是独占 GPU 的计费时间。

所以本章的实测结论是：**GRPO 管线是通的，分层奖励比起点好一点，但在 OCR 后纠错上，它没有理由取代更便宜的继续 SFT。**什么时候值得用 GRPO？当你**没有**逐 token 的标准答案、或者奖励能衡量 SFT 衡量不了的东西（例如渲染后的视觉一致性）时。第 34 章在 VLM 上会再试一次。

> **停下来想一想：**如果把 25.4.5 节那 310 条"正确答案也拿 0 分"的提示滤掉，再跑一次分层奖励的 GRPO，你预计有效组比例和 val EM 会怎样变？写下你的预测，再自己跑一次（练习 25.8）。

### 25.8.7 多种子补充：差距是不是种子噪声

单种子的差距只有零点几个百分点。换一个随机种子，排名会不会翻过来？补充实验给三条链各加了两个训练种子（1、2），连同原来的种子 0 一共三个。其余设置不变：100 步，同一批 500 条 val，test 没有再用（本项目观察，RTX 4090（租用），`outputs/book/ch25/gpu/supp/seed-summary.json`）。

| 链 | 种子 0 | 种子 1 | 种子 2 | 均值 ± 标准差 |
|---|---:|---:|---:|---:|
| GRPO layered | 68.8% | 68.0% | 68.4% | 68.40% ± 0.40 |
| GRPO parse_only | 68.6% | 68.4% | 68.2% | 68.40% ± 0.20 |
| 继续 SFT | 69.2% | 69.0% | 69.2% | 69.13% ± 0.12 |

（本项目观察，val EM_norm，n=500；标准差是三个种子的样本标准差，单位为百分点。）

三个种子里，继续 SFT 每一次都排第一。两种奖励的均值完全相同。用三个种子的配对差算 95% 区间（t 分布，自由度 2，单位为百分点）：

- layered − parse_only：0.00，区间 [−0.86, +0.86]。两种奖励分不出高低。
- 继续 SFT − layered：+0.73，区间 [−0.03, +1.49]，刚好含零。
- 继续 SFT − parse_only：+0.73，区间 [+0.16, +1.31]，不含零。

（本项目观察。这三个区间没有做多重比较校正，属于探索性比较。）

怎么读这组数？

- **"分层奖励比只看解析好"没有证据。** 三个种子的均值一样，区间对称地跨过零。
- **继续 SFT 有一个很小、但方向一致的领先**，大约 0.7 个百分点。只算种子波动时，它对 parse_only 的领先超出了噪声；如果把种子和 500 条样本同时重采样，两个区间都含零（`supp/seed-summary.json` 的 `crossed_seed_example_bootstrap95_pp`）。所以目前能说的是：有继续 SFT 小幅领先的探索性证据，但还不足以说它稳定地更好，也不能下"GRPO 不如 SFT"的结论。
- **三个种子很少。** t 区间依赖"差值近似正态"这个假设；3 × 500 条预测也不能当成 1500 个独立样本。

本章没有跑更长的 GRPO：一条 200 步的长链因为时间预算不够没有启动。所以"GRPO 训久一点会不会赢"仍然是开放问题（待验证）。

补充实验也给 25.5.5 节"没有观察到崩塌"多加了两个种子作为旁证：四次新 GRPO 训练全部正常结束，val CER 在 0.0248–0.0281 之间（本项目观察，`supp/seed1`、`supp/seed2` 下各 `val-metrics.json`）。

## 25.11 和真实框架的对应

下面按本地安装的 TRL 1.15.0 源码核对（`trl/trainer/grpo_config.py`、`grpo_trainer.py`），本项目远程也是 trl 1.15.0。

| 本章 | TRL 1.15.0 | 说明 |
|---|---|---|
| G（组大小） | `num_generations`，默认 8 | 本项目 8。生成 batch（`per_device_train_batch_size × 进程数 × steps_per_generation`）必须能被它整除；本项目 16 × 4 = 64 = 8 组 × 8 |
| β | `beta`，**默认 0.0** | 默认不加 KL、也不加载参考模型；本项目显式设 0.04。文档提到 DeepSeek-R1 用 0.001 |
| ε | `epsilon`，默认 0.2；`epsilon_high` 默认等于 `epsilon` | DAPO 推荐上界 0.28（Clip-Higher）。本项目 0.2，且因比率恒为 1 而没有起作用 |
| 聚合方式 | `loss_type`，**默认 `'dapo'`** | 可选 `grpo`、`dr_grpo`、`dapo`、`bnpo` 等；本项目显式 `'grpo'`（25.7 节） |
| 除以标准差 | `scale_rewards`，默认 `'group'` | `'none'` 即 Dr. GRPO 的只减均值；`'batch'` 用整批标准差 |
| 标准差口径 | `nanstd`，带 $\frac{n}{n-1}$ 修正（样本标准差） | 手写版用总体标准差，差 $\sqrt{G/(G-1)}$ 倍（25.2.3 节） |
| 一批样本更新几次 | `num_iterations`，默认 1 | 为 1 且对齐时 `old = logp.detach()`，比率恒为 1（25.3.6 节） |
| k3 | `per_token_kl = exp(ref - logp) - (ref - logp) - 1` | 和 `grpo_loss` 相同 |
| KL 梯度修正 | `use_bias_correction_kl`，默认 True：`per_token_kl * coef_1` | 手写版**没有**这一步。比率为 1 时值相同，但梯度不同：TRL 多出 $k3\cdot\nabla\log\pi_\theta$ 一项（第 24 章 24.5.7 节） |
| 裁剪统计 | `clip_ratio/low_mean`、`high_mean`、`region_mean`：只数梯度为 0 的两格 | 手写版 `clip_fraction` 不分方向（25.3.5 节） |
| 无效组 | `frac_reward_zero_std` | 有效组比例 = 1 − 它 |
| 长度 | `max_completion_length`；`mask_truncated_completions`，默认 False | `dr_grpo` 的分母用到 `max_completion_length` |
| 奖励函数 | `reward_funcs=[f]`，`f(completions, **数据集列)` 返回浮点列表 | 本项目把 `source`、`target` 作为数据集列传给奖励函数 |

TRL 的 GRPOTrainer 默认配置（`loss_type='dapo'`、`beta=0`）已经不是 DeepSeekMath 论文里的 GRPO。做实验要把这几个参数写进记录，读别人的报告要问清楚。

## 25.12 小结

GRPO 用"同一个提示采样 G 个回答、和组内平均比"替代了价值网络，再套上 PPO 的裁剪目标和 k3 KL 惩罚；组均值带来一点无害的缩放，除以标准差则会放大几乎没有差别的组。奖励就是规格说明：只看解析的奖励能被单字符骗到满分，分层奖励挡住了这些探针，却在 38.75% 的训练提示上让正确答案也只得 0 分。本章的训练保留了这个缺陷，推荐流程是先修验证器再训练。组内奖励全相同的组（全对或全错）没有奖励项梯度（KL 项除外），本项目分层奖励只有 33.75% 的组有效；`loss_type` 决定长短回答怎样分摊损失，TRL 1.15.0 默认是 `'dapo'`，本项目显式用了 `'grpo'`。实测中 GRPO 比 SFT 起点好约 1 个百分点。种子 0 上它和继续 SFT 分不开；三个种子里继续 SFT 每次都排第一，平均领先约 0.7 个百分点，只算探索性证据；GRPO 的训练循环约慢 36 倍。本章报告了文本后纠错面板的 EM_norm、CER、改坏和 fix_rate，test 只评了登记的继续 SFT。在有标准答案的任务上，先问一句"继续 SFT 行不行"。
