## 答案与提示

**23.1** 第一步 SFT：示范数据 → $\pi^{\mathrm{SFT}}$。第二步奖励模型：同一提示的多个回答 + 人工比较 → $r_\phi$。第三步 RL：提示 + 奖励模型 + 参考模型 → $\pi_\theta$。PPO 通常要策略、参考模型、奖励模型、价值模型四个。DPO 只要策略和参考模型；用 LoRA 时参考模型可以是"关闭 adapter 的同一个模型"，只占一份基座（本章就是这样，23.8.1 节）。

**23.2** (a) 23.5.2 节：反解出的奖励含 $\beta\log Z(x)$，代入 BT 后正负抵消。(b) 不成立。不同常数会改变分差。所以 DPO 要求 chosen 和 rejected 来自**同一个提示**。

**23.3** β → ∞：$e^{r/\beta}\to1$，$\pi^*\to\pi_{\mathrm{ref}}$，完全不学偏好。β → 0⁺：概率全部集中到 $\pi_{\mathrm{ref}}>0$ 的回答中奖励最高的那些（不会去 $\pi_{\mathrm{ref}}=0$ 的地方）。参考概率并没有完全失去作用：若奖励最高的回答集合为 $M$，极限是 $\pi^*(y)=\pi_{\mathrm{ref}}(y)/\sum_{z\in M}\pi_{\mathrm{ref}}(z)$，$y\in M$，并列最高的回答之间仍按参考概率分配。例如参考 (0.6, 0.4)、奖励 (1, 1)，任何 β 下都是 (0.6, 0.4)（数学结论）。

**23.4** 策略 = 参考，所以两个对数概率比都是 0，margin = 0，损失 $-\log\sigma(0)=\log2$。accuracy 按"chosen 奖励 > rejected 奖励"计，0 > 0 不成立，所以是 0。

**23.5** SFT 对每个样本权重相同（每个 token 的负对数似然，梯度大小只取决于模型给目标 token 的概率）。DPO 的权重在隐式奖励排错时接近 1，排对且拉开后接近 0。好处：把力气花在还没学会的对上。问题：已经学会的对几乎不再提供约束，而梯度只管差值，不管 chosen 本身是否上升，所以 chosen 的概率可能和 rejected 一起下降（23.5.6 节情形 C、23.8.4 节）。

**23.6** 自己采样：偏好对落在模型自己的输出分布上，学的是它真会犯的错；而且 DPO 的推导是在 $\pi_{\mathrm{ref}}$ 有支撑的回答上进行的，离分布太远的回答对数概率极低，信号不可靠。新提示：避免在 SFT 背过的题上做偏好，那里模型几乎总能写对，候选没有差异，而且偏好会和"记忆"混在一起。

**23.7** 不算"标签错了"：在"离标准答案更近"这个定义下，chosen 确实更好。它是"两个都不好、只是一个没那么差"。人工标注里的看走眼是标签方向本身错了。前者至少方向对，但会把"错得少一点"的写法（如 `\leq`）推高；后者直接把模型往错的方向推。

**23.8** 求和时，回答越长，对数概率的数值越大、差值的范围越大，长度可以直接影响 margin。本章看 `chosen_longer_rate` = 0.388、一样长 61 对、更短 176 对、平均长度 108.2 对 107.7，以及训练后 val 输出平均长度 120.8 对 SFT 120.5，判断没有明显长度偏好（本项目观察）。

**23.9** 分差 2.0；$\sigma(2)=0.8808$；损失 $-\log0.8808=0.1269$（数学结论）。

**23.10** β = 0.5：权重 0.6 和 $0.4e^2=2.9556$，$Z=3.556$，$\pi^*=(0.169,\ 0.831)$。β = 2：权重 0.6 和 $0.4e^{0.5}=0.6595$，$Z=1.259$，$\pi^*=(0.476,\ 0.524)$（数学结论）。

**23.11** (a) $\Delta_w=+1$，$\Delta_l=-2$；$\hat r_w=0.2$，$\hat r_l=-0.4$；margin 0.6。(b) $\sigma(0.6)=0.6457$，损失 0.4375。(c) $\sigma(-0.6)=0.3543$；对 $y_w$：$-0.2\times0.3543=-0.0709$；对 $y_l$：$+0.0709$（数学结论）。

**23.12** $\Delta_w=-1$，$\Delta_l=-5$，margin $0.2\times4=0.8$，损失 $-\log\sigma(0.8)=0.3711$，比 (b) **小**。chosen 的序列概率是参考的 $e^{-1}\approx0.368$ 倍。损失下降，好答案的概率却下降了（数学结论）。

**23.16** 策略起点是"基座 + SFT adapter"，参考却是"基座"，两者不一致，所以第一步 margin ≠ 0、loss ≠ log 2。改法：先把 SFT adapter 合并（本章做法，lab 第 2 部分），以合并模型为起点，新 LoRA 关闭时即为参考；或者显式传一个与起点完全相同的 `ref_model`。

**23.17** margin 很负时 `sigmoid` 下溢为 0，`log(0) = -inf`，反向得到 NaN。改成 `-F.logsigmoid(beta * margin)`。

**23.18** 典型的"β 太小 / 跑偏"：DPO 的梯度只管差值，模型通过同时压低 chosen 和 rejected（rejected 更快）降低损失，偏离 SFT（23.8.4 节）。方向：增大 β；减少步数或学习率；在 val 上看 `logps/chosen` 与改坏数选停止点；检查 chosen 与 rejected 是否高度相似（共享 token 多）；考虑在损失里加 chosen 的 SFT 项（TRL 可用 `loss_type=["sigmoid", "sft"]` 配合 `loss_weights`，具体效果待验证）。

**23.19** 两处：参考前向没有 `no_grad`；参考模型的参数进了优化器，参考在跟着变。梯度会穿过参考的对数概率流向参考模型：把参考给 chosen 的对数概率压低、给 rejected 的抬高，同样能拉大 margin。于是 margin 主要是参考在动造出来的，策略本身几乎没学。23.8.2 节的反推检查：固定同一批样本，不同时刻算出的参考对数概率会对不上；不同运行（不同 β）在同一步反推出的参考值也会对不上。

**23.20** logits 全 0 时每个位置的分布都是均匀的，错位与否，每个 token 的对数概率都是 $\log(1/5)$；只要有效 token 数碰巧一样，结果就一样。能抓到的测试：让不同位置的 logits 不同（例如只把某一个位置的某个 token 设高），使错位会选到不同的值。

**23.21** 按 token 平均后，对数概率比缩小了约"回答 token 数"倍（本章回答的 token 数没有统计，待验证），同样的 β 下 margin 小得多，损失和日志里的 margin 都几乎停在起点附近。若要手感接近，β 要相应放大约"平均 token 数"倍。但这已经不是标准 DPO 了，β 的含义也变了。
