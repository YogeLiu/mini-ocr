## 答案与提示

**1.** (a) 初始时 BA = 0，挂上 LoRA 的模型与原模型完全相同，微调从预训练的好起点出发。(b) 第一步 ∂L/∂A = s(Bᵀg)xᵀ = 0，∂L/∂B = s·g(Ax)ᵀ ≠ 0，所以只有 B 有梯度；第一步更新后 B ≠ 0，第二步 A 也有梯度。(c) 两个梯度都是 0（∂L/∂B 含 Ax = 0，∂L/∂A 含 B = 0），永远不动。(d) 行。乘积仍为 0，起点仍是原模型，只是第一步变成 A 有梯度、B 没有。关键是"乘积为 0、至少一个因子不为 0"。

**2.** (a) 参数数目不变；变的是旁路缩放 α/r，从 2 变成 4，等于把增量放大一倍。(b) 换 r 时旁路缩放保持不变，比较不同 r 时不再混进"缩放变了"这个因素。(c) 第一步只有 ∂L/∂B = s·g(Ax)ᵀ，它有 r 列，每列期望平方范数相同，总平方范数 ∝ r，范数 ∝ √r。本章实测 2.07、4.06、8.17（r = 4、16、64）。

**3.** LoRA 的旁路是线性的、和原层并联：W₀x + sBAx = (W₀ + sBA)x，可以由分配律合成一个矩阵。Adapter 串联在路径上，中间有非线性，无法写成"原矩阵加一个矩阵"。合并后推理结构与原模型相同，没有额外计算。

**4.** LoRA 只缩小了"为更新而存"的梯度、m、v（以及可训练权重本身）。冻结的基座权重全部还在（本章 fp32 下约 2.22 GiB），激活和 logits 随 batch × 长度增长，也一项没少。r = 16、q + v 时静态部分 2.25 GiB 里 98% 是冻结权重；2 × 512 时前向增量还有 3.42 GiB（本项目观察）。

**5.** 量化冻结的基座权重；A、B 及其梯度、优化器状态保持高精度，计算时把基座临时反量化成 bf16。它只缩小账本第 ① 项。0.6B 的权重本来只有 1–2 GiB，长序列时激活和 logits 已经更大；70B 的权重有上百 GiB，① 是最大项，量化效果才显著。

**6.** (a) B = 0 时两边旁路输出都是 0，前向、A 梯度、输入梯度的比较必然通过，查不出缩放写错之类的问题；只剩 B 梯度 s·g(Ax)ᵀ 还依赖缩放，能抓住缩放错误。B 非零时每一项比较才都有意义。(b) 输入梯度是传给前一层的梯度，真实模型里反向要穿过所有层；输入梯度错了，前面所有层的 A、B 梯度都会错，而单看本层 A、B 的梯度发现不了。

**7.** 我们关心的是生成的整条公式对不对。NLL 是 teacher forcing 下每个 token 的平均，绝大多数 token 是照抄，几乎零损失；决定对错的只是少数改错位置，而且生成是自回归的，一步错会影响后面。NLL 和 EM 不一一对应，主指标应当和最终目标一致。

**8.** 可以列：训练量不同（3200 对 8192 次样本，LoRA 不到一轮）；学习率不同且都没有为本对照专门调；长度上限、接受样本数不同；生成预算和批大小不同；选择方式不同（各自在 val 上选步或选配置，乐观偏差大小不同）；LoRA 只挂了注意力投影，没挂 MLP。

**9.** (a) in + out：q 3072，k 2048，v 2048，o 3072，gate 4096，up 4096，down 4096，合计 22,528；× 8 = 180,224。(b) × 28 = 5,046,272，占 0.85%。（练习 20.3 可用 meta 设备核对：本地复核得到 5,046,272。）

**10.** (a) s = 4 / 1 = 4；h = 3 − 1 = 2；Bh = [0, 0]；y = W₀x = [3, 1]。(b) g = [1, 0]。∂L/∂B = s·g·hᵀ = 4 × [1, 0]ᵀ × 2 = [[8], [0]]，形状 `[2, 1]`；∂L/∂A = s(Bᵀg)xᵀ = 0，即 [[0, 0]]，形状 `[1, 2]`。(c) Bh = [0.5, 1]，× 4 = [2, 4]，y = [3, 1] + [2, 4] = [5, 5]。sBA = 4 × [[0.25, −0.25], [0.5, −0.5]] = [[1, −1], [2, −2]]，W' = W₀ + sBA = [[1 + 1, 0 − 1], [0 + 2, 1 − 2]] = [[2, −1], [2, −1]]。W'x = [6 − 1, 6 − 1] = [5, 5]，一致。(d) Bᵀg = 0.25，∂L/∂A = 4 × 0.25 × [3, 1] = [[3, 1]]。

**11.** N_LoRA = 4,587,520（正文 20.7.3 节表）。(a) 4N = 2,384,199,680；16 × 4,587,520 = 73,400,320；合计 2,457,600,000 字节 ≈ 2.29 GiB。(b) 2N = 1,192,099,840；16 × 4,587,520 = 73,400,320（其中 2 字节是 LoRA 权重的 bf16 副本，14 字节是梯度、主权重、m、v）；合计 1,265,500,160 字节 ≈ 1.18 GiB。(c) 全参 16N = 9,536,798,720 字节 ≈ 8.88 GiB；分别省约 6.59 GiB 和 7.70 GiB。

**12.** (a) 4 × 512 × 151,936 × 2 = 622,329,856 字节 ≈ 0.58 GiB。(b) × 2 = 1,244,659,712 字节 ≈ 1.16 GiB（所有位置都被监督时的上界；本章 `causal_loss` 只对监督位置做 fp32 副本）。(c) 573,440 × 12 = 6,881,280 字节 ≈ 6.6 MiB。bf16 logits 约是它的 90 倍，fp32 副本约 181 倍。

**13.** (a) 596,049,920 × 0.5 = 298,024,960 字节。(b) 596,049,920 / 64 = 9,313,280 块 × 4 = 37,253,120 字节；每参数多 32 / 64 = 0.5 bit。(c) 合计 335,278,080 字节 ≈ 0.31 GiB，约是 fp32 的 1/7。这是"全部量化"的理想算法，真实库通常不量化嵌入等层（待验证），所以实际更大；双重量化可以把缩放常数再压小。

**14.** r 从 4 到 256 是 64 倍，√64 = 8，预计约 2.07 × 8 ≈ 16.6（数学推理，期望意义下，待验证）。改成 α/√r、固定 α = 8：范数 ∝ s√r = (α/√r)·√r = α，不再随 r 变化；r = 4 时 s = 4，是原来 s = 2 的两倍，所以预计约 2 × 2.07 ≈ 4.1，且各个 r 大致相同（待验证）。

**15.** (a) 400 × 8 = 3200 次，3200 / 4049 ≈ 0.79 轮。(b) 8192 / 8 = 1024 步。

**16.** B 没有初始化为 0（例如在 `__init__` 末尾对 A、B 都调用了初始化函数），挂上 LoRA 时输出就已偏离基座。`test_initialization_and_first_gradient`（初始最大差应为 0）会失败；`test_tiny_qwen_forward_backward_and_memory` 里"挂上后 logits 等于原模型"也会失败。
