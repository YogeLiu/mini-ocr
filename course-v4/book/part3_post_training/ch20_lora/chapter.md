# 第 20 章 LoRA

## 本章导读

第 19 章用全参数 SFT 教会了 Qwen3-0.6B 改公式。代价是：模型的每一个参数都要有梯度、有两份 AdamW 动量，光是这些静态的东西就要 8.88 GiB（数学结论，20.1.1 节），那次运行的峰值显存是 21.27 GiB（本项目观察，第 19 章 19.7.5 节）。0.6B 已经是很小的模型了；换成 7B，同样的做法要一百多 GiB，一张消费级显卡根本装不下。

这一章学一个让微调变便宜的办法：**LoRA**（Low-Rank Adaptation，低秩适配）。它的想法是：原来的大矩阵 W 冻住不动，只学一个很瘦的修正量 (α/r)·BA。B 和 A 是两个细长的矩阵，加起来的参数常常不到原矩阵的百分之一。本章的实验里，可训练参数从 5.96 亿降到 57 万到 1835 万（本项目观察，20.11 节）。

本章要讲清六件事：

1. 公式 `W + (α/r)·BA` 从哪来，为什么低秩够用（20.1 到 20.2）。
2. 为什么 B 必须从 0 开始（20.3）。
3. 从零写一个 LoRA 层，挂到 Qwen3 上，再合并回原权重并验证一致（20.4 到 20.6）。
4. 可训练参数量怎样随 rank、alpha、目标模块变化，手算 Qwen3-0.6B 一个配置（20.7）。
5. 只训练很少的参数，为什么**仍然**可能显存不足，以及 QLoRA 怎样再省一步（20.8 到 20.9）。
6. 和 Hugging Face 的 PEFT 库对拍，确认我们写的和公认的实现一样（20.10）。

最后用后纠错任务做一次 rank × 目标模块的扫描（20.11），并和第 19 章的全参 SFT 在同一批 val 上比较（20.12）。评测用第 0 章定义的文本后纠错面板。结果先放在这里：六组 LoRA 都远超照抄，选中配置的 val EM_norm 是 0.670，冻结后在 test 上是 0.620；同一批 val 上全参 SFT 是 0.775，不过两边的训练量和超参并不相同（本项目观察）。

先修：第 16 章的显存账（每参数约 16 字节、激活显存）、第 19 章的 SFT 数据格式和训练循环。实验步骤在 `lab.md`，正文只引用它的节号。

**和项目的关系**：TexPixel 后面有两处要微调：后纠错模型和 VLM。两处都用 LoRA。本章亲手写一遍 `miniocr/nn/lora.py`；后面的章节训练时用 PEFT 提供的 LoRA，20.10 节的对拍会确认两者的 LoRA 层算的是同一件事。

## 20.1 全参微调贵在哪里

### 20.1.1 一笔显存账

> **回顾（第 16 章 16.6 节）**：用 AdamW 训练时，每个**可训练**参数要存权重、梯度、一阶矩 m、二阶矩 v。纯 fp32 下是 4 + 4 + 4 + 4 = 16 字节；混合精度下组成不同，合计也是 16 字节。冻结的参数只需要存权重本身。

Qwen3-0.6B（嵌入与输出层共享）有 596,049,920 个参数（数学结论：由本地 config 按结构算出，和本章 tour 第 4 部分统计的基座参数一致）。全参训练的静态显存是

$$596{,}049{,}920 \times 16 = 9{,}536{,}798{,}720 \text{ 字节} \approx 8.88 \text{ GiB}.$$

（数学结论。本书的 GiB 是 2³⁰ = 1,073,741,824 字节，9,536,798,720 ÷ 1,073,741,824 ≈ 8.88。）这还没算激活。第 19 章那次全参 SFT 的峰值是 21.27 GiB（本项目观察，RTX 4090 租用，微批 8、长度上限 512）。

这些东西里，推理要用的只有权重本身。梯度和两份动量是**为了更新**才存的。如果能让大多数参数不更新，这三项就几乎没了。

### 20.1.2 想法：冻住大矩阵，只学修正量

微调前后，一个线性层的权重从 W₀ 变成 W₀ + ΔW。全参微调直接学整个 ΔW，它和 W₀ 一样大。

换个角度：我们并不需要 ΔW 是任意的矩阵。微调只是把一个已经会说话的模型，往会改公式的方向推一点。推这一点所需要的自由度，也许远小于 in × out。

打个比方。一张高清照片有几百万个像素。如果你只是想把它调暖一点，不需要逐像素重新画，只需要调几个旋钮：色温、亮度、对比度。旋钮少，但足以描述你想要的那种改动。LoRA 就是给每个大矩阵配几个旋钮。

### 20.1.3 为什么低秩可能够用

旋钮少这个说法，数学上叫**低秩**。一个矩阵的秩（rank）是它真正独立的方向有几个：不管输入是什么，矩阵乘出来的输出最多只能铺开这么多个独立方向。秩为 r 的 `[out, in]` 矩阵，哪怕有几百万个元素，本质上也只由 r 对方向和它们的强弱决定（20.2.2 节会看到这句话的精确形式）。LoRA 论文（Hu et al., 2021）的出发点是两条观察：

- 预训练模型有较低的"内在维度"：只在一个很小的随机子空间里优化，也能接近全参微调的效果（论文引用 Aghajanyan et al. 2020 的结果，待验证）。
- 由此假设：**微调带来的权重变化 ΔW 也有较低的"内在秩"**。

这是一个假设，不是定理。它在很多任务上表现不错，但不保证在你的任务上成立。本章 20.11 节和 20.12 节会看到：在我们的后纠错任务上，这个假设大体成立，但有代价。

> **停下来想一想**：如果 ΔW 的秩必须很高（比如任务和预训练差别极大），LoRA 会出现什么现象？你会怎样从实验里发现它？（提示：看 rank 增大时 val 指标还在不在涨。）

## 20.2 LoRA 的公式

### 20.2.1 公式和形状

先给结论。对一个线性层 y = W₀x，LoRA 把它改成

$$y = W_0 x + \frac{\alpha}{r}\, B A x.$$

各个量的形状（沿用 PyTorch `nn.Linear` 的约定，权重是 `[out, in]`）：

| 符号 | 形状 | 是否训练 | 含义 |
|---|---|---|---|
| x | `[..., in]` | 不适用 | 输入 |
| W₀ | `[out, in]` | 冻结 | 原权重 |
| A | `[r, in]` | 训练 | 把输入压到 r 维 |
| B | `[out, r]` | 训练 | 再从 r 维放回输出 |
| r | 标量 | 超参 | rank（秩） |
| α | 标量 | 超参 | 缩放系数（alpha） |

所以 BA 的形状是 `[out, r] @ [r, in] = [out, in]`，和 W₀ 一样，可以直接相加。

把它看成两条并联的路：

```text
          ┌──── W₀ (冻结, out×in) ─────────┐
x ──────┤                                  ├──(+)── y
          └── A (r×in) ── B (out×r) ── ×α/r ┘
```

上面那条是原模型，下面那条是"旁路"。旁路中间只有 r 维宽，像一根细管子。

### 20.2.2 低秩矩阵能表示什么

BA 的秩最多是 r（数学结论：秩不超过任一因子的秩，而 A 只有 r 行）。展开来看：

$$BA = \sum_{j=1}^{r} b_j\, a_j^{\top},$$

其中 b_j 是 B 的第 j 列（长 out），a_jᵀ 是 A 的第 j 行（长 in）。每一项 b_j a_jᵀ 是一个"秩 1 矩阵"：它只认输入里的一个方向 a_j，并把读到的大小写到输出的一个方向 b_j 上。

r 个这样的读一个方向、写一个方向叠起来，就是 LoRA 能做的全部改动。r = 4 意味着：这个层的修正只能在 4 个输入方向、4 个输出方向上起作用。旋钮就是这 4 对方向和它们的大小。

反过来，任何秩为 k 的矩阵都能写成 k 个秩 1 项之和，而且有一种最好的写法：**奇异值分解**（singular value decomposition，SVD）。它把任意一个 `[out, in]` 矩阵 M 写成

$$M = \sum_{i=1}^{k} \sigma_i\, u_i v_i^{\top},\qquad \sigma_1 \ge \sigma_2 \ge \dots \ge \sigma_k > 0.$$

这里 u_i（长 out）和 v_i（长 in）都是单位长度的方向，同一组里两两正交；σ_i 叫奇异值，是第 i 对方向上的强度，已经从大到小排好。只保留前 r 项，得到的就是所有秩不超过 r 的矩阵里离 M 最近的一个（Eckart-Young 定理）。用 Frobenius 范数（全部元素平方和再开方）量距离，丢掉部分的大小正好是 √(σ_{r+1}² + … + σ_k²)（数学结论）。

举个数。假设某个 ΔW 的奇异值是 10、3、0.5、0.1（为演示假设的）。平方和是 100 + 9 + 0.25 + 0.01 = 109.26，ΔW 本身的 Frobenius 范数是 √109.26 ≈ 10.45。只留前两项，保留了 (100 + 9) / 109.26 ≈ 99.8% 的平方和，误差的范数是 √(0.25 + 0.01) ≈ 0.51（数学结论）。奇异值掉得越快，低秩近似就越准。20.1.3 节的假设换成这套语言就是：微调需要的 ΔW，奇异值掉得很快，前几项就占了绝大部分。

LoRA 训练时并不做 SVD。它不先算出完整的 ΔW 再截断，而是直接用梯度下降学 B 和 A。把 b_j 看成 σ_j u_j、a_j 看成 v_j，BA 和截断后的 SVD 形状相同；区别是学出来的 b_j、a_j 不必正交，也不按大小排好。SVD 在这里的作用是告诉我们：如果 ΔW 真的接近低秩，r 项之和这个形式就足够把它表示出来。

### 20.2.3 参数省了多少

全参 ΔW 有 in × out 个数。LoRA 有

$$\underbrace{r \cdot in}_{A} + \underbrace{out \cdot r}_{B} = r\,(in + out)$$

个（数学结论）。

用 Qwen3-0.6B 的 q_proj（in = 1024，out = 2048，数学结论：来自本地 config，hidden 1024，16 个头 × head_dim 128）算一下：

- 全参：1024 × 2048 = 2,097,152。
- r = 4：4 × (1024 + 2048) = 12,288，是全参的 0.59%。
- r = 64：64 × 3072 = 196,608，是全参的 9.4%。

（数学结论。）r 越小越省。但 r 太小，旋钮就不够用。

### 20.2.4 α 和 r 的分工

为什么还要一个 α？只用 BA 不行吗？

r 决定有几个旋钮，α/r 决定旋钮拧一格有多大劲。把它们分开，有一个实用的好处：

- 换 r 的时候，如果保持 **α/r 不变**，旁路的缩放就不变，比较不同 r 时少了一个混杂因素。本章实验固定 α/r = 2（r = 4 时 α = 8，r = 64 时 α = 128）。
- 论文的做法是把 α 设成第一次试的 r，之后不再调 α，理由是用 Adam 时调 α 大致相当于调学习率（Hu et al. 2021 §4.1，待验证）。

**α 不改变参数数目**（数学结论：它只是个标量乘数，代码里也不是参数）。测试 `test_attach_counts_alpha_and_atomic_error` 专门检查了这一点：把 α 改成 99，参数统计一个数都不变。

还有一个细节要先记住，20.3.5 节会用到：α/r 固定时，r 越大，旁路的总劲其实越大。因为 BA 是 r 个秩 1 项的和，项越多，同样大小的 B、A 叠出来的 ΔW 越大。有一种变体 rsLoRA 把缩放改成 α/√r，并且**固定 α**（不再随 r 变），这样 s·√r = α，抵消了这个效应；如果仍像本章这样让 α = 2r，缩放会变成 2√r，效应反而更强（数学结论；rsLoRA 的实际效果待验证，本章没有实测）。

## 20.3 为什么 B 要初始化为 0

### 20.3.1 结论：起点必须是原模型

先说结论：**B 初始化为 0，A 随机初始化**。这样一开始 BA = 0，挂上 LoRA 的模型和原模型**一模一样**。

为什么这很重要？因为原模型是我们花大价钱预训练出来的好起点。如果一挂上旁路，模型的输出就变了，等于先往好模型里掺了一把随机噪声，再从被破坏的状态开始训练。微调从原模型出发，才谈得上微调。

那为什么不把 A、B 都设成 0？因为那样它们会**永远**是 0。下面推一遍。

### 20.3.2 一步一步推梯度

记 s = α/r，旁路中间量 h = Ax（形状 `[r]`），输出 y = W₀x + s·Bh。设 g = ∂L/∂y（形状 `[out]`）是从上游传回来的梯度。

**对 B 求梯度。** y 对 B 是线性的：y 的第 i 个分量里含 s·Σⱼ B_ij h_j，所以 ∂y_i/∂B_ij = s·h_j，而 B_ij 只出现在 y_i 里。链式法则给出 ∂L/∂B_ij = g_i · s·h_j，把所有 (i, j) 排成矩阵就是

$$\frac{\partial L}{\partial B} = s\, g\, h^{\top} = s\, g\, (Ax)^{\top}. \quad (\text{形状 } [out, r])$$

**对 A 求梯度。** 先求对 h 的梯度。h_j 出现在每一个 y_i 里，系数是 s·B_ij，所以要对 i 求和：∂L/∂h_j = s·Σᵢ B_ij g_i，写成矩阵就是 ∂L/∂h = s·Bᵀg（形状 `[r]`）。h = Ax 对 A 的关系和 y 对 B 的关系一模一样（把 B、h、g 换成 A、x、∂L/∂h，并且这里没有 s），所以照搬上一步

$$\frac{\partial L}{\partial A} = (s\, B^{\top} g)\, x^{\top}. \quad (\text{形状 } [r, in])$$

（数学结论。有一个 batch 时，对所有 token 求和即可。）

现在代入初始化：

| 初始化 | ∂L/∂A | ∂L/∂B | 后果 |
|---|---|---|---|
| B = 0，A 随机 | **0**（因为含 Bᵀ） | s·g(Ax)ᵀ，**非零** | 第一步只有 B 有梯度，之后 B ≠ 0，A 也开始有梯度 |
| A = 0，B = 0 | 0 | 0（因为 Ax = 0） | 永远不动，旁路是死的 |
| A、B 都随机 | 非零 | 非零 | 能训练，但起点已经偏离原模型 |

第一行就是 LoRA 的做法。第一步 A 的梯度是 0，这不是 bug：B 先长出来，下一步 A 就有梯度了。注意梯度为 0 不等于参数完全不变：本章的 AdamW 带 weight decay 0.01，第一步 A 仍会被乘上 1 − 学习率 × 0.01 = 1 − 2 × 10⁻⁴ × 0.01 = 0.999998，轻轻缩小一点（数学结论）。

把 A 设 0、B 随机也能满足"起点等于原模型"，而且这时第一步是 A 有梯度、B 没有（对称地推一遍即可）。论文和 PEFT 默认用的是 B 为 0 这一种（待验证：PEFT 的其他 `init_lora_weights` 选项本章没有试）。关键是：**乘积为 0，且至少一个因子不为 0**。

### 20.3.3 一个小数字例子

取 in = 3，out = 2，r = 1，α = 2，所以 s = α/r = 2。

$$W_0 = \begin{bmatrix}1&0&0\\0&1&0\end{bmatrix},\quad A = \begin{bmatrix}1&0&1\end{bmatrix},\quad B = \begin{bmatrix}0\\0\end{bmatrix},\quad x = \begin{bmatrix}1\\2\\3\end{bmatrix}.$$

**前向（B = 0）：**

1. W₀x = [1, 2]，形状 `[2]`。
2. h = Ax = 1·1 + 0·2 + 1·3 = 4，形状 `[1]`。
3. Bh = [0, 0]；乘 s 还是 [0, 0]。
4. y = [1, 2]。和原模型完全一样。

**反向**，取 L = y₁ + y₂，所以 g = [1, 1]：

- ∂L/∂B = s·g·hᵀ = 2 × [1, 1]ᵀ × 4 = [[8], [8]]，形状 `[2, 1]`。
- ∂L/∂A = s·(Bᵀg)·xᵀ = 2 × 0 × [1, 2, 3] = [[0, 0, 0]]，形状 `[1, 3]`。

**假设更新后 B = [[0.5], [−1]]：**

- Bh = [2, −4]，乘 s 得 [4, −8]；y = [1, 2] + [4, −8] = **[5, −6]**。
- 这时 ∂L/∂A = 2 × (0.5 − 1) × [1, 2, 3] = [[−1, −2, −3]]，A 开始有梯度了。

**合并**（20.6 节会细讲）：

$$s\,BA = 2\begin{bmatrix}0.5&0&0.5\\-1&0&-1\end{bmatrix} = \begin{bmatrix}1&0&1\\-2&0&-2\end{bmatrix},\quad W' = W_0 + sBA = \begin{bmatrix}2&0&1\\-2&1&-2\end{bmatrix}.$$

W'x = [2 + 0 + 3, −2 + 2 − 6] = **[5, −6]**，和走旁路的结果一样。

参数量：A 有 1 × 3 = 3 个，B 有 2 × 1 = 2 个，共 r(in + out) = 1 × 5 = 5 个。

这组数字都可以用本章的 `LoRALinear` 逐个打印核对（本项目观察，CPU fp32，我们按上面的值手动设置 W₀、A、B 后得到的输出、梯度、合并权重与手算完全相同；练习 20.1 让你自己做一遍）。

### 20.3.4 对照实测：第一步一模一样

本章第 6 部分训练了 6 组配置（20.11 节）。它们的 rank 和目标模块都不同，但**第 1 步的 train loss 全部是 0.35206**（本项目观察，RTX 4090 租用，`full/*-history.json`）。

原因就是 B = 0：第 1 步前向时，6 个模型都还等于同一个基座，喂的又是同一个 batch（同一种子、同一数据顺序），loss 当然一样。如果哪天你看到挂上 LoRA 后第一步的 loss 和基座不同，第一件事就是检查 B 是不是被别的初始化覆盖了。

### 20.3.5 第一步的梯度范数为什么跟着 √r 走

同一份记录里还有一个漂亮的规律。q、v 两个模块、α/r 固定为 2 时，第 1 步（裁剪前）的梯度范数是（本项目观察，`full/*-history.json`）：

| rank | 第 1 步梯度范数 |
|---:|---:|
| 4 | 2.07 |
| 16 | 4.06 |
| 64 | 8.17 |

rank 每翻 4 倍，梯度范数大约翻 2 倍。用 20.3.2 节的公式就能解释：第 1 步 ∂L/∂A = 0，只有 ∂L/∂B = s·g(Ax)ᵀ。三组的 s 都是 2；g 也相同，因为 B = 0 时三个模型都等于基座，喂的又是同一个 batch。不同的只有 A 的行数 r。它的第 j 列是 s·g·(a_jᵀx)。A 的每一行独立同分布地随机初始化，所以每一列的期望平方范数相同，r 列加起来，平方范数正比于 r，范数正比于 √r（数学结论，期望意义下）。√4 = 2，和实测对得上。

这也说明 20.2.4 节那句话：α/r 固定时，r 越大，起步的劲越大。本章训练把梯度范数裁剪到 1（第 19 章同一个训练循环），这几组第 1 步的范数都大于 1，所以开头都被裁剪了。

## 20.4 从零实现 LoRA 层

### 20.4.1 逐行读 `LoRALinear`

代码在 `miniocr/nn/lora.py`，被 `>>> 练习 20.1` 和 `<<<` 包起来的部分是你要自己写的。

```python
class LoRALinear(nn.Module):
    def __init__(self, base, rank=4, alpha=8):
        super().__init__()
        if type(base) is not nn.Linear or not isinstance(rank, int) or rank < 1:
            raise ValueError("需要普通 nn.Linear 与正整数 rank")
        if not math.isfinite(alpha) or alpha <= 0:
            raise ValueError("alpha 必须为正有限数")
        self.base = base.requires_grad_(False)
        self.rank, self.alpha = rank, alpha
        self.A = nn.Parameter(base.weight.new_empty(rank, base.in_features))
        self.B = nn.Parameter(base.weight.new_zeros(base.out_features, rank))
        nn.init.kaiming_uniform_(self.A, a=math.sqrt(5))
```

逐行说：

- **只接受普通 `nn.Linear`。** 写成 `type(base) is not nn.Linear` 而不是 `isinstance`，是为了拒绝子类，例如某些量化层。量化层的 `weight` 不是普通浮点矩阵，直接做 `W + sBA` 会出错。
- **rank 必须是正整数，alpha 必须是正的有限数。** 测试 `test_invalid_hyperparameters` 用 r = 0、−1、α = 0、NaN 检查这一点。
- **`base.requires_grad_(False)`**：冻结原层，权重和 bias 都不再有梯度。
- **A 的形状 `[rank, in]`，B 的形状 `[out, rank]`**，和 20.2.1 节的表一致。用 `base.weight.new_...` 创建，这样 A、B 自动和基座在同一设备、同一 dtype。
- **B 用 `new_zeros`**：20.3 节的结论。
- **A 用 Kaiming 均匀初始化，`a=√5`**。这和 `nn.Linear` 默认的初始化相同，每个元素落在 ±1/√in 之间（数学结论）。论文写的是高斯随机初始化（Hu et al. 2021 §4.1，待验证）；本章跟 PEFT 默认保持一致，所以 20.10 节对拍时可以直接复制 A。

拿 20.3.3 节的数字套一下：`LoRALinear(nn.Linear(3, 2), rank=1, alpha=2)` 会建出 A `[1, 3]`、B `[2, 1]`。

```python
    @property
    def scale(self):
        return self.alpha / self.rank

    def forward(self, x):
        return self.base(x) + F.linear(F.linear(x, self.A), self.B) * self.scale
```

- **`scale` 是属性，不是参数。** 改 α 只改这个数，参数统计不变。上例 scale = 2 / 1 = 2。
- **`F.linear(x, self.A)`** 计算 xAᵀ，就是对每个 token 算 h = Ax。上例得到 4。
- **再 `F.linear(..., self.B)`** 得到 Bh，上例 [0, 0]（B = 0 时）或 [2, −4]（B 更新后）。
- **乘 scale 再加上 `self.base(x)`**。基座的 bias 也在 `self.base(x)` 里，旁路没有 bias。

### 20.4.2 为什么不先算 BA

能不能直接写 `self.base(x) + F.linear(x, self.B @ self.A) * self.scale`？结果一样（数学结论：矩阵乘法有结合律）。

区别在代价。以 q_proj 为例（in = 1024，out = 2048，r = 16），一个 token 的乘加次数大约是：

- 先算 Ax 再乘 B：16 × 1024 + 2048 × 16 = 49,152。
- 先构造 BA：每次前向都要造一个 `[2048, 1024]` 的矩阵，需要 2048 × 16 × 1024 ≈ 3.4 千万次乘加，还要多存一个和 W₀ 一样大的临时矩阵；之后每个 token 再做 2048 × 1024 ≈ 210 万次。

（数学结论。）训练时先算 Ax 又快又省内存。BA 只在**合并**时算一次。

### 20.4.3 验证：机制测试

lab 第 1 节（tour 第 1 部分）用一个 `nn.Linear(11, 7)`、r = 4、α = 8 的层做三件事，结果是（本项目观察，RTX 4090 租用，fp32，`full/part1.json`）：

| 检查 | 结果 |
|---|---|
| 挂上 LoRA 后，输出和基座的最大差 | 0.0 |
| 第一步 A 的梯度范数 | 0.0 |
| 第一步 B 的梯度范数 | 0.285（非零） |
| 给 B 随机非零值后，合并层与旁路输出的最大差 | 1.19 × 10⁻⁷ |
| 可训练参数：公式 / 实际 | 72 / 72 |

72 = 4 × (11 + 7)（数学结论）。总参数 156 = 11 × 7 + 7 + 72，基座的 bias 7 个是冻结的，不算进 LoRA 参数。

注意第四行：验证合并时，**必须先把 B 设成非零**。如果 B 还是 0，BA = 0，合并后和合并前一样是必然的，什么 bug 都查不出来。本章的测试反复用到这条原则：不要用平凡情况证明正确。

在 CPU 上跑同一部分，B 梯度范数和合并误差会略有不同（我们在本地 CPU 上得到 0.2845 和 2.4 × 10⁻⁷），因为 A 和 x 用的是设备上的随机数发生器。前两行等于 0、第三行非零，这几条结论不受影响。

## 20.5 挂到模型上

### 20.5.1 `inject_lora`：先检查，再替换

有了 LoRA 层，还要把它装到模型里正确的位置。`inject_lora` 做的事情是：按名字找到目标 Linear，把它换成包着它的 `LoRALinear`。

```python
def inject_lora(model, targets=("q_proj", "v_proj"), rank=4, alpha=8):
    targets = set(targets)
    modules = [(name, m) for name, m in model.named_modules()
               if name and name.rsplit(".", 1)[-1] in targets]
    found = {name.rsplit(".", 1)[-1] for name, _ in modules}
    if not targets or found != targets or any(type(m) is not nn.Linear for _, m in modules):
        raise ValueError("目标必须全部存在且为未挂载的普通 Linear")
    if not isinstance(rank, int) or rank < 1 or not math.isfinite(alpha) or alpha <= 0:
        raise ValueError("rank/alpha 非法")
    model.requires_grad_(False)
    for name, base in modules:
        parent, _, leaf = name.rpartition(".")
        setattr(model.get_submodule(parent), leaf, LoRALinear(base, rank, alpha))
    return [name for name, _ in modules]
```

几个设计要点：

1. **按叶子名匹配。** Qwen3 里 q_proj 的完整路径是 `model.layers.0.self_attn.q_proj`，`rsplit(".", 1)[-1]` 取最后一段 `q_proj`。28 层各有一个，所以挂 q、v 两个目标时一共替换 56 个模块（本项目观察，`full/part4.json` 的 `modules: 56`）。
2. **先全部检查，再动手。** 如果目标里有一个名字不存在（比如拼错成 `qproj`），或者某个目标已经被挂过（它现在是 `LoRALinear`，不是 `nn.Linear`），函数在**修改任何东西之前**就报错。测试 `test_attach_counts_alpha_and_atomic_error` 检查了：报错以后，模型的所有参数仍然可训练、权重没被动过。要么全改，要么不改，避免留下改了一半的模型。
3. **`model.requires_grad_(False)` 冻结整个模型。** 不只是被替换的那几个层，嵌入、MLP、LayerNorm 全部冻结。随后新建的 A、B 是新参数，默认 `requires_grad=True`，所以最后可训练的只有 A、B。
4. **用 `setattr` 换到父模块上。** `get_submodule("model.layers.0.self_attn")` 找到父模块，再把它的 `q_proj` 属性换掉。

挂完以后，在 tiny Qwen 上做一次前向，输出和挂之前逐元素相同；反向以后，除了 A、B 以外的所有参数梯度都是 `None`（测试 `test_tiny_qwen_forward_backward_and_memory`）。

### 20.5.2 只保存 adapter

训练完，要保存的只有 A、B。`adapter_state` 只取出名字以 `.A`、`.B` 结尾的张量，复制到 CPU：

```python
def adapter_state(model):
    return {f"{name}.{key}": getattr(m, key).detach().cpu().clone()
            for name, m in model.named_modules() if isinstance(m, LoRALinear) for key in ("A", "B")}
```

r = 64、q/k/v/o 的配置有 18,350,080 个可训练参数，fp32 存下来约 70 MiB（数学结论：18,350,080 × 4 = 73,400,320 字节，除以 2²⁰ = 1,048,576 约为 70）；而完整模型 fp32 约 2.2 GiB。这带来 LoRA 的另一个好处：一个基座可以配很多个小 adapter，每个任务一个。

但小文件也有代价：**adapter 离开基座就没有意义**。只存 A、B，不记录基座是哪个快照、rank、α、目标模块是什么，下次就装不回去。tour 的做法是把这些信息另存在 `selection.json` 里（基座快照路径、rank、alpha、targets）。重新加载时先按同样的配置 `inject_lora`，再 `load_state_dict(state, strict=False)`；tour 还会先断言两边的键集合完全相同，防止静默地少加载一部分键。

## 20.6 合并回原权重

### 20.6.1 合并的数学

训练时我们保留两条路，因为 A、B 要更新。训练完以后，旁路的参数不再变了，两条路可以合成一条：

$$W' = W_0 + \frac{\alpha}{r} BA,\qquad W'x = W_0x + \frac{\alpha}{r}BAx.$$

（数学结论，就是分配律。）

合并以后：

- 模型又变回普通的 `nn.Linear`，结构和原模型一样，任何推理框架都能直接加载。
- 推理时**没有额外计算**。这是 LoRA 相对于 Adapter 一类方法的一大优点（20.13 节）：Adapter 在模型里插了新层，推理永远要多算；LoRA 合并以后零开销。

### 20.6.2 逐行读 `merged` 和 `merge_lora`

```python
    @torch.no_grad()
    def merged(self):
        result = nn.Linear(self.base.in_features, self.base.out_features,
                           bias=self.base.bias is not None,
                           device=self.base.weight.device, dtype=self.base.weight.dtype)
        result.weight.copy_(self.base.weight + (self.B @ self.A) * self.scale)
        if result.bias is not None:
            result.bias.copy_(self.base.bias)
        return result.requires_grad_(False).train(self.training)
```

- **`@torch.no_grad()`**：合并不需要进计算图。
- **新建一个 `nn.Linear`**，形状、设备、dtype 都和基座一样。
- **`self.base.weight + (self.B @ self.A) * self.scale`**：就是 W₀ + sBA。用 20.3.3 节的数字，得到 [[2, 0, 1], [−2, 1, −2]]。
- **bias 原样复制**。LoRA 不动 bias。
- **返回独立的新层**，原来的 `base`、A、B 都不改。

为什么不直接原地做 `self.base.weight += sBA`？因为原地修改有一个陷阱：如果不小心调用两次，增量会被加两遍，变成 W₀ + 2sBA，而且你从权重本身看不出来。返回新层的写法天然没有这个问题。

```python
def merge_lora(model):
    if isinstance(model, LoRALinear):
        return model.merged()
    for name, module in list(model.named_modules()):
        if isinstance(module, LoRALinear):
            parent, _, leaf = name.rpartition(".")
            setattr(model.get_submodule(parent), leaf, module.merged())
    return model
```

`merge_lora` 把模型里每个 `LoRALinear` 换成它合并后的普通 Linear。合并一次以后，模型里已经没有 `LoRALinear` 了，再调用一次找不到目标，什么也不做，所以**第二次合并不会重复加增量**。测试 `test_adapter_roundtrip_and_recursive_merge` 连着调用两次 `merge_lora`，检查输出仍然等于合并前。

注意 `list(model.named_modules())`：先把模块列表复制下来再遍历，因为循环里在修改模型结构，边遍历边改会出问题。

### 20.6.3 验证：在真实 Qwen3 上合并

lab 第 4 节（tour 第 4 部分）在 Qwen3-0.6B 上挂 q、v 两个模块，r = 4、α = 8，给所有 B 填上小的非零随机值（标准差 0.001），对一句输入比较合并前后的**完整 logits**（形状 `[1, 序列长度, 151936]`）。结果（本项目观察，RTX 4090 租用，fp32，`full/part4.json`）：

- 替换了 56 个模块，可训练参数 573,440，与公式一致。
- 合并前后 logits 的最大绝对差是 **2.1 × 10⁻⁵**，在容差 2 × 10⁻⁴ 以内。

为什么不是 0？因为合并前算的是 W₀x + s·B(Ax)，合并后算的是 (W₀ + sBA)x，两种运算顺序在浮点数下舍入不同。这个差经过 28 层一路传到 logits，累积到 10⁻⁵ 的量级是正常的。所以对拍要用容差，不能要求逐位相等。

如果在 bf16 下合并，舍入误差会大得多（bf16 的显式尾数只有 7 位，含隐含位共 8 位，第 16 章 16.1 节）。tour 的合并对拍固定用 fp32 就是这个原因。

### 20.6.4 什么时候不合并

合并不是必须的：

- **想换任务**：保持 adapter 分开，一个基座可以切换不同 adapter。
- **还要接着训练**：合并以后 A、B 就没了。
- **基座是量化的**（20.9 节）：4 bit 权重加一个高精度增量，再存回 4 bit 会损失精度。

本章的训练 checkpoint 也只保存 adapter，便于重新加载（lab 第 4 节末尾有用训练好的 adapter 再验证一次合并的命令）。

## 20.7 可训练参数量

### 20.7.1 公式

一个模块的 LoRA 参数是 r(in + out)。整个模型就是对所有被挂载的模块求和：

$$N_{\text{LoRA}} = \sum_{\text{被挂载的模块 } m} r\,(in_m + out_m).$$

（数学结论。）三个超参的影响一目了然：

- **rank**：线性。r 翻 4 倍，参数翻 4 倍。
- **alpha**：没有影响。
- **目标模块**：按每个模块的 in + out 加权，**不是**简单按模块个数算。

`parameter_counts` 同时返回公式值和实际统计值，训练前 tour 会断言两者相等：

```python
expected = sum(m.rank * (m.base.in_features + m.base.out_features)
               for m in model.modules() if isinstance(m, LoRALinear))
trainable = sum(p.numel() for p in model.parameters() if p.requires_grad)
```

如果 `trainable` 比 `expected` 大，通常说明有别的参数忘了冻结（20.14 节）。

### 20.7.2 手算 Qwen3-0.6B：r = 4，挂 q 和 v

先从 config 读出形状（本地 `config.json`）：hidden_size = 1024，num_attention_heads = 16，num_key_value_heads = 8，head_dim = 128，num_hidden_layers = 28，intermediate_size = 3072。

注意 Qwen3 用的是 GQA（分组查询注意力）：K、V 的头数是 Q 的一半。所以四个注意力投影的形状**不一样**：

| 模块 | in | out | in + out |
|---|---:|---:|---:|
| q_proj | 1024 | 16 × 128 = 2048 | 3072 |
| k_proj | 1024 | 8 × 128 = 1024 | 2048 |
| v_proj | 1024 | 8 × 128 = 1024 | 2048 |
| o_proj | 2048 | 1024 | 3072 |
| gate_proj | 1024 | 3072 | 4096 |
| up_proj | 1024 | 3072 | 4096 |
| down_proj | 3072 | 1024 | 4096 |

（数学结论。）

一步一步算 r = 4、q + v：

1. q_proj 一层：4 × 3072 = 12,288。
2. v_proj 一层：4 × 2048 = 8,192。
3. 一层合计：12,288 + 8,192 = 20,480。
4. 28 层：20,480 × 28 = **573,440**。

（数学结论。）实测：tour 第 4 部分的 `trainable` 是 573,440（本项目观察，`full/part4.json`），一个不差。占基座的 573,440 / 596,049,920 ≈ 0.096%。

### 20.7.3 rank 和目标模块的影响

同样的方法算出更多配置（数学结论；前两列六个数也是第 6 部分训练时代码统计的实际值，本项目观察，`full/sweep.json`）：

| rank | q, v | q, k, v, o | 全部 7 种 Linear |
|---:|---:|---:|---:|
| 4 | 573,440 | 1,146,880 | 2,523,136 |
| 16 | 2,293,760 | 4,587,520 | 10,092,544 |
| 64 | 9,175,040 | 18,350,080 | 40,370,176 |

后两列也是照 20.7.2 节的四步算的。以 r = 4 为例：q, k, v, o 一层的 in + out 之和是 3072 + 2048 + 2048 + 3072 = 10,240，乘 r 再乘 28 层得 4 × 10,240 × 28 = 1,146,880；全部 7 种 Linear 再加上三个 MLP 投影各 4096，一层是 10,240 + 3 × 4096 = 22,528，得 4 × 22,528 × 28 = 2,523,136（数学结论）。

几个读法：

- 每一列，r 每翻 4 倍，参数翻 4 倍（线性）。
- q, k, v, o 恰好是 q, v 的两倍。这对标准注意力投影**总是成立**，和 KV 头数无关：k 和 v 形状相同，o 和 q 只是 in、out 互换，in + out 相同，所以多出来的 k + o 正好等于 q + v。设 hidden 为 H、Q 总维度为 Q、KV 总维度为 K，每层的 q + v 是 r(2H + Q + K)，q, k, v, o 是 2r(2H + Q + K)（数学结论）。但别因此按模块个数推算参数：每个模块的参数其实不等，q 是 v 的 1.5 倍；算 q, k 或全部 Linear 时，按个数推就错了。
- 最大的配置（r = 64，全部 Linear）也只占基座的 6.8%（数学结论：40,370,176 / 596,049,920 ≈ 0.068）。

> **停下来想一想**：r = 16 挂 q, k, v, o 有 4,587,520 个参数，r = 64 只挂 q, v 有 9,175,040 个。如果实验里前者效果更好，你能说"挂更多模块比加大 rank 更划算"吗？（提示：两者参数预算不同，不是等预算比较。）

## 20.8 LoRA 只训练少量参数，为什么仍可能显存不足

### 20.8.1 先给结论

很多人第一次用 LoRA，以为可训练参数降到 0.1%，显存也会降到 0.1%。实际上，LoRA 省掉的只是为更新而存的那几项：梯度、m、v。冻结的权重本身、激活、logits 一项都没少，而对小模型、长序列来说，后面这些恰恰是大头。

### 20.8.2 账本：四个部分

训练时 GPU 上的东西分成四类：

| 项 | 全参微调 | LoRA | 随什么变 |
|---|---|---|---|
| ① 冻结的基座权重 | 无（没有冻结参数，权重算在 ② 里） | 全部都在 | 只看基座大小与精度 |
| ② 可训练参数 + 梯度 + m + v | 16N | 16 × N_LoRA | 只看可训练参数 |
| ③ 激活 | 有 | **仍然有** | batch × 长度 × 层数 × hidden |
| ④ logits 与交叉熵中间量 | 有 | **仍然有** | batch × 长度 × 词表 |

LoRA 把 ② 从 16N 降到了几乎为 0，但 ① ③ ④ 原封不动。

### 20.8.3 手算静态部分

本章实验的精度口径（lab 第 0 节）：基座、LoRA 参数、AdamW 状态都是 fp32，计算用 bf16 autocast。所以：

- 冻结权重：4 字节/参数。
- 可训练参数：权重 4 + 梯度 4 + m 4 + v 4 = 16 字节/参数。

$$\text{静态} = 4N + 16N_{\text{LoRA}}.$$

（数学结论。）这里 N 只算基座，N_LoRA 是 LoRA 参数。第 16 章的混合精度口径写作 2N + 14Nₜ，看起来不一样，是因为两处记号和精度都不同：那里基座用 bf16 存，而且 N 是包含可训练参数在内的总参数量。换成本章 N 只算基座的记号，就是 2(N + N_LoRA) + 14N_LoRA = 2N + 16N_LoRA。

代入 r = 16、q + v（N = 596,049,920，N_LoRA = 2,293,760）：

1. 4N = 4 × 596,049,920 = 2,384,199,680 字节。
2. 16 N_LoRA = 16 × 2,293,760 = 36,700,160 字节。
3. 合计 2,420,899,840 字节，除以 2³⁰ = 1,073,741,824，约为 **2.25 GiB**。其中冻结权重 2,384,199,680 字节约为 2.22 GiB。

（数学结论。）和全参的 8.88 GiB 比，省了四分之三。但省下来以后，剩下的 2.25 GiB 里 98% 是**冻结权重本身**（2.22 GiB）。可训练部分已经小到可以忽略，再降 rank 也省不出什么来了。

实测的优化器状态和梯度对得上（本项目观察，`full/part5.json`，r = 16，q + v）：梯度 9,175,040 字节 = 2,293,760 × 4；AdamW 状态 18,350,528 字节，比 m + v 的 2,293,760 × 8 = 18,350,080 多 448 字节。这 448 字节是 112 个参数张量（56 个模块 × A、B 两个）各自的 `step` 计数器，每个 4 字节（数学结论：112 × 4 = 448）。

### 20.8.4 激活为什么省不掉

LoRA 冻结了基座，为什么激活还得存？因为**反向传播要穿过冻结层**。

LoRA 挂在第 0 层到第 27 层的注意力上。第 0 层 A、B 的梯度需要 ∂L/∂(第 0 层的输出)，而这个梯度要从 loss 一层一层往回传，穿过第 27、26、……、1 层，每层的 MLP、RMSNorm、注意力 softmax 都在路上。这些运算求输入梯度时要用到前向保存的中间结果（第 16 章 16.7 节），一个都跳不过去。

有一点能省：冻结的 Linear 不用算权重梯度 ∂L/∂W = gxᵀ，所以理论上不必为它保存输入 x。但非线性运算（SiLU、softmax、归一化）求输入梯度仍要自己的保存量。所以 LoRA 的激活比全参少一些，但绝不是少到 0.1%。

④ logits 更是躲不掉。Qwen3 的词表有 151,936 个词。batch 2、长度 384，bf16 的 logits 就是

$$2 \times 384 \times 151{,}936 \times 2 = 233{,}373{,}696 \text{ 字节} \approx 0.22 \text{ GiB}.$$

交叉熵在 fp32 下算（lab 第 0 节），本章的 `causal_loss` 先挑出被监督的位置再转 fp32，所以 fp32 副本的字节数是监督位置数 × 151,936 × 4；如果所有位置都被监督，上界是 2 × 384 × 151,936 × 4 ≈ 0.43 GiB（数学结论）。这只是最后一层的一个张量，就比所有 LoRA 参数及其状态（r = 16、q + v 时约 35 MiB）大十几倍（466,747,392 ÷ 36,700,160 ≈ 12.7）。

### 20.8.5 先估后测

lab 第 5 节（tour 第 5 部分）在 Qwen3-0.6B 上挂 r = 16 的 q、v，先用 `memory_estimate` 估算，再真的训练两步，记录每个阶段的显存。估算的激活用一个教学代理：

$$\text{激活代理} = 12 \times \text{层数} \times B \times T \times \text{hidden} \times 2\text{ 字节}.$$

意思是每层每个 token 存 12 个 hidden 长的 bf16 向量。这是一个粗略的数，不是上界（代码的 docstring 里写着）。拿 2 × 512 手算一遍：12 × 28 × 2 × 512 × 1024 × 2 = 704,643,072 字节，除以 2³⁰ 约为 0.656 GiB；bf16 logits 是 2 × 512 × 151,936 × 2 = 311,164,928 字节，约 0.290 GiB（数学结论，就是下表最后一行的两个估算值）。

结果（估算是数学结论，实测是本项目观察：RTX 4090 租用，fp32 参数 + bf16 autocast，`full/part5.json`；单位 GiB = 2³⁰ 字节；"前向增量"是第 1 步"前向后"减"前向前"的 allocated）：

| batch × 长度 | token 数 | 激活代理 | logits（bf16） | 估算合计（激活 + logits） | 实测前向增量 | 实测峰值 allocated |
|---|---:|---:|---:|---:|---:|---:|
| 1 × 128 | 128 | 0.082 | 0.036 | 0.118 | 1.383 | 3.76 |
| 2 × 256 | 512 | 0.328 | 0.145 | 0.473 | 2.277 | 5.05 |
| 2 × 512 | 1024 | 0.656 | 0.290 | 0.946 | 3.419 | 6.77 |

三点观察：

**第一，估算严重偏低。** 最长的一行，实测前向增量是估算的约 3.6 倍；最短的一行更是约 12 倍。所以 lab 一再说"估算不能代替运行前的余量检查"。

**第二，前向增量里有一大块固定成本。** 用三个点拟合一条直线：前向增量 ≈ 1.10 GiB + 2.32 MiB × token 数（拟合是对本项目观察的数学处理，三个点的残差都在 0.015 GiB 以内）。每个 token 2.32 MiB，大约是激活代理（0.66 MiB/token）加 bf16 logits（0.29 MiB/token）的 2.5 倍；fp32 交叉熵副本（每个被监督 token 0.58 MiB；本表输入每条前 32 个标签被屏蔽，2 × 512 时监督 2 × 480 个位置，副本 583,434,240 字节，数学结论）能解释一部分，其余没有拆分。

截距 1.10 GiB 和全部 Linear 权重转成 bf16 副本的大小 1.11 GiB（数学结论：595,984,384 × 2 字节，含共享的输出层）非常接近。一个可能的解释是 autocast 在前向时为冻结权重生成的 bf16 副本被保存到反向用完为止，但我们**没有做实验验证**，这里只能标为待验证。

**第三，反向以后显存几乎全部回落。** 2 × 512 那一行，前向后 5.66 GiB，反向后 2.54 GiB，optimizer 后 2.56 GiB（本项目观察）。激活在反向中逐步释放；剩下的就是 20.8.3 节算的静态部分（2.22 GiB 权重，加上 2.25 − 2.22 的 LoRA 相关部分），再加一些缓存。还要注意，峰值 6.77 GiB 比前向后的 5.66 GiB 还高约 1.1 GiB：前向或反向过程中还有一些临时张量（例如交叉熵和反向的工作区）短暂存在过。tour 只在几个阶段的边界记录 allocated，峰值具体出现在哪一刻没有记录。

### 20.8.6 怎样省

按 20.8.2 节的账本，各项有各自的省法：

- **① 冻结权重**：用 bf16 存基座（0.6B 从 2.22 GiB 降到 1.11 GiB，数学结论），或者量化到 4 bit（20.9 节）。
- **③ 激活**：缩短长度、减小微批（用梯度累积保持有效 batch，第 19 章 19.6.5 节）、梯度检查点（第 16 章 16.8 节）。
- **④ logits**：只对答案位置生成 logits，或者分块算交叉熵（本章没有实现：本章的 fp32 交叉熵副本已经只取答案位置，但完整的 bf16 logits 仍然整块生成）。
- **② 可训练参数**：降 rank。但 20.8.3 节已经看到，它在 LoRA 里本来就只有几十 MiB，降 rank 几乎省不出显存。

所以显存不够时，第一反应不该是降 rank。

## 20.9 QLoRA 的思路

### 20.9.1 做法

QLoRA（Dettmers et al., 2023）对准的是账本里的 ①：冻结的基座用 4 bit 存，计算时临时反量化成 bf16；LoRA 的 A、B 和它们的梯度、优化器状态保持高精度。

基座本来就不更新，存成 4 bit 不妨碍训练本身。只有前向和反向用到它时，才把需要的那一块解压成 bf16 算一下。梯度只流向高精度的 A、B。

### 20.9.2 省下多少

4 bit 是 0.5 字节/参数。如果 Qwen3-0.6B 的 596,049,920 个参数都量化到 4 bit，权重是约 0.28 GiB（数学结论），比 fp32 的 2.22 GiB 小 8 倍。实际上还要存每一小块的缩放常数，而且嵌入层通常不量化（待验证，取决于库的实现），所以实际会大一些。

但请对照 20.8.5 节的表：2 × 512 时前向增量有 3.4 GiB。量化只动 ①，**③ 和 ④ 一点没少**。对 0.6B 这样的小模型、几百 token 的序列，QLoRA 能省的比例有限。它的用武之地是大模型：7B、70B 的权重本身就是几十上百 GiB，① 是最大的一项。

### 20.9.3 论文里的三个技巧（概括）

QLoRA 论文 §3 介绍了三样东西（待验证，以论文为准）：

- **4-bit NormalFloat（NF4）**：一种为正态分布权重设计的 4 bit 数据类型，量化点按正态分布的分位数放置。
- **双重量化**：连那些每块的缩放常数也再量化一次，进一步省空间。
- **分页优化器**：显存峰值时把优化器状态临时换到 CPU 内存，避免偶发的 OOM。

### 20.9.4 本章没有实测

租用实例上没有 bitsandbytes，本章**没有**做 QLoRA 训练，也没有测它的速度和显存（本项目观察，`full/part7.json` 的 `bitsandbytes_available: false`）。tour 第 7 部分只打印思路和注意事项。正文里关于 QLoRA 省多少显存、对精度有多少影响的说法，都待验证。

## 20.10 与 PEFT 对拍

### 20.10.1 为什么要对拍

自己写的 LoRA 层，怎么知道它和大家用的一样？最直接的办法：找一个公认的实现，喂完全相同的输入和参数，逐项比较。Hugging Face 的 **PEFT** 库就是这样一个公认的实现。第 21 章用 TRL 训练时，底下的 LoRA 也是 PEFT 提供的。今天对拍过，下一章就可以放心地说"框架里的 LoRA 和我们手写的是同一个东西"。

### 20.10.2 对齐每一个细节

比较本身很容易，难的是让两边真的在做同一件事。tour 第 3 部分逐项对齐（lab 第 3 节）：

| 细节 | 我们 | PEFT 的设置 |
|---|---|---|
| rank、alpha | r = 4，α = 8 | `LoraConfig(r=4, lora_alpha=8)` |
| 缩放 | α/r | 默认也是 `lora_alpha / r`（本节的对拍结果证实了这一点） |
| dropout | 无 | `lora_dropout=0.` |
| bias | 冻结 | `bias='none'` |
| A 的布局 | `[r, in]` | `lora_A` 是一个 `Linear(in, r)`，权重 `[r, in]` |
| B 的布局 | `[out, r]` | `lora_B` 是一个 `Linear(r, out)`，权重 `[out, r]` |
| A、B 的值 | 复制同一份 | 从我们的层复制过去 |

然后做一件关键的事：**把 B 设成非零**（标准差 0.03 的随机值）。原因和 20.4.3 节类似：B = 0 时两边的旁路输出都是 0，前向、A 梯度、输入梯度的比较必然通过，只剩 B 梯度一项还能查出缩放之类的错误；B 非零时四项比较才都有意义。

比较的不只是前向输出，还有 A 的梯度、B 的梯度和输入 x 的梯度。输入梯度很重要：在真实模型里，它就是传给下一层的梯度，20.8.4 节说过反向要一路穿过去。

### 20.10.3 结果

四项的最大差全部是 **0.0**（本项目观察，RTX 4090 租用，fp32，PEFT 0.21.2，`full/part3.json`；本地 CPU 重跑也是 0.0）。

逐位相等说明两边的运算顺序完全一样：都是先算 Ax，再乘 B，再乘缩放。如果你把 `forward` 改成先构造 BA 再乘 x（20.4.2 节），数学上等价，但浮点舍入顺序变了，对拍时很可能出现很小的非零差（待验证，本章没有这样改过），那时就要靠容差判断（测试的容差是 2 × 10⁻⁶）。

PEFT 在本章只用作验证。所有训练用的都是我们自己的 `LoRALinear`。

## 20.11 后纠错实验：rank 与目标模块扫描

### 20.11.1 实验设置

lab 第 6 节（tour 第 6 部分）。设置如下（本项目观察，RTX 4090（租用），fp32 参数 + bf16 autocast，`full/selection.json`、`full/mask-check.json`）：

- **基座**：Qwen3-0.6B，本地快照，只读。
- **数据**：第 19 章同一份 postcorrect-v1（合成噪声，seed 0）。train 前 4096 条，长度过滤后接受 4049 条；val 前 200 条。
- **监督**：第 19 章的 `encode_sft/collate_sft`，提示和 padding 的 label 为 −100，答案末尾监督 EOS。训练前检查：提示全部被屏蔽、全部样本以 EOS 结尾（`mask-check.json` 两项都为 true）。
- **训练**：400 步，微批 2 × 累积 4（有效 batch 8），学习率 2 × 10⁻⁴ 常数，AdamW（weight decay 0.01），梯度裁剪 1，长度上限 384。
- **扫描**：rank ∈ {4, 16, 64} × 目标模块 {q, v；q, k, v, o}，共 6 组。**α/r 固定为 2**。
- **每组公平起跑**：重新加载同一基座、重设随机种子和数据顺序。
- **评测**：贪心、非思考模板，生成预算固定 192 个 token，第 18 章的 `score_postcorrect`。报告第 0 章 0.9.3 节的文本后纠错面板，主指标是**原始输出**的 EM_norm。

每组实际处理了 400 × 8 = 3200 次样本，少于 4049 条，也就是说**连一轮都没跑完**（数学结论）。

选型规则在跑之前就写死了：val 原始 EM_norm 越高越好；同分时 CER 越低越好，再同分 rank 越低越好。不能看了 test 再改。

### 20.11.2 结果

**本项目观察，RTX 4090（租用），fp32 参数 + bf16 autocast，val n = 200，每组 400 步。** 来源：`full/sweep.json`、`full/*-val-metrics.json`。EM_norm 的方括号是 Wilson 95% 区间；val NLL 是 197 条通过长度过滤的 val 样本上的 token 平均。

| 配置 | 可训练参数 | val EM_norm | CER | 改坏 | val NLL |
|---|---:|---|---:|---:|---:|
| r4 q,v | 573,440 | 121/200 = 0.605 [0.536, 0.670] | 0.0166 | 6/59 | 0.0336 |
| r16 q,v | 2,293,760 | 126/200 = 0.630 [0.561, 0.694] | 0.0162 | 5/59 | 0.0308 |
| r64 q,v | 9,175,040 | 128/200 = 0.640 [0.571, 0.703] | 0.0141 | 4/59 | 0.0276 |
| r4 q,k,v,o | 1,146,880 | 125/200 = 0.625 [0.556, 0.689] | 0.0212 | 6/59 | 0.0314 |
| r16 q,k,v,o | 4,587,520 | 129/200 = 0.645 [0.577, 0.708] | 0.0190 | 6/59 | 0.0283 |
| **r64 q,k,v,o（选中）** | 18,350,080 | **134/200 = 0.670 [0.602, 0.731]** | 0.0136 | 2/59 | 0.0292 |

对照（同一批 val 200 条，本项目观察）：

- 照抄输入：73/200 = 0.365。
- 未微调的基座（同一个提示）：0/200，可解析率 0.005。几乎给不出能解析的公式。

"改坏"指 59 条本来就正确的输入里，被模型改错了几条。面板必报的 fix_rate 这张扫描表没有列；六组 LoRA 里，只有选中配置在 20.11.5 节（test）和 20.12.2 节（val）给出。

### 20.11.3 怎样读这张表

**六组都远远超过照抄。** 最差的 r4 q,v 也是 0.605，区间下界 0.536 高于照抄的 0.365。哪怕只训练 0.096% 的参数，LoRA 也教会了模型改公式。

**rank 越大，EM_norm 有上升的趋势，但区间全部重叠。** q,v 一列从 0.605 到 0.640，q,k,v,o 一列从 0.625 到 0.670。只看各自的 Wilson 区间，200 条样本分不清相邻两组谁更好。

配对看会更清楚一点。最小的 r4 q,v 和选中的 r64 q,k,v,o 在同一批 200 条上：只有前者对的 4 条，只有后者对的 17 条（本项目观察，由两组 `*-val-predictions.json` 逐条对照）。McNemar 精确检验（只看两个不一致的格子，原理见 22.3.8 节）的双侧 p ≈ 0.007（数学结论，由 4 和 17 算出）。但这两组是**从六组里挑出来的两端**，而且选型就用的这批 val，多重比较会让差别显得更显著。合理的说法是：在这批 val 上，大配置大概率比最小的配置好，但幅度要在别的数据上再确认。

**val NLL 和 EM 的顺序不一致。** NLL 最低的是 r64 q,v（0.0276），EM 最高的是 r64 q,k,v,o。第 19 章已经讲过原因：NLL 是 teacher forcing 下的 token 平均，EM 是自回归生成的整条对错，两者不一一对应。所以选型规则用 EM，不用 NLL。

**这不是一个等参数量的比较。** 同 rank 下 q,k,v,o 的参数是 q,v 的两倍。r16 q,k,v,o（458 万）比 r64 q,v（918 万）参数少一半，EM 却稍高（0.645 对 0.640，区间几乎完全重叠）。这能暗示"挂更多模块可能比加大 rank 更划算"，Hu et al. 2021 §7.1 也讨论了这个问题；但我们的数据不足以下这个结论。

### 20.11.4 显存与吞吐

同一次扫描的资源记录（本项目观察，RTX 4090 租用，`full/sweep.json`；峰值是 PyTorch 本进程的 allocated，不是整卡占用）：

| 配置 | 峰值 allocated（GiB） | 训练秒（400 步） | 第 1 步梯度范数 |
|---|---:|---:|---:|
| r4 q,v | 5.37 | 243.8 | 2.07 |
| r16 q,v | 5.40 | 284.2 | 4.06 |
| r64 q,v | 5.52 | 558.8 | 8.17 |
| r4 q,k,v,o | 7.71 | 590.1 | 2.36 |
| r16 q,k,v,o | 7.71 | 533.9 | 4.84 |
| r64 q,k,v,o | 5.72 | 445.9 | 9.57 |

**显存：q,v 一列和 20.8 节的分析一致。** r 从 4 到 64，可训练参数涨 16 倍，峰值只从 5.37 涨到 5.52 GiB。按 20.8.3 节的公式，r64 q,v 比 r4 q,v 多出的静态部分是 16 × (9,175,040 − 573,440) 字节 ≈ 0.13 GiB（数学结论），实测差 0.15 GiB，量级相符。峰值的大头是冻结权重和激活，rank 几乎不影响它。

**q,k,v,o 一列有一个我们解释不了的现象**：r4 和 r16 的峰值是 7.71 GiB，r64 反而只有 5.72 GiB。按 20.8 节的账，r64 不应该更省。测量期间同一张卡上还有其他实验在跑，原因没有进一步拆分，**不作结论**。如果你在自己的机器上重跑得到单调的结果，那更符合预期。

**吞吐：不能读出 rank 对速度的影响。** r4 q,k,v,o 用了 590 秒，比 r64 q,k,v,o 的 446 秒还慢，这不合理。可能同样是并行实验抢 GPU 造成的噪声，但原因没有拆开。原理上，LoRA 的额外计算（每个 token 多算 r(in + out) 次乘加）相对于基座很小，rank 对每步时间的影响应当不大；但这只是推理，没有被我们干净地测出来（待验证）。

还要注意：LoRA 并不一定比全参训练每步更快。前向一样要走完整个基座，反向一样要穿过所有层算输入梯度；省掉的只是冻结层的权重梯度那一部分计算。

### 20.11.5 冻结以后，只看一次 test

选型结束、`selection.json` 写好以后，lab 第 8 节用选中的 r64 q,k,v,o 在 test 前 200 条上评了**一次**（本项目观察，`full/final-test-metrics.json.txt`）。按第 0 章 0.10.1 节的规则，选型冻结后，预先登记的候选可以各评一次，不据此改任何设置；本章的候选只有这个选中配置，由事先写死的选型规则（20.11.1 节）决定。结果是：

- 原始输出 EM_norm 124/200 = **0.620** [0.551, 0.684]，CER 0.0275 [0.0163, 0.0414]。
- 改坏 7/63，fix_rate 68/137。

val 是 0.670，test 是 0.620。差距在区间之内，但方向符合预期：**在 val 上挑出来的最好配置，在 val 上的分数天然偏乐观**，因为我们是从六组里挑了 val 分数最高的那一组。test 没有参与选择，0.620 是更诚实的估计。

两点限定：test 上没有算照抄基线（产物里没有这项）；抽取后的 test EM_norm 只有 0.195。第 18 章的抽取器会去掉公式末尾的标点，误伤了多数本来正确的输出，这是评测口径的问题，不是模型能力的结论（第 19 章 19.8.3 节讨论过同一个现象）。

tour 用一个文件守卫防止反复看 test：第一次评测时写下 `FINAL_TEST_STARTED.json`，再次调用直接报错（测试 `test_final_test_refuses_repeated_access_before_loading`）。它只防本目录里的手滑，不是全局的访问控制。test 只保存汇总和置信区间，不保存逐条预测，所以开发期也看不到它的错例。

## 20.12 和第 19 章的全参 SFT 比

### 20.12.1 是不是同一把尺子

要回答"LoRA 比全参差多少"，先检查两边是不是在同一把尺子上量。逐项核对：

**相同的：**

- 基座：Qwen3-0.6B。
- 训练数据：postcorrect-v1 的 train 前 4096 条。
- val：本章的 val 前 200 条，和第 19 章 val 前 500 条的**前 200 条**逐条相同（本项目观察：id、源、目标逐条比对一致）。
- 评测脚本：`score_postcorrect`，原始输出口径；贪心、非思考模板。
- 精度口径：fp32 权重 + bf16 autocast。

**不同的：**

| 项 | 第 19 章全参 | 本章 LoRA（r64 q,k,v,o） |
|---|---|---|
| 可训练参数 | 596,049,920 | 18,350,080 |
| 学习率 | 2 × 10⁻⁵ | 2 × 10⁻⁴ |
| 更新次数 × 有效 batch | 512 × 16 = 8192 次样本 | 400 × 8 = 3200 次样本 |
| 长度上限（接受条数） | 512（4093 条） | 384（4049 条） |
| 生成预算 | min(256, 2 × 最长源 + 32) | 固定 192 |
| 生成批大小 | 16 | 8 |
| 选择方式 | 在 val 前 128 条上选步 | 在 val 前 200 条上选配置 |

所以这**不是**一个只改了"全参 / LoRA"一个变量的对照。全参那一组见过的样本是 LoRA 的 2.56 倍（数学结论：8192 / 3200），学习率也是按各自的方法分别设的。

### 20.12.2 数字

第 19 章报告的是 val 前 500 条（365/500）。为了在同一批题上比，我们从第 19 章保存的逐条结果 `outputs/book/ch19/gpu/final/final-val.jsonl` 里取出前 200 条重新统计。这不是新跑的模型，只是对已有逐条记录的重新计数。

**同一批 val 200 条，原始输出口径**（本项目观察，RTX 4090 租用；第 19 章一行由其逐条记录重算，其余来自本章 `full/` 目录）：

| 方法 | EM_norm | CER | 改坏 | fix_rate |
|---|---|---:|---:|---:|
| 照抄 | 73/200 = 0.365 | 0.0263 | 0/59 | 14/141 |
| 未微调基座 | 0/200 = 0.000 | 1.062 | 59/59 | 0/141 |
| LoRA r64 q,k,v,o | 134/200 = 0.670 [0.602, 0.731] | 0.0136 | 2/59 | 77/141 |
| 全参 SFT（第 19 章第 512 步） | 155/200 = 0.775 [0.712, 0.827] | 0.0114 | 2/59 | 98/141 |

配对比较：两边都对 126 条，只有全参对 29 条，只有 LoRA 对 8 条。McNemar 精确检验双侧 p ≈ 0.0008（数学结论，由 29 和 8 算出）。

### 20.12.3 能下什么结论

**能说的：** 在这批 val 上，本章选中的 LoRA 配置明显不如第 19 章的全参 SFT。差距主要在"改对"上：fix_rate 77/141 对 98/141；"不改坏"两者一样（都是 2/59）。

**不能说的：** "LoRA 天生比全参差 10 个百分点"。20.12.1 节的表里有好几个混杂因素，最大的一个是训练量：LoRA 只见了 3200 次样本，还没跑完一轮；全参见了 8192 次，约两轮。本章的 LoRA 也没有调学习率，2 × 10⁻⁴ 是常见的起点，不是为这个任务找到的最优值。

**还要记住两层乐观偏差：** 全参那一行是在 val 前 128 条上选的步，这 128 条在这 200 条里面；LoRA 那一行是在这 200 条上从六组里选的配置。两边的数字都偏乐观，偏多少不一样。

**测试集：** 第 19 章没有评 test；本章评了一次（0.620）。所以 test 上无法比较两者。

想把这件事比清楚，需要固定训练样本次数和选择方式，再分别为两种方法调学习率。第 21 章用 TRL 再做一次 LoRA SFT，给这张表添一行，但它也不是这样的受控对照；有了框架，这组对照你可以自己补上。

## 20.13 其他 PEFT 方法（概括）

LoRA 属于一大类"参数高效微调"（parameter-efficient fine-tuning，PEFT）方法。它们的共同点是：冻住基座，只训练很少的新参数。区别在于新参数放在哪里。

- **Adapter**（Houlsby et al., 2019）：在每个 Transformer 子层后面插一个小的"瓶颈"网络：先降维、过非线性、再升维，残差加回去。和 LoRA 很像，但它是**串联**在计算路径上的新层，中间有非线性，没法合并进原权重，推理时永远多一段计算。
- **Prefix tuning / Prompt tuning**（Li & Liang, 2021；Lester et al., 2021）：不改权重，而是在输入前面（或每层注意力的 K、V 前面）加一段可训练的"虚拟 token"。参数极少；代价是占用上下文长度，而且在小模型上效果通常不如 LoRA（待验证）。
- **LoRA 的变体**：rsLoRA（缩放改为 α/√r）、DoRA（把权重拆成大小和方向分别适配）等，PEFT 里都有开关（待验证，本章未实测）。

本课程后面都用 LoRA，原因有几个：实现简单（就是本章这几十行代码），可以合并、推理零开销，对超参不太敏感（最后一条是常见经验，本章没有专门验证）。

## 20.14 常见错误

**1. B 没有初始化为 0（或被别的初始化覆盖）。**
- 现象：挂上 LoRA 后、还没训练，模型输出就变了；第 1 步 loss 比基座高。
- 怎样发现：挂完立刻对比基座输出（测试第一项，最大差应为 0）；或者看多组配置的第 1 步 loss 是否完全相同（本章是 0.35206）。

**2. A、B 都初始化为 0。**
- 现象：loss 从头到尾不动，A、B 的梯度永远是 0。
- 怎样发现：打印第 2 步 A、B 的梯度范数。B = 0、A 随机时，第 1 步 A 梯度为 0 是正常的；第 2 步以后还都是 0 就不正常。

**3. 忘了冻结基座。**
- 现象：可训练参数等于（或接近）总参数，显存和全参一样大。
- 怎样发现：训练前打印 `parameter_counts`，断言 `trainable == formula`。tour 每组训练前都做这个断言。

**4. 目标模块名写错，或者匹配到了不想要的层。**
- 现象：要么报错，要么（在宽松的实现里）静默地只挂上了一部分，参数量比预期少。
- 怎样发现：看挂载返回的模块列表长度。Qwen3-0.6B 挂 q、v 应该是 56 个。本章的 `inject_lora` 要求每个目标名至少命中一次，否则报错。

**5. 用 B = 0 做对拍或合并验证。**
- 现象：测试全部通过，但实现其实是错的。比如缩放写成了 r/α，B = 0 时前向输出、A 梯度、输入梯度都看不出来，合并验证更是一定通过；只有 B 的梯度 s·g(Ax)ᵀ 还带着缩放，对拍若不比较 B 梯度就会漏掉。
- 怎样发现：对拍和合并前，先把 B 设成非零随机值（本章所有相关测试都这样做），让每一项比较都真正起作用。

**6. 合并两次。**
- 现象：合并后的模型输出比合并前偏得更远，好像 adapter 的劲翻倍了。
- 怎样发现：合并后比较输出；用返回新层而不是原地 `+=` 的写法从根上避免。

**7. 改 rank 时没有同时考虑 alpha。**
- 现象：rank 扫描的结果混进了缩放的变化，很难解释。
- 怎样发现：在实验记录里同时写 r 和 α。本章固定 α/r = 2；即使这样，20.3.5 节也说明了 r 越大初始梯度越大。

**8. 以为 LoRA 显存就是可训练参数的显存。**
- 现象：r = 4 也 OOM；或者降 rank 以后显存几乎不变。
- 怎样发现：按 20.8.2 节的四项账本先估算，再看前向前后的 allocated。本章 r 从 4 到 64，q,v 的峰值只从 5.37 变到 5.52 GiB（本项目观察）。

**9. 只存 adapter，不记录基座和配置。**
- 现象：换台机器加载，`load_state_dict(strict=False)` 不报错，但效果不对，因为基座版本或 targets 不一样（targets 不同时多出或缺少的键会被静默忽略；rank 不同则 A、B 形状对不上，即使 `strict=False` 也会报尺寸不匹配的错）。
- 怎样发现：保存时同时记录基座快照、rank、alpha、targets；加载后先检查键集合完全相同，再在几条 val 上核对指标。

**10. 用抽取后的指标给后纠错 LoRA 打分。**
- 现象：test EM_norm 从 0.620 掉到 0.195，以为模型很差。
- 怎样发现：原始输出和抽取后两个口径都报，抽取后掉得多时，去 **val** 上看被抽取器"改坏"的样本（开发期 test 只报汇总数字，不看错例）。

**11. 拿共享 GPU 上的吞吐给 rank 排名。**
- 现象：r = 4 反而比 r = 64 慢（本章 q,k,v,o 一列就是这样）。
- 怎样发现：看测量时卡上有没有其他进程；要比速度，在独占的卡上、同一时段重复几次。

## 20.16 小结

LoRA 冻住原权重 W₀，只训练两个瘦矩阵，把每层改成 W₀ + (α/r)·BA；B 从 0 开始，所以起点就是原模型，第一步只有 B 有梯度。可训练参数是 Σ r(in + out)，随 rank 线性增长，与 alpha 无关，按模块的形状而不是个数累加；Qwen3-0.6B 挂 q、v、r = 4 时是 573,440 个（数学结论，与实测一致）。训练完可以把 (α/r)·BA 合并回权重，推理零开销；我们的实现与 PEFT 逐位一致，在 Qwen3 上合并误差约 2 × 10⁻⁵。LoRA 省掉的只是梯度和优化器状态，冻结权重、激活和 logits 一样不少，所以小模型、长序列时降 rank 几乎省不了显存；QLoRA 进一步把冻结权重压到 4 bit，但同样不动激活。在后纠错任务上，六组 LoRA 都远超照抄，选中配置的 val EM_norm 是 0.670、test 0.620，但在同一批 val 上低于第 19 章的全参 SFT（0.670 对 0.775），而两者的训练量和超参并不相同（本项目观察）。

复习时抓住下面几条：

- **低秩的直觉**：秩 r 的矩阵就是 r 个秩 1 项 b_j a_jᵀ 之和，每项读一个输入方向、写一个输出方向。SVD 按奇异值从大到小排好这些项，截掉后面的项得到最好的低秩近似，误差的 Frobenius 范数是被截掉奇异值平方和的平方根。LoRA 假设 ΔW 的奇异值掉得快，但训练时不做 SVD，直接用梯度学 B、A。
- **公式和形状**：y = W₀x + (α/r)·B(Ax)，A 是 `[r, in]`，B 是 `[out, r]`，BA 和 W₀ 同为 `[out, in]`。训练时先算 Ax 再乘 B，不构造 BA。
- **B = 0 的理由**：BA = 0，起点等于原模型；∂L/∂A = s·(Bᵀg)xᵀ 在第一步为 0，∂L/∂B = s·g(Ax)ᵀ 非零，B 先动、A 随后跟上。A、B 都为 0 时两个梯度永远是 0，旁路是死的。
- **参数量**：一个模块 r(in + out)，全模型对被挂载的模块求和。Qwen3-0.6B 的 q_proj 是 in + out = 1024 + 2048，v_proj 是 1024 + 1024，r = 4 挂 q、v：4 × (3072 + 2048) × 28 = 573,440。
- **静态显存**（本章口径：基座、LoRA 参数、AdamW 状态都是 fp32）：4N + 16N_LoRA，r = 16 挂 q、v 时约 2.25 GiB，其中 2.22 GiB 是冻结权重。激活和 logits 另算，它们随 batch 和长度增长；logits 与 rank 无关，激活里只有旁路的中间量 Ax（每个 token r 个数）随 rank 变，和基座的激活比很小；显存不够时先缩长度、减微批、开梯度检查点或压基座精度，降 rank 几乎没用。
- **合并**：W' = W₀ + (α/r)·BA，返回新层而不是原地 `+=`，否则合并两次会把增量加两遍。浮点下合并前后只在容差内相等，fp32 下本章是 10⁻⁵ 量级。
- **最常见的错误**：用 B = 0 的状态去验证合并或对拍（合并验证必然通过，对拍也只剩 B 梯度一项还能查出错误，验证前先把 B 设成非零）；以为可训练参数降到 0.1%，显存也降到 0.1%。
