# A3 书面题参考答案（维护者用，make_student 不复制）

## A3-W1

M1 的例子：`input_ids = (1, 2, 3, 9)`，`labels = (−100, −100, 3, 9)`。位置 t 的 logits 预测位置 t+1（第 19 章 19.3.3 节）。

| 位置 | input_ids | labels | 由哪个位置的 logits 预测 | 是否计入 loss |
|---|---|---|---|---|
| 0 | 1 | −100 | 没有预测者 | 否 |
| 1 | 2 | −100 | 0 | 否 |
| 2 | 3 | 3 | 1 | 是 |
| 3 | 9 | 9 | 2 | 是 |

- 位置 0 的标签没有预测者，移位时被丢掉；
- 位置 3 的 logits 没有后继目标，也用不上；
- 位置 0 的 logits 的目标是 −100，不计 loss；
- 位置 1 的标签是 −100，它的 logits 却预测答案第一个 token，要计 loss（19.2.2 节末尾的问题）。

**不能分别编码再拼接。** BPE 可能跨过拼接点合并。第 19 章 19.2.3 节的例子：`ab` 和 `c` 分别编码是两段，联合编码是一个 token；答案以换行开头时，模板末尾的 `ĊĊ` 会和它合并成 `ĊĊĊ`。这时提示已经不是联合编码结果的前缀，所以要联合编码，再核对前缀，核对不过就报错。

**按 ID 屏蔽（19.5.3 节）。** pad 等于 EOS 时，真实 EOS 也被遮掉，等于漏 EOS，模型得不到“该停了”的监督。代码里看不出来。

用 M2 的第一条样本手算，pad = EOS = 9：

- input_ids = [1, 2, 9, 9]，后一个 9 才是 padding；
- 按位置屏蔽：labels = [−100, 2, 9, −100]；
- 按 ID 屏蔽：labels = [−100, 2, −100, −100]，EOS 没了。

监督终止标志和 padding 是两件事，所以按位置屏蔽。

## A3-W2

**累积。** 正确写法是总和除以总数（19.6.5 节）：

```
正确：(S₁ + S₂) / 5
错误：(S₁ / 1 + S₂ / 4) / 2
```

每个 token 的权重：

| 写法 | 第一个 microbatch 的 token | 第二个 microbatch 的 token |
|---|---|---|
| 正确 | 1/5 | 1/5 |
| 错误 | 1/2 | 1/8 |

错误写法里，短答案的 token 权重是长答案的 4 倍。

数字例子（假设的数字）：S₁ = 2，S₂ = 1。正确是 3/5 = 0.6，错误是 (2 + 0.25)/2 = 1.125。两个 microbatch 的有效 token 数相等时，两种写法才相同。

`tests/test_sft.py` 的 `test_loss_pytorch_gradient_and_token_weighting` 用的就是 1 个和 4 个目标：两个 `sum` 相加再除以 5，等于整批的 `mean`。

**提示的梯度（19.4.3 节）。** 有梯度。−100 只去掉“以提示 token 为目标”的那几项。答案通过注意力读取提示的表示，梯度沿注意力流回提示位置的隐藏状态、embedding 和各层权重。

在 logits 层面：

- 目标是 −100 的位置，logits 梯度是 0；
- 最后一个位置的 logits 没有目标，梯度也是 0；
- 提示的最后一个位置预测答案第一个 token，梯度不是 0。

M3 的手算例子能看到这三种情况：梯度逐位置是 [0, 0]、[1/4, −1/4]、[−1/4, 1/4]、[0, 0]。

## A3-W3

**梯度（20.3.2 节）。** 记 s = α/r。一个 batch 的输入 X 形状 (n, in)，输出的梯度 G = ∂L/∂Y 形状 (n, out)。对每个样本有 y = W₀x + b + s·BAx，逐样本求和后：

```
∂L/∂A = s · Bᵀ Gᵀ X        形状 (r, in)
∂L/∂B = s · Gᵀ X Aᵀ        形状 (out, r)
```

用 M4 的数字核对：s = 2，G = [[1, 1]]，X = [[2, 1]]，A = [[1, −1]]，B = [[2], [3]]。

- BᵀGᵀ = 5，dA = 2 × 5 × [2, 1] = [[20, 10]]；
- XAᵀ = 1，dB = 2 × [[1], [1]] × 1 = [[2], [2]]。

和测试的期望值相同。

**第一步。** B = 0 时，dA 含 Bᵀ，等于 0；dB 不含 B，只要 G、X、A 使 GᵀXAᵀ 不为 0，就非零。所以第一步只有 B 有梯度，B 长出来以后，A 才有梯度。起点的输出等于基座（20.3.1 节）。

有 weight decay 时，梯度为 0 的 A 仍会被轻轻缩小（20.3.2 节）。

**参数量（20.7.1 节）。** A 有 r·in 个，B 有 out·r 个，一共 r(in + out)。基座的 bias 冻结，不算。α 只改缩放，不影响参数量。整个模型对所有挂载模块求和。

手算：in = 4，out = 3，r = 2，得 14（`test_zero_init_freezing_and_first_step`）。

**峰值（20.8 节）。** 减小 r 只减少“可训练参数 + 梯度 + m + v”这一项（约 16 × N_LoRA 字节）。冻结权重、激活、logits 和交叉熵中间量一项不少，不能按可训练参数的比例估总显存。

第 20 章 20.8.3 节的手算：r = 16、q + v 时，静态部分 4N + 16N_LoRA ≈ 2.25 GiB，其中 16N_LoRA 只有 36,700,160 字节。20.14 节常见错误第 8 条的观察：q、v 上 r 从 4 变到 64，峰值只从 5.37 GiB 变到 5.52 GiB（本项目观察，书中那次运行）。

## A3-W4

**loss 降低不够。** loss 只说明模型在拟合你给的目标，不说明目标对不对（19.9.5 节）。

第 19 章 19.9.1 节真实 Qwen3 的例子（本项目观察，书中那次运行）：

| 组 | train loss | 生成 |
|---|---|---|
| label 错一位 | 18.47 → 0.150 | EM_norm 0/80，66/80 写到预算 |
| 提示计入 loss | 2.88 → 0.720 | 比正确组的 loss 高，生成没有明显差别（47/80 和 49/80） |

所以各组的训练 loss 不能互相比。漏 EOS 时 loss 也照样下降，停不停要看模型原来会不会停（19.5.1 节）。

要看固定正确 labels 的 val NLL 和生成指标。训练 loss 继续下降时，val 也可能不再改善（21.9 节）。

**核对。** 在长训练之前做（19.9.5 节，21.3–21.5 节）：

- 模板原文和一条样本的 token 边界；
- 数据版本和样本 ID，拒收计数；
- labels 逐位置打印，有效 token 总数；
- 第一批的提示监督数 = 0，EOS 监督数等于样本数；
- 可训练参数的名字和公式值。

**迁移到 TRL 并保持可比。**

- **数据**：用预编码的 `input_ids` 和 `labels`，避免二次模板化；跳过准备阶段，不让框架再截断（21.2.2 节）。开关不等于效果，第 21 章用的版本里 `completion_only_loss` 在这条路径上没有被用到（21.4.2 节）。要看第一批数据；
- **packing**：第 21 章设为 False（21.2.4 节）。换设置时要重新审查；
- **loss**：同一批数据上比 loss、梯度和一步更新（21.6.4 节）。分母要按全部 microbatch 的 token 总数（21.6.2 节）。CUDA 上的融合 LM head 要在 CUDA 上对拍，CPU 对拍不能代替（21.6.3 节）；
- **比较**：同一批 val、同一评测脚本、同一生成设置和精度，事先写好选择规则（21.8.1 节）。比完整面板和成本，不只比一个数；
- **单变量**：框架、rank、目标模块、训练集大小同时变时，回答不了“框架和自写哪个好”（21.10.2 节）。

框架的选项随版本变，以实际安装的代码和对拍结果为准（21.4.2 节）。
