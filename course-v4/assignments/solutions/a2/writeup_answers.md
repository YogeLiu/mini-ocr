## bpe_by_hand

预分词后的词块（第 6 章 6.4 节）：`ab` × 1，` ab` × 1，` abc` × 3。下面用 ␣ 表示空格。

| 轮 | 所有相邻对的次数 | 选中 | 新编号 |
|---|---|---|---|
| 1 | (a, b) = 5，(␣, a) = 4，(b, c) = 3 | (a, b) | 256 = `ab` |
| 2 | (␣, ab) = 4，(ab, c) = 3 | (␣, ab) | 257 = ` ab` |
| 3 | (␣ab, c) = 3 | (␣ab, c) | 258 = ` abc` |

这三轮都有唯一最大值，用不上平局规则。

编码 `" abcab"`：整段是一个词块，字节是 ␣ a b c a b。按合并的先后顺序：

1. 合并 (a, b)：␣ ab c ab；
2. 合并 (␣, ab)：␣ab c ab；
3. 合并 (␣ab, c)：␣abc ab。

结果是 **[258, 256]**。这和 `tests/test_a2_extended.py` 的 `test_special_literal_and_bpe_hand` 一致。

## rope_relative

二维平面上，f(q, m) = R(mθ)q，f(k, n) = R(nθ)k（第 10 章 10.3.3 节）：

```
f(q, m) · f(k, n) = qᵀ R(mθ)ᵀ R(nθ) k = qᵀ R((n − m)θ) k
```

式子里只剩 n − m。d 维的情况是逐平面成立，再把各平面的点积相加（10.4 节）。

混用约定时（10.5.5 节）：

- 两种约定各自都满足相对位置性质，所以只查平移不变的测试抓不住；
- 权重里本来配对的两维被拆开，频率也对不上，不报错，输出是乱码；
- 要和独立写成的参考公式逐元素对拍才抓得住。A2 的 `test_rope` 用复数写法逐位对拍，“相邻两维”过不了这个测试。

## gpt_accounting

**参数量**（第 11 章 11.3.3 节）。共享权重、RMSNorm、普通多头：

```
N = V·d + L·(4d² + 3df + 2d) + d
```

各变体多出来的部分（13.5.2 节）：

| 变体 | 多多少 | 原因 |
|---|---|---|
| 不共享 | V·d | 输出层单独一个矩阵 |
| 学习式位置 | T·d | T 是 `block_size` |
| LayerNorm | (2L + 1)·d | 每个归一化多一个 bias，共 2L + 1 个 |

本书配置 V = 2258、T = 128、L = 4、d = 256、f = 704（11.3.4 节）：N = 3,791,616；不共享 4,369,664；学习式位置 3,824,384；LayerNorm 3,793,920。阶梯的 tiny、medium、large 分别是 251,328、1,142,144、3,090,240（13.6.3 节）。用来核对学习者的公式，学习者要代入自己的配置。

**KV cache**（15.5.1 节）。k、v 各一份，每层 h 个头，每头 d/h 个数：

```
字节数 = 2·L·B·T·h·(d/h)·s = 2·L·B·T·d·s
```

s 是每个数的字节数。本书配置 B = 1、T = 128、fp32：2 × 4 × 1 × 128 × 256 × 4 = 1,048,576 字节。

**静态内存**（16.6.2 节）。fp32 AdamW 每个可训练参数存参数、梯度、m、v，各 4 字节，约 **16N 字节**。混合精度也是 16 字节，只是组成不同。本书配置约 60,665,856 字节。每个参数张量还多一个 AdamW 的 `step`，很小（16.11.3 节）。

**激活**（16.7 节）。正比于 B·T，注意力还有 T² 项，要实测或按 16.7.3 节逐项数。

**静态加激活不等于峰值**（16.11.3 节）。还有 logits、反向的临时张量、优化器的临时缓冲、分配器的缓存和碎片。用 `zero_grad(set_to_none=True)` 时，完整梯度和全部激活也不一定同时存活。所以这个和既不是峰值，也不保证是峰值的下界。

**计算量**（13.6、16.10 节）。

- 每步 6N·BT，N 用 matmul 口径：总参数 − 输入嵌入 + 输出层。输出层即使共享也要做一次矩阵乘法，所以不能把嵌入一扣了事。共享时这个口径恰好等于总参数，不共享时是总参数 − V·d；
- manual 注意力每步附加约 **12LBT²d**（16.10.2 节）。本书配置 B = 1、T = 128 时，6N·BT = 2,911,961,088，附加项 201,326,592，约多 6.9%；
- MFU = 6N × tokens/秒 ÷ 峰值，峰值的精度要和实际用的精度对应。没有核实的峰值不填，写“待验证”（16.10.3 节）。

## protocol_and_accum

**累积。** 大批的 loss 是全部 token 损失之和除以全部有效 token 数（第 16 章 16.9.2 节）。所以每个微批要用 sum NLL 除以全体有效 token 数；用微批 mean × 本批有效数 ÷ 总有效数，结果相同。

平均各微批的 mean 只在各微批有效 token 数相等时才对，否则短批里的 token 权重偏大。16.9.3 节的例子：长度 [2, 16, 16, 10]，分成 18 和 26 两组。正确权重是 1/44 ≈ 0.0227；错误写法下，前一组每个 token 是 1/36 ≈ 0.0278，后一组是 1/52 ≈ 0.0192。

**bits/byte。**

- 分子：val 前 2000 条里每个内容 token 和 EOS 各一次的总 NLL，除以 ln 2；
- 分母：清洗后原文的 UTF-8 字节和；
- BOS 只作条件，不作目标，输出时屏蔽这一类；EOS 是目标；BOS、EOS 都不计字节（第 7 章 7.1.2 节，第 13 章 13.1.4 节）。

手算检查（`tests/test_a2_evaluate.py` 的玩具例子）：公式 `中` 和 `a`，每个字节一个 token，共 4 个内容 token 加 2 个 EOS，6 个目标，4 字节。屏蔽 BOS 后是 4 类均匀分布，NLL = 6 ln 4，bits/byte = 6 × 2 / 4 = 3。

**测试集**（第 0 章 0.10.1 节）。选型冻结之前只看 val。冻结后，预先登记的候选各评一次，只报告数字和区间，结果不用于修改任何设置，开发期不看 test 错例。已经受了 test 影响，就在报告里写明，再补一份新的测试集。门槛只依据验证集确定，写在 test 评测之前。
