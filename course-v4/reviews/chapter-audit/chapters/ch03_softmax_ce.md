## 章节主线与关键约定

本章从 logits 到 softmax 概率、负对数似然，再推导交叉熵的 `p-y` 梯度。softmax 只依赖分数差；稳定实现先减最大值，直接求 log-softmax；低精度输入的中间结果提升到 fp32。交叉熵是条件概率模型的平均 NLL；总体交叉熵分解为条件熵与 KL，文中已区分总体下界、有限验证估计和训练记忆。

序列张量约定是 logits `(B,T,V)`，类别在最后一维；手写 CE 按最后维 gather，而 PyTorch CE 类别在第1维。`ignore_index=-100`；默认均值分母为有效 token 数。按 token 均值和先逐序列均值再平均是不同权重。全忽略 batch 的 mean 是 NaN。分类器使用补一列1的 X 合并偏置，`dW=Xᵀ(P-Y)/N+2reg W`；中心差分用于梯度检查，默认 float64、h≈1e-5。初始化近均匀预测时 loss≈ln C，困惑度 exp(loss)。末尾把序列 CE 连接到 OCR teacher forcing，并明确 token loss 与全序列 EM 不等价。

## 已确认问题

### CH03-01 · P2 · 从一个 loss 标量反推“只学会类别频率”不成立

**位置与短引文：**1165行“loss 降到 H(频率) 附近，说明模型只学会了猜最常见的类，还没有用上输入的任何信息”；1185行曲线标注“还没用上输入”；1194行再次断言“停在 H(类别频率) 附近说明模型只学会了类别频率”。

**理由：**恒定输出经验类别频率的模型确实达到该熵，这是一个可以计算的基线。但任意输入相关模型的平均 CE 恰好等于基线，不能推出它处处输出基线概率。部分样本概率提高、部分降低，可以相互抵消。这里把充分条件的正向计算倒置成了唯一诊断。停在 ln C 也只能提示排查，不能证明没有利用输入。

**可复核反例：**两个平衡类别样本，标签 `[0,1]`，模型按输入分别输出 `[0.8,0.2]` 与 `[0.6875,0.3125]`。正确类概率为0.8和0.3125，平均 CE `-ln(0.8×0.3125)/2=ln2=H(频率)`，但模型显然没有恒定猜频率 `[0.5,0.5]`。本次 float64 CPU 计算两者都为 `0.6931471805599453`。概率都严格大于0，因此可由有限 logits 表示。

**建议：**改成“这是不利用输入、只预测类别频率的基线；训练 loss 长期接近它值得排查模型是否利用输入，但不能单凭 loss 判断。可进一步比较基线模型、检查逐样本预测，或打乱输入做对照。”修订曲线标注与1194行，保留基线数值本身。

## 待核线索与已经明说的局限

- 995行 `where` 避免被忽略位置的 `inf×0` 污染，作为前向选择成立；不要把它扩展成任意非有限 logits 的反向修复保证。本次 CPU 用忽略行 logits `[inf,0]`、有效行 `[0,0]`，得到有限 loss `ln2`，忽略行梯度仍为 `[nan,nan]`。这是对外推边界的提醒，不另计为正文已作出错误反向承诺。PyTorch autograd 文档也警告事后遮罩不会移除上游无效运算。
- 871行“不管 logits 多大……梯度都不会爆炸”上下文讲的是对 logits 的 `p-y`；不能外推到参数梯度或深层链式传播。后章讲梯度裁剪时需维持这一区分。
- 1169–1174、1573行“每次新模型初始应近 ln C”的诊断依赖小 logits、从头初始化、未加载有效先验。正文1105附近及偏置例子已经提供条件，不将有条件公式判为错误；对后面预训练、SFT 的应用应限定条件。
- 1524行把“错开一位”称为 teacher forcing，需与第7章核对：teacher forcing 的核心是训练时使用真实前文，移位是常见并行实现而不是充分定义。
- 1544行独立假设已明确；661–663行已区分总体与有限样本；1426行已说明特定螺旋实验不是准确率上限；219行已说明概率不等于校准置信度。均不重复指控。
