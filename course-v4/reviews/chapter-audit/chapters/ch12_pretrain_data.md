## 主要内容和关键约定

本章把第 6 章的 latex-v1 公式语料接到第 13 章预训练前的数据处理。主线是探索长度和结构、规范键、精确去重、3-token shingle Jaccard、MinHash、LSH 候选、精确核验和并查集合簇、语法过滤、源混合、带指纹的 uint16 文件与数据报告。

规范键用于分组和比较，模型训练仍用清洗原文；解析失败时 `normalization_key` 回退原串，与第 0 章规则不同。随机排列下 MinHash 碰撞概率等于 J，k 个独立位的标准差为 sqrt(J(1-J)/k)；实际 affine 哈希只是近似。LSH 候选概率为 1-(1-s^r)^b，默认 k128、b16、r8、精确阈值0.8。连通簇不要求任意两点都相似。mathtext 只代表 TeX 子集，过滤可删掉合法的复杂公式。缓存绑定分词器内容、数据版本和格式，数据版本并非内容哈希。

## 已确认问题

### CH12-01 P2 把规范 token 的混合份额称为实际模型 token 份额

- 位置：688行的实际模型token结论及690行的计算量解释；计数来源为677–680行表格。
- 原文短引文：“实际喂给模型的 token 有 23.6% 来自 B”。
- 问题：表中 37.0516 和 103.1982 是手工 LaTeX 规范 token 的平均长度；本章 12.2.3 明确说模型训练用清洗原文，第 6 章和 12.9 则使用 BPE。两种长度之比不保证在 A、B 源中相同，所以 23.6% 只是规范 token 口径的份额，不能直接转写成模型实际 token 的比例或算力配额。
- 证据：同一章 1431602 个规范 token 与 12.9 的1149263个内容 BPE token 已不是同一计数单位。反例：两源规范长度相同，但 BPE 平均长分别10和20；按条数各一半时规范份额各50%，模型 token 份额却为1/3和2/3。此反例是定义层面的算术，不依赖训练结果。
- 建议：例子明确标为“规范 token 的混合演示”；实际训练配额需用最终 tokenizer 对清洗原文编码，重新统计各源长度与份额。698行的 epoch 同样注明计数单位。

## 待验证线索和已声明局限

- 12.4 的 affine 哈希不是严格 min-wise 独立族；正文已经声明近似，不能仅凭此指控理论推导错误。对240对人造集合的近零误差均值不能证明一般无偏，建议保持“本样本未见明显偏差”的措辞。
- MinHash 把 shingle 先压到31位，原 shingle 间可能碰撞。代码注释承认该边界，正文如扩展到全量应补充说明；本轮未测其实际影响，不列确定错误。
- 12.6 已解释相似链误删、长公式关键符号误删和小召回样本不足，不重复列为新增缺陷。
- 12.7 明确区分 mathtext 不支持与 LaTeX 不合法；其矩阵过滤失败属于已经展示的历史局限。
- 12.3.5 的泄漏实验没有实际训练模型，量化的是规范键重叠比例，而非训练后分数虚高幅度。导读“实测泄漏严重性”可理解为该重叠，不应进一步引用成性能增益。
