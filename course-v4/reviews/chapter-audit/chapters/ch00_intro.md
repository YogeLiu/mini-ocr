## 章节主线与关键约定

本章先定义图片到 LaTeX 的忠实转写任务，再以 16 对手写样例区分写法差异和真实识别错误。规范化管线为分词、逐 token 规则、语法树解析、规范序列化；它忽略部分间距和尺寸差异，但不合并 `a+b` 与 `b+a`。解析失败仍返回 token 规则处理后的序列以便计算距离。

EM 默认指规范化完全匹配。CER 默认使用规范化后的字符，语料级聚合为总编辑距离除以总参考长度；CER_token 使用手写 LaTeX 分词，不等于 BPE。可编译率以 mathtext 可解析率近似；渲染一致率只在双方可解析时计算，同时报告覆盖样本数、渲染器、字体、dpi 和容忍度。OCR 主面板、文本后纠错面板及第四部分的 OCR 精简面板具有不同指标范围。

验证集用于选型、看错例和开发协议；测试集只在选型冻结后按预登记候选各评一次，不反哺开发，错例到最终报告冻结后解封。相同规范键整组划分，但这不保证覆盖所有等价写法；需要近重复和来源信息补充。新评测规则必须升级版本，所有候选同口径重算。

## 已确认问题

### CH00-01 P1 字符 CER 拼接重新抹掉命令边界

- 位置：正文 210、738、1011 行；实现 `miniocr/eval/metrics.py` 的 `units` 字符分支及 `score_pair`。
- 原文承诺：先识别 `\alpha` 再丢空格，“所以不会出问题”；字符面板则“规范化后、去掉空白”。
- 问题：token 列表保留了命令与后续字母的边界，但字符计分使用 `list("".join(toks))`，这个映射不是单射，把本来不同的命令序列压成相同字符序列。
- CPU 复现：参考 `\sin h(x)`，预测 `\sinh(x)`，token 分别为 `['\sin','h','(','x',')']` 与 `['\sinh','(','x',')']`；EM_norm = 0，字符 CER = 0，CER_token = 0.4。两者对应正弦复合表达与双曲正弦表达，不是单纯排版差异。`\alpha b` / `\alphab` 同样得到 EM = 0、字符 CER = 0。
- 修改建议：为字符比较定义保留必要词法边界的序列化方式，明确它与 token 比较的关系；补上不同命令边界的反例。若保留当前指标，必须明确其会把这类结构错误计为零，不能继续以“不会出问题”概括整条处理链。修复会影响后续 CER 和基于编辑距离的奖励，需升级评测协议并重算相关结果。

### CH00-02 P2 空白规则的执行层次与适用范围没有在首次说明时说清

- 位置：200–210、246–260 行；关联 449、541 行。
- 原文先说规则“按顺序判断”，列空白丢弃在第 1 条，后说“先用规则 3”识别命令。
- 裁定：现有逐字符代码对 `\alpha b` 的分词是正确的，并不存在全文先删空格的代码错误；问题是讲解没有说明“每个当前位置上的分支判断”和“对全文依次执行的处理步骤”不同。读者按后者理解就会与后文冲突。
- `\text{…}` 例外已经在 449 和 541 行明确承认，不作为新发现的隐蔽缺陷；但 210 行不加条件的“不会出问题”与该限定不一致。CPU 复现 `\text{if x}` / `\text{ifx}` 得 EM_norm = 1。
- 修改建议：将规则前言改为“从左到右扫描，每到一个尚未读取的位置依次判断”；说明普通数学模式空格不产生 token，但仍参与命令终点识别；首次介绍即提示该简化分词器没有保留文字模式空白。

### CH00-03 P2 单元素分组剥除会改变控制声明作用域

- 位置：429、498 行“一个分组里只有一个元素时，直接写这个元素”；实现 `serialize.unwrap`。
- 问题：分组不只承担上下标结构，也承担 TeX 声明的作用域。解析器把未收录到 ARITY 的声明当普通 token，因此“只有一个元素就总能剥括号”并不保证等价。例如 `{\bf}x` 中粗体声明仅在空分组内生效，`\bf x` 则作用于后续 x；实现都会规范成 `\bf x`。此反例和已承认的文字空白盲区不同。
- 证据：实现的 `unwrap` 不检查节点是否为作用域声明；本地反例规范键相同。用本章同一 mathtext 渲染器直接比较：两边均可解析，但 `image_match=False`、`pixel_diff=0.53846`；`{\rm}x` / `\rm x` 也同键而渲染不同（diff=0.89189）。这直接验证了声明作用域的可见后果。
- 修改建议：只对已知无作用域副作用的节点剥除分组，或明确不支持声明类命令，检测到时保守保留分组/回退原串。将这类输入加入“应该不同”回归样例。
