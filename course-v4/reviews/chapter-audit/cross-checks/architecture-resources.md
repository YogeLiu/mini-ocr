## 已确认的跨章问题

### AR-01 / P2：DDP 的“不省显存”遗漏了固定全局批下的激活节省

- **前端**：`book/part2_lm/ch16_training_engineering/chapter.md:1049`：“显存不省，只加速。”主语是显存整体，没有限定静态参数状态。
- **后端**：`book/appendix/a_distributed/chapter.md:121`：固定全局 B=16，单卡激活 54,071,300 字节，四卡每卡 B=4 后为 13,530,116 字节；明确“DDP 也省这一笔，前提是全局批不变”。该附录 `:203` 已准确写成“不省静态显存”。
- **判定**：这不是两种不同的 DDP。前章把“每卡参数、梯度、优化器状态仍完整复制”扩大成“每卡总显存不省”。固定全局批时，每卡输入和激活可以缩小，因此在模型静态部分本来放得下、激活导致超额时，DDP 也可能使训练可运行。若固定每卡批，则没有这项激活节省。通信缓冲还会增加开销，不能进一步承诺峰值必按卡数缩小。
- **联动改法**：16:1049 改为“DDP 不分摊参数、梯度和优化器的静态显存；固定全局批时，每卡批变小，可省激活显存。固定每卡批时主要增加吞吐，详见附录 A”。保留 A:121、203 的细分，不改正确的数值，也不把“约四分之一的激活”改成“四分之一的总显存”。

### AR-02 / P2：checkpoint 的 4/3 被称为一般上限，但其前提不适用于冻结基座

- **前端**：`book/part2_lm/ch16_training_engineering/chapter.md:722–726`：以反向约 2F 推得 4F/3F，并称“所有计算都在块内、而且全部重算时的上限”；`:778` 再称额外计算“上限约 33%”。
- **后端**：`book/part3_post_training/ch20_lora/chapter.md:549–553,731` 明确冻结 Linear 仍算输入梯度，但不算权重梯度；`book/part4_vlm/ch33_vlm_lora/chapter.md:381–385` 给 LoRA 使用 checkpoint 的激活账，并正确说多跑约一次前向、耗时未测。
- **判定**：一般公式是 `1 + R/(F+B)`，R 为实际重算量。4/3 依赖“全参、线性矩阵乘主导、B≈2F、最多重算一次前向”。冻结权重后仍须传播输入梯度，但省掉 dW，B 不再近似 2F；同一次前向重算占原训练计算的比例可以更大。33 本身没有声称 33%，问题在 16 给出的可被跨章沿用的无条件上限。
- **新 CPU 证据**：四组 `Linear(64,64,bias=False)+SiLU`，输入 `[4,16,64]` 且 `requires_grad=True`，非重入 checkpoint；全参：6,291,456 → 8,388,608 FLOPs，比值 1.3333；冻结所有 Linear、仅保留输入反传：4,194,304 → 6,291,456，比值 **1.5**。输入反传对应上游 adapter 仍需接收梯度的机制，但这个简化网络不是实际 LoRA/Qwen 的性能复现。
- **联动改法**：16:726、778 明确“在上述全参矩阵乘近似下约 33%；不是任意冻结策略、重算实现或实际耗时的一般上限”。把 `1+R/(F+B)` 放在 4/3 之前。20:553 可加一句“也会改变重算相对开销的分母”；33:385 加指向 16 限定的提示，继续保留“耗时未测”，不要写成真实 LoRA 一定慢 50%。16:735 的 1.25 实测不因此失效。

### AR-03 / P2：把 token 行置换的定理，扩大成了任意图像空间关系不可辨

- **前端**：`book/part2_lm/ch08_attention/chapter.md:776–782` 的 P 左乘 X 只置换 token 行；`book/part2_lm/ch10_rope/chapter.md:47,55,59,65` 明确对象是字符 token、输出置换等变，并排除了因果 GPT 的直接套用。
- **后端**：`book/part4_vlm/ch29_vit/chapter.md:476–480` 引用前述定理后，直接说不加位置便“分不清分子和分母谁在上面，分不清 x² 和 ²x”。但该章 `:119–126` 已定义 patch 内特征编号 `f=c·p²+u·p+v`，不同像素位置对应投影矩阵的不同列。
- **判定**：无位置编码的双向 ViT 丢失的是整块 patch 之间的显式坐标；它仍保留 patch 内部的固定像素排列。若分子分母或上下标落在同一 patch，改变相对位置会改变特征列，不是同一批 patch token 的行置换。更一般地，移动符号还会改变切块边界，不能自动转化成完整 patch 的重排。8/10 的定理本身正确，不应回改成无位置模型总能认位置。
- **新 CPU 证据**：`TinyViT(image_size=4,patch=4,width=8,depth=1,heads=2,classes=2)`，种子 29，位置表全置零；两张图只有一个墨迹像素，分别在 `(0,0)` 和 `(0,1)`。分类 logits 最大差 **0.3270017207**。这里只有一个图像 patch，足以排除“没有位置表就对 patch 内位置一无所知”的推论；不代表能完成真实公式识别。
- **联动改法**：保留 8/10 的证明。29:480 改成“若两幅图只把完整 patch 重排，且不改变各 patch 内像素，去掉位置编码的编码器无法从内容恢复这些 patch 的绝对网格位置；例如分别处于独立 patch 的分子、分母可能发生这种歧义。patch 内关系仍由投影保留”。配图/反例明确置换单位。29:751 的“一维位置表的行优先排列都是先验”也应区分：可学习的独立位置向量提供位置身份，但任意行号重标并同步重标参数是同一参数化，行优先本身不强制二维邻近结构；二维插值才使用网格邻近关系，见29:503–514。

### AR-04 / P2：等效面积被当成真实非空 token 数，与后章 occupancy 定义不一致

- **前端**：`book/part4_vlm/ch27_image_tensors/chapter.md:455` 把“公式区域面积÷1024”解释成“约合多少个视觉 token 落在公式上”；`:457` 从平均 3.8 个 token 的面积推到“其余全是白纸”。
- **后端**：`book/part4_vlm/ch29_vit/chapter.md:433,450–457` 用某 patch 是否至少有一个像素墨迹值 >0.5 定义非空；`:446` 明说非空比例不是信息保留率或 OCR 准确率；`book/part4_vlm/ch32_real_vlm/chapter.md:199–202` 的面积÷1024 计算的是整幅处理后画布的视觉 token 总数。
- **判定**：画布总面积/1024 在相应整除网格下给总 token 数；公式外接区域面积/1024 只给区域的等效 token 面积；非空 token 数还取决于网格交界及实际墨迹。这三项不能互换。27 和29使用不同样本与不同 patch 配置，不应把其均值之差当作实验数据冲突。
- **新 CPU/几何反例**：128×128 画布、32×32 网格、墨迹为横跨全宽的14像素高实心条，放在行57到70。墨迹面积等效 `14×128/1024=1.75` 个 token，却跨两排、触及 **8** 个 token。其余 8 个为空，不能从 1.75 推成其余约14个全白。稀疏真实字形还须再区分外接框和实际墨迹。
- **联动改法**：27:455 改名“公式外接区域的等效 token 面积”，27:457 改成“公式区域只占画布较小面积；有多少整块 token 全白，需要按网格逐块统计，见29.4.4”。保留 3.8/33.8 作为面积统计，不冒充非空计数。29 的 occupancy 定义保持；32 给总数公式时增加一句“不是内容占用数”。

### AR-05 / P2：检查点的断电承诺超过实际持久化保证，后章才收回

- **前端**：`book/part1_foundations/ch04_training/chapter.md:939` 在“写到一半断电”语境中接上 `os.replace` 的“要么完全是旧文件，要么完全是新文件”；前面的保存实现只执行临时写和替换，没有刷盘协议。
- **后端**：`book/part2_lm/ch13_pretraining/chapter.md:404` 正确限定为进程崩溃/被杀时不会以半截新文件替代旧检查点，明确防断电还须对文件、目录调用 fsync，现代码没有做。
- **判定**：同文件系统 rename/replace 的命名可见性原子性，不等于掉电后的数据与目录项持久化。13 的限制不能消除读者在4已形成的断电保证。这里不声称真实设备掉电必丢，也没有执行断电试验。
- **外部核查**：实际打开 [Linux man-pages 的 fsync(2)](https://man7.org/linux/man-pages/man2/fsync.2.html)，DESCRIPTION 区分文件数据落盘与目录项另需目录 fsync；与13的限制一致。
- **联动改法**：4:939 将故障例子区分“写入进程中途退出”与“系统掉电”。写明当前实现只提供同文件系统替换的原子可见性，掉电持久化未实现，链接13.4.5。若未来要实现持久化，是另一个需明确平台、文件系统及错误处理的实现任务，不能只改措辞就宣称已有保障。13:404 保留。

### AR-06 / P3：注意力 FLOPs 的因子2已经有解释，但13须在公式当地标明口径

- **前端**：`book/part2_lm/ch13_pretraining/chapter.md:568–572` 引 Kaplan 的每token前向 `2N+2LTd`，随后把 `LTd/N` 和 medium 上下文128的5.7%直接用于项目配置的 `attention_extra_ratio`。
- **后端**：`book/part2_lm/ch16_training_engineering/chapter.md:911,915` 已明确 manual 算完整 T×T（遮住的一半也算），训练注意力项 `12LBT²d`，比例 `2LTd/N`；同时说明13的估计少因子2是取因果半矩阵。
- **判定**：不成立的指控是“全书两套公式无解释地矛盾”。正确问题是13当地将论文估算和项目实际算子成本接在一起，未标示差异，顺序阅读者要等到16才发现其项目比例并非 manual 的实算开销。因果有效对数为 `T(T+1)/2`，大T近似半矩阵；manual 则算 T² 对。以13同一个 N=1,142,144、L=4、T=d=128比较，半矩阵估计约5.74%，完整矩阵约11.48%。不能直接拿13的5.7%与16不同词表/不同N及T的7.1%比较。
- **外部核查**：实际打开 [Kaplan et al. 原论文](https://arxiv.org/pdf/2001.08361)，§2.1 式(2.2)、表1与训练计算量段确有该公式，N 是 non-embedding 参数；正文13:534–540另行说明了项目 matmul_params 的词嵌入/输出头处理。半矩阵到完整矩阵的因子2由上述矩阵形状推得，不把论文表格描述成具体硬件内核实测。
- **联动改法**：13:570 前后就地加“这里沿用论文对因果有效半矩阵的估计，不是本项目 manual 注意力的完整矩阵 FLOPs；后者注意力项近似翻倍，见16.10相应对拍”。`attention_extra_ratio` 列清楚称为“论文口径估计”。16:911、915 现有解释保留。不能把13的公式直接判成算术错误，也不要声称任意带 causal 标志的算子必然只算一半。

### AR-07 / P2：DDP 的“完整等价条件”未携带随机算子的同一次实现条件

- **前端**：`book/appendix/a_distributed/chapter.md:80–85` 称四条为“完整的等价条件”：相同初值和更新、相同权重、每样本一次、无跨样本层。
- **关联端**：`book/part2_lm/ch16_training_engineering/chapter.md:780` 明确 dropout 的重算若随机数不同，两次前向不一致，需保持 RNG；`book/part1_foundations/ch04_training/chapter.md:933` 的恢复逻辑恢复 RNG。前述随机实现一致性也影响把单个 batch 切分后的“同一步梯度相等”。
- **判定**：四条件足以支持确定性、样本可分损失的加权梯度代数，但不是含 dropout 等随机算子的逐次/逐位等价充分条件。单卡大张量一次抽样和多卡分块抽样即使各用同一seed，也可能给同一个样本分到不同 mask；数学期望相同不意味着该步实际梯度相同。此外归约顺序不同仍可能产生浮点容差差异。
- **新 CPU 反例**：`x=[1,2,3,4]`，标量权重w=1，loss为 `mean((w*dropout(x,p=.5))²)`。每次前向从seed7开始：整批梯度10；两份 `[1,2]`、`[3,4]` 各从seed7抽样，再平均梯度为60。样本数相等、每样本一次、无BatchNorm、初值相同仍成立。
- **联动改法**：A:80 改为“确定性、样本可分损失下的数学等价条件”，随后说明随机算子若要求同一步数值对拍，需按样本对齐随机实现或在关闭随机性的对拍模式验证；不建议笼统写“各卡seed设相同就足够”。链接4的RNG与16:780；对拍继续按合理浮点容差，不承诺一般多卡逐位相同。

### AR-08 / P3：量化合并的风险在附录被缩写成确定的效果下降

- **定义端**：`book/part3_post_training/ch20_lora/chapter.md:428` 精确说的是“4 bit权重加高精度增量，再存回4 bit会损失精度”；`:418–420` 另分清普通浮点合并的舍入误差。
- **传播端**：`book/appendix/c_quantization/chapter.md:198` 写“把LoRA合并回4 bit基座｜增量被舍入，模型效果变差”；`book/appendix/d_vllm/chapter.md:211` 进一步缩成“量化基座上合并LoRA｜效果变差”，丢掉了“再量化存回低比特”的条件。D:177 的完整模型合并部署路线未就地带此条件。
- **判定**：应区分“不能在本教学Linear上直接操作量化存储”、数学上合并后保留高精度、以及合并后重新量化。重新量化可引入额外误差，却不逻辑保证任务指标下降（增量恰好落在量化格点时还可能无额外舍入）。20的提醒属于合理工程风险，不是禁止所有量化模型一切合并；附录的确定效果用语不够准确。
- **联动改法**：C:198、D:211 均改为“合并后直接再量化存回低比特：可能丢失增量并影响效果，须重新评测”；D:177 加“浮点基座按20.6操作；量化基座须核对具体量化格式/实现，不能直接套用教学nn.Linear合并代码”。20:428可补“保留更高精度是另一条路线，显存账相应改变”。不宣称所有版本的PEFT均支持特定量化合并，接口能力须另查并验证。
