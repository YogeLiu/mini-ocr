### XMD-01 / P1：字符 CER 的序列化丢失命令边界，进入偏好选择与奖励

**源文与传播路径。**第 0 章 `book/ch00_intro/chapter.md:202` 的丢空白约定、738 行的字符口径说明和 1011 行的“规范化后去掉空白”，经 `miniocr/eval/metrics.py:84—94,167—175` 实现为 `list("".join(tokens))`。第 18 章 `ch18_prompting/chapter.md:104—119` 的纠错面板实际经 `miniocr/eval/postcorrect_eval.py:147—178` 使用该字符序列。第 23 章 `ch23_dpo/chapter.md:479—483` 把规范化字符距离用于偏好构造；其 `tour.py:176—198` 按 `(错误率, 原串长度)` 排序。第 25 章 `ch25_grpo/chapter.md:412—413`、`miniocr/eval/rewards.py:18—31` 用它计算改进比例。第 34 章 `ch34_vlm_grpo/chapter.md:245`、`miniocr/train/vlm_grpo.py:24—31` 用它决定接近档位。

**CPU 反例。**参考 `\sin h(x)` 与错误输出 `\sinh(x)` 的词法 token 不同，前者是 sin 后接变量 h，后者是双曲正弦。实际 `score_pair` 返回：

```text
em_norm=False, ed_char=0, len_char=8, ed_token=2, len_token=5
```

这不是“合法忽略空白”的问题，而是已经分词后又无分隔地串接 token：`\sin` 与 `h` 的边界消失。EM 使用保留分隔的 token/string，故仍能区别；字符距离不能区别。

令候选依次为参考、错误输出、`\sin z(z)`，第 23 章的真实排序得到错误率 `[0,0,0.25]`，顺序 `[1,0,2]`：更短的错误输出成为 chosen，正确参考没有被选为 chosen，且 best/worst 间隔 0.25 超过默认 0.05。若组内只有前两个零距离候选，则间隔不足而被丢弃，不能声称这种两候选情况直接生成反向偏好。

同一目标、输入 `\sin z(z)`、输出 `\sinh(x)`：第 25 章实际奖励为 **0.5**，即获得非精确答案的最高部分分；第 34 章返回 `reward=0.5,tier=2,em_norm=False,edit_distance=0`。若输入本身是边界碰撞串，第 25 章 `base<=0` 也不能推出“输入已经正确”（412 行）。

**影响边界。**字符 CER、基于它的 DPO 选择及部分奖励确实受影响；此例的 EM、按 EM 计算的 fix/broken 不受影响。不能据此认定所有 CER 优化都是错误，也不能将整份历史 DPO 数据称为污染。对 `outputs/book/ch23/gpu/candidates.jsonl` 的 2048 个提示、8192 个候选逐个检查，5164 个为规范化精确匹配，**零距离但 EM 不成立为 0 个**。因此已证实可触发机制，未在该归档观察到此种精确零碰撞；其他非零距离排序失真和其他章的历史影响量仍待统计。

**共同修订。**第 0 章先定义保留词法边界的字符序列化，或把既有值明确命名为会碰撞的代理指标；第 18/23/25/34 章随新协议重算，并更新第 25 章 base 判据解释。偏好构造至少加入精确匹配优先规则，不能只靠原串较短打破零距离平局。改指标后记录新版本，保留旧历史结果，不混用新旧 CER。

### XMD-02 / P2：无条件剥单元素组改变声明作用域，规范化键随之误合并数据

**源文与路径。**第 0 章 `ch00_intro/chapter.md:429,498` 的组简化，由 `miniocr/eval/latex_norm.py:245—250,274` 的递归 `unwrap` 实现。第 12 章 `ch12_pretrain_data/chapter.md:125—137` 将键解释为只合并等义写法；`miniocr/data/latex_corpus.py:59—65` 成功解析时复用同一序列化，126—135 行据此分组。`miniocr/data/dedup.py:14—29` 据键进行精确去重。第 31 章 `ch31_mini_ocr/chapter.md:121—135` 承接标准分组；实际 `tour.py:18` 引入的 `contrastive_pairs.prepare_pairs`，最终在 `miniocr/data/contrastive_pairs.py:69—85,98` 用规范键 SHA256 去重图文对。

**CPU 反例。**`{\bf}x` 和 `\bf x` 均得到键 `\bf x`。前者声明的组已结束，后者声明作用于后续 x。本地 `compare_render` 两边均可解析，但 `image_match=False,pixel_diff=0.5384615384615384`；`exact_dedup([a,b])` 只留下第一项并报告删除 1 项。类似 `\rm` 例也不同。这是受支持声明的作用域被改变，不是 SHA256 的随机碰撞；增加哈希长度无济于事。

**影响边界。**共享标准划分会把不同公式误当成同组，影响分组排序及边界；第 31 章装载器还可能据此丢掉视觉不同的样本。两式被同组分配，**此反例不证明跨 train/val 泄漏**。训练仍喂清洗后的原文，没有把所有原文替换成规范键；应指控错误合并/删除，不能指控全体训练文本被重写。尚未统计真实语料中此模式的频率和历史样本变化。渲染验证限于 Mathtext，没有将其冒称为完整 TeX 复现。

**共同修订。**第 0 章给出可安全去组的语法条件，保留影响声明范围的组；第 12/31 章把“键相同即等义”改为有条件的工程假设，并增加这类边界例。共享键修正会改变划分与去重结果，应生成新数据协议版本并报告队列变化，不能悄悄替换历史训练队列。

### XMD-03 / P2：参考 parse_rate 被从描述性基线提升成忠实度判据

**跨章命题。**第 13 章 `ch13_pretraining/chapter.md:813—819` 正确指出真实目标约 0.60 可解析、不是严格上界；但 819 行把较高率解释为“这时它只是更单调”。第 22 章 `ch22_eval/chapter.md:601` 因 63 个失败预测的参考也失败，断定这些失败“只说明”工具不认识结构。第 33 章 `ch33_vlm_lora/chapter.md:549` 将 parse_rate 下降与更贴近目标写法关联；第 34 章 `ch34_vlm_grpo/chapter.md:413` 将其提升为“parse_rate 向目标的比例靠拢才是忠实的表现”。

这些论断混淆每题正确性与边际比例。CPU 构造如下，调用真实 `can_parse`：

| 队列 | 第 1 项 | 第 2 项 | 可解析率 | 规范化精确率 |
|---|---|---|---:|---:|
| 参考 | `x` | `\begin{pmatrix}a\end{pmatrix}` | 0.5 | — |
| 原预测 | `x` | `x` | 1.0 | 0.5 |
| 新预测 | `x{` | `y` | 0.5 | 0 |

新预测的比例完全贴合参考，却两题都错，且每题 parse 标志与参考恰好相反。`x{` 与不可解析矩阵参考也可组成“两边都失败但输出确有自身错误”的例子。因此参考失败不排除预测独立损坏，更不能从双失败数推算解析器漏报数。类似地，可解析率较高还可能是等义改写，而不必是更单调。

**已有澄清必须保留。**第 33 章 549 行另外报告 `&` 输出从 13 到 22、目标 27，这为该案例的风格解释提供额外证据，不能把全段斥为纯凭 parse_rate。第 22 章 623 行的“降到 32 左右”明确是待检验假设，不是已经运行完整 TeX 的结果。第 34 章 465 行逐题列出的 4 个奖励改善而距离未改善案例，也有独立逐题证据，不受本反例推翻。

**实际影响与共同修订。**属于第 13→22→33→34 章解释规则的传播错误，并非 parse_rate 代码计算错误。改成“参考比例用于展示验证器覆盖及数据分布，向其靠拢本身不证明忠实度”。用 reference/prediction 的配对 2×2 表、EM/CER 条件分桶和具体结构检查验证解释。第 22 章把 63 条改为“现有解析器无法据此判断”，保留是否为合法 LaTeX的待检验状态。第 13/34 章删除必要或充分判据式措辞。

### XMD-04 / P2：第 25 章用绝对档位间隔解释优化动力，与同书组内标准化不相容

**源文与代码。**第 25 章 `ch25_grpo/chapter.md:413,458` 将部分分最高 0.5、全对 1.0 解释为留明显台阶，458 行进一步说部分分若到 0.9“模型会满足于差不多对”。同章 125—134、192—206 行其实已讲组标准化及小分差放大；第 34 章 `ch34_vlm_grpo/chapter.md:223—239,328` 又明确解释这一机制。真实 `miniocr/train/vlm_grpo.py:47—59` 为减均值除总体标准差加 epsilon。

对两候选或只有两种奖励的组，忽略 epsilon 时，标准化优势只由各档出现次数决定，不由档位间隔决定。CPU 实际代码（eps=1e-4）结果：

| 奖励 | 优势（约） |
|---|---|
| `[0,0.5]` | `[-0.99960,0.99960]` |
| `[0,0.9]` | `[-0.99978,0.99978]` |
| `[0.5,1]` | `[-0.99960,0.99960]` |
| `[0.9,1]` | `[-0.99800,0.99800]` |
| `[0,0,0,0.1]` | `[-0.57602,-0.57602,-0.57602,1.72806]` |
| `[0,0,0,1]` | `[-0.57722,-0.57722,-0.57722,1.73165]` |

因此 0.5/1 相对于 0.9/1 并不一般性提供更明显的组内优化台阶；0.1 的投机奖也可能产生几乎相同的正优势。这是已在第 34 章讲明的数学事实，却未约束第 25 章的设计动机措辞。

**限制与修订。**不应反向声称奖励档位毫无作用：有三种及以上奖励的组，非仿射改变档位可改变优势比例，epsilon、分组分布、KL 也影响训练。第 25 章应把台阶动机限定为原始奖励设计及多档组的待检验选择，不能由 0.9 接近 1 直接推断满足于部分正确；增加两档反例并链接第 34 章。没有做两套档位 GPU 对照，不报告收益量或哪个配方一定更好。

### XMD-05 / P2：第 34 章把标准答案自评分均值命名为奖励上限，与已披露的奖励投机直接冲突

**跨章来源。**第 22 章指出验证器局限，第 25 章 `ch25_grpo/chapter.md:438—454` 已准确披露：正确答案可能 0 分，错误但能解析的答案反而高分，历史训练保留这一缺陷。第 34 章 `ch34_vlm_grpo/chapter.md:349—360` 也正确推导标准答案自评分均值，并解释别的输出可以更高。但同章 335 行标题、412 行“奖励上限低于 1”、531 行“天花板只有 0.33”、573/764 行继续把它称为奖励天花板。

**CPU/书内反证。**目标 `\begin{pmatrix}a\end{pmatrix}` 原样输出得到 `em_norm=True,parses=False,reward=0`，输出无关的 `x` 却得 0.2。正文 379—382 行自身也列出起点 0.344、GRPO 0.355 均高于所谓 0.33 天花板。因此 0.33 是“完美转写策略在冻结奖励下的均值”，不是最大可获奖励，也不能由它断言优化目标存在低于 1 的上限。

**修订边界。**将第 34 章上述命名统一改为“标准答案自评分基线/奖励与正确性的错配”；保留表格、数值与正确的奖励投机说明。验证器门控和单边 `extract_formula` 去句末标点是第 25/33/34 章已明确承认的历史缺陷，不再当作新发现重复计数；其训练效果仍待对照。新协议需先检查所有标准答案满分条件，再决定修验证器、抽取或数据范围，不能仅为了满分而无说明删除复杂公式。

### XMD-06 / P2：第 12 章规范 token 混合算例被表述为真实模型 token 配额

**源文与实现。**`ch12_pretrain_data/chapter.md:677—690` 的 A/B 均长为 37.0516/103.1982，表头明确是规范 token，23.63% 的计算正确；688 行却说“实际喂给模型的 token 有 23.6% 来自 B”，690 行据此谈计算量。真实 `tour.py:343—377` 全程使用 `len(normalization_key(text).split())`，并在末尾明确“不是 BPE”。第 13 章则实际使用 BPE；共享 `miniocr/data/latex_lm.py:30—45` 在清洗原文上训练/编码 BPE，并添加 BOS/EOS，未以规范 token 喂模型。

同一个公式 `\sin h(x)` 的规范 token 数由词法规则决定，BPE 数取决于训练后的合并表，字节数又是 UTF-8 原文长度；三者没有恒定的比例保证。规范键还删除结构，原始清洗串仍保留。故不能把规范 token 的 A/B 均长比直接代入后续 BPE 训练预算，23.6% 是这一教学单位下的结果，不是已测得的真实训练 token 比例。

**共同修订。**第 12 章 688—690 行改为“按本节规范 token 近似，B 占 23.6%；实际训练须用冻结的模型分词器重新统计”，链接第 13 章 BPE/EOS 预算。未重算真实 A/B 的 BPE 比例，不捏造替代数值。
